## 集約関数 {#aggregate}

**集約関数**は、たくさんの行から 1 つの値を計算します。

```sql run
select count(*)        as 商品数,
       sum(stock)      as 在庫の合計,
       avg(price)      as 平均価格,
       min(price)      as 最安,
       max(price)      as 最高
from products;
```

| 関数 | 意味 | NULL の扱い |
| --- | --- | --- |
| `count(*)` | 行の数 | 行そのものを数えるので、NULL も数える |
| `count(式)` | 式が NULL でない行の数 | NULL は数えない |
| `count(distinct 式)` | 異なる値の数 | NULL は数えない |
| `sum(式)` / `avg(式)` | 合計 / 平均 | NULL は無視する。全部 NULL なら結果は NULL |
| `min(式)` / `max(式)` | 最小 / 最大 | NULL は無視する |

NULL の扱いの違いを、生まれ年で確かめてみましょう。

```sql run
select count(*)                   as 全員,
       count(birth_year)          as 生まれ年あり,
       count(distinct prefecture) as 都道府県の数,
       avg(birth_year)            as 平均の生まれ年,
       sum(birth_year) / count(*) as "合計 ÷ 全員（間違い）"
from customers;
```

`avg` は NULL の 2 人を除いた 8 人で割ります。合計を `count(*)` の 10 で割ると、違う値になります。「NULL を 0 とみなすのか、いないものとみなすのか」は、意味を考えて選ぶ必要があります。

:::warn 空の集合の合計は 0 ではなく NULL
条件に合う行が 1 つもないとき、`count` は 0 を返しますが、`sum` は NULL を返します。画面に表示する金額が NULL になって困るときは、`coalesce(sum(x), 0)` と書きます。
:::

```sql run
select count(*) as 件数, sum(price) as 合計, coalesce(sum(price), 0) as 合計0
from products where price > 1000000;
```

## GROUP BY {#group-by}

`group by` は、指定した列の値が同じ行を 1 つの**グループ**にまとめます。集約関数は、グループごとに計算されます。

```sql run
select status, count(*) as 件数
from orders
group by status
order by 件数 desc;
```

都道府県ごとの顧客数や、カテゴリごとの在庫を出してみます。

```sql run
select prefecture, count(*) as 人数, min(joined_on) as 最初の登録
from customers
group by prefecture
order by 人数 desc, prefecture;
```

複数の列でグループにすると、値の組み合わせごとにまとまります。

```sql run
select date_trunc('month', ordered_at)::date as 月, status, count(*) as 件数
from orders
where ordered_at >= '2025-10-01'
group by 月, status
order by 月, status;
```

### SELECT に書ける列のルール

`group by` を使うと、`select` に書けるのは次のどちらかだけです。

1. `group by` に書いた列（またはそれを使った式）
2. 集約関数

グループの中で値が 1 つに決まらない列を書くと、エラーになります。

```sql run error
select prefecture, name, count(*) from customers group by prefecture;
```

:::pgerr 42803 column "customers.name" must appear in the GROUP BY clause or be used in an aggregate function
東京都のグループには 4 人いるので、`name` をどれにすればよいか決められません。グループの中から 1 つ選びたいなら `min(name)` のように集約するか、`string_agg` で全員つなげるか、`group by` に加えます。
:::

例外があります。**主キーで group by したときは、同じテーブルのほかの列も書けます。** 主キーが決まれば、ほかの列の値も 1 つに決まるからです（関数従属といいます）。

```sql run
select c.id, c.name, c.prefecture, count(o.id) as 注文数
from customers c
left join orders o on o.customer_id = c.id
group by c.id          -- 主キーだけでよい
order by 注文数 desc
limit 5;
```

## HAVING {#having}

`where` は**グループに分ける前**の行を絞ります。グループに分けて集約した**後**の結果を絞るのが `having` です。

```sql run
-- 3 回以上注文した顧客
select customer_id, count(*) as 注文数
from orders
group by customer_id
having count(*) >= 3
order by 注文数 desc;
```


両方を組み合わせることもできます。「キャンセル以外の注文が 2 回以上ある顧客」は次のようになります。

```sql run
select c.name, count(*) as 注文数
from orders o join customers c on c.id = o.customer_id
where o.status <> 'cancelled'      -- まず行を絞る
group by c.id
having count(*) >= 2               -- 次にグループを絞る
order by 注文数 desc;
```

:::tip WHERE で絞れるものは WHERE で
集約の結果に関係ない条件（`status <> 'cancelled'` など）は、`having` ではなく `where` に書きます。グループに分ける前に行を減らせるので、処理が軽くなります。
:::

## FILTER 句 {#filter}

1 回の集計で、条件の違う数字をいくつも出したいことがあります。`filter (where 条件)` を集約関数に付けると、その関数だけが条件に合う行を対象にします。

```sql run
select date_trunc('month', ordered_at)::date as 月,
       count(*)                                     as 全注文,
       count(*) filter (where status = 'shipped')   as 発送済み,
       count(*) filter (where status = 'cancelled') as 取消
from orders
group by 月
order by 月;
```

`filter` は SQL 標準の書き方です。ほかのデータベースでは `sum(case when 条件 then 1 else 0 end)` と書くことが多く、意味は同じです。

## 文字列や配列にまとめる {#string-agg}

`string_agg` はグループ内の値を区切り文字でつなぎ、`array_agg` は配列にまとめます。`order by` で並び順も指定できます。

```sql run
select prefecture,
       string_agg(name, '、' order by joined_on) as 顧客,
       array_agg(id order by id) as id一覧
from customers
group by prefecture
order by count(*) desc;
```

`json_agg` を使うと、グループごとに JSON の配列を作れます。API の応答をデータベースで組み立てるときに便利です。

```sql run
select o.id,
       json_agg(json_build_object('product', p.name, 'qty', oi.quantity) order by p.id) as items
from orders o
join order_items oi on oi.order_id = o.id
join products p on p.id = oi.product_id
where o.id in (1, 6)
group by o.id;
```

## 小計と総計 ROLLUP {#rollup}

報告書には、明細の行に加えて小計と総計の行がよく必要になります。`group by rollup (a, b)` は、`(a, b)` ごとの集計、`a` ごとの小計、全体の総計を一度に出します。

```sql run
select c.prefecture,
       o.status,
       count(*) as 件数
from orders o join customers c on c.id = o.customer_id
where c.prefecture in ('東京都', '大阪府')
group by rollup (c.prefecture, o.status)
order by c.prefecture nulls last, o.status nulls last;
```

小計の行では、まとめられた列が NULL になります。元のデータの NULL と区別するには `grouping()` 関数を使います。まとめられた列なら 1、そうでなければ 0 を返します。

```sql run
select case when grouping(c.prefecture) = 1 then '（総計）' else c.prefecture end as 都道府県,
       case when grouping(o.status) = 1 then '（小計）' else o.status end as 状態,
       count(*) as 件数
from orders o join customers c on c.id = o.customer_id
where c.prefecture in ('東京都', '大阪府')
group by rollup (c.prefecture, o.status)
order by grouping(c.prefecture), c.prefecture, grouping(o.status), o.status;
```

| 書き方 | 作られるグループ |
| --- | --- |
| `rollup (a, b)` | `(a, b)`、`(a)`、`()` |
| `cube (a, b)` | `(a, b)`、`(a)`、`(b)`、`()` |
| `grouping sets ((a), (b), ())` | 指定したものだけ |

## 結合してから集計すると数字が膨らむ {#fanout}

集計で一番多い間違いがこれです。「顧客ごとの注文数と購入額」を出したいとします。

```sql run
-- 間違い：注文数が水増しされている
select c.name,
       count(o.id) as 注文数,
       sum(oi.quantity * oi.unit_price) as 購入額
from customers c
join orders o on o.customer_id = c.id
join order_items oi on oi.order_id = o.id
where c.id = 1
group by c.id;
```

佐藤さんの注文は 4 件のはずなのに、注文数が 9 になっています。第 7 章で見たとおり、結合は相手が複数いると行が増えます。佐藤さんの 4 件の注文にはどれも明細が 2〜3 行あるので、明細と結合した時点で注文の行が 9 行に増え、それを数えてしまったのです。

```fig layout 注文と明細を結合すると、明細の数だけ注文の行が増える。この状態で count(o.id) をすると、注文を重複して数えてしまう
{
  unit: 30,
  rows: [
    { label: '注文 1', cells: [{ w: 3, kind: 'stack', t: '注文 1' }, { w: 4, kind: 'heap', t: '万年筆' }], note: '' },
    { label: '', cells: [{ w: 3, kind: 'accent', t: '注文 1' }, { w: 4, kind: 'heap', t: 'インク' }], note: '← 注文 1 が 2 行に' },
    { label: '注文 3', cells: [{ w: 3, kind: 'stack', t: '注文 3' }, { w: 4, kind: 'heap', t: 'ノート' }] },
    { label: '', cells: [{ w: 3, kind: 'accent', t: '注文 3' }, { w: 4, kind: 'heap', t: '鉛筆' }], note: '← 注文 3 も 2 行に' },
  ],
}
```

直し方は 2 つあります。数える対象の重複を除くか、先に集計してから結合するかです。

```sql run
-- 直し方 1：count(distinct)
select c.name,
       count(distinct o.id) as 注文数,
       sum(oi.quantity * oi.unit_price) as 購入額
from customers c
join orders o on o.customer_id = c.id
join order_items oi on oi.order_id = o.id
where c.id = 1
group by c.id;
```

`count(distinct)` は件数には使えますが、`sum` には使えません（同じ金額の別の注文を 1 つにまとめてしまうため）。より確実なのは、**先に注文ごとの金額を集計してから結合する**方法です。

```sql run
-- 直し方 2：先に集計してから結合する
with order_totals as (
  select order_id, sum(quantity * unit_price) as amount
  from order_items
  group by order_id
)
select c.name, count(o.id) as 注文数, sum(t.amount) as 購入額
from customers c
join orders o on o.customer_id = c.id
join order_totals t on t.order_id = o.id
group by c.id
order by 購入額 desc;
```

`with ... as (...)` は第 9 章で学ぶ CTE です。結合するときに、相手が 1 行に決まる形（注文 1 件につき 1 行）にしておけば、行は増えません。

:::key 集計の前に確認すること
複数の表を結合して集計するときは、「結合したあとの 1 行は何を表しているか」を確かめます。1 行が「明細 1 件」なのに「注文の数」を数えようとすると、数字が膨らみます。
:::

## 統計の集約関数 {#stats}

平均以外の統計量も、集約関数として用意されています。

```sql run
select percentile_cont(0.5) within group (order by price) as 中央値,
       mode() within group (order by category_id)        as 最も多い分類,
       round(stddev(price), 1)                           as 標準偏差,
       bool_and(stock > 0)                               as 全部在庫あり,
       bool_or(price > 10000)                            as 一万円超えがある
from products;
```

`within group (order by ...)` は、値を並べてから計算する集約関数（順序集合集約）の書き方です。中央値は平均と違い、極端に高い万年筆の値段に引っぱられません。

:::try 月ごとの売上レポート
2025 年の月ごとの売上（キャンセルを除く `quantity * unit_price` の合計）を出してください。売上のない月も 0 として出すには、`generate_series` で 12 か月の表を作り、`left join` します。
:::

```sql run title="練習用"
with months as (
  select generate_series(date '2025-01-01', date '2025-12-01', interval '1 month')::date as m
),
sales as (
  select date_trunc('month', o.ordered_at)::date as m, sum(oi.quantity * oi.unit_price) as amount
  from orders o join order_items oi on oi.order_id = o.id
  where o.status <> 'cancelled'
  group by 1
)
select to_char(months.m, 'YYYY-MM') as 月, coalesce(sales.amount, 0) as 売上
from months left join sales on sales.m = months.m
order by months.m;
```

:::key この章のまとめ
- `count(*)` は行を、`count(式)` は NULL でない値を数える。空の `sum` は NULL
- `group by` すると、select にはグループの列と集約関数だけが書ける（主キーで group by したときは例外）
- `where` は集約前の行、`having` は集約後のグループを絞る
- `filter (where ...)` で条件ごとの集計を 1 回で。`rollup` で小計と総計
- 結合すると行が増える。集計する前に「1 行が何を表すか」を確かめる
:::

## 確認問題 {#quiz}

この章で学んだことを使って、自分で SQL を書いてみましょう。「答え合わせ」を押すと、出力が模範解答と同じになっているかを判定します。列名や行の順番は（順番を指定した問題を除いて）問いません。答え合わせは本文とは別のデータベースで毎回取り消しながら行うので、何度でも試せます。

:::quiz 都道府県ごとの顧客数
都道府県ごとに、顧客の人数を出してください。

```sql answer
select prefecture, count(*) from customers group by prefecture;
```
:::

:::quiz 商品ごとの販売数
キャンセルされた注文を除いて、商品ごとに売れた数量（`quantity`）の合計を、商品の名前と一緒に出してください。売れていない商品は出しません。

```sql answer
select p.name, sum(oi.quantity) as 販売数
from order_items oi
join orders o on o.id = oi.order_id
join products p on p.id = oi.product_id
where o.status <> 'cancelled'
group by p.id, p.name;
```

:::hint
`order_items` に `orders`（状態を見る）と `products`（名前を見る）を結合してから `group by` します。
:::
:::

:::quiz 2 回以上注文した顧客
注文（キャンセルも含む）を 2 回以上している顧客について、名前と注文回数を出してください。

```sql answer
select c.name, count(*) as 注文回数
from customers c
join orders o on o.customer_id = c.id
group by c.id, c.name
having count(*) >= 2;
```

:::hint
集約したあとの条件は `where` ではなく `having` に書きます。
:::
:::

:::quiz 状態ごとの件数を 1 行で
注文の件数を、`shipped` の件数、`cancelled` の件数、それ以外の件数の 3 列にして、1 行で出してください。

```sql answer
select count(*) filter (where status = 'shipped')   as 発送済み,
       count(*) filter (where status = 'cancelled') as キャンセル,
       count(*) filter (where status not in ('shipped', 'cancelled')) as その他
from orders;
```

:::hint
`count(*) filter (where 条件)` で、条件に合う行だけを数えられます。
:::
:::
