## サブクエリとは {#what}

第 2 章で見たとおり、SELECT の結果は表です。表なので、ほかの SELECT の材料として使えます。SQL の中に埋め込んだ SELECT を**サブクエリ**と呼びます。

サブクエリは、返す形によって置ける場所が変わります。

| 形 | 返すもの | 置ける場所 | 例 |
| --- | --- | --- | --- |
| スカラーサブクエリ | 1 行 1 列の値 | 値を書ける場所ならどこでも | `(select avg(price) from products)` |
| 列のサブクエリ | 1 列 n 行 | `in`、`any`、`all` の右側 | `id in (select customer_id from orders)` |
| 表のサブクエリ | n 行 n 列 | `from` の中、`exists` の中 | `from (select ...) as t` |

## スカラーサブクエリ {#scalar}

1 つの値を返すサブクエリは、普通の値と同じように使えます。「平均より高い商品」を探してみます。

```sql run
select name, price, (select round(avg(price)) from products) as 平均
from products
where price > (select avg(price) from products)
order by price desc;
```

スカラーサブクエリが 2 行以上を返すとエラーになります。

```sql run error
select name from products where price = (select price from products where category_id = 2);
```

:::pgerr 21000 more than one row returned by a subquery used as an expression
`21000` は「1 行のはずが複数行あった」というエラーです。万年筆は 2 本あるので、価格が 2 行返りました。複数の値と比べたいなら `in` を使います。0 行のときはエラーにならず、NULL になります。
:::

## IN・ANY・ALL・EXISTS {#in-exists}

列のサブクエリは、`in` で「どれかに一致するか」を調べるのに使います。

```sql run
-- ギフトタグの商品を注文したことがある顧客
select name from customers
where id in (
  select o.customer_id
  from orders o join order_items oi on oi.order_id = o.id
  join products p on p.id = oi.product_id
  where 'ギフト' = any(p.tags)
)
order by id;
```

`any` と `all` は、比較演算子と組み合わせます。

```sql run
-- ボールペン（分類 3）のどの商品よりも高く、手帳（分類 7）のどれよりも安いノート
select name, price from products
where category_id = 6
  and price > all (select price from products where category_id = 3)
  and price < all (select price from products where category_id = 7);
```

`> all` は「すべてより大きい」、`> any` は「どれか 1 つより大きい」です。`= any` は `in` と同じ意味です。

`exists` は第 7 章で半結合として紹介しました。サブクエリが 1 行でも返せば真になります。サブクエリの select に何を書くかは関係ないので、`select 1` と書くのが慣習です。

### 相関サブクエリ

`exists` のサブクエリは、外側の行の値（`c.id` など）を参照していました。このように外の行を参照するサブクエリを**相関サブクエリ**と呼びます。論理的には、外側の 1 行ごとにサブクエリが評価されます。

```sql run
-- 各商品について、その分類の中での平均価格と比べる
select p.name, p.category_id, p.price,
       (select round(avg(p2.price)) from products p2 where p2.category_id = p.category_id) as 分類の平均
from products p
order by p.category_id, p.price desc;
```

相関サブクエリは読みやすい反面、書き方によっては行の数だけ実行されて遅くなります。PostgreSQL は `exists` や `in` の相関サブクエリを結合に書き換えて速く実行しますが、select の中のスカラーサブクエリは書き換えられないことが多いので、大きな表では第 10 章のウィンドウ関数や、集計してからの結合を検討します。

## FROM の中のサブクエリ {#derived}

`from` にサブクエリを書くと、その結果をテーブルのように扱えます。**派生テーブル**とも呼びます。必ず別名が必要です。

```sql run
select 都道府県, 人数
from (
  select prefecture as 都道府県, count(*) as 人数
  from customers
  group by prefecture
) as t
where 人数 >= 2;
```

この書き方なら、内側で付けた別名（`人数`）を外側の `where` で使えます。第 3 章で「select の別名は where で使えない」と学んだ問題の、もう 1 つの解決策です。

## CTE（WITH 句） {#cte}

サブクエリを何段も入れ子にすると、内側から読む必要があり、読みにくくなります。**CTE**（Common Table Expression、共通テーブル式）は、サブクエリに名前を付けて、上から順に並べて書く方法です。

```sql run
with order_totals as (            -- 1. 注文ごとの金額
  select order_id, sum(quantity * unit_price) as amount
  from order_items
  group by order_id
),
customer_totals as (              -- 2. 顧客ごとの購入額
  select o.customer_id, sum(t.amount) as amount, count(*) as orders
  from orders o join order_totals t on t.order_id = o.id
  where o.status <> 'cancelled'
  group by o.customer_id
)
select c.name, ct.orders as 注文数, ct.amount as 購入額,
       case when ct.amount >= 20000 then '上得意' else '一般' end as ランク
from customers c join customer_totals ct on ct.customer_id = c.id
order by ct.amount desc;
```

CTE には次の利点があります。

- 処理の段階ごとに名前が付くので、何をしているか読み取りやすい
- 同じ CTE を、後の部分で何度でも参照できる
- 途中の段階だけを取り出して、select で中身を確かめながら作れる

### CTE はいつ計算されるか

PostgreSQL 11 までは、CTE は必ず 1 回だけ計算されて結果が保存されました。そのため CTE は「最適化の壁」になり、外側の `where` の条件が CTE の中に入り込めず、遅くなることがありました。

PostgreSQL 12 からは、1 回しか参照されない CTE は、サブクエリと同じように外側の問い合わせに溶け込ませて最適化します。明示的に選びたいときは `materialized` / `not materialized` を付けます。

```sql run
explain
with expensive as materialized (
  select * from products where price > 1000
)
select * from expensive where id = 1;
```

`CTE Scan` が出ていれば、CTE を先に計算して保存しています。`materialized` を `not materialized` に変えて実行すると、`id = 1` の条件が直接 products に適用されることが確かめられます。

## 再帰 CTE {#recursive}

`with recursive` を使うと、CTE が自分自身を参照できます。木構造や連鎖をたどるときに使います。

まずは 1 から 5 までの数を作る、最も単純な例です。

```sql run
with recursive nums(n) as (
  select 1                          -- ① 出発点
  union all
  select n + 1 from nums where n < 5 -- ② 前の結果から次の行を作る
)
select n from nums;
```

再帰 CTE は 2 つの部分からなります。

1. **非再帰項**（`union all` の前）：最初に 1 回だけ実行される
2. **再帰項**（`union all` の後）：直前に作られた行だけを入力にして、新しい行を作る。新しい行が 0 行になったら終わる

### 組織図をたどる

第 7 章では、自己結合で上司を 1 段だけたどりました。再帰 CTE なら、何段でもたどれます。

```sql run
with recursive org as (
  select id, name, manager_id, 1 as depth, name::text as path
  from employees
  where manager_id is null                         -- 店長から始める
  union all
  select e.id, e.name, e.manager_id, org.depth + 1, org.path || ' > ' || e.name
  from employees e
  join org on e.manager_id = org.id                -- 直前の段の部下を探す
)
select repeat('　', depth - 1) || name as 組織図, depth as 階層, path as 経路
from org
order by path;
```

逆向きに、ある従業員から店長までの上司の列をたどることもできます。

```sql run
with recursive bosses as (
  select id, name, manager_id from employees where id = 8   -- 木村さんから
  union all
  select e.id, e.name, e.manager_id
  from employees e join bosses b on e.id = b.manager_id     -- 上司へ上がる
)
select string_agg(name, ' → ') as 上司をたどる from bosses;
```

### 分類の木を集計する

`categories` も親子の木です。「筆記具」の下にあるすべての分類の商品を数えてみます。

```sql run
with recursive tree as (
  select id, name from categories where name = '筆記具'
  union all
  select c.id, c.name from categories c join tree t on c.parent_id = t.id
)
select t.name as 分類, count(p.id) as 商品数
from tree t left join products p on p.category_id = t.id
group by t.id, t.name
order by t.id;
```

### 循環への備え

データに循環（A の親が B、B の親が A）があると、再帰はいつまでも終わりません。PostgreSQL 14 からは `cycle` 句で、同じ行に戻ってきたら止めることができます。

```sql run
create temporary table link (src int, dst int);
insert into link values (1, 2), (2, 3), (3, 1), (3, 4);  -- 1→2→3→1 が循環

with recursive walk as (
  select src, dst from link where src = 1
  union all
  select l.src, l.dst from link l join walk w on l.src = w.dst
) cycle src set is_cycle using route
select src, dst, is_cycle, route from walk;
```

`is_cycle` が真になった行で、それ以上たどるのを止めています。`route` にはたどった経路が入ります。`cycle` を使えない環境では、経路を配列で持ち、`where not (次の id = any(経路))` で止めるのが定番です。

:::warn 再帰に上限を付ける
データの誤りで深い再帰が起きると、問い合わせが終わらなかったり、メモリを使い果たしたりします。`where depth < 100` のように深さの上限を条件に入れておくと安全です。
:::

## データを書き換える CTE {#dml-cte}

PostgreSQL では、CTE の中に `insert`、`update`、`delete` を書けます。`returning` の結果を、後の部分で使えます。

「キャンセルされた注文を、アーカイブ用のテーブルに移す」を 1 文でやってみます。

```sql run
create table cancelled_orders (like orders);

with moved as (
  delete from orders
  where status = 'cancelled'
    and not exists (select 1 from order_items oi where oi.order_id = orders.id)
  returning *
)
insert into cancelled_orders
select * from moved
returning id, customer_id, status;
```

結果が 0 行でした。注文 5 には明細があるので、`not exists` の条件で弾かれています（明細が外部キーで注文を参照しているので、明細を残したまま注文は消せません）。明細も一緒に移すように書き換えます。

```sql run
create table cancelled_items (like order_items);

with target as (
  select id from orders where status = 'cancelled'
),
del_items as (
  delete from order_items where order_id in (select id from target)
  returning *
),
ins_items as (
  insert into cancelled_items select * from del_items returning order_id
),
del_orders as (
  delete from orders where id in (select id from target)
  returning *
)
insert into cancelled_orders select * from del_orders
returning id, status;
```

```sql run
select (select count(*) from cancelled_orders) as 移した注文,
       (select count(*) from cancelled_items)  as 移した明細,
       (select count(*) from orders where status = 'cancelled') as 残った取消注文;
```

1 つの文なので、全部が成功するか、全部が失敗するかのどちらかです。途中で失敗して「明細だけ消えた」ということは起きません。

:::deep 書き換える CTE の注意点
1 つの文の中の CTE は、すべて**同じスナップショット**（文が始まった時点のデータ）を見ます。そのため、ある CTE で更新した行を、別の CTE の SELECT で読んでも、更新前の値が見えます。後の部分に変更後の値を渡したいときは、`returning` を経由します。
:::

:::try 
1. `with recursive` で、2026 年 4 月の 1 日から 30 日までの日付を作ってください（`generate_series` を使わずに）
2. 分類の木を、`筆記具 > 万年筆` のような経路の文字列つきで全部表示してください
:::

```sql run title="練習用"
with recursive cat as (
  select id, name, name::text as path from categories where parent_id is null
  union all
  select c.id, c.name, cat.path || ' > ' || c.name
  from categories c join cat on c.parent_id = cat.id
)
select path from cat order by path;
```

:::key この章のまとめ
- サブクエリは返す形（値・列・表）で置ける場所が決まる。スカラーサブクエリは 2 行以上でエラー
- 外の行を参照する相関サブクエリは、行ごとに評価される（論理的には）
- CTE は名前を付けて上から読める形にする。12 からは 1 回だけ参照される CTE は自動で溶け込む
- 再帰 CTE は「出発点」と「前の結果から次を作る部分」の 2 つ。循環には `cycle` か深さの上限で備える
- CTE の中で INSERT / UPDATE / DELETE を使うと、複数の変更を 1 つの文（＝原子的）にできる
:::

## 確認問題 {#quiz}

この章で学んだことを使って、自分で SQL を書いてみましょう。「答え合わせ」を押すと、出力が模範解答と同じになっているかを判定します。列名や行の順番は（順番を指定した問題を除いて）問いません。答え合わせは本文とは別のデータベースで毎回取り消しながら行うので、何度でも試せます。

:::quiz 平均より高い商品
価格が全商品の平均価格より高い商品の名前と価格を出してください。

```sql answer
select name, price from products where price > (select avg(price) from products);
```

:::hint
平均は 1 つの値なので、スカラーサブクエリ `(select avg(price) from products)` をそのまま比較に使えます。
:::
:::

:::quiz 万年筆を注文したことのある顧客
万年筆（`category_id = 2` の商品）を注文したことのある顧客の名前を、重複なく出してください。注文の状態は問いません。

```sql answer
select c.name
from customers c
where exists (
  select 1
  from orders o
  join order_items oi on oi.order_id = o.id
  join products p on p.id = oi.product_id
  where o.customer_id = c.id and p.category_id = 2
);
```

:::hint
`exists` を使うと、何回注文していても顧客は 1 回だけ出ます。結合してから `distinct` を付けても同じ結果になります。
:::
:::

:::quiz 上司をたどる
従業員「木村 涼」から始めて、上司、その上司…と店長までたどり、名前を**木村 涼から順に**出してください。

```sql answer ordered
with recursive chain as (
  select id, name, manager_id, 1 as depth from employees where name = '木村 涼'
  union all
  select e.id, e.name, e.manager_id, c.depth + 1
  from employees e join chain c on e.id = c.manager_id
)
select name from chain order by depth;
```

:::hint
出発点は木村 涼の 1 行。次の段は「いまの行の `manager_id` を `id` に持つ従業員」です。
:::

:::hint
順番を保つには、段の深さを数える列を足して、最後に `order by` します。
:::
:::
