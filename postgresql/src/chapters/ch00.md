## この本について {#about}

この本は、PostgreSQL と SQL を、使い方と中身の両方から学ぶための日本語の学習書です。対象のバージョンは PostgreSQL 18 です。

データベースの本は、たいてい次のどちらかに偏ります。

- **SQL の書き方の本**：SELECT や JOIN の文法は詳しいが、データベースの中で何が起きているかには触れない
- **内部構造の本**：ページ、WAL、MVCC には詳しいが、実際に手を動かす場面が少ない

この本はその両方を 1 冊で扱います。前半の 11 章で SQL と設計を、後半の 9 章でデータベースの内部と運用を学びます。前半で書いた SQL が、後半で「ディスクの上で実際にどう動いているか」につながるように構成しています。

書くときに決めたルールは 3 つです。

1. **自分の手で実行する。** 本文の SQL は、ほぼすべてその場で実行できます。読むだけより、実行して結果を見て、少し書き換えてもう一度実行するほうが、何倍も早く身に付きます。
2. **絵で示せるものは、先に絵で示す。** 結合の仕組み、8 KB のページの中身、B-tree インデックスの形、トランザクションどうしの見え方。文章より先に図を置きます。
3. **「なぜそうなっているのか」を書く。** SQL の妙な文法にも、PostgreSQL の設計にも、ほとんどの場合は歴史的な理由か技術的な理由があります。それを毎回はっきりさせます。

## ブラウザの中で動く PostgreSQL {#pglite}

この本の SQL を実行しているのは、あなたのブラウザの中で動いている本物の PostgreSQL です。サーバに SQL を送っているわけではありません。

仕組みは次のとおりです。

```fig graph この本の SQL が実行されるまで。PostgreSQL 本体を WebAssembly にしたもの（PGlite）を、ブラウザが読み込んで動かす
{
  col: 210, row: 90,
  nodes: [
    { id: 'src', label: 'PostgreSQL 18\nの C ソースコード', x: 0, y: 0, mono: false },
    { id: 'wasm', label: 'pglite.wasm', sub: 'WebAssembly に変換', x: 1, y: 0, kind: 'stack' },
    { id: 'cdn', label: 'CDN', sub: '初回だけ約 7 MB', x: 2, y: 0, kind: 'muted', mono: false },
    { id: 'page', label: 'この本のページ', x: 2, y: 1, kind: 'accent', mono: false },
    { id: 'db', label: 'PostgreSQL\n（ブラウザの中）', x: 1, y: 1, kind: 'ext', mono: false },
  ],
  edges: [
    { from: 'src', to: 'wasm', label: 'Emscripten' },
    { from: 'wasm', to: 'cdn' },
    { from: 'cdn', to: 'page', label: '読み込み' },
    { from: 'page', to: 'db', label: 'SQL', style: 'accent' },
  ],
}
```

- [PGlite](https://pglite.dev/) は、PostgreSQL の C のソースコードを WebAssembly（ブラウザで動く機械語のようなもの）に変換したものです。SQL の解釈も、実行計画も、ページの読み書きも、本物の PostgreSQL と同じコードが動きます。
- 最初に「実行」を押したとき、PGlite（約 7 MB）をインターネットから読み込みます。2 回目以降はすぐに動きます。
- データベースは**ページごとに 1 つ**です。同じページの中の SQL ブロックは、同じデータベースを共有します。前のブロックで作ったテーブルは、次のブロックから使えます。
- ページを再読み込みすると、データベースは最初の状態に戻ります。上部の「リセット」ボタンでも戻せます。

:::note 本物の PostgreSQL との違い
PGlite は 1 つの接続しか持てません。そのため、2 つのトランザクションを同時に動かして競合させるような実験はできません。そうした場面は、図と「ここでは実行できない例」のコードで説明します。それ以外の SQL は、サーバ版の PostgreSQL とまったく同じように動きます。
:::

### 実行してみる

下のブロックの「実行」ボタンを押してください。Ctrl + Enter（Mac は ⌘ + Enter）でも実行できます。

```sql run
select 'こんにちは、PostgreSQL' as message, version();
```

結果の下に `(1 行)` と出たら成功です。この表示は、PostgreSQL の公式のコマンドラインツール `psql` の出力をまねています。

コードは書き換えられます。`'こんにちは、PostgreSQL'` の部分を好きな文字に変えて、もう一度実行してみてください。書き換えたあとは「元に戻す」ボタンが現れます。

### エラーも結果のうち

わざと間違えてみましょう。存在しないテーブルを読もうとすると、PostgreSQL はエラーを返します。

```sql run error
select * from no_such_table;
```

エラーの表示には 3 つの情報が入っています。

| 部分 | 例 | 意味 |
| --- | --- | --- |
| 重大度 | `ERROR` | 文の実行が失敗した。ほかに `WARNING`、`NOTICE` などがある |
| メッセージ | `relation "no_such_table" does not exist` | 何が起きたか。relation はテーブルのこと |
| SQLSTATE | `42P01` | エラーの種類を表す 5 文字のコード。SQL 標準で決まっている |
| LINE と `^` | `^` の位置 | SQL のどこで問題が見つかったか |

エラーメッセージは英語ですが、パターンは限られています。この本では、よく出るエラーを章ごとに取り上げて読み方を説明します。

## サンプルのデータベース {#sample}

この本のほとんどの章では、「つばめ文具」という小さな文具店のデータベースを使います。実行ボタンを初めて押したとき、自動的に作られます。

```fig graph つばめ文具のテーブルと、そのつながり。矢印は「この列が、あのテーブルの行を指している」（外部キー）という意味
{
  col: 200, row: 100,
  nodes: [
    { id: 'cu', label: 'customers', sub: '顧客 10 人', x: 0, y: 0, kind: 'stack' },
    { id: 'or', label: 'orders', sub: '注文 20 件', x: 1, y: 0, kind: 'stack' },
    { id: 'oi', label: 'order_items', sub: '注文の明細 35 行', x: 2, y: 0, kind: 'accent' },
    { id: 'pr', label: 'products', sub: '商品 13 点', x: 2, y: 1, kind: 'stack' },
    { id: 'ca', label: 'categories', sub: '分類 9 件（木構造）', x: 1, y: 1, kind: 'stack' },
    { id: 'em', label: 'employees', sub: '従業員 8 人（上司つき）', x: 0, y: 1, kind: 'ext' },
  ],
  edges: [
    { from: 'or', to: 'cu', label: 'customer_id' },
    { from: 'oi', to: 'or', label: 'order_id' },
    { from: 'oi', to: 'pr', label: 'product_id' },
    { from: 'pr', to: 'ca', label: 'category_id' },
    { from: 'ca', to: 'ca', curve: 0 },
  ].filter((e) => e.from !== e.to),
}
```

| テーブル | 中身 | 主な列 |
| --- | --- | --- |
| `customers` | 顧客 | `id`, `name`, `email`, `prefecture`（都道府県）, `joined_on`（登録日）, `birth_year`（生まれ年。未登録は NULL） |
| `products` | 商品 | `id`, `name`, `category_id`, `price`（円）, `stock`（在庫）, `released_on`, `tags`（配列）, `attrs`（JSON） |
| `categories` | 商品の分類 | `id`, `name`, `parent_id`（親の分類。木構造になっている） |
| `orders` | 注文 | `id`, `customer_id`, `ordered_at`（日時）, `status`（pending / paid / shipped / cancelled） |
| `order_items` | 注文の明細 | `order_id`, `product_id`, `quantity`（個数）, `unit_price`（その時の単価） |
| `employees` | 従業員 | `id`, `name`, `manager_id`（上司）, `dept`（部署）, `salary`, `hired_on` |

まずは全部の商品を見てみましょう。

```sql run
select * from products;
```

`tags` 列には `{定番,ギフト}` のような配列が、`attrs` 列には JSON が入っています。PostgreSQL はこうした型を標準で持っていて、第 4 章と第 19 章で詳しく扱います。

:::try 
`products` の部分を `customers` や `orders` に変えて実行し、ほかのテーブルの中身も眺めてみてください。`birth_year` が `NULL` の顧客が 2 人いることにも注目してください。NULL は第 2 章の大事な話題です。
:::

## この本の構成 {#map}

全 20 章と付録は、4 つのまとまりに分かれます。

| まとまり | 章 | 内容 |
| --- | --- | --- |
| 背景 | 1〜2 章 | データベースと SQL の歴史、リレーショナルモデルの考え方 |
| SQL | 3〜11 章 | SELECT、データ型、テーブル定義、データの変更、結合、集約、サブクエリ、ウィンドウ関数、設計 |
| 内部 | 12〜17 章 | ページとタプル、MVCC、インデックス、実行計画、WAL、ロック |
| 応用と運用 | 18〜20 章 | 関数とトリガ、JSON と全文検索と拡張機能、権限・バックアップ・チューニング |

SQL を初めて書く人は、第 1 章から順に読んでください。SQL はひととおり書ける人なら、第 2 章の NULL の話を読んだあと、第 12 章から内部の話に進むのもよい読み方です。

### 記号と表記

| 表記 | 意味 |
| --- | --- |
| 「実行」ボタンのあるコード | ブラウザの中の PostgreSQL で実行できる |
| 「エラーになる」の印 | わざとエラーを起こす例。エラーメッセージを読む練習用 |
| 「ここでは実行できない例」の印 | 2 つの接続が必要な例や、サーバの設定ファイルの例 |
| `psql` と書かれた黒い枠 | サーバ版 PostgreSQL に `psql` でつないだときの画面の例 |
| 「やってみよう」の破線の枠 | 自分で SQL を書き換えて試す課題 |

:::key この本の約束
SQL のキーワードは小文字で書きます（`SELECT` ではなく `select`）。PostgreSQL はキーワードの大文字と小文字を区別しないので、どちらで書いても同じです。本文中で文の種類を指すときだけ、読みやすさのために `SELECT` のように大文字で書きます。
:::

## 確認問題 {#quiz}

この章で学んだことを使って、自分で SQL を書いてみましょう。「答え合わせ」を押すと、出力が模範解答と同じになっているかを判定します。列名や行の順番は（順番を指定した問題を除いて）問いません。答え合わせは本文とは別のデータベースで毎回取り消しながら行うので、何度でも試せます。

:::quiz 商品の名前と価格
`products` テーブルから、すべての商品の名前（`name`）と価格（`price`）を出してください。

```sql answer
select name, price from products;
```

:::hint
`select 列, 列 from テーブル;` の形です。`*` の代わりに列の名前を並べます。
:::
:::
