第 10 章

ウィンドウ関数

行をまとめずに、ほかの行を見ながら計算するのがウィンドウ関数です。順位、累計、前の行との差、移動平均、グループごとの上位 N 件を、OVER 句ひとつで書けるようになります。

8 節図 2 点実行できる SQL 16 個確認問題 4 問目安 70 分

10.1集約との違い

第 8 章の group by は、グループの行を 1 行にまとめました。まとめると、元の行の情報（どの商品か）は消えてしまいます。

ウィンドウ関数は、行をまとめずに、各行の横に「その行から見た集計値」を付け足します。

SQL⌘↵
select name, category_id, price,
       avg(price) over (partition by category_id) as 分類の平均
from products
order by category_id, price desc;

ウィンドウ関数は、集約関数（sum、avg、count など）の後ろに over (...) を付けた形をしています。over の中には、どの行の集まり（窓）で計算するかを書きます。

over の中身意味
partition by 列列の値ごとに窓を分ける。group by に似ているが、行はまとめない
order by 列窓の中での行の順番。順位や累計に必要
rows between ...窓の範囲（フレーム）を、現在の行からの相対位置で決める

over () と中身を空にすると、全行が 1 つの窓になります。

SQL⌘↵
select name, price,
       sum(price) over ()                         as 全商品の合計,
       round(100.0 * price / sum(price) over (), 1) as 構成比
from products
order by price desc;

10.2順位を付ける

順位を付ける関数は 3 つあり、同じ値の扱いが違います。

SQL⌘↵
select name, price,
       row_number() over (order by price desc) as row_number,
       rank()       over (order by price desc) as rank,
       dense_rank() over (order by price desc) as dense_rank
from products
order by price desc;
関数同じ値のとき例（12000, 12000, 4800）
row_number()必ず別の番号（どちらが先かは不定）1, 2, 3
rank()同じ順位。次は飛ぶ1, 1, 3
dense_rank()同じ順位。次は飛ばない1, 1, 2

partition by を付けると、窓ごとに 1 から数え直します。

SQL⌘↵
select category_id, name, price,
       rank() over (partition by category_id order by price desc) as 分類内の順位
from products
order by category_id, 分類内の順位;

グループごとの上位 N 件

「各分類で一番高い商品」のような問い合わせは、ウィンドウ関数の代表的な使い方です。ウィンドウ関数は where では使えない（where は select より先に評価される）ので、サブクエリか CTE の中で番号を付けてから、外側で絞ります。

SQL⌘↵
with ranked as (
  select category_id, name, price,
         row_number() over (partition by category_id order by price desc, id) as rn
  from products
)
select category_id, name, price
from ranked
where rn <= 2
order by category_id, rn;

order by price desc, id と id を足しているのは、同じ価格のときの順番を決めるためです。これがないと、実行するたびに結果が変わる可能性があります。

SQLエラーになる⌘↵
select name, row_number() over (order by price desc) as rn
from products
where rn <= 3;
ERRORcolumn "rn" does not exist42703

第 3 章の評価順を思い出してください。ウィンドウ関数は select の段階で計算されるので、where の時点ではまだ存在しません。where row_number() over (...) <= 3 と直接書いても、「window functions are not allowed in WHERE」というエラーになります。

10.3累計と移動平均

over に order by を書くと、窓は「先頭の行から現在の行まで」になります。sum を使えば累計です。

準備この節で使うテーブルを作る SQL（実行ボタンを押すと自動で流れます）
create table daily (d date primary key, amount int not null);insert into dailyselect d::date, (abs(hashtext(d::text)) % 20000) + 1000from generate_series(date '2026-04-01', date '2026-04-14', interval '1 day') d;
SQL⌘↵
select d, amount,
       sum(amount) over (order by d) as 累計
from daily
order by d;

フレーム

order by を付けたときの既定の窓（フレーム）は「先頭から現在の行まで」です。範囲は rows between ... and ... で自由に指定できます。

書き方意味
unbounded preceding窓の先頭
n preceding現在の行の n 行前
current row現在の行
n following現在の行の n 行後
unbounded following窓の最後
SQL⌘↵
select d, amount,
       round(avg(amount) over (order by d rows between 2 preceding and current row)) as 移動平均3日,
       count(*)           over (order by d rows between 2 preceding and current row) as 窓の行数
from daily
order by d;

最初の 2 日は前の行が足りないので、窓の行数が 1、2 になっています。

深掘りROWS・RANGE・GROUPS の違い

フレームの単位には 3 種類あります。rows は物理的な行の数で数えます。range は order by の値の差で範囲を決め（range between interval '2 days' preceding and current row のように書ける）、同じ値の行をまとめて扱います。groups は同じ値の行を 1 つのグループとして数えます。order by だけを書いたときの既定は range between unbounded preceding and current row なので、同じ値の行があると、それらは全部いっぺんに累計に入ります。

10.4前後の行を見る

lag(列, n) は n 行前の値を、lead(列, n) は n 行後の値を返します。n を省略すると 1 です。「前日比」や「前回の注文からの日数」が簡単に求められます。

SQL⌘↵
select d, amount,
       lag(amount) over (order by d)          as 前日,
       amount - lag(amount) over (order by d) as 前日比
from daily
order by d;
SQL⌘↵
-- 顧客ごとに、前回の注文から何日空いたか
select customer_id, id as 注文, ordered_at::date as 日付,
       ordered_at::date - lag(ordered_at::date) over (partition by customer_id order by ordered_at) as 間隔日数
from orders
where customer_id in (1, 2)
order by customer_id, ordered_at;

first_value と last_value の落とし穴

first_value は窓の最初の値、last_value は窓の最後の値を返します。ところが last_value は、思った通りに動かないことで有名です。

SQL⌘↵
select d, amount,
       first_value(amount) over (order by d) as 初日,
       last_value(amount)  over (order by d) as "最終日？"
from daily
order by d
limit 4;

last_value が毎行、自分自身の値になっています。既定のフレームは「先頭から現在の行まで」なので、窓の最後は常に現在の行だからです。窓全体を見たいときは、フレームを明示します。

SQL⌘↵
select d, amount,
       last_value(amount) over (order by d rows between unbounded preceding and unbounded following) as 最終日
from daily
order by d
limit 4;

10.5窓に名前を付ける

同じ over (...) を何度も書くときは、window 句で名前を付けられます。

SQL⌘↵
select d, amount,
       sum(amount) over w as 累計,
       round(avg(amount) over w) as 累計平均,
       max(amount) over w as これまでの最高
from daily
window w as (order by d)
order by d;

10.6ウィンドウ関数の一覧

分類関数返すもの
順位row_number()窓の中の通し番号
rank() / dense_rank()順位（同じ値は同順位）
percent_rank() / cume_dist()相対的な順位（0〜1）
ntile(n)窓を n 等分したときの番号
前後lag(x, n) / lead(x, n)n 行前 / 後の値
first_value(x) / last_value(x) / nth_value(x, n)フレームの最初 / 最後 / n 番目の値
集約sum、avg、count、min、max などフレームの中での集計値

ntile は、顧客を購入額で上位・中位・下位に分けるような場面で使います。

SQL⌘↵
with totals as (
  select o.customer_id, sum(oi.quantity * oi.unit_price) as amount
  from orders o join order_items oi on oi.order_id = o.id
  where o.status <> 'cancelled'
  group by o.customer_id
)
select c.name, t.amount,
       ntile(3) over (order by t.amount desc) as 層,
       round(cume_dist() over (order by t.amount desc)::numeric, 2) as 上位からの割合
from totals t join customers c on c.id = t.customer_id
order by t.amount desc;

10.7評価順の中での位置

ウィンドウ関数は、group by と having の後、order by の前に計算されます。そのため、集約の結果にウィンドウ関数をかけることができます。

SQL⌘↵
-- 月ごとの売上と、その累計・前月比を 1 つの問い合わせで
select date_trunc('month', o.ordered_at)::date as 月,
       sum(oi.quantity * oi.unit_price) as 売上,
       sum(sum(oi.quantity * oi.unit_price)) over (order by date_trunc('month', o.ordered_at)::date) as 累計,
       sum(oi.quantity * oi.unit_price) - lag(sum(oi.quantity * oi.unit_price)) over (order by date_trunc('month', o.ordered_at)::date) as 前月比
from orders o join order_items oi on oi.order_id = o.id
where o.status <> 'cancelled'
group by 月
order by 月;

sum(sum(...)) over (...) は、内側の sum が group by の集約で、外側の sum ... over がウィンドウ関数です。見た目は奇妙ですが、評価順を知っていれば読めます。

やってみよう
  1. 各顧客について、注文の通し番号（1 回目、2 回目…）を付けてください（row_number() over (partition by customer_id order by ordered_at)）
  2. daily から、売上が前日より増えた日だけを取り出してください
  3. 従業員の給与を、部署ごとの平均と比べた差を出してください
練習用⌘↵
select name, dept, salary,
       salary - round(avg(salary) over (partition by dept)) as 部署平均との差
from employees
order by dept, salary desc;
要点この章のまとめ
  • ウィンドウ関数は行をまとめずに、窓の集計値を各行に付け足す。関数() over (partition by ... order by ...)
  • 順位は row_number（必ず別番号）、rank（飛ぶ）、dense_rank（飛ばない）
  • グループごとの上位 N 件は、CTE で番号を付けてから外で絞る
  • order by を書くと既定のフレームは「先頭から現在の行まで」。last_value では窓を明示する
  • lag / lead で前後の行と比べる。集約の結果にもウィンドウ関数をかけられる

10.8確認問題

この章で学んだことを使って、自分で SQL を書いてみましょう。「答え合わせ」を押すと、出力が模範解答と同じになっているかを判定します。列名や行の順番は（順番を指定した問題を除いて）問いません。答え合わせは本文とは別のデータベースで毎回取り消しながら行うので、何度でも試せます。

問 1

価格の順位

正解済み

商品の名前・価格と、価格の高い順の順位を出してください。同じ価格の商品は同じ順位にし、次の順位は飛ばします（1, 1, 3, …）。

-- ここに SQL を書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵出力の値で判定（行の順番と列名は問わない）
ヒント

row_number は同じ値でも別の番号、rank は同じ番号で次が飛び、dense_rank は飛びません。

模範解答
select name, price, rank() over (order by price desc) as 順位 from products;
問 2

分類ごとのいちばん高い商品

正解済み

分類（category_id）ごとに、いちばん価格の高い商品の分類 ID・名前・価格を出してください。同じ価格で並んだ商品は全部出します。

-- ここに SQL を書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵出力の値で判定（行の順番と列名は問わない）
ヒント

ウィンドウ関数は where に書けません。CTE かサブクエリで順位を付けてから、外側で絞ります。

模範解答
with ranked as (  select category_id, name, price,         rank() over (partition by category_id order by price desc) as r  from products)select category_id, name, price from ranked where r = 1;
問 3

前の日との差

正解済み

daily の各日について、日付・売上（amount）と、前の日の売上との差を出してください。最初の日の差は NULL です。

-- ここに SQL を書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵出力の値で判定（行の順番と列名は問わない）
ヒント

lag(列) over (order by d) で 1 つ前の行の値が取れます。

模範解答
select d, amount, amount - lag(amount) over (order by d) as 前日との差 from daily;
問 4

売上の累計

正解済み

daily の各日について、日付と、その日までの売上の累計を出してください。

-- ここに SQL を書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵出力の値で判定（行の順番と列名は問わない）
ヒント

sum(...) over (order by ...) は、既定で先頭から現在の行までを合計します。

模範解答
select d, sum(amount) over (order by d) as 累計 from daily;
