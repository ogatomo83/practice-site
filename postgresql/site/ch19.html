19.1jsonb の基本

第 4 章で、products.attrs が jsonb 型であることを見ました。この章では、JSON をもっと本格的に扱います。

jsonb は、JSON を解析して 2 進数の形で保存します。そのため、入力したときの空白、キーの順番、重複したキーは保たれません。

SQL⌘↵
select '{"b": 1, "a": 2, "a": 3}'::json  as json型はそのまま,
       '{"b": 1, "a": 2, "a": 3}'::jsonb as jsonb型は正規化;

jsonb ではキーが並べ替えられ、重複した a は最後の値だけが残りました。

取り出す演算子

演算子意味例結果
->キーまたは添え字で取り出す（jsonb のまま）attrs -> 'size'"A5"
->>取り出して text にするattrs ->> 'size'A5
#>パスで取り出す（jsonb）doc #> '{a,b}'
#>>パスで取り出して text にするdoc #>> '{a,b}'

この章では、注文の履歴を JSON で受け取るイベントの表を使います。

準備この節で使うテーブルを作る SQL（実行ボタンを押すと自動で流れます）
create table api_events (  id   int generated always as identity primary key,  body jsonb not null);insert into api_events (body) values  ('{"type": "order", "user": {"id": 1, "name": "佐藤"}, "items": [{"sku": "PEN-F", "qty": 1, "price": 12000}, {"sku": "INK-NIGHT", "qty": 1, "price": 2200}], "coupon": null}'),  ('{"type": "order", "user": {"id": 2, "name": "鈴木"}, "items": [{"sku": "BP-05", "qty": 5, "price": 180}], "coupon": "SPRING"}'),  ('{"type": "view", "user": {"id": 3, "name": "高橋"}, "page": "/products/9"}'),  ('{"type": "order", "user": {"id": 1, "name": "佐藤"}, "items": [{"sku": "NOTE-A5", "qty": 3, "price": 450}, {"sku": "PENCIL-HB", "qty": 10, "price": 150}]}'),  ('{"type": "view", "user": {"id": 2, "name": "鈴木"}, "page": "/products/1", "referrer": "search"}');
SQL⌘↵
select id,
       body ->> 'type'                 as 種類,
       body -> 'user' ->> 'name'       as 名前,
       body #>> '{user,id}'            as ユーザID,
       body -> 'items' -> 0 ->> 'sku'  as 最初の商品,
       jsonb_array_length(body -> 'items') as 商品数
from api_events;

存在しないキーを取り出すと NULL になります（エラーにはなりません）。->> の結果は text なので、数値として計算するときは型を変換します。

SQL⌘↵
select id, (body #>> '{user,id}')::int + 1000 as 変換して計算 from api_events limit 2;

調べる演算子

演算子意味例
@>左が右を含むbody @> '{"type": "order"}'
?このキーがあるbody ? 'coupon'
`?`どれかのキーがある`body ?array['coupon', 'referrer']`
?&すべてのキーがあるbody ?& array['type', 'user']
SQL⌘↵
select id, body ->> 'type' as 種類 from api_events
where body @> '{"user": {"id": 1}}';

@> は入れ子の中まで比べます。「user の id が 1 であるもの」を、構造ごと指定できます。

SQL⌘↵
-- coupon キーはあるが、値が null のものも含む
select id, body ? 'coupon' as キーがある, body -> 'coupon' as 値 from api_events;

? は「キーがあるか」を調べるので、値が JSON の null でも真になります。JSON の null と SQL の NULL は別物です。

19.2JSON を組み立てる・分解する

行を展開する

配列を行に展開するのが jsonb_array_elements、オブジェクトをキーと値の組に展開するのが jsonb_each です。

SQL⌘↵
select e.id, item ->> 'sku' as sku, (item ->> 'qty')::int as 数, (item ->> 'price')::int as 単価
from api_events e,
     jsonb_array_elements(e.body -> 'items') as item
where e.body ->> 'type' = 'order';

from に並べた関数（jsonb_array_elements）は、暗黙的に lateral（第 7 章）になり、左の行ごとに展開されます。これで、JSON の中の明細を普通の表のように集計できます。

SQL⌘↵
select item ->> 'sku' as sku, sum((item ->> 'qty')::int) as 合計数
from api_events, jsonb_array_elements(body -> 'items') item
group by 1 order by 2 desc;

JSON_TABLE

PostgreSQL 17 から、SQL 標準の JSON_TABLE が使えます。JSON から表への変換を、列の定義として宣言的に書けます。

SQL⌘↵
select e.id, jt.*
from api_events e,
     json_table(e.body, '$.items[*]'
       columns (
         line   for ordinality,
         sku    text path '$.sku',
         qty    int  path '$.qty',
         price  int  path '$.price',
         amount int  path '$.qty * $.price'
       )) as jt
order by e.id, jt.line;

path には JSON パス（SQL/JSON path）という小さな言語を書きます。$ が JSON 全体、.sku がキー、[*] が配列の全要素です。

JSON パスで検索する

JSON パスは、条件で絞ることもできます。?( ) の中に条件を書き、@ が今見ている要素です。

SQL⌘↵
select id, jsonb_path_query_array(body, '$.items[*] ? (@.price >= 1000).sku') as 千円以上の商品
from api_events
where body @? '$.items[*] ? (@.price >= 1000)';

行から JSON を作る

逆に、表のデータから JSON を作ることもできます。

SQL⌘↵
select jsonb_build_object(
         'customer', c.name,
         'orders', jsonb_agg(jsonb_build_object('id', o.id, 'status', o.status) order by o.id)
       ) as api_response
from customers c join orders o on o.customer_id = c.id
where c.id = 2
group by c.id;

to_jsonb(行) で、1 行をまるごと JSON にもできます（第 18 章の監査ログで使いました）。

JSON を書き換える

SQL⌘↵
update api_events
set body = (jsonb_set(body, '{user,name}', '"佐藤 葵"')   -- パスの値を置き換える
            || '{"checked": true}'::jsonb)              -- || でキーを足す
           - 'coupon'                                   -- - でキーを消す
where id = 1
returning body;

括弧を付けているのは、演算子の優先順位のためです。PostgreSQL では - のほうが || より先に結び付くので、括弧がないと '{"checked": true}' - 'coupon' を先に計算しようとして、「operator is not unique」というエラーになります。

19.3JSON のインデックス

jsonb の列に GIN インデックス（第 14 章）を張ると、@>、?、@? などの検索が速くなります。

演算子クラス対応する演算子大きさ
jsonb_ops（既定）@> ? `? ?& @? @@`大きい（キーと値を別々に索引に入れる）
jsonb_path_ops@> @? @@小さく速い（パスと値の組のハッシュだけを入れる）
SQL⌘↵
insert into api_events (body)
select jsonb_build_object('type', case when g % 10 = 0 then 'order' else 'view' end,
                          'user', jsonb_build_object('id', g % 500),
                          'page', '/products/' || (g % 13))
from generate_series(1, 30000) g;
create index api_events_body_idx on api_events using gin (body jsonb_path_ops);
analyze api_events;
explain (costs off) select count(*) from api_events where body @> '{"user": {"id": 42}}';

特定のキーだけで検索するなら、式インデックスのほうが小さく、範囲検索にも使えます。

SQL⌘↵
create index api_events_type_idx on api_events ((body ->> 'type'));
explain (costs off) select count(*) from api_events where body ->> 'type' = 'order';
要点列にするか、JSON にするか
  • 検索・結合・制約に使う値は、普通の列にする。型が付き、外部キーや CHECK が使え、統計情報も正確になる
  • 構造が決まっていない値、外から受け取ったそのままのデータ、めったに検索しない付加情報は jsonb にする
  • 迷ったら列。後から JSON の中のキーを列に昇格させるのは、その逆より大変

19.4全文検索

like '%ペン%' は、インデックスなしでは全行を読みます。また、「走る」で検索したときに「走った」を見つけることもできません。全文検索は、文章を単語に分け、語形をそろえてから索引にすることで、これを解決します。

PostgreSQL の全文検索は、2 つの型を使います。

型中身作る関数
tsvector文書を単語（語彙素）に分解し、位置を付けたものto_tsvector(設定, 文書)
tsquery検索条件（単語と、AND・OR・NOT）to_tsquery、websearch_to_tsquery
SQL⌘↵
select to_tsvector('english', 'The quick brown foxes jumped over the lazy dogs') as 文書,
       to_tsquery('english', 'fox & dog') as 検索条件,
       to_tsvector('english', 'The quick brown foxes jumped over the lazy dogs') @@ to_tsquery('english', 'fox & dog') as 一致;

foxes は fox に、jumped は jump に変換され（ステミング）、the や over のようなどこにでも出る語（ストップワード）は捨てられています。@@ は「文書が検索条件に一致するか」を調べる演算子です。

SQL⌘↵
create table articles (id int primary key, title text, body text);
insert into articles values
  (1, 'Choosing a fountain pen', 'A fountain pen with a fine nib writes smoothly on quality paper.'),
  (2, 'Notebook guide', 'Grid notebooks help you write neatly. Pens and pencils both work well.'),
  (3, 'Ink colors', 'Blue-black ink dries quickly. Fountain pens need regular cleaning.');
alter table articles add column tsv tsvector
  generated always as (setweight(to_tsvector('english', title), 'A') || to_tsvector('english', body)) stored;
create index articles_tsv_idx on articles using gin (tsv);

select id, title, ts_rank(tsv, q) as 関連度,
       ts_headline('english', body, q) as 抜粋
from articles, websearch_to_tsquery('english', 'fountain pen') q
where tsv @@ q
order by 関連度 desc;
  • setweight で、題名の単語に高い重み（A）を付けている。題名に出てくる記事が上位になる
  • ts_rank は、単語の出現頻度と重みから関連度を計算する
  • ts_headline は、一致した単語を <b> で囲んだ抜粋を作る
  • websearch_to_tsquery は、Google のような検索窓の入力（"完全一致" -除外）を tsquery に変換する

日本語の場合

日本語は単語の間に空白がないので、PostgreSQL に標準で入っている設定では単語に分けられません。

SQL⌘↵
select to_tsvector('simple', '方眼ノートを買った') as 空白で区切れないので1語;

日本語の全文検索には、形態素解析器を組み込む拡張（PGroonga、pg_bigm など）を使うのが一般的です。ここでは、どの PostgreSQL にも付いてくる pg_trgm を使った方法を紹介します。

19.5pg_trgm：部分一致を速くする

pg_trgm は、文字列を3 文字ずつの組（トライグラム）に分解して索引にします。単語に分ける必要がないので、日本語にも使えます。そして、like '%...%' の部分一致検索をインデックスで速くできます。

SQL⌘↵
create extension if not exists pg_trgm;
select show_trgm('pen') as 英語のトライグラム;

日本語の文字は、内部でハッシュ値として表示されますが、同じように 3 文字ずつに分解されています。

SQL⌘↵
create table catalog (id int primary key, name text);
insert into catalog
select g, (array['方眼ノート', 'ボールペン', '万年筆', '手帳', '鉛筆', '消しゴム'])[1 + g % 6] || ' ' || g || '番'
from generate_series(1, 30000) g;
analyze catalog;
explain (costs off) select * from catalog where name like '%万年筆 12%';

インデックスがないので Seq Scan です。トライグラムの GIN インデックスを張ります。

SQL⌘↵
create index catalog_name_trgm on catalog using gin (name gin_trgm_ops);
explain (analyze, costs off) select * from catalog where name like '%万年筆 12%';

Bitmap Index Scan on catalog_name_trgm に変わりました。検索語のトライグラムをすべて含む行だけを索引で絞り込み、最後に本当に一致するかを確かめています（Recheck）。

pg_trgm は、似ている文字列を探すのにも使えます。% 演算子は類似度がしきい値（既定 0.3）以上か、similarity は類似度そのものを返します。

SQL⌘↵
select name, similarity(name, '万年筆 120番') as 類似度
from catalog
where name % '万年筆 120番'
order by 類似度 desc
limit 5;

入力の打ち間違いに強い検索（「もしかして」）に使えます。

19.6拡張機能

ここまで、pageinspect、pg_walinspect、pg_trgm など、いくつもの拡張機能を create extension で使ってきました。拡張機能は、PostgreSQL に新しい型・関数・演算子・インデックスの種類・バックグラウンド処理を追加するパッケージです。

SQL⌘↵
select extname as 拡張機能, extversion as 版 from pg_extension order by 1;

第 1 章で紹介した Stonebraker の POSTGRES の設計思想、「ユーザが型や索引を追加できる」が、ここで生きています。PostgreSQL の内部には、型を扱う関数や、インデックスのアクセスメソッドを差し替えるための入口（フック）がたくさん用意されていて、拡張機能はそこに自分の実装を差し込みます。

よく使われる拡張機能を紹介します。

拡張機能何を足すか
PostGIS地理空間データ（点・線・多角形）の型と、空間インデックス、距離や面積の関数。地図アプリの定番
pgvectorベクトル型と、近傍探索のインデックス（HNSW、IVFFlat）。AI の埋め込みベクトルの検索に使う
TimescaleDB時系列データの自動パーティショニングと圧縮
Citus表を複数のサーバに分散させる
pg_stat_statements問い合わせごとの実行統計（第 15 章）
pgcryptoハッシュ、暗号化の関数
pg_trgmトライグラムによる類似検索・部分一致
hstore / ltreeキーと値の組の型 / 木の経路の型
pg_partman / pg_cronパーティションの自動管理 / データベースの中での定期実行

自分で型を足してみる

拡張機能を作らなくても、SQL だけで型や演算子を足せます。拡張性の感覚をつかむために、「価格帯」を表す型と、それを比べる演算子を作ってみます。

SQL⌘↵
create domain yen as int check (value >= 0);           -- 制約付きの型（ドメイン）
create type price_band as (low yen, high yen);          -- 複合型

create function band_contains(b price_band, p int) returns boolean
language sql immutable
return p between (b).low and (b).high;

create operator @> (leftarg = price_band, rightarg = int, function = band_contains);

select name, price from products
where row(1000, 5000)::price_band @> price
order by price;

@> という、配列や範囲型と同じ記号の演算子を、自分の型のために定義しました。PostgreSQL は、演算子を「左右の型」で区別するので、同じ記号でも型ごとに別の関数を呼び分けます。PostGIS や pgvector も、この仕組みの上で、何百もの型・関数・演算子を足しています。

SQLエラーになる⌘↵
select 'abc'::yen;
SQLエラーになる⌘↵
select (-5)::yen;
やってみよう
  1. api_events から、referrer キーを持つイベントのユーザ名を取り出してください
  2. catalog から、'消しゴム 7' を含む名前を部分一致で探し、トライグラムのインデックスが使われているか explain で確かめてください
  3. products.attrs に jsonb_path_ops の GIN インデックスを張り、attrs @> '{"color": "黒"}' を検索してください
練習用⌘↵
select body -> 'user' ->> 'name' as 名前, body ->> 'referrer' as 参照元
from api_events where body ? 'referrer';
要点この章のまとめ
  • jsonb は正規化して保存する。-> は jsonb、->> は text で取り出す。@> は入れ子まで含めて比べる
  • jsonb_array_elements や JSON_TABLE で JSON を表にし、jsonb_agg で表から JSON を作る
  • jsonb の検索は GIN（jsonb_path_ops が小さく速い）。よく使うキーは式インデックスか、列に昇格させる
  • 全文検索は tsvector と tsquery。日本語は単語に分けられないので、形態素解析の拡張か pg_trgm を使う
  • pg_trgm で like '%...%' をインデックスで速くでき、似た文字列も探せる
  • 拡張機能は型・関数・演算子・インデックス・フックを足す。POSTGRES 以来の拡張性が PostgreSQL の強み

19.7確認問題

この章で学んだことを使って、自分で SQL を書いてみましょう。「答え合わせ」を押すと、出力が模範解答と同じになっているかを判定します。列名や行の順番は（順番を指定した問題を除いて）問いません。答え合わせは本文とは別のデータベースで毎回取り消しながら行うので、何度でも試せます。

問 1

注文イベントのユーザ名

正解済み

api_events から、type が order のイベントについて、id とユーザの名前（user の中の name）を出してください。

-- ここに SQL を書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵出力の値で判定（行の順番と列名は問わない）
ヒント

入れ子のキーは body -> 'user' ->> 'name' か body #>> '{user,name}' でたどれます。

模範解答
select id, body -> 'user' ->> 'name' as 名前from api_eventswhere body ->> 'type' = 'order';
問 2

SKU ごとの売上

正解済み

注文イベントの items 配列を 1 要素 1 行に展開して、SKU ごとの金額（qty * price）の合計を出してください。

-- ここに SQL を書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵出力の値で判定（行の順番と列名は問わない）
ヒント 1

jsonb_array_elements(配列) を FROM に置くと、配列の要素が 1 行ずつになります。

ヒント 2

->> で取り出した値は text なので、::int で数にしてから掛けます。

模範解答
select item ->> 'sku' as sku, sum((item ->> 'qty')::int * (item ->> 'price')::int) as 金額from api_events, jsonb_array_elements(body -> 'items') as itemgroup by 1;
問 3

全文検索

正解済み

記事の表 articles（id, title, body）が用意されています。英語の全文検索で、本文（body）が ink に一致する記事の id と title を出してください。like '%ink%' では、Thinking に引っかかったり Inks を見落としたりします。

-- ここに SQL を書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵出力の値で判定（行の順番と列名は問わない）
ヒント

to_tsvector('english', 文書) @@ to_tsquery('english', '語') で一致を調べます。

模範解答
select id, title from articleswhere to_tsvector('english', body) @@ to_tsquery('english', 'ink');
