第 3 章

SELECT の基本

データを読み出す SELECT 文を、列の選び方、行の絞り込み、並べ替え、件数の制限の順に学びます。SQL が「書いた順」ではなく「決まった順」で評価されることを図で押さえます。

3.1SELECT 文の骨組み

SELECT 文は、次の部品を決まった順番に並べて書きます。省略できる部品が多く、最低限必要なのは select だけです。

SQL
select   列や式        -- 何を取り出すかfrom     テーブル      -- どこからwhere    条件          -- どの行をgroup by 列            -- どうまとめて（第 8 章）having   条件          -- まとめた後どれを（第 8 章）order by 列            -- どの順でlimit    件数;         -- 何件まで

いちばん小さな SELECT は、テーブルすら使いません。電卓のように使えます。

SQL⌘↵
select 1 + 2 * 3 as answer, 'つばめ' || '文具' as shop, current_date as today;
  • as の後ろは列の別名です。結果の見出しになります
  • || は文字列をつなぐ演算子です
  • current_date は今日の日付を返します（括弧を付けない特殊な関数です）

3.2列を選ぶ

* はすべての列を意味します。

SQL⌘↵
select * from customers;

* は手早く中身を見るのには便利ですが、アプリケーションのコードでは列名を書くのが原則です。後でテーブルに列が増えたとき、* だと意図しない列まで読み込んでしまうからです。

SQL⌘↵
select name, prefecture, joined_on from customers;

式と別名

列の代わりに式を書けます。税込み価格を計算してみましょう。

SQL⌘↵
select name,
       price,
       price * 1.1 as tax_included,
       round(price * 1.1) as rounded
from products;

price は整数（int）ですが、1.1 との掛け算の結果は numeric（任意精度の 10 進数）になり、小数点以下も表示されます。round で四捨五入しています。

別名に日本語や空白を使いたいときは、ダブルクォートで囲みます。

SQL⌘↵
select name as "商品名", price as "価格（円）" from products limit 3;
注意'シングル' と "ダブル" は別物

SQL では、文字列はシングルクォート '...'、識別子（テーブル名・列名）はダブルクォート "..." で囲みます。where name = "佐藤 葵" と書くと、「佐藤 葵」という名前の列を探しに行ってエラーになります。

SQLエラーになる⌘↵
select * from customers where name = "佐藤 葵";
ERRORcolumn "佐藤 葵" does not exist42703

42703 は「その名前の列がない」というエラーです。ダブルクォートで囲んだので、PostgreSQL は 佐藤 葵 を列名だと解釈しました。シングルクォートに直すと動きます。

識別子の大文字と小文字

PostgreSQL は、クォートしていない識別子を小文字に変換してから扱います。select NAME from CUSTOMERS は select name from customers と同じです。ダブルクォートで囲むと大文字小文字がそのまま保たれるので、"Name" と name は別の列になります。混乱を避けるため、識別子は小文字とアンダースコアだけで付けるのが慣習です。

3.3行を絞る WHERE

where の後ろの条件が真になる行だけが残ります。比較演算子は次のとおりです。

演算子意味例
=等しいprefecture = '東京都'
<> または !=等しくないstatus <> 'cancelled'
< <= > >=大小price >= 1000
between a and ba 以上 b 以下price between 400 and 600
in (...)どれかに等しいprefecture in ('東京都', '大阪府')
likeパターンに合う（大文字小文字を区別）name like '%ノート%'
ilikeパターンに合う（区別しない。PostgreSQL 独自）email ilike '%EXAMPLE%'
~正規表現に合う（PostgreSQL 独自）name ~ '^[ぁ-ん]'
is nullNULL であるbirth_year is null
SQL⌘↵
select name, price from products
where price between 400 and 600;
SQL⌘↵
select name, prefecture from customers
where prefecture in ('大阪府', '京都府', '愛知県');

LIKE のパターン

like では 2 つの記号が特別な意味を持ちます。

  • % … 0 文字以上の任意の文字列
  • _ … ちょうど 1 文字
SQL⌘↵
select name from products where name like '%ノート%';
SQL⌘↵
-- 「万年筆 」の後ろにちょうど 2 文字
select name from products where name like 'つばめ万年筆 __';

条件を組み合わせる

and、or、not で条件を組み合わせます。and は or より先に評価されるので、迷ったら括弧を付けます。

SQL⌘↵
-- 在庫が 10 個未満で、しかも 2,000 円以上の商品
select name, price, stock from products
where stock < 10 and price >= 2000;
SQL⌘↵
-- 括弧の有無で意味が変わる例
select name, category_id, price from products
where (category_id = 2 or category_id = 9) and price < 5000;
やってみよう

上の SQL から括弧を外すと、結果はどう変わるでしょうか。category_id = 2 or (category_id = 9 and price < 5000) と同じ意味になることを確かめてください。

3.4並べ替え ORDER BY

第 2 章で見たとおり、テーブルの行には順番がありません。結果の順番を保証する方法は order by だけです。

SQL⌘↵
select name, price from products order by price;

desc で降順（大きい順）、asc で昇順（小さい順、省略時の既定）になります。キーを複数並べると、最初のキーが同じ行どうしを次のキーで並べます。

SQL⌘↵
select name, price, stock from products
order by price desc, stock desc;

NULL はどこに並ぶか

PostgreSQL では、NULL はどんな値よりも大きいものとして並べられます。昇順なら最後、降順なら最初に来ます。nulls first / nulls last で明示的に指定できます。

SQL⌘↵
select name, birth_year from customers
order by birth_year desc nulls last;

nulls last を外して実行し、NULL の 2 人が先頭に来ることを確かめてみてください。

列の番号や別名でも並べられる

order by には、select に書いた別名や、列の位置の番号も使えます。

SQL⌘↵
select name, price * 1.1 as tax_included from products
order by tax_included desc
limit 3;

3.5件数を制限する

limit n で最初の n 行だけを返します。offset m を付けると、最初の m 行を飛ばします。

SQL⌘↵
-- 価格の高い順に 4〜6 番目
select name, price from products
order by price desc
limit 3 offset 3;

SQL 標準の書き方は fetch first です。PostgreSQL ではどちらも使えます。

SQL⌘↵
select name, price from products
order by price desc
offset 3 rows fetch first 3 rows only;

fetch first ... with ties を使うと、最後の行と同じ値の行もまとめて返します。12,000 円の万年筆が 2 本あるので、「上位 1 件」と言っても 2 行返ってきます。

SQL⌘↵
select name, price from products
order by price desc
fetch first 1 rows with ties;
注意ORDER BY のない LIMIT

order by を付けずに limit を使うと、「どれか 3 行」が返ります。どの 3 行かは保証されず、データの更新や実行計画の変化で変わることがあります。上位 n 件が欲しいときは、必ず order by と組み合わせます。

深掘りOFFSET が遅くなる理由

offset 100000 と書くと、PostgreSQL は 100,000 行を実際に読んで捨ててから、次の行を返します。ページ送りが深くなるほど遅くなるのはこのためです。大きなデータのページ送りでは、「前のページの最後の値より後ろ」を条件にする方法（キーセットページネーション）を使います。

where price < 前ページ最後の価格 order by price desc limit 20

こうすれば、索引を使ってすぐに目的の位置から読み始められます。

3.6重複を除く DISTINCT

distinct は、結果から重複した行を取り除きます。

SQL⌘↵
select distinct status from orders order by status;

PostgreSQL 独自の distinct on (式) は、式の値ごとに最初の 1 行だけを残します。「各カテゴリで一番高い商品」のような問い合わせが簡単に書けます。

SQL⌘↵
select distinct on (category_id) category_id, name, price
from products
order by category_id, price desc;

distinct on は、order by の並びで「最初」を決めます。そのため order by の先頭は distinct on の式と同じにする必要があります。同じことを標準 SQL で書くには、第 10 章のウィンドウ関数を使います。

3.7条件で値を変える CASE

case 式は、条件に応じて違う値を返します。プログラミング言語の if 文にあたります。

SQL⌘↵
select name, stock,
       case
         when stock = 0 then '在庫切れ'
         when stock < 10 then '残りわずか'
         else '在庫あり'
       end as 在庫状況
from products
order by stock;

上から順に条件を調べ、最初に真になった then の値を返します。どれにも当てはまらず else もなければ NULL になります。

値が決まっているときは、短い書き方もできます。

SQL⌘↵
select id, status,
       case status
         when 'pending'   then '入金待ち'
         when 'paid'      then '入金済み'
         when 'shipped'   then '発送済み'
         when 'cancelled' then '取消'
       end as 状態
from orders
where id between 15 and 20;

3.8SQL が評価される順番

SELECT 文は select から書き始めますが、PostgreSQL が意味を決める順番は違います。論理的には、次の順で処理されます。

この順番を知っていると、よくあるエラーの理由が分かります。たとえば、select で付けた別名は where では使えません。where が評価される時点では、select はまだ評価されていないからです。

SQLエラーになる⌘↵
select name, price * 1.1 as tax_included from products
where tax_included > 1000;
ERRORcolumn "tax_included" does not exist42703

where の時点では、tax_included という列はまだ存在しません。式をもう一度書くか、サブクエリ（第 9 章）で先に計算します。一方、order by は select の後に評価されるので、別名を使えます。

SQL⌘↵
select name, price * 1.1 as tax_included from products
where price * 1.1 > 1000
order by tax_included;
メモ論理的な順番と、実際の実行順

この順番は「結果の意味」を決めるためのもので、PostgreSQL が実際にこの順で処理するとは限りません。たとえば order by ... limit 3 なら、全部を並べ替えずに上位 3 件だけを保つ方法（top-N ソート）を選びます。結果が同じになる限り、プランナは自由にやり方を変えます。

3.9型の変換

最後に、この先何度も出てくる型変換を紹介しておきます。PostgreSQL では ::型名 で値の型を変えられます。標準 SQL の書き方は cast(値 as 型名) です。

SQL⌘↵
select '42'::int + 1        as 数値に,
       42::text || '番'      as 文字列に,
       '2026-04-01'::date + 30 as 日付に,
       cast('3.14' as numeric) as 標準の書き方;

日付に整数を足すと、その日数だけ後の日付になります。型ごとにどんな演算ができるかは、次の第 4 章で詳しく見ていきます。

やってみよう練習問題

次の問い合わせを書いて実行してください。

  1. 東京都の顧客を、登録日（joined_on）の新しい順に並べる
  2. 名前に「ボールペン」を含む商品の名前と価格
  3. 2025 年に入ってから注文された shipped 以外の注文（ordered_at >= '2025-01-01'）
  4. 価格が 1,000 円未満なら「手頃」、1,000 円以上 10,000 円未満なら「中価格」、それ以上なら「高級」と分類した商品の一覧
練習用⌘↵
-- ここに書いて実行してみましょう
select name, joined_on from customers
where prefecture = '東京都'
order by joined_on desc;
要点この章のまとめ
  • 文字列は '...'、識別子は "..."。クォートしない識別子は小文字になる
  • where は真の行だけを残す。like の % と _、PostgreSQL 独自の ilike と ~
  • 順番が欲しいなら必ず order by。NULL は既定で最も大きい値として並ぶ
  • limit / fetch first は order by と組み合わせて使う
  • SQL は FROM → WHERE → GROUP BY → HAVING → SELECT → DISTINCT → ORDER BY → LIMIT の順で意味が決まる

3.10確認問題

この章で学んだことを使って、自分で SQL を書いてみましょう。「答え合わせ」を押すと、出力が模範解答と同じになっているかを判定します。列名や行の順番は（順番を指定した問題を除いて）問いません。答え合わせは本文とは別のデータベースで毎回取り消しながら行うので、何度でも試せます。

問 1

価格帯で絞って並べる

正解済み

価格が 1,000 円以上 5,000 円以下の商品の名前と価格を、価格の高い順に出してください。

-- ここに SQL を書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵出力の値と並び順で判定
ヒント

between a and b は両端を含みます。price >= 1000 and price <= 5000 でも同じです。

模範解答
select name, price from productswhere price between 1000 and 5000order by price desc;
問 2

名前で探す

正解済み

名前に「ノート」を含む商品の名前を出してください。

-- ここに SQL を書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵出力の値で判定（行の順番と列名は問わない）
ヒント

like の % は「0 文字以上の何か」です。

模範解答
select name from products where name like '%ノート%';

在庫の少ない 3 件

正解済み

在庫（stock）の少ない順に 3 件、商品の名前と在庫数を出してください。

-- ここに SQL を書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵出力の値と並び順で判定
模範解答

問 4

在庫の状態を言葉にする

正解済み

商品ごとに、名前と在庫の状態を出してください。状態は、在庫が 0 なら 品切れ、10 未満なら 残りわずか、それ以外は 在庫あり とします。

-- ここに SQL を書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵出力の値で判定（行の順番と列名は問わない）
ヒント

case when 条件 then 値 when ... else 値 end。条件は上から順に調べられ、最初に真になったものが使われます。

模範解答
select name,       case when stock = 0 then '品切れ'            when stock < 10 then '残りわずか'            else '在庫あり' end as 状態from products;
