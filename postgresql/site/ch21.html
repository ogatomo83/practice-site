21.2psql のコマンド

psql は、PostgreSQL の公式のコマンドラインのクライアントです。バックスラッシュで始まるメタコマンドは psql 自身の機能で、SQL ではありません（この本のブラウザの環境では使えません）。

ターミナルここでは実行できない例
$ psql -h localhost -U postgres -d shop
コマンド意味
\lデータベースの一覧
\c shopデータベース shop に接続し直す
\dtテーブルの一覧
\d ordersorders の列・インデックス・制約
\d+ ordersさらに詳しく（サイズ、ストレージなど）
\di / \dv / \dfインデックス / ビュー / 関数の一覧
\dn / \duスキーマ / ロールの一覧
\x縦長表示の切り替え（列が多いとき）
\timing実行時間の表示の切り替え
\eエディタで直前の SQL を編集
\i file.sqlファイルの SQL を実行
\copy t from 'f.csv' csv header手元のファイルを読み込む
\watch 2直前の SQL を 2 秒ごとに繰り返す
\set ON_ERROR_STOP onエラーで止める（スクリプト用）
\gset結果を psql の変数に入れる
\q終了
\? / \h selectメタコマンドのヘルプ / SQL の構文のヘルプ
psqlここでは実行できない例
shop=# \d order_items             Table "public.order_items"   Column   |  Type   | Collation | Nullable | Default------------+---------+-----------+----------+--------- order_id   | integer |           | not null | product_id | integer |           | not null | quantity   | integer |           | not null | unit_price | integer |           | not null |Indexes:    "order_items_pkey" PRIMARY KEY, btree (order_id, product_id)Check constraints:    "order_items_quantity_check" CHECK (quantity > 0)Foreign-key constraints:    "order_items_order_id_fkey" FOREIGN KEY (order_id) REFERENCES orders(id)    "order_items_product_id_fkey" FOREIGN KEY (product_id) REFERENCES products(id)

psql のプロンプトの記号には意味があります。

プロンプト意味
shop=#スーパーユーザで接続中
shop=>一般ユーザで接続中

shop!#失敗したトランザクションの中（rollback が必要）

21.3よく出る SQLSTATE

SQLSTATE は 5 文字のエラーコードです。先頭 2 文字が分類を表します。アプリケーションでは、メッセージの文字列ではなく、このコードでエラーを判定します。

コード名前意味対処章
23502not_null_violationNOT NULL 違反値を入れる5
23503foreign_key_violation外部キー違反参照先を確かめる2, 5
23505unique_violation一意性違反重複を避ける / UPSERT5, 6
23514check_violationCHECK 違反値を直す5
23P01exclusion_violation排他制約違反重なりを避ける5
22003numeric_value_out_of_range数値が範囲外型を大きくする4
22012division_by_zero0 で割ったnullif(x, 0)
22P02invalid_text_representation入力の形式が不正入力を確かめる4
42601syntax_error文法の誤りSQL を直す15
42P01undefined_table表がない名前・スキーマ・search_path0
42703undefined_column列がない名前・クォート・評価順3
42702ambiguous_column列名が曖昧表の別名を付ける7
42803grouping_errorGROUP BY にない列集約するか GROUP BY に加える8
42501insufficient_privilege権限がないGRANT20
21000cardinality_violationサブクエリが複数行in を使う / limit 19
25P02in_failed_sql_transaction失敗したトランザクションの中ROLLBACK6
40001serialization_failure直列化の失敗再試行13

55P03lock_not_availableロックが取れない（nowait / lock_timeout）時間をおいて再試行17
57014query_canceled取り消された（statement_timeout など）問い合わせを速くする
53300too_many_connections接続数の上限接続プーリング20

ブラウザの環境でも、エラーの右端に SQLSTATE が表示されます。わざとエラーを起こして、コードを確かめてみてください。

21.4システムカタログ

PostgreSQL は、自分自身の情報（テーブル、列、インデックス、統計）も表として持っています。これをシステムカタログと呼びます。

カタログ / ビュー中身使った章
pg_classテーブル・インデックス・ビューなど（relpages, reltuples）12, 15
pg_attribute列実験場
pg_indexインデックスの定義
pg_namespaceスキーマ
pg_rolesロール20
pg_settings設定値16, 20
pg_stats列の統計情報（読みやすいビュー）15
pg_locks取得中のロック17
pg_stat_activity接続と実行中の文15, 17
pg_stat_user_tables / _indexes表・インデックスの利用統計13, 14
information_schema.*SQL 標準の形式のカタログ5, 11
SQL⌘↵
-- 文具店の表を、サイズの大きい順に
select c.relname as 表, c.relkind as 種類, c.reltuples::bigint as 行数の見積もり,
       pg_size_pretty(pg_total_relation_size(c.oid)) as インデックス込みのサイズ
from pg_class c join pg_namespace n on n.oid = c.relnamespace
where n.nspname = 'public' and c.relkind = 'r'
order by pg_total_relation_size(c.oid) desc;

要点最後に

SQL は、何が欲しいかを宣言するだけで、データベースがやり方を考えてくれる言語です。しかし、データベースがどう考え、ディスクの上で何をしているかを知っていると、書く SQL も、作る表も、困ったときの調べ方も、まったく変わります。この本で覗いた 8 KB のページ、xmin と xmax、B-tree の葉、WAL のレコードを、ときどき思い出してください。
