第 6 章

データの変更

INSERT・UPDATE・DELETE でデータを書き換え、RETURNING で結果を受け取り、ON CONFLICT と MERGE で「あれば更新、なければ追加」を 1 文で書きます。変更を取り消せるトランザクションの入り口にも触れます。

6.1INSERT

insert は行を追加します。列名を並べ、values に値を書きます。

SQL⌘↵
insert into customers (id, name, email, prefecture, joined_on)
values (11, '吉田 楓', 'kaede@example.com', '神奈川県', '2026-03-01');
select * from customers where id = 11;

書かなかった列（birth_year）には既定値が入ります。既定値を決めていない列の既定値は NULL です。

values にはカンマで区切って複数の行を書けます。1 行ずつ insert を繰り返すより、ずっと速くなります。

SQL⌘↵
insert into categories (id, name, parent_id) values
  (10, '消しゴム', 1),
  (11, '付箋', 5),
  (12, 'ファイル', 5);
select * from categories where id >= 10;
注意列名は省略しない

insert into customers values (...) のように列名を省略すると、テーブルの列の順番どおりに値を書く必要があります。後で列が追加されると、その SQL は壊れます。列名は必ず書きましょう。

SELECT の結果を入れる

values の代わりに SELECT を書くと、その結果をまとめて追加できます。

SQL⌘↵
create table price_history (
  product_id int,
  price      int,
  recorded_at timestamptz default now()
);
insert into price_history (product_id, price)
select id, price from products where category_id = 2;
select * from price_history;

6.2RETURNING

PostgreSQL の insert、update、delete には returning を付けられます。変更した行の値を、SELECT のように受け取れます。

SQL⌘↵
insert into orders (id, customer_id, ordered_at, status)
values (21, 11, now(), 'pending')
returning id, customer_id, ordered_at;

returning がないと、自動で振られた ID や既定値を知るために、もう一度 SELECT を発行することになります。returning なら 1 往復で済みます。アプリケーションから行を追加するときの定番の書き方です。

6.3UPDATE

update は既存の行の値を変えます。set に新しい値を、where に対象の行を書きます。

SQL⌘↵
update products set stock = stock + 10 where id = 8
returning id, name, stock;

set の右辺では、変更前の値（stock）を使えます。複数の列を一度に変えるときはカンマで区切ります。

SQL⌘↵
update products
set price = price + 20,
    tags  = array_append(tags, '値上げ')
where category_id = 3
returning name, price, tags;

PostgreSQL 18 からは、returning で変更前の値 old と変更後の値 new を両方受け取れます。

SQL⌘↵
update products set price = round(price * 1.05)
where id in (1, 2)
returning name, old.price as 変更前, new.price as 変更後;
注意WHERE を忘れると全行が変わる

update products set price = 0; は、全商品の価格を 0 にします。確認のメッセージは出ません。本番のデータを手で書き換えるときは、まず同じ where で SELECT して対象の行を確かめ、次の節で学ぶトランザクションの中で実行するのが安全です。

ほかのテーブルを見ながら更新する

update ... from で、ほかのテーブルと結合した結果を使って更新できます。「2025 年に 1 度でも売れた商品に 売れ筋 タグを付ける」をやってみます。

SQL⌘↵
update products p
set tags = array_append(p.tags, '売れ筋')
from (
  select distinct oi.product_id
  from order_items oi join orders o on o.id = oi.order_id
  where o.ordered_at >= '2025-01-01' and o.ordered_at < '2026-01-01'
    and o.status = 'shipped'
) sold
where p.id = sold.product_id
  and not ('売れ筋' = any(p.tags))
returning p.name, p.tags;

6.4DELETE と TRUNCATE

delete は行を消します。where を付けないと全行が消えます。

SQL⌘↵
delete from price_history where product_id = 2
returning *;

ほかのテーブルを見ながら消すときは using を使います。

SQL⌘↵
-- キャンセルされた注文の明細を消す
delete from order_items oi
using orders o
where o.id = oi.order_id and o.status = 'cancelled'
returning oi.*;

テーブルの中身をすべて消すなら、truncate のほうがはるかに速く終わります。

SQL⌘↵
truncate price_history;
select count(*) from price_history;
delete from ttruncate t
消し方1 行ずつ「消した」印を付けるテーブルのファイルごと新しいものに取り替える
速さ行数に比例して遅い行数によらず一瞬
where使える使えない（全部消すだけ）
ディスクの空きすぐには戻らない（第 13 章の VACUUM が必要）すぐに戻る
トリガ行ごとのトリガが動く行ごとのトリガは動かない
ロック行のロックテーブル全体の強いロック

delete で消した行がすぐにはディスクから消えない理由は、第 12 章と第 13 章で詳しく見ます。

6.5UPSERT：あれば更新、なければ追加

「この商品の在庫を記録したい。まだ行がなければ追加し、あれば数を足す」という処理はよくあります。素直に書くと、SELECT で行を探し、なければ INSERT、あれば UPDATE です。しかしこの方法は、2 つの接続が同時に実行すると、両方が「なかった」と判断して 2 回 INSERT してしまいます。

PostgreSQL の insert ... on conflict は、これを 1 文で安全に行います。

SQL⌘↵
create table daily_sales (
  sold_on    date,
  product_id int,
  qty        int not null,
  primary key (sold_on, product_id)
);
insert into daily_sales values ('2026-04-01', 3, 5)
on conflict (sold_on, product_id)
do update set qty = daily_sales.qty + excluded.qty
returning *;

同じ SQL をもう一度実行してみてください。行は増えず、qty が 10、15 と増えていきます。

  • on conflict (列) には、一意制約か主キーの列を書きます
  • excluded は「INSERT しようとして弾かれた行」を指す特別な名前です
  • daily_sales.qty は既存の行の値です

ぶつかったら何もしない do nothing もあります。

SQL⌘↵
insert into daily_sales values ('2026-04-01', 3, 99)
on conflict do nothing
returning *;

returning が 0 行なので、何も追加されなかったことが分かります。

6.6MERGE

merge は、SQL 標準の「突き合わせて追加・更新・削除する」文です。PostgreSQL 15 から使えます。外から届いた在庫のデータを、商品テーブルに反映する場面で試します。

SQL⌘↵
create temporary table stock_feed (product_id int, stock int);
insert into stock_feed values (3, 300), (8, 0), (99, 10);

merge into products p
using stock_feed f on f.product_id = p.id
when matched and f.stock = 0 then
  update set stock = 0, tags = array_append(p.tags, '入荷待ち')
when matched then
  update set stock = f.stock
when not matched then
  do nothing
returning merge_action() as 動作, p.id, p.name, p.stock;
句意味
using ... on ...突き合わせる相手と、その条件
when matched [and 条件] then相手に対応する行があったとき（update / delete / do nothing）
when not matched then相手に対応する行がなかったとき（insert / do nothing）
when not matched by source then自分の側にしかない行（PostgreSQL 17 から）

when は上から順に調べられ、最初に当てはまったものだけが実行されます。merge_action() と returning は PostgreSQL 17 から使えます。

メモON CONFLICT と MERGE の使い分け

1 行ずつの「あれば更新、なければ追加」には on conflict を使います。同時実行に対して確実に安全です。merge は、別の表と突き合わせてまとめて反映する処理（データの取り込み、同期）に向いています。merge は同時に動く INSERT と競合したとき、一意制約違反のエラーになることがあります。

6.7トランザクションの入り口

ここまでの変更は、1 文ずつすぐに確定していました。複数の文をひとまとまりにして、全部成功するか、全部なかったことにするかのどちらかにする仕組みがトランザクションです。

SQL⌘↵
begin;
update products set stock = stock - 1 where id = 1;
insert into orders (id, customer_id, ordered_at, status) values (22, 1, now(), 'pending');
insert into order_items values (22, 1, 1, 12000);
select id, stock from products where id = 1;

begin から始まった変更は、まだ確定していません。ここで rollback すると、3 つの変更がまとめて取り消されます。

SQL⌘↵
rollback;
select id, stock from products where id = 1;
select count(*) as 注文22 from orders where id = 22;

在庫が元に戻り、注文 22 も消えました。確定させるときは rollback の代わりに commit を実行します。

エラーが起きたトランザクション

トランザクションの途中でエラーが起きると、そのトランザクションは「失敗した」状態になり、rollback するまで何もできなくなります。

SQLエラーになる⌘↵
begin;
insert into orders (id, customer_id, ordered_at, status) values (23, 1, now(), 'pending');
insert into orders (id, customer_id, ordered_at, status) values (23, 1, now(), 'pending');
SQLエラーになる⌘↵
select 1;
ERRORcurrent transaction is aborted, commands ignored until end of transaction block25P02

25P02 は、失敗したトランザクションの中で文を実行しようとしたときのエラーです。どの文を実行しても同じエラーになります。rollback で抜け出します。

SQL⌘↵
rollback;
select count(*) as 注文23 from orders where id = 23;

1 つ目の INSERT も取り消されて、注文 23 は存在しません。「全部か、ゼロか」が守られています。

セーブポイント

トランザクションの途中にセーブポイントを置くと、そこまでだけ戻れます。

SQL⌘↵
begin;
insert into categories values (20, 'テスト分類A', null);
savepoint sp1;
insert into categories values (21, 'テスト分類B', null);
rollback to savepoint sp1;
commit;
select id, name from categories where id >= 20;

sp1 の後の INSERT だけが取り消され、20 番は残りました。トランザクションの仕組み（ACID、分離レベル、MVCC）は、第 13 章でじっくり扱います。

6.8大量のデータを入れる COPY

何万行ものデータを入れるとき、INSERT を繰り返すのは遅すぎます。PostgreSQL には、ファイルや標準入力からまとめて読み込む copy コマンドがあります。

psqlここでは実行できない例
shop=# \copy products_import from 'products.csv' with (format csv, header true)COPY 120000

copy は 1 行ずつ SQL を解釈する手間がないので、INSERT よりも桁違いに速く読み込めます。\copy は psql のコマンドで、手元のパソコンのファイルを読んでサーバに送ります。SQL の copy ... from 'ファイル名' は、サーバ上のファイルを読みます。

逆に、問い合わせの結果を CSV に書き出すこともできます。

psqlここでは実行できない例
shop=# \copy (select * from orders where status = 'shipped') to 'shipped.csv' with (format csv, header)COPY 15

ブラウザの中の PostgreSQL ではファイルを扱えないので、ここでは雰囲気だけ紹介しました。代わりに、大量の行を作る方法として generate_series を覚えておくと便利です。

SQL⌘↵
create table numbers as
select g as n, md5(g::text) as hash
from generate_series(1, 100000) as g;
select count(*), pg_size_pretty(pg_relation_size('numbers')) as サイズ from numbers;

10 万行が一瞬で作られました。第 12 章以降では、こうして作った大きな表で、ページやインデックスの振る舞いを観察します。

やってみよう
  1. products に新しい商品（ID 14、「消しゴム 白」、分類 4、価格 100、在庫 50）を追加し、returning で追加した行を表示してください
  2. daily_sales に ('2026-04-02', 3, 7) を UPSERT する SQL を 2 回実行して、2 回目に qty が 14 になることを確かめてください
  3. トランザクションの中で全商品の価格を 0 にして SELECT で確かめ、rollback で元に戻してください
練習用⌘↵
begin;
update products set price = 0;
select name, price from products limit 3;
練習用（取り消し）⌘↵
rollback;
select name, price from products limit 3;
要点この章のまとめ
  • INSERT は列名を書く。複数行の values やSELECT の結果をまとめて入れられる
  • returning で、変更した行の値をその場で受け取れる。18 からは old と new も
  • UPDATE と DELETE は where を忘れると全行が対象になる
  • 「あれば更新、なければ追加」は on conflict で 1 文に。突き合わせの一括反映は merge
  • begin 〜 commit / rollback で、複数の変更を「全部か、ゼロか」にできる

6.9確認問題

この章で学んだことを使って、自分で SQL を書いてみましょう。「答え合わせ」を押すと、出力が模範解答と同じになっているかを判定します。列名や行の順番は（順番を指定した問題を除いて）問いません。答え合わせは本文とは別のデータベースで毎回取り消しながら行うので、何度でも試せます。

問 1

方眼ノートを値上げする

正解済み

名前が「方眼ノート」で始まる商品の価格を、それぞれ 1.1 倍にしてください。

-- ここに SQL を書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵実行後のテーブルの中身で判定
ヒント 1

where を忘れると全商品が値上げされます。

ヒント 2

price は int なので、price * 1.1 の結果は整数に丸められて入ります（450 → 495）。

模範解答
update products set price = price * 1.1 where name like '方眼ノート%';

答え合わせでは、実行したあとに次の SQL で中身を調べて比べています。

select id, name, price from products order by id;
問 2

キャンセルした注文の明細を消す

正解済み

order_items から、キャンセルされた注文（orders.status = 'cancelled'）の明細だけを削除してください。

-- ここに SQL を書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵実行後のテーブルの中身で判定
ヒント

削除する行を別のテーブルの条件で決めるには、where order_id in (select ...) か delete ... using orders where ... を使います。

模範解答
delete from order_itemswhere order_id in (select id from orders where status = 'cancelled');

答え合わせでは、実行したあとに次の SQL で中身を調べて比べています。

select count(*) as 明細の行数, sum(quantity) as 数量の合計 from order_items;
問 3

あれば足し、なければ入れる

正解済み

日ごとの販売数の表 daily_sales（主キーは (day, product_id)）が用意されています。('2026-04-02', 3, 4) を入れてください。ただし同じ日・同じ商品の行がすでにあれば、その qty に 4 を足してください。

-- ここに SQL を書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵実行後のテーブルの中身で判定
ヒント

insert ... on conflict (キーの列) do update set ...。入れようとした値は excluded.列 で参照できます。

模範解答
insert into daily_sales (day, product_id, qty)values ('2026-04-02', 3, 4)on conflict (day, product_id)do update set qty = daily_sales.qty + excluded.qty;

答え合わせでは、実行したあとに次の SQL で中身を調べて比べています。

select day, product_id, qty from daily_sales order by day, product_id;
