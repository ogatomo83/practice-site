## SMTP の会話：メールはどんな言葉で運ばれるか {#smtp}


メールを運ぶプロトコルが **SMTP**（Simple Mail Transfer Protocol）です。メールを書く・読むプログラムが MUA、配送するサーバーが MTA、メールボックスに置くのが MDA でした（[図解 LinuC 9.6](../../linuc/site/ch09.html#mta)）。SMTP は、MUA から MTA へ、MTA から MTA へ運ぶときに使います。

SMTP はテキストの会話です。クライアントが 1 行のコマンドを送り、サーバーが **3 桁の数字**で始まる行で答えます。debian:12 の Postfix に、手で話しかけた結果です（`C:` の行がクライアントの送ったもの）。

```console
220 mail.example.com ESMTP Postfix (Debian/GNU)
C: EHLO client.example.net
250-mail.example.com
250-PIPELINING
250-SIZE 10240000
250-VRFY
250-ETRN
250-STARTTLS
250-ENHANCEDSTATUSCODES
250-8BITMIME
250-DSN
250-SMTPUTF8
250 CHUNKING
C: MAIL FROM:<carol@example.net>
250 2.1.0 Ok
C: RCPT TO:<alice@example.com>
250 2.1.5 Ok
C: DATA
354 End data with <CR><LF>.<CR><LF>
C: Subject: hello
C: From: carol@example.net
C: To: alice@example.com
C:
C: This is a test.
C: .
250 2.0.0 Ok: queued as 6DD501318EC
C: QUIT
221 2.0.0 Bye
```

`MAIL FROM` と `RCPT TO` で伝える差出人と宛先を**エンベロープ**（封筒）と呼びます。配送に使われるのはこちらです。`DATA` の中の `From:` や `To:` はメールの**ヘッダー**（便せんに書いた名前）で、配送には使われません。

### コマンドと順番

| コマンド | 意味 |
| --- | --- |
| `HELO ホスト名` | あいさつ（昔の SMTP） |
| `EHLO ホスト名` | あいさつ（拡張 SMTP = **ESMTP**）。サーバーは使える拡張（`STARTTLS`、`AUTH`、`SIZE` …）の一覧を返す |
| `MAIL FROM:<アドレス>` | 差出人（エンベロープ） |
| `RCPT TO:<アドレス>` | 宛先（エンベロープ）。宛先の数だけくり返す |
| `DATA` | ここからメールの中身。「`.`」だけの行で終わる |
| `RSET` | いまのメールの指定を取り消す（接続は続く） |
| `VRFY アドレス` | その宛先があるか確かめる |
| `STARTTLS` | ここから TLS で暗号化する（[TLS と SMTP 認証](#tls-auth)） |
| `AUTH 方式` | SMTP 認証をする |
| `QUIT` | 終わる |

順番は **EHLO（HELO）→ MAIL FROM → RCPT TO → DATA → QUIT** です。`MAIL FROM` の前に `RCPT TO` を送ると、`503 5.5.1 Error: need MAIL command` と断られました。

### 応答コードは 1 桁目で読む

| 1 桁目 | 意味 | 例 |
| --- | --- | --- |
| **2**xx | 成功 | `220` 接続時のあいさつ、`250` 成功、`221` 終了、`235` 認証成功 |
| **3**xx | 続きを送ってよい | `354` DATA のあと「本文を送れ」 |
| **4**xx | **一時的な失敗**。あとでもう一度試せば通るかもしれない | `450`、`451`、`454` |
| **5**xx | **永続的な失敗**。同じことをしても通らない | `550` 宛先がない、`554` 中継の拒否、`530` 認証が要る |

送り側の MTA は、4xx を受け取るとメールをキューに残して、あとで再送します。5xx なら再送せず、差出人にエラーのメール（バウンス）を返します。

### ポート番号

| ポート | 名前 | 使い道 |
| --- | --- | --- |
| **25** | smtp | MTA どうしの配送 |
| **587** | submission | MUA から自分のメールサーバーへの**投稿**。STARTTLS と SMTP 認証を使うのがふつう |
| **465** | submissions（smtps） | 587 と同じ使い道。接続した瞬間から TLS（STARTTLS を使わない） |

宛先のドメインの MTA がどのホストかは、DNS の **MX レコード**で調べます。`alice@example.com` 宛てなら、example.com の MX を引き、そのホストのポート 25 につなぎます。

:::warn 試験の注意：数字の意味
`220` は「つないだ直後のあいさつ」、`250` は「そのコマンドは成功」、`354` は「DATA のあと、本文を送ってよい」、`221` は「QUIT への返事」です。4xx は一時的（再送する）、5xx は永続的（再送しない）です。認証の成功は `235` で、`250` ではありません。
:::

**Postfix** は、sendmail の代わりとして作られた MTA です。設定は **`/etc/postfix/`** にあり、中心は 2 つのファイルです。

| ファイル | 役目 |
| --- | --- |
| **`/etc/postfix/main.cf`** | Postfix 全体の設定。`パラメータ = 値` の行が並ぶ |
| **`/etc/postfix/master.cf`** | master デーモンが起動するサービス（smtpd、qmgr、local …）の表。ポート 587 を開けるのはこちら |

### main.cf の書き方

小さな Linux に、見本の `main.cf` を置いてあります。コメントと空行を除いて読みます。

```sh setup root
myhostname = mail.example.com
mydomain = example.com

# 差出人に付けるドメイン
myorigin = $mydomain

inet_interfaces = all
mydestination = $myhostname, localhost.$mydomain, localhost,
    $mydomain
mynetworks = 127.0.0.0/8, 192.168.1.0/24
```

```sh run title="main.cf から、コメントと空行を除いて読む"
grep -v '^#' /etc/postfix/main.cf | grep -v '^$'
```

書き方の決まりは 4 つです。

- 1 行に `パラメータ = 値`。`=` の前後の空白はあってもなくてもよい
- `#` で始まる行はコメント
- **空白で始まる行は、前の行の続き**（上の `mydestination` の 2 行目）
- `$名前` で、ほかのパラメータの値を使える（`$mydomain`、`$myhostname`）。書く順番は関係ない

### まず覚える 8 つのパラメータ

| パラメータ | 意味 | 例 |
| --- | --- | --- |
| **`myhostname`** | このメールサーバーの名前（FQDN） | `mail.example.com` |
| **`mydomain`** | ドメイン名。書かなければ `myhostname` の最初の部分を除いたもの | `example.com` |
| **`myorigin`** | ローカルで出すメールの**差出人に付ける**ドメイン（`@` より後ろがないアドレスに補う） | `$mydomain` |
| **`mydestination`** | **このサーバーが最終の宛先として受け取る**ドメインの一覧。ここにあるドメイン宛ては、ローカルのメールボックスに配る | `$myhostname, localhost.$mydomain, localhost, $mydomain` |
| **`inet_interfaces`** | 接続を待つアドレス。`all` はすべて、`localhost` は自分の中からだけ | `all` |
| **`mynetworks`** | **信頼するクライアント**のネットワーク。ここからは、ほかのドメイン宛ての中継を許す | `127.0.0.0/8, 192.168.1.0/24` |
| **`relayhost`** | 外へのメールを、まとめて渡す相手（プロバイダのサーバーなど）。空なら自分で MX を引いて直接送る | `[smtp.provider.example]:587` |
| **`home_mailbox`** | 配る先。ホームディレクトリからの相対パス。**末尾が `/` なら Maildir 形式** | `Maildir/` |

`myorigin` と `mydestination` は、向きが逆です。`myorigin` は**出す**メールの差出人、`mydestination` は**受け取る**メールの宛先に関係します。上の設定で alice が `mail bob` と送ると、差出人は `alice@example.com`、宛先は `bob@example.com` になります。

`mydestination` に `$mydomain` を入れ忘れると、`alice@example.com` 宛てのメールを「自分宛てではない」と判断します。外から来たものなら、中継の拒否（Relay access denied）になります。

`relayhost` の `[ ]` は、「MX レコードを引かずに、そのホストに直接つなぐ」という意味です。

`home_mailbox` を書かないと、メールは `mail_spool_directory`（Debian 系は `/var/mail`、Red Hat 系は `/var/spool/mail`）の下の、ユーザー名のファイルに足されます。

| 形式 | 置き方 | 設定 |
| --- | --- | --- |
| **mbox** | 1 つのファイルに、すべてのメールをつなげて入れる | 既定（`/var/mail/ユーザー名`）、または `home_mailbox = Mailbox` |
| **Maildir** | 1 通が 1 ファイル。ディレクトリの中に `cur/`、`new/`、`tmp/` | `home_mailbox = Maildir/` |

:::warn 試験の注意：Red Hat 系の既定は inet_interfaces = localhost
rockylinux:9 に入れたばかりの Postfix は、`inet_interfaces = localhost` でした。この設定では 127.0.0.1 のポート 25 でしか待たないので、**外からは接続できません**。外からメールを受けるには `inet_interfaces = all` にします。`inet_interfaces` を変えたときは、`postfix reload` では足りず、Postfix を止めて起動し直します（Docker で確かめると、reload のあとも 127.0.0.1:25 のままでした）。
:::

### postconf：設定を表示する・書き換える

**`postconf`** は、設定を調べるコマンドです。`main.cf` を目で読むよりも確実です。debian:12 での出力です。

```console
# postconf -n
alias_database = hash:/etc/aliases
alias_maps = hash:/etc/aliases
home_mailbox = Maildir/
inet_interfaces = all
mydestination = $myhostname, localhost.$mydomain, localhost, $mydomain
mydomain = example.com
myhostname = mail.example.com
mynetworks = 127.0.0.0/8
myorigin = $mydomain
…
# postconf myorigin
myorigin = $mydomain
# postconf -h myhostname
mail.example.com
# postconf -d inet_interfaces mail_spool_directory message_size_limit
inet_interfaces = all
mail_spool_directory = /var/mail
message_size_limit = 10240000
# postconf -e 'home_mailbox = Maildir/'
```

| 使い方 | すること |
| --- | --- |
| `postconf` | すべてのパラメータといまの値（900 個以上ある） |
| **`postconf -n`** | **`main.cf` に書いてある**（既定値のままではない）パラメータだけ。**n**ot default |
| **`postconf -d`** | **既定値**（**d**efault）。`main.cf` は見ない |
| `postconf 名前` | そのパラメータだけ |
| `postconf -h 名前` | 値だけを表示（名前と `=` を付けない） |
| **`postconf -e '名前 = 値'`** | `main.cf` を書き換える（**e**dit） |
| `postconf -m` | 使える検索表の種類（`hash`、`btree`、`regexp` …） |
| `postconf -a` | 使える SASL（SMTP 認証）の実装（`cyrus`、`dovecot`） |
| `postconf -M` | `master.cf` の内容 |

パラメータの名前を打ちまちがえても、Postfix は止まりません。`postconf -n` が警告を出すだけです。

```console
# postconf -n
postconf: warning: /etc/postfix/main.cf: unused parameter: mydestinaton=foo
```

### postfix：起動・停止・検査

**`postfix`** コマンドは、Postfix 全体を操作します。systemd のある機械では `systemctl start postfix` などを使いますが、設定の検査と再読み込みには `postfix` コマンドもよく使います。

| コマンド | すること |
| --- | --- |
| `postfix start` / `postfix stop` | 起動 / 停止 |
| **`postfix reload`** | 設定を読み直す（動かしたまま） |
| **`postfix check`** | 設定ファイルの書き方、ディレクトリの持ち主と権限を検査する。問題がなければ何も表示しない |
| `postfix status` | 動いているか |
| `postfix flush` | キューのメールを、いますぐ配送し直す（`postqueue -f` と同じ） |

### master.cf：ポート 587 を開ける

`master.cf` の 1 行が、1 つのサービスです。先頭の `smtp inet … smtpd` が、ポート 25 で待つ smtpd です。rockylinux:9 の `master.cf` には、ポート 587（submission）の行が、コメントになって入っています。

```text
smtp      inet  n       -       n       -       -       smtpd
#submission inet n       -       n       -       -       smtpd
#  -o syslog_name=postfix/submission
#  -o smtpd_tls_security_level=encrypt
#  -o smtpd_sasl_auth_enable=yes
#  -o smtpd_relay_restrictions=permit_sasl_authenticated,reject
#smtps     inet  n       -       n       -       -       smtpd
#  -o smtpd_tls_wrappermode=yes
#  -o smtpd_sasl_auth_enable=yes
```

行頭の `#` を外すと、そのポートでも smtpd が動きます。`-o 名前=値` は、**そのサービスだけ** `main.cf` の値を上書きする指定です。submission では「TLS を必ず使う（`encrypt`）」「SMTP 認証を有効にする」「認証した人だけ中継を許す」としています。`smtps`（ポート 465）の `smtpd_tls_wrappermode=yes` は、接続した瞬間から TLS にする指定です。

```fig graph Postfix が RCPT TO を受け取ったときの判断（既定の smtpd_relay_restrictions）
    { from: 'rcpt', to: 'dest' },
    { from: 'my', to: 'ok', label: 'はい' },
    { from: 'sasl', to: 'ok', label: 'はい' },
    { from: 'dest', to: 'ok', label: 'はい' },
    { from: 'dest', to: 'ng', label: 'どれでもない', style: 'dashed' },
  ],
}
```

### オープンリレーにしない

自分のドメイン宛てでないメールを受け取って、ほかのサーバーへ運ぶことを**中継**（リレー）と呼びます。だれからの中継でも引き受けるサーバーを**オープンリレー**（第三者中継）と呼び、迷惑メールの踏み台にされます。

Postfix は、**`smtpd_relay_restrictions`** で中継を制限します。既定値は次のとおりです。

```text
smtpd_relay_restrictions = permit_mynetworks, permit_sasl_authenticated, defer_unauth_destination
```

左から順に調べて、最初に当てはまったもので決まります。

| 制限 | 意味 |
| --- | --- |
| `permit_mynetworks` | クライアントのアドレスが `mynetworks` の中なら許す |
| `permit_sasl_authenticated` | SMTP 認証に成功したクライアントなら許す |
| `reject_unauth_destination` | 宛先が自分のドメイン（`mydestination` など）でなければ、**`554 5.7.1 Relay access denied`** で断る |
| `defer_unauth_destination` | 同じ条件で、`454 4.7.1`（一時的な失敗）で断る |
| `permit` / `reject` | 無条件で許す / 断る |

`mynetworks` の外から、よそのドメイン宛てを送ろうとした結果です（rockylinux:9、`reject_unauth_destination` にしたとき）。

```console
C: MAIL FROM:<carol@example.net>
250 2.1.0 Ok
C: RCPT TO:<dave@other.example.org>
554 5.7.1 <dave@other.example.org>: Relay access denied
C: RCPT TO:<nosuchuser@mail.example.com>
550 5.1.1 <nosuchuser@mail.example.com>: Recipient address rejected: User unknown in local recipient table
C: RCPT TO:<root@mail.example.com>
250 2.1.5 Ok
```

よそのドメイン宛ては断り、自分のドメイン宛てでも、いないユーザーは `550` で断り、いるユーザーだけ受け取っています。

:::warn 試験の注意：mynetworks を広げすぎない
`mynetworks = 0.0.0.0/0` のように全世界を入れると、だれでも中継できるオープンリレーになります。`mynetworks` に入れるのは、自分自身（`127.0.0.0/8`）と、社内の LAN だけです。社外から送る人には、`mynetworks` を広げるのではなく、SMTP 認証（[TLS と SMTP 認証](#tls-auth)）を使わせます。
:::

### /etc/aliases と newaliases（復習）

**`/etc/aliases`** は、ローカルの宛先の別名の表でした（[図解 LinuC 9.7](../../linuc/site/ch09.html#aliases)）。1 行が `別名: 本当の宛先, …` です。Postfix は `alias_maps = hash:/etc/aliases` で、この表を使います。`hash:` は「`newaliases` で作ったデータベース（`/etc/aliases.db`）を引く」という意味です。

```console
# echo 'admin: alice, bob' >> /etc/aliases
# newaliases
# postalias -q admin hash:/etc/aliases
alice, bob
```

**書き換えたら `newaliases`** です（`postalias /etc/aliases` でも同じ）。宛先には、ユーザー名のほかに、次のものも書けます。

| 右側の書き方 | 意味 |
| --- | --- |
| `alice` | ローカルのユーザー |
| `carol@example.net` | 外のアドレスへ転送 |
| `/var/log/dropbox.txt` | そのファイルに足す |
| `"\|/usr/local/bin/script"` | そのコマンドの標準入力に渡す |
| `:include:/etc/postfix/list.txt` | そのファイルに書いた宛先の一覧を使う |

### バーチャルの別名：virtual_alias_maps と postmap

`/etc/aliases` の左側に書けるのは、`@` のないローカルの名前だけです。`info@example.com` のような**ドメインの付いたアドレス**を書き換えるには、**`virtual_alias_maps`** を使います。

```console
# postconf -e 'virtual_alias_maps = hash:/etc/postfix/virtual'
# cat /etc/postfix/virtual
info@example.com	alice
sales@example.com	alice, bob
# postmap /etc/postfix/virtual
# ls /etc/postfix/virtual*
/etc/postfix/virtual  /etc/postfix/virtual.db
# postmap -q info@example.com hash:/etc/postfix/virtual
alice
```

こちらは `:` を使わず、空白で区切ります。データベースに作り直すコマンドは **`postmap`** です。

| 表 | 作り直すコマンド | できるファイル |
| --- | --- | --- |
| `/etc/aliases` | **`newaliases`**（または `postalias /etc/aliases`） | `/etc/aliases.db` |
| `/etc/postfix/virtual`、`transport`、`access`、`sasl_passwd` など | **`postmap ファイル`** | `ファイル.db` |

:::warn 試験の注意：newaliases と postmap
`/etc/aliases` は `newaliases`、`/etc/postfix/` の下の検索表（`hash:` で指定したもの）は `postmap` です。どちらも、テキストを書き換えただけでは反映されません。`postmap -q キー hash:ファイル` で、表を引いた結果を確かめられます。
:::

### /var/spool/postfix：キューのディレクトリ

受け取ったメールは、配送が終わるまで**キュー**に入ります。Postfix のキューは **`/var/spool/postfix/`**（`queue_directory`）の下の、ディレクトリの集まりです。

| ディレクトリ | 入っているもの |
| --- | --- |
| `maildrop` | ローカルの `sendmail` コマンドで投げ込まれたメール。pickup デーモンが拾う |
| `incoming` | 受け取ったばかりのメール |
| **`active`** | いま配送しようとしているメール |
| **`deferred`** | **一時的に配送に失敗**し、再送を待っているメール |
| **`hold`** | 管理者が保留にしたメール。解放するまで配送しない |
| `corrupt` | 壊れていて読めないキューファイル |
| `private`、`public` | デーモンどうしが話すためのソケット |
| `pid` | デーモンの PID ファイル |

deferred のメールは、間隔を空けながら再送を試みます。`maximal_queue_lifetime`（既定は 5 日）を過ぎても送れなければ、差出人にエラーを返してあきらめます。

### キューを見る・操作する

宛先のドメインが引けないメールを送ったあとの、debian:12 の出力です。

```console
# mailq
-Queue ID-  --Size-- ----Arrival Time---- -Sender/Recipient-------
4659913799A     331 Mon Nov 16 21:20:41  alice@example.com
(Host or domain name not found. Name service error for name=nowhere.invalid type=MX: Host not found, try again)
                                         dave@nowhere.invalid

-- 0 Kbytes in 1 Request.
# find /var/spool/postfix/deferred -type f
/var/spool/postfix/deferred/4/4659913799A
# postsuper -h 4659913799A
postsuper: 4659913799A: placed on hold
postsuper: Placed on hold: 1 message
# postsuper -H 4659913799A
postsuper: 4659913799A: released from hold
postsuper: Released from hold: 1 message
# postsuper -d ALL
postsuper: Deleted: 1 message
# mailq
Mail queue is empty
```

左端の **キュー ID**（`4659913799A`）が、そのメールの名前です。キューファイルの名前にも、ログにも、同じ ID が出ます。括弧の中は、配送できなかった理由です。

| コマンド | すること |
| --- | --- |
| **`mailq`**、**`postqueue -p`**、`sendmail -bp` | キューの一覧を表示する（**p**rint） |
| **`postqueue -f`**、`postfix flush`、`sendmail -q` | キューのメールを、いますぐ配送し直す（**f**lush） |
| `postqueue -i キューID` | その 1 通だけ、いますぐ配送し直す |
| `postqueue -s ドメイン` | そのドメイン宛てだけ、いますぐ配送し直す |
| **`postsuper -d キューID`** | その 1 通を**削除**する（**d**elete） |
| **`postsuper -d ALL`** | キューのメールを**すべて削除**する。`postsuper -d ALL deferred` なら deferred だけ |
| `postsuper -h キューID` | **保留**にする（**h**old）。`ALL` も使える |
| `postsuper -H キューID` | 保留を**解く** |
| `postsuper -r キューID` | キューに入れ直す（**r**equeue）。設定を変えたあと、もう一度処理させる |
| **`postcat -q キューID`** | キューにあるメールの中身（エンベロープと本文）を表示する |

`postqueue` は一般ユーザーでも使えるコマンド、`postsuper` は root だけが使えるコマンドです。

:::warn 試験の注意：postqueue と postsuper
**見る・流す**は `postqueue`（`-p` と `-f`）、**消す・保留する**は `postsuper`（`-d`、`-h`、`-H`）です。`postsuper -d ALL` の `ALL` は大文字です。`postsuper` の `-h` はヘルプではなく hold です。
:::

### ログの場所

Postfix は、syslog の **mail** ファシリティでログを出します（[図解 LinuC 9.3](../../linuc/site/ch09.html#rsyslog)）。どのファイルに入るかは、rsyslog の設定で決まります。

| 系統 | メールのログ |
| --- | --- |
| Red Hat 系 | **`/var/log/maillog`** |
| Debian 系（rsyslog を入れた場合） | **`/var/log/mail.log`**（エラーだけ `/var/log/mail.err` にも） |
| systemd のジャーナル | `journalctl -u postfix`（[図解 LinuC 9.4](../../linuc/site/ch09.html#journal)） |

Dovecot も、既定では同じ mail ファシリティに出すので、同じファイルに入ります。

### ログを読む

小さな Linux の `/var/log/maillog` に、Docker で動かした Postfix のログを置いてあります。1 通のメールは、**同じキュー ID の行**を追うと、受け取りから配送まで読めます。

```sh run title="キュー ID で 1 通のメールを追う"
grep 6DD501318EC /var/log/maillog
```

- `smtpd`：`client=` で、どこから受け取ったか
- `cleanup`：Message-ID を付けた
- `qmgr`：`from=<差出人>`、大きさ、宛先の数。キューに入った（`queue active`）
- `local`：`to=<宛先>`、**`status=sent`**。ローカルのメールボックスに配った（`delivered to maildir`）
- `qmgr`：`removed`。配送が終わって、キューから消した

行の `postfix/smtpd`、`postfix/local` は、ログを出したデーモンの名前です。**`smtpd` は受け取る側**、**`smtp` はよそのサーバーへ送る側**、`local` はローカルに配る役目です。

```sh run title="配送の結果だけを集める"
grep -c 'status=sent' /var/log/maillog
grep 'status=' /var/log/maillog | grep -v 'status=sent'
grep 'reject:' /var/log/maillog
```

| ログの言葉 | 意味 |
| --- | --- |
| `status=sent` | 配送できた |
| **`status=deferred`** | 一時的な失敗。キュー（deferred）に残って、あとで再送する。括弧の中が理由 |
| **`status=bounced`** | 永続的な失敗。差出人にエラーのメールを返した |
| `NOQUEUE: reject: RCPT from …` | 受け取る前に断った（キューに入っていないので NOQUEUE）。そのあとに応答コードと理由 |
| `relay=local` / `relay=ホスト[アドレス]:25` | どこへ渡したか |
| `dsn=2.0.0` / `4.x.x` / `5.x.x` | 配送の状態のコード。1 桁目は SMTP の応答と同じ意味 |
| `orig_to=<admin>` | 別名で書き換える前の宛先 |
| `sasl_method=PLAIN, sasl_username=alice` | SMTP 認証をして送ってきた |

2 つめのコマンドで出た deferred の行は、宛先のドメイン `nowhere.invalid` の MX が DNS で引けなかった、と言っています。3 つめの reject の行は、172.17.0.8 から `dave@other.example.org` 宛ての中継を断った記録です。

:::tip トラブルの切り分け
1. `mailq` でキューに残っているか見る。残っていれば、括弧の中の理由を読む
2. ログをキュー ID か宛先のアドレスで `grep` する
3. `status=deferred` なら相手か DNS か経路の問題、`reject` なら自分の制限（`mynetworks`、`mydestination`、認証）の問題、ログに何も出ないなら、そもそも接続が届いていない（`inet_interfaces`、ファイアウォール、`ss -ltn`（[図解 LinuC 7.10](../../linuc/site/ch07.html#ss)））
:::

### TLS の基本設定

SMTP は、そのままでは平文です。**STARTTLS** は、SMTP の会話の途中で TLS に切り替える仕組みです。Postfix をサーバーとして TLS に対応させるには、証明書と秘密鍵の場所を `main.cf` に書きます（証明書の作り方は [9 章](ch09.html)）。

```text
smtpd_tls_cert_file = /etc/pki/tls/certs/postfix.pem
smtpd_tls_key_file = /etc/pki/tls/private/postfix.key
smtpd_tls_security_level = may
```

これは rockylinux:9 の `main.cf` に初めから入っている 3 行です（debian:12 では `/etc/ssl/certs/` と `/etc/ssl/private/` の下のファイル）。

| パラメータ | 意味 |
| --- | --- |
| **`smtpd_tls_cert_file`** | サーバー証明書（PEM 形式）のファイル |
| **`smtpd_tls_key_file`** | 秘密鍵のファイル |
| **`smtpd_tls_security_level`** | TLS をどこまで求めるか（下の表） |
| `smtpd_tls_CAfile` | クライアント証明書を確かめるときなどに使う、CA の証明書 |
| `smtpd_tls_loglevel` | TLS のログの詳しさ。`1` にすると、接続ごとにプロトコルと暗号が出る |
| `smtpd_tls_auth_only = yes` | TLS で暗号化した接続でだけ、SMTP 認証を受け付ける |
| `smtp_tls_security_level` | Postfix が**クライアントとして**よそへ送るときの TLS |

| `smtpd_tls_security_level` | 動き |
| --- | --- |
| `none`（空も同じ。既定） | TLS を使わない |
| **`may`** | STARTTLS を**案内する**。クライアントが使えば暗号化し、使わなくても受け取る（**日和見の TLS**） |
| **`encrypt`** | TLS を**必須**にする。STARTTLS をしないクライアントは断る |

`encrypt` にしたポートに、STARTTLS なしで送ろうとすると、こう断られます。

```console
C: MAIL FROM:<a@example.net>
530 5.7.0 Must issue a STARTTLS command first
```

インターネットのほかの MTA には、TLS を使えないものもあります。そのため、**ポート 25 は `may`**、**ポート 587 は `master.cf` の `-o` で `encrypt`** にするのがふつうです。

パラメータの名前は、**`smtpd_` がサーバー側**（受け取る）、**`smtp_` がクライアント側**（よそへ送る）です。`smtpd_tls_security_level` と `smtp_tls_security_level` は別の設定です。

`smtpd_tls_loglevel = 1` にして、STARTTLS でつないだときのログです。

```text
Nov 16 21:22:08 mail postfix/smtpd[975]: Anonymous TLS connection established from mail.example.com[172.17.0.8]: TLSv1.3 with cipher TLS_AES_256_GCM_SHA384 (256/256 bits) …
```

手元から確かめるには、`openssl s_client` に `-starttls smtp` を付けます。

```console
$ openssl s_client -connect mail.example.com:25 -starttls smtp
```

:::note 古い書き方：smtpd_use_tls
古い資料では、`smtpd_use_tls = yes`（`may` と同じ）と `smtpd_enforce_tls = yes`（`encrypt` と同じ）が使われています。いまは `smtpd_tls_security_level` を使います。
:::

### SMTP 認証（SMTP AUTH）

もとの SMTP には、送る人を確かめる仕組みがありません。**SMTP 認証**は、`AUTH` コマンドでユーザー名とパスワードを確かめる拡張です。認証には **SASL**（Simple Authentication and Security Layer）という枠組みを使います。Postfix は、パスワードを自分では確かめず、**Cyrus SASL** か **Dovecot** に任せます。

Dovecot に任せるときの `main.cf` です。

```text
smtpd_sasl_auth_enable = yes
smtpd_sasl_type = dovecot
smtpd_sasl_path = private/auth
smtpd_relay_restrictions = permit_mynetworks, permit_sasl_authenticated, reject_unauth_destination
```

| パラメータ | 意味 |
| --- | --- |
| **`smtpd_sasl_auth_enable = yes`** | SMTP 認証を有効にする（既定は `no`） |
| **`smtpd_sasl_type`** | SASL の実装。`cyrus`（既定）か `dovecot` |
| `smtpd_sasl_path` | Dovecot のときは、認証用のソケットの場所（キューのディレクトリからの相対パス。`private/auth` は `/var/spool/postfix/private/auth`） |
| `smtpd_sasl_security_options` | 許さない方式。既定は `noanonymous`（匿名を許さない） |
| **`permit_sasl_authenticated`** | 制限の一覧に書く。認証に成功したクライアントを許す |

`smtpd_sasl_auth_enable = yes` だけでは、認証できるようになるだけです。中継を許すのは、`smtpd_relay_restrictions` の **`permit_sasl_authenticated`** です。

認証を有効にすると、EHLO の返事に `250-AUTH PLAIN` のような行が増えます。`AUTH PLAIN` のあとの文字列は、ユーザー名とパスワードを **base64** にしただけのものです。暗号ではないので、TLS の中で使います。debian:12 で、STARTTLS のあとに認証して、よそのドメイン宛てを送った結果です。

```console
250-AUTH PLAIN
…
AUTH PLAIN AGFsaWNlAHNlY3JldA==
235 2.7.0 Authentication successful
MAIL FROM:<alice@example.com>
250 2.1.0 Ok
RCPT TO:<dave@nowhere.invalid>
250 2.1.5 Ok
```

ログには `sasl_method=PLAIN, sasl_username=alice` と残ります（[ログを読む](#queue)）。

:::deep Postfix がクライアントとして認証する（プロバイダへの中継）
`relayhost` のサーバーが SMTP 認証を求めるときは、Postfix がクライアントとして認証します。こちらは `smtp_`（d なし）のパラメータです。

```text
relayhost = [smtp.provider.example]:587
smtp_sasl_auth_enable = yes
smtp_sasl_password_maps = hash:/etc/postfix/sasl_passwd
smtp_tls_security_level = encrypt
```

`/etc/postfix/sasl_passwd` には `[smtp.provider.example]:587 ユーザー名:パスワード` と書き、`postmap /etc/postfix/sasl_passwd` でデータベースにします。
:::

## exim：もう 1 つの MTA {#exim}

**exim** は、Postfix と同じ役目の MTA です。Debian 系では、既定の MTA として **exim4** が入ります。試験では「Postfix のほかにどんな MTA があるか」「基本のコマンド」がわかれば足ります。

| | Postfix | exim |
| --- | --- | --- |
| 設定の場所 | `/etc/postfix/`（`main.cf`、`master.cf`） | Debian 系は **`/etc/exim4/`**。もとの exim は 1 つの設定ファイル（`exim.conf`） |
| 作り | 役目ごとの小さなデーモンの集まり | 1 つの大きなプログラム（`exim`） |
| キューの一覧 | `mailq`、`postqueue -p` | `mailq`、**`exim -bp`** |
| キューを流す | `postqueue -f` | `exim -q` |
| 宛先の配送先を試す | `postmap -q` など | **`exim -bt アドレス`** |
| ログ | syslog の mail（`/var/log/maillog`） | Debian 系は `/var/log/exim4/mainlog` |

debian:12 に exim4 を入れて確かめました。`sendmail`、`mailq`、`newaliases` は、どれも exim4 へのリンクです。

```console
# ls -l /usr/sbin/sendmail /usr/bin/mailq /usr/sbin/exim
lrwxrwxrwx 1 root root  5 May 27 16:52 /usr/sbin/sendmail -> exim4
lrwxrwxrwx 1 root root 13 May 27 16:52 /usr/bin/mailq -> ../sbin/exim4
lrwxrwxrwx 1 root root  5 May 27 16:52 /usr/sbin/exim -> exim4
# exim -bt root@localhost
root@localhost -> /var/mail/mail
  transport = address_file
# exim -bpc
0
```

`exim -bt` は、そのアドレスがどこへ配られるかを、実際には送らずに表示します（address **t**est）。`exim -bpc` はキューにあるメールの数です。Debian 系では、`/etc/exim4/update-exim4.conf.conf` を書き換えて `update-exim4.conf` を実行すると、本当の設定ファイルが作り直されます。

Postfix は、メールをメールボックスに置くところまでしかしません。離れた機械のメールソフトにメールを読ませるのが **Dovecot** です。Dovecot は **POP3** と **IMAP** のサーバーで、MTA ではありません。

| | POP3 | IMAP |
| --- | --- | --- |
| 考え方 | メールを手元に**ダウンロードする**。ふつうはサーバーから消す | メールを**サーバーに置いたまま**読む。フォルダも既読の印もサーバーにある |

| ポート（平文、STARTTLS） | **110** | **143** |
| ポート（初めから TLS） | **995**（POP3S） | **993**（IMAPS） |

### /etc/dovecot：設定ファイルの置き方

```fig tree Dovecot の設定は、dovecot.conf が conf.d の下のファイルを読み込む形になっている
{
  root: { label: '/etc/dovecot', kind: 'dir', children: [
    { label: 'dovecot.conf', hl: true, note: '中心の設定ファイル。protocols、listen、!include conf.d/*.conf' },
    { label: 'conf.d', kind: 'dir', note: '話題ごとに分けた設定', children: [
      { label: '10-auth.conf', note: '認証（disable_plaintext_auth、auth_mechanisms）' },
      { label: '10-mail.conf', note: 'メールボックスの場所（mail_location）' },
      { label: '10-master.conf', note: 'サービスとポート、ソケット（service、inet_listener）' },
      { label: '10-ssl.conf', hl: true, note: 'TLS（ssl、ssl_cert、ssl_key）' },
      { label: '10-logging.conf', note: 'ログ（log_path、auth_verbose）' },
      { label: '20-imap.conf、20-pop3.conf', note: 'プロトコルごとの設定' },
      { label: 'auth-system.conf.ext', note: 'システムのユーザーで認証する設定（passdb、userdb）' },
    ] },
    { label: 'local.conf', note: 'あれば最後に読まれる（!include_try）' },
  ] },
}
```

設定のディレクトリは **`/etc/dovecot/`**、中心のファイルは **`/etc/dovecot/dovecot.conf`** です。`dovecot.conf` の最後のほうに、次の 2 行があります。

```text
!include conf.d/*.conf
!include_try local.conf
```

`!include` は、ほかのファイルを読み込む指定です。`!include_try` は、ファイルがなくてもエラーにしません。`conf.d/` のファイルは名前の順に読まれ、同じ設定が 2 回出てきたら、**あとから読んだほう**が使われます。

設定の書き方は `名前 = 値` です。`service 名前 { … }` のように、`{ }` で囲んだまとまりもあります。

### まず覚える設定

| 設定 | ファイル | 意味 |
| --- | --- | --- |
| **`protocols`** | `dovecot.conf` | 提供するプロトコル。`protocols = imap pop3`。`lmtp` も書ける |
| **`listen`** | `dovecot.conf` | 接続を待つアドレス。既定は `*, ::`（IPv4 と IPv6 のすべて） |
| **`mail_location`** | `10-mail.conf` | メールボックスの形式と場所 |
| `disable_plaintext_auth` | `10-auth.conf` | 暗号化していない接続での平文の認証を断る。既定は `yes` |
| `auth_mechanisms` | `10-auth.conf` | 使える認証の方式。既定は `plain`。`plain login` のように足す |
| `ssl`、`ssl_cert`、`ssl_key` | `10-ssl.conf` | TLS の設定（[Dovecot の TLS](#dovecot-tls)） |
| `log_path` | `10-logging.conf` | ログの出力先。既定は `syslog` |

rockylinux:9 の `dovecot.conf` では、`protocols` はコメントになっています。

```text
#protocols = imap pop3 lmtp submission
```

POP3 だけを提供したければ、`protocols = pop3` と書きます。debian:12 で試すと、待つポートは 110 と 995 だけになりました。

### mail_location：メールボックスの形式と場所

`mail_location` は、**Postfix が配った場所と形式に合わせます**。合っていないと、ログインはできるのに、メールが 1 通も見えません。

```text
mail_location = maildir:~/Maildir
mail_location = mbox:~/mail:INBOX=/var/mail/%u
```

| 書き方 | 意味 | Postfix 側の設定 |
| --- | --- | --- |
| `maildir:~/Maildir` | Maildir 形式。ホームの `Maildir/` | `home_mailbox = Maildir/` |
| `mbox:~/mail:INBOX=/var/mail/%u` | mbox 形式。受信箱は `/var/mail/ユーザー名`、ほかのフォルダは `~/mail/` | 既定（`home_mailbox` を書かない） |

`%u` はユーザー名、`%h` はホームディレクトリに置き換わります。debian:12 の `10-mail.conf` は、初めから 2 つめの mbox の行でした。rockylinux:9 では `mail_location` が書かれておらず、Dovecot が自動で探します。

### 認証：だれのパスワードで確かめるか

`10-auth.conf` の最後で、認証の元を選びます。

```text
auth_mechanisms = plain
!include auth-system.conf.ext
#!include auth-sql.conf.ext
#!include auth-ldap.conf.ext
#!include auth-passwdfile.conf.ext
```

既定の `auth-system.conf.ext` は、**システムのユーザー**（`/etc/passwd` のユーザーを、PAM で確かめる）を使います。`doveconf -n` には、次のように出ます。

```text
passdb {
  driver = pam
}
userdb {
  driver = passwd
}
```

**passdb** はパスワードを確かめる元、**userdb** はユーザーの UID やホームディレクトリを調べる元です。

**`disable_plaintext_auth = yes`**（既定）は、TLS で守られていない接続で、パスワードをそのまま送る認証（PLAIN、LOGIN）を断る設定です。同じ機械の中からの接続（127.0.0.1 など）は安全とみなされ、平文でも認証できます。

## doveconf と doveadm：設定を確かめ、動かしたまま管理する {#doveadm}

### doveconf：設定を表示する

**`doveconf`** は、Dovecot がいま読んでいる設定を表示します。Postfix の `postconf` にあたります。`conf.d/` に分かれた設定を、まとめて見られます。

```console
# doveconf -n
# 2.3.19.1 (9b53102964): /etc/dovecot/dovecot.conf
# OS: Linux 6.10.14-linuxkit aarch64 Debian 12.15
# Hostname: mail.example.com
log_path = /var/log/dovecot.log
mail_location = maildir:~/Maildir
mail_privileged_group = mail
…
ssl = required
ssl_cert = </etc/ssl/certs/mail.pem
ssl_key = # hidden, use -P to show it
# doveconf protocols mail_location
protocols =  imap pop3
mail_location = maildir:~/Maildir
# doveconf -h mail_location
maildir:~/Maildir
```

| 使い方 | すること |
| --- | --- |
| **`doveconf -n`** | **既定値と違う**設定だけを表示する（Postfix の `postconf -n` と同じ考え方） |
| `doveconf -a` | すべての設定を表示する（**a**ll） |
| `doveconf -d` | 既定値を表示する（**d**efault） |
| `doveconf 名前 …` | その設定だけ |
| `doveconf -h 名前` | 値だけ（名前を付けない） |
| `doveconf -P` | 秘密鍵などの隠される値も表示する |

設定の名前をまちがえると、`doveconf` がエラーで教えてくれます。設定を変えたら、まず `doveconf -n` で検査します。

```console
# doveconf -n
doveconf: Fatal: Error in configuration file /etc/dovecot/local.conf line 3: Unknown setting: ssl_certificate
```

### doveadm：動いている Dovecot を管理する

**`doveadm`** は、動いている Dovecot に対する管理のコマンドです。`doveadm サブコマンド` の形で使います。debian:12 で試した結果です。

```console
# doveadm who

alice    1 pop3  (6541) (127.0.0.1)
# doveadm kick alice
# doveadm user alice
field	value

# doveadm mailbox list -u alice

# doveadm mailbox status -u alice messages INBOX

{SHA512-CRYPT}$6$Zzofp5GJBiQPt…
# doveadm log find

```

| サブコマンド | すること |
| --- | --- |
| **`doveadm reload`** | 設定を読み直す（接続中の人は切らない） |
| `doveadm stop` | Dovecot を止める |
| **`doveadm who`** | いま接続しているユーザー、プロトコル、接続元の一覧 |
| `doveadm kick ユーザー` | そのユーザーの接続を切る |
| `doveadm user ユーザー` | userdb を引いた結果（UID、ホーム、メールボックスの場所） |
| `doveadm mailbox list -u ユーザー` | そのユーザーのメールボックス（フォルダ）の一覧 |
| `doveadm auth test ユーザー [パスワード]` | 認証を試す |
| `doveadm pw -s 方式` | パスワードのハッシュを作る（パスワードファイルに書くため。`-l` で方式の一覧） |
| `doveadm log find` | ログがどのファイルに出ているかを探す。`doveadm log errors` は最近のエラー |

:::warn 試験の注意：doveconf と doveadm
**設定を表示する**のは `doveconf`、**動いているサーバーを管理する**のは `doveadm` です。`doveadm pw` はパスワードのハッシュを**作って表示するだけ**で、だれかのパスワードを変えるコマンドではありません。`doveadm kick` は接続を切るだけで、ユーザーを消しません。
:::

### Dovecot のログ

Dovecot のログは、既定では syslog の mail ファシリティに出ます（Postfix と同じ `/var/log/maillog` や `/var/log/mail.log`）。`log_path = /var/log/dovecot.log` のように、ファイルを指定することもできます。ログインの記録は、こう読みます。

```text
Nov 16 21:20:59 imap-login: Info: Login: user=<alice>, method=PLAIN, rip=172.17.0.8, lip=172.17.0.8, mpid=6933, TLS, session=<PLKyWmtgeOqsEQAI>
Nov 16 21:21:03 pop3-login: Info: Login: user=<alice>, method=PLAIN, rip=172.17.0.8, lip=172.17.0.8, mpid=6942, TLS, session=<HjHoWmtgdrqsEQAI>
Nov 16 21:21:05 pop3(alice)<6942><HjHoWmtgdrqsEQAI>: Info: Disconnected: Logged out top=0/0, retr=0/0, del=0/3, size=1369
```

- `imap-login` / `pop3-login`：どのプロトコルでログインしたか
- `user=<alice>`：ユーザー、`method=PLAIN`：認証の方式
- `rip=`：接続元（**r**emote IP）、`lip=`：サーバー側のアドレス（**l**ocal IP）
- `TLS`：TLS で暗号化された接続

認証の失敗を詳しく調べるときは、`10-logging.conf` で `auth_verbose = yes` にします。

## Dovecot の TLS：ssl、ssl_cert、ssl_key {#dovecot-tls}

TLS の設定は `conf.d/10-ssl.conf` にあります。rockylinux:9 の初めの状態です。

```text
ssl = required
ssl_cert = </etc/pki/dovecot/certs/dovecot.pem
ssl_key = </etc/pki/dovecot/private/dovecot.pem
```

| 設定 | 意味 |
| --- | --- |
| **`ssl`** | `no`：TLS を使わない。`yes`：TLS を使える（使うかはクライアントしだい）。**`required`**：TLS を必須にする。TLS なしではログインできない（同じ機械の中からの接続は安全とみなされ、例外。Docker で確かめた） |
| **`ssl_cert`** | サーバー証明書。**`<` に続けてファイルのパス**を書く |
| **`ssl_key`** | 秘密鍵。同じく `<` に続けてパス |
| `ssl_min_protocol` | 許す TLS の最低のバージョン。既定は `TLSv1.2` |
| `ssl_cipher_list` | 許す暗号の一覧 |

debian:12 では `ssl = yes` で、ファイルは `/etc/dovecot/private/dovecot.pem` と `dovecot.key` でした。

:::warn 試験の注意：ssl_cert の「<」
`ssl_cert = </etc/…` の **`<`** は、「このファイルの**中身**を値にする」という印です。`<` を忘れて `ssl_cert = /etc/…` と書くと、パスの文字列そのものを証明書として読もうとします。Docker で試すと、`doveconf` はエラーを出さず、接続したときにログに `Can't load SSL certificate (ssl_cert setting): There is no valid PEM certificate.` と出て、TLS の接続が切れました。
:::

TLS の使い方は、ポートで 2 通りあります。

| 使い方 | ポート | 確かめ方 |
| --- | --- | --- |
| 初めから TLS（IMAPS、POP3S） | 993、995 | `openssl s_client -connect ホスト:993` |
| 平文でつないで STARTTLS で切り替える | 143、110 | `openssl s_client -connect ホスト:143 -starttls imap` |

debian:12 で、ポート 995 に TLS でつないで POP3 を話した結果です。

```console
$ openssl s_client -connect mail.example.com:995 -quiet
+OK Dovecot (Debian) ready.
USER alice
+OK
PASS secret
+OK Logged in.
STAT
+OK 3 1369
QUIT
+OK Logging out.
```

### Postfix の SMTP 認証を Dovecot が引き受ける

[SMTP 認証](#tls-auth)で、Postfix に `smtpd_sasl_type = dovecot`、`smtpd_sasl_path = private/auth` と書きました。Dovecot の側では、`10-master.conf` の `service auth` に、そのソケットを作る設定を書きます。

```text
service auth {
  unix_listener /var/spool/postfix/private/auth {
    mode = 0660
    user = postfix
    group = postfix
  }
}
```

これで、POP3 / IMAP と SMTP 認証が、**同じユーザー名とパスワード**で通ります。Postfix の `smtpd_sasl_path` は `/var/spool/postfix` からの相対パスなので、2 つの設定は同じソケットを指しています。

:::note Dovecot 2.4 では設定の名前が変わった
この章は、試験の範囲と同じ Dovecot 2.3 までの書き方です。2.4 では、`ssl_cert` が `ssl_server_cert_file`、`mail_location` が `mail_driver` と `mail_path` になるなど、設定の名前が大きく変わりました。試験では、この章の名前（`ssl_cert`、`ssl_key`、`mail_location`）を覚えてください。
:::

:::key まとめ
- SMTP の順番は EHLO（HELO）→ MAIL FROM → RCPT TO → DATA → QUIT。応答は 2xx 成功、354 本文を送れ、4xx 一時的な失敗、5xx 永続的な失敗。ポートは 25（配送）、587（投稿）、465（初めから TLS）
- Postfix の設定は `/etc/postfix/main.cf`（パラメータ）と `master.cf`（サービスとポート）。`myhostname`、`mydomain`、`myorigin`（差出人に付ける）、`mydestination`（自分宛てとして受け取る）、`inet_interfaces`（Red Hat 系の既定は `localhost`）、`mynetworks`（中継を許す相手）、`relayhost`、`home_mailbox = Maildir/`
- `postconf -n`（main.cf に書いたもの）、`-d`（既定値）、`-e`（書き換え）。`postfix check`（検査）、`postfix reload`（読み直し）
- 中継の制限は `smtpd_relay_restrictions = permit_mynetworks, permit_sasl_authenticated, reject_unauth_destination`。断ると `554 5.7.1 Relay access denied`
- `/etc/aliases` は `newaliases`、`/etc/postfix/virtual` などは `postmap`
- キューは `/var/spool/postfix/`（`incoming`、`active`、`deferred`、`hold`）。`mailq` = `postqueue -p`、`postqueue -f`（流す）、`postsuper -d ID` / `-d ALL`（消す）、`-h` / `-H`（保留 / 解く）、`postcat -q ID`（中身）
- ログは `/var/log/maillog`（Red Hat 系）、`/var/log/mail.log`（Debian 系）。キュー ID で追う。`status=sent` / `deferred` / `bounced`、`NOQUEUE: reject`
- TLS：`smtpd_tls_cert_file`、`smtpd_tls_key_file`、`smtpd_tls_security_level = may`（使えれば使う）/ `encrypt`（必須）。`smtpd_` はサーバー側、`smtp_` はクライアント側
- SMTP 認証：`smtpd_sasl_auth_enable = yes`、`smtpd_sasl_type = dovecot`（既定は `cyrus`）、`smtpd_sasl_path`、`permit_sasl_authenticated`
- exim：Debian 系の既定の MTA。`/etc/exim4/`、`exim -bp`（キュー）、`exim -bt`（宛先の試験）
- Dovecot は POP3（110、995）と IMAP（143、993）のサーバー。`/etc/dovecot/dovecot.conf` と `conf.d/`。`protocols`、`listen`、`mail_location = maildir:~/Maildir`、`disable_plaintext_auth`
- `doveconf -n`（既定と違う設定）、`doveadm reload` / `who` / `kick` / `user` / `pw` / `auth test` / `log find`
- Dovecot の TLS：`ssl = yes` / `required` / `no`、`ssl_cert = </パス`、`ssl_key = </パス`（`<` を忘れない）
:::

## 練習問題 {#practice}

:::q 2.10.1-01 single
Postfix の `main.cf` で、「このサーバーが最終の宛先として受け取り、ローカルのメールボックスに配るドメイン」を並べるパラメータはどれか。
- [ ] `myorigin`
- [x] `mydestination`
- [ ] `mynetworks`
- [ ] `relayhost`
- [ ] `inet_interfaces`
:::why
`mydestination` に書いたドメイン宛てのメールを、Postfix は自分宛てとして受け取り、ローカルに配ります。`myorigin` はローカルで出すメールの差出人に補うドメイン、`mynetworks` は中継を許す信頼するクライアントのネットワーク、`relayhost` は外へのメールをまとめて渡す相手、`inet_interfaces` は接続を待つアドレスです（[まず覚える 8 つのパラメータ](#main-cf)）。
:::
:::

:::q 2.10.1-02 single
次の `main.cf` のサーバーで、ローカルのユーザー alice が `mail bob` でメールを送った。差出人のアドレスとして正しいものはどれか。

```text
myhostname = mail.example.com
mydomain = example.com
myorigin = $mydomain
mydestination = $myhostname, localhost.$mydomain, localhost
```
- [ ] `alice@mail.example.com`
- [x] `alice@example.com`
- [ ] `alice@localhost`
- [ ] `alice@localhost.example.com`
:::why
ローカルで出すメールの、`@` より後ろがないアドレスには、`myorigin` の値が補われます。`myorigin = $mydomain` で、`mydomain` は `example.com` なので `alice@example.com` です。`alice@mail.example.com` になるのは `myorigin = $myhostname` のときです。`mydestination` は受け取る宛先のドメインの一覧で、差出人には関係しません（[まず覚える 8 つのパラメータ](#main-cf)）。
:::
:::

:::q 2.10.1-03 fill
Postfix の設定のうち、`main.cf` に書いてある（既定値のままではない）パラメータだけを表示したい。空欄に入るオプションを入力してください。

```text

```

:::why
`postconf -n` は、`main.cf` で明示的に設定したパラメータだけを表示します。`-d` は既定値を表示し（`main.cf` は見ない）、`-e` は `main.cf` を書き換え、`-h` は値だけを表示し、`-m` は使える検索表の種類を表示します（[postconf](#main-cf)）。
:::
:::

:::q 2.10.1-04 single
`main.cf` に `virtual_alias_maps = hash:/etc/postfix/virtual` と書き、`/etc/postfix/virtual` に 1 行を足した。この変更を反映させるために実行するコマンドとして正しいものはどれか。
- [ ] `newaliases`
- [x] `postmap /etc/postfix/virtual`
- [ ] `postconf -e /etc/postfix/virtual`
- [ ] `postsuper -r ALL`
- [ ] `postcat -q /etc/postfix/virtual`
:::why
`hash:` で指定した検索表は、`postmap ファイル` でデータベース（`/etc/postfix/virtual.db`）に作り直します。`newaliases` が作り直すのは `/etc/aliases`（`alias_database`）だけです。`postconf -e` は `main.cf` のパラメータを書き換えるコマンドで、引数は `名前 = 値` です。`postsuper -r` はキューのメールを入れ直すコマンド、`postcat -q` はキューにあるメールの中身を表示するコマンドです（[バーチャルの別名](#relay)）。
:::
:::

:::q 2.10.1-05 multi
Postfix のキューを操作するコマンドの説明として正しいものを 2 つ選択してください。
- [x] `postsuper -d ALL` は、キューにあるメールをすべて削除する
- [x] `postqueue -f` は、キューにあるメールの配送を、いますぐ試みる
- [ ] `postqueue -p` は、キューにあるメールをすべて削除する
- [ ] `postsuper -h キューID` は、保留にしたメールを解放して配送させる
- [ ] `postcat -q キューID` は、そのメールをキューの先頭に移す
:::why
`postsuper -d` は削除（delete）で、`ALL` を付けるとすべてです。`postqueue -f` は flush で、待っているメールの配送をすぐに試みます。`postqueue -p` は一覧の表示（`mailq` と同じ）で、削除はしません。`postsuper -h` は保留（hold）にするほうで、解くのは大文字の `-H` です。`postcat -q` はキューのメールの中身を表示するだけです（[キューを見る・操作する](#queue)）。
:::

:::q 2.10.1-06 single
メールのログに次の行があった。この行の説明として正しいものはどれか。

```text
Nov 16 21:20:43 mail postfix/smtp[6834]: 4659913799A: to=<dave@nowhere.invalid>, relay=none, delay=1.5, delays=1.5/0/0/0, dsn=4.4.3, status=deferred (Host or domain name not found. Name service error for name=nowhere.invalid type=MX: Host not found, try again)
```
- [ ] 外から来たメールを、中継の制限によって受け取らずに断った
- [ ] 宛先のサーバーに永続的なエラーで断られたので、差出人にエラーのメールを返して、キューから消した
- [x] 宛先のドメインの配送先を DNS で引けなかったので、メールをキューに残した。あとで再送を試みる
- [ ] ローカルのユーザー dave のメールボックスに配った
:::why
`status=deferred` は一時的な失敗で、メールは deferred のキューに残り、あとで再送されます。理由は括弧の中にあり、`nowhere.invalid` の MX が引けなかった、と言っています。`postfix/smtp` は、よそのサーバーへ送る側のデーモンです。中継を断った記録は `postfix/smtpd` の `NOQUEUE: reject:` です。永続的な失敗で差出人に返したときは `status=bounced`、配れたときは `status=sent` です（[ログを読む](#queue)）。
:::
:::

:::q 2.10.1-07 single
社外の機械（203.0.113.5）からメールを送ろうとすると断られ、サーバーのログに次の行が残った。`main.cf` は下のとおりである。原因の説明として正しいものはどれか。

```text
postfix/smtpd[975]: NOQUEUE: reject: RCPT from unknown[203.0.113.5]: 554 5.7.1 <dave@other.example.org>: Relay access denied; from=<carol@example.com> to=<dave@other.example.org> proto=ESMTP helo=<pc.example.net>
```

```text
mydestination = $myhostname, localhost, example.com
mynetworks = 127.0.0.0/8, 192.168.1.0/24
smtpd_relay_restrictions = permit_mynetworks, permit_sasl_authenticated, reject_unauth_destination
```
- [ ] `inet_interfaces` が `localhost` なので、外からの接続を受け付けていない
- [ ] 差出人の `carol@example.com` が `/etc/aliases` に登録されていない
- [x] クライアントが `mynetworks` の外にあり、SMTP 認証もしておらず、宛先が自分のドメインでもないので、中継を断った
- [ ] 宛先の `other.example.org` の MX レコードが DNS で引けなかった
- [ ] キューがいっぱいで、新しいメールを受け取れなかった
:::why
`Relay access denied` は、`reject_unauth_destination` で断ったときの応答です。203.0.113.5 は `mynetworks` に入っておらず、認証もしていない（していればログに `sasl_username=` が出ます）ので、宛先が `mydestination` などの自分のドメインでなければ断られます。`inet_interfaces = localhost` なら、そもそも接続できず、smtpd のログは残りません。`/etc/aliases` は宛先の別名の表で、差出人の検査には使いません。MX が引けないときは、受け取ったあとの配送で `status=deferred` になります（[オープンリレーにしない](#relay)）。
:::

:::q 2.10.1-08 single
SMTP で 1 通のメールを送るとき、クライアントが送るコマンドの順番として正しいものはどれか。
- [ ] `MAIL FROM` → `EHLO` → `RCPT TO` → `DATA` → `QUIT`
- [ ] `EHLO` → `RCPT TO` → `MAIL FROM` → `DATA` → `QUIT`
- [x] `EHLO` → `MAIL FROM` → `RCPT TO` → `DATA` → `QUIT`
- [ ] `EHLO` → `DATA` → `MAIL FROM` → `RCPT TO` → `QUIT`
:::why
あいさつ（`EHLO` か `HELO`）、差出人（`MAIL FROM`）、宛先（`RCPT TO`）、中身（`DATA`）、終了（`QUIT`）の順です。Postfix に `MAIL FROM` の前に `RCPT TO` を送ると、`503 5.5.1 Error: need MAIL command` と断られました（[コマンドと順番](#smtp)）。
:::
:::

:::q 2.10.1-09 multi
SMTP の応答コードの説明として正しいものを 2 つ選択してください。
- [x] `354` は、`DATA` コマンドに対して「メールの中身を送ってよい」と答える応答である
- [x] 4 で始まる応答は一時的な失敗、5 で始まる応答は永続的な失敗を表す
- [ ] `220` は、`QUIT` コマンドに対して接続の終了を知らせる応答である
- [ ] `250` は、`AUTH` コマンドによる認証が成功したことだけを表す応答である
- [ ] 5 で始まる応答を受け取った MTA は、メールをキューに残して、あとで再送する
:::why
`DATA` の返事は `354` で、そのあとに本文を送ります。4xx は一時的な失敗（送り側はキューに残して再送する）、5xx は永続的な失敗（再送せず、差出人にエラーを返す）です。`220` は接続した直後のあいさつで、`QUIT` の返事は `221` です。`250` は「そのコマンドは成功」という一般の応答で、認証の成功は `235` です（[応答コードは 1 桁目で読む](#smtp)）。
:::
:::

:::q 2.10.1-10 single
`main.cf` に次の 3 行がある。この設定の説明として正しいものはどれか。

```text
smtpd_tls_cert_file = /etc/pki/tls/certs/postfix.pem
smtpd_tls_key_file = /etc/pki/tls/private/postfix.key
smtpd_tls_security_level = may
```
- [ ] TLS を使わないクライアントからのメールは、すべて断る
- [x] クライアントに STARTTLS を案内し、クライアントが使えば暗号化する。使わないクライアントからも受け取る
- [ ] Postfix がよそのサーバーへ送るときに、相手が対応していれば TLS を使う
- [ ] 接続した瞬間から TLS で話す（STARTTLS は使わない）
:::why
`smtpd_tls_security_level = may` は、サーバーとして STARTTLS を案内するが、必須にはしない設定です。TLS なしを断るのは `encrypt` です。よそへ送るとき（クライアント側）の設定は `smtp_tls_security_level` で、`smtpd_` ではありません。接続した瞬間から TLS にするのは、`master.cf` の smtps（ポート 465）に付ける `smtpd_tls_wrappermode=yes` です（[TLS の基本設定](#tls-auth)）。
:::

:::q 2.10.1-11 fill

:::q 2.10.1-13 single
Red Hat 系のディストリビューションに Postfix を入れて起動した。サーバー自身からは `localhost` のポート 25 に接続できるが、ほかの機械からは接続を拒否される。ファイアウォールはポート 25 を許している。`postconf -n` の出力の一部は次のとおりである。直すべき設定として最も適切なものはどれか。

```text

```
- [x] `inet_interfaces = all` にして、Postfix を起動し直す
- [ ] `mydestination` に `$mydomain` を足して、`postfix reload` を実行する
- [ ] `inet_protocols = ipv4` にして、`postfix reload` を実行する
- [ ] `newaliases` を実行する
:::why
`inet_interfaces = localhost` は、127.0.0.1（と ::1）でしか接続を待ちません。rockylinux:9 の既定がこの値でした。`all` にして、Postfix を止めて起動し直すと、すべてのアドレスで待ちます（`inet_interfaces` の変更は reload では反映されませんでした）。`mydestination` は接続のあとで宛先を判断する設定で、接続の拒否とは関係ありません。`inet_protocols` は IPv4 と IPv6 のどちらを使うかで、`all` のままで構いません。`newaliases` は別名の表を作り直すだけです（[main.cf](#main-cf)）。

- [ ] `SSLCertificateFile /etc/pki/dovecot/certs/dovecot.pem`
:::why
Dovecot では `ssl_cert = <パス` と書きます。`<` は「ファイルの中身を値にする」印で、忘れるとパスの文字列そのものを証明書として読もうとして、接続のときに `There is no valid PEM certificate` のエラーになりました。`ssl_certificate` という設定は Dovecot にはなく、`doveconf` が `Unknown setting` で止まります（nginx の設定の名前です）。`smtpd_tls_cert_file` は Postfix、`SSLCertificateFile` は Apache の設定です（[Dovecot の TLS](#dovecot-tls)）。
:::
:::

:::q 2.10.2-06 fill
Dovecot の設定のうち、既定値と違うものだけを表示して、設定のまちがいがないかを確かめたい。空欄に入るコマンド名を入力してください。

```text
# ____ -n
```
= doveconf
= doveadm config
:::why
`doveconf -n` は、既定値と違う設定だけを表示します。`conf.d/` に分かれた設定をまとめて見られ、書きまちがいがあればエラーで教えてくれます。`-a` はすべての設定、`-d` は既定値です。`doveadm config -n` でも同じ結果になります（[doveconf](#doveadm)）。

:::q 2.10.2-07 multi
`doveadm` のサブコマンドの説明として正しいものを 2 つ選択してください。
- [x] `doveadm reload` は、Dovecot に設定を読み直させる
- [x] `doveadm who` は、いま接続しているユーザーの一覧を表示する
- [ ] `doveadm kick alice` は、ユーザー alice のメールボックスを削除する
- [ ] `doveadm pw` は、システムのユーザーのログインパスワードを変更する
- [ ] `doveadm stop` は、接続しているユーザーを切らずに、設定だけを読み直す
:::why
`doveadm reload` は設定の再読み込み、`doveadm who` は接続中のユーザー・プロトコル・接続元の一覧です。`doveadm kick` は、そのユーザーの接続を切るだけです。`doveadm pw` は、パスワードのハッシュを作って表示するだけで、だれのパスワードも変えません。`doveadm stop` は Dovecot を止めます（[doveadm](#doveadm)）。
:::
:::

:::q 2.10.2-08 single
Dovecot で、POP3 だけを提供して IMAP は提供しないようにしたい。`/etc/dovecot/dovecot.conf` に書く設定として正しいものはどれか。
- [x] `protocols = pop3`
- [ ] `listen = pop3`
- [ ] `mail_location = pop3`
- [ ] `auth_mechanisms = pop3`
- [ ] `ssl = pop3`
:::why
提供するプロトコルは `protocols` に並べます。`protocols = pop3` にすると、待つポートは 110 と 995 だけになりました。`listen` は接続を待つアドレス（`*`、`::`）、`mail_location` はメールボックスの形式と場所、`auth_mechanisms` は認証の方式（`plain`、`login`）、`ssl` は `yes` / `no` / `required` です（[まず覚える設定](#dovecot)）。
:::
:::

:::q 2.10.2-09 multi
Dovecot の `disable_plaintext_auth = yes`（既定値）の説明として正しいものを 2 つ選択してください。
- [x] TLS で暗号化していない接続では、パスワードをそのまま送る認証（PLAIN、LOGIN）を断る
- [x] 同じ機械の中からの接続（127.0.0.1 など）は安全とみなされ、平文でも認証できる
- [ ] TLS で暗号化した接続でも、PLAIN の認証を使えなくする
- [ ] ポート 110 と 143 を閉じて、993 と 995 だけで接続を待つ
- [ ] メールボックスの中のメールを、暗号化して保存する
:::why
`disable_plaintext_auth = yes` は、暗号化していない接続で、平文のパスワードを送らせないための設定です。TLS の中なら PLAIN を使えます（ログにも `method=PLAIN, … TLS` と出ました）。ローカルからの接続は安全とみなされます。待つポートは `protocols` と `10-master.conf` の `inet_listener` で決まり、この設定では変わりません。保存するメールの暗号化とも関係ありません（[認証](#dovecot)）。
:::
:::

:::q 2.10.2-10 single
Dovecot のログに次の行があった。この行の説明として正しいものはどれか。

```text
Nov 16 21:20:59 imap-login: Info: Login: user=<alice>, method=PLAIN, rip=172.17.0.8, lip=172.17.0.2, mpid=6933, TLS, session=<PLKyWmtgeOqsEQAI>
```
- [ ] alice が POP3 でログインした。パスワードは暗号化されずにネットワークを流れた
- [x] alice が、172.17.0.8 の機械から IMAP でログインした。接続は TLS で暗号化されている
- [ ] alice が、172.17.0.2 の機械から IMAP でログインしようとして、認証に失敗した
- [ ] alice が SMTP 認証をして、メールを 1 通送った
:::why
`imap-login` は IMAP のログイン、`Login: user=<alice>` はログインの成功、`rip` は接続元（remote IP）、`lip` はサーバー側のアドレス（local IP）、`TLS` は暗号化された接続を表します。`method=PLAIN` は認証の方式で、TLS の中で送られているので、パスワードは平文ではネットワークを流れません。POP3 なら `pop3-login` と出ます。SMTP 認証の記録は、Postfix のログの `sasl_method=…, sasl_username=…` です（[Dovecot のログ](#doveadm)）。
:::
:::
