## この本について {#about}

この本は、**LinuC（リナック）レベル2** に合格するための学習書です。レベル1 の対策の [図解 LinuC](../../linuc/site/index.html) と、その前の [図解 Linux](../../linux/site/index.html) を読み終えた人を前提にしています。全部を覚えている必要はありません。前提になる所には、各章からリンクで戻れます。

レベル1 とレベル2 は、問われる立場が違います。

| | レベル1（図解 LinuC） | レベル2（この本） |
| --- | --- | --- |
| 立場 | 1 台の Linux を使い、管理する | サーバーを立て、ほかの機械にサービスを出す |
| 中心 | コマンドとオプション、ファイルの場所 | サーバーの**設定ファイル**、管理コマンド、障害の切り分け |
| 範囲 | 1 台の中（ファイル、プロセス、パッケージ、ネットワークの基本） | カーネル、ストレージ、仮想化とコンテナ、DNS・Web・メール・ファイル共有、セキュリティ、システムの設計 |
| 聞き方 | 「このコマンドは何をするか」 | 「この設定の説明として正しいものは」「空欄に入るディレクティブは」 |

レベル2 では、設定ファイルの抜粋を見せて問う問題が増えます。`named.conf` の `allow-transfer`、Apache の `<VirtualHost>`、`smb.conf` の `[homes]`、`sshd_config` の `PermitRootLogin` のように、**ディレクティブの名前と書き方**を正しく覚えることが大事です。この本は、設定ファイルを Docker の中で実際に動かし、検査コマンド（`named-checkconf`、`apachectl -t`、`nginx -t`、`testparm` など）を通したものを載せています。

:::note 問題はこのサイトのオリジナルです
練習問題と模擬試験は、出題範囲をもとにこのサイトが作ったものです。本番の問題を写したものではありません。形（選択肢の数、「2 つ選択してください」、入力する問題）は、本番に近づけてあります。
:::

## 試験の形 {#exam}

LinuC レベル2 に認定されるには、**201 試験と 202 試験の両方**に合格します。どちらから受けてもかまいません。

| 項目 | 内容 |
| --- | --- |
| 問題の数 | 1 回約 60 問 |
| 時間 | 90 分（そのうち 5 分は、試験の後のアンケート。解く時間は実質 85 分） |
| 形 | コンピュータで受ける（CBT）。ほとんどはマウスで選ぶ問題で、キーボードで入力する問題が少しある |
| 受験料 | 1 回 16,500 円（税込） |
| 受ける条件 | なし（レベル1 を持っていなくても受けられる） |
| 認定の条件 | 201 と 202 の両方に 5 年以内に合格し、**レベル1 の認定を持っている** |
| 合格点 | 公表されていない |

60 問を 85 分で解くので、1 問にかけられるのは 1 分 25 秒ほどです。設定ファイルを読む問題は時間がかかります。迷った問題に印を付けて先へ進み、最後に戻ります。

合格点は公表されていません。この本の模擬試験では、**80% 以上を 3 回続けて取ること**を目標にします。

:::warn 申し込む前に、公式のページを確かめる
受験料、試験の形、出題範囲は変わることがあります。上の表は、この本を書いたとき（2026 年 11 月）に [LinuC の公式サイト](https://linuc.org/linuc2/) で確かめたものです。申し込む前に、もう一度公式のページを見てください。
:::

## 合格メソッド：診断 → 学ぶ → 解く → 模試 {#method}

```fig graph 合格メソッドの 4 段階。模試で見つけた苦手の主題へ戻り、輪を回す
{
  col: 180, row: 92,
  nodes: [
    { id: 'diag', label: '1. 診断', sub: '模試を 1 回', x: 0, y: 0, kind: 'plain', mono: false },
    { id: 'learn', label: '2. 学ぶ', sub: '苦手の主題の章を読む', x: 1, y: 0, kind: 'stack', mono: false },
    { id: 'drill', label: '3. 解く', sub: '章末の問題と復習', x: 2, y: 0, kind: 'crate', mono: false },
    { id: 'mock', label: '4. 模試', sub: '80% を 3 回', x: 3, y: 0, kind: 'accent', mono: false },
  ],
  edges: [
    { from: 'diag', to: 'learn' }, { from: 'learn', to: 'drill' }, { from: 'drill', to: 'mock' },
    { from: 'mock', to: 'learn', label: '70% 未満の主題へ', curve: 1, style: 'muted' },
  ],
}
```

1. **診断**：最初に[模擬試験](mock.html)を 1 回受けます。点数は気にしません。採点の後に出る「主題ごとの正答率」を見て、低い主題を 2〜3 個選びます
2. **学ぶ**：選んだ主題の章を読みます。設定ファイルは、ディレクティブの表を声に出して読むくらいに繰り返します
3. **解く**：章の最後の練習問題を解きます。まちがえた問題は記録され、[苦手を解く](review.html)のページに集まります
4. **模試**：もう一度模擬試験を受けます。70% に届かない主題が残っていたら、2 に戻ります。80% 以上を 3 回続けて取れたら、本番を予約します

:::tip サーバーは「設定ファイル・検査・再読み込み」の 3 点で覚える
202 のサーバーは種類が多いので、どれも同じ形で整理します。たとえば BIND なら、設定ファイルは `named.conf`、検査は `named-checkconf` と `named-checkzone`、再読み込みは `rndc reload` です。Apache なら `httpd.conf`（Debian 系は `apache2.conf`）、`apachectl -t`、`apachectl graceful` です。各章の表は、この 3 点をそろえてあります。
:::

## 8 週間の計画 {#plan}

1 日 1 時間ほどで、201 と 202 を続けて受ける計画の例です。

| 週 | やること | 目安 |
| --- | --- | --- |
| 1 週目 | 序章、201 の模試で診断。2.01（起動とカーネル） | レベル1 の起動と systemd を復習しながら |
| 2 週目 | 2.02（ファイルシステムとストレージ）、2.03（ネットワーク構成） | コマンドとオプションの表 |
| 3 週目 | 2.04（保守と運用管理）。Ansible は Playbook を読めるまで | 重要度 16 でいちばん重い |
| 4 週目 | 2.05・2.06（仮想化とコンテナ）、苦手の復習、201 の模試 | 80% を 3 回で 201 を予約 |
| 5 週目 | 202 の模試で診断。2.07（DHCP・PAM・LDAP）、2.08（DNS） | ゾーンファイルは手で書いてみる |
| 6 週目 | 2.09（Web とプロキシ）、2.10（メール） | Apache と nginx の書き方の違い |
| 7 週目 | 2.11（Samba・NFS）、2.12（セキュリティ） | iptables のチェインの図 |
| 8 週目 | 2.13（システムアーキテクチャ）、苦手の復習、202 の模試 | 稼働率の計算を手で。80% を 3 回で 202 を予約 |

2 つの合格は、5 年以内であれば認定されます。レベル1 の認定がまだなら、先にそちらを取ってください（受験の順番は自由ですが、レベル2 の認定はレベル1 の認定の後です）。

## 練習問題の使い方 {#how}

練習問題は 3 つの形です。

- **1 つ選ぶ**：ラジオボタン
- **複数選ぶ**：チェックボックス。本番と同じく「2 つ選択してください」のように、選ぶ数を問題文に書きます
- **入力する**：コマンド、ディレクティブ、ファイルの名前をキーボードで入力します。**綴りが完全に合っていないと不正解**です

試しに解いてみてください。

:::q 2.12.2-91 single
OpenSSH サーバーで、root ユーザーが SSH で直接ログインすることを禁止したい。`/etc/ssh/sshd_config` に書く設定として正しいものはどれか。
- [ ] `AllowRoot no`
- [x] `PermitRootLogin no`
- [ ] `RootLogin deny`
- [ ] `DenyUsers root` だけが方法で、`PermitRootLogin` というディレクティブはない
:::why
`PermitRootLogin no` で、root の SSH ログインを禁止します。`prohibit-password` にすると、パスワードでは入れず、公開鍵でだけ入れます（12 章で扱います）。

- `AllowRoot`、`RootLogin` というディレクティブはありません。`sshd -t` で検査すると、知らないディレクティブとしてエラーになります
- `DenyUsers root` でも root を拒否できますが、`PermitRootLogin` はあります。「〜だけが方法」という説明はまちがいです
:::
:::

:::q 2.08.2-91 multi
DNS のゾーンファイルで、名前から IP アドレスを引くためのリソースレコードを 2 つ選択してください。
- [x] `A`
- [x] `AAAA`
- [ ] `PTR`
- [ ] `MX`
- [ ] `CNAME`
:::why
`A` は名前から IPv4 アドレス、`AAAA` は名前から IPv6 アドレスを引くレコードです。

- `PTR` は逆で、IP アドレスから名前を引く逆引きのレコードです
- `MX` は、そのドメインのメールを受け取るサーバーの名前を示します
- `CNAME` は、名前に別名を付けるレコードで、指す先は IP アドレスではなく別の名前です
:::
:::

:::q 2.02.3-91 fill
LVM で、パーティション `/dev/sdb1` を物理ボリューム（PV）として初期化する。空欄に入るコマンドを入力してください。

```text
# ____ /dev/sdb1
```
= pvcreate
:::why
物理ボリュームを作るのは `pvcreate` です。LVM のコマンドは、何を扱うかで頭が決まります。物理ボリュームは `pv`、ボリュームグループは `vg`、論理ボリュームは `lv` で始まり、作るのは `create`（`pvcreate`、`vgcreate`、`lvcreate`）です（[図解 LinuC 5 章](../../linuc/site/ch05.html#lvm)）。
:::
:::

答えると、正解と解説が出ます。解いた結果はこのブラウザに記録され、ページを開き直すと「前回：正解」「前回：不正解」の印が付きます。

:::key まとめ
- LinuC レベル2 は 201 と 202 の 2 つの試験。1 回約 60 問・90 分。認定にはレベル1 の認定も要る。合格点は公表されていないので、模試で 80% を目指す
- 重要度の合計は各試験 60。重要度はだいたい出る問題の数
- 201 は「保守と運用管理」と「起動とカーネル」が重い。202 は「セキュリティ」と「Web とプロキシ」が重い
- 202 のサーバーは、設定ファイル・検査・再読み込みの 3 点で整理して覚える
- 進め方は、診断 → 学ぶ → 解く → 模試の輪。苦手の主題に戻って回す
:::
