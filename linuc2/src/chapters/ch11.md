どちらも「サーバーのディレクトリを、ネットワークの向こうの機械から使えるようにする」サービスです。相手が Windows なら Samba（SMB という決まり）、Linux や UNIX なら NFS を使うのが基本です。

この章のコマンドの出力は、Docker の debian:12（Samba 4.17、nfs-utils 2.6）と rockylinux:9 で実際に動かしたものです。小さな Linux にはサーバーがないので、実行できる例はありません。

**Samba**（サンバ）は、Windows のファイル共有の決まりである **SMB**（Server Message Block。古い呼び名は CIFS）を Linux で話すソフトウェアです。Linux のディレクトリを Windows から「共有フォルダ」として使えます。

Samba は、役目の違うデーモンに分かれています。

| デーモン | 役目 | ポート |
| --- | --- | --- |
| **smbd** | ファイル共有、プリンタ共有、ユーザーの認証 | **TCP 445**（SMB を直接）、**TCP 139**（NetBIOS のセッション） |
| **nmbd** | NetBIOS の名前解決（コンピュータ名 → IP アドレス）、ブラウジング（ネットワークの一覧）、WINS サーバー | **UDP 137**（名前）、**UDP 138**（データグラム） |
| **winbindd** | Windows のドメイン（AD）のユーザーとグループを、Linux のユーザー（UID・GID）として見せる | （ドメインコントローラへ問い合わせる側） |
| **samba** | Active Directory の**ドメインコントローラ**（AD DC）として動くときの親プロセス | 上のほかに DNS、Kerberos、LDAP |

ポートは、smbd と nmbd を起動して `ss` で確かめたものです（`ss` は [図解 LinuC 7.10](../../linuc/site/ch07.html#ss)）。

```console
# ss -tulnp | grep -E "smbd|nmbd"
udp   UNCONN 0      0             0.0.0.0:137       0.0.0.0:*    users:(("nmbd",pid=5453,fd=14))
udp   UNCONN 0      0             0.0.0.0:138       0.0.0.0:*    users:(("nmbd",pid=5453,fd=15))
tcp   LISTEN 0      50            0.0.0.0:139       0.0.0.0:*    users:(("smbd",pid=5449,fd=32))
tcp   LISTEN 0      50            0.0.0.0:445       0.0.0.0:*    users:(("smbd",pid=5449,fd=31))
```

:::warn 試験の注意：137・138 は UDP で nmbd、139・445 は TCP で smbd
「ファイル共有そのもの」は smbd の TCP 445 と 139 です。「コンピュータ名を引く」は nmbd の UDP 137 です。ファイアウォールで Samba を通すときは、この 4 つを開けます。`/etc/services` での名前は `netbios-ns`（137）、`netbios-dgm`（138）、`netbios-ssn`（139）、`microsoft-ds`（445）です。
:::

### ファイルの場所とサービスの名前

| 場所 | 中身 |
| --- | --- |
| **`/etc/samba/smb.conf`** | Samba の設定ファイル（すべてのデーモンが読む） |
| `/etc/samba/lmhosts` | NetBIOS 名と IP アドレスの対応表（`/etc/hosts` の NetBIOS 版） |
| `/etc/samba/smbusers` など | Windows のユーザー名と Linux のユーザー名の対応表（名前は `username map` で決める） |
| **`/var/log/samba/`** | ログ。`log.smbd`、`log.nmbd`、クライアントごとの `log.クライアント名` |
| `/var/lib/samba/` | Samba のデータベース（`.tdb`）。Debian 系では `private/passdb.tdb` に Samba のパスワード |

サービスの名前は、ディストリビューションで違います（`systemctl` は [図解 Linux 17.5](../../linux/site/ch17.html#systemctl)）。

| | Debian 系 | Red Hat 系 |
| --- | --- | --- |
| パッケージ | `samba`、`smbclient`、`winbind` | `samba`、`samba-client`、`samba-winbind` |
| smbd の unit | `smbd.service` | `smb.service` |
| nmbd の unit | `nmbd.service` | `nmb.service` |
| winbindd の unit | `winbind.service` | `winbind.service` |
| AD DC（samba）の unit | `samba-ad-dc.service` | （標準のパッケージは AD DC に対応していない） |

```console
# systemctl enable --now smb nmb          # Red Hat 系
# systemctl enable --now smbd nmbd        # Debian 系
```

:::note AD DC のときは samba だけを起動する
Samba を Active Directory のドメインコントローラにするときは、`smbd` や `nmbd` を個別に起動しません。**`samba`** という 1 つのデーモンを起動すると、それが必要な子プロセス（smbd や winbindd の役目を含む）を自分で起こします。ファイルサーバーやドメインのメンバーのときは、`smbd`、`nmbd`、（必要なら）`winbindd` を起動します。
:::

## smb.conf はどう書くか：[global] と共有のセクション {#smb-conf}

```fig tree smb.conf は [名前] で始まるセクションの並び。[global] は全体の設定、[homes]・[printers]・[print$] は特別な名前、それ以外は 1 つの共有
{
  root: { label: '/etc/samba/smb.conf', kind: 'accent', children: [
    { label: '[global]', note: 'サーバー全体の設定と、共有の既定値', children: [
      { label: 'workgroup = WORKGROUP', note: 'ワークグループ名・ドメイン名' },
      { label: 'security = user', note: '認証の方式' },
      { label: 'log file = /var/log/samba/log.%m', note: 'ログの場所' },
    ] },
    { label: '[homes]', note: '特別：各ユーザーのホームディレクトリを、ユーザー名の共有として見せる' },
    { label: '[printers]', note: '特別：システムのプリンタをまとめて共有する' },
    { label: '[print$]', note: '特別：プリンタドライバを配る共有' },
    { label: '[share]', note: 'ふつうの共有。\\\\サーバー\\share で見える', children: [
      { label: 'path = /srv/share', note: '共有するディレクトリ' },
      { label: 'read only = no', note: '書き込めるか' },
    ] },
  ] },
}
```

smb.conf は、`[名前]` で始まる**セクション**と、その下の `パラメータ = 値` の行でできています。`#` か `;` で始まる行はコメントです。パラメータ名は大文字と小文字を区別せず、名前の中の空白も無視されます。

- **`[global]`**：サーバー全体の設定です。共有ごとのパラメータをここに書くと、すべての共有の**既定値**になります
- **`[homes]`、`[printers]`、`[print$]`**：特別な名前のセクションです（下で説明します）
- **それ以外の名前**：その名前の共有を 1 つ作ります。`[share]` なら `\\サーバー\share` です

実際に動かした設定です。

```text
[global]
   workgroup = WORKGROUP
   server string = File Server
   netbios name = FS1
   security = user
   passdb backend = tdbsam
   map to guest = Bad User
   log file = /var/log/samba/log.%m
   max log size = 1000
   username map = /etc/samba/smbusers
   hosts allow = 127. 192.168.1.

[homes]
   comment = Home Directories
   browseable = no
   read only = no
   valid users = %S

[share]
   comment = Sales
   path = /srv/share
   valid users = @sales
   write list = alice
   read only = yes
   create mask = 0660
   directory mask = 0770
   force group = sales

[pub]
   path = /srv/pub
   guest ok = yes
   read only = yes
```

### [global] の主なパラメータ

| パラメータ | 意味 | 既定値 |
| --- | --- | --- |
| `workgroup` | ワークグループ名、またはドメインの NetBIOS 名 | `WORKGROUP` |
| `netbios name` | このサーバーの NetBIOS 名 | ホスト名 |
| `server string` | 一覧に出る説明の文字列 | |
| **`security`** | 認証の方式。`user`（Samba 自身のアカウントで認証）、`ads`（AD のメンバーとして Kerberos で認証）、`domain`（NT ドメインのメンバー） | `user` |
| `realm` | AD の Kerberos レルム（`security = ads` のとき。例：`EXAMPLE.COM`） | |
| **`passdb backend`** | Samba のアカウントをしまう場所。`tdbsam`（TDB のデータベース）、`smbpasswd`（テキストのファイル）、`ldapsam`（LDAP） | `tdbsam` |
| `map to guest` | 認証に失敗した人をゲストにするか。`Never`、`Bad User`（**知らないユーザー名**ならゲスト）、`Bad Password` | `Never` |
| `guest account` | ゲストを Linux のどのユーザーとして扱うか | `nobody` |
| `username map` | Windows のユーザー名 → Linux のユーザー名の対応表のファイル | なし |
| `log file` | ログのファイル名。`%m` を入れるとクライアントごとに分かれる | |
| `max log size` | ログの大きさの上限（**KB**）。超えると `.old` に回す | |
| `log level` | ログの細かさ（0〜10。大きいほど細かい） | `0` |
| `hosts allow` / `hosts deny` | つないでよい / いけないクライアント（共有ごとにも書ける） | 制限なし |
| `wins support` | nmbd を WINS サーバーにするか | `no` |
| `wins server` | 使う WINS サーバーの番地（クライアントになる） | |

:::warn 試験の注意：security = share と server はもうない
古い Samba には `security = share`（共有ごとのパスワード）と `security = server` がありましたが、Samba 4 でなくなりました。いま選べるのは `user`、`ads`、`domain` です（`auto` は server role に従います）。「AD のドメインに参加したメンバーサーバー」は **`security = ads`** で、`realm` も必要です。
:::

### 共有のセクションの主なパラメータ

| パラメータ | 意味 | 既定値 |
| --- | --- | --- |
| **`path`** | 共有するディレクトリ | |
| `comment` | 共有の説明 | |
| **`read only`** | 読み取り専用にするか | **`yes`** |
| `writable`（`writeable`、`write ok`） | 書き込めるか。**`read only` の反対**（`writable = yes` は `read only = no` と同じ） | `no` |
| `browseable`（`browsable`） | 共有の一覧に出すか | `yes` |
| `guest ok`（`public`） | パスワードなし（ゲスト）での接続を許すか | `no` |
| `valid users` / `invalid users` | つないでよい / いけないユーザー。`@グループ名` でグループ | 全員 |
| `write list` / `read list` | `read only` に関係なく、書ける / 読むだけにするユーザー | なし |
| `create mask` | 新しい**ファイル**に付く権限の上限 | `0744` |
| `directory mask` | 新しい**ディレクトリ**に付く権限の上限 | `0755` |
| `force user` / `force group` | この共有での操作を、すべてこのユーザー / グループとして行う | なし |
| `printable` | プリンタの共有にするか | `no` |

既定値は `testparm -sv` で確かめたものです。

```console
# testparm -sv 2>/dev/null | grep -E "^\s*(read only|create mask|directory mask|guest ok|browseable|guest account) ="
	guest account = nobody
	browseable = Yes
	create mask = 0744
	directory mask = 0755
	guest ok = No
	read only = Yes
```

:::warn 試験の注意：共有は、何も書かなければ読み取り専用
`read only` の既定値は `yes` です。書き込める共有にするには `read only = no` か `writable = yes` を書きます。「`writable = no`」と「`read only = yes`」は同じ意味です。向きが反対の 2 つの名前を取り違えないでください。
:::

### 特別なセクションと変数

**`[homes]`** は、接続してきたユーザーのホームディレクトリを、そのユーザー名の共有として見せます。alice が接続すると `\\FS1\alice` が現れ、中身は `/home/alice` です。`browseable = no` にすると、一覧には「homes」という名前は出ず、自分の名前の共有だけが出ます。

```console
$ smbclient -L localhost -U alice%pass1
	Sharename       Type      Comment
	---------       ----      -------
	share           Disk      Sales
	pub             Disk      
	IPC$            IPC       IPC Service (File Server)
	alice           Disk      Home Directories
```

**`[printers]`** はシステムのプリンタをまとめて共有し、**`[print$]`** は Windows 用のプリンタドライバを配る共有です。`IPC$` は Samba が自動で作る、通信のための特別な共有です。

値の中の `%` で始まる文字は**変数**で、接続のたびに置き換えられます。

| 変数 | 置き換わるもの |
| --- | --- |
| `%U` | 接続してきたユーザー名（クライアントが名乗った名前） |
| `%u` | その共有を使っている Linux のユーザー名 |
| `%S` | 共有の名前（`[homes]` ではユーザー名になる） |
| `%H` | `%u` のホームディレクトリ |
| `%m` | クライアントの NetBIOS 名 |
| `%I` | クライアントの IP アドレス |
| `%L` | サーバーの NetBIOS 名 |
| `%D` | ユーザーのドメイン名（ワークグループ名） |

`[homes]` の `valid users = %S` は「共有の名前と同じユーザーだけ」、つまり「自分のホームだけ」の意味です。`log file = /var/log/samba/log.%m` は、クライアントごとに別のログになります。

### testparm：smb.conf を検査する

**`testparm`** は smb.conf の書き方を検査して、読み込んだ結果を表示します。smb.conf を書き換えたら、まず testparm です。

```console
# testparm -s
Load smb config files from /etc/samba/smb.conf
Loaded services file OK.

Server role: ROLE_STANDALONE

# Global parameters
[global]
	log file = /var/log/samba/log.%m
	map to guest = Bad User
	max log size = 1000
	netbios name = FS1
	security = USER
	...
[share]
	comment = Sales
	create mask = 0660
	directory mask = 0770
	force group = sales
	path = /srv/share
	valid users = @sales
	write list = alice
```

表示されるのは**既定値と違うパラメータだけ**です。`[share]` に書いた `read only = yes` は既定値と同じなので、出てきません。

| 書き方 | すること |
| --- | --- |
| `testparm` | `/etc/samba/smb.conf` を検査し、Enter を押すと設定を表示する |
| `testparm -s` | Enter を待たずに表示する（`--suppress-prompt`） |
| `testparm -v` | 既定値のままのパラメータも全部表示する（`--verbose`） |
| `testparm ファイル` | 別の設定ファイルを検査する |
| `testparm ファイル ホスト名 IP アドレス` | そのクライアントが `hosts allow` / `hosts deny` で許されるかを調べる |

綴りを間違えたパラメータは、エラーではなく**無視**されます。testparm はそれを教えてくれます。

```console
# testparm -s /tmp/bad.conf
Load smb config files from /tmp/bad.conf
Unknown parameter encountered: "workgrup"
Ignoring unknown parameter "workgrup"
Loaded services file OK.
```

## 共有を使えるのはだれか：hosts allow・valid users・write list・Linux の権限 {#share-access}

```fig graph 共有への書き込みは 4 つの関門を順に通る。Samba の設定で許しても、最後に Linux のファイルの権限（と ACL）で止まることがある
{
  col: 200, row: 100,
  nodes: [
    { id: 'c', label: 'クライアント', x: 0, y: 0, kind: 'ext', mono: false },
    { id: 'h', label: '1. hosts allow / deny', sub: 'その番地はよいか', x: 1, y: 0 },
    { id: 'a', label: '2. 認証', sub: 'Samba のアカウントとパスワード', x: 2, y: 0, mono: false },
    { id: 'v', label: '3. valid users・read only', sub: 'この共有を使えるか、書けるか', x: 2, y: 1 },
    { id: 'p', label: '4. Linux の権限・ACL', sub: 'そのユーザーとしてファイルを開く', x: 1, y: 1, kind: 'accent', mono: false },
    { id: 'f', label: '/srv/share のファイル', x: 0, y: 1, kind: 'stack', mono: false },
  ],
  edges: [
    { from: 'c', to: 'h' },
    { from: 'h', to: 'a' },
    { from: 'a', to: 'v' },
    { from: 'v', to: 'p' },
    { from: 'p', to: 'f', style: 'accent' },
  ],
}
```

共有へのアクセスは、Samba の設定と Linux の権限の**両方**を通ったときだけ許されます。

1. **`hosts allow` / `hosts deny`**：クライアントの番地で絞ります。`hosts allow = 127. 192.168.1.` は「127. で始まる番地と 192.168.1. で始まる番地」です。`192.168.1.0/24` や `192.168.1.0/255.255.255.0` とも書けます。両方に当てはまるときは **`hosts allow` が勝ちます**
2. **認証**：`security = user` なら、Samba のアカウント（次の節）のユーザー名とパスワードで確かめます
3. **共有の設定**：`valid users` にいるか。書き込みは `read only = no` か、`write list` にいるか
4. **Linux の権限**：smbd は、認証したユーザーに対応する Linux のユーザーになって、ファイルを開きます。ディレクトリの権限（[図解 Linux 4.5](../../linux/site/ch04.html#dir)）で書けなければ、Samba が許していても書けません

上の設定の `[share]` で確かめます。`/srv/share` は alice が持ち主、グループは sales、権限は 2770 です。alice は sales の一員で、bob は違います。

```console
$ smbclient //localhost/share -U alice%pass1 -c 'put up.txt; ls'
putting file up.txt as \up.txt (60000.0 kb/s) (average inf kb/s)
  up.txt                              A        6  Mon Nov 16 21:19:01 2026
$ smbclient //localhost/share -U bob%pass2 -c 'ls'
tree connect failed: NT_STATUS_ACCESS_DENIED
# ls -l /srv/share
-rw-rw---- 1 alice sales 6 Nov 16 21:19 up.txt
```

- bob は `valid users = @sales` に入らないので、共有につなぐ（tree connect）ところで断られます
- alice は `read only = yes` でも、`write list` にいるので書けます
- できたファイルの権限は `create mask = 0660` で `rw-rw----`、グループは `force group = sales` です

ゲスト用の `[pub]` は `guest ok = yes` です。`map to guest = Bad User` があるので、Samba に登録のない名前で来た人は、ゲスト（`guest account` の `nobody`）として扱われます。`read only = yes` なので、書こうとすると断られます。

```console
$ smbclient //localhost/pub -N -c 'get readme.txt; put up.txt'
getting file \readme.txt of size 6 as readme.txt
NT_STATUS_ACCESS_DENIED opening remote file \up.txt
```

:::tip 「つながるのに書けない」ときの切り分け
`tree connect failed` なら、`valid users`、`hosts allow`、認証のどれかです。つながったあとで `NT_STATUS_ACCESS_DENIED` が出るなら、`read only` と `write list`、それでもだめなら Linux 側の `ls -ld` と `getfacl` を見ます。Samba の設定は、Linux の権限より広い権利を与えることはできません。
:::

## Samba のユーザーはどこにいるか：smbpasswd・pdbedit・username map {#samba-users}

```fig graph Windows のユーザー名は、username map で Linux のユーザー名に直され、Samba のアカウント（パスワード）で認証され、Linux のユーザー（UID）としてファイルを開く
{
  col: 215, row: 100,

    { id: 'w', label: '"Alice Smith"', sub: 'Windows が名乗る名前', x: 0, y: 0, kind: 'ext' },

    { id: 's', label: 'Samba のアカウント alice', sub: 'passdb.tdb。SMB 用のパスワード', x: 2, y: 0, kind: 'accent', mono: false },
    { id: 'u', label: 'Linux のユーザー alice', sub: '/etc/passwd。UID 1000', x: 2, y: 1, kind: 'stack', mono: false },
  ],
  edges: [

  ],

```

`security = user` の Samba では、ユーザーは **2 か所**に登録されている必要があります。

- **Linux のユーザー**（`/etc/passwd`。[図解 LinuC 8.2](../../linuc/site/ch08.html#account-files)）：ファイルの持ち主や権限の判定に使います
- **Samba のアカウント**（`passdb backend` の中）：SMB の認証に使うパスワードを持ちます。`/etc/shadow` のパスワードとは別物です

SMB の認証は、Linux の `/etc/shadow` のハッシュでは確かめられない方式です。そのため Samba は、自分用のパスワードを別に持ちます。

### smbpasswd と pdbedit

**`smbpasswd`** は Samba のアカウントのパスワードを変えるコマンドです。root が使うと、アカウントの追加や削除もできます。

```console
# useradd -m alice                 # 先に Linux のユーザーを作る
# smbpasswd -a alice               # Samba のアカウントを追加（パスワードを 2 回聞かれる）
New SMB password:
Retype new SMB password:
Added user alice.
# smbpasswd -a nouser              # Linux にいないユーザーは追加できない
Failed to add entry for user nouser.
```

| オプション | すること |
| --- | --- |
| （なし） | 一般ユーザー：自分の Samba のパスワードを変える。root：`smbpasswd ユーザー名` でその人のパスワードを変える |
| **`-a`** | アカウントを**追加**する（add。Linux のユーザーが先に必要） |
| **`-x`** | アカウントを**削除**する |
| **`-d`** | アカウントを**無効**にする（disable） |
| **`-e`** | アカウントを**有効**に戻す（enable） |
| `-n` | パスワードなしにする |
| `-r ホスト` | 別のサーバーの上のパスワードを変える |

**`pdbedit`** は、Samba のアカウントのデータベースを直接扱うコマンドです。一覧を見るときに使います。

```console
# pdbedit -L
alice:1000:
bob:1001:
# smbpasswd -d bob
Disabled user bob.
# pdbedit -L -w
alice:1000:XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX:8D7A851DDE3E7BED903A41D686CD33BE:[U          ]
bob:1001:XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX:9CB25B4C2C6BCB8E6FE9384B74ED2B34:[DU         ]:
```

`pdbedit -L` は一覧、`-v` を足すと詳しく、`-a ユーザー` で追加、`-x ユーザー` で削除です。`-w` は古い smbpasswd ファイルの形で出します。`[DU ]` の `D` は無効（disabled）の印です。

:::warn 試験の注意：smbpasswd は 2 つある
`smbpasswd` は**コマンド**の名前であり、`passdb backend = smbpasswd` のときにアカウントをしまう**ファイル**（`/etc/samba/smbpasswd`）の名前でもあります。いまの既定は `tdbsam` で、アカウントは `passdb.tdb` に入ります。どちらの場合も、追加するコマンドは `smbpasswd -a`（または `pdbedit -a`）です。`useradd` や `passwd` では Samba のアカウントはできません。
:::

### username map：Windows の名前を Linux の名前に直す

Windows のユーザー名は「Alice Smith」のように空白を含んだり、Linux の名前と違ったりします。**`username map`** で指定したファイルに、対応を書きます。

```text
# /etc/samba/smbusers
# Linux のユーザー名 = Windows のユーザー名（空白で区切って何個でも）
root = administrator admin
alice = "Alice Smith" asmith
nobody = guest pcguest smbguest
```

書式は **`Linux の名前 = Windows の名前 …`** です。左が Linux、右が Windows です。空白を含む名前は `"` で囲みます。smb.conf の `[global]` に `username map = /etc/samba/smbusers` と書くと有効になります。

```console
$ smbclient //localhost/share -U asmith%pass1 -c 'ls'
  up.txt                              A        6  Mon Nov 16 21:19:01 2026
```

`asmith` という Samba のアカウントはありませんが、対応表で alice に直されて、alice のパスワードで認証されました。

## 動いている Samba を調べる：smbclient・smbstatus・smbcontrol・nmblookup・net {#samba-tools}

名前の似たコマンドが多いので、まず役目を並べます。

| コマンド | 役目 | 向き |
| --- | --- | --- |
| **`smbclient`** | 共有につないで、ファイルを出し入れする（ftp のような対話式） | クライアント |
| **`smbstatus`** | いま**だれが、どの共有に**つないでいるか、ロックされたファイルを表示する | サーバーの上で |
| **`smbcontrol`** | 動いている smbd・nmbd・winbindd に**メッセージを送る**（設定の再読み込み、ログレベルの変更） | サーバーの上で |
| **`nmblookup`** | NetBIOS 名を IP アドレスに引く（NetBIOS 版の `host`） | クライアント |
| **`net`** | Windows の `net` コマンドに似た管理ツール。ドメインへの参加（`net ads join`）など | 両方 |
| `testparm` | smb.conf を検査する | サーバーの上で |
| `smbpasswd`・`pdbedit` | Samba のアカウントを管理する | サーバーの上で |
| `samba-tool` | AD DC としての Samba を管理する（次の節） | サーバーの上で |

### smbclient

```console
$ smbclient -L fs1 -U alice              # fs1 の共有の一覧（パスワードを聞かれる）
$ smbclient -L fs1 -N                    # パスワードなし（ゲスト）で一覧
$ smbclient //fs1/share -U alice         # 共有につなぐ。smb: \> のプロンプトになる
smb: \> ls
smb: \> get report.txt
smb: \> put memo.txt
smb: \> quit
$ smbclient //fs1/share -U alice%pass1 -c 'ls; get report.txt'
```

| 書き方 | 意味 |
| --- | --- |
| `//サーバー/共有` | つなぐ共有（スラッシュ 2 つで始める。`\\\\サーバー\\共有` でもよいがシェルのエスケープが要る） |
| **`-L ホスト`** | そのホストの共有の**一覧**を出す（`--list`） |
| **`-U ユーザー[%パスワード]`** | 接続するユーザー名（`--user`）。`%` の後ろにパスワードを続けられる |
| **`-N`** | パスワードを聞かない（`--no-pass`） |
| `-c 'コマンド; …'` | 対話せずに、`;` で区切ったコマンドを実行する |
| `-I 番地` | 名前を引かずに、この IP アドレスへつなぐ |
| `-W ワークグループ` | ワークグループ（ドメイン）名 |
| `-m プロトコル` | 使うプロトコルの上限（例：`SMB3`） |

プロンプトの中のコマンドは ftp と同じ形です。`ls`、`cd`、`lcd`（手元のディレクトリを変える）、`get`、`put`、`mget`、`mput`、`mkdir`、`rm`、`quit` を覚えます。

:::note Linux に SMB の共有をマウントするには
`smbclient` はファイルを出し入れするだけです。共有をディレクトリの木につなぐには、cifs-utils パッケージの `mount -t cifs //fs1/share /mnt/share -o username=alice` を使います（[図解 LinuC 5.11](../../linuc/site/ch05.html#mount)）。`/etc/fstab` に書くときは、パスワードを別のファイルに置いて `credentials=ファイル` で指します。
:::

### smbstatus

```console
# smbstatus

Samba version 4.17.12-Debian
PID     Username     Group        Machine                                   Protocol Version  Encryption           Signing              
----------------------------------------------------------------------------------------------------------------------------------------
5461    alice        alice        127.0.0.1 (ipv4:127.0.0.1:51386)          SMB3_11           -                    partial(AES-128-GMAC)

Service      pid     Machine       Connected at                     Encryption   Signing     
---------------------------------------------------------------------------------------------
share        5461    127.0.0.1     Mon Nov 16 21:20:03 2026 UTC     -            -

```

3 つの部分に分かれます。上が**接続しているユーザー**（プロセス）、中が**使われている共有**、下が**ロックされているファイル**です。

| オプション | 表示するもの |
| --- | --- |
| （なし） | 3 つ全部 |
| `-b` | 短く（`--brief`。接続しているユーザーだけ） |
| `-p` | プロセスの一覧だけ（`--processes`） |
| `-S` | 共有の一覧だけ（`--shares`） |
| `-L` | ロックだけ（`--locks`） |
| `-u ユーザー` | そのユーザーの分だけ（`--user`） |

### smbcontrol

**`smbcontrol 宛先 メッセージ [引数]`** の形です。宛先は `smbd`、`nmbd`、`winbindd`、`all`（全部）、またはプロセス ID です。

```console
# smbcontrol smbd ping
PONG from pid 5449
# smbcontrol all reload-config            # smb.conf を読み直させる
# smbcontrol smbd debuglevel              # いまのログレベルを見る
PID 5449: all:1 tdb:1 printdrivers:1 ...
# smbcontrol smbd debug 3                 # 止めずにログレベルを 3 にする
# smbcontrol smbd close-share share       # 共有 share の接続を切る
# smbcontrol smbd shutdown                # デーモンを止める
```

| メッセージ | すること |
| --- | --- |
| **`reload-config`** | smb.conf を読み直す |
| `debug レベル` | ログレベルを変える |
| `debuglevel` | いまのログレベルを表示する |
| `ping` | 生きているか確かめる（PONG が返る） |
| `close-share 共有名` | その共有への接続を切る |
| `shutdown` | デーモンを止める |

smb.conf を書き換えたあとの流れは、`testparm` で検査 → `smbcontrol all reload-config`（または `systemctl reload`）です。smbd は smb.conf の変更を自分でも定期的に確かめますが、すぐ反映したいときは reload-config を送ります。

### nmblookup と net

**`nmblookup`** は、NetBIOS 名を IP アドレスに引きます。答えるのは相手の nmbd（UDP 137）です。

```console
$ nmblookup FS1
172.17.0.12 FS1<00>
$ nmblookup -S FS1                       # 名前を引いて、その機械が持つ名前の一覧（ノードステータス）も出す
Looking up status of 172.17.0.12
	FS1             <00> -         B <ACTIVE> 
	FS1             <03> -         B <ACTIVE> 
	FS1             <20> -         B <ACTIVE> 
	WORKGROUP       <00> - <GROUP> B <ACTIVE> 
	WORKGROUP       <1e> - <GROUP> B <ACTIVE> 
$ nmblookup -A 172.17.0.12               # IP アドレスからノードステータスを引く
```

| オプション | 意味 |
| --- | --- |
| `-S` | 名前を引いたあと、ノードステータス（その機械の NetBIOS 名の一覧）も出す（`--status`） |
| `-A` | 引数を IP アドレスとして扱い、ノードステータスを出す（`--lookup-by-ip`） |
| `-M` | マスターブラウザを探す（`--master-browser`） |
| `-B 番地` | ブロードキャストの宛先を指定する |
| `-U 番地` | その番地（WINS サーバーなど）にユニキャストで聞く |

**`net`** は、Windows の `net` コマンドに似た、いろいろな管理をまとめたツールです。`net 種類 命令` の形で、種類が相手を表します。

| 書き方 | すること |
| --- | --- |
| **`net ads join -U Administrator`** | この機械を **AD のドメインに参加**させる（`security = ads`） |
| `net ads testjoin` | 参加が正しくできているか確かめる |
| `net ads info` | AD のサーバーの情報を表示する |
| `net ads leave` | ドメインから抜ける |
| `net rpc join`、`net rpc user` | 古い NT ドメインの方式（RPC）での参加、ユーザーの管理 |
| `net status sessions` / `net status shares` | 接続と共有の状態（smbstatus に近い） |
| `net share -S ホスト -U ユーザー` | そのホストの共有の一覧 |
| `net usershare add …` | 一般ユーザーが自分で作る共有（ユーザー共有） |
| `net getlocalsid` | このサーバーの SID（識別子）を表示する |

### ログ

ログは **`/var/log/samba/`** に出ます。`log file = /var/log/samba/log.%m` なら、デーモンの `log.smbd`、`log.nmbd` のほかに、クライアントごとの `log.クライアント名` ができます。

```console
# ls /var/log/samba
log.127.0.0.1  log.fs1  log.nmbd  log.smbd  ...
# tail -2 /var/log/samba/log.smbd
[2026/11/16 21:19:03.762942,  3] ../../lib/util/access.c:372(allow_access)
  Allowed connection from 127.0.0.1 (127.0.0.1)
```

1 行目の `3` は、そのメッセージのログレベルです。`log level = 3` にすると、接続の許可や認証の成否まで出ます。普段は 0〜1、調べるときだけ `smbcontrol smbd debug 3` で上げます。

## AD とつなぐ：samba-tool、winbindd、ACL（getfacl・setfacl） {#ad-acl}

Samba と Active Directory（AD。Windows のドメインの仕組み）の関係は、2 通りあります。

| 役目 | smb.conf | 動かすデーモン | 管理コマンド |
| --- | --- | --- | --- |
| **AD のドメインコントローラ**（AD DC）になる | `server role = active directory domain controller` | `samba` | **`samba-tool`** |
| AD の**メンバー**になる（ファイルサーバー） | `security = ads`、`realm = …` | `smbd`、`nmbd`、`winbindd` | **`net ads join`** |

### samba-tool：AD DC を管理する

**`samba-tool`** は、Samba を AD DC として使うときの管理コマンドです。`samba-tool 種類 命令` の形です。

```console
# samba-tool domain provision --realm=EXAMPLE.COM --domain=EXAMPLE --server-role=dc --adminpass='…'
# samba-tool user create taro
User 'taro' added successfully
# samba-tool user list
krbtgt
taro
Guest
Administrator
# samba-tool group add sales
Added group sales
# samba-tool group addmembers sales taro
Added members to group sales
# samba-tool domain level show
Domain and forest function level for domain 'DC=example,DC=com'
```

| 書き方 | すること |
| --- | --- |
| **`samba-tool domain provision`** | 新しい AD のドメインを作る（smb.conf とデータベースを作る） |
| `samba-tool domain join ドメイン DC` | 既存のドメインに、DC として加わる |
| `samba-tool domain level show` | ドメインの機能レベルを表示する |
| `samba-tool user create / list / delete / disable / enable / setpassword` | AD のユーザーを管理する |
| `samba-tool group add / addmembers / listmembers` | AD のグループを管理する |
| `samba-tool dns …` | AD の DNS のレコードを管理する |
| `samba-tool testparm` | 設定を検査する |

provision のあとの smb.conf は、次の形になります。

```text
[global]
	netbios name = DC1
	realm = EXAMPLE.COM
	server role = active directory domain controller
	workgroup = EXAMPLE

[sysvol]
	path = /var/lib/samba/sysvol
	read only = No

[netlogon]
	path = /var/lib/samba/sysvol/example.com/scripts
	read only = No
```

:::warn 試験の注意：ユーザーを作るコマンドは、役目で違う
単体のファイルサーバー（`security = user`）のユーザーは **`smbpasswd -a`**（または `pdbedit -a`）です。AD DC の上のユーザーは **`samba-tool user create`** です。AD に**参加する**のは `net ads join`、AD を**作る**のは `samba-tool domain provision` です。
:::

### winbindd：ドメインのユーザーを Linux のユーザーとして見せる

AD のユーザーは、Linux の `/etc/passwd` にはいません。しかしファイルの持ち主には UID が要ります。**winbindd** は、AD のユーザーとグループに UID・GID を割り当てて（**ID マッピング**）、Linux から見えるようにします。

```text
[global]
   workgroup = EXAMPLE
   realm = EXAMPLE.COM
   security = ads
   idmap config * : backend = tdb
   idmap config * : range = 3000-7999
   idmap config EXAMPLE : backend = rid
   idmap config EXAMPLE : range = 10000-999999
   winbind use default domain = yes
   template shell = /bin/bash
   template homedir = /home/%U
```

`testparm` はこの設定を `Server role: ROLE_DOMAIN_MEMBER` と表示しました。`idmap config` は、どのドメインのユーザーに、どの範囲の UID・GID を、どの方法（backend）で割り当てるかを決めます。

さらに `/etc/nsswitch.conf` の `passwd:` と `group:` の行に `winbind` を足すと、`getent passwd` や `ls -l` でドメインのユーザーが名前で見えるようになります。`wbinfo -u` は、winbindd が知っているドメインのユーザーの一覧を出します。

### ACL：getfacl と setfacl

Windows の共有フォルダは、「このユーザーは読める、あのグループは書ける」と、**何人にでも**個別に権利を付けられます。Linux のふつうの権限は、持ち主・グループ・その他の 3 組だけです（[図解 LinuC 2.1](../../linuc/site/ch02.html#perm)）。その差を埋めるのが **ACL**（Access Control List、アクセス制御リスト）です。

**`getfacl`** で見て、**`setfacl`** で変えます。

```console
# getfacl d/f
# file: d/f
# owner: root
# group: root
user::rw-
group::r--
other::---

# setfacl -m u:bob:rw d/f                 # bob に rw を足す
# getfacl d/f
# file: d/f
# owner: root
# group: root
user::rw-
user:bob:rw-
group::r--
mask::rw-
other::---

# ls -l d/f
-rw-rw----+ 1 root root 0 Nov 16 21:20 d/f
```

- `user::`（名前なし）は持ち主、`group::` は所有グループ、`other::` はその他で、ふつうの権限と同じものです
- **`user:bob:rw-`** が足した項目です。`group:sales:r--` のようにグループにも足せます
- ACL が付いたファイルは、`ls -l` の権限の後ろに **`+`** が付きます
- **`mask::`** は、名前付きのユーザー、所有グループ、名前付きのグループに与えられる権利の**上限**です。`ls -l` のグループの欄（上の `rw-`）は、この mask を表します

mask を狭めると、項目に書いた権利より実際の権利が小さくなり、`#effective:` で示されます。

```console
# setfacl -m g:sales:r,m::r d/f           # sales に r を足し、mask を r にする
# getfacl d/f
user::rw-
user:bob:rw-	#effective:r--
group::r--
group:sales:r--
mask::r--
other::---
```

| 書き方 | すること |
| --- | --- |
| **`setfacl -m u:ユーザー:rwx ファイル`** | ユーザーの項目を足す・変える（modify） |
| `setfacl -m g:グループ:rx ファイル` | グループの項目を足す・変える |
| `setfacl -m m::rx ファイル` | mask を変える |
| **`setfacl -x u:ユーザー ファイル`** | その項目を消す（権限の部分は書かない） |
| **`setfacl -b ファイル`** | 足した ACL を全部消す（`--remove-all`） |
| **`setfacl -d -m u:ユーザー:rwx ディレクトリ`** | **デフォルト ACL** を付ける。その下に作るファイルに引き継がれる |
| `setfacl -k ディレクトリ` | デフォルト ACL を消す |
| `setfacl -R …` | 下の階層にも適用する |
| `setfacl --restore=ファイル` | `getfacl -R` の出力から ACL を戻す |
| `getfacl -R ディレクトリ` | 下の階層も表示する |

**デフォルト ACL** はディレクトリだけに付けられ、`default:` で始まる行で表示されます。そのディレクトリの中に新しく作るファイルとディレクトリが、それを引き継ぎます。

```console
# setfacl -d -m u:bob:rwx d
# getfacl d
user::rwx
group::r-x
other::r-x
default:user::rwx
default:user:bob:rwx
default:group::r-x
default:mask::rwx
default:other::r-x
```

:::deep Samba と ACL：Windows の「セキュリティ」タブ
Windows のエクスプローラーの「セキュリティ」タブで権利を変えると、Samba はそれを Linux の ACL に写します。そのため、共有するファイルシステムは ACL に対応している必要があります（ext4 や XFS は標準で対応）。AD の環境では、Windows の ACL をそのまま拡張属性にしまう `vfs objects = acl_xattr` も使われ、AD DC では自動で有効になります。Samba 経由で「許可したはずなのに開けない」ときは、サーバーの上で `getfacl` を使い、mask と `#effective` を確かめます。
:::

## NFS は何でできているか：rpcbind・mountd・nfsd とポート {#nfs-daemons}

```fig seq NFSv3 のマウント。クライアントはまず rpcbind（111）に mountd のポートを聞き、mountd にマウントを頼み、そのあとのファイルの読み書きは nfsd（2049）と話す
{
  actors: [
    { id: 'c', label: 'クライアント' },
    { id: 'r', label: 'rpcbind（111）' },
    { id: 'm', label: 'rpc.mountd' },
    { id: 'n', label: 'nfsd（2049）' },
  ],
  msgs: [
    { from: 'c', to: 'r', label: 'mountd は何番ポート？' },
    { from: 'r', to: 'c', label: '例：40679 番', style: 'dashed' },
    { from: 'c', to: 'm', label: '/srv/nfs/data をマウントしたい' },
    { self: 'm', label: '/etc/exports の内容と相手の番地を比べる' },
    { from: 'm', to: 'c', label: 'ファイルハンドルを渡す', style: 'dashed' },
    { from: 'c', to: 'n', label: '読む・書く（ファイルハンドルで指す）' },
  ],
}
```

**NFS**（Network File System）は、UNIX 系の機械どうしでディレクトリを共有する仕組みです。サーバーがディレクトリを**エクスポート**（公開）し、クライアントがそれを**マウント**すると、手元のディレクトリと同じように使えます。

NFS は **RPC**（Remote Procedure Call。ネットワーク越しに手続きを呼ぶ仕組み）の上で動きます。RPC のサービスは「プログラム番号」で区別され、どのポートで待つかは起動のたびに変わることがあります。その対応表を持つのが **rpcbind**（古い名前は **portmapper**、portmap）です。

| デーモン | 役目 | ポート |
| --- | --- | --- |
| **rpcbind**（portmapper） | RPC のプログラム番号 → ポート番号の対応を答える | **111**（TCP・UDP） |
| **nfsd**（`rpc.nfsd` が起こすカーネルのスレッド） | ファイルの読み書きに答える本体 | **2049** |
| **rpc.mountd**（mountd） | マウントの要求を受け、`/etc/exports` と照らして許可する | 決まっていない（rpcbind に登録） |
| rpc.statd、lockd（nlockmgr） | ファイルのロックと、再起動の通知（NFSv3） | 決まっていない |
| rpc.idmapd | NFSv4 で、ユーザー名と UID を対応させる | |

**`rpcinfo -p`** は、rpcbind に登録されているサービスの一覧を出します。

```console
# rpcinfo -p
   program vers proto   port  service
    100000    4   tcp    111  portmapper
    100000    3   tcp    111  portmapper
    100000    2   tcp    111  portmapper
    100000    4   udp    111  portmapper
    100003    3   tcp   2049  nfs
    100003    4   tcp   2049  nfs
    100021    1   udp  57485  nlockmgr
    100021    4   tcp  37177  nlockmgr
    100005    1   udp  57582  mountd
    100005    3   tcp  40679  mountd
```

左から、プログラム番号、バージョン、プロトコル、ポート、サービス名です。`rpcinfo -p ホスト名` で、ほかのサーバーも調べられます。ここに **nfs と mountd が出ていなければ、NFS サーバーは動いていません**。

| 書き方 | すること |
| --- | --- |
| **`rpcinfo -p [ホスト]`** | 登録されている RPC のサービスの一覧（portmapper に聞く） |
| `rpcinfo -t ホスト サービス` | TCP でそのサービスを呼んで、応答するか確かめる |
| `rpcinfo -u ホスト サービス` | UDP で同じことをする |

```console
# rpcinfo -t localhost mountd
program 100005 version 1 ready and waiting
program 100005 version 2 ready and waiting
program 100005 version 3 ready and waiting
```

rpcbind が動いていないと、次のようになります。

```console
# rpcinfo -p
rpcinfo: can't contact portmapper: RPC: Remote system error - Connection refused
```

### NFSv3 と NFSv4

| | NFSv3 | NFSv4 |
| --- | --- | --- |
| 使うポート | 111（rpcbind）、2049（nfs）、mountd、statd、lockd | **TCP 2049 だけ** |
| rpcbind と mountd | 要る | マウントには要らない（プロトコルに組み込まれた） |
| ロック | 別のデーモン（lockd、statd） | プロトコルに組み込まれた |
| ユーザーの対応 | UID・GID の**数字**をそのまま使う | 名前（`user@domain`）で運び、rpc.idmapd が対応させる |
| エクスポートの見え方 | 実際のパスそのまま | 1 本の木（疑似ファイルシステム）。根は `fsid=0` |

NFSv4 はポートが 1 つなので、ファイアウォールを通しやすくなっています。NFSv3 でファイアウォールを通すには、mountd などのポートを固定する必要があります。

### パッケージとサービスの名前

| | Debian 系 | Red Hat 系 |
| --- | --- | --- |
| サーバーのパッケージ | `nfs-kernel-server` | `nfs-utils` |
| クライアントのパッケージ | `nfs-common` | `nfs-utils` |
| サービス | `nfs-kernel-server`（`nfs-server` でもよい） | `nfs-server` |
| rpcbind | `rpcbind.service`、`rpcbind.socket` | 同じ |

```console
# systemctl enable --now nfs-server
```

## /etc/exports はどう書くか、exportfs でどう反映するか {#exports}

```fig layout /etc/exports の 1 行。ディレクトリ、空白、クライアント、そのすぐ後ろ（空白なし）にかっこでオプション。クライアントは空白で区切って何個でも並べられる
{
  unit: 10,
  rows: [
    { label: '1 行', cells: [{ t: '/srv/nfs/data', w: 15, kind: 'accent' }, { t: '192.168.1.0/24', w: 16, kind: 'stack' }, { t: '(rw,sync,no_root_squash)', w: 26, kind: 'heap' }] },
    { label: '役目', cells: [{ t: '公開するディレクトリ', w: 15, kind: 'accent' }, { t: 'だれに', w: 16, kind: 'stack' }, { t: 'どんな条件で', w: 26, kind: 'heap' }] },
  ],
}
```

サーバーがどのディレクトリを、だれに、どんな条件で公開するかは、**`/etc/exports`** に書きます。1 行が 1 つのディレクトリです。

```text
# /etc/exports
/srv/nfs/data  192.168.1.0/24(rw,sync,no_subtree_check) 192.168.1.10(rw,sync,no_root_squash,no_subtree_check)
/srv/nfs/pub   *(ro,sync,all_squash,no_subtree_check) *.example.com(rw,sync,no_subtree_check)
```

### クライアントの書き方（ホストとサブネットでの制限）

| 書き方 | 意味 |
| --- | --- |
| `client1.example.com`、`192.168.1.10` | 1 台のホスト（名前か IP アドレス） |
| `192.168.1.0/24`、`192.168.1.0/255.255.255.0` | **サブネット**の全部のホスト |
| `*.example.com` | ワイルドカード（`*` と `?`）に合うホスト名 |
| `*` | すべてのホスト（`exportfs` の表示では `<world>`） |
| `@グループ名` | NIS のネットグループ |

### オプション

| オプション | 意味 | 既定 |
| --- | --- | --- |
| **`ro`** / **`rw`** | 読み取り専用 / 読み書き | **`ro`** |
| **`sync`** / `async` | 書き込みをディスクに書いてから応答する / 書く前に応答する（速いが、サーバーが落ちると失う） | `sync` |
| **`root_squash`** | クライアントの **root（UID 0）を、匿名ユーザーに置き換える** | **有効** |
| **`no_root_squash`** | クライアントの root を、サーバーでも root として扱う | |
| **`all_squash`** | **すべてのユーザー**を匿名ユーザーに置き換える | `no_all_squash` |
| `anonuid=` / `anongid=` | 匿名ユーザーの UID / GID | 65534（nobody） |
| `subtree_check` / `no_subtree_check` | ファイルがエクスポートした部分木の中にあるかを毎回確かめる / 確かめない | `no_subtree_check` |
| `secure` / `insecure` | 1024 未満のポートからの要求だけ受ける / どのポートからでも受ける | `secure` |
| `fsid=0` | NFSv4 の木の根にする | |

既定値は、オプションなしでエクスポートして `exportfs -v` で確かめたものです。

```console
# cat /etc/exports
/srv/nfs/data  192.168.1.5
# exportfs -ra
exportfs: No options for /srv/nfs/data 192.168.1.5: suggest 192.168.1.5(sync) to avoid warning
# exportfs -v
/srv/nfs/data 	192.168.1.5(sync,wdelay,hide,no_subtree_check,sec=sys,ro,secure,root_squash,no_all_squash)
```

`ro`、`sync`、`root_squash` が既定です。

```fig graph root_squash：クライアントの root は、サーバーでは匿名ユーザー（nobody、UID 65534）になる。ふつうのユーザーは UID の数字のまま通る
{
  col: 250, row: 90,
  nodes: [
    { id: 'cr', label: 'クライアントの root', sub: 'UID 0', x: 0, y: 0, kind: 'ext', mono: false },
    { id: 'cu', label: 'クライアントの alice', sub: 'UID 1000', x: 0, y: 1, kind: 'ext', mono: false },
    { id: 'sn', label: 'サーバーの nobody', sub: 'UID 65534（anonuid）', x: 1.3, y: 0, kind: 'accent', mono: false },
    { id: 'su', label: 'サーバーの UID 1000', sub: '名前が違っても数字で決まる', x: 1.3, y: 1, mono: false },
  ],
  edges: [
    { from: 'cr', to: 'sn', label: 'root_squash（既定）', style: 'accent' },
    { from: 'cu', to: 'su', label: 'そのまま' },
  ],
}
```

root_squash を確かめます。クライアントの root でファイルを作ると、持ち主は 65534 になりました。

```console
# touch /mnt/t/byroot                    # クライアントで、root として
# ls -ln /mnt/t
-rw-r--r-- 1     0     0 3 Nov 16 21:21 a.txt
-rw-r--r-- 1 65534 65534 0 Nov 16 21:21 byroot
```

:::warn 試験の注意：squash の 3 つ
- **`root_squash`**（既定）：root だけを匿名にする。クライアントの root に、サーバーのファイルを好きにさせないため
- **`no_root_squash`**：root を root のまま通す。危ないので、信頼できるホストだけに付ける
- **`all_squash`**：全員を匿名にする。だれでも使える公開のディレクトリ向け

NFS（v3 の既定の認証）は、ユーザーを **UID の数字**で見分けます。サーバーとクライアントで同じユーザーの UID が違うと、別の人のファイルに見えます。
:::

:::warn 試験の注意：ホストとかっこの間に空白を入れない
`192.168.1.5(rw)` と `192.168.1.5 (rw)` は、まったく違う意味です。空白を入れると、「192.168.1.5 には既定のオプション（ro）で、**すべてのホスト**（`*`）には rw で」公開してしまいます。

```console
# cat /etc/exports
/srv/nfs/data  192.168.1.5 (rw,sync)
# exportfs -ra
exportfs: No host name given with /srv/nfs/data (rw,sync), suggest *(rw,sync) to avoid warning
# exportfs -v
/srv/nfs/data 	192.168.1.5(sync,wdelay,hide,no_subtree_check,sec=sys,ro,secure,root_squash,no_all_squash)
/srv/nfs/data 	<world>(sync,wdelay,hide,no_subtree_check,sec=sys,rw,secure,root_squash,no_all_squash)
```
:::

### exportfs：エクスポートを反映する

`/etc/exports` を書き換えただけでは、何も変わりません。**`exportfs`** で、カーネルが持っている「いまのエクスポートの表」（`/var/lib/nfs/etab`）に反映します。

| 書き方 | すること |
| --- | --- |
| `exportfs` | いまエクスポートしているものの一覧 |
| **`exportfs -v`** | オプションも付けて一覧（verbose） |
| **`exportfs -a`** | `/etc/exports` の全部をエクスポートする（all） |
| **`exportfs -r`** | `/etc/exports` に**合わせ直す**（reexport。消した行は取り下げる） |
| **`exportfs -ra`** | 書き換えたあとの決まり文句。全部を読み直して反映する |
| **`exportfs -u ホスト:/パス`** | そのエクスポートを取り下げる（unexport） |
| **`exportfs -ua`** | 全部を取り下げる |
| `exportfs -o オプション ホスト:/パス` | `/etc/exports` に書かずに、その場でエクスポートする |

```console
# exportfs -v
/srv/nfs/data 	192.168.1.10(sync,wdelay,hide,no_subtree_check,sec=sys,rw,secure,no_root_squash,no_all_squash)
/srv/nfs/data 	192.168.1.0/24(sync,wdelay,hide,no_subtree_check,sec=sys,rw,secure,root_squash,no_all_squash)
/srv/nfs/pub  	*.example.com(sync,wdelay,hide,no_subtree_check,sec=sys,rw,secure,root_squash,no_all_squash)
/srv/nfs/pub  	<world>(sync,wdelay,hide,no_subtree_check,sec=sys,ro,secure,root_squash,all_squash)
# exportfs -o ro,sync 10.0.0.5:/srv/nfs/pub      # その場で 1 つ足す
# exportfs -u 10.0.0.5:/srv/nfs/pub              # 取り下げる
```

`exportfs -o` で足したものは `/etc/exports` に書かれないので、再起動や `exportfs -r` で消えます。Red Hat 系には `/etc/exports.d/` もあり、その中の `*.exports` というファイルも `/etc/exports` と同じ書式で読まれます。

## クライアントから使う：showmount・mount・/etc/fstab・nfsstat {#nfs-client}

### showmount：サーバーが何を公開しているか

**`showmount`** は、サーバーの mountd に聞いて、エクスポートやマウントの状況を表示します。クライアントからも使えます。

```console
$ showmount -e fs1
Export list for fs1:
/srv/nfs/pub  (everyone)
/srv/nfs/data 192.168.1.0/24,192.168.1.10
# showmount -a                          # サーバーの上で
All mount points on fs1:
192.168.1.10:/srv/nfs/data
```

| オプション | 表示するもの |
| --- | --- |
| **`-e`**（`--exports`） | サーバーの**エクスポートの一覧**と、許されているクライアント |
| `-a`（`--all`） | マウントしている**クライアント:ディレクトリ**の組 |
| `-d`（`--directories`） | クライアントにマウントされているディレクトリだけ |
| （なし） | マウントしているクライアントのホストだけ |

showmount は mountd と話すので、rpcbind か mountd が止まっていると失敗します（`clnt_create: RPC: Timed out` など）。NFSv4 だけを通すファイアウォールの向こうからは使えません。

### mount とマウントオプション

クライアントでは、**`サーバー:/パス`** を装置の代わりに書いてマウントします（[図解 LinuC 5.11](../../linuc/site/ch05.html#mount)）。

```console
# mount -t nfs fs1:/srv/nfs/data /mnt/data
# mount -t nfs -o vers=3,soft,timeo=30,retrans=2,rsize=8192,wsize=8192 fs1:/srv/nfs/data /mnt/data
# mount -t nfs4 fs1:/srv/nfs/data /mnt/data
```

| オプション | 意味 |
| --- | --- |
| **`hard`** | サーバーが応答しないとき、応答するまで**いつまでも繰り返す**（**既定**）。プログラムは待ち続ける |
| **`soft`** | `retrans` 回繰り返してだめなら、プログラムに**エラーを返す**。データが壊れることがある |
| `timeo=n` | 再送までの待ち時間。単位は **0.1 秒**（`timeo=30` は 3 秒） |
| `retrans=n` | 再送の回数 |
| `rsize=n` / `wsize=n` | 1 回に読む / 書くバイト数の上限 |
| `vers=n`（`nfsvers=n`） | NFS のバージョン（3、4、4.2 など） |
| `proto=tcp` / `proto=udp` | 使うトランスポート |
| `bg` / `fg` | マウントに失敗したとき、裏で繰り返す / その場で繰り返す（既定は `fg`） |
| `nolock` | ファイルのロックを使わない（NFSv3） |
| `ro` / `rw`、`nosuid`、`noexec` | ほかのファイルシステムと同じ |
| **`_netdev`** | ネットワークが要る装置である、という印。ネットワークが上がってからマウントする |

`/etc/fstab` に書くと、起動のたびにマウントされます（[図解 LinuC 5.12](../../linuc/site/ch05.html#fstab)）。1 列目が `サーバー:/パス`、3 列目が `nfs`（または `nfs4`）です。

```text
# /etc/fstab
fs1:/srv/nfs/data   /mnt/data   nfs   rw,hard,_netdev   0 0
fs1:/srv/nfs/pub    /mnt/pub    nfs   ro,soft,timeo=30,noauto   0 0
```

NFS のファイルシステムは fsck しないので、5 列目（dump）と 6 列目（fsck の順番）は `0 0` です。

実際に使われているオプションは **`/proc/mounts`**（または `mount`、`nfsstat -m`）で確かめます。指定しなかったものも、決まった値が全部出ます。

```console
$ grep nfs /proc/mounts
fs1:/srv/nfs/data /mnt/data nfs rw,relatime,vers=3,rsize=8192,wsize=8192,namlen=255,soft,proto=tcp,timeo=30,retrans=2,sec=sys,mountaddr=192.168.1.1,mountvers=3,mountport=55615,mountproto=udp,local_lock=none,addr=192.168.1.1 0 0
```

この行からは、NFSv3（`vers=3`）、TCP（`proto=tcp`）、soft マウント、読み書きの単位が 8192 バイト、再送まで 3 秒（`timeo=30`）と読み取れます。

:::warn 試験の注意：hard と soft
既定は **hard** です。サーバーが落ちると、そのディレクトリを触ったプログラムは、サーバーが戻るまで止まったままになります。**soft** はエラーを返して先へ進めますが、書き込みの途中だとデータが壊れることがあります。大事なデータを書く場所は hard、読むだけの場所は soft、が基本です。
:::

### nfsstat：NFS の統計

**`nfsstat`** は、NFS と RPC の呼び出しの回数を表示します。

```console
# nfsstat -s
Server rpc stats:
calls      badcalls   badfmt     badauth    badclnt
12         0          0          0          0       

Server nfs v3:
null             getattr          setattr          lookup           access           
4        28%     3        21%     1         7%     0         0%     1         7%     
...
# nfsstat -m
/mnt/data from fs1:/srv/nfs/data
 Flags:	rw,relatime,vers=3,rsize=8192,wsize=8192,namlen=255,soft,proto=tcp,timeo=30,retrans=2,sec=sys,...
```

| オプション | 表示するもの |
| --- | --- |
| **`-s`**（`--server`） | サーバー側の統計 |
| **`-c`**（`--client`） | クライアント側の統計。`retrans`（再送）が多ければ、ネットワークかサーバーが遅い |
| **`-m`**（`--mounts`） | マウントしている NFS と、その**マウントオプション** |
| `-n`（`--nfs`） / `-r`（`--rpc`） | NFS の部分だけ / RPC の部分だけ |
| `-2` / `-3` / `-4` | そのバージョンの分だけ |

### つながらないときの切り分け

| 症状 | 確かめること |
| --- | --- |
| `rpcinfo: can't contact portmapper` | サーバーで rpcbind が動いているか。111 番がファイアウォールで止まっていないか |
| `rpcinfo -p サーバー` に nfs・mountd がない | NFS サーバー（nfs-server）が起動していない |
| `mount.nfs: access denied by server while mounting …` | `/etc/exports` にそのクライアントがあるか。**`exportfs -ra` を忘れていないか**。`showmount -e サーバー` で確かめる |
| マウントできるが、書けない | `ro` になっていないか（`exportfs -v`）。root なら root_squash。ディレクトリの権限と UID が合っているか |
| ファイルの持ち主が別の人や数字に見える | サーバーとクライアントで UID が違う |
| コマンドが止まったまま戻らない | サーバーが応答していない。hard マウントなので待ち続けている |

```console
# mount -t nfs 127.0.0.1:/srv/nfs/data /mnt/t        # エクスポートを取り下げたあと
mount.nfs: access denied by server while mounting 127.0.0.1:/srv/nfs/data
```

:::key まとめ
- **Samba のデーモン**：`smbd`（ファイル共有。TCP 445・139）、`nmbd`（NetBIOS の名前。UDP 137・138）、`winbindd`（ドメインのユーザー ↔ UID）、`samba`（AD DC）
- 設定は **`/etc/samba/smb.conf`**、ログは **`/var/log/samba/`**。`[global]`、`[homes]`、`[printers]`、それ以外は共有
- 共有の既定は **`read only = yes`**。書けるようにするのは `read only = no` か `writable = yes`。`valid users`、`write list`、`hosts allow`、`guest ok`、`browseable`、`create mask`
- **`testparm`** で smb.conf を検査（`-s` は待たない、`-v` は既定値も表示）。反映は `smbcontrol all reload-config`
- Samba のユーザーは **`smbpasswd -a`** で足す（Linux のユーザーが先に必要）。`-x` 削除、`-d` 無効、`-e` 有効。一覧は `pdbedit -L`
- **`username map`** のファイルは `Linux の名前 = Windows の名前 …`
- `smbclient -L ホスト`（一覧）、`smbclient //ホスト/共有 -U ユーザー`、`smbstatus`（だれがつないでいるか）、`nmblookup`（NetBIOS 名 → IP）、`net ads join`（AD に参加）、`samba-tool`（AD DC の管理）
- ACL は **`getfacl`** で見て **`setfacl -m u:名前:rwx`** で足す。`-x` で消す、`-b` で全部消す、`-d` はデフォルト ACL。`ls -l` の `+` が印、mask が上限
- **NFS のデーモン**：`rpcbind`（portmapper。111）、`nfsd`（2049）、`rpc.mountd`。NFSv4 は TCP 2049 だけ
- **`/etc/exports`**：`ディレクトリ ホスト(オプション)`。ホストとかっこの間に空白を入れない。既定は `ro`、`sync`、`root_squash`
- **`exportfs -ra`** で反映、`-v` で一覧、`-u` で取り下げ、`-ua` で全部取り下げ
- **`showmount -e サーバー`** でエクスポートの一覧、**`rpcinfo -p`** で RPC のサービス、**`nfsstat`**（`-s`、`-c`、`-m`）で統計
- マウントは `mount -t nfs サーバー:/パス マウントポイント`。既定は **hard**。`soft`、`timeo`（0.1 秒単位）、`retrans`、`rsize`、`wsize`、`_netdev`。実際の値は `/proc/mounts`
:::

## 練習問題 {#practice}

:::q 2.11.1-01 single
Samba で、ファイル共有とプリンタ共有、ユーザーの認証を受け持つデーモンはどれか。

- [ ] `winbindd`
- [ ] `rpcbind`
- [ ] `smbcontrol`
:::why
`smbd` がファイルとプリンタの共有、認証を受け持ちます。`nmbd` は NetBIOS の名前解決とブラウジング、`winbindd` はドメインのユーザーを Linux のユーザーに対応させるデーモンです。`rpcbind` は NFS で使う RPC のポートの対応表で、Samba のものではありません。`smbcontrol` はデーモンではなく、デーモンにメッセージを送るコマンドです（[Samba は何でできているか](#samba-daemons)）。
:::

:::q 2.11.1-02 multi

- [x] UDP 138
- [ ] TCP 139
- [ ] TCP 445
- [ ] TCP 111
:::why
`nmbd` は UDP 137（NetBIOS の名前サービス）と UDP 138（データグラム）を使います。TCP 139（NetBIOS のセッション）と TCP 445（SMB を直接）は `smbd` のポートです。111 は NFS で使う rpcbind のポートです（[Samba は何でできているか](#samba-daemons)）。

:::q 2.11.1-03 single


`read only` の既定値は `yes` なので、この共有は読み取り専用です。`valid users = @staff` で接続できるのは staff グループのユーザーだけになり、`write list` に書かれた tanaka は `read only` に関係なく書き込めます。`read only` を省いてもエラーにはなりません（[共有のセクションの主なパラメータ](#smb-conf)、[共有を使えるのはだれか](#share-access)）。

:::q 2.11.1-04 fill

:::why
`testparm` は `/etc/samba/smb.conf`（または引数のファイル）を検査します。知らないパラメータ名は `Unknown parameter encountered` と表示されます。`-s` を付けると Enter を待たずに設定を表示し、`-v` で既定値のままのパラメータも表示します（[testparm](#smb-conf)）。

:::q 2.11.1-05 single

`smbpasswd -a` がアカウントの追加（add）です。`-e` は無効にしたアカウントを有効に戻す、`-x` は削除です。`passwd` が変えるのは `/etc/shadow` の Linux のパスワードで、Samba のパスワードは別に持ちます。`smbclient -U` は、そのユーザー名で共有につなぐクライアントの指定です（[smbpasswd と pdbedit](#samba-users)）。

:::q 2.11.1-06 single

:::q 2.11.1-07 single

`smbstatus` は、接続しているユーザー（プロセス）、使われている共有、ロックされているファイルを表示します。`smbcontrol` はデーモンにメッセージを送る、`smbclient` は共有につなぐクライアント、`testparm` は smb.conf の検査、`nmblookup` は NetBIOS 名の解決です（[smbstatus](#samba-tools)）。

:::q 2.11.1-08 fill

`smbcontrol 宛先 メッセージ` の形で、`reload-config` が smb.conf の読み直しです。宛先の `all` はすべてのデーモンです。ほかのメッセージには、`ping`（生きているか）、`debug レベル`（ログレベルを変える）、`close-share 共有名`、`shutdown` があります（[smbcontrol](#samba-tools)）。

:::q 2.11.1-09 single

- [ ] `map "Taro Yamada" tyamada taro`

username map のファイルは `Linux の名前 = Windows の名前 …` の形です。左が Linux、右が Windows で、右は空白で区切って何個でも書けます。空白を含む名前は `"` で囲みます。左右を逆にしたもの、`:` で区切る形は使えません（[username map](#samba-users)）。

:::q 2.11.1-10 single
次の smb.conf の `[homes]` セクションについての説明として正しいものはどれか。

```text
[homes]
   browseable = no
   read only = no
   valid users = %S
```
- [ ] `/homes` というディレクトリを、homes という名前で全員に公開する
- [ ] `%S` はサーバーの NetBIOS 名に置き換わるので、サーバーと同じ名前のユーザーだけが使える
- [x] 接続したユーザーのホームディレクトリが、そのユーザー名の共有として見え、本人だけが使える
- [ ] `browseable = no` なので、ユーザーは自分のホームに接続できない
- [ ] `path` がないので、この共有は無効になる
:::why
`[homes]` は特別なセクションで、接続したユーザーのホームディレクトリを、ユーザー名の共有として見せます。`path` は書かなくてもホームディレクトリになります。`%S` は共有の名前で、`[homes]` ではユーザー名になるので、`valid users = %S` は「本人だけ」です。`browseable = no` は一覧に「homes」を出さないだけで、接続はできます。サーバーの NetBIOS 名は `%L` です（[特別なセクションと変数](#smb-conf)）。

:::q 2.11.1-11 multi

- [ ] `browseable = yes`
- [ ] `guest ok = yes`
- [ ] `write only = yes`

`read only` の既定値は `yes` です。書き込めるようにするには `read only = no` か、その反対の意味を持つ `writable = yes`（`writeable`、`write ok` も同じ）を書きます。`browseable` は一覧に出すかどうか、`guest ok` はパスワードなしの接続を許すかどうかで、書き込みとは関係ありません。`write only` というパラメータはありません（[共有のセクションの主なパラメータ](#smb-conf)）。
:::

:::q 2.11.1-13 single

- [ ] bob はこのファイルを読み書きできる
- [x] bob はこのファイルを読めるが、書けない
- [ ] bob はこのファイルを読むことも書くこともできない

- [ ] `smbstatus -L` は、サーバーが公開している共有の一覧を、ほかのホストから調べる
:::why
`nmblookup` は NetBIOS 名を IP アドレスに引き、`pdbedit -L` は Samba のアカウントの一覧を出します。`smbpasswd -d` は無効にする（disable）だけで、削除は `-x` です。`testparm -v` は既定値のままのパラメータも表示するオプションで、読み直しは `smbcontrol … reload-config` です。`smbstatus -L` はロックされたファイルの一覧で、共有の一覧をほかのホストから調べるのは `smbclient -L` です（[動いている Samba を調べる](#samba-tools)、[smbpasswd と pdbedit](#samba-users)）。
:::
:::

:::q 2.11.2-01 single
NFS サーバーが、どのディレクトリをどのクライアントに公開するかを書くファイルはどれか。
- [ ] `/etc/fstab`
- [ ] `/etc/nfs.conf`
- [x] `/etc/exports`
- [ ] `/etc/nfsmount.conf`
- [ ] `/var/lib/nfs/exports`
:::why
エクスポートの設定は `/etc/exports` に書きます。`/etc/fstab` はクライアントが起動のたびにマウントするものを書くファイル、`/etc/nfs.conf` は NFS のデーモンの動き方の設定です。いま有効なエクスポートの表は `/var/lib/nfs/etab` にあり、`exportfs` が書きます（[/etc/exports はどう書くか](#exports)）。
:::
:::

:::q 2.11.2-02 single
次の `/etc/exports` についての説明として正しいものはどれか。

```text
/srv/data  192.168.10.0/24(rw,sync) 192.168.10.5(rw,sync,no_root_squash)
```
- [ ] 192.168.10.5 の root は、匿名ユーザー（nobody）として扱われる
- [ ] 192.168.10.0/24 のホストは、読むことだけができる
- [x] 192.168.10.5 の root は、サーバーの上でも root として扱われる
- [ ] 192.168.10.0/24 のホストのすべてのユーザーが、匿名ユーザーとして扱われる
- [ ] この行は書式の誤りで、`exportfs` が受け付けない
:::why
`no_root_squash` を付けたホストの root は、サーバーでも root として扱われます。付けていない 192.168.10.0/24 のほうは既定の `root_squash` で、root だけが匿名ユーザーになります（ふつうのユーザーは UID のまま）。`rw` なので読み書きできます。1 行に、空白で区切って複数のクライアントを並べるのは正しい書式です。全員を匿名にするのは `all_squash` です（[オプション](#exports)）。
:::
:::

:::q 2.11.2-03 single
次の `/etc/exports` の行は、どのように解釈されるか。

```text
/srv/data  client1.example.com (rw,sync)
```
- [ ] client1.example.com だけに、読み書きで公開する
- [ ] client1.example.com だけに、読み取り専用で公開する
- [x] client1.example.com には読み取り専用で、すべてのホストには読み書きで公開する
- [ ] 書式の誤りなので、この行は無視される
- [ ] すべてのホストに、読み取り専用で公開する
:::why
ホスト名とかっこの間に空白があるので、「client1.example.com（オプションなし）」と「ホスト名なしの (rw,sync)」の 2 つに分かれます。オプションなしの既定は `ro` です。ホスト名のないかっこは「すべてのホスト（`*`）」の意味になり、だれでも読み書きできてしまいます。正しくは `client1.example.com(rw,sync)` です（[試験の注意：ホストとかっこの間に空白を入れない](#exports)）。
:::
:::

:::q 2.11.2-04 fill
`/etc/exports` を書き換えた。すべてのエクスポートを `/etc/exports` の内容に合わせ直したい（消した行のエクスポートは取り下げる）。空欄に入るオプションを入力してください。

```text
# exportfs ____
```
= -ra
= -ar
= -r
= -r -a
= -a -r
= -rav
= -arv
= -rv
:::why
`-r`（reexport）は、いまのエクスポートの表を `/etc/exports` に合わせ直します。`-a`（すべて）と組み合わせた `exportfs -ra` が決まり文句です。`-a` だけでは、消した行のエクスポートは残ります。`-u` は取り下げ、`-v` は詳しい表示です（[exportfs](#exports)）。
:::

:::q 2.11.2-05 single
クライアントから、NFS サーバー `fs1` がエクスポートしているディレクトリの一覧を調べるコマンドはどれか。
- [ ] `exportfs -v fs1`
- [x] `showmount -e fs1`
- [ ] `nfsstat -m fs1`
- [ ] `mount -t nfs fs1`
- [ ] `rpcinfo -e fs1`
:::why
`showmount -e ホスト`（`--exports`）は、そのサーバーのエクスポートの一覧と、許されているクライアントを表示します。`exportfs` はサーバーの上で自分のエクスポートを扱うコマンドで、ほかのホストは調べられません。`nfsstat -m` は、手元でマウントしている NFS とそのオプションを表示します。`rpcinfo` に `-e` はなく、`rpcinfo -p fs1` は RPC のサービスの一覧です（[showmount](#nfs-client)）。
:::
:::

:::q 2.11.2-06 multi
NFS サーバーで、次の `rpcinfo -p` の出力が得られた。この出力の説明として正しいものを 2 つ選択してください。

```text
   program vers proto   port  service
    100000    4   tcp    111  portmapper
    100000    2   udp    111  portmapper
    100003    3   tcp   2049  nfs
    100003    4   tcp   2049  nfs
    100005    3   udp  43295  mountd
    100005    3   tcp  40679  mountd
```
- [x] portmapper（rpcbind）は 111 番ポートで待ち受けている
- [x] NFS の本体（nfs）は TCP の 2049 番ポートで待ち受けている
- [ ] mountd は、いつも 40679 番ポートを使うと決まっている
- [ ] このサーバーでは mountd が動いていない
- [ ] このサーバーは NFSv4 に対応していない
:::why
portmapper は 111 番、nfs は 2049 番です。mountd のポートは決まっておらず、起動のたびに変わることがあるので、クライアントは rpcbind に聞いて知ります。mountd の行があるので mountd は動いています。nfs の vers の列に 4 があるので、NFSv4 にも対応しています（[NFS は何でできているか](#nfs-daemons)）。
:::

:::q 2.11.2-07 single
NFS で、RPC のプログラム番号と、そのサービスが待ち受けているポート番号の対応を答えるデーモンはどれか。
- [ ] `rpc.mountd`
- [ ] `nfsd`
- [x] `rpcbind`
- [ ] `rpc.idmapd`
- [ ] `nmbd`
:::why
`rpcbind`（古い名前は portmapper、portmap）が、プログラム番号とポートの対応表を持ち、111 番で答えます。`rpc.mountd` はマウントの要求を `/etc/exports` と照らして許可する、`nfsd` はファイルの読み書きに答える、`rpc.idmapd` は NFSv4 で名前と UID を対応させるデーモンです。`nmbd` は Samba のデーモンです（[NFS は何でできているか](#nfs-daemons)）。
:::
:::

:::q 2.11.2-08 single
クライアントの `/etc/fstab` に、サーバー `fs1` の `/srv/data` を `/mnt/data` へ NFS でマウントする行を書く。正しいものはどれか。
- [ ] `//fs1/srv/data  /mnt/data  nfs  defaults  0 0`
- [x] `fs1:/srv/data  /mnt/data  nfs  defaults,_netdev  0 0`
- [ ] `/mnt/data  fs1:/srv/data  nfs  defaults  0 0`
- [ ] `fs1:/srv/data  /mnt/data  exports  rw,sync  0 0`
- [ ] `nfs://fs1/srv/data  /mnt/data  auto  defaults  1 2`
:::why
NFS は 1 列目に `サーバー:/パス`、2 列目にマウントポイント、3 列目に `nfs`（または `nfs4`）を書きます。`_netdev` は、ネットワークが上がってからマウントする印です。`//サーバー/共有` は SMB（cifs）の書き方です。1 列目と 2 列目を逆にしたもの、種類に `exports` と書いたものは誤りです。NFS は fsck しないので、最後は `0 0` です（[mount とマウントオプション](#nfs-client)）。
:::
:::

:::q 2.11.2-09 multi
NFS のマウントオプション `hard` と `soft` の説明として正しいものを 2 つ選択してください。
- [x] `hard` では、サーバーが応答しない間、プログラムは応答が来るまで待ち続ける
- [x] `soft` では、決められた回数だけ再送してもだめなら、プログラムにエラーが返る
- [ ] どちらも指定しないと `soft` になる
- [ ] `soft` は読み取り専用、`hard` は読み書きでマウントする
- [ ] `hard` は、サーバー側の `/etc/exports` に書くオプションである
:::why
`hard`（既定）はいつまでも再送を繰り返し、プログラムは待ち続けます。`soft` は `retrans` 回の再送のあとでエラーを返します。読み取り専用か読み書きかは `ro` / `rw` で決まり、hard / soft とは関係ありません。どちらもクライアントのマウントオプションで、`/etc/exports` には書きません（[mount とマウントオプション](#nfs-client)）。
:::
:::

:::q 2.11.2-10 single
クライアントで、次の行が `/proc/mounts` にあった。読み取れることとして正しいものはどれか。

```text
fs1:/srv/data /mnt/data nfs rw,relatime,vers=3,rsize=8192,wsize=8192,namlen=255,soft,proto=tcp,timeo=30,retrans=2,sec=sys,addr=192.168.1.1 0 0
```
- [ ] NFSv4 で、UDP を使ってマウントしている
- [ ] 再送までの待ち時間は 30 秒である
- [x] NFSv3 で、TCP を使い、soft マウントしている
- [ ] 読み取り専用でマウントしている
- [ ] サーバーの `/etc/exports` に `rsize=8192` と書かれている
:::why
`vers=3` で NFSv3、`proto=tcp` で TCP、`soft` で soft マウントです。`timeo` の単位は 0.1 秒なので、`timeo=30` は 3 秒です。先頭が `rw` なので読み書きです。`rsize` と `wsize` はクライアントのマウントオプションで、`/etc/exports` に書くものではありません（[mount とマウントオプション](#nfs-client)）。
:::

:::q 2.11.2-11 single
NFS サーバーで、いまエクスポートしているディレクトリを、有効になっているオプションも付けて一覧表示するコマンドはどれか。
- [ ] `exportfs -a`
- [ ] `exportfs -u`
- [x] `exportfs -v`
- [ ] `showmount -d`
- [ ] `nfsstat -s`
:::why
`exportfs -v` は、エクスポートとそのオプション（指定しなかった既定のものも含む）を表示します。`-a` は `/etc/exports` の全部をエクスポートする、`-u` は取り下げるオプションです。`showmount -d` はクライアントにマウントされているディレクトリの一覧で、オプションは出ません。`nfsstat -s` はサーバー側の呼び出しの統計です（[exportfs](#exports)）。
:::
:::

:::q 2.11.2-12 single
だれでも使える公開用のディレクトリを NFS でエクスポートする。どのユーザーが書いたファイルも、サーバーの上では UID 65534 の持ち物になるようにしたい。`/etc/exports` の行として正しいものはどれか。
- [ ] `/srv/pub  *(rw,sync,no_root_squash)`
- [ ] `/srv/pub  *(rw,sync,root_squash)`
- [x] `/srv/pub  *(rw,sync,all_squash,anonuid=65534,anongid=65534)`
- [ ] `/srv/pub  *(rw,sync,nobody)`
- [ ] `/srv/pub  all(rw,sync,squash=65534)`
:::why
`all_squash` は、すべてのユーザーを匿名ユーザーに置き換えます。匿名ユーザーの UID と GID は `anonuid` と `anongid` で決めます（既定も 65534）。`root_squash` が置き換えるのは root だけ、`no_root_squash` は root も置き換えません。`nobody` や `squash=` というオプションはなく、すべてのホストは `all` ではなく `*` と書きます（[オプション](#exports)）。
:::
:::

:::q 2.11.2-13 multi
`/etc/exports` で、公開する相手（クライアント）の書き方として正しいものを 2 つ選択してください。
- [x] `192.168.1.0/24`
- [x] `*.example.com`
- [ ] `192.168.1.0-192.168.1.255`
- [ ] `//client1/`
- [ ] `ALL EXCEPT 192.168.1.5`
:::why
クライアントは、1 台のホスト（名前か IP アドレス）、サブネット（`192.168.1.0/24` や `192.168.1.0/255.255.255.0`）、ワイルドカード（`*.example.com`、`*`）、ネットグループ（`@名前`）で書けます。番地の範囲を `-` でつなぐ書き方、`//` で始める書き方、`ALL EXCEPT` はありません（[クライアントの書き方](#exports)）。
:::

`nfsstat -m`（`--mounts`）は、マウントしている NFS ごとに、サーバーと `Flags:`（マウントオプション）を表示します。`-s` はサーバー側、`-c` はクライアント側の呼び出しの統計です。同じ内容は `/proc/mounts` でも確かめられます（[nfsstat](#nfs-client)）。

:::q 2.11.2-15 single
NFS サーバー fs1 の `/etc/exports` に、クライアント 192.168.1.20 向けの行を足した。ところが、クライアントでマウントすると次のエラーになった。サーバーで `rpcinfo -p` を実行すると nfs と mountd は表示される。原因として最も考えられるものはどれか。

```text
# mount -t nfs fs1:/srv/data /mnt/data
mount.nfs: access denied by server while mounting fs1:/srv/data
```
- [ ] サーバーで rpcbind が動いていない
- [x] サーバーで `exportfs -ra` を実行しておらず、足した行がまだ有効になっていない
- [ ] クライアントのマウントオプションに `hard` を指定していない
- [ ] サーバーのエクスポートに `root_squash` が付いている
- [ ] クライアントの `/etc/fstab` に行を書いていない
:::why
`access denied by server` は、mountd が「そのクライアントには公開していない」と断ったときのメッセージです。`/etc/exports` は書き換えただけでは効かないので、`exportfs -ra` で反映します。`rpcinfo -p` に nfs と mountd が出ているので、rpcbind とサーバーは動いています。`hard` は既定で、指定しなくてもマウントの可否には関係ありません。`root_squash` は root を匿名にするだけで、マウントは断りません。`/etc/fstab` は起動のときのためのもので、`mount` に全部の引数を与えていれば要りません（[つながらないときの切り分け](#nfs-client)）。
:::
