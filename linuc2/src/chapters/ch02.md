## /etc/fstab と mount：6 つの欄と、レベル2 で増えるオプション {#fstab}

`/etc/fstab` は、「何を・どこに・種類・オプション・dump・fsck」の 6 欄でした（[図解 LinuC 5.12](../../linuc/site/ch05.html#fstab)）。小さな Linux の fstab で、形を思い出します。

```sh run title="/etc/fstab の 6 欄"
cat /etc/fstab
```

本物のサーバーの fstab は、たとえばこうです。レベル2 では、4 欄目のオプションと、1 欄目の書き方が細かく問われます。

```text
# <何を>                                   <どこに>    <種類> <オプション>                 <dump> <fsck>
UUID=6109cec1-643a-4028-8cd9-7dff05eef572  /           ext4   defaults,errors=remount-ro   0      1
/dev/mapper/vg01-lv_var                    /var        xfs    defaults,noatime             0      2
LABEL=LOGS                                 /var/log    xfs    defaults,nodev,nosuid,noexec 0      2
UUID=4a98790c-1865-4763-917c-63280a83a0c8  none        swap   sw,pri=5                     0      0
/dev/sdc1                                  /mnt/usb    vfat   noauto,user,nofail           0      0
nfs1:/export/home                          /home       nfs    _netdev,x-systemd.automount  0      0
```

| 欄 | 中身 | 覚えること |
| --- | --- | --- |
| 1 | 何を | デバイス名、`UUID=`、`LABEL=`、`PARTUUID=`（GPT のパーティションの UUID）、`/dev/mapper/…`、NFS は `サーバー:/パス` |
| 2 | どこに | マウントポイント。スワップは `none`（または `swap`） |
| 3 | 種類 | `ext4`、`xfs`、`btrfs`、`vfat`、`nfs`、`swap`、`tmpfs`。`auto` は自動判定 |
| 4 | オプション | `mount -o` と同じものを、カンマで区切る |
| 5 | dump | `dump` コマンドが見る印。0 は取らない |
| 6 | fsck | 起動時に検査する順。`/` は 1、ほかは 2、0 は検査しない。**同じ番号で別のディスクにあるものは、並行して検査される** |

レベル1 の表（`ro`、`noexec`、`nosuid`、`nodev`、`noauto`、`user`、`users`、`defaults`）に、次を足します。

| オプション | 意味 |
| --- | --- |
| `noatime` | 読んだだけでは、アクセス時刻（atime）を更新しない。書き込みが減る |
| `relatime` | atime が mtime・ctime より古いときなどにだけ更新する。**今のカーネルの既定** |
| `nofail` | その装置がなくても、起動を失敗にしない |
| `_netdev` | ネットワークが要る装置（iSCSI の上の ext4 など）。ネットワークが使えるようになってからマウントする |
| `errors=remount-ro` | ext 系。エラーを見つけたら読み取り専用に付け直す（ほかに `continue`、`panic`） |
| `pri=数` | スワップの優先度（[2.5](#swap)） |
| `x-systemd.automount` | systemd が、**最初にアクセスされたとき**にマウントする（[2.4](#systemd-mount)） |
| `x-systemd.device-timeout=秒` | 装置が現れるのを待つ時間 |

### mount と umount のオプション

```console
# mount -a                       ← fstab の、noauto でないもの全部
# mount -a -t xfs                ← そのうち、種類が xfs のものだけ
# mount -a -t nonfs,nfs4         ← 種類の前に no を付けると「それ以外」
# mount -o remount,ro /var       ← 外さずにオプションを付け直す
# mount -U 6109cec1-…  /data     ← UUID=… と同じ
# mount -L LOGS /var/log         ← LABEL=… と同じ
# mount --bind /srv/www /var/www ← ディレクトリを別の場所にも見せる（-o bind、-B）
# mount -o loop disk.iso /mnt    ← ファイルをループデバイスにしてマウント
# mount -r /dev/sdb1 /mnt        ← 読み取り専用（-o ro と同じ）
# mount /mnt/usb                 ← fstab に行があれば、片方だけでよい
# umount -a                      ← 全部外す（シャットダウンのとき）
# umount -l /data                ← lazy：今すぐ木から切り離し、使い終わったら片づける
# umount -f /home                ← 強制（応答しない NFS サーバーのとき）
# umount -R /srv                 ← その下にマウントしたものも、まとめて外す
```

| コマンド | オプション | 意味 |
| --- | --- | --- |
| `mount` | `-a` | fstab の全部（`noauto` を除く） |
| | `-t 種類` | 種類を指定。`-a` と組むと、その種類だけに絞る |
| | `-o オプション` | カンマ区切りのマウントオプション |
| | `-r` / `-w` | 読み取り専用 / 読み書き |
| | `-U UUID` / `-L ラベル` | UUID / ラベルで指定 |
| | `-B`、`--bind` | バインドマウント |
| | `-n` | `/etc/mtab` に書かない |
| | `-T ファイル` | `/etc/fstab` の代わりのファイルを読む |
| `umount` | `-a` | 全部外す |
| | `-l` | lazy（切り離しだけ先にする） |
| | `-f` | 強制（届かない NFS） |
| | `-R` | 下のマウントも再帰的に外す |
| | `-r` | 外せなかったら、読み取り専用で付け直す |

:::warn 試験の注意：mount -a は、何をしないか
- `mount -a` は **`noauto` の行をマウントしません**。すでにマウントしてあるものは、そのままです
- `mount -a` は**スワップを有効にしません**。スワップは `swapon -a` の仕事です
- `mount -o remount` は、オプションの付け直しです。別のマウントポイントへ移すことはできません（移すのは `mount --move`）
- コマンドの名前は **`umount`**。`unmount` ではありません
:::

| ファイル | だれが書くか | 特徴 |
| --- | --- | --- |
| `/etc/fstab` | 管理者 | 起動時にマウントする予定。`mount -a`、systemd が読む |
| `/etc/mtab` | 昔は `mount` と `umount` | 昔は普通のファイル。`/` が読み取り専用だと更新できず、**実際とずれることがあった**。`mount -n` は、ここに書かずにマウントする。今のディストリビューションでは **`/proc/self/mounts` へのシンボリックリンク** |
| `/proc/mounts` | カーネル | **カーネルが持つ実際のマウントの表**。`/proc/self/mounts` へのリンクで、そのプロセスから見えるマウントが出る |

Debian 12 でも Rocky Linux 9 でも、`/etc/mtab` はリンクです。

```console
# ls -l /etc/mtab
lrwxrwxrwx 1 root root 19 Nov 16 21:18 /etc/mtab -> ../proc/self/mounts
# grep /data /proc/mounts
/dev/sdb1 /data ext4 rw,relatime 0 0
# mount | grep /data
/dev/sdb1 on /data type ext4 (rw,relatime)
# findmnt /data
TARGET SOURCE    FSTYPE OPTIONS
/data  /dev/sdb1 ext4   rw,relatime
```

`/proc/mounts` の 1 行は、fstab と同じ 6 欄の形です。最後の 2 つ（dump と fsck）は、形を合わせるための飾りで、いつも `0 0` です。4 欄目には、指定しなかった既定のオプション（`relatime` など）も、実際に効いている形で出ます。

小さな Linux で、tmpfs をマウントして確かめます。

```sh run root title="マウントすると /proc/mounts に 1 行増える"
mkdir -p /srv/data
mount -t tmpfs -o size=1m tmpfs /srv/data
grep /srv/data /proc/mounts
mount | grep /srv/data
df -hT /srv/data
```

| 見るコマンド | 表示 |
| --- | --- |
| `mount`（引数なし） | マウントの一覧（`何 on どこ type 種類 (オプション)`） |
| `cat /proc/mounts` | 同じ内容を fstab の形で |
| `findmnt` | 木の形で。`findmnt マウントポイント` で 1 つだけ。`findmnt --verify` は fstab の書きまちがいを調べる |
| `df -hT` | 使用量と種類 |

:::warn 試験の注意：どれが「実際」か
「現在マウントされているファイルシステムを、カーネルの情報から確かめる」なら **`/proc/mounts`**（または `/proc/self/mounts`）です。`/etc/fstab` は予定の表で、手で `mount` したものは載りません。`/etc/mtab` は「mount コマンドが記録するファイル」として問われ、`/proc/mounts` は「カーネルが提供する」として問われます。
:::

## systemd とマウントの順番：fstab は .mount ユニットになる {#systemd-mount}

systemd の Linux では、起動のときに `mount -a` を実行しているのではありません。**`systemd-fstab-generator`** という小さなプログラムが fstab を読み、1 行ごとに **`.mount` ユニット**（スワップは `.swap` ユニット）を作ります。systemd は、それをほかのユニットと同じように、依存の順に起動します（unit については [図解 Linux 17.4](../../linux/site/ch17.html#unit)、[図解 LinuC 1.8](../../linuc/site/ch01.html#boot)）。

```fig graph fstab の 1 行が、起動のたびに .mount ユニットに変換される。作られたユニットは /run/systemd/generator/ に置かれる
{

  nodes: [
    { id: 'f', label: '/etc/fstab', sub: '/var/log の行', x: 0, y: 0, kind: 'static' },
    { id: 'g', label: 'systemd-fstab-generator', sub: '起動時と daemon-reload で動く', x: 1, y: 0, kind: 'accent' },
    { id: 'u', label: 'var-log.mount', sub: '/run/systemd/generator/', x: 2, y: 0, kind: 'crate' },
    { id: 'p', label: 'var.mount', sub: '親のパス。先にマウント', x: 2, y: 1, kind: 'crate' },
    { id: 't', label: 'local-fs.target', sub: 'ローカルのマウントが済んだ印', x: 3, y: 0, kind: 'stack' },
    { id: 'r', label: 'remote-fs.target', sub: 'NFS や _netdev はこちら\nネットワークの後', x: 3, y: 1, kind: 'ext' },
  ],
  edges: [
    { from: 'f', to: 'g' }, { from: 'g', to: 'u' },
    { from: 'p', to: 'u', label: 'After=' }, { from: 'u', to: 't' },
  ],
}
```

### マウントの順番は、何で決まるか

| 場面 | 順番の決まり方 |
| --- | --- |
| `mount -a` | **fstab に書いた順**（上から）。だから `/var` の行は `/var/log` の行より上に書く |
| systemd の起動 | fstab の行の順ではなく、**依存**で決まる。マウントポイントのパスが親子なら、**親（`/var`）が先、子（`/var/log`）が後**になる依存を、systemd が自動で付ける |
| ローカルとネットワーク | ローカルのものは `local-fs.target` の前に。NFS などのネットワークのファイルシステムと `_netdev` の付いたものは、ネットワークが使えるようになった後、`remote-fs.target` の前に |
| fsck | 6 欄目の番号の順（1 → 2）。0 は検査しない |

親が先でなければならない理由は、小さな Linux で確かめられます。親（`/srv/data`）の上に子（`/srv/data/logs`）をマウントすると、子を外すまで親は外せません。外すときは、マウントの逆の順です。

```sh run root error title="子をマウントしたまま、親は外せない"
mkdir /srv/data/logs
mount -t tmpfs tmpfs /srv/data/logs
grep /srv /proc/mounts
umount /srv/data
```

```sh run root title="外すのは、子 → 親の順"
umount /srv/data/logs
umount /srv/data
```

fstab の必須の行（`nofail` も `noauto` もない行）のマウントに失敗すると、`local-fs.target` が失敗し、systemd は**緊急モード**（emergency.target。root のパスワードを聞くシェル）に入ります。fstab の UUID を書きまちがえたときに起きる、よくある起動のトラブルです。このとき、起動の画面や `journalctl -xb` には、次のような行が出ます。装置が現れるのを待ち（既定で 90 秒）、時間切れになっています。

```text
[ TIME ] Timed out waiting for device dev-disk-by\x2duuid-6109cec1….device.
[DEPEND] Dependency failed for data.mount - /data.
[DEPEND] Dependency failed for local-fs.target - Local File Systems.
You are in emergency mode. After logging in, type "journalctl -xb" to view system logs, …
```

直し方は、root でログインし、`/etc/fstab` のその行を直す（か、`#` で止める、`nofail` を付ける）ことです。`/` が読み取り専用なら、先に `mount -o remount,rw /` を実行します。

### .mount ユニットを自分で書く

fstab を使わずに、ユニットのファイルを直接書くこともできます。置き場所は `/etc/systemd/system/` です。

```text
# /etc/systemd/system/var-lib-data.mount
[Unit]
Description=Data volume

[Mount]
What=/dev/disk/by-uuid/6109cec1-643a-4028-8cd9-7dff05eef572
Where=/var/lib/data
Type=ext4
Options=defaults,noatime

[Install]
WantedBy=multi-user.target
```

| 決まり | 中身 |
| --- | --- |
| ファイル名 | **マウントポイントのパスから決まる**。先頭の `/` を取り、残りの `/` を `-` に変えて `.mount` を付ける。`/var/lib/data` → **`var-lib-data.mount`**。`/` そのものは `-.mount` |
| `[Mount]` | `What=`（何を）、`Where=`（どこに）、`Type=`（種類）、`Options=`（オプション）。fstab の 1〜4 欄にあたる |
| `.automount` | 同じ名前の `var-lib-data.automount`（`[Automount]` に `Where=`）を置くと、最初にアクセスされたときにマウントする。fstab なら `x-systemd.automount` |
| `.swap` | スワップのユニット。`/dev/sdb5` → `dev-sdb5.swap`。`[Swap]` に `What=`、`Priority=` |

名前は `systemd-escape` で確かめられます（Debian 12 で実行）。パスの中の `-` は `\x2d` に変わります。

```console
$ systemd-escape -p --suffix=mount /var/lib/data
var-lib-data.mount
$ systemd-escape -p --suffix=mount /srv/my-data
srv-my\x2ddata.mount
# systemctl daemon-reload                 ← fstab やユニットを書き換えたら、必ず
# systemctl start var-lib-data.mount      ← マウントする
# systemctl enable var-lib-data.mount     ← 起動のたびにマウントする
# systemctl status var-lib-data.mount
# systemctl list-units --type=mount       ← .mount ユニットの一覧
```

:::warn 試験の注意：systemd のマウント
- fstab を書き換えただけでは、systemd が持っているユニットは古いままです。**`systemctl daemon-reload`** で作り直します
- `.mount` ユニットの**ファイル名は自由に付けられません**。`Where=` のパスと合っていないと、読み込みに失敗します
- fstab から作られたユニットは **`/run/systemd/generator/`**、自分で書くものは `/etc/systemd/system/`、パッケージのものは `/usr/lib/systemd/system/`
:::

## スワップ：優先度と、有効・無効の切り替え {#swap}

スワップは、`mkswap` で作り、`swapon` で使い始めるのでした（[図解 LinuC 5.10](../../linuc/site/ch05.html#swap)）。レベル2 では、複数のスワップの**優先度**が加わります。

```console
# mkswap -L SW1 /dev/sdb5
Setting up swapspace version 1, size = 400 MiB (419426304 bytes)
LABEL=SW1, UUID=29ecc6cc-225c-4bdf-a0d3-30a2d1acee51
# mkswap /dev/sdc5
Setting up swapspace version 1, size = 400 MiB (419426304 bytes)
no label, UUID=d7326490-7f26-45a6-8e8c-60a1cb4b514f
# swapon -p 10 /dev/sdb5
# swapon /dev/sdc5
# swapon --show
NAME          TYPE       SIZE USED PRIO
/var/lib/swap file      1024M   0B   -2
/dev/sdb5     partition  400M   0B   10
/dev/sdc5     partition  400M   0B   -3
# cat /proc/swaps
Filename                                Type            Size            Used            Priority
/var/lib/swap                           file            1048572         0               -2
/dev/sdb5                               partition       409596          0               10
/dev/sdc5                               partition       409596          0               -3
```

（Debian 12 の Docker で、ループデバイスを使って実行し、デバイス名を読み替えたものです。`/var/lib/swap` は、もともとあったスワップファイルです）

- 優先度は、**数が大きいほうから先に使われます**。上の例では、`/dev/sdb5`（10）が一杯になるまで、ほかは使われません
- `-p` で指定できるのは 0〜32767 です。指定しないと、カーネルが**負の数**を、有効にした順に -2、-3 … と小さくしながら付けます
- **同じ優先度**のスワップが複数あると、順番に少しずつ（ラウンドロビンで）使われます。速さの同じディスクを並べるときに使います
- fstab では、4 欄目に **`pri=10`** と書きます。`swapon -a` と systemd が、これを読みます

| コマンド | すること |
| --- | --- |
| `mkswap [-L ラベル] 装置` | スワップ領域を作る（UUID が付く） |
| `swapon 装置` | 有効にする |
| `swapon -p 数 装置` | 優先度を付けて有効にする |
| `swapon -a` | fstab の swap の行を全部有効にする（`noauto` を除く） |
| `swapon --show`、`swapon -s` | 一覧。`-s` は `/proc/swaps` と同じ表で、古い形 |
| `swapoff 装置`、`swapoff -a` | 無効にする。中身はメモリに戻すので、メモリが足りないと失敗する |
| `free`、`cat /proc/swaps` | 使用量の確認 |

:::tip スワップの大きさを変えるとき
使っているスワップは、そのままでは作り直せません。`swapoff` で止め、`mkswap` で作り直し、`swapon` で戻します。`mkswap` し直すと UUID が変わるので、fstab に UUID で書いているなら、そこも直します（`mkswap -U UUID` で同じ UUID を指定することもできます）。
:::

## UUID を調べる：blkid と lsblk {#blkid}

デバイス名（`/dev/sdb1`）は、ディスクを足したり、つなぐ口を変えたりすると変わります。だから fstab には UUID かラベルで書くのが普通です。調べるコマンドは `blkid` と `lsblk` です。

```console
# blkid /dev/sdb1
/dev/sdb1: LABEL="DATA" UUID="458cfc86-8399-41ac-8665-90fde7e9f2ab" BLOCK_SIZE="1024" TYPE="ext4"
# blkid -s UUID -o value /dev/sdb1         ← UUID の値だけ（スクリプト向き）
458cfc86-8399-41ac-8665-90fde7e9f2ab
# blkid -U 458cfc86-8399-41ac-8665-90fde7e9f2ab   ← UUID → デバイス名
/dev/sdb1
# blkid -L DATA                             ← ラベル → デバイス名
/dev/sdb1
# lsblk -f
NAME   FSTYPE FSVER LABEL UUID                                 FSAVAIL FSUSE% MOUNTPOINTS
sdb
├─sdb1 ext4   1.0   DATA  458cfc86-8399-41ac-8665-90fde7e9f2ab  350.2M     2% /data
└─sdb5 swap   1     SW1   29ecc6cc-225c-4bdf-a0d3-30a2d1acee51                [SWAP]
# lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINT /dev/sdb
# ls -l /dev/disk/by-uuid/
lrwxrwxrwx 1 root root 10 … 458cfc86-8399-41ac-8665-90fde7e9f2ab -> ../../sdb1
```

| コマンド | 表示 |
| --- | --- |
| `blkid [装置]` | UUID、ラベル、種類（TYPE）。引数なしなら全部の装置 |
| `blkid -U UUID` / `blkid -L ラベル` | その UUID / ラベルを持つデバイス名 |
| `blkid -s タグ -o value 装置` | 指定したタグ（UUID、LABEL、TYPE）の値だけ |
| `lsblk` | ディスク、パーティション、LV の木。大きさとマウントポイント |
| `lsblk -f` | 上に、種類、ラベル、UUID を足す |
| `lsblk -o 列,列` | 表示する列を選ぶ |
| `/dev/disk/by-uuid/`、`by-label/` | udev が作るシンボリックリンク。UUID やラベルから実際のデバイスへ |

UUID は、ファイルシステムを作ったとき（`mkfs`、`mkswap`）に付きます。**`mkfs` し直すと UUID は変わります**。UUID だけを変えるには、ext 系は `tune2fs -U`、XFS は `xfs_admin -U` を使います。

## mkfs と mke2fs：作るときに決めること {#mkfs}

`mkfs -t 種類` は `mkfs.種類` を呼ぶ入口で、`-t` を省くと ext2 でした（[図解 LinuC 5.9](../../linuc/site/ch05.html#mkfs)）。ext2・ext3・ext4 を作る本体は **`mke2fs`** で、`mkfs.ext4` は `mke2fs -t ext4` と同じです。

ext4 は、ディスクを**ブロックグループ**に分け、先頭に全体の情報を持つ**スーパーブロック**を置きます（[図解 Linux 11.9](../../linux/site/ch11.html#ext4)）。スーパーブロックが壊れるとマウントできないので、**控え（バックアップスーパーブロック）**が、いくつかのグループの先頭に置かれます。

```fig layout ext4 のスーパーブロックと、その控え。控えの場所は、作るときに表示される。ブロックサイズ 1 KiB なら 8193、4 KiB なら 32768 が最初の控え
{
  unit: 30,
  rows: [
    { label: 'ディスク', cells: [
      { t: 'SB', w: 2, kind: 'accent' },
      { t: 'グループ 0', w: 5, kind: 'stack' },
      { t: '控え', w: 2, kind: 'static' },
      { t: 'グループ 1', w: 5, kind: 'stack' },
      { t: 'グループ 2', w: 5, kind: 'stack' },
      { t: '控え', w: 2, kind: 'static' },
      { t: 'グループ 3 …', w: 5, kind: 'stack' },
    ], note: '控えは、グループ 1、3、5、7、9 … に置かれる（sparse_super）' },
  ],
}
```

```console
# mkfs.ext4 -L DATA -m 1 /dev/sdb1
mke2fs 1.47.0 (5-Feb-2023)
Creating filesystem with 409600 1k blocks and 102400 inodes
Filesystem UUID: 458cfc86-8399-41ac-8665-90fde7e9f2ab
Superblock backups stored on blocks:
        8193, 24577, 40961, 57345, 73729, 204801, 221185, 401409

Allocating group tables: done
Writing inode tables: done
Creating journal (8192 blocks): done
Writing superblocks and filesystem accounting information: done
```

| `mke2fs` のオプション | 意味 |
| --- | --- |
| `-t 種類` | `ext2`、`ext3`、`ext4`。省くと ext2（`mke2fs` として呼んだとき） |
| `-j` | ジャーナルを付ける（= ext3 になる） |
| `-b バイト` | ブロックサイズ（1024、2048、4096） |
| `-i バイト` | **何バイトごとに inode を 1 つ作るか**（bytes-per-inode）。小さくすると inode が増える |
| `-N 数` | inode の数を直接指定する |
| `-m 割合` | **root のための予約ブロック**の割合（%）。既定は **5** |
| `-L ラベル` | ラベルを付ける |
| `-c` | 作る前に、不良ブロックを検査する |
| `-n` | **実際には作らず**、作るとしたらどうなるか（控えの場所など）を表示する |
| `-T 用途` | `/etc/mke2fs.conf` にある用途の型（`small`、`news`、`largefile` など）で、inode の割合などをまとめて選ぶ |
| `-O 機能` | 機能を有効・無効にする（`^has_journal` のように `^` で無効） |

**inode の数は、作るときに決まり、あとから増やせません**。小さなファイルを大量に置く領域（メールのスプールなど）では、`-i` を小さくするか `-N` を大きくして作ります。inode が尽きると、空きブロックがあっても `No space left on device` になります（`df -i` で確かめます。[図解 Linux 11.8](../../linux/site/ch11.html#full)）。

`mke2fs` の既定値は **`/etc/mke2fs.conf`** にあります。Debian 12 のものです。

```text
[defaults]
	base_features = sparse_super,large_file,filetype,resize_inode,dir_index,ext_attr
	default_mntopts = acl,user_xattr
	enable_periodic_fsck = 0
	blocksize = 4096
	inode_size = 256
	inode_ratio = 16384

[fs_types]
	ext3 = {
		features = has_journal
	}
	ext4 = {
		features = has_journal,extent,huge_file,flex_bg,metadata_csum,64bit,dir_nlink,extra_isize
	}
```

ext3 は「ext2 + `has_journal`」、ext4 は、それに `extent` などを足したもの、と読めます。

ほかの種類の `mkfs` は、次のとおりです。

| コマンド | 主なオプション |
| --- | --- |
| `mkfs.xfs` | `-L ラベル`、`-f`（すでにファイルシステムがあっても作る）、`-b size=4096`（ブロックサイズ） |
| `mkfs.btrfs` | `-L ラベル`、`-d 種類`（データの置き方：`single`、`raid0`、`raid1` など）、`-m 種類`（メタデータの置き方）、装置を複数並べられる |
| `mkfs.vfat` | `-n ラベル`、`-F 32`（FAT32） |

## tune2fs と dumpe2fs：ext4 の設定を見る、変える {#tune2fs}

作ったあとの ext2/3/4 の設定は、**`tune2fs`** で変え、**`dumpe2fs`** で見ます。どちらも、マウントポイントではなく**デバイス**を引数に取ります。

```console
# tune2fs -l /dev/sdb1          ← スーパーブロックの中身（抜粋）
Filesystem volume name:   DATA
Filesystem UUID:          458cfc86-8399-41ac-8665-90fde7e9f2ab
Filesystem features:      has_journal ext_attr resize_inode dir_index filetype extent 64bit flex_bg sparse_super large_file huge_file dir_nlink extra_isize metadata_csum
Default mount options:    user_xattr acl
Filesystem state:         clean
Errors behavior:          Continue
Inode count:              102400
Block count:              409600
Reserved block count:     4096
Free blocks:              373344
Free inodes:              102389
Block size:               1024
Mount count:              1
Maximum mount count:      -1
Last checked:             Mon Nov 16 21:19:19 2026
Check interval:           0 (<none>)
# tune2fs -c 20 -i 30d /dev/sdb1
Setting maximal mount count to 20
Setting interval between checks to 2592000 seconds
# tune2fs -m 5 /dev/sdb1
Setting reserved blocks percentage to 5% (20480 blocks)
# tune2fs -O ^has_journal /dev/sdb1     ← ジャーナルを外す（ext2 相当になる）
# tune2fs -j /dev/sdb1                  ← ジャーナルを付ける
Creating journal inode: done
```

| `tune2fs` のオプション | 意味 |
| --- | --- |
| `-l` | スーパーブロックの内容を**表示**する（list） |
| `-c 回数` | **何回マウントしたら** fsck するか（最大マウント回数）。0 か -1 で、回数では検査しない |
| `-C 回数` | 現在のマウント回数を書き換える |
| `-i 間隔` | **前の検査から、どれだけたったら** fsck するか。`30d`（日）、`4w`（週）、`6m`（月）。0 で無効 |
| `-j` | **ジャーナルを追加**する（ext2 → ext3） |
| `-L ラベル` | ラベルを変える（`e2label` と同じ） |
| `-m 割合` | root のための予約ブロックの割合（%）を変える |
| `-r 数` | 予約ブロックを、ブロックの数で指定する |
| `-e 動作` | エラーを見つけたときの動作：`continue`、`remount-ro`、`panic` |
| `-o オプション` | 既定のマウントオプション（`acl`、`user_xattr` など） |
| `-O 機能` | 機能を足す、外す（`^` を付けると外す） |
| `-U UUID` | UUID を変える（`random` で新しく作る） |

`Maximum mount count: -1` と `Check interval: 0` は、「回数でも日数でも、定期的な fsck はしない」という意味です。今の mke2fs の既定はこれです（`mke2fs.conf` の `enable_periodic_fsck = 0`）。`-c` や `-i` を設定すると、起動時の fsck が、その条件で動くようになります。

**予約ブロック**は、一般ユーザーが使い切っても root（とログなどを書くデーモン）が書けるように、残しておく領域です。既定の 5% は、大きなデータ専用の領域ではむだが多いので、`tune2fs -m 1` のように減らすことがあります。

`dumpe2fs` は、スーパーブロックに加えて、ブロックグループごとの情報を全部出します。

```console
# dumpe2fs -h /dev/sdb1                 ← スーパーブロックだけ（tune2fs -l とほぼ同じ）
# dumpe2fs /dev/sdb1 | grep -i superblock
  Primary superblock at 1, Group descriptors at 2-5
  Backup superblock at 8193, Group descriptors at 8194-8197
  Backup superblock at 24577, Group descriptors at 24578-24581
  …
```

| コマンド | すること |
| --- | --- |
| `dumpe2fs 装置` | スーパーブロックと、全ブロックグループの情報（控えのスーパーブロックの場所も） |
| `dumpe2fs -h 装置` | スーパーブロックの情報だけ |
| `tune2fs -l 装置` | スーパーブロックの情報だけ（`dumpe2fs -h` と同じ内容） |
| `e2label 装置 [ラベル]` | ラベルを表示、変更 |
| `resize2fs 装置 [大きさ]` | ext 系の大きさを変える（広げるのはマウントしたままでもできる。縮めるのは外してから） |
| `debugfs 装置` | ext 系の中を対話で調べる（消したファイルの inode を探すなど） |

:::warn 試験の注意：tune2fs の -c、-C、-i と、-j
- 小文字の **`-c` は最大マウント回数**、大文字の `-C` は現在のマウント回数、**`-i` は検査の間隔（時間）**です。`mke2fs` の `-c`（不良ブロックの検査）や `-i`（bytes-per-inode）とは意味が違います
- ext2 を ext3 にするのは **`tune2fs -j`**。データはそのままです。`mkfs.ext3` を実行すると、中身が消えます
- `tune2fs` は ext 系だけの道具です。XFS は `xfs_admin`、Btrfs は `btrfs` を使います
:::

## fsck と e2fsck：検査と修復 {#fsck}

**`fsck`**（file system check）は、ファイルシステムの整合性を検査し、直すコマンドです。`mkfs` と同じく入口で、実際の仕事は `fsck.種類`（ext 系は **`e2fsck`**）がします。

```console
# fsck -N /dev/sdb1                     ← 実行せずに、何を呼ぶかだけ表示
fsck from util-linux 2.38.1
[/usr/sbin/fsck.ext4 (1) -- /dev/sdb1] fsck.ext4 /dev/sdb1
# e2fsck -n /dev/sdb1                   ← 読むだけ。質問には全部 no
DATA: clean, 11/102400 files, 36256/409600 blocks
# e2fsck -f /dev/sdb1                   ← clean でも、強制的に全部調べる
# mount /dev/sdb1 /data
# fsck /dev/sdb1                        ← マウント中は、直せない
e2fsck 1.47.0 (5-Feb-2023)
/dev/sdb1 is mounted.
e2fsck: Cannot continue, aborting.
```

:::warn 試験の注意：fsck はマウントを外してから
**読み書きでマウントしているファイルシステムに fsck を実行すると、ファイルシステムを壊すことがあります**。`umount` してから実行します。`/` は外せないので、起動の途中（読み取り専用でマウントしている間）か、レスキュー用の媒体から起動して検査します。
:::

| `fsck`（入口）のオプション | 意味 |
| --- | --- |
| `-A` | **`/etc/fstab` に書かれた全部**を、6 欄目の順に検査する（起動のときの使い方） |
| `-R` | `-A` と組んで、`/` を飛ばす |
| `-t 種類` | 種類を指定する。`-A` と組むと、その種類だけ |
| `-N` | 実行せず、何をするかを表示する |
| `-M` | マウント中のものは検査しない |
| `-C` | 進み具合を表示する |
| `-V` | くわしく表示する |

| `e2fsck` のオプション | 意味 |
| --- | --- |
| `-p`（`-a` も同じ） | **質問せずに、安全に直せるものを自動で直す**（preen）。人の判断が要る問題があれば、直さずに止まる |
| `-y` | すべての質問に **yes** と答える |
| `-n` | すべての質問に **no** と答える。**何も書き換えない** |
| `-f` | 状態が clean でも、強制的に検査する |
| `-b 番号` | **控えのスーパーブロック**を使って検査する |
| `-c` | 不良ブロックを探して、使わないリストに入れる |
| `-v` | くわしく表示する |

`-p`、`-y`、`-n` は、同時には 1 つしか指定できません。

### スーパーブロックが壊れたとき

先頭のスーパーブロックを壊すと、マウントできなくなります。控えを指定して直します（Debian 12 で、わざと壊して確かめたものです）。

```console
# mount /dev/sdb1 /data
mount: /data: wrong fs type, bad option, bad superblock on /dev/sdb1, missing codepage or helper program, or other error.
# mke2fs -n /dev/sdb1                   ← 控えの場所を調べる（-n なので作らない）
Superblock backups stored on blocks:
        8193, 24577, 40961, 57345, 73729, 204801, 221185, 401409
# e2fsck -b 8193 /dev/sdb1              ← 控えを使って修復
```

控えの場所は、`dumpe2fs` でも見られますが、先頭のスーパーブロックが読めないと `dumpe2fs` も失敗します。そのときは、作ったときと同じオプションで `mke2fs -n` を実行して調べます（**`-n` を忘れると、本当に作り直されて、中身が消えます**）。今の `e2fsck` は、先頭が壊れていると、自分で控えを探して使ってくれます。

検査で見つかった「どのディレクトリからも指されていないファイル」は、そのファイルシステムの一番上の **`lost+found`** ディレクトリに、inode 番号の名前でつながれます。

### 終了ステータス

`fsck` の終了ステータスは、次の数の**足し算**です。起動のスクリプトは、これを見て、再起動するか止まるかを決めます。

| 値 | 意味 |
| --- | --- |
| 0 | エラーなし |
| 1 | エラーがあり、**直した** |
| 2 | 直した。**再起動が必要** |
| 4 | エラーが**直らずに残っている** |
| 8 | 実行そのものの失敗（マウント中だった、など） |
| 16 | 使い方や文法のまちがい |
| 32 | 利用者が中断した |
| 128 | 共有ライブラリのエラー |

:::note XFS と Btrfs の fsck
`fsck.xfs` と `fsck.btrfs` は、**何もせずに成功（0）を返すだけ**のコマンドです。起動時の `fsck -A` がエラーにならないように置いてあります。実際の検査と修復は、XFS は `xfs_repair`（[2.11](#xfs)）、Btrfs は `btrfs check`（[2.12](#btrfs)）でします。
:::

## dump と restore：ext のバックアップ {#dump}

**`dump`** は、ext2/3/4 のファイルシステムを、まるごとバックアップするコマンドです。`tar` と違って、**レベル**（0〜9）を使った増分バックアップの仕組みを、自分で持っています。戻すのは **`restore`** です。

| レベル | 取るもの |
| --- | --- |
| **0** | 全部（フルバックアップ） |
| 1〜9 | **自分より小さいレベルの、最後のバックアップ**より後に変わったファイル |

たとえば、日曜にレベル 0、月曜から土曜に毎日レベル 1 を取ると、毎日「日曜からの変更ぶん」が取れます（差分）。月曜にレベル 1、火曜にレベル 2、水曜にレベル 3 と上げていくと、毎日「前の日からの変更ぶん」だけが取れます（増分）。

```console
# dump -0u -f /backup/data.0.dump /data
  DUMP: Date of this level 0 dump: Mon Nov 16 21:19:41 2026
  DUMP: Dumping /dev/sdb1 (/data) to /backup/data.0.dump
  …
  DUMP: DUMP IS DONE
# echo new > /data/c.txt
# dump -1u -f /backup/data.1.dump /data
# cat /var/lib/dumpdates                      ← Debian。昔からの場所は /etc/dumpdates
/data 0 Mon Nov 16 21:19:41 2026 +0000
/data 1 Mon Nov 16 21:19:41 2026 +0000
# dump -W                                      ← ファイルシステムごとに、最後に取った日時とレベルを表示
```

| `dump` のオプション | 意味 |
| --- | --- |
| `-0`〜`-9` | レベル。0 が全部 |
| `-u` | 取った日時とレベルを **dumpdates ファイル**（`/etc/dumpdates`。Debian は `/var/lib/dumpdates`）に**記録する**。次の増分の基準になる |
| `-f 出力先` | 書き出すファイルかデバイス（`/dev/st0` などのテープ、`-` で標準出力） |
| `-z`、`-j` | zlib / bzlib で圧縮する |
| `-W`、`-w` | fstab と dumpdates を見て、ファイルシステムごとの最後のバックアップを表示する（`-w` は、取る必要があるものだけ） |

`-u` を付けないと、dumpdates に記録が残らず、次のレベル 1 が「どこからの変更か」を決められません。fstab の 5 欄目（dump）は、`dump -W` や `-w` が「取るべきファイルシステム」を探すときに見ます。

```console
# restore -tf /backup/data.0.dump              ← 中身の一覧
Level 0 dump of /data on host:/dev/sdb1
         2	.
        11	./lost+found
        12	./a.txt
     65537	./dir
     65538	./dir/b.txt
# cd /restore
# restore -rf /backup/data.0.dump              ← 全部を、いまのディレクトリに戻す
# restore -rf /backup/data.1.dump              ← 続けて、レベル 1 を重ねる
# ls
a.txt  c.txt  dir  lost+found  restoresymtable
```

| `restore` のオプション | 意味 |
| --- | --- |
| `-r` | ファイルシステム全体を**作り直す**（rebuild）。新しく `mkfs` した所へ、レベル 0 から順に重ねる |
| `-x [ファイル…]` | 指定したファイルやディレクトリだけを**取り出す**（extract） |
| `-i` | **対話**で、取り出すものを選ぶ（`ls`、`cd`、`add`、`extract`） |
| `-t` | 中身の**一覧**を表示する |
| `-C` | バックアップと、いまのファイルシステムを**比べる** |
| `-f ファイル` | 読むファイルかデバイス |

`restore` は、**いまいるディレクトリ**に戻します。だから、先に戻す先へ `cd` します。`-r` で戻すと、増分を重ねるための記録として `restoresymtable` というファイルができます。全部戻し終わったら消します。

:::warn 試験の注意：dump と restore
- **レベル 0 がフルバックアップ**。数が大きいほど「全部」ではありません
- 戻す順は、**レベル 0 → 1 → 2 …**（小さいほうから）
- `dump` は ext 系の道具です。XFS には `xfsdump`、どのファイルシステムでも使えるのは `tar` や `rsync` です
- 動いているファイルシステムを dump すると、途中で変わったファイルが正しく取れないことがあります。外すか、読み取り専用にするか、LVM のスナップショット（[2.15](#lvm-ops)）を取ってそれを dump します
:::

## XFS：xfs_info、xfs_repair、xfsdump {#xfs}

XFS は、Red Hat 系の標準のファイルシステムです。道具は `xfs_` で始まる別のコマンドになっていて、ext 系の道具（`tune2fs`、`e2fsck`、`dump`）は使えません。

| すること | ext2/3/4 | XFS |
| --- | --- | --- |
| 作る | `mkfs.ext4`（`mke2fs`） | `mkfs.xfs` |
| 情報を見る | `tune2fs -l`、`dumpe2fs` | **`xfs_info`** |
| 設定を変える | `tune2fs` | `xfs_admin` |
| 検査、修復 | `e2fsck`（`fsck`） | **`xfs_repair`**（昔は検査に `xfs_check`） |
| 広げる | `resize2fs` | `xfs_growfs`（マウントしたまま。**縮められない**） |
| バックアップ | `dump` / `restore` | **`xfsdump` / `xfsrestore`** |
| 中を調べる | `debugfs` | `xfs_db` |

```console
# mkfs.xfs -L XDATA /dev/sdc1
# mount /dev/sdc1 /data
# xfs_info /data
meta-data=/dev/sdc1              isize=512    agcount=4, agsize=25600 blks
         =                       sectsz=512   attr=2, projid32bit=1
         =                       crc=1        finobt=1, sparse=1, rmapbt=0
data     =                       bsize=4096   blocks=102400, imaxpct=25
naming   =version 2              bsize=4096   ascii-ci=0, ftype=1
log      =internal log           bsize=4096   blocks=16384, version=2
realtime =none                   extsz=4096   blocks=0, rtextents=0
```

`xfs_info` は、ブロックサイズ（`bsize`）、ブロックの数、**アロケーショングループ**の数（`agcount`。ext4 のブロックグループにあたり、グループごとに並行して割り当てができる）、ログ（ジャーナル）の場所を表示します。`mkfs.xfs` が作るときに表示するものと同じ形です。

### 検査と修復

```console
# xfs_repair /dev/sdc1                  ← マウント中は実行できない
xfs_repair: /dev/sdc1 contains a mounted filesystem
fatal error -- couldn't initialize XFS library
# umount /data
# xfs_repair -n /dev/sdc1               ← 検査だけ（書き換えない）
# xfs_repair /dev/sdc1                  ← 修復
Phase 1 - find and verify superblock...
…
Phase 7 - verify and correct link counts...
done
# fsck /dev/sdc1                        ← fsck.xfs は何もしない
If you wish to check the consistency of an XFS filesystem or
repair a damaged filesystem, see xfs_repair(8).
```

| コマンド | すること |
| --- | --- |
| `xfs_repair 装置` | 修復する。**マウントを外して**から |
| `xfs_repair -n 装置` | 検査だけして、**書き換えない**（no modify） |
| `xfs_repair -L 装置` | ログ（ジャーナル）を捨ててから修復する。**最後の手段**（書きかけの変更が失われる） |
| `xfs_check 装置` | 昔の検査コマンド。**今の xfsprogs にはなく、`xfs_repair -n` が代わり** |
| `xfs_admin -L ラベル 装置` | ラベルを変える（`-l` で表示）。`-U` で UUID を変える（`-u` で表示）。マウントを外してから |
| `xfs_growfs マウントポイント` | 広げる。**マウントしたまま**実行する |
| `xfs_db 装置` | 中を調べるデバッガ |
| `xfs_fsr` | 断片化を直す（マウントしたまま） |

XFS は、電源が落ちたあとの最初の**マウントのとき**に、ログを読んで整合性を取り戻します。だから、ログに書きかけの変更が残っている XFS に `xfs_repair` をかけると、「先にマウントしてログを反映せよ」と言われます。マウントもできないほど壊れているときにだけ、`-L` でログを捨てます。

### xfsdump と xfsrestore

```console
# xfsdump -l 0 -L sess0 -M media0 -f /backup/x.0.xfsdump /data
xfsdump: /var/lib/xfsdump/inventory created
xfsdump: dumping ino map
xfsdump: dumping directories
xfsdump: dumping non-directory files
xfsdump: Dump Status: SUCCESS
# xfsdump -l 1 -L sess1 -M media1 -f /backup/x.1.xfsdump /data
# xfsdump -I                                   ← これまでのバックアップの記録（インベントリ）
file system 0:
	fs id:		3e023313-6e09-4e7c-bbc3-fc1be1ccb952
	session 0:
		mount point:	host:/data
		device:		host:/dev/sdc1
		session label:	"sess0"
		level:		0
# xfsrestore -t -f /backup/x.0.xfsdump          ← 中身の一覧
# xfsrestore -f /backup/x.0.xfsdump /restore    ← /restore に戻す
# xfsrestore -r -f /backup/x.0.xfsdump /restore ← 増分を重ねるとき：レベル 0 から順に -r で
# xfsrestore -r -f /backup/x.1.xfsdump /restore
```

| `xfsdump` | 意味 |
| --- | --- |
| `-l レベル` | 0〜9。**0 が全部**。考え方は `dump` と同じ |
| `-f 出力先` | 書き出すファイルかテープ |
| `-L ラベル` | このバックアップ（セッション）のラベル。省くと対話で聞かれる |
| `-M ラベル` | 媒体のラベル。省くと対話で聞かれる |
| `-I` | インベントリ（`/var/lib/xfsdump/inventory/` にある記録）を表示する |

| `xfsrestore` | 意味 |
| --- | --- |
| `-f 入力元` | 読むファイルかテープ |
| `-r` | 増分を順に重ねて戻す（cumulative） |
| `-t` | 中身の一覧だけ |
| `-i` | 対話で選ぶ |
| 最後の引数 | **戻す先のディレクトリ**（`restore` と違い、引数で渡す） |

:::warn 試験の注意：xfsdump は「マウントした」XFS を取る
`xfsdump` の対象は、**マウントされている XFS**（マウントポイントか、そのデバイス）です。外した状態のデバイスを渡すと失敗します。逆に、`xfs_repair` と `xfs_admin` は**外してから**、`xfs_growfs` と `xfs_info` は**マウントしたまま**使います。`dump` の dumpdates にあたる記録は、`xfsdump` では**インベントリ**（`/var/lib/xfsdump/inventory/`）です。
:::

## Btrfs：サブボリュームとスナップショット {#btrfs}

**Btrfs** は、コピーオンライト（書き換えるときに、元を残して別の場所に書く）で作られたファイルシステムです。LVM がしていた「領域を分ける」「スナップショットを取る」「ディスクを足す」を、ファイルシステム自身が持っています。操作はすべて **`btrfs`** コマンドのサブコマンドです。

```fig tree Btrfs の中。サブボリュームは、ディレクトリのように見える「別の木」。スナップショットも、サブボリュームの 1 つ
{
  root: { label: '/data（最上位のサブボリューム、ID 5）', kind: 'dir', children: [
    { label: 'home', kind: 'dir', hl: true, note: 'サブボリューム ID 256', children: [
      { label: 'f', note: 'ファイル' },
    ] },
    { label: 'var', kind: 'dir', hl: true, note: 'サブボリューム ID 257' },
    { label: 'home-snap', kind: 'dir', note: 'home のスナップショット（書ける）ID 258' },
    { label: 'home-ro', kind: 'dir', note: 'home のスナップショット（-r：読み取り専用）ID 259' },
  ] },
}
```

**サブボリューム**は、1 つの Btrfs の中に作る、独立した木です。見た目はディレクトリですが、それぞれを別々にマウントでき、別々にスナップショットを取れます。パーティションと違って、大きさを決めずに作れ、空き領域は全体で共有します。

```console
# mkfs.btrfs -L BT /dev/sdd
# mount /dev/sdd /data
# btrfs subvolume create /data/home
Create subvolume '/data/home'
# btrfs subvolume create /data/var
# btrfs subvolume snapshot /data/home /data/home-snap
Create a snapshot of '/data/home' in '/data/home-snap'
# btrfs subvolume snapshot -r /data/home /data/home-ro
Create a readonly snapshot of '/data/home' in '/data/home-ro'
# touch /data/home-ro/z
touch: cannot touch '/data/home-ro/z': Read-only file system
# btrfs subvolume list /data
ID 256 gen 8 top level 5 path home
ID 257 gen 7 top level 5 path var
ID 258 gen 7 top level 5 path home-snap
ID 259 gen 8 top level 5 path home-ro
# mount -o subvol=home /dev/sdd /mnt/x          ← サブボリュームだけをマウント
# grep /mnt/x /proc/mounts
/dev/sdd /mnt/x btrfs rw,relatime,ssd,discard=async,space_cache=v2,subvolid=256,subvol=/home 0 0
# btrfs subvolume delete /data/home-snap
```

**スナップショット**は、あるサブボリュームの「その瞬間の姿」を持つ、新しいサブボリュームです。コピーオンライトなので、**作った瞬間にはデータをコピーせず、すぐ終わり、領域もほとんど使いません**。元とスナップショットは同じブロックを共有し、どちらかが書き換えられたブロックだけが別になります。既定では**書けるスナップショット**で、`-r` を付けると読み取り専用になります。

| コマンド | すること |
| --- | --- |
| `btrfs subvolume create パス` | サブボリュームを作る |
| `btrfs subvolume list パス` | サブボリュームの一覧（ID とパス） |
| `btrfs subvolume snapshot [-r] 元 先` | スナップショットを作る。`-r` で読み取り専用 |
| `btrfs subvolume delete パス` | サブボリューム（スナップショットも）を消す |
| `btrfs subvolume set-default ID パス` | `subvol=` を付けずにマウントしたときに見えるサブボリュームを変える |
| `btrfs subvolume show パス` | 1 つのサブボリュームのくわしい情報 |
| `mount -o subvol=名前`、`-o subvolid=ID` | そのサブボリュームをマウントする |
| `btrfs filesystem show` | Btrfs の一覧と、使っている装置 |
| `btrfs filesystem df パス`、`usage パス` | データとメタデータの使用量（`df` より正確） |
| `btrfs filesystem resize 大きさ パス` | 大きさを変える（`+1g`、`-1g`、`max`）。マウントしたまま |
| `btrfs device add 装置 パス`、`device remove` | 装置を足す、外す（マウントしたまま） |
| `btrfs balance start パス` | 装置のあいだでデータを配り直す。`-dconvert=raid1` などで置き方を変える |
| `btrfs scrub start パス` | 全部のデータを読んで、チェックサムを確かめる（マウントしたまま） |
| `btrfs check 装置` | 整合性の検査（**マウントを外して**から）。`fsck.btrfs` は何もしない |

fstab には、サブボリュームごとに 1 行ずつ書きます。

```text
UUID=df60c60d-d538-4065-9b83-13fb64587004  /home  btrfs  subvol=home,defaults  0  0
UUID=df60c60d-d538-4065-9b83-13fb64587004  /var   btrfs  subvol=var,defaults   0  0
```

同じ UUID（同じ Btrfs）が 2 行に出てきて、`subvol=` だけが違います。6 欄目（fsck）は 0 にします。

### btrfs-convert：ext4 を、中身ごと Btrfs に変える

**`btrfs-convert`** は、ext2/3/4 を、**中のファイルを残したまま** Btrfs に変換します。対象はマウントを外しておきます。

```console
# btrfs-convert /dev/sdb1
Create initial btrfs filesystem
Create ext2 image file
Create btrfs metadata
Conversion complete
# blkid /dev/sdb1
/dev/sdb1: UUID="eff21c25-…" BLOCK_SIZE="4096" TYPE="btrfs"
# mount /dev/sdb1 /data; ls /data
ext2_saved  keep.txt  lost+found
# btrfs subvolume list /data
ID 256 gen 3 top level 5 path ext2_saved
# umount /data
# btrfs-convert -r /dev/sdb1             ← 元の ext4 に戻す（rollback）
Rollback succeeded
```

変換すると、元の ext のイメージが **`ext2_saved`** というサブボリュームに残ります。これがある間は、**`btrfs-convert -r`** で元に戻せます。戻す必要がなくなったら、`btrfs subvolume delete /data/ext2_saved` で消して、領域を空けます（消したら、もう戻せません）。

:::warn 試験の注意：Btrfs
- スナップショットを作るのは **`btrfs subvolume snapshot`**。`btrfs snapshot create` ではありません。スナップショットは「サブボリュームの一種」です
- 読み取り専用は **`-r`**。付けなければ書けます（LVM のスナップショットとは別の仕組みで、領域の大きさも指定しません）
- 最上位のサブボリュームの ID は **5** です。作ったサブボリュームは 256 から始まります
- `btrfs-convert` の元に戻すオプションは **`-r`**（`--rollback`）です
:::

## smartd と smartctl：ディスクの故障の前ぶれを見る {#smart}

**S.M.A.R.T.**（Self-Monitoring, Analysis and Reporting Technology）は、HDD や SSD が自分の状態（読み取りエラーの数、代わりのセクタに置き換えた数、温度、通電時間など）を記録して、報告する仕組みです。Linux では **smartmontools** パッケージの 2 つのプログラムで使います。

| プログラム | 役割 |
| --- | --- |
| **`smartctl`** | コマンド。その場でディスクの S.M.A.R.T. の情報を読み、自己診断を始める |
| **`smartd`** | デーモン。定期的に（既定は 30 分ごと）ディスクを調べ、異常を syslog に書き、メールで知らせる |

```console
# smartctl -i /dev/sda               ← 型番、シリアル番号、S.M.A.R.T. に対応しているか
# smartctl -H /dev/sda               ← 健康状態の判定
SMART overall-health self-assessment test result: PASSED
# smartctl -a /dev/sda               ← S.M.A.R.T. の情報を全部
# smartctl -A /dev/sda               ← 属性（Reallocated_Sector_Ct、Temperature_Celsius など）の表
# smartctl -t short /dev/sda         ← 短い自己診断を始める（数分。裏で進む）
# smartctl -t long /dev/sda          ← 長い自己診断（全面を読む。数時間）
# smartctl -l selftest /dev/sda      ← 自己診断の結果の記録
# smartctl -l error /dev/sda         ← エラーの記録
# smartctl -s on /dev/sda            ← S.M.A.R.T. を有効にする
```

| `smartctl` のオプション | 意味 |
| --- | --- |
| `-i`、`--info` | 装置の情報（型番、容量、対応の有無） |
| `-H`、`--health` | 健康状態（PASSED / FAILED） |
| `-a`、`--all` | S.M.A.R.T. の情報を全部（`-x` は、さらに全部） |
| `-A`、`--attributes` | 属性の表 |
| `-c`、`--capabilities` | 対応している機能と、自己診断にかかる時間 |
| `-t 種類`、`--test=種類` | 自己診断を始める：`short`、`long`、`offline`、`conveyance` |
| `-X`、`--abort` | 実行中の自己診断を止める |
| `-l 種類`、`--log=種類` | 記録を表示：`error`、`selftest` |
| `-s on` / `-s off`、`--smart=` | S.M.A.R.T. を有効 / 無効にする |
| `-d 種類`、`--device=` | 装置の種類を指定（`ata`、`scsi`、`nvme`、`megaraid,N` など。RAID カードの裏のディスクを見るとき） |
| `--scan` | 装置を探して一覧にする |

`-t` は診断を**始めるだけ**で、結果は表示しません。終わったころに `-l selftest` で見ます。

### smartd と smartd.conf

`smartd` の設定ファイルは **`smartd.conf`** です。場所は、Debian 系が **`/etc/smartd.conf`**、Red Hat 系が **`/etc/smartmontools/smartd.conf`** です。1 行に、装置と、その装置への指示（ディレクティブ）を書きます。

```text
# Debian 12 の既定
DEVICESCAN -d removable -n standby -m root -M exec /usr/share/smartmontools/smartd-runner

# 装置ごとに書く例
/dev/sda -a -o on -S on -s (S/../.././02|L/../../6/03) -m admin@example.com
/dev/sdb -H -m admin@example.com
```

| 書くもの | 意味 |
| --- | --- |
| `DEVICESCAN` | 見つかった装置を全部、監視する。**この行より後の行は読まれない** |
| `/dev/sda` | 監視する装置を、名前で書く |
| `-a` | よく使う監視を全部有効にする（`-H`、`-f`、`-t`、`-l error`、`-l selftest` などをまとめたもの） |
| `-H` | 健康状態だけを見る |
| `-m アドレス` | 異常のときに、**メールを送る先** |
| `-M exec プログラム` | メールの代わりに、プログラムを実行する。`-M test` は、起動時に試しのメールを送る |
| `-s 正規表現` | **自己診断の予定**。`種類/月/日/曜日/時` の形。`S/../.././02` は「毎日 2 時に短い診断」、`L/../../6/03` は「毎週土曜 3 時に長い診断」 |
| `-d 種類` | 装置の種類（`smartctl -d` と同じ） |
| `-n standby` | ディスクが止まって（スタンバイで）いたら、起こさずに飛ばす |
| `-W 差,情報,危険` | 温度の監視 |

サービスの名前は `smartd` です（`systemctl enable --now smartd`。Debian では `smartmontools.service` が本名で、`smartd.service` は別名）。調べる間隔は、`smartd -i 秒` で変えます（既定 1800 秒）。異常は、syslog（journal）に `smartd` の名前で記録されます。

:::note S.M.A.R.T. でわかること、わからないこと
S.M.A.R.T. は、**ディスクという装置**の状態を見るもので、ファイルシステムの整合性は見ません。ファイルシステムの検査は `fsck` です。また、`PASSED` でも、ある日突然壊れるディスクはあります。代わりのセクタの数（Reallocated_Sector_Ct）が増え続けていたら、判定が `PASSED` でも交換を考えます。
:::

## LVM の復習と、調べるコマンド：pv*、vg*、lv* {#lvm}

LVM は、ディスクを **PV**（物理ボリューム）にし、PV を束ねて **VG**（ボリュームグループ）を作り、VG から **LV**（論理ボリューム）を切り出すのでした（[図解 LinuC 5.8](../../linuc/site/ch05.html#lvm)）。レベル2 では、その中の単位である **PE** と、3 つの層それぞれのコマンドの組が問われます。

```fig graph VG は PE（物理エクステント）という同じ大きさのかけらの集まり。LV は、PE をいくつか借りて並べたもの（LE）。PE がどの PV にあるかは、LV からは見えない
{
  col: 205, row: 84,
  nodes: [
    { id: 'pv1', label: 'PV /dev/sdb', sub: 'PE 0〜48', x: 0, y: 0, kind: 'ext' },
    { id: 'pv2', label: 'PV /dev/sdc', sub: 'PE 0〜48', x: 0, y: 1, kind: 'ext' },
    { id: 'vg', label: 'VG vg01', sub: 'PE 98 個（1 個 8 MiB）\nvgcreate -s 8M', x: 1, y: 0.5, kind: 'accent' },
    { id: 'lv1', label: 'LV lv_data', sub: 'LE 25 個 = 200 MiB\nlvcreate -L 200M', x: 2, y: 0, kind: 'crate' },
    { id: 'lv2', label: 'LV lv_log', sub: 'LE 10 個 = 80 MiB\nlvcreate -l 10', x: 2, y: 1, kind: 'crate' },
    { id: 'fs1', label: '/dev/vg01/lv_data', sub: 'この上に mkfs、mount', x: 3, y: 0, kind: 'stack' },
    { id: 'fs2', label: '/dev/mapper/vg01-lv_log', sub: '同じものの、もう 1 つの名前の形', x: 3, y: 1, kind: 'stack' },
  ],
  edges: [
    { from: 'pv1', to: 'vg' }, { from: 'pv2', to: 'vg' },
    { from: 'vg', to: 'lv1' }, { from: 'vg', to: 'lv2' },

```

- **PE**（Physical Extent、物理エクステント）は、VG を区切る単位です。大きさは **`vgcreate -s`** で決め、既定は **4 MiB** です。VG を作ったあとは変えられません
- **LE**（Logical Extent）は、LV から見た単位で、大きさは PE と同じです。LV の大きさは、必ず PE の倍数になります（`-L +100M` が 104 MiB に丸められる、というように）
- `lvcreate -L 200M` は**大きさ**で、`lvcreate -l 10` は **PE の個数**で指定します。`-l 100%FREE` は「VG の空き全部」、`-l 50%VG` は「VG の半分」です

400 MiB のディスク 2 台で作った例です（Debian 12、Docker のループデバイスで実行し、デバイス名を読み替えました）。

```console
# pvcreate /dev/sdb /dev/sdc /dev/sdd
# vgcreate -s 8M vg01 /dev/sdb /dev/sdc
  Volume group "vg01" successfully created
# lvcreate -L 200M -n lv_data vg01
# lvcreate -l 10 -n lv_log vg01
# pvs

  /dev/sdb   vg01 lvm2 a--  392.00m 112.00m
  /dev/sdc   vg01 lvm2 a--  392.00m 392.00m
  /dev/sdd        lvm2 ---  400.00m 400.00m
# vgs
  VG   #PV #LV #SN Attr   VSize   VFree
  vg01   2   2   0 wz--n- 784.00m 504.00m
# lvs
  LV      VG   Attr       LSize   Pool Origin Data%  Meta%  Move Log Cpy%Sync Convert
  lv_data vg01 -wi-a----- 200.00m
  lv_log  vg01 -wi-a-----  80.00m
# lvscan
  ACTIVE            '/dev/vg01/lv_data' [200.00 MiB] inherit
  ACTIVE            '/dev/vg01/lv_log' [80.00 MiB] inherit
# vgdisplay vg01 | grep -E 'PE|Size'
  VG Size               784.00 MiB
  PE Size               8.00 MiB
  Total PE              98
  Alloc PE / Size       35 / 280.00 MiB
  Free  PE / Size       63 / 504.00 MiB
```

`/dev/sdd` は、PV にはしたが、まだどの VG にも入っていません（`pvs` の VG の欄が空）。

3 つの層に、同じ形のコマンドが並びます。

| すること | PV | VG | LV |
| --- | --- | --- | --- |
| 作る | `pvcreate` | `vgcreate` | `lvcreate` |
| 1 行ずつの一覧 | `pvs` | `vgs` | `lvs` |
| くわしく表示 | `pvdisplay` | `vgdisplay` | `lvdisplay` |
| 探して一覧にする | `pvscan` | `vgscan` | `lvscan` |
| 属性を変える | `pvchange` | `vgchange` | `lvchange` |
| 消す | `pvremove` | `vgremove` | `lvremove` |
| 大きさを変える | `pvresize` | `vgextend`、`vgreduce` | `lvextend`、`lvreduce`、`lvresize` |
| 名前を変える | — | `vgrename` | `lvrename` |
| そのほか | `pvmove`（中身を移す）、`pvck` | `vgcfgbackup`、`vgcfgrestore`、`vgexport`、`vgimport`、`vgck` | `lvconvert` |

これらは全部、**`lvm`** という 1 つのプログラムのサブコマンドです（`pvs` は `lvm` へのシンボリックリンク）。`lvm pvs` と書いても同じで、引数なしで `lvm` を実行すると、`lvm>` というプロンプトの対話のシェルになります。`lvm version` はバージョンを、`lvm help` はコマンドの一覧を表示します。

:::warn 試験の注意：ない名前に注意
- PV は「広げる」のではなく、下のパーティションを広げたあとに **`pvresize`** で合わせます。`pvextend` はありません
- VG に PV を足すのは **`vgextend`**、外すのは **`vgreduce`**。`vgresize` はありません
- LV は `lvextend`、`lvreduce`、**`lvresize`**（どちらもできる）の 3 つがあります
- `pvrename` はありません。PV の名前は、デバイス名そのものです
:::

## LVM を動かしたまま変える：広げる、移す、止める {#lvm-ops}

### LV とファイルシステムを広げる、縮める

```console
# lvextend -L +100M -r vg01/lv_data
  Rounding size to boundary between physical extents: 104.00 MiB.
  Size of logical volume vg01/lv_data changed from 200.00 MiB (25 extents) to 304.00 MiB (38 extents).
  Logical volume vg01/lv_data successfully resized.
resize2fs 1.47.0 (5-Feb-2023)
Filesystem at /dev/mapper/vg01-lv_data is mounted on /data; on-line resizing required
# umount /data
# lvreduce -L 150M -r vg01/lv_data
Resizing the filesystem on /dev/mapper/vg01-lv_data to 155648 (1k) blocks.
  Size of logical volume vg01/lv_data changed from 304.00 MiB (38 extents) to 152.00 MiB (19 extents).
```

| 向き | 順番 | コマンド |
| --- | --- | --- |
| **広げる** | **LV → ファイルシステム** | `lvextend -L +量 LV` のあと、ext は `resize2fs 装置`、XFS は `xfs_growfs マウントポイント`。または `lvextend -r` でまとめて |
| **縮める** | **ファイルシステム → LV** | `umount` → `e2fsck -f` → `resize2fs 装置 大きさ` → `lvreduce -L 大きさ LV`。または `lvreduce -r` でまとめて。**XFS は縮められない** |

`-L +100M` は「100 MiB 足す」、`-L 100M` は「100 MiB にする」です。`+` の有無で意味が変わります。順番を逆にして、ファイルシステムより先に LV を縮めると、ファイルシステムの後ろが切り落とされて壊れます。

### ディスクを入れ替える：vgextend、pvmove、vgreduce

古いディスク（`/dev/sdb`）を、サービスを止めずに新しいディスク（`/dev/sdd`）に入れ替える手順です。

```fig graph ディスクの入れ替え。pvmove は、使っている PE を、同じ VG のほかの PV へ移す。LV はマウントしたままでよい
{

  nodes: [
    { id: 'a', label: '1. vgextend', sub: 'vgextend vg01 /dev/sdd\n新しい PV を VG に足す', x: 0, y: 0, kind: 'stack' },
    { id: 'b', label: '2. pvmove', sub: 'pvmove /dev/sdb /dev/sdd\nPE を新しい PV へ移す', x: 1, y: 0, kind: 'accent' },
    { id: 'c', label: '3. vgreduce', sub: 'vgreduce vg01 /dev/sdb\n空になった PV を VG から外す', x: 2, y: 0, kind: 'stack' },
    { id: 'd', label: '4. pvremove', sub: 'pvremove /dev/sdb\nPV の印を消す', x: 3, y: 0, kind: 'ext' },
  ],
  edges: [ { from: 'a', to: 'b' }, { from: 'b', to: 'c' }, { from: 'c', to: 'd' } ],

```

```console
# vgextend vg01 /dev/sdd
  Volume group "vg01" successfully extended
# pvmove /dev/sdb /dev/sdd            ← 移す先を省くと、VG のほかの PV の空きへ
# vgreduce vg01 /dev/sdb
# pvremove /dev/sdb

```

`pvmove` をせずに外そうとすると、こうなります。

```console
# vgreduce vg01 /dev/sdb
  Physical volume "/dev/sdb" still in use
# pvremove /dev/sdb
  PV /dev/sdb is used by VG vg01 so please use vgreduce first.
```

### 有効と無効、名前、ほかのマシンへの移動

```console
# vgchange -an vg01                   ← VG の中の LV を全部、無効にする（/dev/vg01/ が消える）
  0 logical volume(s) in volume group "vg01" now active
# lvscan
  inactive          '/dev/vg01/lv_data' [200.00 MiB] inherit
  inactive          '/dev/vg01/lv_log' [80.00 MiB] inherit
# vgchange -ay vg01                   ← 有効にする
  2 logical volume(s) in volume group "vg01" now active
# lvchange -an vg01/lv_log            ← LV を 1 つだけ無効にする
# lvrename vg01 lv_log lv_logs
  Renamed "lv_log" to "lv_logs" in volume group "vg01"
# vgrename vg01 vg02
  Volume group "vg01" successfully renamed to "vg02"
# vgchange -an vg02; vgexport vg02    ← ほかのマシンへ持っていく前に
  Volume group "vg02" successfully exported
# vgimport vg02                       ← 持っていった先で
```

| コマンド | すること |
| --- | --- |
| `vgchange -ay [VG]` / `-an [VG]` | VG の中の LV を、有効（activate）/ 無効にする。有効な LV だけが `/dev/VG/LV` に見える |
| `lvchange -ay LV` / `-an LV` | LV を 1 つだけ、有効 / 無効にする |
| `vgscan`、`pvscan`、`lvscan` | ディスクを調べて、VG・PV・LV を探す。レスキュー用の媒体から起動したときは、`vgscan` のあと `vgchange -ay` で LV が使えるようになる |
| `vgexport VG` → `vgimport VG` | VG を、ほかのマシンへ移す。先に `vgchange -an` で無効にする |
| `vgrename 旧 新`、`lvrename VG 旧 新` | 名前を変える |
| `pvmove 元 [先]` | PV の中身（PE）を、同じ VG のほかの PV へ移す |
| `lvremove LV` → `vgremove VG` → `pvremove PV` | 消す。作るのと逆の順 |

### スナップショットと、ストライプ、ミラー

```console
# lvcreate -s -L 50M -n snap1 vg01/lv_data     ← スナップショット
# mount -o ro /dev/vg01/snap1 /mnt/snap         ← その瞬間の姿をマウントして、バックアップを取る
# umount /mnt/snap; lvremove vg01/snap1         ← 使い終わったら消す
# lvconvert --merge vg01/snap1                  ← または：スナップショットの中身で、元の LV を巻き戻す
# lvcreate -i 2 -L 1G -n lv_fast vg01           ← 2 台にストライプ（分けて書く。速さのため）
# lvcreate -m 1 -L 1G -n lv_safe vg01           ← ミラー（控えを 1 つ。安全のため）
```

LVM のスナップショットは、`lvcreate -s`（`--snapshot`）で作る、**元の LV の変更前の中身を退避するための LV** です（[図解 LinuC 5.8](../../linuc/site/ch05.html#lvm)）。Btrfs と違い、**退避のための大きさ（`-L`）を指定します**。元の LV への書き込みがこの大きさを超えると、スナップショットは壊れて使えなくなります。`lvs` の `Data%` の欄で、使った割合がわかります。

| `lvcreate` のオプション | 意味 |
| --- | --- |
| `-L 大きさ` | 大きさ（`200M`、`10G`） |
| `-l 個数` | PE の個数。`100%FREE`、`50%VG` の形も |
| `-n 名前` | LV の名前（省くと `lvol0` などになる） |
| `-s` | スナップショット。最後の引数は、元の LV |
| `-i 数` | ストライプの数（何台の PV に分けて書くか） |
| `-m 数` | ミラーの控えの数（`-m 1` で 2 重） |

## lvm.conf とメタデータのバックアップ {#lvm-conf}

LVM の設定ファイルは **`/etc/lvm/lvm.conf`** です。`名前 { … }` の形の節に、`項目 = 値` を書きます。

```text
devices {
	# どの装置を PV の候補として調べるか。a は受け入れ、r は除く。上から順に、最初に合ったものが効く
	filter = [ "a|^/dev/sd.*|", "r|.*|" ]
}
backup {
	backup = 1
	backup_dir = "/etc/lvm/backup"
	archive = 1
	archive_dir = "/etc/lvm/archive"
	retain_min = 10
	retain_days = 30
}
global {
	umask = 077
}
activation {
	# 起動時に自動で有効にする VG / LV を絞る
	auto_activation_volume_list = [ "vg01", "vg02/lv_data" ]
}
```

| 節 | 主な項目 |
| --- | --- |
| `devices` | **`filter`**：LVM が調べる装置を、正規表現で絞る。`"a|パターン|"` が受け入れ（accept）、`"r|パターン|"` が除く（reject）。`global_filter` は、LVM のすべての部品に効く版 |
| `backup` | メタデータのバックアップ（`backup`、`backup_dir`）と、履歴（`archive`、`archive_dir`、`retain_min`、`retain_days`） |
| `log` | ログの出し方（`verbose`、`syslog`、`file`） |
| `global` | 全体の設定（`umask` など） |
| `activation` | LV の有効化（`volume_list`、`auto_activation_volume_list`、`udev_sync`） |
| `allocation` | PE の割り当て方 |

上の `filter` は、「`/dev/sd` で始まる装置だけを調べ、ほかは全部除く」という意味です。上から順に見て、最初に合ったパターンで決まります。だから、`"r|.*|"` を先に書くと、全部が除かれてしまいます。CD-ROM や、マルチパスの下の個々のパスを、LVM に触らせないために使います。

いまの設定は、**`lvmconfig`**（`lvm config`、古い名前は `lvm dumpconfig`）で見られます。

```console
# lvmconfig devices/filter
filter=["a|^/dev/sd.*|","r|.*|"]
# lvmconfig --type default backup/backup_dir backup/archive_dir backup/retain_min
# backup_dir="/etc/lvm/backup"
# archive_dir="/etc/lvm/archive"
# retain_min=10
```

### メタデータのバックアップ：vgcfgbackup と vgcfgrestore

LVM の**メタデータ**は、「どの PV の何番の PE が、どの LV の何番目か」という対応の表です。各 PV の先頭に書かれていて、その写しが、テキストのファイルとして `/etc/lvm/` の下にも保存されます。

| 場所 | 中身 |
| --- | --- |
| **`/etc/lvm/backup/VG名`** | **いまの**メタデータの写し。VG ごとに 1 ファイル |
| **`/etc/lvm/archive/VG名_番号-….vg`** | **変更の前**のメタデータの履歴。`lvcreate` などで構成を変えるたびに、1 つ増える |

```console
# ls /etc/lvm/backup /etc/lvm/archive
/etc/lvm/archive:
vg01_00000-870558149.vg  vg01_00001-1707352245.vg
/etc/lvm/backup:
vg01
# head -6 /etc/lvm/backup/vg01
# Generated by LVM2 version 2.03.16(2) (2022-05-18): Mon Nov 16 21:20:03 2026

contents = "Text Format Volume Group"
version = 1

description = "Created *after* executing 'lvcreate -l 10 -n lv_log vg01'"
# vgcfgbackup vg01                              ← 手でバックアップを取る
  Volume group "vg01" successfully backed up.
# vgcfgbackup -f /root/vg01.bak vg01            ← 別のファイルに
# vgcfgrestore --list vg01                      ← 戻せる履歴の一覧
  File:		/etc/lvm/archive/vg01_00000-870558149.vg
  VG name:    	vg01
  Description:	Created *before* executing 'lvcreate -L 200M -n lv_data vg01'
# vgcfgrestore -f /etc/lvm/archive/vg01_00001-1707352245.vg vg01   ← その時点の構成に戻す
```

| コマンド | すること |
| --- | --- |
| `vgcfgbackup [VG]` | VG のメタデータを `/etc/lvm/backup/` に書く（`-f` で別のファイルへ） |
| `vgcfgrestore VG` | `/etc/lvm/backup/` のものから、メタデータを PV に書き戻す |
| `vgcfgrestore -f ファイル VG` | 指定したファイル（archive の中のものなど）から戻す |
| `vgcfgrestore --list VG` | 戻せるバックアップと履歴の一覧 |

:::warn 試験の注意：vgcfgbackup が取るのは、メタデータだけ
`vgcfgbackup` が保存するのは、**LVM の構成の情報（メタデータ）だけ**です。LV の中のファイルは入っていません。まちがえて `lvremove` した LV を、すぐに `vgcfgrestore` で構成ごと戻せば、中身が上書きされていない限り、データも元どおり見えます。しかし、ディスクが壊れたときに、データを取り戻す手段にはなりません。
:::

:::deep lvm.conf を書き換えなくても、設定は変えられる
1 回だけ設定を変えたいときは、コマンドに `--config` を付けます（例：`pvs --config 'devices { filter = [ "a|.*|" ] }'`）。Red Hat 系の新しい LVM（RHEL 9）では、`filter` の代わりに、使う装置の一覧を `/etc/lvm/devices/system.devices` に持つ仕組み（devices ファイル。`lvmdevices` コマンドで管理）が既定になっています。試験の範囲は `lvm.conf` の `filter` です。
:::

:::warn 本物との違い
- この小さな Linux には、ブロックデバイス、スワップ、LVM、ext4 以外のファイルシステムの道具がありません。`mkfs`、`tune2fs`、`fsck`、`dump`、`xfs_*`、`btrfs`、`pv*`・`vg*`・`lv*` は、Debian 12 の Docker（ループデバイス）で実行した出力を ```console で載せ、デバイス名を `/dev/sdb1` などに読み替えました
- `pvmove` と LVM のスナップショット、`smartctl`、systemd の `.mount` ユニットの起動は、Docker の中では動かせないので、出力を省くか、よく知られた形だけを載せています
- この Linux の `/etc/mtab` はありません。`/proc/mounts` を見てください
:::

:::key まとめ
- **fstab** の 6 欄：何を・どこに・種類・オプション・dump・fsck。`nofail`、`_netdev`、`noatime`、`pri=`、`x-systemd.automount`。`mount -a` は `noauto` 以外を**書いた順に**マウントし、スワップは `swapon -a`
- **`/proc/mounts`** はカーネルが見せる実際のマウント。**`/etc/mtab`** は昔は mount が書くファイル、今は `/proc/self/mounts` へのリンク
- systemd は fstab を **`.mount` ユニット**に変換する（`/run/systemd/generator/`）。順番は**パスの親が先**。ユニット名はパスから決まる（`/var/lib/data` → `var-lib-data.mount`）。`[Mount]` に `What=`、`Where=`、`Type=`、`Options=`。書き換えたら `systemctl daemon-reload`
- スワップの優先度は**大きいほうが先**。`swapon -p`、fstab の `pri=`。確認は `swapon --show`、`/proc/swaps`
- UUID は `blkid`（`-U`、`-L`、`-s UUID -o value`）、`lsblk -f`、`/dev/disk/by-uuid/`
- **mke2fs**：`-b` ブロック、`-i` bytes-per-inode、`-N` inode 数、`-m` 予約（既定 5%）、`-j` ジャーナル、`-n` 作らずに表示。既定値は `/etc/mke2fs.conf`
- **tune2fs**：`-l` 表示、`-c` 最大マウント回数、`-i` 検査の間隔、`-j` ジャーナル追加、`-m` 予約、`-L` ラベル、`-O` 機能。**dumpe2fs** は全部、`-h` でスーパーブロックだけ
- **fsck** は外してから。`fsck -A` は fstab の全部。**e2fsck**：`-p` 自動、`-y` 全部 yes、`-n` 書かない、`-f` 強制、`-b` 控えのスーパーブロック。終了ステータス 1 = 直した、4 = 残っている
- **dump**：レベル 0 が全部、`-u` で dumpdates に記録、`-f` 出力先。**restore**：`-r` 全部、`-x` 取り出す、`-i` 対話、`-t` 一覧。戻す先はいまのディレクトリ
- **XFS**：`xfs_info`、`xfs_repair`（外して。`-n` は検査だけ。`xfs_check` は昔の名前）、`xfs_admin`、`xfs_growfs`（縮小は不可）、`xfsdump -l レベル -f 先 マウントポイント`、`xfsrestore -f 元 先`
- **Btrfs**：`btrfs subvolume create / list / snapshot [-r] / delete`、`mount -o subvol=`。**`btrfs-convert`** で ext を変換、`-r` で戻す（`ext2_saved` がある間）
- **smartctl**：`-i`、`-H`、`-a`、`-t short|long`、`-l selftest`、`-s on`。**smartd**：`smartd.conf`（`DEVICESCAN`、`-a`、`-m`、`-s`）
- **LVM**：PE の大きさは `vgcreate -s`（既定 4 MiB）。`pvs`/`vgs`/`lvs`、`*display`、`*scan`。入れ替えは `vgextend` → `pvmove` → `vgreduce` → `pvremove`。`vgchange -ay`/`-an`。広げるのは LV → FS、縮めるのは FS → LV
- **`/etc/lvm/lvm.conf`**：`devices { filter = [ "a|…|", "r|…|" ] }`。メタデータは `/etc/lvm/backup/`（いま）と `/etc/lvm/archive/`（履歴）。`vgcfgbackup`、`vgcfgrestore`
:::

## 練習問題 {#practice}

本番と同じ形の問題です。細かい項目ごとに、重要度 × 5 問あります。

### 2.02.1 ファイルシステムの設定とマウント

:::q 2.02.1-01 single
現在マウントされているファイルシステムの一覧を、カーネルが提供する情報として読めるファイルはどれか。
- [ ] `/etc/fstab`
- [x] `/proc/mounts`
- [ ] `/proc/filesystems`
- [ ] `/etc/filesystems`
- [ ] `/proc/partitions`
:::why
`/proc/mounts`（`/proc/self/mounts` へのリンク）は、カーネルが持つ実際のマウントの表です（[2.3](#mtab)）。

- `/etc/fstab` は、起動時にマウントする「予定」を管理者が書くファイルで、手で `mount` したものは載りません
- `/proc/filesystems` は、カーネルが扱える**種類**の一覧です
- `/etc/filesystems` は、`mount` が種類を自動判定するときに試す順を書くファイルです
- `/proc/partitions` は、カーネルが知っているパーティションの一覧で、マウントしているかどうかは出ません
:::
:::

:::q 2.02.1-02 single
`/etc/fstab` に次の行がある。この行の説明として正しいものはどれか。

```text
UUID=a19c9c57-6cab-4f31-a1b5-122156a0949e  /var/log  xfs  defaults,nofail  0  2
```
- [ ] 起動時にはマウントされず、`mount /var/log` を実行したときにだけマウントされる
- [x] この UUID の装置が見つからなくても、起動は失敗にならない
- [ ] `dump` コマンドのバックアップの対象になる
- [ ] 起動時の fsck は、`/` より先にこのファイルシステムに対して実行される
:::why
`nofail` は「装置がなくても、起動を失敗にしない」オプションです（[2.2](#fstab)）。

- 起動時にマウントしないのは `noauto` です。`defaults` には `auto` が入っています
- 5 欄目（dump）が 0 なので、`dump` の対象ではありません
- 6 欄目（fsck）の 2 は「`/`（1）の後」です。`/` より先にはなりません
:::
:::

:::q 2.02.1-03 single
`/etc/mtab` の説明として正しいものはどれか。
- [ ] 起動時にマウントするファイルシステムを、管理者が書いておくファイルである
- [ ] systemd が fstab から作った `.mount` ユニットを置くディレクトリである
- [x] もともとは `mount` コマンドがマウントの状態を記録するファイルで、現在の多くのディストリビューションでは `/proc/self/mounts` へのシンボリックリンクになっている
- [ ] スワップ領域の一覧だけを記録するファイルである
:::why
`/etc/mtab` は、昔は `mount` と `umount` が書き換える普通のファイルでした。`/` が読み取り専用のときなどに実際とずれるので、今は `/proc/self/mounts` へのリンクになっています（[2.3](#mtab)）。Debian 12 と Rocky Linux 9 で `ls -l /etc/mtab` を実行すると、`-> ../proc/self/mounts` と表示されます。

- 管理者が予定を書くのは `/etc/fstab` です
- fstab から作られたユニットは `/run/systemd/generator/` にあります
- スワップの一覧は `/proc/swaps` です
:::
:::

:::q 2.02.1-04 multi
`mount -a` の説明として正しいものを 2 つ選択してください。
- [x] `/etc/fstab` の行のうち、`noauto` が付いたものはマウントしない
- [ ] `/etc/fstab` にあるスワップ領域も、同時に有効にする
- [x] `/etc/fstab` に書かれた順に、上から処理する
- [ ] すでにマウントしてあるものを、いったん外してからマウントし直す
- [ ] `/proc/mounts` にあるものを、すべて読み取り専用で付け直す
:::why
`mount -a` は、fstab を上から読み、`noauto` でない行をマウントします（[2.2](#fstab)、[2.4](#systemd-mount)）。だから、`/var` の行は `/var/log` の行より上に書きます。

- スワップを有効にするのは `swapon -a` です
- すでにマウントしてあるものは、そのままにされます
- オプションを付け直すのは `mount -o remount,ro マウントポイント` で、`-a` の仕事ではありません
:::
:::

:::q 2.02.1-05 fill
systemd を使っているシステムで `/etc/fstab` を書き換えた。systemd に、fstab から作るユニットを作り直させるコマンドを、サブコマンドも含めて入力してください。
= systemctl daemon-reload
:::why
systemd は、`systemd-fstab-generator` で fstab を `.mount` ユニットに変換して持っています。fstab を書き換えたら、`systemctl daemon-reload` で作り直させます（[2.4](#systemd-mount)）。実行しないと、`mount` のたびに「fstab が変わったが、systemd は古いものを使っている」という注意が出ます。`systemctl reload` は、指定したサービスに設定を読み直させるもので、ユニットの作り直しではありません。
:::
:::

:::q 2.02.1-06 single
`/var/lib/data` にマウントする systemd のマウントユニットを、自分で作る。ユニットファイルの名前として正しいものはどれか。
- [ ] `data.mount`
- [ ] `var/lib/data.mount`
- [x] `var-lib-data.mount`
- [ ] `var_lib_data.mount`
- [ ] `-var-lib-data.mount`
:::why
マウントユニットの名前は、マウントポイントのパスから決まります。先頭の `/` を取り、残りの `/` を `-` に変えて、`.mount` を付けます（[2.4](#systemd-mount)）。`systemd-escape -p --suffix=mount /var/lib/data` で確かめられます。名前が `Where=` のパスと合っていないユニットは、読み込みに失敗します。先頭に `-` は付きません（`-.mount` は `/` そのもののユニットです）。
:::
:::

:::q 2.02.1-07 single
次のマウントユニットの、空欄に入るものはどれか。

```text
[Mount]
What=/dev/disk/by-uuid/6109cec1-643a-4028-8cd9-7dff05eef572
____=/var/lib/data
Type=ext4
Options=defaults,noatime
```
- [ ] `Target`
- [x] `Where`
- [ ] `MountPoint`
- [ ] `Directory`
- [ ] `Path`
:::why
`[Mount]` の節には、`What=`（何を）、`Where=`（どこに）、`Type=`（種類）、`Options=`（オプション）を書きます。fstab の 1〜4 欄にあたります（[2.4](#systemd-mount)）。`Target`、`MountPoint`、`Directory`、`Path` という項目は、`[Mount]` にはありません。
:::
:::

:::q 2.02.1-08 single
`swapon --show` の出力が次のとおりだった。メモリが足りなくなったとき、最初に使われるスワップはどれか。

```text
NAME          TYPE       SIZE USED PRIO
/var/lib/swap file      1024M   0B   -2
/dev/sdb5     partition  400M   0B   10
/dev/sdc5     partition  400M   0B   -3
```
- [ ] `/var/lib/swap`。一覧の最初にあるから
- [x] `/dev/sdb5`。優先度の数が最も大きいから
- [ ] `/dev/sdc5`。優先度の数が最も小さいから
- [ ] `/var/lib/swap`。大きさが最も大きいから
- [ ] 3 つが同じ割合で、順番に使われる
:::why
スワップは、優先度（PRIO）の**数が大きいもの**から先に使われます（[2.5](#swap)）。10 の `/dev/sdb5` が一杯になってから、-2、-3 の順に使われます。順番に少しずつ使われるのは、優先度が**同じ**もの同士のときだけです。一覧の順や大きさは関係ありません。
:::
:::

:::q 2.02.1-09 fill
スワップ領域 `/dev/sdb5` を、優先度 5 で有効にする。空欄に入るオプションを入力してください。

```text
swapon ____ 5 /dev/sdb5
```
= -p
= --priority
:::why
`swapon -p 数`（`--priority 数`）で、優先度を指定して有効にします（[2.5](#swap)）。`/etc/fstab` に書くときは、4 欄目に `pri=5` です。指定しないと、カーネルが負の数を付けます。
:::
:::

:::q 2.02.1-10 multi
パーティションの上にあるファイルシステムの UUID を調べられるコマンドを 2 つ選択してください。
- [x] `blkid`
- [ ] `df -T`
- [x] `lsblk -f`
- [ ] `swapon -s`
- [ ] `free`
:::why
`blkid` は装置ごとの UUID、ラベル、種類を、`lsblk -f` は装置の木にファイルシステムの種類、ラベル、UUID を足して表示します（[2.6](#blkid)）。

- `df -T` は、使用量と種類を表示します。UUID は出ません
- `swapon -s` は、有効なスワップの一覧（名前、種類、大きさ、使用量、優先度）です
- `free` は、メモリとスワップの量です
:::
:::

:::q 2.02.1-11 single
systemd を使っているシステムの `/etc/fstab` に、`/var/log` の行が先、`/var` の行が後に書かれている（どちらも別のパーティションで、`defaults` でマウントする）。起動時のマウントの説明として正しいものはどれか。
- [ ] fstab に書かれた順に、`/var/log`、`/var` の順でマウントされる
- [x] マウントポイントのパスの親子の関係から、`/var` が先、`/var/log` が後になる
- [ ] 6 欄目（fsck の順）の数が小さいほうが、先にマウントされる
- [ ] デバイス名のアルファベット順でマウントされる
- [ ] 順番が決まらないので、systemd は起動を止めて緊急モードに入る
:::why
systemd は、fstab の各行を `.mount` ユニットに変換し、マウントポイントのパスが親子なら「親が先、子が後」という依存を自動で付けます（[2.4](#systemd-mount)）。だから、fstab の行の順は関係ありません。行の順どおりに処理するのは、`mount -a` を手で実行したときです。6 欄目は fsck の順で、マウントの順ではありません。
:::
:::

:::q 2.02.1-12 single
`/etc/fstab` で、スワップ領域の優先度を 10 にする。空欄に入るものはどれか。

```text
UUID=4a98790c-1865-4763-917c-63280a83a0c8  none  swap  sw,____=10  0  0
```
- [x] `pri`
- [ ] `priority`
- [ ] `prio`
- [ ] `order`
- [ ] `pass`
:::why
fstab のスワップの行では、4 欄目に `pri=数` と書いて優先度を指定します（[2.5](#swap)）。コマンドでは `swapon -p 数`（`--priority`）ですが、fstab のオプションの名前は `pri` です。`PRIO` は、`swapon --show` の列の見出しです。
:::
:::

:::q 2.02.1-13 multi
`/etc/fstab` の 4 欄目に書くオプションの説明として正しいものを 2 つ選択してください。
- [x] `noatime`：ファイルを読んだだけでは、アクセス時刻を更新しない
- [ ] `nofail`：起動時の fsck を実行しない
- [ ] `_netdev`：ネットワークが使えなくてもマウントできる装置であることを示す
- [x] `x-systemd.automount`：起動時にはマウントせず、最初にアクセスされたときに systemd がマウントする
- [ ] `noauto`：一般ユーザーにはマウントさせない
:::why
`noatime` は atime の更新をやめて書き込みを減らし、`x-systemd.automount` は自動マウント（`.automount` ユニット）にします（[2.2](#fstab)、[2.4](#systemd-mount)）。

- `nofail` は「装置がなくても起動を失敗にしない」です。fsck をしないのは、6 欄目の 0 です
- `_netdev` は「ネットワークが**要る**装置」の印で、ネットワークが使えるようになってからマウントされます
- `noauto` は「`mount -a` や起動時にはマウントしない」です。一般ユーザーのマウントを決めるのは `user`、`users`、`nouser` です
:::
:::

:::q 2.02.1-14 single
`umount -l /data` の説明として正しいものはどれか。
- [ ] `/data` を使っているプロセスを強制終了してから、マウントを外す
- [ ] `/data` の下にマウントされているものも、まとめて外す
- [x] いますぐ `/data` をディレクトリの木から切り離し、使っているプロセスがいなくなってから後片づけをする
- [ ] 外せなかったときに、読み取り専用で付け直す
- [ ] ラベルが `/data` のファイルシステムを外す
:::why
`-l`（`--lazy`）は、木からの切り離しだけを先に行い、片づけを後に回します（[2.2](#fstab)）。プロセスを終了させはしません。

- 下のマウントもまとめて外すのは `-R`（`--recursive`）です
- 外せなかったら読み取り専用で付け直すのは `-r` です
- `umount` に、ラベルで指定する `-l` はありません（`mount -L` は「ラベルで指定」、`mount -l` は「ラベルも表示」です）
:::
:::

:::q 2.02.1-15 single
データ用のディスクを取り外したサーバーを再起動したところ、次の表示が出て、root のパスワードを求められた。原因として最も考えられるものはどれか。

```text
[ TIME ] Timed out waiting for device dev-disk-by\x2duuid-6109cec1….device.
[DEPEND] Dependency failed for data.mount - /data.
[DEPEND] Dependency failed for local-fs.target - Local File Systems.
You are in emergency mode.
```
- [ ] `/data` のファイルシステムのスーパーブロックが壊れている
- [x] `/etc/fstab` に、取り外したディスクの UUID を指す行が、`nofail` も `noauto` もなしで残っている
- [ ] `/etc/mtab` が `/proc/self/mounts` へのシンボリックリンクになっている
- [ ] スワップ領域の優先度が設定されていない
- [ ] `/data` に、一般ユーザーが書き込める権限がない
:::why
「装置を待ったが、時間切れになった」「そのせいで `data.mount` と `local-fs.target` が失敗した」と読めます。fstab の必須の行（`nofail` も `noauto` もない行）の装置が見つからないと、systemd は緊急モードに入ります（[2.4](#systemd-mount)）。直すには、root でログインして fstab のその行を消すか、`nofail` を付けます。

- スーパーブロックが壊れているなら、装置は見つかったうえで、fsck かマウントが失敗します。「装置を待って時間切れ」にはなりません
- `/etc/mtab` がリンクなのは、今の普通の状態です
- スワップの優先度や、ディレクトリの権限は、起動の失敗の原因になりません
:::
:::

### 2.02.2 ファイルシステムの管理

:::q 2.02.2-01 multi
`smartctl` のオプションの説明として正しいものを 2 つ選択してください。
- [x] `-H`：ディスクの健康状態の判定（PASSED など）を表示する
- [ ] `-l selftest`：自己診断を開始する
- [x] `-t long`：長い自己診断を開始する
- [ ] `-s on`：`smartd` デーモンを起動する
- [ ] `-i`：S.M.A.R.T. を無効にする
:::why
`-H`（`--health`）は健康状態を表示し、`-t short` や `-t long` は自己診断を始めます（[2.13](#smart)）。

- `-l selftest` は、自己診断の**結果の記録を表示**します。始めるのは `-t` です
- `-s on` は、そのディスクの S.M.A.R.T. の機能を有効にします。デーモンの起動は `systemctl start smartd` です
- `-i` は、型番やシリアル番号などの装置の情報を表示します。無効にするのは `-s off` です
:::
:::

:::q 2.02.2-02 single
小さなファイルを大量に置くために、inode の数を多くして ext4 を作りたい。`mke2fs`（`mkfs.ext4`）で、「何バイトごとに inode を 1 つ作るか」を指定するオプションはどれか。
- [ ] `-b`
- [x] `-i`
- [ ] `-m`
- [ ] `-c`
- [ ] `-j`
:::why
`-i バイト`（bytes-per-inode）を小さくすると、inode が多く作られます。`-N 数` で、数を直接指定することもできます（[2.7](#mkfs)）。inode の数は、作ったあとには増やせません。

- `-b` はブロックサイズです
- `-m` は、root のための予約ブロックの割合（既定 5%）です
- `-c` は、作る前に不良ブロックを検査します
- `-j` は、ジャーナルを付けます
:::
:::

:::q 2.02.2-03 single
次のコマンドを実行した。この ext4 ファイルシステムの説明として正しいものはどれか。

```text
# tune2fs -c 20 -i 30d /dev/sdb1
```
- [ ] 20 日ごと、または 30 回のマウントごとに、起動時の fsck の対象になる
- [x] 20 回マウントするか、前の検査から 30 日たつかの、どちらか早いほうで、起動時の fsck の対象になる
- [ ] inode を 20 個、予約ブロックを 30 個に設定する
- [ ] 不良ブロックを 20 回検査し、30 バイトごとに inode を 1 つ作る
- [ ] 20 回マウントすると、30 日間マウントできなくなる
:::why
`tune2fs -c` は最大マウント回数、`-i` は検査の間隔（`d` は日、`w` は週、`m` は月）です（[2.8](#tune2fs)）。実際に実行すると、`Setting maximal mount count to 20` と `Setting interval between checks to 2592000 seconds`（30 日）と表示されます。回数と日数の、どちらか早いほうで検査の対象になります。「不良ブロックの検査」と「bytes-per-inode」は、`mke2fs` の `-c` と `-i` の意味で、`tune2fs` とは違います。
:::
:::

:::q 2.02.2-04 fill
ext2 のファイルシステム `/dev/sdb1` に、中のデータを残したままジャーナルを追加して、ext3 にする。空欄に入るオプションを入力してください。

```text
tune2fs ____ /dev/sdb1
```
= -j
= -O has_journal
= -Ohas_journal
:::why
`tune2fs -j` は、すでにあるファイルシステムにジャーナルを追加します（[2.8](#tune2fs)）。`mkfs.ext3` や `mke2fs -j` は、新しく作り直すので、中身が消えます。`tune2fs -O has_journal` でも同じことができます。
:::
:::

:::q 2.02.2-05 single
`tune2fs -l /dev/sdb1` の出力に、次の 2 行があった。説明として正しいものはどれか。

```text
Maximum mount count:      -1
Check interval:           0 (<none>)
```
- [ ] マウントの回数の上限を超えたので、次の起動で必ず fsck が実行される
- [ ] このファイルシステムは、一度もマウントされていない
- [x] マウントの回数でも、経過した時間でも、定期的な fsck は実行されない設定である
- [ ] fsck が、エラーを直せずに終わった
- [ ] このファイルシステムは、読み取り専用でしかマウントできない
:::why
`Maximum mount count` が -1（または 0）なら回数による検査はなく、`Check interval` が 0 なら時間による検査もありません（[2.8](#tune2fs)）。今の `mke2fs` は、既定でこの設定で作ります。`tune2fs -c 回数` と `-i 間隔` で変えられます。マウントした回数は `Mount count`、状態は `Filesystem state` の行に出ます。
:::
:::

:::q 2.02.2-06 multi
ext4 ファイルシステム `/dev/sdb1` の、バックアップスーパーブロック（控え）の場所を調べる方法を 2 つ選択してください。
- [x] `dumpe2fs /dev/sdb1` の出力から、`Backup superblock at` の行を探す
- [ ] `tune2fs -c /dev/sdb1` を実行する
- [x] 作ったときと同じオプションで、`mke2fs -n /dev/sdb1` を実行する
- [ ] `blkid /dev/sdb1` を実行する
- [ ] `e2fsck -y /dev/sdb1` を実行する
:::why
`dumpe2fs` は、ブロックグループごとの情報の中で、控えのスーパーブロックの場所を表示します。`mke2fs -n` は、**実際には作らず**に、作るとしたら控えをどこに置くかを表示します（[2.8](#tune2fs)、[2.9](#fsck)）。

- `tune2fs -c` は、最大マウント回数を**設定**するオプションで、値が要ります
- `blkid` が表示するのは、UUID、ラベル、種類です
- `e2fsck -y` は、すべての質問に yes と答えて修復します。場所を調べるコマンドではありません
:::
:::

:::q 2.02.2-07 single
ext4 の `/dev/sdb1` が、先頭のスーパーブロックの破損でマウントできない。ブロック 8193 にある控えのスーパーブロックを使って検査、修復するコマンドはどれか。
- [ ] `e2fsck -c 8193 /dev/sdb1`
- [ ] `tune2fs -b 8193 /dev/sdb1`
- [x] `e2fsck -b 8193 /dev/sdb1`
- [ ] `mke2fs -b 8193 /dev/sdb1`
- [ ] `fsck -A 8193 /dev/sdb1`
:::why
`e2fsck -b 番号` は、控えのスーパーブロックを使って検査します（[2.9](#fsck)）。

- `e2fsck -c` は、不良ブロックを探すオプションです
- `tune2fs` に `-b` はありません
- `mke2fs -b` はブロックサイズの指定で、実行すると新しく作り直されて、中身が消えます
- `fsck -A` は、fstab の全部を検査するオプションです
:::
:::

:::q 2.02.2-08 single
`e2fsck -p /dev/sdb1` の説明として正しいものはどれか。
- [ ] 何も書き換えずに、検査の結果だけを表示する
- [ ] すべての質問に yes と答えて、どんな問題も修復する
- [x] 質問をせずに、安全に直せる問題だけを自動で修復し、人の判断が要る問題があれば止まる
- [ ] 検査の進み具合を、棒で表示する
- [ ] 状態が clean でも、強制的に検査する
:::why
`-p`（preen。`-a` も同じ）は、起動のときに使われる「自動で、安全な範囲だけ直す」オプションです（[2.9](#fsck)）。

- 何も書き換えないのは `-n` です
- すべてに yes と答えるのは `-y` です
- 進み具合の表示は `-C` です
- clean でも強制的に検査するのは `-f` です
:::
:::

:::q 2.02.2-09 multi
`fsck` の終了ステータスの説明として正しいものを 2 つ選択してください。
- [ ] 0：ファイルシステムの種類がわからず、検査しなかった
- [x] 1：エラーを見つけて、修復した
- [ ] 2：利用者が検査を中断した
- [x] 4：エラーが、修復されずに残っている
- [ ] 8：修復したので、再起動が必要である
:::why
`fsck` の終了ステータスは、0（エラーなし）、1（直した）、2（直した。再起動が必要）、4（直らずに残っている）、8（実行そのものの失敗）、16（使い方のまちがい）、32（利用者が中断）、128（共有ライブラリのエラー）の足し算です（[2.9](#fsck)）。マウント中の装置に `fsck` を実行すると、8 で終わります。
:::
:::

:::q 2.02.2-10 single
`/data` に読み書きでマウントしている ext4 の `/dev/sdb1` に、エラーがある疑いがある。検査と修復の手順として最も適切なものはどれか。
- [ ] マウントしたまま、`e2fsck -y /dev/sdb1` を実行する
- [ ] マウントしたまま、`fsck -A` を実行する
- [x] `umount /data` で外してから、`e2fsck -f /dev/sdb1` を実行する
- [ ] `mkfs.ext4 /dev/sdb1` を実行してから、`fsck /dev/sdb1` を実行する
- [ ] `xfs_repair /dev/sdb1` を実行する
:::why
読み書きでマウントしているファイルシステムを fsck で修復すると、カーネルが持っている情報と食い違って、かえって壊すことがあります。外してから実行します（[2.9](#fsck)）。`e2fsck` は、マウント中の装置を渡すと `is mounted` と表示して止まります。

- `mkfs.ext4` は、ファイルシステムを作り直すので、中身が消えます
- `xfs_repair` は XFS の道具で、ext4 には使えません
:::
:::

:::q 2.02.2-11 fill
`/etc/fstab` に書かれているすべてのファイルシステムを、6 欄目の順に検査する。空欄に入る `fsck` のオプションを入力してください。

```text
fsck ____
```
= -A
:::why
`fsck -A` は、fstab を読んで、6 欄目（fsck の順）が 0 でないものを、番号の順に検査します（[2.9](#fsck)）。起動のときの使い方です。`-R` を足すと、`/` を飛ばします。小文字の `-a` は、`e2fsck` に渡されて「質問せずに自動で直す」（`-p` と同じ）の意味になります。
:::
:::

:::q 2.02.2-12 single
次のコマンドの説明として正しいものはどれか。

```text
# dump -0u -f /backup/data.dump /data
```
- [ ] `/data` の、前回のバックアップより後に変わったファイルだけを取る
- [x] `/data` のファイルシステムの全部を `/backup/data.dump` に取り、取った日時とレベルを dumpdates ファイルに記録する
- [ ] `/backup/data.dump` の中身を、`/data` に戻す
- [ ] `/data` を、圧縮せずに、ユーザーごとに分けて取る
- [ ] `/backup/data.dump` の中身の一覧を表示する

レベル 0 は全部（フルバックアップ）、`-u` は dumpdates ファイル（`/etc/dumpdates`。Debian では `/var/lib/dumpdates`）への記録、`-f` は出力先です（[2.10](#dump)）。`-u` の記録が、次のレベル 1 以上の「どこからの変更を取るか」の基準になります。戻すのと、一覧の表示は、`restore`（`-r`、`-x`、`-t`）の仕事です。
:::
:::

:::q 2.02.2-13 single
`dump` で、日曜にレベル 0、月曜にレベル 1、火曜にレベル 2、水曜にレベル 1 のバックアップを、どれも `-u` を付けて取った。水曜のバックアップに入るものはどれか。
- [ ] 火曜のバックアップより後に変わったファイル
- [ ] 月曜のバックアップより後に変わったファイル
- [x] 日曜のバックアップより後に変わったファイル
- [ ] ファイルシステムのすべてのファイル
- [ ] 水曜に変わったファイルだけ
:::why
レベル n の dump は、「**自分より小さいレベル**の、最後のバックアップ」より後に変わったファイルを取ります（[2.10](#dump)）。水曜のレベル 1 より小さいレベルは、日曜のレベル 0 だけです。月曜のレベル 1 は同じレベル、火曜のレベル 2 は大きいレベルなので、基準になりません。全部を取るのはレベル 0 です。
:::
:::

:::q 2.02.2-14 multi
`restore` のオプションの説明として正しいものを 2 つ選択してください。
- [x] `-r`：バックアップから、ファイルシステム全体を作り直す
- [ ] `-x`：バックアップを圧縮する
- [ ] `-i`：これまでのバックアップの記録（インベントリ）を表示する
- [x] `-t`：バックアップの中身の一覧を表示する
- [ ] `-C`：新しいバックアップを作る
:::why
`-r` は全体を戻し（レベル 0 から順に重ねる）、`-t` は一覧を表示します（[2.10](#dump)）。

- `-x` は、指定したファイルだけを**取り出す**（extract）オプションです
- `-i` は、**対話**で取り出すものを選ぶオプションです。インベントリの表示は、`xfsdump -I` です
- `-C` は、バックアップと、いまのファイルシステムを**比べる**オプションです。作るのは `dump` です
:::
:::

:::q 2.02.2-15 single
XFS のファイルシステム `/dev/sdc1` を、何も書き換えずに検査だけしたい。適切なコマンドはどれか（マウントは外してある）。
- [ ] `fsck.xfs /dev/sdc1`
- [x] `xfs_repair -n /dev/sdc1`
- [ ] `xfs_repair -L /dev/sdc1`
- [ ] `xfs_info /dev/sdc1`
- [ ] `e2fsck -n /dev/sdc1`
:::why
`xfs_repair -n` は、検査だけして書き換えません（no modify）。昔の `xfs_check` の代わりです（[2.11](#xfs)）。

- `fsck.xfs` は、何もせずに成功を返すだけのコマンドです
- `xfs_repair -L` は、ログを捨ててから修復する最後の手段で、書きかけの変更が失われます
- `xfs_info` は、ブロックサイズなどの構成を表示するだけで、検査はしません
- `e2fsck` は ext 系の道具です
:::
:::

:::q 2.02.2-16 single
`/home` にマウントしている XFS の、レベル 0 のバックアップを `/backup/home.dump` に取るコマンドとして正しいものはどれか。
- [ ] `xfsdump -0u -f /backup/home.dump /home`
- [ ] `xfsdump -l 0 /home /backup/home.dump`
- [x] `xfsdump -l 0 -f /backup/home.dump /home`
- [ ] `xfs_dump -l 0 -f /backup/home.dump /home`
- [ ] `xfsrestore -l 0 -f /backup/home.dump /home`
:::why
`xfsdump` は、レベルを `-l 数`、出力先を `-f` で指定し、最後にマウントポイント（またはそのデバイス）を書きます（[2.11](#xfs)）。

- `-0u` は、ext 系の `dump` の書き方です
- 出力先は `-f` で渡します。引数を 2 つ並べる形ではありません
- コマンドの名前は `xfsdump` で、`_` は入りません（`xfs_info`、`xfs_repair` とは違います）
- `xfsrestore` は、戻すコマンドです
:::
:::

:::q 2.02.2-17 multi
対象のファイルシステムを**マウントしたまま**実行するコマンドを 2 つ選択してください。
- [x] `xfs_growfs`
- [ ] `xfs_repair`
- [x] `xfsdump`
- [ ] `e2fsck -f`
- [ ] `btrfs check`
:::why
`xfs_growfs` は、マウントしている XFS を、マウントポイントを指定して広げます。`xfsdump` も、マウントされている XFS を対象にします（[2.11](#xfs)）。

- `xfs_repair` は、マウント中だと `contains a mounted filesystem` と表示して止まります
- `e2fsck` は、マウント中だと `is mounted` と表示して止まります
- `btrfs check` は、マウントを外した Btrfs の検査です。マウントしたまま調べるのは `btrfs scrub` です（[2.12](#btrfs)）
:::
:::

:::q 2.02.2-18 single
`/data` にマウントしている Btrfs の、サブボリューム `/data/home` の読み取り専用のスナップショットを、`/data/home-ro` に作るコマンドはどれか。
- [ ] `btrfs snapshot create -r /data/home /data/home-ro`
- [x] `btrfs subvolume snapshot -r /data/home /data/home-ro`
- [ ] `btrfs subvolume create -s /data/home /data/home-ro`
- [ ] `lvcreate -s -n home-ro /data/home`
- [ ] `btrfs-convert -r /data/home /data/home-ro`
:::why
Btrfs のスナップショットは `btrfs subvolume snapshot 元 先` で作り、`-r` で読み取り専用になります（[2.12](#btrfs)）。スナップショットは、サブボリュームの一種です。

- `btrfs snapshot` というサブコマンドはありません
- `btrfs subvolume create` は、空のサブボリュームを作ります。`-s` というオプションはありません
- `lvcreate -s` は、LVM のスナップショットです
- `btrfs-convert -r` は、ext から変換した Btrfs を、元の ext に戻すコマンドです
:::
:::

:::q 2.02.2-19 fill
`btrfs-convert` で ext4 から Btrfs に変換した `/dev/sdb1` を、元の ext4 に戻す。空欄に入るオプションを入力してください。

```text
btrfs-convert ____ /dev/sdb1
```
= -r
= --rollback
:::why
`btrfs-convert -r`（`--rollback`）は、変換のときに `ext2_saved` サブボリュームに残した元のイメージを使って、ext に戻します（[2.12](#btrfs)）。`ext2_saved` を消したあとは、戻せません。
:::
:::

:::q 2.02.2-20 single
`smartd.conf` に次の行がある。説明として正しいものはどれか。

```text
/dev/sda -a -m admin@example.com -s (S/../.././02|L/../../6/03)
```
- [ ] `/dev/sda` を 2 時間ごとに調べ、6 回失敗したら 3 通のメールを送る
- [x] `/dev/sda` を監視し、異常があれば admin@example.com にメールを送る。短い自己診断を毎日 2 時に、長い自己診断を毎週土曜の 3 時に実行する
- [ ] `/dev/sda` の S.M.A.R.T. を無効にし、admin@example.com に報告する
- [ ] `/dev/sda` 以外のすべてのディスクを監視する
- [ ] `/dev/sda` のファイルシステムを、毎日 2 時に fsck で検査する
:::why
`-a` は主な監視をまとめて有効にし、`-m` は知らせるメールの宛先、`-s` は自己診断の予定です（[2.13](#smart)）。予定は `種類/月/日/曜日/時` の形の正規表現で、`S/../.././02` は短い（Short）診断を毎日 2 時、`L/../../6/03` は長い（Long）診断を曜日 6（土曜）の 3 時、という意味です。見つかった装置を全部監視するのは `DEVICESCAN` です。S.M.A.R.T. は装置の状態を見るもので、ファイルシステムの検査（fsck）はしません。
:::
:::

### 2.02.3 論理ボリュームマネージャの設定と管理

:::q 2.02.3-01 single
LVM の PE（物理エクステント）の大きさを、既定の 4 MiB ではなく 8 MiB にしたい。どのコマンドのどのオプションで指定するか。
- [ ] `pvcreate -s 8M`
- [x] `vgcreate -s 8M`
- [ ] `lvcreate -s 8M`
- [ ] `vgchange -l 8M`
- [ ] `lvcreate -l 8M`
:::why
PE の大きさは VG の属性で、`vgcreate -s`（`--physicalextentsize`）で決めます（[2.14](#lvm)）。

- `pvcreate` に、PE の大きさを決めるオプションはありません
- `lvcreate -s` は、スナップショットを作るオプションです
- `lvcreate -l` は、LV の大きさを PE の**個数**で指定するオプションです
- `vgchange -l` は、VG に作れる LV の数の上限を変えるオプションです
:::
:::

:::q 2.02.3-02 single
VG `vg01` で使っている古いディスク `/dev/sdb` を、LV をマウントしたまま、新しいディスク `/dev/sdd`（`pvcreate` 済み）に入れ替える。コマンドの順番として正しいものはどれか。
- [ ] `pvmove` → `vgextend` → `pvremove` → `vgreduce`
- [ ] `vgreduce` → `vgextend` → `pvmove` → `pvremove`
- [x] `vgextend` → `pvmove` → `vgreduce` → `pvremove`
- [ ] `vgextend` → `vgreduce` → `pvmove` → `pvremove`
- [ ] `pvremove` → `vgextend` → `pvmove` → `vgreduce`
:::why
まず `vgextend vg01 /dev/sdd` で新しい PV を VG に入れ、`pvmove /dev/sdb /dev/sdd` で中身を移し、空になった `/dev/sdb` を `vgreduce vg01 /dev/sdb` で VG から外し、最後に `pvremove /dev/sdb` で PV の印を消します（[2.15](#lvm-ops)）。`pvmove` の移す先は同じ VG の PV でなければならないので、`vgextend` が先です。中身が残っている PV は、`vgreduce` で外せません。
:::
:::

:::q 2.02.3-03 fill
PV `/dev/sdb` で使われている PE（中身）を、同じ VG のほかの PV の空きへ移すコマンドの名前を入力してください。
= pvmove
= /sbin/pvmove
= /usr/sbin/pvmove
= lvm pvmove
:::why
`pvmove 元 [先]` は、PV の上の PE を、同じ VG のほかの PV へ移します。LV をマウントしたまま実行できます（[2.15](#lvm-ops)）。移す先を省くと、VG の中の空いている PV が使われます。
:::
:::

:::q 2.02.3-04 single
`/etc/lvm/lvm.conf` に次の設定がある。説明として正しいものはどれか。

```text
devices {
	filter = [ "a|^/dev/sd.*|", "r|.*|" ]
}
```
- [ ] `/dev/sd` で始まる装置を除き、ほかのすべての装置を LVM の対象にする
- [x] `/dev/sd` で始まる装置だけを LVM の対象にし、ほかの装置は調べない
- [ ] すべての装置を除くので、LVM は PV を 1 つも見つけられない
- [ ] `/dev/sd` で始まる装置の上の LV を、読み取り専用にする
- [ ] `/dev/sd` で始まる装置を、起動時に自動で有効にする
:::why
`filter` の `a` は受け入れ（accept）、`r` は除く（reject）で、上から順に見て、最初に合ったパターンが効きます（[2.16](#lvm-conf)）。`/dev/sda` などは先に `a` に合うので対象になり、それ以外は `"r|.*|"` で除かれます。順番が逆（`r|.*|` が先）なら、全部が除かれます。`r` は read-only ではありません。自動で有効にする範囲は、`activation` の節の `auto_activation_volume_list` です。
:::
:::

:::q 2.02.3-05 single
LVM が、VG の構成を変えるたびに、**変更の前**のメタデータを履歴として保存する、既定のディレクトリはどれか。
- [ ] `/etc/lvm/backup/`
- [x] `/etc/lvm/archive/`
- [ ] `/var/lib/lvm/`
- [ ] `/etc/lvm/profile/`
- [ ] `/run/lvm/`
:::why
`/etc/lvm/archive/` には、`lvcreate` や `vgextend` などで構成を変える前のメタデータが、`VG名_番号-….vg` の名前で増えていきます。`/etc/lvm/backup/` には、VG ごとに**いまの**メタデータが 1 つあります（[2.16](#lvm-conf)）。場所は `lvm.conf` の `backup` の節の `archive_dir` と `backup_dir` で決まります。`/etc/lvm/profile/` は、設定のひな形（プロファイル）の置き場所です。
:::
:::

:::q 2.02.3-06 multi
`vgcfgbackup` の説明として正しいものを 2 つ選択してください。
- [x] VG のメタデータ（PV・VG・LV の構成の情報）を、ファイルに保存する
- [ ] LV の中のファイルシステムのデータも、一緒に保存する
- [x] 既定では、`/etc/lvm/backup/` の下の、VG の名前のファイルに保存する
- [ ] 保存したメタデータを、PV に書き戻す
- [ ] 実行する前に、VG を無効（`vgchange -an`）にしなければならない
:::why
`vgcfgbackup` は、LVM の構成の情報だけを `/etc/lvm/backup/VG名` に書きます（`-f` で別のファイルにもできます）（[2.16](#lvm-conf)）。

- LV の中のデータは入りません。データのバックアップは、`dump`、`xfsdump`、`tar` などで別に取ります
- 書き戻すのは `vgcfgrestore` です
- VG を使ったまま実行できます
:::
:::

:::q 2.02.3-07 single
`/data` にマウントしている ext4 の LV `/dev/vg01/lv_data` を、500 MiB 大きくし、ファイルシステムも同時に広げるコマンドはどれか。
- [ ] `lvextend -L 500M /dev/vg01/lv_data`
- [ ] `lvextend -l +500M /dev/vg01/lv_data`
- [x] `lvextend -L +500M -r /dev/vg01/lv_data`
- [ ] `vgextend -L +500M -r /dev/vg01/lv_data`
- [ ] `resize2fs -L +500M /dev/vg01/lv_data`
:::why
`-L +500M` は「500 MiB **足す**」、`-r`（`--resizefs`）は、ファイルシステムも一緒に広げるオプションです（[2.15](#lvm-ops)）。

- `-L 500M`（`+` なし）は「500 MiB **にする**」です。`-r` もないので、ファイルシステムは広がりません
- 小文字の `-l` は PE の個数で、`500M` という指定はできません
- `vgextend` は、VG に PV を足すコマンドです
- `resize2fs` は、LV を広げたあとにファイルシステムを広げるコマンドで、`-L` というオプションはありません
:::
:::

:::q 2.02.3-08 single
ext4 のファイルシステムがある LV を、小さくする。`-r` オプションを使わないときの手順として正しいものはどれか。
- [ ] `lvreduce` → `resize2fs` → `e2fsck -f` → `umount`
- [ ] `umount` → `lvreduce` → `e2fsck -f` → `resize2fs`
- [x] `umount` → `e2fsck -f` → `resize2fs` → `lvreduce`
- [ ] `umount` → `xfs_growfs` → `lvreduce`
- [ ] マウントしたまま、`lvreduce` だけを実行する
:::why
縮めるときは、**ファイルシステムが先、LV が後**です（[2.15](#lvm-ops)）。ext4 は、マウントを外し、`e2fsck -f` で検査してから、`resize2fs 装置 大きさ` で縮め、最後に `lvreduce` で LV を同じ大きさ（か、少し大きめ）にします。LV を先に縮めると、ファイルシステムの後ろが切り落とされて壊れます。`xfs_growfs` は XFS を広げるコマンドで、XFS は縮められません。
:::
:::

:::q 2.02.3-09 fill
レスキュー用の媒体から起動した。`vgscan` で見つけた VG `vg01` の中の LV を、すべて有効にして `/dev/vg01/` に見えるようにする。空欄に入るオプションを入力してください。

```text
vgchange ____ vg01
```
= -ay
= -a y
= --activate y
= --activate=y
:::why
`vgchange -ay`（`--activate y`）は、VG の中の LV を有効にします。無効にするのは `-an` です（[2.15](#lvm-ops)）。無効な LV は、`lvscan` で `inactive` と表示され、`/dev/VG/LV` のデバイスファイルがありません。
:::
:::

:::q 2.02.3-10 single
`vgs` の出力が次のとおりだった。説明として正しいものはどれか。

```text
  VG   #PV #LV #SN Attr   VSize   VFree
  vg01   2   2   0 wz--n- 784.00m 504.00m
```
- [ ] `vg01` には LV を 2 つまでしか作れず、もう作れない
- [ ] `vg01` には、PV にできるディスクが、あと 2 台必要である
- [x] `vg01` は 2 つの PV でできていて、LV が 2 つあり、まだ 504 MiB を LV に割り当てられる
- [ ] `vg01` の LV は、合わせて 504 MiB を使っている
- [ ] `vg01` には、スナップショットが 2 つある
:::why
`#PV` は VG を作っている PV の数、`#LV` は LV の数、`#SN` はスナップショットの数、`VSize` は VG の大きさ、`VFree` は、まだどの LV にも割り当てていない空きです（[2.14](#lvm)）。LV が使っているのは 784 - 504 = 280 MiB です。`#LV` は上限ではなく、いまの数です。
:::
:::

:::q 2.02.3-11 multi
LVM のコマンドとして**存在する**ものを 2 つ選択してください。
- [ ] `pvextend`
- [x] `pvresize`
- [ ] `vgresize`
- [x] `lvresize`
- [ ] `pvrename`
:::why
`pvresize` は、下のパーティションの大きさを変えたあとに、PV の大きさを合わせるコマンドです。`lvresize` は、LV を広げることも縮めることもできます（[2.14](#lvm)）。

- `pvextend` はありません（PV は `pvresize`）
- `vgresize` はありません（VG は `vgextend` で PV を足し、`vgreduce` で外します）
- `pvrename` はありません（名前を変えられるのは `vgrename` と `lvrename`）
:::
:::

:::q 2.02.3-12 single
VG から PV を外そうとして、次のエラーになった。先にするべきことはどれか。

```text
# vgreduce vg01 /dev/sdb
  Physical volume "/dev/sdb" still in use
```
- [ ] `pvremove /dev/sdb` で、PV の印を消す
- [x] `pvmove /dev/sdb` で、`/dev/sdb` の上の PE を、VG のほかの PV へ移す
- [ ] `vgextend vg01 /dev/sdb` で、PV を VG に足し直す
- [ ] `pvcreate /dev/sdb` で、PV を作り直す
- [ ] `vgcfgbackup vg01` で、メタデータを保存する
:::why
`still in use` は、その PV の PE が、まだ LV に使われているという意味です。`pvmove` でほかの PV へ移して空にすれば、`vgreduce` で外せます（[2.15](#lvm-ops)）。

- `pvremove` は、VG に入っている PV には `please use vgreduce first` と表示して失敗します
- `/dev/sdb` は、すでに VG に入っています
- `pvcreate` は、VG に入っている PV には `-ff` なしでは失敗します。強制して作り直すと、PV の情報が上書きされて、LV が壊れます
- メタデータの保存は、外せない原因とは関係ありません
:::
:::

:::q 2.02.3-13 single
次のコマンドの説明として正しいものはどれか。

```text
# lvcreate -l 100%FREE -n lv_all vg01
```
- [ ] `vg01` の全体と同じ大きさの LV を作る。すでにある LV は消される
- [x] `vg01` の、まだ割り当てていない空きを全部使って、`lv_all` という LV を作る
- [ ] `lv_all` という LV の、100% の大きさのスナップショットを作る
- [ ] 100 MiB の LV を作る
- [ ] `vg01` の空きがなくなるまで、4 MiB の LV をいくつも作る
:::why
`-l` は、PE の個数か割合での指定です。`100%FREE` は「VG の空きの全部」、`50%VG` は「VG 全体の半分」です（[2.14](#lvm)）。大きさを量で指定するのは、大文字の `-L 100M` です。スナップショットは `-s` です。すでにある LV には影響しません。
:::
:::

:::q 2.02.3-14 multi
LVM のスナップショット（シンプロビジョニングではない、通常の LV のスナップショット）の説明として正しいものを 2 つ選択してください。
- [x] `lvcreate` に `-s`（`--snapshot`）を付け、元の LV を指定して作る
- [ ] 元の LV と同じ大きさを指定しなければ、作れない
- [ ] 作るときに、元の LV の中身をすべてコピーするので、時間がかかる
- [x] 元の LV への書き込みが、スナップショットに指定した大きさを超えると、スナップショットは使えなくなる
- [ ] `btrfs subvolume snapshot` と同じく、大きさを指定せずに作る
:::why
LVM のスナップショットは `lvcreate -s -L 大きさ -n 名前 元のLV` で作り、元の LV のブロックが書き換えられるときに、**変更前の中身だけ**を退避します（[2.15](#lvm-ops)、[図解 LinuC 5.8](../../linuc/site/ch05.html#lvm)）。

- 退避するぶんだけあればよいので、元より小さく作れます
- 作った瞬間にはコピーしないので、すぐ終わります
- 退避の領域が一杯になると、スナップショットは壊れます。`lvs` の `Data%` で使った割合を見ます
- 大きさを指定しないのは、Btrfs のスナップショットです（[2.12](#btrfs)）
:::
:::

:::q 2.02.3-15 fill

= /etc/lvm/lvm.conf

:::
