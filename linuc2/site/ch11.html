11.1Samba は何でできているか：smbd・nmbd・winbindd とポート

Samba（サンバ）は、Windows のファイル共有の決まりである SMB（Server Message Block。古い呼び名は CIFS）を Linux で話すソフトウェアです。Linux のディレクトリを Windows から「共有フォルダ」として使えます。

Samba は、役目の違うデーモンに分かれています。

デーモン役目ポート
smbdファイル共有、プリンタ共有、ユーザーの認証TCP 445（SMB を直接）、TCP 139（NetBIOS のセッション）
nmbdNetBIOS の名前解決（コンピュータ名 → IP アドレス）、ブラウジング（ネットワークの一覧）、WINS サーバーUDP 137（名前）、UDP 138（データグラム）
winbinddWindows のドメイン（AD）のユーザーとグループを、Linux のユーザー（UID・GID）として見せる（ドメインコントローラへ問い合わせる側）
sambaActive Directory のドメインコントローラ（AD DC）として動くときの親プロセス上のほかに DNS、Kerberos、LDAP

ポートは、smbd と nmbd を起動して ss で確かめたものです（ss は 図解 LinuC 7.10）。

ターミナル

「ファイル共有そのもの」は smbd の TCP 445 と 139 です。「コンピュータ名を引く」は nmbd の UDP 137 です。ファイアウォールで Samba を通すときは、この 4 つを開けます。/etc/services での名前は netbios-ns（137）、netbios-dgm（138）、netbios-ssn（139）、microsoft-ds（445）です。

11.2smb.conf はどう書くか：[global] と共有のセクション

smb.conf は、[名前] で始まるセクションと、その下の パラメータ = 値 の行でできています。# か ; で始まる行はコメントです。パラメータ名は大文字と小文字を区別せず、名前の中の空白も無視されます。

  • [global]：サーバー全体の設定です。共有ごとのパラメータをここに書くと、すべての共有の既定値になります
  • [homes]、[printers]、[print$]：特別な名前のセクションです（下で説明します）
  • それ以外の名前：その名前の共有を 1 つ作ります。[share] なら \\サーバー\share です

実際に動かした設定です。

[global]   workgroup = WORKGROUP   server string = File Server   netbios name = FS1   security = user   passdb backend = tdbsam   map to guest = Bad User   log file = /var/log/samba/log.%m   max log size = 1000   username map = /etc/samba/smbusers   hosts allow = 127. 192.168.1. [homes]   comment = Home Directories   browseable = no   read only = no   valid users = %S [share]   comment = Sales   path = /srv/share   valid users = @sales   write list = alice   read only = yes   create mask = 0660   directory mask = 0770   force group = sales [pub]   path = /srv/pub   guest ok = yes   read only = yes

特別なセクションと変数

[homes] は、接続してきたユーザーのホームディレクトリを、そのユーザー名の共有として見せます。alice が接続すると \\FS1\alice が現れ、中身は /home/alice です。browseable = no にすると、一覧には「homes」という名前は出ず、自分の名前の共有だけが出ます。

[printers] はシステムのプリンタをまとめて共有し、[print$] は Windows 用のプリンタドライバを配る共有です。IPC$ は Samba が自動で作る、通信のための特別な共有です。

11.3共有を使えるのはだれか：hosts allow・valid users・write list・Linux の権限

共有へのアクセスは、Samba の設定と Linux の権限の両方を通ったときだけ許されます。

  1. hosts allow / hosts deny：クライアントの番地で絞ります。hosts allow = 127. 192.168.1. は「127. で始まる番地と 192.168.1. で始まる番地」です。192.168.1.0/24 や 192.168.1.0/255.255.255.0 とも書けます。両方に当てはまるときは hosts allow が勝ちます
  2. 認証：security = user なら、Samba のアカウント（次の節）のユーザー名とパスワードで確かめます
  3. 共有の設定：valid users にいるか。書き込みは read only = no か、write list にいるか
  4. Linux の権限：smbd は、認証したユーザーに対応する Linux のユーザーになって、ファイルを開きます。ディレクトリの権限（図解 Linux 4.5）で書けなければ、Samba が許していても書けません

上の設定の [share] で確かめます。/srv/share は alice が持ち主、グループは sales、権限は 2770 です。alice は sales の一員で、bob は違います。

ターミナル
$ smbclient //localhost/share -U alice%pass1 -c 'put up.txt; ls'putting file up.txt as \up.txt (60000.0 kb/s) (average inf kb/s)  up.txt                              A        6  Mon Nov 16 21:19:01 2026$ smbclient //localhost/share -U bob%pass2 -c 'ls'tree connect failed: NT_STATUS_ACCESS_DENIED# ls -l /srv/share-rw-rw---- 1 alice sales 6 Nov 16 21:19 up.txt
  • bob は valid users = @sales に入らないので、共有につなぐ（tree connect）ところで断られます
  • alice は read only = yes でも、write list にいるので書けます
  • できたファイルの権限は create mask = 0660 で rw-rw----、グループは force group = sales です

ゲスト用の [pub] は guest ok = yes です。map to guest = Bad User があるので、Samba に登録のない名前で来た人は、ゲスト（guest account の nobody）として扱われます。read only = yes なので、書こうとすると断られます。

ターミナル
$ smbclient //localhost/pub -N -c 'get readme.txt; put up.txt'getting file \readme.txt of size 6 as readme.txtNT_STATUS_ACCESS_DENIED opening remote file \up.txt
コツ「つながるのに書けない」ときの切り分け

tree connect failed なら、valid users、hosts allow、認証のどれかです。つながったあとで NT_STATUS_ACCESS_DENIED が出るなら、read only と write list、それでもだめなら Linux 側の ls -ld と getfacl を見ます。Samba の設定は、Linux の権限より広い権利を与えることはできません。

11.4Samba のユーザーはどこにいるか：smbpasswd・pdbedit・username map

security = user の Samba では、ユーザーは 2 か所に登録されている必要があります。

  • Linux のユーザー（/etc/passwd。図解 LinuC 8.2）：ファイルの持ち主や権限の判定に使います
  • Samba のアカウント（passdb backend の中）：SMB の認証に使うパスワードを持ちます。/etc/shadow のパスワードとは別物です

SMB の認証は、Linux の /etc/shadow のハッシュでは確かめられない方式です。そのため Samba は、自分用のパスワードを別に持ちます。

smbpasswd と pdbedit

smbpasswd は Samba のアカウントのパスワードを変えるコマンドです。root が使うと、アカウントの追加や削除もできます。

ターミナル
# useradd -m alice                 # 先に Linux のユーザーを作る# smbpasswd -a alice               # Samba のアカウントを追加（パスワードを 2 回聞かれる）New SMB password:Retype new SMB password:Added user alice.# smbpasswd -a nouser              # Linux にいないユーザーは追加できないFailed to add entry for user nouser.
オプションすること
（なし）一般ユーザー：自分の Samba のパスワードを変える。root：smbpasswd ユーザー名 でその人のパスワードを変える
-aアカウントを追加する（add。Linux のユーザーが先に必要）
-xアカウントを削除する
-dアカウントを無効にする（disable）
-eアカウントを有効に戻す（enable）
-nパスワードなしにする
-r ホスト別のサーバーの上のパスワードを変える

pdbedit は、Samba のアカウントのデータベースを直接扱うコマンドです。一覧を見るときに使います。

ターミナル
# pdbedit -Lalice:1000:bob:1001:# smbpasswd -d bobDisabled user bob.# pdbedit -L -walice:1000:XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX:8D7A851DDE3E7BED903A41D686CD33BE:[U          ]bob:1001:XXXXXXXXXXXXXXXXXXXXXXXXXXXXXXXX:9CB25B4C2C6BCB8E6FE9384B74ED2B34:[DU         ]:

pdbedit -L は一覧、-v を足すと詳しく、-a ユーザー で追加、-x ユーザー で削除です。-w は古い smbpasswd ファイルの形で出します。[DU ] の D は無効（disabled）の印です。

注意試験の注意：smbpasswd は 2 つある

smbpasswd はコマンドの名前であり、passdb backend = smbpasswd のときにアカウントをしまうファイル（/etc/samba/smbpasswd）の名前でもあります。いまの既定は tdbsam で、アカウントは passdb.tdb に入ります。どちらの場合も、追加するコマンドは smbpasswd -a（または pdbedit -a）です。useradd や passwd では Samba のアカウントはできません。

username map：Windows の名前を Linux の名前に直す

Windows のユーザー名は「Alice Smith」のように空白を含んだり、Linux の名前と違ったりします。username map で指定したファイルに、対応を書きます。

# /etc/samba/smbusers# Linux のユーザー名 = Windows のユーザー名（空白で区切って何個でも）root = administrator adminalice = "Alice Smith" asmithnobody = guest pcguest smbguest

書式は Linux の名前 = Windows の名前 … です。左が Linux、右が Windows です。空白を含む名前は " で囲みます。smb.conf の [global] に username map = /etc/samba/smbusers と書くと有効になります。

ターミナル
$ smbclient //localhost/share -U asmith%pass1 -c 'ls'  up.txt                              A        6  Mon Nov 16 21:19:01 2026

asmith という Samba のアカウントはありませんが、対応表で alice に直されて、alice のパスワードで認証されました。

testparm はこの設定を Server role: ROLE_DOMAIN_MEMBER と表示しました。idmap config は、どのドメインのユーザーに、どの範囲の UID・GID を、どの方法（backend）で割り当てるかを決めます。

さらに /etc/nsswitch.conf の passwd: と group: の行に winbind を足すと、getent passwd や ls -l でドメインのユーザーが名前で見えるようになります。wbinfo -u は、winbindd が知っているドメインのユーザーの一覧を出します。

ACL：getfacl と setfacl

Windows の共有フォルダは、「このユーザーは読める、あのグループは書ける」と、何人にでも個別に権利を付けられます。Linux のふつうの権限は、持ち主・グループ・その他の 3 組だけです（図解 LinuC 2.1）。その差を埋めるのが ACL（Access Control List、アクセス制御リスト）です。

getfacl で見て、setfacl で変えます。

ターミナル
# getfacl d/f# file: d/f# owner: root# group: rootuser::rw-group::r--other::--- # setfacl -m u:bob:rw d/f                 # bob に rw を足す# getfacl d/f# file: d/f# owner: root# group: rootuser::rw-user:bob:rw-group::r--mask::rw-other::--- # ls -l d/f-rw-rw----+ 1 root root 0 Nov 16 21:20 d/f
  • user::（名前なし）は持ち主、group:: は所有グループ、other:: はその他で、ふつうの権限と同じものです
  • user:bob:rw- が足した項目です。group:sales:r-- のようにグループにも足せます
  • ACL が付いたファイルは、ls -l の権限の後ろに + が付きます
  • mask:: は、名前付きのユーザー、所有グループ、名前付きのグループに与えられる権利の上限です。ls -l のグループの欄（上の rw-）は、この mask を表します

mask を狭めると、項目に書いた権利より実際の権利が小さくなり、#effective: で示されます。

ターミナル
# setfacl -m g:sales:r,m::r d/f           # sales に r を足し、mask を r にする# getfacl d/fuser::rw-user:bob:rw-    #effective:r--group::r--group:sales:r--mask::r--other::---
書き方すること
setfacl -m u:ユーザー:rwx ファイルユーザーの項目を足す・変える（modify）
setfacl -m g:グループ:rx ファイルグループの項目を足す・変える
setfacl -m m::rx ファイルmask を変える
setfacl -x u:ユーザー ファイルその項目を消す（権限の部分は書かない）
setfacl -b ファイル足した ACL を全部消す（--remove-all）
setfacl -d -m u:ユーザー:rwx ディレクトリデフォルト ACL を付ける。その下に作るファイルに引き継がれる
setfacl -k ディレクトリデフォルト ACL を消す
setfacl -R …下の階層にも適用する
setfacl --restore=ファイルgetfacl -R の出力から ACL を戻す
getfacl -R ディレクトリ下の階層も表示する

デフォルト ACL はディレクトリだけに付けられ、default: で始まる行で表示されます。そのディレクトリの中に新しく作るファイルとディレクトリが、それを引き継ぎます。

ターミナル
# setfacl -d -m u:bob:rwx d# getfacl duser::rwxgroup::r-xother::r-xdefault:user::rwxdefault:user:bob:rwxdefault:group::r-xdefault:mask::rwxdefault:other::r-x
深掘りSamba と ACL：Windows の「セキュリティ」タブ

Windows のエクスプローラーの「セキュリティ」タブで権利を変えると、Samba はそれを Linux の ACL に写します。そのため、共有するファイルシステムは ACL に対応している必要があります（ext4 や XFS は標準で対応）。AD の環境では、Windows の ACL をそのまま拡張属性にしまう vfs objects = acl_xattr も使われ、AD DC では自動で有効になります。Samba 経由で「許可したはずなのに開けない」ときは、サーバーの上で getfacl を使い、mask と #effective を確かめます。

11.7NFS は何でできているか：rpcbind・mountd・nfsd とポート

NFS（Network File System）は、UNIX 系の機械どうしでディレクトリを共有する仕組みです。サーバーがディレクトリをエクスポート（公開）し、クライアントがそれをマウントすると、手元のディレクトリと同じように使えます。

NFS は RPC（Remote Procedure Call。ネットワーク越しに手続きを呼ぶ仕組み）の上で動きます。RPC のサービスは「プログラム番号」で区別され、どのポートで待つかは起動のたびに変わることがあります。その対応表を持つのが rpcbind（古い名前は portmapper、portmap）です。

デーモン役目ポート
rpcbind（portmapper）RPC のプログラム番号 → ポート番号の対応を答える111（TCP・UDP）
nfsd（rpc.nfsd が起こすカーネルのスレッド）ファイルの読み書きに答える本体2049
rpc.mountd（mountd）マウントの要求を受け、/etc/exports と照らして許可する決まっていない（rpcbind に登録）
rpc.statd、lockd（nlockmgr）ファイルのロックと、再起動の通知（NFSv3）決まっていない
rpc.idmapdNFSv4 で、ユーザー名と UID を対応させる

11.8/etc/exports はどう書くか、exportfs でどう反映するか

サーバーがどのディレクトリを、だれに、どんな条件で公開するかは、/etc/exports に書きます。1 行が 1 つのディレクトリです。

# /etc/exports/srv/nfs/data  192.168.1.0/24(rw,sync,no_subtree_check) 192.168.1.10(rw,sync,no_root_squash,no_subtree_check)/srv/nfs/pub   *(ro,sync,all_squash,no_subtree_check) *.example.com(rw,sync,no_subtree_check)

クライアントの書き方（ホストとサブネットでの制限）

書き方意味
client1.example.com、192.168.1.101 台のホスト（名前か IP アドレス）
192.168.1.0/24、192.168.1.0/255.255.255.0サブネットの全部のホスト

オプション

オプション意味既定
ro / rw読み取り専用 / 読み書きro
sync / async書き込みをディスクに書いてから応答する / 書く前に応答する（速いが、サーバーが落ちると失う）sync

ターミナル

ro、sync、root_squash が既定です。

root_squash を確かめます。クライアントの root でファイルを作ると、持ち主は 65534 になりました。

ターミナル
# touch /mnt/t/byroot                    # クライアントで、root として# ls -ln /mnt/t-rw-r--r-- 1     0     0 3 Nov 16 21:21 a.txt-rw-r--r-- 1 65534 65534 0 Nov 16 21:21 byroot
注意試験の注意：squash の 3 つ
  • root_squash（既定）：root だけを匿名にする。クライアントの root に、サーバーのファイルを好きにさせないため
  • no_root_squash：root を root のまま通す。危ないので、信頼できるホストだけに付ける
  • all_squash：全員を匿名にする。だれでも使える公開のディレクトリ向け

NFS（v3 の既定の認証）は、ユーザーを UID の数字で見分けます。サーバーとクライアントで同じユーザーの UID が違うと、別の人のファイルに見えます。

注意試験の注意：ホストとかっこの間に空白を入れない

192.168.1.5(rw) と 192.168.1.5 (rw) は、まったく違う意味です。空白を入れると、「192.168.1.5 には既定のオプション（ro）で、すべてのホスト（*）には rw で」公開してしまいます。

ターミナル
# cat /etc/exports/srv/nfs/data  192.168.1.5 (rw,sync)# exportfs -raexportfs: No host name given with /srv/nfs/data (rw,sync), suggest *(rw,sync) to avoid warning# exportfs -v/srv/nfs/data     192.168.1.5(sync,wdelay,hide,no_subtree_check,sec=sys,ro,secure,root_squash,no_all_squash)/srv/nfs/data     <world>(sync,wdelay,hide,no_subtree_check,sec=sys,rw,secure,root_squash,no_all_squash)

exportfs：エクスポートを反映する

/etc/exports を書き換えただけでは、何も変わりません。exportfs で、カーネルが持っている「いまのエクスポートの表」（/var/lib/nfs/etab）に反映します。

書き方すること
exportfsいまエクスポートしているものの一覧
exportfs -vオプションも付けて一覧（verbose）
exportfs -a/etc/exports の全部をエクスポートする（all）
exportfs -r/etc/exports に合わせ直す（reexport。消した行は取り下げる）
exportfs -ra書き換えたあとの決まり文句。全部を読み直して反映する
exportfs -u ホスト:/パスそのエクスポートを取り下げる（unexport）
exportfs -ua全部を取り下げる
exportfs -o オプション ホスト:/パス/etc/exports に書かずに、その場でエクスポートする
ターミナル
# exportfs -v/srv/nfs/data     192.168.1.10(sync,wdelay,hide,no_subtree_check,sec=sys,rw,secure,no_root_squash,no_all_squash)/srv/nfs/data     192.168.1.0/24(sync,wdelay,hide,no_subtree_check,sec=sys,rw,secure,root_squash,no_all_squash)/srv/nfs/pub      *.example.com(sync,wdelay,hide,no_subtree_check,sec=sys,rw,secure,root_squash,no_all_squash)/srv/nfs/pub      <world>(sync,wdelay,hide,no_subtree_check,sec=sys,ro,secure,root_squash,all_squash)# exportfs -o ro,sync 10.0.0.5:/srv/nfs/pub      # その場で 1 つ足す# exportfs -u 10.0.0.5:/srv/nfs/pub              # 取り下げる

exportfs -o で足したものは /etc/exports に書かれないので、再起動や exportfs -r で消えます。Red Hat 系には /etc/exports.d/ もあり、その中の *.exports というファイルも /etc/exports と同じ書式で読まれます。

11.9クライアントから使う：showmount・mount・/etc/fstab・nfsstat

showmount：サーバーが何を公開しているか

showmount は、サーバーの mountd に聞いて、エクスポートやマウントの状況を表示します。クライアントからも使えます。

ターミナル
$ showmount -e fs1Export list for fs1:/srv/nfs/pub  (everyone)/srv/nfs/data 192.168.1.0/24,192.168.1.10# showmount -a                          # サーバーの上でAll mount points on fs1:192.168.1.10:/srv/nfs/data
オプション表示するもの
-e（--exports）サーバーのエクスポートの一覧と、許されているクライアント
-a（--all）マウントしているクライアント:ディレクトリの組
-d（--directories）クライアントにマウントされているディレクトリだけ
（なし）マウントしているクライアントのホストだけ

showmount は mountd と話すので、rpcbind か mountd が止まっていると失敗します（clnt_create: RPC: Timed out など）。NFSv4 だけを通すファイアウォールの向こうからは使えません。

mount とマウントオプション

クライアントでは、サーバー:/パス を装置の代わりに書いてマウントします（図解 LinuC 5.11）。

ターミナル
# mount -t nfs fs1:/srv/nfs/data /mnt/data# mount -t nfs -o vers=3,soft,timeo=30,retrans=2,rsize=8192,wsize=8192 fs1:/srv/nfs/data /mnt/data# mount -t nfs4 fs1:/srv/nfs/data /mnt/data
オプション意味
hardサーバーが応答しないとき、応答するまでいつまでも繰り返す（既定）。プログラムは待ち続ける
softretrans 回繰り返してだめなら、プログラムにエラーを返す。データが壊れることがある
timeo=n再送までの待ち時間。単位は 0.1 秒（timeo=30 は 3 秒）
retrans=n再送の回数
rsize=n / wsize=n1 回に読む / 書くバイト数の上限
vers=n（nfsvers=n）NFS のバージョン（3、4、4.2 など）
proto=tcp / proto=udp使うトランスポート
bg / fgマウントに失敗したとき、裏で繰り返す / その場で繰り返す（既定は fg）
nolockファイルのロックを使わない（NFSv3）
ro / rw、nosuid、noexecほかのファイルシステムと同じ
_netdevネットワークが要る装置である、という印。ネットワークが上がってからマウントする

/etc/fstab に書くと、起動のたびにマウントされます（図解 LinuC 5.12）。1 列目が サーバー:/パス、3 列目が nfs（または nfs4）です。

# /etc/fstabfs1:/srv/nfs/data   /mnt/data   nfs   rw,hard,_netdev   0 0fs1:/srv/nfs/pub    /mnt/pub    nfs   ro,soft,timeo=30,noauto   0 0

NFS のファイルシステムは fsck しないので、5 列目（dump）と 6 列目（fsck の順番）は 0 0 です。

実際に使われているオプションは /proc/mounts（または mount、nfsstat -m）で確かめます。指定しなかったものも、決まった値が全部出ます。

ターミナル
$ grep nfs /proc/mountsfs1:/srv/nfs/data /mnt/data nfs rw,relatime,vers=3,rsize=8192,wsize=8192,namlen=255,soft,proto=tcp,timeo=30,retrans=2,sec=sys,mountaddr=192.168.1.1,mountvers=3,mountport=55615,mountproto=udp,local_lock=none,addr=192.168.1.1 0 0

この行からは、NFSv3（vers=3）、TCP（proto=tcp）、soft マウント、読み書きの単位が 8192 バイト、再送まで 3 秒（timeo=30）と読み取れます。

注意試験の注意：hard と soft

既定は hard です。サーバーが落ちると、そのディレクトリを触ったプログラムは、サーバーが戻るまで止まったままになります。soft はエラーを返して先へ進めますが、書き込みの途中だとデータが壊れることがあります。大事なデータを書く場所は hard、読むだけの場所は soft、が基本です。

症状確かめること

要点まとめ
  • Samba のデーモン：smbd（ファイル共有。TCP 445・139）、nmbd（NetBIOS の名前。UDP 137・138）、winbindd（ドメインのユーザー ↔ UID）、samba（AD DC）
  • 設定は /etc/samba/smb.conf、ログは /var/log/samba/。[global]、[homes]、[printers]、それ以外は共有
  • 共有の既定は read only = yes。書けるようにするのは read only = no か writable = yes。valid users、write list、hosts allow、guest ok、browseable、create mask
  • testparm で smb.conf を検査（-s は待たない、-v は既定値も表示）。反映は smbcontrol all reload-config
  • Samba のユーザーは smbpasswd -a で足す（Linux のユーザーが先に必要）。-x 削除、-d 無効、-e 有効。一覧は pdbedit -L
  • username map のファイルは Linux の名前 = Windows の名前 …
  • smbclient -L ホスト（一覧）、smbclient //ホスト/共有 -U ユーザー、smbstatus（だれがつないでいるか）、nmblookup（NetBIOS 名 → IP）、net ads join（AD に参加）、samba-tool（AD DC の管理）
  • ACL は getfacl で見て setfacl -m u:名前:rwx で足す。-x で消す、-b で全部消す、-d はデフォルト ACL。ls -l の + が印、mask が上限
  • NFS のデーモン：rpcbind（portmapper。111）、nfsd（2049）、rpc.mountd。NFSv4 は TCP 2049 だけ
  • /etc/exports：ディレクトリ ホスト(オプション)。ホストとかっこの間に空白を入れない。既定は ro、sync、root_squash
  • exportfs -ra で反映、-v で一覧、-u で取り下げ、-ua で全部取り下げ
  • showmount -e サーバー でエクスポートの一覧、rpcinfo -p で RPC のサービス、nfsstat（-s、-c、-m）で統計
  • マウントは mount -t nfs サーバー:/パス マウントポイント。既定は hard。soft、timeo（0.1 秒単位）、retrans、rsize、wsize、_netdev。実際の値は /proc/mounts
