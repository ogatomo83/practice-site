10.1SMTP の会話：メールはどんな言葉で運ばれるか

メールを運ぶプロトコルが SMTP（Simple Mail Transfer Protocol）です。メールを書く・読むプログラムが MUA、配送するサーバーが MTA、メールボックスに置くのが MDA でした（図解 LinuC 9.6）。SMTP は、MUA から MTA へ、MTA から MTA へ運ぶときに使います。

SMTP はテキストの会話です。クライアントが 1 行のコマンドを送り、サーバーが 3 桁の数字で始まる行で答えます。debian:12 の Postfix に、手で話しかけた結果です（C: の行がクライアントの送ったもの）。

ターミナル
220 mail.example.com ESMTP Postfix (Debian/GNU)C: EHLO client.example.net250-mail.example.com250-PIPELINING250-SIZE 10240000250-VRFY250-ETRN250-STARTTLS250-ENHANCEDSTATUSCODES250-8BITMIME250-DSN250-SMTPUTF8250 CHUNKINGC: MAIL FROM:<carol@example.net>250 2.1.0 OkC: RCPT TO:<alice@example.com>250 2.1.5 OkC: DATA354 End data with <CR><LF>.<CR><LF>C: Subject: helloC: From: carol@example.netC: To: alice@example.comC:C: This is a test.C: .250 2.0.0 Ok: queued as 6DD501318ECC: QUIT221 2.0.0 Bye

MAIL FROM と RCPT TO で伝える差出人と宛先をエンベロープ（封筒）と呼びます。配送に使われるのはこちらです。DATA の中の From: や To: はメールのヘッダー（便せんに書いた名前）で、配送には使われません。

コマンドと順番

コマンド意味
HELO ホスト名あいさつ（昔の SMTP）
EHLO ホスト名あいさつ（拡張 SMTP = ESMTP）。サーバーは使える拡張（STARTTLS、AUTH、SIZE …）の一覧を返す
MAIL FROM:<アドレス>差出人（エンベロープ）
RCPT TO:<アドレス>宛先（エンベロープ）。宛先の数だけくり返す
DATAここからメールの中身。「.」だけの行で終わる
RSETいまのメールの指定を取り消す（接続は続く）
VRFY アドレスその宛先があるか確かめる
STARTTLSここから TLS で暗号化する（TLS と SMTP 認証）
AUTH 方式SMTP 認証をする
QUIT終わる

順番は EHLO（HELO）→ MAIL FROM → RCPT TO → DATA → QUIT です。MAIL FROM の前に RCPT TO を送ると、503 5.5.1 Error: need MAIL command と断られました。

応答コードは 1 桁目で読む

1 桁目意味例
2xx成功220 接続時のあいさつ、250 成功、221 終了、235 認証成功
3xx続きを送ってよい354 DATA のあと「本文を送れ」
4xx一時的な失敗。あとでもう一度試せば通るかもしれない450、451、454
5xx永続的な失敗。同じことをしても通らない550 宛先がない、554 中継の拒否、530 認証が要る

送り側の MTA は、4xx を受け取るとメールをキューに残して、あとで再送します。5xx なら再送せず、差出人にエラーのメール（バウンス）を返します。

ポート番号

ポート名前使い道
25smtpMTA どうしの配送
587submissionMUA から自分のメールサーバーへの投稿。STARTTLS と SMTP 認証を使うのがふつう
465submissions（smtps）587 と同じ使い道。接続した瞬間から TLS（STARTTLS を使わない）

宛先のドメインの MTA がどのホストかは、DNS の MX レコードで調べます。alice@example.com 宛てなら、example.com の MX を引き、そのホストのポート 25 につなぎます。

注意試験の注意：数字の意味

220 は「つないだ直後のあいさつ」、250 は「そのコマンドは成功」、354 は「DATA のあと、本文を送ってよい」、221 は「QUIT への返事」です。4xx は一時的（再送する）、5xx は永続的（再送しない）です。認証の成功は 235 で、250 ではありません。

書き方の決まりは 4 つです。

  • 1 行に パラメータ = 値。= の前後の空白はあってもなくてもよい
  • # で始まる行はコメント
  • 空白で始まる行は、前の行の続き（上の mydestination の 2 行目）
  • $名前 で、ほかのパラメータの値を使える（$mydomain、$myhostname）。書く順番は関係ない

まず覚える 8 つのパラメータ

パラメータ意味例
myhostnameこのメールサーバーの名前（FQDN）mail.example.com
mydomainドメイン名。書かなければ myhostname の最初の部分を除いたものexample.com
myoriginローカルで出すメールの差出人に付けるドメイン（@ より後ろがないアドレスに補う）$mydomain
mydestinationこのサーバーが最終の宛先として受け取るドメインの一覧。ここにあるドメイン宛ては、ローカルのメールボックスに配る$myhostname, localhost.$mydomain, localhost, $mydomain
inet_interfaces接続を待つアドレス。all はすべて、localhost は自分の中からだけall
mynetworks信頼するクライアントのネットワーク。ここからは、ほかのドメイン宛ての中継を許す127.0.0.0/8, 192.168.1.0/24
relayhost外へのメールを、まとめて渡す相手（プロバイダのサーバーなど）。空なら自分で MX を引いて直接送る[smtp.provider.example]:587
home_mailbox配る先。ホームディレクトリからの相対パス。末尾が / なら Maildir 形式Maildir/

myorigin と mydestination は、向きが逆です。myorigin は出すメールの差出人、mydestination は受け取るメールの宛先に関係します。上の設定で alice が mail bob と送ると、差出人は alice@example.com、宛先は bob@example.com になります。

mydestination に $mydomain を入れ忘れると、alice@example.com 宛てのメールを「自分宛てではない」と判断します。外から来たものなら、中継の拒否（Relay access denied）になります。

relayhost の [ ] は、「MX レコードを引かずに、そのホストに直接つなぐ」という意味です。

home_mailbox を書かないと、メールは mail_spool_directory（Debian 系は /var/mail、Red Hat 系は /var/spool/mail）の下の、ユーザー名のファイルに足されます。

形式置き方設定
mbox1 つのファイルに、すべてのメールをつなげて入れる既定（/var/mail/ユーザー名）、または home_mailbox = Mailbox
Maildir1 通が 1 ファイル。ディレクトリの中に cur/、new/、tmp/home_mailbox = Maildir/
注意試験の注意：Red Hat 系の既定は inet_interfaces = localhost

rockylinux:9 に入れたばかりの Postfix は、inet_interfaces = localhost でした。この設定では 127.0.0.1 のポート 25 でしか待たないので、外からは接続できません。外からメールを受けるには inet_interfaces = all にします。inet_interfaces を変えたときは、postfix reload では足りず、Postfix を止めて起動し直します（Docker で確かめると、reload のあとも 127.0.0.1:25 のままでした）。

master.cf：ポート 587 を開ける

master.cf の 1 行が、1 つのサービスです。先頭の smtp inet … smtpd が、ポート 25 で待つ smtpd です。rockylinux:9 の master.cf には、ポート 587（submission）の行が、コメントになって入っています。

smtp      inet  n       -       n       -       -       smtpd#submission inet n       -       n       -       -       smtpd#  -o syslog_name=postfix/submission#  -o smtpd_tls_security_level=encrypt#  -o smtpd_sasl_auth_enable=yes#  -o smtpd_relay_restrictions=permit_sasl_authenticated,reject#smtps     inet  n       -       n       -       -       smtpd#  -o smtpd_tls_wrappermode=yes#  -o smtpd_sasl_auth_enable=yes

行頭の # を外すと、そのポートでも smtpd が動きます。-o 名前=値 は、そのサービスだけ main.cf の値を上書きする指定です。submission では「TLS を必ず使う（encrypt）」「SMTP 認証を有効にする」「認証した人だけ中継を許す」としています。smtps（ポート 465）の smtpd_tls_wrappermode=yes は、接続した瞬間から TLS にする指定です。

10.3中継の制限と別名：だれのメールを、どこへ運ぶか

オープンリレーにしない

自分のドメイン宛てでないメールを受け取って、ほかのサーバーへ運ぶことを中継（リレー）と呼びます。だれからの中継でも引き受けるサーバーをオープンリレー（第三者中継）と呼び、迷惑メールの踏み台にされます。

Postfix は、smtpd_relay_restrictions で中継を制限します。既定値は次のとおりです。

smtpd_relay_restrictions = permit_mynetworks, permit_sasl_authenticated, defer_unauth_destination

左から順に調べて、最初に当てはまったもので決まります。

制限意味
permit_mynetworksクライアントのアドレスが mynetworks の中なら許す
permit_sasl_authenticatedSMTP 認証に成功したクライアントなら許す
reject_unauth_destination宛先が自分のドメイン（mydestination など）でなければ、554 5.7.1 Relay access denied で断る
defer_unauth_destination同じ条件で、454 4.7.1（一時的な失敗）で断る
permit / reject無条件で許す / 断る

mynetworks の外から、よそのドメイン宛てを送ろうとした結果です（rockylinux:9、reject_unauth_destination にしたとき）。

ターミナル
C: MAIL FROM:<carol@example.net>250 2.1.0 OkC: RCPT TO:<dave@other.example.org>554 5.7.1 <dave@other.example.org>: Relay access deniedC: RCPT TO:<nosuchuser@mail.example.com>550 5.1.1 <nosuchuser@mail.example.com>: Recipient address rejected: User unknown in local recipient tableC: RCPT TO:<root@mail.example.com>250 2.1.5 Ok

よそのドメイン宛ては断り、自分のドメイン宛てでも、いないユーザーは 550 で断り、いるユーザーだけ受け取っています。

注意試験の注意：mynetworks を広げすぎない

mynetworks = 0.0.0.0/0 のように全世界を入れると、だれでも中継できるオープンリレーになります。mynetworks に入れるのは、自分自身（127.0.0.0/8）と、社内の LAN だけです。社外から送る人には、mynetworks を広げるのではなく、SMTP 認証（TLS と SMTP 認証）を使わせます。

/etc/aliases と newaliases（復習）

/etc/aliases は、ローカルの宛先の別名の表でした（図解 LinuC 9.7）。1 行が 別名: 本当の宛先, … です。Postfix は alias_maps = hash:/etc/aliases で、この表を使います。hash: は「newaliases で作ったデータベース（/etc/aliases.db）を引く」という意味です。

ターミナル
# echo 'admin: alice, bob' >> /etc/aliases# newaliases# postalias -q admin hash:/etc/aliasesalice, bob

書き換えたら newaliases です（postalias /etc/aliases でも同じ）。宛先には、ユーザー名のほかに、次のものも書けます。

右側の書き方意味
aliceローカルのユーザー
carol@example.net外のアドレスへ転送
/var/log/dropbox.txtそのファイルに足す
"|/usr/local/bin/script"そのコマンドの標準入力に渡す
:include:/etc/postfix/list.txtそのファイルに書いた宛先の一覧を使う

バーチャルの別名：virtual_alias_maps と postmap

/etc/aliases の左側に書けるのは、@ のないローカルの名前だけです。info@example.com のようなドメインの付いたアドレスを書き換えるには、virtual_alias_maps を使います。

ターミナル
# postconf -e 'virtual_alias_maps = hash:/etc/postfix/virtual'# cat /etc/postfix/virtualinfo@example.com    alicesales@example.com    alice, bob# postmap /etc/postfix/virtual# ls /etc/postfix/virtual*/etc/postfix/virtual  /etc/postfix/virtual.db# postmap -q info@example.com hash:/etc/postfix/virtualalice

こちらは : を使わず、空白で区切ります。データベースに作り直すコマンドは postmap です。

表作り直すコマンドできるファイル
/etc/aliasesnewaliases（または postalias /etc/aliases）/etc/aliases.db
/etc/postfix/virtual、transport、access、sasl_passwd などpostmap ファイルファイル.db
注意試験の注意：newaliases と postmap

/etc/aliases は newaliases、/etc/postfix/ の下の検索表（hash: で指定したもの）は postmap です。どちらも、テキストを書き換えただけでは反映されません。postmap -q キー hash:ファイル で、表を引いた結果を確かめられます。

10.4キューとログ：届かないメールを追う

/var/spool/postfix：キューのディレクトリ

受け取ったメールは、配送が終わるまでキューに入ります。Postfix のキューは /var/spool/postfix/（queue_directory）の下の、ディレクトリの集まりです。

ディレクトリ入っているもの
maildropローカルの sendmail コマンドで投げ込まれたメール。pickup デーモンが拾う
incoming受け取ったばかりのメール
activeいま配送しようとしているメール
deferred一時的に配送に失敗し、再送を待っているメール
hold管理者が保留にしたメール。解放するまで配送しない
corrupt壊れていて読めないキューファイル
private、publicデーモンどうしが話すためのソケット
pidデーモンの PID ファイル

deferred のメールは、間隔を空けながら再送を試みます。maximal_queue_lifetime（既定は 5 日）を過ぎても送れなければ、差出人にエラーを返してあきらめます。

宛先のドメインが引けないメールを送ったあとの、debian:12 の出力です。

ログの場所

Postfix は、syslog の mail ファシリティでログを出します（図解 LinuC 9.3）。どのファイルに入るかは、rsyslog の設定で決まります。

系統メールのログ
Red Hat 系/var/log/maillog
Debian 系（rsyslog を入れた場合）/var/log/mail.log（エラーだけ /var/log/mail.err にも）
systemd のジャーナルjournalctl -u postfix（図解 LinuC 9.4）

Dovecot も、既定では同じ mail ファシリティに出すので、同じファイルに入ります。

ログを読む

小さな Linux の /var/log/maillog に、Docker で動かした Postfix のログを置いてあります。1 通のメールは、同じキュー ID の行を追うと、受け取りから配送まで読めます。

キュー ID で 1 通のメールを追う⌘↵
grep 6DD501318EC /var/log/maillog
  • smtpd：client= で、どこから受け取ったか
  • cleanup：Message-ID を付けた
  • qmgr：from=<差出人>、大きさ、宛先の数。キューに入った（queue active）
  • local：to=<宛先>、status=sent。ローカルのメールボックスに配った（delivered to maildir）
  • qmgr：removed。配送が終わって、キューから消した

行の postfix/smtpd、postfix/local は、ログを出したデーモンの名前です。smtpd は受け取る側、smtp はよそのサーバーへ送る側、local はローカルに配る役目です。

配送の結果だけを集める⌘↵
grep -c 'status=sent' /var/log/mailloggrep 'status=' /var/log/maillog | grep -v 'status=sent'grep 'reject:' /var/log/maillog
ログの言葉意味
status=sent配送できた
status=deferred一時的な失敗。キュー（deferred）に残って、あとで再送する。括弧の中が理由
status=bounced永続的な失敗。差出人にエラーのメールを返した
NOQUEUE: reject: RCPT from …受け取る前に断った（キューに入っていないので NOQUEUE）。そのあとに応答コードと理由
relay=local / relay=ホスト[アドレス]:25どこへ渡したか
dsn=2.0.0 / 4.x.x / 5.x.x配送の状態のコード。1 桁目は SMTP の応答と同じ意味
orig_to=<admin>別名で書き換える前の宛先
sasl_method=PLAIN, sasl_username=aliceSMTP 認証をして送ってきた

2 つめのコマンドで出た deferred の行は、宛先のドメイン nowhere.invalid の MX が DNS で引けなかった、と言っています。3 つめの reject の行は、172.17.0.8 から dave@other.example.org 宛ての中継を断った記録です。

コツトラブルの切り分け
  1. mailq でキューに残っているか見る。残っていれば、括弧の中の理由を読む
  2. ログをキュー ID か宛先のアドレスで grep する
  3. status=deferred なら相手か DNS か経路の問題、reject なら自分の制限（mynetworks、mydestination、認証）の問題、ログに何も出ないなら、そもそも接続が届いていない（inet_interfaces、ファイアウォール、ss -ltn（図解 LinuC 7.10））

10.5TLS と SMTP 認証：暗号化して、本人を確かめる

TLS の基本設定

SMTP は、そのままでは平文です。STARTTLS は、SMTP の会話の途中で TLS に切り替える仕組みです。Postfix をサーバーとして TLS に対応させるには、証明書と秘密鍵の場所を main.cf に書きます（証明書の作り方は 9 章）。

smtpd_tls_cert_file = /etc/pki/tls/certs/postfix.pemsmtpd_tls_key_file = /etc/pki/tls/private/postfix.keysmtpd_tls_security_level = may

これは rockylinux:9 の main.cf に初めから入っている 3 行です（debian:12 では /etc/ssl/certs/ と /etc/ssl/private/ の下のファイル）。

パラメータ意味
smtpd_tls_cert_fileサーバー証明書（PEM 形式）のファイル
smtpd_tls_key_file秘密鍵のファイル
smtpd_tls_security_levelTLS をどこまで求めるか（下の表）
smtpd_tls_CAfileクライアント証明書を確かめるときなどに使う、CA の証明書
smtpd_tls_loglevelTLS のログの詳しさ。1 にすると、接続ごとにプロトコルと暗号が出る
smtpd_tls_auth_only = yesTLS で暗号化した接続でだけ、SMTP 認証を受け付ける
smtp_tls_security_levelPostfix がクライアントとしてよそへ送るときの TLS
smtpd_tls_security_level動き
none（空も同じ。既定）TLS を使わない
maySTARTTLS を案内する。クライアントが使えば暗号化し、使わなくても受け取る（日和見の TLS）
encryptTLS を必須にする。STARTTLS をしないクライアントは断る

encrypt にしたポートに、STARTTLS なしで送ろうとすると、こう断られます。

ターミナル
C: MAIL FROM:<a@example.net>530 5.7.0 Must issue a STARTTLS command first

インターネットのほかの MTA には、TLS を使えないものもあります。そのため、ポート 25 は may、ポート 587 は master.cf の -o で encrypt にするのがふつうです。

パラメータの名前は、smtpd_ がサーバー側（受け取る）、smtp_ がクライアント側（よそへ送る）です。smtpd_tls_security_level と smtp_tls_security_level は別の設定です。

smtpd_tls_loglevel = 1 にして、STARTTLS でつないだときのログです。

Nov 16 21:22:08 mail postfix/smtpd[975]: Anonymous TLS connection established from mail.example.com[172.17.0.8]: TLSv1.3 with cipher TLS_AES_256_GCM_SHA384 (256/256 bits) …

手元から確かめるには、openssl s_client に -starttls smtp を付けます。

ターミナル
$ openssl s_client -connect mail.example.com:25 -starttls smtp
メモ古い書き方：smtpd_use_tls

古い資料では、smtpd_use_tls = yes（may と同じ）と smtpd_enforce_tls = yes（encrypt と同じ）が使われています。いまは smtpd_tls_security_level を使います。

SMTP 認証（SMTP AUTH）

もとの SMTP には、送る人を確かめる仕組みがありません。SMTP 認証は、AUTH コマンドでユーザー名とパスワードを確かめる拡張です。認証には SASL（Simple Authentication and Security Layer）という枠組みを使います。Postfix は、パスワードを自分では確かめず、Cyrus SASL か Dovecot に任せます。

Dovecot に任せるときの main.cf です。

smtpd_sasl_auth_enable = yessmtpd_sasl_type = dovecotsmtpd_sasl_path = private/authsmtpd_relay_restrictions = permit_mynetworks, permit_sasl_authenticated, reject_unauth_destination
パラメータ意味
smtpd_sasl_auth_enable = yesSMTP 認証を有効にする（既定は no）
smtpd_sasl_typeSASL の実装。cyrus（既定）か dovecot
smtpd_sasl_pathDovecot のときは、認証用のソケットの場所（キューのディレクトリからの相対パス。private/auth は /var/spool/postfix/private/auth）
smtpd_sasl_security_options許さない方式。既定は noanonymous（匿名を許さない）
permit_sasl_authenticated制限の一覧に書く。認証に成功したクライアントを許す

smtpd_sasl_auth_enable = yes だけでは、認証できるようになるだけです。中継を許すのは、smtpd_relay_restrictions の permit_sasl_authenticated です。

認証を有効にすると、EHLO の返事に 250-AUTH PLAIN のような行が増えます。AUTH PLAIN のあとの文字列は、ユーザー名とパスワードを base64 にしただけのものです。暗号ではないので、TLS の中で使います。debian:12 で、STARTTLS のあとに認証して、よそのドメイン宛てを送った結果です。

ターミナル
250-AUTH PLAIN…AUTH PLAIN AGFsaWNlAHNlY3JldA==235 2.7.0 Authentication successfulMAIL FROM:<alice@example.com>250 2.1.0 OkRCPT TO:<dave@nowhere.invalid>250 2.1.5 Ok

ログには sasl_method=PLAIN, sasl_username=alice と残ります（ログを読む）。

深掘りPostfix がクライアントとして認証する（プロバイダへの中継）

relayhost のサーバーが SMTP 認証を求めるときは、Postfix がクライアントとして認証します。こちらは smtp_（d なし）のパラメータです。

relayhost = [smtp.provider.example]:587smtp_sasl_auth_enable = yessmtp_sasl_password_maps = hash:/etc/postfix/sasl_passwdsmtp_tls_security_level = encrypt

/etc/postfix/sasl_passwd には [smtp.provider.example]:587 ユーザー名:パスワード と書き、postmap /etc/postfix/sasl_passwd でデータベースにします。

/etc/dovecot：設定ファイルの置き方

設定のディレクトリは /etc/dovecot/、中心のファイルは /etc/dovecot/dovecot.conf です。dovecot.conf の最後のほうに、次の 2 行があります。

!include conf.d/*.conf!include_try local.conf

!include は、ほかのファイルを読み込む指定です。!include_try は、ファイルがなくてもエラーにしません。conf.d/ のファイルは名前の順に読まれ、同じ設定が 2 回出てきたら、あとから読んだほうが使われます。

設定の書き方は 名前 = 値 です。service 名前 { … } のように、{ } で囲んだまとまりもあります。

まず覚える設定

設定ファイル意味
protocolsdovecot.conf提供するプロトコル。protocols = imap pop3。lmtp も書ける
listendovecot.conf接続を待つアドレス。既定は *, ::（IPv4 と IPv6 のすべて）
mail_location10-mail.confメールボックスの形式と場所
disable_plaintext_auth10-auth.conf暗号化していない接続での平文の認証を断る。既定は yes
auth_mechanisms10-auth.conf使える認証の方式。既定は plain。plain login のように足す

rockylinux:9 の dovecot.conf では、protocols はコメントになっています。

#protocols = imap pop3 lmtp submission

POP3 だけを提供したければ、protocols = pop3 と書きます。debian:12 で試すと、待つポートは 110 と 995 だけになりました。

mail_location：メールボックスの形式と場所

mail_location は、Postfix が配った場所と形式に合わせます。合っていないと、ログインはできるのに、メールが 1 通も見えません。

mail_location = maildir:~/Maildirmail_location = mbox:~/mail:INBOX=/var/mail/%u
書き方意味Postfix 側の設定
maildir:~/MaildirMaildir 形式。ホームの Maildir/home_mailbox = Maildir/
mbox:~/mail:INBOX=/var/mail/%umbox 形式。受信箱は /var/mail/ユーザー名、ほかのフォルダは ~/mail/既定（home_mailbox を書かない）

%u はユーザー名、%h はホームディレクトリに置き換わります。debian:12 の 10-mail.conf は、初めから 2 つめの mbox の行でした。rockylinux:9 では mail_location が書かれておらず、Dovecot が自動で探します。

認証：だれのパスワードで確かめるか

10-auth.conf の最後で、認証の元を選びます。

auth_mechanisms = plain!include auth-system.conf.ext#!include auth-sql.conf.ext#!include auth-ldap.conf.ext#!include auth-passwdfile.conf.ext

既定の auth-system.conf.ext は、システムのユーザー（/etc/passwd のユーザーを、PAM で確かめる）を使います。doveconf -n には、次のように出ます。

passdb {  driver = pam}userdb {  driver = passwd}

passdb はパスワードを確かめる元、userdb はユーザーの UID やホームディレクトリを調べる元です。

disable_plaintext_auth = yes（既定）は、TLS で守られていない接続で、パスワードをそのまま送る認証（PLAIN、LOGIN）を断る設定です。同じ機械の中からの接続（127.0.0.1 など）は安全とみなされ、平文でも認証できます。

  • imap-login / pop3-login：どのプロトコルでログインしたか
  • user=<alice>：ユーザー、method=PLAIN：認証の方式
  • rip=：接続元（remote IP）、lip=：サーバー側のアドレス（local IP）
  • TLS：TLS で暗号化された接続

認証の失敗を詳しく調べるときは、10-logging.conf で auth_verbose = yes にします。

10.9Dovecot の TLS：ssl、ssl_cert、ssl_key

TLS の設定は conf.d/10-ssl.conf にあります。rockylinux:9 の初めの状態です。

ssl = requiredssl_cert = </etc/pki/dovecot/certs/dovecot.pemssl_key = </etc/pki/dovecot/private/dovecot.pem
設定意味
sslno：TLS を使わない。yes：TLS を使える（使うかはクライアントしだい）。required：TLS を必須にする。TLS なしではログインできない（同じ機械の中からの接続は安全とみなされ、例外。Docker で確かめた）
ssl_certサーバー証明書。< に続けてファイルのパスを書く
ssl_key秘密鍵。同じく < に続けてパス
ssl_min_protocol許す TLS の最低のバージョン。既定は TLSv1.2
ssl_cipher_list許す暗号の一覧

debian:12 では ssl = yes で、ファイルは /etc/dovecot/private/dovecot.pem と dovecot.key でした。

注意試験の注意：ssl_cert の「<」

ssl_cert = </etc/… の < は、「このファイルの中身を値にする」という印です。< を忘れて ssl_cert = /etc/… と書くと、パスの文字列そのものを証明書として読もうとします。Docker で試すと、doveconf はエラーを出さず、接続したときにログに Can't load SSL certificate (ssl_cert setting): There is no valid PEM certificate. と出て、TLS の接続が切れました。

TLS の使い方は、ポートで 2 通りあります。

使い方ポート確かめ方
初めから TLS（IMAPS、POP3S）993、995openssl s_client -connect ホスト:993
平文でつないで STARTTLS で切り替える143、110openssl s_client -connect ホスト:143 -starttls imap

debian:12 で、ポート 995 に TLS でつないで POP3 を話した結果です。

ターミナル
$ openssl s_client -connect mail.example.com:995 -quiet+OK Dovecot (Debian) ready.USER alice+OKPASS secret+OK Logged in.STAT+OK 3 1369QUIT+OK Logging out.

Postfix の SMTP 認証を Dovecot が引き受ける

SMTP 認証で、Postfix に smtpd_sasl_type = dovecot、smtpd_sasl_path = private/auth と書きました。Dovecot の側では、10-master.conf の service auth に、そのソケットを作る設定を書きます。

service auth {  unix_listener /var/spool/postfix/private/auth {    mode = 0660    user = postfix    group = postfix  }}

これで、POP3 / IMAP と SMTP 認証が、同じユーザー名とパスワードで通ります。Postfix の smtpd_sasl_path は /var/spool/postfix からの相対パスなので、2 つの設定は同じソケットを指しています。

メモDovecot 2.4 では設定の名前が変わった

この章は、試験の範囲と同じ Dovecot 2.3 までの書き方です。2.4 では、ssl_cert が ssl_server_cert_file、mail_location が mail_driver と mail_path になるなど、設定の名前が大きく変わりました。試験では、この章の名前（ssl_cert、ssl_key、mail_location）を覚えてください。

要点まとめ
  • SMTP の順番は EHLO（HELO）→ MAIL FROM → RCPT TO → DATA → QUIT。応答は 2xx 成功、354 本文を送れ、4xx 一時的な失敗、5xx 永続的な失敗。ポートは 25（配送）、587（投稿）、465（初めから TLS）
  • Postfix の設定は /etc/postfix/main.cf（パラメータ）と master.cf（サービスとポート）。myhostname、mydomain、myorigin（差出人に付ける）、mydestination（自分宛てとして受け取る）、inet_interfaces（Red Hat 系の既定は localhost）、mynetworks（中継を許す相手）、relayhost、home_mailbox = Maildir/
  • postconf -n（main.cf に書いたもの）、-d（既定値）、-e（書き換え）。postfix check（検査）、postfix reload（読み直し）
  • 中継の制限は smtpd_relay_restrictions = permit_mynetworks, permit_sasl_authenticated, reject_unauth_destination。断ると 554 5.7.1 Relay access denied
  • /etc/aliases は newaliases、/etc/postfix/virtual などは postmap
  • キューは /var/spool/postfix/（incoming、active、deferred、hold）。mailq = postqueue -p、postqueue -f（流す）、postsuper -d ID / -d ALL（消す）、-h / -H（保留 / 解く）、postcat -q ID（中身）
  • ログは /var/log/maillog（Red Hat 系）、/var/log/mail.log（Debian 系）。キュー ID で追う。status=sent / deferred / bounced、NOQUEUE: reject
  • TLS：smtpd_tls_cert_file、smtpd_tls_key_file、smtpd_tls_security_level = may（使えれば使う）/ encrypt（必須）。smtpd_ はサーバー側、smtp_ はクライアント側
  • SMTP 認証：smtpd_sasl_auth_enable = yes、smtpd_sasl_type = dovecot（既定は cyrus）、smtpd_sasl_path、permit_sasl_authenticated
  • exim：Debian 系の既定の MTA。/etc/exim4/、exim -bp（キュー）、exim -bt（宛先の試験）
  • Dovecot は POP3（110、995）と IMAP（143、993）のサーバー。/etc/dovecot/dovecot.conf と conf.d/。protocols、listen、mail_location = maildir:~/Maildir、disable_plaintext_auth
  • doveconf -n（既定と違う設定）、doveadm reload / who / kick / user / pw / auth test / log find
  • Dovecot の TLS：ssl = yes / required / no、ssl_cert = </パス、ssl_key = </パス（< を忘れない）
