4.1ソースからインストールする流れは、取る → 展開する → configure → make → make install

ふつう、ソフトウェアはパッケージ（.deb、.rpm）で入れます（図解 LinuC 4 章）。しかし、パッケージがまだない新しい版を使いたいとき、機能の有効・無効を自分で選びたいときは、ソースコードから自分で組み立てます。これをビルドと呼びます。

手順は、ほとんどのソフトで同じです。

段階コマンドすること権限
1. 取るgit clone URL、または .tar.gz をダウンロードソースコードを手元に置く一般ユーザー
2. 展開するtar xf、unzip、必要なら patchアーカイブをほどき、修正を当てる一般ユーザー
3. 調べる./configureコンパイラやライブラリがあるかを調べ、Makefile を作る一般ユーザー
4. 組み立てるmakeMakefile を読んでコンパイルする一般ユーザー
5. 入れるmake installできたファイルを、インストール先へコピーするroot（/usr/local に書くため）

ソースの中には、たいてい README と INSTALL という文書があります。そのソフトだけの手順やオプションは、そこに書いてあります。まず読みます。

注意試験の注意：root が要るのは make install だけ

./configure と make は、ソースのディレクトリの中にファイルを作るだけなので、一般ユーザーで実行します。root が要るのは、/usr/local などシステムのディレクトリへ書き込む make install だけです。「make を root で実行する必要がある」という選択肢は誤りです。

4.2ソースを手に入れる：git clone とタグ、tar と圧縮

git clone、git tag -l、git checkout

多くのソフトは、Git のリポジトリ（変更の履歴を持つ置き場所）で公開されています。使うコマンドは 3 つです。

コマンドすること
git clone URL [ディレクトリ]リポジトリを履歴ごと手元に複製する。ディレクトリを省くと、リポジトリの名前（最後の .git を除いたもの）で作る
git clone -b 名前 URL複製して、そのブランチかタグを取り出す
git clone --depth 1 URL最新の 1 つの版だけを複製する（履歴を取らないので速い）
git tag -l（git tag）タグの一覧を表示する。git tag -l 'v1.*' のようにパターンで絞れる
git checkout タグ作業ディレクトリを、そのタグの版の中身に切り替える
git checkout -b 新ブランチ タグそのタグの版から、新しいブランチを作って切り替える

タグは、リリースした版に付ける名前（v1.0 など）です。複製した直後の作業ディレクトリは、開発中の最新の状態です。安定した版をビルドしたいときは、git tag -l でタグを調べ、git checkout でその版に切り替えます。Debian 12 で実際に動かした結果です。

ターミナル
$ git clone /root/up projCloning into 'proj'...done.$ cd proj$ git tag -lv1.0v1.1v2.0$ git tag -l 'v1.*'v1.0v1.1$ git checkout v1.1Note: switching to 'v1.1'.…HEAD is now at a957c41 two$ git branch* (HEAD detached at v1.1)  main

タグを git checkout すると、detached HEAD（どのブランチにも乗っていない状態）になります。エラーではありません。その版を見たりビルドしたりするだけなら、このままでかまいません。元に戻るには git checkout main のようにブランチの名前を指定します。

アーカイブを展開する：tar、gzip、bzip2、xz、unzip

配布されるソースは、名前-版.tar.gz のような tarball（tar でまとめて圧縮したファイル）が普通です。tar と 3 つの圧縮コマンドは 図解 LinuC 2.5 で学びました。対応を表で復習します。

拡張子圧縮のコマンド展開のコマンド中身を標準出力へtar のオプション
.gz（.tar.gz、.tgz）gzipgunzip、gzip -dzcat、gzip -dcz
.bz2（.tar.bz2）bzip2bunzip2、bzip2 -dbzcat、bzip2 -dcj
.xz（.tar.xz）xzunxz、xz -dxzcat、xz -dcJ（大文字）
.zipzip -runzipunzip -p—（tar は使わない）

圧縮率は、ふつう gzip < bzip2 < xz の順に高くなり、かかる時間もその順に長くなります。3 つとも、圧縮すると元のファイルは消えて圧縮したファイルだけが残ります。元を残すのは -k（keep）か、-c で標準出力に書く方法です。

ターミナル
$ tar xzf hello-2.12.1.tar.gz          … gzip の tarball を展開$ tar xjf proj.tar.bz2 -C /usr/local/src … bzip2。-C で展開先を指定$ tar xJf linux-6.1.tar.xz             … xz$ tar xf d.tar.bz2                     … GNU tar は、展開のときは圧縮の種類を自分で見分ける$ tar tzf hello-2.12.1.tar.gz | head -3  … 展開せずに中身の一覧を見る$ tar xzf d.tar.xzgzip: stdin: not in gzip formattar: Child returned status 1

最後の例のように、圧縮の種類と違うオプション（xz のファイルに z）を付けると失敗します。z、j、J を付けずに tar xf とすれば、GNU tar が自分で見分けます。

.zip は、まとめることと圧縮を 1 つのコマンドでする別の形式です。展開は unzip です。

書き方意味
unzip file.zipいまのディレクトリに展開する
unzip file.zip -d ディレクトリ-d で指定したディレクトリに展開する
unzip -l file.zip展開せずに、中身の一覧を表示する
unzip -t file.zip壊れていないかを検査する
unzip -o file.zip確認せずに上書きする

-d の意味はコマンドで違います。gzip -d、bzip2 -d、xz -d の -d は「展開する（decompress）」です。unzip -d の -d は「展開先のディレクトリ」です。tar で展開先を決めるのは -C（大文字）です。

4.3patch、configure、make、make install は、それぞれ何をするか

patch：差分を当てる

パッチは、古いソースと新しいソースの差分を書いたファイルです。diff で作り、patch で当てます。ソース全体を配り直さなくても、修正だけを小さなファイルで配れます。

ターミナル
$ diff -Nur hello-1.0 hello-1.1 > d.patch       … 2 つのディレクトリの差分を作る$ cat d.patchdiff -Nur hello-1.0/src/a.txt hello-1.1/src/a.txt--- hello-1.0/src/a.txt    2026-11-16 21:20:01.311614003 +0000+++ hello-1.1/src/a.txt    2026-11-16 21:20:01.311614003 +0000 -1,3 +1,4 @@ line1-line2+line2 changed line3+line4

- で始まる行が消える行、+ で始まる行が足される行です。--- と +++ の行に、対象のファイルのパスが書いてあります。このパスの先頭を何個削って使うかを決めるのが、-p です。

ターミナル
$ cd work                                  … hello-1.0 と同じ中身のディレクトリ$ patch --dry-run -p1 < ../d.patch         … 試すだけ。ファイルは変えないchecking file src/a.txt$ patch -p1 < ../d.patch                   … 当てるpatching file src/a.txt$ patch -R -p1 < ../d.patch                … -R で元に戻すpatching file src/a.txt$ patch -p0 < ../d.patch                   … -p の数がまちがっていると、ファイルが見つからないcan't find file to patch at input line 4Perhaps you used the wrong -p or --strip option?
オプション意味
-p数（--strip=数）パッチの中のパスの先頭から、その数だけディレクトリの部分を削る。-p0 は削らない。-p を付けないと、ファイル名だけ（ディレクトリの部分を全部削ったもの）を使う
-R（--reverse）逆向きに当てる。当てたパッチを取り消す
--dry-run当てられるかを試すだけで、ファイルを変えない
-b（--backup）元のファイルを 名前.orig として残す
-i ファイルパッチを標準入力ではなく、そのファイルから読む（patch -p1 -i x.patch は patch -p1 < x.patch と同じ）
-d ディレクトリそのディレクトリに移ってから当てる

パッチがソースと合わず、当てられなかった部分（ハンク）は、名前.rej というファイルに書き出されます。

configure：環境を調べて Makefile を作る

configure は、ソースに付いてくるシェルスクリプトです。ソースのディレクトリの中で ./configure として実行します。コンパイラ、必要なライブラリ、ヘッダファイルがその機械にあるかを調べ、結果に合わせた Makefile を作ります。

ターミナル
$ ./configure --prefix=/opt/hellochecking for a BSD-compatible install... /usr/bin/install -cchecking whether build environment is sane... yes…configure: creating ./config.statusconfig.status: creating Makefileconfig.status: creating config.h$ ls Makefile config.status config.logMakefileconfig.logconfig.status
オプション意味
--prefix=ディレクトリインストール先の起点。既定は /usr/local（実行ファイルは /usr/local/bin、ライブラリは /usr/local/lib に入る）
--helpそのソフトで使えるオプションの一覧を表示する
--bindir=、--sysconfdir=、--mandir= など種類ごとの置き場所を細かく指定する
--enable-機能、--disable-機能、--with-パッケージ機能や、使う外部のライブラリを選ぶ（ソフトごとに違う）

必要なライブラリが足りないと、configure は error: を出して止まり、Makefile を作りません。調べた記録は config.log に残るので、原因はそこで調べます。

make と make install

make は、カレントディレクトリの Makefile を読み、そこに書かれた手順でコンパイルします。Makefile には「ターゲット（作るもの）」と、その作り方が並んでいます。make ターゲット で、そのターゲットを作ります。ターゲットを省くと、Makefile の最初のターゲット（ふつうは全体をビルドする all）を作ります。

ターミナル
$ make                                 … コンパイルする…gcc  -g -O2   -o hello src/hello.o  ./lib/libhello.a$ ls -l hello-rwxr-xr-x 1 root root 204312 Nov 16 21:20 hello# make install                         … root で。prefix の下へコピーする /usr/bin/mkdir -p '/opt/hello/share/man/man1' /usr/bin/install -c -m 644 hello.1 '/opt/hello/share/man/man1'$ /opt/hello/bin/helloHello, world!
書き方すること
make最初のターゲット（ふつう all）を作る。コンパイルする
make installできたファイルを、prefix の下へコピーする
make cleanコンパイルでできたファイル（.o や実行ファイル）を消す。Makefile は残る
make distcleanmake clean に加えて、configure が作ったもの（Makefile など）も消す。配布された状態に戻す
make uninstallインストールしたファイルを消す（Makefile に用意されているときだけ）
make -j 44 つの仕事を並行して実行する（速くなる）
make -n実行するコマンドを表示するだけで、実行しない
make -f ファイルMakefile ではなく、そのファイルを読む
make -C ディレクトリそのディレクトリに移ってから実行する
make install DESTDIR=/tmp/stageインストール先の前に DESTDIR を付ける（/tmp/stage/opt/hello/bin/hello に入る。パッケージを作るときに使う）
メモパッケージ管理の外に入る

make install で入れたソフトは、dpkg -l や rpm -qa に出ません。更新も削除も自分でします。make uninstall が用意されていないソフトもあります。だから、既定のインストール先は、パッケージが使う /usr と分けた /usr/local になっています。--prefix=/opt/名前 のように 1 つのディレクトリにまとめておくと、消すときはそのディレクトリを消すだけで済みます。

4.4バックアップは、何を・どれだけ・どこへ取るか

フル、差分、増分

毎日全部を写すと、時間も場所もかかります。そこで、前のバックアップから変わったものだけを取る方法を組み合わせます。

種類取るもの1 回の量と時間元に戻す（リストア）のに要るもの
フルバックアップ全部いちばん大きいそのフル 1 つ
差分バックアップ（differential）最後のフルから変わったもの日がたつほど大きくなるフル + 最新の差分 1 つ
増分バックアップ（incremental）直前のバックアップ（フルでも増分でも）から変わったものいちばん小さいフル + その後の増分を全部、順番に

上の図で、水曜の夜に壊れたとします。差分なら「日曜のフル → 水曜の差分」の 2 つで戻せます。増分なら「日曜のフル → 月 → 火 → 水」の 4 つを順に戻します。増分は取るのが速い代わりに、戻すのに手間がかかり、途中の 1 つが壊れるとそれより後が戻せません。

ファイル、ブロック、イメージ

「何の単位で写すか」にも種類があります。

単位写すもの道具の例特徴
ファイル単位ファイルとディレクトリtar、rsync、cpio必要なファイルだけ選べる。1 つのファイルだけ戻せる。ファイルシステムの種類が違う所へも戻せる
ブロック単位デバイスのブロック（中身を解釈しない）ddファイルシステムの種類に関係なく、そっくり写せる。使っていない領域も写すので大きい
イメージディスクやパーティションの全体を 1 つのファイル（イメージ）にしたものdd if=/dev/sda of=sda.imgブートローダやパーティション表も含めて、システムを丸ごと戻せる

媒体：テープ、ハードディスク、光学メディア

媒体読み書き向いている使い方
テープ（LTO など）順番にしか読み書きできない（シーケンシャルアクセス）。途中のファイルを取り出すのは遅い容量あたりの値段が安く、長く保管できる。大量のデータの長期保管
ハードディスク好きな場所をすぐ読み書きできる（ランダムアクセス）速い。日々のバックアップと、すばやいリストア
光学メディア（CD-R、DVD-R、BD-R）書き込みは 1 回だけのものが多い。容量は小さい書き換えられないので、改ざんされては困るデータの保管

ネットワークバックアップのソフト

たくさんの機械のバックアップを 1 台のサーバーで集中して管理する、オープンソースのソフトです。名前と特徴の組み合わせが問われます。

名前特徴
Amanda1 台のバックアップサーバーから、ネットワーク上の多くのクライアントをテープやディスクへ取る。中では OS に標準の dump や tar を使うので、Amanda がなくても戻せる
BaculaDirector（全体の指揮）、Storage Daemon（媒体への読み書き）、File Daemon（クライアント側）、Catalog（何をどこに取ったかのデータベース）、Console に分かれた構成。企業向けの大きな構成に使われる
BareosBacula から分かれた（フォークした）ソフト。構成は Bacula と同じ（Director、Storage Daemon、File Daemon）
BackupPCディスクへ取る。Web の画面で操作する。クライアントに専用のソフトを入れず、rsync、tar（ssh 経由）、SMB で取る。同じ中身のファイルは 1 つだけ保存して、場所を節約する

4.5tar、dd、rsync でバックアップを取る

tar：増分バックアップは -g

tar でファイル単位のバックアップを取ります。基本の c、x、t、f、v、z は 図解 LinuC 2.5 の通りです。バックアップで使うオプションを足します。

オプション意味
-g ファイル（--listed-incremental=ファイル）増分バックアップ。そのファイル（スナップショットファイル）に「前回どこまで取ったか」を記録し、次からは変わったものだけを取る
-N 日付（--newer=日付）その日付より新しいファイルだけを取る
-p（--preserve-permissions）展開のとき、パーミッションをアーカイブの通りに戻す
--exclude=パターンパターンに合うファイルを除く
-M（--multi-volume）1 本のテープに入りきらないとき、複数の媒体に分ける
-W（--verify）書いた後に、正しく書けたかを確かめる
-C ディレクトリそのディレクトリに移ってから処理する

-g の使い方を、Debian 12 で確かめます。スナップショットファイルがまだないときは、全部を取ります（フル）。同じスナップショットファイルを指定してもう一度実行すると、変わったものだけを取ります（増分）。

ターミナル
# tar -czf full.tar.gz -g snap.snar data        … 1 回目：snap.snar がないので、フル# echo c > data/c.txt; echo a2 >> data/a.txt    … 1 つ足し、1 つ書き換える# tar -czvf inc1.tar.gz -g snap.snar data       … 2 回目：変わったものだけdata/data/sub/data/a.txtdata/c.txt# echo d > data/d.txt; rm data/sub/b.txt# tar -czvf inc2.tar.gz -g snap.snar data       … 3 回目：2 回目から変わったものだけdata/data/sub/data/d.txt

戻すときは、フルから順番に、-g /dev/null を付けて展開します。増分のアーカイブには「消されたファイル」の情報も入っているので、途中で消した b.txt は、戻した先でも消えます。

Debian 12 で、上の 3 つを for f in full inc1 inc2; do tar -xzf $f.tar.gz -g /dev/null -C r; done の順に戻すと、a.txt、c.txt、d.txt が戻り、b.txt はありませんでした。

テープに直接書くときは、f にテープのデバイスを指定します（tar cvf /dev/st0 /home）。

dd：ブロック単位で丸ごと写す

dd は、ファイルシステムの中身を解釈せず、ブロックをそのまま写します（図解 LinuC 2.5、図解 Linux 15.7）。ディスクやパーティションのイメージを取るのに使います。

ターミナル
# dd if=/dev/sda of=/backup/sda.img bs=4M            … ディスク全体をイメージファイルへ# dd if=/backup/sda.img of=/dev/sda bs=4M            … イメージからディスクへ戻す# dd if=/dev/sda of=/dev/sdb bs=4M                   … ディスクからディスクへ複製# dd if=/dev/sda of=mbr.bin bs=512 count=1           … 先頭の 512 バイト（MBR）だけ# dd if=/dev/sda1 bs=4M | gzip > sda1.img.gz         … 圧縮しながら取る# dd if=/dev/sda of=sda.img bs=4M conv=noerror,sync  … 読めないブロックがあっても続ける

if= が読む元、of= が書く先です。bs= は 1 回に読み書きする大きさ、count= は回数です。conv=noerror は読み取りエラーがあっても止まらずに続け、sync は読めなかった分を 0 で埋めて位置がずれないようにします。壊れかけたディスクを写すときの組み合わせです。

rsync：変わった分だけを送って、同じにする

rsync は、コピー元とコピー先を比べて、違うところだけを送り、2 つのディレクトリを同じにするコマンドです。2 回目からは変わったファイルだけを送るので、速く終わります。ネットワーク越しのコピーにも使えます。

ターミナル
$ rsync -av data/ dst2                 … data の中身を dst2 へsending incremental file lista.txtc.txtsub/sub/b.txt sent 274 bytes  received 81 bytes  710.00 bytes/sectotal size is 9  speedup is 0.03
オプション意味
-a（--archive）アーカイブモード。-rlptgoD と同じ。ディレクトリの中をたどり（r）、シンボリックリンク（l）、パーミッション（p）、時刻（t）、グループ（g）、所有者（o）、デバイスファイル（D）を保つ
-v送ったファイルの名前を表示する
-z送るときにデータを圧縮する（回線が遅いときに効く。コピー先のファイルは圧縮されない）
-n（--dry-run）何が起きるかを表示するだけで、実際には何もしない
--deleteコピー元にないファイルを、コピー先から消す
-e ssh（--rsh=ssh）リモートへつなぐのに使うコマンドを指定する
-u（--update）コピー先のほうが新しいファイルは飛ばす

-a には、ハードリンク（-H）、ACL（-A）、拡張属性（-X）は入っていません。必要なら足します。

何もオプションを付けないと、コピー元にないファイルはコピー先に残ります。コピー元とまったく同じにする（ミラーにする）には --delete を付けます。

注意試験の注意：--delete とドライラン

--delete は、コピー元とコピー先を取り違えると、大事なファイルを消します。先に -n（--dry-run）を付けて、何が消されるかを確かめます。rsync -avn --delete … の出力の最後には (DRY RUN) と出ます。

4.6テープは、巻き戻すデバイスと巻き戻さないデバイスを使い分ける

SCSI のテープ装置は、2 つの名前で見えます。どちらも同じ装置ですが、使い終わった（デバイスファイルを閉じた）ときの動きが違います。

デバイスファイル閉じたとき使いどころ
/dev/st0テープを先頭まで巻き戻す（rewind）1 本のテープに 1 つだけアーカイブを書くとき
/dev/nst0巻き戻さない（no rewind）。書き終わった位置で止まる1 本のテープに、続けていくつもアーカイブを書くとき

st は SCSI tape、先頭の n は no rewind です。2 台目の装置は /dev/st1 と /dev/nst1 になります。

/dev/st0 に 2 回続けて tar で書くと、1 回目の後に巻き戻るので、2 回目は先頭から書いて 1 回目を上書きします。続けて書きたいときは /dev/nst0 を使います。

テープの位置を動かすのが mt（magnetic tape）です。書式は mt -f デバイス 操作 [回数] です。-f を省くと、環境変数 TAPE に書かれたデバイスを使います。

操作すること
status装置とテープの状態を表示する
rewind先頭まで巻き戻す
fsf 数その数だけ先のファイル（アーカイブ）の先頭へ進む（forward space file）
bsf 数その数だけ前へ戻る（backward space file）
eod書かれているデータの終わりへ進む（続きを書き足すとき）
offline（rewoffl）巻き戻して、テープを取り出せる状態にする
eraseテープを消去する
ターミナル
# tar cvf /dev/nst0 /etc           … 1 つ目を書く。巻き戻さない# tar cvf /dev/nst0 /home          … 続けて 2 つ目を書く# mt -f /dev/nst0 rewind           … 先頭へ巻き戻す# mt -f /dev/nst0 fsf 1            … 1 つ先（2 つ目のアーカイブ）へ進む# tar tvf /dev/nst0                … 2 つ目の中身の一覧# mt -f /dev/nst0 offline          … 巻き戻して取り出す

「n が付いたら no rewind」です。続けて書く、mt fsf で位置を合わせて読む、という操作は、勝手に巻き戻されると困るので、必ず /dev/nst0 を使います。

4.11OOM Killer は、メモリが尽きたときにだれを終わらせるか

物理メモリもスワップも使い切ると、カーネルは OOM Killer（Out Of Memory Killer）を動かします。プロセスを 1 つ選んで SIGKILL で終わらせ、そのメモリを取り返します（図解 Linux 13.10）。小さな Linux で、メモリを食い尽くすプログラムを動かして確かめます。

メモリを使い切ると、Killed で終わるエラーになる⌘↵
memhog 8M > /dev/null
カーネルのログに記録が残る⌘↵
dmesg | grep 'Out of memory'

「プログラムが何も言わずに消えた」ときは、dmesg か journalctl -k で Out of memory: Killed process を探します。

だれを選ぶかは、プロセスごとの点数で決まります。

ファイル意味
/proc/PID/oom_scoreいまの点数。メモリを多く使っているほど高い。高いものから終わらせる。読むだけ
/proc/PID/oom_score_adj点数の調整値。-1000 〜 1000。大きくすると選ばれやすく、小さくすると選ばれにくい。-1000 にすると、そのプロセスは選ばれない
/proc/PID/oom_adj古い調整値（-17 〜 15。-17 で選ばれない）。いまは oom_score_adj を使う
oom_score_adj で、選ばれやすさを変える⌘↵
cat /proc/$$/oom_score /proc/$$/oom_score_adjecho 500 > /proc/$$/oom_score_adjcat /proc/$$/oom_scoresudo sh -c "echo -1000 > /proc/$$/oom_score_adj"cat /proc/$$/oom_score

調整値を 500 にすると点数が上がり、-1000 にすると 0 になりました。0 より小さい値にする（既定より選ばれにくくする）には root の権限が要ります。一般ユーザーが自分のプロセスに書けるのは、選ばれやすくする向きだけです。データベースのように、終わらせられては困るプロセスに -1000 を設定する、という使い方をします。systemd のサービスなら、unit ファイルに OOMScoreAdjust=-1000 と書けます。

メモリの確保をどこまで許すかは、カーネルのパラメータで決まります。

パラメータ（sysctl の名前）意味
vm.overcommit_memory0（既定）：明らかに無理な要求だけ断る。1：いつも許す。2：スワップ + 物理メモリの一定の割合（vm.overcommit_ratio。既定 50%）までしか許さない
vm.panic_on_oom0（既定）：OOM Killer がプロセスを終わらせる。1：プロセスを終わらせる代わりに、カーネルパニックにする
vm.oom_kill_allocating_task0（既定）：点数の高いプロセスを選ぶ。1：メモリを要求したプロセス自身を終わらせる

4.13Ansible は、エージェントなしで、SSH で設定を配る

サーバーが 1 台なら、手でコマンドを打って設定できます。50 台になると、同じ操作を 50 回まちがえずに繰り返すのは無理です。構成管理ツールは、「サーバーがどういう状態であるべきか」をファイルに書いておき、その通りにたくさんの機械を設定します。Ansible は、その代表です。

用語意味
コントロールノードAnsible を入れて、コマンドを実行する機械

インベントリ管理対象ノードの一覧。グループに分けて書く
モジュール1 つの仕事をする部品（パッケージを入れる、ファイルを置く、サービスを起動する）

Ansible の特徴は 3 つです。

  • エージェントレス：管理対象ノードに、専用の常駐プログラム（エージェント）を入れません。SSH でつないで、その場でモジュールを送り込んで実行します
  • プッシュ型：コントロールノードのほうから、設定を送りつけます
  • YAML で書く：手順（Playbook）は、プログラミング言語ではなく、読みやすい YAML で書きます

冪等性

Ansible のモジュールは、「この操作をしろ」ではなく、「この状態であれ」と書きます。state: present（入っている状態）と書いたパッケージは、入っていなければ入れ、すでに入っていれば何もしません。だから、同じ Playbook を何回実行しても、結果は同じです。これが冪等性です。

シェルスクリプトで echo "port=8080" >> app.conf と書くと、実行するたびに行が増えます。これは冪等ではありません。Ansible で同じファイルを 2 回コピーした結果を見ます（Debian 12、ansible-core 2.14）。

ターミナル

handlers:ハンドラーのリスト。呼ばれたものだけが、全部のタスクが終わった後に 1 回動く

注意試験の注意：--syntax-check と --check

--syntax-check は、YAML と Playbook の書き方を確かめるだけで、管理対象ノードにはつなぎません。--check（-C）は、管理対象ノードにつないで、変更せずに何が変わるかを調べます。「実際には変更しないで試す（ドライラン）」は --check です。なお、command と shell のタスクは、チェックモードでは実行されず、skipping になります。
