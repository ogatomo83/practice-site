2.3/etc/mtab と /proc/mounts：いま何がつながっているか

fstab は「起動のときにつなぐ予定」の表です。「いま実際につながっているもの」は、別の 2 つの場所で見ます。

ファイルだれが書くか特徴
/etc/fstab管理者起動時にマウントする予定。mount -a、systemd が読む
/etc/mtab昔は mount と umount昔は普通のファイル。/ が読み取り専用だと更新できず、実際とずれることがあった。mount -n は、ここに書かずにマウントする。今のディストリビューションでは /proc/self/mounts へのシンボリックリンク
/proc/mountsカーネルカーネルが持つ実際のマウントの表。/proc/self/mounts へのリンクで、そのプロセスから見えるマウントが出る

Debian 12 でも Rocky Linux 9 でも、/etc/mtab はリンクです。

ターミナル

小さな Linux で、tmpfs をマウントして確かめます。

マウントすると /proc/mounts に 1 行増えるroot で実行⌘↵

mount（引数なし）マウントの一覧（何 on どこ type 種類 (オプション)）
cat /proc/mounts同じ内容を fstab の形で
findmnt木の形で。findmnt マウントポイント で 1 つだけ。findmnt --verify は fstab の書きまちがいを調べる

注意試験の注意：どれが「実際」か

「現在マウントされているファイルシステムを、カーネルの情報から確かめる」なら /proc/mounts（または /proc/self/mounts）です。/etc/fstab は予定の表で、手で mount したものは載りません。/etc/mtab は「mount コマンドが記録するファイル」として問われ、/proc/mounts は「カーネルが提供する」として問われます。

2.4systemd とマウントの順番：fstab は .mount ユニットになる

systemd の Linux では、起動のときに mount -a を実行しているのではありません。systemd-fstab-generator という小さなプログラムが fstab を読み、1 行ごとに .mount ユニット（スワップは .swap ユニット）を作ります。systemd は、それをほかのユニットと同じように、依存の順に起動します（unit については 図解 Linux 17.4、図解 LinuC 1.8）。

マウントの順番は、何で決まるか

場面順番の決まり方
mount -afstab に書いた順（上から）。だから /var の行は /var/log の行より上に書く
systemd の起動fstab の行の順ではなく、依存で決まる。マウントポイントのパスが親子なら、親（/var）が先、子（/var/log）が後になる依存を、systemd が自動で付ける
ローカルとネットワークローカルのものは local-fs.target の前に。NFS などのネットワークのファイルシステムと _netdev の付いたものは、ネットワークが使えるようになった後、remote-fs.target の前に
fsck6 欄目の番号の順（1 → 2）。0 は検査しない

親が先でなければならない理由は、小さな Linux で確かめられます。親（/srv/data）の上に子（/srv/data/logs）をマウントすると、子を外すまで親は外せません。外すときは、マウントの逆の順です。

子をマウントしたまま、親は外せないエラーになるroot で実行⌘↵
mkdir /srv/data/logsmount -t tmpfs tmpfs /srv/data/logsgrep /srv /proc/mountsumount /srv/data
外すのは、子 → 親の順root で実行⌘↵
umount /srv/data/logsumount /srv/data

fstab の必須の行（nofail も noauto もない行）のマウントに失敗すると、local-fs.target が失敗し、systemd は緊急モード（emergency.target。root のパスワードを聞くシェル）に入ります。fstab の UUID を書きまちがえたときに起きる、よくある起動のトラブルです。このとき、起動の画面や journalctl -xb には、次のような行が出ます。装置が現れるのを待ち（既定で 90 秒）、時間切れになっています。

[ TIME ] Timed out waiting for device dev-disk-by\x2duuid-6109cec1….device.[DEPEND] Dependency failed for data.mount - /data.[DEPEND] Dependency failed for local-fs.target - Local File Systems.You are in emergency mode. After logging in, type "journalctl -xb" to view system logs, …

直し方は、root でログインし、/etc/fstab のその行を直す（か、# で止める、nofail を付ける）ことです。/ が読み取り専用なら、先に mount -o remount,rw / を実行します。

.mount ユニットを自分で書く

fstab を使わずに、ユニットのファイルを直接書くこともできます。置き場所は /etc/systemd/system/ です。

# /etc/systemd/system/var-lib-data.mount[Unit]Description=Data volume [Mount]What=/dev/disk/by-uuid/6109cec1-643a-4028-8cd9-7dff05eef572Where=/var/lib/dataType=ext4Options=defaults,noatime [Install]WantedBy=multi-user.target
決まり中身
ファイル名マウントポイントのパスから決まる。先頭の / を取り、残りの / を - に変えて .mount を付ける。/var/lib/data → var-lib-data.mount。/ そのものは -.mount
[Mount]What=（何を）、Where=（どこに）、Type=（種類）、Options=（オプション）。fstab の 1〜4 欄にあたる
.automount同じ名前の var-lib-data.automount（[Automount] に Where=）を置くと、最初にアクセスされたときにマウントする。fstab なら x-systemd.automount
.swapスワップのユニット。/dev/sdb5 → dev-sdb5.swap。[Swap] に What=、Priority=

名前は systemd-escape で確かめられます（Debian 12 で実行）。パスの中の - は \x2d に変わります。

ターミナル
$ systemd-escape -p --suffix=mount /var/lib/datavar-lib-data.mount$ systemd-escape -p --suffix=mount /srv/my-datasrv-my\x2ddata.mount# systemctl daemon-reload                 ← fstab やユニットを書き換えたら、必ず# systemctl start var-lib-data.mount      ← マウントする# systemctl enable var-lib-data.mount     ← 起動のたびにマウントする# systemctl status var-lib-data.mount# systemctl list-units --type=mount       ← .mount ユニットの一覧
注意試験の注意：systemd のマウント
  • fstab を書き換えただけでは、systemd が持っているユニットは古いままです。systemctl daemon-reload で作り直します
  • .mount ユニットのファイル名は自由に付けられません。Where= のパスと合っていないと、読み込みに失敗します
  • fstab から作られたユニットは /run/systemd/generator/、自分で書くものは /etc/systemd/system/、パッケージのものは /usr/lib/systemd/system/

2.5スワップ：優先度と、有効・無効の切り替え

スワップは、mkswap で作り、swapon で使い始めるのでした（図解 LinuC 5.10）。レベル2 では、複数のスワップの優先度が加わります。

  • 優先度は、数が大きいほうから先に使われます。上の例では、/dev/sdb5（10）が一杯になるまで、ほかは使われません
  • -p で指定できるのは 0〜32767 です。指定しないと、カーネルが負の数を、有効にした順に -2、-3 … と小さくしながら付けます

2.7mkfs と mke2fs：作るときに決めること

mkfs -t 種類 は mkfs.種類 を呼ぶ入口で、-t を省くと ext2 でした（図解 LinuC 5.9）。ext2・ext3・ext4 を作る本体は mke2fs で、mkfs.ext4 は mke2fs -t ext4 と同じです。

ext4 は、ディスクをブロックグループに分け、先頭に全体の情報を持つスーパーブロックを置きます（図解 Linux 11.9）。スーパーブロックが壊れるとマウントできないので、控え（バックアップスーパーブロック）が、いくつかのグループの先頭に置かれます。

ターミナル

-t 種類ext2、ext3、ext4。省くと ext2（mke2fs として呼んだとき）
-jジャーナルを付ける（= ext3 になる）
-b バイトブロックサイズ（1024、2048、4096）

inode の数は、作るときに決まり、あとから増やせません。小さなファイルを大量に置く領域（メールのスプールなど）では、-i を小さくするか -N を大きくして作ります。inode が尽きると、空きブロックがあっても No space left on device になります（df -i で確かめます。図解 Linux 11.8）。

ext3 は「ext2 + has_journal」、ext4 は、それに extent などを足したもの、と読めます。

2.9fsck と e2fsck：検査と修復

fsck（file system check）は、ファイルシステムの整合性を検査し、直すコマンドです。mkfs と同じく入口で、実際の仕事は fsck.種類（ext 系は e2fsck）がします。

ターミナル
# fsck -N /dev/sdb1                     ← 実行せずに、何を呼ぶかだけ表示fsck from util-linux 2.38.1[/usr/sbin/fsck.ext4 (1) -- /dev/sdb1] fsck.ext4 /dev/sdb1# e2fsck -n /dev/sdb1                   ← 読むだけ。質問には全部 noDATA: clean, 11/102400 files, 36256/409600 blocks# e2fsck -f /dev/sdb1                   ← clean でも、強制的に全部調べる# mount /dev/sdb1 /data# fsck /dev/sdb1                        ← マウント中は、直せないe2fsck 1.47.0 (5-Feb-2023)/dev/sdb1 is mounted.e2fsck: Cannot continue, aborting.
注意試験の注意：fsck はマウントを外してから

読み書きでマウントしているファイルシステムに fsck を実行すると、ファイルシステムを壊すことがあります。umount してから実行します。/ は外せないので、起動の途中（読み取り専用でマウントしている間）か、レスキュー用の媒体から起動して検査します。

fsck（入口）のオプション意味
-A/etc/fstab に書かれた全部を、6 欄目の順に検査する（起動のときの使い方）
-R-A と組んで、/ を飛ばす
-t 種類種類を指定する。-A と組むと、その種類だけ
-N実行せず、何をするかを表示する
-Mマウント中のものは検査しない
-C進み具合を表示する
-Vくわしく表示する
e2fsck のオプション意味
-p（-a も同じ）質問せずに、安全に直せるものを自動で直す（preen）。人の判断が要る問題があれば、直さずに止まる
-yすべての質問に yes と答える
-nすべての質問に no と答える。何も書き換えない
-f状態が clean でも、強制的に検査する
-b 番号控えのスーパーブロックを使って検査する
-c不良ブロックを探して、使わないリストに入れる
-vくわしく表示する

-p、-y、-n は、同時には 1 つしか指定できません。

スーパーブロックが壊れたとき

先頭のスーパーブロックを壊すと、マウントできなくなります。控えを指定して直します（Debian 12 で、わざと壊して確かめたものです）。

ターミナル
# mount /dev/sdb1 /datamount: /data: wrong fs type, bad option, bad superblock on /dev/sdb1, missing codepage or helper program, or other error.# mke2fs -n /dev/sdb1                   ← 控えの場所を調べる（-n なので作らない）Superblock backups stored on blocks:        8193, 24577, 40961, 57345, 73729, 204801, 221185, 401409# e2fsck -b 8193 /dev/sdb1              ← 控えを使って修復

控えの場所は、dumpe2fs でも見られますが、先頭のスーパーブロックが読めないと dumpe2fs も失敗します。そのときは、作ったときと同じオプションで mke2fs -n を実行して調べます（-n を忘れると、本当に作り直されて、中身が消えます）。今の e2fsck は、先頭が壊れていると、自分で控えを探して使ってくれます。

検査で見つかった「どのディレクトリからも指されていないファイル」は、そのファイルシステムの一番上の lost+found ディレクトリに、inode 番号の名前でつながれます。

終了ステータス

fsck の終了ステータスは、次の数の足し算です。起動のスクリプトは、これを見て、再起動するか止まるかを決めます。

値意味
0エラーなし
1エラーがあり、直した
2直した。再起動が必要
4エラーが直らずに残っている
8実行そのものの失敗（マウント中だった、など）
16使い方や文法のまちがい
32利用者が中断した
128共有ライブラリのエラー
メモXFS と Btrfs の fsck

fsck.xfs と fsck.btrfs は、何もせずに成功（0）を返すだけのコマンドです。起動時の fsck -A がエラーにならないように置いてあります。実際の検査と修復は、XFS は xfs_repair（2.11）、Btrfs は btrfs check（2.12）でします。

2.10dump と restore：ext のバックアップ

dump は、ext2/3/4 のファイルシステムを、まるごとバックアップするコマンドです。tar と違って、レベル（0〜9）を使った増分バックアップの仕組みを、自分で持っています。戻すのは restore です。

レベル取るもの
0全部（フルバックアップ）
1〜9自分より小さいレベルの、最後のバックアップより後に変わったファイル

たとえば、日曜にレベル 0、月曜から土曜に毎日レベル 1 を取ると、毎日「日曜からの変更ぶん」が取れます（差分）。月曜にレベル 1、火曜にレベル 2、水曜にレベル 3 と上げていくと、毎日「前の日からの変更ぶん」だけが取れます（増分）。

ターミナル
# dump -0u -f /backup/data.0.dump /data  DUMP: Date of this level 0 dump: Mon Nov 16 21:19:41 2026  DUMP: Dumping /dev/sdb1 (/data) to /backup/data.0.dump  …  DUMP: DUMP IS DONE# echo new > /data/c.txt# dump -1u -f /backup/data.1.dump /data# cat /var/lib/dumpdates                      ← Debian。昔からの場所は /etc/dumpdates/data 0 Mon Nov 16 21:19:41 2026 +0000/data 1 Mon Nov 16 21:19:41 2026 +0000# dump -W                                      ← ファイルシステムごとに、最後に取った日時とレベルを表示
dump のオプション意味
-0〜-9レベル。0 が全部
-u取った日時とレベルを dumpdates ファイル（/etc/dumpdates。Debian は /var/lib/dumpdates）に記録する。次の増分の基準になる
-f 出力先書き出すファイルかデバイス（/dev/st0 などのテープ、- で標準出力）
-z、-jzlib / bzlib で圧縮する
-W、-wfstab と dumpdates を見て、ファイルシステムごとの最後のバックアップを表示する（-w は、取る必要があるものだけ）

-u を付けないと、dumpdates に記録が残らず、次のレベル 1 が「どこからの変更か」を決められません。fstab の 5 欄目（dump）は、dump -W や -w が「取るべきファイルシステム」を探すときに見ます。

ターミナル

restore のオプション意味
-rファイルシステム全体を作り直す（rebuild）。新しく mkfs した所へ、レベル 0 から順に重ねる
-x [ファイル…]指定したファイルやディレクトリだけを取り出す（extract）
-i対話で、取り出すものを選ぶ（ls、cd、add、extract）
-t中身の一覧を表示する
-Cバックアップと、いまのファイルシステムを比べる
-f ファイル読むファイルかデバイス

restore は、いまいるディレクトリに戻します。だから、先に戻す先へ cd します。-r で戻すと、増分を重ねるための記録として restoresymtable というファイルができます。全部戻し終わったら消します。

注意試験の注意：dump と restore
  • レベル 0 がフルバックアップ。数が大きいほど「全部」ではありません
  • 戻す順は、レベル 0 → 1 → 2 …（小さいほうから）
  • dump は ext 系の道具です。XFS には xfsdump、どのファイルシステムでも使えるのは tar や rsync です
  • 動いているファイルシステムを dump すると、途中で変わったファイルが正しく取れないことがあります。外すか、読み取り専用にするか、LVM のスナップショット（2.15）を取ってそれを dump します

2.12Btrfs：サブボリュームとスナップショット

Btrfs は、コピーオンライト（書き換えるときに、元を残して別の場所に書く）で作られたファイルシステムです。LVM がしていた「領域を分ける」「スナップショットを取る」「ディスクを足す」を、ファイルシステム自身が持っています。操作はすべて btrfs コマンドのサブコマンドです。

サブボリュームは、1 つの Btrfs の中に作る、独立した木です。見た目はディレクトリですが、それぞれを別々にマウントでき、別々にスナップショットを取れます。パーティションと違って、大きさを決めずに作れ、空き領域は全体で共有します。

ターミナル

スナップショットは、あるサブボリュームの「その瞬間の姿」を持つ、新しいサブボリュームです。コピーオンライトなので、作った瞬間にはデータをコピーせず、すぐ終わり、領域もほとんど使いません。元とスナップショットは同じブロックを共有し、どちらかが書き換えられたブロックだけが別になります。既定では書けるスナップショットで、-r を付けると読み取り専用になります。

btrfs-convert は、ext2/3/4 を、中のファイルを残したまま Btrfs に変換します。対象はマウントを外しておきます。

ターミナル

注意試験の注意：Btrfs
  • スナップショットを作るのは btrfs subvolume snapshot。btrfs snapshot create ではありません。スナップショットは「サブボリュームの一種」です
  • 読み取り専用は -r。付けなければ書けます（LVM のスナップショットとは別の仕組みで、領域の大きさも指定しません）
  • 最上位のサブボリュームの ID は 5 です。作ったサブボリュームは 256 から始まります
  • btrfs-convert の元に戻すオプションは -r（--rollback）です

2.13smartd と smartctl：ディスクの故障の前ぶれを見る

S.M.A.R.T.（Self-Monitoring, Analysis and Reporting Technology）は、HDD や SSD が自分の状態（読み取りエラーの数、代わりのセクタに置き換えた数、温度、通電時間など）を記録して、報告する仕組みです。Linux では smartmontools パッケージの 2 つのプログラムで使います。

メモS.M.A.R.T. でわかること、わからないこと

S.M.A.R.T. は、ディスクという装置の状態を見るもので、ファイルシステムの整合性は見ません。ファイルシステムの検査は fsck です。また、PASSED でも、ある日突然壊れるディスクはあります。代わりのセクタの数（Reallocated_Sector_Ct）が増え続けていたら、判定が PASSED でも交換を考えます。

2.14LVM の復習と、調べるコマンド：pv*、vg*、lv*

LVM は、ディスクを PV（物理ボリューム）にし、PV を束ねて VG（ボリュームグループ）を作り、VG から LV（論理ボリューム）を切り出すのでした（図解 LinuC 5.8）。レベル2 では、その中の単位である PE と、3 つの層それぞれのコマンドの組が問われます。

  • PE（Physical Extent、物理エクステント）は、VG を区切る単位です。大きさは vgcreate -s で決め、既定は 4 MiB です。VG を作ったあとは変えられません
  • LE（Logical Extent）は、LV から見た単位で、大きさは PE と同じです。LV の大きさは、必ず PE の倍数になります（-L +100M が 104 MiB に丸められる、というように）
  • lvcreate -L 200M は大きさで、lvcreate -l 10 は PE の個数で指定します。-l 100%FREE は「VG の空き全部」、-l 50%VG は「VG の半分」です

2.16lvm.conf とメタデータのバックアップ

LVM の設定ファイルは /etc/lvm/lvm.conf です。名前 { … } の形の節に、項目 = 値 を書きます。

devices {    # どの装置を PV の候補として調べるか。a は受け入れ、r は除く。上から順に、最初に合ったものが効く    filter = [ "a|^/dev/sd.*|", "r|.*|" ]}backup {    backup = 1    backup_dir = "/etc/lvm/backup"    archive = 1    archive_dir = "/etc/lvm/archive"    retain_min = 10    retain_days = 30}global {    umask = 077}activation {    # 起動時に自動で有効にする VG / LV を絞る    auto_activation_volume_list = [ "vg01", "vg02/lv_data" ]}
節主な項目
devicesfilter：LVM が調べる装置を、正規表現で絞る。`"aパターン" が受け入れ（accept）、"rパターン" が除く（reject）。global_filter` は、LVM のすべての部品に効く版
backupメタデータのバックアップ（backup、backup_dir）と、履歴（archive、archive_dir、retain_min、retain_days）
logログの出し方（verbose、syslog、file）
global全体の設定（umask など）
activationLV の有効化（volume_list、auto_activation_volume_list、udev_sync）
allocationPE の割り当て方

上の filter は、「/dev/sd で始まる装置だけを調べ、ほかは全部除く」という意味です。上から順に見て、最初に合ったパターンで決まります。だから、"r|.*|" を先に書くと、全部が除かれてしまいます。CD-ROM や、マルチパスの下の個々のパスを、LVM に触らせないために使います。

いまの設定は、lvmconfig（lvm config、古い名前は lvm dumpconfig）で見られます。

ターミナル

LVM のメタデータは、「どの PV の何番の PE が、どの LV の何番目か」という対応の表です。各 PV の先頭に書かれていて、その写しが、テキストのファイルとして /etc/lvm/ の下にも保存されます。

vgcfgbackup が保存するのは、LVM の構成の情報（メタデータ）だけです。LV の中のファイルは入っていません。まちがえて lvremove した LV を、すぐに vgcfgrestore で構成ごと戻せば、中身が上書きされていない限り、データも元どおり見えます。しかし、ディスクが壊れたときに、データを取り戻す手段にはなりません。

深掘りlvm.conf を書き換えなくても、設定は変えられる

1 回だけ設定を変えたいときは、コマンドに --config を付けます（例：pvs --config 'devices { filter = [ "a|.*|" ] }'）。Red Hat 系の新しい LVM（RHEL 9）では、filter の代わりに、使う装置の一覧を /etc/lvm/devices/system.devices に持つ仕組み（devices ファイル。lvmdevices コマンドで管理）が既定になっています。試験の範囲は lvm.conf の filter です。

注意本物との違い
  • この小さな Linux には、ブロックデバイス、スワップ、LVM、ext4 以外のファイルシステムの道具がありません。mkfs、tune2fs、fsck、dump、xfs_*、btrfs、pv*・vg*・lv* は、Debian 12 の Docker（ループデバイス）で実行した出力を ``console で載せ、デバイス名を /dev/sdb1` などに読み替えました
  • pvmove と LVM のスナップショット、smartctl、systemd の .mount ユニットの起動は、Docker の中では動かせないので、出力を省くか、よく知られた形だけを載せています
  • この Linux の /etc/mtab はありません。/proc/mounts を見てください
要点まとめ
  • fstab の 6 欄：何を・どこに・種類・オプション・dump・fsck。nofail、_netdev、noatime、pri=、x-systemd.automount。mount -a は noauto 以外を書いた順にマウントし、スワップは swapon -a
  • /proc/mounts はカーネルが見せる実際のマウント。/etc/mtab は昔は mount が書くファイル、今は /proc/self/mounts へのリンク
  • systemd は fstab を .mount ユニットに変換する（/run/systemd/generator/）。順番はパスの親が先。ユニット名はパスから決まる（/var/lib/data → var-lib-data.mount）。[Mount] に What=、Where=、Type=、Options=。書き換えたら systemctl daemon-reload
  • スワップの優先度は大きいほうが先。swapon -p、fstab の pri=。確認は swapon --show、/proc/swaps
  • UUID は blkid（-U、-L、-s UUID -o value）、lsblk -f、/dev/disk/by-uuid/
  • mke2fs：-b ブロック、-i bytes-per-inode、-N inode 数、-m 予約（既定 5%）、-j ジャーナル、-n 作らずに表示。既定値は /etc/mke2fs.conf
  • tune2fs：-l 表示、-c 最大マウント回数、-i 検査の間隔、-j ジャーナル追加、-m 予約、-L ラベル、-O 機能。dumpe2fs は全部、-h でスーパーブロックだけ
  • fsck は外してから。fsck -A は fstab の全部。e2fsck：-p 自動、-y 全部 yes、-n 書かない、-f 強制、-b 控えのスーパーブロック。終了ステータス 1 = 直した、4 = 残っている
  • dump：レベル 0 が全部、-u で dumpdates に記録、-f 出力先。restore：-r 全部、-x 取り出す、-i 対話、-t 一覧。戻す先はいまのディレクトリ
  • XFS：xfs_info、xfs_repair（外して。-n は検査だけ。xfs_check は昔の名前）、xfs_admin、xfs_growfs（縮小は不可）、xfsdump -l レベル -f 先 マウントポイント、xfsrestore -f 元 先
  • Btrfs：btrfs subvolume create / list / snapshot [-r] / delete、mount -o subvol=。btrfs-convert で ext を変換、-r で戻す（ext2_saved がある間）
  • smartctl：-i、-H、-a、-t short|long、-l selftest、-s on。smartd：smartd.conf（DEVICESCAN、-a、-m、-s）
  • LVM：PE の大きさは vgcreate -s（既定 4 MiB）。pvs/vgs/lvs、*display、*scan。入れ替えは vgextend → pvmove → vgreduce → pvremove。vgchange -ay/-an。広げるのは LV → FS、縮めるのは FS → LV
  • /etc/lvm/lvm.conf：devices { filter = [ "a|…|", "r|…|" ] }。メタデータは /etc/lvm/backup/（いま）と /etc/lvm/archive/（履歴）。vgcfgbackup、vgcfgrestore
