12.2パケットはどのテーブルとチェインを通るか

5 つのチェインと、パケットの道すじ

レベル1 で学んだのは、filter テーブルの INPUT、OUTPUT、FORWARD でした。Linux をルーターとして使うときは、これにあと 2 つのチェインが加わります。経路を決める前に通る PREROUTING と、出ていく直前に通る POSTROUTING です。

規則は、目的ごとにテーブルに分かれています。-t テーブル で選び、省くと filter です。

テーブル役目組み込みのチェイン
filter（既定）通すか捨てるかを決めるINPUT、FORWARD、OUTPUT
natアドレスやポートを書き換える（NAT）PREROUTING、INPUT、OUTPUT、POSTROUTING
mangleパケットのヘッダ（TOS、TTL、印）を書き換える5 つ全部
raw接続の追跡（conntrack）の対象から外すPREROUTING、OUTPUT

試験で問われるのは filter と nat です。「あて先を書き換えるのは経路を決める前（PREROUTING）、送り元を書き換えるのは出ていく直前（POSTROUTING）」と覚えます。あて先を先に書き換えておかないと、経路の判断がまちがうからです。

規則の書き方の復習と、レベル2 で足すもの

-A（最後に足す）、-I（先頭に入れる）、-D（消す）、-P（ポリシー）、-F（全部消す）、-L（表示）は 図解 LinuC 10.7 で学びました。ここでは、実際のサーバーらしい規則を組みます。Debian 12（iptables 1.8.9）で実行した結果です。

ターミナル

2 番の規則が大事です。-m state --state ESTABLISHED,RELATED は、「すでに成立した接続の続き（と、それに関係するパケット）」に当てはまります。これがないと、ポリシーが DROP のとき、自分から出した通信の返事まで捨ててしまいます。-m は、追加の条件（マッチ）を読み込むオプションです。新しい書き方の -m conntrack --ctstate ESTABLISHED,RELATED も同じ意味です。

5 番の LOG は、当てはまったパケットをカーネルのログ（dmesg、journalctl -k）に書きます。ACCEPT や DROP と違って、そこで調べるのをやめません。パケットは次の規則へ進み、ここでは最後にポリシーで捨てられます。

オプション意味

-L [チェイン]規則を表で表示する。-n は名前に直さず数字のまま、-v はパケット数とインターフェースも、--line-numbers は番号付き

注意試験の注意：書けない組み合わせ
  • --dport と --sport は、-p tcp か -p udp と一緒でないと使えません（unknown option "--dport" になります）
  • ポリシー（-P）に指定できるのは ACCEPT か DROP だけです。REJECT は規則のターゲットにはできますが、ポリシーにはできません
  • -i は入ってくる側のチェイン（PREROUTING、INPUT、FORWARD）、-o は出ていく側（FORWARD、OUTPUT、POSTROUTING）でしか使えません。PREROUTING に -o を書くとエラーです
  • -L は、-t を付けなければ filter テーブルしか表示しません。NAT の規則を見るには iptables -t nat -L です

ip6tables：IPv6 は別の規則

iptables の規則が調べるのは IPv4 のパケットだけです。IPv6 のパケットは、ip6tables で設定した別の規則で調べられます。書き方は同じです。

ターミナル
# ip6tables -A INPUT -p tcp --dport 22 -j ACCEPT# ip6tables -A INPUT -p ipv6-icmp -j ACCEPT# ip6tables -S INPUT-P INPUT ACCEPT-A INPUT -p tcp -m tcp --dport 22 -j ACCEPT-A INPUT -p ipv6-icmp -j ACCEPT

IPv4 だけを固く閉じて、IPv6 が開いたままになっている、という事故がよくあります。保存と復元のコマンドも ip6tables-save、ip6tables-restore と別になっています。IPv6 では、近くの機械を探す仕組み（近隣探索）が ICMPv6 に乗っているので、ICMPv6 をまるごと捨てると通信できなくなります。

12.3ルーターにする：IP フォワーディング、NAT、ポートのリダイレクト

IP フォワーディング：/proc/sys/net/ipv4/ip_forward

Linux は、既定では、ほかの機械あてのパケットを受け取っても中継しません（捨てます）。ネットワークインターフェースを 2 つ持つ機械をルーターにするには、カーネルの IP フォワーディングを有効にします。スイッチは /proc/sys/net/ の下のファイルです。

ファイルsysctl の名前
IPv4/proc/sys/net/ipv4/ip_forwardnet.ipv4.ip_forward
IPv6/proc/sys/net/ipv6/conf/all/forwardingnet.ipv6.conf.all.forwarding

中身が 0 なら中継しない、1 なら中継します。IPv4 と IPv6 で、ファイルの名前も場所の深さも違うことに注意します。

ターミナル
# cat /proc/sys/net/ipv4/ip_forward0# echo 1 > /proc/sys/net/ipv4/ip_forward# sysctl net.ipv4.ip_forwardnet.ipv4.ip_forward = 1# sysctl -w net.ipv6.conf.all.forwarding=1net.ipv6.conf.all.forwarding = 1# cat /proc/sys/net/ipv6/conf/all/forwarding1

echo で書いても sysctl -w で書いても、効くのはいまだけです。再起動すると 0 に戻ります。残すには、/etc/sysctl.conf（または /etc/sysctl.d/*.conf）に書きます。

ターミナル
# grep -n forward /etc/sysctl.conf27:# Uncomment the next line to enable packet forwarding for IPv428:#net.ipv4.ip_forward=130:# Uncomment the next line to enable packet forwarding for IPv633:#net.ipv6.conf.all.forwarding=1# echo 'net.ipv4.ip_forward = 1' > /etc/sysctl.d/99-forward.conf# sysctl -p /etc/sysctl.d/99-forward.confnet.ipv4.ip_forward = 1

sysctl -p [ファイル] は、ファイル（省くと /etc/sysctl.conf）を読んで、いますぐ反映します。sysctl --system は、/etc/sysctl.d/ などを全部読み直します。sysctl そのものは、レベル2 の 1 章（2.01.5）でも扱います。

注意試験の注意：フォワーディングと FORWARD チェインは別のもの

中継には、2 つの関門があります。カーネルの IP フォワーディングが 1 であること、そして filter テーブルの FORWARD チェインがそのパケットを通すことです。「NAT の規則を書いたのに、LAN から外へ出られない」ときは、まず /proc/sys/net/ipv4/ip_forward が 1 かを確かめます。

NAT：送り元を書き換える SNAT と MASQUERADE

LAN の機械はプライベートアドレス（192.168.1.0/24 など）を使っているので、そのままではインターネットと通信できません。ルーターが、出ていくパケットの送り元を自分のグローバルアドレスに書き換えます。これが SNAT（source NAT）です。返事が来たら、ルーターは覚えておいた対応表で元のあて先に戻します。

ターミナル
# iptables -P FORWARD DROP# iptables -A FORWARD -i eth1 -o eth0 -s 192.168.1.0/24 -j ACCEPT# iptables -A FORWARD -m state --state ESTABLISHED,RELATED -j ACCEPT# iptables -t nat -A POSTROUTING -o eth0 -s 192.168.1.0/24 -j MASQUERADE

MASQUERADE は、送り元を「出ていくインターフェースに、いま付いているアドレス」に書き換えます。プロバイダからアドレスを動的にもらう回線（PPPoE、DHCP）では、アドレスが変わるのでこちらを使います。アドレスが固定なら、SNAT で書き換え先をはっきり書きます。

iptables -t nat -A POSTROUTING -o eth0 -s 192.168.1.0/24 -j SNAT --to-source 203.0.113.1

あて先を書き換える DNAT と、ポートのリダイレクト

外から来たパケットのあて先を書き換えるのが DNAT（destination NAT）です。ルーターのグローバルアドレスに来た通信を、LAN の中のサーバーへ回します（ポートフォワーディング）。nat テーブルの PREROUTING に書きます。

ターミナル
# iptables -t nat -A PREROUTING -i eth0 -p tcp --dport 8080 -j DNAT --to-destination 192.168.1.10:80

REDIRECT は、あて先を「この機械自身の、別のポート」に書き換えます。あて先のアドレスを書く必要がありません。LAN の PC が外の 80 番へ出そうとした通信を、ルーター上のプロキシ（Squid の 3128 番など）に吸い込む「透過プロキシ」で使います。

ターミナル

メモDNAT したパケットは FORWARD も通る

DNAT であて先を書き換えたパケットは、そのあと経路の判断を受け、FORWARD チェインを通ります。FORWARD のポリシーが DROP なら、書き換えた後のあて先（-d 192.168.1.10 -p tcp --dport 80）を通す規則が要ります。

iptables で入れた規則は、カーネルのメモリにあるだけです。再起動すると全部消えます。iptables-save は、いまの規則を標準出力に書き出します。iptables-restore は、それを標準入力から読んで、まとめて入れ直します。

12.6sshd_config の書き方と、確かめ方

/etc/ssh にあるファイル

OpenSSH のサーバーのプログラムは sshd です。設定は /etc/ssh/sshd_config に書きます。同じディレクトリにある ssh_config はクライアント（ssh コマンド）の設定です。名前が 1 文字しか違わないので、試験では必ず区別します。

書式：「ディレクティブ 値」、先に書いたものが勝つ

sshd_config は、1 行に「ディレクティブ 値」を書きます。配布されたファイルには、既定値が # 付きのコメントで並んでいます。

ターミナル

決まりは 3 つです。

  • ディレクティブの名前は、大文字と小文字を区別しません。値（yes、ユーザー名、パス）は区別します
  • 同じディレクティブを 2 回書くと、先に出てきたほうが使われます。後ろの行は無視されます（Port、ListenAddress、HostKey のように、何個も並べられるものは別です）
  • Include で読み込まれたファイルは、その行の場所に書いたのと同じ扱いです。Debian も Red Hat 系も、Include /etc/ssh/sshd_config.d/*.conf がファイルの先頭近くにあるので、sshd_config.d/ に置いた設定のほうが、sshd_config の本体より優先されます
注意試験の注意：後ろに書き足しても効かない

多くの設定ファイルは「後に書いたものが勝つ」ですが、sshd_config は逆です。ファイルの終わりに PermitRootLogin no を足しても、それより前に PermitRootLogin yes があれば、root はログインできます。Debian 12 で試すと、PermitRootLogin yes、PermitRootLogin no の順に書いたとき、root はログインできました。

12.7だれを、どの方法でログインさせるか

この節のディレクティブが、2.12.2 の中心です。出題範囲に名前が出ているのは PermitRootLogin、PubkeyAuthentication、PasswordAuthentication、AllowUsers の 4 つです。

PasswordAuthentication no にすると、鍵を登録していないユーザーは入れなくなります。先に ssh-copy-id で公開鍵を置き（図解 LinuC 10.8）、鍵でログインできることを確かめてから変えます。また、PermitRootLogin prohibit-password は「root を禁止する」ではありません。鍵があれば root で入れます。root を完全に止めるのは no です。

AllowUsers を書くと、そこに並べたユーザーだけがログインできます。書かれていないユーザーは、正しい鍵やパスワードを持っていても入れません。名前は空白で区切ります。

ターミナル

ユーザー@ホスト の形にすると、「その送り元からのときだけ」になります。* と ? が使えます。上の例では、alice はどこからでも、bob は 192.168.1.* からだけ入れます。root は書かれていないので入れません。

12.8ホスト鍵：サーバーが本物であることの証明

ユーザーの鍵（~/.ssh/id_ed25519）は「ユーザーが本人であること」をサーバーに示します。ホスト鍵はその逆で、「サーバーが本物であること」をクライアントに示します。ホスト鍵がなければ、にせもののサーバーにパスワードを打ち込んでも気づけません。

ホスト鍵は、鍵の種類ごとに /etc/ssh/ssh_host_種類_key（秘密鍵）と /etc/ssh/ssh_host_種類_key.pub（公開鍵）の組になっています。

ターミナル

秘密鍵は root だけが読める 600 です。権限が緩い（644 など）と、sshd は UNPROTECTED PRIVATE KEY FILE! と警告して、その鍵を使いません。ホスト鍵が 1 つもなければ、sshd は sshd: no hostkeys available -- exiting. と言って起動しません。

ホスト鍵は、ふつうパッケージを入れたときか、最初の起動のときに自動で作られます。手で作り直すには ssh-keygen -A を使います。足りない種類のホスト鍵を、既定の場所にまとめて作ります。

/etc/ssh/ssh_known_hostsクライアント側。全ユーザー共通の記録（管理者が配る）
ssh-keygen -A足りないホスト鍵を全部作る
ssh-keygen -l -f 鍵ファイル鍵の指紋を表示する（初めての接続のとき、表示された指紋と比べる）
ssh-keygen -R ホスト名known_hosts から、そのホストの記録を消す
ssh-keyscan ホスト名サーバーのホスト鍵（公開鍵）を集めて表示する
注意試験の注意：3 つのファイルを混ぜない
  • /etc/ssh/ssh_host_*_key：サーバーが自分を証明する鍵。サーバーに 1 組（種類ごと）
  • ~/.ssh/authorized_keys：サーバーにある、ログインを許すユーザーの公開鍵の一覧
  • ~/.ssh/known_hosts：クライアントにある、接続先のサーバーの公開鍵の記録

「ホスト鍵を authorized_keys に登録する」「ユーザーの公開鍵を known_hosts に入れる」は、どちらもまちがいです。

12.9OpenVPN は何をするか

VPN（Virtual Private Network）は、インターネットの上に暗号化した通り道（トンネル）を作り、離れた場所の機械を、同じ LAN にいるかのようにつなぐ仕組みです。OpenVPN は、SSL/TLS を使う VPN のソフトウェアです。Web の HTTPS と同じ技術で、相手を証明書で確かめ、通信を暗号化します。

OpenVPN の考え方で、試験に出るのは次の点です。

項目内容
動く場所ふつうのプロセス（ユーザー空間）として動く。プログラムは openvpn 1 つで、設定によってサーバーにもクライアントにもなる
仮想インターフェースカーネルの TUN/TAP デバイス（/dev/net/tun）を使う
ポート既定は 1194 番の UDP（/etc/services にも openvpn 1194/udp）。proto tcp で TCP にもできる
認証と暗号SSL/TLS。認証局（CA）が署名した証明書を、サーバーとクライアントの両方が持つ
設定の場所/etc/openvpn/（/etc/openvpn/server/、/etc/openvpn/client/）

仮想インターフェースには 2 種類あり、dev で選びます。

dev tundev tap
運ぶものIP パケット（レイヤ 3）イーサネットフレーム（レイヤ 2）
つなぎ方ルーティング。VPN は別のサブネット（10.8.0.0/24 など）になるブリッジ。VPN の先も、同じサブネットになる
ブロードキャスト届かない届く（IP 以外のプロトコルも運べる）
向いている用途ふつうのリモートアクセス。軽い同じ LAN にいるように見せたいとき

認証に使うファイルは 4 種類です。PKI（公開鍵基盤）と呼ばれる、証明書の仕組みです。作るには、OpenVPN と一緒に配られる easy-rsa や、openssl（2.09.2）を使います。

ファイル持つ人秘密か
ca.crt（CA の証明書）サーバーと、全部のクライアント公開してよい
server.crt、server.key（サーバーの証明書と秘密鍵）サーバーだけ.key は秘密
client1.crt、client1.key（クライアントの証明書と秘密鍵）そのクライアントだけ.key は秘密
dh.pem（DH パラメータ）サーバーだけ公開してよい

CA の秘密鍵（ca.key）は、証明書に署名するときにしか使いません。VPN サーバーには置かず、別の安全な機械で保管します。

メモ証明書を使わない方法：静的鍵

2 つの機械だけをつなぐなら、同じ鍵のファイルを両方に置く静的鍵（共有鍵）方式もあります。openvpn --genkey secret static.key で鍵を作り、両方の設定に secret static.key と書きます。手軽ですが、クライアントは 1 つだけで、鍵が漏れると過去の通信まで読まれます。何人もが使うサーバーは、証明書（TLS）方式にします。

12.11nc と nmap で、開いているポートを外から確かめる

ここからは 2.12.4「セキュリティ業務」です。まず、自分のサーバーが外からどう見えるかを確かめる道具です。ss -tlnp（図解 LinuC 10.3）は「この機械で何が待ち受けているか」を内側から見ます。nc と nmap は、ファイアウォールを通った後の姿を外側から見ます。

注意ポートスキャンは、自分が管理する機械にだけ

ポートスキャンは、攻撃の下調べと同じ動作です。他人のサーバーやネットワークに向けると、不正アクセスの準備とみなされたり、IDS に検知されて通報されたりします。自分が管理している機械か、はっきり許可をもらった相手にだけ使います。

nc（netcat）：1 つのポートにつなぐ、待ち受ける

nc（netcat。Nmap に付いてくる版は ncat）は、TCP や UDP のポートにつないで、標準入力を送り、受け取ったものを表示します。図解 Linux 16.3 で、サーバーとクライアントの両方として使いました。

5000 番で待ち受けて、開いているかを確かめる⌘↵
nc -l -p 5000 &ss -tlnnc -zv 127.0.0.1 5000

-z は、データを送らずに、つながるかどうかだけを確かめます。-v を付けないと、結果は終了ステータスにしか出ません。待ち受けていないポートでは、失敗します。

閉じているポートエラーになる⌘↵
nc -zv 127.0.0.1 23

Debian 12 の nc（OpenBSD 版）で、sshd を動かして試した結果です。ポートは範囲でも書けます。つないで何も送らなければ、サーバーが最初に出す文字（バナー）が見えます。

ターミナル

オプション意味
nc ホスト ポートつなぐ（クライアント）
-l待ち受ける（listen）。ポートは -p 5000 で書く（OpenBSD 版と ncat は nc -l 5000 でもよい）
-p ポート自分の側のポート
-uUDP を使う（付けなければ TCP）
-zデータを送らず、つながるかだけを調べる（ポートスキャン）
-v結果を詳しく表示する
-w 秒タイムアウト
-k待ち受けで、1 回つながった後も終わらずに次を待つ

nc は、ファイアウォールの規則を書いた後の確かめに便利です。サーバーで nc -l -p 8080 を待たせ、外から nc -zv サーバー 8080 を打てば、そのポートが通るかがすぐわかります。

nmap（Network Mapper）は、ポートスキャナです。たくさんのポート、たくさんのホストを一度に調べ、開いているポート、動いているサービスの版、OS の種類まで推定します。sshd を動かした Debian 12 のコンテナで、自分自身（127.0.0.1）を調べた結果です。

12.13IDS と脆弱性の検査、情報の入手先

道具種類何をするか
Snortネットワーク型 IDS（侵入検知システム）流れているパケットを見張り、ルール（シグネチャ）に合う攻撃の通信を見つけて、警告を記録する

IDS（Intrusion Detection System）は、侵入や攻撃を見つけて知らせる仕組みです。見つけるだけで、止めはしません。止めるところまでするものは IPS（Intrusion Prevention System）と呼びます。ネットワークを流れるパケットを見るものがネットワーク型（NIDS）、ホストの中のファイルやログを見るものがホスト型（HIDS）です。Snort はネットワーク型の代表です。

OpenVAS と OpenSCAP：弱点を探す

OpenVAS（Open Vulnerability Assessment Scanner）は、脆弱性スキャナです。もとは Nessus という製品から分かれたもので、いまは Greenbone 社が中心になって開発しています。対象のホストにネットワークからいろいろな検査を当て、古い版のサービスや危ない設定を見つけて、報告書にまとめます。検査の内容（脆弱性テスト）は、フィードとして日々更新されます。nmap が「どのポートが開いているか」までなのに対し、OpenVAS は「そこに既知の弱点があるか」まで調べます。

OpenSCAP は、SCAP（Security Content Automation Protocol）という、米国の NIST が決めた規格の実装です。セキュリティの基準（「root の SSH ログインを禁止しているか」「パスワードの最短の長さは」といった項目の一覧）を機械が読める形で書いておき、機械の設定がそれに合っているかを自動で調べます。コマンドは oscap です。Rocky Linux 9 で確かめました。

注意試験の注意：道具の役目を取り違えない
  • Snort は IDS（検知）。パケットを見る。ログは見ない
  • fail2ban はログを見て遮断する。パケットの中身は見ない
  • OpenVAS は脆弱性スキャナ。外から調べる
  • OpenSCAP（oscap）は、基準への適合を、その機械の中で調べる
  • nmap はポートスキャナ、nc は 1 つのポートにつなぐ道具
  • Bugtraq、CERT、CIAC は、道具ではなく情報の入手先
要点まとめ
  • テーブルは -t で選ぶ。filter（既定）は INPUT / FORWARD / OUTPUT、nat は PREROUTING / POSTROUTING（と INPUT / OUTPUT）
  • 送り元の書き換えは nat の POSTROUTING に SNAT --to-source か MASQUERADE（アドレスが動的なとき）。あて先の書き換えは PREROUTING に DNAT --to-destination、自分の別のポートへは REDIRECT --to-ports
  • 中継には IP フォワーディングが要る。/proc/sys/net/ipv4/ip_forward、/proc/sys/net/ipv6/conf/all/forwarding を 1 に。残すには /etc/sysctl.conf に net.ipv4.ip_forward = 1
  • iptables-save > ファイル、iptables-restore < ファイル。保存先は Red Hat 系 /etc/sysconfig/iptables、Debian 系 /etc/iptables/rules.v4。IPv6 は ip6tables で別に設定する
  • firewalld：--add-masquerade、--add-forward-port=port=…:proto=…:toport=…[:toaddr=…]、--permanent と --reload、--runtime-to-permanent。設定は /etc/firewalld/zones/。ufw：ufw enable、ufw allow 22/tcp、ufw default deny incoming
  • サーバーの設定は /etc/ssh/sshd_config（ssh_config はクライアント）。同じディレクティブは先に書いたものが有効。sshd -t で検査、sshd -T で有効な設定を表示
  • PermitRootLogin は yes / prohibit-password（鍵なら可。既定）/ forced-commands-only / no。鍵だけにするなら PubkeyAuthentication yes と PasswordAuthentication no
  • AllowUsers は並べたユーザーだけを許す（ユーザー@ホスト も書ける）。順番は DenyUsers → AllowUsers → DenyGroups → AllowGroups で、Deny が強い
  • ホスト鍵は /etc/ssh/ssh_host_*_key（600）と .pub。ssh-keygen -A で作る。クライアントは ~/.ssh/known_hosts に記録し、変わると警告する（ssh-keygen -R で消す）
  • OpenVPN は SSL/TLS の VPN。既定は 1194/udp。dev tun はルーティング、dev tap はブリッジ。サーバーは server ネットワーク マスク、dh、push "route …"。クライアントは client、remote ホスト ポート。設定は /etc/openvpn/
  • nc -zv ホスト ポート でつながるかを確かめる。nmap は -sS SYN、-sT connect、-sU UDP、-sn ホスト探し、-sV 版、-O OS、-p ポート。filtered はファイアウォールに遮られている
  • fail2ban は、findtime の間に maxretry 回失敗したアドレスを bantime だけ遮断する。設定は /etc/fail2ban/jail.local、操作は fail2ban-client status sshd
  • Snort は IDS、OpenVAS は脆弱性スキャナ、OpenSCAP（oscap）は基準への適合の検査。情報の入手先は Bugtraq、CERT、CIAC
