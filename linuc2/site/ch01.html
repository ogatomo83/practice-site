1.2電源からカーネルまで：BIOS と UEFI の 2 つの道

電源を入れると、最初に動くのは基板の上のファームウェアです。ファームウェアには古い BIOS と、いまの UEFI の 2 種類があります（図解 LinuC 5.5）。どちらも、機械を点検し（POST）、ブートローダを見つけて実行します。違うのはブートローダの探し方です。

BIOS と MBR

BIOS は、起動ディスクの最初のセクタ（MBR、512 バイト）を読み込んで実行します。MBR の中身は 3 つに分かれます。

位置大きさ中身
先頭446 バイトブートローダの 1 段目（GRUB の boot.img）
次64 バイトパーティション表（16 バイト × 4 つ）
最後2 バイト署名（0x55AA）

446 バイトには GRUB の全部は入りません。1 段目は、すぐ後ろに置かれた 2 段目（core.img）を読み込み、2 段目が /boot/grub/ のモジュールと grub.cfg を読みます。GPT のディスクを BIOS で起動するときは、core.img の置き場所として BIOS ブートパーティションを作ります。

UEFI と ESP

UEFI は、FAT のファイルシステムを自分で読めます。ブートローダは、EFI システムパーティション（ESP） の中の .efi ファイルです。Linux では ESP を /boot/efi にマウントします。

ターミナル
# ls /boot/efi/EFI/rockyBOOTAA64.CSV  grubaa64.efi  mmaa64.efi  shim.efi  shimaa64-rocky.efi  shimaa64.efi

（ARM 64 ビットの Rocky Linux 9 の例です。x86_64 の機械では shimx64.efi、grubx64.efi という名前になります）

shim は、セキュアブート（署名のあるプログラムだけを起動する UEFI の機能）のための小さなブートローダです。UEFI が shim を実行し、shim が GRUB を実行します。

どの .efi をどの順番で試すかは、基板の不揮発メモリ（NVRAM）に起動エントリとして記録されています。これを Linux から見て、変えるのが efibootmgr です。

ターミナル
# efibootmgr -vBootCurrent: 0001Timeout: 0 secondsBootOrder: 0001,0000,0002Boot0000* UEFI: PXE IPv4Boot0001* Rocky Linux    HD(1,GPT,…)/File(\EFI\rocky\shimx64.efi)Boot0002* debian    HD(1,GPT,…)/File(\EFI\debian\shimx64.efi)
efibootmgrすること
（オプションなし）起動エントリと順番（BootOrder）を表示する
-v詳しく表示する（.efi ファイルのパスも出る）
-o 0002,0001起動の順番（BootOrder）を決める
-n 0002次の 1 回だけ起動するエントリ（BootNext）を決める
-c -d /dev/sda -p 1 -L 名前 -l '\EFI\…\grubx64.efi'エントリを新しく作る（-d ディスク、-p パーティション番号、-L ラベル、-l ローダのパス）
-b 0002 -Bエントリ 0002 を消す
-t 秒メニューを待つ時間を決める

efibootmgr は、UEFI で起動した機械でしか使えません。UEFI で起動したかどうかは、/sys/firmware/efi ディレクトリがあるかで見分けられます。

UEFI シェルは、ファームウェアが持つコマンドラインです。OS が起動しないときに、fs0: のように ESP を選び、.efi ファイルを直接実行できます。起動エントリを編集する bcfg コマンドもあります。

BIOSUEFI
ブートローダの場所MBR（先頭 446 バイト）とその後ろESP（FAT）の中の .efi ファイル
典型のパーティション表MBRGPT
起動順の記録BIOS の設定画面NVRAM の起動エントリ（efibootmgr）
Linux でのマウント先—/boot/efi
セキュアブートないある（shim）
注意試験の注意：ESP と /boot
  • /boot … カーネル（vmlinuz-…）、initramfs、GRUB の設定とモジュール。ext4 や XFS でよい
  • /boot/efi … ESP。UEFI が読むので FAT（vfat）。.efi ファイルを置く
  • MBR の 512 バイトは「446 + 64 + 2」。パーティション表は 64 バイトで、基本パーティションが 4 つまでなのはこのため

1.3GRUB 2 の設定：grub.cfg は書かずに、作る

GRUB 2 は、メニューを出し、選ばれたカーネルと initramfs をメモリに読み込み、カーネルに引数を渡して実行します。メニューの中身は grub.cfg に書かれていますが、このファイルは手で編集しません。元になるファイルから、コマンドで作ります。

Debian 系と Red Hat 系では、コマンドとディレクトリの名前が違います。Red Hat 系は、名前に 2 が付きます。

Debian 系Red Hat 系
設定を作るgrub-mkconfig -o /boot/grub/grub.cfg（update-grub でも同じ）grub2-mkconfig -o /boot/grub2/grub.cfg
ブートローダを入れるgrub-installgrub2-install
設定の置き場所/boot/grub/grub.cfg/boot/grub2/grub.cfg
編集するファイル/etc/default/grub、/etc/grub.d/同じ

grub-mkconfig は、-o を付けないと結果を標準出力に出すだけで、ファイルは変わりません。Debian 系の update-grub は、中で grub-mkconfig -o /boot/grub/grub.cfg を実行するだけの短いスクリプトです。

ターミナル
# cat /usr/sbin/update-grub#!/bin/shset -eexec grub-mkconfig -o /boot/grub/grub.cfg "$@"

/etc/default/grub

Debian 12 の /etc/default/grub の主な行です。

GRUB_DEFAULT=0GRUB_TIMEOUT=5GRUB_DISTRIBUTOR=`lsb_release -i -s 2> /dev/null || echo Debian`GRUB_CMDLINE_LINUX_DEFAULT="quiet"GRUB_CMDLINE_LINUX=""#GRUB_DISABLE_RECOVERY="true"
変数意味
GRUB_DEFAULT既定で選ぶメニューの項目。0 が 1 番上。saved なら、grub-set-default（grub2-set-default）で保存した項目
GRUB_TIMEOUTメニューを出して待つ秒数。0 ならすぐ起動、-1 なら選ぶまで待つ
GRUB_CMDLINE_LINUXすべての Linux の項目で、カーネルに渡す引数
GRUB_CMDLINE_LINUX_DEFAULTふつうの項目だけに足す引数（リカバリーモードの項目には付かない）
GRUB_DISABLE_RECOVERYtrue なら、リカバリーモードの項目を作らない

/etc/grub.d/ には、番号で始まるスクリプトが並びます。grub-mkconfig は番号の順に実行し、出力をつないで grub.cfg にします。

ファイル役目
00_header/etc/default/grub の変数を読み、全体の設定を出す
10_linux/boot にあるカーネルを探して、メニューの項目を作る

注意試験の注意：変えたら、作り直す

/etc/default/grub や /etc/grub.d/ を書き換えただけでは、何も変わりません。grub-mkconfig -o …（grub2-mkconfig -o …）を実行して、はじめて grub.cfg に反映されます。逆に、grub.cfg を直接編集しても、次に grub-mkconfig を実行した（カーネルを更新した）ときに消えます。

grub.cfg の 1 つの項目を読む

作られた grub.cfg の中で、メニューの 1 項目は menuentry のかたまりです。

menuentry 'Debian GNU/Linux' {        set root='hd0,gpt2'        linux   /vmlinuz-6.1.0-18-amd64 root=UUID=3f1c… ro quiet        initrd  /initrd.img-6.1.0-18-amd64}
行意味
set root='hd0,gpt2'GRUB がファイルを探すパーティション。ディスクは 0 から、パーティションは 1 から数える。hd0,gpt2 は 1 台目のディスクの 2 番目（GPT）、MBR なら hd0,msdos1 のように書く
linux読み込むカーネルのファイルと、カーネルに渡す引数（カーネルパラメータ）
initrd読み込む initramfs のファイル

set root= は GRUB から見た場所で、linux の行の root= はカーネルがルートファイルシステムとしてマウントする装置です。名前が同じでも別のものです。

メニューが出ているときに使うキーは 2 つです。

  • e … 選んだ項目を、その場で編集する（linux の行に引数を足すなど）。編集したら Ctrl + x か F10 で起動する。変更はその 1 回だけ
  • c … GRUB のコマンドライン（grub>）に入る。ls でディスクを調べ、linux、initrd、boot を手で打って起動できる

grub-install：ブートローダそのものを入れる

grub-mkconfig が作るのは設定（grub.cfg）だけです。ブートローダのプログラムをディスクに書き込むのは grub-install（grub2-install）です。MBR を壊した、ディスクを替えた、というときに使います。

ターミナル
# grub-install /dev/sda                    ← BIOS：ディスク（パーティションではない）の MBR に書く# grub-install --target=x86_64-efi --efi-directory=/boot/efi --bootloader-id=debian                                           ← UEFI：ESP に .efi を置き、NVRAM にエントリを作る
オプション意味
--boot-directory=DIRGRUB のファイルを DIR/grub（Red Hat 系は DIR/grub2）に置く。既定は /boot
--efi-directory=DIRESP のマウント先（ふつう /boot/efi）
--bootloader-id=IDESP の中のディレクトリ名と、NVRAM のエントリの名前
--target=TARGET対象の種類。i386-pc（BIOS）、x86_64-efi（UEFI）など
--removableNVRAM に頼らない既定のパス（EFI/BOOT/）に入れる

/boot の中身

ターミナル

RHEL 8 以降では、メニューの各項目は grub.cfg の中ではなく、/boot/loader/entries/*.conf に 1 項目 1 ファイルで置かれます（BootLoaderSpec、BLS）。中身は title、linux、initrd、options の行です。カーネルパラメータを変えるには、grubby --update-kernel=ALL --args="…" を使います。古い教材の「UEFI では /boot/efi/EFI/redhat/grub.cfg に出力する」は RHEL 7・8 の話で、RHEL 9 では UEFI でも /boot/grub2/grub.cfg です。試験では「Red Hat 系は grub2-mkconfig と /boot/grub2/」を押さえておけば足ります。

1.4initramfs とカーネルパラメータ

GRUB は、カーネルと一緒に initramfs をメモリに読み込みます。initramfs は、本当のルートファイルシステムをマウントするまでの、仮の小さなルートファイルシステムです。

なぜ要るのでしょうか。ルートが LVM や RAID、暗号化ディスクの上にあると、マウントするにはそのためのドライバ（モジュール）が要ります。しかし、モジュールはルートファイルシステムの /lib/modules/ にあります。この「鶏と卵」を解くために、必要なモジュールと道具をまとめた initramfs を、先にメモリに広げます。

名前が 2 つあるのは、歴史のためです。

initrd（初期 RAM ディスク）initramfs
形ファイルシステムのイメージ（ext2 など）cpio アーカイブ（gzip などで圧縮）
使い方RAM ディスクというブロックデバイスとしてマウントするメモリ上のファイルシステム（tmpfs）に展開する
時代カーネル 2.4 までカーネル 2.6 から。いまはこちら

いまの Linux が使うのは initramfs ですが、ファイル名（Debian 系の initrd.img-…）や GRUB のコマンド（initrd）には、古い名前が残っています。作るコマンドは 1.10 で見ます。

カーネルパラメータ

GRUB が linux の行でカーネルに渡した引数は、起動した後も /proc/cmdline で見られます。小さな Linux で確かめます。

カーネルに渡された引数と、起動の記録⌘↵
cat /proc/cmdlinedmesg | grep -i -e "command line" -e initramfs -e "init process"

dmesg の 3 行は、「引数を受け取った」「initramfs を広げた」「/init を実行した」です。上の図の順番が、カーネルの記録に残っています。

パラメータ意味
root=/dev/sda2、root=UUID=…ルートファイルシステムにする装置
ro / rwルートを最初は読み取り専用 / 読み書きでマウントする
quiet起動中のカーネルのメッセージを減らす
init=/bin/bashPID 1 として実行するプログラムを変える（既定は /sbin/init）
systemd.unit=rescue.targetsystemd が目指すターゲットを変える（1.7）
single、1、Sレスキューモード（シングルユーザーモード）で起動する
crashkernel=256Mkdump のためにメモリを取っておく（1.14）

systemd.unit= のように、名前に点が付いた引数は、カーネルではなく systemd が読みます。カーネルは自分の知らない引数を、そのまま PID 1 に渡します。

1.5unit ファイルの 3 つの置き場所と優先順位

systemd が管理するものは、すべて unit でした（図解 LinuC 1.8、図解 Linux 17.4）。unit ファイルの置き場所は 3 つあり、同じ名前のファイルがあれば、優先順位の高いほうだけが使われます。

ディレクトリだれが置くか優先順位
/etc/systemd/system/システムの管理者。enable のシンボリックリンクもここ1（最高）
/run/systemd/system/実行中に作られるもの。/run は tmpfs なので再起動で消える2
/usr/lib/systemd/system/パッケージ（ディストリビューション）。更新で上書きされる3（最低）

Debian 系では /lib/systemd/system/ と書かれることがありますが、/lib は /usr/lib へのシンボリックリンクなので同じ場所です。/etc/systemd/ には、unit のほかに systemd 自身の設定（system.conf、journald.conf、logind.conf）もあります。

パッケージの unit を変えたいときは、/usr/lib/systemd/system/ のファイルを書き換えません。パッケージの更新で元に戻るからです。方法は 2 つあります。

方法置くものコマンド
全体を置き換える/etc/systemd/system/名前.service（同じ名前のファイル）systemctl edit --full 名前
一部だけ変える（ドロップイン）/etc/systemd/system/名前.service.d/*.conf（変えたい行だけ）systemctl edit 名前（override.conf ができる）

小さな Linux で、全体を置き換えてみます。ticker.service は /usr/lib/systemd/system/ にあります。

/etc に同じ名前の unit を置くと、そちらが使われるroot で実行⌘↵
systemctl cat ticker | head -3cp /usr/lib/systemd/system/ticker.service /etc/systemd/system/ticker.servicesed -i 's/^Description=.*/Description=My ticker/' /etc/systemd/system/ticker.servicesystemctl daemon-reloadsystemctl cat ticker | head -3

systemctl cat の 1 行目が、読まれているファイルのパスです。/etc/systemd/system/ に置いた後は、そちらに変わりました。unit ファイルを手で置いたり書き換えたりしたら、systemctl daemon-reload で systemd に読み直させます。

systemd-delta：どこが上書きされているかを調べる

「このサーバーでは、パッケージの設定からどこが変えられているか」を一覧するのが systemd-delta です。Rocky Linux 9 で、chronyd.service を /etc に置き換え、sshd.service にドロップインを足し、crond.service を mask した後の出力です。

ターミナル
# systemd-delta --no-pager[OVERRIDDEN] /etc/systemd/system/chronyd.service → /usr/lib/systemd/system/chronyd.service[MASKED]     /etc/systemd/system/crond.service → /usr/lib/systemd/system/crond.service[EQUIVALENT] /etc/systemd/system/ctrl-alt-del.target → /usr/lib/systemd/system/ctrl-alt-del.target[EXTENDED]   /usr/lib/systemd/system/sshd.service → /etc/systemd/system/sshd.service.d/override.conf# systemd-delta --type=overridden      ← 種類をしぼる
表示意味
[OVERRIDDEN]優先順位の高い場所に同じ名前のファイルがあり、中身が違う（差分も表示される）
[EQUIVALENT]上書きされているが、中身は同じ
[MASKED]/dev/null へのリンクで封じられている
[EXTENDED].d/ のドロップインで、設定が足されている
[REDIRECTED]別のファイルへのシンボリックリンクで置き換えられている
注意試験の注意：優先順位は /etc > /run > /usr/lib
  • 管理者の /etc/systemd/system/ がいちばん強い。パッケージの /usr/lib/systemd/system/ がいちばん弱い
  • /run/systemd/system/ はその間。再起動で消える（systemctl mask --runtime などが使う）
  • 上書きの一覧は systemd-delta。systemctl list-unit-files は unit の一覧で、上書きの関係は出ない

1.6systemctl：状態を見る、変える、封じる

systemctl の基本はレベル1 で見ました（図解 LinuC 1.8）。ここでは、出力の読み方と、mask を足します。

enable、start、statusroot で実行⌘↵
systemctl enable tickersystemctl start tickersystemctl status ticker

status の出力は、上から次のように読みます。

行読み方
Loaded:読んだ unit ファイルのパス。その後ろが enable の状態（enabled / disabled / static / masked）と、ディストリビューションの既定（preset）
Active:いまの状態。active (running)、inactive (dead)、failed など
Main PID:サービスの主なプロセス
CGroup:サービスに属するプロセスの一覧
最後の数行ジャーナルに残った最近のログ

「起動時に動くか」（Loaded の行）と「いま動いているか」（Active の行）は、別のものです。

mask の正体は、優先順位がいちばん高い /etc/systemd/system/ に、同じ名前で /dev/null へのシンボリックリンクを置くことです。systemd は空のファイルを読むことになり、何も起こせません。前の節の優先順位が、そのまま使われています。

systemctl unmask 名前mask を解く（/dev/null へのリンクを消す）
注意試験の注意：enable と start、disable と mask
  • enable は次の起動から。いまは起こさない。いまも起こすなら enable --now か、start も実行する
  • disable したサービスは手で起こせる。mask したサービスは、unmask するまで起こせない
  • mask は /etc/systemd/system/名前 → /dev/null のシンボリックリンク。enable は …target.wants/名前 → unit ファイルのシンボリックリンク

小さな Linux の systemctl に mask はありません。後片付けをしておきます。

1.7レスキューモードと緊急モード

設定をまちがえて起動しなくなったときは、ふつうより手前の段階で止めて、root のシェルで直します。そのための段階が 2 つあります（図解 LinuC 1.9）。

レスキューモード（rescue.target）緊急モード（emergency.target）
昔の名前シングルユーザーモード（ランレベル 1）—
どこまで進むかsysinit.target まで。ローカルのファイルシステムをマウントするほぼ何もしない。ルートだけを読み取り専用でマウント
ネットワーク、ほかのサービス起こさない起こさない
入るときroot のパスワードを聞かれるroot のパスワードを聞かれる
使う場面ふつうの修理（パスワード、サービスの設定）レスキューモードにも入れないとき（/etc/fstab のまちがいなど）

unit ファイルを見ると、違いがそのまま書かれています（Rocky Linux 9）。

# /usr/lib/systemd/system/rescue.target[Unit]Description=Rescue ModeRequires=sysinit.target rescue.serviceAfter=sysinit.target rescue.serviceAllowIsolate=yes # /usr/lib/systemd/system/emergency.target[Unit]Description=Emergency ModeRequires=emergency.serviceAfter=emergency.serviceAllowIsolate=yes

rescue.target は sysinit.target を必要とし、emergency.target は必要としません。/etc/fstab に存在しない装置を書いてしまうと、sysinit.target の途中（ローカルのマウント）で失敗します。このときに使えるのが緊急モードです。

入り方は 2 通りあります。

入り方レスキューモード緊急モード
動いているシステムでsystemctl rescue（systemctl isolate rescue.target）systemctl emergency（systemctl isolate emergency.target）
起動時に（GRUB で e を押し、linux の行の最後に足す）systemd.unit=rescue.target、rescue、single、s、S、1systemd.unit=emergency.target、emergency、-b

緊急モードでは、ルートが読み取り専用です。ファイルを直すには、まず読み書きできるようにマウントし直します。

ターミナル
# mount -o remount,rw /# vi /etc/fstab# systemctl reboot            ← または systemctl default で、既定のターゲットへ進む
コツroot のパスワードを忘れたとき

レスキューモードも緊急モードも、root のパスワードを聞いてきます。パスワードを忘れたときは、GRUB で linux の行に init=/bin/bash（Red Hat 系では rd.break）を足して起動し、systemd を通さずにシェルを得ます。その後、mount -o remount,rw / をしてから passwd で付け直します。GRUB の編集は機械の前にいればだれでもできるので、サーバーには GRUB のパスワードや、物理的な鍵が要ります。

1.8カーネルのイメージと、ソースの置き場所

Linux カーネルは、本体（イメージ） と、あとから足せるモジュール（.ko）でできています（図解 LinuC 5.2）。本体は起動のときに GRUB がメモリへ読み込む 1 つのファイルで、モジュールは /lib/modules/カーネルバージョン/ の下に並びます。

イメージの名前：vmlinux、zImage、bzImage、vmlinuz

カーネルのイメージには、似た名前が 4 つあります。

名前何か
vmlinux圧縮されていないカーネル（ELF 形式）。ビルドするとソースの一番上にできる。そのままでは起動に使わない。デバッグに使う
zImage圧縮されたイメージの古い形。大きさに制限があり（512 KB ほどまで）、いまの x86 では使わない
bzImagebig zImage。大きなカーネルも扱える、圧縮されたイメージ。x86 では arch/x86/boot/bzImage にできる
vmlinuz/boot に置かれた、圧縮されたカーネルのファイルの名前。中身は bzImage

イメージの先頭には、自分を展開する小さなプログラムが付いています。GRUB がメモリに読み込むと、まずこのプログラムが動いて、圧縮された本体を展開します。

注意試験の注意：bzImage の bz は bzip2 ではない

bzImage の b は big です。bzip2 で圧縮されているという意味ではありません。圧縮の方式は、ビルドの設定で選びます。既定は gzip で、ほかに bzip2、LZMA、xz、LZO、LZ4、zstd が選べます。

圧縮の方式：gzip と xz

圧縮の方式は、カーネルの設定（1.9）の「Kernel compression mode」で選びます。

方式設定の名前特徴
gzipCONFIG_KERNEL_GZIP既定。圧縮率と展開の速さのつり合いがよい
bzip2CONFIG_KERNEL_BZIP2gzip より 1 割ほど小さい。展開は遅い
xzCONFIG_KERNEL_XZgzip より 3 割ほど小さい。圧縮に時間がかかる

モジュールも圧縮できます。Red Hat 系では、モジュールは xz で圧縮されて .ko.xz という名前になっています。

ターミナル
# modinfo -n xfs/lib/modules/5.14.0-741.22.1.el9_9.aarch64/kernel/fs/xfs/xfs.ko.xz

（Rocky Linux 9 の例です。Debian 12 では、圧縮されていない .ko です）

ソースの置き場所とバージョン

カーネルのソースは、昔から /usr/src/linux/ に置く習慣です。ふつうは、/usr/src/linux-6.1.0/ のようにバージョンの付いたディレクトリに展開し、/usr/src/linux をそこへのシンボリックリンクにします。

ディレクトリ・ファイル中身
/usr/src/linux/Makefileビルドの手順。先頭にバージョンが書かれている
/usr/src/linux/.configビルドの設定（1.9）
/usr/src/linux/Documentation/カーネルの文書。カーネルパラメータ、/proc/sys の項目、各ドライバの説明など
/usr/src/linux/arch/CPU の種類ごとのコード（arch/x86/ など）。できたイメージもこの下
/usr/src/linux/drivers/、fs/、net/、kernel/、mm/ドライバ、ファイルシステム、ネットワーク、中心の部分、メモリ管理

バージョンは、Makefile の先頭の 4 行で決まります。

VERSION = 6PATCHLEVEL = 1SUBLEVEL = 0EXTRAVERSION =

この例は「6.1.0」です。EXTRAVERSION に -custom と書けば「6.1.0-custom」になり、uname -r の出力と、モジュールのディレクトリ（/lib/modules/6.1.0-custom/）の名前が変わります。

動いているカーネルのバージョン⌘↵

メモモノリシックカーネルと、モジュール

Linux は、ファイルシステムもドライバもカーネルの中で動くモノリシックカーネルです。ただし、多くの部品をローダブルモジュールとして本体から分け、必要なときに読み込めるようにしています。本体に組み込むか、モジュールにするか、入れないかは、次の節の .config で 1 つずつ決めます。

ターミナル

新しいカーネルを入れたら、そのカーネルのモジュールが入った initramfs（1.4）を作ります。コマンドは、ディストリビューションで違います。

コマンド例

どちらも、カーネルバージョンを省くと、いま動いているカーネル（uname -r）のものを作ります。mkinitramfs は出力先を -o で指定し、dracut は引数の 1 つ目に書きます。dracut は、同じ名前のファイルがすでにあると上書きしないので、作り直すときは -f（--force）を付けます。

Dracut は、initramfs を作る仕組みの名前でもあります。/usr/lib/dracut/modules.d/ の部品（dracut モジュール）を組み合わせて initramfs を作り、設定は /etc/dracut.conf と /etc/dracut.conf.d/ に書きます。mkinitrd は昔の Red Hat 系のコマンドで、RHEL 8 までは dracut を呼び出す互換用のスクリプトとして残っていました（RHEL 9 にはありません）。

中身を見るコマンドもあります。Debian 系は lsinitramfs ファイル、Red Hat 系は lsinitrd ファイル です。initramfs の実体は cpio アーカイブで、gzip、bzip2、xz、zstd などで圧縮されています。

DKMS：カーネルを更新しても、外部のモジュールを作り直す

カーネルのソースに入っていないドライバ（外部のモジュール）は、カーネルのバージョンごとにビルドし直す必要があります。カーネルを更新するたびに手でビルドするのは大変です。これを自動でするのが DKMS（Dynamic Kernel Module Support）です。

DKMS には、モジュールのソースを登録しておきます。新しいカーネルが入ると、DKMS がそのカーネル用にビルドして、インストールします。

ターミナル

1.12/proc/sys と sysctl：カーネルのパラメータを変える

カーネルの動きの多くは、動かしたまま変えられます。その入口が /proc/sys/ です（図解 Linux 12.3）。ここのファイルを読むといまの値が分かり、書き込むと値が変わります。

/proc/sys/kernel の中⌘↵
ls /proc/sysls /proc/sys/kernelcat /proc/sys/kernel/ostype /proc/sys/kernel/osrelease
書き込むと、その場で変わるroot で実行⌘↵
cat /proc/sys/kernel/hostnameecho web01 > /proc/sys/kernel/hostnamehostnameecho zukai > /proc/sys/kernel/hostname
ディレクトリ中身
/proc/sys/kernel/カーネル全体のパラメータ。hostname、osrelease、ostype、pid_max、panic、sysrq、modules_disabled など
/proc/sys/net/ネットワーク。net/ipv4/ip_forward（IP フォワーディング）など
/proc/sys/vm/メモリ管理。swappiness、drop_caches など
/proc/sys/fs/ファイルシステム。file-max（開けるファイルの数の上限）など

同じことを、名前で扱うのが sysctl コマンドです。名前は、/proc/sys/ から後ろのパスの / を . に変えたものです。/proc/sys/net/ipv4/ip_forward は net.ipv4.ip_forward になります。小さな Linux に sysctl はないので、Rocky Linux 9 で確かめた結果を見ます。

ターミナル
# sysctl net.ipv4.ip_forward              ← 読むnet.ipv4.ip_forward = 1# sysctl -w net.ipv4.ip_forward=0         ← 書くnet.ipv4.ip_forward = 0# cat /proc/sys/net/ipv4/ip_forward0# sysctl -n kernel.ostype                 ← 値だけLinux# sysctl -a | grep -c .                   ← 全部1799
sysctl意味
sysctl 名前値を表示する
sysctl -aすべてのパラメータを表示する
sysctl -n 名前名前を付けずに、値だけを表示する
sysctl -w 名前=値値を変える（-w は省ける）
sysctl -p [ファイル]ファイルを読んで設定する。ファイルを省くと /etc/sysctl.conf
sysctl --systemすべての設定ファイル（/usr/lib/sysctl.d/、/run/sysctl.d/、/etc/sysctl.d/、/etc/sysctl.conf）を読んで設定する

再起動しても残す：/etc/sysctl.conf と /etc/sysctl.d/

echo や sysctl -w で変えた値は、再起動すると元に戻ります。残すには、設定ファイルに書きます。

# /etc/sysctl.d/90-forward.confnet.ipv4.ip_forward = 1kernel.panic = 10
ファイル役目
/etc/sysctl.conf昔からの設定ファイル
/etc/sysctl.d/*.conf管理者が置く設定。名前の順に読まれる
/usr/lib/sysctl.d/*.confパッケージが置く設定。同じ名前のファイルは /etc/sysctl.d/ が優先

書式は「名前 = 値」です。起動のときに読み込まれます。書いた後、再起動せずにいますぐ反映するには、sysctl -p（/etc/sysctl.conf だけ）か sysctl -p ファイル、または sysctl --system を実行します。

注意試験の注意：sysctl -w は一時的
  • sysctl -w と echo 値 > /proc/sys/… はいまだけ。再起動で消える
  • 残すなら /etc/sysctl.conf か /etc/sysctl.d/*.conf に書く。書いただけでは反映されないので、sysctl -p で読み込む
  • sysctl -p は引数なしなら /etc/sysctl.conf を読む。-a は表示、-w は書き込み

/sys（sysfs）

/proc/sys がカーネルの「調整つまみ」なのに対して、/sys（sysfs）は装置とドライバのつながりを木で見せるファイルシステムです（図解 LinuC 5.3）。

/sys/bus/バスの種類ごと（pci、usb）
/sys/class/装置の種類ごと（net、block）
/sys/devices/装置の木の本体
/sys/module/読み込まれているモジュール。/sys/module/名前/parameters/ にモジュールの引数
/sys/firmware/efi/UEFI で起動したときだけある

udev：ルールと、udevadm monitor

カーネルが装置を見つけると、udev（systemd-udevd）に知らせ（uevent）が届きます。udev はルールに従って、/dev にデバイスファイルを作り、名前やリンクを付けます（図解 LinuC 5.4）。

場所中身
/etc/udev/rules.d/管理者が置くルール。/usr/lib/udev/rules.d/ の同じ名前のファイルより優先
/usr/lib/udev/rules.d/パッケージが置くルール（Debian 系は /lib/udev/rules.d/）
/etc/udev/udev.confudev 自身の設定

ルールのファイルは 70-usb-disk.rules のように、番号で始まり .rules で終わる名前にします。番号の小さい順に読まれます。

# /etc/udev/rules.d/70-usb-disk.rulesACTION=="add", SUBSYSTEM=="block", ATTRS{serial}=="AB12CD34", SYMLINK+="backupdisk"

== は条件（一致するか）、= と += は設定（値を入れる、足す）です。この行は「ブロックデバイスが追加され、シリアル番号が AB12CD34 なら、/dev/backupdisk というシンボリックリンクを足す」という意味です。

届いている知らせをその場で見るのが udevadm monitor です。

ターミナル
# udevadm monitormonitor will print the received events for:UDEV - the event which udev sends out after rule processingKERNEL - the kernel uevent KERNEL[36974.592077] add      /devices/…/block/sdb (block)UDEV  [36974.611204] add      /devices/…/block/sdb (block)

KERNEL の行がカーネルからの知らせ、UDEV の行が、udev がルールを処理し終えた知らせです。USB メモリを挿しても KERNEL の行が出なければカーネル（ドライバ）の問題、KERNEL は出るのに /dev に期待した名前ができなければルールの問題、と切り分けられます。

コマンドすること
udevadm monitorカーネルと udev の知らせを表示し続ける。-k カーネルだけ、-u udev だけ、-p プロパティも表示

udevadm control --reloadルールを読み直させる
udevadm trigger装置の知らせをもう一度起こして、ルールを適用し直す

udevmonitor は、udevadm monitor の昔の名前です。いまのディストリビューションには udevadm しかありません。

1.14kdump と kexec：クラッシュの記録を取る

カーネルが続けられないほどのエラーを起こすことを、カーネルパニックと呼びます。パニックの原因を調べるには、そのときのメモリの中身（クラッシュダンプ）が要ります。しかし、壊れたカーネルは自分でファイルを書けません。そこで、別のカーネルに切り替えて、そちらに書かせます。

  • kexec … 動いているカーネルから、別のカーネルを直接起動する仕組みとコマンド。ファームウェア（BIOS / UEFI）とブートローダを通らないので、ふつうの再起動より速い
  • kdump … kexec を使って、パニックのときにキャプチャ用のカーネルを起動し、クラッシュダンプを保存する仕組み
項目内容
メモリの予約カーネルパラメータ crashkernel=（crashkernel=256M など）。2 つ目のカーネルが使うメモリを、起動のときに取っておく
設定ファイルRed Hat 系は /etc/kdump.conf、Debian 系は /etc/default/kdump-tools
サービスRed Hat 系は kdump.service（kdumpctl status で状態を見る）、Debian 系は kdump-tools.service
ダンプの元2 つ目のカーネルから見える /proc/vmcore（1 つ目のカーネルのメモリ）
保存先既定は /var/crash/
調べる道具crash コマンド

Rocky Linux 9 の /etc/kdump.conf の、コメントでない行です。

path /var/crashcore_collector makedumpfile -l --message-level 7 -d 31

path が保存先、core_collector がダンプを作るコマンドです。makedumpfile は、要らないページを除いて圧縮し、ダンプを小さくします。

kexec コマンドは、手で使うこともできます。

ターミナル
# kexec -l /boot/vmlinuz-5.14.0-custom --initrd=/boot/initramfs-5.14.0-custom.img --reuse-cmdline# kexec -e                    ← 読み込んでおいたカーネルを、すぐに起動する# systemctl kexec             ← サービスを順に止めてから、kexec で起動する
kexec意味
-l（--load）次に起動するカーネルを読み込む
-e（--exec）読み込んであるカーネルを起動する
-p（--load-panic）パニックのときに起動するカーネルを読み込む（kdump が使う）
-u（--unload）読み込んだカーネルを捨てる
--initrd=ファイルinitramfs を指定する
--append=文字列カーネルパラメータを指定する
--reuse-cmdlineいまのカーネルパラメータ（/proc/cmdline）をそのまま使う
メモパニックのときの動きを決めるパラメータ

/proc/sys/kernel/panic（kernel.panic）は、パニックの後に自動で再起動するまでの秒数です。0 なら再起動せずに止まったままになります。kernel.panic_on_oops を 1 にすると、軽いエラー（oops）でもパニックにします。kdump を仕掛けたサーバーでは、こうした値を /etc/sysctl.d/ に書いておきます。

要点まとめ
  • BIOS は MBR（446 + 64 + 2 バイト）のブートローダを実行する。UEFI は ESP（FAT、/boot/efi）の .efi を実行し、起動エントリは efibootmgr で見る・変える
  • grub.cfg は手で書かない。/etc/default/grub と /etc/grub.d/ を編集し、grub-mkconfig -o /boot/grub/grub.cfg（Red Hat 系は grub2-mkconfig -o /boot/grub2/grub.cfg）で作る。ブートローダ本体は grub-install（grub2-install）
  • initramfs は、本当のルートをマウントするための仮のルート（cpio アーカイブ）。カーネルパラメータは /proc/cmdline で見られる
  • unit ファイルの優先順位は /etc/systemd/system/ ＞ /run/systemd/system/ ＞ /usr/lib/systemd/system/。上書きの一覧は systemd-delta
  • disable は自動起動をやめるだけ。mask は /dev/null へのリンクで、手でも起こせなくする
  • レスキューモード（rescue.target）はローカルのファイルシステムをマウントする。緊急モード（emergency.target）はルートだけを読み取り専用で。どちらも root のパスワードが要る
  • bzImage は big zImage。圧縮は既定で gzip、xz も選べる。ソースは /usr/src/linux/、文書は Documentation/
  • 設定は .config（=y 組み込み、=m モジュール）。menuconfig（ncurses）、xconfig（Qt）、gconfig（GTK+）、oldconfig（既存を引き継ぐ）。mrproper は .config も消す
  • make modules_install → /lib/modules/カーネルバージョン/。initramfs は mkinitramfs -o（Debian 系）、dracut（Red Hat 系）。外部のモジュールは DKMS が作り直す
  • modprobe は modules.dep（depmod が作る）で依存を解決する。設定は /etc/modprobe.d/（options、blacklist、alias、install）
  • sysctl -w は一時的。残すなら /etc/sysctl.conf か /etc/sysctl.d/ に書き、sysctl -p で読み込む。net.ipv4.ip_forward ＝ /proc/sys/net/ipv4/ip_forward
  • カーネルのメッセージは dmesg と journalctl -k。装置は lspci -k、lsusb、lsdev。udev の知らせは udevadm monitor、ルールは /etc/udev/rules.d/
  • kexec はカーネルから別のカーネルを直接起動する。kdump はそれを使ってクラッシュダンプを /var/crash/ に保存する。メモリは crashkernel= で予約する
