## シェル変数と環境変数：set、export、env、unset {#vars}

```fig graph set はシェル変数も環境変数も全部、env と export -p は環境変数だけを表示する。子プロセスに渡るのは環境変数だけ

    { id: 'set', label: 'set', sub: 'シェル変数と環境変数の全部（関数も）', x: 0, y: 1, kind: 'plain', mono: false },
    { id: 'env', label: 'env ／ export -p', sub: '環境変数だけ', x: 1, y: 1, kind: 'plain', mono: false },

  ],

    { from: 'sh', to: 'set', label: '全部' },

    { from: 'sh', to: 'child', label: 'export したものだけコピー' },
  ],

```

シェルの変数は 2 種類です。`名前=値` で作っただけの**シェル変数**は、そのシェルの中にしかありません。`export` すると**環境変数**になり、そのシェルが起動するコマンド（子プロセス）にコピーされます（[図解 Linux 2.6](../../linux/site/ch02.html#vars)、[7.9](../../linux/site/ch07.html#env)）。

試験では「どのコマンドで、どの変数が見えるか」が問われます。小さな Linux で確かめます。

```sh run error title="シェル変数は env には出ない"
city=Tokyo
set | grep city
env | grep city
sh -c 'echo "child sees [$city]"'
```

`set` には出ますが、`env` には出ません（`grep` が 1 行も見つけられず、終了ステータス 1 になりました）。子のシェルにも渡っていません。

```sh run title="export すると環境変数になる"
export city
env | grep city
export -p | grep city
sh -c 'echo "child sees [$city]"'
unset city
echo "[$city]"
```

`export -p` の表示は、小さな Linux の `sh` では `export city="Tokyo"`、bash では `declare -x city="Tokyo"` の形になります。

最後の 2 行のように、`unset` は変数そのものを消します。消した変数を取り出しても、エラーにはならず空になります。

`env 名前=値 コマンド` は、そのコマンドにだけ環境変数を足して（変えて）実行します。

```console
$ env LANG=C sh -c 'echo $LANG'
C
$ echo $LANG
ja_JP.UTF-8
```

シェル自身の `LANG` は変わっていません。`名前=値 コマンド` と書いても同じです。

| コマンド | 働き |
| --- | --- |
| `名前=値` | シェル変数を作る（`=` の前後に空白を入れない） |
| `export 名前` / `export 名前=値` | 環境変数にする（子プロセスに渡る） |
| `export` / `export -p` | 環境変数の一覧（`declare -x 名前="値"` の形。bash の場合） |
| `export -n 名前` | 環境変数の印だけを外し、シェル変数に戻す（bash） |
| `set` | シェル変数と環境変数の全部（bash では関数の定義も）を表示する |
| `set -o` / `set -o オプション名` / `set +o オプション名` | シェルのオプションの一覧 / 有効にする / 無効にする |
| `unset 名前` | 変数を消す。`unset -f 名前` なら関数を消す |
| `env` / `printenv` | 環境変数の一覧 |
| `env 名前=値 コマンド` | 環境変数を足してコマンドを実行する |
| `env -i コマンド` | 環境変数を空にしてコマンドを実行する |

:::warn 試験の注意：set と env の違い
「export していない変数も含めて、すべての変数を表示する」のは `set` です。`env`・`printenv`・`export -p` は環境変数だけです。また、`set` は引数を付けると別の働き（シェルのオプションや位置パラメータの設定）になります。`set -o noclobber` のような形も、ここで出てきます（[1.03.3](#redirect)）。
:::

覚えておく主な環境変数です。

| 変数 | 意味 |
| --- | --- |
| `PATH` | コマンドを探すディレクトリの並び（`:` 区切り） |
| `HOME` | ホームディレクトリ |
| `PWD` / `OLDPWD` | いまのディレクトリ / 1 つ前のディレクトリ（`cd -` の行き先） |
| `SHELL` | ログインシェルのパス |
| `LANG` | 言語と文字コード |
| `EDITOR` / `VISUAL` | `crontab -e` などが使うエディタ（[1.03.5](#editors)） |
| `HISTFILE` / `HISTSIZE` / `HISTFILESIZE` | 履歴のファイル / 覚える件数 / ファイルに残す件数（[次の節](#history)） |

## 引用符とパス：echo が何を表示するか {#quoting}

シェルは、コマンドを実行する前に `$名前` や `$(…)` を**展開**します（[図解 Linux 2.7](../../linux/site/ch02.html#quoting)）。引用符は、展開を止めたり、空白を守ったりするためのものです。試験では「次の `echo` の出力はどれか」の形でよく問われます。

| 書き方 | 名前 | 中で `$変数` は | 中で `` `コマンド` ``・`$(コマンド)` は | 空白 |
| --- | --- | --- | --- | --- |
| `'…'` | シングルクォート（一重引用符） | 展開しない | 展開しない | 守る |
| `"…"` | ダブルクォート（二重引用符） | 展開する | 展開する | 守る |
| `\文字` | バックスラッシュ（エスケープ） | 次の 1 文字だけ、特別な意味をなくす | 同じ | `\ ` で空白も守れる |
| `` `…` `` | バッククォート | — | 中のコマンドの出力に置き換える（`$(…)` と同じ） | — |

```sh run title="引用符の違い"
echo "$HOME" '$HOME' \$HOME
echo "today: `date +%Y`" 'today: `date +%Y`'
x='a    b'
echo $x
echo "$x"
echo -n "no newline"; echo "<"
echo -e "a\tb"
```

`echo $x` では、展開の後で空白が単語の区切りとみなされ、`a` と `b` の 2 つの引数になります。`echo` は引数を空白 1 つでつなぐので、空白が縮みました。`"$x"` と囲めば 1 つの引数のままです。

`echo` 自身のオプションも、ときどき問われます（上の最後の 2 行）。

| オプション | 意味 |
| --- | --- |
| `-n` | 最後に改行を出さない |
| `-e` | `\t`（タブ）や `\n`（改行）などを解釈する（bash の組み込みの echo） |

### 絶対パス、相対パス、. と ..

`/` で始まるパスが**絶対パス**、それ以外が**相対パス**です（[図解 Linux 3.3](../../linux/site/ch03.html#paths)）。相対パスは、いまのディレクトリ（`pwd` で表示される場所）から数えます。

| 書き方 | 意味 |
| --- | --- |
| `/` で始まる | 絶対パス（ルートから） |
| `.` | いまのディレクトリ |
| `..` | 1 つ上のディレクトリ |
| `~` | ホームディレクトリ（シェルが展開する） |
| `cd -` | 1 つ前にいたディレクトリへ戻る（`$OLDPWD`） |
| `cd`（引数なし） | ホームディレクトリへ |

```sh run title="pwd と相対パス"
cd /usr/bin
pwd
cd ../share
pwd
cd -
cd
pwd
```

カレントディレクトリにあるスクリプトを実行するときは、`./hello.sh` のように `./` を付けます。`.` は ふつう `PATH` に入っていないので、名前だけでは見つからないからです（[図解 Linux 2.4](../../linux/site/ch02.html#path)）。

`.` はもう 1 つ、**コマンド**としても使われます。`. ファイル`（`source ファイル` と同じ）は、ファイルの中身を**いまのシェル**で実行します。`bash ファイル` は新しい bash（子プロセス）で実行するので、中で設定した変数は残りません（[図解 Linux 7.10](../../linux/site/ch07.html#subshell)）。

```sh run title="./ で実行する、. で読み込む"
cat hello.sh
chmod +x hello.sh
./hello.sh
. ./hello.sh
```

`./hello.sh` で実行するには、実行の権限（`chmod +x`）が要ります。`. ./hello.sh` は、ファイルを読めれば実行の権限がなくても動きます。

Linux の多くのディストリビューションで、ログインしたときのシェルは **bash**（Bourne Again SHell）です。`bash` と打つと、いまのシェルの子として新しい bash が起動し、`exit` で元に戻ります。小さな Linux のシェルは `sh` ですが、この章の書き方は bash でもそのまま動きます。シェルの設定ファイル（`~/.bashrc` など）は 1.06 で扱います。

## 履歴と man：前のコマンドと使い方を呼び出す {#history}

```fig graph bash は打ったコマンドをメモリの履歴に覚え、終わるときに ~/.bash_history へ書き出す。次に起動したとき、そのファイルから読み込む
{
  col: 250, row: 100,
  nodes: [
    { id: 'type', label: '打ったコマンド', x: 0, y: 0, kind: 'plain', mono: false },
    { id: 'mem', label: 'メモリの履歴', sub: 'HISTSIZE 件まで。history で表示', x: 1, y: 0, kind: 'accent', mono: false },
    { id: 'file', label: '~/.bash_history', sub: 'HISTFILESIZE 行まで', x: 2, y: 0, kind: 'stack' },
  ],
  edges: [
    { from: 'type', to: 'mem', label: '実行するたび' },
    { from: 'mem', to: 'file', label: 'シェルを終えるとき書く' },
    { from: 'file', to: 'mem', label: '起動するとき読む', curve: 1, style: 'muted' },
  ],
}
```

bash は、打ったコマンドを**履歴**として覚えています。組み込みコマンドの `history` で番号つきの一覧が出ます。履歴はシェルを終えるときに、ホームディレクトリの **`.bash_history`**（`HISTFILE` 変数で決まる）に書き出されます。

```sh run title="history で一覧を見る"
echo one
echo two
history 3
```

本物の bash では、履歴を `!` で呼び出せます（**履歴展開**）。小さな Linux にはこの書き方がないので、Debian 12 の bash での例を見せます。呼び出したコマンドは、実行する前に画面に表示されます。

```console
$ echo hello
hello
$ !!
echo hello
hello
$ echo world
world
$ history 4
    1  echo hello
    2  echo hello
    3  echo world
    4  history 4
$ !1
echo hello
hello
$ !ec
echo hello
hello
```

| 書き方 | 意味 |
| --- | --- |
| `!!` | 直前のコマンド |
| `!番号` | 履歴のその番号のコマンド（`!1`） |
| `!-番号` | 番号だけ前のコマンド（`!-2` は 2 つ前） |
| `!文字列` | その文字列で**始まる**いちばん新しいコマンド |
| `!?文字列?` | その文字列を**含む**いちばん新しいコマンド |
| `^古い^新しい` | 直前のコマンドの「古い」を「新しい」に置き換えて実行 |
| `history 数` | 最後の数件を表示 |
| `history -c` | メモリの履歴を消す |
| Ctrl + R | 履歴を検索する |

| 変数 | 意味 |
| --- | --- |
| `HISTFILE` | 履歴を保存するファイル。既定は `~/.bash_history` |
| `HISTSIZE` | メモリに覚える件数 |
| `HISTFILESIZE` | ファイルに残す行数 |
| `HISTCONTROL` | `ignorespace`（空白で始まる行を残さない）、`ignoredups`（続けて同じ行を残さない）、`ignoreboth`（両方） |

:::warn 試験の注意：履歴のファイル名
履歴のファイルは `~/.bash_history` です。`~/.history` や `~/.bash_log` ではありません。また、ファイルに書かれるのは**シェルを終えるとき**なので、別の端末で開いている bash の履歴は、その bash を終えるまでファイルに現れません。
:::

### man：マニュアルとセクション番号

`man コマンド名` で、マニュアルを表示します。表示には `less` が使われるので、`q` で閉じ、`/文字列` で検索、スペースで次のページです。マニュアルは**セクション**（章）に分かれています。

| セクション | 内容 | 例 |
| --- | --- | --- |
| 1 | ユーザーのコマンド | `ls(1)`、`passwd(1)` |
| 2 | システムコール | `open(2)` |
| 3 | ライブラリ関数 | `printf(3)` |
| 4 | デバイスファイル（`/dev` の下） | `null(4)` |
| 5 | 設定ファイルの書式 | `passwd(5)`、`crontab(5)` |
| 6 | ゲーム | |
| 7 | その他（約束ごと、概要） | `regex(7)`、`man(7)` |
| 8 | 管理者用のコマンド | `mount(8)`、`useradd(8)` |

同じ名前が複数のセクションにあるときは、番号を付けて選びます。`passwd` はコマンド（1）と、ファイル `/etc/passwd` の書式（5）の両方にあります。

```console
$ man -f passwd
passwd (1)           - change user password
passwd (5)           - the password file
$ man 5 passwd
PASSWD(5)               File Formats and Configuration               PASSWD(5)

NAME
       passwd - the password file
...
$ man -k "copy files"
cp (1)               - copy files and directories
install (1)          - copy files and set attributes
$ man -w 5 passwd
/usr/share/man/man5/passwd.5.gz
```

| 書き方 | 意味 |
| --- | --- |
| `man 名前` | 最初に見つかったセクションのマニュアル（ふつうは 1 が先） |
| `man 5 passwd` | セクション 5 の passwd |
| `man -k キーワード` | 名前と説明からキーワードを探す（`apropos` と同じ） |
| `man -f 名前` | その名前のページの一覧と短い説明（`whatis` と同じ） |
| `man -w 名前` | マニュアルのファイルの場所を表示する |

マニュアルのファイルは `/usr/share/man/man1/`、`/usr/share/man/man5/` のように、セクションごとのディレクトリにあります。探す場所は `MANPATH` 変数や `/etc/manpath.config` で決まります。

`LS(1)` や `PASSWD(5)` の括弧の中がセクション番号です。問題文に `crontab(5)` とあれば「crontab の設定ファイルの書式のページ」、`crontab(1)` なら「crontab コマンドのページ」です。

## 見る・数える・番号を付ける：cat、less、head、tail、wc、nl、od {#view}

**フィルタ**は、標準入力（またはファイル）を読んで、加工した結果を標準出力に書くコマンドです（[図解 Linux 5.5](../../linux/site/ch05.html#filter)）。1.03.2 の 19 個のコマンドを、役目で 3 つに分けて覚えます。

| 役目 | コマンド |
| --- | --- |
| 見る・数える・番号を付ける | `cat`、`less`、`head`、`tail`、`wc`、`nl`、`od` |
| 列を切る・つなぐ・並べる・分ける | `cut`、`paste`、`join`、`sort`、`uniq`、`tr`、`split` |
| 整える | `expand`、`unexpand`、`fmt`、`pr`、`sed` |

### cat と less

小さな Linux のホームディレクトリには、練習用のファイル（`fruits.txt`、`numbers.txt`、`poem.txt`、`scores.csv`、`memo.txt`）があります。

```sh run title="cat のオプション"
cat fruits.txt
cat -n poem.txt
printf 'x\n\ny\n' > blank.txt
cat -b blank.txt
cat -E fruits.txt | head -n 2
```

| `cat` のオプション | 意味 |
| --- | --- |
| `-n` | すべての行に番号を付ける |
| `-b` | 空でない行にだけ番号を付ける |
| `-s` | 続いた空行を 1 行にまとめる |
| `-E` | 行の終わりに `$` を表示する |
| `-T` | タブを `^I` で表示する |
| `-A` | 見えない文字を全部表示する（`-vET` と同じ） |

`less` は、長いファイルを 1 画面ずつ見るページャです。前にも戻れます（`more` は基本的に前へ進むだけ）。

| `less` のキー | 動き |
| --- | --- |
| スペース / `b` | 次の画面 / 前の画面 |
| `j` / `k` | 1 行下 / 1 行上 |
| `g` / `G` | 先頭 / 末尾 |
| `/文字列` / `?文字列` | 下へ検索 / 上へ検索 |
| `n` / `N` | 次の一致 / 逆向きの一致 |
| `q` | 終わる |

### head と tail

```sh run title="head と tail"
head -n 3 fruits.txt
tail -n 2 fruits.txt
tail -n +8 fruits.txt
head -n -7 fruits.txt
head -c 9 poem.txt; echo
```

| 書き方 | 意味 |
| --- | --- |
| `head ファイル` / `tail ファイル` | 先頭 / 末尾の **10 行**（既定） |
| `head -n 3` / `head -3` | 先頭の 3 行 |
| `head -n -7` | 最後の 7 行を**除いた**全部 |
| `head -c 9` | 先頭の 9 バイト |
| `tail -n 2` / `tail -2` | 末尾の 2 行 |
| `tail -n +8` | **8 行目から**最後まで |
| `tail -f` | 末尾を表示した後、足された行を表示し続ける（ログの監視。Ctrl + C で止める） |
| `tail -F` | `-f` に加えて、ファイルが作り直されても追いかける |

:::warn 試験の注意：tail の + と head の -
`tail -n +8` は「8 行目から」、`tail -n 8` は「最後の 8 行」です。`head -n -7` は「最後の 7 行を除く」です。符号で意味が変わるので、問題文の `+` と `-` を見落とさないでください。ログを見張り続けるのは `tail -f` で、`head` に `-f` はありません。
:::

### wc

```sh run title="wc は 行・単語・バイト の順。nl は空行を飛ばす"
wc poem.txt
wc -l fruits.txt numbers.txt
wc -c memo.txt
wc -m memo.txt
nl blank.txt
cat -n blank.txt
```

`wc` の出力は、**行数、単語数、バイト数**の順です。ファイルを複数与えると、最後に `total`（合計）の行が付きます。`memo.txt` は日本語なので、バイト数（`-c`）と文字数（`-m`）が違います。

| オプション | 数えるもの |
| --- | --- |
| `-l` | 行（改行の数） |
| `-w` | 単語（空白で区切られたもの） |
| `-c` | バイト |
| `-m` | 文字 |
| `-L` | いちばん長い行の長さ |

### nl

`nl` は行番号を付けます。上の最後の 2 つを比べると、`cat -n` と違い、**既定では空の行に番号を付けない**ことがわかります。

番号の付け方は、オプションで変えられます（小さな Linux の `nl` にはオプションがないので、Debian 12 での例です）。

```console
$ nl -b a blank.txt
     1	x
     2	
     3	y
$ nl -v 10 -i 5 -w 3 -s: fruits.txt | head -n 3
 10:apple
 15:banana
 20:cherry
```

| オプション | 意味 |
| --- | --- |
| `-b a` | 空行も含めて、すべての行に番号を付ける |
| `-b t` | 空でない行だけ（既定） |
| `-b n` | 番号を付けない |
| `-v 数` | 最初の番号 |
| `-i 数` | 番号の増やし方 |
| `-w 数` | 番号の桁の幅 |
| `-s 文字列` | 番号の後に付ける区切り（既定はタブ） |
| `-n ln` / `rn` / `rz` | 左寄せ / 右寄せ（既定）/ 右寄せで 0 を詰める |

### od

```fig layout printf 'AB\n' の 3 バイトを od で見ると。-c は文字、-t x1 は 16 進、-b は 8 進で 1 バイトずつ表示する
{
  unit: 92,
  rows: [
    { label: '-c', cells: [ { t: 'A', kind: 'accent' }, { t: 'B', kind: 'accent' }, { t: '\\n', kind: 'stack' } ] },
    { label: '-t x1', cells: [ { t: '41', kind: 'accent' }, { t: '42', kind: 'accent' }, { t: '0a', kind: 'stack' } ] },
    { label: '-b', cells: [ { t: '101', kind: 'accent' }, { t: '102', kind: 'accent' }, { t: '012', kind: 'stack' } ] },
  ],
}
```

`od`（octal dump）は、ファイルの中身をバイトの値で表示します。改行やタブのような見えない文字を確かめるときに使います。左端の数字は、そのバイトの位置（既定は 8 進数）です。

```sh run title="od で見えない文字を見る"
printf 'a\tb\n' > tab.txt
od -c tab.txt
od -t x1 tab.txt
od -A x -c tab.txt
```

オプションを付けない `od` は、2 バイトずつを 8 進数で表示します（Debian 12）。

```console
$ printf 'AB\n' > ab
$ od ab

0000003
$ od -x ab
0000000 4241 000a
0000003
```

| オプション | 表示のしかた |
| --- | --- |
| （なし） | 2 バイトずつ 8 進数 |
| `-c` | 文字（`\n`、`\t` など） |
| `-b` | 1 バイトずつ 8 進数 |
| `-x` | 2 バイトずつ 16 進数 |
| `-t x1` / `-t o1` / `-t c` | 型を指定（1 バイトずつ 16 進 / 8 進 / 文字） |
| `-A x` / `-A d` / `-A n` | 左端の位置を 16 進 / 10 進 / 表示しない |

## 列を切る・つなぐ・並べる：cut、paste、join、sort、uniq、tr、split {#columns}

### cut と paste

```sh run title="cut で切り、paste でつなぐ"
cut -d, -f1,3 scores.csv | head -n 3
cut -d, -f2- scores.csv | head -n 2
cut -c 1-3 fruits.txt | head -n 2
printf 'a\tb\tc\n' | cut -f 2
paste fruits.txt numbers.txt | head -n 3
paste -d, fruits.txt numbers.txt | head -n 2
paste -s -d+ numbers.txt
```

| `cut` のオプション | 意味 |
| --- | --- |
| `-d 文字` | 区切りの文字。**既定はタブ** |
| `-f 列` | 取り出す列。`1,3`、`2-4`、`2-`（2 列目から最後まで） |
| `-c 位置` | 取り出す文字の位置（`1-3`） |
| `-b 位置` | 取り出すバイトの位置 |
| `-s` | 区切りの文字を含まない行を出さない |

後半の `paste` は、ファイルの**同じ行番号の行**を横につなぎます。区切りは**既定でタブ**です。

| `paste` のオプション | 意味 |
| --- | --- |
| `-d 文字` | つなぐ文字（既定はタブ） |
| `-s` | 1 つのファイルの全部の行を、1 行に横につなぐ |

### join：共通の列でつなぐ

```fig graph join は 2 つのファイルを、共通の列（既定は 1 列目）が同じ行どうしでつなぐ。paste は列の値を見ずに、同じ行番号どうしをつなぐ
{
  col: 210, row: 96,
  nodes: [
    { id: 'n', label: 'names.txt', sub: '1 sato / 2 suzuki / 3 tanaka', x: 0, y: 0, kind: 'stack' },
    { id: 's', label: 'subj.txt', sub: '1 math / 3 english / 4 art', x: 0, y: 1, kind: 'stack' },
    { id: 'j', label: 'join names.txt subj.txt', sub: '1 sato math / 3 tanaka english', x: 1.5, y: 0.5, kind: 'accent' },
  ],
  edges: [
    { from: 'n', to: 'j', label: '1 列目が同じ行' },
    { from: 's', to: 'j' },
  ],
}
```

`join` は、データベースの結合と同じことをします。**両方のファイルが、つなぐ列で並べ替え済み**であることが前提です（並んでいないと `join: input is not in sorted order` と警告します）。小さな Linux にはないので、Debian 12 での例です。

```console
$ cat names.txt
1 sato
2 suzuki
3 tanaka
$ cat subj.txt
1 math
3 english
4 art
$ join names.txt subj.txt
1 sato math
3 tanaka english
$ join -a 1 names.txt subj.txt
1 sato math
2 suzuki
3 tanaka english
$ join -v 2 names.txt subj.txt
4 art
$ join -o 1.2,2.2 names.txt subj.txt
sato math
tanaka english
$ join -t, -1 2 -2 1 c1.csv c2.csv
1,sato,math
2,suzuki,art
```

最後の例は、`c1.csv`（`sato,1` の形）の 2 列目と、`c2.csv`（`1,math` の形）の 1 列目でつないでいます。

| `join` のオプション | 意味 |
| --- | --- |
| （なし） | 両方の 1 列目が同じ行をつなぐ。区切りは空白 |
| `-t 文字` | 区切りの文字 |
| `-1 列` / `-2 列` | 1 つ目 / 2 つ目のファイルの、つなぐ列 |
| `-a 1` | 1 つ目のファイルの、相手がない行も出す |
| `-v 2` | 2 つ目のファイルの、相手がない行**だけ**を出す |
| `-o 1.2,2.2` | 出す列（ファイル番号.列番号） |

### sort と uniq

```sh run title="sort は既定で文字の順。uniq は隣り合った行だけ"
sort numbers.txt | head -n 3
sort -n numbers.txt | head -n 3
sort -t, -k3 -nr scores.csv | head -n 3
sort -u fruits.txt
uniq fruits.txt | wc -l
sort fruits.txt | uniq -c
sort fruits.txt | uniq -d
sort fruits.txt | uniq -u
```

| `sort` のオプション | 意味 |
| --- | --- |
| `-n` | 数として比べる |
| `-r` | 逆順 |
| `-k 2` / `-k 2,2` | 2 列目から行末まで / 2 列目だけで比べる |
| `-t 文字` | 列の区切り（既定は空白の並び） |
| `-u` | 同じ行を 1 つにまとめる |
| `-f` | 大文字と小文字を区別しない |
| `-b` | 先頭の空白を無視する |
| `-h` | `2K`、`1G` のような単位付きの数として比べる |
| `-M` | 月の名前（`JAN` … `DEC`）として比べる |
| `-o ファイル` | 結果をファイルに書く（入力と同じファイルでもよい） |

後半の `uniq` は、**隣り合った**同じ行をまとめます。離れた同じ行はまとめないので（`uniq fruits.txt` は 9 行のまま）、先に `sort` します（[図解 Linux 5.7](../../linux/site/ch05.html#sort)）。

| `uniq` のオプション | 意味 |
| --- | --- |
| `-c` | 行の前に、まとめた数を付ける |
| `-d` | 重複している行だけを（1 つずつ）出す |
| `-u` | 重複していない行だけを出す |
| `-i` | 大文字と小文字を区別しない |

### tr

`tr` は、**標準入力だけ**を読みます。ファイル名を引数に取らないので、`tr a-z A-Z < file` や `cat file | tr …` の形で使います。

```sh run title="tr：1 文字ずつ置き換える・消す・縮める"
echo hello | tr el ip
tr '[:lower:]' '[:upper:]' < fruits.txt | head -n 2
echo hello | tr -d l
echo "a    b" | tr -s ' '
echo abc123 | tr -cd '0-9'; echo
```

`tr el ip` は、`e` を `i` に、`l` を `p` に、1 文字ずつ対応させて置き換えます。`hello` は `hippo` になりました。文字列 `el` を `ip` に置き換えるのではありません。

| `tr` のオプション | 意味 |
| --- | --- |
| （なし） | 集合 1 の文字を、集合 2 の同じ位置の文字に置き換える |
| `-d` | 集合 1 の文字を消す |
| `-s` | 同じ文字の続きを 1 つに縮める |
| `-c` | 集合 1 **以外**の文字を対象にする（`-cd '0-9'` は数字以外を消す） |

### split

`split` は、大きなファイルを分けます。**既定では 1000 行ごと**に、`xaa`、`xab`、`xac` … という名前のファイルを作ります（Debian 12 での例）。

```console
$ seq 2500 > big
$ split big
$ ls
big  xaa  xab  xac
$ wc -l xaa
1000 xaa
$ split -l 1000 big part_
$ ls part_*
part_aa  part_ab  part_ac
$ split -b 100 -d fruits.txt chunk
$ ls chunk*
chunk00
```

| 書き方 | 意味 |
| --- | --- |
| `split ファイル` | 1000 行ごとに `xaa`、`xab` … へ |
| `split ファイル 接頭辞` | 名前を `接頭辞aa`、`接頭辞ab` … にする |
| `-l 行数` | 何行ごとに分けるか |
| `-b 大きさ` | 何バイトごとに分けるか（`-b 10M` のように単位も書ける） |
| `-d` | 名前の後ろを数字（`00`、`01` …）にする |

分けたファイルは `cat xa* > big2` で元に戻せます。

## 整える：expand、unexpand、fmt、pr、sed {#format}

この節のコマンドは、`sed` のほかは小さな Linux にありません。Debian 12 での例を見せます。`cat -A` は、タブを `^I`、行の終わりを `$` で表示します。

### expand と unexpand：タブと空白

```console
$ cat -A tab.txt
a^Ibc^Idef$
^Ix$
$ expand tab.txt | cat -A
a       bc      def$
        x$
$ expand -t 4 tab.txt | cat -A
a   bc  def$
    x$
$ expand -i tab.txt | cat -A
a^Ibc^Idef$
        x$
```

`expand` はタブを空白に変えます。タブの位置は**既定で 8 文字ごと**で、`-t` で変えられます。`-i` は行の先頭のタブだけを変えます。

```console
$ cat -A sp.txt
        a       b$
    c$
$ unexpand sp.txt | cat -A
^Ia       b$
    c$
$ unexpand -a sp.txt | cat -A
^Ia^Ib$
    c$
```

`unexpand` は逆に、空白をタブに変えます。**既定では行の先頭の空白だけ**を変え、`-a` で行の中の空白も変えます。

| コマンド | 既定 | 主なオプション |
| --- | --- | --- |
| `expand` | タブ → 空白（8 文字ごと） | `-t 数`（タブの幅）、`-i`（行頭のタブだけ） |
| `unexpand` | 空白 → タブ（行頭だけ） | `-a`（行の中も）、`-t 数` |

### fmt：段落を決まった幅に詰め直す

```console
$ cat long.txt
The quick brown fox jumps over the lazy dog. A journey of a thousand miles begins with a single step.
$ fmt -w 30 long.txt
The quick brown fox jumps
over the lazy dog. A journey
of a thousand miles begins
with a single step.
$ printf 'one\ntwo\nthree\n\nfour\n' | fmt
one two three

four
```

`fmt` は、段落（空行で区切られたまとまり）の中の行をつなぎ直して、決まった幅に収めます。幅は**既定で 75 文字**、`-w` で変えます。空行は段落の区切りとして残ります。

### pr：印刷用にページを作る

```console
$ pr -h TITLE -l 15 names.txt


2026-11-16 11:15                      TITLE                       Page 1


1 sato
2 suzuki
3 tanaka
（以下、15 行になるまで空行）
$ seq 6 | pr -2 -t
1				    4
2				    5
3				    6
$ pr -t -n names.txt
    1	1 sato
    2	2 suzuki
    3	3 tanaka
```

`pr` は、テキストを印刷向けのページに分けます。各ページの頭に、日時・見出し（既定はファイル名）・ページ番号の**ヘッダ**を付けます。1 ページは**既定で 66 行**です。

| `pr` のオプション | 意味 |
| --- | --- |
| `-h 文字列` | ヘッダの見出し |
| `-l 行数` | 1 ページの行数（既定 66） |
| `-t` | ヘッダとフッタを付けない |
| `-数` | その数の段組にする（`-2` で 2 段） |
| `-n` | 行番号を付ける |
| `-d` | 1 行おきに空行を入れる（ダブルスペース） |
| `-w 数` | ページの幅（段組のとき。既定 72） |

:::warn 試験の注意：似た名前、似た役目
- 行番号を付けるのは `nl`、`cat -n`、`pr -n`。`nl` だけが既定で空行を飛ばす
- 横につなぐのは `paste`（行番号で）と `join`（共通の列の値で）
- 幅をそろえるのは `fmt`（段落を詰め直す）。ページに分けてヘッダを付けるのは `pr`
- タブを空白にするのは `expand`、空白をタブにするのは `unexpand`
:::

### sed の基本

`sed`（stream editor）は、行ごとに編集の命令を当てはめるフィルタです（[図解 Linux 5.8](../../linux/site/ch05.html#cut)）。`sed 's/a/A/g'` で置き換え、`sed -n '2,3p'` で 2〜3 行目だけを表示、`sed '1d'` で 1 行目を消す、という使い方をします。正規表現と組み合わせることが多いので、[1.03.4](#grep-sed) で詳しく扱います。

## リダイレクト：<、>、>>、2>、2>&1 {#redirect}

どのプロセスも、3 つの口を持って始まります。**標準入力（0）**、**標準出力（1）**、**標準エラー（2）**です。数字はファイルディスクリプタの番号です（[図解 Linux 5.1](../../linux/site/ch05.html#stdio)）。リダイレクトは、この口の行き先をファイルに付け替えるシェルの書き方です。

```sh run error title="> は上書き、>> は追記、2> はエラーだけ"
echo first > out.txt
echo second >> out.txt
cat out.txt
wc -l < fruits.txt
ls fruits.txt nope > ok.txt 2> ng.txt
cat ok.txt
cat ng.txt
```

| 書き方 | 意味 |
| --- | --- |
| `> ファイル`（`1>` と同じ） | 標準出力をファイルへ。ファイルがあれば**空にしてから**書く |
| `>> ファイル` | 標準出力をファイルの**末尾に足す** |
| `< ファイル`（`0<` と同じ） | 標準入力をファイルから読む |
| `2> ファイル` | 標準エラーをファイルへ |
| `2>> ファイル` | 標準エラーをファイルの末尾に足す |
| `> ファイル 2>&1` | 標準出力と標準エラーの両方をファイルへ |
| `&> ファイル` | 上と同じ（bash の書き方） |
| `2> /dev/null` | エラーを捨てる |
| `<< 終わりの印` | 次の行から「終わりの印」だけの行までを標準入力にする（ヒアドキュメント） |
| `<<< 文字列` | 文字列を標準入力にする（ヒアストリング。bash） |
| `>\| ファイル` | `noclobber` が有効でも上書きする |

### 2>&1 は書く順番で意味が変わる

```fig graph > all.txt 2>&1 と 2>&1 > all.txt の違い。シェルは左から順に、口の行き先を付け替える。ボタンで 1 つずつ進めてください
{
  col: 280, row: 84,
  nodes: [
    { id: 'p', label: 'ls', sub: '口 1 と 口 2', x: 0, y: 0.5, kind: 'accent' },
    { id: 't', label: '端末', x: 1, y: 0, kind: 'ext', mono: false },
    { id: 'f', label: 'all.txt', x: 1, y: 1, kind: 'ext' },
  ],
  edges: [
    { from: 'p', to: 't', label: '1 と 2' },
  ],
  steps: [
    { title: 'はじめ', say: '何も書かなければ、口 1（標準出力）も口 2（標準エラー）も端末を向いています。' },
    {
      title: '> all.txt',
      say: '<code>&gt; all.txt 2&gt;&amp;1</code> の場合。まず <code>&gt; all.txt</code> で、口 1 が all.txt を向きます。',
      edges: [ { from: 'p', to: 't', label: '2', style: 'bad' }, { from: 'p', to: 'f', label: '1', style: 'accent' } ],
    },
    {
      title: '2>&1',
      say: '次の <code>2&gt;&amp;1</code> は「口 2 を、<strong>いま口 1 が向いているところ</strong>へ」。口 1 はもう all.txt なので、両方がファイルに入ります。',
      edges: [ { from: 'p', to: 'f', label: '1 と 2', style: 'accent' } ],
    },
    {
      title: '逆の順番',
      say: '<code>2&gt;&amp;1 &gt; all.txt</code> と書くと、先に口 2 が「いま口 1 が向いているところ」＝端末へ向き（変化なし）、そのあと口 1 だけが all.txt へ向きます。エラーは画面に出たままです。',
      edges: [ { from: 'p', to: 't', label: '2', style: 'bad' }, { from: 'p', to: 'f', label: '1', style: 'accent' } ],
    },
  ],
}
```

`2>&1` は「口 2 を、**その時点で**口 1 が向いている先に向ける」という意味です。そのため、書く順番で結果が変わります（[図解 Linux 9.5](../../linux/site/ch09.html#order)）。

```sh run error title="順番を逆にすると、エラーは画面に出る"
ls fruits.txt nope > all.txt 2>&1
cat all.txt
ls fruits.txt nope 2>&1 > all2.txt
cat all2.txt
```

パイプとの組み合わせも同じ考え方です。`|` は、リダイレクトより**先に**口 1 をパイプにつなぎます。

| 書き方 | パイプに流れるもの |
| --- | --- |
| `コマンド \| wc -l` | 標準出力だけ（エラーは画面へ） |
| `コマンド 2>&1 \| wc -l` | 標準出力と標準エラーの両方 |
| `コマンド \|& wc -l` | 上と同じ（bash の書き方） |
| `コマンド 2>&1 > /dev/null \| wc -l` | 標準エラーだけ（標準出力は捨てる） |

:::warn 試験の注意：2>&1 の位置
「標準出力と標準エラーの両方を `log` に書く」正しい書き方は `コマンド > log 2>&1`（または `&> log`）です。`コマンド 2>&1 > log` ではエラーが画面に残ります。`2>1` と書くと、`1` という名前のファイルができるだけです。`&` を忘れないでください。
:::

### noclobber：うっかりの上書きを防ぐ

`>` は、ファイルがあれば中身を消してから書きます。bash の `set -o noclobber`（`set -C` と同じ）を有効にすると、`>` で既にあるファイルを上書きしようとしたときにエラーになります。小さな Linux にはないので、Debian 12 の bash での例です。

```console
$ echo a > f
$ set -o noclobber
$ echo b > f
bash: f: cannot overwrite existing file
$ echo c >| f
$ cat f
c
$ set +o noclobber
```

`>|` は、noclobber を無視して上書きします。`>>`（追記）は noclobber の対象ではありません。

```fig graph パイプは前のコマンドの標準出力を次の標準入力へ流す。tee は流れを分けてファイルにも書く。xargs は流れてきた言葉を、次のコマンドの引数に並べる
{
  col: 170, row: 100,
  nodes: [
    { id: 'a', label: 'sort', x: 0, y: 0, kind: 'plain' },
    { id: 'tee', label: 'tee log.txt', x: 1, y: 0, kind: 'accent' },
    { id: 'f', label: 'log.txt', x: 1, y: 1, kind: 'stack' },
    { id: 'b', label: 'head', x: 2, y: 0, kind: 'plain' },
    { id: 'find', label: 'find', x: 0, y: 2, kind: 'plain' },
    { id: 'x', label: 'xargs rm', x: 1, y: 2, kind: 'accent' },
    { id: 'rm', label: 'rm a b c', sub: '引数になる', x: 2, y: 2, kind: 'crate', mono: false },
  ],

    { from: 'a', to: 'tee', label: '|' }, { from: 'tee', to: 'b', label: '|' }, { from: 'tee', to: 'f', label: '書く' },
    { from: 'find', to: 'x', label: '| a b c' }, { from: 'x', to: 'rm', label: '実行' },
  ],

```

**パイプ** `|` は、左のコマンドの標準出力を、右のコマンドの標準入力につなぎます（[図解 Linux 5.4](../../linux/site/ch05.html#pipe)）。つなぐのは標準出力だけで、標準エラーは通りません。

**`tee`** は、標準入力を**標準出力とファイルの両方**に書きます。パイプの途中の結果を残したいとき、画面で見ながらファイルにも保存したいときに使います。

**`xargs`** は、標準入力から読んだ言葉を、指定したコマンドの**引数**に並べて実行します。`rm` や `cp` のように、標準入力を読まず引数で相手を受け取るコマンドに、パイプの結果を渡すときに使います。

```sh run title="tee と xargs"
sort fruits.txt | uniq -c | sort -rn | tee count.txt | head -n 1
wc -l count.txt
echo a b c d e | xargs -n 2
echo fruits.txt | xargs -t wc -l
ls *.txt | xargs -I {} cp {} {}.bak
ls *.bak | head -n 3
```

`-t` は、実行するコマンドを標準エラーに表示してから実行します。`-I {}` は、`{}` の場所に 1 行ずつ入れて、1 行に 1 回実行します。

| `tee` / `xargs` | 意味 |
| --- | --- |
| `tee ファイル` | 標準入力を、標準出力とファイルへ（ファイルは上書き） |
| `tee -a ファイル` | ファイルに追記する |
| `tee f1 f2` | 複数のファイルへ同時に |
| `xargs コマンド` | 標準入力の言葉を、コマンドの引数に並べて実行する（コマンドを省くと `echo`） |
| `xargs -n 数` | 1 回に渡す引数の数 |
| `xargs -I {} コマンド {}` | `{}` を 1 行ずつの入力に置き換え、1 行に 1 回実行する |
| `xargs -t` | 実行するコマンドを表示する |
| `xargs -0` | 区切りを空白や改行ではなく NUL 文字にする（`find -print0` と組み合わせる） |

ファイル名に空白が入っていると、`xargs` はそこで区切ってしまいます。`find … -print0 | xargs -0 …` と書くと、名前の終わりを NUL 文字（`\0`）で区切るので、空白を含む名前も正しく渡せます。

```console
$ find /tmp -name '*.log' -print0 | xargs -0 rm
```

`sudo echo text > /etc/motd` は失敗します。`> /etc/motd` を開くのは、root ではない**いまのシェル**だからです。`echo text | sudo tee /etc/motd` なら、root で動く `tee` がファイルを開きます。追記なら `sudo tee -a` です（[図解 Linux 5.3](../../linux/site/ch05.html#stderr)）。

## 正規表現：基本（BRE）と拡張（ERE） {#regex}

```fig layout 正規表現 ^b(an)+a$ を部品に分けると。( ) と + は拡張正規表現の書き方なので、grep -E で使う
{
  unit: 64,
  rows: [
    { label: '部品', cells: [ { t: '^', kind: 'stack' }, { t: 'b', kind: 'pad' }, { t: '(an)', w: 2, kind: 'accent' }, { t: '+', kind: 'accent' }, { t: 'a', kind: 'pad' }, { t: '$', kind: 'stack' } ] },
    { label: '意味', cells: [ { t: '行頭', kind: 'stack' }, { t: 'b', kind: 'pad' }, { t: 'an のまとまり', w: 2, kind: 'accent' }, { t: '1 回以上', kind: 'accent' }, { t: 'a', kind: 'pad' }, { t: '行末', kind: 'stack' } ] },
  ],
}
```

**正規表現**は、文字の並びの「型」を書く書き方です。`grep`、`sed`、`less` や vi の検索で使えます。マニュアルでは `regex(7)` に説明があります（`man 7 regex`）。

正規表現には 2 つの流儀があります。**基本正規表現（BRE）** と **拡張正規表現（ERE）** です。違いは、`+`、`?`、`{ }`、`( )`、`|` を、そのまま書くか `\` を付けて書くか、だけです。

| 意味 | BRE（`grep`、`sed`） | ERE（`grep -E`、`egrep`、`sed -E`） |
| --- | --- | --- |
| 任意の 1 文字 | `.` | `.` |
| 直前の 0 回以上のくり返し | `*` | `*` |
| 行頭 / 行末 | `^` / `$` | `^` / `$` |
| どれか 1 文字 / それ以外の 1 文字 | `[abc]` / `[^abc]` | `[abc]` / `[^abc]` |
| 範囲 | `[a-z]`、`[0-9]` | `[a-z]`、`[0-9]` |
| 直前の 1 回以上 | `\+`（GNU の拡張） | `+` |
| 直前の 0 回か 1 回 | `\?`（GNU の拡張） | `?` |
| 直前の n 回 / n〜m 回 | `\{n\}` / `\{n,m\}` | `{n}` / `{n,m}` |
| まとまり（グループ） | `\( \)` | `( )` |
| または | `\\|`（GNU の拡張） | `\|` |
| 文字そのもの（`.` など） | `\.` | `\.` |

文字の種類の名前も使えます。`[[:digit:]]`（数字）、`[[:alpha:]]`（英字）、`[[:upper:]]`（大文字）、`[[:lower:]]`（小文字）、`[[:space:]]`（空白）です。外側の `[ ]` が要ることに注意してください。GNU の grep と sed では、`\<` と `\>` で単語の始まりと終わりも表せます。

```sh run title="正規表現の部品"
grep 'an*a' fruits.txt
grep -E 'ap+le|^g' fruits.txt
grep 'p\{2\}' fruits.txt
grep -E '^[a-c].*a$' fruits.txt
grep 'a.e' fruits.txt
grep '\.' poem.txt | wc -l
grep '.' poem.txt | wc -l
```

最後の 2 つの違いに注意してください。`\.` はピリオドそのもの（3 行）、`.` は「何か 1 文字」なので、空でない行すべて（5 行）に合います。

よく使う形に、`^$`（行頭のすぐ後が行末＝**空行**）と `^#`（`#` で始まる行＝設定ファイルの**コメント行**）があります。`grep -v '^#' 設定ファイル | grep -v '^$'` で、コメントと空行を除いた中身だけを見られます。

:::warn 試験の注意：* はワイルドカードと違う
シェルのワイルドカードの `*` は「任意の文字列」ですが、正規表現の `*` は「**直前の文字の** 0 回以上のくり返し」です。正規表現で「任意の文字列」は `.*` です。`grep 'a*'` はすべての行に合います（`a` が 0 回でもよいため）。また、パターンはシングルクォートで囲みます。囲まないと、シェルが `*` や `$` を先に展開してしまいます。
:::

## grep と sed で正規表現を使う {#grep-sed}

### grep、egrep、fgrep

| コマンド | パターンの解釈 |
| --- | --- |
| `grep` | 基本正規表現（BRE） |
| `grep -E` / `egrep` | 拡張正規表現（ERE） |
| `grep -F` / `fgrep` | 正規表現として**解釈しない**（固定の文字列。`.` や `*` もただの文字） |

`egrep` と `fgrep` は古い名前で、いまは `grep -E` と `grep -F` を使うことが勧められています。Debian 12 では、`/usr/bin/fgrep` の中身は `exec grep -F "$@"` という 3 行のシェルスクリプトです。小さな Linux に `fgrep` はないので、`grep -F` で試します。

```sh run title="grep -F は . をただの文字として探す"
grep -c . poem.txt
grep -F -c . poem.txt
egrep -c 'apple|melon' fruits.txt
```

| `grep` のオプション | 意味 |
| --- | --- |
| `-i` | 大文字と小文字を区別しない |
| `-v` | 合わ**ない**行を出す |
| `-n` | 行番号を付ける |
| `-c` | 合った行の**数**だけを出す |
| `-l` | 合った行がある**ファイルの名前**だけを出す |
| `-L` | 合った行が 1 つもないファイルの名前を出す |
| `-w` | 単語全体として合うものだけ（`the` は `there` に合わない） |
| `-x` | 行全体として合うものだけ |
| `-o` | 合った部分だけを出す |
| `-r` | ディレクトリの中を再帰的に探す |
| `-h` / `-H` | ファイル名を付けない / 付ける |
| `-e パターン` | パターンを指定する（複数書けば「どれか」） |
| `-f ファイル` | パターンをファイルから読む |
| `-q` | 何も出さず、終了ステータスだけで答える（0 = 見つかった） |
| `-E` / `-F` | 拡張正規表現 / 固定の文字列 |

```sh run title="grep のオプション"
grep -n -i '^the' poem.txt
grep -w the poem.txt
grep -c 'e$' fruits.txt
grep -v -c apple fruits.txt
grep -l fox poem.txt fruits.txt
grep -e apple -e melon fruits.txt
```

### sed：置き換え、表示、削除

`sed` は、各行に命令を当てはめて、結果を標準出力に書きます。元のファイルは変わりません（`-i` のときだけ書き換えます）。

```text
sed [オプション] '[アドレス]命令' ファイル
```

**アドレス**は、命令を当てはめる行を選びます。書かなければ全部の行です。

| アドレス | 選ぶ行 |
| --- | --- |
| `3` | 3 行目 |
| `2,4` | 2〜4 行目 |
| `$` | 最後の行 |
| `3,$` | 3 行目から最後まで |
| `/正規表現/` | 正規表現に合う行 |

| 命令 | 意味 |
| --- | --- |
| `s/正規表現/置き換え/` | 各行の最初の 1 つを置き換える |
| `s/…/…/g` | 行の中の全部を置き換える |
| `s/…/…/2` | 2 つ目だけを置き換える |
| `p` | その行を表示する（`-n` と一緒に使う） |
| `d` | その行を消す（出力しない） |

置き換えの側では、`&` が「合った部分の全体」、`\1`、`\2` が「1 つ目、2 つ目の `( )` に合った部分」になります。

| オプション | 意味 |
| --- | --- |
| `-n` | 自動の出力をしない。`p` で指示した行だけが出る |
| `-e 命令` | 命令を指定する。複数書くと順に当てはめる |
| `-f ファイル` | 命令をファイルから読む |
| `-i` | ファイルを直接書き換える。`-i.bak` なら元を `ファイル.bak` に残す |
| `-E`（`-r`） | 拡張正規表現を使う |

```sh run title="sed の s、p、d、-n、-i"
echo banana | sed 's/a/A/2'
echo banana | sed 's/an/[&]/g'
echo 'sato,82' | sed -E 's/(.*),(.*)/\2,\1/'
sed -n '/^b/p' fruits.txt
sed '/apple/d' fruits.txt
sed -n '$p' fruits.txt
cp fruits.txt f.txt
sed -i.bak 's/apple/APPLE/g' f.txt
head -n 1 f.txt f.txt.bak
```

`-n` を付けずに `p` を使うと、選んだ行が 2 回出ます（自動の出力と `p` の出力）。「合った行だけを表示する」は `sed -n '/…/p'` で、`grep` と同じ働きです。

命令を 2 つ以上当てはめるときは、`-e` を重ねるか、`;` で区切ります（Debian 12 での例です）。

```console
$ sed -e 's/a/A/' -e 's/n/N/' fruits.txt | head -n 2
Apple
bANana
$ sed 's/a/A/;s/n/N/' fruits.txt | head -n 2
Apple
bANana
```

:::warn 試験の注意：sed の -n と -i
- `sed '2p'` は全部の行を出し、2 行目だけを 2 回出す。2 行目だけを出すのは `sed -n '2p'`
- `sed '2d'` は 2 行目を**除いた**全部を出す
- `sed 's/a/b/'` は各行の**最初の 1 つ**だけ。全部なら末尾に `g`
- ファイルそのものを書き換えるのは `-i` だけ。`sed 's/a/b/' f > f` はファイルを空にしてしまう（シェルが先に `> f` で空にする）
:::

## vi：3 つのモードを行き来する {#vi}

```fig graph vi のモード。起動するとコマンドモード。i a o などで挿入モードへ、ESC で戻る。: でコマンドラインに入り、:w や :q を打つ
{
  col: 250, row: 120,
  nodes: [
    { id: 'n', label: 'コマンドモード', sub: '起動した直後。h j k l、dd、yy、p', x: 1, y: 0, kind: 'accent', mono: false },
    { id: 'i', label: '挿入モード', sub: '打った文字が入る', x: 0, y: 1, kind: 'stack', mono: false },
    { id: 'c', label: 'コマンドライン（ex）', sub: ':w :q! :wq :e!、/ と ? で検索', x: 2, y: 1, kind: 'crate', mono: false },
  ],
  edges: [
    { from: 'n', to: 'i', label: 'i a o I A O' },
    { from: 'i', to: 'n', label: 'ESC', curve: 1, style: 'muted' },

    { from: 'c', to: 'n', label: 'Enter で実行', curve: 1, style: 'muted' },
  ],

```

**vi** は、どの Linux にもほぼ必ず入っているエディタです。多くのディストリビューションでは、`vi` を打つと改良版の **vim** が起動します（Debian 12 では `vim.tiny`）。小さな Linux には vi がないので、この節の例は Debian 12 の vi で確かめたものです。

vi のいちばんの特徴は、**モード**があることです。起動した直後は**コマンドモード**（ノーマルモード）で、キーを押すと文字が入るのではなく、「移動」「削除」などの命令になります。文字を入れるには**挿入モード**に入り、終わったら **ESC** でコマンドモードに戻ります。

### 挿入モードに入る

| キー | どこから入力するか |
| --- | --- |
| `i` | カーソルの**前**から |
| `a` | カーソルの**後**から |
| `I` | 行の先頭から |
| `A` | 行の末尾から |
| `o` | 下に新しい行を作って |
| `O` | 上に新しい行を作って |
| ESC | 挿入モードを終えて、コマンドモードに戻る |

### 移動

| キー | 動き |
| --- | --- |
| `h` / `j` / `k` / `l` | 左 / 下 / 上 / 右 |
| `w` / `b` | 次の単語の先頭 / 前の単語の先頭 |
| `0` / `$` | 行の先頭 / 行の末尾 |
| `gg` / `G` | ファイルの先頭の行 / 最後の行 |
| `数G`（`5G`） / `:5` | 5 行目へ |

### 削除、コピー、貼り付け、変更

| キー | 働き |
| --- | --- |
| `x` | カーソルの 1 文字を消す |
| `dd` | 1 行を消す（`3dd` で 3 行） |
| `yy` | 1 行をコピーする（ヤンク。`3yy` で 3 行） |
| `p` / `P` | 消した・コピーしたものを、カーソルの後（行なら下）/ 前（行なら上）に貼る |
| `r文字` | カーソルの 1 文字を置き換える |
| `u` | 直前の操作を取り消す |
| `.` | 直前の変更をくり返す |

`d`（削除）、`y`（コピー）、`c`（変更）は、後ろに**移動のキー**を付けて範囲を指定します。`c` は消した後、挿入モードに入ります。同じキーを 2 回（`dd`、`yy`、`cc`）なら 1 行全体です。

| 組み合わせ | 働き |
| --- | --- |
| `dw` / `yw` / `cw` | 単語の終わりまで 消す / コピー / 書き換える |
| `d$`（`D`）/ `c$`（`C`） | 行末まで 消す / 書き換える |
| `d0` | 行頭まで消す |
| `dG` | いまの行からファイルの最後まで消す |
| `dgg` | いまの行からファイルの先頭まで消す |
| `cc` | 行全体を書き換える |
| `2dw` | 2 単語を消す |

Debian 12 の vi で、4 行のファイルに操作をした結果です（カーソルは 1 行目の先頭から）。

```console
元のファイル     ddp の後         yyjjp の後       wD の後
line1 alpha     line2 gamma      line1 alpha      line1
line2 gamma     line1 alpha      line2 gamma      line2 gamma
line3 delta     line3 delta      line3 delta      line3 delta
line4 eps       line4 eps        line1 alpha      line4 eps
                                 line4 eps
```

`ddp` は「1 行目を消して、次の行の下に貼る」ので、1 行目と 2 行目が入れ替わります。`yyjjp` は、1 行目をコピーし、2 行下へ動いて、その下に貼ります。`wD` は、次の単語へ動いて、行末まで消します。

### 検索

| キー | 働き |
| --- | --- |
| `/文字列` | 下（後ろ）へ向かって検索 |
| `?文字列` | 上（前）へ向かって検索 |
| `n` | 同じ向きに次を探す |
| `N` | 逆の向きに探す |

### 保存と終了（コマンドライン）

| コマンド | 働き |
| --- | --- |
| `:w` | 保存する |
| `:w!` | 強制的に保存する（読み取り専用のファイルでも、権限があれば） |
| `:w 名前` | 別の名前で保存する |
| `:q` | 終わる（変更が保存されていなければ、警告して終わらない） |
| `:q!` | 変更を**捨てて**終わる |
| `:wq` / `:x` / `ZZ` | 保存して終わる（`ZZ` はコロンなしで、コマンドモードで打つ） |
| `:e!` | 変更を捨てて、ファイルを最後に保存した状態から読み直す（vi は終わらない） |
| `:e ファイル` | 別のファイルを開く |
| `:set number` / `:set nu` | 行番号を表示する |
| `:%s/古い/新しい/g` | ファイル全体で置き換える（sed と同じ書き方） |

:::warn 試験の注意：:q! と :e! と ZZ
- 保存せずに**終わる**のは `:q!`。保存せずに**やり直す**（vi は終わらない）のは `:e!`
- `ZZ` は「保存して終わる」で、`:wq` と同じ。`ZQ` は `:q!` と同じ
- `:w!` は「強制的に保存」で、終わらない
- 挿入モードのまま `:wq` と打つと、文字として入ってしまう。先に ESC を押す
:::

## vi 以外のエディタと EDITOR {#editors}

`crontab -e` や `git commit` のように、途中でエディタを開くコマンドがあります。どのエディタを開くかは、環境変数 **`EDITOR`**（または `VISUAL`）で決まります。

```console
$ export EDITOR=vi
$ crontab -e          ← vi で開く
$ export EDITOR=nano
$ crontab -e          ← nano で開く
```

いつも同じエディタを使うなら、`export EDITOR=vi` を `~/.bashrc` などに書いておきます。Debian 系では、`EDITOR` が決まっていないときに使う既定のエディタ（`/usr/bin/editor`）を、`update-alternatives` や `select-editor` で選べます。Debian 12 の既定は nano です。

**nano** は、画面の下に操作の一覧が出る、初心者向けのエディタです。モードはなく、打った文字はそのまま入ります。`^` は Ctrl キーの意味です。

| nano のキー | 働き |
| --- | --- |
| Ctrl + O | 保存する（Write Out） |
| Ctrl + X | 終わる（保存していなければ、保存するかを聞く） |
| Ctrl + W | 検索する（Where Is） |
| Ctrl + K / Ctrl + U | 行を切り取る / 貼り付ける |
| Ctrl + G | ヘルプ |

**emacs** は、GNU プロジェクトの高機能なエディタです。こちらもモードはなく、Ctrl（`C-`）と Alt（`M-`）の組み合わせで操作します。

| emacs のキー | 働き |
| --- | --- |
| `C-x C-s` | 保存する |
| `C-x C-c` | 終わる |
| `C-x C-f` | ファイルを開く |
| `C-f` / `C-b` / `C-n` / `C-p` | 右 / 左 / 下 / 上 |
| `C-g` | 途中の操作を取り消す |

小さな Linux にはエディタがありません。ファイルを作るときは、`echo … > ファイル` や、ヒアドキュメント（`cat > ファイル <<END` … `END`）を使ってください。

:::key まとめ
- `set` はシェル変数も環境変数も全部、`env`・`printenv`・`export -p` は環境変数だけ。`export` で子に渡り、`unset` で消える。`env 名前=値 コマンド` は 1 回だけ変える
- `'…'` は何も展開しない、`"…"` は `$` と `` ` `` を展開する、`\` は 1 文字だけ守る
- 履歴は `~/.bash_history`（シェルを終えるときに書く）。`!!` 直前、`!番号`、`!文字列`、`history -c` で消す
- man のセクション：1 コマンド、5 設定ファイルの書式、7 その他（regex）、8 管理コマンド。`man -k` = apropos、`man -f` = whatis
- `cut -d -f`（既定の区切りはタブ）、`paste`（行番号で横に）、`join`（共通の列で。並べ替え済みが前提）、`nl`（既定で空行を飛ばす）、`split`（1000 行ごとに `xaa` …）、`expand`（タブ→空白）と `unexpand`（空白→タブ、既定は行頭だけ）、`fmt`（幅 75 に詰め直す）、`pr`（66 行のページ、ヘッダ付き）、`od`（バイトを 8 進・16 進で）
- `tail -n +N` は N 行目から、`tail -f` で追いかける。`uniq` の前に `sort`
- `> file 2>&1` で両方を file へ（逆順はエラーが画面に残る）。`set -o noclobber` で `>` の上書きを禁止、`>|` で強行
- `tee` は流れを分けてファイルにも書く（`-a` で追記）。`xargs` は標準入力を引数にする（`-n`、`-I {}`、`-0`）
- BRE と ERE の違いは `+ ? { } ( ) |` に `\` が要るかどうか。`grep -E` = `egrep`、`grep -F` = `fgrep`（固定の文字列）
- `sed -n '…p'` で選んだ行だけ、`d` で消す、`s///g` で全部置き換え、`-i` でファイルを書き換え
- vi：起動はコマンドモード。`i a o` で挿入、ESC で戻る。`dd yy p`、`dw cw`、`/ ? n N`、`:wq` = `ZZ`、`:q!` で捨てて終わる、`:e!` で読み直す
:::

## 練習問題 {#practice}

### 1.03.1 コマンドラインの操作

:::q 1.03.1-01 single
export していないシェル変数も含めて、いまのシェルのすべての変数を表示するコマンドはどれか。
- [ ] `env`
- [ ] `printenv`
- [ ] `export -p`
- [x] `set`
:::why
引数なしの `set` は、シェル変数と環境変数の全部（bash では関数の定義も）を表示します。`env` と `printenv` は環境変数だけ、`export -p` も export された変数（環境変数）だけを表示するので、export していないシェル変数は出ません（[シェル変数と環境変数](#vars)）。
:::
:::

:::q 1.03.1-02 single
次のコマンドを順に実行した。2 行目の出力として正しいものはどれか。

```text
$ city=Tokyo
$ bash -c 'echo "[$city]"'
```
- [ ] `[Tokyo]`
- [x] `[]`
- [ ] `[$city]`
- [ ] `bash: city: unbound variable` と表示される
:::why
`city=Tokyo` はシェル変数を作るだけで、export していません。`bash -c` は子プロセスの新しい bash なので、`city` を受け取らず、空の文字に展開されて `[]` になります。`'…'` で囲んでいるのは親のシェルに展開させないためで、子の bash の中では `"…"` の中の `$city` が展開されます。未設定の変数はエラーにならず空になります（`set -u` を付けたときだけエラー）（[シェル変数と環境変数](#vars)）。
:::
:::

:::q 1.03.1-03 multi
変数 `LANG` の値を `C` にし、このシェルから起動するコマンドにも渡るようにしたい。正しいものを 2 つ選択してください。
- [x] `export LANG=C`
- [x] `LANG=C; export LANG`
- [ ] `set LANG=C`
- [ ] `env LANG`
- [ ] `unset LANG=C`
:::why
`export 名前=値` と、値を入れてから `export 名前` の 2 つが正しい書き方です。

- `set LANG=C` は変数を作りません。`set` に引数を与えると、位置パラメータ（`$1`）が `LANG=C` になります
- `env LANG` は、`LANG` という名前のコマンドを実行しようとします
- `unset` は変数を消すコマンドで、値は入れられません（[シェル変数と環境変数](#vars)）
:::
:::

:::q 1.03.1-04 single
次のコマンドの出力として正しいものはどれか。

```text
$ name=Linux
$ echo '$name' "$name" \$name
```
- [ ] `Linux Linux Linux`
- [x] `$name Linux $name`
- [ ] `$name Linux Linux`
- [ ] `Linux Linux $name`
:::why
シングルクォートの中は何も展開されないので `$name` のまま。ダブルクォートの中は変数が展開されて `Linux`。`\$` は `$` の特別な意味をなくすので `$name` のままです（[引用符とパス](#quoting)）。
:::
:::

:::q 1.03.1-05 fill
環境変数をすべて空にした状態で `sh` を起動したい。空欄に入るオプションを入力してください。

```text
env ____ sh
```
= -i
= --ignore-environment
= -
:::why
`env -i コマンド` は、環境変数を何も持たない状態でコマンドを実行します（`-` だけでも同じ）。`env 名前=値 コマンド` なら、環境変数を足して実行します（[シェル変数と環境変数](#vars)）。
:::
:::

:::q 1.03.1-06 single
`unset` コマンドの説明として正しいものはどれか。
- [ ] 環境変数を、シェル変数に戻す
- [x] 変数を削除する
- [ ] 変数の値を空の文字にするが、変数そのものは残す
- [ ] 環境変数の一覧を表示する
:::why
`unset 名前` は変数そのものを消します（`-f` なら関数を消す）。環境変数の印だけを外してシェル変数に戻すのは bash の `export -n`、環境変数の一覧は `env` や `printenv` です。値を空にするだけなら `名前=` と書きます（[シェル変数と環境変数](#vars)）。
:::
:::

:::q 1.03.1-07 single
コマンドの出力に置き換わる（コマンド置換になる）書き方はどれか。
- [x] `$(date)`
- [ ] `${date}`
- [ ] `'date'`
- [ ] `"date"`
:::why
`$(コマンド)` とバッククォート `` `コマンド` `` がコマンド置換です。`${date}` は変数 `date` の値、`'date'` と `"date"` はただの文字列 `date` です（[引用符とパス](#quoting)）。
:::
:::

:::q 1.03.1-08 multi
絶対パスで書かれているものを 2 つ選択してください。
- [x] `/etc/passwd`
- [x] `/home/you/../you/memo.txt`
- [ ] `etc/passwd`
- [ ] `./bin/run.sh`
- [ ] `../etc/hosts`
:::why
`/` で始まるパスが絶対パスです。途中に `..` が入っていても、`/` から始まっていれば絶対パスです。`etc/passwd`、`./bin/run.sh`、`../etc/hosts` は、いまのディレクトリから数える相対パスです（[絶対パス、相対パス](#quoting)）。
:::
:::

:::q 1.03.1-09 single
カレントディレクトリにある実行可能なスクリプト `run.sh` を実行したい。環境変数 `PATH` にカレントディレクトリは含まれていない。正しい実行方法はどれか。
- [ ] `run.sh`
- [x] `./run.sh`
- [ ] `.run.sh`
- [ ] `~run.sh`
:::why
`.` は PATH に入っていないので、名前だけの `run.sh` では見つからず `command not found` になります。`./run.sh` とパスを付ければ、PATH を探さずにそのファイルを実行します。`.run.sh` は「.run.sh という名前のコマンド」、`~run.sh` は「ユーザー run.sh のホーム」の意味になります（[絶対パス、相対パス](#quoting)）。
:::
:::

:::q 1.03.1-10 single
`cd -` を実行したときの動きとして正しいものはどれか。
- [ ] ホームディレクトリへ移動する
- [ ] 1 つ上のディレクトリへ移動する
- [x] 直前にいたディレクトリへ移動する
- [ ] ルートディレクトリへ移動する
:::why
`cd -` は、1 つ前にいたディレクトリ（`$OLDPWD`）へ戻り、その場所を表示します。ホームへは引数なしの `cd`（または `cd ~`）、1 つ上へは `cd ..`、ルートへは `cd /` です（[絶対パス、相対パス](#quoting)）。
:::
:::

:::q 1.03.1-11 single
スクリプト `setenv.sh` の中で設定した変数を、実行した後もいまのシェルで使えるようにしたい。正しい実行方法はどれか。
- [ ] `bash setenv.sh`
- [ ] `./setenv.sh`
- [x] `. ./setenv.sh`
- [ ] `sh -c ./setenv.sh`
:::why
`. ファイル`（`source ファイル` と同じ）は、ファイルの中身をいまのシェルで実行するので、設定した変数が残ります。`bash setenv.sh`、`./setenv.sh`、`sh -c` は、どれも子プロセスの新しいシェルで実行するので、終わると変数は消えます（[図解 Linux 7.10](../../linux/site/ch07.html#subshell)）。
:::
:::

:::q 1.03.1-12 single
bash が、打ったコマンドの履歴を既定で保存するファイルはどれか。
- [ ] `~/.history`
- [x] `~/.bash_history`
- [ ] `~/.bashrc`
- [ ] `/var/log/bash_history`
:::why
既定の履歴ファイルは、ホームディレクトリの `.bash_history` です（変数 `HISTFILE` で変えられます）。`~/.bashrc` は bash の設定ファイルで、履歴ではありません。`~/.history` や `/var/log/bash_history` は bash の既定ではありません（[履歴と man](#history)）。
:::
:::

:::q 1.03.1-13 single
bash で、直前に実行したコマンドをもう一度実行する書き方はどれか。
- [x] `!!`
- [ ] `!0`
- [ ] `!$`
- [ ] `$!`
:::why
`!!` が直前のコマンドです。`!0` は履歴の 0 番という意味になりますが、履歴は 1 番から始まるのでエラーになります。`!$` は直前のコマンドの**最後の引数**、`$!` は最後にバックグラウンドで起動したプロセスの PID です（[履歴と man](#history)）。
:::
:::

:::q 1.03.1-14 fill
bash の履歴で 105 番のコマンドを、もう一度実行したい。打つものを入力してください。
= !105
:::why
`!番号` で、履歴のその番号のコマンドを実行します。番号は `history` で確かめられます。`!-2` のように `-` を付けると「2 つ前」という意味になります（[履歴と man](#history)）。
:::
:::

:::q 1.03.1-15 single
`history` の出力が次のとき、続けて `!ls` と打つと実行されるコマンドはどれか。

```text
  101  ls -l /etc
  102  cat /etc/hosts
  103  ls /tmp
  104  history
```
- [ ] `ls -l /etc`
- [x] `ls /tmp`
- [ ] `ls`
- [ ] 101 番と 103 番の両方
:::why
`!文字列` は、その文字列で始まる**いちばん新しい**コマンドを実行します。`ls` で始まる最新は 103 番の `ls /tmp` です。いちばん古いものや、全部ではありません（[履歴と man](#history)）。
:::
:::

:::q 1.03.1-16 multi
bash の履歴の説明として正しいものを 2 つ選択してください。
- [x] `HISTSIZE` は、メモリに覚えておく履歴の件数である
- [x] `history -c` で、メモリの履歴を消せる
- [ ] コマンドを実行するたびに、すぐ `~/.bash_history` に書き込まれる
- [ ] `!-2` は、履歴の 2 番のコマンドを実行する
- [ ] `HISTFILE` の既定値は `~/.history` である
:::why
`HISTSIZE` はメモリの件数（ファイルの行数は `HISTFILESIZE`）、`history -c` はメモリの履歴を消します。

- 履歴がファイルに書かれるのは、ふつうは**シェルを終えるとき**です
- `!-2` は「2 つ前」のコマンド。2 番は `!2` です
- `HISTFILE` の既定値は `~/.bash_history` です（[履歴と man](#history)）
:::

:::q 1.03.1-17 single
man のセクション 5 に置かれているものはどれか。

- [ ] システムコール
- [x] 設定ファイルの書式
- [ ] 管理者用のコマンド
:::why
セクション 5 は設定ファイルの書式（`passwd(5)`、`crontab(5)` など）です。ユーザーのコマンドは 1、システムコールは 2、管理者用のコマンドは 8 です（[man：マニュアルとセクション番号](#history)）。

:::q 1.03.1-18 fill
ファイル `/etc/passwd` の書式を説明したマニュアルを表示したい。空欄に入るものを入力してください。

:::q 1.03.1-19 single
「どのコマンドを使えばよいかわからないが、キーワードは決まっている」とき、マニュアルの名前と説明からキーワードを探すものはどれか。

1 がユーザーのコマンド、8 が管理者用のコマンド（`mount(8)` など）です。2 はシステムコール、3 がライブラリ関数、5 が設定ファイルの書式、7 はその他（`regex(7)` など）です（[man：マニュアルとセクション番号](#history)）。

### 1.03.2 フィルタを使ったテキストストリームの処理

:::q 1.03.2-01 single
ファイルの各行に行番号を付けて表示したい。ただし、空の行には番号を付けない（既定の動きのまま）。使うコマンドはどれか。
- [ ] `cat -n`
- [x] `nl`
- [ ] `wc -l`
- [ ] `od -c`
:::why
`nl` は既定で空でない行にだけ番号を付けます（`-b t`）。`cat -n` は空行も含めて全部の行に番号を付けます（空行を飛ばすのは `cat -b`）。`wc -l` は行数を数えるだけ、`od -c` はバイトを文字で表示するだけです（[nl](#view)）。
:::
:::

:::q 1.03.2-02 fill
`/etc/passwd` から、ユーザー名（1 列目）とログインシェル（7 列目）だけを取り出したい。区切りは `:` である。空欄に入るオプションを入力してください。

```text
cut ____ -f 1,7 /etc/passwd
```
= -d:
= -d :
= -d ':'
= -d':'
= -d ":"
= -d":"
= --delimiter=:
= --delimiter=':'
:::why
`-d` で区切りの文字を指定します。`cut` の既定の区切りはタブなので、`:` 区切りのファイルでは `-d:` が必要です。`-f 1,7` で 1 列目と 7 列目を取り出します（[cut と paste](#columns)）。
:::
:::

:::q 1.03.2-03 single
`list.txt` の中身が次のとき、`tail -n +3 list.txt` の出力として正しいものはどれか。

```text
a
b
c
d
e
```
- [ ] `c d e` を 1 行に並べたもの
- [x] `c`、`d`、`e` の 3 行
- [ ] `d`、`e` の 2 行
- [ ] `a`、`b` の 2 行
:::why
`tail -n +3` は「3 行目から最後まで」なので `c`、`d`、`e` です。最後の 3 行も同じく `c d e` になりますが、意味が違います。最後の 2 行（`d`、`e`）は `tail -n 2`、先頭の 2 行は `head -n 2` です。最後の 3 行を除いた `a`、`b` は `head -n -3` です（[head と tail](#view)）。
:::
:::

:::q 1.03.2-04 single
次のコマンドの出力として正しいものはどれか。

```text
$ echo banana | tr an AN
```
- [x] `bANANA`
- [ ] `bANana`
- [ ] `bAnana`
- [ ] `banana`
:::why
`tr` は 1 文字ずつ対応させて置き換えます。`a` → `A`、`n` → `N` なので、`banana` のすべての `a` と `n` が大文字になり `bANANA` です。文字列 `an` を 1 回だけ置き換えるのではありません（それは `sed 's/an/AN/'` の動きで、`bANana` になります）（[tr](#columns)）。
:::
:::

:::q 1.03.2-05 single
`data.txt` の中身が次のとき、`uniq -c data.txt` の出力として正しいものはどれか。

```text
a
a
b
a
```
- [ ] `3 a` と `1 b` の 2 行
- [x] `2 a`、`1 b`、`1 a` の 3 行
- [ ] `1 b` の 1 行
- [ ] `a`、`b` の 2 行
:::why
`uniq` は**隣り合った**同じ行だけをまとめます。最初の 2 行の `a` が `2 a`、次の `b` が `1 b`、離れた最後の `a` は別に `1 a` になります。`3 a` と `1 b` にしたければ、先に `sort` して `sort data.txt | uniq -c` とします（[sort と uniq](#columns)）。
:::
:::

:::q 1.03.2-06 multi
`join` コマンドの説明として正しいものを 2 つ選択してください。
- [x] オプションを付けなければ、両方のファイルの 1 列目が同じ行どうしをつなぐ
- [x] 入力のファイルは、つなぐ列で並べ替え済みである必要がある
- [ ] 既定の区切りの文字はタブである
- [ ] 列の値を見ずに、同じ行番号の行どうしを横につなぐ
- [ ] `-v 1` を付けると、両方のファイルにある行だけを出す
:::why
`join` は既定で 1 列目をキーにしてつなぎ、入力はキーで並べ替え済みであることが前提です。

- 既定の区切りは空白です（`-t` で変える）
- 行番号どうしを横につなぐのは `paste` です
- `-v 1` は、1 つ目のファイルの**相手がない行だけ**を出します（[join](#columns)）
:::
:::

:::q 1.03.2-07 single
オプションを付けずに `split big.log` を実行したときの動きとして正しいものはどれか。
- [ ] 100 行ごとに `big.log.1`、`big.log.2` … を作る
- [x] 1000 行ごとに `xaa`、`xab` … を作る
- [ ] 1 MB ごとに `xaa`、`xab` … を作る
- [ ] 1000 行ごとに `x00`、`x01` … を作る
:::why
`split` の既定は 1000 行ごとで、名前は接頭辞 `x` に `aa`、`ab` … を付けたものです。大きさで分けるのは `-b`、名前の後ろを数字（`00`、`01` …）にするのは `-d` です（[split](#columns)）。
:::
:::

:::q 1.03.2-08 single
ファイルの中のタブを、空白に置き換えて表示するコマンドはどれか。
- [x] `expand`
- [ ] `unexpand`
- [ ] `fmt`
- [ ] `paste`
:::why
`expand` はタブを空白に変えます（既定で 8 文字ごとのタブ位置）。`unexpand` は逆に空白をタブに変えます。`fmt` は段落を決まった幅に詰め直し、`paste` は行を横につなぎます（[expand と unexpand](#format)）。
:::
:::

:::q 1.03.2-09 single
長い行が続く文章を、1 行が 60 文字以内になるように段落ごとに詰め直したい。使うコマンドはどれか。
- [ ] `pr -w 60`
- [x] `fmt -w 60`
- [ ] `cut -c 1-60`
- [ ] `expand -t 60`
:::why
`fmt -w 60` は、段落の中の行をつなぎ直して、60 文字以内で折り返します（既定の幅は 75）。`pr -w` は段組のときのページ幅、`cut -c 1-60` は各行の 61 文字目以降を**捨てる**だけ、`expand -t 60` はタブの幅を 60 にするだけです（[fmt](#format)）。
:::
:::

:::q 1.03.2-10 single
`pr` コマンドの説明として正しいものはどれか。
- [ ] ファイルをプリンタに送って印刷する
- [x] テキストをページに区切り、日時やページ番号のヘッダを付けて出力する
- [ ] 段落を決まった幅に詰め直す
- [ ] ファイルを決まった行数ごとに分割する
:::why
`pr` は印刷向けに整形するだけで、出力は標準出力です（プリンタには送りません）。1 ページは既定で 66 行で、各ページに日時・見出し・ページ番号のヘッダが付きます。段落を詰め直すのは `fmt`、分割は `split` です（[pr](#format)）。
:::
:::

:::q 1.03.2-11 single
`tab.txt` に対してあるコマンドを実行したところ、次の出力になった。実行したコマンドはどれか。

```text

0000004
```
- [ ] `od tab.txt`
- [ ] `od -x tab.txt`
- [x] `od -c tab.txt`
- [ ] `cat -A tab.txt`
:::why
`\t`（タブ）や `\n`（改行）を文字で見せるのは `od -c` です。オプションなしの `od` は 2 バイトずつ 8 進数、`od -x` は 2 バイトずつ 16 進数で表示します。`cat -A` は `a^Ib$` のように表示し、左端の位置の数字は出ません（[od](#view)）。
:::
:::

:::q 1.03.2-12 multi
`wc` コマンドの説明として正しいものを 2 つ選択してください。
- [x] オプションを付けないと、行数、単語数、バイト数の順に表示する
- [x] `-c` はバイト数を数える
- [ ] `-w` は文字数を数える
- [ ] `-m` は行数を数える
- [ ] `-l` は単語数を数える
:::why
`wc` の既定は「行数 単語数 バイト数 ファイル名」の順です。`-c` がバイト、`-m` が文字、`-w` が単語、`-l` が行です。日本語のように 1 文字が複数バイトのときは、`-c` と `-m` の値が違います（[wc](#view)）。
:::
:::

:::q 1.03.2-13 single
数だけが 1 行に 1 つ書かれたファイル `num.txt` を、大きい数から順に並べたい。正しいものはどれか。
- [ ] `sort -r num.txt`
- [x] `sort -nr num.txt`
- [ ] `sort -u num.txt`
- [ ] `sort -k 1 num.txt`
:::why
数として比べる `-n` と、逆順の `-r` を組み合わせます。`-r` だけでは文字の順の逆になるので、`9` が `10` より前に来ます。`-u` は重複を除くだけ、`-k 1` は 1 列目で比べるだけで、どちらも文字の順です（[sort と uniq](#columns)）。
:::
:::

:::q 1.03.2-14 fill
`numbers.txt` のすべての行を、`,` でつないで 1 行にしたい。空欄に入るオプションを入力してください。

= -s -d,
= -sd,
= -d, -s
= -s -d ,
= -d , -s
= -s -d ','
= -sd ','
= -d ',' -s
= -sd ,
= -s --delimiters=,
= --serial --delimiters=,
= --delimiters=, --serial
:::why
`-s` で 1 つのファイルの全部の行を横につなぎ、`-d,` でつなぐ文字を `,` にします。`-s` だけなら、つなぐ文字はタブです（[cut と paste](#columns)）。

:::q 1.03.2-15 multi
コマンドとその動きの組み合わせとして正しいものを 2 つ選択してください。
- [x] `head -n -3 file`：最後の 3 行を除いた全部を表示する
- [x] `tail -f file`：末尾を表示した後、足された行を表示し続ける
- [ ] `head -c 5 file`：先頭の 5 行を表示する

:::why
`head -n -3` は最後の 3 行を除いた全部、`tail -f` はファイルを追いかけて表示し続けます。

- `head -c 5` は先頭の 5 **バイト**です
- `tail -n +5` は **5 行目から**最後までです
- `sort -u` は重複を除きます。逆順は `-r` です（[head と tail](#view)、[sort と uniq](#columns)）
:::

### 1.03.3 ストリーム、パイプ、リダイレクトの使用

:::q 1.03.3-01 single
`date >> log.txt` の動きとして正しいものはどれか。
- [ ] `log.txt` を空にしてから、`date` の出力を書く
- [x] `log.txt` の末尾に、`date` の出力を足す。`log.txt` がなければ作る
- [ ] `log.txt` の中身を、`date` の標準入力にする
- [ ] `date` の標準エラーを `log.txt` の末尾に足す
:::why
`>>` は標準出力の追記です。ファイルがなければ新しく作ります。空にしてから書くのは `>`、ファイルから読むのは `<`、標準エラーの追記は `2>>` です（[リダイレクト](#redirect)）。
:::
:::

:::q 1.03.3-02 single
コマンド `ls /x` の標準出力と標準エラーを、両方とも `out.txt` に書きたい。正しいものはどれか。
- [ ] `ls /x 2>&1 > out.txt`
- [ ] `ls /x > out.txt 2>1`
- [x] `ls /x > out.txt 2>&1`
- [ ] `ls /x 1> out.txt 2> /dev/null`
:::why
`> out.txt` で口 1 をファイルに向けてから、`2>&1` で口 2 を「いま口 1 が向いている先」に向けます。

- `2>&1 > out.txt` は順番が逆で、口 2 は端末を向いたまま（エラーは画面に出る）
- `2>1` は `&` がないので、`1` という名前のファイルにエラーを書く
- `2> /dev/null` はエラーを捨てる（[2>&1 は書く順番で意味が変わる](#redirect)）
:::
:::

:::q 1.03.3-03 single
`fruits.txt` はあり、`nope` はないとする。次のコマンドを実行したとき、**画面に表示されるもの**はどれか。

```text
$ ls fruits.txt nope 2>&1 > all.txt
```
- [ ] 何も表示されない
- [x] `nope` についてのエラーだけ
- [ ] `fruits.txt` だけ
- [ ] `fruits.txt` とエラーの両方
:::why
シェルは左から処理します。先に `2>&1` で口 2 が「いま口 1 が向いている先」＝端末に向き（変化なし）、そのあと `> all.txt` で口 1 だけがファイルに向きます。そのため `fruits.txt` は `all.txt` に入り、エラーは画面に出ます（[2>&1 は書く順番で意味が変わる](#redirect)、[図解 Linux 9.5](../../linux/site/ch09.html#order)）。
:::
:::

:::q 1.03.3-04 fill
`find / -name core` のエラー（`Permission denied` など）を画面に出さずに捨てたい。空欄に入るものを入力してください。

```text
find / -name core ____
```
= 2>/dev/null
= 2> /dev/null
:::why
`2>` で標準エラー（2 番）の行き先を変え、何でも捨てる特別なファイル `/dev/null` に向けます。見つかったファイル名（標準出力）は画面に出たままです（[リダイレクト](#redirect)）。
:::
:::

:::q 1.03.3-05 single
`fruits.txt` は 9 行のファイルである。`wc -l < fruits.txt` の出力として正しいものはどれか。
- [x] `9`
- [ ] `9 fruits.txt`
- [ ] `fruits.txt 9`
- [ ] 何も表示されない
:::why
`<` を使うと、`wc` はファイル名を知らずに標準入力から読むので、数だけを表示します。`wc -l fruits.txt` とファイル名を引数で渡したときは `9 fruits.txt` と表示されます（[リダイレクト](#redirect)）。
:::
:::

:::q 1.03.3-06 multi
パイプ `|` の説明として正しいものを 2 つ選択してください。
- [x] 左のコマンドの標準出力を、右のコマンドの標準入力につなぐ
- [x] 何もしなければ、左のコマンドの標準エラーはパイプを通らない
- [ ] 左のコマンドが終わってから、右のコマンドが起動する
- [ ] 左のコマンドの出力を、いったん一時ファイルに書いてから右へ渡す
- [ ] `|&` と書くと、標準エラーだけがパイプを通る
:::why
パイプがつなぐのは標準出力だけです。両方のコマンドは**同時に**動き、データはカーネルの中のバッファを通ります（一時ファイルは作りません）。`|&` は `2>&1 |` と同じで、標準出力と標準エラーの**両方**が通ります（[パイプ、tee、xargs](#pipe)、[図解 Linux 5.4](../../linux/site/ch05.html#pipe)）。
:::
:::

:::q 1.03.3-07 multi
`tee` コマンドの説明として正しいものを 2 つ選択してください。
- [x] 標準入力から読んだものを、標準出力とファイルの両方に書く
- [x] 書き込み先のファイルを複数指定できる
- [ ] 既定では、ファイルの末尾に追記する
- [ ] 標準入力から読んだものを、標準エラーにも書く
- [ ] ファイルにだけ書き、標準出力には何も出さない
:::why
`tee` は流れを分けて、標準出力とファイル（`tee f1 f2` のように複数も可）に書きます。既定は**上書き**で、追記は `-a` です。標準エラーには書きません（[パイプ、tee、xargs](#pipe)）。
:::
:::

:::q 1.03.3-08 fill
`ls` の結果を画面に出しながら、`list.txt` の末尾にも足していきたい。空欄に入るオプションを入力してください。

```text
ls | tee ____ list.txt
```
= -a
= --append
:::why
`tee -a` は、ファイルを上書きせずに末尾に足します。`-a` がないと、`list.txt` は毎回空にされてから書かれます（[パイプ、tee、xargs](#pipe)）。
:::
:::

:::q 1.03.3-09 single
`find . -name '*.tmp' | xargs rm` の動きの説明として正しいものはどれか。
- [ ] `find` の出力を `rm` の標準入力として渡す
- [x] `find` が出力したファイル名を、`rm` の引数に並べて実行する
- [ ] `find` の出力を、`xargs` というファイルに書く
- [ ] `find` と `rm` を順に実行し、`find` の結果は使わない
:::why
`xargs` は、標準入力から読んだ言葉を、指定したコマンドの**引数**に並べて実行します。`rm` は標準入力を読まないので、`find … | rm` では消せません。`xargs` を間に入れると、`rm ./a.tmp ./b.tmp …` の形で実行されます（[パイプ、tee、xargs](#pipe)）。
:::
:::

:::q 1.03.3-10 single
次のコマンドの出力として正しいものはどれか。

```text
$ echo 1 2 3 4 5 | xargs -n 2
```
- [ ] `1 2 3 4 5` の 1 行
- [x] `1 2`、`3 4`、`5` の 3 行
- [ ] `1 2`、`3 4` の 2 行（`5` は捨てられる）
- [ ] `2`、`4` の 2 行
:::why
`-n 2` は「1 回に引数を 2 つずつ渡す」です。コマンドを省いたので `echo` が使われ、`echo 1 2`、`echo 3 4`、`echo 5` の 3 回実行されます。残りの 1 つも捨てられずに渡されます（[パイプ、tee、xargs](#pipe)）。
:::
:::

:::q 1.03.3-11 single
名前に空白を含むファイルがあるディレクトリで、`find` で見つけたファイルを安全に `rm` に渡したい。正しいものはどれか。
- [ ] `find . -name '*.log' | xargs rm`
- [x] `find . -name '*.log' -print0 | xargs -0 rm`
- [ ] `find . -name '*.log' | xargs -n 1 rm`
- [ ] `find . -name '*.log' | tee rm`
:::why
`-print0` は名前の終わりを NUL 文字で区切って出し、`xargs -0` は NUL 文字で区切って読みます。空白で分けないので、空白を含む名前も 1 つの引数になります。ふつうの `xargs` は `-n 1` を付けても空白で区切るので、`my file.log` が `my` と `file.log` に分かれます。`tee rm` は `rm` という名前のファイルに書くだけです（[パイプ、tee、xargs](#pipe)）。
:::
:::

:::q 1.03.3-12 single
bash で `set -o noclobber` を有効にした。既にあるファイル `out.txt` を、それでも上書きしたい。正しい書き方はどれか。
- [ ] `echo hi >> out.txt`
- [x] `echo hi >| out.txt`
- [ ] `echo hi >& out.txt`
- [ ] `echo hi 2> out.txt`
:::why
`>|` は noclobber を無視して上書きします。`>>` は追記なので上書きにはなりません。`>&` は `&>` と同じく「両方をファイルへ」で、noclobber の対象なので失敗します。`2>` も上書きのリダイレクトなので、noclobber で止められます（[noclobber](#redirect)）。
:::
:::

:::q 1.03.3-13 multi
標準出力と標準エラーの両方を `log` に書くものを 2 つ選択してください。
- [x] `make &> log`
- [x] `make > log 2>&1`
- [ ] `make 2>&1 > log`
- [ ] `make 2> log`
- [ ] `make > log 2>1`
:::why
`&> log` と `> log 2>&1` は同じ意味です。`2>&1 > log` は順番が逆なのでエラーは画面に残り、`2> log` はエラーだけ、`2>1` は `1` という名前のファイルにエラーを書きます（[2>&1 は書く順番で意味が変わる](#redirect)）。
:::
:::

:::q 1.03.3-14 single
次のように入力したときの、`<<` の働きの説明として正しいものはどれか。

```text
$ cat << END
hello
END
```
- [ ] `END` という名前のファイルの末尾に `hello` を足す
- [x] 次の行から `END` だけの行の手前までを、`cat` の標準入力にする
- [ ] `END` という名前のファイルから読む
- [ ] `cat` の出力を `END` という名前のファイルに書く
:::why
`<< 印` はヒアドキュメントです。次の行から「印」だけの行までを標準入力として渡すので、`hello` が表示されます。ファイルの末尾に足すのは `>>`、ファイルから読むのは `<`、ファイルに書くのは `>` です（[リダイレクト](#redirect)）。
:::
:::

:::q 1.03.3-15 single
一般ユーザーが、root だけが書ける `/etc/motd` に文字を書き込みたい。`sudo` を使った正しい方法はどれか。
- [ ] `sudo echo "hello" > /etc/motd`
- [x] `echo "hello" | sudo tee /etc/motd`
- [ ] `echo "hello" > sudo /etc/motd`
- [ ] `sudo > /etc/motd echo "hello"`
:::why
`>` でファイルを開くのは、root ではない**いまのシェル**です。そのため `sudo echo … > /etc/motd` や `sudo > /etc/motd …` は `Permission denied` になります。`sudo tee` なら、root で動く `tee` がファイルを開いて書きます。`> sudo` は `sudo` という名前のファイルに書くだけです（[パイプ、tee、xargs](#pipe)）。
:::
:::

:::q 1.03.3-16 single
`ls /etc /nope 2>&1 | wc -l` で `wc` が数えるものはどれか。
- [ ] `/etc` の一覧の行だけ
- [ ] エラーの行だけ
- [x] `/etc` の一覧の行と、エラーの行の両方
- [ ] 何も数えない（0 を表示する）
:::why
`|` が口 1 をパイプにつないだ後、`2>&1` が口 2 も同じパイプに向けます。そのため、標準出力と標準エラーの両方が `wc` に流れます。`2>&1` がなければ、エラーは画面に出て数えられません（[2>&1 は書く順番で意味が変わる](#redirect)）。
:::
:::

:::q 1.03.3-17 multi
`xargs` のオプションの説明として正しいものを 2 つ選択してください。
- [x] `-I {}` は、コマンドの中の `{}` を入力の 1 行に置き換え、1 行ごとに実行する
- [x] `-t` は、実行するコマンドを表示してから実行する
- [ ] `-n` は、入力の区切りを NUL 文字にする
- [ ] `-0` は、1 回に渡す引数を 0 個にする
- [ ] `-I` は、標準入力を読まずにコマンドを実行する
:::why
`-I {}` は置き換えの文字列の指定、`-t` は実行するコマンドの表示（標準エラーへ）です。入力の区切りを NUL 文字にするのは `-0`、1 回に渡す引数の数は `-n` です（[パイプ、tee、xargs](#pipe)）。
:::
:::

:::q 1.03.3-18 fill
コマンド `cmd` の**標準エラーだけ**をパイプで `wc -l` に渡し、標準出力は捨てたい。空欄に入るものを入力してください。

= 2>&1 >/dev/null
= 2>&1 > /dev/null
= 2>&1 1>/dev/null
= 2>&1 1> /dev/null
:::why
`|` で口 1 がパイプを向いた状態から、`2>&1` で口 2 をパイプに向け、そのあと `>/dev/null` で口 1 だけを捨てます。順番を逆の `>/dev/null 2>&1` にすると、両方が捨てられて `wc` には何も届きません（[2>&1 は書く順番で意味が変わる](#redirect)）。
:::
:::

:::q 1.03.3-19 single
`data.txt` に数行のデータがある。`sort data.txt > data.txt` を実行した後の `data.txt` はどうなるか。
- [ ] 並べ替えた内容になる
- [x] 空になる
- [ ] 元の内容のまま変わらない
- [ ] 元の内容の後ろに、並べ替えた内容が足される
:::why
シェルは `sort` を起動する**前に** `> data.txt` を処理し、ファイルを空にします。`sort` が読むときには中身がないので、空のまま終わります。同じファイルに並べ替えた結果を書くには、`sort -o data.txt data.txt` を使うか、別のファイルに書いてから `mv` します（[sed の注意](#grep-sed)、[sort と uniq](#columns)）。
:::
:::

:::q 1.03.3-20 multi
`fruits.txt` の行数を数えるために、`wc -l` の標準入力をファイルから読ませたい。正しいものを 2 つ選択してください。
- [x] `wc -l < fruits.txt`
- [x] `wc -l 0< fruits.txt`
- [ ] `wc -l > fruits.txt`
- [ ] `wc -l << fruits.txt`
- [ ] `wc -l | fruits.txt`
:::why
`<` は `0<`（0 番 = 標準入力）の省略です。

- `> fruits.txt` は、`fruits.txt` を空にしてそこへ書きます（中身が消える）
- `<< fruits.txt` はヒアドキュメントで、`fruits.txt` だけの行が打たれるまで端末から読みます
- `| fruits.txt` は、`fruits.txt` をコマンドとして実行しようとします（[リダイレクト](#redirect)）
:::

### 1.03.4 正規表現を使用したテキストファイルの検索

:::q 1.03.4-01 single
`+` や `|` をそのまま書く拡張正規表現で検索したい。正しいコマンドはどれか。
- [ ] `grep -F`
- [x] `grep -E`
- [ ] `grep -x`
- [ ] `fgrep`
:::why
`grep -E`（`egrep` と同じ）は拡張正規表現（ERE）を使います。`grep -F` と `fgrep` は正規表現として解釈しない固定の文字列、`grep -x` は行全体が合うものだけを選ぶオプションです（[grep、egrep、fgrep](#grep-sed)）。
:::
:::

:::q 1.03.4-02 single
`grep -c error app.log` の出力の説明として正しいものはどれか。
- [ ] `error` を含む行に、行番号を付けて表示する
- [x] `error` を含む行の数を表示する
- [ ] `error` が出てくる回数（1 行に 2 回あれば 2 と数える）を表示する
- [ ] `error` を含む行がある、ファイルの名前を表示する
:::why
`-c` は合った**行の数**です。1 行に 2 回あっても 1 行と数えます。行番号を付けるのは `-n`、ファイル名だけは `-l` です（[grep、egrep、fgrep](#grep-sed)）。
:::
:::

:::q 1.03.4-03 single
次のコマンドの目的として正しいものはどれか。

```text
$ grep -v '^#' /etc/ssh/sshd_config | grep -v '^$'
```
- [ ] `#` を含む行と、`$` を含む行だけを表示する
- [x] `#` で始まるコメント行と空行を除いて表示する
- [ ] `#` で始まる行だけを表示する
- [ ] すべての `#` と `$` の文字を消して表示する
:::why
`^#` は「`#` で始まる行」、`^$` は「行頭のすぐ後が行末＝空行」です。`-v` で合わない行を残すので、コメント行と空行を除いた設定の中身だけが出ます。文字を消すのは `tr -d` や `sed` の仕事で、`grep` は行を選ぶだけです（[正規表現](#regex)）。
:::
:::

:::q 1.03.4-04 multi
`color` と `colour` の両方を含む行を選びたい。正しいものを 2 つ選択してください（GNU grep を使う）。
- [x] `grep -E 'colou?r' file`
- [x] `grep 'colou\?r' file`
- [ ] `grep 'colou?r' file`
- [ ] `grep -F 'colou?r' file`
- [ ] `grep 'colo.r' file`
:::why
「`u` が 0 回か 1 回」は、ERE では `?`、GNU の BRE では `\?` です。

- BRE の `grep 'colou?r'` では `?` はただの文字なので、`colou?r` という文字列を探します
- `grep -F` は固定の文字列なので、同じく `colou?r` を探します
- `colo.r` は `colo` と `r` の間にちょうど 1 文字を要求するので、`colour` には合いますが `color` には合いません（[正規表現](#regex)）
:::
:::

:::q 1.03.4-05 fill
`fruits.txt` の各行にある `apple` を、1 行に何回あっても全部 `APPLE` に置き換えて表示したい。空欄に入るものを入力してください。

```text
sed '____' fruits.txt
```
= s/apple/APPLE/g
= s|apple|APPLE|g
= s#apple#APPLE#g
= s:apple:APPLE:g
:::why
`s/古い/新しい/` は各行の最初の 1 つだけを置き換えます。行の中の全部を置き換えるには、末尾に `g` を付けます（[sed](#grep-sed)）。区切りの `/` は、`|` や `#` など別の文字にもできます。
:::
:::

:::q 1.03.4-06 single
`sed -n '3,5p' file` の動きとして正しいものはどれか。
- [x] 3〜5 行目だけを表示する
- [ ] 3〜5 行目を除いて表示する
- [ ] 全部の行を表示し、3〜5 行目はもう 1 回表示する
- [ ] 3 行目と 5 行目だけを表示する
:::why
`-n` で自動の出力を止め、`3,5p` で 3〜5 行目だけを表示します。`-n` がなければ全部の行が出て、3〜5 行目は 2 回出ます。3〜5 行目を除くのは `sed '3,5d'` です。`3,5` は範囲で、「3 と 5」ではありません（[sed](#grep-sed)）。
:::
:::

:::q 1.03.4-07 single
`sed '/^$/d' memo.txt` の動きとして正しいものはどれか。
- [ ] `$` を含む行を消して表示する
- [x] 空行を消して表示する
- [ ] 空行だけを表示する
- [ ] `memo.txt` から空行を消して、ファイルを書き換える
:::why
`/^$/` は空行に合うアドレス、`d` はその行を出力しない命令です。`$` そのものを探すなら `\$` と書きます。空行だけを表示するのは `sed -n '/^$/p'`。`-i` を付けていないので、ファイルは書き換わりません（[sed](#grep-sed)）。
:::
:::

:::q 1.03.4-08 single
`/etc` の下のファイルのうち、`localhost` を含むファイルの**名前だけ**を一覧にしたい。正しいものはどれか。
- [ ] `grep -c localhost /etc/*`
- [x] `grep -l localhost /etc/*`
- [ ] `grep -n localhost /etc/*`
- [ ] `grep -w localhost /etc/*`
:::why
`-l` は、合った行があるファイルの名前だけを出します。`-c` はファイルごとの行数、`-n` は行番号つきの行、`-w` は単語として合う行を出します（[grep、egrep、fgrep](#grep-sed)）。
:::
:::

:::q 1.03.4-09 multi
`fgrep` の説明として正しいものを 2 つ選択してください。
- [x] `grep -F` と同じ動きをする
- [x] パターンの中の `.` や `*` を、ただの文字として探す
- [ ] 拡張正規表現を使う
- [ ] 大文字と小文字を区別せずに探す
- [ ] ディレクトリの中を再帰的に探す
:::why
`fgrep` は `grep -F`（固定の文字列）と同じです。正規表現を使わないので、`.` や `*` もそのままの文字として探します。拡張正規表現は `egrep`（`grep -E`）、大文字と小文字を区別しないのは `-i`、再帰的に探すのは `-r` です（[grep、egrep、fgrep](#grep-sed)）。
:::
:::

:::q 1.03.4-10 fill
`sed` で、結果を標準出力に出すのではなく、元のファイルを直接書き換えたい。使うオプションを入力してください。
= -i
= --in-place
:::why
`sed -i` はファイルを直接書き換えます。`-i.bak` のように拡張子を付けると、元のファイルを `ファイル.bak` として残します。`-i` がなければ、`sed` は結果を標準出力に出すだけです（[sed](#grep-sed)）。
:::
:::

### 1.03.5 エディタを使った基本的なファイル編集の実行

:::q 1.03.5-01 single
`vi file.txt` で起動した直後のモードはどれか。
- [x] コマンドモード
- [ ] 挿入モード
- [ ] 置換モード
- [ ] ビジュアルモード
:::why
vi は**コマンドモード**（ノーマルモード）で起動します。このとき文字のキーは命令になります。文字を入れるには `i` などで挿入モードに入り、ESC で戻ります（[vi](#vi)）。
:::
:::

:::q 1.03.5-02 single
vi で編集した内容を保存せずに、vi を終わりたい。正しいものはどれか。
- [ ] `:wq`
- [ ] `ZZ`
- [x] `:q!`
- [ ] `:w!`
:::why
`:q!` は変更を捨てて終わります。`:wq` と `ZZ` は保存して終わり、`:w!` は強制的に保存するだけで終わりません。`!` なしの `:q` は、変更があると警告して終わりません（[保存と終了](#vi)）。
:::
:::

:::q 1.03.5-03 single
vi のコマンド `:e!` の動きとして正しいものはどれか。
- [ ] 保存して終わる
- [ ] 変更を捨てて vi を終わる
- [x] 変更を捨てて、ファイルを最後に保存した状態から読み直す
- [ ] 読み取り専用のファイルに強制的に保存する
:::why
`:e!` は、いまの変更を捨ててファイルを開き直します。vi は終わらないので、そのまま編集を続けられます。保存して終わるのは `:wq` や `ZZ`、捨てて終わるのは `:q!`、強制的に保存するのは `:w!` です（[保存と終了](#vi)）。
:::
:::

:::q 1.03.5-04 multi
vi で、編集した内容を保存して終わるものを 2 つ選択してください。
- [x] `:wq`
- [x] `ZZ`
- [ ] `:q!`
- [ ] `:e!`
- [ ] `:w!`
:::why
`:wq` と `ZZ`（コマンドモードで大文字の Z を 2 回）は、どちらも保存して終わります（`:x` も同じ）。`:q!` は保存せずに終わり、`:e!` は変更を捨てて読み直し、`:w!` は保存するだけで終わりません（[保存と終了](#vi)）。
:::
:::

:::q 1.03.5-05 single
vi のコマンドモードで、カーソルのある行の**下**に新しい行を作り、挿入モードに入るキーはどれか。
- [ ] `O`
- [x] `o`
- [ ] `a`
- [ ] `A`
:::why
`o` は下に、`O`（大文字）は上に新しい行を作って挿入モードに入ります。`a` はカーソルの後から、`A` は行の末尾から入力を始めます（[挿入モードに入る](#vi)）。
:::
:::

:::q 1.03.5-06 single
次の 3 行のファイルを vi で開き、カーソルが 1 行目にある状態で `ddp` と打った。結果として正しいものはどれか。

```text
one
two
three
```
- [ ] `two`、`three` の 2 行
- [x] `two`、`one`、`three` の 3 行
- [ ] `one`、`one`、`two`、`three` の 4 行
- [ ] `one`、`two`、`three` のまま変わらない
:::why
`dd` で 1 行目の `one` を消すと、カーソルは `two` の行に移ります。`p` は消した行をカーソルの行の**下**に貼るので、`two` の下に `one` が入り、1 行目と 2 行目が入れ替わります。`dd` だけなら 2 行、`yyp` なら `one` が 2 つになります（[削除、コピー、貼り付け、変更](#vi)）。
:::
:::

:::q 1.03.5-07 single
vi で `/error` と打って下向きに検索した。続けて、**上向き**に前の `error` を探すキーはどれか。
- [ ] `n`
- [x] `N`
- [ ] `p`
- [ ] `u`
:::why
`n` は最後の検索と同じ向き（ここでは下）、`N` は逆の向き（ここでは上）に次を探します。`p` は貼り付け、`u` は取り消しです（[検索](#vi)）。
:::
:::

:::q 1.03.5-08 multi
vi のコマンドモードのキーと働きの組み合わせとして正しいものを 2 つ選択してください。
- [x] `x`：カーソルの 1 文字を消す
- [x] `dw`：カーソルから単語の終わりまでを消す
- [ ] `yy`：1 行を消す
- [ ] `cw`：単語をコピーする
- [ ] `P`：カーソルの後ろに貼り付ける
:::why
`x` は 1 文字、`dw` は単語の終わりまでを消します。

- `yy` は 1 行を**コピー**します（消すのは `dd`）
- `cw` は単語を消して挿入モードに入る**書き換え**です（コピーは `yw`）
- `P` はカーソルの**前**（行なら上）に貼ります。後ろは `p` です（[削除、コピー、貼り付け、変更](#vi)）
:::
:::

:::q 1.03.5-09 fill
vi のコマンドモードで、カーソルのある行から 3 行をコピー（ヤンク）したい。打つキーを入力してください。
= 3yy
= 3Y
= y2j
:::why
`yy` が 1 行のコピーで、前に数を付けると、その行数をコピーします。貼り付けは `p`（下）か `P`（上）です。消すなら `3dd` です（[削除、コピー、貼り付け、変更](#vi)）。
:::
:::

:::q 1.03.5-10 fill
`crontab -e` などが起動するエディタを nano にしたい。空欄に入る環境変数の名前を入力してください。

```text
export ____=nano
```
= EDITOR
= VISUAL
:::why
`crontab -e` や `git commit` などは、環境変数 `EDITOR`（または `VISUAL`）に書かれたエディタを起動します。いつもそうしたいなら、`~/.bashrc` などに書いておきます（[vi 以外のエディタと EDITOR](#editors)）。
:::
:::
