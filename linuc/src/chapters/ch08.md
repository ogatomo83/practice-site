図解 Linux では、ユーザーとグループの**仕組み**（uid と gid、`/etc/passwd`、`id`）を学びました。この章では、それを**作って管理するコマンド**を足します。cron とロケールは、ほぼ新しく学ぶ範囲です。

小さな Linux には `useradd` や `crontab` がありません。そこで、ファイルを読む・`passwd` を試すところは小さな Linux で動かし、ほかは Debian 12 と Rocky Linux 9（Red Hat 系）で実際に動かした結果を載せます。

## アカウントの情報は、どの 3 つのファイルにあるか {#account-files}

ユーザーとグループの情報は、`/etc` の下のテキストファイルにあります。試験に出るのは次の 4 つです。

| ファイル | 中身 | 1 行の欄の数 | だれが読めるか |
| --- | --- | --- | --- |
| `/etc/passwd` | ユーザーの一覧 | 7 | だれでも |
| `/etc/shadow` | パスワードのハッシュと期限 | 9 | root（と shadow グループ）だけ |
| `/etc/group` | グループの一覧 | 4 | だれでも |
| `/etc/gshadow` | グループのパスワード | 4 | root（と shadow グループ）だけ |

まず小さな Linux で、ファイルの権限を見ます。

```sh run title="3 つのファイルの権限"
ls -l /etc/passwd /etc/shadow /etc/group
```

`/etc/passwd` と `/etc/group` は、だれでも読めます（`r--` が「その他」にもある）。`ls -l` が uid を名前に直すために、どのユーザーも読む必要があるからです。パスワードのハッシュだけを `/etc/shadow` に分けて、root しか読めないようにしてあります。

### /etc/passwd の 7 つの欄（復習）

```sh run title="ユーザーの一覧"
cat /etc/passwd
```

欄は `ユーザー名:x:uid:gid:説明:ホーム:シェル` の 7 つです（[図解 Linux 4.1](../../linux/site/ch04.html#users)）。2 番目の `x` は「パスワードは /etc/shadow にある」という印です。4 番目は**主グループ**の gid、5 番目は説明（GECOS 欄。本名などを書く）です。

`:` 区切りなので、`cut` や `awk` で欄を取り出せます。uid が 1000 以上の人について、名前とホームとシェルを出します。

```sh run title="欄を取り出す"
awk -F: '$3 >= 1000 {print $1, $6, $7}' /etc/passwd
```

`nobody`（65534）も出ました。uid が 1000 以上でも、人ではないユーザーもいます。

### /etc/shadow の 9 つの欄

```fig layout /etc/shadow の 1 行。日付はどれも「1970 年 1 月 1 日からの日数」で書く
{
  unit: 12,
  rows: [
    { label: '値', cells: [{ t: 'ken', w: 4, kind: 'accent' }, { t: '$6$…', w: 5, kind: 'stack' }, { t: '20773', w: 5, kind: 'heap' }, { t: '0', w: 3, kind: 'static' }, { t: '99999', w: 5, kind: 'static' }, { t: '7', w: 3, kind: 'static' }, { t: '', w: 3, kind: 'plain' }, { t: '20908', w: 5, kind: 'heap' }, { t: '', w: 3, kind: 'plain' }] },
    { label: '欄', cells: [{ t: '1 名前', w: 4, kind: 'accent' }, { t: '2 ハッシュ', w: 5, kind: 'stack' }, { t: '3 最終変更', w: 5, kind: 'heap' }, { t: '4 最短', w: 3, kind: 'static' }, { t: '5 最長', w: 5, kind: 'static' }, { t: '6 警告', w: 3, kind: 'static' }, { t: '7 猶予', w: 3, kind: 'plain' }, { t: '8 失効日', w: 5, kind: 'heap' }, { t: '9 予約', w: 3, kind: 'plain' }] },
  ],
}
```

| 欄 | 意味 | 値の例と読み方 |
| --- | --- | --- |
| 1 | ユーザー名 | `ken` |
| 2 | パスワードのハッシュ | `$6$…`。先頭が `!` ならロック中。`*` や `!!` はログインに使えるパスワードがない。空ならパスワードなし |
| 3 | 最後にパスワードを変えた日 | 1970-01-01 からの日数。`20773` は 2026-11-16。**`0` は「次のログインで変更させる」** |
| 4 | 最短日数 | 変えてから、次に変えられるまでの日数。`0` ならいつでも変えられる |
| 5 | 最長日数 | この日数がたつと、変えなければならない。`99999` は事実上無期限 |
| 6 | 警告の日数 | 期限の何日前から警告するか |
| 7 | 猶予の日数 | 期限が切れてから、何日でアカウントを使えなくするか |
| 8 | アカウントの失効日 | 1970-01-01 からの日数。この日にアカウントが使えなくなる |
| 9 | 予約 | 使わない |

ハッシュの先頭の `$数字$` は、ハッシュの方式を表します。`$1$` は MD5、`$5$` は SHA-256、`$6$` は SHA-512、`$y$` は yescrypt です。Rocky Linux 9 は `$6$`、Debian 12 は `$y$` を使います。

```sh run title="root なら読める"
sudo cat /etc/shadow
```

```sh run error title="ふつうのユーザーは読めない"
cat /etc/shadow
```

`root` の 2 番目の欄は `*` なので、root にはパスワードでログインできません。この Linux では `sudo` を使います。

### /etc/group と /etc/gshadow

```sh run title="グループの一覧と、そのメンバー"
cut -d: -f1,3,4 /etc/group
```

`/etc/group` は `グループ名:x:gid:メンバー` の 4 つの欄です。4 番目のメンバーは、そのグループを**補助グループ**（主グループのほかに入っているグループ）にしているユーザーです。主グループは `/etc/passwd` の 4 番目で決まるので、ここには書きません。2 番目の `x` は「グループのパスワードは /etc/gshadow にある」という印です。

### getent と id：情報を引く

ユーザーの情報は、`/etc/passwd` のほかに、LDAP などのネットワークのデータベースに置くこともできます。どこを見るかは `/etc/nsswitch.conf` で決まります。`getent` は、その設定に従って項目を引くコマンドです。

```sh run title="getent でユーザーとグループを引く"
getent passwd you
getent passwd 1001
getent group staff
```

`getent データベース名 キー` の形です。データベース名は `passwd`、`group`、`hosts` などで、キーは名前でも番号でもかまいません。キーを省くと全部を出します。本物の Linux では、root なら `getent shadow ユーザー名` で `/etc/shadow` の行も引けます。

```sh run title="id の主なオプション"
id alice
id -u alice
id -g alice
id -Gn alice
```

| コマンド | 出すもの |
| --- | --- |
| `id [ユーザー]` | uid、主グループの gid、所属するすべてのグループ |
| `id -u` | uid だけ |
| `id -g` | 主グループの gid だけ |
| `id -G` | 所属するすべてのグループの gid |
| `id -n` | （`-u`、`-g`、`-G` と組み合わせて）番号の代わりに名前 |
| `groups [ユーザー]` | 所属するグループの名前 |

## useradd：ユーザーを作ると何が起きるか {#useradd}

```fig graph useradd は 3 か所から既定値を読み、4 つのファイルとホームディレクトリを作る
{

    { id: 'ua', label: 'useradd', sub: 'オプションが既定値より優先', x: 1, y: 1, kind: 'accent' },
    { id: 'files', label: '/etc/passwd /etc/shadow\n/etc/group /etc/gshadow', sub: '1 行ずつ足す', x: 2, y: 0.5, kind: 'stack' },
    { id: 'home', label: '/home/ken/', sub: '-m のとき作り、skel を写す', x: 2, y: 1.7, kind: 'crate' },
  ],
  edges: [
    { from: 'def', to: 'ua' }, { from: 'login', to: 'ua' }, { from: 'skel', to: 'home', style: 'dashed', label: 'コピー' },

```

`useradd ユーザー名` は、root が実行するユーザーを作るコマンドです。オプションで指定しなかったことは、既定値で埋めます。既定値は 2 つのファイルにあります。

- `/etc/default/useradd`：`useradd` だけが読む既定値（ログインシェル、ホームの親ディレクトリ、スケルトンなど）
- `/etc/login.defs`：ユーザー管理のコマンドが共通に読む値（uid の範囲 `UID_MIN`、パスワードの期限 `PASS_MAX_DAYS`、ハッシュの方式 `ENCRYPT_METHOD`、ホームを作るかどうか `CREATE_HOME` など）

### useradd のオプション

| オプション | 意味 |
| --- | --- |
| `-m` | ホームディレクトリを作り、`/etc/skel` の中身をコピーする |
| `-M` | ホームディレクトリを作らない |
| `-d ディレクトリ` | ホームディレクトリの場所（`-m` がなければ、`/etc/passwd` に書くだけで作らない） |
| `-s シェル` | ログインシェル |
| `-g グループ` | 主グループ（1 つ） |
| `-G グループ,グループ…` | 補助グループ（カンマ区切りで複数） |
| `-u uid` | uid を指定する |
| `-c "説明"` | 説明の欄（GECOS 欄。本名など） |
| `-e 日付` | アカウントの失効日（`YYYY-MM-DD`）。`/etc/shadow` の 8 番目の欄に入る |
| `-k ディレクトリ` | `/etc/skel` の代わりに使うひな形（`-m` と一緒に使う） |
| `-r` | システムアカウント（デーモン用。uid を小さい範囲から取る） |
| `-D` | 既定値を表示する。ほかのオプションと組み合わせると、既定値を変える |

Debian 12 で、オプションを付けて作ってみた結果です。

```console
# useradd -m -s /bin/bash -c "Hanako Yamada" -u 1500 hanako
# grep hanako /etc/passwd /etc/shadow
/etc/passwd:hanako:x:1500:1500:Hanako Yamada:/home/hanako:/bin/bash
/etc/shadow:hanako:!:20773:0:99999:7:::
# ls -a /home/hanako
.  ..  .bash_logout  .bashrc  .profile
```

`/etc/skel` にあった `.bashrc` などが、ホームにコピーされました。`/etc/shadow` の 2 番目は `!` で、まだパスワードがない（ログインできない）状態です。`passwd hanako` でパスワードを決めると使えるようになります。

主グループを指定しなかったので、ユーザーと同じ名前のグループ `hanako`（gid 1500）が作られました。これは `/etc/login.defs` の `USERGROUPS_ENAB yes` による動きで、Debian も Red Hat 系も同じです。

```console
# groupadd -g 2000 dev
# groupadd ops
# useradd -m -d /srv/jiro -g dev -G ops,users -e 2027-03-31 jiro
# grep jiro /etc/passwd /etc/shadow
/etc/passwd:jiro:x:1501:2000::/srv/jiro:/bin/sh
/etc/shadow:jiro:!:20773:0:99999:7::20908:
# id jiro
uid=1501(jiro) gid=2000(dev) groups=2000(dev),100(users),2001(ops)
```

`-g dev` で主グループが dev になり、`-G ops,users` で補助グループが 2 つ付きました。`-e` の日付は、`/etc/shadow` の 8 番目に日数（20908）で入っています。

:::warn 試験の注意：-g と -G、-d と -m
- 小文字の `-g` は**主グループ（1 つ）**、大文字の `-G` は**補助グループ（カンマで複数）**。`usermod` でも同じ
- `-d` はホームの**場所を決めるだけ**。ディレクトリを作るのは `-m`
- `-D` は「既定値（Default）」。`-d`（directory）と取り違えない
:::

### 既定値は Debian と Red Hat 系で違う

`useradd -D` で既定値を見ます。左が Debian 12、右が Rocky Linux 9 です。

:::cols
:::col Debian 12
```console
# useradd -D
GROUP=100
HOME=/home
INACTIVE=-1
EXPIRE=
SHELL=/bin/sh
SKEL=/etc/skel
CREATE_MAIL_SPOOL=no
LOG_INIT=yes
```
:::
:::col Rocky Linux 9
```console
# useradd -D
GROUP=100
HOME=/home
INACTIVE=-1
EXPIRE=
SHELL=/bin/bash
SKEL=/etc/skel
CREATE_MAIL_SPOOL=yes
```
:::
:::

同じ `useradd taro` を、オプションなしで実行して比べました。

| | Debian 12 | Rocky Linux 9 |
| --- | --- | --- |
| ホームディレクトリ | **作られない**（`-m` が必要） | 作られる（`/etc/login.defs` に `CREATE_HOME yes`）。権限は `drwx------` |
| ログインシェル | `/bin/sh` | `/bin/bash` |
| `/etc/shadow` の 2 番目 | `!` | `!!` |
| `/etc/skel` の中身 | `.bash_logout`、`.bashrc`、`.profile` | `.bash_logout`、`.bash_profile`、`.bashrc` |

Debian 系には、対話的にユーザーを作る `adduser` という別のコマンドもあります。こちらはホームを作り、パスワードもたずねます。試験で「useradd」と書いてあれば、上の動きです。

既定値を変えるには、`useradd -D` にオプションを付けます。変えた値は `/etc/default/useradd` に書き込まれます。

```console
# useradd -D -s /bin/zsh
# grep SHELL /etc/default/useradd
SHELL=/bin/zsh
```

| `useradd -D` と組む | 変える既定値 |
| --- | --- |
| `-s シェル` | ログインシェル（SHELL） |
| `-b ディレクトリ` | ホームの親ディレクトリ（HOME） |
| `-g グループ` | 主グループ（GROUP。ユーザーと同じ名前のグループを作らないとき） |
| `-e 日付` | 失効日（EXPIRE） |
| `-f 日数` | 猶予の日数（INACTIVE） |

`/etc/skel` に置いたものは、次から作るユーザーに配られます。`/etc/skel` に、たとえば共通の `.bashrc` や `.vimrc` を置いておくと、そのあと `-m` で作るユーザー全員のホームにコピーされます。すでにいるユーザーには配られません。

## usermod・userdel・グループのコマンド {#usermod}

作ったユーザーを変えるのが `usermod`、消すのが `userdel` です。オプションの多くは `useradd` と同じ文字です。

| オプション | usermod での意味 |
| --- | --- |
| `-G グループ,…` | 補助グループを、**指定したものだけに置き換える** |
| `-a -G グループ`（`-aG`） | 補助グループに**足す**（今のものを残す） |
| `-g グループ` | 主グループを変える |
| `-l 新しい名前` | ログイン名を変える（`usermod -l 新 旧`）。ホームの名前は変わらない |
| `-d ディレクトリ` | ホームの場所を変える。`-m` を足すと中身も移す |
| `-s シェル` | ログインシェルを変える |
| `-c "説明"` | 説明の欄を変える |
| `-u uid` | uid を変える |
| `-e 日付` | アカウントの失効日を変える |
| `-L` | パスワードをロックする（ハッシュの先頭に `!` を付ける） |
| `-U` | ロックを外す（`!` を取る） |

### -G と -aG の違い

```fig layout hanako の補助グループ。-G は置き換え、-aG は足す
{
  unit: 12,
  rows: [
    { label: '最初', cells: [{ t: 'hanako', w: 6, kind: 'accent' }, { t: 'dev', w: 4, kind: 'stack' }], note: '主 + 補助 dev' },
    { label: '-aG ops', cells: [{ t: 'hanako', w: 6, kind: 'accent' }, { t: 'dev', w: 4, kind: 'stack' }, { t: 'ops', w: 4, kind: 'heap' }], note: 'dev が残る' },
    { label: '-G ops', cells: [{ t: 'hanako', w: 6, kind: 'accent' }, { t: 'ops', w: 4, kind: 'heap' }], note: 'dev が消える' },
  ],
}
```

Debian 12 で確かめた結果です。

```console
# usermod -G dev hanako
# id hanako
uid=1500(hanako) gid=1500(hanako) groups=1500(hanako),2000(dev)
# usermod -aG ops hanako
# id hanako
uid=1500(hanako) gid=1500(hanako) groups=1500(hanako),2000(dev),2001(ops)
# usermod -G ops hanako
# id hanako
uid=1500(hanako) gid=1500(hanako) groups=1500(hanako),2001(ops)
```

最後の `-G ops` で、dev から外れてしまいました。主グループ（hanako）は `-G` では変わりません。

:::warn 試験の注意：-a を忘れると、ほかのグループから外れる
「今の所属を残したまま docker グループに入れる」は `usermod -aG docker ユーザー` です。`-a` だけでは意味がなく、必ず `-G` と組みます。`-a` を忘れると、補助グループが docker だけになります。
:::

### 名前、シェル、ロック

```console
# usermod -l jiro2 jiro
# usermod -s /usr/sbin/nologin jiro2
# grep jiro2 /etc/passwd
jiro2:x:1501:2000::/srv/jiro:/usr/sbin/nologin
```

`-l` は「新しい名前、古い名前」の順です。uid とホーム（`/srv/jiro`）はそのままです。シェルを `/usr/sbin/nologin` にすると、そのユーザーではログインできなくなります（メッセージを出してすぐ終わるプログラムです）。

`usermod -L` はハッシュの先頭に `!` を付けて、パスワードを合わなくします。`-U` で外します。ただし Debian では、まだパスワードを決めていないユーザー（`!` だけ）の `-U` は「パスワードなしのアカウントになる」として断られました。

### userdel

| コマンド | すること |
| --- | --- |
| `userdel ユーザー` | `/etc/passwd`、`/etc/shadow`、`/etc/group` などからユーザーを消す。**ホームは残る** |
| `userdel -r ユーザー` | ホームディレクトリとメールスプールも消す |
| `userdel -f ユーザー` | ログイン中でも強制的に消す |

### グループのコマンド

| コマンド | すること |
| --- | --- |
| `groupadd [-g gid] グループ` | グループを作る。`-g` がなければ空いている gid を使う |
| `groupmod -n 新しい名前 グループ` | グループの名前を変える |
| `groupmod -g 新しい gid グループ` | gid を変える |
| `groupdel グループ` | グループを消す |

```console
# groupmod -n devel dev
# groupmod -g 2100 devel
# grep devel /etc/group
devel:x:2100:
# groupdel hanako
groupdel: cannot remove the primary group of user 'hanako'
```

`groupmod -n` も「新しい名前、古い名前」の順です。gid を変えると、そのグループを主グループにしていたユーザーの `/etc/passwd` の 4 番目も新しい gid になります。**だれかの主グループになっているグループは、`groupdel` で消せません。**先にユーザーを消すか、主グループを変えます。

:::warn 試験の注意：-l と -n、「新しい名前」が先
ユーザー名を変えるのは `usermod -l`（login）、グループ名を変えるのは `groupmod -n`（name）です。どちらも `新しい名前 古い名前` の順に書きます。`groupmod -g` の後ろは名前ではなく数字（gid）です。
:::

## passwd：パスワードとその期限 {#passwd}

`passwd` は、ふつうのユーザーが自分のパスワードを変えるコマンドです（setuid で root として動く仕組みは[図解 Linux 4.9](../../linux/site/ch04.html#special)）。root はオプションで、ほかのユーザーのロックや期限も操作できます。

| オプション | すること（root だけ） | /etc/shadow の変化 |
| --- | --- | --- |
| `passwd ユーザー` | そのユーザーのパスワードを変える | 2 番目と 3 番目 |
| `-l` | ロックする | 2 番目の先頭に `!` |
| `-u` | ロックを外す | `!` を取る |
| `-d` | パスワードを消す（空にする） | 2 番目が空 |
| `-e` | 期限切れにして、次のログインで変更させる | 3 番目が `0` |
| `-S` | 状態を表示する | 変わらない |
| `-n 日数` | 最短日数 | 4 番目 |
| `-x 日数` | 最長日数 | 5 番目 |
| `-w 日数` | 警告の日数 | 6 番目 |
| `-i 日数` | 猶予の日数 | 7 番目 |

小さな Linux で、alice をロックして外します。

```sh run title="ロックすると ! が付く"
sudo passwd -l alice
sudo passwd -S alice
sudo grep '^alice:' /etc/shadow
```

`passwd -S` の 2 番目の `L` はロック中（Locked）、`P` は使えるパスワードがある（Password）、`NP` はパスワードがない（No Password）です。`/etc/shadow` のハッシュの前に `!` が付きました。ハッシュ自体は残っているので、外せば元のパスワードで入れます。

```sh run title="ロックを外す"
sudo passwd -u alice
sudo passwd -S alice
```

期限の 4 つのオプションをまとめて付けた結果です（Debian 12）。

```console
# passwd -n 1 -x 90 -w 14 -i 30 hanako
passwd: password changed.
# grep hanako /etc/shadow
hanako:$y$j9T$…:20773:1:90:14:30::
# passwd -e hanako
passwd: password changed.
# grep hanako /etc/shadow
hanako:$y$j9T$…:0:1:90:14:30::
```

`-e` で 3 番目が `0` になりました。hanako は次のログインで、新しいパスワードを決めさせられます。期限をもっと細かく扱う `chage` は、1.10（セキュリティ）で扱います。

:::note Red Hat 系の passwd は表示が違う
Rocky Linux 9 の `passwd` は別の実装で、`-S` が `hanako LK 2026-11-16 0 99999 7 -1 (Password locked.)` のように 2 文字で答えます（`LK` ロック、`PS` パスワードあり、`NP` なし）。`passwd -l` が付けるのは `!!`、`usermod -L` が付けるのは `!` でした。root がパスワードを標準入力から渡す `--stdin` も Red Hat 系だけのオプションです。
:::

## cron：決まった時刻に繰り返す {#cron}

**cron**（クーロン）は、決まった時刻にコマンドを繰り返し実行する仕組みです。デーモンの `crond`（Debian では `cron`）が毎分起きて、予定の表（**crontab**）を見ます。

```fig layout crontab の 1 行。5 つの時刻の欄のあとに、実行するコマンド
{
  unit: 13,
  rows: [
    { label: '書き方', cells: [{ t: '30', w: 3, kind: 'accent' }, { t: '9', w: 3, kind: 'accent' }, { t: '*', w: 3, kind: 'stack' }, { t: '*', w: 3, kind: 'stack' }, { t: '1-5', w: 4, kind: 'heap' }, { t: '/home/ken/report.sh', w: 14, kind: 'plain' }] },
    { label: '欄', cells: [{ t: '分', w: 3, kind: 'accent' }, { t: '時', w: 3, kind: 'accent' }, { t: '日', w: 3, kind: 'stack' }, { t: '月', w: 3, kind: 'stack' }, { t: '曜日', w: 4, kind: 'heap' }, { t: 'コマンド', w: 14, kind: 'plain' }], note: '月〜金の 9:30' },
  ],
}
```

| 欄 | 範囲 |
| --- | --- |
| 1 分 | 0〜59 |
| 2 時 | 0〜23 |
| 3 日 | 1〜31 |
| 4 月 | 1〜12（`jan`、`feb` … でもよい） |
| 5 曜日 | 0〜7。**0 と 7 が日曜**、1 が月曜 … 6 が土曜（`sun`、`mon` … でもよい） |

| 書き方 | 意味 | 例 |
| --- | --- | --- |
| `*` | すべて | 時の欄が `*` なら毎時 |
| `a-b` | 範囲 | 曜日の `1-5` は月〜金 |
| `a,b,c` | 並べる | 日の `1,15` は 1 日と 15 日 |
| `*/n` | n ごと | 分の `*/5` は 0, 5, 10 … 55 分 |
| `a-b/n` | 範囲の中で n ごと | 時の `9-17/2` は 9, 11, 13, 15, 17 時 |

`*/5` が何分に当たるかは、0 から 5 ずつ数えたものです。

```sh run title="*/5 の分"
seq 0 5 59 | paste -s -d ' '
```

曜日の番号は、`date` の `%w` と同じです（0 が日曜）。

```sh run title="2026-11-15 は何曜日で何番か"
date -d 2026-11-15 +%A
date -d 2026-11-15 +%w
```

自分で crontab の形の行を書き、`awk` で欄に分けて確かめます。

```sh run title="crontab の欄を読む"
cat > mycron <<'EOF'
30 9 * * 1-5 /home/you/bin/report.sh
*/10 * * * * /home/you/bin/check.sh
0 3 1,15 * * /home/you/bin/backup.sh
EOF
awk '{print "分=" $1, "時=" $2, "日=" $3, "月=" $4, "曜日=" $5, "→ " $6}' mycron
```

| crontab の行 | いつ |
| --- | --- |
| `30 9 * * 1-5` | 月〜金の 9:30 |
| `*/10 * * * *` | 10 分ごと |
| `0 3 1,15 * *` | 毎月 1 日と 15 日の 3:00 |
| `0 */2 * * *` | 2 時間ごとの 0 分（0:00、2:00 …） |
| `0 0 1 1 *` | 1 月 1 日の 0:00 |
| `0 3 * * 0` | 毎週日曜の 3:00（`7` や `sun` でも同じ） |

:::warn 試験の注意：分の欄を * にしない
`* 9 * * 1` は「月曜の 9 時台の**毎分**」で、60 回動きます。「月曜の 9:00 に 1 回」は `0 9 * * 1` です。また、日の欄と曜日の欄の**両方**に `*` 以外を書くと、「どちらかに合えば」動きます（`0 0 1 * 1` は毎月 1 日と、毎週月曜）。
:::

### crontab コマンド

ユーザーごとの crontab は、`crontab` コマンドで扱います。ファイルを直接開いて書き換えてはいけません。

| コマンド | すること |
| --- | --- |
| `crontab -e` | 自分の crontab をエディタで編集する |
| `crontab -l` | 自分の crontab を表示する |
| `crontab -r` | 自分の crontab を**確認なしで**消す |
| `crontab -i -r` | 消す前に確認する |
| `crontab ファイル` | ファイルの中身で crontab を置き換える |
| `crontab -u ユーザー -e`（`-l`、`-r`） | ほかのユーザーの crontab を扱う（root だけ） |

Debian 12 で、nobody の crontab を作って、見て、消しました。

```console
# echo "*/5 * * * * /usr/bin/true" | crontab -u nobody -
# crontab -l -u nobody
*/5 * * * * /usr/bin/true
# ls -l /var/spool/cron/crontabs
-rw------- 1 nobody crontab 201 Nov 16 11:15 nobody
# crontab -r -u nobody
# crontab -l -u nobody
no crontab for nobody
```

保存される場所は、ディストリビューションで違います。

| | ユーザーの crontab の場所 |
| --- | --- |
| Red Hat 系（cronie） | `/var/spool/cron/ユーザー名` |
| Debian 系 | `/var/spool/cron/crontabs/ユーザー名` |

`crontab -r` は何も聞かずに消します。キーボードで `e` と `r` は隣り合っているので、打ちまちがえると予定がすべて消えます。`-l` で見てから操作し、不安なら `-i` を付けます。

ユーザーの crontab の行の先頭に、`@reboot`（起動したとき 1 回）、`@daily`（`0 0 * * *` と同じ）、`@hourly`、`@weekly`、`@monthly` といった略記を使うこともできます。

## システムの cron：/etc/crontab と cron.d と cron.daily {#system-cron}

### /etc/crontab と /etc/cron.d：ユーザー名の欄がある

Debian 12 の `/etc/crontab` です（コメントと空行を除く）。

```console
$ grep -Ev '^(#|$)' /etc/crontab
SHELL=/bin/sh
PATH=/usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin
17 *	* * *	root	cd / && run-parts --report /etc/cron.hourly
25 6	* * *	root	test -x /usr/sbin/anacron || { cd / && run-parts --report /etc/cron.daily; }
47 6	* * 7	root	test -x /usr/sbin/anacron || { cd / && run-parts --report /etc/cron.weekly; }
52 6	1 * *	root	test -x /usr/sbin/anacron || { cd / && run-parts --report /etc/cron.monthly; }
```

5 つの時刻の欄のあと、**6 番目がユーザー名**（ここでは `root`）です。システムの crontab は 1 つのファイルにいろいろなユーザーの予定を書くので、だれとして動かすかを書きます。ユーザーの crontab（`crontab -e`）には、この欄がありません。

`/etc/cron.d/` に置くファイルも、`/etc/crontab` と同じ形（ユーザー名の欄あり）です。パッケージが自分の予定を置くのに使います。Rocky Linux 9 の `/etc/cron.d/0hourly` は次の 1 行が中心です。

```console
$ grep -Ev '^(#|$)' /etc/cron.d/0hourly
SHELL=/bin/bash
PATH=/sbin:/bin:/usr/sbin:/usr/bin
MAILTO=root
01 * * * * root run-parts /etc/cron.hourly
```

`run-parts ディレクトリ` は、ディレクトリの中の実行できるファイルを、名前の順に全部実行するコマンドです。つまり `/etc/cron.hourly/` に実行権の付いたスクリプトを置けば、毎時実行されます。`cron.daily`、`cron.weekly`、`cron.monthly` も同じで、**時刻を書かずにスクリプトを置くだけ**で使えます。

| 場所 | 中身の形 | ユーザー名の欄 |
| --- | --- | --- |
| `crontab -e`（`/var/spool/cron/…`） | 5 欄 + コマンド | なし |
| `/etc/crontab` | 5 欄 + ユーザー + コマンド | あり |
| `/etc/cron.d/*` | 5 欄 + ユーザー + コマンド | あり |
| `/etc/cron.{hourly,daily,weekly,monthly}/` | スクリプトそのもの | — |

### anacron：止まっていた間の分を、あとで実行する

cron は「その時刻に動いていれば」実行します。毎日 3:00 の予定でも、ノート PC が夜は電源を切っていれば、一度も動きません。

**anacron** は、日単位の予定について「最後に実行してから何日たったか」を見ます。期間が過ぎていれば、起動したあとに実行します。最後に実行した日は `/var/spool/anacron/` に記録します。設定は `/etc/anacrontab` です（Rocky Linux 9）。

```console
$ grep -Ev '^(#|$)' /etc/anacrontab
SHELL=/bin/sh
PATH=/sbin:/bin:/usr/sbin:/usr/bin
MAILTO=root
RANDOM_DELAY=45
START_HOURS_RANGE=3-22
1	5	cron.daily		nice run-parts /etc/cron.daily
7	25	cron.weekly		nice run-parts /etc/cron.weekly
@monthly 45	cron.monthly		nice run-parts /etc/cron.monthly
```

| 欄 | 意味 | `7 25 cron.weekly …` の行 |
| --- | --- | --- |
| 1 | 期間（日数。`@monthly` も可） | 7 日ごと |
| 2 | 遅延（分）。anacron が動き始めてから待つ時間 | 25 分待ってから |
| 3 | ジョブの名前（記録のファイル名になる） | cron.weekly |
| 4 | コマンド | cron.weekly の中身を全部実行 |

Red Hat 系では、`/etc/cron.hourly/0anacron` が毎時 anacron を起こし、anacron が `cron.daily`・`weekly`・`monthly` を受け持ちます。Debian 系でも、anacron が入っていれば同じく anacron が受け持ちます（上の `/etc/crontab` の `test -x /usr/sbin/anacron ||` は「anacron がなければ cron が実行する」という意味です）。anacron の単位は日で、分や時は指定できません。

### cron.allow と cron.deny

```fig graph crontab を使えるかの決まり。cron.allow があれば、cron.deny は見ない

  nodes: [
    { id: 'q1', label: 'cron.allow がある？', x: 0, y: 0, kind: 'accent', mono: false },

    { id: 'q2', label: 'cron.deny がある？', x: 0, y: 1, kind: 'accent', mono: false },
    { id: 'd', label: '書いてある人は使えない', sub: 'ほかの人は使える', x: 1, y: 1, kind: 'stack', mono: false },
    { id: 'n', label: 'どちらもない', sub: 'cron は実装による。at は root だけ', x: 0, y: 2, kind: 'muted', mono: false },

  edges: [

    { from: 'q2', to: 'd', label: 'ある' }, { from: 'q2', to: 'n', label: 'ない' },
  ],
}
```

`/etc/cron.allow` と `/etc/cron.deny` は、`crontab` コマンドを使えるユーザーを決めます。1 行に 1 人ずつユーザー名を書きます。**cron.allow があれば、そちらだけが使われます。** Rocky Linux 9 で、alice を両方に書いて試しました。

```console
# echo alice > /etc/cron.allow
# echo alice > /etc/cron.deny
# su alice -c "crontab -l"
no crontab for alice
# su bob -c "crontab -l"
You (bob) are not allowed to use this program (crontab)
# rm /etc/cron.allow
# su alice -c "crontab -l"
You (alice) are not allowed to use this program (crontab)
```

cron.allow があるあいだは、cron.deny に書いてあっても alice は使え、cron.allow にいない bob は使えません。cron.allow を消すと cron.deny が効き、alice が使えなくなりました。

Rocky Linux 9 には最初から**空の** `/etc/cron.deny` があるので、だれでも使えます。どちらもないときの扱いは cron の実装と設定によって違います。

`at` にも同じ形の `/etc/at.allow` と `/etc/at.deny` があり、決まりも同じです。ただし **at はどちらもなければ root だけ**が使えます（Rocky Linux 9 で、両方を消すと一般ユーザーの `atq` が `You do not have permission to use atq.` になりました）。空の `at.deny` が置いてあるのは「全員に許す」という意味です。

:::warn 試験の注意：allow が先
「cron.allow と cron.deny の両方に同じユーザーが書いてある」→ cron.allow があるので、**使える**。「cron.allow が空のファイルで存在する」→ だれも書いていないので、root 以外は使えない。allow は「許す名簿」、deny は「断る名簿」と覚えます。
:::

## at と systemd タイマー：1 回だけ、または unit で {#at}

**at** は、指定した時刻に**1 回だけ**コマンドを実行します。デーモンの `atd` が動いている必要があります。コマンドは標準入力から読み、端末なら `Ctrl+D` で入力を終えます。

```console
# echo "date > /tmp/x" | at now + 5 minutes
warning: commands will be executed using /bin/sh
job 1 at Mon Nov 16 11:23:00 2026
# echo "echo" | at 17:00 tomorrow
job 2 at Tue Nov 17 17:00:00 2026
# echo "echo" | at noon
job 3 at Mon Nov 16 12:00:00 2026
# atq
1	Mon Nov 16 11:23:00 2026 a root
2	Tue Nov 17 17:00:00 2026 a root
3	Mon Nov 16 12:00:00 2026 a root
# atrm 2
# atq
1	Mon Nov 16 11:23:00 2026 a root
3	Mon Nov 16 12:00:00 2026 a root
```

`atq` の各行は、ジョブ番号、実行する日時、キュー（`a`）、ユーザーです。

| コマンド | すること |
| --- | --- |
| `at 時刻` | 時刻にコマンドを実行する予約をする |
| `at -f ファイル 時刻` | コマンドを標準入力ではなくファイルから読む |
| `atq`（`at -l`） | 予約の一覧 |
| `atrm 番号`（`at -d 番号`） | 予約を消す |
| `at -c 番号` | 予約の中身（実行されるシェルスクリプト）を表示する |
| `batch` | 時刻ではなく、システムの負荷が下がったときに実行する |

| 時刻の書き方 | 意味 |
| --- | --- |
| `now + 5 minutes` | 5 分後（`hours`、`days`、`weeks` も使える） |
| `17:00` | 次の 17:00（今日が過ぎていれば明日） |
| `17:00 tomorrow` | 明日の 17:00 |
| `noon`、`midnight` | 正午、真夜中 |
| `10:00 2026-12-24` | 日付を付ける |

### systemd のタイマー

systemd を使う系では、cron の代わりに**タイマー**の unit（`.timer`）で定期実行することもできます（unit の仕組みは[図解 Linux 17.4](../../linux/site/ch17.html#unit)）。`名前.timer` が、同じ名前の `名前.service` を起こします。Rocky Linux 9 にある `fstrim.timer` の`[Timer]` と `[Install]` の部分です（ファイルは /usr/lib/systemd/system/fstrim.timer）。

```text
[Timer]
OnCalendar=weekly
AccuracySec=1h
Persistent=true

[Install]
WantedBy=timers.target
```

| 設定 | 意味 |
| --- | --- |
| `OnCalendar=` | 暦の時刻で動かす（`daily`、`weekly`、`Mon..Fri 09:00`、`*-*-* 03:00:00` など） |
| `OnBootSec=` | 起動してからの時間で動かす（例 `10min`） |
| `OnUnitActiveSec=` | 前に動いてからの時間で繰り返す |
| `Persistent=true` | 止まっていて逃した分を、次の起動で実行する（anacron に近い） |

タイマーの一覧は `systemctl list-timers` で見ます。有効にするのは `systemctl enable --now 名前.timer` です。

| 仕組み | 回数 | 単位 | 止まっていた分 |
| --- | --- | --- | --- |
| cron | 繰り返し | 分 | 実行しない |
| anacron | 繰り返し | 日 | 起動後に実行する |
| at | 1 回 | 分 | — |
| systemd タイマー | 繰り返し・1 回 | 秒まで | `Persistent=true` なら実行する |

## ロケール：言語と国と文字コードの組 {#locale}

**国際化**（internationalization）は、プログラムを特定の言語や国に依存しないように作ることです。最初の i と最後の n の間に 18 文字あるので **i18n** と書きます。**地域化**（localization、**l10n**）は、国際化したプログラムに、特定の言語や国の翻訳・書式を与えることです。

Linux では、言語と国と文字コードの組を**ロケール**と呼び、環境変数で選びます。名前は `言語_国.文字コード` の形です。

| ロケール名 | 意味 |
| --- | --- |
| `ja_JP.UTF-8` | 日本語、日本、UTF-8 |
| `en_US.UTF-8` | 英語、アメリカ、UTF-8 |
| `ja_JP.eucJP` | 日本語、日本、EUC-JP |
| `C`（= `POSIX`） | 翻訳しない最小のロケール。メッセージは英語、並べ替えはバイトの順 |

### LANG、LC_*、LC_ALL の優先順位

```fig graph 項目ごとに、LC_ALL → LC_項目 → LANG の順に見て、最初に設定されているものを使う
{
  col: 200, row: 80,
  nodes: [
    { id: 'all', label: 'LC_ALL', sub: 'すべてを上書き', x: 0, y: 0, kind: 'accent' },
    { id: 'lc', label: 'LC_TIME など', sub: 'その項目だけ', x: 1, y: 0, kind: 'stack' },
    { id: 'lang', label: 'LANG', sub: '全体の既定値', x: 2, y: 0, kind: 'crate' },
    { id: 'c', label: 'C', sub: 'どれもなければ', x: 3, y: 0, kind: 'muted' },
  ],
  edges: [
    { from: 'all', to: 'lc', label: '空なら' }, { from: 'lc', to: 'lang', label: '空なら' }, { from: 'lang', to: 'c', label: '空なら' },
  ],
}
```

ロケールは、項目（カテゴリ）ごとに分かれています。

| 変数 | 決めるもの |
| --- | --- |
| `LC_CTYPE` | 文字の種類（どのバイト列が 1 文字か、大文字と小文字） |
| `LC_COLLATE` | 並べ替えの順番 |
| `LC_TIME` | 日付と時刻の書式 |
| `LC_NUMERIC` | 数の書式（小数点の記号など） |
| `LC_MONETARY` | 通貨の書式 |
| `LC_MESSAGES` | メッセージの言語 |
| `LC_PAPER` ほか | 紙の大きさ、住所や電話番号の書式など |
| `LANG` | 上のどれも設定されていない項目の既定値 |
| `LC_ALL` | すべての項目を、これで上書きする |

**優先順位は `LC_ALL` → `LC_項目` → `LANG`** です。Rocky Linux 9 で、日本語のロケールを入れて `date` を動かしました。

```console
$ LANG=ja_JP.UTF-8 date
2026年 11月 16日 月曜日 11:16:54 UTC
$ LANG=ja_JP.UTF-8 LC_TIME=C date
Mon Nov 16 11:16:54 UTC 2026
$ LC_ALL=C LANG=ja_JP.UTF-8 date
Mon Nov 16 11:16:54 UTC 2026
$ LC_ALL=ja_JP.UTF-8 LC_TIME=C locale | grep -E 'LC_TIME|LC_ALL'
LC_TIME="ja_JP.UTF-8"
LC_ALL=ja_JP.UTF-8
```

2 つ目は `LC_TIME` が `LANG` に勝ち、3 つ目は `LC_ALL` が `LANG` に勝ちました。4 つ目では、`LC_TIME=C` を設定しても `LC_ALL` が勝っています。

小さな Linux でも、環境変数そのものは同じように渡せます（小さな Linux の `date` は翻訳を持たないので、表示は英語のままです）。

```sh run title="LANG と、1 回だけの LC_ALL"
echo "$LANG"
LC_ALL=C sh -c 'echo "LC_ALL=$LC_ALL LANG=$LANG"'
```

:::tip スクリプトの中では LC_ALL=C
`sort` の順番、`ls` の日付の形、エラーメッセージの言語は、ロケールで変わります。スクリプトで出力を加工するときは、先頭で `export LC_ALL=C` としておくと、どのユーザーが実行しても同じ結果になります。`LANG=C` では、ユーザーが `LC_ALL` や `LC_COLLATE` を設定していると負けてしまいます。
:::

### locale と localectl

```console
$ locale
LANG=
LC_CTYPE="POSIX"
LC_NUMERIC="POSIX"
LC_TIME="POSIX"
…
LC_ALL=
$ locale -a
C
C.utf8
POSIX
ja_JP.eucjp
ja_JP.utf8
```

| コマンド | すること |
| --- | --- |
| `locale` | いまの各項目のロケールを表示する（値が `"` で囲まれているのは、LANG などから決まったもの） |
| `locale -a` | 使えるロケールの一覧 |
| `locale -m` | 使える文字コード（文字の対応表）の一覧 |
| `locale charmap` | いまの文字コード（`UTF-8` など） |
| `localectl` または `localectl status` | システムの既定のロケールとキーボード配列を表示する |
| `localectl set-locale LANG=ja_JP.UTF-8` | システムの既定のロケールを設定する |
| `localectl list-locales` | 使えるロケールの一覧 |

`localectl` は systemd のコマンドで、システム全体の既定値を書きます。書く先は `/etc/locale.conf`（Red Hat 系など）です。Debian 系では `/etc/default/locale` も使われます。ユーザーごとに変えたいときは、`~/.bashrc` などで `LANG` を export します。

## 文字コードと iconv {#iconv}

コンピュータの中で、文字はバイトの並びです。どの文字をどのバイトにするかの決まりを**文字コード**（文字エンコーディング）と呼びます。同じ「あ」でも、文字コードによってバイトが違います。

```fig layout 「あA」と改行を各文字コードにしたバイト（Debian 12 の iconv と od で確かめた値。16 進数）
{
  unit: 10,
  rows: [
    { label: 'UTF-8', cells: [{ t: 'e3 81 82', w: 8, kind: 'accent' }, { t: '41', w: 3, kind: 'stack' }, { t: '0a', w: 3, kind: 'plain' }], note: 'あ = 3 バイト' },
    { label: 'EUC-JP', cells: [{ t: 'a4 a2', w: 6, kind: 'accent' }, { t: '41', w: 3, kind: 'stack' }, { t: '0a', w: 3, kind: 'plain' }] },
    { label: 'Shift_JIS', cells: [{ t: '82 a0', w: 6, kind: 'accent' }, { t: '41', w: 3, kind: 'stack' }, { t: '0a', w: 3, kind: 'plain' }] },
    { label: 'ISO-2022-JP', cells: [{ t: '1b 24 42', w: 8, kind: 'heap' }, { t: '24 22', w: 6, kind: 'accent' }, { t: '1b 28 42', w: 8, kind: 'heap' }, { t: '41', w: 3, kind: 'stack' }, { t: '0a', w: 3, kind: 'plain' }], note: 'ESC で切り替え' },
    { label: 'UTF-16', cells: [{ t: 'ff fe', w: 6, kind: 'heap' }, { t: '42 30', w: 6, kind: 'accent' }, { t: '41 00', w: 6, kind: 'stack' }, { t: '0a 00', w: 6, kind: 'plain' }], note: '先頭は BOM' },
  ],
}
```

`A`（0x41）と改行（0x0a）は、UTF-16 以外ではどれも同じ 1 バイトです。これが ASCII の部分です。

| 文字コード | 特徴 |
| --- | --- |
| **ASCII** | 7 ビット、128 文字。英字、数字、記号、制御文字だけ。日本語は表せない |
| **ISO-8859** | 8 ビット、1 文字 1 バイトの文字コードの集まり。下半分は ASCII と同じ。`ISO-8859-1`（Latin-1）は西ヨーロッパの文字（é など）。日本語は表せない |
| **Unicode** | 世界の文字に番号（コードポイント）を付けた**文字の集合**。「あ」は `U+3042`。バイトにする方式が UTF-8、UTF-16 など |
| **UTF-8** | Unicode を 1〜4 バイトで表す。ASCII の文字は ASCII と同じ 1 バイト。日本語の多くは 3 バイト。いまの Linux の標準 |
| **UTF-16** | Unicode を 2 バイト（または 4 バイト）単位で表す。ASCII とは互換がない |
| **ISO-2022-JP** | 7 ビットだけで日本語を表す。エスケープシーケンス（`ESC $ B` など）で ASCII と日本語を切り替える。JIS コードとも呼ぶ。昔の電子メールで使われた |
| **EUC-JP** | 日本語の文字を 2 バイト（上位ビットが 1）で表す。古い Unix で使われた |
| **Shift_JIS** | 日本語の文字を 2 バイトで表す。Windows で使われた（その拡張が CP932） |

小さな Linux の端末は UTF-8 です。`od` でバイトを見ます。

```sh run title="あ は 3 バイト、A は 1 バイト"
printf 'あA\n' | od -An -tx1
printf 'あ' | wc -c
```

`wc -c` はバイトの数なので、「あ」1 文字で 3 です。

### iconv：文字コードを変える

`iconv` は、ファイルの文字コードを変えて標準出力に書きます。

| オプション | 意味 |
| --- | --- |
| `-f 文字コード` | 元の文字コード（from） |
| `-t 文字コード` | 変えた後の文字コード（to） |
| `-l` | 扱える文字コードの一覧 |
| `-o ファイル` | 標準出力ではなくファイルに書く |
| `-c` | 変えられない文字を捨てて続ける |

Debian 12 で、UTF-8 のファイルを Shift_JIS にして、戻しました。

```console
$ printf 'あA\n' > u.txt
$ iconv -f UTF-8 -t SHIFT_JIS u.txt | od -An -tx1
 82 a0 41 0a
$ iconv -f UTF-8 -t SJIS u.txt -o s.txt
$ iconv -f SJIS -t UTF-8 s.txt
あA
$ iconv -f UTF-8 -t ASCII u.txt
iconv: illegal input sequence at position 0
$ iconv -l | tr ',' '\n' | grep -E 'EUC-JP|ISO-2022-JP|SHIFT_JIS'
EUC-JP//
ISO-2022-JP//
SHIFT_JIS//
```

`SHIFT_JIS` と `SJIS` は同じ文字コードの別名です。ASCII に「あ」はないので、変えられずに止まりました（`-c` を付けると「あ」を捨てて続けます）。

:::warn 試験の注意：-f が元、-t が先
`iconv -f 元 -t 先 ファイル` です。from と to で覚えます。ファイルを直接書き換えるオプションはないので、`-o` か `>` で別のファイルに書きます（同じファイルに `>` すると、読む前に空になります）。
:::

:::key まとめ
- `/etc/passwd`（7 欄、だれでも読める）、`/etc/shadow`（9 欄、root だけ）、`/etc/group`（4 欄）。shadow の日付は 1970-01-01 からの日数。3 番目が 0 なら次のログインで変更、ハッシュの先頭の `!` はロック
- `useradd -m`（ホームを作り /etc/skel を写す）、`-d`（場所だけ）、`-g`（主グループ）、`-G`（補助グループ）、`-s -u -c -e`。既定値は `useradd -D` で表示・変更、`/etc/default/useradd` に入る。Debian は -m がないとホームを作らない
- `usermod -aG` は足す、`-G` だけは置き換え。`-l 新 旧`、`-L` / `-U`、`-s`。`userdel -r` でホームも消す。`groupmod -n 新 旧`、主グループのグループは `groupdel` できない
- `passwd -l -u -d -e -S -n -x -w -i`。`getent` は nsswitch.conf に従って引く。`id -u -g -G -n`
- crontab は「分 時 日 月 曜日 コマンド」。曜日は 0 と 7 が日曜。`*/5`、`1-5`、`1,15`。`crontab -e -l -r -u`。`/etc/crontab` と `/etc/cron.d` は 6 番目にユーザー名
- `/etc/cron.{hourly,daily,weekly,monthly}` はスクリプトを置くだけ。anacron は日単位で、止まっていた分をあとで実行（/etc/anacrontab は 期間・遅延・名前・コマンド）
- cron.allow があれば cron.deny は見ない。at はどちらもなければ root だけ
- `at now + 5 minutes`、`atq`（at -l）、`atrm`（at -d）。systemd は `.timer` の `OnCalendar=`、`systemctl list-timers`
- ロケールは `LC_ALL` → `LC_項目` → `LANG` の順。`locale`、`locale -a`、`localectl set-locale`。i18n は国際化、l10n は地域化
- `iconv -f 元 -t 先`、`-l` で一覧。UTF-8 は ASCII 互換で 1〜4 バイト、ISO-2022-JP は 7 ビットとエスケープ、EUC-JP と Shift_JIS は日本語の 2 バイト
:::

## 練習問題 {#practice}

### 1.08.1 アカウント管理

:::q 1.08.1-01 single
`/etc/shadow` に記録されない情報はどれか。
- [ ] パスワードを最後に変更した日
- [ ] パスワードの最長有効日数
- [ ] アカウントの失効日
- [x] ホームディレクトリ
- [ ] パスワードのハッシュ
:::why
ホームディレクトリは `/etc/passwd` の 6 番目の欄です。`/etc/shadow` は、ハッシュ（2 番目）、最終変更日（3 番目）、最短・最長・警告・猶予の日数（4〜7 番目）、アカウントの失効日（8 番目）を持ちます（[/etc/shadow の 9 つの欄](#account-files)）。
:::
:::

:::q 1.08.1-02 single
`/etc/passwd` に次の行がある。4 番目の欄の `100` が表すものはどれか。

```text
ken:x:1003:100:Ken Sato:/home/ken:/bin/bash
```
- [ ] ken の uid
- [x] ken の主グループの gid
- [ ] ken が入っている補助グループの数
- [ ] パスワードの最長有効日数
:::why
欄は `ユーザー名:x:uid:gid:説明:ホーム:シェル` です。4 番目は主グループの gid、3 番目の `1003` が uid です。補助グループは `/etc/group` の 4 番目の欄に書かれ、`/etc/passwd` にはありません。最長有効日数は `/etc/shadow` の 5 番目です（[図解 Linux 4.1](../../linux/site/ch04.html#users)）。
:::
:::

:::q 1.08.1-03 single
`useradd` で、ユーザーのホームディレクトリを作り、`/etc/skel` の中身をそこにコピーさせるオプションはどれか。
- [ ] `-d`
- [x] `-m`
- [ ] `-k`
- [ ] `-M`
- [ ] `-s`
:::why
`-m`（create-home）がホームを作り、スケルトンをコピーします。`-d` はホームの場所を `/etc/passwd` に書くだけで、`-m` がなければ作りません。`-k` は `/etc/skel` の代わりに使うディレクトリの指定で、`-m` と組んで使います。`-M` は逆に「作らない」、`-s` はログインシェルです（[useradd のオプション](#useradd)）。
:::
:::

:::q 1.08.1-04 multi
`useradd -D` の説明として正しいものを 2 つ選択してください。
- [x] オプションを付けずに実行すると、useradd の既定値を表示する
- [x] `useradd -D -s /bin/zsh` とすると、既定のログインシェルが変わり、`/etc/default/useradd` に書き込まれる
- [ ] `/etc/login.defs` の中身をすべて表示する
- [ ] 指定したユーザーのホームディレクトリを削除する
- [ ] `/etc/skel` を作り直す
:::why
`-D`（defaults）は既定値の表示と変更です。変えた値は `/etc/default/useradd` に入ります。`/etc/login.defs`（uid の範囲や期限）は表示しません。ユーザーを消すのは `userdel`、`/etc/skel` を作り直す働きはありません（[既定値は Debian と Red Hat 系で違う](#useradd)）。
:::
:::

:::q 1.08.1-05 single
ユーザー ken の主グループは ken、補助グループは dev と ops である。root が次のコマンドを実行した。実行後の ken の所属として正しいものはどれか。

```text
# usermod -G wheel ken
```
- [ ] 主グループ ken、補助グループ dev、ops、wheel
- [x] 主グループ ken、補助グループ wheel だけ
- [ ] 主グループ wheel、補助グループ dev、ops
- [ ] 主グループ wheel、補助グループなし
:::why
`-a` を付けない `-G` は、補助グループを「指定したものだけ」に置き換えます。dev と ops から外れ、wheel だけになります。主グループは `-g` で変えるもので、`-G` では変わりません。今の所属を残して足すなら `usermod -aG wheel ken` です（[-G と -aG の違い](#usermod)）。
:::
:::

:::q 1.08.1-06 fill
ユーザー ken を、今の補助グループを残したまま docker グループにも入れる。空欄に入るオプションを入力してください。

```text
usermod ____ docker ken
```
= -aG
= -a -G
= -Ga
= --append --groups
= -a --groups
= --append -G
= -G -a
:::why
`-a`（append）と `-G`（補助グループ）を組み合わせます。`-a` は `-G` と一緒でなければ意味がありません。`-G` だけだと、補助グループが docker だけになります（[-G と -aG の違い](#usermod)）。
:::
:::

:::q 1.08.1-07 single
ユーザー ken を削除し、同時にホームディレクトリとメールスプールも削除するコマンドはどれか。
- [x] `userdel -r ken`
- [ ] `userdel -f ken`
- [ ] `userdel -m ken`
- [ ] `userdel ken`
- [ ] `usermod -r ken`
:::why
`userdel -r`（remove）がホームとメールスプールも消します。オプションなしの `userdel` は、アカウントを消してもホームは残します。`-f` はログイン中でも強制的に消すオプションです。`userdel` に `-m` はありません。`usermod` はユーザーを変えるコマンドで、削除はしません（[userdel](#usermod)）。
:::
:::

:::q 1.08.1-08 single
`/etc/shadow` に次の行がある。この行から分かることとして正しいものはどれか。

```text
ken:!$6$Qx1F...$M0aE...:20773:0:99999:7:::
```
- [ ] ken にはパスワードが設定されていないので、パスワードなしでログインできる
- [x] ken のパスワードはロックされている
- [ ] ken のパスワードは次のログインで変更しなければならない
- [ ] ken のアカウントは 99999 日後に削除される
:::why
ハッシュの先頭の `!` はロックの印です（`passwd -l` や `usermod -L` が付ける）。ハッシュは残っているので、ロックを外せば元のパスワードで入れます。パスワードがないなら 2 番目の欄は空です。次のログインで変更させるときは 3 番目が `0` になります。`99999` は 5 番目の最長日数で、アカウントの削除とは関係ありません（[passwd](#passwd)）。
:::
:::

:::q 1.08.1-09 multi
ユーザー ken のパスワードをロックするコマンドを 2 つ選択してください。
- [x] `passwd -l ken`
- [ ] `passwd -u ken`
- [x] `usermod -L ken`
- [ ] `usermod -U ken`
- [ ] `passwd -d ken`
:::why
`passwd -l` と `usermod -L` は、どちらもハッシュの先頭に `!` を付けてロックします。`passwd -u` と `usermod -U` はロックを外す、`passwd -d` はパスワードを消して空にするオプションです（[passwd](#passwd)、[usermod](#usermod)）。
:::
:::

:::q 1.08.1-10 multi
root が使う `passwd` のオプションの説明として正しいものを 2 つ選択してください。
- [x] `-l` は、指定したユーザーのパスワードをロックする
- [x] `-e` は、パスワードを期限切れにして、次のログインで変更させる
- [ ] `-d` は、指定したユーザーのアカウントを削除する
- [ ] `-u` は、指定したユーザーの uid を変える
- [ ] `-S` は、パスワードを平文で表示する
:::why
`-l` はロック、`-e`（expire）は `/etc/shadow` の 3 番目を `0` にして次のログインで変更させます。`-d` はアカウントではなく**パスワード**を消します（空にする）。`-u` はロックを外す（unlock）オプションで、uid を変えるのは `usermod -u` です。`-S` は状態（L、P、NP など）を表示するだけで、パスワードは表示しません（[passwd](#passwd)）。
:::
:::

:::q 1.08.1-11 single
グループ dev の名前を devel に変えるコマンドとして正しいものはどれか。
- [ ] `groupmod -n dev devel`
- [x] `groupmod -n devel dev`
- [ ] `groupmod -g devel dev`
- [ ] `usermod -l devel dev`
- [ ] `groupadd -n devel dev`
:::why

### 1.08.2 ジョブスケジューリング

:::q 1.08.2-01 single
ユーザーの crontab に次の行がある。このコマンドが実行されるのはいつか。

```text
30 9 * * 1-5 /home/ken/bin/report.sh
```
- [x] 月曜日から金曜日の 9 時 30 分
- [ ] 毎月 1 日から 5 日の 9 時 30 分
- [ ] 1 月から 5 月の毎日 9 時 30 分

- [ ] 30 日の 9 時、1 分から 5 分まで

欄は「分 時 日 月 曜日」です。分が 30、時が 9、曜日が `1-5`（月〜金）です。日は 3 番目、月は 4 番目の欄なので、ここでは `*`（すべて）です（[cron](#cron)）。

:::q 1.08.2-02 single

- [ ] `0-15 * * * *`
:::why
`*/15` を分の欄に書くと、0、15、30、45 分に実行します。`15 * * * *` は毎時 15 分に 1 回だけ、`* */15 * * *` は 0 時台と 15 時台の毎分、`0-15 * * * *` は毎時 0〜15 分の毎分です（[cron](#cron)）。
:::
:::

:::q 1.08.2-15 single
`atrm 3` を実行したときの動きとして正しいものはどれか。
- [ ] 3 分後にジョブを実行する
- [x] ジョブ番号 3 の予約を取り消す
- [ ] ジョブ番号 3 の内容を表示する
- [ ] 3 番目のユーザーの予約をすべて取り消す
:::why
`atrm ジョブ番号` は予約を消します。番号は `atq` の 1 列目です。内容を表示するのは `at -c 3` です（[at](#at)）。
:::
:::

:::q 1.08.2-16 multi
at の時刻の指定として正しいものを 2 つ選択してください。
- [x] `at now + 5 minutes`
- [x] `at 17:00 tomorrow`
- [ ] `at every 5 minutes`
- [ ] `at */5 * * * *`
- [ ] `at 25:00`
:::why
`now + 5 minutes`（5 分後）、`17:00 tomorrow`（明日の 17 時）は at の書き方です。at は 1 回だけ実行するので「every」の繰り返しはありません。`*/5 * * * *` は crontab の書き方です。25 時は時刻として正しくありません（[at](#at)）。
:::
:::

:::q 1.08.2-17 single
`/etc/at.allow` と `/etc/at.deny` のどちらもないとき、at を使えるユーザーはどれか。
- [ ] すべてのユーザー
- [x] root だけ
- [ ] wheel グループのユーザーだけ
- [ ] だれも使えない
:::why
at は、どちらのファイルもなければ root だけが使えます。すべてのユーザーに許すには、空の `/etc/at.deny` を置きます（多くのディストリビューションの初期状態）（[cron.allow と cron.deny](#system-cron)）。
:::
:::

:::q 1.08.2-18 single
Red Hat 系（cronie）で、一般ユーザー ken が `crontab -e` で作った crontab が保存される場所はどれか。
- [x] `/var/spool/cron/ken`
- [ ] `/var/spool/cron/crontabs/ken`
- [ ] `/etc/cron.d/ken`
- [ ] `/home/ken/.crontab`
:::why
Red Hat 系は `/var/spool/cron/ユーザー名` です。`/var/spool/cron/crontabs/ユーザー名` は Debian 系の場所です。`/etc/cron.d` はシステムの設定を置くところで、ユーザーの crontab は入りません（[crontab コマンド](#cron)）。
:::
:::

:::q 1.08.2-19 fill
毎週日曜日の 3 時 0 分に実行する。空欄に入る曜日の値を入力してください。

```text
0 3 * * ____ /usr/local/bin/weekly.sh
```
= 0
= 7
= sun
= Sun
= SUN
:::why
曜日の欄は 0〜7 で、0 と 7 がどちらも日曜です。`sun` のような英語の略称も使えます。1 が月曜、6 が土曜です（[cron](#cron)）。
:::
:::

:::q 1.08.2-20 multi
systemd のタイマーの説明として正しいものを 2 つ選択してください。
- [x] `.timer` の unit に `OnCalendar=` で実行する時刻を書く
- [x] `systemctl list-timers` で、タイマーの一覧と次に動く時刻を確認できる
- [ ] タイマーは `crontab -e` で編集する
- [ ] タイマーの設定は `/etc/anacrontab` に書く
- [ ] タイマーは 1 日単位でしか動かせない
:::why
タイマーは `名前.timer` の unit で、`OnCalendar=`（暦の時刻）や `OnBootSec=`（起動からの時間）を書き、同じ名前の `.service` を起こします。一覧は `systemctl list-timers` です。crontab や anacrontab とは別の仕組みで、時刻は秒まで指定できます（[systemd のタイマー](#at)）。
:::
:::

### 1.08.3 ローカライゼーションと国際化

:::q 1.08.3-01 single
i18n の説明として正しいものはどれか。
- [x] 国際化（internationalization）の略で、プログラムを特定の言語や国に依存しないように作ること
- [ ] 地域化（localization）の略で、特定の言語の翻訳を用意すること
- [ ] Unicode の 18 番目の版のこと
- [ ] 18 か国語に対応した文字コードのこと
:::why
i と n の間に 18 文字ある internationalization の略です。特定の言語の翻訳や書式を与えることは地域化（localization、l10n）です。数字は文字の数で、版や言語の数ではありません（[ロケール](#locale)）。
:::
:::

:::q 1.08.3-02 single
環境変数が `LANG=ja_JP.UTF-8`、`LC_TIME=C` で、`LC_ALL` は設定されていない。日本語のロケールが使えるシステムで `date` を実行したときの日付の表示として正しいものはどれか。
- [ ] `2026年 11月 16日 月曜日` のように日本語で表示される
- [x] `Mon Nov 16` のように英語で表示される
- [ ] LANG と LC_TIME が矛盾するので、エラーになる
- [ ] 日付の部分だけが日本語、時刻の部分は英語で表示される
:::why
日付の書式は `LC_TIME` の項目です。`LC_TIME` は `LANG` より優先されるので、C ロケールの英語の表示になります（[LANG、LC_*、LC_ALL の優先順位](#locale)）。
:::
:::

:::q 1.08.3-03 single
ロケールの環境変数の優先順位として正しいものはどれか（左ほど優先される）。
- [x] `LC_ALL` → `LC_CTYPE` などの `LC_*` → `LANG`
- [ ] `LANG` → `LC_*` → `LC_ALL`
- [ ] `LC_*` → `LC_ALL` → `LANG`
- [ ] `LANG` → `LC_ALL` → `LC_*`
:::why
`LC_ALL` はすべての項目を上書きします。それがなければ項目ごとの `LC_*`、それもなければ `LANG` を使います（[LANG、LC_*、LC_ALL の優先順位](#locale)）。
:::
:::

:::q 1.08.3-04 multi
ロケールの項目の説明として正しいものを 2 つ選択してください。
- [x] `LC_TIME` は日付と時刻の書式を決める
- [x] `LC_COLLATE` は文字列を並べ替える順番を決める
- [ ] `LC_MESSAGES` は文字コードを決める
- [ ] `LC_NUMERIC` は通貨の記号を決める
- [ ] `LC_CTYPE` は時刻の書式を決める
:::why
`LC_TIME` は日付と時刻、`LC_COLLATE` は並べ替えです。`LC_MESSAGES` はメッセージの言語、文字の種類（どのバイト列が 1 文字か）は `LC_CTYPE`、通貨は `LC_MONETARY`、`LC_NUMERIC` は数の書式（小数点の記号など）です（[LANG、LC_*、LC_ALL の優先順位](#locale)）。
:::
:::

:::q 1.08.3-05 fill
システムで使えるロケールの一覧を表示するコマンドを、オプションも含めて入力してください。
= locale -a
= locale --all-locales
:::why
`locale -a` です。`locale` だけなら、いまの各項目の設定を表示します。`localectl list-locales` でも一覧を見られますが、ここでは `locale` コマンドを問うています（[locale と localectl](#locale)）。
:::
:::

:::q 1.08.3-06 single
`localectl set-locale LANG=ja_JP.UTF-8` の説明として正しいものはどれか。
- [ ] 今のシェルだけで `LANG` を変える
- [x] システム全体の既定のロケールを設定し、`/etc/locale.conf` などに書き込む
- [ ] ja_JP.UTF-8 のロケールのデータを新しく作る
- [ ] ファイルの文字コードを UTF-8 に変換する
:::why
`localectl` は systemd のコマンドで、システムの既定のロケールを設定ファイルに書きます。今のシェルだけなら `export LANG=…` です。ファイルの文字コードを変えるのは `iconv` です（[locale と localectl](#locale)）。
:::
:::

:::q 1.08.3-07 single
ISO-2022-JP の説明として正しいものはどれか。
- [ ] 1 文字を 1〜4 バイトで表し、ASCII と互換がある
- [x] 7 ビットだけを使い、エスケープシーケンスで ASCII と日本語を切り替える。電子メールで使われてきた
- [ ] 西ヨーロッパの文字を 1 バイトで表す
- [ ] Windows で使われてきた、日本語を 2 バイトで表す文字コード
:::why
ISO-2022-JP（JIS コード）は 7 ビットで、`ESC $ B` などで切り替えます。1〜4 バイトで ASCII 互換なのは UTF-8、西ヨーロッパは ISO-8859-1、Windows で使われたのは Shift_JIS です（[文字コードと iconv](#iconv)）。
:::
:::

:::q 1.08.3-08 single
UTF-8 の説明として正しいものはどれか。
- [x] Unicode の文字を 1〜4 バイトで表し、ASCII の文字は ASCII と同じ 1 バイトになる
- [ ] すべての文字を必ず 2 バイトで表す
- [ ] 日本語だけを表すための文字コードである
- [ ] 7 ビットの文字コードで、128 文字だけを表す
:::why
UTF-8 は可変長で、ASCII の部分は ASCII とまったく同じバイトです。日本語の多くは 3 バイトになります。2 バイト単位なのは UTF-16、128 文字だけなのは ASCII です（[文字コードと iconv](#iconv)）。
:::
:::

:::q 1.08.3-09 multi
日本語の文字を表すことができる文字コードを 2 つ選択してください。
- [x] EUC-JP
- [x] Shift_JIS
- [ ] ASCII
- [ ] ISO-8859-1
- [ ] ISO-8859-5
:::why
EUC-JP と Shift_JIS は日本語の文字コードです。ASCII は英字と記号の 128 文字だけ、ISO-8859 の各部は 1 バイトでヨーロッパの文字を表すもので（-1 は西ヨーロッパ、-5 はキリル文字）、日本語は表せません（[文字コードと iconv](#iconv)）。
:::
:::

:::q 1.08.3-10 fill
Shift_JIS で書かれたファイル `sjis.txt` を UTF-8 に変換して表示する。空欄に入るオプションを入力してください。

```text
iconv ____ SHIFT_JIS -t UTF-8 sjis.txt
```
= -f
= --from-code
:::why
`-f`（from）が元の文字コード、`-t`（to）が変換後の文字コードです（[iconv](#iconv)）。
:::
:::

:::q 1.08.3-11 single
`iconv -l` を実行したときの動きとして正しいものはどれか。
- [x] iconv が扱える文字コードの一覧を表示する
- [ ] 現在のロケールの文字コードを表示する
- [ ] ファイルの文字コードを調べて表示する
- [ ] 変換できなかった文字を捨てて変換を続ける
:::why
`-l`（list）は文字コードの一覧です。いまの文字コードは `locale charmap` で見ます。iconv はファイルの文字コードを調べません（`-f` で人が指定する）。変換できない文字を捨てるのは `-c` です（[iconv](#iconv)）。
:::
:::

:::q 1.08.3-12 single
端末で次のように実行した。この端末の文字コードとして考えられるものはどれか。

```text
$ printf 'あ' | od -An -tx1
 e3 81 82
```
- [x] UTF-8
- [ ] Shift_JIS
- [ ] EUC-JP
- [ ] ISO-2022-JP
:::why
「あ」が 3 バイトの `e3 81 82` になるのは UTF-8 です。Shift_JIS なら `82 a0`、EUC-JP なら `a4 a2` の 2 バイト、ISO-2022-JP ならエスケープシーケンス（`1b 24 42`）が前に付きます（[文字コードと iconv](#iconv)）。
:::
:::

:::q 1.08.3-13 single
ASCII の説明として正しいものはどれか。
- [x] 7 ビットで、英字・数字・記号・制御文字の 128 文字を表す
- [ ] 8 ビットで、西ヨーロッパの文字を含む 256 文字を表す
- [ ] 世界中の文字に番号を付けた文字の集合である
- [ ] 日本語を 2 バイトで表す
:::why
ASCII は 7 ビット、128 文字です。8 ビットで西ヨーロッパの文字を足したのが ISO-8859-1、世界の文字に番号を付けたのが Unicode です。日本語は表せません（[文字コードと iconv](#iconv)）。
:::
:::

:::q 1.08.3-14 multi
Unicode と UTF-8 の関係の説明として正しいものを 2 つ選択してください。
- [x] Unicode は、文字に番号（コードポイント）を付けた文字の集合である
- [x] UTF-8 は、Unicode の番号をバイトの並びにする方式の 1 つである
- [ ] UTF-8 では、すべての文字が 2 バイトの固定長になる
- [ ] Unicode は日本語だけを集めた文字の集合である
- [ ] UTF-16 と UTF-8 では、ASCII の文字のバイトは同じになる
:::why
Unicode は「あ = U+3042」のような番号の表で、それをバイトにする方式が UTF-8、UTF-16 などです。UTF-8 は 1〜4 バイトの可変長です。Unicode は世界の文字を集めたものです。UTF-16 では `A` が `41 00` のように 2 バイトになり、ASCII と同じではありません（[文字コードと iconv](#iconv)）。
:::
:::

:::q 1.08.3-15 fill
シェルスクリプトの先頭で、ほかのどのロケールの設定よりも優先して、すべての項目を C ロケールにしたい。空欄に入る環境変数の名前を入力してください。

```text
export ____=C
```
= LC_ALL
:::why
`LC_ALL` はすべての項目を上書きし、`LC_*` や `LANG` より優先されます。`LANG=C` では、ユーザーが `LC_COLLATE` などを設定しているとそちらが勝ちます（[LANG、LC_*、LC_ALL の優先順位](#locale)）。
:::
