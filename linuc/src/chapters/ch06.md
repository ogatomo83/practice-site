ページの中で動く「小さな Linux」の `sh` は、POSIX のシェルに bash の書き方の一部を足したものです。`bash` というコマンドはありません。本物の bash だけで確かめられること（設定ファイルの読まれる順番、`bash -v`、スクリプトの中の alias）は、Docker の Debian 12（bash 5.2）と Rocky Linux 9 で実際に動かした出力を、実行しない例で見せます。

## ログインシェルと非ログインシェル：bash はどの設定ファイルを読むか {#startup}

bash は、起動のしかたによって、読む設定ファイルが変わります。試験で問われるのは、次の 2 つの起動のしかたです。

- **ログインシェル**：ユーザー名とパスワードでログインしたときに、最初に起動するシェル。コンソールからのログイン、`ssh` での接続、`su -`（`su -l`）、`bash --login`（`bash -l`）
- **対話的な非ログインシェル**：ログインした後で、新しく起動したシェル。端末で `bash` と打ったとき、`su`（`-` なし）、デスクトップで端末のウィンドウを開いたとき（多くの環境）

ログインシェルの bash は、次の順に読みます。

1. **/etc/profile**（全員に共通）
2. **~/.bash_profile、~/.bash_login、~/.profile** の順に探して、**最初に見つかった 1 つだけ**
3. ログアウトするときに **~/.bash_logout**

**~/.bashrc** は、ログインシェルの bash が直接は読みません。それでもログインしたシェルで ~/.bashrc の設定が効くのは、~/.profile（Red Hat 系では ~/.bash_profile）の中に「~/.bashrc があれば `.` で読み込む」と書いてあるからです。

対話的な非ログインシェルの bash は、**/etc/bash.bashrc**（Debian 系）と **~/.bashrc** を読みます。/etc/profile や ~/.profile は読みません。シェルスクリプトを実行するシェル（対話的でない）は、どれも読みません。

| 起動のしかた | 読むファイル（Debian 12 の bash） |
| --- | --- |
| ログインシェル（ログイン、`ssh`、`su -`、`bash -l`） | /etc/profile →（その中から /etc/bash.bashrc）→ ~/.bash_profile・~/.bash_login・~/.profile のうち最初の 1 つ →（~/.profile の中から ~/.bashrc）。終わるときに ~/.bash_logout |
| 対話的な非ログインシェル（`bash`、`su`） | /etc/bash.bashrc → ~/.bashrc |
| 対話的でないシェル（`bash スクリプト`） | どれも読まない |

### Docker の Debian 12 で、読まれる順番を確かめる

それぞれのファイルの 1 行目に「`echo "[ファイル名]"`」を足して、ユーザー alice で起動してみました。

```console
# su - alice              ← ログインシェル（- あり）
[/etc/profile]
[/etc/bash.bashrc]
[~/.profile]
[~/.bashrc]
alice@debian:~$ echo $0; shopt login_shell
-bash
login_shell     on
alice@debian:~$ exit
logout
[~/.bash_logout]
# su alice                ← 非ログインシェル（- なし）
[/etc/bash.bashrc]
[~/.bashrc]
alice@debian:~$ echo $0; shopt login_shell
bash
login_shell     off
```

ログインシェルでは `$0` が `-bash` のように、先頭に `-` が付きます。`shopt login_shell` でも確かめられます。

次に、alice のホームに ~/.bash_profile と ~/.bash_login を作って、`bash -l`（ログインシェル）を起動しました。

```console
alice@debian:~$ ls -a
.  ..  .bash_login  .bash_logout  .bash_profile  .bashrc  .profile
alice@debian:~$ bash -l
[/etc/profile]
[/etc/bash.bashrc]
[~/.bash_profile]
```

~/.bash_profile があるので、~/.bash_login と ~/.profile は読まれません。~/.profile の中にある「~/.bashrc を読む」行も実行されないので、~/.bashrc も読まれなくなりました。~/.bash_profile を消すと、今度は ~/.bash_login だけが読まれます。

:::warn 試験の注意：3 つのうち「1 つだけ」
~/.bash_profile、~/.bash_login、~/.profile は、**全部を順に読むのではありません**。この順に探して、最初に見つかった 1 つだけを読みます。「~/.bash_profile を作ったら、~/.profile に書いた PATH が効かなくなった」という事故は、これが原因です。
:::

### Red Hat 系との違い

Red Hat 系（Rocky Linux 9）には /etc/bash.bashrc がなく、代わりに **/etc/bashrc** があります。ユーザーのファイルも、~/.profile ではなく ~/.bash_profile が最初から置いてあります。中身は、Rocky Linux 9 の /etc/skel（新しいユーザーのホームにコピーされるひな形）で確かめました。

```console
$ cat /etc/skel/.bash_profile
# .bash_profile

# Get the aliases and functions
if [ -f ~/.bashrc ]; then
	. ~/.bashrc
fi
$ head -6 /etc/skel/.bashrc
# .bashrc

# Source global definitions
if [ -f /etc/bashrc ]; then
	. /etc/bashrc
fi
```

~/.bash_profile が ~/.bashrc を読み、~/.bashrc が /etc/bashrc を読む、という鎖です。どちらの系統でも「**ログインシェルでも、結局は ~/.bashrc が読まれるように**」書いてあります。

| ファイル | だれの | いつ読まれる | 書くもの |
| --- | --- | --- | --- |
| /etc/profile | 全員 | ログインシェル | 全員の環境変数（PATH など）、umask |
| ~/.bash_profile、~/.bash_login、~/.profile | 各ユーザー | ログインシェル（最初の 1 つ） | そのユーザーの環境変数 |
| /etc/bash.bashrc（Debian 系）、/etc/bashrc（Red Hat 系） | 全員 | 対話的なシェル | 全員のプロンプト、alias |
| ~/.bashrc | 各ユーザー | 対話的な非ログインシェル（ログインシェルでは ~/.profile などから） | そのユーザーの alias、関数、プロンプト |
| ~/.bash_logout | 各ユーザー | ログインシェルの終了時 | 画面を消すなどの後片付け |

小さな Linux にも、/etc/profile と ~/.profile が置いてあります（中身はコメントだけです）。

```sh run title="小さな Linux の設定ファイル"
echo $0
cat /etc/profile
cat ~/.profile
ls -a ~
```

## source と .：設定をいまのシェルに読み込む {#source}

設定ファイルを書き換えても、いま動いているシェルには反映されません。ファイルが読まれるのは、シェルが起動するときだけだからです。ログインし直さずに反映させるには、**source**（または **.**）で読み込みます。


[図解 Linux 7.10](../../linux/site/ch07.html#subshell) で見たとおり、`sh ファイル` や `./ファイル` は、子プロセスの新しいシェルで実行します。子で変えた変数や `cd` は、子が終わると消えます。`source ファイル` と `. ファイル` は、いまのシェルがファイルを読んで実行するので、設定が残ります。

```sh run title="sh で実行すると残らない。. と source なら残る"
cat > env.sh <<'EOF'
GREETING=hello
cd notes
EOF
sh env.sh
echo "[$GREETING] $(pwd)"
. ./env.sh
echo "[$GREETING] $(pwd)"
cd
```

設定ファイルに alias を書き足して、読み直してみます。書き足しただけでは、まだ使えません。

```sh run error title="~/.profile に書き足しても、読み直すまでは効かない"
echo "alias ll='ls -l'" >> ~/.profile
ll hello.sh
. ~/.profile
ll hello.sh
```

`. ~/.profile` のあとで、`ll` が使えるようになりました。本物の bash で ~/.bashrc を書き換えたときは、`source ~/.bashrc` か `. ~/.bashrc` です。

| 書き方 | どこで実行するか | 実行権限 | 変数・cd・alias |
| --- | --- | --- | --- |
| `source ファイル` | いまのシェル | 要らない | 残る |
| `. ファイル` | いまのシェル（`source` と同じ） | 要らない | 残る |
| `bash ファイル`、`sh ファイル` | 子のシェル | 要らない（読めればよい） | 残らない |
| `./ファイル` | 子のシェル（`#!` のプログラム） | 要る | 残らない |

:::warn 試験の注意：. の後ろには空白
`. ~/.bashrc` の `.` はコマンドの名前です。後ろに空白が要ります。`./.bashrc` と続けて書くと、「カレントディレクトリの .bashrc を子のシェルで実行する」という別の意味になります（実行権限がなければ失敗します）。`source` は bash の書き方で、POSIX のシェル（Debian の /bin/sh である dash など）では `.` を使います。
:::

## alias、PATH、そして ; && || {#alias}

### alias：コマンドに別名を付ける

**alias** は、長いコマンドに短い別名を付けるシェルの組み込みコマンドです。`alias 名前='コマンド'` で定義し、引数なしの `alias` で一覧を表示します。消すのは **unalias** で、`unalias -a` はすべての別名を消します。別名と同じ名前のコマンドを、別名を使わずに実行したいときは、先頭に `\` を付けるか、`command` を付けます。

```sh run title="alias で定義し、一覧を見て、消す。\ls と command ls は別名を使わない"
alias la='ls -a'
alias
type la
la notes
unalias la
alias
alias ls='echo 別名の ls'
ls -d /
\ls -d /
command ls -d /
unalias ls
```

`alias` で定義した別名は、そのシェルが終わると消えます。いつも使いたい別名は、~/.bashrc に書きます（ログインシェルでも ~/.profile などから ~/.bashrc が読まれるので、ここに書けば両方で効きます）。

:::warn 試験の注意：スクリプトの中では alias は展開されない
本物の bash は、**対話的でないシェル（スクリプト）では alias を展開しません**。Debian 12 の bash で確かめた結果です。

```console
$ cat al.sh
alias hi='echo hi'
hi
$ bash al.sh
al.sh: line 2: hi: command not found
```

スクリプトの中で同じことをしたいなら、関数を使います（`shopt -s expand_aliases` を書けば展開されますが、ふつうは関数にします）。なお、小さな Linux の `sh` は、スクリプトの中でも alias を展開します。これは本物と違うところです。
:::

### PATH にディレクトリを足す

[図解 Linux 2.4](../../linux/site/ch02.html#path) で見たとおり、シェルは `/` を含まないコマンド名を、**環境変数 PATH** に `:` で区切って並んだディレクトリの中から、前から順に探します。自分のコマンドを置くディレクトリは、PATH に足します。

```sh run error title="~/bin を PATH の最後に足す"
echo $PATH
mkdir -p bin
cat > bin/today <<'EOF'
#!/bin/sh
date +%F
EOF
chmod +x bin/today
today
PATH=$PATH:$HOME/bin
echo $PATH
today
```

| 書き方 | 意味 |
| --- | --- |
| `PATH=$PATH:$HOME/bin` | 最後に足す（同じ名前のコマンドがあれば、元のほうが優先） |
| `PATH=$HOME/bin:$PATH` | 先頭に足す（自分のほうが優先） |
| `export PATH=$PATH:$HOME/bin` | 足して、子プロセスにも渡す |
| `PATH=$HOME/bin` | **置き換え**。`ls` などが見つからなくなる |

PATH は最初から環境変数（export 済み）なので、代入するだけで子プロセスにも渡ります。それでも設定ファイルには `export PATH=…` と書くのが習慣です。新しく作った変数を子プロセスに渡すには、`export` が必要です（[図解 Linux 7.9](../../linux/site/ch07.html#env)）。ずっと使いたいなら、~/.profile か ~/.bash_profile に書きます。Debian の ~/.profile には、最初から「~/bin があれば PATH の先頭に足す」行が入っています。

:::warn 試験の注意：PATH の書き方の誤り
`$PATH=…`（左辺に `$`）、`PATH = …`（`=` の前後に空白）、`PATH=$PATH;~/bin`（区切りが `;`）は、どれも誤りです。区切りは `:`、代入は空白なしの `名前=値` です。PATH に `.`（カレントディレクトリ）を入れるのは、危険なので避けます（[図解 Linux 6.1](../../linux/site/ch06.html#script)）。
:::

### ; && || でコマンドをつなぐ

1 行に複数のコマンドを書くときは、つなぎ方で「次を実行するかどうか」が変わります。判断に使うのは、直前のコマンドの**終了ステータス**（0 が成功）です。

| 書き方 | B を実行するのは |
| --- | --- |
| `A ; B` | いつでも（A が終わったら） |
| `A && B` | A が成功（終了ステータス 0）したときだけ |
| `A \|\| B` | A が失敗（0 以外）したときだけ |

```sh run error title="; と && と ||"
echo one; echo two
grep -q apple fruits.txt && echo "apple がある"
grep -q mango fruits.txt && echo "mango がある"
grep -q mango fruits.txt || echo "mango はない"
cd /nonexistent && ls
cd /nonexistent ; pwd
```

`cd /nonexistent && ls` は、`cd` が失敗したので `ls` を実行しません。`;` でつなぐと、`cd` に失敗しても `pwd` を実行します。`&&` や `||` を並べたときは、左から順に、直前の結果で判断します（[図解 Linux 6.5](../../linux/site/ch06.html#status)）。

## スクリプトを動かす：#!、実行権限、引数、終了ステータス {#script}

### 3 つの実行のしかた

スクリプトの 1 行目の **`#!`**（シバン、shebang）は、カーネルが読みます（[図解 Linux 6.1](../../linux/site/ch06.html#script)）。`./run.sh` と実行すると、カーネルは `#!` の後ろのプログラム（`#!/bin/bash` なら /bin/bash）を起動して、スクリプトのパスを渡します。`bash run.sh` のようにシェルに渡したときは、1 行目はただのコメントです。

名前で実行するには、ファイルに **x（実行）の権限**が要ります。

```sh run error title="x の権限がないと ./ では実行できない。sh なら動く。chmod で x を付ける"
cat > greet.sh <<'EOF'
#!/bin/sh
echo "Hello, $1"
EOF
ls -l greet.sh
./greet.sh you
sh greet.sh you
chmod 755 greet.sh
ls -l greet.sh
./greet.sh you
```

最初の `./greet.sh` は `Permission denied` で、終了ステータスは 126 です。x の権限がなくても、`sh greet.sh` や `. ./greet.sh` なら、シェルがファイルを読むだけなので実行できます。`chmod 755` のあとは `./` でも動きました。`chmod +x` でも `chmod u+x` でもかまいません（[図解 Linux 4.3](../../linux/site/ch04.html#chmod)）。持ち主を変えるのは **chown**（`chown 持ち主:グループ ファイル`）で、root だけが使えます（[図解 Linux 4.7](../../linux/site/ch04.html#chown)）。

```sh run root title="root で持ち主とグループを変える（プロンプトが # になる）"
chown alice:staff /home/you/greet.sh
ls -l /home/you/greet.sh
chown you:you /home/you/greet.sh
```

`./` を付けずに名前だけで実行したいなら、置き場所を PATH に入れます（前の節の ~/bin）。`#!` に書いたプログラムがないと、`cannot execute: required file not found` で終了ステータス 127 になります（Debian 12 の bash でも同じ文でした）。

| 終了ステータス | 意味 |
| --- | --- |
| 0 | 成功 |
| 1〜125 | 失敗（意味はコマンドによる。`grep` は見つからないと 1） |
| 126 | 見つかったが実行できない（x の権限がない） |
| 127 | コマンドが見つからない（`#!` のプログラムがないときも） |

### 引数と特別な変数

スクリプトに渡した引数は、**位置パラメータ**に入ります（[図解 Linux 6.4](../../linux/site/ch06.html#args)）。

| 変数 | 中身 |
| --- | --- |
| `$0` | スクリプトの名前（起動したときのパス） |
| `$1`、`$2`、…、`${10}` | 1 番目、2 番目、… の引数。10 番目からは `{}` で囲む |
| `$#` | 引数の個数 |
| `"$@"` | すべての引数。**1 つずつ別の単語**のまま |
| `"$*"` | すべての引数を、**1 つの文字列**につないだもの（区切りは空白） |
| `$*`、`$@`（引用符なし） | すべての引数。さらに空白で分かれる |
| `$?` | 直前のコマンドの終了ステータス |
| `$$` | シェル自身の PID |

```sh run title="位置パラメータと shift"
cat > args.sh <<'EOF'
#!/bin/sh
echo "\$0=$0  \$#=$#  \$1=$1  \$2=$2"
for a in "$@"; do echo "\"\$@\" -> [$a]"; done
for a in "$*"; do echo "\"\$*\" -> [$a]"; done
shift
echo "shift のあと: \$#=$#  \$1=$1"
EOF
chmod +x args.sh
./args.sh "my file" b c
```

`"my file"` は引用符で囲んだので 1 個の引数です。`"$@"` は 3 個のまま、`"$*"` は 1 個につながりました。

```fig layout ./args.sh "my file" b c の位置パラメータ。shift は $1 を捨てて、残りを 1 つずつ前へずらす
{
  unit: 14,
  rows: [
    { label: '最初', cells: [{ t: '$1 = my file', w: 8, kind: 'accent' }, { t: '$2 = b', w: 5, kind: 'stack' }, { t: '$3 = c', w: 5, kind: 'stack' }], note: '$# = 3' },
    { label: 'shift', cells: [{ t: '$1 = b', w: 5, kind: 'stack' }, { t: '$2 = c', w: 5, kind: 'stack' }], note: '$# = 2' },
    { label: 'shift 2', cells: [{ t: '（なし）', w: 6, kind: 'plain' }], note: 'もう一度 2 つずらすと $# = 0' },
  ],
}
```

`shift 数` は、その数だけずらします。引数の数より大きい数を指定すると、何もずらさずに 1 で終わります（bash で確かめました）。

### exit で終了ステータスを返す

スクリプトの終了ステータスは、**`exit 数`** で決めます。`exit` を書かないとき、または数を付けない `exit` は、**最後に実行したコマンドの終了ステータス**になります。

```sh run title="exit で終了ステータスを決める"
cat > check.sh <<'EOF'
#!/bin/sh
if [ $# -eq 0 ]; then
  echo "usage: $0 file" >&2
  exit 2
fi
[ -f "$1" ]
EOF
chmod +x check.sh
./check.sh; echo "引数なし: $?"
./check.sh memo.txt; echo "memo.txt: $?"
./check.sh nosuch; echo "nosuch: $?"
```

終了ステータスは 0〜255 です。bash で `exit 300` とすると、256 で割った余りの 44 になりました。

:::warn 試験の注意："$@" と "$*"
引数をそのまま別のコマンドに渡すときは `"$@"` です。`"$*"` は全部が 1 つの文字列になり、`$*` と `$@`（引用符なし）は空白を含む引数が分かれてしまいます。`$#` は個数、`$0` は**スクリプトの名前**で、1 番目の引数ではありません。
:::

## 条件とくり返し：if、test、case、for、while、until {#control}

### if は、コマンドの終了ステータスを見る

```fig graph if [ -f memo.txt ]; then … の流れ。[ は test と同じコマンドで、条件が成り立てば 0、成り立たなければ 1 で終わる。if はその終了ステータスだけを見る
{

    { id: 'if', label: 'if', sub: '条件のコマンドを実行', x: 0, y: 0, kind: 'plain' },

    { id: 'th', label: 'then の側', sub: '', x: 2, y: 0, kind: 'accent', mono: false },
    { id: 'el', label: 'else の側', sub: '', x: 2, y: 1, kind: 'ext', mono: false },
  ],

    { from: 't', to: 'el', label: '0 以外' },
  ],

```

`if` の後ろに書くのは、式ではなく**コマンド**です（[図解 Linux 6.6](../../linux/site/ch06.html#if)）。`[ 条件 ]` は `test 条件` と同じコマンドで、`[` の後ろと `]` の前に空白が要ります。形は次のとおりです。

```console
if 条件のコマンド; then
  …
elif 条件のコマンド; then
  …
else
  …
fi
```

`then` を同じ行に書くときは、前に `;` が要ります。終わりは `fi`（if を逆から書いたもの）です。

```sh run title="test の条件を確かめる"
[ -f memo.txt ]; echo "-f memo.txt: $?"
[ -d notes ]; echo "-d notes: $?"
[ -e nosuch ]; echo "-e nosuch: $?"
s=""
[ -z "$s" ]; echo "-z 空: $?"
[ -n "$s" ]; echo "-n 空: $?"
[ 10 -lt 9 ]; echo "10 -lt 9: $?"
[ abc = abc ]; echo "abc = abc: $?"
[ abc != abd ]; echo "abc != abd: $?"
```

| 条件 | 成り立つとき |
| --- | --- |
| `-e パス` | 存在する（種類は問わない） |
| `-f パス` | 通常のファイル |
| `-d パス` | ディレクトリ |
| `-r`、`-w`、`-x パス` | 読める、書ける、実行できる |
| `-s パス` | 大きさが 0 でない |
| `-z 文字列` | 空（長さ 0） |
| `-n 文字列` | 空でない |
| `文字列1 = 文字列2`、`!=` | 文字列として同じ、違う（bash の `[` では `==` も使える） |
| `数1 -eq 数2`、`-ne` | 数として等しい、等しくない |
| `-lt`、`-le`、`-gt`、`-ge` | より小さい（less than）、以下、より大きい（greater than）、以上 |
| `! 条件`、`条件 -a 条件`、`条件 -o 条件` | でない、かつ、または |

:::warn 試験の注意：数の比較は -lt、文字列の比較は =
`[ 10 < 9 ]` の `<` はリダイレクトになり、「9 というファイルから読む」になってしまいます。`\<` と書いても、それは**文字列**の比較（辞書の順）です。bash では `[ 10 \< 9 ]` が「成り立つ」（0）になりました。数は `-eq -ne -lt -le -gt -ge`、文字列は `= !=` と覚えます。変数は `"$x"` と引用符で囲みます。空の変数で `[ $x = a ]` とすると、bash は `unary operator expected` のエラーで 2 を返します。
:::

### case：パターンで分ける

```sh run title="case で答えを分けるスクリプト"
cat > yesno.sh <<'EOF'
#!/bin/sh
read -p "続けますか (y/n)? " ans
case "$ans" in
  [Yy]|[Yy]es) echo "続けます" ;;
  [Nn]*)       echo "やめます" ;;
  *)           echo "y か n で答えてください"; exit 1 ;;
esac
EOF
chmod +x yesno.sh
```

```sh run stdin="Yes\n" title="Yes と答える"
./yesno.sh
```

```sh run error stdin="maybe\n" title="maybe と答える（どれにも合わず exit 1）"
./yesno.sh
```

- 上から順に比べて、**最初に合ったもの**だけを実行する。パターンには `*`、`?`、`[ ]` が使える
- `|` で、パターンを並べられる
- 各項目の終わりは `;;`、全体の終わりは **`esac`**（case を逆から書いたもの）
- `*)` は何にでも合うので、最後に置く

**read** は標準入力から 1 行読んで変数に入れます。`read -p "文字列" 変数` は、読む前に文字列を表示します（bash では、入力が端末のときだけ表示します）。変数を 2 つ以上書くと、空白で分けて前から入れ、**残りは全部が最後の変数**に入ります。変数を書かないと、`REPLY` という変数に入ります。

```sh run stdin="Linus Benedict Torvalds\n" title="read は残りを最後の変数に入れる"
read first rest; echo "first=$first / rest=$rest"
```

### for、while、until、seq

```sh run title="for と seq"
for c in red green blue; do echo "色: $c"; done
for i in $(seq 1 3); do echo "$i 回目"; done
seq 2 2 8
seq -s , 5
seq -w 8 10
```

**seq** は数の並びを出力します。

| 書き方 | 出力 |
| --- | --- |
| `seq 5` | 1 から 5 |
| `seq 2 5` | 2 から 5 |
| `seq 1 3 10` | 1 から 10 まで 3 ずつ（1 4 7 10）。**真ん中が増分** |
| `seq 5 -1 1` | 5 から 1 へ 1 ずつ減らす |
| `seq -s , 5` | 区切りを改行から `,` に（1,2,3,4,5） |
| `seq -w 8 10` | 桁をそろえる（08 09 10） |

`while` は条件のコマンドが**成功（0）のあいだ**、`until` は**失敗（0 以外）のあいだ**くり返します。`until` は「〜になるまで」と読むと覚えやすくなります。ファイルを 1 行ずつ処理するときは、`while read 変数; do …; done < ファイル` です（[図解 Linux 6.7](../../linux/site/ch06.html#loop)）。

```sh run title="while と until は条件が逆。while read で 1 行ずつ"
i=1
while [ $i -le 3 ]; do echo "while $i"; i=$((i + 1)); done
i=1
until [ $i -gt 3 ]; do echo "until $i"; i=$((i + 1)); done
while read n; do
  if [ "$n" -ge 20 ]; then echo "20 以上: $n"; fi
done < numbers.txt
```

| 構文 | 形 |
| --- | --- |
| for | `for 変数 in 単語…; do …; done` |
| while | `while 条件のコマンド; do …; done`（成功のあいだ） |
| until | `until 条件のコマンド; do …; done`（失敗のあいだ） |
| case | `case 単語 in パターン) …;; esac` |
| ループを抜ける、次の回へ | `break`、`continue` |

## 関数の 2 つの書き方と、bash -x・bash -v {#function}

### function キーワードと 名前()

bash の関数には、2 つの書き方があります。

```sh run title="関数の 2 つの書き方"
function hello {
  echo "hello, $1"
}
bye() {
  echo "bye, $1（引数 $# 個）"
  return 3
}
hello you
bye you me; echo "bye の終了ステータス: $?"
```

| 書き方 | 説明 |
| --- | --- |
| `名前() { コマンド; }` | POSIX の書き方。どのシェルでも使える |
| `function 名前 { コマンド; }` | bash の書き方。`function 名前() { …; }` と `()` を付けてもよい |

- 関数の中の `$1`、`$#`、`"$@"` は、**関数に渡した引数**。`$0` はスクリプトの名前のまま
- `return 数` で、関数の終了ステータスを返す。書かなければ、最後のコマンドの終了ステータス。`exit` を書くと、関数ではなく**シェル（スクリプト）全体**が終わる
- 関数は、呼ぶより前に定義しておく
- `{` の後ろには空白が、`}` の前には `;` か改行が要る。`hello() {echo hi;}` や `hello() { echo hi }` は、bash では構文エラー（Debian 12 で確かめました）
- 関数の定義は、alias と同じく、~/.bashrc に書けば毎回使える

:::note function は POSIX のシェルにはない
Debian の /bin/sh（dash）で `function f { echo F; }` を実行すると、`Syntax error: "}" unexpected` になりました。`#!/bin/sh` のスクリプトでは `名前() { …; }` を使います。小さな Linux の `sh` は、どちらの書き方も受け付けます。
:::

### bash -x、bash -v、set -x：スクリプトのデバッグ

スクリプトが思ったとおりに動かないときは、実行の様子を表示させます。

```sh run title="sh -x：変数を置き換えた後のコマンドを + 付きで表示"
sh -x ./args.sh a "b c"
```

`+` の行が、実際に実行したコマンドです（標準エラー出力に出ます）。本物の bash では `bash -x スクリプト` です（bash では `+ for a in "$@"` のように、ループの行にも `+` が付きます）。**`-v`** は、置き換える前の、**読んだ行をそのまま**表示します。Debian 12 の bash で、両方を比べました。

```console
$ cat v.sh
#!/bin/bash
# comment
n=$1
echo "n=$n"
$ bash -v v.sh 3
#!/bin/bash
# comment
n=$1
echo "n=$n"
n=3
$ bash -x v.sh 3
+ n=3
+ echo n=3
n=3
```

`-v` はコメントも含めて書いたとおりに、`-x` は `$1` や `$n` を値に置き換えた形で表示しています。両方を付けた `bash -xv` もできます。

スクリプトの一部だけを追いたいときは、その範囲を **`set -x`** と **`set +x`** で挟みます（`-` で始めて、`+` で止める）。

```sh run title="set -x から set +x までを追う"
set -x
n=$(wc -l < fruits.txt)
echo "$n 行"
set +x
```

| 書き方 | 表示するもの |
| --- | --- |
| `bash -x スクリプト` | 実行するコマンドを、展開した後の形で、`+` 付きで |
| `bash -v スクリプト` | 読んだ行を、展開する前の形のまま |
| `set -x` / `set +x` | スクリプトの中で、`-x` を始める / 止める（`set -o xtrace` も同じ） |
| `set -v` / `set +v` | スクリプトの中で、`-v` を始める / 止める |
| `bash -n スクリプト` | 実行せずに、構文の誤りだけを調べる |

:::tip -x は eXecute、-v は Verbose
`-x` は「実行（execute）するもの」を、`-v` は「読んだもの全部（verbose、くどく）」を表示する、と覚えます。試験では「変数の値が展開されて表示されるのはどちらか」が問われます。答えは `-x` です。
:::

:::key まとめ
- ログインシェル：/etc/profile → ~/.bash_profile、~/.bash_login、~/.profile の**最初の 1 つだけ** → 終了時に ~/.bash_logout
- 対話的な非ログインシェル：/etc/bash.bashrc（Red Hat 系は /etc/bashrc）と ~/.bashrc。~/.bashrc はログインシェルでも ~/.profile や ~/.bash_profile から `.` で読まれる
- `source ファイル` と `. ファイル` は、いまのシェルで実行する。設定ファイルの読み直しに使う
- `alias 名前='コマンド'`、`unalias 名前`（`-a` で全部）。別名を避けるのは `\名前` か `command 名前`。bash のスクリプトでは alias は展開されない
- PATH は `PATH=$PATH:$HOME/bin`（区切りは `:`）。子にも渡すなら `export`
- `A ; B` はいつでも、`A && B` は A が成功したら、`A || B` は A が失敗したら B
- `#!` はカーネルが読む。`./スクリプト` には x の権限（`chmod +x`）。権限がなくても `bash スクリプト` と `source` は動く。126 は実行できない、127 は見つからない
- `$0` 名前、`$1` 引数、`$#` 個数、`"$@"` 1 つずつ、`"$*"` 1 つにつなぐ、`$?` 直前の終了ステータス、`shift` で 1 つずらす。`exit` だけなら最後のコマンドの終了ステータス
- `[ ]` の数の比較は `-eq -ne -lt -le -gt -ge`、文字列は `= !=`、空は `-z`、空でないは `-n`、ファイルは `-f`、ディレクトリは `-d`、存在は `-e`
- `if …; then …; elif …; else …; fi`、`case … in パターン) …;; esac`、`while` は成功のあいだ、`until` は失敗のあいだ。`seq 最初 増分 最後`
- 関数は `名前() { …; }` と `function 名前 { …; }`。`return` で終了ステータス
- `bash -x` は展開後のコマンドを `+` 付きで、`bash -v` は読んだ行をそのまま表示。途中からは `set -x`、止めるのは `set +x`
:::

### 1.06.1 シェル環境のカスタマイズ

:::q 1.06.1-01 single
bash がログインシェルとして起動したとき、最初に読み込むシステム全体の設定ファイルはどれか。

- [x] `/etc/profile`
- [ ] `/etc/bashrc`
- [ ] `~/.bash_profile`
- [ ] `/etc/environment`
:::why
ログインシェルの bash は、まず `/etc/profile` を読みます（[ログインシェルと非ログインシェル](#startup)）。

- `/etc/bash.bashrc` は Debian 系で対話的なシェルが読む全体のファイルです。ログインシェルでは /etc/profile の中から読まれるので、最初ではありません
- `/etc/bashrc` は Red Hat 系で ~/.bashrc から読まれるファイルです
- `~/.bash_profile` はユーザーごとのファイルで、/etc/profile の後に読まれます
- `/etc/environment` は bash が読むファイルではありません（ログインの仕組み PAM が読みます）
:::
:::

- [ ] `~/.bash_profile` と `~/.bash_login`
- [ ] 3 つすべてを、`~/.bash_profile`、`~/.bash_login`、`~/.profile` の順に
- [ ] 3 つすべてを、`~/.profile`、`~/.bash_login`、`~/.bash_profile` の順に
- [ ] `~/.profile` だけ
:::why
ログインシェルの bash は、`~/.bash_profile`、`~/.bash_login`、`~/.profile` の順に探して、**最初に見つかった 1 つだけ**を読みます。3 つあれば `~/.bash_profile` だけです（[ログインシェルと非ログインシェル](#startup)）。全部を読むことはありません。
:::
:::

:::q 1.06.1-03 multi
Debian 系のディストリビューションで、ログイン後に端末で `bash` と入力して起動した対話的な非ログインシェルが読み込むファイルを 2 つ選択してください。
- [x] `/etc/bash.bashrc`
- [ ] `/etc/profile`
- [x] `~/.bashrc`
- [ ] `~/.profile`
- [ ] `~/.bash_logout`
:::why
対話的な非ログインシェルは、`/etc/bash.bashrc` と `~/.bashrc` を読みます（[ログインシェルと非ログインシェル](#startup)）。Docker の Debian 12 で `su alice`（`-` なし）を実行したときも、この 2 つだけが読まれました。

- `/etc/profile` と `~/.profile` は、ログインシェルだけが読みます
- `~/.bash_logout` は、ログインシェルが終わるときに読みます
:::
:::

:::q 1.06.1-04 single
ログインシェルを終了するときに bash が実行するファイルはどれか。
- [ ] `~/.bashrc`
- [ ] `~/.bash_exit`
- [x] `~/.bash_logout`
- [ ] `/etc/logout`
- [ ] `~/.logout`
:::why
ログインシェルが終わるとき、bash は `~/.bash_logout` を読みます（[ログインシェルと非ログインシェル](#startup)）。Debian では、画面を消す設定が最初から入っています。`~/.bash_exit`、`/etc/logout`、`~/.logout` は bash が読むファイルではありません（`~/.logout` は csh 系のシェルの名前です）。`~/.bashrc` は起動のときに読むファイルです。

:::

:::q 1.06.1-05 single

- [x] `~/.bash_login` だけ
- [ ] `~/.bash_login` と `~/.profile`

:::why
探す順は `~/.bash_profile` → `~/.bash_login` → `~/.profile` です。`~/.bash_profile` がないので、次の `~/.bash_login` が見つかり、それだけを読みます（[ログインシェルと非ログインシェル](#startup)）。Debian 12 で確かめたときも、`~/.profile` は読まれませんでした。
:::

:::q 1.06.1-06 single

:::q 1.06.1-12 single

:::q 1.06.1-13 single

- [x] `PATH=$PATH:$HOME/bin`
- [ ] `PATH=$PATH;$HOME/bin`

- `PATH = …` は、`PATH` というコマンドに `=` などを渡す意味になります
- `;` はコマンドの区切りなので、`$HOME/bin` を実行しようとします
- `PATH=$HOME/bin` は追加ではなく置き換えです。`ls` などが見つからなくなります

:::q 1.06.1-15 single
`コマンド1 && コマンド2` と入力したとき、コマンド2 が実行されるのはどの場合か。

:::q 1.06.1-16 single

- [ ] `OK` と `NG` と `END`

:::

:::q 1.06.1-17 multi
コマンドをつなぐ記号の説明として正しいものを 2 つ選択してください。
- [x] `A ; B` は、A が失敗しても B を実行する
- [ ] `A && B` は、A が失敗したときだけ B を実行する
- [x] `A || B` は、A が成功したら B を実行しない
- [ ] `A ; B` は、A と B を同時に実行する
- [ ] `A || B` は、A の標準出力を B の標準入力につなぐ
:::why
`;` は A の結果にかかわらず、A が終わってから B を実行します。`||` は A が失敗したときだけ B を実行するので、A が成功すれば B は実行しません（[; && ||](#alias)）。

- `&&` は A が**成功**したときだけ B を実行します
- 同時に実行するのは `A & B` です
- 標準出力を標準入力につなぐのは `|`（パイプ、1 本）です
:::
:::

:::q 1.06.1-18 single

### 1.06.2 シェルスクリプト

:::q 1.06.2-01 single
スクリプトの 1 行目に書く `#!/bin/bash` の説明として正しいものはどれか。
- [ ] bash が読むコメントで、実行には何の影響もない
- [x] `./スクリプト` で実行したとき、カーネルがこの行を読んで `/bin/bash` を起動し、スクリプトを読ませる
- [ ] スクリプトに実行権限を与える
- [ ] スクリプトを `/bin/bash` にコピーしてから実行する
:::why
`#!`（シバン）はカーネルが読みます。`./スクリプト` で実行すると、カーネルは `#!` の後ろのプログラムを起動して、スクリプトのパスを渡します（[3 つの実行のしかた](#script)、[図解 Linux 6.1](../../linux/site/ch06.html#script)）。`bash スクリプト` で実行したときは、1 行目は単なるコメントです。実行権限は `chmod` で与えます。
:::
:::

:::q 1.06.2-02 single
次のように表示された。スクリプトを `./backup.sh` で実行できるようにするコマンドとして正しいものはどれか。

```text
-rw-r--r-- 1 you you 120 Apr  1 09:00 backup.sh
$ ./backup.sh
bash: ./backup.sh: Permission denied
```
- [ ] `chown you backup.sh`
- [ ] `chmod +r backup.sh`
- [x] `chmod u+x backup.sh`
- [ ] `chmod 644 backup.sh`
- [ ] `export backup.sh`
:::why
`./スクリプト` で実行するには、x（実行）の権限が要ります。`chmod u+x`（`chmod +x`、`chmod 755` なども）で付けます（[3 つの実行のしかた](#script)）。

- 持ち主はすでに you なので、`chown you` では何も変わりません
- r（読み取り）はすでにあります
- `chmod 644` は `-rw-r--r--` で、いまと同じです
- `export` は変数を環境変数にするコマンドです
:::
:::

:::q 1.06.2-03 multi

- `./test.sh` と `exec ./test.sh` は、ファイルをプログラムとして実行するので x の権限が要り、`Permission denied`（126）になります
- `test.sh` だけでは、PATH の中を探すので見つかりません（127）。なお `test` という組み込みコマンドとは別の名前です

:::q 1.06.2-04 fill

- [ ] `[ ! -e /etc/passwd ]`
:::why
`-f` は通常のファイル、`-e` は存在する（種類は問わない）ときに成り立ちます（[if は、コマンドの終了ステータスを見る](#control)）。

- `-d` はディレクトリのときだけです
- `-z` は文字列が空のときで、`/etc/passwd` という文字列は空ではありません
- `! -e` は「存在しない」です
:::
:::

:::q 1.06.2-14 single
`[ -z "$name" ]` が成り立つのはどの場合か。
- [x] 変数 `name` が空か、設定されていない
- [ ] 変数 `name` が空でない
- [ ] `name` という名前のファイルの大きさが 0
- [ ] 変数 `name` の値が数の 0
:::why
`-z` は文字列の長さが 0（zero）のときに成り立ちます。設定されていない変数も `"$name"` で空の文字列になるので成り立ちます（[if は、コマンドの終了ステータスを見る](#control)）。空でないときに成り立つのは `-n` です。ファイルの大きさを調べるのは `-s`（0 でないとき）です。
:::
:::

:::q 1.06.2-15 multi
変数 `a` の値が、数として変数 `b` の値より小さいときに成り立つ条件を 2 つ選択してください。
- [x] `[ "$a" -lt "$b" ]`
- [x] `test "$a" -lt "$b"`
- [ ] `[ "$a" < "$b" ]`
- [ ] `[ "$a" -gt "$b" ]`
- [ ] `[ "$a" -lt "$b"]`
:::why
数の「より小さい」は `-lt`（less than）です。`[ … ]` と `test …` は同じです（[if は、コマンドの終了ステータスを見る](#control)）。

- `<` はリダイレクトになり、`$b` という名前のファイルから読もうとします
- `-gt` は「より大きい」です
- `"$b"]` のように `]` の前に空白がないと、最後の引数が `]` にならず、エラーになります
:::
:::

:::q 1.06.2-16 single
変数 `ans` の値が文字列 `yes` と等しいかを調べる条件として正しいものはどれか。
- [x] `[ "$ans" = "yes" ]`
- [ ] `[ "$ans" -eq "yes" ]`
- [ ] `[ "$ans" := "yes" ]`
- [ ] `[ $ans -z yes ]`
:::why
文字列が等しいかは `=` で調べます（bash の `[` では `==` も使えます）。`-eq` は**数**の比較で、`yes` は数ではないので `integer expression expected` のエラーになります（[if は、コマンドの終了ステータスを見る](#control)）。`:=` という比較はありません。`-z` は 1 つの文字列が空かを調べるものです。
:::
:::

:::q 1.06.2-17 single
bash の if 文の書き方として正しいものはどれか。
- [ ] `if [ -f memo.txt ] then echo ok; fi`
- [x] `if [ -f memo.txt ]; then echo ok; fi`
- [ ] `if [ -f memo.txt ]; then echo ok; endif`
- [ ] `if [-f memo.txt]; then echo ok; fi`
- [ ] `if [ -f memo.txt ]; do echo ok; done`
:::why
`if 条件; then …; fi` です。`then` を同じ行に書くときは、前に `;` が要ります（[if は、コマンドの終了ステータスを見る](#control)）。

- 1 つ目は `then` の前の `;` がありません（`[` の引数になってしまいます）
- `endif` ではなく `fi` で閉じます
- `[-f` のように空白がないと、`[-f` というコマンドを探してしまいます
- `do … done` はループの書き方です
:::
:::

:::q 1.06.2-18 single
次のスクリプトを `./kind.sh apple.txt` で実行したときの出力はどれか。

```text
#!/bin/bash
case "$1" in
  *.sh)  echo script ;;
  a*)    echo a ;;
  *.txt) echo text ;;
  *)     echo other ;;
esac
```
- [ ] `text`
- [x] `a`
- [ ] `a` と `text`
- [ ] `other`
:::why
`case` は上から順に比べて、**最初に合ったもの**だけを実行します。`apple.txt` は `a*` に先に合うので、`a` だけを表示します（[case：パターンで分ける](#control)。Debian 12 の bash で確かめました）。`*.txt` にも合いますが、そこまで比べません。
:::
:::

:::q 1.06.2-19 fill
case 文の終わりを示す単語を入力してください。

```text
case "$1" in
  start) echo start ;;
  stop)  echo stop ;;
____
```
= esac
:::why
`case` は `esac`（case を逆から書いたもの）で閉じます。`if` を `fi` で閉じるのと同じ考え方です（[case：パターンで分ける](#control)）。各項目の終わりは `;;` です。
:::

:::q 1.06.2-20 single
次のコマンドの出力として正しいものはどれか。

```text
$ for i in $(seq 1 3 10); do echo -n "$i "; done
```
- [ ] `1 2 3 `
- [x] `1 4 7 10 `
- [ ] `1 3 5 7 9 `
- [ ] `3 6 9 `
:::why
`seq 最初 増分 最後` なので、`seq 1 3 10` は 1 から 10 まで 3 ずつ、`1 4 7 10` です（[for、while、until、seq](#control)）。**真ん中が増分**です。`echo -n` は改行しません。
:::
:::

:::q 1.06.2-21 single
`seq` で、1 から 5 までの数を `1,2,3,4,5` のように 1 行にカンマ区切りで出力したい。正しいものはどれか。
- [ ] `seq -w , 5`
- [x] `seq -s , 5`
- [ ] `seq 1 , 5`
- [ ] `seq -f , 5`
:::why
`-s 文字列` は、数の区切りを改行からその文字列に変えます（[for、while、until、seq](#control)）。`-w` は桁をそろえる（08 09 10）、`-f` は printf の書式（`seq -f "%02g" 3` で 01 02 03）を指定するオプションです。`seq 1 , 5` は `,` が数ではないのでエラーです。
:::
:::

:::q 1.06.2-22 single
`until 条件のコマンド; do …; done` の説明として正しいものはどれか。
- [ ] 条件のコマンドが成功（0）のあいだ、くり返す
- [x] 条件のコマンドが失敗（0 以外）のあいだ、くり返す
- [ ] 条件のコマンドの結果にかかわらず、1 回だけ実行する
- [ ] 条件のコマンドが出力した行の数だけ、くり返す
:::why
`until` は条件が成り立つ**まで**、つまり失敗のあいだくり返します。成功のあいだくり返すのは `while` です（[for、while、until、seq](#control)）。
:::
:::

:::q 1.06.2-23 single
次のスクリプトの出力として正しいものはどれか。

```text
#!/bin/bash
i=5
while [ $i -gt 2 ]; do
  echo $i
  i=$((i - 1))
done
```
- [ ] `5`、`4`、`3`、`2`
- [x] `5`、`4`、`3`
- [ ] `4`、`3`
- [ ] 何も表示しない
:::why
`$i` が 2 より大きい（`-gt`）あいだ、表示して 1 減らします。5、4、3 を表示したあと `i` が 2 になり、`[ 2 -gt 2 ]` が成り立たないので終わります（[for、while、until、seq](#control)）。

:::q 1.06.2-24 single
次のコマンドを実行したとき、変数 `y` の値はどれか。

```text
$ echo "red green blue" | { read x y; echo "$y"; }
```
- [ ] `green`
- [x] `green blue`
- [ ] `blue`
- [ ] 空
:::why
`read` は空白で分けて前から変数に入れ、**残りは全部が最後の変数**に入ります。`x` は `red`、`y` は `green blue` です（[case：パターンで分ける](#control) の read）。

:::q 1.06.2-25 multi
bash で関数を定義する書き方として正しいものを 2 つ選択してください。
- [x] `function hello { echo hi; }`
- [x] `hello() { echo hi; }`
- [ ] `hello { echo hi; }`
- [ ] `hello() {echo hi;}`
- [ ] `def hello() { echo hi; }`
:::why
bash の関数は `名前() { …; }` と `function 名前 { …; }` の 2 通りで書けます（[function キーワードと 名前()](#function)）。

- `hello { …; }` は `()` も `function` もないので、構文エラーです
- `{echo` のように `{` の直後に空白がないと、`{echo` が 1 つの単語になり、構文エラーです（Debian 12 で確かめました）
- `def` は Python などの書き方です

:::q 1.06.2-26 single
`bash -x script.sh` で実行したときの動作として正しいものはどれか。

- [ ] スクリプトの各行を、読んだとおりのまま表示しながら実行する
- [x] 変数などを展開した後のコマンドを、先頭に `+` を付けて表示しながら実行する

:::q 1.06.2-29 multi

- [x] ファイルはあるが実行権限がなく実行できないとき、終了ステータスは 126 になる
