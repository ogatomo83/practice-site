## カーネルモジュール：ドライバはあとから足せる {#modules}

装置を動かすプログラムを**ドライバ**と呼びます。Linux のドライバの多くは、カーネル本体に入っているのではなく、**カーネルモジュール**（`.ko` のファイル）として別になっています。必要になったときに読み込み、要らなくなったら外せます。ファイルシステム（xfs、vfat など）も、モジュールになっていることが多いものです。

モジュールのファイルは、`/lib/modules/カーネルのリリース番号/` の下にあります。リリース番号は `uname -r` で見られます。

```sh run title="カーネルのリリース番号"
uname -r
```

本物の Linux なら、`/lib/modules/6.8.0-…/kernel/` の下に、装置の種類ごとのディレクトリがあり、そこに `.ko` のファイルが並んでいます。この小さな Linux にはモジュールの仕組みがないので、ここからのコマンドは実行しない例で見ます。

```fig graph modprobe は、依存の表（modules.dep）を見て、先に要るモジュールから順に読み込む。insmod は、渡された 1 つのファイルを読み込むだけ
{

  nodes: [
    { id: 'mp', label: 'modprobe xfs', sub: '名前で指定', x: 0, y: 0, kind: 'accent' },
```

モジュールを扱うコマンドは 4 つです。

```console
# lsmod
Module                  Size  Used by
xfs                  2060288  1
libcrc32c              12288  2 xfs,nf_conntrack
usb_storage            86016  0
# modprobe vfat              ← 名前で。依存するモジュール（fat）も一緒に読み込む
# modprobe -r vfat           ← 外す（使われなくなった依存も外す）
# insmod /lib/modules/$(uname -r)/kernel/fs/fat/fat.ko   ← ファイルのパスで。依存は解決しない
# rmmod usb_storage          ← 外す
```

`lsmod` の 3 列は、モジュールの名前、大きさ（バイト）、**使われている数と、使っているモジュールの名前**です。上の例の `libcrc32c` は、`xfs` と `nf_conntrack` の 2 つから使われています。使われている数が 0 でないモジュールは、外せません。`lsmod` は、`/proc/modules` を読みやすく整えて表示しています。

| コマンド | すること | 指定のしかた | 依存の解決 |
| --- | --- | --- | --- |
| `lsmod` | 読み込まれているモジュールの一覧 | 引数なし | — |
| `modprobe 名前` | 読み込む | モジュールの**名前** | **する** |
| `modprobe -r 名前` | 外す | 名前 | する（要らなくなった依存も外す） |
| `insmod ファイル` | 読み込む | `.ko` の**ファイルのパス** | しない |
| `rmmod 名前` | 外す | 名前 | しない |
| `modinfo 名前` | モジュールの説明、作者、引数、依存を表示 | 名前 | — |

:::warn 試験の注意：modprobe と insmod
- **依存関係を解決してくれるのは `modprobe`**。ふだんはこちらを使う。`insmod` は依存を見ないので、先に要るモジュールがないと失敗する
- 外すのは `rmmod` と **`modprobe -r`**。`insmod -r` や `lsmod -r` というオプションはない
- `modprobe` は名前、`insmod` はファイルのパス。`insmod xfs` のように名前だけでは動かない
:::

:::deep 4 つのコマンドの正体
Debian でも Red Hat 系でも、`lsmod`、`modprobe`、`insmod`、`rmmod` は、どれも `kmod` という 1 つのプログラムへのシンボリックリンクです（`ls -l /sbin/lsmod` で `-> /bin/kmod` と見えます）。呼ばれた名前で動きを変える作りで、図解 Linux 19 章の busybox と同じ考え方です。`modprobe` が使う依存の表 `modules.dep` は、`depmod` コマンドが `/lib/modules/$(uname -r)/` に作ります。
:::

## 装置を調べる：/sys、/proc、/dev と lspci・lsusb {#devices}


**sysfs**（`/sys`）は、カーネルが知っている装置、バス、ドライバのつながりを、ディレクトリの木で見せるファイルシステムです。`/proc` がプロセスの情報から始まったのに対して、`/sys` は装置の情報のために作られました。

```sh run title="/sys の中と、ディスクの情報"
ls /sys
ls /sys/block
cat /sys/block/sda/size
cat /sys/block/sda/queue/rotational
```

`size` はセクタ（512 バイト）の数です。`rotational` は、ディスクが回転する装置かどうかで、**1 なら HDD、0 なら SSD** などの回転しない装置です。この小さな Linux の `sda` は 1（HDD のふり）です。

`/proc` にも、ハードウェアの情報があります。

```sh run title="/proc の CPU の情報"
head -4 /proc/cpuinfo
```

| ファイル | 中身 |
| --- | --- |
| `/proc/cpuinfo` | CPU の種類、数、機能 |
| `/proc/meminfo` | メモリの量と使い方（`free` の元） |
| `/proc/interrupts` | 装置ごとの割り込み（IRQ）の番号と回数 |
| `/proc/ioports` | 装置が使う I/O ポートの番地 |
| `/proc/modules` | 読み込まれているモジュール（`lsmod` の元） |
| `/proc/partitions` | カーネルが認識しているディスクとパーティション |
| `/proc/mounts` | いまのマウントの一覧 |
| `/proc/swaps` | 使っているスワップ |

`/dev` には、装置を開くための**デバイスファイル**が並びます。先頭の `c` はキャラクタデバイス、`b` は**ブロックデバイス**（ディスクのように、ブロック単位で読み書きする装置）です。

```sh run title="デバイスファイルの種類"
ls -l /dev/null /dev/zero /dev/tty
```

### PCI と USB の装置を一覧する

基板の上の装置（ネットワークカード、ディスクのコントローラ、グラフィックなど）の多くは **PCI**（PCI Express）でつながっています。その一覧は `lspci`、USB の装置の一覧は `lsusb` です。

```console
$ lspci
00:00.0 Host bridge: Apple Inc. Device 1a05
00:01.0 Ethernet controller: Red Hat, Inc. Virtio 1.0 network device (rev 01)
00:05.0 Communication controller: Red Hat, Inc. Virtio 1.0 console (rev 01)
$ lsusb
Bus 002 Device 001: ID 1d6b:0003 Linux Foundation 3.0 root hub
Bus 001 Device 001: ID 1d6b:0002 Linux Foundation 2.0 root hub
```

（Docker の中の仮想マシンで実行したものです。本物の PC では、もっと多くの行が出ます）

| オプション | lspci | lsusb |
| --- | --- | --- |
| `-v` | 詳しく表示（`-vv` でもっと詳しく） | 詳しく表示 |
| `-t` | バスの木の形で表示 | **つながりを木の形で表示** |
| `-k` | 各装置を扱うカーネルドライバを表示 | — |
| `-n` | 名前でなく番号（ベンダー ID など）で表示 | — |
| `-s` | 指定した場所の装置だけ | 指定したバス・装置番号だけ |
| `-d` | — | 指定したベンダー ID:製品 ID だけ |

`ID 1d6b:0003` の左がベンダー（作った会社）の番号、右が製品の番号です。

## udev と dbus、記憶装置の種類 {#udev}

USB メモリを挿すと、`/dev/sdb` が現れ、デスクトップにアイコンが出ます。この流れを 3 つの部品が受け持ちます。


| 部品 | 役目 |
| --- | --- |
| **sysfs**（`/sys`） | カーネルが認識した装置を、ファイルの木として見せる |
| **udev** | カーネルからの通知（**uevent**）を受け取り、**規則に従って `/dev` のデバイスファイルを整える**（名前、権限、`/dev/disk/by-uuid/…` などのリンク）。デーモンは `systemd-udevd` |
| **dbus** | プロセスどうしがメッセージを送り合う仕組み（**プロセス間通信のバス**）。装置が増えた、ネットワークがつながった、などをデスクトップのプログラムに伝える |

udev の規則は、`/lib/udev/rules.d/`（Red Hat 系は `/usr/lib/udev/rules.d/`。パッケージが置く）と、**`/etc/udev/rules.d/`**（管理者が書く。同じ名前なら、こちらが優先）にあります。`udevadm monitor` で、届く uevent を眺められます。

起動したときにすでにつながっている装置は、udev が起動の途中でまとめて処理します（コールドプラグ）。動いている途中で抜き差しする USB 機器は、そのたびに uevent が届きます（ホットプラグ）。どちらも、デバイスファイルを作るのは udev の仕事で、`mknod` を手で打つことはまずありません。

### HDD、SSD、光学ドライブ

| 種類 | 仕組み | 特徴 | デバイスファイルの例 |
| --- | --- | --- | --- |
| **HDD** | 回転する円盤（プラッタ）に磁気で記録し、ヘッドを動かして読む | 容量あたりが安い。ヘッドを動かす待ち（シーク）があり、ばらばらの場所を読むと遅い | `/dev/sda`（SATA・SAS・USB） |
| **SSD** | フラッシュメモリ。動く部品がない | ランダムな読み書きが速い。書き換えの回数に上限があり、空いた場所をまとめて知らせる **TRIM**（`fstrim`）を使う | `/dev/sda`（SATA）、`/dev/nvme0n1`（NVMe） |
| **光学ドライブ** | CD・DVD・Blu-ray をレーザーで読む | ファイルシステムは ISO 9660 や UDF | **`/dev/sr0`**（`/dev/cdrom` はその別名のリンク） |

ディスクの名前は、`/dev/sd` + 見つかった順の英字（`a`、`b`…）+ パーティションの番号（`1`、`2`…）です。2 台目のディスクの 3 番目のパーティションは `/dev/sdb3` です。NVMe の SSD は `/dev/nvme0n1` がディスク、`/dev/nvme0n1p1` がその 1 番目のパーティションと、`p` が入ります。仮想マシンでは `/dev/vda`（virtio）もよく見ます。

`sda`、`sdb` の英字は、カーネルが装置を見つけた順に付きます。ディスクを足したり、USB メモリを挿したまま起動したりすると、順番が入れ替わることがあります。だから `/etc/fstab` には、`/dev/sdb1` ではなく **UUID やラベル**で書くのが勧められます（[5.12](#fstab)）。

## MBR と GPT：パーティション表の 2 つの形 {#mbr-gpt}

1 台のディスクを、いくつかの区画に分けたものを**パーティション**と呼びます。どこからどこまでが何番のパーティションかを書いた表（**パーティション表**）は、ディスクの先頭に置かれます。その形には、古い **MBR** と新しい **GPT** の 2 つがあります。

```fig layout MBR のディスク。先頭 512 バイトに表があり、基本パーティションは 4 つまで。それ以上は、1 つを拡張パーティションにして、その中に論理パーティションを作る
{
  unit: 28,
  rows: [
    { label: 'ディスク', cells: [
      { t: 'MBR', w: 2, kind: 'accent' },
      { t: 'sda1 基本', w: 5, kind: 'stack' },
      { t: 'sda2 基本', w: 5, kind: 'stack' },
      { t: 'sda3 拡張パーティション', w: 13, kind: 'heap' },
    ] },
    { label: 'sda3 の中', cells: [
      { t: '', w: 12, kind: 'empty' },
      { t: 'sda5 論理', w: 6, kind: 'static' },
      { t: 'sda6 論理', w: 6, kind: 'static' },
      { t: '…', w: 1, kind: 'empty' },
    ] },
    { label: 'MBR の 512 B', cells: [
      { t: 'ブートローダ 446 B', w: 16, kind: 'plain' },
      { t: '表 64 B（16 B × 4）', w: 7, kind: 'accent' },
      { t: '署名 2 B', w: 2, kind: 'static' },
    ] },
  ],
}
```

**MBR**（Master Boot Record）は、ディスクの最初の 512 バイトです。ブートローダの最初の部分（446 バイト）、パーティション表（16 バイト × 4 個 = 64 バイト）、終わりの印（2 バイト、`55 AA`）が入っています。表の枠が 4 つしかないので、**基本パーティションは 4 つまで**です。

それより多く分けたいときは、4 つのうちの 1 つを**拡張パーティション**にし、その中に**論理パーティション**を作ります。拡張パーティションは「入れ物」で、それ自体にはファイルシステムを作りません。**論理パーティションの番号は、5 から**始まります（1〜4 は基本と拡張のための番号）。

**GPT**（GUID Partition Table）は、UEFI と一緒に決められた新しい形です。

```fig layout GPT のディスク。先頭に保護用の MBR、次に GPT のヘッダと表。末尾にヘッダと表の控えがある
{
  unit: 28,
  rows: [
    { label: 'ディスク', cells: [
      { t: '保護 MBR', w: 3, kind: 'pad' },
      { t: 'ヘッダ', w: 2, kind: 'accent' },
      { t: '表 128 個', w: 3, kind: 'accent' },
      { t: 'sda1', w: 4, kind: 'stack' },
      { t: 'sda2', w: 4, kind: 'stack' },
      { t: 'sda3 …', w: 5, kind: 'stack' },
      { t: '表の控え', w: 3, kind: 'static' },
      { t: '控え', w: 2, kind: 'static' },
    ] },
  ],
}
```

| | MBR | GPT |
| --- | --- | --- |
| 表の場所 | 先頭 512 バイト | 先頭（保護 MBR の次）と、**末尾に控え** |
| パーティションの数 | 基本 4 つまで（拡張 + 論理で増やす） | **既定で 128 個**。基本・拡張・論理の区別がない |
| 扱えるディスクの大きさ | **2 TiB まで**（512 バイトのセクタのとき） | 2 TiB を超えられる（事実上、制限なし） |
| パーティションの識別 | 1 バイトの種類の番号（`83` Linux、`82` スワップ など） | GUID（長い番号）。パーティションごとにも UUID がある |
| 主な起動の方式 | BIOS | **UEFI** |

先頭の**保護 MBR** は、GPT を知らない古い道具が「空のディスク」と思って上書きしないように、「ディスク全体が使用中」と書いた見かけだけの MBR です。

### UEFI と ESP

**UEFI** は、BIOS に代わるファームウェアです（[図解 Linux 17.1](../../linux/site/ch17.html#boot)）。BIOS は MBR の 446 バイトにあるブートローダを実行しましたが、UEFI は**ファイルシステムを読んで、ブートローダのファイル（`.efi`）を実行します**。その置き場所が **ESP**（EFI System Partition）です。

| 項目 | ESP |
| --- | --- |
| ファイルシステム | **FAT**（FAT32。Linux での種類の名前は `vfat`） |
| マウントする場所 | **`/boot/efi`** がふつう |
| 中身 | `EFI/debian/grubx64.efi` のようなブートローダのファイル |
| 大きさ | 数百 MiB（100〜550 MiB ほど） |
| gdisk の種類のコード | `EF00` |

「BIOS と MBR」「UEFI と GPT」が典型の組み合わせです。ESP は UEFI のためのもので、ファイルシステムは ext4 ではなく **FAT**（vfat）です。GPT には拡張パーティションも論理パーティションもありません。

## fdisk・gdisk・parted：パーティションを切る {#partition-tools}

パーティション表を編集するコマンドは 3 つです。どれも root で、ディスクのデバイスファイル（`/dev/sdb` など。パーティションの `/dev/sdb1` ではない）を渡します。

| コマンド | 扱える表 | 書き込むとき |
| --- | --- | --- |
| **fdisk** | MBR（新しい版は GPT も） | 対話の最後に `w` |
| **gdisk** | **GPT**（fdisk に似た操作の GPT 版） | 対話の最後に `w` |
| **parted** | MBR と GPT の両方 | **コマンドごとに、すぐ書き込む** |

### fdisk

`fdisk -l` は、パーティション表を表示して終わります。次は、1 GiB のディスクのイメージに、基本 2 つ、拡張 1 つ、その中に論理 1 つを作り、論理パーティションの種類をスワップ（82）にしたものです（Debian 12 の Docker で実行）。

```console
# fdisk -l /dev/sdb
Disk /dev/sdb: 1 GiB, 1073741824 bytes, 2097152 sectors
Units: sectors of 1 * 512 = 512 bytes
Sector size (logical/physical): 512 bytes / 512 bytes
I/O size (minimum/optimal): 512 bytes / 512 bytes
Disklabel type: dos
Disk identifier: 0x3ce4a3f2

Device     Boot   Start     End Sectors  Size Id Type
/dev/sdb1          2048  411647  409600  200M 83 Linux
/dev/sdb2        411648 1026047  614400  300M 83 Linux
/dev/sdb3       1026048 2097151 1071104  523M  5 Extended
/dev/sdb5       1028096 1232895  204800  100M 82 Linux swap / Solaris
```

`Disklabel type: dos` が MBR のことです。拡張パーティション（`sdb3`、Id `5`）の中の論理パーティションが、`sdb4` ではなく **`sdb5`** になっています。

`fdisk /dev/sdb` と引数にディスクだけを渡すと、対話になります。1 文字のコマンドを打ちます。

| コマンド | すること |
| --- | --- |
| `m` | メニュー（使えるコマンドの一覧）を表示 |
| `p` | パーティション表を表示（print） |
| `n` | 新しいパーティションを作る。基本（`p`）か拡張（`e`）かを聞かれる |
| `d` | パーティションを消す（delete） |
| `t` | パーティションの種類を変える（type） |
| `l` | 種類の番号の一覧（list） |
| `a` | ブートフラグを付け外し（MBR） |
| `o` / `g` | 空の MBR / 空の GPT の表を新しく作る |
| `w` | **書き込んで終わる**（write） |
| `q` | **書き込まずに終わる**（quit） |

`w` を打つまでは、変更はメモリの上だけです。まちがえたら `q` で抜ければ、ディスクは元のままです。

| 種類の番号（fdisk、MBR） | 意味 |
| --- | --- |
| `83` | Linux（ふつうのファイルシステム） |
| `82` | Linux スワップ |
| `8e` | Linux LVM |
| `5` | 拡張パーティション |
| `ef` | EFI（ESP） |

### gdisk

`gdisk` は GPT 用です。操作は fdisk と同じ 1 文字（`p`、`n`、`d`、`t`、`l`、`w`、`q`、`?` でメニュー）で、種類は 4 桁のコードです。

```console
# gdisk -l /dev/sdc
…
Number  Start (sector)    End (sector)  Size       Code  Name
   1            2048          206847   100.0 MiB   EF00  EFI system partition
   2          206848         2095103   922.0 MiB   8300  Linux filesystem
```

| コード（gdisk） | 意味 |
| --- | --- |
| `8300` | Linux のファイルシステム |
| `8200` | Linux スワップ |
| `8E00` | Linux LVM |
| `EF00` | EFI System Partition（ESP） |

### parted

`parted` は、対話でも、コマンドを並べても使えます。**`w` がなく、1 つのコマンドを打つたびにディスクへ書き込みます**。

```console
# parted -s /dev/sdd mklabel gpt mkpart primary ext4 1MiB 50MiB mkpart primary linux-swap 50MiB 100% print
Model:  (file)
Disk /dev/sdd: 105MB
Sector size (logical/physical): 512B/512B
Partition Table: gpt
Disk Flags:

Number  Start   End     Size    File system     Name     Flags
 1      1049kB  52.4MB  51.4MB  ext4            primary
 2      52.4MB  105MB   52.4MB  linux-swap(v1)  primary  swap
```

| parted のコマンド | すること |
| --- | --- |
| `mklabel gpt` / `mklabel msdos` | 新しい GPT / MBR の表を作る |
| `mkpart 種類 [FS の種類] 始め 終わり` | パーティションを作る |
| `print` | 表を表示する |
| `rm 番号` | 消す |
| `resizepart 番号 終わり` | 大きさを変える |
| `set 番号 フラグ on` | `boot`、`esp`、`lvm` などの印を付ける |

:::warn 試験の注意：parted はすぐ書く
fdisk と gdisk は `w` で書き込み、`q` で取り消せます。**parted には取り消しがありません**。また、3 つとも作るのは「区画」だけです。`mkpart` に `ext4` と書いても、ファイルシステムは作られません（種類の印が付くだけ）。中身を作るのは次の節の `mkfs` です。
:::

## パーティションの分け方：/、/boot、/var、/home、スワップ {#layout}

インストールのとき、ディスクを 1 つの大きな `/` にもできますが、役目ごとに分けることもあります。分けると、1 つが一杯になっても、ほかに広がりません。

```fig tree よくある分け方の例（UEFI、GPT）。色のついたものが、別のパーティション（または論理ボリューム）
{
  root: { label: '/', kind: 'dir', hl: true, note: 'ルート。/etc、/bin、/sbin、/lib、/dev はここに必ず置く', children: [
    { label: 'boot', kind: 'dir', hl: true, note: 'カーネルと initramfs。数百 MiB〜1 GiB', children: [
      { label: 'efi', kind: 'dir', hl: true, note: 'ESP（FAT）' },
    ] },
    { label: 'var', kind: 'dir', hl: true, note: 'ログ、スプール、キャッシュ。増え続ける' },
    { label: 'home', kind: 'dir', hl: true, note: 'ユーザーのデータ' },
    { label: 'etc', kind: 'dir', note: '/ の中（分けられない）' },
    { label: '[スワップ]', note: 'マウントしない。メモリの退避先' },
  ] },
}
```

| 分けるもの | 分ける理由 |
| --- | --- |
| `/boot` | カーネルと initramfs を、ブートローダが確実に読める単純な場所に置く。`/` を LVM や暗号化にしたときに必要になる |
| `/boot/efi` | UEFI で起動するための ESP（FAT） |
| `/var` | ログ（`/var/log`）、メールや印刷のスプール、パッケージのキャッシュは増え続ける。**一杯になっても `/` を巻き込まない** |
| `/home` | ユーザーのデータ。**OS を入れ直すときも、フォーマットせずに残せる**。ユーザーが一杯にしても、システムは止まらない |
| `/tmp` | だれでも書ける一時ファイル。tmpfs にすることも多い |
| スワップ | メモリが足りないとき、使われていないページを書き出す場所 |

**`/etc`、`/bin`、`/sbin`、`/lib`、`/dev` は、`/` と別のパーティションにできません**。`/` をマウントした直後に、ほかのものをマウントするための道具（`mount`）と設定（`/etc/fstab`）が、そこから読まれるからです。

**スワップ**（swap）は、メモリが足りなくなったときに、しばらく使われていないページの中身をディスクへ退避する場所です（[図解 Linux 13.10](../../linux/site/ch13.html#oom) の囲み）。専用の**スワップパーティション**のほか、ふつうのファイルを**スワップファイル**として使うこともできます。大きさの目安は時代と使い方で変わりますが、休止状態（ハイバネーション）を使うなら、メモリの量以上が要ります。

## LVM：パーティションを、あとから伸び縮みさせる {#lvm}

パーティションは、一度切ると大きさを変えにくいものです。後ろに別のパーティションがあると、伸ばせません。**LVM**（Logical Volume Manager）は、ディスクとファイルシステムのあいだに 1 段かませて、この不便をなくします。

```fig graph LVM の 3 層。ディスク（やパーティション）を PV にし、PV を集めて VG という大きな池を作り、そこから LV を切り出す。ファイルシステムは LV の上に作る
{
  col: 200, row: 82,
  nodes: [
    { id: 'd1', label: '/dev/sdb1', sub: 'パーティション', x: 0, y: 0, kind: 'ext' },
    { id: 'd2', label: '/dev/sdc', sub: 'ディスク全体', x: 0, y: 1, kind: 'ext' },
    { id: 'p1', label: 'PV', sub: 'pvcreate', x: 1, y: 0, kind: 'stack' },
    { id: 'p2', label: 'PV', sub: 'pvcreate', x: 1, y: 1, kind: 'stack' },
    { id: 'vg', label: 'VG vg01', sub: 'vgcreate。PE（既定 4 MiB）の池', x: 2, y: 0.5, kind: 'accent' },
    { id: 'l1', label: 'LV lv_data', sub: 'lvcreate', x: 3, y: 0, kind: 'crate' },
    { id: 'l2', label: 'LV lv_home', sub: 'lvcreate', x: 3, y: 1, kind: 'crate' },
  ],
  edges: [
    { from: 'd1', to: 'p1' }, { from: 'd2', to: 'p2' },
    { from: 'p1', to: 'vg' }, { from: 'p2', to: 'vg' },
    { from: 'vg', to: 'l1' }, { from: 'vg', to: 'l2' },
  ],
}
```

| 層 | 名前 | 作るコマンド | 見るコマンド |
| --- | --- | --- | --- |
| **PV**（物理ボリューム） | LVM で使うと決めたディスクやパーティション | `pvcreate` | `pvs`、`pvdisplay` |
| **VG**（ボリュームグループ） | PV を束ねた池。**PE**（物理エクステント、既定 4 MiB）という小さな単位に分けて管理する | `vgcreate` | `vgs`、`vgdisplay` |
| **LV**（論理ボリューム） | VG から切り出した領域。パーティションの代わりに、この上に mkfs する | `lvcreate` | `lvs`、`lvdisplay` |

300 MiB のディスク 2 台で、実際に作った例です（Debian 12、Docker のループデバイスで実行）。

```console
# pvcreate /dev/sdb /dev/sdc
  Physical volume "/dev/sdb" successfully created.
  Physical volume "/dev/sdc" successfully created.
# vgcreate vg01 /dev/sdb /dev/sdc
  Volume group "vg01" successfully created
# lvcreate -L 200M -n lv_data vg01
  Logical volume "lv_data" created.
# vgs
  VG   #PV #LV #SN Attr   VSize   VFree
  vg01   2   1   0 wz--n- 592.00m 392.00m
# lvs
  LV      VG   Attr       LSize   Pool Origin Data%  Meta%  Move Log Cpy%Sync Convert
  lv_data vg01 -wi-a----- 200.00m
```

300 MiB の PV が 296 MiB（74 個の PE）になっているのは、LVM の管理情報のぶんです。2 台を束ねた VG は 592 MiB で、そこから 200 MiB の LV を切り出しました。

LV のデバイスファイルは 2 つの名前で見えます。

- **`/dev/VG名/LV名`**（例 `/dev/vg01/lv_data`）
- **`/dev/mapper/VG名-LV名`**（例 `/dev/mapper/vg01-lv_data`。実体はこちらで、上はこれへのシンボリックリンク）

`lvcreate` の大きさは、`-L 200M` のように量で、または `-l 50` のように PE の個数で（`-l 100%FREE` なら残り全部）指定します。名前は `-n` です。

### 伸ばす、縮める

LV は、VG に空きがあれば、使いながら伸ばせます。VG の空きが足りなければ、ディスクを足して `vgextend vg01 /dev/sdd` で VG を広げます。

```console
# lvextend -L +100M -r /dev/vg01/lv_data
  Size of logical volume vg01/lv_data changed from 200.00 MiB (50 extents) to 300.00 MiB (75 extents).
  Logical volume vg01/lv_data successfully resized.
resize2fs 1.47.0 (5-Feb-2023)
Filesystem at /dev/mapper/vg01-lv_data is mounted on /data; on-line resizing required
```

`-L +100M` は「100 MiB 足す」、`-L 300M` は「300 MiB にする」です。**LV を伸ばしただけでは、上のファイルシステムは元の大きさのまま**です。`-r`（`--resizefs`）を付けると、ファイルシステムも一緒に広げます。付けなかったときは、ext4 なら `resize2fs`、XFS なら `xfs_growfs` で広げます。

縮めるのは `lvreduce` ですが、先にファイルシステムを縮めないとデータが壊れます。**XFS は縮められません**（大きくすることだけできる）。ext4 は、マウントを外せば縮められます。

| コマンド | すること |
| --- | --- |
| `vgextend VG PV` | VG に PV を足す |
| `vgreduce VG PV` | VG から PV を外す |
| `lvextend -L +量 [-r] LV` | LV を伸ばす |
| `lvreduce -L -量 [-r] LV` | LV を縮める |
| `lvresize` | 伸ばすのも縮めるのもできる |
| `lvremove`、`vgremove`、`pvremove` | 消す（LV → VG → PV の順） |

### スナップショット

**スナップショット**は、ある瞬間の LV の姿を、別の LV として残す機能です。`lvcreate` に **`-s`**（`--snapshot`）を付け、元の LV を指定します。

```console
# lvcreate -s -L 50M -n snap1 vg01/lv_data
```

作った瞬間には中身をコピーしません。元の LV のブロックが書き換えられるときに、**書き換えの前の中身だけをスナップショットの領域に退避します**（コピーオンライト）。だから、`-L 50M` のように元より小さな領域で作れます。動いているデータベースのバックアップを取るときに、スナップショットを作ってそれをマウントし、ゆっくりコピーする、という使い方をします。退避の量が領域を超えると、スナップショットは使えなくなります。

:::warn 試験の注意：LVM の順番と名前
- 作る順は **PV → VG → LV**（`pvcreate` → `vgcreate` → `lvcreate`）。その後で `mkfs`、`mount`
- `vgcreate` の最初の引数は**新しい VG の名前**、`lvcreate` の `-n` は **LV の名前**、最後の引数が VG
- スナップショットは `lvcreate -s`。`lvsnapshot` というコマンドはない
- LV を伸ばしてもファイルシステムは伸びない（`-r` か resize2fs・xfs_growfs）。XFS は縮められない
:::

## ファイルシステムの種類と mkfs {#mkfs}

パーティションや LV は、まだ何も書かれていない区画です。そこに inode 表やスーパーブロック（[図解 Linux 11.9](../../linux/site/ch11.html#ext4)）を書き込んで、ファイルを置けるようにするのが **`mkfs`**（make filesystem）です。

```console
# mkfs -t ext4 /dev/sdb1       ← 種類を -t で
# mkfs.ext4 /dev/sdb1          ← 上と同じ（mkfs は mkfs.ext4 を呼ぶだけ）
# mkfs.xfs -L LOGS /dev/sdb2   ← -L でラベルを付ける
# mkfs.vfat /dev/sdc1
# mke2fs -t ext4 /dev/sdb1     ← ext 系を作る本体
```

`mkfs` は入口で、実際の仕事は `mkfs.種類` という名前の別のコマンドがします。`ls /sbin/mkfs*` には `mkfs.ext2`、`mkfs.ext3`、`mkfs.ext4`、`mkfs.xfs`、`mkfs.vfat`、`mkfs.btrfs` などが並びます。**`-t` を省くと ext2** になります（`mkfs --help` の説明に `when unspecified, ext2 is used` とあります）。

カーネルが読めるファイルシステムの種類は、`/proc/filesystems` に出ています（[図解 Linux 12.2](../../linux/site/ch12.html#vfs)）。`nodev` が付いたものは、ディスク（ブロックデバイス）を使わない種類です。

```sh run title="カーネルが知っているファイルシステムの種類"
cat /proc/filesystems
```

| 種類 | 特徴 | 主な使い道 |
| --- | --- | --- |
| **ext2** | ジャーナルなし。古い | 小さな領域 |
| **ext3** | ext2 に**ジャーナル**を足したもの | 古いシステムの標準 |
| **ext4** | ext3 の後継。エクステント（[図解 Linux 11.9](../../linux/site/ch11.html#ext4)）、大きなファイル、ジャーナル | Debian、Ubuntu の標準 |
| **XFS** | ジャーナル。大きなファイルと並列の読み書きに強い。**縮小できない** | Red Hat 系（RHEL 7 以降）の標準 |
| **Btrfs** | **コピーオンライト**。スナップショット、サブボリューム、複数のディスクをまとめる機能、データのチェックサムを、ファイルシステム自身が持つ | openSUSE、Fedora の標準 |
| **VFAT**（FAT32） | Windows や macOS でも読める。所有者や権限を持たない | **USB メモリ、SD カード、ESP** |
| **tmpfs** | **メモリの上**。再起動で消える。mkfs は要らない | `/tmp`、`/run`、`/dev/shm` |
| ISO 9660 | CD・DVD 用。読み取り専用 | 光学メディア |

**ジャーナル**は、書き換えの予定を先に専用の場所に書いておき、途中で電源が落ちても整合性を取り戻せるようにする仕組みです（[図解 Linux 11.9](../../linux/site/ch11.html#ext4) の囲み）。ジャーナルがあると、電源断のあとの `fsck`（ファイルシステムの検査と修復）がすぐ終わります。

**tmpfs** はディスクを使わないので、`mkfs` をせず、いきなり `mount -t tmpfs` します（[図解 Linux 12.5](../../linux/site/ch12.html#tmpfs)）。

:::warn 試験の注意：mkfs は中身を消す
`mkfs` は、区画の先頭から新しい管理情報を書き込みます。**すでにあるファイルは読めなくなります**。ラベルを付け直したいだけなら、`mkfs -L` ではなく、ext 系は `e2label` か `tune2fs -L`、XFS は `xfs_admin -L` を使います（[5.12](#fstab)）。
:::

## スワップ：mkswap、swapon、swapoff {#swap}

スワップも、作って（`mkswap`）、使い始める（`swapon`）の 2 段です。マウントはしません。

```console
# mkswap /dev/sdb5
Setting up swapspace version 1, size = 100 MiB (104853504 bytes)
no label, UUID=b61f237a-5e07-41f4-8832-5c738f508c62
# swapon /dev/sdb5
# swapon --show
NAME          TYPE       SIZE USED PRIO
/var/lib/swap file      1024M   0B   -2
/dev/sdb5     partition  100M   0B   -3
# swapoff /dev/sdb5
```

（Debian 12 の Docker で、ループデバイスを使って確かめたものです。`/var/lib/swap` は、もともとあったスワップファイルです）

| コマンド | すること |
| --- | --- |
| `mkswap 装置` | スワップ領域を作る（`-L` でラベル） |
| `swapon 装置` | そのスワップを使い始める |
| `swapon -a` | **`/etc/fstab` に書いた swap を全部**使い始める（起動のときに実行される） |
| `swapon --show`、`swapon -s` | 使っているスワップの一覧（`-s` は古い形で、`/proc/swaps` と同じ表を出す） |
| `swapoff 装置` | そのスワップを使うのをやめる（中身はメモリへ戻す） |
| `swapoff -a` | 全部やめる |

使っているスワップは、`free` の `Swap:` の行と、`/proc/swaps` でも見られます。この小さな Linux には、スワップがありません。

```sh run title="スワップの量（この Linux では 0）"
free
grep -i swap /proc/meminfo
```

スワップファイルを作るときは、ファイルを用意し、**持ち主だけが読み書きできる権限**（600）にしてから `mkswap` します。

```console
# dd if=/dev/zero of=/swapfile bs=1M count=1024
# chmod 600 /swapfile
# mkswap /swapfile
# swapon /swapfile
```

:::warn 試験の注意：作るのと使うのは別
`mkswap` は領域を作るだけで、それだけではスワップとして使われません。`swapon` して初めて使われます。ファイルシステムの `mkfs` → `mount` と同じ関係です。`/etc/fstab` に書いておけば、起動のたびに `swapon -a` で有効になります。
:::

## mount と umount：木につなぐ、外す {#mount}

`mount -t 種類 何を どこに` でつなぎ、`umount どこに`（または `umount 何を`）で外します（[図解 Linux 12.6](../../linux/site/ch12.html#mount)、[12.7](../../linux/site/ch12.html#umount)）。つなぐ先のディレクトリを**マウントポイント**と呼び、前もって作っておきます。種類は、ディスクの中身を見て自動で見分けてくれるので、`-t` を省くこともできます。

```console
# mount /dev/sdb1 /mnt                 ← 種類は自動
# mount -t xfs /dev/sdb2 /data
# mount -o ro /dev/sr0 /media/cdrom    ← 読み取り専用で
# mount UUID=6109cec1-643a-4028-8cd9-7dff05eef572 /data
# mount LABEL=DATA /data
# mount                                 ← 引数なし：マウントの一覧
# mount -a                              ← /etc/fstab の（noauto 以外の）全部をマウント
```

小さな Linux では、tmpfs で試せます。`/media/usb` に、読み取り専用（`ro`）で、1 MiB の tmpfs をつなぎます。

```sh run root title="読み取り専用でマウントする"
mkdir /media/usb
mount -t tmpfs -o ro,size=1m tmpfs /media/usb
grep /media/usb /proc/mounts
```

```sh run root error title="読み取り専用には書けない"
touch /media/usb/a.txt
```

`-o remount` を付けると、外さずにオプションだけを変えられます。

```sh run root title="書けるように付け直す"
mount -o remount,rw /media/usb
touch /media/usb/a.txt
ls /media/usb
```

| オプション（`-o`） | 意味 |
| --- | --- |
| `ro` / `rw` | 読み取り専用 / 読み書き |
| `remount` | マウントしたまま、オプションを付け直す |
| `noexec` / `exec` | その中のプログラムの実行を許さない / 許す |
| `nosuid` / `suid` | SUID・SGID のビットを無視する / 効かせる |
| `nodev` / `dev` | その中のデバイスファイルを使わせない / 使わせる |
| `sync` / `async` | 書き込みをすぐディスクに書く / まとめて後で書く |
| `auto` / `noauto` | `mount -a`（起動時）でマウントする / しない |
| `user` / `nouser` | 一般ユーザーにマウントを許す（外すのはマウントした本人だけ） / 許さない |
| `users` | 一般ユーザーのだれでもマウントでき、だれでも外せる |
| `defaults` | **`rw`、`suid`、`dev`、`exec`、`auto`、`nouser`、`async`** をまとめたもの |
| `loop` | ファイル（ISO イメージなど）を、ディスクのようにマウントする |

`user` と `users` は、指定すると `noexec`、`nosuid`、`nodev` も付いたことになります（一般ユーザーが持ち込んだ媒体から、権限を取られないように）。

### umount と target is busy

マウントの中のファイルをだれかが開いている、またはだれかのカレントディレクトリがその中にあると、`umount` は失敗します。

```sh run root error title="中に cd したまま外そうとする"
cd /media/usb
umount /media/usb
```

```sh run root title="外に出てから外す"
cd /
umount /media/usb
ls /media/usb
```

使っているプロセスは `fuser -m /media/usb` や `lsof /media/usb` で探せます（1.10 で学びます）。`umount -l`（lazy）は、いますぐ木から切り離し、使っているプロセスがいなくなってから片づけます。

### /mnt と /media

| ディレクトリ | 用途 |
| --- | --- |
| **`/mnt`** | 管理者が**一時的に手でマウントする**ための場所 |
| **`/media`** | USB メモリや CD などの**取り外せる媒体**を**自動でマウント**する場所。デスクトップでは `/media/ユーザー名/ラベル` に作られる（Red Hat 系の GNOME では `/run/media/ユーザー名/…`） |

どちらも FHS（ファイルシステムの階層の標準）で決められた場所で、マウントポイントにする空のディレクトリを置いておく所です。

## /etc/fstab と UUID・ラベル：起動のたびにつなぐ {#fstab}

起動のたびにマウントするものは、**`/etc/fstab`** に 1 行ずつ書きます。起動の途中で `mount -a` と `swapon -a` に当たる処理が、このファイルを上から読みます。

```sh run title="この Linux の /etc/fstab"
cat /etc/fstab
```

本物の Linux の `/etc/fstab` は、たとえばこうです。

```text
# <file system>                            <mount point> <type> <options>         <dump> <pass>
UUID=6109cec1-643a-4028-8cd9-7dff05eef572  /             ext4   defaults          0      1
UUID=5CD0-BB2D                             /boot/efi     vfat   umask=0077        0      2
LABEL=LOGS                                 /var/log      xfs    defaults          0      2
/dev/mapper/vg01-lv_home                   /home         ext4   defaults,nosuid   0      2
UUID=4a98790c-1865-4763-917c-63280a83a0c8  none          swap   sw                0      0
tmpfs                                      /tmp          tmpfs  size=512m         0      0
/dev/sr0                                   /media/cdrom  iso9660 ro,noauto,user   0      0
```

| 欄 | 中身 | 書き方 |
| --- | --- | --- |
| 1 | マウントするもの | `/dev/sdb1`、**`UUID=…`**、**`LABEL=…`**、`/dev/mapper/…`、tmpfs や proc は目印の文字列 |
| 2 | マウントポイント | スワップは `none`（`swap` と書くものもある） |
| 3 | 種類 | `ext4`、`xfs`、`vfat`、`btrfs`、`tmpfs`、**`swap`** など |
| 4 | オプション | `mount -o` と同じ。`defaults`、`noauto`、`ro` などをカンマで |
| 5 | **dump** | `dump` コマンドでバックアップするか。**0 でしない**、1 でする |
| 6 | **fsck の順番** | 起動時に検査する順。**`/` は 1**、ほかは 2、**0 は検査しない** |

この小さな Linux の fstab から、2 欄目、3 欄目、5 欄目、6 欄目だけを取り出してみます。

```sh run title="欄を取り出す"
awk '!/^#/ {print $2, $3, $5, $6}' /etc/fstab
```

### UUID とラベル

前に見たとおり、`/dev/sdb` のような名前は、ディスクを足すと変わることがあります。そこで、ファイルシステムを作るときに付く **UUID**（ほぼ重ならない長い番号）や、自分で付ける**ラベル**で指定します。どちらも、ファイルシステムの中に書かれているので、つなぐ場所や順番が変わっても同じです。

調べるコマンドは `blkid` と `lsblk -f` です。

```console
# blkid
/dev/sdb1: LABEL="DATA" UUID="6109cec1-643a-4028-8cd9-7dff05eef572" BLOCK_SIZE="1024" TYPE="ext4"
/dev/sdb2: LABEL="LOGS" UUID="a19c9c57-6cab-4f31-a1b5-122156a0949e" BLOCK_SIZE="512" TYPE="xfs"
/dev/sdb5: LABEL="SWAP1" UUID="4a98790c-1865-4763-917c-63280a83a0c8" TYPE="swap"
/dev/sdc1: LABEL="USB" UUID="5CD0-BB2D" BLOCK_SIZE="512" TYPE="vfat"
# lsblk -f
NAME   FSTYPE FSVER LABEL UUID                                 FSAVAIL FSUSE% MOUNTPOINTS
sdb
├─sdb1 ext4   1.0   DATA  6109cec1-643a-4028-8cd9-7dff05eef572  350.2M     2% /data
├─sdb2 xfs          LOGS  a19c9c57-6cab-4f31-a1b5-122156a0949e  230.1M     5% /var/log
└─sdb5 swap   1     SWAP1 4a98790c-1865-4763-917c-63280a83a0c8                [SWAP]
```

| コマンド | 表示 |
| --- | --- |
| `blkid [装置]` | 装置ごとの **UUID、ラベル、種類**（TYPE） |
| `lsblk` | ディスクとパーティション、LV の**木**と大きさ、マウント先 |
| `lsblk -f` | 上に、ファイルシステムの種類、ラベル、UUID を足したもの |

VFAT の UUID は `5CD0-BB2D` のように短く、大文字です。ラベルを付ける、付け替えるコマンドは種類ごとに違います。

| 種類 | 作るときに | あとから付け替える |
| --- | --- | --- |
| ext2/3/4 | `mkfs.ext4 -L 名前` | **`e2label 装置 名前`**、`tune2fs -L 名前 装置` |
| XFS | `mkfs.xfs -L 名前` | `xfs_admin -L 名前 装置` |
| スワップ | `mkswap -L 名前` | `swaplabel -L 名前 装置` |

fstab にまちがいがあると、次の起動が途中で止まることがあります。書き換えたら `mount -a` を実行して、エラーが出ないことを確かめます（すでにマウントしてあるものは、そのままにされます）。無くても起動を止めたくない USB ディスクなどには `nofail` を付けます。

:::warn 試験の注意：fstab の欄の順番
- 欄の順は「**何を・どこに・種類・オプション・dump・fsck**」。5 番目と 6 番目を取り違えない
- 6 番目の fsck は、`/` が **1**、ほかが **2**、検査しないものが **0**。tmpfs、proc、swap は 0
- `noauto` は「起動時（`mount -a`）にはマウントしない」。fstab に書いてあれば、`mount /media/cdrom` とマウントポイントだけで手でマウントできる
:::

:::warn 本物との違い
- この小さな Linux には、ブロックデバイス（ディスクの区画）、カーネルモジュール、スワップ、LVM がありません。`fdisk`、`lsmod`、`mkfs`、`mkswap`、`blkid`、`lvcreate` などは、Debian 12 の Docker で実行した出力を ```console で載せました
- この Linux の `mount` は `noexec` などのオプションを表示しません。また `mount -a` は、fstab を読まずに一覧を表示します
:::

:::key まとめ
- ドライバの多くは**カーネルモジュール**。一覧は `lsmod`、読み込みは **`modprobe`（依存も解決）**、`insmod`（ファイルのパス、依存なし）。外すのは `rmmod` か **`modprobe -r`**。置き場所は `/lib/modules/$(uname -r)/`
- 装置の情報は **`/sys`（sysfs）**、`/proc`、`/dev`。PCI は `lspci`（`-k` でドライバ）、USB は `lsusb`（`-t` で木）。**udev** が uevent を受けて `/dev` を整え（規則は `/etc/udev/rules.d/`）、**dbus** がデスクトップへ知らせる
- HDD は回転する円盤、SSD はフラッシュで速い（`rotational` が 0）。光学ドライブは `/dev/sr0`
- **MBR**：先頭 512 バイト、基本 4 つまで（拡張 + 論理、**論理は 5 番から**）、2 TiB まで。**GPT**：既定 128 個、2 TiB 超、末尾に控え、UEFI と組む。**ESP** は FAT で `/boot/efi`
- **fdisk**（MBR。`p` 表示、`n` 作る、`t` 種類、`w` 書く、`q` やめる）、**gdisk**（GPT）、**parted**（すぐ書く）
- `/var`、`/home`、`/boot` は分けられる。`/etc` などは `/` から分けられない
- **LVM**：PV（`pvcreate`）→ VG（`vgcreate`）→ LV（`lvcreate -L 量 -n 名前 VG`）。`/dev/VG/LV`。`lvextend -r` で FS も広げる。XFS は縮められない。スナップショットは `lvcreate -s`
- `mkfs -t 種類` = `mkfs.種類`。`-t` を省くと ext2。ジャーナル：ext3/ext4/XFS。Btrfs はコピーオンライトとスナップショット。VFAT は USB と ESP。tmpfs はメモリで mkfs 不要
- スワップは `mkswap` → `swapon`。`swapon -a` は fstab の全部、`swapon --show`／`-s`／`/proc/swaps` で確認、`swapoff` で止める
- `mount -o ro,remount` など。`defaults` = rw, suid, dev, exec, auto, nouser, async。使用中だと umount は `target is busy`
- **/etc/fstab** の 6 欄：何を・どこに・種類・オプション・**dump**・**fsck（/ は 1、ほか 2、0 は検査なし）**。`UUID=` と `LABEL=` で書く。調べるのは `blkid`、`lsblk -f`
- `/mnt` は一時的な手動マウント、`/media` は取り外せる媒体の自動マウント
:::

## 練習問題 {#practice}

### 1.05.1 ハードウェアの基礎知識と設定

:::q 1.05.1-01 single
依存関係にあるモジュールも含めて、カーネルモジュールを名前で読み込むコマンドはどれか。
- [ ] `insmod`
- [x] `modprobe`
- [ ] `lsmod`
- [ ] `modinfo`
- [ ] `rmmod`
:::why
`modprobe` は `/lib/modules/$(uname -r)/modules.dep` を見て、先に必要なモジュールから順に読み込みます（[5.2](#modules)）。

- `insmod` は `.ko` ファイルのパスを受け取って 1 つだけ読み込み、依存は解決しません
- `lsmod` は読み込まれているモジュールの一覧を表示します
- `modinfo` はモジュールの説明や引数を表示するだけです
- `rmmod` は外すコマンドです
:::
:::

:::q 1.05.1-02 single
`insmod` の説明として正しいものはどれか。
- [ ] モジュールの名前を指定すると、依存するモジュールも自動で読み込む
- [x] モジュールのファイルのパスを指定して読み込み、依存関係は解決しない
- [ ] `-r` オプションを付けると、モジュールを取り外す
- [ ] 読み込まれているモジュールの一覧を表示する
:::why
`insmod` は渡された `.ko` ファイルを 1 つ読み込むだけです。依存するモジュールが読み込まれていなければ失敗します（[5.2](#modules)）。名前で依存も含めて読み込むのは `modprobe`、取り外しは `rmmod` か `modprobe -r` で、`insmod` に `-r` はありません。一覧は `lsmod` です。
:::
:::

:::q 1.05.1-03 fill
現在カーネルに読み込まれているモジュールの一覧を、名前、大きさ、使われている数とともに表示するコマンドを入力してください。
= lsmod
= /sbin/lsmod
= cat /proc/modules
:::why
`lsmod` は `/proc/modules` を読みやすく整えて、「Module」「Size」「Used by」の 3 列で表示します（[5.2](#modules)）。`cat /proc/modules` でも同じ情報が見られます。
:::
:::

:::q 1.05.1-04 single
`lsmod` を実行したところ、次の行が表示された。この行の説明として正しいものはどれか。

```text
Module                  Size  Used by
libcrc32c              12288  2 xfs,nf_conntrack
```
- [ ] `libcrc32c` は、`xfs` と `nf_conntrack` に依存している
- [x] `libcrc32c` は、`xfs` と `nf_conntrack` の 2 つのモジュールから使われている
- [ ] `libcrc32c` は 2 回読み込まれている
- [ ] `libcrc32c` は 12288 個の装置を扱っている
:::why
3 列目の「Used by」は、そのモジュールを使っている数と、使っているモジュールの名前です（[5.2](#modules)）。`xfs` と `nf_conntrack` が `libcrc32c` に依存している、という向きです。2 列目は大きさ（バイト）で、装置の数ではありません。同じモジュールを 2 回読み込むことはできません。使われている数が 0 でないので、このままでは `rmmod libcrc32c` で外せません。
:::
:::

:::q 1.05.1-05 multi
読み込まれているカーネルモジュール `usb_storage` を取り外すコマンドを 2 つ選択してください。
- [x] `rmmod usb_storage`
- [x] `modprobe -r usb_storage`
- [ ] `insmod -r usb_storage`
- [ ] `lsmod -r usb_storage`
- [ ] `modprobe -d usb_storage`
:::why
取り外すのは `rmmod` と `modprobe -r` です（[5.2](#modules)）。`modprobe -r` は、使われなくなった依存モジュールも一緒に外します。`insmod` と `lsmod` には取り外しのオプションはありません。`modprobe -d` はモジュールの置き場所の根のディレクトリを指定するオプションで、外す意味はありません。
:::
:::

:::q 1.05.1-06 single
ネットワークカードやディスクのコントローラなど、PCI バスにつながった装置の一覧を表示するコマンドはどれか。
- [ ] `lsusb`
- [x] `lspci`
- [ ] `lsmod`
- [ ] `lsblk`
:::why
PCI（PCI Express）の装置の一覧は `lspci` です（[5.3](#devices)）。`lsusb` は USB の装置、`lsmod` はカーネルモジュール、`lsblk` はディスクとパーティションの一覧です。
:::
:::

:::q 1.05.1-07 single
`lsusb` で、USB の装置がハブを通してどうつながっているかを木の形で表示するオプションはどれか。
- [ ] `-v`
- [x] `-t`
- [ ] `-d`
- [ ] `-s`
:::why
`lsusb -t` は、USB の装置のつながりを木の形で表示します（[5.3](#devices)）。`-v` は詳しい情報（記述子）、`-d` はベンダー ID と製品 ID で絞り込み、`-s` はバスと装置の番号で絞り込みます。
:::
:::

:::q 1.05.1-08 single
カーネルが認識している装置、バス、ドライバのつながりを、ディレクトリの木として見せる sysfs がマウントされる場所はどれか。
- [ ] `/proc`
- [x] `/sys`
- [ ] `/dev`
- [ ] `/etc/udev`
:::why
sysfs は `/sys` にマウントされます（[5.3](#devices)）。`/proc` は procfs（プロセスとカーネルの情報）、`/dev` は devtmpfs（デバイスファイル）です。`/etc/udev` は udev の設定ファイルを置くディレクトリで、ファイルシステムのマウント先ではありません。
:::
:::

:::q 1.05.1-09 single
udev の説明として正しいものはどれか。
- [ ] カーネルモジュールの依存関係の表を作る
- [x] カーネルからの通知を受け取り、規則に従って `/dev` のデバイスファイルを作ったり名前を付けたりする
- [ ] デスクトップのプログラムどうしでメッセージを送り合うためのバス
- [ ] 起動時に `/etc/fstab` を読んでファイルシステムをマウントする
:::why
udev（デーモンは systemd-udevd）は、装置が増えたり減ったりしたときにカーネルが出す uevent を受け取り、規則（rules.d）に従って `/dev` のデバイスファイルを整えます（[5.4](#udev)）。依存の表を作るのは `depmod`、プログラムどうしのメッセージのバスは dbus、fstab を読んでマウントするのは `mount -a`（systemd では起動の処理）です。
:::
:::

:::q 1.05.1-10 multi
udev の規則ファイルを置くディレクトリを 2 つ選択してください。
- [x] `/etc/udev/rules.d/`
- [x] `/lib/udev/rules.d/`
- [ ] `/proc/udev/`
- [ ] `/sys/udev/rules/`
- [ ] `/dev/udev.d/`
:::why
パッケージが入れる規則は `/lib/udev/rules.d/`（Red Hat 系では `/usr/lib/udev/rules.d/`）、管理者が書く規則は `/etc/udev/rules.d/` に置きます。同じ名前なら `/etc` のほうが優先されます（[5.4](#udev)）。`/proc`、`/sys`、`/dev` はカーネルが中身を作るファイルシステムで、規則を置く場所ではありません。
:::
:::

:::q 1.05.1-11 single
dbus の説明として正しいものはどれか。
- [ ] 装置を PCI バスにつなぐための規格
- [ ] カーネルモジュールを読み込むデーモン
- [x] プロセスどうしがメッセージを送り合う仕組みで、装置が増えたことなどをデスクトップのプログラムに伝える
- [ ] USB の装置の一覧を表示するコマンド
:::why
dbus はプロセス間通信のバスです（[5.4](#udev)）。udev が整えた装置の知らせなどを、デスクトップのプログラムが受け取るのに使います。PCI は基板の上のバスの規格、モジュールの読み込みは `modprobe`、USB の一覧は `lsusb` です。
:::
:::

:::q 1.05.1-12 multi
ハードウェアの情報を得られる `/proc` の下のファイルを 2 つ選択してください。
- [x] `/proc/cpuinfo`
- [x] `/proc/interrupts`
- [ ] `/proc/fstab`
- [ ] `/proc/udev.conf`
- [ ] `/proc/lspci`
:::why
`/proc/cpuinfo` は CPU の種類や数、`/proc/interrupts` は装置ごとの割り込みの番号と回数です（[5.3](#devices)）。fstab は `/etc/fstab`、udev の設定は `/etc/udev/udev.conf` で、`/proc` にはありません。`lspci` はコマンドで、`/proc` のファイルではありません。
:::
:::

:::q 1.05.1-13 single
SATA でつないだ 1 台目の光学ドライブ（CD/DVD）のデバイスファイルとして、一般的なものはどれか。
- [ ] `/dev/sda`
- [ ] `/dev/hdc1`
- [x] `/dev/sr0`
- [ ] `/dev/nvme0n1`
:::why
光学ドライブは `/dev/sr0` で、`/dev/cdrom` はその別名のリンクとして作られることが多いものです（[5.4](#udev)）。`/dev/sda` はディスク（HDD や SATA の SSD）、`/dev/nvme0n1` は NVMe の SSD です。`/dev/hd…` は古い IDE の名前で、`1` が付くとパーティションです。
:::
:::

:::q 1.05.1-14 multi
HDD と SSD の説明として正しいものを 2 つ選択してください。
- [x] SSD は動く部品がなく、ばらばらの場所を読み書きするのが HDD より速い
- [x] `/sys/block/sda/queue/rotational` が `0` なら、`sda` は回転しない装置（SSD など）とみなされている
- [ ] HDD は書き換え回数に上限があるので、TRIM で空き領域を知らせる
- [ ] SSD はヘッドを動かす待ち時間（シーク）があるので、ばらばらの場所を読むと遅い
- [ ] NVMe の SSD は `/dev/hda` という名前になる
:::why
SSD はフラッシュメモリで動く部品がなく、ランダムな読み書きが速い装置です。`rotational` が 1 なら回転する装置（HDD）、0 なら回転しない装置です（[5.3](#devices)、[5.4](#udev)）。書き換え回数の上限と TRIM は SSD の話、シークは HDD の話です。NVMe の SSD は `/dev/nvme0n1` です。
:::
:::

:::q 1.05.1-15 fill
カーネルモジュールは `/lib/modules/` の下の、動いているカーネルのリリース番号と同じ名前のディレクトリにある。そのリリース番号を表示するコマンドを、オプションも含めて入力してください。
= uname -r
= uname --kernel-release
:::why
`uname -r` はカーネルのリリース番号（例 `6.8.0-…`）を表示します（[5.2](#modules)）。モジュールの場所は `/lib/modules/$(uname -r)/` と書けます。`uname -a` はすべての情報を 1 行に出すので、リリース番号だけにはなりません。
:::
:::

### 1.05.2 ハードディスクのレイアウトとパーティション

:::q 1.05.2-01 single
MBR のパーティション表で作れる基本パーティションの数の上限はどれか。
- [ ] 2
- [x] 4
- [ ] 15
- [ ] 128
:::why
MBR のパーティション表は 64 バイトで、16 バイトの枠が 4 つしかありません。だから基本パーティションは 4 つまでです（[5.5](#mbr-gpt)）。それ以上は、1 つを拡張パーティションにして、中に論理パーティションを作ります。128 は GPT の既定の数です。
:::
:::

:::q 1.05.2-02 single
MBR のディスク `/dev/sdb` に、基本パーティション 2 つと拡張パーティション 1 つがある。拡張パーティションの中に最初の論理パーティションを作ったときの名前はどれか。

```text
Device     Boot   Start     End Sectors  Size Id Type
/dev/sdb1          2048  411647  409600  200M 83 Linux
/dev/sdb2        411648 1026047  614400  300M 83 Linux
/dev/sdb3       1026048 2097151 1071104  523M  5 Extended
```
- [ ] `/dev/sdb4`
- [x] `/dev/sdb5`
- [ ] `/dev/sdb3a`
- [ ] `/dev/sdb31`
:::why
論理パーティションの番号は、基本・拡張がいくつあっても 5 から始まります（[5.5](#mbr-gpt)、[5.6](#partition-tools)）。1〜4 は基本と拡張のための番号です。`sdb3a` や `sdb31` のような名前は付きません。
:::
:::

:::q 1.05.2-03 single
XFS のファイルシステムを載せた論理ボリュームの大きさを変えるときの説明として正しいものはどれか。
- [ ] XFS は大きくすることも小さくすることもできない
- [x] XFS は大きくできるが、小さくすることはできない
- [ ] XFS は小さくできるが、大きくすることはできない
- [ ] `lvreduce` で論理ボリュームを縮めれば、XFS も自動で縮む
:::why
XFS は広げる（`xfs_growfs`、または `lvextend -r`）ことはできますが、縮めることはできません（[5.8](#lvm)）。縮めたいときは、バックアップを取って作り直します。ファイルシステムより先に LV を縮めると、データが壊れます。
:::
:::

:::q 1.05.2-04 multi
GPT の説明として正しいものを 2 つ選択してください。
- [x] 2 TiB を超えるディスクにパーティションを作れる
- [x] ディスクの末尾に、ヘッダとパーティション表の控えを持つ
- [ ] 5 つ以上のパーティションを作るには拡張パーティションが必要
- [ ] パーティション表はディスクの先頭 512 バイトだけに収まる
- [ ] BIOS で起動するために作られた形式で、UEFI では使えない
:::why
GPT は 2 TiB を超える大きさを扱え、既定で 128 個のパーティションを作れ、末尾に控えを持ちます（[5.5](#mbr-gpt)）。拡張パーティションや先頭 512 バイトだけの表は MBR の特徴です。GPT は UEFI と一緒に決められた形式で、UEFI と組むのが典型です。
:::
:::

:::q 1.05.2-05 single
UEFI で起動するために使う ESP（EFI System Partition）のファイルシステムとして正しいものはどれか。
- [ ] ext4
- [ ] XFS
- [x] FAT（vfat）
- [ ] swap
:::why
UEFI のファームウェアが読めるように、ESP は FAT（FAT32。Linux での種類の名前は vfat）で作ります（[5.5](#mbr-gpt)）。ext4 や XFS は、ふつうの UEFI のファームウェアには読めません。
:::
:::

:::q 1.05.2-06 single
Linux で ESP をマウントする場所として一般的なものはどれか。
- [ ] `/efi/boot`
- [x] `/boot/efi`
- [ ] `/media/efi`
- [ ] `/mnt/esp`
:::why
ESP は `/boot/efi` にマウントするのが一般的です（[5.5](#mbr-gpt)）。中に `EFI/debian/grubx64.efi` のようなブートローダのファイルが入ります。`/media` は取り外せる媒体、`/mnt` は一時的な手動マウントの場所です。
:::
:::

:::q 1.05.2-07 single
`fdisk /dev/sdb` の対話で、ここまでの変更をディスクに書き込んで終了するコマンドはどれか。
- [ ] `q`
- [ ] `s`
- [x] `w`
- [ ] `x`
:::why
`w`（write）が書き込んで終わります（[5.6](#partition-tools)）。`q` は書き込まずに終わるので、変更は捨てられます。`s` は新しい Sun 形式の表を作るコマンド、`x` は上級者向けの機能のメニューです。
:::
:::

:::q 1.05.2-08 fill
`fdisk` の対話で、現在のパーティション表を表示するコマンド（1 文字）を入力してください。
= p
:::why
`p`（print）でパーティション表を表示します（[5.6](#partition-tools)）。`n` は作る、`d` は消す、`t` は種類を変える、`l` は種類の番号の一覧、`m` はメニューです。
:::
:::

:::q 1.05.2-09 single
`fdisk -l /dev/sdb` の出力の一部である。`/dev/sdb5` について正しいものはどれか。

```text
Device     Boot   Start     End Sectors  Size Id Type
/dev/sdb1          2048  411647  409600  200M 83 Linux
/dev/sdb3       1026048 2097151 1071104  523M  5 Extended
/dev/sdb5       1028096 1232895  204800  100M 82 Linux swap / Solaris
```
- [ ] 基本パーティションで、種類は Linux のファイルシステム
- [x] 論理パーティションで、種類はスワップ
- [ ] 拡張パーティションで、中に論理パーティションを持つ
- [ ] LVM の物理ボリュームとして使う種類
:::why
番号が 5 以上なので論理パーティションで、拡張パーティション `sdb3` の範囲（1026048〜2097151）の中にあります。Id `82` はスワップです（[5.6](#partition-tools)）。`83` が Linux、`5` が拡張、`8e` が LVM です。
:::
:::

:::q 1.05.2-10 multi
GPT のパーティション表を編集できるコマンドを 2 つ選択してください。
- [x] `gdisk`
- [x] `parted`
- [ ] `mkfs`
- [ ] `blkid`
- [ ] `lsblk`
:::why
`gdisk` は GPT 用の fdisk 風のコマンド、`parted` は MBR と GPT の両方を扱えます（[5.6](#partition-tools)）。`mkfs` はファイルシステムを作り、`blkid` は UUID などを表示し、`lsblk` はディスクの木を表示するだけで、パーティション表は編集しません。
:::
:::

:::q 1.05.2-11 single
`parted` の説明として正しいものはどれか。
- [ ] MBR のディスクしか扱えない
- [x] コマンドを実行するたびに、すぐディスクへ書き込まれる
- [ ] 変更は `w` を実行するまでメモリの上だけにある
- [ ] `mkpart` に `ext4` と指定すると、ext4 のファイルシステムも作られる
:::why
`parted` には `w` がなく、`mklabel` や `mkpart` などを実行したときにすぐ書き込まれます（[5.6](#partition-tools)）。MBR（`msdos`）と GPT の両方を扱えます。`w` で書き込むのは fdisk と gdisk です。`mkpart` の種類の指定は印を付けるだけで、ファイルシステムは `mkfs` で作ります。
:::
:::

:::q 1.05.2-12 multi
ディレクトリを `/` とは別のパーティションにする理由として正しいものを 2 つ選択してください。
- [x] `/var` を分けると、ログが増えて一杯になっても `/` が一杯にならない
- [x] `/home` を分けると、OS を入れ直すときにユーザーのデータを残しやすい
- [ ] `/etc` を分けると、設定ファイルの読み込みが速くなる
- [ ] `/boot` を分けると、スワップが要らなくなる
- [ ] `/home` を分けると、そのパーティションには ext4 が使えなくなる
:::why
`/var` はログやスプールが増え続ける場所、`/home` はユーザーのデータの場所なので、分けると被害を閉じ込めたり、入れ直しのときに残したりできます（[5.7](#layout)）。`/etc` は `/` から分けられません。`/boot` を分けることとスワップは関係ありません。どのパーティションにも ext4 を使えます。
:::
:::

:::q 1.05.2-13 single
`/` とは別のパーティションにできないディレクトリはどれか。
- [ ] `/home`
- [ ] `/var`
- [ ] `/boot`
- [ ] `/tmp`
- [x] `/etc`
:::why
`/etc` には `/etc/fstab` など、ほかのファイルシステムをマウントするための設定があるので、`/` と同じファイルシステムに置く必要があります（[5.7](#layout)）。`/bin`、`/sbin`、`/lib`、`/dev` も同じです。`/home`、`/var`、`/boot`、`/tmp` は別のパーティションにできます。
:::
:::

:::q 1.05.2-14 multi
スワップとして使えるものを 2 つ選択してください。
- [x] `mkswap` で初期化したパーティション（種類は 82 の Linux swap にしておく）
- [x] `mkswap` で初期化したふつうのファイル
- [ ] tmpfs
- [ ] `/proc/swaps`
- [ ] ESP
:::why
スワップには専用のパーティションと、スワップファイルの 2 つがあり、どちらも `mkswap` で初期化してから `swapon` で使います。パーティションの種類の番号 82 は目印で、それだけではスワップになりません（[5.7](#layout)、[5.10](#swap)）。tmpfs はメモリの上のファイルシステムで、スワップの置き場所ではありません。`/proc/swaps` は使っているスワップを表示するファイル、ESP は UEFI の起動用です。
:::
:::

:::q 1.05.2-15 single
LVM で、ディスクに論理ボリュームを用意するまでの順番として正しいものはどれか。
- [ ] `vgcreate` → `pvcreate` → `lvcreate`
- [x] `pvcreate` → `vgcreate` → `lvcreate`
- [ ] `lvcreate` → `vgcreate` → `pvcreate`
- [ ] `pvcreate` → `lvcreate` → `vgcreate`
:::why
ディスクやパーティションを物理ボリューム（PV）にし、PV を束ねてボリュームグループ（VG）を作り、VG から論理ボリューム（LV）を切り出します（[5.8](#lvm)）。そのあとで LV に `mkfs` して `mount` します。
:::
:::

:::q 1.05.2-16 fill
LVM で、パーティション `/dev/sdb1` を物理ボリュームとして初期化する。空欄に入るコマンドを入力してください。

```text
# ____ /dev/sdb1
```
= pvcreate
:::why
物理ボリュームを作るのは `pvcreate` です（[5.8](#lvm)）。次に `vgcreate VG名 /dev/sdb1` でボリュームグループを作ります。
:::
:::

:::q 1.05.2-17 single
次のコマンドを実行したあと、作られた論理ボリュームのデバイスファイルとして正しいものはどれか。

```text
# lvcreate -L 10G -n lv_home vg01
```
- [x] `/dev/vg01/lv_home`
- [ ] `/dev/lv_home/vg01`
- [ ] `/dev/lvm/lv_home`
- [ ] `/dev/sdb_lv_home`
:::why
論理ボリュームは `/dev/VG名/LV名` で見えます。実体は `/dev/mapper/vg01-lv_home` で、`/dev/vg01/lv_home` はそれへのシンボリックリンクです（[5.8](#lvm)）。`-L` が大きさ、`-n` が LV の名前、最後の引数が VG です。
:::
:::

:::q 1.05.2-18 multi
LVM を使う利点として正しいものを 2 つ選択してください。
- [x] 複数のディスクを 1 つのボリュームグループにまとめ、ディスクより大きな論理ボリュームを作れる
- [x] ボリュームグループに空きがあれば、論理ボリュームを使いながら大きくできる
- [ ] 論理ボリュームには `mkfs` をしなくてもファイルを置ける
- [ ] LVM を使うとパーティション表が要らなくなり、UEFI も要らなくなる
- [ ] 論理ボリュームを伸ばすと、上のファイルシステムも必ず自動で伸びる
:::why
LVM は PV を VG に束ね、そこから LV を切り出すので、ディスクの境目に縛られず、あとから伸ばせます（[5.8](#lvm)）。LV にも `mkfs` が必要です。UEFI やパーティション表とは関係ありません。LV を伸ばしただけではファイルシステムは元の大きさのままで、`-r` を付けるか `resize2fs`・`xfs_growfs` が要ります。
:::
:::

:::q 1.05.2-19 single
論理ボリューム `vg01/lv_data` の、ある瞬間の状態を残すスナップショットを作るコマンドはどれか。
- [ ] `lvsnapshot -L 1G -n snap vg01/lv_data`
- [x] `lvcreate -s -L 1G -n snap vg01/lv_data`
- [ ] `vgcreate -s snap vg01/lv_data`
- [ ] `lvextend -s 1G vg01/lv_data`
:::why
スナップショットは `lvcreate` に `-s`（`--snapshot`）を付け、元の LV を指定して作ります（[5.8](#lvm)）。`lvsnapshot` というコマンドはありません。`vgcreate` は VG を作るコマンド、`lvextend` は LV を伸ばすコマンドです。スナップショットは書き換え前の中身だけを退避するので、元より小さい大きさで作れます。
:::
:::

:::q 1.05.2-20 fill
論理ボリューム `/dev/vg01/lv_data` を 5 GiB 大きくし、その上のファイルシステムも同時に広げる。空欄に入る、大きさを指定するオプションと値を入力してください。

```text
# lvextend ____ -r /dev/vg01/lv_data
```
= -L +5G
= -L+5G
= --size +5G
= --size=+5G
= -L +5g
= -L+5g
= --size +5g
= --size=+5g
:::why
`-L +5G` で「5 GiB 足す」です（[5.8](#lvm)）。`+` を付けないと「5 GiB にする」の意味になります。`-r`（`--resizefs`）が、ファイルシステムも一緒に広げる指定です。
:::
:::

### 1.05.3 ファイルシステムの作成と管理、マウント

:::q 1.05.3-01 single
`mkfs -t xfs /dev/sdb1` と同じ結果になるコマンドはどれか。
- [ ] `mkfs /dev/sdb1`
- [x] `mkfs.xfs /dev/sdb1`
- [ ] `mkfs -L xfs /dev/sdb1`
- [ ] `mount -t xfs /dev/sdb1`
:::why
`mkfs -t 種類` は、`mkfs.種類` というコマンドを呼ぶ入口です（[5.9](#mkfs)）。`-t` を省いた `mkfs /dev/sdb1` は ext2 を作ります。`-L` はラベルの指定です。`mount` は作ったファイルシステムをつなぐコマンドで、作りはしません。
:::
:::

:::q 1.05.3-02 single
`mkfs /dev/sdb1` のように、`-t` で種類を指定せずに `mkfs` を実行したときに作られるファイルシステムはどれか。
- [x] ext2
- [ ] ext4
- [ ] XFS
- [ ] VFAT
:::why
`mkfs` は、種類を指定しないと ext2 を作ります（`mkfs --help` に `when unspecified, ext2 is used`）（[5.9](#mkfs)）。ext4 や XFS を作るには、`-t ext4` や `mkfs.xfs` のように指定します。
:::
:::

:::q 1.05.3-03 multi
ジャーナルを持つファイルシステムを 2 つ選択してください。
- [ ] ext2
- [x] ext3
- [x] XFS
- [ ] VFAT
- [ ] tmpfs
:::why
ext3 は ext2 にジャーナルを足したもので、XFS もジャーナルを持ちます（ext4 も持ちます）（[5.9](#mkfs)）。ext2 と VFAT はジャーナルを持ちません。tmpfs はメモリの上にあり、電源が切れると中身が消えるので、ジャーナルは要りません。
:::
:::

:::q 1.05.3-04 single
tmpfs の説明として正しいものはどれか。
- [ ] 使う前に `mkfs.tmpfs` でフォーマットする
- [ ] CD や DVD のためのファイルシステムである
- [x] 中身をメモリの上に置き、再起動すると中身は残らない
- [ ] 一時ファイルを置くために、ディスクの最後に自動で作られるパーティションである
:::why
tmpfs はメモリの上のファイルシステムで、mkfs は要らず、`mount -t tmpfs tmpfs /mnt/x` のようにいきなりマウントします（[5.9](#mkfs)、[図解 Linux 12.5](../../linux/site/ch12.html#tmpfs)）。`/tmp`、`/run`、`/dev/shm` に使われます。CD・DVD は ISO 9660 や UDF です。
:::
:::

:::q 1.05.3-05 single
Btrfs の特徴として正しいものはどれか。
- [ ] Windows と共用する USB メモリのための、所有者や権限を持たない形式である
- [x] コピーオンライトで、スナップショットや複数のディスクをまとめる機能をファイルシステム自身が持つ
- [ ] 一度作ると大きくすることも小さくすることもできない
- [ ] ext2 にジャーナルを足しただけのもの
:::why
Btrfs はコピーオンライトのファイルシステムで、スナップショット、サブボリューム、複数のディスクをまとめる機能、データのチェックサムを持ちます（[5.9](#mkfs)）。所有者や権限を持たないのは VFAT、ext2 にジャーナルを足したのは ext3 です。
:::
:::

:::q 1.05.3-06 multi
VFAT（FAT32）のファイルシステムがよく使われる場所を 2 つ選択してください。
- [x] Windows や macOS とも読み書きしたい USB メモリ
- [x] UEFI の ESP（EFI System Partition）
- [ ] Linux の `/`（ルート）
- [ ] `/proc`
- [ ] スワップ領域
:::why
VFAT は多くの OS で読めるので、USB メモリや SD カード、UEFI のファームウェアが読む ESP に使われます（[5.5](#mbr-gpt)、[5.9](#mkfs)）。所有者や権限を持たないので、Linux の `/` には向きません。`/proc` は procfs、スワップは `mkswap` で作る専用の形式です。
:::
:::

:::q 1.05.3-07 fill
パーティション `/dev/sdb5` をスワップ領域として初期化するコマンドを入力してください（このあと `swapon` で使い始める）。

```text
# ____ /dev/sdb5
```
= mkswap
= /sbin/mkswap
:::why
スワップ領域を作るのは `mkswap` です（[5.10](#swap)）。作っただけでは使われず、`swapon /dev/sdb5` で使い始めます。`-L` でラベルを付けられます。
:::
:::

:::q 1.05.3-08 single
`swapon -a` の説明として正しいものはどれか。
- [ ] 使っているスワップをすべて止める
- [x] `/etc/fstab` に書かれたスワップをすべて使い始める
- [ ] 使っているスワップの一覧を表示する
- [ ] すべてのパーティションをスワップとして初期化する
:::why
`swapon -a` は、`/etc/fstab` で種類が `swap` の行を全部有効にします。起動のときに実行されます（[5.10](#swap)）。すべて止めるのは `swapoff -a`、一覧は `swapon --show` や `swapon -s`、初期化は `mkswap` です。
:::
:::

:::q 1.05.3-09 multi
現在使われているスワップ領域を確認する方法を 2 つ選択してください。
- [x] `swapon --show`
- [x] `cat /proc/swaps`
- [ ] `mkswap -l`
- [ ] `swapoff -s`
- [ ] `lsmod`
:::why
`swapon --show`（古い形は `swapon -s`）と `/proc/swaps` で、使っているスワップの名前、種類、大きさ、使用量、優先度が見られます（[5.10](#swap)）。`free` の `Swap:` の行でも量はわかります。`mkswap` は作るコマンドで `-l` はなく、`swapoff` は止めるコマンドです。`lsmod` はモジュールの一覧です。
:::
:::

:::q 1.05.3-10 single
次の `/etc/fstab` の行で、5 番目の欄（`0`）の意味として正しいものはどれか。

```text
UUID=6109cec1-643a-4028-8cd9-7dff05eef572  /home  ext4  defaults  0  2
```
- [ ] 起動時に fsck で検査する順番
- [x] `dump` コマンドでバックアップするかどうか
- [ ] マウントするときの優先度
- [ ] 一般ユーザーにマウントを許すかどうか
:::why
6 つの欄は「何を・どこに・種類・オプション・dump・fsck の順番」です（[5.12](#fstab)）。5 番目は dump（0 でしない）、6 番目（ここでは `2`）が fsck の順番です。一般ユーザーに許すかどうかは、4 番目のオプション（`user`）で決めます。
:::
:::

:::q 1.05.3-11 fill
`/etc/fstab` で、ルートファイルシステム（`/`）の 6 番目の欄（起動時の fsck の順番）に通常書く数字を入力してください。
= 1
:::why
fsck の順番は、`/` が 1、ほかの検査するファイルシステムが 2、検査しないもの（tmpfs、proc、swap など）が 0 です（[5.12](#fstab)）。
:::
:::

:::q 1.05.3-12 multi
マウントのオプション `defaults` に含まれるものを 2 つ選択してください。
- [x] `rw`
- [x] `exec`
- [ ] `ro`
- [ ] `noauto`
- [ ] `user`
:::why
`defaults` は `rw`、`suid`、`dev`、`exec`、`auto`、`nouser`、`async` をまとめたものです（[5.11](#mount)）。`ro`、`noauto`、`user` は、それぞれ `rw`、`auto`、`nouser` の反対で、含まれません。
:::
:::

:::q 1.05.3-13 single
`/etc/fstab` のオプション欄に `noauto` と書いた行の説明として正しいものはどれか。
- [ ] その行のファイルシステムは、どんな方法でもマウントできない
- [x] 起動時（`mount -a`）にはマウントされないが、手でマウントできる
- [ ] 一般ユーザーだけがマウントできる
- [ ] 起動時に fsck で検査しない
:::why
`noauto` は「`mount -a`（起動時）ではマウントしない」という意味です（[5.11](#mount)、[5.12](#fstab)）。fstab に書いてあるので、`mount /media/cdrom` のようにマウントポイントだけで手でマウントできます。一般ユーザーに許すのは `user`、fsck をしないのは 6 番目の欄を 0 にすることです。
:::
:::

:::q 1.05.3-14 single
マウント中の `/data` を、外さずに読み取り専用へ切り替えるコマンドはどれか。
- [ ] `mount -r /data`
- [x] `mount -o remount,ro /data`
- [ ] `umount -r /data`
- [ ] `mount -o ro,bind /data`
:::why
`remount` はマウントしたままオプションを付け直します。`ro` と組み合わせて読み取り専用にします（[5.11](#mount)）。`mount -r` は `-o ro` と同じで、新しくマウントするときの指定です。`remount` がないので、マウント中のものを付け直すことにはなりません。`umount -r` は外すのに失敗したときに読み取り専用にするオプションで、外すことが目的です。`bind` はバインドマウントです。
:::
:::

:::q 1.05.3-15 single
`umount /media/usb` を実行したところ、次のように表示された。原因として最も考えられるものはどれか。

```text
umount: /media/usb: target is busy.
```
- [ ] `/media/usb` は読み取り専用でマウントされている
- [x] あるプロセスが `/media/usb` の中のファイルを開いているか、中をカレントディレクトリにしている
- [ ] `/etc/fstab` に `/media/usb` の行がない
- [ ] `/media/usb` にはまだ何もマウントされていない
:::why
`target is busy`（EBUSY）は、そのファイルシステムを使っているプロセスがいるという意味です（[5.11](#mount)、[図解 Linux 12.7](../../linux/site/ch12.html#umount)）。開いているファイルやカレントディレクトリがあると外せません。読み取り専用でも、fstab になくても外せます。何もマウントされていなければ `not mounted` と表示されます。
:::
:::

:::q 1.05.3-16 fill
次の出力のように、ブロックデバイスのファイルシステムの種類、ラベル、UUID を表示する。空欄に入るコマンドを入力してください。

```text
# ____ /dev/sdb1
/dev/sdb1: LABEL="DATA" UUID="6109cec1-643a-4028-8cd9-7dff05eef572" BLOCK_SIZE="1024" TYPE="ext4"
```
= blkid
= /sbin/blkid
:::why
`blkid` は装置ごとに `LABEL=`、`UUID=`、`TYPE=` の形で表示します（[5.12](#fstab)）。`lsblk -f` でも同じ情報を表の形で見られますが、出力の形が違います。
:::
:::

:::q 1.05.3-17 multi
`/etc/fstab` の 1 番目の欄に、デバイスファイル名の代わりに書けるものを 2 つ選択してください。
- [x] `UUID=6109cec1-643a-4028-8cd9-7dff05eef572`
- [x] `LABEL=DATA`
- [ ] `NAME=DATA`
- [ ] `TYPE=ext4`
- [ ] `MOUNT=/data`
:::why
1 番目の欄には、`/dev/sdb1` のほか、`UUID=` と `LABEL=`（GPT なら `PARTUUID=`、`PARTLABEL=` も）が書けます（[5.12](#fstab)）。ディスクを足すと `sdb` などの名前は変わることがあるので、UUID やラベルが勧められます。`TYPE` は 3 番目の欄で書く内容で、`NAME=` や `MOUNT=` という書き方はありません。
:::
:::

:::q 1.05.3-18 single
データを残したまま、ext4 のファイルシステム `/dev/sdb1` のラベルを `data` に変えるコマンドはどれか。
- [x] `e2label /dev/sdb1 data`
- [ ] `mkfs.ext4 -L data /dev/sdb1`
- [ ] `lsblk -L data /dev/sdb1`
- [ ] `mount -L data /dev/sdb1`
:::why
ext 系のラベルは `e2label 装置 ラベル`（または `tune2fs -L ラベル 装置`）で付け替えます（[5.12](#fstab)）。`mkfs.ext4 -L` もラベルを付けますが、ファイルシステムを作り直すので中のデータは読めなくなります。`mount -L data` は「ラベルが data のものをマウントする」という指定で、ラベルを変えるものではありません。`lsblk` に `-L` はありません。
:::
:::

:::q 1.05.3-19 single
`/media` と `/mnt` の使い分けとして正しいものはどれか。
- [ ] `/media` は管理者が一時的に手でマウントする場所、`/mnt` は USB メモリなどが自動でマウントされる場所
- [x] `/media` は USB メモリや CD など取り外せる媒体が自動でマウントされる場所、`/mnt` は管理者が一時的に手でマウントする場所
- [ ] どちらもスワップ領域をマウントする場所
- [ ] `/media` は音声や動画のファイルを置く場所で、マウントポイントには使わない
:::why
取り外せる媒体は `/media` の下（デスクトップでは `/media/ユーザー名/ラベル`）に自動でマウントされ、`/mnt` は管理者が一時的に使う場所です（[5.11](#mount)）。スワップはマウントしません。`/media` は名前は似ていますが、音声や動画の置き場所ではありません。
:::
:::

:::q 1.05.3-20 single
MBR の説明として正しいものはどれか。
- [x] ディスクの先頭 512 バイトに、ブートローダの最初の部分とパーティション表が入っている
- [ ] ディスクの末尾に、パーティション表の控えが置かれている
- [ ] 既定で 128 個のパーティションを作れる
- [ ] UEFI のファームウェアが読むブートローダのファイルを置く、FAT のパーティションのことである
:::why
MBR は先頭 512 バイトで、ブートローダ（446 バイト）、パーティション表（64 バイト）、終わりの印（2 バイト）でできています（[5.5](#mbr-gpt)）。末尾の控えと 128 個は GPT の特徴です。UEFI のブートローダを置く FAT のパーティションは ESP です。
:::
:::
