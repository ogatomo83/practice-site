## パーミッションは 9 文字と 3 桁で読む {#perm}

`ls -l` の先頭 10 文字は、1 文字目がファイルの種類、残りの 9 文字が「持ち主（u）・グループ（g）・その他（o）」の 3 組の権限です（[図解 Linux 4.2](../../linux/site/ch04.html#rwx)）。試験では、この 9 文字と 8 進数の 3 桁を、すばやく行き来できることが求められます。

`chmod` には、2 つの書き方があります。

- **8 進数**：`chmod 754 file`。3 組を全部まとめて指定し直す
- **記号**：`chmod u+x,g-w,o= file`。**いまの権限を元に**、一部だけ足す・引く・決める

記号の書き方は「だれの（u / g / o / a）」「どうする（+ / - / =）」「何を（r / w / x / s / t）」の 3 つを並べます。カンマで区切れば、いちどに何組でも書けます。`=` は「その組をこれだけにする」で、`o=` のように右を空にすると、その組の権限を全部取ります。

```sh run title="記号と 8 進数で変える"
cd
mkdir lab
cd lab
touch a.txt
ls -l a.txt
chmod u+x,g+w,o= a.txt
ls -l a.txt
chmod a=r a.txt
ls -l a.txt
chmod 640 a.txt
ls -l a.txt
stat -c '%a %A %n' a.txt
chmod -R 755 /home/you/lab
ls -ld /home/you/lab
```

`touch` で作った直後は 644（`rw-r--r--`）でした。`u+x,g+w,o=` で、持ち主に x を足し、グループに w を足し、その他を空にして `rwxrw----`（760）になりました。`a=r` は、3 組とも `r` だけにします。8 進数の `640` は、3 組を全部決め直します。`stat -c '%a'` は、権限を 8 進数で表示します。`-R` は、ディレクトリの中まで再帰的に変えるオプションです（大文字の R。`chown -R`、`chgrp -R` も同じ）。

| 書き方 | 意味 |
| --- | --- |
| `u` / `g` / `o` / `a` | 持ち主 / グループ / その他 / 全員（ugo） |
| `+` / `-` / `=` | 足す / 取る / それだけにする |
| `r` = 4、`w` = 2、`x` = 1 | 足して 1 桁にする。7 = rwx、6 = rw-、5 = r-x、4 = r-- |
| `chmod -R` | ディレクトリの中まで再帰的に |
| よく出る数字 | 755 `rwxr-xr-x`、644 `rw-r--r--`、700 `rwx------`、600 `rw-------` |

:::warn 試験の注意
- 8 進数は「3 組を全部決め直す」、記号は「指定した所だけ変える」。`chmod g+w` は、ほかのビットを変えません
- `a` を省いて `chmod +x file` と書くと、全員に x が付きます。ただし、このときは umask で取り除かれるビットは付きません（[図解 Linux 4.6](../../linux/site/ch04.html#umask)）
- 再帰は `-R`（大文字）。`-r` は chmod では権限の「r を取る」という意味の記号と読まれることがあり、オプションではありません
:::

### chown と chgrp：持ち主とグループを変える {#chown}

`chown` は持ち主を、`chgrp` はグループを変えます（[図解 Linux 4.7](../../linux/site/ch04.html#chown)）。`chown` は「持ち主:グループ」の形で、両方をいちどに変えられます。

```sh run root title="chown の書き方"
cd /home/you/lab
chown alice a.txt
ls -l a.txt
chown :staff a.txt
ls -l a.txt
chown bob:users a.txt
ls -l a.txt
chown alice: a.txt
ls -l a.txt
chown -R you:you /home/you/lab
ls -l a.txt
```

`chown alice: a.txt` のように、コロンの後ろを空にすると、グループは alice の主グループになります。古い書き方の `bob.users`（ドット区切り）も使えますが、ユーザー名にドットが入ると紛らわしいので、試験でもコロンが正解になります。

| 書き方 | 意味 |
| --- | --- |
| `chown 持ち主 file` | 持ち主だけ変える |
| `chown 持ち主:グループ file` | 両方変える |
| `chown :グループ file` | グループだけ変える（`chgrp グループ file` と同じ） |
| `chown 持ち主: file` | 持ち主と、その人の主グループに変える |
| `chown -R` / `chgrp -R` | ディレクトリの中まで再帰的に |
| だれができるか | 持ち主を変えるのは **root だけ**。グループは、持ち主が**自分の入っているグループ**へなら変えられる |

## umask は「与えない」ビット {#umask}

新しく作るファイルの権限は、**umask** で決まります（[図解 Linux 4.6](../../linux/site/ch04.html#umask)）。プログラムはふつう、ファイルなら 666、ディレクトリなら 777 で作ろうとします。カーネルは、そこから umask で 1 になっているビットを**取り除きます**。

```sh run title="umask を 027 にして作る"
umask
umask 027
touch f027
mkdir d027
ls -ld f027 d027
umask -S
umask 022
```

ファイルは 640、ディレクトリは 750 になりました。`umask -S` は、umask を「**作るときに残す権限**」の記号で表示します（`u=rwx,g=rx,o=` は、027 を裏返したものです）。最後に既定の 022 へ戻しています。

計算の手順を表にまとめます。

| umask | ファイル（666 から） | ディレクトリ（777 から） |
| --- | --- | --- |
| 022（よくある既定） | 644 | 755 |
| 002 | 664 | 775 |
| 027 | 640 | 750 |
| 077 | 600 | 700 |
| 033 | **644**（633 ではない） | 744 |

:::warn 試験の注意：引き算ではない
umask が 033 のとき、ファイルは 666 − 033 = 633 ではなく **644** です。666 にはもともと x がないので、umask の x のビットは取り除くものがありません。「ファイルは x が付かない」と覚えておけば、計算で迷いません。ディレクトリは 777 から取り除くので、744 になります。
:::

umask は**プロセスごと**の値で、子プロセスに受け継がれます。シェルで `umask 027` と打っても、そのシェルとそこから起動したものにしか効きません。ログインのたびに同じにしたいときは、`~/.bashrc` や `~/.profile`（すべてのユーザーなら `/etc/profile`）に書きます。なお、umask が効くのは「作るとき」だけです。すでにあるファイルの権限や、`chmod 777` の結果は変えません。`mkdir -m 700` のように作るときに権限を明示した場合も、その値がそのまま使われます。

| 覚えること | 内容 |
| --- | --- |
| `umask` | いまの値を 8 進数で表示（例 `0022`） |
| `umask 027` | 値を変える（そのシェルの中だけ） |
| `umask -S` | 残す権限を記号で表示（例 `u=rwx,g=rx,o=rx`） |
| 計算 | ファイル = 666 から、ディレクトリ = 777 から、umask のビットを取り除く |

## SUID・SGID・スティッキービットの s と t {#special}

12 ビットの先頭の 3 つが、特別なビットです（[図解 Linux 4.9](../../linux/site/ch04.html#special)）。8 進数では、3 桁の前に 4 桁目として書きます。

| ビット | 8 進数 | 記号 | 表示の場所 | 働き |
| --- | --- | --- | --- | --- |
| SUID（セットユーザー ID） | 4000 | `u+s` | 持ち主の x の場所が `s` | 実行すると、**ファイルの持ち主**の権限で動く（例 `/usr/bin/passwd`） |
| SGID（セットグループ ID） | 2000 | `g+s` | グループの x の場所が `s` | ファイル：ファイルのグループの権限で動く。ディレクトリ：中に作ったファイルのグループが、**ディレクトリのグループ**になる |
| スティッキービット | 1000 | `o+t` | その他の x の場所が `t` | ディレクトリの中のファイルを、**そのファイルの持ち主、ディレクトリの持ち主、root しか消せない・名前を変えられない**（例 `/tmp`） |

表示で大事なのは、**小文字と大文字**の違いです。特別なビットは x と同じ場所に表示されるので、x があるかどうかを文字の大きさで表します。

- `s` / `t`（小文字）：特別なビットと x の**両方**が立っている
- `S` / `T`（大文字）：特別なビットだけが立っていて、x は**ない**

```sh run title="s と S、t と T"
touch sp
chmod 4755 sp
ls -l sp
chmod 4644 sp
ls -l sp
chmod 2755 sp
ls -l sp
chmod 6755 sp
ls -l sp
mkdir pub
chmod 1777 pub
ls -ld pub
chmod 1776 pub
ls -ld pub
```

`4644` は持ち主に x がないので `rwS` になりました。`6755` は SUID と SGID の両方（4 + 2）で `rwsr-sr-x` です。`1776` は、その他の x がないので `T` です。

SGID をディレクトリに付けると、グループで共有する場所が作れます。you は staff グループに入っています。

```sh run title="SGID のディレクトリと、SUID のファイル探し"
mkdir share
chgrp staff share
chmod g+s share
ls -ld share
touch share/new
ls -l share
find /usr/bin -perm -4000
```

`share/new` のグループは、you の主グループ（you）ではなく、ディレクトリのグループ staff になりました。

最後の行は、`/usr/bin` の中で SUID が付いたファイルを探しています。SUID のファイルは、悪用されると root の権限を取られる入口になるので、管理者は `find` で一覧を作って確かめます。`-perm -4000` の `-` は「**少なくともこのビットが立っている**」という意味です（[find の節](#find)）。

:::warn 試験の注意
- `s` と `S`、`t` と `T`：大文字は「x がない」。`-rwSr--r--` は、SUID は立っているが持ち主に実行権がないので、実行できない
- 数字は SUID = 4、SGID = 2、スティッキー = 1。並びは「4 桁目」で、`chmod 4755` の 4 が SUID。`chmod 1777` はスティッキー
- スティッキービットは**ディレクトリ**に付けて意味があるもの。記号では `o+t`（`+t` でもよい）
- SUID のファイル探しは `find / -perm -4000`。`-perm 4000`（`-` なし）は「権限がちょうど 4000」のものだけになり、ふつうは何も見つからない
:::

## 見る・作る・コピーする・消す {#ops}

ここからは 1.02.2 です。ファイルを扱う基本のコマンドと、名前のパターン（ワイルドカード）を整理します。

### ls・file・touch・mkdir：見る、作る {#basic}

まず、ファイルを見るコマンドと作るコマンドのオプションを、試験で問われる分だけ整理します（[図解 Linux 3.4](../../linux/site/ch03.html#ls)、[3.6](../../linux/site/ch03.html#ops)）。

```sh run title="ls のオプション"
cd /home/you
ls -a
ls -A
ls -d notes
ls -F
ls -lh /usr/bin/ls
ls -R notes
```

`-a` は `.` と `..` を含めて全部、`-A` は `.` と `..` だけを除いて隠しファイルを出します。`-d` はディレクトリの**中身ではなく、そのもの**を表示します（`ls -ld /tmp` のように `-l` と組み合わせて使います）。

| ls のオプション | 意味 |
| --- | --- |
| `-l` | 詳しく（権限、リンク数、持ち主、グループ、大きさ、更新時刻） |
| `-a` / `-A` | 隠しファイルも（`-A` は `.` と `..` を除く） |
| `-d` | ディレクトリそのものを表示 |
| `-F` | 種類の印を付ける（`/` `*` `@` `\|` `=`。[1.02.3](#lsfi)） |
| `-i` | inode 番号を表示 |
| `-h` | 大きさを K、M、G で（`-l` と一緒に） |
| `-R` | サブディレクトリの中も再帰的に |
| `-t` / `-S` / `-r` | 更新時刻順 / 大きさ順 / 逆順 |

`file` は、拡張子ではなく**中身**を調べて種類を表示します。`touch` は、ファイルがなければ空のファイルを作り、あれば**タイムスタンプを今にする**コマンドです。`mkdir -p` は途中のディレクトリもまとめて作り、すでにあってもエラーにしません。

```sh run error title="file、touch、mkdir"
file hello.sh notes /etc/passwd /usr/bin/ls /dev/null
touch -c nothing
ls nothing
mkdir -p lab/x/y/z
mkdir -m 700 lab/secret
ls -ld lab/x/y/z lab/secret
```

`touch -c` は「なければ作らない」なので、`nothing` はできていません（`ls` が失敗するのは正しい結果です）。`mkdir -m 700` は、umask に関係なく 700 で作ります。

| コマンド | 主なオプション |
| --- | --- |
| `touch` | `-c` 作らない、`-t [[CC]YY]MMDDhhmm[.ss]` 時刻を指定、`-a` アクセス時刻だけ、`-m` 更新時刻だけ |
| `mkdir` | `-p` 親もまとめて作る、`-m モード` 権限を指定 |
| `file` | 中身から種類を判定（`ASCII text`、`directory`、`ELF 64-bit …`） |

```console
# Debian 12 で実際に実行した例（小さな Linux の touch は -t を持たない）
$ touch -t 202601011230 t
$ ls -l --time-style=+%F_%R t
-rw-r--r-- 1 root root 0 2026-01-01_12:30 t
```

### cp・mv・rm・rmdir のオプション {#cp}

コピー、移動、削除の 4 つは、オプションの意味がよく似ていて、試験の引っかけになりやすいところです。

```sh run title="cp と cp -p と cp -a"
ls -l memo.txt
cp memo.txt lab/m1
cp -p memo.txt lab/m2
cp -a memo.txt lab/m3
ls -l lab/m1 lab/m2 lab/m3
```

ふつうの `cp` で作ったコピーは、更新時刻が「いま」になります。`-p`（preserve）は、権限・持ち主・タイムスタンプを元のまま保ちます。`-a`（archive）は、`-p` の働きに加えて、**ディレクトリを再帰的に**コピーし、**シンボリックリンクはリンクのまま**コピーします。バックアップに向いた「全部そのまま」のオプションです。

```sh run error title="ディレクトリには -r が要る"
cp notes lab/n1
cp -r notes lab/n1
cp -a notes lab/n2
ls -l lab/n1 lab/n2
```

`-r` がないと、ディレクトリはコピーされません（`omitting directory`）。`-r` のコピーは中身の時刻が「いま」になり、`-a` は元の時刻のままです。

| オプション | cp | mv | rm |
| --- | --- | --- | --- |
| `-i` | 上書きの前に確かめる | 上書きの前に確かめる | 消す前に 1 つずつ確かめる |
| `-f` | 書き込めない先を消してでもコピー | 確かめずに上書き | 確かめない。ないファイルもエラーにしない |
| `-n` | 上書きしない | 上書きしない | — |
| `-r` / `-R` | ディレクトリを再帰的に | （不要。ディレクトリもそのまま動かせる） | ディレクトリを中身ごと |
| `-p` | 権限・持ち主・時刻を保つ | — | — |
| `-a` | `-p` + `-r` + リンクはリンクのまま | — | — |
| `-u` | コピー元が新しいときだけ | 移動元が新しいときだけ | — |
| `-b` | — | 上書きされるファイルのバックアップ（`名前~`）を残す | — |
| `-v` | したことを表示 | したことを表示 | したことを表示 |

`rmdir` は、**空の**ディレクトリしか消せません。中にファイルがあると失敗します。`-p` を付けると、指定したパスの親も順に消します。`rmdir -p a/b/c` は `rmdir a/b/c a/b a` と同じです。

```sh run error title="rmdir、rmdir -p、rm -r"
rmdir lab/x
rmdir -p lab/x/y/z
ls lab
rm -r lab/n1
rm -rf lab/n2 lab/no-such-file
ls lab
```

`rmdir lab/x` は、中に y があるので `Directory not empty` で失敗します。`rmdir -p lab/x/y/z` は、z、y、x と消していき、`lab` で止まりました。`lab` にはほかのファイルがあるので、ここで `Directory not empty` のエラーになります（それまでに消したものは消えたままです）。`rm -r` は中身ごと消します。`rm -rf` は、ないファイルを指定しても何も言いません。

:::warn 試験の注意
- ディレクトリをコピーするのは `cp -r`（`-R` も同じ）。`mv` は `-r` なしでディレクトリを動かせる
- 権限と時刻を保つのは `cp -p`。ディレクトリごと全部を保つのは `cp -a`
- 空のディレクトリを消すのは `rmdir`（または `rm -d`）。中身ごとなら `rm -r`。`rmdir -p` は親までさかのぼって消す
- `rm` と `mv` で `-f` と `-i` を両方書くと、**後に書いたほう**が効く
:::

### ワイルドカード：名前のパターン {#glob}

`*` や `?` は、コマンドではなく**シェルが**ファイル名に展開します（[図解 Linux 2 章](../../linux/site/ch02.html)）。コマンドに渡るのは、展開した後の名前の並びです。

| パターン | 意味 | 例 |
| --- | --- | --- |
| `*` | 0 文字以上の、どんな文字列にも合う | `*.txt` |
| `?` | ちょうど 1 文字に合う | `????.txt` は名前が 4 文字の .txt |
| `[abc]` | 括弧の中のどれか 1 文字 | `[mn]*` は m か n で始まる名前 |
| `[a-c]` | 範囲の中の 1 文字 | `file[0-9]` |
| `[!a-c]`、`[^a-c]` | 括弧の中**以外**の 1 文字 | `[!f-n]*` |
| `{a,b}` | a と b の両方に**書き換える**（ファイルがなくても作る。ブレース展開） | `*.{txt,csv}` |

```sh run title="ワイルドカード"
ls
ls ????.txt
ls [mn]*
ls [!f-n]*
ls *.{txt,csv}
echo file{1,2,3}
```

`*` は、先頭が `.` の名前（隠しファイル）には合いません。`ls *` で隠しファイルが出ないのはこのためです。

## まとめる・縮める・写す：tar、圧縮、dd {#archive}

バックアップやファイルの受け渡しで使う、tar、3 つの圧縮コマンド、dd です。tar と圧縮は、図解 Linux になかった新しい範囲です。

### tar：まとめる、取り出す {#tar}

`tar` は、たくさんのファイルを 1 つのファイル（**アーカイブ**）にまとめます。tar 自身は圧縮しません。圧縮は gzip・bzip2・xz の仕事で、tar のオプション 1 文字でそれを呼び出せます。

```fig graph tar はまとめるだけ。z / j / J を付けると、まとめた後に gzip / bzip2 / xz で圧縮する
{
  col: 200, row: 92,
  nodes: [
    { id: 'files', label: 'docs/', sub: 'たくさんのファイル', x: 0, y: 0.5, kind: 'stack', mono: true },
    { id: 'tar', label: 'docs.tar', sub: 'まとめただけ', x: 1, y: 0.5, mono: true },
    { id: 'gz', label: 'docs.tar.gz', sub: 'tar czf（gzip）', x: 2, y: 0, kind: 'accent', mono: true },
    { id: 'bz', label: 'docs.tar.bz2', sub: 'tar cjf（bzip2）', x: 2, y: 1, kind: 'accent', mono: true },
    { id: 'xz', label: 'docs.tar.xz', sub: 'tar cJf（xz）', x: 2, y: 2, kind: 'accent', mono: true },
  ],
  edges: [
    { from: 'files', to: 'tar', label: 'tar cf' },
    { from: 'tar', to: 'gz', label: 'z' },
    { from: 'tar', to: 'bz', label: 'j' },
    { from: 'tar', to: 'xz', label: 'J' },

```

tar の操作は、**何をするか（c / x / t）を必ず 1 つ**選び、必要なら圧縮の種類とほかのオプションを足します。

| オプション | 意味 |
| --- | --- |
| `c` | create。アーカイブを作る |
| `x` | extract。取り出す（展開する） |
| `t` | list。中身の一覧を表示する（取り出さない） |
| `f ファイル` | アーカイブのファイル名を指定する。**すぐ後ろの引数がファイル名** |
| `z` | gzip（`.tar.gz`、`.tgz`） |
| `j` | bzip2（`.tar.bz2`） |
| `J` | xz（`.tar.xz`。大文字） |
| `v` | 処理したファイルの名前を表示する |
| `C ディレクトリ` | そのディレクトリに移ってから処理する（展開先を決める） |
| `r` / `u` | 圧縮していないアーカイブに足す / 新しいものだけ足す |

小さな Linux には tar がないので、Debian 12 で実際に動かした結果を見ます。

```console
$ tar cvf p.tar proj
proj/
proj/src/
proj/src/b.c
proj/a.txt
$ tar tvf p.tar
drwxr-xr-x root/root         0 2026-11-16 11:15 proj/
drwxr-xr-x root/root         0 2026-11-16 11:15 proj/src/
-rw-r--r-- root/root         6 2026-11-16 11:15 proj/src/b.c
-rw-r--r-- root/root         6 2026-11-16 11:15 proj/a.txt
$ tar czf p.tgz proj
$ tar tzf p.tgz
proj/
proj/src/
proj/src/b.c
proj/a.txt
$ mkdir out
$ tar xzf p.tgz -C out
$ find out
out
out/proj
out/proj/src
out/proj/src/b.c
out/proj/a.txt
```

`-` を付けても付けなくても書けます（`tar czf` と `tar -czf` は同じ）。GNU tar は、展開のときは圧縮の種類を自分で見分けるので、`tar xf p.tgz` でも展開できます。ただ、作るとき（`c`）は z / j / J を書かないと圧縮されません。

:::warn 試験の注意：f はファイル名の直前に
`-` を付けた書き方で `f` を最後に置かないと、`f` のすぐ後ろの文字がファイル名と読まれます。`tar -cfv backup.tar docs` は、`v` という名前のアーカイブを作り、`backup.tar` と `docs` をその中に入れようとします（Debian 12 で実行すると `tar: backup.tar: Cannot stat: No such file or directory` と出て、`v` というファイルができます）。正しくは `tar -cvf backup.tar docs` です。
:::

### gzip・bzip2・xz：圧縮と展開 {#compress}

3 つの圧縮コマンドは、使い方がほぼ同じです。違うのは、拡張子と、展開・表示のコマンド名です。

| | gzip | bzip2 | xz |
| --- | --- | --- | --- |
| 拡張子 | `.gz` | `.bz2` | `.xz` |
| 圧縮 | `gzip file` | `bzip2 file` | `xz file` |
| 展開 | `gunzip file.gz`、`gzip -d` | `bunzip2 file.bz2`、`bzip2 -d` | `unxz file.xz`、`xz -d` |
| 展開して標準出力へ | `zcat`、`gzip -dc` | `bzcat` | `xzcat` |
| tar のオプション | `z` | `j` | `J` |
| 縮み方（一般に） | ふつう・速い | よく縮む | いちばんよく縮む・遅い |

共通のオプションも覚えます。

| オプション | 意味 |
| --- | --- |
| `-d` | 展開する（decompress） |
| `-k` | 元のファイルを残す（keep）。既定では、圧縮すると**元のファイルは消えて** `.gz` だけが残る |
| `-c` | 結果を標準出力へ書く。元のファイルは残る（`gzip -c file > file.gz`） |
| `-1`〜`-9` | 速さ優先 〜 圧縮率優先 |
| `-l` | 圧縮ファイルの情報（gzip と xz） |
| `-r` | ディレクトリの中のファイルを 1 つずつ圧縮（gzip） |
| `-v` | 圧縮率などを表示 |

Debian 12 で、同じテキストを 3 つの方法で圧縮した結果です（`-k` で元を残しています）。

```console
$ gzip -k big.txt; bzip2 -k big.txt; xz -k big.txt
$ ls -l big.txt*
-rw-r--r-- 1 root root 105447 Nov 16 11:17 big.txt
-rw-r--r-- 1 root root  14782 Nov 16 11:17 big.txt.bz2
-rw-r--r-- 1 root root  33903 Nov 16 11:17 big.txt.gz
-rw-r--r-- 1 root root  11508 Nov 16 11:17 big.txt.xz
$ echo hi > a; echo yo > b
$ gzip a b
$ ls a* b*
a.gz
b.gz
$ gzip -d a.gz
$ ls a*
a
$ gzip d
gzip: d is a directory -- ignored
```

`gzip a b` は、2 つを 1 つにまとめるのではなく、`a.gz` と `b.gz` を**別々に**作ります。ディレクトリは圧縮できません。ディレクトリをまとめて圧縮したいときは、`tar czf` を使います。

「まとめる」のは tar、「縮める」のは gzip・bzip2・xz、という役割分担を覚えておくと、選択肢の誤りがすぐ分かります。`gzip -r dir` も、dir の中の各ファイルを別々に `.gz` にするだけで、1 つのファイルにはなりません。

### dd：ブロック単位で写す {#dd}

`dd` は、入力から出力へ、決まった大きさのブロックで、決まった回数だけデータを写します。ディスク全体の複製、MBR（ディスクの先頭 512 バイト）のバックアップ、決まった大きさのファイル作りに使います。

| 指定 | 意味 |
| --- | --- |
| `if=入力` | 入力ファイル（省くと標準入力） |
| `of=出力` | 出力ファイル（省くと標準出力） |
| `bs=大きさ` | 1 回に読み書きする大きさ（ブロックの大きさ。既定 512 バイト。`1K`、`1M` も書ける） |
| `count=回数` | 何ブロック写すか |
| `skip=N` / `seek=N` | 入力の先頭 N ブロックを飛ばす / 出力の先頭 N ブロックを飛ばして書く |

```sh run title="dd で 4 KiB のファイルを作り、一部を切り出す"
dd if=/dev/zero of=lab/zero.img bs=1K count=4
ls -l lab/zero.img
printf 'ABCDEFGHIJKLMNOPQRST' > lab/abc
dd if=lab/abc of=lab/part bs=5 count=2 status=none
cat lab/part; echo
dd if=lab/abc bs=5 skip=2 count=1 status=none; echo
```

`bs=1K count=4` で 4096 バイトです。終わると、写したブロックの数（`4+0 records in`）と量を**標準エラー**に表示します。`skip=2` は、入力の先頭 2 ブロック（10 バイト）を飛ばしました。

実際のディスクを使う例は、次のようになります（実行しない例）。

```console
# dd if=/dev/sda of=/dev/sdb bs=4M         … sda をまるごと sdb へ複製
# dd if=/dev/sda of=mbr.bin bs=512 count=1 … 先頭 512 バイト（MBR）をファイルへ
# dd if=/dev/zero of=swapfile bs=1M count=1024 … 1 GiB の、中身が 0 のファイルを作る
```

`if` と `of` を取り違えると、ディスクを上書きして壊します。「in = 読む元、out = 書く先」です。`bs` はバイト数、`count` は回数なので、写す量は **bs × count** です。

## find：条件でファイルを探す {#find}

`find 場所 条件 動作` の形で、ディレクトリの木を**いま実際に**たどって探します（[図解 Linux 3.9](../../linux/site/ch03.html#find)）。場所を省くとカレントディレクトリ、動作を省くと `-print`（パスを表示）です。

| 条件 | 意味 |
| --- | --- |
| `-name パターン` | 名前がパターンに合う（大文字小文字を区別。`-iname` は区別しない）。シェルに展開されないよう `'*.txt'` と引用符で囲む |
| `-type f` / `d` / `l` | 通常ファイル / ディレクトリ / シンボリックリンク |
| `-size +10M` | 大きさ。`+` はより大きい、`-` はより小さい。単位 `c`（バイト）、`k`、`M`、`G`。単位なしは 512 バイトのブロック |
| `-mtime n` | 更新が n 日前（`-mmin` は分。`-atime` はアクセス、`-ctime` は inode の変更） |
| `-newer ファイル` | そのファイルより後に更新された |
| `-perm モード` | 権限がちょうどモード。`-perm -モード` はそのビットを**全部含む**、`-perm /モード` は**どれかを含む** |
| `-user 名前` / `-group 名前` | 持ち主 / グループ |
| `-inum 番号` / `-samefile ファイル` | inode 番号で（ハードリンクを探す。[1.02.3](#links)） |
| `-maxdepth n` | n 階層までしか下りない |

`-mtime` の数え方は、24 時間を 1 日として**切り捨て**ます。

```fig layout -mtime の数え方。「いま」から 24 時間ごとに区切り、何番目の区切りに入るかで比べる
{

  rows: [
    { label: 'いつ更新', cells: [
      { t: '0〜24 時間前', w: 2, kind: 'plain' }, { t: '24〜48 時間前', w: 2, kind: 'plain' }, { t: '48 時間以上前', w: 3, kind: 'plain' },
    ] },
    { label: '日数', cells: [
      { t: '0', w: 2, kind: 'pad' }, { t: '1', w: 2, kind: 'pad' }, { t: '2, 3, 4…', w: 3, kind: 'pad' },
    ] },
    { label: '-mtime -1', cells: [
      { t: '合う', w: 2, kind: 'accent' }, { t: '', w: 2, kind: 'empty' }, { t: '', w: 3, kind: 'empty' },
    ] },
    { label: '-mtime 1', cells: [
      { t: '', w: 2, kind: 'empty' }, { t: '合う', w: 2, kind: 'stack' }, { t: '', w: 3, kind: 'empty' },
    ] },
    { label: '-mtime +1', cells: [
      { t: '', w: 2, kind: 'empty' }, { t: '', w: 2, kind: 'empty' }, { t: '合う', w: 3, kind: 'heap' },

  ],

```

`-mtime +7` は「8 日以上前（7 日を超えて前）」、`-mtime -7` は「7 日未満（1 週間以内）」です。Debian 12 で、12 時間前・36 時間前・60 時間前のファイルを作って確かめた結果が、図のとおりになります（`-1` は 12 時間前だけ、`1` は 36 時間前だけ、`+1` は 60 時間前だけ）。

```sh run title="名前、種類、大きさ、時刻、持ち主、権限、-exec"
find . -name '*.txt' -type f
find lab -type d
find . -size +100c -type f
find . -mtime +2 -type f
find lab -mmin -10 -type f
find lab -user you -name 'm*'
find lab -perm 640
find lab -name 'm*' -exec ls -l {} \;
find lab -name 'm*' -exec rm {} +
ls lab
```

ホームの元からあるファイルは 3 月 28 日、いまは 4 月 1 日なので、`-mtime +2` に合います。`lab` の中は、いま作ったファイルなので `-mmin -10`（10 分以内）に合います。

`-exec コマンド {} \;` は、見つかったファイルごとにコマンドを実行します。`{}` が見つかったパスに置き換わり、`\;` がコマンドの終わりです（`;` はシェルの区切りなので `\` で守ります）。`{} +` で終えると、見つかったものをまとめて 1 回のコマンドに渡します（上の例では、`rm` が 1 回だけ動き、m1・m2・m3 をまとめて消しました）。`-ok` は `-exec` と同じですが、1 つずつ実行してよいかをたずねます。

:::warn 試験の注意
- `-exec` は `\;`（または `{} +`）で終える。`\;` を忘れると 「missing argument to -exec」 のエラー
- `-perm 4000` は「ちょうど」、`-perm -4000` は「含む」。SUID を探すのは `-4000`
- `-size` は単位なしだと 512 バイトのブロック。`-size +100M` で 100 MiB を超えるもの
- `-mtime +7` は「7 日より前」、`-mtime -7` は「7 日以内」
:::

## ハードリンクとシンボリックリンク {#links}

ここからは 1.02.3 です。ファイルの名前は、ディレクトリの中の「名前 → inode 番号」の対応にすぎません（[図解 Linux 11.2](../../linux/site/ch11.html#directory)）。**ハードリンク**は、同じ inode に名前をもう 1 つ付けたもの、**シンボリックリンク**は、行き先のパスを中身に書いた別のファイルです（[図解 Linux 11.3](../../linux/site/ch11.html#hardlink)、[11.4](../../linux/site/ch11.html#symlink)）。

```fig graph ハードリンクは同じ inode を指す 2 つ目の名前。シンボリックリンクは、パスを書いた自分の inode を持つ
{
  col: 210, row: 90,
  nodes: [
    { id: 'orig', label: 'orig', sub: '名前', x: 0, y: 0, mono: true },
    { id: 'hard', label: 'hard', sub: '名前（ln）', x: 0, y: 1, mono: true },
    { id: 'soft', label: 'soft', sub: '名前（ln -s）', x: 0, y: 2, mono: true },
    { id: 'i1', label: 'inode 301', sub: 'リンク数 2・中身 abc', x: 1.5, y: 0.5, kind: 'accent', mono: false },
    { id: 'i2', label: 'inode 302', sub: '種類 l・中身「orig」', x: 1.5, y: 2, kind: 'stack', mono: false },
  ],
  edges: [
    { from: 'orig', to: 'i1' }, { from: 'hard', to: 'i1' },
    { from: 'soft', to: 'i2' },
    { from: 'i2', to: 'orig', label: 'パスでたどる', style: 'muted', curve: -1 },
  ],
}
```

```sh run title="ln と ln -s"
cd /home/you/lab
printf 'abc\n' > orig
ln orig hard
ln -s orig soft
ls -li orig hard soft
```

`orig` と `hard` は inode 番号（1 列目）が同じで、リンク数（3 列目）が 2 です。`soft` は別の inode を持ち、種類が `l`、権限はいつも `rwxrwxrwx`、大きさは「`orig`」という 4 文字ぶんです。

元の名前を消すと、違いがはっきりします。

```sh run error title="元を消すと、シンボリックリンクは切れる"
rm orig
cat hard
ls -l hard soft
cat soft
```

`hard` は inode を直接指しているので、読めます（リンク数は 1 に減りました）。`soft` は「orig」というパスをたどるので、その名前がなくなると `No such file or directory` になります。行き先のないシンボリックリンクを、**壊れたリンク**（ぶら下がったリンク）と呼びます。

ハードリンクには、2 つの制限があります。

```sh run error title="ハードリンクにできないもの"
ln /home/you/notes nlink
echo hi > /tmp/x
ln /tmp/x xlink
ln -s /tmp/x xsym
ls -l xsym
ln -sf hard soft
ls -l soft
cat soft
```

ディレクトリにはハードリンクを作れません。また、inode 番号はファイルシステムの中でしか意味がないので、**別のファイルシステム**（ここでは tmpfs の `/tmp`）のファイルにもハードリンクは作れません（`Invalid cross-device link`）。シンボリックリンクなら、どちらもできます。

すでにある名前にリンクを作ると `File exists` で失敗します。最後の `ln -sf hard soft` のように `-f` を付けると、その名前を消してから作り直します。切れていた `soft` が `hard` を指すようになり、また読めるようになりました。

| | ハードリンク（`ln`） | シンボリックリンク（`ln -s`） |
| --- | --- | --- |
| inode | 元と**同じ** | **自分の** inode を持つ |
| リンク数 | 1 増える | 元のリンク数は変わらない |
| 元の名前を消すと | そのまま読める | 切れる（No such file or directory） |
| ディレクトリ | 作れない | 作れる |
| 別のファイルシステム | 作れない | 作れる |
| ls -l の表示 | ふつうのファイルと同じ | 種類 `l`、`名前 -> 行き先`、権限 `rwxrwxrwx` |
| 引数の順番 | `ln 元 新しい名前` | `ln -s 元（行き先） 新しい名前` |

:::warn 試験の注意
- 引数は `cp` と同じ順番で「**元が先、新しい名前が後**」。`ln -s 行き先 リンク名`
- シンボリックリンクの行き先を相対パスで書くと、**リンクの置き場所から**たどる。`ln -s orig /tmp/s` の `/tmp/s` は `/tmp/orig` を指してしまう
- 同じ inode のファイルを探すには `find / -inum 番号` か `find / -samefile ファイル`
:::

## ls -lFi で見分ける {#lsfi}

試験では、`ls` の出力を見せて「どれがリンクか」「これは何の番号か」を問う形が多く出ます。`-l`（詳しく）、`-F`（種類の印）、`-i`（inode 番号）をまとめた `ls -lFi` の 1 行を読めるようにします。

```sh run title="ls -lFi"
cd /home/you/lab
chmod +x hard
ln hard hard2
ls -lFi
```

| 列 | 例 | 意味 |
| --- | --- | --- |
| 1 列目 | `301` | inode 番号（`-i`） |
| 2 列目 | `-rwxr-xr-x` | 種類と権限 |
| 3 列目 | `2` | リンク数（ハードリンクの数。ディレクトリは `2 + サブディレクトリの数`） |
| 名前の後ろ | `/`、`*`、`@` | `-F` の印 |

`-F` の印は 5 つです。小さな Linux にない種類も含めて、Debian 12 の表示で確かめます。

```console
$ ls -lFi
1018012 drwxr-xr-x 2 root root 4096 Nov 16 11:16 d/
1018013 -rw-r--r-- 1 root root    0 Nov 16 11:16 f
1018018 lrwxrwxrwx 1 root root    1 Nov 16 11:16 l -> f
1018010 prw-r--r-- 1 root root    0 Nov 16 11:16 p|
1018014 -rwxr-xr-x 1 root root    0 Nov 16 11:16 x*
$ ls -F
d/  f  l@  p|  x*
```

| 印 | 種類 | ls -l の 1 文字目 |
| --- | --- | --- |
| `/` | ディレクトリ | `d` |
| `*` | 実行できるファイル | `-`（x がある） |
| `@` | シンボリックリンク | `l` |
| `\|` | 名前付きパイプ（FIFO） | `p` |
| `=` | ソケット | `s` |
| （なし） | ふつうのファイル | `-` |

`ls -lF` では、シンボリックリンクは `l -> f` の形で行き先を表示し、`@` の代わりに矢印で示します（`-l` なしの `ls -F` では `l@` と出ます）。

ディレクトリのリンク数は、親の中の名前と、自分の中の `.`、そしてサブディレクトリの `..` の数を足したものです。サブディレクトリがなければ 2 です（[図解 Linux 11.3](../../linux/site/ch11.html#hardlink)）。

## find と locate：今たどるか、表を引くか {#locate}

ここからは 1.02.4 です。ファイルを名前で探すコマンドは 2 つあります。`find` はディレクトリの木を**いま**たどります。`locate` は、あらかじめ作っておいた**ファイル名の一覧（データベース）**を引くだけなので、とても速く探せます。

```fig graph locate はデータベースを引くだけ。データベースを作り直すのは updatedb で、ふつうは 1 日 1 回自動で動く
{
  col: 210, row: 90,
  nodes: [
    { id: 'fs', label: 'ファイルシステム', sub: '/ から下の全部', x: 0, y: 0.5, kind: 'stack', mono: false },
    { id: 'up', label: 'updatedb', sub: '/etc/updatedb.conf を読む', x: 1, y: 0, mono: true },
    { id: 'db', label: 'データベース', sub: '/var/lib/mlocate/mlocate.db など', x: 2, y: 0, kind: 'crate', mono: false },
    { id: 'lo', label: 'locate 名前', sub: '一覧を引くだけ・速い', x: 3, y: 0, kind: 'accent', mono: true },
    { id: 'fi', label: 'find 場所 条件', sub: 'いまたどる・遅いが最新', x: 2, y: 1, kind: 'accent', mono: true },
  ],
  edges: [
    { from: 'fs', to: 'up', label: 'たどる' },
    { from: 'up', to: 'db', label: '書く' },
    { from: 'db', to: 'lo', label: '引く' },
    { from: 'fs', to: 'fi', label: 'たどる' },
  ],

```

一覧はふつう、1 日 1 回、cron や systemd のタイマーで `updatedb` が作り直します。そのため、**作ったばかりのファイルは locate で見つからず、消したファイルが見つかる**ことがあります。すぐに反映したいときは、root で `updatedb` を実行します。Rocky Linux 9（mlocate）で確かめた結果です。

```console
# touch /srv/data/report2026.txt
# locate report2026
# updatedb
# locate report2026
/srv/data/report2026.txt
# rm /srv/data/report2026.txt
# locate report2026
/srv/data/report2026.txt
```

最初の `locate` は何も出しません。`updatedb` の後で見つかり、消した後も一覧には残っています。

`locate` は名前の一部に合えば表示します。`-i` は大文字と小文字を区別しない、`-c` は数だけを表示します。`find` のような「大きさ」「権限」「持ち主」の条件は使えません。

`updatedb` の設定は **`/etc/updatedb.conf`** です。一覧に入れないものを決めます。

```text
PRUNE_BIND_MOUNTS = "yes"
PRUNEFS = "9p afs anon_inodefs auto autofs bdev binfmt_misc cgroup … nfs nfs4 … proc … sysfs tmpfs …"
PRUNENAMES = ".git .hg .svn .bzr .arch-ids {arch} CVS"
PRUNEPATHS = "/afs /media /mnt /net /sfs /tmp /udev … /var/tmp …"
```

| 項目 | 意味 |
| --- | --- |
| `PRUNEPATHS` | 一覧に入れない**ディレクトリのパス**（`/tmp`、`/media` など） |
| `PRUNEFS` | 一覧に入れない**ファイルシステムの種類**（`nfs`、`proc`、`tmpfs` など） |
| `PRUNENAMES` | 一覧に入れない**名前**（`.git` など） |
| `PRUNE_BIND_MOUNTS` | バインドマウントを入れないか（`yes`） |

`locate` には、古い slocate、Red Hat 系でいまも使われる **mlocate**（データベースは `/var/lib/mlocate/mlocate.db`）、Debian 12 などの新しい **plocate**（`/var/lib/plocate/plocate.db`）があります。どれも、`locate`・`updatedb`・`/etc/updatedb.conf` という名前と使い方は同じです。

| | find | locate |
| --- | --- | --- |
| 探し方 | ディレクトリの木をいまたどる | データベースを引く |
| 速さ | 遅い | 速い |
| 新しいファイル | 見つかる | `updatedb` の後でないと見つからない |
| 条件 | 名前、種類、大きさ、時刻、権限、持ち主… | 名前（の一部）だけ |
| 設定 | なし | `/etc/updatedb.conf` |

## type・which・whereis：コマンドの正体 {#which}

コマンドの名前を打ったとき、実際に何が動くのかを調べる 3 つのコマンドがあります。

```sh run error title="type と which"
alias ll='ls -l'
type ll
type cd
type ls
which ls
which cd
```

`type` はシェルの**組み込みコマンド**なので、エイリアス、関数、組み込みコマンド、外部コマンドのどれかを答えます。`which` は**環境変数 PATH のディレクトリ**から実行ファイルを探すだけなので、`cd`（組み込み）や `ll`（エイリアス）は見つけられず、何も表示しません（終了ステータスは 1）。

:::note Red Hat 系の which
Rocky Linux などの Red Hat 系では、ログインシェルで `/etc/profile.d/which2.sh` が読まれ、`which` がシェル関数に置き換わります。この関数はエイリアスと関数の一覧を `/usr/bin/which` に渡すので、エイリアスも表示します。試験では、`which` の本来の働き（PATH から実行ファイルを探す）で答えます。
:::

`whereis` は、実行ファイル（バイナリ）に加えて、**マニュアル**と**ソース**の場所も、決まったディレクトリから探します。小さな Linux にはないので、Debian 12 と Rocky Linux 9 の結果です。

```console
$ whereis ls
ls: /usr/bin/ls /usr/share/man/man1/ls.1.gz
$ whereis -b ls
ls: /usr/bin/ls
$ whereis passwd
passwd: /usr/bin/passwd /etc/passwd /usr/share/man/man1/passwd.1ossl.gz
```

| コマンド | 何を答えるか | 探す場所 |
| --- | --- | --- |
| `type 名前` | エイリアス・関数・組み込み・外部コマンドのどれか（外部ならパス） | シェルの中と PATH |
| `which 名前` | 実行されるファイルのパス | PATH だけ |
| `whereis 名前` | バイナリ、マニュアル（`-m`）、ソース（`-s`）の場所。`-b` はバイナリだけ | 決まった標準のディレクトリ |

## FHS：どこに何を置くか {#fhs}

**FHS**（Filesystem Hierarchy Standard、ファイルシステム階層標準）は、Linux のディレクトリの使い分けを決めた標準です。どのディストリビューションでも、`/etc` には設定、`/var/log` にはログ、という配置がそろっているのは FHS のおかげです。

小さな Linux（と Debian 12、Rocky Linux 9）では、`/bin`、`/sbin`、`/lib` は `/usr` の下を指すシンボリックリンクになっています（**usr 統合**）。FHS の役目の考え方は変わりません。

| ディレクトリ | 置くもの | 試験での見分け方 |
| --- | --- | --- |
| `/etc` | 設定ファイル | 「設定」なら /etc |
| `/bin` / `/sbin` | 基本のコマンド / 管理用のコマンド | sbin は root が使うもの |
| `/boot` | カーネル（vmlinuz）、initramfs、GRUB の設定 | 起動に要るもの |
| `/dev` | デバイスファイル（`/dev/sda`） | |
| `/lib` | 共有ライブラリ、カーネルモジュール | |
| `/media` / `/mnt` | 取り外せる媒体の自動マウント / 一時的に手でマウント | |
| `/opt` | 追加のソフトウェア一式 | 「パッケージごとのディレクトリ」 |
| `/proc` / `/sys` | カーネルの情報を見せる仮想ファイルシステム | |
| `/root` | root のホーム | `/home/root` ではない |
| `/run` | 起動してからの実行時のデータ（PID ファイル） | |
| `/srv` | サービスが提供するデータ | |
| `/tmp` / `/var/tmp` | 一時ファイル。`/tmp` は再起動で消えてよい、`/var/tmp` は**残す** | |
| `/usr/local` | 管理者がソースから入れたものなど（ディストリのパッケージは入れない） | |
| `/usr/share` | マニュアル、ドキュメントなど | |
| `/var/log` | ログ | |
| `/var/spool` | 印刷・メール・cron の処理待ち | |

:::key まとめ
- chmod の 8 進数は r = 4、w = 2、x = 1 の合計。記号は `u/g/o/a` `+/-/=` `r/w/x/s/t`。再帰は `-R`
- umask はファイル 666・ディレクトリ 777 からビットを取り除く。022 → 644 / 755、027 → 640 / 750、033 → 644 / 744
- SUID = 4000（`u+s`）、SGID = 2000（`g+s`）、スティッキー = 1000（`o+t`）。小文字 s / t は x あり、大文字 S / T は x なし。SUID を探すのは `find / -perm -4000`
- 持ち主を変えるのは root だけ。`chown 持ち主:グループ`、`chown :グループ`
- `cp -r` ディレクトリ、`cp -p` 属性を保つ、`cp -a` 全部そのまま。`rmdir -p` 親もさかのぼって消す。`rm -rf` 確かめずに中身ごと
- tar は `c / x / t` のどれか + `z`（gzip）/ `j`（bzip2）/ `J`（xz）+ `f ファイル`（f はファイル名の直前）。`-C` で展開先
- 圧縮は元のファイルを消す。残すには `-k` か `-c`。展開は `-d`、`gunzip` / `bunzip2` / `unxz`
- dd は `if=` 読む元、`of=` 書く先、量は `bs × count`
- find：`-name`、`-type f/d/l`、`-size +100M`、`-mtime +7`（7 日より前）、`-perm -4000`、`-user`、`-exec コマンド {} \;`
- ハードリンクは同じ inode・ディレクトリと別のファイルシステムには不可。シンボリックリンクは自分の inode・元を消すと切れる。`ls -F` の印は `/ * @ | =`
- locate はデータベースを引く。`updatedb` で作り直し、設定は `/etc/updatedb.conf`（`PRUNEPATHS` など）
- `type` は組み込みやエイリアスも分かる。`which` は PATH だけ。`whereis` はバイナリ・マニュアル・ソース
- FHS：設定 `/etc`、ログ `/var/log`、一時 `/tmp`（消えてよい）と `/var/tmp`（残す）、自分で入れたもの `/usr/local`、追加ソフト `/opt`、取り外せる媒体 `/media`
:::

## 練習問題 {#practice}

### 1.02.1 ファイルの所有者とパーミッション

:::q 1.02.1-01 single
`chmod 754 report.sh` を実行した後の `ls -l` の権限の表示として正しいものはどれか。
- [ ] `-rwxr-x-wx`
- [x] `-rwxr-xr--`
- [ ] `-rwxrw-r--`
- [ ] `-rw-r-xr--`
- [ ] `-r-xr-xrw-`
:::why
7 = 4 + 2 + 1 で `rwx`、5 = 4 + 1 で `r-x`、4 で `r--` です（[パーミッションの節](#perm)）。

- `-rwxr-x-wx` はその他が `-wx`（3）で、753 です
- `-rwxrw-r--` はグループが `rw-`（6）で、764 です
- `-rw-r-xr--` は持ち主に x がなく、654 です
- `-r-xr-xrw-` は 556 です
:::
:::

:::q 1.02.1-02 single
権限が `-rw-rw-r--` のファイルに対して、`chmod u+x,g-w,o= file` を実行した。実行後の権限として正しいものはどれか。
- [ ] `-rwxrw-r--`
- [ ] `-rwx-w----`
- [x] `-rwxr-----`
- [ ] `---xr-----`
- [ ] `-rwxr--r--`
:::why
記号の書き方は、指定した所だけを変えます。持ち主に x を足して `rwx`、グループから w を取って `r--`、その他は `=` の右が空なので全部取って `---` です。結果は 740 です（[パーミッションの節](#perm)）。

- `-rwxrw-r--` は g-w と o= が効いていません
- `-rwx-w----` はグループの r と w を取り違えています
- `---xr-----` は `u+x` を `u=x` と取り違えています
- `-rwxr--r--` は `o=` が効いていません
:::
:::

:::q 1.02.1-03 fill
umask が `027` のシェルで `touch new.txt` を実行した。`new.txt` の権限を 8 進数 3 桁で入力してください。
= 640
= 0640
:::why
ファイルは 666（`rw-rw-rw-`）から umask のビットを取り除きます。027 はグループの w と、その他の rwx を取り除くので、`rw-r-----` = 640 です（[umask の節](#umask)）。ディレクトリなら 777 から取り除いて 750 になります。
:::
:::

:::q 1.02.1-04 single
umask が `0033` のとき、`mkdir dir1` で作ったディレクトリの権限として正しいものはどれか。
- [ ] 733
- [x] 744
- [ ] 644
- [ ] 755
- [ ] 700
:::why
ディレクトリは 777 から umask のビットを取り除きます。033 はグループとその他の w と x（2 + 1）を取り除くので、`rwxr--r--` = 744 です（[umask の節](#umask)）。

- 733 は「残す」と「取り除く」を逆にしています
- 644 は、同じ umask で**ファイル**を作ったときの値です（666 から取り除く。633 にはなりません）
- 755 は umask 022、700 は umask 077 のときのディレクトリです
:::
:::

:::q 1.02.1-05 multi
umask の説明として正しいものを 2 つ選択してください。
- [x] umask の値はプロセスごとに持ち、子プロセスに受け継がれる
- [ ] umask を変えると、すでにあるファイルの権限も変わる
- [x] `umask -S` は、新しく作るときに残す権限を記号で表示する
- [ ] umask 022 のとき、新しいファイルは 755 で作られる
- [ ] umask は、chmod で指定した 8 進数の権限からも取り除かれる
:::why
umask はプロセスの属性で、シェルから起動したコマンドに受け継がれます。`umask -S` は `u=rwx,g=rx,o=rx` のように「残す」側を記号で表示します（[umask の節](#umask)）。

- umask が効くのは「作るとき」だけで、すでにあるファイルは変わりません
- umask 022 でファイルは 644 です。755 はディレクトリです（ファイルは 666 から取り除くので x が付きません）
- `chmod 777` のように数字で指定した権限は、そのまま付きます
:::
:::

:::q 1.02.1-06 single
次の出力の `s` が表す意味として正しいものはどれか。

```text
-rwsr-xr-x 1 root root 72048 Dec 14  2025 /usr/bin/passwd
```
- [ ] だれが実行しても、実行したユーザーの権限で動く
- [x] だれが実行しても、ファイルの持ち主（root）の権限で動く
- [ ] ファイルのグループ（root）の権限で動く
- [ ] ファイルの持ち主しか、このファイルを削除できない
- [ ] 持ち主は実行できるが、SUID は立っていない
:::why
持ち主の x の場所の `s` は SUID（4000）です。実行したプロセスの実効ユーザーが、ファイルの持ち主になります。passwd はこれで、ふつうのユーザーが自分の `/etc/shadow` の行を書き換えられます（[SUID の節](#special)、[図解 Linux 4.9](../../linux/site/ch04.html#special)）。

- 「実行したユーザーの権限で動く」のは、特別なビットのないふつうの動きです
- グループの権限で動くのは SGID で、グループの x の場所に `s` が出ます
- 削除の制限はスティッキービットで、その他の x の場所に `t` が出ます
- 小文字の `s` は SUID と x の両方が立っている印です
:::
:::

:::q 1.02.1-07 single
`ls -l` の権限が `-rwSr--r--` と表示された。この意味として正しいものはどれか。
- [ ] SUID が立っており、持ち主は実行できる
- [x] SUID が立っているが、持ち主の実行権はない
- [ ] SGID が立っているが、グループの実行権はない
- [ ] スティッキービットが立っている
- [ ] 持ち主の権限が壊れている
:::why
特別なビットは x と同じ場所に表示されるので、大文字・小文字で x の有無を表します。大文字の `S` は「SUID はあるが x はない」です。8 進数では 4644 です（[SUID の節](#special)）。

- 持ち主が実行できるなら小文字の `s`（4744 など）になります
- SGID ならグループの位置（6 文字目）に出ます
- スティッキービットは、その他の位置に `t` または `T` で出ます
:::
:::

:::q 1.02.1-08 fill
ディレクトリ `/share/tmp` を、だれでも読み書きと移動ができ、さらにスティッキービットが立った状態（`/tmp` と同じ `drwxrwxrwt`）にする。`chmod` に与える 8 進数 4 桁を入力してください。
= 1777
:::why
スティッキービットは 4 桁目の 1、だれでも `rwx` は 777 なので、`chmod 1777 /share/tmp` です（[SUID の節](#special)）。SUID は 4、SGID は 2 です。記号なら `chmod 777` の後に `chmod o+t` でも同じ結果になります。
:::
:::

:::q 1.02.1-09 single
`/tmp` に設定されているスティッキービットの働きとして正しいものはどれか。
- [ ] `/tmp` の中のファイルは、再起動のときに必ず消される
- [ ] `/tmp` の中に作ったファイルのグループが、`/tmp` のグループになる
- [x] `/tmp` の中のファイルは、そのファイルの持ち主、ディレクトリの持ち主、root しか削除や名前の変更ができない
- [ ] `/tmp` の中のプログラムは、`/tmp` の持ち主の権限で動く
- [ ] `/tmp` に書き込めるのは root だけになる
:::why
スティッキービットを付けたディレクトリでは、書き込み権があっても、他人のファイルは消せず名前も変えられません。だれでも書ける `/tmp` で、他人のファイルを消されないための仕組みです（[SUID の節](#special)、[図解 Linux 4.9](../../linux/site/ch04.html#special)）。

- 再起動で消すかどうかは、ディストリビューションの設定（tmpfs など）の話で、スティッキービットとは関係ありません
- グループを引き継ぐのはディレクトリの SGID です
- 持ち主の権限で動くのは SUID です
- `drwxrwxrwt` なので、だれでも書き込めます
:::
:::

:::q 1.02.1-10 multi
ディレクトリに付けた SGID の説明として正しいものを 2 つ選択してください。
- [x] そのディレクトリの中に作ったファイルのグループは、ディレクトリのグループになる
- [x] 8 進数では、4 桁目の 2（例 `2775`）で表す
- [ ] 表示は、その他の x の位置に `t` で出る
- [ ] そのディレクトリの中のファイルは、持ち主しか削除できなくなる
- [ ] 8 進数では、4 桁目の 4（例 `4775`）で表す
:::why
ディレクトリの SGID は、中に作ったファイルのグループを、作った人の主グループではなくディレクトリのグループにします。グループで共有する場所に使います。数字は 2000、記号は `g+s`、表示はグループの x の位置の `s` です（[SUID の節](#special)）。

- その他の位置の `t` と「持ち主しか消せない」は、スティッキービット（1000）です
- 4000 は SUID です
:::
:::

:::q 1.02.1-11 single
システム全体から、SUID が設定されたファイルを探すコマンドとして正しいものはどれか。
- [ ] `find / -perm 4000 -type f`
- [x] `find / -perm -4000 -type f`
- [ ] `find / -perm -2000 -type f`
- [ ] `find / -perm -1000 -type f`
- [ ] `find / -user root -type f`
:::why
`-perm -4000` は「SUID のビットを含むもの」です。ほかのビット（755 など）は問いません（[find の節](#find)）。

- `-perm 4000`（`-` なし）は権限が**ちょうど** 4000（`---S------`）のものだけで、ふつうの SUID のファイル（4755 など）は合いません
- `-2000` は SGID、`-1000` はスティッキービットを探します
- `-user root` は持ち主が root のファイルで、SUID とは関係ありません
:::
:::

:::q 1.02.1-12 single
ファイル `data.csv` の持ち主を alice に、グループを staff に、1 つのコマンドで変えたい。正しいものはどれか。
- [x] `chown alice:staff data.csv`
- [ ] `chown staff:alice data.csv`
- [ ] `chgrp alice:staff data.csv`
- [ ] `chmod alice:staff data.csv`
- [ ] `chown -g staff alice data.csv`
:::why
`chown 持ち主:グループ ファイル` で両方を変えます（[chown の節](#chown)）。

- `staff:alice` は持ち主とグループが逆です
- `chgrp` はグループだけを変えるコマンドで、`持ち主:グループ` の形は取りません
- `chmod` は権限を変えるコマンドです
- `chown` に `-g` でグループを指定するオプションはありません
:::
:::

:::q 1.02.1-13 multi
`chown` と `chgrp` の説明として正しいものを 2 つ選択してください。
- [x] ファイルの持ち主を変えられるのは root だけである
- [ ] 一般ユーザーは、自分のファイルの持ち主を、ほかのユーザーに変えられる
- [x] `chown :staff file` は、`chgrp staff file` と同じくグループだけを変える
- [ ] ディレクトリの中まで再帰的に変えるオプションは `-r`（小文字）である
- [ ] 一般ユーザーは、自分が入っていないグループにもファイルのグループを変えられる
:::why
持ち主を変えるのは root だけです。`chown :グループ` はグループだけを変える書き方です（[chown の節](#chown)、[図解 Linux 4.7](../../linux/site/ch04.html#chown)）。

- 一般ユーザーは、自分のファイルでも、持ち主を他人に変えられません
- 再帰のオプションは `-R`（大文字）です
- 持ち主がグループを変えられるのは、自分が入っているグループへだけです
:::
:::

:::q 1.02.1-14 fill
ディレクトリ `project` に SGID を設定する。記号の書き方で、空欄に入るものを入力してください。

```text
chmod ____ project
```
= g+s
:::why
SGID は「グループ（g）に s を足す」で `g+s` です（[SUID の節](#special)）。SUID なら `u+s`、スティッキービットなら `o+t`（または `+t`）です。8 進数なら `chmod 2775 project` のように 4 桁目に 2 を書きます。
:::
:::

:::q 1.02.1-15 single
`chmod 6755 tool` を実行した後の `ls -l` の権限の表示として正しいものはどれか。
- [ ] `-rwsr-xr-x`
- [ ] `-rwxr-sr-x`
- [x] `-rwsr-sr-x`
- [ ] `-rwsr-xr-t`
- [ ] `-rwSr-Sr-x`
:::why
4 桁目の 6 = 4（SUID）+ 2（SGID）です。755 で持ち主もグループも x があるので、どちらも小文字の `s` になります（[SUID の節](#special)）。

- `-rwsr-xr-x` は 4755（SUID だけ）、`-rwxr-sr-x` は 2755（SGID だけ）です
- `-rwsr-xr-t` は 5755（SUID とスティッキー）です
- 大文字の `S` は x がないときの表示なので、755 では出ません
:::
:::

### 1.02.2 基本的なファイル管理の実行

:::q 1.02.2-01 single
ディレクトリ `/srv/www` を `/backup/www` へ、中身ごと、権限・持ち主・タイムスタンプを保ち、シンボリックリンクはリンクのままでコピーしたい。最も適切なコマンドはどれか。
- [ ] `cp -r /srv/www /backup/www`
- [ ] `cp -p /srv/www /backup/www`
- [x] `cp -a /srv/www /backup/www`
- [ ] `cp -i /srv/www /backup/www`
- [ ] `cp -f /srv/www /backup/www`
:::why
`-a`（archive）は、再帰的なコピー、属性を保つ、リンクをリンクのままコピー、のすべてを行います（[cp の節](#cp)）。

- `-r` は中身ごとコピーしますが、時刻や持ち主は保ちません
- `-p` は属性を保ちますが、`-r` がないのでディレクトリはコピーできません（`-r not specified; omitting directory`）
- `-i` は上書きの前に確かめる、`-f` は書き込めない先を消してでもコピーする、というオプションで、どちらもディレクトリのコピーはできません
:::
:::

:::q 1.02.2-02 fill
空のディレクトリ `a/b/c` を消し、続けて空になった `a/b` と `a` も消したい。空欄に入るオプションを入力してください。

```text
rmdir ____ a/b/c
```
= -p
= --parents
:::why
`rmdir -p a/b/c` は、`rmdir a/b/c a/b a` と同じ働きで、親までさかのぼって消します（[cp の節](#cp)）。`rmdir` は空のディレクトリしか消せないので、途中のディレクトリにほかのファイルがあると、そこで止まります。
:::
:::

:::q 1.02.2-03 single
ディレクトリ `old` を、中のファイルごと、確認のメッセージを出さずに削除するコマンドとして正しいものはどれか。
- [ ] `rmdir old`
- [ ] `rmdir -p old`
- [ ] `rm -ri old`
- [x] `rm -rf old`
- [ ] `rm -d old`
:::why
`rm -r` で中身ごと消し、`-f` で確認をせず、ないファイルもエラーにしません（[cp の節](#cp)）。

- `rmdir` と `rmdir -p` は空のディレクトリしか消せません
- `rm -ri` は 1 つずつ確認をたずねます
- `rm -d` は空のディレクトリを消すオプションです
:::
:::

:::q 1.02.2-04 single
`mv` で、移動先に同じ名前のファイルがあるとき、上書きしてよいかをたずねるオプションはどれか。
- [ ] `-f`
- [x] `-i`
- [ ] `-n`
- [ ] `-u`
- [ ] `-b`
:::why
`-i`（interactive）は上書きの前にたずねます（[cp の節](#cp)）。

- `-f` は確認せずに上書きします
- `-n` は上書きしません（たずねもしません）
- `-u` は移動元が新しいときだけ移動します
- `-b` は上書きされるファイルのバックアップを残します
:::
:::

:::q 1.02.2-05 single
ディレクトリ `/home/user` を、gzip で圧縮したアーカイブ `home.tar.gz` にまとめるコマンドとして正しいものはどれか。
- [ ] `tar xzf home.tar.gz /home/user`
- [x] `tar czf home.tar.gz /home/user`
- [ ] `tar cjf home.tar.gz /home/user`
- [ ] `tar tzf home.tar.gz /home/user`
- [ ] `tar czf /home/user home.tar.gz`
:::why
作るのは `c`、gzip は `z`、`f` のすぐ後ろがアーカイブの名前です（[tar の節](#tar)）。

- `x` は取り出す、`t` は一覧を表示する操作です
- `j` は bzip2 で圧縮します（拡張子は .tar.bz2 がふさわしい）
- `czf /home/user home.tar.gz` は、`/home/user` という名前のアーカイブを作ろうとします
:::
:::

:::q 1.02.2-06 single
カレントディレクトリに `docs` ディレクトリがあり、`backup.tar` というファイルはない。次のコマンドを実行した結果として正しいものはどれか。

```text
$ tar -cfv backup.tar docs
```
- [ ] `backup.tar` が作られ、入れたファイルの名前が表示される
- [x] `v` という名前のアーカイブが作られ、`backup.tar` がないというエラーが出る
- [ ] `backup.tar` から `docs` が取り出される
- [ ] オプションの順番が違うため、何も作られずに終わる
:::why
`-` を付けた書き方では、`f` のすぐ後ろ（ここでは同じ塊の残りの `v`）がアーカイブの名前になります。tar は `v` というアーカイブを作り、`backup.tar` と `docs` を入れようとして、`backup.tar: Cannot stat: No such file or directory` を出します（[tar の節](#tar)）。正しくは `tar -cvf backup.tar docs` です。
:::
:::

:::q 1.02.2-07 fill
xz で圧縮されたアーカイブの中身を、展開せずに一覧表示する。圧縮の種類を指定する 1 文字を、空欄に入力してください。

```text
tar -t_f archive.tar.xz
```
= J
:::why
xz は大文字の `J` です。gzip は `z`、bzip2 は `j`（小文字）です（[tar の節](#tar)）。`t` は一覧の表示、`f` の後ろがアーカイブの名前です。
:::
:::

:::q 1.02.2-08 multi
`data.txt.bz2` を展開して `data.txt` に戻すコマンドを 2 つ選択してください。
- [x] `bunzip2 data.txt.bz2`
- [x] `bzip2 -d data.txt.bz2`
- [ ] `gunzip data.txt.bz2`
- [ ] `bzip2 -k data.txt.bz2`
- [ ] `xz -d data.txt.bz2`
:::why
bzip2 の展開は `bunzip2` か `bzip2 -d` です（[圧縮の節](#compress)）。

- `gunzip` は gzip（.gz）の展開です
- `-k` は元のファイルを残すオプションで、展開はしません
- `xz -d` は xz（.xz）の展開です
:::
:::

:::q 1.02.2-09 multi
`log.txt` を gzip で圧縮し、元の `log.txt` も残したい。正しいものを 2 つ選択してください。
- [x] `gzip -k log.txt`
- [x] `gzip -c log.txt > log.txt.gz`
- [ ] `gzip log.txt`
- [ ] `gzip -d log.txt`
- [ ] `gzip -r log.txt`
:::why
`-k`（keep）は元を残します。`-c` は結果を標準出力に書くので、元は残り、リダイレクトで `.gz` ができます（[圧縮の節](#compress)）。

- オプションなしの `gzip log.txt` は、`log.txt.gz` を作って元を消します
- `-d` は展開です
- `-r` はディレクトリの中を再帰的に圧縮するオプションで、元は残りません
:::
:::

:::q 1.02.2-10 single
カレントディレクトリに `apple.txt`、`banana.txt`、`cherry.txt`、`melon.txt`、`note.csv` がある。`ls [!a-c]*.txt` で表示されるものはどれか。
- [ ] `apple.txt banana.txt cherry.txt`
- [x] `melon.txt`
- [ ] `melon.txt note.csv`
- [ ] `note.csv`
:::why
`[!a-c]` は「a〜c **以外**の 1 文字」です。先頭が a、b、c のものが外れ、残りのうち `.txt` で終わるのは `melon.txt` だけです（[ワイルドカードの節](#glob)）。`note.csv` は `.txt` で終わらないので合いません。
:::
:::

:::q 1.02.2-11 single
ディスク `/dev/sda` の先頭 512 バイト（MBR）を、ファイル `mbr.bin` に保存するコマンドとして正しいものはどれか。
- [x] `dd if=/dev/sda of=mbr.bin bs=512 count=1`
- [ ] `dd if=mbr.bin of=/dev/sda bs=512 count=1`
- [ ] `dd if=/dev/sda of=mbr.bin bs=512 count=2`
- [ ] `dd if=/dev/sda of=mbr.bin bs=1024 count=1`
- [ ] `dd if=/dev/sda of=mbr.bin bs=512 skip=1 count=1`
:::why
`if` が読む元、`of` が書く先、量は `bs × count` = 512 × 1 です（[dd の節](#dd)）。

- `if` と `of` が逆だと、ファイルの中身をディスクの先頭に書き込みます（復元の操作）
- `count=2` と `bs=1024` は 1024 バイトを写します
- `skip=1` は先頭の 512 バイトを飛ばし、次の 512 バイトを写します
:::
:::

:::q 1.02.2-12 single
`/var/log` の下から、最後の更新が 7 日より前（8 日以上前）のファイルを探すコマンドとして正しいものはどれか。
- [ ] `find /var/log -mtime -7`
- [ ] `find /var/log -mtime 7`
- [x] `find /var/log -mtime +7`
- [ ] `find /var/log -mmin +7`
- [ ] `find /var/log -newer 7`
:::why
`-mtime` は 24 時間を 1 日として切り捨てて数えます。`+7` は「7 より大きい」で、8 日以上前のものです（[find の節](#find)）。

- `-7` は 7 日未満（1 週間以内）に更新されたものです
- `7` はちょうど 7 日前（7×24〜8×24 時間前）のものです
- `-mmin` は分で数えます
- `-newer` はファイルを引数に取り、そのファイルより新しいものを探します
:::
:::

:::q 1.02.2-13 fill
`/home` の下から、大きさが 100 MiB を超えるファイルを探す。空欄に入るものを入力してください。

```text
find /home -type f -size ____
```
= +100M
:::why
`-size` の `+` は「より大きい」、`M` は MiB です（[find の節](#find)）。`-100M` なら 100 MiB より小さいもの、単位を書かない `+100` は 512 バイトのブロックで 100 個（約 50 KiB）を超えるもの、という意味になります。
:::
:::

:::q 1.02.2-14 multi
カレントディレクトリの下の `.tmp` で終わるファイルを、すべて削除する。正しく動くものを 2 つ選択してください。
- [x] `find . -name '*.tmp' -exec rm {} \;`
- [x] `find . -name '*.tmp' -exec rm {} +`
- [ ] `find . -name '*.tmp' -exec rm {}`
- [ ] `find . -name '*.tmp' -exec rm \; {}`
- [ ] `find . -name '*.tmp' -exec rm [] \;`
:::why
`-exec` は、見つかったパスを `{}` に入れてコマンドを実行し、`\;` か `+` で終えます。`\;` は 1 つずつ、`{} +` はまとめて 1 回のコマンドに渡します（[find の節](#find)）。

- `\;` も `+` もないと、「missing argument to -exec」 のエラーになります
- `\;` の後ろに `{}` を書くと、`rm` に名前が渡らず、余った `{}` は 「paths must precede expression」 のエラーになります
- 置き換わる印は `{}` で、`[]` ではありません
:::
:::

:::q 1.02.2-15 single
`/home` の下から、持ち主が alice の**通常ファイル**だけを探すコマンドとして正しいものはどれか。
- [x] `find /home -type f -user alice`
- [ ] `find /home -type d -user alice`
- [ ] `find /home -type f -group alice`
- [ ] `find /home -type f -name alice`
- [ ] `find /home -type l -user alice`
:::why
`-type f` は通常ファイル、`-user` は持ち主で絞ります（[find の節](#find)）。

- `-type d` はディレクトリ、`-type l` はシンボリックリンクです
- `-group` はグループで絞ります
- `-name alice` は名前が alice のものを探します
:::
:::

### 1.02.3 ハードリンクとシンボリックリンク

:::q 1.02.3-01 single
次の出力から分かることとして正しいものはどれか。

```text
$ ls -li
1311 -rw-r--r-- 2 you you 120 Apr  1 09:00 a.txt
1311 -rw-r--r-- 2 you you 120 Apr  1 09:00 b.txt
1315 lrwxrwxrwx 1 you you   5 Apr  1 09:01 c.txt -> a.txt
```
- [ ] `b.txt` は `a.txt` のシンボリックリンクである
- [x] `a.txt` と `b.txt` は同じ inode を指すハードリンクである
- [ ] `c.txt` を消すと `a.txt` も消える
- [ ] `a.txt` を消すと `b.txt` も読めなくなる
- [ ] `c.txt` は `a.txt` のハードリンクである
:::why
1 列目の inode 番号が同じ（1311）で、リンク数が 2 なので、`a.txt` と `b.txt` は同じ本体に付いた 2 つの名前です（[リンクの節](#links)）。

- シンボリックリンクは種類が `l` で、`->` が付きます。それは `c.txt` です
- シンボリックリンクを消しても、行き先は消えません
- `a.txt` を消しても、`b.txt` は同じ inode を指しているので読めます（`c.txt` は切れます）
:::
:::

:::q 1.02.3-02 multi
ハードリンクを作れないものを 2 つ選択してください。
- [x] ディレクトリへのハードリンク
- [x] 別のファイルシステムにあるファイルへのハードリンク
- [ ] 同じディレクトリの中の、通常ファイルへのハードリンク
- [ ] 持ち主が自分である通常ファイルへのハードリンク
- [ ] 同じファイルシステムの、別のディレクトリにある通常ファイルへのハードリンク
:::why
ディレクトリへのハードリンクは、木の形が壊れる（ループができる）ので許されません（`hard link not allowed for directory`）。inode 番号はファイルシステムの中でしか意味がないので、別のファイルシステムのファイルにも作れません（`Invalid cross-device link`）（[リンクの節](#links)）。同じファイルシステムなら、ディレクトリが違っても作れます。
:::
:::

:::q 1.02.3-03 fill
`/etc/nginx/nginx.conf` を指す `conf` という名前のシンボリックリンクを作る。空欄に入るオプションを入力してください。

```text
ln ____ /etc/nginx/nginx.conf conf
```
= -s
= --symbolic
:::why
`ln -s 行き先 リンク名` でシンボリックリンクを作ります。`-s` がなければハードリンクです（[リンクの節](#links)）。引数の順番は `cp` と同じく「元が先、新しい名前が後」です。
:::
:::

:::q 1.02.3-04 single
次のコマンドを順に実行した。最後の 2 つのコマンドの結果として正しいものはどれか。

```text
$ echo abc > orig
$ ln orig hard
$ ln -s orig soft
$ rm orig
$ cat hard
$ cat soft
```
- [ ] どちらも `abc` を表示する
- [x] `cat hard` は `abc` を表示し、`cat soft` は `No such file or directory` のエラーになる
- [ ] `cat hard` はエラーになり、`cat soft` は `abc` を表示する
- [ ] どちらもエラーになる
:::why
`hard` は inode を直接指しているので、`orig` の名前を消しても読めます。`soft` は「orig」というパスをたどるので、名前がなくなると切れたリンクになります（[リンクの節](#links)、[図解 Linux 11.5](../../linux/site/ch11.html#unlink)）。
:::
:::

:::q 1.02.3-05 single
`ls -F` の出力で、名前の後ろに `@` が付いているものは何か。
- [ ] ディレクトリ
- [ ] 実行できるファイル
- [x] シンボリックリンク
- [ ] 名前付きパイプ
- [ ] ソケット
:::why
`-F` の印は、`/` ディレクトリ、`*` 実行できるファイル、`@` シンボリックリンク、`|` 名前付きパイプ、`=` ソケットです（[ls -lFi の節](#lsfi)）。
:::
:::

:::q 1.02.3-06 single
次の `ls -lFi` の出力の、1 列目の数字（`2621445`）は何を表すか。

```text
2621445 drwxr-xr-x 3 you you 4096 Apr  1 09:00 work/
```
- [ ] ファイルの大きさ
- [ ] リンク数
- [x] inode 番号
- [ ] ディスクのブロック数
- [ ] 持ち主のユーザー ID
:::why
`-i` を付けると、先頭に inode 番号が出ます（[ls -lFi の節](#lsfi)）。リンク数は権限の次の `3`、大きさは `4096` です。ブロック数は `-s` で出す値で、ユーザー ID は `-n` を付けると名前の代わりに出ます。
:::
:::

:::q 1.02.3-07 multi
シンボリックリンクの説明として正しいものを 2 つ選択してください。
- [x] 行き先とは別の、自分の inode を持つ
- [x] ディレクトリを指すことができる
- [ ] 作ると、行き先のファイルのリンク数が 1 増える
- [ ] `ls -l` で表示される大きさは、行き先のファイルの大きさと同じである
- [ ] 別のファイルシステムにあるファイルは指せない
:::why
シンボリックリンクは、行き先のパスを中身に書いた別のファイルです。自分の inode を持ち、ディレクトリも別のファイルシステムも指せます（[リンクの節](#links)）。

- 行き先のリンク数は変わりません。リンク数が増えるのはハードリンクです
- 表示される大きさは、行き先の**パスの文字数**です（`orig` なら 4）
:::
:::

:::q 1.02.3-08 single
`ls -F` の出力で、名前の後ろに `*` が付いているものは何か。
- [ ] 隠しファイル
- [x] 実行権のある通常ファイル
- [ ] シンボリックリンク
- [ ] ディレクトリ
- [ ] ワイルドカードを含む名前のファイル
:::why
`*` は実行できる（x のある）ファイルの印です（[ls -lFi の節](#lsfi)）。シンボリックリンクは `@`、ディレクトリは `/` です。隠しファイルは名前が `.` で始まるもので、`-F` の印はありません。
:::
:::

:::q 1.02.3-09 fill
inode 番号が 1311 のファイル（ハードリンクの名前）を、`/home` の下からすべて探す。空欄に入る find の条件を入力してください。

```text
find /home -____ 1311
```
= inum
:::why
`-inum 番号` は inode 番号で探します。同じ inode を持つ名前（ハードリンク）がすべて見つかります（[リンクの節](#links)）。ファイル名で指定したいときは `-samefile ファイル` も使えます。
:::
:::

:::q 1.02.3-10 single
`link` という名前のシンボリックリンクがすでにある。`ln -s new.conf link` を実行すると `File exists` で失敗した。すでにある `link` を、確認をたずねずに置き換えて作り直すには、どのオプションを足すか。
- [ ] `-i`
- [x] `-f`
- [ ] `-n`
- [ ] `-r`
- [ ] `-p`
:::why
`-f`（force）は、同じ名前があれば消してからリンクを作ります。`ln -sf new.conf link` です（[リンクの節](#links)）。`-i` は置き換える前にたずねます（`y` と答えれば置き換わりますが、たずねずに置き換えるのは `-f` です）。`-n` は「リンク名がディレクトリへのシンボリックリンクのとき、その中に作らない」という別の意味です。`-r` は `-s` と一緒に使い、行き先を相対パスで書くオプションです。`-p` は ln にはありません。
:::
:::

### 1.02.4 ファイルの配置と検索

:::q 1.02.4-01 single
`/srv/data/report.txt` を作った直後に `locate report.txt` を実行したが、何も表示されなかった。原因として最も適切なものはどれか。
- [ ] `locate` は通常ファイルを探せない
- [x] `locate` の使うデータベースが、まだ `updatedb` で更新されていない
- [ ] `locate` はカレントディレクトリの下しか探さない
- [ ] `locate` には `-name` を付ける必要がある
:::why
`locate` は、`updatedb` が作ったファイル名のデータベースを引くだけです。データベースはふつう 1 日 1 回作り直すので、その後に作ったファイルは見つかりません。root で `updatedb` を実行すると見つかるようになります（[locate の節](#locate)）。`locate` は種類を問わず、全体の一覧から探し、`-name` は find の条件です。
:::
:::

:::q 1.02.4-02 fill
`updatedb` がデータベースを作るときに、対象から外すディレクトリやファイルシステムの種類を書く設定ファイルを、絶対パスで入力してください。
= /etc/updatedb.conf
:::why
`/etc/updatedb.conf` に、`PRUNEPATHS`（外すパス）、`PRUNEFS`（外すファイルシステムの種類）、`PRUNENAMES`（外す名前）などを書きます（[locate の節](#locate)）。
:::
:::

:::q 1.02.4-03 single
`/etc/updatedb.conf` に次の行がある。この行の意味として正しいものはどれか。

```text
PRUNEPATHS = "/afs /media /mnt /tmp /var/tmp"
```
- [ ] 書かれたディレクトリだけを、locate のデータベースに入れる
- [x] 書かれたディレクトリの下は、locate のデータベースに入れない
- [ ] 書かれたディレクトリに、locate のデータベースを置く
- [ ] 書かれたディレクトリの下は、find でも探さない
:::why
`PRUNE` は「刈り込む」で、`PRUNEPATHS` は一覧から**外す**パスです（[locate の節](#locate)）。データベースの置き場所は実装で決まっています（mlocate なら `/var/lib/mlocate/mlocate.db`）。このファイルは `updatedb` の設定なので、`find` には関係ありません。
:::
:::

:::q 1.02.4-04 multi
`find` と `locate` の説明として正しいものを 2 つ選択してください。
- [x] `locate` は、あらかじめ作ったデータベースを引くので、`find` より速い
- [x] `find` は、大きさや権限、持ち主といった条件でも探せる
- [ ] `locate` は、ディレクトリの木をいまたどるので、常に最新の結果を返す
- [ ] `find` を使う前に、`updatedb` を実行しておく必要がある
- [ ] `locate -perm -4000` で、SUID のファイルを探せる
:::why
`locate` はデータベースを引くだけなので速い代わりに、データベースが古いと結果も古くなります。`find` は実際にたどるので遅いですが最新で、`-size`、`-perm`、`-user` などの条件が使えます（[locate の節](#locate)）。`updatedb` は locate のためのもので、find には要りません。`locate` には権限の条件はありません。
:::
:::

:::q 1.02.4-05 single
コマンド `ls` について、実行ファイルとマニュアルの場所をまとめて表示するコマンドはどれか。
- [ ] `which ls`
- [ ] `type ls`
- [x] `whereis ls`
- [ ] `locate -b ls`
- [ ] `file ls`
:::why
`whereis` は、バイナリ、マニュアル、ソースの場所を表示します（`ls: /usr/bin/ls /usr/share/man/man1/ls.1.gz`）（[type・which・whereis の節](#which)）。

- `which` と `type` は、実行されるもの（のパス）だけです
- `locate` は名前を含むすべてのパスを一覧から出すので、`ls` を含む無関係なパスもたくさん出ます
- `file` はファイルの種類を調べるコマンドです
:::
:::

:::q 1.02.4-06 single
bash で次のコマンドを実行した。出力として正しいものはどれか。

```text
$ type cd
```
- [ ] `/usr/bin/cd`
- [x] `cd is a shell builtin`
- [ ] `cd: /usr/bin/cd /usr/share/man/man1/cd.1.gz`
- [ ] 何も表示されない
:::why
`type` は、名前がエイリアス・関数・組み込みコマンド・外部コマンドのどれかを答えます。`cd` はシェルの組み込みコマンドです（[type・which・whereis の節](#which)）。何も表示しないのは `which cd` のほうで、which は PATH の中の実行ファイルしか探しません。`cd: …` の形は whereis の出力です。
:::
:::

:::q 1.02.4-07 single
FHS で、システムやサービスのログファイルを置くディレクトリとして定められているものはどれか。
- [ ] `/etc/log`
- [x] `/var/log`
- [ ] `/usr/log`
- [ ] `/tmp/log`
- [ ] `/var/spool`
:::why
動いている間に増え続けるデータは `/var` に置き、ログは `/var/log` です（[FHS の節](#fhs)）。`/etc` は設定、`/usr` は読むだけのプログラムとデータ、`/var/spool` は印刷・メール・cron などの処理待ちです。
:::
:::

:::q 1.02.4-08 multi
FHS の説明として正しいものを 2 つ選択してください。
- [x] `/etc` には、システムの設定ファイルを置く
- [x] `/usr/local` には、管理者が独自に入れたソフトウェアを置く
- [ ] `/opt` には、カーネルとブートローダーのファイルを置く
- [ ] `/root` は、すべてのユーザーのホームディレクトリの親である
- [ ] `/media` は、プロセスの情報を見せる仮想ファイルシステムである
:::why
`/etc` は設定、`/usr/local` はディストリビューションのパッケージ以外に、管理者がソースから入れたものなどを置きます（[FHS の節](#fhs)）。

- カーネルとブートローダーは `/boot` です。`/opt` は追加のソフトウェア一式です
- `/root` は root ユーザーのホームです。ユーザーのホームの親は `/home` です
- `/media` は取り外せる媒体のマウントポイントで、プロセスの情報は `/proc` です
:::
:::

:::q 1.02.4-09 single
FHS での `/tmp` と `/var/tmp` の違いとして正しいものはどれか。
- [ ] `/tmp` は root だけが使い、`/var/tmp` は一般ユーザーが使う
- [x] `/tmp` の中身は再起動で消えてよいが、`/var/tmp` の中身は再起動の後も残す
- [ ] `/var/tmp` の中身は再起動で消えてよいが、`/tmp` の中身は再起動の後も残す
- [ ] `/var/tmp` は `/tmp` を指すシンボリックリンクと決められている
:::why
FHS では、`/tmp` は再起動で消してよい一時ファイル、`/var/tmp` は再起動をまたいで残す一時ファイルの場所です（[FHS の節](#fhs)）。どちらもだれでも書き込め、スティッキービットが付いています。
:::
:::

:::q 1.02.4-10 fill
FHS で、USB メモリや CD-ROM のような取り外せる媒体をマウントする場所として定められたディレクトリを、絶対パスで入力してください。
= /media
= /media/
:::why
取り外せる媒体は `/media`（その下に媒体ごとのディレクトリ）です。一時的に管理者が手でマウントする場所は `/mnt` です（[FHS の節](#fhs)）。
:::
:::
