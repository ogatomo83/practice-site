## パッケージとは何か {#package}

ソフトウェアを使うには、プログラムのファイルを `/usr/bin` に、説明書を `/usr/share/man` に、設定を `/etc` に置く必要があります（場所の決まりは[図解 Linux 3.1](../../linux/site/ch03.html#tree)）。これを手で 1 つずつやるのは大変です。

**パッケージ**は、置くファイルをまとめて 1 つにしたものです。中には、ファイルのほかに**メタデータ**（名前、版、どのパッケージを必要とするか、説明）と、入れる前後に動かす**スクリプト**も入っています。パッケージを入れたら、システムは「どのパッケージのどのファイルをどこに置いたか」を**パッケージのデータベース**に記録します。だから、後で消すときも、何を消せばよいかが分かります。

パッケージの形は、ディストリビューションの系統で 2 つに分かれます。

| | Debian 系 | Red Hat 系 |
| --- | --- | --- |
| 代表 | Debian、Ubuntu | RHEL、CentOS、Rocky Linux、AlmaLinux、Fedora |
| パッケージファイル | `.deb` | `.rpm` |
| 低レベルの道具（1 つのファイルを扱う） | `dpkg` | `rpm` |
| 高レベルの道具（リポジトリと依存を扱う） | `apt`、`apt-get`、`apt-cache` | `yum`、`dnf` |
| リポジトリの設定 | `/etc/apt/sources.list` | `/etc/yum.repos.d/*.repo` |
| データベース | `/var/lib/dpkg/` | `/var/lib/rpm/` |

パッケージのファイル名には、名前と版と CPU の種類（アーキテクチャ）が入っています。区切り方が 2 つの系統で違います。

| 系統 | 例 | 読み方 |
| --- | --- | --- |
| Debian 系 | `tree_2.1.0-1_arm64.deb` | 名前 `_` 版 `-` Debian での改訂 `_` アーキテクチャ |
| Red Hat 系 | `tree-1.8.0-10.el9.aarch64.rpm` | 名前 `-` 版 `-` リリース `.` アーキテクチャ |

```sh run title="パッケージのファイル名を、区切りで分けてみる"
echo tree_2.1.0-1_arm64.deb | tr '_' '\n'
echo tree-1.8.0-10.el9.aarch64.rpm | sed 's/\.rpm$//' | awk -F. '{print "アーキテクチャ:", $NF}'
```

`all`（Debian 系）や `noarch`（Red Hat 系）は、CPU の種類によらないパッケージです。シェルスクリプトや文書だけのパッケージがそうです。

## 依存関係とリポジトリ {#repo}

```fig tree curl パッケージの依存関係（一部）。curl を動かすには、下にあるライブラリのパッケージがすべて要る

    { label: 'zlib1g', note: '圧縮' },
    { label: 'libcurl4', kind: 'dir', hl: true, note: 'HTTP などを話すライブラリ', children: [
      { label: 'libssl3', note: '暗号（TLS）' },

      { label: 'libpsl5', note: 'ドメインの一覧' },
    ] },

```

ほとんどのプログラムは、ほかのパッケージに入っている**共有ライブラリ**を使います（仕組みは[図解 Linux 18.7](../../linux/site/ch18.html#dynlink)）。だから、`curl` パッケージだけを入れても動きません。`libcurl4` も、その先の `libssl3` も要ります。これを**依存関係**といいます。パッケージのメタデータには「何に依存するか」が書いてあります。

依存するパッケージを自分で 1 つずつ探して入れるのは大変です。そこで、パッケージを集めて置いておく**リポジトリ**（配布元のサーバ）と、それを使う高レベルの道具があります。

```fig seq apt-get install curl のときに起きること。apt が依存を解決してまとめてダウンロードし、1 つずつ dpkg に渡す

```

流れは 2 段です。まず `update` で、リポジトリから**パッケージの一覧**（インデックス）を取ってきて手元に保存します。次に `install` で、手元の一覧を見て依存をたどり、必要な `.deb` を全部ダウンロードして、低レベルの道具（`dpkg`）に渡します。Red Hat 系でも同じで、`yum` / `dnf` が依存を解いて、`rpm` のしくみで入れます。

低レベルの道具は、渡された 1 つのファイルしか扱いません。依存するパッケージが入っていなければ、エラーで止まるだけです。実際に、`curl` の `.deb` だけを `dpkg -i` で入れると、こうなります。

```console
# dpkg -i curl_7.88.1-10+deb12u15_arm64.deb
Selecting previously unselected package curl.
(Reading database ... 6090 files and directories currently installed.)
Preparing to unpack curl_7.88.1-10+deb12u15_arm64.deb ...
Unpacking curl (7.88.1-10+deb12u15) ...
dpkg: dependency problems prevent configuration of curl:
 curl depends on libcurl4 (= 7.88.1-10+deb12u15); however:
  Package libcurl4 is not installed.

dpkg: error processing package curl (--install):
 dependency problems - leaving unconfigured
Errors were encountered while processing:
 curl
```

`curl` は展開されたものの、設定されないまま残りました。ここで `apt-get install -f`（`-f` は fix-broken、壊れた依存を直す）を実行すると、apt が足りない 21 個を入れて、`curl` の設定まで終わらせます。

パッケージのメタデータの依存の行は、カンマで区切った一覧です。次は、その形の例です。

```sh run title="Depends の行を、1 行に 1 つの依存に分ける"
echo 'Depends: libc6 (>= 2.17), libcurl4 (= 7.88.1-10+deb12u15), zlib1g (>= 1:1.1.4)' | sed 's/^Depends: //' | tr ',' '\n' | sed 's/^ //'
```

`(>= 2.17)` は「2.17 以上の版」、`(= …)` は「ちょうどこの版」という条件です。

| 用語 | 意味 |
| --- | --- |
| パッケージ | ファイル + メタデータ + スクリプトをまとめたもの（`.deb`、`.rpm`） |
| 依存関係 | そのパッケージが動くのに必要な、ほかのパッケージ |
| リポジトリ | パッケージを集めて配るサーバ（や、ディレクトリ） |
| 低レベルの道具 | 手元の 1 つのファイルを入れる・消す・調べる。依存は解決しない（`dpkg`、`rpm`） |
| 高レベルの道具 | リポジトリから依存ごとまとめて入れる（`apt`、`yum`、`dnf`） |

依存関係を自動で解決するのは、高レベルの道具（`apt-get`、`apt`、`yum`、`dnf`）です。`dpkg -i` と `rpm -i` は、依存が足りなければエラーで止まるだけです。

## apt の 3 つのコマンド：apt-get、apt-cache、apt {#apt}

Debian 系の高レベルの道具は、昔から `apt-get`（入れる・消す・更新する）と `apt-cache`（一覧を調べる）の 2 つに分かれていました。あとから、よく使う機能を 1 つにまとめた `apt` ができました。`apt` は進み具合の表示などが人に見やすく、`apt-get` と `apt-cache` は出力の形が変わらないのでスクリプト向きです。

| やりたいこと | apt-get / apt-cache | apt |
| --- | --- | --- |
| 一覧を更新する | `apt-get update` | `apt update` |
| 入れる | `apt-get install 名前` | `apt install 名前` |
| 消す | `apt-get remove 名前` | `apt remove 名前` |
| 設定ファイルも消す | `apt-get purge 名前` | `apt purge 名前` |
| 不要になった依存を消す | `apt-get autoremove` | `apt autoremove` |
| 入っているものを新しくする | `apt-get upgrade` | `apt upgrade` |
| 依存の変化も含めて新しくする | `apt-get dist-upgrade` | `apt full-upgrade` |
| ダウンロードした .deb を消す | `apt-get clean` | `apt clean` |
| 探す | `apt-cache search 正規表現` | `apt search 正規表現` |
| 詳しく見る | `apt-cache show 名前` | `apt show 名前` |
| 依存を見る | `apt-cache depends 名前` | — |
| 版と優先度を見る | `apt-cache policy 名前` | `apt policy 名前` |
| 入っているものの一覧 | — | `apt list --installed` |

入れる・消す・更新するには root の権限が要ります（`sudo apt install …`。[図解 Linux 4.8](../../linux/site/ch04.html#root)）。この章の `# ` のプロンプトは root で打った例です。

## /etc/apt/sources.list の 1 行を読む {#sources-list}

```fig layout sources.list の 1 行。種類、URL、suite（ディストリビューションの版の名前）、component（区分）を空白で区切る
{
  unit: 12,
  rows: [
    { label: '1 行', cells: [{ t: 'deb', w: 4, kind: 'accent' }, { t: 'http://deb.debian.org/debian', w: 25, kind: 'stack' }, { t: 'bookworm', w: 9, kind: 'heap' }, { t: 'main', w: 5, kind: 'static' }, { t: 'contrib', w: 8, kind: 'static' }] },
    { label: '意味', cells: [{ t: '種類', w: 4, kind: 'accent' }, { t: 'URL（どこから）', w: 25, kind: 'stack' }, { t: 'suite', w: 9, kind: 'heap' }, { t: 'component（1 個以上）', w: 13, kind: 'static' }] },
  ],
}
```

apt がどのリポジトリを見るかは、`/etc/apt/sources.list` と、`/etc/apt/sources.list.d/` の下のファイルに書きます。1 行が 1 つのリポジトリで、空白で区切った 4 つ以上の欄でできています。

| 欄 | 例 | 意味 |
| --- | --- | --- |
| 種類 | `deb` / `deb-src` | `deb` はビルド済みのパッケージ、`deb-src` はソースコードのパッケージ |
| URL | `http://deb.debian.org/debian` | リポジトリの場所。`http://`、`https://`、`file:/`、`cdrom:` など |
| suite | `bookworm`、`bookworm-updates`、`bookworm-security`、`stable` | ディストリビューションの版の名前（コードネーム）か、`stable` のような種類 |
| component | `main`、`contrib`、`non-free`、`non-free-firmware` | リポジトリの中の区分。Debian では、`main` が自由なソフトウェアだけ、`contrib` は自由だが自由でないものに依存するもの、`non-free` は自由でないもの |

Docker の `debian:12` で、次の 4 行の `sources.list` を書いて `apt-get update` をすると、3 つのリポジトリから一覧を取ってきました（`deb-src` の行はソースの一覧です）。

```console
# cat /etc/apt/sources.list
deb http://deb.debian.org/debian bookworm main contrib non-free non-free-firmware
deb http://deb.debian.org/debian bookworm-updates main
deb http://deb.debian.org/debian-security bookworm-security main
deb-src http://deb.debian.org/debian bookworm main
# apt-get update
Hit:1 http://deb.debian.org/debian bookworm InRelease
Hit:2 http://deb.debian.org/debian bookworm-updates InRelease
Hit:3 http://deb.debian.org/debian-security bookworm-security InRelease
Reading package lists...
```

同じ書式のファイルを、小さな Linux で作って読んでみます。

```sh run title="sources.list の欄を awk で取り出す"
mkdir -p ~/apt
cat > ~/apt/sources.list <<'EOF'
# Debian 12 (bookworm)
deb http://deb.debian.org/debian bookworm main contrib non-free
deb http://deb.debian.org/debian bookworm-updates main
deb http://deb.debian.org/debian-security bookworm-security main
#deb-src http://deb.debian.org/debian bookworm main
EOF
grep -v '^#' ~/apt/sources.list | awk '{print "種類=" $1, "suite=" $3, "component の数=" NF-3}'
```

`#` で始まる行はコメントで、apt は読みません。最後の `deb-src` の行は、`#` を外すと有効になります。

:::note 新しい書き方：.sources（deb822 形式）
Debian 12 の Docker イメージには `/etc/apt/sources.list` がなく、`/etc/apt/sources.list.d/debian.sources` に、次の形で書かれていました。中身は同じで、欄に名前が付いただけです。試験で問われるのは、上の 1 行の形です。

```console
# cat /etc/apt/sources.list.d/debian.sources
Types: deb
URIs: http://deb.debian.org/debian
Suites: bookworm bookworm-updates
Components: main
Signed-By: /usr/share/keyrings/debian-archive-keyring.gpg
```
:::

:::warn 試験の注意
sources.list の欄の順番は **種類 → URL → suite → component** です。`bookworm` や `stable` は suite、`main` や `contrib` は component です。書き換えたら、`apt-get update` で一覧を取り直すまで、apt は新しいリポジトリのパッケージを知りません。
:::

## update と upgrade は別のもの {#update-upgrade}

名前が似ていて、試験でよく問われるところです。

| コマンド | 何をするか |
| --- | --- |
| `apt-get update` | リポジトリから**パッケージの一覧**を取ってきて、手元の一覧を新しくする。パッケージそのものは何も変えない |
| `apt-get upgrade` | 入っているパッケージを、一覧にある新しい版に入れ替える。**新しいパッケージを入れることも、パッケージを消すこともしない**。それが要る更新は保留する |
| `apt-get dist-upgrade` | upgrade に加えて、依存の変化に合わせて**新しいパッケージを入れたり、パッケージを消したり**もする |
| `apt full-upgrade` | `apt-get dist-upgrade` にあたる、apt の名前 |
| `apt upgrade` | 入っているものを新しくする。必要なら新しいパッケージは入れるが、消すことはしない |

ふつうの手順は「`update` してから `upgrade`」です。`update` をしないと、apt は古い一覧しか知らないので、新しい版があることに気づきません。

```console
# apt-get update
（省略）
# apt-get upgrade
Reading package lists...
Building dependency tree...
Reading state information...
0 upgraded, 0 newly installed, 0 to remove and 0 not upgraded.
```

最後の行は「入れ替えた数、新しく入れた数、消す数、保留した数」です。`upgrade` で保留された（`not upgraded`）ものがあるとき、それは「新しく入れるか消すかが要る更新」です。`dist-upgrade` なら入ります。

:::warn 試験の注意
**update はパッケージを更新しません**。一覧を取ってくるだけです。Red Hat 系の `yum update` はパッケージを更新するので、名前が同じでも意味が逆に近いことに気をつけます（[yum のサブコマンド](#yum-cmd)）。
:::

`install` には、`.deb` のファイル名ではなく**パッケージの名前**を渡します（`apt-get install tree`）。依存するパッケージは、apt が自動で選んで一緒に入れます。

```console
# apt-get install -y tree
（省略）
0 upgraded, 1 newly installed, 0 to remove and 0 not upgraded.
Need to get 50.9 kB of archives.
After this operation, 169 kB of additional disk space will be used.
Get:1 http://deb.debian.org/debian bookworm/main arm64 tree arm64 2.1.0-1 [50.9 kB]
Fetched 50.9 kB in 0s (1218 kB/s)
Selecting previously unselected package tree.
Preparing to unpack .../tree_2.1.0-1_arm64.deb ...
Unpacking tree (2.1.0-1) ...
Setting up tree (2.1.0-1) ...
```

`-y` は「よろしいですか」に自動で yes と答えるオプションです。ダウンロードした `.deb` は `/var/cache/apt/archives/` に置かれます。`apt-get clean` で、ここを空にできます。

消し方は 3 つあります。

- `remove`：プログラムなどのファイルを消す。**`/etc` などの設定ファイルは残す**（入れ直したとき、前の設定がそのまま使えるように）
- `purge`：設定ファイルも消す。`apt-get remove --purge` と書いても同じ
- `autoremove`：依存のために**自動で**入ったパッケージのうち、もう使うものがなくなったものを消す

`cron` パッケージで確かめました。`cron` には設定ファイル（`/etc/default/cron` など）があります。`remove` の後もそれは残り、`dpkg -l` の状態は `rc` になります。`purge` で消えます。

```console
# apt-get remove -y cron
（省略）
# ls /etc/default/cron
/etc/default/cron
# dpkg -l cron | tail -1
rc  cron           3.0pl1-162   arm64        process scheduling daemon
# apt-get purge -y cron
（省略）
# ls /etc/default/cron
ls: cannot access '/etc/default/cron': No such file or directory
```

`autoremove` は、`curl` を入れて消したときに出てきます。`curl` と一緒に入った 18 個のライブラリが、`curl` を消した後に「もう要らない」と表示されます。

```console
# apt-get remove -y curl
（省略）
The following packages were automatically installed and are no longer required:
  krb5-locales libbrotli1 libcurl4 libgssapi-krb5-2 libk5crypto3 libkeyutils1
  libkrb5-3 libkrb5support0 libldap-2.5-0 libldap-common libnghttp2-14 libpsl5
  librtmp1 libsasl2-2 libsasl2-modules libsasl2-modules-db libssh2-1
  publicsuffix
Use 'apt autoremove' to remove them.
# apt-get autoremove -y
（省略）
The following packages will be REMOVED:
  krb5-locales libbrotli1 libcurl4 libgssapi-krb5-2 libk5crypto3 libkeyutils1
  ...
```

| コマンド | 意味 |
| --- | --- |
| `apt-get install 名前` | 依存ごと入れる。`-y` で確認なし |
| `apt-get install -f` | 壊れた依存を直す（足りない依存を入れる）。`--fix-broken` |
| `apt-get install -d 名前` | ダウンロードだけする（`--download-only`）。`.deb` は `/var/cache/apt/archives/` へ |
| `apt-get download 名前` | `.deb` をいまのディレクトリにダウンロードするだけ |
| `apt-get remove 名前` | 消す。設定ファイルは残る |
| `apt-get purge 名前` | 設定ファイルも消す（`remove --purge` と同じ） |
| `apt-get autoremove` | 自動で入って不要になった依存を消す |
| `apt-get clean` | `/var/cache/apt/archives/` の `.deb` を消す（`autoclean` は、もう手に入らない古い版だけ） |

**apt なら .deb のファイルも渡せます。** `apt install ./tree_2.1.0-1_arm64.deb` のように `./` を付けてファイルを渡すと、apt はそのファイルを入れ、足りない依存はリポジトリから入れます。`dpkg -i` と違って依存で止まりません。

## 調べる：search、show、depends、policy、apt-file {#apt-cache}

`apt-cache` は、`update` で手元に取ってきた一覧を調べるだけのコマンドです。何も変えないので、root でなくても使えます。

```console
$ apt-cache search --names-only '^tree$'
tree - displays an indented directory tree, in color
$ apt-cache show tree
Package: tree
Version: 2.1.0-1
Installed-Size: 165
Maintainer: Florian Ernst <florian@debian.org>
Architecture: arm64
Depends: libc6 (>= 2.34)
Description: displays an indented directory tree, in color
（省略）
Section: utils
Priority: optional
Filename: pool/main/t/tree/tree_2.1.0-1_arm64.deb
Size: 50920
$ apt-cache depends curl
curl
  Depends: libc6
  Depends: libcurl4
  Depends: zlib1g
$ apt-cache rdepends libcurl4
libcurl4
Reverse Depends:
  curl
  systemd-journal-remote
（省略）
```

`search` の引数は正規表現で、名前と説明の両方から探します（`--names-only` で名前だけ）。`depends` は「このパッケージが必要とするもの」、`rdepends`（reverse depends）は逆に「このパッケージを必要とするもの」です。

`policy` は、版の情報を見ます。

```console
$ apt-cache policy tree
tree:
  Installed: 2.1.0-1
  Candidate: 2.1.0-1
  Version table:
 *** 2.1.0-1 500
        500 http://deb.debian.org/debian bookworm/main arm64 Packages
        100 /var/lib/dpkg/status
```

| 行 | 意味 |
| --- | --- |
| `Installed:` | いま入っている版。入っていなければ `(none)` |
| `Candidate:` | `install` や `upgrade` をしたら入る版（候補） |
| `Version table:` | 手に入る版と、どのリポジトリにあるか。数字は優先度。`***` がいま入っている版 |

**apt-file** は、「このファイルはどのパッケージに入っているか」を、**まだ入れていないパッケージも含めて**調べる道具です。別のパッケージ（`apt-file`）なので、入れてから `apt-file update` で、ファイルの一覧を取ってきます。

```console
# apt-get install -y apt-file
# apt-file update
$ apt-file search bin/htop
htop: /usr/bin/htop
$ apt-file list tree
tree: /usr/bin/tree
tree: /usr/share/doc/tree/README.gz
tree: /usr/share/doc/tree/TODO
（省略）
tree: /usr/share/man/man1/tree.1.gz
```

`htop` は入れていませんが、`/usr/bin/htop` は `htop` パッケージにあると分かりました。

| コマンド | 調べる対象 | 何が分かるか |
| --- | --- | --- |
| `apt-cache search 正規表現` | リポジトリの一覧 | 名前か説明に合うパッケージ |
| `apt-cache show 名前` | リポジトリの一覧 | 版、依存、大きさ、説明 |
| `apt-cache depends 名前` | リポジトリの一覧 | 依存するパッケージ |
| `apt-cache rdepends 名前` | リポジトリの一覧 | そのパッケージに依存するパッケージ |
| `apt-cache policy 名前` | リポジトリの一覧と、入っているもの | 入っている版、候補の版、優先度 |
| `apt-file search ファイル` | リポジトリのファイルの一覧 | そのファイルを含むパッケージ（入っていなくてよい） |
| `apt-file list 名前` | リポジトリのファイルの一覧 | パッケージに入っているファイル（入っていなくてよい） |
| `apt list --installed` | 入っているもの | 入っているパッケージの一覧 |

:::warn 試験の注意
「ファイルからパッケージを探す」には 2 つあります。`dpkg -S` は**入っているパッケージ**だけ、`apt-file search` は**リポジトリにあるすべてのパッケージ**から探します。`apt-cache search` は名前と説明を探すもので、中のファイル名は探しません。
:::

## dpkg：.deb を直接扱う {#dpkg}

`dpkg` は Debian 系の低レベルの道具です。手元の `.deb` ファイルを入れたり、入っているパッケージを消したり調べたりします。依存の解決はしません。

| オプション | 長い形 | 意味 | 引数 |
| --- | --- | --- | --- |
| `-i` | `--install` | 入れる | `.deb` ファイル |
| `-r` | `--remove` | 消す。設定ファイルは残る | パッケージ名 |
| `-P` | `--purge` | 設定ファイルも消す | パッケージ名 |
| `-l` | `--list` | 入っているパッケージを状態つきで一覧（パターンも可） | なし / パターン |
| `-L` | `--listfiles` | そのパッケージが置いたファイルの一覧 | パッケージ名 |
| `-S` | `--search` | そのファイルを置いたパッケージを探す | ファイル（パターン） |
| `-s` | `--status` | 状態と詳しい情報 | パッケージ名 |
| | `--configure` | 展開したが設定していないパッケージを設定する。`-a` ですべて | パッケージ名 / `-a` |
| `-c` | `--contents` | `.deb` ファイルの中身の一覧 | `.deb` ファイル |
| `-I` | `--info` | `.deb` ファイルのメタデータ | `.deb` ファイル |

`-i` だけがファイルを、`-r`、`-P`、`-L`、`-s` はパッケージ名を取ります。`dpkg --help` にも、そう書いてあります。

```console
$ dpkg --help
（抜粋）
  -i|--install       <.deb file name>... | -R|--recursive <directory>...
  --configure        <package>... | -a|--pending
  -r|--remove        <package>... | -a|--pending
  -P|--purge         <package>... | -a|--pending
  -s|--status [<package>...]       Display package status details.
  -L|--listfiles <package>...      List files 'owned' by package(s).
  -l|--list [<pattern>...]         List packages concisely.
  -S|--search <pattern>...         Find package(s) owning file(s).
```

調べるときの出力です。

```console
$ dpkg -L tree
/.
/usr
/usr/bin
/usr/bin/tree
/usr/share
/usr/share/doc
/usr/share/doc/tree
/usr/share/doc/tree/README.gz
（省略）
/usr/share/man/man1/tree.1.gz
$ dpkg -S /usr/bin/tree
tree: /usr/bin/tree
$ dpkg -s tree
Package: tree
Status: install ok installed
Priority: optional
Section: utils
Installed-Size: 165
Maintainer: Florian Ernst <florian@debian.org>
Architecture: arm64
Version: 2.1.0-1
Depends: libc6 (>= 2.34)
（省略）
```

`dpkg -i` で入れて、`-r` と `-P` で消す流れです。`-r` の後に `-P` をすると、残っていた設定ファイルの記録も消えます。

```console
# dpkg -i /var/cache/apt/archives/tree_2.1.0-1_arm64.deb
Selecting previously unselected package tree.
(Reading database ... 6090 files and directories currently installed.)
Preparing to unpack .../tree_2.1.0-1_arm64.deb ...
Unpacking tree (2.1.0-1) ...
Setting up tree (2.1.0-1) ...
# dpkg -r tree
(Reading database ... 6098 files and directories currently installed.)
Removing tree (2.1.0-1) ...
```

`dpkg -i` は「展開（unpack）」と「設定（setting up、configure）」の 2 段で入れます。途中で止まって、展開だけされたパッケージが残ったときは、`dpkg --configure -a` で、設定していないものをすべて設定します。依存が足りないのが原因なら、先に `apt-get install -f` です。

:::warn 試験の注意
大文字と小文字で別の意味です。`-l`（一覧）と `-L`（ファイルの一覧）、`-s`（状態）と `-S`（ファイルからパッケージを探す）、`-r`（消す）と `-P`（設定ファイルも消す）。`-L` と `-S` は**入っているパッケージ**だけが対象です。
:::

頭の 2 文字は、上の 3 行の見出しの頭文字です。1 文字目は「望む状態」（**i**nstall、**r**emove、**p**urge、**h**old、**u**nknown）、2 文字目は「いまの状態」（**i**nst = 入っている、**c**onf-files = 設定ファイルだけ、**n**ot = 入っていない、**U**npacked = 展開だけ）です。

この章でも、`rc` は `cron` を `remove` した後、`iU` は `curl` を依存なしで `dpkg -i` した後に出ました。

```console
$ dpkg -l curl | tail -1

```

一覧から、設定ファイルだけ残っているパッケージを探すのは、よくある作業です。`dpkg -l` の出力の形をした例のファイルで試します。

```sh run title="dpkg -l の出力から、状態ごとに取り出す"
cat > ~/apt/dpkg-l.txt <<'EOF'
ii  adduser        3.134        all          add and remove users and groups
ii  apt            2.6.2        arm64        commandline package manager
rc  cron           3.0pl1-162   arm64        process scheduling daemon
ii  tree           2.1.0-1      arm64        displays an indented directory tree, in color
iU  curl           7.88.1-10    arm64        command line tool for transferring data
EOF
grep '^rc' ~/apt/dpkg-l.txt
awk '$1 == "ii" { n++ } END { print "入っている:", n }' ~/apt/dpkg-l.txt
```

`rc` のものをまとめて消すなら、本物では `dpkg -P cron` のように、名前を `dpkg -P` に渡します。

## dpkg-reconfigure：最初の質問に答え直す {#dpkg-reconfigure}

パッケージの中には、入れるときに質問をするものがあります。`tzdata`（タイムゾーン）、`locales`（言語）、`keyboard-configuration`（キーボード）などです。答えは debconf という仕組みが覚えていて、設定ファイルに反映されます。

`dpkg-reconfigure パッケージ名` は、入っているパッケージの**設定をやり直す**コマンドです。質問がもう一度出て、答え直すと設定ファイルが書き換わります。

```console
# cat /etc/timezone
Etc/UTC
# dpkg-reconfigure tzdata
（地域と都市を選ぶ画面が出る。Asia → Tokyo を選ぶ）

Current default time zone: 'Asia/Tokyo'
Local time is now:      Mon Nov 16 20:16:02 JST 2026.
Universal Time is now:  Mon Nov 16 11:16:02 UTC 2026.

# cat /etc/timezone
Asia/Tokyo
```

（Docker では画面が出せないので、答えを先に `debconf-set-selections` で入れてから、`dpkg-reconfigure -f noninteractive tzdata` で実行しました。出力の後半はそのときのものです。）

| コマンド | 意味 |
| --- | --- |
| `dpkg-reconfigure パッケージ名` | 入っているパッケージの設定の質問に答え直す |
| `dpkg --configure パッケージ名` | 展開されて、まだ設定されていないパッケージを設定する（`-a` ですべて） |

`dpkg-reconfigure` は**入っているパッケージの設定をやり直す**もので、パッケージを入れ直すわけではありません。`dpkg --configure` は「途中で止まったものの設定を済ませる」もので、目的が違います。

## yum と dnf {#yum}

Red Hat 系の高レベルの道具は、長く **yum** でした。RHEL 8 からは、その後継の **dnf** になり、`yum` というコマンドは dnf への別名として残っています。Rocky Linux 9 では、どちらも同じ `dnf-3` を指すリンクです。

```console
$ ls -l /usr/bin/yum /usr/bin/dnf
lrwxrwxrwx 1 root root 5 Nov  1  2023 /usr/bin/dnf -> dnf-3
lrwxrwxrwx 1 root root 5 Nov  1  2023 /usr/bin/yum -> dnf-3
$ yum --version | head -1
4.14.0
```

サブコマンドは、yum と dnf でほぼ同じです（`yum install` と `dnf install`）。試験の範囲の名前は yum なので、この本も yum で書きます。

## リポジトリの設定：.repo と yum.conf {#yum-repo}

yum がどのリポジトリを見るかは、`/etc/yum.repos.d/` の下の、名前が **`.repo`** で終わるファイルに書きます。1 つのファイルに、`[ID]` で始まるリポジトリをいくつ書いてもかまいません。

| キー | 意味 |
| --- | --- |
| `[ID]` | リポジトリの ID。`yum repolist` の `repo id` に出る |
| `name` | 人が読むための名前 |
| `baseurl` | リポジトリの URL（`http://`、`https://`、`ftp://`、`file://`） |
| `mirrorlist` / `metalink` | baseurl の代わりに、ミラーの一覧を返す URL |
| `enabled` | `1` で有効、`0` で無効 |
| `gpgcheck` | `1` でパッケージの GPG 署名を確かめる、`0` で確かめない |
| `gpgkey` | 署名を確かめる公開鍵の場所 |

`$releasever`（OS の版。Rocky 9 なら 9）と `$basearch`（CPU の種類）は、yum が実際の値に置き換えます。Rocky Linux 9 にある `rocky.repo` の始めです。

```console
$ ls /etc/yum.repos.d/
rocky-addons.repo
rocky-devel.repo
rocky-extras.repo
rocky.repo
$ cat /etc/yum.repos.d/rocky.repo
（コメントは省略）
[baseos]
name=Rocky Linux $releasever - BaseOS
mirrorlist=https://mirrors.rockylinux.org/mirrorlist?arch=$basearch&repo=BaseOS-$releasever$rltype
#baseurl=http://dl.rockylinux.org/$contentdir/$releasever/BaseOS/$basearch/os/
gpgcheck=1
enabled=1
countme=1
metadata_expire=6h
gpgkey=file:///etc/pki/rpm-gpg/RPM-GPG-KEY-Rocky-9

[baseos-debug]
name=Rocky Linux $releasever - BaseOS - Debug
（省略）
enabled=0
```

自分で `.repo` を作って置くと、`yum repolist` に出ました。`enabled=0` にすると、`repolist all` で `disabled` と出ます。その時だけ使いたいなら `--enablerepo=ID` を付けます。

```console
# cat /etc/yum.repos.d/myrepo.repo
[myrepo]
name=My Repository
baseurl=http://dl.rockylinux.org/pub/rocky/$releasever/BaseOS/$basearch/os/
enabled=1
gpgcheck=0
# yum repolist
repo id                         repo name
appstream                       Rocky Linux 9 - AppStream
baseos                          Rocky Linux 9 - BaseOS
extras                          Rocky Linux 9 - Extras
myrepo                          My Repository
# sed -i s/enabled=1/enabled=0/ /etc/yum.repos.d/myrepo.repo
# yum repolist all | grep myrepo
myrepo                  My Repository                                   disabled
```

同じ形のファイルを、小さな Linux で読んでみます。

```sh run title=".repo の ID と enabled を取り出す"
mkdir -p ~/yum
cat > ~/yum/sample.repo <<'EOF'
[baseos]
name=Rocky Linux $releasever - BaseOS
baseurl=http://dl.rockylinux.org/pub/rocky/$releasever/BaseOS/$basearch/os/
gpgcheck=1
enabled=1

[baseos-debug]
name=Rocky Linux $releasever - BaseOS - Debug
baseurl=http://dl.rockylinux.org/pub/rocky/$releasever/BaseOS/$basearch/debug/tree/
gpgcheck=1
enabled=0
EOF
grep -E '^\[|^enabled' ~/yum/sample.repo
```

```sh run title="enabled=0 のリポジトリの ID だけを出す"
awk '/^\[/ { id = $0 } /^enabled=0/ { print id }' ~/yum/sample.repo
```

**`/etc/yum.conf`** は、yum 全体の設定です。`[main]` の節に、すべてのリポジトリに効く既定値を書きます。Rocky Linux 9 では、dnf の設定ファイル `/etc/dnf/dnf.conf` へのリンクになっていました。

```console
$ ls -l /etc/yum.conf
lrwxrwxrwx 1 root root 12 Nov  1  2023 /etc/yum.conf -> dnf/dnf.conf
$ cat /etc/yum.conf
[main]
gpgcheck=1
installonly_limit=3
clean_requirements_on_remove=True
best=True
skip_if_unavailable=False
```

| ファイル | 役目 |
| --- | --- |
| `/etc/yum.conf` | yum 全体の設定（`[main]`）。RHEL 8 以降は `/etc/dnf/dnf.conf` と同じもの |
| `/etc/yum.repos.d/*.repo` | リポジトリの設定。拡張子が `.repo` のものだけ読まれる |
| `/var/cache/yum/`（dnf は `/var/cache/dnf/`） | ダウンロードしたメタデータとパッケージ。`yum clean all` で消す |

ディレクトリは `/etc/yum.repos.d/`（`repos` と複数形、最後に `.d`）、ファイルの拡張子は `.repo`（単数形）です。`baseurl` は 1 語、`enabled` と `gpgcheck` の値は `1` / `0` です。

## yumdownloader：入れずにダウンロードだけ {#yumdownloader}

`yumdownloader` は、リポジトリから `.rpm` ファイルを**ダウンロードするだけ**のコマンドです。入れはしません。別の機械に持っていく、中身を `rpm -qp` で調べる、といったときに使います。`yum-utils`（dnf では `dnf-utils` と同じもの）パッケージに入っています。

```console
# yum install -y yum-utils
$ cd /tmp
$ yumdownloader tree tmux
（省略）
(1/2): tree-1.8.0-10.el9.aarch64.rpm            317 kB/s |  54 kB     00:00
(2/2): tmux-3.2a-5.el9.aarch64.rpm              1.2 MB/s | 460 kB     00:00
$ ls
tmux-3.2a-5.el9.aarch64.rpm
tree-1.8.0-10.el9.aarch64.rpm
```

| オプション | 意味 |
| --- | --- |
| `--resolve` | 依存するパッケージも一緒にダウンロードする |
| `--destdir ディレクトリ` | 保存する場所（既定はいまのディレクトリ） |
| `--source` | ソースの `.src.rpm` をダウンロードする |

ほかに「ダウンロードだけ」をするコマンドは、Debian 系では `apt-get download 名前`（いまのディレクトリへ）か、`apt-get install -d 名前`（`/var/cache/apt/archives/` へ）です。dnf では `dnf download 名前` も使えます（dnf-plugins-core のプラグイン）。

## rpm：入れる、新しくする、消す {#rpm-install}

```fig graph rpm の -i、-U、-F の違い。すでに古い版が入っているかどうかで、することが変わる
{
  col: 210, row: 84,
  nodes: [
    { id: 'q', label: '古い版が入っている？', x: 1, y: 0, kind: 'plain', mono: false },
    { id: 'i', label: '-i', sub: '入っていなければ入れる', x: 0, y: 1, kind: 'stack' },
    { id: 'U', label: '-U', sub: 'どちらでも入れる', x: 1, y: 1, kind: 'accent' },
    { id: 'F', label: '-F', sub: '入っていれば新しくする', x: 2, y: 1, kind: 'stack' },
  ],
  edges: [
    { from: 'q', to: 'i', label: 'いいえ のとき' },
    { from: 'q', to: 'U', label: '両方' },
    { from: 'q', to: 'F', label: 'はい のとき' },
  ],

```

`rpm` は Red Hat 系の低レベルの道具で、`dpkg` にあたります。手元の `.rpm` を扱い、依存は解決しません。

| オプション | 長い形 | 意味 |
| --- | --- | --- |
| `-i` | `--install` | 入れる（同じものが入っているとエラー） |
| `-U` | `--upgrade` | 新しくする。**入っていなければ入れる** |
| `-F` | `--freshen` | 新しくする。**入っていなければ何もしない** |
| `-e` | `--erase` | 消す（パッケージ名を渡す） |
| `-v` / `-h` | | 詳しく表示 / 進み具合を `#` で表示。`-ivh`、`-Uvh` とまとめて使う |
| | `--nodeps` | 依存を確かめない（足りなくても入れる・消す） |

`rpm --help` の説明も、`-F` は「入っていれば新しくする」です。

```console
$ rpm --help
（抜粋）
  -e, --erase=<package>+             erase (uninstall) package
  -F, --freshen=<packagefile>+       upgrade package(s) if already installed
  -i, --install                      install package(s)
      --nodeps                       do not verify package dependencies
  -U, --upgrade=<packagefile>+       upgrade package(s)
```

`tree` が入っていない状態で、`-F` と `-U` を比べました。`-F` は何もせず成功で終わり、`-U` は入れました。もう一度 `-i` をすると、入っているのでエラーです。

```console
# rpm -Fvh tree-1.8.0-10.el9.aarch64.rpm
# rpm -q tree
package tree is not installed
# rpm -Uvh tree-1.8.0-10.el9.aarch64.rpm
Verifying...                          ########################################
Preparing...                          ########################################
Updating / installing...
tree-1.8.0-10.el9                     ########################################
# rpm -ivh tree-1.8.0-10.el9.aarch64.rpm
Verifying...                          ########################################
Preparing...                          	package tree-1.8.0-10.el9.aarch64 is already installed
```

依存が足りない `.rpm`（`wget` は `libpsl` を必要とする）を `-i` すると、止まります。`--nodeps` を付けると入りますが、ライブラリがないので動きません。`yum install ./ファイル` なら、足りない依存をリポジトリから入れます。

```console
# rpm -ivh wget-1.21.1-11.el9_8.aarch64.rpm
error: Failed dependencies:
	libpsl.so.5()(64bit) is needed by wget-1.21.1-11.el9_8.aarch64
# rpm -ivh --nodeps wget-1.21.1-11.el9_8.aarch64.rpm
（入る）
$ wget --version
wget: error while loading shared libraries: libpsl.so.5: cannot open shared object file: No such file or directory
# rpm -e --nodeps wget
# yum install -y ./wget-1.21.1-11.el9_8.aarch64.rpm
（抜粋）
Installing:
 wget                       aarch64    1.21.1-11.el9_8    @commandline    761 k
Installing dependencies:
 libpsl                     aarch64    0.21.1-5.el9       baseos           63 k
 publicsuffix-list-dafsa    noarch     20210518-3.el9     baseos           58 k
```

消すときも依存を確かめます。ほかのパッケージが使っているものは、`-e` で消せません。

```console
# rpm -e libevent
error: Failed dependencies:
	libevent-2.1.so.7()(64bit) is needed by (installed) openldap-2.6.3-1.el9.aarch64
```

:::warn 試験の注意
`-U` と `-F` の違いは「入っていないとき」です。`-U` は入れる、`-F` は何もしない。`-e` には**パッケージ名**（`tree`）を渡し、ファイル名（`tree-1.8.0-10.el9.aarch64.rpm`）は渡しません。`--nodeps` は依存の確認を飛ばすだけで、足りない依存を入れてはくれません。
:::

## rpm -q：問い合わせる {#rpm-query}

`-q`（query）は、データベースに問い合わせるオプションです。後ろに文字を足して、何を聞くかを決めます。

| オプション | 対象 | 何が分かるか |
| --- | --- | --- |
| `rpm -q 名前` | 入っているもの | 入っているか、入っていれば正確な名前と版 |
| `rpm -qa` | 入っているもの全部 | すべてのパッケージの一覧（all） |
| `rpm -qi 名前` | 入っているもの | 詳しい情報（info）。版、入れた日、説明 |
| `rpm -ql 名前` | 入っているもの | 入っているファイルの一覧（list） |
| `rpm -qf ファイル` | 入っているもの | そのファイルを含むパッケージ（file） |
| `rpm -qR 名前` | 入っているもの | 依存するもの（requires） |
| `rpm -qc 名前` / `rpm -qd 名前` | 入っているもの | 設定ファイル / 文書ファイルの一覧 |
| `rpm -qp… ファイル.rpm` | **手元の .rpm ファイル** | `-qpi`、`-qpl`、`-qpR` のように組み合わせる（package） |

Rocky Linux 9 の `bash` で試した出力です。


まだ入れていない `.rpm` ファイルを調べるときは、**`-p` を付けます**。付けないと、rpm はファイル名をパッケージ名だと思って、データベースを探してしまいます。


`rpm -qa` の出力は 1 行に 1 つのパッケージです。`grep` と組み合わせて使います。同じ形の例の一覧で試します。

```sh run title="rpm -qa の一覧から、名前で探して数える"
mkdir -p ~/rpm
cat > ~/rpm/qa.txt <<'EOF'

grep '^bash-' ~/rpm/qa.txt
grep -c 'noarch$' ~/rpm/qa.txt
sort ~/rpm/qa.txt | head -3
```

`rpm -qf` は「ファイル → パッケージ」、`rpm -ql` は「パッケージ → ファイル」です。dpkg では `-S` と `-L` にあたります。`-qf` は入っているパッケージだけが対象で、リポジトリから探すなら `yum provides` です。

## rpm -V と --import：検査と署名の鍵 {#rpm-verify}

```fig layout rpm -V の 1 行。9 文字の印のうち、変わったところだけが文字になる。. は「変わっていない」
{
  unit: 14,
  rows: [
    { label: '出力', cells: [{ t: 'S', w: 1, kind: 'accent' }, { t: '.', w: 1 }, { t: '5', w: 1, kind: 'accent' }, { t: '.', w: 1 }, { t: '.', w: 1 }, { t: '.', w: 1 }, { t: '.', w: 1 }, { t: 'T', w: 1, kind: 'accent' }, { t: '.', w: 1 }, { t: 'd', w: 2, kind: 'stack' }, { t: '/usr/share/doc/tree/README', w: 18, kind: 'plain' }] },
    { label: '意味', cells: [{ t: '大', w: 1, kind: 'accent' }, { t: 'M', w: 1 }, { t: '中', w: 1, kind: 'accent' }, { t: 'D', w: 1 }, { t: 'L', w: 1 }, { t: 'U', w: 1 }, { t: 'G', w: 1 }, { t: '時', w: 1, kind: 'accent' }, { t: 'P', w: 1 }, { t: '種類', w: 2, kind: 'stack' }, { t: 'ファイル', w: 18, kind: 'plain' }] },
  ],
}
```

`rpm -V 名前`（verify）は、入れたときのファイルの記録と、いまのファイルを比べて、**変わったものだけ**を表示します。何も出なければ、変わっていません。`rpm -Va` ですべてのパッケージを検査します。

`tree` を入れた後、文書のファイルに 1 行足し、コマンドのファイルを消してから検査しました。

```console
# echo x >> /usr/share/doc/tree/README
# rm /usr/bin/tree
# rpm -V tree
missing     /usr/bin/tree
S.5....T.  d /usr/share/doc/tree/README
$ rpm -V bash
$ echo $?
0
```

| 印 | 意味 |
| --- | --- |
| `S` | 大きさ（Size）が違う |
| `M` | 権限やファイルの種類（Mode）が違う |
| `5` | 中身のダイジェスト（昔は MD5）が違う＝中身が変わった |
| `T` | 更新時刻（mTime）が違う |
| `U` / `G` | 持ち主 / グループが違う |
| `missing` | ファイルがない |
| `c` / `d` | 設定ファイル / 文書ファイル（印の後ろの 1 文字） |

```sh run title="rpm -V の出力から、中身が変わったもの（3 文字目が 5）を探す"
cat > ~/rpm/verify.txt <<'EOF'
missing     /usr/bin/tree
S.5....T.  d /usr/share/doc/tree/README
.M.......    /var/log
S.5....T.  c /etc/sample.conf
EOF
cut -c1-9 ~/rpm/verify.txt
awk 'substr($0, 3, 1) == "5" { print $NF }' ~/rpm/verify.txt
```

**`rpm --import 鍵のファイル`** は、パッケージの署名を確かめるための **GPG 公開鍵**を、rpm のデータベースに取り込みます。取り込んだ鍵は、`gpg-pubkey` という名前のパッケージのように見えます。`.repo` の `gpgcheck=1` は、この鍵で署名を確かめるという意味です（yum は `gpgkey=` の鍵を、初めて使うときに自動で取り込みます）。

```console
$ rpm -q gpg-pubkey
package gpg-pubkey is not installed
# rpm --import /etc/pki/rpm-gpg/RPM-GPG-KEY-Rocky-9
$ rpm -q gpg-pubkey
gpg-pubkey-350d275d-6279464b
```

| コマンド | 意味 |
| --- | --- |
| `rpm -V 名前` | 入っているパッケージのファイルが変わっていないか検査する（`--verify`）。`-Va` で全部 |
| `rpm --import 鍵` | GPG 公開鍵を取り込む |

:::deep rpm と dpkg の対応表
2 つの低レベルの道具は、できることがほぼ対応しています。片方を覚えたら、もう片方は文字の違いで覚えられます。

| やりたいこと | dpkg | rpm |
| --- | --- | --- |
| ファイルから入れる | `dpkg -i x.deb` | `rpm -i x.rpm`（`-U` も） |
| 消す | `dpkg -r 名前` / `dpkg -P 名前` | `rpm -e 名前` |
| 一覧 | `dpkg -l` | `rpm -qa` |
| 詳しい情報 | `dpkg -s 名前` | `rpm -qi 名前` |
| 入っているファイル | `dpkg -L 名前` | `rpm -ql 名前` |
| ファイル → パッケージ | `dpkg -S ファイル` | `rpm -qf ファイル` |
| パッケージファイルの中身 | `dpkg -c x.deb` | `rpm -qpl x.rpm` |
:::

:::key まとめ
- パッケージは、ファイル + メタデータ（名前・版・依存）+ スクリプト。Debian 系は `.deb`、Red Hat 系は `.rpm`
- 低レベルの道具（`dpkg`、`rpm`）は 1 つのファイルを扱い、依存を解決しない。高レベルの道具（`apt`、`apt-get`、`yum`、`dnf`）はリポジトリから依存ごと入れる
- `/etc/apt/sources.list` は `deb URL suite component…`。`apt-get update` は一覧を取るだけ、`upgrade` は入れ替えるだけ（追加・削除なし）、`dist-upgrade`（apt では `full-upgrade`）は追加・削除もする
- `remove` は設定ファイルを残し（`dpkg -l` で `rc`）、`purge` は消す。`autoremove` は不要になった自動の依存を消す
- 調べる：`apt-cache search / show / depends / policy`。ファイルから探す：入っているものは `dpkg -S` / `rpm -qf`、リポジトリからは `apt-file search` / `yum provides`
- dpkg：`-i` ファイル、`-r` / `-P` 消す、`-l` 一覧、`-L` ファイル一覧、`-S` 持ち主、`-s` 状態、`--configure -a`。`dpkg-reconfigure` は設定の質問に答え直す
- yum（いまは dnf の別名）：`install / remove / update / search / info / list / provides / groupinstall / repolist / clean all`。`yum update` は実際に更新する
- `/etc/yum.repos.d/*.repo` は `[ID]`、`name`、`baseurl`、`enabled`、`gpgcheck`。全体の設定は `/etc/yum.conf`。`yumdownloader` はダウンロードだけ（`--resolve` で依存も）
- rpm：`-i` 入れる、`-U` 入っていなくても入れる、`-F` 入っていれば新しくする、`-e` 消す、`--nodeps` 依存を見ない。`-q` に `a i l f R` を足して問い合わせ、`-p` で手元のファイル。`-V` で検査、`--import` で鍵
:::

## 練習問題 {#practice}

### 1.04.1 apt コマンドによるパッケージ管理

:::q 1.04.1-01 single
Debian 系のシステムで `apt-get update` を実行したときの動作として正しいものはどれか。
- [ ] インストールされているパッケージを、新しい版に入れ替える
- [x] `/etc/apt/sources.list` などに書かれたリポジトリから、パッケージの一覧を取得する
- [ ] apt-get 自身を最新の版に入れ替える
- [ ] 依存関係が壊れたパッケージを修復する
:::why
`update` は、リポジトリから**パッケージの一覧**（インデックス）を取ってきて、手元の一覧（`/var/lib/apt/lists/`）を新しくするだけです。パッケージそのものは変えません（[update と upgrade は別のもの](#update-upgrade)）。

- 入っているパッケージを新しくするのは `apt-get upgrade`（や `dist-upgrade`）です
- apt-get 自身だけを特別に更新する機能はありません。apt も 1 つのパッケージとして `upgrade` で新しくなります
- 壊れた依存を直すのは `apt-get install -f` です
:::
:::

:::q 1.04.1-02 single
Debian 系のシステムで、新しい版に必要な依存関係が変わったために、新しいパッケージの追加や既存のパッケージの削除が必要な更新も含めて、システムを更新したい。使うコマンドとして最も適切なものはどれか。
- [ ] `apt-get update`
- [ ] `apt-get upgrade`
- [x] `apt-get dist-upgrade`
- [ ] `apt-get autoremove`
- [ ] `apt-get install -f`
:::why
`apt-get dist-upgrade`（apt では `apt full-upgrade`）は、依存の変化に合わせて、新しいパッケージを入れたり、パッケージを消したりしながら更新します。

- `apt-get upgrade` は、パッケージの追加も削除もしません。それが必要な更新は保留（`not upgraded`）にします
- `apt-get update` は一覧を取るだけで、何も更新しません
- `apt-get autoremove` は、自動で入って不要になった依存を消すだけです
- `apt-get install -f` は壊れた依存を直すもので、システム全体の更新ではありません
:::
:::

:::q 1.04.1-03 multi
Debian 系のシステムで、パッケージ `nginx` を、`/etc` の下の設定ファイルも含めて削除するコマンドを 2 つ選択してください。
- [ ] `apt-get remove nginx`
- [x] `apt-get purge nginx`
- [ ] `apt-get autoremove nginx`
- [x] `apt-get remove --purge nginx`
- [ ] `apt-get clean nginx`
:::why
`purge` と `remove --purge` は同じ意味で、設定ファイルも消します（[入れる・消す](#install-remove)）。

- `remove` は設定ファイルを残します。`dpkg -l` で状態が `rc` になります
- `autoremove` は、依存のために自動で入り、もう使われなくなったパッケージを消すものです。指定したパッケージの設定ファイルを消すものではありません
- `clean` は、`/var/cache/apt/archives/` にダウンロードした `.deb` を消すもので、入っているパッケージには触りません
:::
:::

:::q 1.04.1-04 single
`/etc/apt/sources.list` に次の行がある。`bookworm` の欄の説明として正しいものはどれか。

```text
deb http://deb.debian.org/debian bookworm main contrib
```
- [ ] リポジトリの中の区分（component）を表す
- [x] ディストリビューションの版の名前（suite）を表す
- [ ] ソースコードのパッケージを取るかどうかを表す
- [ ] リポジトリのサーバのホスト名を表す
:::why
欄の順番は「種類 → URL → suite → component」です。3 番目の `bookworm` は suite で、Debian 12 のコードネームです（[sources.list の 1 行を読む](#sources-list)）。

- component は 4 番目以降の `main` と `contrib` です
- ソースを取るかどうかは 1 番目の種類（`deb` か `deb-src`）で決まります
- サーバのホスト名は、2 番目の URL の中の `deb.debian.org` です
:::
:::

:::q 1.04.1-05 fill
Debian 系のシステムで、apt が参照するリポジトリを 1 行に 1 つずつ書く、伝統的な設定ファイルのパスを絶対パスで入力してください。

:::why

:::
:::

:::q 1.04.1-06 single
パッケージ `curl` が依存しているパッケージだけを一覧で表示するコマンドとして最も適切なものはどれか。

- [ ] `apt-cache policy curl`
- [x] `apt-cache depends curl`
- [ ] `apt-cache rdepends curl`
- [ ] `apt-cache search curl`
:::why
`apt-cache depends` は、そのパッケージが必要とするパッケージを `Depends:` の形で一覧します（[調べる](#apt-cache)）。

- `show` は詳しい情報で、`Depends:` の行も含みますが、依存の一覧を出すためのコマンドではなく、版や大きさや説明も出ます。「依存の一覧を表示する」には `depends` がはっきり合います
- `policy` は、入っている版と候補の版、優先度を出します
- `rdepends` は逆で、**curl に依存しているパッケージ**を出します
- `search` は、名前と説明から正規表現で探します
:::
:::

:::q 1.04.1-07 single

```text

  Installed: (none)
  Candidate: 2.1.0-1
  Version table:
     2.1.0-1 500
        500 http://deb.debian.org/debian bookworm/main arm64 Packages
```
- [ ] tree の 2.1.0-1 がインストールされている
- [x] tree はインストールされておらず、インストールすると 2.1.0-1 が入る

- [ ] tree は削除されたが設定ファイルが残っている

`Installed: (none)` は「入っていない」、`Candidate:` は「`install` したら入る版」です。`Version table` に、`bookworm/main` のリポジトリにあることが出ています（[調べる](#apt-cache)）。

- 入っていれば `Installed:` に版が出て、`Version table` のその版に `***` が付きます
- リポジトリにあることは `Version table` で分かります
- 設定ファイルだけ残っているかは、`dpkg -l` の `rc` で分かります
:::

:::q 1.04.1-08 single

- [x] `apt-file search /usr/bin/htop`
- [ ] `apt-cache depends htop`

`apt-file search` は、リポジトリにあるすべてのパッケージのファイルの一覧から探します。先に `apt-file update` で一覧を取っておきます（[調べる](#apt-cache)）。

- `dpkg -S` も「ファイル → パッケージ」ですが、**入っているパッケージ**だけが対象です
- `apt-cache search` は、パッケージの名前と説明を探すもので、中のファイル名は探しません
- `apt-cache depends` は、依存するパッケージを出すものです
:::
:::

:::q 1.04.1-09 single

- `clean` は、ダウンロードした `.deb` のキャッシュを消すだけです
- `purge curl` は curl の設定ファイルを消すもので、依存のパッケージは消しません
- `upgrade` は入っているパッケージを新しくするものです
:::
:::

:::q 1.04.1-10 multi

:::q 1.04.1-12 single
`apt` コマンドの説明として誤っているものはどれか。
- [ ] `apt` は、`apt-get` と `apt-cache` のよく使う機能を 1 つのコマンドにまとめたものである

ほかの選択肢はどれも正しい説明です。`apt` は人が打つための入口で、`apt-get` と `apt-cache` の機能をまとめています。
:::

:::q 1.04.1-13 multi
Debian 系のシステムで、インストールされているパッケージの一覧を表示できるコマンドを 2 つ選択してください。

- [ ] `apt-cache depends`

- `apt-cache pkgnames` は、リポジトリの一覧にある**すべての**パッケージの名前を出します。入っているかどうかは関係ありません（Debian 12 では 6 万個を超えました）

- `apt-get` に `list` というサブコマンドはありません
:::
:::

:::q 1.04.1-14 single
`curl` の `.deb` ファイルを `dpkg -i` でインストールしたところ、次のエラーになった。足りない依存パッケージをリポジトリから入れて、この状態を直すコマンドとして最も適切なものはどれか。

- `update` は一覧を取るだけで、パッケージは入れません

### 1.04.2 Debian パッケージ管理

:::q 1.04.2-01 single
`dpkg -l` の出力に次の行があった。このパッケージの状態として正しいものはどれか。

```text
rc  cron           3.0pl1-162   arm64        process scheduling daemon
```
- [ ] インストールされていて、正常に動く状態である
- [x] 削除されたが、設定ファイルが残っている
- [ ] 展開されたが、まだ設定されていない
- [ ] 設定ファイルも含めて完全に削除された
:::why
1 文字目の `r` は「望む状態が remove」、2 文字目の `c` は「いまは設定ファイル（Conf-files）だけ残っている」です。`apt-get remove` や `dpkg -r` の後にこうなります（[dpkg -l の 2 文字を読む](#dpkg-l)）。

- 入っているふつうの状態は `ii` です
- 展開だけされて設定されていないものは `iU` です
- 完全に消したもの（purge の後）は、一覧に出ないか、`un` です
:::
:::

:::q 1.04.2-02 single
インストール済みのファイル `/usr/bin/tree` が、どのパッケージに含まれているかを調べる dpkg のオプションはどれか。
- [ ] `dpkg -L /usr/bin/tree`
- [x] `dpkg -S /usr/bin/tree`
- [ ] `dpkg -s /usr/bin/tree`
- [ ] `dpkg -l /usr/bin/tree`
- [ ] `dpkg -c /usr/bin/tree`
:::why
`-S`（`--search`）は、ファイルからパッケージを探します。出力は `tree: /usr/bin/tree` です（[dpkg](#dpkg)）。

- `-L` は逆で、パッケージ名を渡すと、そのパッケージのファイルを一覧します
- `-s` は、パッケージ名を渡すと状態と詳しい情報を出します
- `-l` は、パッケージの一覧を状態つきで出します
- `-c` は、`.deb` ファイルの中身を一覧します
:::
:::

:::q 1.04.2-03 multi
dpkg の説明として正しいものを 2 つ選択してください。
- [x] `dpkg -i` は、依存するパッケージが入っていないとき、それをリポジトリから取ってくることはしない
- [x] `dpkg -P` でパッケージを削除すると、設定ファイルも削除される
- [ ] `dpkg -r` でパッケージを削除すると、設定ファイルも削除される
- [ ] `dpkg -L` は、インストールしていないパッケージのファイルの一覧も、リポジトリから調べて表示する
- [ ] `dpkg -i` にパッケージ名を渡すと、リポジトリからダウンロードしてインストールする
:::why
dpkg は低レベルの道具で、手元の `.deb` ファイルとデータベースだけを扱います。依存が足りなければエラーで止まります。`-P`（purge）は設定ファイルも消します（[dpkg](#dpkg)）。

- `-r`（remove）は設定ファイルを残します（`dpkg -l` で `rc`）
- `-L` は入っているパッケージだけが対象です。入っていないものは `apt-file list` で調べます
- `-i` に渡すのは `.deb` ファイルです。リポジトリから取ってくるのは apt です
:::
:::

:::q 1.04.2-04 fill
Debian 系のシステムで、インストール済みのパッケージ `tzdata` の設定の質問（タイムゾーンの選択）にもう一度答えて、設定をやり直したい。空欄に入るコマンド名を入力してください。

```text
# ____ tzdata
```
= dpkg-reconfigure
:::why
`dpkg-reconfigure` は、入っているパッケージの設定の質問をもう一度出し、答えに合わせて設定ファイルを書き直します（[dpkg-reconfigure](#dpkg-reconfigure)）。`locales` や `keyboard-configuration` などにも使います。`dpkg --configure` は、展開されて設定されていないパッケージの設定を済ませるもので、質問に答え直すためのものではありません。
:::
:::

:::q 1.04.2-05 single
パッケージのインストールが途中で止まり、展開されたが設定されていないパッケージが残った。それらをすべて設定するコマンドとして正しいものはどれか。
- [ ] `dpkg -s -a`
- [x] `dpkg --configure -a`
- [ ] `dpkg -L -a`
- [ ] `apt-get update`
:::why
`dpkg --configure -a` は、展開されて、まだ設定されていないパッケージ（`-a` は `--pending`）を、すべて設定します（[dpkg](#dpkg)）。

- `-s` は状態を見るだけで、何も設定しません
- `-L` はファイルの一覧を見るだけです
- `apt-get update` は一覧を取るだけで、パッケージの状態は変えません
:::

### 1.04.3 yum コマンドによるパッケージ管理

:::q 1.04.3-01 single
Red Hat 系のシステムで、yum が利用するリポジトリの設定ファイルを置くディレクトリはどれか。
- [ ] `/etc/yum/repos/`
- [x] `/etc/yum.repos.d/`
- [ ] `/etc/apt/sources.list.d/`
- [ ] `/var/cache/yum/`
:::why
`/etc/yum.repos.d/` の下の、名前が `.repo` で終わるファイルに書きます（[リポジトリの設定](#yum-repo)）。

- `/etc/yum/repos/` というディレクトリは使われません
- `/etc/apt/sources.list.d/` は Debian 系の apt のものです
- `/var/cache/yum/` は、ダウンロードしたメタデータとパッケージのキャッシュです
:::
:::

:::q 1.04.3-02 single
`/etc/yum.repos.d/local.repo` が次の内容である。このリポジトリについて正しいものはどれか。

```text
[local]
name=Local Repository
baseurl=file:///srv/repo/
enabled=0
gpgcheck=1
```
- [ ] 署名を確かめずにパッケージを入れる
- [x] ふだんは使われず、`yum repolist` に表示されない
- [ ] パッケージを `http://` で取ってくる
- [ ] リポジトリの ID は `Local Repository` である
:::why
`enabled=0` なので、このリポジトリは無効です。`yum repolist` には出ず、`yum repolist all` で `disabled` と出ます。その時だけ使うなら `--enablerepo=local` を付けます（[リポジトリの設定](#yum-repo)）。

- `gpgcheck=1` なので、署名を確かめます
- `baseurl` は `file:///` で、手元のディレクトリです
- ID は `[ ]` の中の `local` です。`Local Repository` は `name` で、人が読むための名前です
:::
:::

:::q 1.04.3-03 fill
次の `.repo` ファイルの空欄には、リポジトリのパッケージがある場所の URL を指定するキーが入る。空欄に入るキーを入力してください。

```text
[myrepo]
name=My Repository
____=http://repo.example.com/el9/x86_64/
enabled=1
gpgcheck=0
```

:::why
`baseurl` です（[リポジトリの設定](#yum-repo)）。1 語で、`base_url` や `baseURL` ではありません。URL の代わりにミラーの一覧を返す URL を書くときは、`mirrorlist` や `metalink` を使います。
:::
:::

:::q 1.04.3-04 single
`.repo` ファイルの `gpgcheck=1` の意味として正しいものはどれか。
- [ ] リポジトリのメタデータを 1 時間ごとに取り直す
- [x] パッケージの GPG 署名を確かめてから入れる
- [ ] GPG 公開鍵を 1 つだけ使う
- [ ] リポジトリとの通信を暗号化する
:::why
`gpgcheck=1` は、入れるパッケージの GPG 署名を確かめます。確かめる鍵は `gpgkey=` で指定し、`rpm --import` で取り込むこともできます（[リポジトリの設定](#yum-repo)、[rpm -V と --import](#rpm-verify)）。`0` なら確かめません。

- メタデータを取り直す間隔は `metadata_expire` などで決めます
- 鍵の数を決める設定ではありません
- 通信の暗号化は、`baseurl` を `https://` にするかどうかの話です
:::
:::

:::q 1.04.3-05 single
Red Hat 系のシステムで、まだインストールしていない `/usr/bin/tmux` というファイルが、リポジトリのどのパッケージに含まれているかを調べたい。使うコマンドとして最も適切なものはどれか。
- [ ] `yum search /usr/bin/tmux`
- [ ] `yum info /usr/bin/tmux`
- [x] `yum provides /usr/bin/tmux`
- [ ] `rpm -qf /usr/bin/tmux`
:::why
`yum provides`（`whatprovides`）は、リポジトリにあるパッケージのファイルからも探します（[yum のサブコマンド](#yum-cmd)）。

- `yum search` は、パッケージの名前と要約から探します。ファイルのパスでは探しません
- `yum info` は、パッケージ名を渡して詳しい情報を見るものです
- `rpm -qf` は「ファイル → パッケージ」ですが、**入っているパッケージ**だけが対象です
:::
:::

:::q 1.04.3-06 multi
Red Hat 系のシステムで、ファイル `/usr/bin/tree` を提供するパッケージを、リポジトリから探すことができるコマンドを 2 つ選択してください。
- [x] `yum provides /usr/bin/tree`
- [x] `yum whatprovides /usr/bin/tree`
- [ ] `yum search /usr/bin/tree`
- [ ] `yum list /usr/bin/tree`
- [ ] `yum repolist /usr/bin/tree`
:::why
`provides` と `whatprovides` は同じサブコマンドの 2 つの名前です。出力には、パッケージとリポジトリ（`Repo : baseos`）と、合ったファイル名が出ます（[yum のサブコマンド](#yum-cmd)）。

- `search` は名前と要約から探すもので、ファイルのパスは探しません
- `list` はパッケージ名（やパターン）で一覧するものです
- `repolist` はリポジトリの一覧を出すものです
:::
:::

:::q 1.04.3-07 single
Red Hat 系のシステムで、コンパイラなどの開発用パッケージの組み合わせ「Development Tools」を、まとめてインストールしたい。正しいコマンドはどれか。

- [x] `yum groupinstall "Development Tools"`
- [ ] `yum grouplist "Development Tools"`
- [ ] `yum update "Development Tools"`
:::why
グループは `groupinstall`（`group install`）で入れます。名前に空白があるので、引用符で囲みます（[yum のサブコマンド](#yum-cmd)）。

- 引用符なしの `install Development Tools` は、`Development` と `Tools` という 2 つのパッケージを探してしまいます
- `grouplist` は、グループの一覧を見るだけです
- `update` は、入っているパッケージを新しくするものです
:::
:::

:::q 1.04.3-08 single
yum で、現在有効になっているリポジトリの一覧を表示するコマンドはどれか。
- [ ] `yum list`
- [x] `yum repolist`
- [ ] `yum info repos`
- [ ] `yum check-update`
:::why
`yum repolist` は、有効なリポジトリの `repo id` と `repo name` を一覧します。`yum repolist all` で、無効なもの（`disabled`）も出ます（[yum のサブコマンド](#yum-cmd)）。

- `yum list` は、パッケージの一覧です
- `yum info` は、パッケージの詳しい情報を見るもので、`repos` という名前のパッケージを探すだけです
- `yum check-update` は、更新できるパッケージを一覧します
:::
:::

:::q 1.04.3-09 fill
yum がダウンロードして保存したリポジトリのメタデータとパッケージのキャッシュを、すべて削除したい。空欄に入るものを入力してください。

```text
# yum clean ____
```
= all
:::why
`yum clean all` は、キャッシュ（`/var/cache/yum/`、dnf では `/var/cache/dnf/`）にあるメタデータとパッケージをすべて消します（[yum のサブコマンド](#yum-cmd)）。リポジトリの設定を変えたのに古い情報が使われるときなどに使います。dnf でも `dnf clean all` です。
:::
:::

:::q 1.04.3-10 single
`yumdownloader tree` の動作として正しいものはどれか。
- [ ] `tree` をリポジトリからダウンロードしてインストールする
- [x] `tree` の `.rpm` ファイルをリポジトリからダウンロードするが、インストールはしない
- [ ] `tree` のソースコードをダウンロードしてビルドする
- [ ] `tree` を含むリポジトリの `.repo` ファイルをダウンロードする
:::why
`yumdownloader` は、`.rpm` をいまのディレクトリにダウンロードするだけです。`yum-utils` パッケージに入っています（[yumdownloader](#yumdownloader)）。

- 入れるのは `yum install` です
- ソースの `.src.rpm` を取るには `--source` を付けますが、ビルドはしません
- `.repo` ファイルを取るものではありません
:::
:::

:::q 1.04.3-11 single
`yumdownloader` で、指定したパッケージに加えて、そのパッケージが依存するパッケージもダウンロードするオプションはどれか。
- [ ] `--destdir`
- [x] `--resolve`
- [ ] `--source`
- [ ] `--nodeps`
:::why
`--resolve` で、依存を解決して必要なパッケージも一緒にダウンロードします（[yumdownloader](#yumdownloader)）。

- `--destdir` は、保存するディレクトリを指定します
- `--source` は、ソースの `.src.rpm` をダウンロードします
- `--nodeps` は rpm のオプションで、依存を確かめずに入れる・消すものです
:::
:::

:::q 1.04.3-12 multi
yum と dnf の説明として正しいものを 2 つ選択してください。
- [x] dnf は yum の後継で、RHEL 8 以降の系統では `yum` コマンドを実行すると dnf が動く
- [x] dnf にも `install`、`remove`、`search`、`provides` などのサブコマンドがある
- [ ] dnf は `.deb` 形式のパッケージを扱う
- [ ] dnf は rpm のデータベースを使わず、独自のデータベースだけで管理する
- [ ] dnf は `/etc/yum.repos.d/` の設定を読まない
:::why
RHEL 8 以降の系統では、`/usr/bin/yum` は dnf へのリンクです（Rocky Linux 9 では、どちらも `dnf-3` を指していました）。サブコマンドもほぼ同じです（[yum と dnf](#yum)）。

- dnf が扱うのは `.rpm` です。`.deb` は Debian 系です
- dnf は rpm のしくみでパッケージを入れ、rpm のデータベースに記録します。だから `rpm -qa` に出ます
- dnf も `/etc/yum.repos.d/*.repo` を読みます
:::
:::

:::q 1.04.3-13 single
yum 全体の動作の設定（すべてのリポジトリに効く既定値）を `[main]` の節に書くファイルはどれか。
- [x] `/etc/yum.conf`
- [ ] `/etc/yum.repos.d/main.repo`
- [ ] `/etc/apt/apt.conf`
- [ ] `/etc/sysconfig/yum`
:::why
`/etc/yum.conf` の `[main]` に、`gpgcheck` や `installonly_limit` などの全体の設定を書きます。RHEL 8 以降では `/etc/dnf/dnf.conf` へのリンクです（[リポジトリの設定](#yum-repo)）。

- `/etc/yum.repos.d/` の `.repo` は、リポジトリごとの設定を書く場所です。`main.repo` という決まったファイルはありません
- `/etc/apt/apt.conf` は Debian 系の apt の設定です
- `/etc/sysconfig/yum` という設定ファイルは使われません
:::
:::

:::q 1.04.3-14 multi
Red Hat 系のシステムで、新しい版があるパッケージを一覧するが、更新はしないコマンドを 2 つ選択してください。
- [x] `yum check-update`
- [x] `yum list updates`
- [ ] `yum update`
- [ ] `yum upgrade`
- [ ] `yum clean all`
:::why
`check-update` と `list updates` は、更新できるパッケージを表示するだけです（[yum のサブコマンド](#yum-cmd)）。

- `yum update` と `yum upgrade` は、実際にパッケージを新しくします（名前を付けなければすべて）。apt の `update` とは意味が違うので注意します
- `yum clean all` はキャッシュを消すものです
:::
:::

:::q 1.04.3-15 single
`yum list tree` を実行したところ、次のように表示された。この出力から分かることとして正しいものはどれか。

```text
Installed Packages
tree.aarch64                        1.8.0-10.el9                         @baseos
```
- [ ] tree はまだインストールされておらず、baseos リポジトリから入れられる
- [x] tree はインストールされていて、baseos リポジトリから入れたものである
- [ ] tree には新しい版があり、baseos リポジトリから更新できる
- [ ] tree は baseos という名前のグループに属している
:::why
`Installed Packages` の下にあり、リポジトリ名に `@` が付いているので、「入っていて、baseos から入れたもの」です（[yum のサブコマンド](#yum-cmd)）。

- 入っていないときは `Available Packages` の下に、`@` なしの `baseos` と出ます
- 更新できる版は `yum list updates` や `yum check-update` で見ます
- グループの一覧は `yum grouplist` で見るもので、この欄はリポジトリです

### 1.04.4 RPM パッケージ管理

:::q 1.04.4-01 single
rpm のオプションで、指定したパッケージの古い版がインストールされている場合だけ新しい版に更新し、インストールされていない場合は何もしないものはどれか。
- [ ] `-i`
- [ ] `-U`
- [x] `-F`
- [ ] `-e`
:::why
`-F`（`--freshen`）は「入っていれば新しくする」です。入っていなければ何もしません（[rpm：入れる、新しくする、消す](#rpm-install)）。

- `-i` は入れるもので、同じものが入っているとエラーになります
- `-U`（`--upgrade`）も新しくしますが、**入っていなければ入れます**
- `-e` は消すものです
:::
:::

:::q 1.04.4-02 single
次のコマンドの実行結果として表示されるものはどれか。

```text
$ rpm -qf /usr/bin/bash
```
- [ ] `/usr/bin/bash` の大きさや権限などの情報
- [x] `/usr/bin/bash` を含むインストール済みのパッケージの名前と版
- [ ] bash パッケージに含まれるファイルの一覧
- [ ] bash パッケージが依存するパッケージの一覧
:::why
`-qf` は「ファイル → パッケージ」です。出力は `bash-5.1.8-6.el9_1.aarch64` のような、パッケージの名前と版です（[rpm -q](#rpm-query)）。

- ファイルの大きさや権限は `ls -l` や `stat` で見ます
- ファイルの一覧は `rpm -ql bash` です
- 依存するものは `rpm -qR bash` です
:::
:::

:::q 1.04.4-03 multi
まだインストールしていないパッケージファイル `tree-1.8.0-10.el9.x86_64.rpm` の情報を調べるコマンドを 2 つ選択してください。
- [x] `rpm -qpi tree-1.8.0-10.el9.x86_64.rpm`
- [x] `rpm -qpl tree-1.8.0-10.el9.x86_64.rpm`
- [ ] `rpm -qi tree-1.8.0-10.el9.x86_64.rpm`
- [ ] `rpm -qf tree-1.8.0-10.el9.x86_64.rpm`
- [ ] `rpm -qa tree-1.8.0-10.el9.x86_64.rpm`
:::why
手元の `.rpm` ファイルを調べるには `-p` を付けます。`-qpi` は詳しい情報、`-qpl` は中のファイルの一覧です（[rpm -q](#rpm-query)）。

- `-p` のない `-qi` は、引数をパッケージ名として、入っているパッケージのデータベースを探します。入っていないので見つかりません
- `-qf` は、入っているファイルからパッケージを探すものです
- `-qa` は、入っているパッケージをすべて一覧するもので、ファイルの中は見ません
:::
:::

:::q 1.04.4-04 fill
インストール済みのパッケージ `tree` のファイルを検査したところ、次のように表示された。空欄に入るオプションを入力してください。

```text
# rpm ____ tree
missing     /usr/bin/tree
S.5....T.  d /usr/share/doc/tree/README
```
= -V
= --verify
:::why
`-V`（`--verify`）は、入れたときの記録といまのファイルを比べて、変わったものを表示します。`missing` はファイルがない、`S` は大きさ、`5` は中身、`T` は更新時刻が違う、`d` は文書ファイルという意味です（[rpm -V と --import](#rpm-verify)）。何も変わっていなければ、何も表示しません。
:::
:::

:::q 1.04.4-05 single
`rpm --import /etc/pki/rpm-gpg/RPM-GPG-KEY-Rocky-9` の説明として正しいものはどれか。
- [ ] 指定したファイルを含むパッケージをインストールする
- [x] パッケージの署名を確かめるための GPG 公開鍵を rpm のデータベースに取り込む
- [ ] リポジトリの設定を `/etc/yum.repos.d/` に追加する
- [ ] インストール済みのパッケージの署名をすべて取り消す
:::why
`--import` は GPG 公開鍵を取り込みます。取り込んだ鍵は `rpm -q gpg-pubkey` で `gpg-pubkey-…` として見えます。この鍵で、`gpgcheck=1` のときにパッケージの署名を確かめます（[rpm -V と --import](#rpm-verify)）。

- パッケージを入れるのは `-i` や `-U` です
- リポジトリの設定は `.repo` ファイルを書いて追加します
- 署名を取り消す機能ではありません
:::
:::
