## 時計は 2 つある：システムクロックとハードウェアクロック {#clock}

Linux の機械には、時計が 2 つあります。

- **ハードウェアクロック**（RTC、リアルタイムクロック）：マザーボードの上の時計です。電池で動くので、電源を切っても進みます
- **システムクロック**：カーネルが数えている時計です。プログラムが時刻を聞くと、こちらが答えます。電源を切ると消えます

起動するとき、カーネルはハードウェアクロックを読んで、システムクロックの初めの値にします。そのあとは 2 つが別々に進むので、少しずつずれます。ずれを NTP（後の節）で直すのは、システムクロックのほうです。

### date：システムクロックを読む・変える

**`date`** はシステムクロックを表示します。`+` で始まる引数を与えると、その書式で表示します。小さな Linux で試します（この機械の時計は、いつも 2026 年 4 月 1 日の 9 時から始まります）。

```sh run title="date の書式"
date
date -u
date +%Y-%m-%d
date "+%Y/%m/%d %H:%M:%S"
```

`-u` は UTC（協定世界時）で表示します。日本の時刻（JST）は UTC より 9 時間進んでいます。書式に空白を含めるときは、引数全体を引用符で囲みます。

```sh run title="いまではない時刻を表示する"
date +%s
date -d @0
date -d "2024-01-01" +%A
```

`%s` は 1970 年 1 月 1 日 0 時（UTC）からの秒数です。`-d` は「いま」の代わりに指定した時刻を表示します。`@0` は「秒数 0 の時刻」です。

| 書式 | 意味 | 例 |
| --- | --- | --- |
| `%Y` / `%y` | 年（4 桁 / 下 2 桁） | 2026 / 26 |
| `%m` / `%d` | 月 / 日（2 桁） | 04 / 01 |
| `%H` / `%M` / `%S` | 時（00〜23）/ 分 / 秒 | 09 / 00 / 00 |
| `%a` / `%A` | 曜日（短い / 長い） | Wed / Wednesday |
| `%F` / `%T` | `%Y-%m-%d` / `%H:%M:%S` | 2026-04-01 / 09:00:00 |
| `%Z` / `%z` | タイムゾーンの略称 / 時差 | JST / +0900 |
| `%s` | 1970-01-01 00:00 UTC からの秒数 | 1775001600 |
| `%j` | 1 年の何日目か | 091 |

時刻を**変える**には root が必要です。書き方は 2 つあります。

```console
# date -s "2026-04-01 09:00:00"
# date 040109002026
```

2 つめは `MMDDhhmm[[CC]YY][.ss]` の形です。月・日・時・分の順で、年は最後です。`date 040109002026` は「4 月 1 日 9 時 0 分、2026 年」です。

:::warn 試験の注意：date の数字の並び
`date` に直接与える数字は**月日時分年**の順（`MMDDhhmmYYYY`）で、年が最後です。`YYYYMMDDhhmm` と思い込むと間違えます。表示の書式（`+%Y%m%d`）とは別物です。
:::

### hwclock：ハードウェアクロックを読む・書く

**`hwclock`** はハードウェアクロックを扱います（root で実行します）。

| オプション | 長い形 | すること |
| --- | --- | --- |
| `-r` | `--show` | ハードウェアクロックを表示する（何も付けないときと同じ） |
| `-w` | `--systohc` | システムクロック → ハードウェアクロック（**sys to hc**） |
| `-s` | `--hctosys` | ハードウェアクロック → システムクロック（**hc to sys**） |
| `-u` / `-l` | `--utc` / `--localtime` | ハードウェアクロックを UTC / 地方時として扱う |

長い形は「どちらからどちらへ」を名前で表しています。ハードウェアクロックのずれの記録などは `/etc/adjtime` に書かれます。`systohc` は system to hardware clock です。`date` で時刻を直したあと、`hwclock -w` で書き込んでおくと、次の起動でも正しい時刻から始まります。

:::warn 試験の注意：-w と -s の向き
「システムクロックをハードウェアクロックに合わせる」は `-s`（hctosys）、「ハードウェアクロックをシステムクロックに合わせる」は `-w`（systohc）です。「〜に合わせる」の「〜」が**写す元**です。迷ったら長い形を思い出してください。
:::

## タイムゾーンと NTP：正しい時刻に合わせ続ける {#ntp}

### タイムゾーン

システムクロックは、カーネルの中では UTC で数えています。それを「日本時間」で表示するのは、**タイムゾーン**の設定です。タイムゾーンの情報は、`/usr/share/zoneinfo/` の下に地域ごとのファイルとして入っています（`Asia/Tokyo`、`America/New_York`、`UTC` …）。

| 場所 | 役目 |
| --- | --- |
| `/usr/share/zoneinfo/` | タイムゾーンのデータ（地域ごとのバイナリのファイル） |
| `/etc/localtime` | **システムのタイムゾーン**。zoneinfo のファイルへのシンボリックリンク（またはコピー） |
| `/etc/timezone` | Debian 系にある、タイムゾーンの名前を書いたテキスト（例：`Etc/UTC`）。Red Hat 系にはない |
| 環境変数 `TZ` | そのプロセス（とその子）だけのタイムゾーン。`/etc/localtime` より優先する |

Docker の debian:12 と rockylinux:9 で確かめた形です。

```console
$ ls -l /etc/localtime                       # debian:12
lrwxrwxrwx 1 root root 27 Nov  4 21:23 /etc/localtime -> /usr/share/zoneinfo/Etc/UTC
$ cat /etc/timezone
Etc/UTC
$ ls -l /etc/localtime                       # rockylinux:9
lrwxrwxrwx 1 root root 25 Nov 19  2023 /etc/localtime -> ../usr/share/zoneinfo/UTC
$ ls -l /etc/timezone
ls: cannot access '/etc/timezone': No such file or directory
```

`/etc/localtime` はシンボリックリンクです（[図解 Linux 11.4](../../linux/site/ch11.html#symlink)）。システムのタイムゾーンを日本にするには、リンクを張り替えます。`TZ` を使えば、そのコマンドだけ別のタイムゾーンで表示できます。

```console
# ln -sf /usr/share/zoneinfo/Asia/Tokyo /etc/localtime
```

`TZ` を付けたコマンドは、システムの設定（ここでは UTC のまま）とは別のタイムゾーンで表示します。debian:12 での結果です。

```console
$ date
Mon Nov 16 11:16:42 UTC 2026
$ TZ=Asia/Tokyo date
Mon Nov 16 20:16:42 JST 2026
$ TZ=America/New_York date
Mon Nov 16 06:16:42 EST 2026
```

**`tzselect`** は、大陸と国を番号で選ばせて、それに当たる `TZ` の値を表示するだけのコマンドです。**システムの設定は変えません**。表示された値を `~/.profile` に `TZ='Asia/Tokyo'; export TZ` と書くのは、利用者の仕事です。

```console
$ tzselect
Please select a continent, ocean, "coord", or "TZ".
 …
 4) Asia
 …
#? 4
 …
24) Japan
#? 24
 …
Therefore TZ='Asia/Tokyo' will be used.
 …
Asia/Tokyo
```

### timedatectl：systemd の時刻の窓口

systemd の機械では、**`timedatectl`** が時刻とタイムゾーンをまとめて扱います。

```console
$ timedatectl
               Local time: Mon 2026-11-16 20:19:52 JST
           Universal time: Mon 2026-11-16 11:19:52 UTC
                 RTC time: Mon 2026-11-16 11:19:52
                Time zone: Asia/Tokyo (JST, +0900)
System clock synchronized: yes
              NTP service: active
          RTC in local TZ: no
```

1 回でシステムクロック（Local / Universal time）、ハードウェアクロック（RTC time）、タイムゾーン、NTP で合っているかが見えます。

| コマンド | すること |
| --- | --- |
| `timedatectl`（`status`） | 状態を表示する |
| `timedatectl set-timezone Asia/Tokyo` | タイムゾーンを変える（`/etc/localtime` を張り替える） |
| `timedatectl list-timezones` | 選べるタイムゾーンの一覧 |
| `timedatectl set-time "2026-04-01 09:00:00"` | 時刻を変える（NTP が有効だと拒まれる） |
| `timedatectl set-ntp true` | NTP による同期を有効にする |

### NTP：ネットワークで時刻を合わせる

```fig tree NTP は階層（stratum）になっている。数字が小さいほど基準の時計に近い
{
  root: { label: 'stratum 0', note: '原子時計・GPS（ネットワークにはつながらない）', kind: 'accent', children: [
    { label: 'stratum 1', note: '基準の時計に直接つながったサーバ', children: [
      { label: 'stratum 2', note: 'stratum 1 から時刻をもらう', children: [
        { label: 'stratum 3', note: '社内のサーバ、あなたの機械 …' },
      ] },
      { label: 'stratum 2', note: 'pool.ntp.org の多くのサーバ' },
    ] },
  ] },
}
```

**NTP**（Network Time Protocol）は、ネットワーク越しに時刻を合わせる決まりです。**UDP の 123 番**ポートを使います。サーバは階層になっていて、その段を **stratum**（ストラタム）と呼びます。数字が小さいほど、原子時計などの基準に近くなります。

**pool.ntp.org** は、世界中のボランティアが提供する多数の NTP サーバをまとめた名前です。引くたびに違うサーバの番地が返ります。`2.debian.pool.ntp.org` や `2.rocky.pool.ntp.org` のように、ディストリビューションごとの名前もあります。

NTP を話すプログラムは、主に 3 つです。

| プログラム | 形 | 設定ファイル | 状態を見る |
| --- | --- | --- | --- |
| **chronyd** | デーモン。いまの Red Hat 系・Debian 系の標準 | Red Hat 系 `/etc/chrony.conf`、Debian 系 `/etc/chrony/chrony.conf` | `chronyc sources`、`chronyc tracking` |
| **ntpd** | デーモン。古くからの実装 | `/etc/ntp.conf`（ntpsec では `/etc/ntpsec/ntp.conf`） | `ntpq -p` |
| **ntpdate** | 1 回だけ合わせて終わるコマンド | なし（`ntpdate サーバ` と引数で） | — |

デーモン（chronyd、ntpd）は、時刻を**少しずつ**速めたり遅めたりして合わせ続けます。時刻が急に飛ぶと、ログの順番や cron が乱れるからです。ntpdate は、その場で**一気に**合わせます。

rockylinux:9 に chrony を入れたときの `/etc/chrony.conf` の設定の行です（コメントを除く）。

```conf
pool 2.rocky.pool.ntp.org iburst
sourcedir /run/chrony-dhcp
driftfile /var/lib/chrony/drift
makestep 1.0 3
rtcsync
keyfile /etc/chrony.keys
ntsdumpdir /var/lib/chrony
leapsectz right/UTC
logdir /var/log/chrony
```

| 行 | 意味 |
| --- | --- |
| `pool 名前 iburst` | 複数のサーバを返す名前を、時刻の元にする（1 台なら `server 名前`）。`iburst` は起動直後に速く合わせる |
| `driftfile` | 時計の進み・遅れの癖を覚えておくファイル |
| `makestep 1.0 3` | 最初の 3 回の更新では、1 秒以上ずれていたら一気に合わせる |
| `rtcsync` | ハードウェアクロックもときどき合わせる |

ntpd の `ntp.conf` も、`server` / `pool` の行で相手を書く形は同じです。

`chronyc sources` と `ntpq -p` は、どちらも「どのサーバを使っているか」の一覧です。Docker の debian:12 で動かした出力です。

```console
$ chronyc sources
MS Name/IP address         Stratum Poll Reach LastRx Last sample
===============================================================================
^- ntp-jp.vulp.ca                2   6    17    13   +466us[ +466us] +/- 6235us
^* 44.30.62.51                   2   6    17    14   -548us[-1708us] +/- 7769us
^- pred-374.chl.la               3   6    17    15   +320us[ +320us] +/- 6505us
$ ntpq -p
     remote           refid      st t when poll reach   delay   offset   jitter
===============================================================================
-time.cloudflare 10.192.8.136     3 u   13   64    1  10.2636   9.8735   0.6945
+45.66.166.63    133.243.238.164  2 u   13   64    1  11.4333  10.9274   0.8085
*ntp-jp.vulp.ca  133.243.238.243  2 u   12   64    1   8.7066  11.2981   0.7690
```

どちらも、行の頭の **`*` がいま同期に使っているサーバ**です。`+` は候補として合わせて使っているもの、`-` は外したものです。`chronyc tracking` は、システムクロックがどれだけずれているか（`System time : 0.011283040 seconds slow of NTP time` のような行）を表示します。

:::note chronyd と ntpd を同時に動かさない
どちらも同じポート 123 を使い、どちらもシステムクロックを動かそうとします。1 台の機械では、どちらか 1 つだけを動かします。ntpdate も、デーモンが動いている間は使いません。
:::

| 覚えること | 内容 |
| --- | --- |
| NTP のポート | UDP 123 |
| stratum | 小さいほど基準に近い。stratum 1 は基準の時計に直接つながる |
| 同期中の印 | `chronyc sources`、`ntpq -p` の行頭の `*` |
| 1 回だけ合わせる | `ntpdate サーバ`（または `chronyc makestep`） |
| タイムゾーンの選び方を表示するだけ | `tzselect` |

## rsyslog：facility.priority で振り分ける {#rsyslog}

```fig graph ログを書きたいプログラムは /dev/log に送る。rsyslogd が設定の行と照らし、行き先のファイルに書く

  ],
  edges: [
    { from: 'app', to: 'r', label: '/dev/log' },

```

Linux のログには、2 つの仕組みがあります。昔からの **syslog**（いまの実装は **rsyslog**）と、systemd の **journald**（次の節）です。多くのディストリビューションは、両方を動かしています。journald が集めたものを rsyslogd が受け取り、テキストのファイルに書きます。

ログを書きたいプログラムは、「**どこから来たか**（facility）」と「**どれくらい重大か**（priority）」の 2 つの印を付けて、メッセージを送ります。rsyslogd は、設定ファイル **`/etc/rsyslog.conf`**（と `/etc/rsyslog.d/*.conf`）の行と照らして、行き先を決めます。

### 設定の書式

1 行が 1 つの規則です。

```text
facility.priority        出力先
```

左の `facility.priority` を **セレクタ**、右を **アクション**と呼びます。Docker の debian:12 の `/etc/rsyslog.conf` にある規則の行です。

```conf
*.*;auth,authpriv.none		-/var/log/syslog
auth,authpriv.*			/var/log/auth.log
cron.*				-/var/log/cron.log
kern.*				-/var/log/kern.log
mail.*				-/var/log/mail.log
user.*				-/var/log/user.log
*.emerg				:omusrmsg:*
```

小さな Linux にも、同じ規則を置いておきました（rsyslogd は動いていないので、ファイルを読むだけです）。

```sh setup root
cat > /etc/rsyslog.conf <<'EOT'
# /etc/rsyslog.conf（debian:12 の規則の部分）
module(load="imuxsock") # provides support for local system logging
module(load="imklog")   # provides kernel logging support
$IncludeConfig /etc/rsyslog.d/*.conf

*.*;auth,authpriv.none		-/var/log/syslog
auth,authpriv.*			/var/log/auth.log
cron.*				-/var/log/cron.log
kern.*				-/var/log/kern.log
mail.*				-/var/log/mail.log
user.*				-/var/log/user.log
*.emerg				:omusrmsg:*
EOT
```

```sh run title="規則の行だけを取り出す"
grep -v '^#' /etc/rsyslog.conf | grep -v '^$' | grep -v '^module' | grep -v '^\$'
grep 'mail' /etc/rsyslog.conf
```

### facility と priority

| facility | 何のログか |
| --- | --- |
| `auth` / `authpriv` | 認証（ログイン、su、sudo）。`authpriv` は秘密を含むもの |
| `cron` | cron と at |
| `daemon` | ほかのデーモン |
| `kern` | カーネル |
| `mail` | メール |
| `user` | 一般のプログラム（`logger` の既定） |
| `lpr`、`news`、`uucp`、`syslog` | 印刷、ニュース、UUCP、rsyslogd 自身 |
| `local0`〜`local7` | 利用者が自由に使ってよい |

priority は 8 段階です。上ほど重大で、番号が小さくなります。

| 番号 | priority | 意味 |
| --- | --- | --- |
| 0 | `emerg`（`panic`） | システムが使えない |
| 1 | `alert` | すぐ対処が必要 |
| 2 | `crit` | 致命的 |
| 3 | `err`（`error`） | エラー |
| 4 | `warning`（`warn`） | 警告 |
| 5 | `notice` | 通常だが重要 |
| 6 | `info` | 情報 |
| 7 | `debug` | デバッグ |

覚え方は頭文字で「**e a c e w n i d**」です。

### セレクタの記号

priority を 1 つ書くと、**その priority 以上（より重大なもの）すべて**を意味します。

| 書き方 | 選ぶもの |
| --- | --- |
| `mail.err` | mail の err・crit・alert・emerg（err **以上**） |
| `mail.=err` | mail の err **だけ** |
| `mail.*` | mail のすべての priority |
| `mail.none` | mail は 1 つも選ばない（ほかの指定から除く） |
| `mail.*;mail.!err` | mail のうち、err 以上を除いたもの（`!` は除く） |
| `auth,authpriv.*` | `,` で facility を並べる |
| `*.info;mail.none` | `;` で条件を続ける。全 facility の info 以上から、mail を除く |

Docker の debian:12 で、`local0` の規則を置いて `logger` で送り、どのファイルに入るかを確かめました。

```console
# cat /etc/rsyslog.d/50-test.conf
local0.*                 /var/log/l0-all.log
local0.err               /var/log/l0-err.log
local0.=info             /var/log/l0-eqinfo.log

```

`local0.err` には err と、より重大な crit が入りました。`local0.=info` には info だけです。

### 出力先

| 書き方 | 行き先 |
| --- | --- |
| `/var/log/ファイル` | ファイル |
| `-/var/log/ファイル` | ファイル。`-` は書くたびにディスクへ同期しない（速い） |
| `@ホスト` | ほかの機械の rsyslog へ **UDP**（514 番）で転送 |
| `@@ホスト` | ほかの機械の rsyslog へ **TCP** で転送 |
| `*` または `:omusrmsg:*` | ログインしている全員の端末に表示 |
| `ユーザー名` | そのユーザーがログインしていれば、端末に表示 |

Red Hat 系の `/etc/rsyslog.conf` は、新しい書き方（`action(type="omfile" file="…")`）で書かれていますが、セレクタは同じです。rockylinux:9 の規則です。

```conf
*.info;mail.none;authpriv.none;cron.none action(type="omfile" file="/var/log/messages")
authpriv.* action(type="omfile" file="/var/log/secure")
mail.* action(type="omfile" file="/var/log/maillog" sync="on")
cron.* action(type="omfile" file="/var/log/cron")
*.emerg action(type="omusrmsg" users="*")
```

:::warn 試験の注意：「以上」と「だけ」、@ と @@
`mail.err` は err **以上**、`mail.=err` は err **だけ**です。`none` はその facility を除きます。転送は `@` が UDP、`@@` が TCP です。
:::

### /var/log の主なファイル

| Debian 系 | Red Hat 系 | 中身 |
| --- | --- | --- |
| `/var/log/syslog` | `/var/log/messages` | ほぼすべての一般のログ |
| `/var/log/auth.log` | `/var/log/secure` | 認証（ログイン、sudo、sshd） |
| `/var/log/mail.log` | `/var/log/maillog` | メール |
| `/var/log/kern.log` | — | カーネル |
| `/var/log/cron.log` | `/var/log/cron` | cron |
| `/var/log/wtmp`、`/var/log/btmp`、`/var/log/lastlog` | 同じ | ログインの記録（バイナリ。`last`、`lastb`、`lastlog` で読む） |
| `/var/log/journal/` | 同じ | journald の保存先（次の節） |

小さな Linux の `/var/log` にも、Debian 系の形のファイルがあります。syslog と auth.log は、root か adm グループの人しか読めません。

```sh run root title="/var/log を見る"
ls -l /var/log
grep kernel /var/log/syslog
```

### logger：シェルからログを書く

**`logger`** は、引数の文字をログに送るコマンドです。シェルスクリプトから記録を残すのに使います。

```console
$ logger "backup finished"
$ logger -p local0.err -t backup "disk is full"
$ tail -2 /var/log/syslog
2026-11-16T02:19:52.657863+00:00 host root: backup finished
2026-11-16T02:19:52.658390+00:00 host backup: disk is full
```

| オプション | 意味 |
| --- | --- |
| `-p facility.priority` | 印を付ける。付けなければ **`user.notice`** |
| `-t タグ` | 行に付く名前（既定はユーザー名） |
| `-i` | logger の PID を付ける |
| `-f ファイル` | ファイルの中身を送る |

[図解 Linux 17.7](../../linux/site/ch17.html#journal) で見たとおり、systemd のもとでは、サービスの標準出力と標準エラーは journald に集まり、**ジャーナル**として保存されます。ジャーナルはバイナリ形式なので、`cat` ではなく **`journalctl`** で読みます。

小さな Linux でサービスを 1 つ作り、ログを残させます。標準出力に 1 行、標準エラーに 1 行書いて、眠り続けるだけのサービスです。

```sh run root title="ログを書くサービスを作って起こす"
cat > /usr/local/bin/tick <<'EOT'
#!/bin/sh
echo "tick started"
echo "disk almost full" >&2
sleep 1000
EOT
chmod +x /usr/local/bin/tick
cat > /etc/systemd/system/tick.service <<'EOT'
[Unit]
Description=Tick

[Service]
ExecStart=/usr/local/bin/tick
EOT
systemctl daemon-reload
systemctl start tick
sleep 2
```

```sh run root title="unit で絞る・新しい順・行数"
journalctl -u tick
journalctl -u tick -r
journalctl -u tick -n 1
```

`-u` で unit を選び、`-r` で新しい順に、`-n 1` で最後の 1 件だけにしました。次は、失敗するサービスを起こして、priority で絞ります。

```sh run root title="priority で絞る"
cat > /etc/systemd/system/bad.service <<'EOT'
[Service]
ExecStart=/bin/false
EOT
systemctl daemon-reload
systemctl start bad
sleep 1
journalctl -u bad
journalctl -p warning
```

`-p warning` は、warning **以上**（warning・err・crit・alert・emerg）を表示します。rsyslog のセレクタと同じ考え方です。`-p 4` のように番号でも書けます。

```sh run root title="カーネルのログと、今回の起動"
journalctl -k -n 3
journalctl -b -n 2
```

| オプション | 意味 |
| --- | --- |
| `-u unit` | その unit のログ |
| `-f` | 新しい行を待って出し続ける（`tail -f` と同じ） |
| `-b` | 今回の起動から。`-b -1` は 1 つ前の起動 |
| `-p priority` | その priority **以上**。`-p err`、`-p 3` |
| `-n 数` | 最後の N 件（数を省くと 10 件） |
| `-r` | 新しい順に表示する |
| `-k` | カーネルのログだけ（`dmesg` と同じもの） |
| `--since` / `--until` | 時刻で絞る。`--since "2026-11-01 09:00"`、`--since today`、`--since "10 min ago"` |
| `-t 名前` | logger の `-t` などで付けた名前で絞る |
| `-o 形` | 表示の形。`-o cat`（本文だけ）、`-o json`、`-o short-iso` |
| `--list-boots`、`--disk-usage` | 起動の一覧、ジャーナルの大きさ |

本物の systemd（Docker の debian:12 で systemd を PID 1 として動かしたもの）では、`logger` で送ったものもジャーナルに入ります。

```console
# logger -p user.err -t myapp "disk is full"
# journalctl -t myapp
Nov 16 11:19:52 host myapp[81]: disk is full
# journalctl --since "10 min ago" -p err
Nov 16 11:19:52 host myapp[81]: disk is full
```

### systemd-cat：コマンドの出力をジャーナルへ

**`systemd-cat`** は、コマンドの標準出力（と標準エラー）をジャーナルにつなぎます。パイプの先に置いて、標準入力を送ることもできます。

```console
# echo "from cat" | systemd-cat -t mycat -p warning
# systemd-cat -t backup /usr/local/bin/backup.sh
# journalctl -t mycat
Nov 16 11:19:52 host mycat[84]: from cat
```

`-t` は名前（identifier）、`-p` は priority（`0`〜`7` か名前）です。logger と同じ文字ですが、logger は「引数の文字をログに送る」、systemd-cat は「コマンドを実行して、その出力を送る」という違いがあります。

### journald.conf と、ログを残すかどうか

journald の設定ファイルは **`/etc/systemd/journald.conf`** です。debian:12 では、すべての行がコメント（`#`）で、既定の値を示しています。

```conf
[Journal]
#Storage=auto
#Compress=yes
#SystemMaxUse=
#MaxRetentionSec=
#ForwardToSyslog=yes
```

いちばん大事なのは **`Storage=`** です。

| 値 | 保存先 |
| --- | --- |
| `volatile` | `/run/log/journal/`（メモリの上）。再起動で消える |
| `persistent` | `/var/log/journal/`（ディスク）。なければ作る |
| `auto`（既定） | `/var/log/journal/` が**あれば**そこに、なければ `/run/log/journal/` に |
| `none` | 保存しない（転送だけ） |

既定の `auto` で再起動後もログを残すには、**`/var/log/journal` ディレクトリを作る**か、`Storage=persistent` にします。debian:12 に systemd を入れると、`/var/log/journal` は最初から作られていました。`ForwardToSyslog=yes` は、rsyslogd へ渡す設定です。設定を変えたら `systemctl restart systemd-journald` で読み直させます。

テキストのファイルを追いかけるのは `tail -f /var/log/syslog`、ジャーナルを追いかけるのは `journalctl -f` です。サービス 1 つなら `journalctl -u nginx -f` と組み合わせます。

## logrotate：ログを回して古いものを消す {#logrotate}

```fig graph rotate 3 のとき。いまのファイルを .1 にずらし、新しい空のファイルを作る。.3 より古いものは消える
{
  col: 150, row: 90,
  nodes: [
    { id: 'l', label: 'app.log', sub: 'いま書いている', x: 0, y: 0, kind: 'accent' },
    { id: 'l1', label: 'app.log.1', sub: '1 回前', x: 1, y: 0 },
    { id: 'l2', label: 'app.log.2.gz', sub: '2 回前', x: 2, y: 0 },
    { id: 'l3', label: 'app.log.3.gz', sub: '3 回前', x: 3, y: 0 },
    { id: 'x', label: '消す', x: 4, y: 0, kind: 'plain', mono: false },
    { id: 'n', label: 'app.log（新）', sub: 'create で空のファイル', x: 0, y: 1, kind: 'ext' },
  ],
  edges: [
    { from: 'l', to: 'l1' }, { from: 'l1', to: 'l2', label: '圧縮' }, { from: 'l2', to: 'l3' },
    { from: 'l3', to: 'x', style: 'bad' },
    { from: 'n', to: 'l', style: 'muted' },
  ],
}
```

ログのファイルは、放っておくと大きくなり続け、ディスクを埋めます。**`logrotate`** は、決まった間隔でファイルの名前をずらし（**ローテーション**）、古いものを圧縮し、決まった数より古いものを消します。logrotate 自身はデーモンではありません。cron（`/etc/cron.daily/logrotate`）や systemd のタイマー（`logrotate.timer`）から 1 日 1 回実行されます。

小さな Linux に logrotate はないので、することを `mv` で手で真似ます。`rotate 3` のつもりで、4 回回します。

```sh run title="名前をずらして、新しいファイルを作る"
cd /tmp
echo "day1" > app.log
for day in 2 3 4 5; do
  rm -f app.log.3
  [ -f app.log.2 ] && mv app.log.2 app.log.3
  [ -f app.log.1 ] && mv app.log.1 app.log.2
  mv app.log app.log.1
  echo "day$day" > app.log
done
ls
head app.log*
```

**番号が小さいほど新しい**ことと、`day1` が消えたことを確かめてください。

### 設定ファイル

全体の設定は **`/etc/logrotate.conf`**、パッケージごとの設定は **`/etc/logrotate.d/`** の下のファイルです。`logrotate.conf` の `include /etc/logrotate.d` の行で読み込まれます。debian:12 の `/etc/logrotate.conf`（コメントを除く）と、rsyslog の分です。

```sh setup root
cat > /etc/logrotate.conf <<'EOT'
# see "man logrotate" for details
weekly
rotate 4
create
#dateext
#compress
include /etc/logrotate.d
EOT
mkdir -p /etc/logrotate.d
cat > /etc/logrotate.d/rsyslog <<'EOT'
/var/log/syslog
/var/log/mail.log
/var/log/kern.log
/var/log/auth.log
/var/log/user.log
/var/log/cron.log
{
	rotate 4
	weekly
	missingok
	notifempty
	compress
	delaycompress
	sharedscripts
	postrotate
		/usr/lib/rsyslog/rsyslog-rotate
	endscript
}
EOT
```

```sh run title="全体の設定と、パッケージごとの設定"
grep -v '^#' /etc/logrotate.conf
ls /etc/logrotate.d
cat /etc/logrotate.d/rsyslog
```

`logrotate.conf` に書いたものが既定で、`/etc/logrotate.d/` の各ファイルの `{ }` の中で上書きします。

| 指示 | 意味 |
| --- | --- |
| `daily` / `weekly` / `monthly` | 回す間隔 |
| `size 100M` | 大きさがこれを超えたら回す |
| `rotate 4` | 古いものを **4 世代**残す（それより古いものは消す） |
| `compress` | 古いものを gzip で圧縮する（`.gz`） |
| `delaycompress` | 1 回前（`.1`）は圧縮せず、次の回に圧縮する |
| `missingok` | ログのファイルがなくてもエラーにしない |
| `notifempty` | 空なら回さない |
| `create 0640 root adm` | 回したあと、この権限・持ち主で空のファイルを作る |
| `dateext` | 番号の代わりに日付を付ける（`messages-20261116`）。rockylinux:9 の既定 |
| `postrotate` 〜 `endscript` | 回した**あと**に実行するコマンド（`prerotate` は前） |
| `sharedscripts` | 複数のファイルを回しても、postrotate を 1 回だけ実行する |

Docker の debian:12 で、`rotate 3`、`compress`、`delaycompress`、`notifempty`、`create 0640 root adm` の設定を作り、`logrotate -f` で 5 回回した結果です（`-f` は間隔を待たずに今すぐ回す）。

```console
# ls -l /var/log/myapp
-rw-r----- 1 root adm   0 Nov 16 11:18 app.log
-rw-r----- 1 root adm   7 Nov 16 11:18 app.log.1
-rw-r----- 1 root adm  27 Nov 16 11:18 app.log.2.gz
-rw-r----- 1 root adm  27 Nov 16 11:18 app.log.3.gz
-rw-r--r-- 1 root root  0 Nov 16 11:18 empty.log
```

`.1` だけ圧縮されていないのは `delaycompress`、空の `empty.log` に番号付きのファイルがないのは `notifempty` のためです。

:::deep なぜ postrotate でデーモンに知らせるのか
rsyslogd は、ログのファイルを開いたまま書き続けます。`mv` で名前を変えても、デーモンが持っている fd は同じ inode を指したままなので、`app.log.1` に書き続けてしまいます（[図解 Linux 11.6](../../linux/site/ch11.html#rename)、[9.9](../../linux/site/ch09.html#deleted)）。そこで postrotate で HUP シグナルを送り、ファイルを開き直させます。rockylinux:9 の `/etc/logrotate.d/rsyslog` の postrotate は `/usr/bin/systemctl -s HUP kill rsyslog.service` です。開き直せないプログラムには、中身をコピーしてから元を空にする `copytruncate` を使います。
:::

:::warn 試験の注意：rotate は「回数」、daily は「間隔」
`rotate 7` は「7 世代残す」で、7 日ごとではありません。間隔は `daily` / `weekly` / `monthly` で決まります。`daily` と `rotate 7` を組み合わせると、1 週間分が残ります。
:::

## MTA・MUA・MDA：メールが届くまで {#mta}

```fig seq メールは MUA から MTA へ、MTA から MTA へ SMTP で運ばれ、MDA がメールボックスに置く
{
  actors: [
    { id: 'a', label: 'MUA（送る人）' },
    { id: 'm1', label: '送り側の MTA' },
    { id: 'm2', label: '受け側の MTA' },
    { id: 'd', label: 'MDA' },
    { id: 'b', label: 'MUA（読む人）' },
  ],
  msgs: [
    { from: 'a', to: 'm1', label: 'SMTP（587・25）' },
    { from: 'm1', to: 'm2', label: 'SMTP（25）' },
    { from: 'm2', to: 'd', label: '渡す' },
    { self: 'd', label: '/var/mail/ユーザー に置く' },
    { from: 'b', to: 'd', label: 'mail で読む・POP / IMAP', style: 'dashed' },
  ],
}
```

メールは、役目の違う 3 種類のプログラムで運ばれます。

| 略称 | 名前 | 役目 | 例 |
| --- | --- | --- | --- |
| **MUA** | Mail User Agent | 利用者がメールを書く・読む | `mail`、Thunderbird |
| **MTA** | Mail Transfer Agent | メールを受け取り、宛先のサーバへ**配送する**（SMTP、ポート 25） | **postfix**、**exim**、**sendmail** |
| **MDA** | Mail Delivery Agent | 届いたメールを利用者のメールボックスに置く | procmail、postfix の local |

POP や IMAP でメールボックスを読ませる **dovecot** は、MTA ではなく、受け取ったメールを MUA に渡すサーバです。

MTA の主な実装は 3 つです。

| MTA | 特徴 |
| --- | --- |
| **sendmail** | 最も古い。設定が難しい。`sendmail` というコマンド名は、ほかの MTA も互換のために持っている |
| **postfix** | 安全さと速さを重んじた設計。Red Hat 系の標準。設定は `/etc/postfix/main.cf` |
| **exim** | Debian 系の標準（Debian の既定の MTA は exim4） |

どの MTA を入れても、`sendmail`、`mailq`、`newaliases` というコマンドが使えます。postfix は、これらを互換のために用意しています。Docker で確かめると、どちらもリンクでした。

```console
$ ls -l /usr/bin/mailq /usr/bin/newaliases          # debian:12 + postfix
lrwxrwxrwx 1 root root 16 Mar  6  2024 /usr/bin/mailq -> ../sbin/sendmail
lrwxrwxrwx 1 root root 16 Mar  6  2024 /usr/bin/newaliases -> ../sbin/sendmail
$ ls -l /usr/sbin/sendmail                          # rockylinux:9 + postfix
lrwxrwxrwx 1 root root 21 Nov 16 11:16 /usr/sbin/sendmail -> /etc/alternatives/mta
```

:::note 1 台のサーバでも MTA は働いている
インターネットにメールを出さない機械でも、cron の実行結果や、`/etc/aliases` で root 宛てにまとめたシステムのお知らせは、ローカルの MTA が `/var/mail/ユーザー名`（Red Hat 系では `/var/spool/mail` と同じ場所）に配ります。postfix の既定の `inet_interfaces` は、rockylinux:9 では `localhost` で、外からのメールは受け付けません。
:::

## /etc/aliases と ~/.forward、mail と mailq {#aliases}

### /etc/aliases：宛先の別名

**`/etc/aliases`** は、宛先の名前を別の宛先に置き換える表です。1 行が「`別名: 本当の宛先, …`」です。

```sh setup root
cat > /etc/aliases <<'EOT'
# See man 5 aliases for format
mailer-daemon:	postmaster
postmaster:	root
bin:		root
daemon:		root
root:		alice
admin:		alice, bob
EOT
```

```sh run title="/etc/aliases を読む"
cat /etc/aliases
grep '^admin' /etc/aliases
```

- `postmaster: root`：postmaster 宛てのメールは root に届く
- `root: alice`：root 宛てはさらに alice へ（別名はつながる）
- `admin: alice, bob`：1 つの別名で、複数の人に配る

MTA は、このテキストを直接は読みません。**`newaliases`** で、検索の速いデータベース（`/etc/aliases.db`）に作り直して使います。**書き換えたら `newaliases` を実行する**のを忘れないでください。debian:12 + postfix で試した結果です。

```console
# echo "admin: alice, bob" >> /etc/aliases
# newaliases
# ls -l /etc/aliases.db
-rw-r--r-- 1 root root 12288 Nov 16 11:16 /etc/aliases.db
# echo "hello body" | mail -s "test1" admin
# ls -l /var/mail
-rw------- 1 alice mail 549 Nov 16 11:16 alice
-rw------- 1 bob   mail 549 Nov 16 11:16 bob
```

`admin` 宛ての 1 通が、alice と bob の両方のメールボックスに届きました。

### ~/.forward：自分宛てを転送する

`/etc/aliases` は root が管理するシステム全体の表です。一般の利用者が自分宛てのメールを転送したいときは、ホームディレクトリに **`~/.forward`** を置き、転送先を書きます。

```sh run title="自分宛てを転送する ~/.forward"
echo "you@example.com" > ~/.forward
cat ~/.forward
ls -l ~/.forward
```

ほかの人に書き換えられないよう、持ち主だけが書ける権限にしておきます（他人が書ける `.forward` は、MTA に無視されることがあります）。

### mail と mailq

**`mail`** は端末で使う簡単な MUA です。

| 使い方 | すること |
| --- | --- |
| `mail -s "件名" 宛先 < 本文.txt` | 送る。`-s` は**件名**（subject） |
| `echo "本文" \| mail -s "件名" 宛先` | 本文をパイプで渡して送る |
| `mail -c 宛先` | CC を付ける |
| `mail` | 自分のメールボックスを読む（対話で番号を選ぶ） |

送ったのに届かないメールは、MTA の**キュー**（送信待ちの列）に残ります。**`mailq`** はキューの一覧を表示します（`sendmail -bp`、postfix では `postqueue -p` と同じ）。宛先の名前が引けないメールを送ったときの、debian:12 + postfix の出力です。

```console
$ mailq
-Queue ID-  --Size-- ----Arrival Time---- -Sender/Recipient-------
81EF5D8487      547 Mon Nov 16 11:16:49  root@mail.example.com
(Host or domain name not found. Name service error for name=nowhere.invalid type=MX: Host not found, try again)
                                         bob@nowhere.invalid

-- 0 Kbytes in 1 Request.
```

キューが空なら `Mail queue is empty` と表示されます。

| コマンド・ファイル | 役目 |
| --- | --- |
| `/etc/aliases` | システム全体の別名の表（root が編集） |
| `newaliases` | `/etc/aliases` を `/etc/aliases.db` に作り直す（`sendmail -bi` と同じ） |
| `~/.forward` | 利用者が自分宛てを転送する |
| `mail` | 送る・読む（MUA） |
| `mailq` | 送信待ちのキューを見る（`sendmail -bp`、`postqueue -p`） |
| `/var/mail/ユーザー名` | ローカルのメールボックス |

:::warn 試験の注意：newaliases と mailq は「MTA のコマンド」
`newaliases` も `mailq` も、どの MTA（postfix、exim、sendmail）でも同じ名前で使えます。`/etc/aliases` を書き換えただけでは反映されず、`newaliases` が必要です。`~/.forward` は利用者ごと、`/etc/aliases` はシステム全体です。
:::

:::key まとめ
- 時計は 2 つ。ハードウェアクロック（RTC）とシステムクロック。`hwclock -w`（`--systohc`）は sys → hc、`-s`（`--hctosys`）は hc → sys、`-r` は表示
- `date +%Y-%m-%d` で書式を指定して表示。`date MMDDhhmm[[CC]YY]` と `date -s` で設定（root）
- タイムゾーン：`/usr/share/zoneinfo/` のデータ、`/etc/localtime`（システム全体）、`/etc/timezone`（Debian 系）、`TZ`（プロセスごと）。`tzselect` は値を表示するだけ。`timedatectl set-timezone`
- NTP は UDP 123。chronyd（`/etc/chrony.conf`、`chronyc sources` / `tracking`）、ntpd（`/etc/ntp.conf`、`ntpq -p`）、ntpdate は 1 回だけ。行頭の `*` が同期中。pool.ntp.org
- rsyslog：`/etc/rsyslog.conf` に `facility.priority 出力先`。priority は emerg > alert > crit > err > warning > notice > info > debug。1 つ書くと「以上」、`=` は「だけ」、`!` は除く、`none` は facility を除く。`@` は UDP、`@@` は TCP で転送
- `/var/log/messages`（Red Hat 系）と `/var/log/syslog`（Debian 系）、`secure` と `auth.log`
- `logger -p facility.priority -t タグ`（既定は user.notice）、`systemd-cat` はコマンドの出力をジャーナルへ
- `journalctl -u`、`-f`、`-b`、`-p`（以上）、`-n`、`-r`、`-k`、`--since` / `--until`。`/etc/systemd/journald.conf` の `Storage=`（auto は `/var/log/journal` があれば残す）
- logrotate：`/etc/logrotate.conf` と `/etc/logrotate.d/`。`daily` / `weekly`、`rotate N`（世代数）、`compress`、`missingok`、`notifempty`、`create`、`postrotate` 〜 `endscript`
- MUA（書く・読む）、MTA（配送。postfix・exim・sendmail）、MDA（メールボックスへ）。`/etc/aliases` を変えたら `newaliases`。`~/.forward` で転送。`mailq` でキュー
:::

## 練習問題 {#practice}

:::q 1.09.1-01 single
システムクロックの時刻を、ハードウェアクロックに書き込むコマンドはどれか。
- [ ] `hwclock -r`
- [ ] `hwclock -s`
- [x] `hwclock -w`
- [ ] `hwclock --hctosys`
- [ ] `date -u`
:::why
`-w`（`--systohc`、system to hardware clock）は、システムクロックをハードウェアクロックに書き込みます。`-r`（`--show`）はハードウェアクロックを表示するだけ、`-s` と `--hctosys` は同じもので、逆向き（ハードウェアクロック → システムクロック）です。`date -u` は UTC で表示するだけです（[時計は 2 つある](#clock)）。
:::
:::

:::q 1.09.1-02 fill
起動したばかりの機械で、ハードウェアクロックの時刻をシステムクロックに設定したい。空欄に入るオプションを入力してください。

```text
# hwclock ____
```
= -s
= --hctosys
:::why
ハードウェアクロック（hc）からシステムクロック（sys）へ写すのは `-s`、長い形で `--hctosys` です。`-w`（`--systohc`）は逆向きです（[時計は 2 つある](#clock)）。
:::
:::

:::q 1.09.1-03 single
システムクロックが 2026 年 4 月 1 日 9 時 5 分のとき、次のコマンドの出力として正しいものはどれか。

```text
$ date "+%Y%m%d-%H%M"
```
- [x] `20260401-0905`
- [ ] `2026-04-01 09:05`
- [ ] `0401-0905`
- [ ] `26041-95`
:::why
`%Y` は 4 桁の年、`%m` と `%d` は 2 桁の月と日、`%H` と `%M` は 2 桁の時と分です。書式の中の `-` はそのまま出ます。区切りのない数字が並ぶので `20260401-0905` です。`%m` と `%d` は 0 で埋められるので `041` のようにはなりません（[date の書式](#clock)）。
:::
:::

:::q 1.09.1-04 single
システム全体のタイムゾーンを決めるファイルで、通常は `/usr/share/zoneinfo/` の下のファイルへのシンボリックリンクになっているものはどれか。
- [ ] `/etc/timezone`
- [x] `/etc/localtime`
- [ ] `/etc/adjtime`
- [ ] `/etc/tz.conf`
- [ ] `/usr/share/zoneinfo/localtime`
:::why
`/etc/localtime` がシステムのタイムゾーンです。Docker の debian:12 では `/usr/share/zoneinfo/Etc/UTC` へのリンクでした。`/etc/timezone` は Debian 系にある、タイムゾーンの**名前**を書いたテキストで、zoneinfo へのリンクではありません。`/etc/adjtime` は hwclock がハードウェアクロックのずれなどを記録するファイルです。`/etc/tz.conf` というファイルはなく、`/usr/share/zoneinfo/localtime` も使われません（[タイムゾーン](#ntp)）。
:::
:::

:::q 1.09.1-05 multi
システムのタイムゾーンを日本時間（Asia/Tokyo）に変更する操作として正しいものを 2 つ選択してください。
- [x] `timedatectl set-timezone Asia/Tokyo`
- [x] `ln -sf /usr/share/zoneinfo/Asia/Tokyo /etc/localtime`
- [ ] `tzselect` を実行して Asia と Japan を選ぶ
- [ ] `hwclock --localtime`
- [ ] `date -s Asia/Tokyo`
:::why
`timedatectl set-timezone` は `/etc/localtime` を張り替えます。`ln -sf` で直接張り替えても同じです。`tzselect` は選んだ地域の `TZ` の値（`Asia/Tokyo`）を**表示するだけ**で、システムの設定は変えません。`hwclock --localtime` はハードウェアクロックを地方時として扱う指定で、タイムゾーンを決めるものではありません。`date -s` は時刻を設定するオプションで、タイムゾーンの名前は受け付けません（[タイムゾーン](#ntp)）。
:::
:::

:::q 1.09.1-06 single
`tzselect` の説明として正しいものはどれか。
- [ ] 選んだタイムゾーンに合わせて `/etc/localtime` を書き換える
- [ ] NTP サーバに問い合わせて、タイムゾーンを自動で決める
- [x] 対話で地域を選ばせ、それに当たる `TZ` 環境変数の値を表示する
- [ ] ハードウェアクロックを、選んだタイムゾーンの時刻に設定する
:::why
`tzselect` は大陸と国を番号で選ばせ、最後に `Asia/Tokyo` のような `TZ` の値を表示します。システムのファイルは何も変えません。その値を `~/.profile` などで `TZ` に設定するのは利用者です。`/etc/localtime` を変えるのは `timedatectl set-timezone` や `ln -sf`、ハードウェアクロックを書くのは `hwclock` です（[タイムゾーン](#ntp)）。
:::
:::

:::q 1.09.1-07 single
chronyd が動いている機械で、時刻の元にしている NTP サーバの一覧と、どれに同期しているかを表示するコマンドはどれか。
- [x] `chronyc sources`
- [ ] `chronyc tracking`
- [ ] `ntpdate -q`
- [ ] `timedatectl list-timezones`
- [ ] `chronyd -q`
:::why
`chronyc sources` は時刻の元（サーバ）の一覧で、行頭の `*` が同期中のサーバです。`chronyc tracking` は、システムクロックがどれだけずれているかなど、同期の状態を表示します（サーバの一覧ではありません）。`ntpdate -q` はサーバに問い合わせてずれを表示する 1 回だけのコマンドで、chronyd の状態とは関係ありません。`timedatectl list-timezones` はタイムゾーンの一覧です。`chronyd -q` は、chronyd を常駐させずに 1 回だけ時刻を合わせて終わる起動のしかたです（[NTP](#ntp)）。
:::
:::

:::q 1.09.1-08 single

```text
===============================================================================
-time.cloudflare 10.192.8.136     3 u   13   64    1  10.2636   9.8735   0.6945
```

`*` は、いま同期の元にしているサーバです。`+` は合わせて使う候補、`-` は外したものです。stratum は `st` の列に数字で出ます（この行は 2）。chronyc sources の `^*` も同じ意味です（[NTP](#ntp)）。

:::q 1.09.1-10 multi
NTP の説明として正しいものを 2 つ選択してください。
- [x] NTP は UDP の 123 番ポートを使う
- [x] pool.ntp.org は、ボランティアが提供する多数の NTP サーバをまとめた名前である
- [ ] stratum の数字が大きいサーバほど、基準の時計に近く正確である
- [ ] ntpdate は常駐して、時刻を少しずつ合わせ続ける
- [ ] 1 台の機械で chronyd と ntpd を同時に動かすと、より正確になる
:::why
NTP は UDP 123 番です。pool.ntp.org は引くたびに違うサーバを返す、ボランティアのサーバの集まりです。stratum は**小さい**ほど基準に近くなります（stratum 1 が基準の時計に直接つながる）。ntpdate は 1 回だけ一気に合わせて終わるコマンドで、常駐して少しずつ合わせるのは chronyd や ntpd です。chronyd と ntpd は同じポートを使い、どちらも時計を動かそうとするので、どちらか 1 つだけを動かします（[NTP](#ntp)）。

- [x] mail の warning、err、crit、alert、emerg
- [ ] mail の debug から warning まで

priority を 1 つ書くと、**その priority 以上**（より重大なもの）すべてを選びます。warning より重大なのは err、crit、alert、emerg です。warning だけを選ぶには `mail.=warning` と書きます。facility は `mail` に限られています（[セレクタの記号](#rsyslog)）。

:::q 1.09.2-03 single
rsyslog のセレクタで、cron の info **だけ**を選ぶ書き方はどれか。

- [ ] `cron.*info`
- [ ] `cron.info;cron.none`
:::why
`=` を付けると、その priority だけを選びます。`cron.info` は info 以上（info、notice、warning、err …）です。`!` は除く指定で、`cron.*;cron.!info` のように選んだものから除くのに使います。`cron.*info` という書き方はありません。`cron.none` は cron を何も選ばない指定です（[セレクタの記号](#rsyslog)）。

:::why
`systemd-cat コマンド` は、そのコマンドの出力をジャーナルにつなぎます。`echo 文 | systemd-cat -t 名前` のように、標準入力を送ることもできます。ジャーナルを表示するのは `journalctl` です。ほかの 2 つは systemd-cat の働きではありません（[systemd-cat](#journal)）。

:::q 1.09.2-13 single
httpd.service のログだけをジャーナルから表示するコマンドはどれか。

- [ ] `journalctl -k httpd.service`
- [x] `journalctl -u httpd.service`
- [ ] `journalctl -p httpd.service`

:::why
`-u` で unit を指定します。`-k` はカーネルのログ、`-p` は priority の指定で、unit 名は取りません。`-s` は `--since` の短い形ではなく（短い形は `-S`）、unit の指定でもありません。`systemctl journal` というサブコマンドはありません（[journalctl](#journal)）。

`-f`（`--follow`）は、新しい行を待って出し続けます。`-u 名前` と組み合わせて、1 つのサービスだけを追いかけることもできます（[journalctl](#journal)）。

:::q 1.09.2-15 multi

- [x] emerg
- [ ] warning
- [ ] notice
- [ ] debug
:::why
`-p` に 1 つの priority を書くと、その priority **以上**（err、crit、alert、emerg）を表示します。warning、notice、debug は err より低いので出ません。rsyslog のセレクタの「以上」と同じ考え方です（[journalctl](#journal)）。

:::q 1.09.2-16 multi
journalctl のオプションの説明として正しいものを 2 つ選択してください。
- [x] `-r` は、新しいものから順に表示する
- [x] `-k` は、カーネルのメッセージだけを表示する
- [ ] `-b` は、1 つ前の起動のログだけを表示する
- [ ] `-u` は、ユーザー名を指定してそのユーザーのログを表示する
- [ ] `-n 20` は、20 分前からのログを表示する
:::why
`-r` は逆順（新しい順）、`-k` はカーネルのログ（`dmesg` と同じもの）です。`-b` は**今回の**起動からで、1 つ前は `-b -1` です。`-u` は unit の指定です。`-n 20` は最後の 20 件で、時刻で絞るのは `--since` です（[journalctl](#journal)）。

:::q 1.09.2-17 single
次のコマンドの説明として正しいものはどれか。

```text
$ journalctl --since "2026-11-01 09:00" --until "2026-11-01 10:00"
```

- [ ] 11 月 1 日の 9 時より前と、10 時より後のログを表示する
- [ ] 11 月 1 日 9 時から 10 時までのログを削除する
- [ ] 9 時から 10 時まで、新しいログを表示し続ける
:::why
`--since` は「この時刻より新しい」、`--until` は「この時刻より古い」で、組み合わせるとその間を表示します。ジャーナルを消すのは `--vacuum-time` などで、表示し続けるのは `-f` です（[journalctl](#journal)）。
:::

:::q 1.09.2-18 single
`/etc/systemd/journald.conf` の Storage が既定の `auto` のまま、再起動してもジャーナルが残るようにしたい。最も簡単な方法はどれか。
- [ ] `/run/log/journal` ディレクトリを作る
- [x] `/var/log/journal` ディレクトリを作る
- [ ] `Storage=volatile` にする
- [ ] rsyslogd を止める
:::why
`Storage=auto` は、`/var/log/journal` が**あれば**ディスクに残し、なければ `/run/log/journal`（メモリの上）に書きます。ディレクトリを作れば、設定を変えずに残るようになります（`Storage=persistent` にする方法もあります）。`/run/log/journal` は再起動で消える場所、`volatile` はメモリだけに保存する設定です。rsyslogd を止めても、ジャーナルの保存先は変わりません（[journald.conf](#journal)）。

:::q 1.09.2-20 single
logrotate の設定で、ログのファイルが空のときはローテーションしないようにする指示はどれか。
- [ ] `missingok`
- [x] `notifempty`
- [ ] `delaycompress`
- [ ] `nocreate`
- [ ] `sharedscripts`
:::why
`notifempty` は「空なら回さない」です。`missingok` はファイルが**ない**ときにエラーにしない指示です。`delaycompress` は 1 回前のものの圧縮を次の回に延ばす、`nocreate` は回したあとに新しいファイルを作らない、`sharedscripts` は postrotate を 1 回だけ実行する指示です（[logrotate](#logrotate)）。
:::
:::

:::q 1.09.2-21 single
`/etc/logrotate.d/myapp` が次の内容のとき、説明として正しいものはどれか。

```text
/var/log/myapp/*.log {
    weekly
    rotate 4
    compress
    missingok
}
```
- [x] 1 週間ごとに回し、古いものを 4 世代まで圧縮して残す
- [ ] 4 週間ごとに回し、古いものを 1 世代だけ残す
- [ ] 1 週間ごとに回し、4 日より古いものを消す
- [ ] ファイルがないときはエラーを出して止まる
:::why
`weekly` が間隔、`rotate 4` が残す世代の数、`compress` が圧縮です。`rotate` は日数ではありません。`missingok` があるので、ファイルがなくてもエラーにしません（[logrotate](#logrotate)）。
:::
:::

:::q 1.09.2-22 multi
logrotate の設定の指示の説明として正しいものを 2 つ選択してください。
- [x] `create 0640 root adm` は、回したあとに、その権限と持ち主で空のファイルを作る
- [x] `postrotate` と `endscript` の間のコマンドは、回したあとに実行される
- [ ] `rotate 7` は、7 日ごとにログを回す
- [ ] `delaycompress` は、圧縮をまったく行わない
- [ ] `daily` は、logrotate を常駐させて 1 日中見張らせる
:::why
`create` は新しい空のファイルを作る指示で、権限・持ち主・グループを書けます。`postrotate` 〜 `endscript` は回したあとのコマンド（デーモンに HUP を送るなど）です。`rotate 7` は 7 世代残す指示で、間隔は `daily` などで決まります。`delaycompress` は `compress` と組み合わせて、`.1` だけ圧縮を次の回に延ばします。logrotate は常駐せず、cron や systemd のタイマーから 1 日 1 回実行されます（[logrotate](#logrotate)）。
:::

:::q 1.09.2-24 single
`rotate 3` と `compress`（`delaycompress` はなし）の設定で何回もローテーションしたあと、`/var/log/app/` に次のファイルがある。ローテーションで残された中で**最も新しい**ログはどれか。

```text
app.log  app.log.1.gz  app.log.2.gz  app.log.3.gz
```

- [ ] `app.log.3.gz`

- [x] `app.log.1.gz`

:::q 1.09.2-25 single
logrotate の設定で、`postrotate` に rsyslogd へ HUP シグナルを送るコマンドを書く理由として正しいものはどれか。
- [ ] rsyslogd を止めないと、logrotate がファイルを圧縮できないから
- [x] rsyslogd は名前を変えられた古いファイルを開いたまま書き続けるので、新しいファイルを開き直させるため
- [ ] HUP を送ると、rsyslogd が古いログを自動で消すから
- [ ] logrotate は root で動かないため、rsyslogd に代わりに回させるから
:::why
デーモンが持っている fd は、名前ではなく inode を指しています。`mv` で名前を変えても、デーモンは古いファイル（`.1`）に書き続けます。HUP で開き直させると、新しく作られた空のファイルに書くようになります（[図解 Linux 11.6](../../linux/site/ch11.html#rename)）。HUP はログを消す指示ではありません。logrotate は root で実行され、自分でファイルを回します（[logrotate](#logrotate)）。
:::

:::q 1.09.3-01 single
MTA（Mail Transfer Agent）の役目として正しいものはどれか。
- [ ] 利用者がメールを書いたり読んだりするための画面を提供する
- [x] メールを受け取り、宛先のメールサーバへ SMTP で配送する
- [ ] 届いたメールを、POP や IMAP で利用者の端末に渡す
- [ ] メールの本文を暗号化して保存する
:::why
MTA はメールを運ぶ（転送・配送する）プログラムで、postfix、exim、sendmail が代表です。書く・読むのは MUA（`mail`、Thunderbird）、POP や IMAP でメールボックスを読ませるのは dovecot などのサーバです。メールボックスに置くのは MDA です（[MTA・MUA・MDA](#mta)）。
:::

- [ ] procmail
:::why
postfix（Red Hat 系の標準）と exim（Debian 系の標準）は MTA です。sendmail も MTA です。dovecot は POP・IMAP のサーバ、Thunderbird は MUA、procmail はメールボックスへ配る MDA です（[MTA・MUA・MDA](#mta)）。

:::q 1.09.3-03 single
`/etc/aliases` を書き換えたあと、その内容を MTA に反映させるために実行するコマンドはどれか。
