5.2カーネルモジュール：ドライバはあとから足せる

装置を動かすプログラムをドライバと呼びます。Linux のドライバの多くは、カーネル本体に入っているのではなく、カーネルモジュール（.ko のファイル）として別になっています。必要になったときに読み込み、要らなくなったら外せます。ファイルシステム（xfs、vfat など）も、モジュールになっていることが多いものです。

モジュールのファイルは、/lib/modules/カーネルのリリース番号/ の下にあります。リリース番号は uname -r で見られます。

カーネルのリリース番号⌘↵
uname -r

本物の Linux なら、/lib/modules/6.8.0-…/kernel/ の下に、装置の種類ごとのディレクトリがあり、そこに .ko のファイルが並んでいます。この小さな Linux にはモジュールの仕組みがないので、ここからのコマンドは実行しない例で見ます。

モジュールを扱うコマンドは 4 つです。

ターミナル
# lsmodModule                  Size  Used byxfs                  2060288  1libcrc32c              12288  2 xfs,nf_conntrackusb_storage            86016  0# modprobe vfat              ← 名前で。依存するモジュール（fat）も一緒に読み込む# modprobe -r vfat           ← 外す（使われなくなった依存も外す）# insmod /lib/modules/$(uname -r)/kernel/fs/fat/fat.ko   ← ファイルのパスで。依存は解決しない# rmmod usb_storage          ← 外す

lsmod の 3 列は、モジュールの名前、大きさ（バイト）、使われている数と、使っているモジュールの名前です。上の例の libcrc32c は、xfs と nf_conntrack の 2 つから使われています。使われている数が 0 でないモジュールは、外せません。lsmod は、/proc/modules を読みやすく整えて表示しています。

コマンドすること指定のしかた依存の解決
lsmod読み込まれているモジュールの一覧引数なし—
modprobe 名前読み込むモジュールの名前する
modprobe -r 名前外す名前する（要らなくなった依存も外す）
insmod ファイル読み込む.ko のファイルのパスしない
rmmod 名前外す名前しない
modinfo 名前モジュールの説明、作者、引数、依存を表示名前—
注意試験の注意：modprobe と insmod
  • 依存関係を解決してくれるのは modprobe。ふだんはこちらを使う。insmod は依存を見ないので、先に要るモジュールがないと失敗する
  • 外すのは rmmod と modprobe -r。insmod -r や lsmod -r というオプションはない
  • modprobe は名前、insmod はファイルのパス。insmod xfs のように名前だけでは動かない
深掘り4 つのコマンドの正体

Debian でも Red Hat 系でも、lsmod、modprobe、insmod、rmmod は、どれも kmod という 1 つのプログラムへのシンボリックリンクです（ls -l /sbin/lsmod で -> /bin/kmod と見えます）。呼ばれた名前で動きを変える作りで、図解 Linux 19 章の busybox と同じ考え方です。modprobe が使う依存の表 modules.dep は、depmod コマンドが /lib/modules/$(uname -r)/ に作ります。

5.3装置を調べる：/sys、/proc、/dev と lspci・lsusb

カーネルが見つけた装置の情報は、3 つの場所にファイルとして出ています。どれも図解 Linux で見た「ディスクの上にないファイルシステム」です（図解 Linux 12.3、12.4）。

sysfs（/sys）は、カーネルが知っている装置、バス、ドライバのつながりを、ディレクトリの木で見せるファイルシステムです。/proc がプロセスの情報から始まったのに対して、/sys は装置の情報のために作られました。

/sys の中と、ディスクの情報⌘↵
ls /sysls /sys/blockcat /sys/block/sda/sizecat /sys/block/sda/queue/rotational

size はセクタ（512 バイト）の数です。rotational は、ディスクが回転する装置かどうかで、1 なら HDD、0 なら SSD などの回転しない装置です。この小さな Linux の sda は 1（HDD のふり）です。

/proc にも、ハードウェアの情報があります。

/proc の CPU の情報⌘↵
head -4 /proc/cpuinfo
ファイル中身
/proc/cpuinfoCPU の種類、数、機能
/proc/meminfoメモリの量と使い方（free の元）
/proc/interrupts装置ごとの割り込み（IRQ）の番号と回数
/proc/ioports装置が使う I/O ポートの番地
/proc/modules読み込まれているモジュール（lsmod の元）
/proc/partitionsカーネルが認識しているディスクとパーティション
/proc/mountsいまのマウントの一覧
/proc/swaps使っているスワップ

/dev には、装置を開くためのデバイスファイルが並びます。先頭の c はキャラクタデバイス、b はブロックデバイス（ディスクのように、ブロック単位で読み書きする装置）です。

デバイスファイルの種類⌘↵
ls -l /dev/null /dev/zero /dev/tty

5.4udev と dbus、記憶装置の種類

USB メモリを挿すと、/dev/sdb が現れ、デスクトップにアイコンが出ます。この流れを 3 つの部品が受け持ちます。

部品役目
sysfs（/sys）カーネルが認識した装置を、ファイルの木として見せる
udevカーネルからの通知（uevent）を受け取り、規則に従って /dev のデバイスファイルを整える（名前、権限、/dev/disk/by-uuid/… などのリンク）。デーモンは systemd-udevd
dbusプロセスどうしがメッセージを送り合う仕組み（プロセス間通信のバス）。装置が増えた、ネットワークがつながった、などをデスクトップのプログラムに伝える

udev の規則は、/lib/udev/rules.d/（Red Hat 系は /usr/lib/udev/rules.d/。パッケージが置く）と、/etc/udev/rules.d/（管理者が書く。同じ名前なら、こちらが優先）にあります。udevadm monitor で、届く uevent を眺められます。

起動したときにすでにつながっている装置は、udev が起動の途中でまとめて処理します（コールドプラグ）。動いている途中で抜き差しする USB 機器は、そのたびに uevent が届きます（ホットプラグ）。どちらも、デバイスファイルを作るのは udev の仕事で、mknod を手で打つことはまずありません。

HDD、SSD、光学ドライブ

種類仕組み特徴デバイスファイルの例
HDD回転する円盤（プラッタ）に磁気で記録し、ヘッドを動かして読む容量あたりが安い。ヘッドを動かす待ち（シーク）があり、ばらばらの場所を読むと遅い/dev/sda（SATA・SAS・USB）
SSDフラッシュメモリ。動く部品がないランダムな読み書きが速い。書き換えの回数に上限があり、空いた場所をまとめて知らせる TRIM（fstrim）を使う/dev/sda（SATA）、/dev/nvme0n1（NVMe）
光学ドライブCD・DVD・Blu-ray をレーザーで読むファイルシステムは ISO 9660 や UDF/dev/sr0（/dev/cdrom はその別名のリンク）

ディスクの名前は、/dev/sd + 見つかった順の英字（a、b…）+ パーティションの番号（1、2…）です。2 台目のディスクの 3 番目のパーティションは /dev/sdb3 です。NVMe の SSD は /dev/nvme0n1 がディスク、/dev/nvme0n1p1 がその 1 番目のパーティションと、p が入ります。仮想マシンでは /dev/vda（virtio）もよく見ます。

sda、sdb の英字は、カーネルが装置を見つけた順に付きます。ディスクを足したり、USB メモリを挿したまま起動したりすると、順番が入れ替わることがあります。だから /etc/fstab には、/dev/sdb1 ではなく UUID やラベルで書くのが勧められます（5.12）。

5.5MBR と GPT：パーティション表の 2 つの形

1 台のディスクを、いくつかの区画に分けたものをパーティションと呼びます。どこからどこまでが何番のパーティションかを書いた表（パーティション表）は、ディスクの先頭に置かれます。その形には、古い MBR と新しい GPT の 2 つがあります。

MBR（Master Boot Record）は、ディスクの最初の 512 バイトです。ブートローダの最初の部分（446 バイト）、パーティション表（16 バイト × 4 個 = 64 バイト）、終わりの印（2 バイト、55 AA）が入っています。表の枠が 4 つしかないので、基本パーティションは 4 つまでです。

それより多く分けたいときは、4 つのうちの 1 つを拡張パーティションにし、その中に論理パーティションを作ります。拡張パーティションは「入れ物」で、それ自体にはファイルシステムを作りません。論理パーティションの番号は、5 から始まります（1〜4 は基本と拡張のための番号）。

GPT（GUID Partition Table）は、UEFI と一緒に決められた新しい形です。

MBRGPT
表の場所先頭 512 バイト先頭（保護 MBR の次）と、末尾に控え
パーティションの数基本 4 つまで（拡張 + 論理で増やす）既定で 128 個。基本・拡張・論理の区別がない
扱えるディスクの大きさ2 TiB まで（512 バイトのセクタのとき）2 TiB を超えられる（事実上、制限なし）
パーティションの識別1 バイトの種類の番号（83 Linux、82 スワップ など）GUID（長い番号）。パーティションごとにも UUID がある
主な起動の方式BIOSUEFI

先頭の保護 MBR は、GPT を知らない古い道具が「空のディスク」と思って上書きしないように、「ディスク全体が使用中」と書いた見かけだけの MBR です。

UEFI と ESP

UEFI は、BIOS に代わるファームウェアです（図解 Linux 17.1）。BIOS は MBR の 446 バイトにあるブートローダを実行しましたが、UEFI はファイルシステムを読んで、ブートローダのファイル（.efi）を実行します。その置き場所が ESP（EFI System Partition）です。

項目ESP
ファイルシステムFAT（FAT32。Linux での種類の名前は vfat）
マウントする場所/boot/efi がふつう
中身EFI/debian/grubx64.efi のようなブートローダのファイル
大きさ数百 MiB（100〜550 MiB ほど）
gdisk の種類のコードEF00

「BIOS と MBR」「UEFI と GPT」が典型の組み合わせです。ESP は UEFI のためのもので、ファイルシステムは ext4 ではなく FAT（vfat）です。GPT には拡張パーティションも論理パーティションもありません。

パーティション表を編集するコマンドは 3 つです。どれも root で、ディスクのデバイスファイル（/dev/sdb など。パーティションの /dev/sdb1 ではない）を渡します。

5.7パーティションの分け方：/、/boot、/var、/home、スワップ

インストールのとき、ディスクを 1 つの大きな / にもできますが、役目ごとに分けることもあります。分けると、1 つが一杯になっても、ほかに広がりません。

分けるもの分ける理由
/bootカーネルと initramfs を、ブートローダが確実に読める単純な場所に置く。/ を LVM や暗号化にしたときに必要になる
/boot/efiUEFI で起動するための ESP（FAT）
/varログ（/var/log）、メールや印刷のスプール、パッケージのキャッシュは増え続ける。一杯になっても / を巻き込まない
/homeユーザーのデータ。OS を入れ直すときも、フォーマットせずに残せる。ユーザーが一杯にしても、システムは止まらない
/tmpだれでも書ける一時ファイル。tmpfs にすることも多い
スワップメモリが足りないとき、使われていないページを書き出す場所

/etc、/bin、/sbin、/lib、/dev は、/ と別のパーティションにできません。/ をマウントした直後に、ほかのものをマウントするための道具（mount）と設定（/etc/fstab）が、そこから読まれるからです。

スワップ（swap）は、メモリが足りなくなったときに、しばらく使われていないページの中身をディスクへ退避する場所です（図解 Linux 13.10 の囲み）。専用のスワップパーティションのほか、ふつうのファイルをスワップファイルとして使うこともできます。大きさの目安は時代と使い方で変わりますが、休止状態（ハイバネーション）を使うなら、メモリの量以上が要ります。

5.8LVM：パーティションを、あとから伸び縮みさせる

パーティションは、一度切ると大きさを変えにくいものです。後ろに別のパーティションがあると、伸ばせません。LVM（Logical Volume Manager）は、ディスクとファイルシステムのあいだに 1 段かませて、この不便をなくします。

層名前作るコマンド見るコマンド
PV（物理ボリューム）LVM で使うと決めたディスクやパーティションpvcreatepvs、pvdisplay
VG（ボリュームグループ）PV を束ねた池。PE（物理エクステント、既定 4 MiB）という小さな単位に分けて管理するvgcreatevgs、vgdisplay
LV（論理ボリューム）VG から切り出した領域。パーティションの代わりに、この上に mkfs するlvcreatelvs、lvdisplay

300 MiB のディスク 2 台で、実際に作った例です（Debian 12、Docker のループデバイスで実行）。

ターミナル
# pvcreate /dev/sdb /dev/sdc  Physical volume "/dev/sdb" successfully created.  Physical volume "/dev/sdc" successfully created.# vgcreate vg01 /dev/sdb /dev/sdc  Volume group "vg01" successfully created# lvcreate -L 200M -n lv_data vg01  Logical volume "lv_data" created.# vgs  VG   #PV #LV #SN Attr   VSize   VFree  vg01   2   1   0 wz--n- 592.00m 392.00m# lvs  LV      VG   Attr       LSize   Pool Origin Data%  Meta%  Move Log Cpy%Sync Convert  lv_data vg01 -wi-a----- 200.00m

300 MiB の PV が 296 MiB（74 個の PE）になっているのは、LVM の管理情報のぶんです。2 台を束ねた VG は 592 MiB で、そこから 200 MiB の LV を切り出しました。

LV のデバイスファイルは 2 つの名前で見えます。

  • /dev/VG名/LV名（例 /dev/vg01/lv_data）
  • /dev/mapper/VG名-LV名（例 /dev/mapper/vg01-lv_data。実体はこちらで、上はこれへのシンボリックリンク）

lvcreate の大きさは、-L 200M のように量で、または -l 50 のように PE の個数で（-l 100%FREE なら残り全部）指定します。名前は -n です。

伸ばす、縮める

LV は、VG に空きがあれば、使いながら伸ばせます。VG の空きが足りなければ、ディスクを足して vgextend vg01 /dev/sdd で VG を広げます。

ターミナル
# lvextend -L +100M -r /dev/vg01/lv_data  Size of logical volume vg01/lv_data changed from 200.00 MiB (50 extents) to 300.00 MiB (75 extents).  Logical volume vg01/lv_data successfully resized.resize2fs 1.47.0 (5-Feb-2023)Filesystem at /dev/mapper/vg01-lv_data is mounted on /data; on-line resizing required

-L +100M は「100 MiB 足す」、-L 300M は「300 MiB にする」です。LV を伸ばしただけでは、上のファイルシステムは元の大きさのままです。-r（--resizefs）を付けると、ファイルシステムも一緒に広げます。付けなかったときは、ext4 なら resize2fs、XFS なら xfs_growfs で広げます。

縮めるのは lvreduce ですが、先にファイルシステムを縮めないとデータが壊れます。XFS は縮められません（大きくすることだけできる）。ext4 は、マウントを外せば縮められます。

コマンドすること
vgextend VG PVVG に PV を足す
vgreduce VG PVVG から PV を外す
lvextend -L +量 [-r] LVLV を伸ばす
lvreduce -L -量 [-r] LVLV を縮める
lvresize伸ばすのも縮めるのもできる
lvremove、vgremove、pvremove消す（LV → VG → PV の順）

スナップショット

スナップショットは、ある瞬間の LV の姿を、別の LV として残す機能です。lvcreate に -s（--snapshot）を付け、元の LV を指定します。

ターミナル
# lvcreate -s -L 50M -n snap1 vg01/lv_data

作った瞬間には中身をコピーしません。元の LV のブロックが書き換えられるときに、書き換えの前の中身だけをスナップショットの領域に退避します（コピーオンライト）。だから、-L 50M のように元より小さな領域で作れます。動いているデータベースのバックアップを取るときに、スナップショットを作ってそれをマウントし、ゆっくりコピーする、という使い方をします。退避の量が領域を超えると、スナップショットは使えなくなります。

注意試験の注意：LVM の順番と名前
  • 作る順は PV → VG → LV（pvcreate → vgcreate → lvcreate）。その後で mkfs、mount
  • vgcreate の最初の引数は新しい VG の名前、lvcreate の -n は LV の名前、最後の引数が VG
  • スナップショットは lvcreate -s。lvsnapshot というコマンドはない
  • LV を伸ばしてもファイルシステムは伸びない（-r か resize2fs・xfs_growfs）。XFS は縮められない

5.9ファイルシステムの種類と mkfs

パーティションや LV は、まだ何も書かれていない区画です。そこに inode 表やスーパーブロック（図解 Linux 11.9）を書き込んで、ファイルを置けるようにするのが mkfs（make filesystem）です。

ターミナル
# mkfs -t ext4 /dev/sdb1       ← 種類を -t で# mkfs.ext4 /dev/sdb1          ← 上と同じ（mkfs は mkfs.ext4 を呼ぶだけ）# mkfs.xfs -L LOGS /dev/sdb2   ← -L でラベルを付ける# mkfs.vfat /dev/sdc1# mke2fs -t ext4 /dev/sdb1     ← ext 系を作る本体

mkfs は入口で、実際の仕事は mkfs.種類 という名前の別のコマンドがします。ls /sbin/mkfs* には mkfs.ext2、mkfs.ext3、mkfs.ext4、mkfs.xfs、mkfs.vfat、mkfs.btrfs などが並びます。-t を省くと ext2 になります（mkfs --help の説明に when unspecified, ext2 is used とあります）。

カーネルが読めるファイルシステムの種類は、/proc/filesystems に出ています（図解 Linux 12.2）。nodev が付いたものは、ディスク（ブロックデバイス）を使わない種類です。

カーネルが知っているファイルシステムの種類⌘↵
cat /proc/filesystems
種類特徴主な使い道
ext2ジャーナルなし。古い小さな領域
ext3ext2 にジャーナルを足したもの古いシステムの標準
ext4ext3 の後継。エクステント（図解 Linux 11.9）、大きなファイル、ジャーナルDebian、Ubuntu の標準
XFSジャーナル。大きなファイルと並列の読み書きに強い。縮小できないRed Hat 系（RHEL 7 以降）の標準
Btrfsコピーオンライト。スナップショット、サブボリューム、複数のディスクをまとめる機能、データのチェックサムを、ファイルシステム自身が持つopenSUSE、Fedora の標準
VFAT（FAT32）Windows や macOS でも読める。所有者や権限を持たないUSB メモリ、SD カード、ESP
tmpfsメモリの上。再起動で消える。mkfs は要らない/tmp、/run、/dev/shm
ISO 9660CD・DVD 用。読み取り専用光学メディア

ジャーナルは、書き換えの予定を先に専用の場所に書いておき、途中で電源が落ちても整合性を取り戻せるようにする仕組みです（図解 Linux 11.9 の囲み）。ジャーナルがあると、電源断のあとの fsck（ファイルシステムの検査と修復）がすぐ終わります。

tmpfs はディスクを使わないので、mkfs をせず、いきなり mount -t tmpfs します（図解 Linux 12.5）。

注意試験の注意：mkfs は中身を消す

mkfs は、区画の先頭から新しい管理情報を書き込みます。すでにあるファイルは読めなくなります。ラベルを付け直したいだけなら、mkfs -L ではなく、ext 系は e2label か tune2fs -L、XFS は xfs_admin -L を使います（5.12）。

5.10スワップ：mkswap、swapon、swapoff

スワップも、作って（mkswap）、使い始める（swapon）の 2 段です。マウントはしません。

ターミナル
# mkswap /dev/sdb5Setting up swapspace version 1, size = 100 MiB (104853504 bytes)no label, UUID=b61f237a-5e07-41f4-8832-5c738f508c62# swapon /dev/sdb5# swapon --showNAME          TYPE       SIZE USED PRIO/var/lib/swap file      1024M   0B   -2/dev/sdb5     partition  100M   0B   -3# swapoff /dev/sdb5

（Debian 12 の Docker で、ループデバイスを使って確かめたものです。/var/lib/swap は、もともとあったスワップファイルです）

コマンドすること
mkswap 装置スワップ領域を作る（-L でラベル）
swapon 装置そのスワップを使い始める
swapon -a/etc/fstab に書いた swap を全部使い始める（起動のときに実行される）
swapon --show、swapon -s使っているスワップの一覧（-s は古い形で、/proc/swaps と同じ表を出す）
swapoff 装置そのスワップを使うのをやめる（中身はメモリへ戻す）

使っているスワップは、free の Swap: の行と、/proc/swaps でも見られます。この小さな Linux には、スワップがありません。

スワップの量（この Linux では 0）⌘↵
freegrep -i swap /proc/meminfo

スワップファイルを作るときは、ファイルを用意し、持ち主だけが読み書きできる権限（600）にしてから mkswap します。

ターミナル
# dd if=/dev/zero of=/swapfile bs=1M count=1024# chmod 600 /swapfile# mkswap /swapfile# swapon /swapfile
注意試験の注意：作るのと使うのは別

mkswap は領域を作るだけで、それだけではスワップとして使われません。swapon して初めて使われます。ファイルシステムの mkfs → mount と同じ関係です。/etc/fstab に書いておけば、起動のたびに swapon -a で有効になります。

5.11mount と umount：木につなぐ、外す

mount -t 種類 何を どこに でつなぎ、umount どこに（または umount 何を）で外します（図解 Linux 12.6、12.7）。つなぐ先のディレクトリをマウントポイントと呼び、前もって作っておきます。種類は、ディスクの中身を見て自動で見分けてくれるので、-t を省くこともできます。

ターミナル
# mount /dev/sdb1 /mnt                 ← 種類は自動# mount -t xfs /dev/sdb2 /data# mount -o ro /dev/sr0 /media/cdrom    ← 読み取り専用で# mount UUID=6109cec1-643a-4028-8cd9-7dff05eef572 /data# mount LABEL=DATA /data# mount                                 ← 引数なし：マウントの一覧# mount -a                              ← /etc/fstab の（noauto 以外の）全部をマウント

小さな Linux では、tmpfs で試せます。/media/usb に、読み取り専用（ro）で、1 MiB の tmpfs をつなぎます。

読み取り専用でマウントするroot で実行⌘↵
mkdir /media/usbmount -t tmpfs -o ro,size=1m tmpfs /media/usbgrep /media/usb /proc/mounts
読み取り専用には書けないエラーになるroot で実行⌘↵
touch /media/usb/a.txt

-o remount を付けると、外さずにオプションだけを変えられます。

書けるように付け直すroot で実行⌘↵
mount -o remount,rw /media/usbtouch /media/usb/a.txtls /media/usb
オプション（-o）意味
ro / rw読み取り専用 / 読み書き
remountマウントしたまま、オプションを付け直す
noexec / execその中のプログラムの実行を許さない / 許す
nosuid / suidSUID・SGID のビットを無視する / 効かせる
nodev / devその中のデバイスファイルを使わせない / 使わせる
sync / async書き込みをすぐディスクに書く / まとめて後で書く
auto / noautomount -a（起動時）でマウントする / しない
user / nouser一般ユーザーにマウントを許す（外すのはマウントした本人だけ） / 許さない
users一般ユーザーのだれでもマウントでき、だれでも外せる
defaultsrw、suid、dev、exec、auto、nouser、async をまとめたもの
loopファイル（ISO イメージなど）を、ディスクのようにマウントする

user と users は、指定すると noexec、nosuid、nodev も付いたことになります（一般ユーザーが持ち込んだ媒体から、権限を取られないように）。

umount と target is busy

マウントの中のファイルをだれかが開いている、またはだれかのカレントディレクトリがその中にあると、umount は失敗します。

中に cd したまま外そうとするエラーになるroot で実行⌘↵
cd /media/usbumount /media/usb
外に出てから外すroot で実行⌘↵
cd /umount /media/usbls /media/usb

使っているプロセスは fuser -m /media/usb や lsof /media/usb で探せます（1.10 で学びます）。umount -l（lazy）は、いますぐ木から切り離し、使っているプロセスがいなくなってから片づけます。

/mnt と /media

ディレクトリ用途
/mnt管理者が一時的に手でマウントするための場所
/mediaUSB メモリや CD などの取り外せる媒体を自動でマウントする場所。デスクトップでは /media/ユーザー名/ラベル に作られる（Red Hat 系の GNOME では /run/media/ユーザー名/…）

どちらも FHS（ファイルシステムの階層の標準）で決められた場所で、マウントポイントにする空のディレクトリを置いておく所です。

前に見たとおり、/dev/sdb のような名前は、ディスクを足すと変わることがあります。そこで、ファイルシステムを作るときに付く UUID（ほぼ重ならない長い番号）や、自分で付けるラベルで指定します。どちらも、ファイルシステムの中に書かれているので、つなぐ場所や順番が変わっても同じです。

  • noauto は「起動時（mount -a）にはマウントしない」。fstab に書いてあれば、mount /media/cdrom とマウントポイントだけで手でマウントできる
注意本物との違い
  • この小さな Linux には、ブロックデバイス（ディスクの区画）、カーネルモジュール、スワップ、LVM がありません。fdisk、lsmod、mkfs、mkswap、blkid、lvcreate などは、Debian 12 の Docker で実行した出力を ```console で載せました
  • この Linux の mount は noexec などのオプションを表示しません。また mount -a は、fstab を読まずに一覧を表示します
要点まとめ
  • ドライバの多くはカーネルモジュール。一覧は lsmod、読み込みは modprobe（依存も解決）、insmod（ファイルのパス、依存なし）。外すのは rmmod か modprobe -r。置き場所は /lib/modules/$(uname -r)/
  • 装置の情報は /sys（sysfs）、/proc、/dev。PCI は lspci（-k でドライバ）、USB は lsusb（-t で木）。udev が uevent を受けて /dev を整え（規則は /etc/udev/rules.d/）、dbus がデスクトップへ知らせる
  • HDD は回転する円盤、SSD はフラッシュで速い（rotational が 0）。光学ドライブは /dev/sr0
  • MBR：先頭 512 バイト、基本 4 つまで（拡張 + 論理、論理は 5 番から）、2 TiB まで。GPT：既定 128 個、2 TiB 超、末尾に控え、UEFI と組む。ESP は FAT で /boot/efi
  • fdisk（MBR。p 表示、n 作る、t 種類、w 書く、q やめる）、gdisk（GPT）、parted（すぐ書く）
  • /var、/home、/boot は分けられる。/etc などは / から分けられない
  • LVM：PV（pvcreate）→ VG（vgcreate）→ LV（lvcreate -L 量 -n 名前 VG）。/dev/VG/LV。lvextend -r で FS も広げる。XFS は縮められない。スナップショットは lvcreate -s
  • mkfs -t 種類 = mkfs.種類。-t を省くと ext2。ジャーナル：ext3/ext4/XFS。Btrfs はコピーオンライトとスナップショット。VFAT は USB と ESP。tmpfs はメモリで mkfs 不要
  • スワップは mkswap → swapon。swapon -a は fstab の全部、swapon --show／-s／/proc/swaps で確認、swapoff で止める
  • mount -o ro,remount など。defaults = rw, suid, dev, exec, auto, nouser, async。使用中だと umount は target is busy
  • /etc/fstab の 6 欄：何を・どこに・種類・オプション・dump・fsck（/ は 1、ほか 2、0 は検査なし）。UUID= と LABEL= で書く。調べるのは blkid、lsblk -f
  • /mnt は一時的な手動マウント、/media は取り外せる媒体の自動マウント
