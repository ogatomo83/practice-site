3.2シェル変数と環境変数：set、export、env、unset

シェルの変数は 2 種類です。名前=値 で作っただけのシェル変数は、そのシェルの中にしかありません。export すると環境変数になり、そのシェルが起動するコマンド（子プロセス）にコピーされます（図解 Linux 2.6、7.9）。

試験では「どのコマンドで、どの変数が見えるか」が問われます。小さな Linux で確かめます。

シェル変数は env には出ないエラーになる⌘↵
city=Tokyoset | grep cityenv | grep citysh -c 'echo "child sees [$city]"'

set には出ますが、env には出ません（grep が 1 行も見つけられず、終了ステータス 1 になりました）。子のシェルにも渡っていません。

export すると環境変数になる⌘↵
export cityenv | grep cityexport -p | grep citysh -c 'echo "child sees [$city]"'unset cityecho "[$city]"

export -p の表示は、小さな Linux の sh では export city="Tokyo"、bash では declare -x city="Tokyo" の形になります。

最後の 2 行のように、unset は変数そのものを消します。消した変数を取り出しても、エラーにはならず空になります。

env 名前=値 コマンド は、そのコマンドにだけ環境変数を足して（変えて）実行します。

ターミナル
$ env LANG=C sh -c 'echo $LANG'C$ echo $LANGja_JP.UTF-8

シェル自身の LANG は変わっていません。名前=値 コマンド と書いても同じです。

コマンド働き
名前=値シェル変数を作る（= の前後に空白を入れない）
export 名前 / export 名前=値環境変数にする（子プロセスに渡る）
export / export -p環境変数の一覧（declare -x 名前="値" の形。bash の場合）
export -n 名前環境変数の印だけを外し、シェル変数に戻す（bash）
setシェル変数と環境変数の全部（bash では関数の定義も）を表示する
set -o / set -o オプション名 / set +o オプション名シェルのオプションの一覧 / 有効にする / 無効にする
unset 名前変数を消す。unset -f 名前 なら関数を消す
env / printenv環境変数の一覧
env 名前=値 コマンド環境変数を足してコマンドを実行する
env -i コマンド環境変数を空にしてコマンドを実行する
注意試験の注意：set と env の違い

「export していない変数も含めて、すべての変数を表示する」のは set です。env・printenv・export -p は環境変数だけです。また、set は引数を付けると別の働き（シェルのオプションや位置パラメータの設定）になります。set -o noclobber のような形も、ここで出てきます（1.03.3）。

3.3引用符とパス：echo が何を表示するか

シェルは、コマンドを実行する前に $名前 や $(…) を展開します（図解 Linux 2.7）。引用符は、展開を止めたり、空白を守ったりするためのものです。試験では「次の echo の出力はどれか」の形でよく問われます。

書き方名前中で $変数 は中で ` コマンド ・$(コマンド)` は空白
'…'シングルクォート（一重引用符）展開しない展開しない守る
"…"ダブルクォート（二重引用符）展開する展開する守る
\文字バックスラッシュ（エスケープ）次の 1 文字だけ、特別な意味をなくす同じ\ で空白も守れる
` … `バッククォート—中のコマンドの出力に置き換える（$(…) と同じ）—
引用符の違い⌘↵
echo "$HOME" '$HOME' \$HOMEecho "today: `date +%Y`" 'today: `date +%Y`'x='a    b'echo $xecho "$x"echo -n "no newline"; echo "<"echo -e "a\tb"

echo $x では、展開の後で空白が単語の区切りとみなされ、a と b の 2 つの引数になります。echo は引数を空白 1 つでつなぐので、空白が縮みました。"$x" と囲めば 1 つの引数のままです。

echo 自身のオプションも、ときどき問われます（上の最後の 2 行）。

オプション意味
-n最後に改行を出さない
-e\t（タブ）や \n（改行）などを解釈する（bash の組み込みの echo）

絶対パス、相対パス、. と ..

/ で始まるパスが絶対パス、それ以外が相対パスです（図解 Linux 3.3）。相対パスは、いまのディレクトリ（pwd で表示される場所）から数えます。

書き方意味
/ で始まる絶対パス（ルートから）
.いまのディレクトリ
..1 つ上のディレクトリ
~ホームディレクトリ（シェルが展開する）
cd -1 つ前にいたディレクトリへ戻る（$OLDPWD）
cd（引数なし）ホームディレクトリへ
pwd と相対パス⌘↵
cd /usr/binpwdcd ../sharepwdcd -cdpwd

カレントディレクトリにあるスクリプトを実行するときは、./hello.sh のように ./ を付けます。. は ふつう PATH に入っていないので、名前だけでは見つからないからです（図解 Linux 2.4）。

. はもう 1 つ、コマンドとしても使われます。. ファイル（source ファイル と同じ）は、ファイルの中身をいまのシェルで実行します。bash ファイル は新しい bash（子プロセス）で実行するので、中で設定した変数は残りません（図解 Linux 7.10）。

./ で実行する、. で読み込む⌘↵
cat hello.shchmod +x hello.sh./hello.sh. ./hello.sh

./hello.sh で実行するには、実行の権限（chmod +x）が要ります。. ./hello.sh は、ファイルを読めれば実行の権限がなくても動きます。

Linux の多くのディストリビューションで、ログインしたときのシェルは bash（Bourne Again SHell）です。bash と打つと、いまのシェルの子として新しい bash が起動し、exit で元に戻ります。小さな Linux のシェルは sh ですが、この章の書き方は bash でもそのまま動きます。シェルの設定ファイル（~/.bashrc など）は 1.06 で扱います。

3.4履歴と man：前のコマンドと使い方を呼び出す

bash は、打ったコマンドを履歴として覚えています。組み込みコマンドの history で番号つきの一覧が出ます。履歴はシェルを終えるときに、ホームディレクトリの .bash_history（HISTFILE 変数で決まる）に書き出されます。

history で一覧を見る⌘↵
echo oneecho twohistory 3

本物の bash では、履歴を ! で呼び出せます（履歴展開）。小さな Linux にはこの書き方がないので、Debian 12 の bash での例を見せます。呼び出したコマンドは、実行する前に画面に表示されます。

ターミナル
$ echo hellohello$ !!echo hellohello$ echo worldworld$ history 4    1  echo hello    2  echo hello    3  echo world    4  history 4$ !1echo hellohello$ !ececho hellohello
書き方意味
!!直前のコマンド
!番号履歴のその番号のコマンド（!1）
!-番号番号だけ前のコマンド（!-2 は 2 つ前）
!文字列その文字列で始まるいちばん新しいコマンド
!?文字列?その文字列を含むいちばん新しいコマンド
^古い^新しい直前のコマンドの「古い」を「新しい」に置き換えて実行
history 数最後の数件を表示
history -cメモリの履歴を消す
Ctrl + R履歴を検索する
変数意味
HISTFILE履歴を保存するファイル。既定は ~/.bash_history
HISTSIZEメモリに覚える件数
HISTFILESIZEファイルに残す行数
HISTCONTROLignorespace（空白で始まる行を残さない）、ignoredups（続けて同じ行を残さない）、ignoreboth（両方）
注意試験の注意：履歴のファイル名

履歴のファイルは ~/.bash_history です。~/.history や ~/.bash_log ではありません。また、ファイルに書かれるのはシェルを終えるときなので、別の端末で開いている bash の履歴は、その bash を終えるまでファイルに現れません。

man：マニュアルとセクション番号

man コマンド名 で、マニュアルを表示します。表示には less が使われるので、q で閉じ、/文字列 で検索、スペースで次のページです。マニュアルはセクション（章）に分かれています。

セクション内容例
1ユーザーのコマンドls(1)、passwd(1)

同じ名前が複数のセクションにあるときは、番号を付けて選びます。passwd はコマンド（1）と、ファイル /etc/passwd の書式（5）の両方にあります。

ターミナル
$ man -f passwdpasswd (1)           - change user passwordpasswd (5)           - the password file$ man 5 passwdPASSWD(5)               File Formats and Configuration               PASSWD(5) NAME       passwd - the password file...$ man -k "copy files"cp (1)               - copy files and directoriesinstall (1)          - copy files and set attributes$ man -w 5 passwd/usr/share/man/man5/passwd.5.gz
書き方意味

LS(1) や PASSWD(5) の括弧の中がセクション番号です。問題文に crontab(5) とあれば「crontab の設定ファイルの書式のページ」、crontab(1) なら「crontab コマンドのページ」です。

cat と less

小さな Linux のホームディレクトリには、練習用のファイル（fruits.txt、numbers.txt、poem.txt、scores.csv、memo.txt）があります。

cat のオプション⌘↵

cat のオプション意味
-nすべての行に番号を付ける

-E行の終わりに $ を表示する

head と tail

head と tail⌘↵

書き方意味
head ファイル / tail ファイル先頭 / 末尾の 10 行（既定）

wc

wc は 行・単語・バイト の順。nl は空行を飛ばす⌘↵
wc poem.txtwc -l fruits.txt numbers.txtwc -c memo.txtwc -m memo.txtnl blank.txtcat -n blank.txt

wc の出力は、行数、単語数、バイト数の順です。ファイルを複数与えると、最後に total（合計）の行が付きます。memo.txt は日本語なので、バイト数（-c）と文字数（-m）が違います。

オプション数えるもの

nl

nl は行番号を付けます。上の最後の 2 つを比べると、cat -n と違い、既定では空の行に番号を付けないことがわかります。

番号の付け方は、オプションで変えられます（小さな Linux の nl にはオプションがないので、Debian 12 での例です）。

ターミナル

オプション意味
-b a空行も含めて、すべての行に番号を付ける
-b t空でない行だけ（既定）
-b n番号を付けない
-v 数最初の番号
-i 数番号の増やし方
-w 数番号の桁の幅
-s 文字列番号の後に付ける区切り（既定はタブ）
-n ln / rn / rz左寄せ / 右寄せ（既定）/ 右寄せで 0 を詰める

od

od（octal dump）は、ファイルの中身をバイトの値で表示します。改行やタブのような見えない文字を確かめるときに使います。左端の数字は、そのバイトの位置（既定は 8 進数）です。

od で見えない文字を見る⌘↵
printf 'a\tb\n' > tab.txtod -c tab.txtod -t x1 tab.txtod -A x -c tab.txt

オプションを付けない od は、2 バイトずつを 8 進数で表示します（Debian 12）。

ターミナル
$ printf 'AB\n' > ab$ od ab0000000 041101 0000120000003$ od -x ab0000000 4241 000a0000003
オプション表示のしかた
（なし）2 バイトずつ 8 進数
-c文字（\n、\t など）
-b1 バイトずつ 8 進数
-x2 バイトずつ 16 進数
-t x1 / -t o1 / -t c型を指定（1 バイトずつ 16 進 / 8 進 / 文字）
-A x / -A d / -A n左端の位置を 16 進 / 10 進 / 表示しない

cut と paste

cut で切り、paste でつなぐ⌘↵
cut -d, -f1,3 scores.csv | head -n 3cut -d, -f2- scores.csv | head -n 2cut -c 1-3 fruits.txt | head -n 2printf 'a\tb\tc\n' | cut -f 2paste fruits.txt numbers.txt | head -n 3paste -d, fruits.txt numbers.txt | head -n 2paste -s -d+ numbers.txt
cut のオプション意味
-d 文字区切りの文字。既定はタブ
-f 列取り出す列。1,3、2-4、2-（2 列目から最後まで）
-c 位置取り出す文字の位置（1-3）
-b 位置取り出すバイトの位置
-s区切りの文字を含まない行を出さない

後半の paste は、ファイルの同じ行番号の行を横につなぎます。区切りは既定でタブです。

paste のオプション意味
-d 文字つなぐ文字（既定はタブ）
-s1 つのファイルの全部の行を、1 行に横につなぐ

join：共通の列でつなぐ

join は、データベースの結合と同じことをします。両方のファイルが、つなぐ列で並べ替え済みであることが前提です（並んでいないと join: input is not in sorted order と警告します）。小さな Linux にはないので、Debian 12 での例です。

ターミナル
$ cat names.txt1 sato2 suzuki3 tanaka$ cat subj.txt1 math3 english4 art$ join names.txt subj.txt1 sato math3 tanaka english$ join -a 1 names.txt subj.txt1 sato math2 suzuki3 tanaka english$ join -v 2 names.txt subj.txt4 art$ join -o 1.2,2.2 names.txt subj.txtsato mathtanaka english$ join -t, -1 2 -2 1 c1.csv c2.csv1,sato,math2,suzuki,art

最後の例は、c1.csv（sato,1 の形）の 2 列目と、c2.csv（1,math の形）の 1 列目でつないでいます。

join のオプション意味
（なし）両方の 1 列目が同じ行をつなぐ。区切りは空白
-t 文字区切りの文字
-1 列 / -2 列1 つ目 / 2 つ目のファイルの、つなぐ列
-a 11 つ目のファイルの、相手がない行も出す
-v 22 つ目のファイルの、相手がない行だけを出す

3.8リダイレクト：<、>、>>、2>、2>&1

どのプロセスも、3 つの口を持って始まります。標準入力（0）、標準出力（1）、標準エラー（2）です。数字はファイルディスクリプタの番号です（図解 Linux 5.1）。リダイレクトは、この口の行き先をファイルに付け替えるシェルの書き方です。

> は上書き、>> は追記、2> はエラーだけエラーになる⌘↵
echo first > out.txtecho second >> out.txtcat out.txtwc -l < fruits.txtls fruits.txt nope > ok.txt 2> ng.txtcat ok.txtcat ng.txt
書き方意味
> ファイル（1> と同じ）標準出力をファイルへ。ファイルがあれば空にしてから書く
>> ファイル標準出力をファイルの末尾に足す
< ファイル（0< と同じ）標準入力をファイルから読む
2> ファイル標準エラーをファイルへ
2>> ファイル標準エラーをファイルの末尾に足す
> ファイル 2>&1標準出力と標準エラーの両方をファイルへ
&> ファイル上と同じ（bash の書き方）
2> /dev/nullエラーを捨てる
<< 終わりの印次の行から「終わりの印」だけの行までを標準入力にする（ヒアドキュメント）
<<< 文字列文字列を標準入力にする（ヒアストリング。bash）
>| ファイルnoclobber が有効でも上書きする

2>&1 は書く順番で意味が変わる

2>&1 は「口 2 を、その時点で口 1 が向いている先に向ける」という意味です。そのため、書く順番で結果が変わります（図解 Linux 9.5）。

順番を逆にすると、エラーは画面に出るエラーになる⌘↵
ls fruits.txt nope > all.txt 2>&1cat all.txtls fruits.txt nope 2>&1 > all2.txtcat all2.txt

パイプとの組み合わせも同じ考え方です。| は、リダイレクトより先に口 1 をパイプにつなぎます。

書き方パイプに流れるもの
コマンド | wc -l標準出力だけ（エラーは画面へ）
コマンド 2>&1 | wc -l標準出力と標準エラーの両方
コマンド |& wc -l上と同じ（bash の書き方）
コマンド 2>&1 > /dev/null | wc -l標準エラーだけ（標準出力は捨てる）
注意試験の注意：2>&1 の位置

「標準出力と標準エラーの両方を log に書く」正しい書き方は コマンド > log 2>&1（または &> log）です。コマンド 2>&1 > log ではエラーが画面に残ります。2>1 と書くと、1 という名前のファイルができるだけです。& を忘れないでください。

noclobber：うっかりの上書きを防ぐ

> は、ファイルがあれば中身を消してから書きます。bash の set -o noclobber（set -C と同じ）を有効にすると、> で既にあるファイルを上書きしようとしたときにエラーになります。小さな Linux にはないので、Debian 12 の bash での例です。

ターミナル

>| は、noclobber を無視して上書きします。>>（追記）は noclobber の対象ではありません。

3.9パイプ、tee、xargs

パイプ | は、左のコマンドの標準出力を、右のコマンドの標準入力につなぎます（図解 Linux 5.4）。つなぐのは標準出力だけで、標準エラーは通りません。

tee は、標準入力を標準出力とファイルの両方に書きます。パイプの途中の結果を残したいとき、画面で見ながらファイルにも保存したいときに使います。

xargs は、標準入力から読んだ言葉を、指定したコマンドの引数に並べて実行します。rm や cp のように、標準入力を読まず引数で相手を受け取るコマンドに、パイプの結果を渡すときに使います。

tee と xargs⌘↵
sort fruits.txt | uniq -c | sort -rn | tee count.txt | head -n 1wc -l count.txtecho a b c d e | xargs -n 2echo fruits.txt | xargs -t wc -lls *.txt | xargs -I {} cp {} {}.bakls *.bak | head -n 3

-t は、実行するコマンドを標準エラーに表示してから実行します。-I {} は、{} の場所に 1 行ずつ入れて、1 行に 1 回実行します。

tee / xargs意味
tee ファイル標準入力を、標準出力とファイルへ（ファイルは上書き）
tee -a ファイルファイルに追記する
tee f1 f2複数のファイルへ同時に
xargs コマンド標準入力の言葉を、コマンドの引数に並べて実行する（コマンドを省くと echo）
xargs -n 数1 回に渡す引数の数
xargs -I {} コマンド {}{} を 1 行ずつの入力に置き換え、1 行に 1 回実行する
xargs -t実行するコマンドを表示する
xargs -0区切りを空白や改行ではなく NUL 文字にする（find -print0 と組み合わせる）

ファイル名に空白が入っていると、xargs はそこで区切ってしまいます。find … -print0 | xargs -0 … と書くと、名前の終わりを NUL 文字（\0）で区切るので、空白を含む名前も正しく渡せます。

ターミナル

sudo echo text > /etc/motd は失敗します。> /etc/motd を開くのは、root ではないいまのシェルだからです。echo text | sudo tee /etc/motd なら、root で動く tee がファイルを開きます。追記なら sudo tee -a です（図解 Linux 5.3）。

3.10正規表現：基本（BRE）と拡張（ERE）

正規表現は、文字の並びの「型」を書く書き方です。grep、sed、less や vi の検索で使えます。マニュアルでは regex(7) に説明があります（man 7 regex）。

正規表現には 2 つの流儀があります。基本正規表現（BRE） と 拡張正規表現（ERE） です。違いは、+、?、{ }、( )、| を、そのまま書くか \ を付けて書くか、だけです。

意味BRE（grep、sed）ERE（grep -E、egrep、sed -E）
任意の 1 文字..
直前の 0 回以上のくり返し**
行頭 / 行末^ / $^ / $
どれか 1 文字 / それ以外の 1 文字[abc] / [^abc][abc] / [^abc]
範囲[a-z]、[0-9][a-z]、[0-9]
直前の 1 回以上\+（GNU の拡張）+
直前の 0 回か 1 回\?（GNU の拡張）?
直前の n 回 / n〜m 回\{n\} / \{n,m\}{n} / {n,m}
まとまり（グループ）\( \)( )
または\|（GNU の拡張）|
文字そのもの（. など）\.\.

文字の種類の名前も使えます。[[:digit:]]（数字）、[[:alpha:]]（英字）、[[:upper:]]（大文字）、[[:lower:]]（小文字）、[[:space:]]（空白）です。外側の [ ] が要ることに注意してください。GNU の grep と sed では、\< と \> で単語の始まりと終わりも表せます。

正規表現の部品⌘↵
grep 'an*a' fruits.txtgrep -E 'ap+le|^g' fruits.txtgrep 'p\{2\}' fruits.txtgrep -E '^[a-c].*a$' fruits.txtgrep 'a.e' fruits.txtgrep '\.' poem.txt | wc -lgrep '.' poem.txt | wc -l

最後の 2 つの違いに注意してください。\. はピリオドそのもの（3 行）、. は「何か 1 文字」なので、空でない行すべて（5 行）に合います。

よく使う形に、^$（行頭のすぐ後が行末＝空行）と ^#（# で始まる行＝設定ファイルのコメント行）があります。grep -v '^#' 設定ファイル | grep -v '^$' で、コメントと空行を除いた中身だけを見られます。

注意試験の注意：* はワイルドカードと違う

シェルのワイルドカードの * は「任意の文字列」ですが、正規表現の * は「直前の文字の 0 回以上のくり返し」です。正規表現で「任意の文字列」は .* です。grep 'a*' はすべての行に合います（a が 0 回でもよいため）。また、パターンはシングルクォートで囲みます。囲まないと、シェルが * や $ を先に展開してしまいます。

3.13vi 以外のエディタと EDITOR

crontab -e や git commit のように、途中でエディタを開くコマンドがあります。どのエディタを開くかは、環境変数 EDITOR（または VISUAL）で決まります。

ターミナル
$ export EDITOR=vi$ crontab -e          ← vi で開く$ export EDITOR=nano$ crontab -e          ← nano で開く

いつも同じエディタを使うなら、export EDITOR=vi を ~/.bashrc などに書いておきます。Debian 系では、EDITOR が決まっていないときに使う既定のエディタ（/usr/bin/editor）を、update-alternatives や select-editor で選べます。Debian 12 の既定は nano です。

nano は、画面の下に操作の一覧が出る、初心者向けのエディタです。モードはなく、打った文字はそのまま入ります。^ は Ctrl キーの意味です。

nano のキー働き
Ctrl + O保存する（Write Out）
Ctrl + X終わる（保存していなければ、保存するかを聞く）
Ctrl + W検索する（Where Is）
Ctrl + K / Ctrl + U行を切り取る / 貼り付ける
Ctrl + Gヘルプ

emacs は、GNU プロジェクトの高機能なエディタです。こちらもモードはなく、Ctrl（C-）と Alt（M-）の組み合わせで操作します。

emacs のキー働き
C-x C-s保存する
C-x C-c終わる
C-x C-fファイルを開く
C-f / C-b / C-n / C-p右 / 左 / 下 / 上
C-g途中の操作を取り消す

小さな Linux にはエディタがありません。ファイルを作るときは、echo … > ファイル や、ヒアドキュメント（cat > ファイル <<END … END）を使ってください。

要点まとめ
  • set はシェル変数も環境変数も全部、env・printenv・export -p は環境変数だけ。export で子に渡り、unset で消える。env 名前=値 コマンド は 1 回だけ変える
  • '…' は何も展開しない、"…" は $ と ` ` を展開する、\` は 1 文字だけ守る
  • 履歴は ~/.bash_history（シェルを終えるときに書く）。!! 直前、!番号、!文字列、history -c で消す
  • man のセクション：1 コマンド、5 設定ファイルの書式、7 その他（regex）、8 管理コマンド。man -k = apropos、man -f = whatis
  • cut -d -f（既定の区切りはタブ）、paste（行番号で横に）、join（共通の列で。並べ替え済みが前提）、nl（既定で空行を飛ばす）、split（1000 行ごとに xaa …）、expand（タブ→空白）と unexpand（空白→タブ、既定は行頭だけ）、fmt（幅 75 に詰め直す）、pr（66 行のページ、ヘッダ付き）、od（バイトを 8 進・16 進で）
  • tail -n +N は N 行目から、tail -f で追いかける。uniq の前に sort
  • > file 2>&1 で両方を file へ（逆順はエラーが画面に残る）。set -o noclobber で > の上書きを禁止、>| で強行
  • tee は流れを分けてファイルにも書く（-a で追記）。xargs は標準入力を引数にする（-n、-I {}、-0）
  • BRE と ERE の違いは + ? { } ( ) | に \ が要るかどうか。grep -E = egrep、grep -F = fgrep（固定の文字列）
  • sed -n '…p' で選んだ行だけ、d で消す、s///g で全部置き換え、-i でファイルを書き換え
  • vi：起動はコマンドモード。i a o で挿入、ESC で戻る。dd yy p、dw cw、/ ? n N、:wq = ZZ、:q! で捨てて終わる、:e! で読み直す
