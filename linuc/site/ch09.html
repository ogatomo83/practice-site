9.1時計は 2 つある：システムクロックとハードウェアクロック

Linux の機械には、時計が 2 つあります。

  • ハードウェアクロック（RTC、リアルタイムクロック）：マザーボードの上の時計です。電池で動くので、電源を切っても進みます
  • システムクロック：カーネルが数えている時計です。プログラムが時刻を聞くと、こちらが答えます。電源を切ると消えます

起動するとき、カーネルはハードウェアクロックを読んで、システムクロックの初めの値にします。そのあとは 2 つが別々に進むので、少しずつずれます。ずれを NTP（後の節）で直すのは、システムクロックのほうです。

date：システムクロックを読む・変える

date はシステムクロックを表示します。+ で始まる引数を与えると、その書式で表示します。小さな Linux で試します（この機械の時計は、いつも 2026 年 4 月 1 日の 9 時から始まります）。

date の書式⌘↵
datedate -udate +%Y-%m-%ddate "+%Y/%m/%d %H:%M:%S"

-u は UTC（協定世界時）で表示します。日本の時刻（JST）は UTC より 9 時間進んでいます。書式に空白を含めるときは、引数全体を引用符で囲みます。

いまではない時刻を表示する⌘↵
date +%sdate -d @0date -d "2024-01-01" +%A

%s は 1970 年 1 月 1 日 0 時（UTC）からの秒数です。-d は「いま」の代わりに指定した時刻を表示します。@0 は「秒数 0 の時刻」です。

書式意味例
%Y / %y年（4 桁 / 下 2 桁）2026 / 26
%m / %d月 / 日（2 桁）04 / 01
%H / %M / %S時（00〜23）/ 分 / 秒09 / 00 / 00
%a / %A曜日（短い / 長い）Wed / Wednesday
%F / %T%Y-%m-%d / %H:%M:%S2026-04-01 / 09:00:00
%Z / %zタイムゾーンの略称 / 時差JST / +0900
%s1970-01-01 00:00 UTC からの秒数1775001600
%j1 年の何日目か091

時刻を変えるには root が必要です。書き方は 2 つあります。

ターミナル
# date -s "2026-04-01 09:00:00"# date 040109002026

2 つめは MMDDhhmm[[CC]YY][.ss] の形です。月・日・時・分の順で、年は最後です。date 040109002026 は「4 月 1 日 9 時 0 分、2026 年」です。

注意試験の注意：date の数字の並び

date に直接与える数字は月日時分年の順（MMDDhhmmYYYY）で、年が最後です。YYYYMMDDhhmm と思い込むと間違えます。表示の書式（+%Y%m%d）とは別物です。

hwclock：ハードウェアクロックを読む・書く

hwclock はハードウェアクロックを扱います（root で実行します）。

オプション長い形すること
-r--showハードウェアクロックを表示する（何も付けないときと同じ）
-w--systohcシステムクロック → ハードウェアクロック（sys to hc）
-s--hctosysハードウェアクロック → システムクロック（hc to sys）
-u / -l--utc / --localtimeハードウェアクロックを UTC / 地方時として扱う

長い形は「どちらからどちらへ」を名前で表しています。ハードウェアクロックのずれの記録などは /etc/adjtime に書かれます。systohc は system to hardware clock です。date で時刻を直したあと、hwclock -w で書き込んでおくと、次の起動でも正しい時刻から始まります。

注意試験の注意：-w と -s の向き

「システムクロックをハードウェアクロックに合わせる」は -s（hctosys）、「ハードウェアクロックをシステムクロックに合わせる」は -w（systohc）です。「〜に合わせる」の「〜」が写す元です。迷ったら長い形を思い出してください。

9.2タイムゾーンと NTP：正しい時刻に合わせ続ける

タイムゾーン

システムクロックは、カーネルの中では UTC で数えています。それを「日本時間」で表示するのは、タイムゾーンの設定です。タイムゾーンの情報は、/usr/share/zoneinfo/ の下に地域ごとのファイルとして入っています（Asia/Tokyo、America/New_York、UTC …）。

場所役目
/usr/share/zoneinfo/タイムゾーンのデータ（地域ごとのバイナリのファイル）
/etc/localtimeシステムのタイムゾーン。zoneinfo のファイルへのシンボリックリンク（またはコピー）
/etc/timezoneDebian 系にある、タイムゾーンの名前を書いたテキスト（例：Etc/UTC）。Red Hat 系にはない
環境変数 TZそのプロセス（とその子）だけのタイムゾーン。/etc/localtime より優先する

Docker の debian:12 と rockylinux:9 で確かめた形です。

ターミナル
$ ls -l /etc/localtime                       # debian:12lrwxrwxrwx 1 root root 27 Nov  4 21:23 /etc/localtime -> /usr/share/zoneinfo/Etc/UTC$ cat /etc/timezoneEtc/UTC$ ls -l /etc/localtime                       # rockylinux:9lrwxrwxrwx 1 root root 25 Nov 19  2023 /etc/localtime -> ../usr/share/zoneinfo/UTC$ ls -l /etc/timezonels: cannot access '/etc/timezone': No such file or directory

/etc/localtime はシンボリックリンクです（図解 Linux 11.4）。システムのタイムゾーンを日本にするには、リンクを張り替えます。TZ を使えば、そのコマンドだけ別のタイムゾーンで表示できます。

ターミナル
# ln -sf /usr/share/zoneinfo/Asia/Tokyo /etc/localtime

TZ を付けたコマンドは、システムの設定（ここでは UTC のまま）とは別のタイムゾーンで表示します。debian:12 での結果です。

ターミナル
$ dateMon Nov 16 11:16:42 UTC 2026$ TZ=Asia/Tokyo dateMon Nov 16 20:16:42 JST 2026$ TZ=America/New_York dateMon Nov 16 06:16:42 EST 2026

tzselect は、大陸と国を番号で選ばせて、それに当たる TZ の値を表示するだけのコマンドです。システムの設定は変えません。表示された値を ~/.profile に TZ='Asia/Tokyo'; export TZ と書くのは、利用者の仕事です。

ターミナル
$ tzselectPlease select a continent, ocean, "coord", or "TZ". … 4) Asia …#? 4 …24) Japan#? 24 …Therefore TZ='Asia/Tokyo' will be used. …Asia/Tokyo

timedatectl：systemd の時刻の窓口

systemd の機械では、timedatectl が時刻とタイムゾーンをまとめて扱います。

ターミナル
$ timedatectl               Local time: Mon 2026-11-16 20:19:52 JST           Universal time: Mon 2026-11-16 11:19:52 UTC                 RTC time: Mon 2026-11-16 11:19:52                Time zone: Asia/Tokyo (JST, +0900)System clock synchronized: yes              NTP service: active          RTC in local TZ: no

1 回でシステムクロック（Local / Universal time）、ハードウェアクロック（RTC time）、タイムゾーン、NTP で合っているかが見えます。

コマンドすること
timedatectl（status）状態を表示する
timedatectl set-timezone Asia/Tokyoタイムゾーンを変える（/etc/localtime を張り替える）
timedatectl list-timezones選べるタイムゾーンの一覧
timedatectl set-time "2026-04-01 09:00:00"時刻を変える（NTP が有効だと拒まれる）
timedatectl set-ntp trueNTP による同期を有効にする

NTP：ネットワークで時刻を合わせる

NTP（Network Time Protocol）は、ネットワーク越しに時刻を合わせる決まりです。UDP の 123 番ポートを使います。サーバは階層になっていて、その段を stratum（ストラタム）と呼びます。数字が小さいほど、原子時計などの基準に近くなります。

pool.ntp.org は、世界中のボランティアが提供する多数の NTP サーバをまとめた名前です。引くたびに違うサーバの番地が返ります。2.debian.pool.ntp.org や 2.rocky.pool.ntp.org のように、ディストリビューションごとの名前もあります。

NTP を話すプログラムは、主に 3 つです。

プログラム形設定ファイル状態を見る
chronydデーモン。いまの Red Hat 系・Debian 系の標準Red Hat 系 /etc/chrony.conf、Debian 系 /etc/chrony/chrony.confchronyc sources、chronyc tracking
ntpdデーモン。古くからの実装/etc/ntp.conf（ntpsec では /etc/ntpsec/ntp.conf）ntpq -p
ntpdate1 回だけ合わせて終わるコマンドなし（ntpdate サーバ と引数で）—

デーモン（chronyd、ntpd）は、時刻を少しずつ速めたり遅めたりして合わせ続けます。時刻が急に飛ぶと、ログの順番や cron が乱れるからです。ntpdate は、その場で一気に合わせます。

rockylinux:9 に chrony を入れたときの /etc/chrony.conf の設定の行です（コメントを除く）。

conf
pool 2.rocky.pool.ntp.org iburstsourcedir /run/chrony-dhcpdriftfile /var/lib/chrony/driftmakestep 1.0 3rtcsynckeyfile /etc/chrony.keysntsdumpdir /var/lib/chronyleapsectz right/UTClogdir /var/log/chrony
行意味
pool 名前 iburst複数のサーバを返す名前を、時刻の元にする（1 台なら server 名前）。iburst は起動直後に速く合わせる
driftfile時計の進み・遅れの癖を覚えておくファイル
makestep 1.0 3最初の 3 回の更新では、1 秒以上ずれていたら一気に合わせる
rtcsyncハードウェアクロックもときどき合わせる

ntpd の ntp.conf も、server / pool の行で相手を書く形は同じです。

chronyc sources と ntpq -p は、どちらも「どのサーバを使っているか」の一覧です。Docker の debian:12 で動かした出力です。

ターミナル

タイムゾーンの選び方を表示するだけtzselect

9.3rsyslog：facility.priority で振り分ける

Linux のログには、2 つの仕組みがあります。昔からの syslog（いまの実装は rsyslog）と、systemd の journald（次の節）です。多くのディストリビューションは、両方を動かしています。journald が集めたものを rsyslogd が受け取り、テキストのファイルに書きます。

ログを書きたいプログラムは、「どこから来たか（facility）」と「どれくらい重大か（priority）」の 2 つの印を付けて、メッセージを送ります。rsyslogd は、設定ファイル /etc/rsyslog.conf（と /etc/rsyslog.d/*.conf）の行と照らして、行き先を決めます。

設定の書式

1 行が 1 つの規則です。

facility.priority        出力先

左の facility.priority を セレクタ、右を アクションと呼びます。Docker の debian:12 の /etc/rsyslog.conf にある規則の行です。

conf
*.*;auth,authpriv.none        -/var/log/syslogauth,authpriv.*            /var/log/auth.logcron.*                -/var/log/cron.logkern.*                -/var/log/kern.logmail.*                -/var/log/mail.loguser.*                -/var/log/user.log*.emerg                :omusrmsg:*

小さな Linux にも、同じ規則を置いておきました（rsyslogd は動いていないので、ファイルを読むだけです）。

この章の準備最初の実行のときに、自動で流れるコマンド
cat > /etc/rsyslog.conf <<'EOT'# /etc/rsyslog.conf（debian:12 の規則の部分）module(load="imuxsock") # provides support for local system loggingmodule(load="imklog")   # provides kernel logging support$IncludeConfig /etc/rsyslog.d/*.conf *.*;auth,authpriv.none        -/var/log/syslogauth,authpriv.*            /var/log/auth.logcron.*                -/var/log/cron.logkern.*                -/var/log/kern.logmail.*                -/var/log/mail.loguser.*                -/var/log/user.log*.emerg                :omusrmsg:*EOT
規則の行だけを取り出す⌘↵
grep -v '^#' /etc/rsyslog.conf | grep -v '^$' | grep -v '^module' | grep -v '^\$'grep 'mail' /etc/rsyslog.conf

facility と priority

facility何のログか
auth / authpriv認証（ログイン、su、sudo）。authpriv は秘密を含むもの
croncron と at
daemonほかのデーモン
kernカーネル
mailメール
user一般のプログラム（logger の既定）
lpr、news、uucp、syslog印刷、ニュース、UUCP、rsyslogd 自身
local0〜local7利用者が自由に使ってよい

priority は 8 段階です。上ほど重大で、番号が小さくなります。

番号priority意味
0emerg（panic）システムが使えない
1alertすぐ対処が必要
2crit致命的
3err（error）エラー
4warning（warn）警告
5notice通常だが重要
6info情報
7debugデバッグ

覚え方は頭文字で「e a c e w n i d」です。

セレクタの記号

priority を 1 つ書くと、その priority 以上（より重大なもの）すべてを意味します。

書き方選ぶもの
mail.errmail の err・crit・alert・emerg（err 以上）
mail.=errmail の err だけ
mail.*mail のすべての priority
mail.nonemail は 1 つも選ばない（ほかの指定から除く）
mail.*;mail.!errmail のうち、err 以上を除いたもの（! は除く）
auth,authpriv.*, で facility を並べる
*.info;mail.none; で条件を続ける。全 facility の info 以上から、mail を除く

Docker の debian:12 で、local0 の規則を置いて logger で送り、どのファイルに入るかを確かめました。

ターミナル
# cat /etc/rsyslog.d/50-test.conflocal0.*                 /var/log/l0-all.loglocal0.err               /var/log/l0-err.loglocal0.=info             /var/log/l0-eqinfo.loglocal0.*;local0.!=debug  /var/log/l0-nodebug.log# logger -p local0.debug "msg debug"; logger -p local0.info "msg info"# logger -p local0.err "msg err";     logger -p local0.crit "msg crit"# cat /var/log/l0-err.log2026-11-16T11:16:41.261959+00:00 af2bf29d1eb0 root: msg err2026-11-16T11:16:41.262514+00:00 af2bf29d1eb0 root: msg crit# cat /var/log/l0-eqinfo.log2026-11-16T11:16:41.260889+00:00 af2bf29d1eb0 root: msg info

local0.err には err と、より重大な crit が入りました。local0.=info には info だけです。

出力先

書き方行き先
/var/log/ファイルファイル
-/var/log/ファイルファイル。- は書くたびにディスクへ同期しない（速い）
@ホストほかの機械の rsyslog へ UDP（514 番）で転送
@@ホストほかの機械の rsyslog へ TCP で転送
* または :omusrmsg:*ログインしている全員の端末に表示
ユーザー名そのユーザーがログインしていれば、端末に表示

Red Hat 系の /etc/rsyslog.conf は、新しい書き方（action(type="omfile" file="…")）で書かれていますが、セレクタは同じです。rockylinux:9 の規則です。

conf
*.info;mail.none;authpriv.none;cron.none action(type="omfile" file="/var/log/messages")authpriv.* action(type="omfile" file="/var/log/secure")mail.* action(type="omfile" file="/var/log/maillog" sync="on")cron.* action(type="omfile" file="/var/log/cron")*.emerg action(type="omusrmsg" users="*")
注意試験の注意：「以上」と「だけ」、@ と @@

mail.err は err 以上、mail.=err は err だけです。none はその facility を除きます。転送は @ が UDP、@@ が TCP です。

/var/log の主なファイル

Debian 系Red Hat 系中身
/var/log/syslog/var/log/messagesほぼすべての一般のログ
/var/log/auth.log/var/log/secure認証（ログイン、sudo、sshd）
/var/log/mail.log/var/log/maillogメール
/var/log/kern.log—カーネル
/var/log/cron.log/var/log/croncron
/var/log/wtmp、/var/log/btmp、/var/log/lastlog同じログインの記録（バイナリ。last、lastb、lastlog で読む）
/var/log/journal/同じjournald の保存先（次の節）

小さな Linux の /var/log にも、Debian 系の形のファイルがあります。syslog と auth.log は、root か adm グループの人しか読めません。

/var/log を見るroot で実行⌘↵
ls -l /var/loggrep kernel /var/log/syslog

logger：シェルからログを書く

logger は、引数の文字をログに送るコマンドです。シェルスクリプトから記録を残すのに使います。

ターミナル
$ logger "backup finished"$ logger -p local0.err -t backup "disk is full"$ tail -2 /var/log/syslog2026-11-16T02:19:52.657863+00:00 host root: backup finished2026-11-16T02:19:52.658390+00:00 host backup: disk is full
オプション意味
-p facility.priority印を付ける。付けなければ user.notice
-t タグ行に付く名前（既定はユーザー名）
-ilogger の PID を付ける
-f ファイルファイルの中身を送る

9.4journald と journalctl：systemd のログ

図解 Linux 17.7 で見たとおり、systemd のもとでは、サービスの標準出力と標準エラーは journald に集まり、ジャーナルとして保存されます。ジャーナルはバイナリ形式なので、cat ではなく journalctl で読みます。

小さな Linux でサービスを 1 つ作り、ログを残させます。標準出力に 1 行、標準エラーに 1 行書いて、眠り続けるだけのサービスです。

ログを書くサービスを作って起こすroot で実行⌘↵
cat > /usr/local/bin/tick <<'EOT'#!/bin/shecho "tick started"echo "disk almost full" >&2sleep 1000EOTchmod +x /usr/local/bin/tickcat > /etc/systemd/system/tick.service <<'EOT'[Unit]Description=Tick[Service]ExecStart=/usr/local/bin/tickEOTsystemctl daemon-reloadsystemctl start ticksleep 2
unit で絞る・新しい順・行数root で実行⌘↵
journalctl -u tickjournalctl -u tick -rjournalctl -u tick -n 1

-u で unit を選び、-r で新しい順に、-n 1 で最後の 1 件だけにしました。次は、失敗するサービスを起こして、priority で絞ります。

priority で絞るroot で実行⌘↵
cat > /etc/systemd/system/bad.service <<'EOT'[Service]ExecStart=/bin/falseEOTsystemctl daemon-reloadsystemctl start badsleep 1journalctl -u badjournalctl -p warning

-p warning は、warning 以上（warning・err・crit・alert・emerg）を表示します。rsyslog のセレクタと同じ考え方です。-p 4 のように番号でも書けます。

カーネルのログと、今回の起動root で実行⌘↵
journalctl -k -n 3journalctl -b -n 2
オプション意味
-u unitその unit のログ
-f新しい行を待って出し続ける（tail -f と同じ）
-b今回の起動から。-b -1 は 1 つ前の起動
-p priorityその priority 以上。-p err、-p 3
-n 数最後の N 件（数を省くと 10 件）
-r新しい順に表示する
-kカーネルのログだけ（dmesg と同じもの）
--since / --until時刻で絞る。--since "2026-11-01 09:00"、--since today、--since "10 min ago"
-t 名前logger の -t などで付けた名前で絞る
-o 形表示の形。-o cat（本文だけ）、-o json、-o short-iso
--list-boots、--disk-usage起動の一覧、ジャーナルの大きさ

本物の systemd（Docker の debian:12 で systemd を PID 1 として動かしたもの）では、logger で送ったものもジャーナルに入ります。

ターミナル
# logger -p user.err -t myapp "disk is full"# journalctl -t myappNov 16 11:19:52 host myapp[81]: disk is full# journalctl --since "10 min ago" -p errNov 16 11:19:52 host myapp[81]: disk is full

systemd-cat：コマンドの出力をジャーナルへ

systemd-cat は、コマンドの標準出力（と標準エラー）をジャーナルにつなぎます。パイプの先に置いて、標準入力を送ることもできます。

ターミナル
# echo "from cat" | systemd-cat -t mycat -p warning# systemd-cat -t backup /usr/local/bin/backup.sh# journalctl -t mycatNov 16 11:19:52 host mycat[84]: from cat

-t は名前（identifier）、-p は priority（0〜7 か名前）です。logger と同じ文字ですが、logger は「引数の文字をログに送る」、systemd-cat は「コマンドを実行して、その出力を送る」という違いがあります。

journald.conf と、ログを残すかどうか

journald の設定ファイルは /etc/systemd/journald.conf です。debian:12 では、すべての行がコメント（#）で、既定の値を示しています。

conf
[Journal]#Storage=auto#Compress=yes#SystemMaxUse=#MaxRetentionSec=#ForwardToSyslog=yes

いちばん大事なのは Storage= です。

値保存先
volatile/run/log/journal/（メモリの上）。再起動で消える
persistent/var/log/journal/（ディスク）。なければ作る
auto（既定）/var/log/journal/ があればそこに、なければ /run/log/journal/ に
none保存しない（転送だけ）

既定の auto で再起動後もログを残すには、/var/log/journal ディレクトリを作るか、Storage=persistent にします。debian:12 に systemd を入れると、/var/log/journal は最初から作られていました。ForwardToSyslog=yes は、rsyslogd へ渡す設定です。設定を変えたら systemctl restart systemd-journald で読み直させます。

テキストのファイルを追いかけるのは tail -f /var/log/syslog、ジャーナルを追いかけるのは journalctl -f です。サービス 1 つなら journalctl -u nginx -f と組み合わせます。

9.5logrotate：ログを回して古いものを消す

ログのファイルは、放っておくと大きくなり続け、ディスクを埋めます。logrotate は、決まった間隔でファイルの名前をずらし（ローテーション）、古いものを圧縮し、決まった数より古いものを消します。logrotate 自身はデーモンではありません。cron（/etc/cron.daily/logrotate）や systemd のタイマー（logrotate.timer）から 1 日 1 回実行されます。

小さな Linux に logrotate はないので、することを mv で手で真似ます。rotate 3 のつもりで、4 回回します。

名前をずらして、新しいファイルを作る⌘↵
cd /tmpecho "day1" > app.logfor day in 2 3 4 5; do  rm -f app.log.3  [ -f app.log.2 ] && mv app.log.2 app.log.3  [ -f app.log.1 ] && mv app.log.1 app.log.2  mv app.log app.log.1  echo "day$day" > app.logdonelshead app.log*

番号が小さいほど新しいことと、day1 が消えたことを確かめてください。

設定ファイル

全体の設定は /etc/logrotate.conf、パッケージごとの設定は /etc/logrotate.d/ の下のファイルです。logrotate.conf の include /etc/logrotate.d の行で読み込まれます。debian:12 の /etc/logrotate.conf（コメントを除く）と、rsyslog の分です。

この章の準備最初の実行のときに、自動で流れるコマンド
cat > /etc/logrotate.conf <<'EOT'# see "man logrotate" for detailsweeklyrotate 4create#dateext#compressinclude /etc/logrotate.dEOTmkdir -p /etc/logrotate.dcat > /etc/logrotate.d/rsyslog <<'EOT'/var/log/syslog/var/log/mail.log/var/log/kern.log/var/log/auth.log/var/log/user.log/var/log/cron.log{    rotate 4    weekly    missingok    notifempty    compress    delaycompress    sharedscripts    postrotate        /usr/lib/rsyslog/rsyslog-rotate    endscript}EOT
全体の設定と、パッケージごとの設定⌘↵
grep -v '^#' /etc/logrotate.confls /etc/logrotate.dcat /etc/logrotate.d/rsyslog

logrotate.conf に書いたものが既定で、/etc/logrotate.d/ の各ファイルの { } の中で上書きします。

指示意味
daily / weekly / monthly回す間隔
size 100M大きさがこれを超えたら回す
rotate 4古いものを 4 世代残す（それより古いものは消す）
compress古いものを gzip で圧縮する（.gz）
delaycompress1 回前（.1）は圧縮せず、次の回に圧縮する
missingokログのファイルがなくてもエラーにしない
notifempty空なら回さない
create 0640 root adm回したあと、この権限・持ち主で空のファイルを作る
dateext番号の代わりに日付を付ける（messages-20261116）。rockylinux:9 の既定
postrotate 〜 endscript回したあとに実行するコマンド（prerotate は前）
sharedscripts複数のファイルを回しても、postrotate を 1 回だけ実行する

Docker の debian:12 で、rotate 3、compress、delaycompress、notifempty、create 0640 root adm の設定を作り、logrotate -f で 5 回回した結果です（-f は間隔を待たずに今すぐ回す）。

ターミナル
# ls -l /var/log/myapp-rw-r----- 1 root adm   0 Nov 16 11:18 app.log-rw-r----- 1 root adm   7 Nov 16 11:18 app.log.1-rw-r----- 1 root adm  27 Nov 16 11:18 app.log.2.gz-rw-r----- 1 root adm  27 Nov 16 11:18 app.log.3.gz-rw-r--r-- 1 root root  0 Nov 16 11:18 empty.log

.1 だけ圧縮されていないのは delaycompress、空の empty.log に番号付きのファイルがないのは notifempty のためです。

深掘りなぜ postrotate でデーモンに知らせるのか

rsyslogd は、ログのファイルを開いたまま書き続けます。mv で名前を変えても、デーモンが持っている fd は同じ inode を指したままなので、app.log.1 に書き続けてしまいます（図解 Linux 11.6、9.9）。そこで postrotate で HUP シグナルを送り、ファイルを開き直させます。rockylinux:9 の /etc/logrotate.d/rsyslog の postrotate は /usr/bin/systemctl -s HUP kill rsyslog.service です。開き直せないプログラムには、中身をコピーしてから元を空にする copytruncate を使います。

注意試験の注意：rotate は「回数」、daily は「間隔」

rotate 7 は「7 世代残す」で、7 日ごとではありません。間隔は daily / weekly / monthly で決まります。daily と rotate 7 を組み合わせると、1 週間分が残ります。

9.6MTA・MUA・MDA：メールが届くまで

メールは、役目の違う 3 種類のプログラムで運ばれます。

略称名前役目例
MUAMail User Agent利用者がメールを書く・読むmail、Thunderbird
MTAMail Transfer Agentメールを受け取り、宛先のサーバへ配送する（SMTP、ポート 25）postfix、exim、sendmail
MDAMail Delivery Agent届いたメールを利用者のメールボックスに置くprocmail、postfix の local

POP や IMAP でメールボックスを読ませる dovecot は、MTA ではなく、受け取ったメールを MUA に渡すサーバです。

MTA の主な実装は 3 つです。

MTA特徴
sendmail最も古い。設定が難しい。sendmail というコマンド名は、ほかの MTA も互換のために持っている
postfix安全さと速さを重んじた設計。Red Hat 系の標準。設定は /etc/postfix/main.cf
eximDebian 系の標準（Debian の既定の MTA は exim4）

どの MTA を入れても、sendmail、mailq、newaliases というコマンドが使えます。postfix は、これらを互換のために用意しています。Docker で確かめると、どちらもリンクでした。

ターミナル
$ ls -l /usr/bin/mailq /usr/bin/newaliases          # debian:12 + postfixlrwxrwxrwx 1 root root 16 Mar  6  2024 /usr/bin/mailq -> ../sbin/sendmaillrwxrwxrwx 1 root root 16 Mar  6  2024 /usr/bin/newaliases -> ../sbin/sendmail$ ls -l /usr/sbin/sendmail                          # rockylinux:9 + postfixlrwxrwxrwx 1 root root 21 Nov 16 11:16 /usr/sbin/sendmail -> /etc/alternatives/mta
メモ1 台のサーバでも MTA は働いている

インターネットにメールを出さない機械でも、cron の実行結果や、/etc/aliases で root 宛てにまとめたシステムのお知らせは、ローカルの MTA が /var/mail/ユーザー名（Red Hat 系では /var/spool/mail と同じ場所）に配ります。postfix の既定の inet_interfaces は、rockylinux:9 では localhost で、外からのメールは受け付けません。

9.7/etc/aliases と ~/.forward、mail と mailq

/etc/aliases：宛先の別名

/etc/aliases は、宛先の名前を別の宛先に置き換える表です。1 行が「別名: 本当の宛先, …」です。

この章の準備最初の実行のときに、自動で流れるコマンド
cat > /etc/aliases <<'EOT'# See man 5 aliases for formatmailer-daemon:    postmasterpostmaster:    rootbin:        rootdaemon:        rootroot:        aliceadmin:        alice, bobEOT
/etc/aliases を読む⌘↵
cat /etc/aliasesgrep '^admin' /etc/aliases
  • postmaster: root：postmaster 宛てのメールは root に届く
  • root: alice：root 宛てはさらに alice へ（別名はつながる）
  • admin: alice, bob：1 つの別名で、複数の人に配る

MTA は、このテキストを直接は読みません。newaliases で、検索の速いデータベース（/etc/aliases.db）に作り直して使います。書き換えたら newaliases を実行するのを忘れないでください。debian:12 + postfix で試した結果です。

ターミナル
# echo "admin: alice, bob" >> /etc/aliases# newaliases# ls -l /etc/aliases.db-rw-r--r-- 1 root root 12288 Nov 16 11:16 /etc/aliases.db# echo "hello body" | mail -s "test1" admin# ls -l /var/mail-rw------- 1 alice mail 549 Nov 16 11:16 alice-rw------- 1 bob   mail 549 Nov 16 11:16 bob

admin 宛ての 1 通が、alice と bob の両方のメールボックスに届きました。

~/.forward：自分宛てを転送する

/etc/aliases は root が管理するシステム全体の表です。一般の利用者が自分宛てのメールを転送したいときは、ホームディレクトリに ~/.forward を置き、転送先を書きます。

自分宛てを転送する ~/.forward⌘↵
echo "you@example.com" > ~/.forwardcat ~/.forwardls -l ~/.forward

ほかの人に書き換えられないよう、持ち主だけが書ける権限にしておきます（他人が書ける .forward は、MTA に無視されることがあります）。

mail と mailq

mail は端末で使う簡単な MUA です。

使い方すること
mail -s "件名" 宛先 < 本文.txt送る。-s は件名（subject）
echo "本文" | mail -s "件名" 宛先本文をパイプで渡して送る
mail -c 宛先CC を付ける
mail自分のメールボックスを読む（対話で番号を選ぶ）

送ったのに届かないメールは、MTA のキュー（送信待ちの列）に残ります。mailq はキューの一覧を表示します（sendmail -bp、postfix では postqueue -p と同じ）。宛先の名前が引けないメールを送ったときの、debian:12 + postfix の出力です。

ターミナル
$ mailq-Queue ID-  --Size-- ----Arrival Time---- -Sender/Recipient-------81EF5D8487      547 Mon Nov 16 11:16:49  root@mail.example.com(Host or domain name not found. Name service error for name=nowhere.invalid type=MX: Host not found, try again)                                         bob@nowhere.invalid -- 0 Kbytes in 1 Request.

キューが空なら Mail queue is empty と表示されます。

コマンド・ファイル役目
/etc/aliasesシステム全体の別名の表（root が編集）
newaliases/etc/aliases を /etc/aliases.db に作り直す（sendmail -bi と同じ）
~/.forward利用者が自分宛てを転送する
mail送る・読む（MUA）
mailq送信待ちのキューを見る（sendmail -bp、postqueue -p）
/var/mail/ユーザー名ローカルのメールボックス
注意試験の注意：newaliases と mailq は「MTA のコマンド」

newaliases も mailq も、どの MTA（postfix、exim、sendmail）でも同じ名前で使えます。/etc/aliases を書き換えただけでは反映されず、newaliases が必要です。~/.forward は利用者ごと、/etc/aliases はシステム全体です。

要点まとめ
  • 時計は 2 つ。ハードウェアクロック（RTC）とシステムクロック。hwclock -w（--systohc）は sys → hc、-s（--hctosys）は hc → sys、-r は表示
  • date +%Y-%m-%d で書式を指定して表示。date MMDDhhmm[[CC]YY] と date -s で設定（root）
  • タイムゾーン：/usr/share/zoneinfo/ のデータ、/etc/localtime（システム全体）、/etc/timezone（Debian 系）、TZ（プロセスごと）。tzselect は値を表示するだけ。timedatectl set-timezone
  • NTP は UDP 123。chronyd（/etc/chrony.conf、chronyc sources / tracking）、ntpd（/etc/ntp.conf、ntpq -p）、ntpdate は 1 回だけ。行頭の * が同期中。pool.ntp.org
  • rsyslog：/etc/rsyslog.conf に facility.priority 出力先。priority は emerg > alert > crit > err > warning > notice > info > debug。1 つ書くと「以上」、= は「だけ」、! は除く、none は facility を除く。@ は UDP、@@ は TCP で転送
  • /var/log/messages（Red Hat 系）と /var/log/syslog（Debian 系）、secure と auth.log
  • logger -p facility.priority -t タグ（既定は user.notice）、systemd-cat はコマンドの出力をジャーナルへ
  • journalctl -u、-f、-b、-p（以上）、-n、-r、-k、--since / --until。/etc/systemd/journald.conf の Storage=（auto は /var/log/journal があれば残す）
  • logrotate：/etc/logrotate.conf と /etc/logrotate.d/。daily / weekly、rotate N（世代数）、compress、missingok、notifempty、create、postrotate 〜 endscript
  • MUA（書く・読む）、MTA（配送。postfix・exim・sendmail）、MDA（メールボックスへ）。/etc/aliases を変えたら newaliases。~/.forward で転送。mailq でキュー
