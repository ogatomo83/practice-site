10.2SUID ファイルとパスワードの期限を点検する

find -perm で SUID / SGID のファイルを探す

図解 Linux 4.9 で見たとおり、SUID（setuid）ビットの付いたプログラムは、起動した人ではなくファイルの持ち主の権限で動きます。持ち主が root なら、だれが起動しても root として動きます。passwd や sudo に必要な仕組みですが、攻撃者が SUID root のシェルを置いていけば、それは裏口になります。

そこで管理者は、SUID と SGID（setgid）の付いたファイルを定期的に一覧にし、見覚えのないものがないかを調べます。使うのは find の -perm（permission）です。

SUID の付いたファイルを探す⌘↵
find /usr/bin -perm -4000 -ls

-ls は、見つけたファイルを ls -dils の形で表示します。3 つとも持ち主の x の場所が s になっています。特別なビットの数字を、もう一度確かめておきます。

ビット数字ls -l の表示探し方の例
SUID4000持ち主の x が s（x がなければ S）find / -perm -4000
SGID2000グループの x が s（x がなければ S）find / -perm -2000
スティッキー1000その他の x が t（x がなければ T）find / -perm -1000

-perm は、数字の前に付ける記号で意味が変わります。ここが試験でいちばん問われます。

書き方意味-perm ? 4000 に 4755 は合うか
-perm 4755権限がぴったりその値-perm 4000 には合わない（4755 ≠ 4000）
-perm -4000書いたビットが全部立っている（ほかのビットは問わない）合う
-perm /6000書いたビットのどれか 1 つでも立っている合う

SGID のファイルを 1 つ作って、3 つの書き方を比べます。

-perm の 3 つの書き方を比べるroot で実行⌘↵
cp /usr/bin/cat /usr/local/bin/gcatchmod 2755 /usr/local/bin/gcatls -l /usr/local/bin/gcatfind /usr -perm /6000 -type ffind /usr -perm -2000 -type ffind /usr -perm -6000 -type f

/6000 は「SUID か SGID のどちらか」なので、4 つ全部が出ました。-2000 は SGID だけです。-6000 は「SUID と SGID の両方」なので、1 つも出ません。

片づけるroot で実行⌘↵
rm /usr/local/bin/gcat
注意試験の注意：-perm の - と /

-perm -4000 は「全部のビット」、-perm /6000 は「どれか 1 つ」です。SUID と SGID のどちらかが付いたファイルを探すなら /6000、両方なら -6000 です。記号なしの -perm 4000 は「権限がちょうど 4000」という意味になり、ふつうは何も見つかりません。古い本には +6000 という書き方もありますが、今の GNU find では使えません。記号の形（-perm -u=s、-perm /u=s,g=s）でも書けます。

本物の Linux で / 全体を探すと、読めないディレクトリや /proc の中で消えたファイルのエラーが出ます。find / -perm -4000 -type f 2>/dev/null のように、標準エラーを捨てて使うのが定番です。

passwd と usermod でアカウントをロックする

退職した人や、しばらく使わないアカウントは、消す前にまずロックします。ロックすると、パスワードではログインできなくなります。

alice をロックし、状態を見る⌘↵
sudo passwd -S alicesudo passwd -l alicesudo passwd -S alicesudo grep '^alice:' /etc/shadow

passwd -S（status）は、自分の状態なら一般ユーザーでも、他人の状態は root だけが見られます。2 つ目の欄が P（使えるパスワードがある）から L（locked）に変わりました。/etc/shadow を見ると、パスワードのハッシュの先頭に ! が付いています。ロックの正体はこれだけです。ハッシュの頭に ! が付くと、どんなパスワードを打っても合わなくなります。元のハッシュは残っているので、! を取れば元のパスワードで入れます。

ロックを外す⌘↵
sudo passwd -u alicesudo passwd -S alice

他人のアカウントをロックできるのは root だけです。

一般ユーザーは他人をロックできないエラーになる⌘↵
passwd -l alice

usermod でも同じことができます。-L（大文字）でロック、-U で解除です。Debian で確かめると、passwd -l と同じく、ハッシュの先頭に ! が付きます。

ターミナル
# usermod -L alice# grep '^alice:' /etc/shadowalice:!$y$j9T$WW54jiwe9F7d2E55D2yF3/$3IBd…:20773:0:99999:7:::# usermod -U alice
したいことpasswdusermod
ロックするpasswd -l ユーザーusermod -L ユーザー
ロックを外すpasswd -u ユーザーusermod -U ユーザー
状態を見るpasswd -S ユーザー—
アカウントの有効期限を決める—usermod -e 2027-03-31 ユーザー
注意試験の注意：ロックは「パスワードで入れない」だけ

passwd -l と usermod -L が止めるのは、パスワードによる認証です。SSH の公開鍵（1.10.3）で入る道は、これだけでは止まりません。アカウントそのものを使えなくするには、有効期限を過去の日付にする（usermod -e や chage -E）か、ログインシェルを /usr/sbin/nologin にします（1.10.2）。また、passwd -l の l は小文字、usermod -L の L は大文字です。

chage でパスワードの期限を決める

パスワードを長く変えないままにしないよう、期限を決めます。期限の情報は /etc/shadow の 3〜8 番目の欄に入っていて、chage（change age）で見たり変えたりします。chage は小さな Linux にないので、Debian 12 で実行した結果を見ます。

ターミナル
# chage -l aliceLast password change                    : Nov 16, 2026Password expires                    : neverPassword inactive                    : neverAccount expires                        : neverMinimum number of days between password change        : 0Maximum number of days between password change        : 99999Number of days of warning before password expires    : 7# chage -M 90 -m 7 -W 14 -I 30 -E 2027-03-31 alice# chage -l aliceLast password change                    : Nov 16, 2026Password expires                    : Feb 14, 2027Password inactive                    : Mar 16, 2027Account expires                        : Mar 31, 2027Minimum number of days between password change        : 7Maximum number of days between password change        : 90Number of days of warning before password expires    : 14# grep '^alice:' /etc/shadowalice:$y$j9T$WW54jiwe9F7d2E55D2yF3/$3IBd…:20773:7:90:14:30:20908:

最後に変えた日（11 月 16 日）から 90 日で期限が切れ（2 月 14 日）、その 30 日後（3 月 16 日）にはパスワードが使えなくなります。それとは別に、アカウントそのものが 3 月 31 日で使えなくなります。/etc/shadow の数字の欄は、1970 年 1 月 1 日からの日数です（20773 が 2026 年 11 月 16 日）。

オプション意味/etc/shadow の欄
-l期限の情報を表示する（list）—
-d 日付最後にパスワードを変えた日にする。-d 0 なら、次のログインで変更を強制3
-m 日数変えてから次に変えられるまでの最短日数（minimum）4
-M 日数パスワードの有効期間の最長日数（maximum）5
-W 日数期限切れの何日前から警告するか（warning）6
-I 日数期限が切れてから、使えなくなるまでの猶予（inactive）7
-E 日付アカウントの有効期限（expire）。-E -1 で期限なし8

オプションを付けずに chage alice と打つと、1 つずつ質問される対話の形になります。

-m と -M、-E と -M。 小文字の -m は最短日数、大文字の -M は最長日数です。「90 日ごとに変えさせたい」なら -M 90 です。また、-M が決めるのはパスワードの期限で、-E が決めるのはアカウントの期限です。-E の日を過ぎると、パスワードが正しくてもログインできません。

10.3開いているポート、使っているプロセス、ログインした人

侵入の入り口になるのは、外から接続を受け付けているポートです。不要なサービスが待ち受けていないかを、内側と外側の両方から調べます。

ss と netstat：待ち受けているポートの一覧

図解 Linux 16.6 で使った ss です。Web サーバを起動して、待ち受けている TCP のポートを見ます。

待ち受けているポートを見る⌘↵
sudo systemctl start httpdss -tlnss -tlnpsudo ss -tlnp

-p（process）を付けると、そのソケットを持っているプロセスが出ます。ただし、他人のプロセスは root でないと見えません。httpd は root で動いているので、sudo を付けたときだけ users:(("httpd",pid=…)) が出ました。

netstat は ss の前から使われてきたコマンドで、主なオプションの文字は同じです（Debian では net-tools というパッケージに入っています）。

ターミナル
# netstat -tlnpActive Internet connections (only servers)Proto Recv-Q Send-Q Local Address           Foreign Address         State       PID/Program name    tcp        0      0 0.0.0.0:8080            0.0.0.0:*               LISTEN      3352/python3
オプションss と netstat で共通の意味
-tTCP
-uUDP
-l待ち受け中（LISTEN）だけ
-a待ち受け中も、接続中も全部
-nポート番号やアドレスを名前に直さない（:22 を :ssh にしない）
-p使っているプロセス（PID と名前）

ss -tulnp（または netstat -tulnp）は「TCP と UDP の、待ち受け中のポートを、番号のまま、プロセス付きで」という、点検の定番の形です。

lsof と fuser：だれが、それを使っているか

lsof（list open files）は、プロセスが開いているファイルを一覧にします。Linux ではソケットも fd の 1 つなので、ネットワークの接続も出ます（図解 Linux 9.9）。

httpd が開いているもの⌘↵
sudo lsof -p $(pgrep httpd)

fd 3 の sock が、80 番で待ち受けているソケットです。本物の lsof には、ネットワークのファイルだけを選ぶ -i があります（小さな Linux の lsof には -i がないので、Debian 12 の結果を見ます）。

ターミナル
# lsof -i :8080COMMAND  PID USER   FD   TYPE DEVICE SIZE/OFF NODE NAMEpython3 3352 root    3u  IPv4 120195      0t0  TCP *:8080 (LISTEN)# lsof -i tcp:8080 -P -nCOMMAND  PID USER   FD   TYPE DEVICE SIZE/OFF NODE NAMEpython3 3352 root    3u  IPv4 120195      0t0  TCP *:8080 (LISTEN)
書き方意味
lsof -iネットワークのファイル（ソケット）を全部
lsof -i :ポートそのポートを使っているもの
lsof -i tcp:22TCP の 22 番
lsof -p PIDそのプロセスが開いているもの全部
lsof ファイルそのファイルを開いているプロセス

fuser（file user）は、逆向きに「このファイルやポートを使っているプロセスの PID」を出します。-v で詳しく、-k でそのプロセスを殺します（既定は SIGKILL）。

ターミナル
# fuser -v -n tcp 8080                     USER        PID ACCESS COMMAND8080/tcp:            root       3352 F.... python3# fuser -v /tmp                     USER        PID ACCESS COMMAND/tmp:                root       3362 ..c.. sh                     root       3363 ..c.. sleep# fuser -k /tmp/tmp:                 3362c  3363c

-n tcp 8080 は 8080/tcp とも書けます。ACCESS の欄の c はカレントディレクトリ、F は開いているファイル、e は実行中のプログラム、r はルートディレクトリとして使っている、という意味です。umount が「target is busy」で失敗したとき、fuser -vm /mnt/usb で犯人を探し、fuser -km でまとめて終わらせる、という使い方をします。

nmap：外から見て、開いているポート

ss は「この機械が待ち受けているつもりのポート」です。ファイアウォールで閉じていれば、外からは届きません。外から本当に開いて見えるかは、ポートスキャナの nmap で、別の機械から確かめます。

ターミナル
$ nmap 127.0.0.1Starting Nmap 7.93 ( https://nmap.org ) at 2026-11-16 11:15 UTCNmap scan report for localhost (127.0.0.1)Host is up (0.0000010s latency).Not shown: 999 closed tcp ports (reset)PORT     STATE SERVICE8080/tcp open  http-proxy$ nmap -p 22,80,8080 127.0.0.1PORT     STATE  SERVICE22/tcp   closed ssh80/tcp   closed http8080/tcp open   http-proxy

引数なしでは、よく使われる 1000 個のポートを調べます。-p で調べるポートを決められます。STATE の open は受け付けている、closed はだれも待ち受けていない、filtered はファイアウォールで応答がない、という意味です。

他人の機械に nmap を使わない。 ポートスキャンは、攻撃の下調べと同じ動きです。自分が管理していない機械やネットワークに向けて実行すると、不正アクセスを疑われ、契約や法律に反することがあります。点検は、自分の管理する機械に、許可を得て行います。

10.4権限と資源を絞る：su、sudo、ulimit、TMOUT

su と su -

su は別のユーザーのシェルを始めるコマンドで、相手のパスワードをたずねます（図解 Linux 4.8）。ユーザー名を省くと root です。試験で問われるのは、-（ハイフン）を付けるかどうかの違いです。

su と su - の違い⌘↵
pwdsudo su alice -c 'pwd; echo $HOME'sudo su - alice -c 'pwd; echo $HOME'

su alice は、ユーザーだけが alice に変わり、いる場所は /home/you のままです。su - alice は、alice がログインしたのと同じ状態を作ります。ホームディレクトリへ移り、ログインのときに読む設定ファイル（/etc/profile、~/.bash_profile など）を読み直し、環境変数も alice のものに入れ替えます。

書き方意味
suroot になる。いまの場所と環境変数の多くは引き継ぐ
su -（su -l、su --login）root としてログインし直した状態になる。root のホームへ移り、PATH なども root のもの
su ユーザー / su - ユーザーそのユーザーになる
su -c 'コマンド' ユーザーそのユーザーとしてコマンドを 1 つ実行して戻る
注意試験の注意：su - を使う理由

su だけで root になると、PATH が一般ユーザーのままのことがあり、/usr/sbin のコマンドが見つからない、自分の作った同名のコマンドが動いてしまう、といった事故が起きます。root の作業は su - で始めるのが安全です。また、su でたずねられるのはなる相手のパスワード、sudo でたずねられるのは自分のパスワードです。

sudo と /etc/sudoers

sudo は、/etc/sudoers で許されたコマンドだけを、root などの別のユーザーとして実行します。root のパスワードを教えずに、必要な権限だけを渡せます。

小さな Linux の /etc/sudoers⌘↵
sudo cat /etc/sudoerssudo -lsudo -u alice id

-l は自分に許されていることの一覧、-u ユーザー は root 以外のユーザーとして実行する、という意味です。

/etc/sudoers の 1 行は、次の形です。

Debian 12 で、2 つの規則を書いてから確かめた例です。

ターミナル
# cat /etc/sudoers.d/testalice ALL=(root) /usr/bin/systemctl restart nginx, /usr/bin/journalctl%ops ALL=(ALL) NOPASSWD: ALL# visudo -c/etc/sudoers: parsed OK/etc/sudoers.d/README: parsed OK/etc/sudoers.d/test: parsed OK# sudo -l -U alice…User alice may run the following commands on 7a717555d2b0:    (root) /usr/bin/systemctl restart nginx, /usr/bin/journalctl

alice は 2 つのコマンドだけを root として実行でき、そのたびに自分のパスワードをたずねられます。ops グループのメンバーは、何でも、パスワードなしで実行できます。

書き方意味
aliceユーザー alice
%wheel、%sudoそのグループのメンバー
ALLすべて（機械、ユーザー、コマンド）
(root)、(ALL)、(ALL:ALL)だれとして実行できるか（: の後ろはグループ）
NOPASSWD:パスワードをたずねない
コマンド, コマンド許すコマンド。フルパスで、カンマで区切る

管理者のグループは、Debian 系では sudo（%sudo ALL=(ALL:ALL) ALL）、Red Hat 系では wheel（%wheel ALL=(ALL) ALL）です。

/etc/sudoers は、エディタで直接開かずに visudo で編集します。visudo は、ほかの人と同時に編集しないようにロックし、保存するときに書式を検査します。書きまちがえたまま保存すると、sudo がまったく使えなくなるからです。visudo -c は検査だけをします。

ターミナル
# echo "alice ALL=(root /usr/bin/ls" > /etc/sudoers.d/bad# visudo -c/etc/sudoers.d/bad:1:28: syntax erroralice ALL=(root /usr/bin/ls                           ^

規則は /etc/sudoers.d/ に分けて置ける。 今の /etc/sudoers の最後には @includedir /etc/sudoers.d（古い形は #includedir）があり、/etc/sudoers.d/ の中のファイルも読まれます。規則を用途ごとのファイルに分けると、管理しやすくなります。そのファイルも visudo -f /etc/sudoers.d/ファイル で編集します。

ulimit：プロセスが使える資源の上限

1 人のユーザーがプロセスを作りすぎたり、巨大なファイルを書いたりすると、機械全体が止まります。シェルの組み込みコマンド ulimit は、そのシェルと、そこから起動するプロセスが使える資源に上限を付けます（図解 Linux 8.3 では core の大きさに使いました）。

いまの上限を全部見る⌘↵
ulimit -a
オプション資源
-a全部を表示する

10.7パケットを選ぶ：iptables と firewalld

iptables：チェインと規則

Linux のカーネルには、パケットを調べて通すか捨てるかを決める仕組み（netfilter）があります。それに規則を設定する、昔からのコマンドが iptables です。

パケットは、どこからどこへ行くかによって、3 つのチェイン（規則の列）のどれかで調べられます。

チェインの中の規則は上から順に調べられ、最初に当てはまった規則のターゲット（-j で指定）が実行されます。どの規則にも当てはまらなければ、チェインのポリシー（既定の動作）が使われます。iptables は小さな Linux にないので、Debian 12 で実行した結果を見ます。

ターミナル
# iptables -P INPUT DROP# iptables -A INPUT -p tcp --dport 22 -s 192.168.1.0/24 -j ACCEPT# iptables -A INPUT -p tcp --dport 80 -j ACCEPT# iptables -I INPUT -p tcp --dport 23 -j REJECT# iptables -L INPUT --line-numbersChain INPUT (policy DROP)num  target     prot opt source               destination         1    REJECT     tcp  --  anywhere             anywhere             tcp dpt:telnet reject-with icmp-port-unreachable2    ACCEPT     tcp  --  192.168.1.0/24       anywhere             tcp dpt:ssh3    ACCEPT     tcp  --  anywhere             anywhere             tcp dpt:http# iptables -D INPUT 1# iptables -F INPUT# iptables -L INPUTChain INPUT (policy DROP)target     prot opt source               destination

-I で入れた 23 番の規則は、後から入れたのに先頭に入りました。-F で規則を全部消しても、ポリシーは DROP のままです。この状態では、自分あてのパケットはすべて捨てられます。

オプション意味
-A チェイン 規則規則を最後に足す（append）
-I チェイン [番号] 規則規則を先頭（または番号の位置）に入れる（insert）
-D チェイン 番号 / -D チェイン 規則規則を消す（delete）
-L [チェイン]規則を表示する（list）。-n で番号のまま、--line-numbers で番号付き
-P チェイン ターゲットポリシーを決める（policy）
-F [チェイン]規則を全部消す（flush）。ポリシーは変わらない

-i eth0 / -o入ってきた / 出ていくインターフェース
ターゲット動作

DROP黙って捨てる。送り主には何も返らない（相手はタイムアウトまで待つ）
REJECT捨てて、送り主に「拒否した」というエラー（ICMP など）を返す

iptables の規則はメモリの中にあるだけで、再起動すると消えます。残すには iptables-save でファイルに書き出し、起動時に iptables-restore で読み込みます。

注意試験の注意：-A と -I、-F とポリシー

規則は上から順に調べられるので、順番が意味を持ちます。-A は最後に、-I は先頭に入れます。すべてを DROP するポリシーの前に許可の規則を入れずに -P INPUT DROP を実行すると、SSH で作業中の自分も締め出されます。-F はポリシーを ACCEPT に戻さないことにも注意します。

10.9SSH のポート転送

SSH の暗号化された接続の中に、ほかの TCP の通信を通すことができます。これをポート転送（トンネル）と呼びます。暗号化されていないプロトコルを守ったり、ファイアウォールの内側にあるサーバへ、SSH のサーバを踏み台にして届いたりするのに使います。

ターミナル
$ ssh -L 15432:db.internal:5432 you@gw.example.com（別の端末で）$ psql -h localhost -p 15432 …   ← gw を通って db.internal:5432 へ届く$ ssh -R 9000:localhost:8080 you@gw.example.com（gw の上で）$ curl http://localhost:9000/       ← 手元の PC の 8080 番へ届く$ ssh -D 1080 you@gw.example.com（ブラウザの SOCKS プロキシを localhost:1080 にすると、通信が gw から出ていく）

Debian 12 のコンテナの中で、自分自身に SSH でつないで 3 つを確かめました。8080 番で hello-from-8080 を返す Web サーバに、どれも転送で届きました。

ターミナル
$ ssh -f -N -L 9000:localhost:8080 root@localhost$ curl -s http://localhost:9000/hello-from-8080$ ssh -f -N -R 9100:localhost:8080 root@localhost$ curl -s http://localhost:9100/hello-from-8080$ ssh -f -N -D 1080 root@localhost$ curl -s --socks5-hostname localhost:1080 http://127.0.0.1:8080/hello-from-8080
オプション名前待ち受ける場所書き方
-Lローカル転送手元（ssh を実行した側）-L 手元のポート:目的地:目的地のポート
-Rリモート転送SSH サーバの側-R サーバ側のポート:目的地:目的地のポート
-Dダイナミック転送手元。SOCKS プロキシになる-D 手元のポート
-N—コマンドを実行しない（転送だけ）
-f—認証の後、バックグラウンドに回る

-L と -R の「目的地」。 -L 15432:db.internal:5432 の db.internal は、SSH サーバから見た名前です。手元の PC から db.internal に届かなくてもかまいません。-R の localhost:8080 は、手元から見た localhost です。どちらの側でポートが開くか（-L は手元、-R はサーバ側）で区別します。

10.11クラウドのアカウントを守る

クラウド（IaaS）では、物理的なサーバやネットワーク機器は事業者が管理し、その上の仮想マシン（インスタンス）の OS から先は利用者が管理します。この分担を責任共有モデルと呼びます。OS の更新、ファイアウォールの設定、アカウントの管理は、利用者の責任です。この章でここまで学んだことは、クラウドの仮想マシンにもそのまま当てはまります。

管理コンソールのアカウント

管理コンソールは、クラウドの資源（仮想マシン、ストレージ、ネットワーク）を Web の画面で操作する場所です。そこにログインできる人は、すべての仮想マシンを消すことも、データを持ち出すこともできます。仮想マシンの root より強い権限なので、いちばん念入りに守ります。

  • 最上位のアカウント（契約したときに作られる、すべての権限を持つアカウント。AWS ではルートユーザー）は、日々の作業に使わず、多要素認証を付けて大切に保管する
  • 作業する人には、1 人 1 つのアカウントを作り、仕事に必要な権限だけを与える（最小権限）。共有しない
  • 使わなくなったアカウントや、プログラム用のアクセスキーは、すぐに無効にする
  • 操作の記録（監査ログ）を残す

多要素認証とワンタイムパスワード

本人であることを確かめる材料（認証の要素）には、3 種類あります。

要素例
知っているもの（知識）パスワード、PIN、秘密の質問の答え
持っているもの（所持）スマートフォンの認証アプリ、ハードウェアトークン、IC カード
本人の体（生体）指紋、顔

多要素認証（MFA、Multi-Factor Authentication）は、種類の違う要素を 2 つ以上組み合わせます。パスワードが漏れても、スマートフォンを持っていなければ入れません。多段階認証は、認証を何段階かに分けて行うことです。「パスワードの後に秘密の質問」は 2 段階ですが、どちらも「知っているもの」なので、多要素ではありません。

多要素認証でよく使われるのが、ワンタイムパスワード（OTP、One-Time Password）です。1 回しか使えない、短い数字です。スマートフォンの認証アプリが出す 6 桁の数字は、TOTP（Time-based OTP）という方式で、事前に共有した秘密といまの時刻から計算され、30 秒ほどで変わります。盗み見られても、すぐに使えなくなります。

多段階と多要素。 「多要素」は要素の種類が 2 つ以上、「多段階」は確認の回数が 2 回以上です。パスワード + SMS や認証アプリのコードは、知識 + 所持なので多要素です。パスワード + 秘密の質問は、多段階ですが多要素ではありません。

10.12クラウドのネットワークとデータの置き場所

ファイアウォールとルーティング

クラウドの仮想ネットワークには、事業者が用意したファイアウォールがあります。AWS などのセキュリティグループは、仮想マシン（のネットワークインターフェース）ごとに付ける、許可の規則の一覧です。「どのポートへの、どこからの通信を許すか」を書き、書いていない通信はすべて拒否されます。

  • セキュリティグループ：必要なポートだけを、必要な送り元にだけ開ける。SSH（22）を 0.0.0.0/0（どこからでも）に開けたままにしない
  • ルーティング：サブネットの経路表に、インターネットへの出口（インターネットゲートウェイ）への経路があるかどうかで、外から届くサブネットか、届かないサブネットかが決まる。データベースのように外から使わないサーバは、外への経路のないサブネットに置く
  • クラウドのファイアウォールと、OS の中のファイアウォール（firewalld、iptables）は別のもので、両方を設定できる。片方があるからといって、もう片方を省いてよいわけではない

リージョンの選択とデータの所在地

リージョンは、事業者のデータセンターがある地域（東京、大阪、北米東部など）です。リージョンごとに、データが物理的に置かれる国が決まります。選ぶときに考えることは次のとおりです。

  • データの所在地：個人情報などは、国の法令や契約で「国内に保管すること」と決められていることがある。データを置いた国の法律が適用される
  • 遅延：利用者に近いリージョンほど、応答が速い
  • 料金と使える機能：リージョンによって料金が違い、新しい機能がまだないこともある
  • 災害への備え：1 つのリージョンの中にも、離れた場所のデータセンター（アベイラビリティゾーン）がある。大事なシステムは複数に分けて置く

揮発性ストレージと永続ストレージ

仮想マシンのディスクには、2 種類あります。

種類例データの寿命向いている用途
揮発性（エフェメラル）ストレージAWS のインスタンスストアインスタンスを停止・削除したとき、物理サーバが故障したときに消える一時ファイル、キャッシュ、作り直せるデータ
永続ストレージブロックストレージのボリューム（AWS の EBS）、オブジェクトストレージインスタンスと独立して残るOS、データベース、ログ、バックアップ

揮発性のストレージは、物理サーバに直接つながっていて速いのですが、仮想マシンが別の物理サーバに移ると中身はついてきません。消えて困るデータは、永続ストレージに置き、さらにバックアップを取ります。

メンテナンスによる再起動

事業者は、物理サーバの部品の交換やソフトウェアの更新のために、メンテナンスを行います。そのとき、その上で動いている仮想マシンが、事前の通知の後に再起動や停止・起動を求められることがあります（予定された日時を過ぎると、事業者が行うこともあります）。停止・起動で別の物理サーバに移ると、揮発性ストレージの中身は消えます。

利用者が備えておくことは、次のとおりです。

  • 必要なサービスは systemctl enable で、起動したら自動で動くようにしておく（1.10.2）
  • 残すデータは永続ストレージに置く
  • 事業者からのメンテナンスの通知を受け取れるようにしておき、都合のよい時間に自分で再起動する
  • 1 台が止まってもサービスが続くよう、複数の仮想マシンやゾーンに分けておく
要点まとめ
  • SUID / SGID の点検は find / -perm -4000（SUID）、-perm -2000（SGID）、-perm /6000（どちらか）。- は全部、/ はどれか、記号なしはぴったり
  • ロックは passwd -l / usermod -L（ハッシュの先頭に !）、解除は passwd -u / usermod -U。期限は chage：-l 表示、-M 最長、-m 最短、-W 警告、-I 猶予、-E アカウントの期限、-d 0 次回に変更を強制
  • ポートは ss -tulnp / netstat -tulnp（内から）、nmap（外から）。プロセスは lsof -i :ポート、fuser -v 8080/tcp、fuser -k で殺す。who・w はいまの人、last は履歴（wtmp）、lastb は失敗（btmp）
  • ulimit：-n ファイル数、-u プロセス数、-f ファイルの大きさ、-c core。-S ソフト、-H ハード。一般ユーザーはハードを上げられない。TMOUT は放置したシェルを自動ログアウト
  • su - はログインし直した状態。/etc/sudoers は visudo で。書式は ユーザー ホスト=(だれとして) コマンド、%グループ、NOPASSWD:

  • systemctl stop（いま）・disable（次から）・mask（絶対に）。古い形は service、chkconfig、/etc/init.d/
  • iptables：INPUT・OUTPUT・FORWARD、-A 最後・-I 先頭・-D 削除・-L 表示・-P ポリシー・-F 全消し（ポリシーは残る）、DROP は黙って捨て、REJECT はエラーを返す。firewalld：--permanent + --reload
  • SSH：ssh-keygen -t rsa|ecdsa|ed25519、秘密鍵 ~/.ssh/id_種類、公開鍵 .pub、サーバの ~/.ssh/authorized_keys（ssh-copy-id）、ssh-agent と ssh-add。転送は -L（手元で待つ）、-R（サーバ側で待つ）、-D（SOCKS）。PermitRootLogin no、PasswordAuthentication no
  • GPG：暗号化は相手の公開鍵（-e -r）、復号は自分の秘密鍵（-d）、署名は自分の秘密鍵（-s）、検証は相手の公開鍵（--verify）。鍵は ~/.gnupg/、パスフレーズは gpg-agent が覚える
  • クラウド：管理コンソールの最上位アカウントは MFA を付けて封印。多要素は要素の種類が 2 つ以上。セキュリティグループとルーティングで入口を絞る。リージョンはデータの所在地と遅延で選ぶ。揮発性ストレージは停止で消える。メンテナンスの再起動に備えて enable と永続ストレージ
