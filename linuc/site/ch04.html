第 4 章

リポジトリとパッケージ管理

4.2パッケージとは何か

ソフトウェアを使うには、プログラムのファイルを /usr/bin に、説明書を /usr/share/man に、設定を /etc に置く必要があります（場所の決まりは図解 Linux 3.1）。これを手で 1 つずつやるのは大変です。

パッケージは、置くファイルをまとめて 1 つにしたものです。中には、ファイルのほかにメタデータ（名前、版、どのパッケージを必要とするか、説明）と、入れる前後に動かすスクリプトも入っています。パッケージを入れたら、システムは「どのパッケージのどのファイルをどこに置いたか」をパッケージのデータベースに記録します。だから、後で消すときも、何を消せばよいかが分かります。

パッケージの形は、ディストリビューションの系統で 2 つに分かれます。

Debian 系Red Hat 系
代表Debian、UbuntuRHEL、CentOS、Rocky Linux、AlmaLinux、Fedora
パッケージファイル.deb.rpm
低レベルの道具（1 つのファイルを扱う）dpkgrpm
高レベルの道具（リポジトリと依存を扱う）apt、apt-get、apt-cacheyum、dnf
リポジトリの設定/etc/apt/sources.list/etc/yum.repos.d/*.repo
データベース/var/lib/dpkg//var/lib/rpm/

パッケージのファイル名には、名前と版と CPU の種類（アーキテクチャ）が入っています。区切り方が 2 つの系統で違います。

系統例読み方
Debian 系tree_2.1.0-1_arm64.deb名前 _ 版 - Debian での改訂 _ アーキテクチャ
Red Hat 系tree-1.8.0-10.el9.aarch64.rpm名前 - 版 - リリース . アーキテクチャ
パッケージのファイル名を、区切りで分けてみる⌘↵
echo tree_2.1.0-1_arm64.deb | tr '_' '\n'echo tree-1.8.0-10.el9.aarch64.rpm | sed 's/\.rpm$//' | awk -F. '{print "アーキテクチャ:", $NF}'

all（Debian 系）や noarch（Red Hat 系）は、CPU の種類によらないパッケージです。シェルスクリプトや文書だけのパッケージがそうです。

4.3依存関係とリポジトリ

ほとんどのプログラムは、ほかのパッケージに入っている共有ライブラリを使います（仕組みは図解 Linux 18.7）。だから、curl パッケージだけを入れても動きません。libcurl4 も、その先の libssl3 も要ります。これを依存関係といいます。パッケージのメタデータには「何に依存するか」が書いてあります。

依存するパッケージを自分で 1 つずつ探して入れるのは大変です。そこで、パッケージを集めて置いておくリポジトリ（配布元のサーバ）と、それを使う高レベルの道具があります。

流れは 2 段です。まず update で、リポジトリからパッケージの一覧（インデックス）を取ってきて手元に保存します。次に install で、手元の一覧を見て依存をたどり、必要な .deb を全部ダウンロードして、低レベルの道具（dpkg）に渡します。Red Hat 系でも同じで、yum / dnf が依存を解いて、rpm のしくみで入れます。

低レベルの道具は、渡された 1 つのファイルしか扱いません。依存するパッケージが入っていなければ、エラーで止まるだけです。実際に、curl の .deb だけを dpkg -i で入れると、こうなります。

ターミナル
# dpkg -i curl_7.88.1-10+deb12u15_arm64.debSelecting previously unselected package curl.(Reading database ... 6090 files and directories currently installed.)Preparing to unpack curl_7.88.1-10+deb12u15_arm64.deb ...Unpacking curl (7.88.1-10+deb12u15) ...dpkg: dependency problems prevent configuration of curl: curl depends on libcurl4 (= 7.88.1-10+deb12u15); however:  Package libcurl4 is not installed. dpkg: error processing package curl (--install): dependency problems - leaving unconfiguredErrors were encountered while processing: curl

curl は展開されたものの、設定されないまま残りました。ここで apt-get install -f（-f は fix-broken、壊れた依存を直す）を実行すると、apt が足りない 21 個を入れて、curl の設定まで終わらせます。

パッケージのメタデータの依存の行は、カンマで区切った一覧です。次は、その形の例です。

Depends の行を、1 行に 1 つの依存に分ける⌘↵
echo 'Depends: libc6 (>= 2.17), libcurl4 (= 7.88.1-10+deb12u15), zlib1g (>= 1:1.1.4)' | sed 's/^Depends: //' | tr ',' '\n' | sed 's/^ //'

(>= 2.17) は「2.17 以上の版」、(= …) は「ちょうどこの版」という条件です。

用語意味
パッケージファイル + メタデータ + スクリプトをまとめたもの（.deb、.rpm）
依存関係そのパッケージが動くのに必要な、ほかのパッケージ
リポジトリパッケージを集めて配るサーバ（や、ディレクトリ）
低レベルの道具手元の 1 つのファイルを入れる・消す・調べる。依存は解決しない（dpkg、rpm）
高レベルの道具リポジトリから依存ごとまとめて入れる（apt、yum、dnf）

依存関係を自動で解決するのは、高レベルの道具（apt-get、apt、yum、dnf）です。dpkg -i と rpm -i は、依存が足りなければエラーで止まるだけです。

4.4apt の 3 つのコマンド：apt-get、apt-cache、apt

Debian 系の高レベルの道具は、昔から apt-get（入れる・消す・更新する）と apt-cache（一覧を調べる）の 2 つに分かれていました。あとから、よく使う機能を 1 つにまとめた apt ができました。apt は進み具合の表示などが人に見やすく、apt-get と apt-cache は出力の形が変わらないのでスクリプト向きです。

やりたいことapt-get / apt-cacheapt
一覧を更新するapt-get updateapt update
入れるapt-get install 名前apt install 名前
消すapt-get remove 名前apt remove 名前
設定ファイルも消すapt-get purge 名前apt purge 名前
不要になった依存を消すapt-get autoremoveapt autoremove
入っているものを新しくするapt-get upgradeapt upgrade
依存の変化も含めて新しくするapt-get dist-upgradeapt full-upgrade
ダウンロードした .deb を消すapt-get cleanapt clean
探すapt-cache search 正規表現apt search 正規表現
詳しく見るapt-cache show 名前apt show 名前
依存を見るapt-cache depends 名前—
版と優先度を見るapt-cache policy 名前apt policy 名前
入っているものの一覧—apt list --installed

入れる・消す・更新するには root の権限が要ります（sudo apt install …。図解 Linux 4.8）。この章の # のプロンプトは root で打った例です。

4.5/etc/apt/sources.list の 1 行を読む

apt がどのリポジトリを見るかは、/etc/apt/sources.list と、/etc/apt/sources.list.d/ の下のファイルに書きます。1 行が 1 つのリポジトリで、空白で区切った 4 つ以上の欄でできています。

欄例意味
種類deb / deb-srcdeb はビルド済みのパッケージ、deb-src はソースコードのパッケージ
URLhttp://deb.debian.org/debianリポジトリの場所。http://、https://、file:/、cdrom: など
suitebookworm、bookworm-updates、bookworm-security、stableディストリビューションの版の名前（コードネーム）か、stable のような種類
componentmain、contrib、non-free、non-free-firmwareリポジトリの中の区分。Debian では、main が自由なソフトウェアだけ、contrib は自由だが自由でないものに依存するもの、non-free は自由でないもの

Docker の debian:12 で、次の 4 行の sources.list を書いて apt-get update をすると、3 つのリポジトリから一覧を取ってきました（deb-src の行はソースの一覧です）。

ターミナル
# cat /etc/apt/sources.listdeb http://deb.debian.org/debian bookworm main contrib non-free non-free-firmwaredeb http://deb.debian.org/debian bookworm-updates maindeb http://deb.debian.org/debian-security bookworm-security maindeb-src http://deb.debian.org/debian bookworm main# apt-get updateHit:1 http://deb.debian.org/debian bookworm InReleaseHit:2 http://deb.debian.org/debian bookworm-updates InReleaseHit:3 http://deb.debian.org/debian-security bookworm-security InReleaseReading package lists...

同じ書式のファイルを、小さな Linux で作って読んでみます。

sources.list の欄を awk で取り出す⌘↵
mkdir -p ~/aptcat > ~/apt/sources.list <<'EOF'# Debian 12 (bookworm)deb http://deb.debian.org/debian bookworm main contrib non-freedeb http://deb.debian.org/debian bookworm-updates maindeb http://deb.debian.org/debian-security bookworm-security main#deb-src http://deb.debian.org/debian bookworm mainEOFgrep -v '^#' ~/apt/sources.list | awk '{print "種類=" $1, "suite=" $3, "component の数=" NF-3}'

# で始まる行はコメントで、apt は読みません。最後の deb-src の行は、# を外すと有効になります。

メモ新しい書き方：.sources（deb822 形式）

Debian 12 の Docker イメージには /etc/apt/sources.list がなく、/etc/apt/sources.list.d/debian.sources に、次の形で書かれていました。中身は同じで、欄に名前が付いただけです。試験で問われるのは、上の 1 行の形です。

ターミナル
# cat /etc/apt/sources.list.d/debian.sourcesTypes: debURIs: http://deb.debian.org/debianSuites: bookworm bookworm-updatesComponents: mainSigned-By: /usr/share/keyrings/debian-archive-keyring.gpg
注意試験の注意

sources.list の欄の順番は 種類 → URL → suite → component です。bookworm や stable は suite、main や contrib は component です。書き換えたら、apt-get update で一覧を取り直すまで、apt は新しいリポジトリのパッケージを知りません。

4.6update と upgrade は別のもの

名前が似ていて、試験でよく問われるところです。

コマンド何をするか
apt-get updateリポジトリからパッケージの一覧を取ってきて、手元の一覧を新しくする。パッケージそのものは何も変えない
apt-get upgrade入っているパッケージを、一覧にある新しい版に入れ替える。新しいパッケージを入れることも、パッケージを消すこともしない。それが要る更新は保留する
apt-get dist-upgradeupgrade に加えて、依存の変化に合わせて新しいパッケージを入れたり、パッケージを消したりもする
apt full-upgradeapt-get dist-upgrade にあたる、apt の名前
apt upgrade入っているものを新しくする。必要なら新しいパッケージは入れるが、消すことはしない

ふつうの手順は「update してから upgrade」です。update をしないと、apt は古い一覧しか知らないので、新しい版があることに気づきません。

ターミナル
# apt-get update（省略）# apt-get upgradeReading package lists...Building dependency tree...Reading state information...0 upgraded, 0 newly installed, 0 to remove and 0 not upgraded.

最後の行は「入れ替えた数、新しく入れた数、消す数、保留した数」です。upgrade で保留された（not upgraded）ものがあるとき、それは「新しく入れるか消すかが要る更新」です。dist-upgrade なら入ります。

注意試験の注意

update はパッケージを更新しません。一覧を取ってくるだけです。Red Hat 系の yum update はパッケージを更新するので、名前が同じでも意味が逆に近いことに気をつけます（yum のサブコマンド）。

4.7入れる・消す：install、remove、purge、autoremove

install には、.deb のファイル名ではなくパッケージの名前を渡します（apt-get install tree）。依存するパッケージは、apt が自動で選んで一緒に入れます。

ターミナル
# apt-get install -y tree（省略）0 upgraded, 1 newly installed, 0 to remove and 0 not upgraded.Need to get 50.9 kB of archives.After this operation, 169 kB of additional disk space will be used.Get:1 http://deb.debian.org/debian bookworm/main arm64 tree arm64 2.1.0-1 [50.9 kB]Fetched 50.9 kB in 0s (1218 kB/s)Selecting previously unselected package tree.Preparing to unpack .../tree_2.1.0-1_arm64.deb ...Unpacking tree (2.1.0-1) ...Setting up tree (2.1.0-1) ...

-y は「よろしいですか」に自動で yes と答えるオプションです。ダウンロードした .deb は /var/cache/apt/archives/ に置かれます。apt-get clean で、ここを空にできます。

消し方は 3 つあります。

  • remove：プログラムなどのファイルを消す。/etc などの設定ファイルは残す（入れ直したとき、前の設定がそのまま使えるように）
  • purge：設定ファイルも消す。apt-get remove --purge と書いても同じ
  • autoremove：依存のために自動で入ったパッケージのうち、もう使うものがなくなったものを消す

cron パッケージで確かめました。cron には設定ファイル（/etc/default/cron など）があります。remove の後もそれは残り、dpkg -l の状態は rc になります。purge で消えます。

ターミナル
# apt-get remove -y cron（省略）# ls /etc/default/cron/etc/default/cron# dpkg -l cron | tail -1rc  cron           3.0pl1-162   arm64        process scheduling daemon# apt-get purge -y cron（省略）# ls /etc/default/cronls: cannot access '/etc/default/cron': No such file or directory

autoremove は、curl を入れて消したときに出てきます。curl と一緒に入った 18 個のライブラリが、curl を消した後に「もう要らない」と表示されます。

ターミナル
# apt-get remove -y curl（省略）The following packages were automatically installed and are no longer required:  krb5-locales libbrotli1 libcurl4 libgssapi-krb5-2 libk5crypto3 libkeyutils1  libkrb5-3 libkrb5support0 libldap-2.5-0 libldap-common libnghttp2-14 libpsl5  librtmp1 libsasl2-2 libsasl2-modules libsasl2-modules-db libssh2-1  publicsuffixUse 'apt autoremove' to remove them.# apt-get autoremove -y（省略）The following packages will be REMOVED:  krb5-locales libbrotli1 libcurl4 libgssapi-krb5-2 libk5crypto3 libkeyutils1  ...
コマンド意味
apt-get install 名前依存ごと入れる。-y で確認なし
apt-get install -f壊れた依存を直す（足りない依存を入れる）。--fix-broken
apt-get install -d 名前ダウンロードだけする（--download-only）。.deb は /var/cache/apt/archives/ へ
apt-get download 名前.deb をいまのディレクトリにダウンロードするだけ
apt-get remove 名前消す。設定ファイルは残る
apt-get purge 名前設定ファイルも消す（remove --purge と同じ）
apt-get autoremove自動で入って不要になった依存を消す
apt-get clean/var/cache/apt/archives/ の .deb を消す（autoclean は、もう手に入らない古い版だけ）

apt なら .deb のファイルも渡せます。 apt install ./tree_2.1.0-1_arm64.deb のように ./ を付けてファイルを渡すと、apt はそのファイルを入れ、足りない依存はリポジトリから入れます。dpkg -i と違って依存で止まりません。

4.8調べる：search、show、depends、policy、apt-file

apt-cache は、update で手元に取ってきた一覧を調べるだけのコマンドです。何も変えないので、root でなくても使えます。

ターミナル
$ apt-cache search --names-only '^tree$'tree - displays an indented directory tree, in color$ apt-cache show treePackage: treeVersion: 2.1.0-1Installed-Size: 165Maintainer: Florian Ernst <florian@debian.org>Architecture: arm64Depends: libc6 (>= 2.34)Description: displays an indented directory tree, in color（省略）Section: utilsPriority: optionalFilename: pool/main/t/tree/tree_2.1.0-1_arm64.debSize: 50920$ apt-cache depends curlcurl  Depends: libc6  Depends: libcurl4  Depends: zlib1g$ apt-cache rdepends libcurl4libcurl4Reverse Depends:  curl  systemd-journal-remote（省略）

search の引数は正規表現で、名前と説明の両方から探します（--names-only で名前だけ）。depends は「このパッケージが必要とするもの」、rdepends（reverse depends）は逆に「このパッケージを必要とするもの」です。

policy は、版の情報を見ます。

ターミナル
$ apt-cache policy treetree:  Installed: 2.1.0-1  Candidate: 2.1.0-1  Version table: *** 2.1.0-1 500        500 http://deb.debian.org/debian bookworm/main arm64 Packages        100 /var/lib/dpkg/status
行意味
Installed:いま入っている版。入っていなければ (none)
Candidate:install や upgrade をしたら入る版（候補）
Version table:手に入る版と、どのリポジトリにあるか。数字は優先度。*** がいま入っている版

apt-file は、「このファイルはどのパッケージに入っているか」を、まだ入れていないパッケージも含めて調べる道具です。別のパッケージ（apt-file）なので、入れてから apt-file update で、ファイルの一覧を取ってきます。

ターミナル
# apt-get install -y apt-file# apt-file update$ apt-file search bin/htophtop: /usr/bin/htop$ apt-file list treetree: /usr/bin/treetree: /usr/share/doc/tree/README.gztree: /usr/share/doc/tree/TODO（省略）tree: /usr/share/man/man1/tree.1.gz

htop は入れていませんが、/usr/bin/htop は htop パッケージにあると分かりました。

コマンド調べる対象何が分かるか
apt-cache search 正規表現リポジトリの一覧名前か説明に合うパッケージ
apt-cache show 名前リポジトリの一覧版、依存、大きさ、説明
apt-cache depends 名前リポジトリの一覧依存するパッケージ
apt-cache rdepends 名前リポジトリの一覧そのパッケージに依存するパッケージ
apt-cache policy 名前リポジトリの一覧と、入っているもの入っている版、候補の版、優先度
apt-file search ファイルリポジトリのファイルの一覧そのファイルを含むパッケージ（入っていなくてよい）
apt-file list 名前リポジトリのファイルの一覧パッケージに入っているファイル（入っていなくてよい）
apt list --installed入っているもの入っているパッケージの一覧
注意試験の注意

「ファイルからパッケージを探す」には 2 つあります。dpkg -S は入っているパッケージだけ、apt-file search はリポジトリにあるすべてのパッケージから探します。apt-cache search は名前と説明を探すもので、中のファイル名は探しません。

4.9dpkg：.deb を直接扱う

dpkg は Debian 系の低レベルの道具です。手元の .deb ファイルを入れたり、入っているパッケージを消したり調べたりします。依存の解決はしません。

オプション長い形意味引数
-i--install入れる.deb ファイル
-r--remove消す。設定ファイルは残るパッケージ名
-P--purge設定ファイルも消すパッケージ名
-l--list入っているパッケージを状態つきで一覧（パターンも可）なし / パターン
-L--listfilesそのパッケージが置いたファイルの一覧パッケージ名
-S--searchそのファイルを置いたパッケージを探すファイル（パターン）
-s--status状態と詳しい情報パッケージ名
--configure展開したが設定していないパッケージを設定する。-a ですべてパッケージ名 / -a

4.11dpkg-reconfigure：最初の質問に答え直す

パッケージの中には、入れるときに質問をするものがあります。tzdata（タイムゾーン）、locales（言語）、keyboard-configuration（キーボード）などです。答えは debconf という仕組みが覚えていて、設定ファイルに反映されます。

dpkg-reconfigure パッケージ名 は、入っているパッケージの設定をやり直すコマンドです。質問がもう一度出て、答え直すと設定ファイルが書き換わります。

ターミナル

コマンド意味
dpkg-reconfigure パッケージ名入っているパッケージの設定の質問に答え直す
dpkg --configure パッケージ名展開されて、まだ設定されていないパッケージを設定する（-a ですべて）

dpkg-reconfigure は入っているパッケージの設定をやり直すもので、パッケージを入れ直すわけではありません。dpkg --configure は「途中で止まったものの設定を済ませる」もので、目的が違います。

4.14リポジトリの設定：.repo と yum.conf

yum がどのリポジトリを見るかは、/etc/yum.repos.d/ の下の、名前が .repo で終わるファイルに書きます。1 つのファイルに、[ID] で始まるリポジトリをいくつ書いてもかまいません。

キー意味
[ID]リポジトリの ID。yum repolist の repo id に出る

4.16rpm：入れる、新しくする、消す

rpm は Red Hat 系の低レベルの道具で、dpkg にあたります。手元の .rpm を扱い、依存は解決しません。

オプション長い形意味
-i--install入れる（同じものが入っているとエラー）
-U--upgrade新しくする。入っていなければ入れる
-F--freshen新しくする。入っていなければ何もしない

-v / -h詳しく表示 / 進み具合を # で表示。-ivh、-Uvh とまとめて使う

rpm --help の説明も、-F は「入っていれば新しくする」です。

ターミナル

tree が入っていない状態で、-F と -U を比べました。-F は何もせず成功で終わり、-U は入れました。もう一度 -i をすると、入っているのでエラーです。

-U と -F の違いは「入っていないとき」です。-U は入れる、-F は何もしない。-e にはパッケージ名（tree）を渡し、ファイル名（tree-1.8.0-10.el9.aarch64.rpm）は渡しません。--nodeps は依存の確認を飛ばすだけで、足りない依存を入れてはくれません。

-q（query）は、データベースに問い合わせるオプションです。後ろに文字を足して、何を聞くかを決めます。

4.18rpm -V と --import：検査と署名の鍵

rpm -V 名前（verify）は、入れたときのファイルの記録と、いまのファイルを比べて、変わったものだけを表示します。何も出なければ、変わっていません。rpm -Va ですべてのパッケージを検査します。

tree を入れた後、文書のファイルに 1 行足し、コマンドのファイルを消してから検査しました。

印意味
S大きさ（Size）が違う
M権限やファイルの種類（Mode）が違う
5中身のダイジェスト（昔は MD5）が違う＝中身が変わった
T更新時刻（mTime）が違う
U / G持ち主 / グループが違う
missingファイルがない
c / d設定ファイル / 文書ファイル（印の後ろの 1 文字）
rpm -V の出力から、中身が変わったもの（3 文字目が 5）を探す⌘↵
cat > ~/rpm/verify.txt <<'EOF'missing     /usr/bin/treeS.5....T.  d /usr/share/doc/tree/README.M.......    /var/logS.5....T.  c /etc/sample.confEOFcut -c1-9 ~/rpm/verify.txtawk 'substr($0, 3, 1) == "5" { print $NF }' ~/rpm/verify.txt

rpm --import 鍵のファイル は、パッケージの署名を確かめるための GPG 公開鍵を、rpm のデータベースに取り込みます。取り込んだ鍵は、gpg-pubkey という名前のパッケージのように見えます。.repo の gpgcheck=1 は、この鍵で署名を確かめるという意味です（yum は gpgkey= の鍵を、初めて使うときに自動で取り込みます）。

ターミナル
$ rpm -q gpg-pubkeypackage gpg-pubkey is not installed# rpm --import /etc/pki/rpm-gpg/RPM-GPG-KEY-Rocky-9$ rpm -q gpg-pubkeygpg-pubkey-350d275d-6279464b
コマンド意味
rpm -V 名前入っているパッケージのファイルが変わっていないか検査する（--verify）。-Va で全部
rpm --import 鍵GPG 公開鍵を取り込む
深掘りrpm と dpkg の対応表

2 つの低レベルの道具は、できることがほぼ対応しています。片方を覚えたら、もう片方は文字の違いで覚えられます。

やりたいことdpkgrpm
ファイルから入れるdpkg -i x.debrpm -i x.rpm（-U も）
消すdpkg -r 名前 / dpkg -P 名前rpm -e 名前
一覧dpkg -lrpm -qa
詳しい情報dpkg -s 名前rpm -qi 名前
入っているファイルdpkg -L 名前rpm -ql 名前
ファイル → パッケージdpkg -S ファイルrpm -qf ファイル
パッケージファイルの中身dpkg -c x.debrpm -qpl x.rpm
要点まとめ
  • パッケージは、ファイル + メタデータ（名前・版・依存）+ スクリプト。Debian 系は .deb、Red Hat 系は .rpm
  • 低レベルの道具（dpkg、rpm）は 1 つのファイルを扱い、依存を解決しない。高レベルの道具（apt、apt-get、yum、dnf）はリポジトリから依存ごと入れる
  • /etc/apt/sources.list は deb URL suite component…。apt-get update は一覧を取るだけ、upgrade は入れ替えるだけ（追加・削除なし）、dist-upgrade（apt では full-upgrade）は追加・削除もする
  • remove は設定ファイルを残し（dpkg -l で rc）、purge は消す。autoremove は不要になった自動の依存を消す
  • 調べる：apt-cache search / show / depends / policy。ファイルから探す：入っているものは dpkg -S / rpm -qf、リポジトリからは apt-file search / yum provides
  • dpkg：-i ファイル、-r / -P 消す、-l 一覧、-L ファイル一覧、-S 持ち主、-s 状態、--configure -a。dpkg-reconfigure は設定の質問に答え直す
  • yum（いまは dnf の別名）：install / remove / update / search / info / list / provides / groupinstall / repolist / clean all。yum update は実際に更新する
  • /etc/yum.repos.d/*.repo は [ID]、name、baseurl、enabled、gpgcheck。全体の設定は /etc/yum.conf。yumdownloader はダウンロードだけ（--resolve で依存も）
  • rpm：-i 入れる、-U 入っていなくても入れる、-F 入っていれば新しくする、-e 消す、--nodeps 依存を見ない。-q に a i l f R を足して問い合わせ、-p で手元のファイル。-V で検査、--import で鍵
