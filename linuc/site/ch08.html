8.2アカウントの情報は、どの 3 つのファイルにあるか

ユーザーとグループの情報は、/etc の下のテキストファイルにあります。試験に出るのは次の 4 つです。

ファイル中身1 行の欄の数だれが読めるか
/etc/passwdユーザーの一覧7だれでも
/etc/shadowパスワードのハッシュと期限9root（と shadow グループ）だけ
/etc/groupグループの一覧4だれでも
/etc/gshadowグループのパスワード4root（と shadow グループ）だけ

まず小さな Linux で、ファイルの権限を見ます。

3 つのファイルの権限⌘↵
ls -l /etc/passwd /etc/shadow /etc/group

/etc/passwd と /etc/group は、だれでも読めます（r-- が「その他」にもある）。ls -l が uid を名前に直すために、どのユーザーも読む必要があるからです。パスワードのハッシュだけを /etc/shadow に分けて、root しか読めないようにしてあります。

/etc/passwd の 7 つの欄（復習）

ユーザーの一覧⌘↵
cat /etc/passwd

欄は ユーザー名:x:uid:gid:説明:ホーム:シェル の 7 つです（図解 Linux 4.1）。2 番目の x は「パスワードは /etc/shadow にある」という印です。4 番目は主グループの gid、5 番目は説明（GECOS 欄。本名などを書く）です。

: 区切りなので、cut や awk で欄を取り出せます。uid が 1000 以上の人について、名前とホームとシェルを出します。

欄を取り出す⌘↵
awk -F: '$3 >= 1000 {print $1, $6, $7}' /etc/passwd

nobody（65534）も出ました。uid が 1000 以上でも、人ではないユーザーもいます。

/etc/shadow の 9 つの欄

欄意味値の例と読み方
1ユーザー名ken
2パスワードのハッシュ$6$…。先頭が ! ならロック中。* や !! はログインに使えるパスワードがない。空ならパスワードなし
3最後にパスワードを変えた日1970-01-01 からの日数。20773 は 2026-11-16。0 は「次のログインで変更させる」
4最短日数変えてから、次に変えられるまでの日数。0 ならいつでも変えられる
5最長日数この日数がたつと、変えなければならない。99999 は事実上無期限
6警告の日数期限の何日前から警告するか
7猶予の日数期限が切れてから、何日でアカウントを使えなくするか
8アカウントの失効日1970-01-01 からの日数。この日にアカウントが使えなくなる
9予約使わない

ハッシュの先頭の $数字$ は、ハッシュの方式を表します。$1$ は MD5、$5$ は SHA-256、$6$ は SHA-512、$y$ は yescrypt です。Rocky Linux 9 は $6$、Debian 12 は $y$ を使います。

root なら読める⌘↵
sudo cat /etc/shadow
ふつうのユーザーは読めないエラーになる⌘↵
cat /etc/shadow

root の 2 番目の欄は * なので、root にはパスワードでログインできません。この Linux では sudo を使います。

/etc/group と /etc/gshadow

グループの一覧と、そのメンバー⌘↵
cut -d: -f1,3,4 /etc/group

/etc/group は グループ名:x:gid:メンバー の 4 つの欄です。4 番目のメンバーは、そのグループを補助グループ（主グループのほかに入っているグループ）にしているユーザーです。主グループは /etc/passwd の 4 番目で決まるので、ここには書きません。2 番目の x は「グループのパスワードは /etc/gshadow にある」という印です。

getent と id：情報を引く

ユーザーの情報は、/etc/passwd のほかに、LDAP などのネットワークのデータベースに置くこともできます。どこを見るかは /etc/nsswitch.conf で決まります。getent は、その設定に従って項目を引くコマンドです。

getent でユーザーとグループを引く⌘↵
getent passwd yougetent passwd 1001getent group staff

getent データベース名 キー の形です。データベース名は passwd、group、hosts などで、キーは名前でも番号でもかまいません。キーを省くと全部を出します。本物の Linux では、root なら getent shadow ユーザー名 で /etc/shadow の行も引けます。

id の主なオプション⌘↵
id aliceid -u aliceid -g aliceid -Gn alice
コマンド出すもの
id [ユーザー]uid、主グループの gid、所属するすべてのグループ
id -uuid だけ
id -g主グループの gid だけ
id -G所属するすべてのグループの gid
id -n（-u、-g、-G と組み合わせて）番号の代わりに名前
groups [ユーザー]所属するグループの名前

8.3useradd：ユーザーを作ると何が起きるか

useradd ユーザー名 は、root が実行するユーザーを作るコマンドです。オプションで指定しなかったことは、既定値で埋めます。既定値は 2 つのファイルにあります。

  • /etc/default/useradd：useradd だけが読む既定値（ログインシェル、ホームの親ディレクトリ、スケルトンなど）
  • /etc/login.defs：ユーザー管理のコマンドが共通に読む値（uid の範囲 UID_MIN、パスワードの期限 PASS_MAX_DAYS、ハッシュの方式 ENCRYPT_METHOD、ホームを作るかどうか CREATE_HOME など）

useradd のオプション

オプション意味
-mホームディレクトリを作り、/etc/skel の中身をコピーする
-Mホームディレクトリを作らない
-d ディレクトリホームディレクトリの場所（-m がなければ、/etc/passwd に書くだけで作らない）
-s シェルログインシェル
-g グループ主グループ（1 つ）
-G グループ,グループ…補助グループ（カンマ区切りで複数）
-u uiduid を指定する
-c "説明"説明の欄（GECOS 欄。本名など）
-e 日付アカウントの失効日（YYYY-MM-DD）。/etc/shadow の 8 番目の欄に入る
-k ディレクトリ/etc/skel の代わりに使うひな形（-m と一緒に使う）
-rシステムアカウント（デーモン用。uid を小さい範囲から取る）
-D既定値を表示する。ほかのオプションと組み合わせると、既定値を変える

Debian 12 で、オプションを付けて作ってみた結果です。

ターミナル
# useradd -m -s /bin/bash -c "Hanako Yamada" -u 1500 hanako# grep hanako /etc/passwd /etc/shadow/etc/passwd:hanako:x:1500:1500:Hanako Yamada:/home/hanako:/bin/bash/etc/shadow:hanako:!:20773:0:99999:7:::# ls -a /home/hanako.  ..  .bash_logout  .bashrc  .profile

/etc/skel にあった .bashrc などが、ホームにコピーされました。/etc/shadow の 2 番目は ! で、まだパスワードがない（ログインできない）状態です。passwd hanako でパスワードを決めると使えるようになります。

主グループを指定しなかったので、ユーザーと同じ名前のグループ hanako（gid 1500）が作られました。これは /etc/login.defs の USERGROUPS_ENAB yes による動きで、Debian も Red Hat 系も同じです。

ターミナル
# groupadd -g 2000 dev# groupadd ops# useradd -m -d /srv/jiro -g dev -G ops,users -e 2027-03-31 jiro# grep jiro /etc/passwd /etc/shadow/etc/passwd:jiro:x:1501:2000::/srv/jiro:/bin/sh/etc/shadow:jiro:!:20773:0:99999:7::20908:# id jirouid=1501(jiro) gid=2000(dev) groups=2000(dev),100(users),2001(ops)

-g dev で主グループが dev になり、-G ops,users で補助グループが 2 つ付きました。-e の日付は、/etc/shadow の 8 番目に日数（20908）で入っています。

注意試験の注意：-g と -G、-d と -m
  • 小文字の -g は主グループ（1 つ）、大文字の -G は補助グループ（カンマで複数）。usermod でも同じ
  • -d はホームの場所を決めるだけ。ディレクトリを作るのは -m
  • -D は「既定値（Default）」。-d（directory）と取り違えない

既定値は Debian と Red Hat 系で違う

useradd -D で既定値を見ます。左が Debian 12、右が Rocky Linux 9 です。

Debian 12
ターミナル
# useradd -DGROUP=100HOME=/homeINACTIVE=-1EXPIRE=SHELL=/bin/shSKEL=/etc/skelCREATE_MAIL_SPOOL=noLOG_INIT=yes
Rocky Linux 9
ターミナル
# useradd -DGROUP=100HOME=/homeINACTIVE=-1EXPIRE=SHELL=/bin/bashSKEL=/etc/skelCREATE_MAIL_SPOOL=yes

同じ useradd taro を、オプションなしで実行して比べました。

Debian 12Rocky Linux 9
ホームディレクトリ作られない（-m が必要）作られる（/etc/login.defs に CREATE_HOME yes）。権限は drwx------
ログインシェル/bin/sh/bin/bash
/etc/shadow の 2 番目!!!
/etc/skel の中身.bash_logout、.bashrc、.profile.bash_logout、.bash_profile、.bashrc

Debian 系には、対話的にユーザーを作る adduser という別のコマンドもあります。こちらはホームを作り、パスワードもたずねます。試験で「useradd」と書いてあれば、上の動きです。

既定値を変えるには、useradd -D にオプションを付けます。変えた値は /etc/default/useradd に書き込まれます。

ターミナル
# useradd -D -s /bin/zsh# grep SHELL /etc/default/useraddSHELL=/bin/zsh
useradd -D と組む変える既定値
-s シェルログインシェル（SHELL）
-b ディレクトリホームの親ディレクトリ（HOME）
-g グループ主グループ（GROUP。ユーザーと同じ名前のグループを作らないとき）
-e 日付失効日（EXPIRE）
-f 日数猶予の日数（INACTIVE）

/etc/skel に置いたものは、次から作るユーザーに配られます。/etc/skel に、たとえば共通の .bashrc や .vimrc を置いておくと、そのあと -m で作るユーザー全員のホームにコピーされます。すでにいるユーザーには配られません。

8.4usermod・userdel・グループのコマンド

作ったユーザーを変えるのが usermod、消すのが userdel です。オプションの多くは useradd と同じ文字です。

オプションusermod での意味
-G グループ,…補助グループを、指定したものだけに置き換える
-a -G グループ（-aG）補助グループに足す（今のものを残す）
-g グループ主グループを変える
-l 新しい名前ログイン名を変える（usermod -l 新 旧）。ホームの名前は変わらない
-d ディレクトリホームの場所を変える。-m を足すと中身も移す
-s シェルログインシェルを変える
-c "説明"説明の欄を変える
-u uiduid を変える
-e 日付アカウントの失効日を変える
-Lパスワードをロックする（ハッシュの先頭に ! を付ける）
-Uロックを外す（! を取る）

-G と -aG の違い

Debian 12 で確かめた結果です。

ターミナル
# usermod -G dev hanako# id hanakouid=1500(hanako) gid=1500(hanako) groups=1500(hanako),2000(dev)# usermod -aG ops hanako# id hanakouid=1500(hanako) gid=1500(hanako) groups=1500(hanako),2000(dev),2001(ops)# usermod -G ops hanako# id hanakouid=1500(hanako) gid=1500(hanako) groups=1500(hanako),2001(ops)

最後の -G ops で、dev から外れてしまいました。主グループ（hanako）は -G では変わりません。

注意試験の注意：-a を忘れると、ほかのグループから外れる

「今の所属を残したまま docker グループに入れる」は usermod -aG docker ユーザー です。-a だけでは意味がなく、必ず -G と組みます。-a を忘れると、補助グループが docker だけになります。

名前、シェル、ロック

ターミナル
# usermod -l jiro2 jiro# usermod -s /usr/sbin/nologin jiro2# grep jiro2 /etc/passwdjiro2:x:1501:2000::/srv/jiro:/usr/sbin/nologin

-l は「新しい名前、古い名前」の順です。uid とホーム（/srv/jiro）はそのままです。シェルを /usr/sbin/nologin にすると、そのユーザーではログインできなくなります（メッセージを出してすぐ終わるプログラムです）。

usermod -L はハッシュの先頭に ! を付けて、パスワードを合わなくします。-U で外します。ただし Debian では、まだパスワードを決めていないユーザー（! だけ）の -U は「パスワードなしのアカウントになる」として断られました。

userdel

コマンドすること
userdel ユーザー/etc/passwd、/etc/shadow、/etc/group などからユーザーを消す。ホームは残る
userdel -r ユーザーホームディレクトリとメールスプールも消す
userdel -f ユーザーログイン中でも強制的に消す

グループのコマンド

コマンドすること
groupadd [-g gid] グループグループを作る。-g がなければ空いている gid を使う
groupmod -n 新しい名前 グループグループの名前を変える
groupmod -g 新しい gid グループgid を変える
groupdel グループグループを消す
ターミナル
# groupmod -n devel dev# groupmod -g 2100 devel# grep devel /etc/groupdevel:x:2100:# groupdel hanakogroupdel: cannot remove the primary group of user 'hanako'

groupmod -n も「新しい名前、古い名前」の順です。gid を変えると、そのグループを主グループにしていたユーザーの /etc/passwd の 4 番目も新しい gid になります。だれかの主グループになっているグループは、groupdel で消せません。先にユーザーを消すか、主グループを変えます。

注意試験の注意：-l と -n、「新しい名前」が先

ユーザー名を変えるのは usermod -l（login）、グループ名を変えるのは groupmod -n（name）です。どちらも 新しい名前 古い名前 の順に書きます。groupmod -g の後ろは名前ではなく数字（gid）です。

8.5passwd：パスワードとその期限

passwd は、ふつうのユーザーが自分のパスワードを変えるコマンドです（setuid で root として動く仕組みは図解 Linux 4.9）。root はオプションで、ほかのユーザーのロックや期限も操作できます。

オプションすること（root だけ）/etc/shadow の変化
passwd ユーザーそのユーザーのパスワードを変える2 番目と 3 番目
-lロックする2 番目の先頭に !
-uロックを外す! を取る
-dパスワードを消す（空にする）2 番目が空
-e期限切れにして、次のログインで変更させる3 番目が 0
-S状態を表示する変わらない
-n 日数最短日数4 番目
-x 日数最長日数5 番目
-w 日数警告の日数6 番目
-i 日数猶予の日数7 番目

小さな Linux で、alice をロックして外します。

ロックすると ! が付く⌘↵
sudo passwd -l alicesudo passwd -S alicesudo grep '^alice:' /etc/shadow

passwd -S の 2 番目の L はロック中（Locked）、P は使えるパスワードがある（Password）、NP はパスワードがない（No Password）です。/etc/shadow のハッシュの前に ! が付きました。ハッシュ自体は残っているので、外せば元のパスワードで入れます。

ロックを外す⌘↵
sudo passwd -u alicesudo passwd -S alice

期限の 4 つのオプションをまとめて付けた結果です（Debian 12）。

ターミナル
# passwd -n 1 -x 90 -w 14 -i 30 hanakopasswd: password changed.# grep hanako /etc/shadowhanako:$y$j9T$…:20773:1:90:14:30::# passwd -e hanakopasswd: password changed.# grep hanako /etc/shadowhanako:$y$j9T$…:0:1:90:14:30::

-e で 3 番目が 0 になりました。hanako は次のログインで、新しいパスワードを決めさせられます。期限をもっと細かく扱う chage は、1.10（セキュリティ）で扱います。

メモRed Hat 系の passwd は表示が違う

Rocky Linux 9 の passwd は別の実装で、-S が hanako LK 2026-11-16 0 99999 7 -1 (Password locked.) のように 2 文字で答えます（LK ロック、PS パスワードあり、NP なし）。passwd -l が付けるのは !!、usermod -L が付けるのは ! でした。root がパスワードを標準入力から渡す --stdin も Red Hat 系だけのオプションです。

8.6cron：決まった時刻に繰り返す

cron（クーロン）は、決まった時刻にコマンドを繰り返し実行する仕組みです。デーモンの crond（Debian では cron）が毎分起きて、予定の表（crontab）を見ます。

欄範囲
1 分0〜59
2 時0〜23
3 日1〜31
4 月1〜12（jan、feb … でもよい）
5 曜日0〜7。0 と 7 が日曜、1 が月曜 … 6 が土曜（sun、mon … でもよい）
書き方意味例
*すべて時の欄が * なら毎時
a-b範囲曜日の 1-5 は月〜金
a,b,c並べる日の 1,15 は 1 日と 15 日
*/nn ごと分の */5 は 0, 5, 10 … 55 分
a-b/n範囲の中で n ごと時の 9-17/2 は 9, 11, 13, 15, 17 時

*/5 が何分に当たるかは、0 から 5 ずつ数えたものです。

*/5 の分⌘↵
seq 0 5 59 | paste -s -d ' '

曜日の番号は、date の %w と同じです（0 が日曜）。

2026-11-15 は何曜日で何番か⌘↵
date -d 2026-11-15 +%Adate -d 2026-11-15 +%w

自分で crontab の形の行を書き、awk で欄に分けて確かめます。

crontab の欄を読む⌘↵
cat > mycron <<'EOF'30 9 * * 1-5 /home/you/bin/report.sh*/10 * * * * /home/you/bin/check.sh0 3 1,15 * * /home/you/bin/backup.shEOFawk '{print "分=" $1, "時=" $2, "日=" $3, "月=" $4, "曜日=" $5, "→ " $6}' mycron
crontab の行いつ
30 9 * * 1-5月〜金の 9:30
*/10 * * * *10 分ごと
0 3 1,15 * *毎月 1 日と 15 日の 3:00
0 */2 * * *2 時間ごとの 0 分（0:00、2:00 …）
0 0 1 1 *1 月 1 日の 0:00
0 3 * * 0毎週日曜の 3:00（7 や sun でも同じ）
注意試験の注意：分の欄を * にしない

* 9 * * 1 は「月曜の 9 時台の毎分」で、60 回動きます。「月曜の 9:00 に 1 回」は 0 9 * * 1 です。また、日の欄と曜日の欄の両方に * 以外を書くと、「どちらかに合えば」動きます（0 0 1 * 1 は毎月 1 日と、毎週月曜）。

crontab コマンド

ユーザーごとの crontab は、crontab コマンドで扱います。ファイルを直接開いて書き換えてはいけません。

コマンドすること
crontab -e自分の crontab をエディタで編集する
crontab -l自分の crontab を表示する
crontab -r自分の crontab を確認なしで消す
crontab -i -r消す前に確認する
crontab ファイルファイルの中身で crontab を置き換える
crontab -u ユーザー -e（-l、-r）ほかのユーザーの crontab を扱う（root だけ）

Debian 12 で、nobody の crontab を作って、見て、消しました。

ターミナル
# echo "*/5 * * * * /usr/bin/true" | crontab -u nobody -# crontab -l -u nobody*/5 * * * * /usr/bin/true# ls -l /var/spool/cron/crontabs-rw------- 1 nobody crontab 201 Nov 16 11:15 nobody# crontab -r -u nobody# crontab -l -u nobodyno crontab for nobody

保存される場所は、ディストリビューションで違います。

ユーザーの crontab の場所
Red Hat 系（cronie）/var/spool/cron/ユーザー名
Debian 系/var/spool/cron/crontabs/ユーザー名

crontab -r は何も聞かずに消します。キーボードで e と r は隣り合っているので、打ちまちがえると予定がすべて消えます。-l で見てから操作し、不安なら -i を付けます。

ユーザーの crontab の行の先頭に、@reboot（起動したとき 1 回）、@daily（0 0 * * * と同じ）、@hourly、@weekly、@monthly といった略記を使うこともできます。

8.7システムの cron：/etc/crontab と cron.d と cron.daily

ユーザーの crontab のほかに、システム全体の予定を置く場所が /etc にあります。

/etc/crontab と /etc/cron.d：ユーザー名の欄がある

Debian 12 の /etc/crontab です（コメントと空行を除く）。

ターミナル
$ grep -Ev '^(#|$)' /etc/crontabSHELL=/bin/shPATH=/usr/local/sbin:/usr/local/bin:/sbin:/bin:/usr/sbin:/usr/bin17 *    * * *    root    cd / && run-parts --report /etc/cron.hourly25 6    * * *    root    test -x /usr/sbin/anacron || { cd / && run-parts --report /etc/cron.daily; }47 6    * * 7    root    test -x /usr/sbin/anacron || { cd / && run-parts --report /etc/cron.weekly; }52 6    1 * *    root    test -x /usr/sbin/anacron || { cd / && run-parts --report /etc/cron.monthly; }

5 つの時刻の欄のあと、6 番目がユーザー名（ここでは root）です。システムの crontab は 1 つのファイルにいろいろなユーザーの予定を書くので、だれとして動かすかを書きます。ユーザーの crontab（crontab -e）には、この欄がありません。

/etc/cron.d/ に置くファイルも、/etc/crontab と同じ形（ユーザー名の欄あり）です。パッケージが自分の予定を置くのに使います。Rocky Linux 9 の /etc/cron.d/0hourly は次の 1 行が中心です。

ターミナル
$ grep -Ev '^(#|$)' /etc/cron.d/0hourlySHELL=/bin/bashPATH=/sbin:/bin:/usr/sbin:/usr/binMAILTO=root01 * * * * root run-parts /etc/cron.hourly

run-parts ディレクトリ は、ディレクトリの中の実行できるファイルを、名前の順に全部実行するコマンドです。つまり /etc/cron.hourly/ に実行権の付いたスクリプトを置けば、毎時実行されます。cron.daily、cron.weekly、cron.monthly も同じで、時刻を書かずにスクリプトを置くだけで使えます。

場所中身の形ユーザー名の欄
crontab -e（/var/spool/cron/…）5 欄 + コマンドなし
/etc/crontab5 欄 + ユーザー + コマンドあり
/etc/cron.d/*5 欄 + ユーザー + コマンドあり
/etc/cron.{hourly,daily,weekly,monthly}/スクリプトそのもの—

anacron：止まっていた間の分を、あとで実行する

cron は「その時刻に動いていれば」実行します。毎日 3:00 の予定でも、ノート PC が夜は電源を切っていれば、一度も動きません。

anacron は、日単位の予定について「最後に実行してから何日たったか」を見ます。期間が過ぎていれば、起動したあとに実行します。最後に実行した日は /var/spool/anacron/ に記録します。設定は /etc/anacrontab です（Rocky Linux 9）。

ターミナル
$ grep -Ev '^(#|$)' /etc/anacrontabSHELL=/bin/shPATH=/sbin:/bin:/usr/sbin:/usr/binMAILTO=rootRANDOM_DELAY=45START_HOURS_RANGE=3-221    5    cron.daily        nice run-parts /etc/cron.daily7    25    cron.weekly        nice run-parts /etc/cron.weekly@monthly 45    cron.monthly        nice run-parts /etc/cron.monthly
欄意味7 25 cron.weekly … の行
1期間（日数。@monthly も可）7 日ごと
2遅延（分）。anacron が動き始めてから待つ時間25 分待ってから
3ジョブの名前（記録のファイル名になる）cron.weekly
4コマンドcron.weekly の中身を全部実行

Red Hat 系では、/etc/cron.hourly/0anacron が毎時 anacron を起こし、anacron が cron.daily・weekly・monthly を受け持ちます。Debian 系でも、anacron が入っていれば同じく anacron が受け持ちます（上の /etc/crontab の test -x /usr/sbin/anacron || は「anacron がなければ cron が実行する」という意味です）。anacron の単位は日で、分や時は指定できません。

cron.allow と cron.deny

/etc/cron.allow と /etc/cron.deny は、crontab コマンドを使えるユーザーを決めます。1 行に 1 人ずつユーザー名を書きます。cron.allow があれば、そちらだけが使われます。 Rocky Linux 9 で、alice を両方に書いて試しました。

ターミナル
# echo alice > /etc/cron.allow# echo alice > /etc/cron.deny# su alice -c "crontab -l"no crontab for alice# su bob -c "crontab -l"You (bob) are not allowed to use this program (crontab)# rm /etc/cron.allow# su alice -c "crontab -l"You (alice) are not allowed to use this program (crontab)

cron.allow があるあいだは、cron.deny に書いてあっても alice は使え、cron.allow にいない bob は使えません。cron.allow を消すと cron.deny が効き、alice が使えなくなりました。

Rocky Linux 9 には最初から空の /etc/cron.deny があるので、だれでも使えます。どちらもないときの扱いは cron の実装と設定によって違います。

at にも同じ形の /etc/at.allow と /etc/at.deny があり、決まりも同じです。ただし at はどちらもなければ root だけが使えます（Rocky Linux 9 で、両方を消すと一般ユーザーの atq が You do not have permission to use atq. になりました）。空の at.deny が置いてあるのは「全員に許す」という意味です。

注意試験の注意：allow が先

「cron.allow と cron.deny の両方に同じユーザーが書いてある」→ cron.allow があるので、使える。「cron.allow が空のファイルで存在する」→ だれも書いていないので、root 以外は使えない。allow は「許す名簿」、deny は「断る名簿」と覚えます。

8.8at と systemd タイマー：1 回だけ、または unit で

at は、指定した時刻に1 回だけコマンドを実行します。デーモンの atd が動いている必要があります。コマンドは標準入力から読み、端末なら Ctrl+D で入力を終えます。

ターミナル
# echo "date > /tmp/x" | at now + 5 minuteswarning: commands will be executed using /bin/shjob 1 at Mon Nov 16 11:23:00 2026# echo "echo" | at 17:00 tomorrowjob 2 at Tue Nov 17 17:00:00 2026# echo "echo" | at noonjob 3 at Mon Nov 16 12:00:00 2026# atq1    Mon Nov 16 11:23:00 2026 a root2    Tue Nov 17 17:00:00 2026 a root3    Mon Nov 16 12:00:00 2026 a root# atrm 2# atq1    Mon Nov 16 11:23:00 2026 a root3    Mon Nov 16 12:00:00 2026 a root

atq の各行は、ジョブ番号、実行する日時、キュー（a）、ユーザーです。

コマンドすること
at 時刻時刻にコマンドを実行する予約をする
at -f ファイル 時刻コマンドを標準入力ではなくファイルから読む
atq（at -l）予約の一覧
atrm 番号（at -d 番号）予約を消す
at -c 番号予約の中身（実行されるシェルスクリプト）を表示する
batch時刻ではなく、システムの負荷が下がったときに実行する
時刻の書き方意味
now + 5 minutes5 分後（hours、days、weeks も使える）
17:00次の 17:00（今日が過ぎていれば明日）
17:00 tomorrow明日の 17:00
noon、midnight正午、真夜中
10:00 2026-12-24日付を付ける

systemd のタイマー

systemd を使う系では、cron の代わりにタイマーの unit（.timer）で定期実行することもできます（unit の仕組みは図解 Linux 17.4）。名前.timer が、同じ名前の 名前.service を起こします。Rocky Linux 9 にある fstrim.timer の[Timer] と [Install] の部分です（ファイルは /usr/lib/systemd/system/fstrim.timer）。

[Timer]OnCalendar=weeklyAccuracySec=1hPersistent=true [Install]WantedBy=timers.target
設定意味

タイマーの一覧は systemctl list-timers で見ます。有効にするのは systemctl enable --now 名前.timer です。

仕組み回数単位止まっていた分

at1 回分—

8.9ロケール：言語と国と文字コードの組

国際化（internationalization）は、プログラムを特定の言語や国に依存しないように作ることです。最初の i と最後の n の間に 18 文字あるので i18n と書きます。地域化（localization、l10n）は、国際化したプログラムに、特定の言語や国の翻訳・書式を与えることです。

Linux では、言語と国と文字コードの組をロケールと呼び、環境変数で選びます。名前は 言語_国.文字コード の形です。

ロケール名意味
ja_JP.UTF-8日本語、日本、UTF-8
en_US.UTF-8英語、アメリカ、UTF-8
ja_JP.eucJP日本語、日本、EUC-JP
C（= POSIX）翻訳しない最小のロケール。メッセージは英語、並べ替えはバイトの順

LANG、LC_*、LC_ALL の優先順位

ロケールは、項目（カテゴリ）ごとに分かれています。

変数決めるもの
LC_CTYPE文字の種類（どのバイト列が 1 文字か、大文字と小文字）
LC_COLLATE並べ替えの順番
LC_TIME日付と時刻の書式
LC_NUMERIC数の書式（小数点の記号など）
LC_MONETARY通貨の書式
LC_MESSAGESメッセージの言語
LC_PAPER ほか紙の大きさ、住所や電話番号の書式など
LANG上のどれも設定されていない項目の既定値
LC_ALLすべての項目を、これで上書きする

優先順位は LC_ALL → LC_項目 → LANG です。Rocky Linux 9 で、日本語のロケールを入れて date を動かしました。

ターミナル
$ LANG=ja_JP.UTF-8 date2026年 11月 16日 月曜日 11:16:54 UTC$ LANG=ja_JP.UTF-8 LC_TIME=C dateMon Nov 16 11:16:54 UTC 2026$ LC_ALL=C LANG=ja_JP.UTF-8 dateMon Nov 16 11:16:54 UTC 2026$ LC_ALL=ja_JP.UTF-8 LC_TIME=C locale | grep -E 'LC_TIME|LC_ALL'LC_TIME="ja_JP.UTF-8"LC_ALL=ja_JP.UTF-8

2 つ目は LC_TIME が LANG に勝ち、3 つ目は LC_ALL が LANG に勝ちました。4 つ目では、LC_TIME=C を設定しても LC_ALL が勝っています。

小さな Linux でも、環境変数そのものは同じように渡せます（小さな Linux の date は翻訳を持たないので、表示は英語のままです）。

LANG と、1 回だけの LC_ALL⌘↵
echo "$LANG"LC_ALL=C sh -c 'echo "LC_ALL=$LC_ALL LANG=$LANG"'
コツスクリプトの中では LC_ALL=C

sort の順番、ls の日付の形、エラーメッセージの言語は、ロケールで変わります。スクリプトで出力を加工するときは、先頭で export LC_ALL=C としておくと、どのユーザーが実行しても同じ結果になります。LANG=C では、ユーザーが LC_ALL や LC_COLLATE を設定していると負けてしまいます。

locale と localectl

ターミナル

コマンドすること
localeいまの各項目のロケールを表示する（値が " で囲まれているのは、LANG などから決まったもの）

localectl は systemd のコマンドで、システム全体の既定値を書きます。書く先は /etc/locale.conf（Red Hat 系など）です。Debian 系では /etc/default/locale も使われます。ユーザーごとに変えたいときは、~/.bashrc などで LANG を export します。

8.10文字コードと iconv

コンピュータの中で、文字はバイトの並びです。どの文字をどのバイトにするかの決まりを文字コード（文字エンコーディング）と呼びます。同じ「あ」でも、文字コードによってバイトが違います。

A（0x41）と改行（0x0a）は、UTF-16 以外ではどれも同じ 1 バイトです。これが ASCII の部分です。

文字コード特徴
ASCII7 ビット、128 文字。英字、数字、記号、制御文字だけ。日本語は表せない
ISO-88598 ビット、1 文字 1 バイトの文字コードの集まり。下半分は ASCII と同じ。ISO-8859-1（Latin-1）は西ヨーロッパの文字（é など）。日本語は表せない
Unicode世界の文字に番号（コードポイント）を付けた文字の集合。「あ」は U+3042。バイトにする方式が UTF-8、UTF-16 など
UTF-8Unicode を 1〜4 バイトで表す。ASCII の文字は ASCII と同じ 1 バイト。日本語の多くは 3 バイト。いまの Linux の標準
UTF-16Unicode を 2 バイト（または 4 バイト）単位で表す。ASCII とは互換がない
ISO-2022-JP7 ビットだけで日本語を表す。エスケープシーケンス（ESC $ B など）で ASCII と日本語を切り替える。JIS コードとも呼ぶ。昔の電子メールで使われた
EUC-JP日本語の文字を 2 バイト（上位ビットが 1）で表す。古い Unix で使われた
Shift_JIS日本語の文字を 2 バイトで表す。Windows で使われた（その拡張が CP932）

小さな Linux の端末は UTF-8 です。od でバイトを見ます。

あ は 3 バイト、A は 1 バイト⌘↵
printf 'あA\n' | od -An -tx1printf 'あ' | wc -c

wc -c はバイトの数なので、「あ」1 文字で 3 です。

iconv：文字コードを変える

iconv は、ファイルの文字コードを変えて標準出力に書きます。

オプション意味
-f 文字コード元の文字コード（from）
-t 文字コード変えた後の文字コード（to）
-l扱える文字コードの一覧
-o ファイル標準出力ではなくファイルに書く
-c変えられない文字を捨てて続ける

Debian 12 で、UTF-8 のファイルを Shift_JIS にして、戻しました。

ターミナル
$ printf 'あA\n' > u.txt$ iconv -f UTF-8 -t SHIFT_JIS u.txt | od -An -tx1 82 a0 41 0a$ iconv -f UTF-8 -t SJIS u.txt -o s.txt$ iconv -f SJIS -t UTF-8 s.txtあA$ iconv -f UTF-8 -t ASCII u.txticonv: illegal input sequence at position 0$ iconv -l | tr ',' '\n' | grep -E 'EUC-JP|ISO-2022-JP|SHIFT_JIS'EUC-JP//ISO-2022-JP//SHIFT_JIS//

SHIFT_JIS と SJIS は同じ文字コードの別名です。ASCII に「あ」はないので、変えられずに止まりました（-c を付けると「あ」を捨てて続けます）。

注意試験の注意：-f が元、-t が先

iconv -f 元 -t 先 ファイル です。from と to で覚えます。ファイルを直接書き換えるオプションはないので、-o か > で別のファイルに書きます（同じファイルに > すると、読む前に空になります）。

要点まとめ
  • /etc/passwd（7 欄、だれでも読める）、/etc/shadow（9 欄、root だけ）、/etc/group（4 欄）。shadow の日付は 1970-01-01 からの日数。3 番目が 0 なら次のログインで変更、ハッシュの先頭の ! はロック
  • useradd -m（ホームを作り /etc/skel を写す）、-d（場所だけ）、-g（主グループ）、-G（補助グループ）、-s -u -c -e。既定値は useradd -D で表示・変更、/etc/default/useradd に入る。Debian は -m がないとホームを作らない
  • usermod -aG は足す、-G だけは置き換え。-l 新 旧、-L / -U、-s。userdel -r でホームも消す。groupmod -n 新 旧、主グループのグループは groupdel できない
  • passwd -l -u -d -e -S -n -x -w -i。getent は nsswitch.conf に従って引く。id -u -g -G -n
  • crontab は「分 時 日 月 曜日 コマンド」。曜日は 0 と 7 が日曜。*/5、1-5、1,15。crontab -e -l -r -u。/etc/crontab と /etc/cron.d は 6 番目にユーザー名
  • /etc/cron.{hourly,daily,weekly,monthly} はスクリプトを置くだけ。anacron は日単位で、止まっていた分をあとで実行（/etc/anacrontab は 期間・遅延・名前・コマンド）
  • cron.allow があれば cron.deny は見ない。at はどちらもなければ root だけ
  • at now + 5 minutes、atq（at -l）、atrm（at -d）。systemd は .timer の OnCalendar=、systemctl list-timers
  • ロケールは LC_ALL → LC_項目 → LANG の順。locale、locale -a、localectl set-locale。i18n は国際化、l10n は地域化
  • iconv -f 元 -t 先、-l で一覧。UTF-8 は ASCII 互換で 1〜4 バイト、ISO-2022-JP は 7 ビットとエスケープ、EUC-JP と Shift_JIS は日本語の 2 バイト
