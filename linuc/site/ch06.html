6.1ログインシェルと非ログインシェル：bash はどの設定ファイルを読むか

bash は、起動のしかたによって、読む設定ファイルが変わります。試験で問われるのは、次の 2 つの起動のしかたです。

  • ログインシェル：ユーザー名とパスワードでログインしたときに、最初に起動するシェル。コンソールからのログイン、ssh での接続、su -（su -l）、bash --login（bash -l）
  • 対話的な非ログインシェル：ログインした後で、新しく起動したシェル。端末で bash と打ったとき、su（- なし）、デスクトップで端末のウィンドウを開いたとき（多くの環境）

ログインシェルの bash は、次の順に読みます。

  1. /etc/profile（全員に共通）
  2. ~/.bash_profile、~/.bash_login、~/.profile の順に探して、最初に見つかった 1 つだけ
  3. ログアウトするときに ~/.bash_logout

~/.bashrc は、ログインシェルの bash が直接は読みません。それでもログインしたシェルで ~/.bashrc の設定が効くのは、~/.profile（Red Hat 系では ~/.bash_profile）の中に「~/.bashrc があれば . で読み込む」と書いてあるからです。

対話的な非ログインシェルの bash は、/etc/bash.bashrc（Debian 系）と ~/.bashrc を読みます。/etc/profile や ~/.profile は読みません。シェルスクリプトを実行するシェル（対話的でない）は、どれも読みません。

起動のしかた読むファイル（Debian 12 の bash）
ログインシェル（ログイン、ssh、su -、bash -l）/etc/profile →（その中から /etc/bash.bashrc）→ ~/.bash_profile・~/.bash_login・~/.profile のうち最初の 1 つ →（~/.profile の中から ~/.bashrc）。終わるときに ~/.bash_logout
対話的な非ログインシェル（bash、su）/etc/bash.bashrc → ~/.bashrc
対話的でないシェル（bash スクリプト）どれも読まない

Docker の Debian 12 で、読まれる順番を確かめる

それぞれのファイルの 1 行目に「echo "[ファイル名]"」を足して、ユーザー alice で起動してみました。

ターミナル
# su - alice              ← ログインシェル（- あり）[/etc/profile][/etc/bash.bashrc][~/.profile][~/.bashrc]alice@debian:~$ echo $0; shopt login_shell-bashlogin_shell     onalice@debian:~$ exitlogout[~/.bash_logout]# su alice                ← 非ログインシェル（- なし）[/etc/bash.bashrc][~/.bashrc]alice@debian:~$ echo $0; shopt login_shellbashlogin_shell     off

ログインシェルでは $0 が -bash のように、先頭に - が付きます。shopt login_shell でも確かめられます。

次に、alice のホームに ~/.bash_profile と ~/.bash_login を作って、bash -l（ログインシェル）を起動しました。

ターミナル
alice@debian:~$ ls -a.  ..  .bash_login  .bash_logout  .bash_profile  .bashrc  .profilealice@debian:~$ bash -l[/etc/profile][/etc/bash.bashrc][~/.bash_profile]

~/.bash_profile があるので、~/.bash_login と ~/.profile は読まれません。~/.profile の中にある「~/.bashrc を読む」行も実行されないので、~/.bashrc も読まれなくなりました。~/.bash_profile を消すと、今度は ~/.bash_login だけが読まれます。

注意試験の注意：3 つのうち「1 つだけ」

~/.bash_profile、~/.bash_login、~/.profile は、全部を順に読むのではありません。この順に探して、最初に見つかった 1 つだけを読みます。「~/.bash_profile を作ったら、~/.profile に書いた PATH が効かなくなった」という事故は、これが原因です。

Red Hat 系との違い

Red Hat 系（Rocky Linux 9）には /etc/bash.bashrc がなく、代わりに /etc/bashrc があります。ユーザーのファイルも、~/.profile ではなく ~/.bash_profile が最初から置いてあります。中身は、Rocky Linux 9 の /etc/skel（新しいユーザーのホームにコピーされるひな形）で確かめました。

ターミナル
$ cat /etc/skel/.bash_profile# .bash_profile # Get the aliases and functionsif [ -f ~/.bashrc ]; then    . ~/.bashrcfi$ head -6 /etc/skel/.bashrc# .bashrc # Source global definitionsif [ -f /etc/bashrc ]; then    . /etc/bashrcfi

~/.bash_profile が ~/.bashrc を読み、~/.bashrc が /etc/bashrc を読む、という鎖です。どちらの系統でも「ログインシェルでも、結局は ~/.bashrc が読まれるように」書いてあります。

ファイルだれのいつ読まれる書くもの
/etc/profile全員ログインシェル全員の環境変数（PATH など）、umask
~/.bash_profile、~/.bash_login、~/.profile各ユーザーログインシェル（最初の 1 つ）そのユーザーの環境変数
/etc/bash.bashrc（Debian 系）、/etc/bashrc（Red Hat 系）全員対話的なシェル全員のプロンプト、alias
~/.bashrc各ユーザー対話的な非ログインシェル（ログインシェルでは ~/.profile などから）そのユーザーの alias、関数、プロンプト
~/.bash_logout各ユーザーログインシェルの終了時画面を消すなどの後片付け

小さな Linux にも、/etc/profile と ~/.profile が置いてあります（中身はコメントだけです）。

小さな Linux の設定ファイル⌘↵
echo $0cat /etc/profilecat ~/.profilels -a ~

6.2source と .：設定をいまのシェルに読み込む

設定ファイルを書き換えても、いま動いているシェルには反映されません。ファイルが読まれるのは、シェルが起動するときだけだからです。ログインし直さずに反映させるには、source（または .）で読み込みます。

図解 Linux 7.10 で見たとおり、sh ファイル や ./ファイル は、子プロセスの新しいシェルで実行します。子で変えた変数や cd は、子が終わると消えます。source ファイル と . ファイル は、いまのシェルがファイルを読んで実行するので、設定が残ります。

sh で実行すると残らない。. と source なら残る⌘↵
cat > env.sh <<'EOF'GREETING=hellocd notesEOFsh env.shecho "[$GREETING] $(pwd)". ./env.shecho "[$GREETING] $(pwd)"cd

設定ファイルに alias を書き足して、読み直してみます。書き足しただけでは、まだ使えません。

~/.profile に書き足しても、読み直すまでは効かないエラーになる⌘↵
echo "alias ll='ls -l'" >> ~/.profilell hello.sh. ~/.profilell hello.sh

. ~/.profile のあとで、ll が使えるようになりました。本物の bash で ~/.bashrc を書き換えたときは、source ~/.bashrc か . ~/.bashrc です。

書き方どこで実行するか実行権限変数・cd・alias
source ファイルいまのシェル要らない残る
. ファイルいまのシェル（source と同じ）要らない残る
bash ファイル、sh ファイル子のシェル要らない（読めればよい）残らない
./ファイル子のシェル（#! のプログラム）要る残らない
注意試験の注意：. の後ろには空白

. ~/.bashrc の . はコマンドの名前です。後ろに空白が要ります。./.bashrc と続けて書くと、「カレントディレクトリの .bashrc を子のシェルで実行する」という別の意味になります（実行権限がなければ失敗します）。source は bash の書き方で、POSIX のシェル（Debian の /bin/sh である dash など）では . を使います。

6.3alias、PATH、そして ; && ||

alias：コマンドに別名を付ける

alias は、長いコマンドに短い別名を付けるシェルの組み込みコマンドです。alias 名前='コマンド' で定義し、引数なしの alias で一覧を表示します。消すのは unalias で、unalias -a はすべての別名を消します。別名と同じ名前のコマンドを、別名を使わずに実行したいときは、先頭に \ を付けるか、command を付けます。

alias で定義し、一覧を見て、消す。\ls と command ls は別名を使わない⌘↵
alias la='ls -a'aliastype lala notesunalias laaliasalias ls='echo 別名の ls'ls -d /\ls -d /command ls -d /unalias ls

alias で定義した別名は、そのシェルが終わると消えます。いつも使いたい別名は、~/.bashrc に書きます（ログインシェルでも ~/.profile などから ~/.bashrc が読まれるので、ここに書けば両方で効きます）。

注意試験の注意：スクリプトの中では alias は展開されない

本物の bash は、対話的でないシェル（スクリプト）では alias を展開しません。Debian 12 の bash で確かめた結果です。

ターミナル
$ cat al.shalias hi='echo hi'hi$ bash al.shal.sh: line 2: hi: command not found

スクリプトの中で同じことをしたいなら、関数を使います（shopt -s expand_aliases を書けば展開されますが、ふつうは関数にします）。なお、小さな Linux の sh は、スクリプトの中でも alias を展開します。これは本物と違うところです。

PATH にディレクトリを足す

図解 Linux 2.4 で見たとおり、シェルは / を含まないコマンド名を、環境変数 PATH に : で区切って並んだディレクトリの中から、前から順に探します。自分のコマンドを置くディレクトリは、PATH に足します。

~/bin を PATH の最後に足すエラーになる⌘↵
echo $PATHmkdir -p bincat > bin/today <<'EOF'#!/bin/shdate +%FEOFchmod +x bin/todaytodayPATH=$PATH:$HOME/binecho $PATHtoday
書き方意味
PATH=$PATH:$HOME/bin最後に足す（同じ名前のコマンドがあれば、元のほうが優先）
PATH=$HOME/bin:$PATH先頭に足す（自分のほうが優先）
export PATH=$PATH:$HOME/bin足して、子プロセスにも渡す
PATH=$HOME/bin置き換え。ls などが見つからなくなる

PATH は最初から環境変数（export 済み）なので、代入するだけで子プロセスにも渡ります。それでも設定ファイルには export PATH=… と書くのが習慣です。新しく作った変数を子プロセスに渡すには、export が必要です（図解 Linux 7.9）。ずっと使いたいなら、~/.profile か ~/.bash_profile に書きます。Debian の ~/.profile には、最初から「~/bin があれば PATH の先頭に足す」行が入っています。

注意試験の注意：PATH の書き方の誤り

$PATH=…（左辺に $）、PATH = …（= の前後に空白）、PATH=$PATH;~/bin（区切りが ;）は、どれも誤りです。区切りは :、代入は空白なしの 名前=値 です。PATH に .（カレントディレクトリ）を入れるのは、危険なので避けます（図解 Linux 6.1）。

; && || でコマンドをつなぐ

1 行に複数のコマンドを書くときは、つなぎ方で「次を実行するかどうか」が変わります。判断に使うのは、直前のコマンドの終了ステータス（0 が成功）です。

書き方B を実行するのは
A ; Bいつでも（A が終わったら）
A && BA が成功（終了ステータス 0）したときだけ
A || BA が失敗（0 以外）したときだけ
; と && と ||エラーになる⌘↵
echo one; echo twogrep -q apple fruits.txt && echo "apple がある"grep -q mango fruits.txt && echo "mango がある"grep -q mango fruits.txt || echo "mango はない"cd /nonexistent && lscd /nonexistent ; pwd

cd /nonexistent && ls は、cd が失敗したので ls を実行しません。; でつなぐと、cd に失敗しても pwd を実行します。&& や || を並べたときは、左から順に、直前の結果で判断します（図解 Linux 6.5）。

6.4スクリプトを動かす：#!、実行権限、引数、終了ステータス

3 つの実行のしかた

スクリプトの 1 行目の #!（シバン、shebang）は、カーネルが読みます（図解 Linux 6.1）。./run.sh と実行すると、カーネルは #! の後ろのプログラム（#!/bin/bash なら /bin/bash）を起動して、スクリプトのパスを渡します。bash run.sh のようにシェルに渡したときは、1 行目はただのコメントです。

名前で実行するには、ファイルに x（実行）の権限が要ります。

x の権限がないと ./ では実行できない。sh なら動く。chmod で x を付けるエラーになる⌘↵
cat > greet.sh <<'EOF'#!/bin/shecho "Hello, $1"EOFls -l greet.sh./greet.sh yoush greet.sh youchmod 755 greet.shls -l greet.sh./greet.sh you

最初の ./greet.sh は Permission denied で、終了ステータスは 126 です。x の権限がなくても、sh greet.sh や . ./greet.sh なら、シェルがファイルを読むだけなので実行できます。chmod 755 のあとは ./ でも動きました。chmod +x でも chmod u+x でもかまいません（図解 Linux 4.3）。持ち主を変えるのは chown（chown 持ち主:グループ ファイル）で、root だけが使えます（図解 Linux 4.7）。

root で持ち主とグループを変える（プロンプトが # になる）root で実行⌘↵
chown alice:staff /home/you/greet.shls -l /home/you/greet.shchown you:you /home/you/greet.sh

./ を付けずに名前だけで実行したいなら、置き場所を PATH に入れます（前の節の ~/bin）。#! に書いたプログラムがないと、cannot execute: required file not found で終了ステータス 127 になります（Debian 12 の bash でも同じ文でした）。

終了ステータス意味
0成功
1〜125失敗（意味はコマンドによる。grep は見つからないと 1）
126見つかったが実行できない（x の権限がない）
127コマンドが見つからない（#! のプログラムがないときも）

引数と特別な変数

スクリプトに渡した引数は、位置パラメータに入ります（図解 Linux 6.4）。

変数中身
$0スクリプトの名前（起動したときのパス）
$1、$2、…、${10}1 番目、2 番目、… の引数。10 番目からは {} で囲む
$#引数の個数
"$@"すべての引数。1 つずつ別の単語のまま
"$*"すべての引数を、1 つの文字列につないだもの（区切りは空白）
$*、$@（引用符なし）すべての引数。さらに空白で分かれる
$?直前のコマンドの終了ステータス
$$シェル自身の PID
位置パラメータと shift⌘↵
cat > args.sh <<'EOF'#!/bin/shecho "\$0=$0  \$#=$#  \$1=$1  \$2=$2"for a in "$@"; do echo "\"\$@\" -> [$a]"; donefor a in "$*"; do echo "\"\$*\" -> [$a]"; doneshiftecho "shift のあと: \$#=$#  \$1=$1"EOFchmod +x args.sh./args.sh "my file" b c

"my file" は引用符で囲んだので 1 個の引数です。"$@" は 3 個のまま、"$*" は 1 個につながりました。

shift 数 は、その数だけずらします。引数の数より大きい数を指定すると、何もずらさずに 1 で終わります（bash で確かめました）。

exit で終了ステータスを返す

スクリプトの終了ステータスは、exit 数 で決めます。exit を書かないとき、または数を付けない exit は、最後に実行したコマンドの終了ステータスになります。

exit で終了ステータスを決める⌘↵
cat > check.sh <<'EOF'#!/bin/shif [ $# -eq 0 ]; then  echo "usage: $0 file" >&2  exit 2fi[ -f "$1" ]EOFchmod +x check.sh./check.sh; echo "引数なし: $?"./check.sh memo.txt; echo "memo.txt: $?"./check.sh nosuch; echo "nosuch: $?"

終了ステータスは 0〜255 です。bash で exit 300 とすると、256 で割った余りの 44 になりました。

注意試験の注意："$@" と "$*"

引数をそのまま別のコマンドに渡すときは "$@" です。"$*" は全部が 1 つの文字列になり、$* と $@（引用符なし）は空白を含む引数が分かれてしまいます。$# は個数、$0 はスクリプトの名前で、1 番目の引数ではありません。

6.5条件とくり返し：if、test、case、for、while、until

if は、コマンドの終了ステータスを見る

if の後ろに書くのは、式ではなくコマンドです（図解 Linux 6.6）。[ 条件 ] は test 条件 と同じコマンドで、[ の後ろと ] の前に空白が要ります。形は次のとおりです。

ターミナル
if 条件のコマンド; then  …elif 条件のコマンド; then  …else  …fi

then を同じ行に書くときは、前に ; が要ります。終わりは fi（if を逆から書いたもの）です。

test の条件を確かめる⌘↵
[ -f memo.txt ]; echo "-f memo.txt: $?"[ -d notes ]; echo "-d notes: $?"[ -e nosuch ]; echo "-e nosuch: $?"s=""[ -z "$s" ]; echo "-z 空: $?"[ -n "$s" ]; echo "-n 空: $?"[ 10 -lt 9 ]; echo "10 -lt 9: $?"[ abc = abc ]; echo "abc = abc: $?"[ abc != abd ]; echo "abc != abd: $?"
条件成り立つとき
-e パス存在する（種類は問わない）
-f パス通常のファイル
-d パスディレクトリ
-r、-w、-x パス読める、書ける、実行できる
-s パス大きさが 0 でない
-z 文字列空（長さ 0）
-n 文字列空でない
文字列1 = 文字列2、!=文字列として同じ、違う（bash の [ では == も使える）
数1 -eq 数2、-ne数として等しい、等しくない
-lt、-le、-gt、-geより小さい（less than）、以下、より大きい（greater than）、以上
! 条件、条件 -a 条件、条件 -o 条件でない、かつ、または
注意試験の注意：数の比較は -lt、文字列の比較は =

[ 10 < 9 ] の < はリダイレクトになり、「9 というファイルから読む」になってしまいます。\< と書いても、それは文字列の比較（辞書の順）です。bash では [ 10 \< 9 ] が「成り立つ」（0）になりました。数は -eq -ne -lt -le -gt -ge、文字列は = != と覚えます。変数は "$x" と引用符で囲みます。空の変数で [ $x = a ] とすると、bash は unary operator expected のエラーで 2 を返します。

case：パターンで分ける

case で答えを分けるスクリプト⌘↵
cat > yesno.sh <<'EOF'#!/bin/shread -p "続けますか (y/n)? " anscase "$ans" in  [Yy]|[Yy]es) echo "続けます" ;;  [Nn]*)       echo "やめます" ;;  *)           echo "y か n で答えてください"; exit 1 ;;esacEOFchmod +x yesno.sh
Yes と答える入力：Yes ⏎⌘↵
./yesno.sh
maybe と答える（どれにも合わず exit 1）エラーになる入力：maybe ⏎⌘↵
./yesno.sh
  • 上から順に比べて、最初に合ったものだけを実行する。パターンには *、?、[ ] が使える
  • | で、パターンを並べられる
  • 各項目の終わりは ;;、全体の終わりは esac（case を逆から書いたもの）
  • *) は何にでも合うので、最後に置く

read は標準入力から 1 行読んで変数に入れます。read -p "文字列" 変数 は、読む前に文字列を表示します（bash では、入力が端末のときだけ表示します）。変数を 2 つ以上書くと、空白で分けて前から入れ、残りは全部が最後の変数に入ります。変数を書かないと、REPLY という変数に入ります。

read は残りを最後の変数に入れる入力：Linus Benedict Torvalds ⏎⌘↵
read first rest; echo "first=$first / rest=$rest"

for と seq⌘↵
for c in red green blue; do echo "色: $c"; donefor i in $(seq 1 3); do echo "$i 回目"; doneseq 2 2 8seq -s , 5seq -w 8 10

seq は数の並びを出力します。

while は条件のコマンドが成功（0）のあいだ、until は失敗（0 以外）のあいだくり返します。until は「〜になるまで」と読むと覚えやすくなります。ファイルを 1 行ずつ処理するときは、while read 変数; do …; done < ファイル です（図解 Linux 6.7）。

6.6関数の 2 つの書き方と、bash -x・bash -v

function キーワードと 名前()

bash の関数には、2 つの書き方があります。

関数の 2 つの書き方⌘↵
function hello {  echo "hello, $1"}bye() {  echo "bye, $1（引数 $# 個）"  return 3}hello youbye you me; echo "bye の終了ステータス: $?"
書き方説明
名前() { コマンド; }POSIX の書き方。どのシェルでも使える
function 名前 { コマンド; }bash の書き方。function 名前() { …; } と () を付けてもよい
  • 関数の中の $1、$#、"$@" は、関数に渡した引数。$0 はスクリプトの名前のまま
  • return 数 で、関数の終了ステータスを返す。書かなければ、最後のコマンドの終了ステータス。exit を書くと、関数ではなくシェル（スクリプト）全体が終わる
  • 関数は、呼ぶより前に定義しておく
  • { の後ろには空白が、} の前には ; か改行が要る。hello() {echo hi;} や hello() { echo hi } は、bash では構文エラー（Debian 12 で確かめました）
  • 関数の定義は、alias と同じく、~/.bashrc に書けば毎回使える
メモfunction は POSIX のシェルにはない

Debian の /bin/sh（dash）で function f { echo F; } を実行すると、Syntax error: "}" unexpected になりました。#!/bin/sh のスクリプトでは 名前() { …; } を使います。小さな Linux の sh は、どちらの書き方も受け付けます。

bash -x、bash -v、set -x：スクリプトのデバッグ

スクリプトが思ったとおりに動かないときは、実行の様子を表示させます。

sh -x：変数を置き換えた後のコマンドを + 付きで表示⌘↵
sh -x ./args.sh a "b c"

+ の行が、実際に実行したコマンドです（標準エラー出力に出ます）。本物の bash では bash -x スクリプト です（bash では + for a in "$@" のように、ループの行にも + が付きます）。-v は、置き換える前の、読んだ行をそのまま表示します。Debian 12 の bash で、両方を比べました。

ターミナル
$ cat v.sh#!/bin/bash# commentn=$1echo "n=$n"$ bash -v v.sh 3#!/bin/bash# commentn=$1echo "n=$n"n=3$ bash -x v.sh 3+ n=3+ echo n=3n=3

-v はコメントも含めて書いたとおりに、-x は $1 や $n を値に置き換えた形で表示しています。両方を付けた bash -xv もできます。

スクリプトの一部だけを追いたいときは、その範囲を set -x と set +x で挟みます（- で始めて、+ で止める）。

set -x から set +x までを追う⌘↵
set -xn=$(wc -l < fruits.txt)echo "$n 行"set +x
書き方表示するもの
bash -x スクリプト実行するコマンドを、展開した後の形で、+ 付きで
bash -v スクリプト読んだ行を、展開する前の形のまま
set -x / set +xスクリプトの中で、-x を始める / 止める（set -o xtrace も同じ）
set -v / set +vスクリプトの中で、-v を始める / 止める
bash -n スクリプト実行せずに、構文の誤りだけを調べる
コツ-x は eXecute、-v は Verbose

-x は「実行（execute）するもの」を、-v は「読んだもの全部（verbose、くどく）」を表示する、と覚えます。試験では「変数の値が展開されて表示されるのはどちらか」が問われます。答えは -x です。

要点まとめ
  • ログインシェル：/etc/profile → ~/.bash_profile、~/.bash_login、~/.profile の最初の 1 つだけ → 終了時に ~/.bash_logout
  • 対話的な非ログインシェル：/etc/bash.bashrc（Red Hat 系は /etc/bashrc）と ~/.bashrc。~/.bashrc はログインシェルでも ~/.profile や ~/.bash_profile から . で読まれる
  • source ファイル と . ファイル は、いまのシェルで実行する。設定ファイルの読み直しに使う
  • alias 名前='コマンド'、unalias 名前（-a で全部）。別名を避けるのは \名前 か command 名前。bash のスクリプトでは alias は展開されない
  • PATH は PATH=$PATH:$HOME/bin（区切りは :）。子にも渡すなら export
  • A ; B はいつでも、A && B は A が成功したら、A || B は A が失敗したら B
  • #! はカーネルが読む。./スクリプト には x の権限（chmod +x）。権限がなくても bash スクリプト と source は動く。126 は実行できない、127 は見つからない
  • $0 名前、$1 引数、$# 個数、"$@" 1 つずつ、"$*" 1 つにつなぐ、$? 直前の終了ステータス、shift で 1 つずらす。exit だけなら最後のコマンドの終了ステータス
  • [ ] の数の比較は -eq -ne -lt -le -gt -ge、文字列は = !=、空は -z、空でないは -n、ファイルは -f、ディレクトリは -d、存在は -e
  • if …; then …; elif …; else …; fi、case … in パターン) …;; esac、while は成功のあいだ、until は失敗のあいだ。seq 最初 増分 最後
  • 関数は 名前() { …; } と function 名前 { …; }。return で終了ステータス
  • bash -x は展開後のコマンドを + 付きで、bash -v は読んだ行をそのまま表示。途中からは set -x、止めるのは set +x
