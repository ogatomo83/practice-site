2.1パーミッションは 9 文字と 3 桁で読む

ls -l の先頭 10 文字は、1 文字目がファイルの種類、残りの 9 文字が「持ち主（u）・グループ（g）・その他（o）」の 3 組の権限です（図解 Linux 4.2）。試験では、この 9 文字と 8 進数の 3 桁を、すばやく行き来できることが求められます。

chmod には、2 つの書き方があります。

  • 8 進数：chmod 754 file。3 組を全部まとめて指定し直す
  • 記号：chmod u+x,g-w,o= file。いまの権限を元に、一部だけ足す・引く・決める

記号の書き方は「だれの（u / g / o / a）」「どうする（+ / - / =）」「何を（r / w / x / s / t）」の 3 つを並べます。カンマで区切れば、いちどに何組でも書けます。= は「その組をこれだけにする」で、o= のように右を空にすると、その組の権限を全部取ります。

記号と 8 進数で変える⌘↵
cdmkdir labcd labtouch a.txtls -l a.txtchmod u+x,g+w,o= a.txtls -l a.txtchmod a=r a.txtls -l a.txtchmod 640 a.txtls -l a.txtstat -c '%a %A %n' a.txtchmod -R 755 /home/you/labls -ld /home/you/lab

touch で作った直後は 644（rw-r--r--）でした。u+x,g+w,o= で、持ち主に x を足し、グループに w を足し、その他を空にして rwxrw----（760）になりました。a=r は、3 組とも r だけにします。8 進数の 640 は、3 組を全部決め直します。stat -c '%a' は、権限を 8 進数で表示します。-R は、ディレクトリの中まで再帰的に変えるオプションです（大文字の R。chown -R、chgrp -R も同じ）。

書き方意味
u / g / o / a持ち主 / グループ / その他 / 全員（ugo）
+ / - / =足す / 取る / それだけにする
r = 4、w = 2、x = 1足して 1 桁にする。7 = rwx、6 = rw-、5 = r-x、4 = r--
chmod -Rディレクトリの中まで再帰的に
よく出る数字755 rwxr-xr-x、644 rw-r--r--、700 rwx------、600 rw-------
注意試験の注意
  • 8 進数は「3 組を全部決め直す」、記号は「指定した所だけ変える」。chmod g+w は、ほかのビットを変えません
  • a を省いて chmod +x file と書くと、全員に x が付きます。ただし、このときは umask で取り除かれるビットは付きません（図解 Linux 4.6）
  • 再帰は -R（大文字）。-r は chmod では権限の「r を取る」という意味の記号と読まれることがあり、オプションではありません

chown と chgrp：持ち主とグループを変える

chown は持ち主を、chgrp はグループを変えます（図解 Linux 4.7）。chown は「持ち主:グループ」の形で、両方をいちどに変えられます。

chown の書き方root で実行⌘↵
cd /home/you/labchown alice a.txtls -l a.txtchown :staff a.txtls -l a.txtchown bob:users a.txtls -l a.txtchown alice: a.txtls -l a.txtchown -R you:you /home/you/labls -l a.txt

chown alice: a.txt のように、コロンの後ろを空にすると、グループは alice の主グループになります。古い書き方の bob.users（ドット区切り）も使えますが、ユーザー名にドットが入ると紛らわしいので、試験でもコロンが正解になります。

書き方意味
chown 持ち主 file持ち主だけ変える
chown 持ち主:グループ file両方変える
chown :グループ fileグループだけ変える（chgrp グループ file と同じ）
chown 持ち主: file持ち主と、その人の主グループに変える
chown -R / chgrp -Rディレクトリの中まで再帰的に
だれができるか持ち主を変えるのは root だけ。グループは、持ち主が自分の入っているグループへなら変えられる

2.2umask は「与えない」ビット

新しく作るファイルの権限は、umask で決まります（図解 Linux 4.6）。プログラムはふつう、ファイルなら 666、ディレクトリなら 777 で作ろうとします。カーネルは、そこから umask で 1 になっているビットを取り除きます。

umask を 027 にして作る⌘↵
umaskumask 027touch f027mkdir d027ls -ld f027 d027umask -Sumask 022

ファイルは 640、ディレクトリは 750 になりました。umask -S は、umask を「作るときに残す権限」の記号で表示します（u=rwx,g=rx,o= は、027 を裏返したものです）。最後に既定の 022 へ戻しています。

計算の手順を表にまとめます。

umaskファイル（666 から）ディレクトリ（777 から）
022（よくある既定）644755
002664775
027640750
077600700
033644（633 ではない）744
注意試験の注意：引き算ではない

umask が 033 のとき、ファイルは 666 − 033 = 633 ではなく 644 です。666 にはもともと x がないので、umask の x のビットは取り除くものがありません。「ファイルは x が付かない」と覚えておけば、計算で迷いません。ディレクトリは 777 から取り除くので、744 になります。

umask はプロセスごとの値で、子プロセスに受け継がれます。シェルで umask 027 と打っても、そのシェルとそこから起動したものにしか効きません。ログインのたびに同じにしたいときは、~/.bashrc や ~/.profile（すべてのユーザーなら /etc/profile）に書きます。なお、umask が効くのは「作るとき」だけです。すでにあるファイルの権限や、chmod 777 の結果は変えません。mkdir -m 700 のように作るときに権限を明示した場合も、その値がそのまま使われます。

覚えること内容
umaskいまの値を 8 進数で表示（例 0022）
umask 027値を変える（そのシェルの中だけ）
umask -S残す権限を記号で表示（例 u=rwx,g=rx,o=rx）
計算ファイル = 666 から、ディレクトリ = 777 から、umask のビットを取り除く

2.3SUID・SGID・スティッキービットの s と t

12 ビットの先頭の 3 つが、特別なビットです（図解 Linux 4.9）。8 進数では、3 桁の前に 4 桁目として書きます。

ビット8 進数記号表示の場所働き
SUID（セットユーザー ID）4000u+s持ち主の x の場所が s実行すると、ファイルの持ち主の権限で動く（例 /usr/bin/passwd）
SGID（セットグループ ID）2000g+sグループの x の場所が sファイル：ファイルのグループの権限で動く。ディレクトリ：中に作ったファイルのグループが、ディレクトリのグループになる
スティッキービット1000o+tその他の x の場所が tディレクトリの中のファイルを、そのファイルの持ち主、ディレクトリの持ち主、root しか消せない・名前を変えられない（例 /tmp）

表示で大事なのは、小文字と大文字の違いです。特別なビットは x と同じ場所に表示されるので、x があるかどうかを文字の大きさで表します。

  • s / t（小文字）：特別なビットと x の両方が立っている
  • S / T（大文字）：特別なビットだけが立っていて、x はない
s と S、t と T⌘↵
touch spchmod 4755 spls -l spchmod 4644 spls -l spchmod 2755 spls -l spchmod 6755 spls -l spmkdir pubchmod 1777 publs -ld pubchmod 1776 publs -ld pub

4644 は持ち主に x がないので rwS になりました。6755 は SUID と SGID の両方（4 + 2）で rwsr-sr-x です。1776 は、その他の x がないので T です。

SGID をディレクトリに付けると、グループで共有する場所が作れます。you は staff グループに入っています。

SGID のディレクトリと、SUID のファイル探し⌘↵
mkdir sharechgrp staff sharechmod g+s sharels -ld sharetouch share/newls -l sharefind /usr/bin -perm -4000

share/new のグループは、you の主グループ（you）ではなく、ディレクトリのグループ staff になりました。

最後の行は、/usr/bin の中で SUID が付いたファイルを探しています。SUID のファイルは、悪用されると root の権限を取られる入口になるので、管理者は find で一覧を作って確かめます。-perm -4000 の - は「少なくともこのビットが立っている」という意味です（find の節）。

注意試験の注意
  • s と S、t と T：大文字は「x がない」。-rwSr--r-- は、SUID は立っているが持ち主に実行権がないので、実行できない
  • 数字は SUID = 4、SGID = 2、スティッキー = 1。並びは「4 桁目」で、chmod 4755 の 4 が SUID。chmod 1777 はスティッキー
  • スティッキービットはディレクトリに付けて意味があるもの。記号では o+t（+t でもよい）
  • SUID のファイル探しは find / -perm -4000。-perm 4000（- なし）は「権限がちょうど 4000」のものだけになり、ふつうは何も見つからない

2.4見る・作る・コピーする・消す

ここからは 1.02.2 です。ファイルを扱う基本のコマンドと、名前のパターン（ワイルドカード）を整理します。

ls・file・touch・mkdir：見る、作る

まず、ファイルを見るコマンドと作るコマンドのオプションを、試験で問われる分だけ整理します（図解 Linux 3.4、3.6）。

ls のオプション⌘↵
cd /home/youls -als -Als -d notesls -Fls -lh /usr/bin/lsls -R notes

-a は . と .. を含めて全部、-A は . と .. だけを除いて隠しファイルを出します。-d はディレクトリの中身ではなく、そのものを表示します（ls -ld /tmp のように -l と組み合わせて使います）。

ls のオプション意味
-l詳しく（権限、リンク数、持ち主、グループ、大きさ、更新時刻）
-a / -A隠しファイルも（-A は . と .. を除く）
-dディレクトリそのものを表示
-F種類の印を付ける（/ * @ | =。1.02.3）
-iinode 番号を表示
-h大きさを K、M、G で（-l と一緒に）
-Rサブディレクトリの中も再帰的に
-t / -S / -r更新時刻順 / 大きさ順 / 逆順

file は、拡張子ではなく中身を調べて種類を表示します。touch は、ファイルがなければ空のファイルを作り、あればタイムスタンプを今にするコマンドです。mkdir -p は途中のディレクトリもまとめて作り、すでにあってもエラーにしません。

file、touch、mkdirエラーになる⌘↵
file hello.sh notes /etc/passwd /usr/bin/ls /dev/nulltouch -c nothingls nothingmkdir -p lab/x/y/zmkdir -m 700 lab/secretls -ld lab/x/y/z lab/secret

touch -c は「なければ作らない」なので、nothing はできていません（ls が失敗するのは正しい結果です）。mkdir -m 700 は、umask に関係なく 700 で作ります。

コマンド主なオプション
touch-c 作らない、-t [[CC]YY]MMDDhhmm[.ss] 時刻を指定、-a アクセス時刻だけ、-m 更新時刻だけ
mkdir-p 親もまとめて作る、-m モード 権限を指定
file中身から種類を判定（ASCII text、directory、ELF 64-bit …）
ターミナル
# Debian 12 で実際に実行した例（小さな Linux の touch は -t を持たない）$ touch -t 202601011230 t$ ls -l --time-style=+%F_%R t-rw-r--r-- 1 root root 0 2026-01-01_12:30 t

cp・mv・rm・rmdir のオプション

コピー、移動、削除の 4 つは、オプションの意味がよく似ていて、試験の引っかけになりやすいところです。

cp と cp -p と cp -a⌘↵
ls -l memo.txtcp memo.txt lab/m1cp -p memo.txt lab/m2cp -a memo.txt lab/m3ls -l lab/m1 lab/m2 lab/m3

ふつうの cp で作ったコピーは、更新時刻が「いま」になります。-p（preserve）は、権限・持ち主・タイムスタンプを元のまま保ちます。-a（archive）は、-p の働きに加えて、ディレクトリを再帰的にコピーし、シンボリックリンクはリンクのままコピーします。バックアップに向いた「全部そのまま」のオプションです。

ディレクトリには -r が要るエラーになる⌘↵
cp notes lab/n1cp -r notes lab/n1cp -a notes lab/n2ls -l lab/n1 lab/n2

-r がないと、ディレクトリはコピーされません（omitting directory）。-r のコピーは中身の時刻が「いま」になり、-a は元の時刻のままです。

オプションcpmvrm
-i上書きの前に確かめる上書きの前に確かめる消す前に 1 つずつ確かめる
-f書き込めない先を消してでもコピー確かめずに上書き確かめない。ないファイルもエラーにしない
-n上書きしない上書きしない—
-r / -Rディレクトリを再帰的に（不要。ディレクトリもそのまま動かせる）ディレクトリを中身ごと
-p権限・持ち主・時刻を保つ——
-a-p + -r + リンクはリンクのまま——
-uコピー元が新しいときだけ移動元が新しいときだけ—
-b—上書きされるファイルのバックアップ（名前~）を残す—
-vしたことを表示したことを表示したことを表示

rmdir は、空のディレクトリしか消せません。中にファイルがあると失敗します。-p を付けると、指定したパスの親も順に消します。rmdir -p a/b/c は rmdir a/b/c a/b a と同じです。

rmdir、rmdir -p、rm -rエラーになる⌘↵
rmdir lab/xrmdir -p lab/x/y/zls labrm -r lab/n1rm -rf lab/n2 lab/no-such-filels lab

rmdir lab/x は、中に y があるので Directory not empty で失敗します。rmdir -p lab/x/y/z は、z、y、x と消していき、lab で止まりました。lab にはほかのファイルがあるので、ここで Directory not empty のエラーになります（それまでに消したものは消えたままです）。rm -r は中身ごと消します。rm -rf は、ないファイルを指定しても何も言いません。

注意試験の注意
  • ディレクトリをコピーするのは cp -r（-R も同じ）。mv は -r なしでディレクトリを動かせる
  • 権限と時刻を保つのは cp -p。ディレクトリごと全部を保つのは cp -a
  • 空のディレクトリを消すのは rmdir（または rm -d）。中身ごとなら rm -r。rmdir -p は親までさかのぼって消す
  • rm と mv で -f と -i を両方書くと、後に書いたほうが効く

ワイルドカード：名前のパターン

* や ? は、コマンドではなくシェルがファイル名に展開します（図解 Linux 2 章）。コマンドに渡るのは、展開した後の名前の並びです。

パターン意味例
*0 文字以上の、どんな文字列にも合う*.txt
?ちょうど 1 文字に合う????.txt は名前が 4 文字の .txt
[abc]括弧の中のどれか 1 文字[mn]* は m か n で始まる名前
[a-c]範囲の中の 1 文字file[0-9]
[!a-c]、[^a-c]括弧の中以外の 1 文字[!f-n]*
{a,b}a と b の両方に書き換える（ファイルがなくても作る。ブレース展開）*.{txt,csv}
ワイルドカード⌘↵
lsls ????.txtls [mn]*ls [!f-n]*ls *.{txt,csv}echo file{1,2,3}

* は、先頭が . の名前（隠しファイル）には合いません。ls * で隠しファイルが出ないのはこのためです。

2.5まとめる・縮める・写す：tar、圧縮、dd

バックアップやファイルの受け渡しで使う、tar、3 つの圧縮コマンド、dd です。tar と圧縮は、図解 Linux になかった新しい範囲です。

tar：まとめる、取り出す

tar は、たくさんのファイルを 1 つのファイル（アーカイブ）にまとめます。tar 自身は圧縮しません。圧縮は gzip・bzip2・xz の仕事で、tar のオプション 1 文字でそれを呼び出せます。

tar の操作は、何をするか（c / x / t）を必ず 1 つ選び、必要なら圧縮の種類とほかのオプションを足します。

オプション意味
ccreate。アーカイブを作る
xextract。取り出す（展開する）
tlist。中身の一覧を表示する（取り出さない）
f ファイルアーカイブのファイル名を指定する。すぐ後ろの引数がファイル名
zgzip（.tar.gz、.tgz）
jbzip2（.tar.bz2）
Jxz（.tar.xz。大文字）
v処理したファイルの名前を表示する
C ディレクトリそのディレクトリに移ってから処理する（展開先を決める）
r / u圧縮していないアーカイブに足す / 新しいものだけ足す

小さな Linux には tar がないので、Debian 12 で実際に動かした結果を見ます。

ターミナル
$ tar cvf p.tar projproj/proj/src/proj/src/b.cproj/a.txt$ tar tvf p.tardrwxr-xr-x root/root         0 2026-11-16 11:15 proj/drwxr-xr-x root/root         0 2026-11-16 11:15 proj/src/-rw-r--r-- root/root         6 2026-11-16 11:15 proj/src/b.c-rw-r--r-- root/root         6 2026-11-16 11:15 proj/a.txt$ tar czf p.tgz proj$ tar tzf p.tgzproj/proj/src/proj/src/b.cproj/a.txt$ mkdir out$ tar xzf p.tgz -C out$ find outoutout/projout/proj/srcout/proj/src/b.cout/proj/a.txt

- を付けても付けなくても書けます（tar czf と tar -czf は同じ）。GNU tar は、展開のときは圧縮の種類を自分で見分けるので、tar xf p.tgz でも展開できます。ただ、作るとき（c）は z / j / J を書かないと圧縮されません。

注意試験の注意：f はファイル名の直前に

- を付けた書き方で f を最後に置かないと、f のすぐ後ろの文字がファイル名と読まれます。tar -cfv backup.tar docs は、v という名前のアーカイブを作り、backup.tar と docs をその中に入れようとします（Debian 12 で実行すると tar: backup.tar: Cannot stat: No such file or directory と出て、v というファイルができます）。正しくは tar -cvf backup.tar docs です。

gzip・bzip2・xz：圧縮と展開

3 つの圧縮コマンドは、使い方がほぼ同じです。違うのは、拡張子と、展開・表示のコマンド名です。

gzipbzip2xz
拡張子.gz.bz2.xz
圧縮gzip filebzip2 filexz file
展開gunzip file.gz、gzip -dbunzip2 file.bz2、bzip2 -dunxz file.xz、xz -d
展開して標準出力へzcat、gzip -dcbzcatxzcat
tar のオプションzjJ
縮み方（一般に）ふつう・速いよく縮むいちばんよく縮む・遅い

共通のオプションも覚えます。

オプション意味
-d展開する（decompress）
-k元のファイルを残す（keep）。既定では、圧縮すると元のファイルは消えて .gz だけが残る
-c結果を標準出力へ書く。元のファイルは残る（gzip -c file > file.gz）

-v圧縮率などを表示

Debian 12 で、同じテキストを 3 つの方法で圧縮した結果です（-k で元を残しています）。

ターミナル
$ gzip -k big.txt; bzip2 -k big.txt; xz -k big.txt$ ls -l big.txt*-rw-r--r-- 1 root root 105447 Nov 16 11:17 big.txt-rw-r--r-- 1 root root  14782 Nov 16 11:17 big.txt.bz2-rw-r--r-- 1 root root  33903 Nov 16 11:17 big.txt.gz-rw-r--r-- 1 root root  11508 Nov 16 11:17 big.txt.xz$ echo hi > a; echo yo > b$ gzip a b$ ls a* b*a.gzb.gz$ gzip -d a.gz$ ls a*a$ gzip dgzip: d is a directory -- ignored

gzip a b は、2 つを 1 つにまとめるのではなく、a.gz と b.gz を別々に作ります。ディレクトリは圧縮できません。ディレクトリをまとめて圧縮したいときは、tar czf を使います。

「まとめる」のは tar、「縮める」のは gzip・bzip2・xz、という役割分担を覚えておくと、選択肢の誤りがすぐ分かります。gzip -r dir も、dir の中の各ファイルを別々に .gz にするだけで、1 つのファイルにはなりません。

dd：ブロック単位で写す

dd は、入力から出力へ、決まった大きさのブロックで、決まった回数だけデータを写します。ディスク全体の複製、MBR（ディスクの先頭 512 バイト）のバックアップ、決まった大きさのファイル作りに使います。

指定意味
if=入力入力ファイル（省くと標準入力）
of=出力出力ファイル（省くと標準出力）
bs=大きさ1 回に読み書きする大きさ（ブロックの大きさ。既定 512 バイト。1K、1M も書ける）
count=回数何ブロック写すか
skip=N / seek=N入力の先頭 N ブロックを飛ばす / 出力の先頭 N ブロックを飛ばして書く
dd で 4 KiB のファイルを作り、一部を切り出す⌘↵
dd if=/dev/zero of=lab/zero.img bs=1K count=4ls -l lab/zero.imgprintf 'ABCDEFGHIJKLMNOPQRST' > lab/abcdd if=lab/abc of=lab/part bs=5 count=2 status=nonecat lab/part; echodd if=lab/abc bs=5 skip=2 count=1 status=none; echo

bs=1K count=4 で 4096 バイトです。終わると、写したブロックの数（4+0 records in）と量を標準エラーに表示します。skip=2 は、入力の先頭 2 ブロック（10 バイト）を飛ばしました。

実際のディスクを使う例は、次のようになります（実行しない例）。

ターミナル
# dd if=/dev/sda of=/dev/sdb bs=4M         … sda をまるごと sdb へ複製# dd if=/dev/sda of=mbr.bin bs=512 count=1 … 先頭 512 バイト（MBR）をファイルへ# dd if=/dev/zero of=swapfile bs=1M count=1024 … 1 GiB の、中身が 0 のファイルを作る

if と of を取り違えると、ディスクを上書きして壊します。「in = 読む元、out = 書く先」です。bs はバイト数、count は回数なので、写す量は bs × count です。

2.6find：条件でファイルを探す

find 場所 条件 動作 の形で、ディレクトリの木をいま実際にたどって探します（図解 Linux 3.9）。場所を省くとカレントディレクトリ、動作を省くと -print（パスを表示）です。

条件意味
-name パターン名前がパターンに合う（大文字小文字を区別。-iname は区別しない）。シェルに展開されないよう '*.txt' と引用符で囲む
-type f / d / l通常ファイル / ディレクトリ / シンボリックリンク
-size +10M大きさ。+ はより大きい、- はより小さい。単位 c（バイト）、k、M、G。単位なしは 512 バイトのブロック
-mtime n更新が n 日前（-mmin は分。-atime はアクセス、-ctime は inode の変更）
-newer ファイルそのファイルより後に更新された
-perm モード権限がちょうどモード。-perm -モード はそのビットを全部含む、-perm /モード はどれかを含む
-user 名前 / -group 名前持ち主 / グループ
-inum 番号 / -samefile ファイルinode 番号で（ハードリンクを探す。1.02.3）
-maxdepth nn 階層までしか下りない

-mtime の数え方は、24 時間を 1 日として切り捨てます。

-mtime +7 は「8 日以上前（7 日を超えて前）」、-mtime -7 は「7 日未満（1 週間以内）」です。Debian 12 で、12 時間前・36 時間前・60 時間前のファイルを作って確かめた結果が、図のとおりになります（-1 は 12 時間前だけ、1 は 36 時間前だけ、+1 は 60 時間前だけ）。

名前、種類、大きさ、時刻、持ち主、権限、-exec⌘↵
find . -name '*.txt' -type ffind lab -type dfind . -size +100c -type ffind . -mtime +2 -type ffind lab -mmin -10 -type ffind lab -user you -name 'm*'find lab -perm 640find lab -name 'm*' -exec ls -l {} \;find lab -name 'm*' -exec rm {} +ls lab

ホームの元からあるファイルは 3 月 28 日、いまは 4 月 1 日なので、-mtime +2 に合います。lab の中は、いま作ったファイルなので -mmin -10（10 分以内）に合います。

-exec コマンド {} \; は、見つかったファイルごとにコマンドを実行します。{} が見つかったパスに置き換わり、\; がコマンドの終わりです（; はシェルの区切りなので \ で守ります）。{} + で終えると、見つかったものをまとめて 1 回のコマンドに渡します（上の例では、rm が 1 回だけ動き、m1・m2・m3 をまとめて消しました）。-ok は -exec と同じですが、1 つずつ実行してよいかをたずねます。

注意試験の注意
  • -exec は \;（または {} +）で終える。\; を忘れると 「missing argument to -exec」 のエラー
  • -perm 4000 は「ちょうど」、-perm -4000 は「含む」。SUID を探すのは -4000
  • -size は単位なしだと 512 バイトのブロック。-size +100M で 100 MiB を超えるもの
  • -mtime +7 は「7 日より前」、-mtime -7 は「7 日以内」

2.7ハードリンクとシンボリックリンク

ここからは 1.02.3 です。ファイルの名前は、ディレクトリの中の「名前 → inode 番号」の対応にすぎません（図解 Linux 11.2）。ハードリンクは、同じ inode に名前をもう 1 つ付けたもの、シンボリックリンクは、行き先のパスを中身に書いた別のファイルです（図解 Linux 11.3、11.4）。

ln と ln -s⌘↵
cd /home/you/labprintf 'abc\n' > origln orig hardln -s orig softls -li orig hard soft

orig と hard は inode 番号（1 列目）が同じで、リンク数（3 列目）が 2 です。soft は別の inode を持ち、種類が l、権限はいつも rwxrwxrwx、大きさは「orig」という 4 文字ぶんです。

元の名前を消すと、違いがはっきりします。

元を消すと、シンボリックリンクは切れるエラーになる⌘↵
rm origcat hardls -l hard softcat soft

hard は inode を直接指しているので、読めます（リンク数は 1 に減りました）。soft は「orig」というパスをたどるので、その名前がなくなると No such file or directory になります。行き先のないシンボリックリンクを、壊れたリンク（ぶら下がったリンク）と呼びます。

ハードリンクには、2 つの制限があります。

ハードリンクにできないものエラーになる⌘↵
ln /home/you/notes nlinkecho hi > /tmp/xln /tmp/x xlinkln -s /tmp/x xsymls -l xsymln -sf hard softls -l softcat soft

ディレクトリにはハードリンクを作れません。また、inode 番号はファイルシステムの中でしか意味がないので、別のファイルシステム（ここでは tmpfs の /tmp）のファイルにもハードリンクは作れません（Invalid cross-device link）。シンボリックリンクなら、どちらもできます。

すでにある名前にリンクを作ると File exists で失敗します。最後の ln -sf hard soft のように -f を付けると、その名前を消してから作り直します。切れていた soft が hard を指すようになり、また読めるようになりました。

ハードリンク（ln）シンボリックリンク（ln -s）
inode元と同じ自分の inode を持つ
リンク数1 増える元のリンク数は変わらない
元の名前を消すとそのまま読める切れる（No such file or directory）
ディレクトリ作れない作れる
別のファイルシステム作れない作れる
ls -l の表示ふつうのファイルと同じ種類 l、名前 -> 行き先、権限 rwxrwxrwx
引数の順番ln 元 新しい名前ln -s 元（行き先） 新しい名前
注意試験の注意
  • 引数は cp と同じ順番で「元が先、新しい名前が後」。ln -s 行き先 リンク名
  • シンボリックリンクの行き先を相対パスで書くと、リンクの置き場所からたどる。ln -s orig /tmp/s の /tmp/s は /tmp/orig を指してしまう
  • 同じ inode のファイルを探すには find / -inum 番号 か find / -samefile ファイル

試験では、ls の出力を見せて「どれがリンクか」「これは何の番号か」を問う形が多く出ます。-l（詳しく）、-F（種類の印）、-i（inode 番号）をまとめた ls -lFi の 1 行を読めるようにします。

2.9find と locate：今たどるか、表を引くか

ここからは 1.02.4 です。ファイルを名前で探すコマンドは 2 つあります。find はディレクトリの木をいまたどります。locate は、あらかじめ作っておいたファイル名の一覧（データベース）を引くだけなので、とても速く探せます。

一覧はふつう、1 日 1 回、cron や systemd のタイマーで updatedb が作り直します。そのため、作ったばかりのファイルは locate で見つからず、消したファイルが見つかることがあります。すぐに反映したいときは、root で updatedb を実行します。Rocky Linux 9（mlocate）で確かめた結果です。

ターミナル
# touch /srv/data/report2026.txt# locate report2026# updatedb# locate report2026/srv/data/report2026.txt# rm /srv/data/report2026.txt# locate report2026/srv/data/report2026.txt

最初の locate は何も出しません。updatedb の後で見つかり、消した後も一覧には残っています。

locate は名前の一部に合えば表示します。-i は大文字と小文字を区別しない、-c は数だけを表示します。find のような「大きさ」「権限」「持ち主」の条件は使えません。

updatedb の設定は /etc/updatedb.conf です。一覧に入れないものを決めます。

PRUNE_BIND_MOUNTS = "yes"PRUNEFS = "9p afs anon_inodefs auto autofs bdev binfmt_misc cgroup … nfs nfs4 … proc … sysfs tmpfs …"PRUNENAMES = ".git .hg .svn .bzr .arch-ids {arch} CVS"PRUNEPATHS = "/afs /media /mnt /net /sfs /tmp /udev … /var/tmp …"
項目意味
PRUNEPATHS一覧に入れないディレクトリのパス（/tmp、/media など）
PRUNEFS一覧に入れないファイルシステムの種類（nfs、proc、tmpfs など）
PRUNENAMES一覧に入れない名前（.git など）
PRUNE_BIND_MOUNTSバインドマウントを入れないか（yes）

locate には、古い slocate、Red Hat 系でいまも使われる mlocate（データベースは /var/lib/mlocate/mlocate.db）、Debian 12 などの新しい plocate（/var/lib/plocate/plocate.db）があります。どれも、locate・updatedb・/etc/updatedb.conf という名前と使い方は同じです。

findlocate

速さ遅い速い

条件名前、種類、大きさ、時刻、権限、持ち主…名前（の一部）だけ
設定なし/etc/updatedb.conf

2.10type・which・whereis：コマンドの正体

コマンドの名前を打ったとき、実際に何が動くのかを調べる 3 つのコマンドがあります。

type と whichエラーになる⌘↵
alias ll='ls -l'type lltype cdtype lswhich lswhich cd

type はシェルの組み込みコマンドなので、エイリアス、関数、組み込みコマンド、外部コマンドのどれかを答えます。which は環境変数 PATH のディレクトリから実行ファイルを探すだけなので、cd（組み込み）や ll（エイリアス）は見つけられず、何も表示しません（終了ステータスは 1）。

メモRed Hat 系の which

Rocky Linux などの Red Hat 系では、ログインシェルで /etc/profile.d/which2.sh が読まれ、which がシェル関数に置き換わります。この関数はエイリアスと関数の一覧を /usr/bin/which に渡すので、エイリアスも表示します。試験では、which の本来の働き（PATH から実行ファイルを探す）で答えます。

whereis は、実行ファイル（バイナリ）に加えて、マニュアルとソースの場所も、決まったディレクトリから探します。小さな Linux にはないので、Debian 12 と Rocky Linux 9 の結果です。

ターミナル
$ whereis lsls: /usr/bin/ls /usr/share/man/man1/ls.1.gz$ whereis -b lsls: /usr/bin/ls$ whereis passwdpasswd: /usr/bin/passwd /etc/passwd /usr/share/man/man1/passwd.1ossl.gz
コマンド何を答えるか探す場所
type 名前エイリアス・関数・組み込み・外部コマンドのどれか（外部ならパス）シェルの中と PATH
which 名前実行されるファイルのパスPATH だけ
whereis 名前バイナリ、マニュアル（-m）、ソース（-s）の場所。-b はバイナリだけ決まった標準のディレクトリ

2.11FHS：どこに何を置くか

FHS（Filesystem Hierarchy Standard、ファイルシステム階層標準）は、Linux のディレクトリの使い分けを決めた標準です。どのディストリビューションでも、/etc には設定、/var/log にはログ、という配置がそろっているのは FHS のおかげです。

小さな Linux のトップ⌘↵
ls /ls -ld /bin /sbin /libls /usr /var

小さな Linux（と Debian 12、Rocky Linux 9）では、/bin、/sbin、/lib は /usr の下を指すシンボリックリンクになっています（usr 統合）。FHS の役目の考え方は変わりません。

ディレクトリ置くもの試験での見分け方
/etc設定ファイル「設定」なら /etc
/bin / /sbin基本のコマンド / 管理用のコマンドsbin は root が使うもの
/bootカーネル（vmlinuz）、initramfs、GRUB の設定起動に要るもの
/devデバイスファイル（/dev/sda）
/lib共有ライブラリ、カーネルモジュール
/media / /mnt取り外せる媒体の自動マウント / 一時的に手でマウント
/opt追加のソフトウェア一式「パッケージごとのディレクトリ」
/proc / /sysカーネルの情報を見せる仮想ファイルシステム
/rootroot のホーム/home/root ではない
/run起動してからの実行時のデータ（PID ファイル）
/srvサービスが提供するデータ
/tmp / /var/tmp一時ファイル。/tmp は再起動で消えてよい、/var/tmp は残す
/usr/local管理者がソースから入れたものなど（ディストリのパッケージは入れない）
/usr/shareマニュアル、ドキュメントなど
/var/logログ
/var/spool印刷・メール・cron の処理待ち
要点まとめ
  • chmod の 8 進数は r = 4、w = 2、x = 1 の合計。記号は u/g/o/a +/-/= r/w/x/s/t。再帰は -R
  • umask はファイル 666・ディレクトリ 777 からビットを取り除く。022 → 644 / 755、027 → 640 / 750、033 → 644 / 744
  • SUID = 4000（u+s）、SGID = 2000（g+s）、スティッキー = 1000（o+t）。小文字 s / t は x あり、大文字 S / T は x なし。SUID を探すのは find / -perm -4000
  • 持ち主を変えるのは root だけ。chown 持ち主:グループ、chown :グループ
  • cp -r ディレクトリ、cp -p 属性を保つ、cp -a 全部そのまま。rmdir -p 親もさかのぼって消す。rm -rf 確かめずに中身ごと
  • tar は c / x / t のどれか + z（gzip）/ j（bzip2）/ J（xz）+ f ファイル（f はファイル名の直前）。-C で展開先
  • 圧縮は元のファイルを消す。残すには -k か -c。展開は -d、gunzip / bunzip2 / unxz
  • dd は if= 読む元、of= 書く先、量は bs × count
  • find：-name、-type f/d/l、-size +100M、-mtime +7（7 日より前）、-perm -4000、-user、-exec コマンド {} \;
  • ハードリンクは同じ inode・ディレクトリと別のファイルシステムには不可。シンボリックリンクは自分の inode・元を消すと切れる。ls -F の印は / * @ | =
  • locate はデータベースを引く。updatedb で作り直し、設定は /etc/updatedb.conf（PRUNEPATHS など）
  • type は組み込みやエイリアスも分かる。which は PATH だけ。whereis はバイナリ・マニュアル・ソース
  • FHS：設定 /etc、ログ /var/log、一時 /tmp（消えてよい）と /var/tmp（残す）、自分で入れたもの /usr/local、追加ソフト /opt、取り外せる媒体 /media
