# 図解サイトの作り方

`~/workspace/sandbox/docs/` には、同じ作りの学習サイトが並んでいる。

| サイト | 特徴 | 雛形にするとき |
| --- | --- | --- |
| `docs/rust` | 図が中心。コードは読むだけ | 実行環境が要らない題材 |
| `docs/postgresql` | 本文の SQL をブラウザ内の PostgreSQL 18（PGlite）で実行できる。DB ビュー、確認問題、実験場がある | ブラウザで動かせる既存の実行環境がある題材（SQL、Python/Pyodide、JS など） |
| `docs/cpu` | 実行環境を自作した例。RISC-V エミュレータ（rv.js）と論理回路シミュレータ（logic.js）、判定を集約した grade.js、ステップ実行の「CPU を見る」。設計は `cpu/DESIGN.md` | 実行環境そのものを作る題材。作り方の流れ（設計書 → 中心部品を並行で作りテスト → 判定の共通部品と章の検査スクリプト → 画面と章を並行 → 仕上げ）の手本 |
| `docs/linux` | 実行環境を自作した 2 つめの例。JS のジェネレータで書いた教育用カーネル（VFS、プロセス、シグナル、システムコールと strace、sh、コマンド約 130、仮想メモリ、CFS、ページキャッシュ、TCP、名前空間、systemd 風 init）。確認問題は clone した機械で模範解答と比べ、`vary` で準備を変えて答えの直書きを防ぐ | OS やシステムのように「中が見えない」題材。本物を動かさず、振る舞いをまねたシミュレータで中身（プロセス表、fd 表、ページ表）を見せる手本。本物との出力の照合は Docker で |

入口は `docs/index.html`（各サイトへのカードの一覧）。どのサイトも `site/index.html` を file:// で開けば読め、サーバは要らない。

GitHub: https://github.com/ogatomo83/practice-site（`docs/` がリポジトリのルート）。main への push で GitHub Pages（https://ogatomo83.github.io/practice-site/ ）に公開される。このスキル自体も `docs/.claude/skills/zukai-site/` に入っていて、`~/.claude/skills/zukai-site` はそこへのシンボリックリンクになっている。

**どこまで・どの細かさで作るかは [references/granularity.md](references/granularity.md)、実行環境を作るときは [references/runtime.md](references/runtime.md) を先に読む。**

## 新しいサイトを作る手順

1. **雛形を丸ごと複製する。** 一から書かない。実行できる題材なら `docs/postgresql`、読むだけなら `docs/rust` を `docs/<topic>` にコピーして `site/` を消す。
2. **サイト固有の名前を置き換える。**
   - `build.mjs` の `BRAND`
   - localStorage のキーの接頭辞（rust は `zr-`、postgresql は `zp-`）。file:// のページはブラウザで同じオリジン扱いになりやすく、接頭辞が同じだと読了や設定が混ざる。必ず別のものにする
   - ハイライタ（`src/lib/highlight.mjs`）の言語
   - 実行環境（`sql.js` に相当するランナー）、データセット
3. **章立てを先に決めてユーザーに見せる。** 序章（ch00）から本編、最後に付録（`appendix: true`、早見表と用語集）。各章のタイトル、1 行のリード、目安の時間を表にして合意を取ってから本文に入る。
4. **原稿を書く**（下の「原稿の書き方」）。1 章ずつ書き、書くたびに `node src/build.mjs` を通す。
5. **検査する**（下の「検査」）。
6. **`docs/index.html` にカードを足す。** 既存の `<a class="card …">` を真似て、パス、名前、1 文の説明、`N 章 · 図 N · 実行できる X N` を書く。
7. **`README.md` を書く**（読む / 編集・ビルド / ファイル表 / 原稿の記法 / 検査）。既存サイトの README が見本。

## 原稿の書き方

記法の詳細は [references/notation.md](references/notation.md)。文章の方針は次のとおり。

- **日本語の です・ます 調。** 1 文は短くし、1 段落は 3 文程度に収める。専門用語は初出で言い換える。
- **図が先、文が後。** 仕組みは `fig` で描いてから文で補う。状態が変わる話（MVCC、所有権の移動など）は `steps` で段階を切り替えられる図にする。
- **節は 1 つの問いに 1 つの答え。** 見出しには `{#id}` を付ける。リンクと読了の記録がこれに依存する。
- **動かせるものは動かす。** 説明に使う例は、本文のその場で実行できるブロックにする。章の中の実行ブロックは上から順に積み上がる前提で書く（前のブロックで作った表を後で使う）。章の専用データは `setup` ブロックに書く。
- **エラーも教材にする。** よくある失敗は「エラーになる」印のブロック（`error` / `fail`）で実際に出し、直後にエラー解説カード（`:::pgerr` / `:::rustc`）で理由と直し方を書く。
- **章末の型。** `:::try`（やってみよう）→ 練習用の実行ブロック → `:::key まとめ` → `## 確認問題 {#quiz}`（実行できる題材のみ）。
- **歴史や背景は `:::hist` / `:::deep` に逃がす。** 本筋を細くしない。
- 数値・バージョン・挙動は、実際に動かして確かめたものだけを書く。記憶で書かない。

## 確認問題（`:::quiz`）

ユーザーの方針は「最後に自分で書けるか試す」「自由に試す画面とは別の小さな枠で、正解・不正解を判定する」「出力が合っていれば基本 OK」。採点の仕組みは `docs/postgresql/src/assets/quiz.js`。

- **採点用の環境は別に立てる。** 本文の環境を汚さないためで、毎回トランザクションの中で実行して ROLLBACK する。
- **比べるのは出力の値だけ。** 列名、行の順番、列の順番、`2000` と `2000.00` の違いは問わない。「〜順に」と指定した問題だけ `ordered` を付けて並び順も判定する。
- **書き換えの問題は結果を調べる。** INSERT / UPDATE / DDL の問題は `check` で実行後の状態を調べて比べる。制約の問題は `try_sql()` で「通るか、どの SQLSTATE で止まるか」を表にする。
- **1 章 3〜4 問。** 序章などの軽い章は 1 問。本文で扱った範囲だけから出す。
- **誤答を通さない作りにする。** 典型的な誤答でも同じ出力になってしまう問題は作り直す。過去の例：
  - 税率 10% では、切り捨ての有無で値が変わらなかった → 8% にした
  - `like '%ink%'` でも全文検索と同じ行が出た → データを足して差が出るようにした
- **実行ごとに変わる値を答えにしない。** `now()`、xmin、乱数などは使わない。
- 正解した記録は localStorage（`<接頭辞>quiz`）に残す。

## 検査

作ったら必ず全部動かす。テンプレートは `scripts/` にある（PostgreSQL 版。題材に合わせて書き換える）。依存は `@electric-sql/pglite` と `puppeteer-core` で、Chrome はインストール済みの `/Applications/Google Chrome.app` を使う。スクリプトと `node_modules` はスクラッチパッドに置き、サイトの中には入れない（サイトに package.json はない）。

1. `node src/build.mjs` が通り、章数・図・実行ブロック・問題の数が出る。
2. **全実行ブロック**をヘッドレス Chrome で file:// から開いたページ上で実行する。「エラーになる」印のブロックだけがエラーになり、他は通ることを確かめる。
3. **確認問題**：`scripts/verify-quiz.mjs <site>` を使う。次を確かめる。
   - 模範解答が通る
   - 2 回実行して同じ出力になる
   - 別解（`alts.json` の `ok`）は正解になる
   - 誤答（`ng`）は不正解になる
4. **画面**：`scripts/browser-check.mjs`。次を確かめる。
   - 各判定（正解・並び順違い・エラー・トランザクション文・未入力・不正解）が表示される
   - 本文の DB が変わっていない
   - ライトとダークの両方で表示が崩れない
   - 幅 390px で横スクロールが出ない
   - ページのエラーが 0 件
5. 既存の章の末尾に足したときは、追加部分より前の本文が変わっていないことを確かめる。元の原稿を退避しておき、先頭からの一致を比べる。

## UI の約束

- 色は CSS 変数で定義し、ライト / ダークの両方を用意する。図（`diagrams.mjs`）も色は CSS クラス経由で指定する。
- 外部から読み込むのは、フォント（Google Fonts）と実行環境の CDN だけ。どちらもバージョンを固定する。
- 見た目は unslop（https://github.com/heydamir/unslop, CC BY 4.0）のチェックリストに沿って調整する。README にクレジットを残す。
