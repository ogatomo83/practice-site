## プログラムもメモリの中の数 {#stored}

第 8 章のメモリマップで、命令は 0 番地から置かれると書きました。命令がメモリにあるのなら、データと同じように `lw` で読めるはずです。プログラムに、自分自身の先頭を読ませてみます。

```asm run title="プログラムが、自分の 1 つ目の命令を読む"
    lw   a0, 0(zero)     # 0 番地のワードを読む（zero はいつも 0 のレジスタ）
    li   a7, 34          # a0 を 16 進数で表示
    ecall
```

`0x00002503` と表示されます。これが、1 行目の `lw a0, 0(zero)` という命令の正体です。CPU が実際に実行しているのは、アセンブリの文字ではなく、この 32 ビットの数です。この数を**機械語**と呼びます。

3 つの命令は、メモリに次のように入っています。

```fig layout 上のプログラムが入ったメモリ。命令は 1 つが 4 バイト（1 ワード）で、0 番地から順に並ぶ。リトルエンディアンなので、下の桁のバイトが先に来る
{
  unit: 30,
  rows: [
    { label: '0x0000', cells: [{ t: '03', w: 1.6, kind: 'accent' }, { t: '25', w: 1.6, kind: 'accent' }, { t: '00', w: 1.6, kind: 'accent' }, { t: '00', w: 1.6, kind: 'accent' }], note: '0x00002503 ＝ lw a0, 0(zero)' },
    { label: '0x0004', cells: [{ t: '93', w: 1.6 }, { t: '08', w: 1.6 }, { t: '20', w: 1.6 }, { t: '02', w: 1.6 }], note: '0x02200893 ＝ li a7, 34' },
    { label: '0x0008', cells: [{ t: '73', w: 1.6 }, { t: '00', w: 1.6 }, { t: '00', w: 1.6 }, { t: '00', w: 1.6 }], note: '0x00000073 ＝ ecall' },
  ],
}
```

第 1 章で見た**プログラム内蔵方式**が、これです。プログラムは数の並びで、データと同じメモリに入っています。アセンブリは、その数を人が読み書きしやすいように文字で書いたものにすぎません。アセンブリを機械語に直すプログラムを**アセンブラ**と呼びます。

| 呼び名 | 例 | だれのためのものか |
| --- | --- | --- |
| アセンブリ | `lw a0, 0(zero)` | 人が読み書きする |
| 機械語 | `0x00002503` | CPU が実行する |

RISC-V の基本の命令は、**どれも 32 ビット（4 バイト）ちょうど**です。長い命令も短い命令もありません。だから、1 つ目の命令が 0 番地なら、2 つ目は 4 番地、3 つ目は 8 番地と決まります。

:::note 命令の長さがそろっていない CPU もある
x86 の命令は、1 バイトのものから 15 バイトのものまであります。次の命令がどこから始まるかは、今の命令を読み解くまで分かりません。命令の長さをそろえるのは、RISC の設計の特徴の 1 つです（第 1 章）。RISC-V にも、よく使う命令を 16 ビットに縮める拡張（C 拡張）がありますが、このサイトの CPU は使いません。
:::

## 取り出す・読み解く・実行する {#cycle}

CPU は、メモリに並んだ機械語をどうやって実行するのでしょうか。CPU の中には、**次に実行する命令の番地**を覚えている特別なレジスタがあります。これを **pc**（program counter、プログラムカウンタ）と呼びます。

CPU がしているのは、次の 3 つの繰り返しだけです。

1. **フェッチ**（取り出す）：pc の番地から、メモリの 4 バイトを読む
2. **デコード**（読み解く）：その 32 ビットを区切って、何の命令か、どのレジスタを使うかを調べる
3. **実行**：計算して結果をレジスタに書く。pc を 4 増やして、次の命令に進む

```fig seq 命令 1 つ分の流れ。この 1 周を、電源が切れるまで繰り返す。くわしい回路は第 16 章で作る

    { id: 'dec', label: 'デコーダ' },
    { id: 'reg', label: 'レジスタ', kind: 'stack' },
    { id: 'alu', label: '演算回路（ALU）' },
  ],
  msgs: [

    { from: 'dec', to: 'reg', label: 'a1 と a2 を読む' },

```

デコーダは第 6 章で、ALU も第 6 章で、レジスタは第 7 章で作った部品です。CPU は、これらの部品を命令のビットでつないで動かす回路です。

次のブロックは、ステップ実行の画面で開きます。「1 命令進む」を押すたびに、pc が 0、4、8 と 4 ずつ増え、今の命令の機械語が表示されるのを確かめてください。

```asm run step title="1 命令ずつ進めて、pc と機械語を見る" regs="a0"
    li   a0, 1
    addi a0, a0, 1       # a0 に 1 を足す
    addi a0, a0, 1
    addi a0, a0, 1
```

4 命令を実行すると pc は 16 になり、そこにはもう命令がないので、プログラムは終わります。`a0` は 4 です。

## 32 ビットを区切る：R 形式 {#r-format}

デコードでは、32 ビットを決まった位置で区切ります。区切った 1 つ 1 つを**フィールド**と呼びます。まず、レジスタどうしを計算する命令 `add a0, a1, a2`（`a0 ← a1 + a2`）を見ます。

```fig layout add a0, a1, a2 の機械語 0x00C58533。レジスタどうしの計算に使う R 形式は、6 つのフィールドに分かれる

      { t: '14…12', w: 3, kind: 'empty' }, { t: '11 … 7', w: 5, kind: 'empty' }, { t: '6 … 0', w: 7, kind: 'empty' },
    ] },
    { label: 'フィールド', cells: [
      { t: 'funct7', w: 7, kind: 'static' }, { t: 'rs2', w: 5, kind: 'heap' }, { t: 'rs1', w: 5, kind: 'heap' },
      { t: 'funct3', w: 3, kind: 'static' }, { t: 'rd', w: 5, kind: 'stack' }, { t: 'opcode', w: 7, kind: 'accent' },
    ] },
    { label: '中身', cells: [
      { t: '0000000', w: 7 }, { t: '01100', w: 5 }, { t: '01011', w: 5 },

      { t: '', w: 3, kind: 'empty' }, { t: 'a0 = x10', w: 5, kind: 'empty' }, { t: 'レジスタの計算', w: 7, kind: 'empty' },
    ] },
  ],
}
```

| フィールド | 幅 | 役目 |
| --- | --- | --- |
| **opcode**（オペコード） | 7 ビット | 命令の大きな種類。`0110011` は「レジスタどうしの計算」 |
| **rd** | 5 ビット | 結果を書くレジスタの番号（destination） |
| **funct3** | 3 ビット | opcode の中での細かい種類 |
| **rs1** | 5 ビット | 1 つ目の入力のレジスタの番号（source 1） |
| **rs2** | 5 ビット | 2 つ目の入力のレジスタの番号（source 2） |
| **funct7** | 7 ビット | さらに細かい種類 |

この区切り方を **R 形式**（Register の R）と呼びます。

レジスタの欄が 5 ビットなのは、レジスタが 32 本だからです。5 ビットで 0 から 31 までの番号を表せます。`a0` や `t0` という名前は呼びやすくするための別名で、機械語の中では番号になります。この章でよく使うレジスタの番号は次のとおりです（全部の表は第 10 章にあります）。

| 名前 | `zero` | `ra` | `sp` | `t0` | `t1` | `t2` | `s0` | `a0` | `a1` | `a2` | `a7` |
| --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 番号 | 0 | 1 | 2 | 5 | 6 | 7 | 8 | 10 | 11 | 12 | 17 |

### 手で組み立てて、動かす

図のビットを左から順につなげ、4 ビットずつに区切り直して 16 進数にします。

```text
funct7   rs2    rs1    f3   rd     opcode
0000000  01100  01011  000  01010  0110011

0000 0000 1100 0101 1000 0101 0011 0011
   0    0    C    5    8    5    3    3     →  0x00C58533
```

第 8 章で使った `.word` は、ワードを 1 つ置くディレクティブでした。命令の場所に `.word` で数を置けば、CPU はそれを命令として実行します。`add a0, a1, a2` と書く代わりに、今作った数を置いてみます。

```asm run title="add の代わりに、機械語を数として書く" regs="a0,a1,a2"
    li   a1, 30
    li   a2, 12
    .word 0x00C58533     # add a0, a1, a2 の機械語
    li   a7, 1           # a0 を 10 進数で表示
    ecall
```

`42` と表示されます。アセンブリを 1 文字も書かなくても、数が合っていれば命令として動きます。

funct7 を 1 か所だけ変えます。`0000000` を `0100000` にすると、機械語は `0x40C58533` になります。

```asm run title="funct7 を変えると、別の命令になる" regs="a0,a1,a2"
    li   a1, 30
    li   a2, 12
    .word 0x40C58533     # funct7 = 0100000
    li   a7, 1
    ecall
```

`18` と表示されます。30 − 12 です。この機械語は `sub a0, a1, a2` でした。opcode と funct3 が同じで、funct7 の 1 ビットだけが足し算と引き算を分けています。第 5 章で、引き算は「片方を反転して 1 を足す」だけで足し算の回路を使い回せると学びました。その切り替えのスイッチが、このビットです。

同じ opcode の命令は、funct3 と funct7 で区別されます。

| 命令 | funct7 | funct3 | 意味 |
| --- | --- | --- | --- |
| `add` | 0000000 | 000 | 足す |
| `sub` | 0100000 | 000 | 引く |
| `xor` | 0000000 | 100 | 排他的論理和 |
| `or` | 0000000 | 110 | 論理和 |
| `and` | 0000000 | 111 | 論理積 |
| `mul` | 0000001 | 000 | 掛ける（M 拡張） |

## 数を埋め込む：I 形式 {#i-format}

`addi a0, zero, 42` は、「`zero` の値（0）に 42 を足して `a0` に入れる」命令です。42 という数は、レジスタではなく命令の中に直接書かれています。このように命令に埋め込まれた数を**即値**（immediate、略して imm）と呼びます。

即値を持つ命令は **I 形式**（Immediate の I）です。R 形式の funct7 と rs2 の場所、合わせて 12 ビットが、即値の置き場になります。

```fig layout addi a0, zero, 42 の機械語 0x02A00513。I 形式は、上の 12 ビットが即値。rs1・funct3・rd・opcode の位置は R 形式と同じ

    ] },
    { label: 'フィールド', cells: [

  ],
}
```

`imm[11:0]` は「即値のビット 11 からビット 0 まで」という意味の書き方です。同じ手順で 16 進数にします。

```text
imm           rs1    f3   rd     opcode
000000101010  00000  000  01010  0010011

0000 0010 1010 0000 0000 0101 0001 0011
   0    2    A    0    0    5    1    3     →  0x02A00513
```

今度は、プログラム全体を機械語だけで書きます。2 行目は `addi a7, zero, 1`（rd が `a7` = 17 = `10001`、即値が 1）、3 行目は `ecall` です。

```asm run title="機械語だけで書いたプログラム"
    .word 0x02A00513     # addi a0, zero, 42
    .word 0x00100893     # addi a7, zero, 1
    .word 0x00000073     # ecall
```

`42` と表示されます。アセンブラが私たちの代わりにしてくれているのは、この数を作る作業です。

:::tip 書き換えて試す
1 行目の `02A` の部分が即値です。`0x06400513` にすると 100 が、`0x00700513` にすると 7 が表示されます。即値が 16 進数の上 3 桁にそのまま見えるのは、I 形式の即値がちょうど上の 12 ビットだからです。
:::

### 負の即値

即値の 12 ビットは、**2 の補数**（第 3 章）で表した符号付きの数です。範囲は -2048 から 2047 までです。-1 は 12 ビットで `111111111111` なので、`addi a0, a0, -1` の機械語は上 3 桁が `FFF` になります。

```asm run title="-1 を足す addi" regs="a0"
    li   a0, 10
    .word 0xFFF50513     # addi a0, a0, -1
    .word 0xFFF50513     # もう 1 回
```

`a0` は 8 になります。CPU は、12 ビットの即値を 32 ビットに符号拡張してから足します。引き算専用の `subi` という命令が RISC-V にないのは、`addi` に負の数を渡せば済むからです。

RISC-V の基本の命令は、すべて次の 6 つの形式のどれかです。

| 形式 | 使う命令 | opcode |
| --- | --- | --- |
| R | レジスタどうしの計算：`add` `sub` `and` `or` `xor` `sll` `mul` `div` など | `0110011` |
| I | 即値との計算：`addi` `andi` `ori` `xori` `slli` など | `0010011` |
| I | メモリから読む：`lb` `lh` `lw` `lbu` `lhu` | `0000011` |
| S | メモリに書く：`sb` `sh` `sw` | `0100011` |
| B | 条件付きの分岐：`beq` `bne` `blt` `bge` `bltu` `bgeu` | `1100011` |
| U | 上位 20 ビットを作る：`lui` | `0110111` |
| J | ジャンプ：`jal` | `1101111` |

CPU は、まず下の 7 ビットの opcode を見ます。それで形式が決まり、残りのビットの区切り方が決まります。

この表には、設計の工夫が見えます。

- **同じ役目のフィールドは、いつも同じ位置にある。** rs1 はどの形式でもビット 19〜15、rs2 はビット 24〜20、rd はビット 11〜7 です。CPU は、命令の種類が分かる前から、この位置のビットを使ってレジスタを読み始められます
- **即値の符号ビットは、いつもビット 31 にある。** どの形式でも、命令のいちばん上のビットが即値の符号です。符号拡張の回路は、形式を調べずにビット 31 を引き伸ばせばよくなります
- **使わないフィールドは即値に回す。** I 形式は rs2 が要らないので、その場所を即値に使います。U 形式と J 形式は rs1 も funct3 も要らないので、20 ビットを即値にできます

規則正しく並べるのは、見た目のためではなく、**デコードの回路を小さく、速くするため**です。第 16 章で CPU の中身を組み立てるときに、この並びのありがたみが分かります。

## S 形式と B 形式：即値が分かれている理由 {#sb-format}

メモリに書く `sw a0, 12(sp)` は、「`sp + 12` の番地に `a0` の値を書く」命令です。番地を作る `sp`（rs1）と、書く値の `a0`（rs2）の 2 本のレジスタを読みます。書き込む先のレジスタはないので、rd は要りません。

そこで **S 形式**（Store の S）は、rd の場所に即値の下の 5 ビットを置きます。即値は 2 つに分かれますが、rs1 と rs2 は R 形式と同じ位置のままです。

```text
sw a0, 12(sp)        即値 12 = 0000000 01100

imm[11:5]  rs2    rs1    f3   imm[4:0]  opcode
0000000    01010  00010  010  01100     0100011      →  0x00A12623
           a0     sp     ワード
```

即値を 1 か所にまとめると、今度は rs2 の位置がずれます。RISC-V は「レジスタの番号の位置を動かさない」ほうを選びました。即値はつなぎ直すだけ（配線だけ）で元に戻せますが、レジスタの番号の位置が命令ごとに変わると、選ぶ回路が余計に必要になるからです。

### B 形式：ビットの並びが飛び飛び

条件付きの分岐 `beq a0, a1, 飛び先` は、「`a0` と `a1` が等しければ、飛び先に進む」命令です（第 11 章）。2 本のレジスタを比べ、rd は使いません。S 形式と同じ材料です。

即値には、**今の命令から飛び先までの距離**（バイト数）が入ります。命令は 4 バイトずつ並ぶので、この距離はいつも偶数です。つまり、ビット 0 はいつも 0 で、書いておく必要がありません。そこで **B 形式**（Branch の B）は、ビット 0 を省き、代わりにビット 12 までの 13 ビットぶんの距離（-4096〜4094）を表します。

問題は、その 12 個のビットをどこに置くかです。

```fig layout S 形式と B 形式の即値の置き場。数字は「即値の何ビット目か」。色の付いた 2 か所だけが違い、残りの 10 ビットは同じ位置にある
{
  unit: 21,
  rows: [
    { label: 'ビット', cells: [
      { t: '31', w: 1.5, kind: 'empty' }, { t: '30 … 25', w: 5.5, kind: 'empty' }, { t: '24 … 20', w: 5, kind: 'empty' }, { t: '19 … 15', w: 5, kind: 'empty' },
      { t: '14…12', w: 3, kind: 'empty' }, { t: '11 … 8', w: 3.5, kind: 'empty' }, { t: '7', w: 1.5, kind: 'empty' }, { t: '6 … 0', w: 7, kind: 'empty' },
    ] },
    { label: 'S', cells: [
      { t: '11', w: 1.5, kind: 'accent' }, { t: '10:5', w: 5.5 }, { t: 'rs2', w: 5, kind: 'heap' }, { t: 'rs1', w: 5, kind: 'heap' },
      { t: 'funct3', w: 3, kind: 'static' }, { t: '4:1', w: 3.5 }, { t: '0', w: 1.5, kind: 'accent' }, { t: 'opcode', w: 7, kind: 'empty' },
    ] },
    { label: 'B', cells: [
      { t: '12', w: 1.5, kind: 'accent' }, { t: '10:5', w: 5.5 }, { t: 'rs2', w: 5, kind: 'heap' }, { t: 'rs1', w: 5, kind: 'heap' },
      { t: 'funct3', w: 3, kind: 'static' }, { t: '4:1', w: 3.5 }, { t: '11', w: 1.5, kind: 'accent' }, { t: 'opcode', w: 7, kind: 'empty' },
    ] },
  ],
}
```

B 形式の即値は、上から `12`、`10:5`、`4:1`、`11` と飛び飛びに並んでいます。でたらめに見えますが、S 形式と見比べると理由が分かります。

- ビット `10:5` と `4:1` は、S 形式と**まったく同じ位置**に置く。回路を共有できる
- いちばん上のビット（符号）は、ほかの形式と同じく**ビット 31** に置く。B 形式ではそれが即値のビット 12
- 残ったビット 11 は、S 形式でビット 0 が入っていた場所（命令のビット 7）に置く。B 形式ではビット 0 は要らないので、そこが空いている

もし即値を 1 つ左にずらして素直に詰めると、12 個のビットすべての位置が S 形式とずれてしまいます。飛び飛びの並びは、**形式が違っても、即値の各ビットがなるべく同じ場所から来るようにした**結果です。J 形式の `imm[20|10:1|11|19:12]` も、同じ考え方で並んでいます。

手で組み立ててみます。`beq a0, a1, 8 バイト先` の即値は 8 = `0 0 000000 0100 0`（ビット 12、11、10:5、4:1、0 の順）です。

```text
imm[12|10:5]  rs2    rs1    f3   imm[4:1|11]  opcode
0 000000      01011  01010  000  0100 0       1100011     →  0x00B50463
              a1     a0     等しい
```

```asm run title="機械語で書いた beq が、命令を 1 つ飛び越す"
    li   a0, 1
    li   a1, 1
    .word 0x00B50463     # beq a0, a1, 8 バイト先
    li   a0, 99          # 飛び越される
    li   a7, 1           # ここが 8 バイト先
    ecall
```

`1` と表示されます。`li a0, 99` は実行されませんでした。`li a1, 1` を `li a1, 2` に変えると、2 つは等しくないので飛ばず、`99` と表示されます。

後ろに戻る分岐は、距離が負の数になります。`bne a0, zero, 4 バイト前`（`a0` が 0 でなければ 1 つ前の命令に戻る）の機械語は `0xFE051EE3` です。

```asm run title="戻る分岐で、同じ命令を繰り返す" regs="a0"
    li   a0, 5
    addi a0, a0, -1      # a0 を 1 減らす
    .word 0xFE051EE3     # bne a0, zero, 4 バイト前（上の addi に戻る）
```

`a0` は 0 になり、実行した命令は 11 個です（最初の `li` が 1 個、`addi` と `bne` が 5 回ずつ）。3 行しかないプログラムが 11 命令ぶん動きました。これがループです。第 11 章でくわしく扱います。

:::note 距離で書く利点
分岐の即値は、飛び先の番地そのものではなく、今の pc からの距離です。プログラム全体をメモリの別の場所に移しても、距離は変わらないので、機械語を書き直す必要がありません。アセンブリではラベルを書けば、アセンブラが距離を計算してくれます。
:::

## 即値は 12 ビットまで：lui と addi {#lui}

I 形式の即値は 12 ビットでした。32 ビットの命令から、opcode の 7、rd の 5、funct3 の 3、rs1 の 5 を引くと、残りは 12 ビットしかないからです。

> 32 − 7 − 5 − 3 − 5 ＝ 12

そのため、`addi` に書ける数は -2048 から 2047 までです。範囲の外の数を書くと、アセンブラが断ります。

```asm run error title="addi に大きすぎる数を書く"
    addi a0, zero, 5000
```

「数 5000 は `addi` に入りません」というエラーになります。機械語にする方法がないからです。

では、`0x12345678` のような 32 ビットいっぱいの数は、どうやってレジスタに入れるのでしょうか。32 ビットの命令の中に、32 ビットの数は入りません。答えは、**2 つの命令に分ける**ことです。

- `lui rd, 数`（load upper immediate）：20 ビットの即値を、レジスタの**上位 20 ビット**に入れる。下位 12 ビットは 0 になる。U 形式
- `addi rd, rd, 数`：下位 12 ビットを足す

```asm run title="lui と addi で 32 ビットの数を作る" regs="a0"
    lui  a0, 0x12345     # a0 = 0x12345000
    addi a0, a0, 0x678   # a0 = 0x12345678
    li   a7, 34
    ecall
```

`0x12345678` と表示されます。20 ビット + 12 ビットで、ちょうど 32 ビットです。

これまで何度も使ってきた `li` は、じつは CPU の命令ではありません。アセンブラが `addi` や `lui` に書き直してくれる、便利な書き方です。こういうものを**疑似命令**と呼びます（第 10 章）。`li` が何に化けたかを、プログラム自身に読ませて確かめます。

```asm run title="li は 2 つの命令に展開される"
    li   t0, 0x12345678  # 0 番地と 4 番地の 2 語になる
    lw   a0, 0(zero)     # 0 番地の機械語
    li   a7, 34
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    lw   a0, 4(zero)     # 4 番地の機械語
    li   a7, 34
    ecall
```

```console
0x123452b7
0x67828293
```

1 語目の下 7 ビットは `0110111` で、`lui` の opcode です。上の 5 桁に `12345` がそのまま見えます。2 語目は上 3 桁が `678` の `addi` です。1 行の `li` が、`lui t0, 0x12345` と `addi t0, t0, 0x678` の 2 つの命令になりました。数が -2048〜2047 に収まるときは、`li` は `addi` 1 つだけになります。

### 下位 12 ビットが 0x800 以上のときの落とし穴

`0x12345FFF` を作るには、`lui a0, 0x12345` と `addi a0, a0, 0xFFF` でよさそうに見えます。しかし `addi` の即値は符号付きなので、`0xFFF` という 12 ビットは 4095 ではなく **-1** です（4095 と書くとアセンブラに断られます）。

```asm run title="素直に分けると、1 つ足りなくなる" regs="a0"
    lui  a0, 0x12345     # a0 = 0x12345000
    addi a0, a0, -1      # 12 ビットで 0xFFF。でも意味は -1
    li   a7, 34
    ecall
```

`0x12344fff` になってしまいました。上位の桁から 1 を借りてしまったのです。そこで、**あらかじめ上位に 1 を足しておきます**。

```asm run title="上位に 1 を足しておく" regs="a0"
    lui  a0, 0x12346     # 1 多い 0x12346000
    addi a0, a0, -1      # 1 引いて 0x12345FFF
    li   a7, 34
    ecall
```

今度は `0x12345fff` です。下位 12 ビットが `0x800` 以上（符号ビットが 1）のときは、上位に 1 を足す。`li` と書けば、アセンブラがこの調整もしてくれます。

## 機械語を読む {#disasm}

逆向きの作業、機械語からアセンブリに戻すことを**逆アセンブル**と呼びます。`0x00A28333` を手で読んでみます。

1. 2 進数にする：`0000 0000 1010 0010 1000 0011 0011 0011`
2. 下の 7 ビットを見る：`0110011`。表から、レジスタどうしの計算で、R 形式
3. R 形式の幅（7・5・5・3・5・7）で区切る

```text
0000000  01010  00101  000  00110  0110011
funct7   rs2    rs1    f3   rd     opcode
足し算   x10    x5          x6
         a0     t0          t1
```

4. funct7 が `0000000`、funct3 が `000` なので `add`。rd が `t1`、rs1 が `t0`、rs2 が `a0`

答えは `add t1, t0, a0` です。アセンブリでは「結果、入力 1、入力 2」の順に書きますが、機械語の中では rs2、rs1、rd と逆の順に並んでいる点に注意してください。動かして確かめます。

```asm run title="読み解いた機械語を実行する" regs="t0,a0,t1"
    li   t0, 40
    li   a0, 2
    .word 0x00A28333     # add t1, t0, a0 のはず
```

`t1` が 42 になりました。読み解きは合っていたことになります。

:::tip 「CPU を見る」でも確かめられる
ステップ実行の画面には、今の命令の機械語と、フィールドごとの区切りが表示されます。自分で読み解いた結果と見比べてみてください。
:::

## 命令とデータに区別はない {#self}

メモリの中の数が命令なのかデータなのかを決めているのは、数そのものではありません。**pc がそこを指したら命令、`lw` で読んだらデータ**です。

命令として意味のない数を pc が指すと、CPU は実行できません。

```asm run error title="命令ではない数を実行する"
    li   a0, 1
    .word 0xFFFFFFFF     # どの命令の形にも合わない
```

「機械語 0xffffffff は命令として解釈できません」というエラーで止まります。これを**不正命令**の例外と呼びます（第 19 章）。データを置いた場所に pc が迷い込むと、こうなります。

逆に、命令をデータとして**書き換える**こともできます。次のプログラムは、`nop`（何もしない命令）が置いてある場所に、実行中に別の機械語を書き込みます。

```asm run title="プログラムが自分の命令を書き換える" regs="a0"
main:
    li   t0, 0x02A00513  # addi a0, zero, 42 の機械語
    la   t1, slot        # 書き換える場所の番地
    sw   t0, 0(t1)       # 命令のある場所に、数として書く
slot:
    nop                  # ここに来たときには、もう nop ではない
    li   a7, 1
    ecall
```

`42` と表示されます。ソースには `a0` に 42 を入れる命令は書かれていません。実行の途中で、プログラムが自分で作りました。

プログラム内蔵方式の力は、ここにあります。プログラムが数なら、**プログラムを作るプログラム**が書けます。アセンブラもコンパイラも、命令の数をメモリやファイルに書き出すプログラムです。OS がアプリを起動するときも、ファイルから機械語をメモリに読み込んで、pc をそこに向けています。

:::warn 便利さと危うさは同じもの
データを命令として実行できる性質は、攻撃にも使われます。外から送り込まれたデータを、だまして実行させる手口です。今の CPU と OS は、メモリの領域ごとに「実行してよいか」「書いてよいか」の印を付けて、データの領域が実行されないように守っています。このサイトの CPU には、その仕組みはありません。
:::

:::try やってみよう
下のプログラムは、機械語だけで書かれています。

1. 実行する前に、1 行目を手で読み解く。何を表示するプログラムか
2. 1 行目の即値を書き換えて、`2025` を表示させる（2025 は 16 進数で `0x7E9`）
3. 1 行目を、`a0` に -1 を入れる機械語に変える
:::

```asm run title="練習用：機械語を読んで、書き換える"
    .word 0x3E800513
    .word 0x00100893
    .word 0x00000073
```

:::key この章のまとめ
- 命令は 32 ビットの数（**機械語**）で、データと同じメモリに入っている。アセンブリは機械語を人が読める形で書いたもの
- CPU は **pc** の番地から 4 バイトを取り出し（フェッチ）、区切って読み解き（デコード）、実行して、pc を 4 増やす。これを繰り返す
- 32 ビットは **opcode・rd・funct3・rs1・rs2・funct7・即値**のフィールドに区切られる。区切り方は **R・I・S・B・U・J** の 6 形式
- opcode はいつも下の 7 ビット。rd・rs1・rs2 の位置はどの形式でも同じ。即値の符号はいつもビット 31。デコードの回路を単純にするための設計
- S 形式と B 形式は、レジスタの位置を守るために即値を 2 つに分ける。B 形式の飛び飛びの並びは、S 形式となるべく同じ位置にビットを置いた結果
- I 形式の即値は 12 ビット（-2048〜2047）。32 ビットの数は **`lui`（上位 20 ビット）+ `addi`（下位 12 ビット）** で作る。`li` はそれに展開される疑似命令
- `.word` で置いた数は、pc が指せば命令として実行される。命令とデータの違いは、使われ方だけ
:::

## 確認問題 {#quiz}

機械語を自分の手で読み、組み立てます。レジスタの番号は本文の表を見てください。最初の 2 問と最後の問題では、あなたが書いた 1 つ目の命令（0 番地のワード）を、採点用のプログラムが読んで 16 進数で表示し、その表示を比べます。

:::quiz 機械語を読む
機械語 `0x40B50633` が表す命令を、アセンブリで 1 行書いてください。コンソールには、あなたが書いた命令の機械語が 16 進数で表示されます。

```asm starter
# ここに 1 行で書く
```

```asm answer
    sub  a2, a0, a1
```

```asm given
main:
    lw   a0, 0(zero)
    li   a7, 34
    ecall
    ret
```

:::hint
下の 7 ビットは `0110011` なので R 形式です。7・5・5・3・5・7 ビットに区切ります。funct7 が `0100000` の命令は何でしたか。
:::
:::

:::quiz 機械語を組み立てる
`addi s0, sp, -16` の機械語を手で組み立て、`.word` で 1 行書いてください（`s0` は x8、`sp` は x2）。コンソールには、あなたが書いたワードが 16 進数で表示されます。

```asm starter
    .word 0x00000000     # ここを書き換える
```

```asm answer
    .word 0xFF010413
```

```asm given
main:
    lw   a0, 0(zero)
    li   a7, 34
    ecall
    ret
```

:::hint
I 形式です。-16 を 12 ビットの 2 の補数にすると `111111110000` です。その後ろに rs1（5 ビット）、funct3（`000`）、rd（5 ビット）、opcode（`0010011`）を続けます。
:::
:::

:::quiz li を使わずに大きな数を作る
`li` を使わずに、`lui` と `addi` で `a0` に `0x00ABCFFF` を入れてください。判定は `a0` の値で行います。

```asm starter
    lui  a0, 0
    addi a0, a0, 0
```

```asm answer regs="a0"
    lui  a0, 0xABD
    addi a0, a0, -1
```

:::hint
下位 12 ビットは `0xFFF` で、`addi` にとっては -1 です。上位はそのぶんを見込んで決めます。
:::
:::

:::quiz メモリに書く命令を読む
機械語 `0x0062A423` が表す命令を、アセンブリで 1 行書いてください。コンソールには、あなたが書いた命令の機械語が 16 進数で表示されます。

```asm starter
# ここに 1 行で書く
```

```asm answer
    sw   t1, 8(t0)
```

```asm given
main:
    lw   a0, 0(zero)
    li   a7, 34
    ecall
    ret
```

:::hint
下の 7 ビットは `0100011` で、S 形式です。即値は上の 7 ビットと、rd の位置の 5 ビットに分かれています。funct3 の `010` はワードです。
:::
:::
