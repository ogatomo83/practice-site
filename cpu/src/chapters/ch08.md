## メモリは番号の付いた箱の列 {#boxes}

第 7 章では、1 ビットを覚える回路（フリップフロップ）を作り、それを並べて数を覚える**レジスタ**にしました。同じ「覚える部品」をもっと大量に並べたものが**メモリ**です。

メモリの作りは単純です。**1 バイト（8 ビット）が入る箱**が 1 列に並んでいて、箱には 0 から順に番号が付いています。この番号を**番地**または**アドレス**と呼びます。

```fig layout メモリは 1 バイトの箱の列。箱には 0 から順に番地が付いている。番地は 16 進数で書くことが多い
{
  unit: 30,
  rows: [
    { label: '番地', cells: [
      { t: '0x8000', w: 2.4, kind: 'empty' }, { t: '0x8001', w: 2.4, kind: 'empty' }, { t: '0x8002', w: 2.4, kind: 'empty' },
      { t: '0x8003', w: 2.4, kind: 'empty' }, { t: '0x8004', w: 2.4, kind: 'empty' }, { t: '0x8005', w: 2.4, kind: 'empty' }, { t: '…', w: 1.4, kind: 'empty' },
    ] },
    { label: '中身', cells: [
      { t: '65', w: 2.4, kind: 'accent' }, { t: '0', w: 2.4 }, { t: '200', w: 2.4 },
      { t: '7', w: 2.4 }, { t: '0', w: 2.4 }, { t: '255', w: 2.4 }, { t: '…', w: 1.4, kind: 'empty' },
    ], note: '1 箱 = 1 バイト（0〜255）' },
  ],
}
```

メモリにできることは 2 つだけです。

- **書く**（ストア）：番地を指定して、その箱に数を入れる
- **読む**（ロード）：番地を指定して、その箱の中身を取り出す

実際にやってみます。この章のプログラムは**アセンブリ**（CPU の命令を 1 行に 1 つ書いたもの）で書きます。命令のくわしい説明は第 10 章からですが、この章で使うのは次の数個だけです。

| 命令 | 意味 |
| --- | --- |
| `li t0, 数` | レジスタ `t0` に数を入れる。`t0` `t1` `a0` などは CPU の中の作業用の置き場（レジスタ） |
| `sb t1, 0(t0)` | `t0` に入っている番地の箱に、`t1` の値を **1 バイト**書く（store byte） |
| `lbu a0, 0(t0)` | `t0` に入っている番地の箱を **1 バイト**読んで `a0` に入れる（load byte unsigned） |
| `li a7, 1` と `ecall` | `a0` の値を 10 進数でコンソールに表示する。`a7` を 34 にすると 16 進数で表示する |

`0(t0)` は「`t0` の番地から 0 個先」という意味です。`1(t0)` なら 1 つ隣の箱になります。

```asm run title="0x8000 番地の箱に 65 を書いて、読み戻す" regs="t0,t1,a0" mem="0x8000,8"
    li   t0, 0x8000      # t0 ← 番地 0x8000
    li   t1, 65          # t1 ← 入れたい数
    sb   t1, 0(t0)       # 0x8000 番地の箱に 65 を書く
    lbu  a0, 0(t0)       # 同じ箱を読んで a0 に入れる
    li   a7, 1           # a0 を 10 進数で表示
    ecall
```

`65` と表示されます。書いた数が、同じ番地から読めました。出力のメモリの欄で、0x8000 番地のバイトが `41`（65 の 16 進数）になっていることも確かめてください。

隣の箱は別の箱です。`sb t1, 0(t0)` の後ろに、`li t1, 20` と `sb t1, 1(t0)` の 2 行を足してみてください。メモリの欄の 0x8001 番地が `14`（20 の 16 進数）になり、0x8000 番地の `41` はそのまま残ります。

:::note 電源を入れた直後の箱の中身
このサイトの CPU では、プログラムを実行するたびに新しい機械が用意され、何も書いていない箱はすべて 0 です。本物の機械では、電源を入れた直後のメモリの中身は決まっていません。
:::

## 1 つの箱には 255 までしか入らない {#byte}

箱は 1 バイト、つまり 8 ビットです。8 ビットで表せるのは 0 から 255 までの 256 通りでした（第 2 章）。では、箱に 300 を書こうとするとどうなるでしょうか。

```asm run title="1 バイトの箱に 300 を書く" regs="t1,a0"
    li   t0, 0x8000
    li   t1, 300         # 300 = 0x12C（9 ビット必要）
    sb   t1, 0(t0)       # 下位 8 ビットだけが書かれる
    lbu  a0, 0(t0)
    li   a7, 1
    ecall
```

表示は `44` です。300 は 16 進数で `0x12C` で、`sb` はその下位 8 ビットの `0x2C`（= 44）だけを箱に書きます。あふれた上の桁は捨てられます。

これでは大きな数を覚えられません。そこで、**隣り合う箱をいくつかまとめて、1 つの数として使います**。

| 名前 | 大きさ | 表せる範囲（符号なし） | 書く命令 | 読む命令 |
| --- | --- | --- | --- | --- |
| バイト | 1 バイト（8 ビット） | 0〜255 | `sb` | `lb` / `lbu` |
| ハーフワード | 2 バイト（16 ビット） | 0〜65,535 | `sh` | `lh` / `lhu` |
| ワード | 4 バイト（32 ビット） | 0〜4,294,967,295 | `sw` | `lw` |

**ワード**は、その CPU がいちどに扱う数の大きさです。このサイトの CPU は 32 ビットの RISC-V（RV32）なので、ワードは 4 バイトです。レジスタも 1 本が 32 ビットで、ワード 1 つがちょうど入ります。

```asm run title="ワード（4 バイト）なら 300 もそのまま入る" mem="0x8000,8"
    li   t0, 0x8000
    li   t1, 300
    sw   t1, 0(t0)       # 0x8000〜0x8003 の 4 つの箱に書く
    lw   a0, 0(t0)       # 4 つの箱をまとめて読む
    li   a7, 1
    ecall
```

今度は `300` と表示されます。メモリの欄を見ると、0x8000 番地が `2c`、0x8001 番地が `01` になっています。4 つの箱に分かれて入ったわけです。この入り方は、すぐ後でくわしく見ます。

### 読むときの符号：lb と lbu

1 バイトを読む命令には `lb` と `lbu` の 2 つがあります。箱の中身は 8 ビットですが、読み込む先のレジスタは 32 ビットです。空いた上の 24 ビットをどう埋めるかが違います。

- `lbu`（unsigned）：上を 0 で埋める。箱の中身を 0〜255 の数として読む
- `lb`：箱の最上位ビットを上に引き伸ばす（**符号拡張**、第 3 章）。箱の中身を -128〜127 の数として読む

```asm run title="同じ箱を lbu と lb で読む" regs="a1,a2"
    li   t0, 0x8000
    li   t1, 200         # 200 = 0b11001000（最上位ビットが 1）
    sb   t1, 0(t0)
    lbu  a1, 0(t0)       # 符号なし：200
    lb   a2, 0(t0)       # 符号付き：-56
    mv   a0, a2          # a2 を表示する（mv はレジスタの値の写し）
    li   a7, 1
    ecall
```

表示は `-56` です。箱の中身は同じ `0xC8` でも、`lbu` で読めば 200、`lb` で読めば -56 になります。文字やピクセルのような「ただのバイト」を読むときは `lbu` を使う、と覚えておくと安全です。ハーフワードの `lh` と `lhu` も同じ関係です。

## 4 バイトはどの順に入るか：リトルエンディアン {#endian}

ワードは 4 つの箱にまたがります。では、32 ビットの数の**どの部分が、どの番地の箱に入る**のでしょうか。`0x12345678` を書いて、1 バイトずつ読んで確かめます。16 進数の 2 桁が 1 バイトなので、この数は `12` `34` `56` `78` の 4 バイトです。

```asm run title="sw で書いたワードを、lbu で 1 バイトずつ読む" mem="0x8000,8"
    li   t0, 0x8000
    li   t1, 0x12345678
    sw   t1, 0(t0)       # ワードを書く

    lbu  a0, 0(t0)       # いちばん小さい番地のバイト
    li   a7, 34          # a0 を 16 進数で表示
    ecall
    li   a0, '\n'        # 改行
    li   a7, 11          # a0 の文字を表示
    ecall
    lbu  a0, 3(t0)       # いちばん大きい番地のバイト
    li   a7, 34
    ecall
```

出力は次のとおりです。

```console
0x00000078
0x00000012
```

いちばん小さい番地（0x8000）に入っていたのは、数の**いちばん下の桁**の `78` でした。いちばん上の桁の `12` は、いちばん大きい番地（0x8003）にあります。

```fig layout 0x12345678 を 0x8000 番地に書いたときの並び。リトルエンディアンは下の桁（小さい方の端）から先に置く。ビッグエンディアンは上の桁から置く
{
  unit: 30,
  rows: [
    { label: '番地', cells: [
      { t: '0x8000', w: 2.6, kind: 'empty' }, { t: '0x8001', w: 2.6, kind: 'empty' }, { t: '0x8002', w: 2.6, kind: 'empty' }, { t: '0x8003', w: 2.6, kind: 'empty' },
    ] },
    { label: 'リトルエンディアン', cells: [
      { t: '78', w: 2.6, kind: 'accent' }, { t: '56', w: 2.6 }, { t: '34', w: 2.6 }, { t: '12', w: 2.6, kind: 'stack' },
    ], note: 'RISC-V、x86、ARM（ふつうの設定）' },
    { label: 'ビッグエンディアン', cells: [
      { t: '12', w: 2.6, kind: 'stack' }, { t: '34', w: 2.6 }, { t: '56', w: 2.6 }, { t: '78', w: 2.6, kind: 'accent' },
    ], note: 'ネットワークの通信の決まりなど' },
  ],
}
```

下の桁のバイトを小さい番地に置くこの並べ方を、**リトルエンディアン**（little endian）と呼びます。RISC-V はリトルエンディアンです。逆に、上の桁から置く方式が**ビッグエンディアン**です。

逆向きにも確かめます。4 つの箱に 1 バイトずつ書いてから、ワードとして読みます。

```asm run title="1 バイトずつ書いて、ワードとして読む" mem="0x8000,8"
    li   t0, 0x8000
    li   t1, 0xEF
    sb   t1, 0(t0)       # 0x8000 ← EF（いちばん下の桁）
    li   t1, 0xBE
    sb   t1, 1(t0)       # 0x8001 ← BE
    li   t1, 0xAD
    sb   t1, 2(t0)       # 0x8002 ← AD
    li   t1, 0xDE
    sb   t1, 3(t0)       # 0x8003 ← DE（いちばん上の桁）
    lw   a0, 0(t0)
    li   a7, 34
    ecall
```

`0xdeadbeef` と表示されます。メモリの欄には `ef be ad de` と、目で読む向きとは逆に並んでいます。メモリの中身を 16 進数で眺めるときは、「ワードは右から左に読む」と覚えておきましょう。

:::tip リトルエンディアンの良いところ
小さな数をワードとして書くと、その数は先頭の箱に入り、残りの箱は 0 になります。だから、同じ番地を `lw` で読んでも `lbu` で読んでも同じ数が得られます。次の例で確かめます。
:::

```asm run title="小さな数は、どの幅で読んでも同じ番地から読める" regs="a1,a2,a3"
    li   t0, 0x8000
    li   t1, 5
    sw   t1, 0(t0)       # ワードとして 5 を書く
    lw   a1, 0(t0)       # 4 バイトで読む
    lhu  a2, 0(t0)       # 2 バイトで読む
    lbu  a3, 0(t0)       # 1 バイトで読む
```

`a1` `a2` `a3` はどれも 5 です。

:::hist エンディアンという名前
「エンディアン」は、『ガリバー旅行記』に出てくる、ゆで卵を大きい方の端（big end）から割るか、小さい方の端（little end）から割るかで争う人々の話から取られました。1980 年に Danny Cohen が、バイトの並び順をめぐる論争をこの話にたとえた文章を書き、名前として定着しました。どちらが正しいということはなく、決めて、そろえることが大事です。
:::

## ワードは 4 の倍数の番地に置く {#align}

ワードは 4 つの箱を使います。では、ワードを置く先頭の番地はどこでもよいのでしょうか。0x8001 番地から `lw` で読んでみます。

```asm run error title="4 の倍数でない番地から lw で読む"
    li   t0, 0x8001
    lw   a0, 0(t0)       # 0x8001〜0x8004 を読もうとする
```

エラーで止まります。「番地 0x00008001 は 4 の倍数ではないので lw で読めません」という内容です。

このサイトの CPU では、`lw` と `sw` の番地は **4 の倍数**、`lh` と `sh` の番地は **2 の倍数**でなければなりません。大きさの倍数の番地にそろえることを**整列**（アラインメント）と呼びます。1 バイトの `lb` `lbu` `sb` は、どの番地でも使えます。

| 命令 | 使える番地 | 例 |
| --- | --- | --- |
| `lb` `lbu` `sb` | どこでも | 0x8000, 0x8001, 0x8002, … |
| `lh` `lhu` `sh` | 2 の倍数 | 0x8000, 0x8002, 0x8004, … |
| `lw` `sw` | 4 の倍数 | 0x8000, 0x8004, 0x8008, … |

:::deep なぜ整列させるのか
メモリの回路は、4 バイトをひとまとまりにして読み書きするように作るのがふつうです。ワードがまとまりの境目をまたぐと、2 回に分けて読んでつなぎ合わせる必要があり、回路が複雑で遅くなります。RISC-V の仕様は、整列していない番地の読み書きを「対応してもよいし、例外にしてもよい」としていて、どちらにするかは機械ごとに決まります。このサイトの CPU は例外にしています。例外については第 19 章で扱います。
:::

## データを並べて置く：.data {#data}

ここまでは、番地 `0x8000` を自分で数として書いてきました。プログラムが大きくなると、どの番地に何を置いたかを覚えておくのが大変です。そこで、**データの置き場所に名前を付け、最初から中身を入れておく**書き方を使います。

```asm run title=".data にワードを置き、ラベルで読む" mem="0x8000,16"
.data                    # ここからはデータ
price:  .word 1200       # ワードを 1 つ置き、price という名前を付ける
count:  .word 3

.text                    # ここからは命令
    la   t0, price       # t0 ← price の番地
    lw   a0, 0(t0)       # price の中身を読む
    li   a7, 1
    ecall
```

`1200` と表示されます。新しく出てきたものを順に見ます。

- `.data` と `.text`：ピリオドで始まる行は命令ではなく、アセンブラ（アセンブリを機械語に直すプログラム）への指示です。**ディレクティブ**と呼びます。`.data` の後ろはデータ、`.text` の後ろは命令として扱われます
- `price:`：**ラベル**。その場所の番地に付けた名前です
- `.word 1200`：ワードを 1 つ置く。`.word 1, 2, 3` のようにコンマで並べると、続けて置かれます
- `la t0, price`：ラベルの番地を `t0` に入れる（load address）

ラベルの正体はただの番地です。番地そのものを表示して確かめます。

```asm run title="ラベルは番地の別名"
.data
price:  .word 1200
count:  .word 3

.text
    la   a0, price
    li   a7, 34          # 16 進数で表示
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    la   a0, count
    li   a7, 34
    ecall
```

```console
0x00008000
0x00008004
```

このサイトの CPU では、`.data` の中身は 0x8000 番地から順に置かれます。`price` は 4 バイトを使うので、次の `count` は 0x8004 番地です。

### .byte と .half

1 バイトや 2 バイトのデータを置くディレクティブもあります。

| ディレクティブ | 置くもの |
| --- | --- |
| `.byte 1, 2, 3` | 1 バイトずつ |
| `.half 1000` | ハーフワード（2 バイト） |
| `.word 100000` | ワード（4 バイト） |
| `.asciz "abc"` | 文字列と、終わりの印の 0 |
| `.space 16` | 0 が入った箱を 16 バイトぶん空ける |

```asm run title=".byte と .word を混ぜて置く" mem="0x8000,16"
.data
a:  .byte 1, 2, 3        # 0x8000, 0x8001, 0x8002
b:  .word 0x11223344     # 次の 4 の倍数の番地から
c:  .half 0x5566

.text
    la   a0, b           # b の番地を表示する
    li   a7, 34
    ecall
```

`b` の番地は `0x00008004` です。`a` が 3 バイトを使ったので、続きは 0x8003 番地のはずですが、`.word` は 4 の倍数の番地にしか置けません。このサイトのアセンブラは、`.word` の前に自動ですき間を空けて 0x8004 番地にそろえます（`.half` は 2 の倍数にそろえます）。メモリの欄は次のようになります。

```text
0x8000: 01 02 03 00 44 33 22 11 66 55 00 00 00 00 00 00
        a─────┘  ↑  b────────┘ c───┘
              すき間
```

`b` の中身が `44 33 22 11` と逆順に見えるのは、リトルエンディアンだからです。

### 文字列は文字コードの列

文字は、文字コードという数で表すのでした（第 2 章）。文字列は、その数を小さい番地から順に 1 バイトずつ並べたものです。

```asm run title="文字列を置いて表示する" mem="0x8000,8"
.data
msg:  .asciz "Hi!\n"     # 'H' 'i' '!' 改行、最後に 0

.text
    la   a0, msg         # a0 ← 文字列の先頭の番地
    li   a7, 4           # a0 の番地から始まる文字列を表示
    ecall
```

メモリの欄は `48 69 21 0a 00` です。`0x48` が `H`、`0x69` が `i`、`0x21` が `!`、`0x0a` が改行です。最後の `00` は `.asciz` が自動で足した**終わりの印**で、`ecall` の 4 番はこの 0 に出会うまで文字を表示し続けます。

文字列の中身も箱なので、1 文字だけ読んだり、書き換えたりできます。

```asm run title="文字列の 1 文字目を書き換える"
.data
msg:  .asciz "cat\n"

.text
    la   t0, msg
    li   t1, 'b'         # 'b' の文字コード（98）
    sb   t1, 0(t0)       # 1 文字目の箱に上書き
    mv   a0, t0
    li   a7, 4
    ecall
```

`bat` と表示されます。`0(t0)` を `2(t0)` に、`'b'` を `'r'` に変えると `car` になります。

:::note 文字列にエンディアンは関係ない
文字列は 1 バイトの列なので、いつも先頭の文字が小さい番地に来ます。並びが逆になるのは、2 バイト以上をまとめて 1 つの数として扱うときだけです。日本語の文字は UTF-8 で 1 文字が 3 バイトになりますが、これも「3 つのバイトを順に並べる」決まりなので、エンディアンの影響は受けません。
:::

## このサイトの CPU のメモリマップ {#map}

番地のどこに何があるかをまとめた地図を、**メモリマップ**と呼びます。メモリマップは CPU の命令セットではなく、機械ごとの決まりです。**このサイトの CPU** では次のようになっています。

```fig layout このサイトの CPU のメモリマップ。番地は 32 ビットで表すが、中身があるのはこの 3 か所だけ

      { t: '.text（命令）0x0000 から', w: 7.5, kind: 'accent' }, { t: '.data 0x8000 から', w: 5.5, kind: 'static' },
      { t: '空き', w: 2.5, kind: 'empty' }, { t: '← スタック', w: 4, kind: 'stack' },
    ], note: 'RAM 64 KiB' },
    { label: '0x10000〜0x103FF', cells: [
      { t: '画面 32 × 32（1 バイト = 1 ピクセル）', w: 12, kind: 'heap' },
    ], note: '1,024 バイト' },
    { label: '0x20000〜0x20014', cells: [
      { t: 'コンソール', w: 4 }, { t: 'キー', w: 2.5 }, { t: '乱数', w: 2.5 }, { t: '命令数', w: 3 }, { t: 'フレーム', w: 3.5 },
    ], note: '入出力' },
  ],
}
```

- **RAM**（0x0000〜0xFFFF、64 KiB）：自由に読み書きできるメモリ。前半の 0x0000 からプログラムの命令（`.text`）が、後半の 0x8000 から `.data` が置かれます
- **スタック**：RAM の終わり（0x10000）から、小さい番地に向かって使っていく作業場所。その先頭を指すレジスタ `sp` の最初の値は 0x10000 です。第 13 章で使います
- **画面**（0x10000〜0x103FF）：32 × 32 個の点。この番地に書くと画面に色が付きます
- **入出力**（0x20000〜）：コンソールやキーボードなど。第 14 章でくわしく扱います

命令もメモリの中に置かれている、という点に注目してください。命令の正体は次の第 9 章の主題です。ここでは、命令に付けたラベルの番地、データのラベルの番地、`sp` の値を表示して、地図のとおりになっているかを確かめます。

```asm run title="命令・データ・スタックの番地を表示する"
.data
value:  .word 7

.text
main:
    nop                  # 何もしない命令（場所を取るだけ）
here:
    la   a0, here        # 命令に付けたラベルの番地
    li   a7, 34
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    la   a0, value       # データのラベルの番地
    li   a7, 34
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    mv   a0, sp          # スタックの先頭を指すレジスタ
    li   a7, 34
    ecall
```

```console
0x00000004
0x00008000
0x00010000
```

`here` は 2 つ目の命令なので 4 番地です。命令は 1 つが 4 バイトで、0 番地から順に並んでいます。

地図にない番地を読み書きすると、エラーになります。

```asm run error title="何もない番地を読む"
    li   t0, 0x30000     # RAM でも画面でも入出力でもない
    lw   a0, 0(t0)
```

「番地 0x00030000 にはメモリも入出力もない」と言われます。番地そのものは 32 ビットで 0 から約 43 億まで書けますが、実際に箱があるのはその一部だけです。

:::note 本物の機械のメモリマップ
パソコンやマイコンにも、それぞれのメモリマップがあります。RAM が何番地から始まり、どの番地が画面や通信の装置につながっているかは、機械の説明書に書かれています。OS のある機械では、プログラムから見える番地（仮想アドレス）と本当の番地を OS が対応づけるので、話がもう 1 段深くなります。第 19 章で触れます。
:::

## 番地に書くだけで点が打てる {#screen}

メモリマップの 0x10000 番地から先は、RAM ではなく**画面**につながっています。CPU から見ると、やることはメモリと同じで「番地に 1 バイト書く」だけです。書いた値が色番号になり、その場所の点（ピクセル）の色が変わります。

```asm run title="画面の左上に赤い点を打つ"
    li   t0, 0x10000     # 画面の先頭の番地 ＝ 左上の点
    li   t1, 2           # 色番号 2 ＝ 赤
    sb   t1, 0(t0)
```

出力に 32 × 32 の画面が現れ、左上が 1 点だけ赤くなります。

画面の点は、左上から右へ 32 個、次の行の左端からまた右へ、という順に番地が割り当てられています。横の位置を x（0〜31）、縦の位置を y（0〜31）とすると、番地は次の式で決まります。

> 番地 ＝ 0x10000 ＋ y × 32 ＋ x

```fig layout 画面の点と番地の対応。1 行は 32 バイト。右端の次は、次の行の左端になる
{

  rows: [
    { label: 'y = 0', cells: [
      { t: '+0', w: 2, kind: 'accent' }, { t: '+1', w: 2 }, { t: '+2', w: 2 }, { t: '…', w: 2, kind: 'empty' }, { t: '+30', w: 2 }, { t: '+31', w: 2 },
    ], note: '0x10000 から' },
    { label: 'y = 1', cells: [
      { t: '+32', w: 2 }, { t: '+33', w: 2, kind: 'heap' }, { t: '+34', w: 2 }, { t: '…', w: 2, kind: 'empty' }, { t: '+62', w: 2 }, { t: '+63', w: 2 },
    ], note: '(1, 1) は 1 × 32 + 1 = +33' },
    { label: 'y = 2', cells: [

    ] },
    { label: 'y = 31', cells: [
      { t: '+992', w: 2 }, { t: '+993', w: 2 }, { t: '+994', w: 2 }, { t: '…', w: 2, kind: 'empty' }, { t: '+1022', w: 2 }, { t: '+1023', w: 2, kind: 'stack' },
```

色番号は 0 から 15 までの 16 色です。

| 番号 | 色 | 番号 | 色 | 番号 | 色 | 番号 | 色 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 0 | 黒 | 4 | 青 | 8 | 橙 | 12 | 濃い灰 |
| 1 | 白 | 5 | 黄 | 9 | 紫 | 13 | 濃い緑 |
| 2 | 赤 | 6 | 水色 | 10 | 茶 | 14 | 紺 |
| 3 | 緑 | 7 | 桃 | 11 | 灰 | 15 | 肌色 |

式を使って、好きな場所に点を打ちます。(10, 4) なら 4 × 32 + 10 = 138 です。

```asm run title="(10, 4) に黄色、(31, 31) に白の点"
    li   t0, 0x10000
    li   t1, 5           # 黄
    sb   t1, 138(t0)     # 4 × 32 + 10 = 138
    li   t1, 1           # 白
    sb   t1, 1023(t0)    # 31 × 32 + 31 = 1023（右下の角）
```

数を書き換えて、点を動かしてみてください。番地を 1 増やすと右へ、32 増やすと下へ動きます。

### sw で書くと 4 点がいちどに付く

画面も 1 バイトの箱の列なので、`sw` でワードを書けば 4 つの箱、つまり横に並んだ 4 点がいちどに変わります。どの点がどの色になるかは、リトルエンディアンの決まりのとおりです。

```asm run title="ワードを 1 つ書くと、4 点が並ぶ"
    li   t0, 0x10000
    li   t1, 0x05040302  # 上の桁から 05 04 03 02
    sw   t1, 0(t0)
```

左から、赤（2）、緑（3）、青（4）、黄（5）の順に並びます。ワードのいちばん下の桁の `02` が、いちばん小さい番地、つまり左端に入りました。エンディアンが目で見える例です。

これを縦に重ねると、小さな絵になります。番地を 32 ずつ進めれば 1 行下です。

```asm run title="sw を 4 回使って、4 × 4 の旗を描く"
    li   t0, 0x10000
    li   t1, 0x02020101  # 左 2 点が白、右 2 点が赤
    sw   t1, 68(t0)      # y = 2、x = 4〜7（2 × 32 + 4 = 68）
    sw   t1, 100(t0)     # y = 3
    li   t1, 0x04040505  # 左 2 点が黄、右 2 点が青
    sw   t1, 132(t0)     # y = 4
    sw   t1, 164(t0)     # y = 5
```

1 点ずつ命令を書くのは大変です。第 11 章でループを学ぶと、数行の命令で画面全体に模様を描けるようになります。

:::deep コンソールも番地でできている
入出力の 0x20000 番地は、コンソールにつながっています。ここに 1 バイト書くと、その文字が表示されます。`li t0, 0x20000`、`li t1, 'A'`、`sb t1, 0(t0)` の 3 行で `A` が出ます。このように、装置を番地に割り当ててメモリと同じ命令で扱う方式を**メモリマップド I/O** と呼びます。`ecall` との違いも含めて、第 14 章で扱います。
:::

```asm run title="0x20000 番地に書くと文字が出る"
    li   t0, 0x20000     # コンソールの番地
    li   t1, 'O'
    sb   t1, 0(t0)
    li   t1, 'K'
    sb   t1, 0(t0)       # 同じ番地に書くたびに 1 文字出る
```

:::try やってみよう
下のプログラムは、`.data` に置いた 4 バイトをワードとして読み、16 進数で表示します。

1. 実行する前に、何と表示されるかを予想する
2. `lw` を `lhu` に変えると、何と表示されるか
3. `.byte` の 4 つの数を並べ替えて、`0x00c0ffee` と表示させる
:::

```asm run title="練習用：4 バイトをワードとして読む" mem="0x8000,8"
.data
bytes:  .byte 0x0D, 0xF0, 0xAD, 0x0B

.text
    la   t0, bytes
    lw   a0, 0(t0)
    li   a7, 34
    ecall
```

:::key この章のまとめ
- **メモリ**は 1 バイトの箱の列。箱には 0 から順に**番地（アドレス）**が付いていて、番地を指定して読み書きする
- 1 バイトは 0〜255。大きな数は、隣り合う箱をまとめて使う。**ハーフワード**は 2 バイト、**ワード**は 4 バイト（RV32 の場合）
- 書く命令は `sb` `sh` `sw`、読む命令は `lb` `lbu` `lh` `lhu` `lw`。`u` の付く命令は上を 0 で埋め、付かない命令は符号拡張する
- RISC-V は**リトルエンディアン**。ワードの下の桁のバイトが、小さい番地に入る
- このサイトの CPU では、`lw` と `sw` の番地は 4 の倍数、`lh` と `sh` は 2 の倍数にそろえる（整列）
- `.data` に `.word` `.half` `.byte` `.asciz` でデータを置き、**ラベル**で番地に名前を付ける。`la` でラベルの番地をレジスタに入れる
- **メモリマップ**は番地の地図。このサイトの CPU では、0x0000 から命令、0x8000 からデータ、0x10000 から画面、0x20000 から入出力
- 画面の (x, y) の番地は `0x10000 + y × 32 + x`。そこに色番号を 1 バイト書くと点が付く
:::

## 確認問題 {#quiz}

番地、バイトの並び、画面の番地の計算を、自分でプログラムを書いて確かめます。初期値として入っているプログラムを書き足す形で進めてください。

:::quiz いちばん大きい番地のバイト
`.data` の先頭に、ワード `0xCAFEF00D` が置いてあります。このワードが使う 4 バイトのうち、**いちばん大きい番地にあるバイト**を符号なしで読み、`ecall` の 34 番で 16 進数としてコンソールに表示してください。

```asm starter
.data
v:  .word 0xCAFEF00D

.text
    la   t0, v
    # ここに書く
```

```asm answer
.data
v:  .word 0xCAFEF00D

.text
    la   t0, v
    lbu  a0, 3(t0)
    li   a7, 34
    ecall
```

:::hint
リトルエンディアンでは、上の桁のバイトほど大きい番地に入ります。符号なしで 1 バイト読む命令は `lbu` です。
:::
:::

:::quiz 2 つの点を打つ
画面の (5, 3) に赤（色番号 2）の点を、(3, 5) に緑（色番号 3）の点を打ってください。(x, y) の x は横、y は縦の位置です。判定は画面の内容で行います。

```asm starter
    li   t0, 0x10000
    # ここに書く
```

```asm answer screen
    li   t0, 0x10000
    li   t1, 2
    sb   t1, 101(t0)     # 3 × 32 + 5
    li   t1, 3
    sb   t1, 163(t0)     # 5 × 32 + 3
```

:::hint
番地は `0x10000 + y × 32 + x` です。(5, 3) は x = 5、y = 3 なので、3 × 32 + 5 を計算します。
:::
:::

:::quiz 1 バイトずつ書いてワードを作る
0x8000 番地から 0x8003 番地までの 4 つの箱に、`sb` で 1 バイトずつ書き、その後に 0x8000 番地を `lw` で読んで `a0` に入れてください。`a0` が `0x0A0B0C0D` になるようにします。判定は `a0` の値と、0x8000 番地からの 4 バイトで行います。

```asm starter
    li   t0, 0x8000
    # ここに書く
```

```asm answer regs="a0" mem="0x8000,4"
    li   t0, 0x8000
    li   t1, 0x0D
    sb   t1, 0(t0)
    li   t1, 0x0C
    sb   t1, 1(t0)
    li   t1, 0x0B
    sb   t1, 2(t0)
    li   t1, 0x0A
    sb   t1, 3(t0)
    lw   a0, 0(t0)
```

:::hint
いちばん下の桁の `0D` を、いちばん小さい番地に書きます。
:::
:::

:::quiz 文字列と、その中の 1 文字
`.data` に文字列 `CPU` と改行を置き、`ecall` の 4 番でコンソールに表示してください。続けて、その文字列の **2 文字目**（`P`）の文字コードを、`ecall` の 1 番で 10 進数として表示してください。出力は 2 行になります（1 行目が `CPU`、2 行目が数）。

```asm starter
.data
msg:  .asciz "CPU\n"

.text
    la   t0, msg
    # ここに書く
```

```asm answer
.data
msg:  .asciz "CPU\n"

.text
    la   t0, msg
    mv   a0, t0
    li   a7, 4
    ecall
    lbu  a0, 1(t0)
    li   a7, 1
    ecall
```

:::hint
1 文字目は `0(t0)`、2 文字目は `1(t0)` の箱にあります。`ecall` を呼ぶと `a0` を使うので、文字列の番地は `t0` に残しておきます。
:::
:::
