## 選ぶ回路：マルチプレクサ {#mux}

前の章で、足し算も引き算もする回路ができました。CPU は、ほかにも AND や OR など、いろいろな計算をします。そこで必要になるのが、「いくつかある結果のうち、**どれを使うかを選ぶ**」回路です。

いちばん小さな「選ぶ回路」を考えます。入力は a と b の 2 本と、どちらを選ぶかを決める s（select、選択）の 1 本です。s が 0 なら a、s が 1 なら b を、そのまま出力 y に出します。これを**マルチプレクサ**（multiplexer）と呼びます。**MUX**（マックス）と略します。

線路の切り替えポイントを思い浮かべてください。2 本の線路のどちらを先へつなぐかを、レバー 1 本で決めます。

```fig circuit 2 入力のマルチプレクサ。AND は「通すか、止めるか」を決める門として働く。s が 0 なら上の AND が、1 なら下の AND が開く
{
  parts: [
    { id: 'a', type: 'in', x: 0, y: 1.5 }, { id: 's', type: 'in', x: 0, y: 4 }, { id: 'b', type: 'in', x: 0, y: 6.5 },
    { id: 'inv', type: 'not', x: 3, y: 2.5 }, { id: 'g1', type: 'and', x: 7, y: 2 }, { id: 'g2', type: 'and', x: 7, y: 6 },
    { id: 'o', type: 'or', x: 11.5, y: 4 }, { id: 'y', type: 'out', x: 15.5, y: 4 },
  ],
  wires: ['a -> g1.a', { from: 's', to: 'inv', mid: 2 }, 'inv -> g1.b', { from: 's', to: 'g2.a', mid: 2 }, 'b -> g2.b', { from: 'g1', to: 'o.a', mid: 10.5 }, { from: 'g2', to: 'o.b', mid: 10.5 }, 'o -> y'],
  steps: [
    { title: 's = 0（a を選ぶ）', hl: ['a', 'inv', 'g1', 'o'], vals: { s: 0 }, say: 'NOT の出力が 1 になり、上の AND が a をそのまま通します。下の AND は s = 0 を受けて、b が何であっても 0 を出します。' },
    { title: 's = 1（b を選ぶ）', hl: ['s', 'b', 'g2', 'o'], vals: { s: 1 }, say: 'こんどは下の AND が b をそのまま通し、上の AND は 0 を出します。OR は、通ってきたほうをそのまま出力します。' },
  ],
}
```

仕組みの中心は、AND の使い方です。`x and 1` は x のまま、`x and 0` はいつも 0 です。AND は、片方の入力で「通す / 止める」を切り替える**門**として使えます。2 つの門のうち、いつも片方だけが開くようにしておき、最後に OR でまとめます。

```logic run title="ゲートで作るマルチプレクサ"
in s, a, b
out y
y = (a and not s) or (b and s)
```

入力が 3 本なので 8 行です。上の 4 行（s = 0）では y が a の列と同じに、下の 4 行（s = 1）では y が b の列と同じになっています。

マルチプレクサはとてもよく使うので、この回路記述には `mux(s, a, b)` という書き方が用意されています。回路図では台形で描きます。

```logic run title="mux(s, a, b)"
in s, a, b
out y1, y2
y1 = (a and not s) or (b and s)
y2 = mux(s, a, b)        # s が 0 なら a、1 なら b
```

`y1` と `y2` は、8 行すべてで一致します。

:::note プログラムの if にあたるもの
`mux(s, a, b)` は、プログラムの「もし s なら b、そうでなければ a」にあたります。ただし、プログラムと違って、回路は**両方を計算してから選びます**。a を作る回路も b を作る回路も、いつも働いています。使わないほうの結果は、ただ捨てられます。
:::

## 数を選ぶ、4 つから選ぶ {#mux4}

### バスを選ぶ

1 ビットのマルチプレクサをビットの数だけ並べ、同じ s をつなげば、数を丸ごと選べます。

```logic run title="4 ビットの数を選ぶ"
in s, a[4], b[4]
out y[4]
y = mux(s, a, b)
test s=0, a=3, b=12
test s=1, a=3, b=12
```

表の下のゲートの数は「MUX 4」です。4 ビットなので、1 ビットのマルチプレクサを 4 個使っています。

### 4 つから 1 つを選ぶ

選ぶ相手が 4 つあるときは、s を 2 ビットにします。2 ビットあれば 00、01、10、11 の 4 通りを区別できます。4 入力のマルチプレクサは、2 入力のものを 3 個使って作れます。勝ち抜き戦の形です。

```fig circuit 2 入力のマルチプレクサ 3 個で作る、4 入力のマルチプレクサ。s[0] で 1 回戦（上の組と下の組）、s[1] で決勝を決める
{
  parts: [
    { id: 'd0', type: 'in', x: 1, y: 1.5 }, { id: 'd1', type: 'in', x: 1, y: 2.5 }, { id: 'd2', type: 'in', x: 1, y: 5.5 }, { id: 'd3', type: 'in', x: 1, y: 6.5 },
    { id: 'm0', type: 'mux', x: 4, y: 2 }, { id: 'm1', type: 'mux', x: 4, y: 6 }, { id: 'm2', type: 'mux', x: 10, y: 4 },
    { id: 's0', type: 'in', x: 1, y: 9, label: 's[0]' }, { id: 's1', type: 'in', x: 1, y: 10, label: 's[1]' }, { id: 'y', type: 'out', x: 14, y: 4 },
  ],
  wires: ['d0 -> m0.a', 'd1 -> m0.b', 'd2 -> m1.a', 'd3 -> m1.b', { from: 'm0', to: 'm2.a', mid: 8.5 }, { from: 'm1', to: 'm2.b', mid: 8.5 },
    's0 -> m1.s', { from: 's0', to: 'm0.s', via: [[3, 9], [3, 4]] }, 's1 -> m2.s', 'm2 -> y'],
  steps: [
    { title: 's = 00（d0）', hl: ['d0', 'm0', 'm2'], vals: { s0: 0, s1: 0 }, say: '1 回戦は、どちらの組も上（0 の側）が勝ちます。決勝も上が勝つので、d0 が出力されます。' },
    { title: 's = 10（d2）', hl: ['d2', 'm1', 'm2', 's1'], vals: { s0: 0, s1: 1 }, say: '1 回戦は同じく上が勝ち、d0 と d2 が残ります。決勝は s[1] = 1 なので下が勝ち、d2 が出力されます。' },
    { title: 's = 11（d3）', hl: ['d3', 'm1', 'm2', 's0', 's1'], vals: { s0: 1, s1: 1 }, say: '1 回戦は下（1 の側）が勝ち、d1 と d3 が残ります。決勝も下が勝って、d3 が出力されます。' },
  ],

```

```logic run title="4 入力のマルチプレクサ"
in s[2], d0, d1, d2, d3
out y
lo = mux(s[0], d0, d1)     # 1 回戦：d0 と d1
hi = mux(s[0], d2, d3)     # 1 回戦：d2 と d3
y  = mux(s[1], lo, hi)     # 決勝
test s=0, d0=1, d1=0, d2=0, d3=0
test s=1, d0=0, d1=1, d2=0, d3=0
test s=2, d0=0, d1=0, d2=1, d3=0
test s=3, d0=0, d1=0, d2=0, d3=1
test s=2, d0=1, d1=1, d2=0, d3=1
```

最初の 4 行では、s の番号の入力だけを 1 にしました。どの行でも y は 1 で、s の番号の入力が選ばれていることがわかります。最後の行は、選ばれる d2 だけが 0 なので、y は 0 です。

s が 2 ビットのときは、`mux(s, d0, d1, d2, d3)` と 1 行でも書けます。s の値の番目が選ばれます。同じ作り方を繰り返せば、s が 3 ビットで 8 入力、5 ビットで 32 入力のマルチプレクサになります。

## デコーダ：番号から 1 本を選ぶ {#decoder}

マルチプレクサと対になる部品が、**デコーダ**（decoder）です。デコーダは、番号（2 進数）を受け取って、何本もある出力のうち**その番号の 1 本だけ**を 1 にします。

2 ビットの番号なら、出力は 4 本です。

```fig circuit 2 ビットのデコーダ。4 個の AND が、それぞれ 00、01、10、11 の「番号の一致」を調べる
{
  parts: [
    { id: 'a1', type: 'in', x: 0, y: 1, label: 'a[1]' }, { id: 'a0', type: 'in', x: 0, y: 13, label: 'a[0]' },
    { id: 'n1', type: 'not', x: 3, y: 1 }, { id: 'n0', type: 'not', x: 3, y: 13 },
    { id: 'g0', type: 'and', x: 10, y: 3 }, { id: 'g1', type: 'and', x: 10, y: 5.5 }, { id: 'g2', type: 'and', x: 10, y: 8 }, { id: 'g3', type: 'and', x: 10, y: 10.5 },
    { id: 'y0', type: 'out', x: 14.5, y: 3, label: 'y[0]' }, { id: 'y1', type: 'out', x: 14.5, y: 5.5, label: 'y[1]' },
    { id: 'y2', type: 'out', x: 14.5, y: 8, label: 'y[2]' }, { id: 'y3', type: 'out', x: 14.5, y: 10.5, label: 'y[3]' },
  ],
  wires: [
    'a1 -> n1', 'a0 -> n0',
    { from: 'n1', to: 'g0.a', mid: 7 }, { from: 'n1', to: 'g1.a', mid: 7 },
    { from: 'a1', to: 'g2.a', mid: 1.5 }, { from: 'a1', to: 'g3.a', mid: 1.5 },
    { from: 'a0', to: 'g1.b', mid: 2.5 }, { from: 'a0', to: 'g3.b', mid: 2.5 },
    { from: 'n0', to: 'g0.b', mid: 8 }, { from: 'n0', to: 'g2.b', mid: 8 },
    'g0 -> y0', 'g1 -> y1', 'g2 -> y2', 'g3 -> y3',
  ],
  steps: [
    { title: 'a = 00', hl: ['n1', 'n0', 'g0'], vals: { a1: 0, a0: 0, y0: 1, y1: 0, y2: 0, y3: 0 }, say: '2 つの NOT がどちらも 1 を出します。両方を受けるいちばん上の AND だけが 1 になります。' },
    { title: 'a = 10', hl: ['a1', 'n0', 'g2'], vals: { a1: 1, a0: 0, y0: 0, y1: 0, y2: 1, y3: 0 }, say: 'a[1] そのものと、a[0] の NOT が 1 です。この 2 本を受ける 3 番目の AND だけが 1 になります。' },
    { title: 'a = 11', hl: ['a1', 'a0', 'g3'], vals: { a1: 1, a0: 1, y0: 0, y1: 0, y2: 0, y3: 1 }, say: 'a[1] と a[0] がどちらも 1 です。いちばん下の AND だけが 1 になります。' },
  ],
}
```

作り方は、第 4 章の「真理値表から回路を作る」と同じです。4 通りの番号のそれぞれを、AND 1 個で見分けます。

```logic run title="2 ビットのデコーダ"
in a[2]
out y[4]
y[0] = not a[1] and not a[0]     # 00 のとき
y[1] = not a[1] and a[0]         # 01 のとき
y[2] = a[1] and not a[0]         # 10 のとき
y[3] = a[1] and a[0]             # 11 のとき
```

「2 進で表示」を押すと、y が `0001`、`0010`、`0100`、`1000` と、1 がちょうど 1 個だけ立っているのが見えます。a が 0 なら y[0]、a が 3 なら y[3] です。

デコーダは、**番号で相手を指名する**ところに使われます。

- CPU には 32 本のレジスタがある。「5 番のレジスタに書き込む」という指示から、5 番だけに届く書き込みの合図を作る（第 16 章）
- メモリには番地がある。番地から、その 1 か所だけを選ぶ（第 8 章）

マルチプレクサが「たくさんの中から 1 つを**取り出す**」部品なら、デコーダは「たくさんの中の 1 つを**指す**」部品です。

## 比べる回路 {#compare}

次は、2 つの数を比べる回路です。結果は「はい」か「いいえ」なので、出力は 1 ビットです。

### 等しいかどうか

2 つの数が等しいのは、**すべての桁が同じ**ときです。1 ビットが同じかどうかは XNOR でわかりました（同じなら 1）。あとは、全部の桁の結果を AND でまとめます。

```fig circuit 4 ビットの「等しい」比較器。桁ごとに XNOR で「同じか」を調べ、4 入力の AND で「全部同じか」をまとめる
{
  parts: [
    ...[0, 1, 2, 3].flatMap((i) => [
      { id: 'a' + i, type: 'in', x: 0, y: 1 + i * 3, label: `a[${i}]` }, { id: 'b' + i, type: 'in', x: 0, y: 2 + i * 3, label: `b[${i}]` },
      { id: 'x' + i, type: 'xnor', x: 2, y: 1.5 + i * 3 },
    ]),
    { id: 'g', type: 'and', inputs: 4, x: 9, y: 6 }, { id: 'eq', type: 'out', x: 13.5, y: 6 },
  ],
  wires: [
    ...[0, 1, 2, 3].flatMap((i) => [`a${i} -> x${i}.a`, `b${i} -> x${i}.b`]),
    { from: 'x0', to: 'g.a', mid: 8 }, { from: 'x1', to: 'g.b', mid: 7 }, { from: 'x2', to: 'g.c', mid: 7 }, { from: 'x3', to: 'g.d', mid: 8 }, 'g -> eq',
  ],
}
```

```logic run title="等しいかどうか"
in a[4], b[4]
out eq
e = a xnor b                      # 桁ごとに「同じなら 1」
eq = and(e[0], e[1], e[2], e[3])  # 全部の桁が同じなら 1
test a=5, b=5
test a=5, b=4
test a=0, b=8
test a=15, b=15
```

5 と 4 は、2 進数では `0101` と `0100` で、1 ビットしか違いません。それでも eq は 0 になります。この回路記述では、同じことを `a == b` と書けます。

### どちらが小さいか

大小の比較は、前の章の最後に予告したとおり、**引き算**を使います。a − b を計算して、引けなかったら（答えが負になったら）a のほうが小さい、とわかります。

符号なしの数で考えます。4 ビットのままでは「負になった」ことがわからないので、上に 0 を 1 ビット足して 5 ビットで引き算をします。a が b より小さいと、いちばん上のビットが 1 になります。

```logic run title="a < b（符号なし）"
in a[4], b[4]
out lt, d[5]
d = {0, a} - {0, b}      # 5 ビットで引き算
lt = d[4]                # いちばん上のビットが 1 なら、a < b
test a=3, b=5
test a=5, b=3
test a=5, b=5
test a=15, b=1
```

3 − 5 は −2 で、5 ビットの 2 の補数では `11110`（表示は 30）です。いちばん上が 1 なので lt は 1 です。5 − 3 と 5 − 5 は負にならないので、lt は 0 です。lt は less than（より小さい）の略です。

### 符号付きの比較は少し違う

最後の行を見てください。15 と 1 では、もちろん 15 のほうが大きいので、lt は 0 です。ところが、同じビット `1111` を**符号付き**の数として読むと −1 でした（第 3 章）。−1 は 1 より小さいので、符号付きの比較なら答えは 1 のはずです。

**大小の比較は、符号付きと符号なしで答えが変わります。** 足し算と引き算は 1 つの回路で両方に使えましたが、比較は別々に作る必要があります。

符号付きの比較は、a − b の答えの符号を見ます。負なら a のほうが小さい、というわけです。ただし、引き算がオーバーフローしたときは符号が逆になっているので、そのときだけひっくり返します。

```logic run title="a < b（符号付き）"
in a[4], b[4]
out lt
d = a - b
v = (a[3] xor b[3]) and (a[3] xor d[3])   # 引き算のオーバーフロー
lt = d[3] xor v                           # 答えの符号。あふれたときは逆にする
test a=3, b=5
test a=15, b=1
test a=7, b=8
test a=8, b=7
test a=9, b=9
```

| a | b | 符号付きで読むと | lt |
| --- | --- | --- | --- |
| 3 | 5 | 3 < 5 | 1 |
| 15 | 1 | −1 < 1 | 1 |
| 7 | 8 | 7 < −8 ではない | 0 |
| 8 | 7 | −8 < 7 | 1 |
| 9 | 9 | −7 < −7 ではない | 0 |

RISC-V に、符号付きで比べる命令（`slt`、`blt`）と、符号なしで比べる命令（`sltu`、`bltu`）が別々にあるのは、このためです。

## ALU を組み立てる {#alu}

部品がそろいました。ここまでに作ったものを 1 つにまとめて、**ALU**（Arithmetic Logic Unit、算術論理演算装置）を組み立てます。ALU は、CPU の中で実際に計算をする部分です。

ALU は、2 つの数 a と b を受け取り、**op**（operation、演算）という信号で指定された計算の結果を 1 つ出します。この章で作る ALU は 4 ビットで、5 種類の計算ができます。

| op | 名前 | 結果 y |
| --- | --- | --- |
| `000` | AND | a and b（ビットごと） |
| `001` | OR | a or b（ビットごと） |
| `010` | ADD | a + b |
| `110` | SUB | a − b |
| `111` | SLT | a < b なら 1、そうでなければ 0（符号付き） |

op の 3 ビットは、でたらめに割り振ったのではありません。

- **下の 2 ビット**（op[1:0]）は、4 入力のマルチプレクサの選択。00 なら AND、01 なら OR、10 なら加算器、11 なら比較の結果を選ぶ
- **いちばん上のビット**（op[2]）は、前の章の加減算器の `sub`。1 なら b を反転して 1 を足すので、加算器が引き算をする

```fig circuit 4 ビットの ALU。AND、OR、加算器がいつも全部の計算をしていて、最後にマルチプレクサが 1 つを選ぶ。lt は、引き算の結果の符号から作る 1 ビット
{
  parts: [
    { id: 'a', type: 'in', x: 0, y: 1 }, { id: 'b', type: 'in', x: 0, y: 2 },
    { id: 'and', type: 'and', x: 7, y: 1.5, label: 'AND' }, { id: 'or', type: 'or', x: 7, y: 4.5, label: 'OR' },
    { id: 'x', type: 'xor', x: 3, y: 10 },
    { id: 'add', type: 'box', x: 7, y: 8.5, w: 4, h: 3, label: '加算器', ins: ['a', 'b'], outs: ['s', 'lt'], bottoms: ['cin'] },
    { id: 'op2', type: 'in', x: 0, y: 12.5, label: 'op[2]' },
    { id: 'm', type: 'mux', x: 16, y: 5.5, inputs: 4, labels: ['00', '01', '10', '11'] },

    { title: 'op = 000（AND）', hl: ['and', 'm'], vals: { op2: 0, op10: '00' }, say: 'マルチプレクサが、いちばん上の入力（AND の結果）を選びます。加算器も計算していますが、結果は使われません。' },
    { title: 'op = 010（ADD）', hl: ['x', 'add.s->m.in2', 'm'], vals: { op2: 0, op10: '10' }, say: 'op[2] が 0 なので、XOR は b をそのまま通し、加算器は a + b を計算します。マルチプレクサが 3 番目の入力を選びます。' },
    { title: 'op = 110（SUB）', hl: ['op2', 'x', 'add.s->m.in2', 'm'], vals: { op2: 1, op10: '10' }, say: 'マルチプレクサの選択は ADD と同じです。op[2] が 1 なので、XOR が b を反転し、cin の 1 が足されて、加算器は a − b を計算します。' },
    { title: 'op = 111（SLT）', hl: ['op2', 'x', 'add.lt->m.in3', 'm'], vals: { op2: 1, op10: '11' }, say: '加算器は SUB と同じく a − b を計算します。マルチプレクサは、その符号から作った lt を選びます。' },

```

この図を、そのまま回路記述にします。1 行 1 行が、ここまでの章で作ってきた部品です。

```logic run title="4 ビットの ALU"
in a[4], b[4], op[3]
out y[4]
x = b xor op[2]                                 # op[2] が 1 なら b を反転（第 5 章）
sum = a + x + op[2]                             # 加減算器
v = (a[3] xnor x[3]) and (a[3] xor sum[3])      # オーバーフロー
lt = sum[3] xor v                               # 符号付きの a < b
y = mux(op[1:0], a and b, a or b, sum, {0b000, lt})

test a=12, b=10, op=0b000
test a=12, b=10, op=0b001
test a=12, b=10, op=0b010
test a=12, b=10, op=0b110
test a=3, b=5, op=0b111
test a=5, b=3, op=0b111
```

a = 12（`1100`）、b = 10（`1010`）に対して、上から順に AND は 8（`1000`）、OR は 14（`1110`）、ADD は 6（22 の下 4 ビット）、SUB は 2 です。最後の 2 行は SLT で、3 < 5 は 1、5 < 3 は 0 になります。

`{0b000, lt}` は、1 ビットの lt の上に 0 を 3 個付けて、ほかの結果と同じ 4 ビットにそろえる書き方です。

わずか 5 行で、5 種類の計算ができる回路になりました。`test` の行を書き換えて、いろいろな計算をさせてみてください。

:::note 選ばれない計算も、いつも行われている
ALU の中では、AND も OR も加算器も、**いつも全部が計算しています**。op が決めるのは、最後にどの結果を外に出すかだけです。無駄に見えますが、回路は「必要なときだけ動く」ことができません。全部を並べておいて選ぶのが、いちばん単純で速い作り方です。
:::

## ゼロフラグ {#zero}

ALU には、計算の結果のほかに、もう 1 本だけ出力を付けます。**結果が 0 のとき 1 になる**線で、**ゼロフラグ**（zero）と呼びます。フラグ（flag）は「旗」で、何かが起きたことを知らせる 1 ビットの印という意味です。

結果が 0 というのは、すべてのビットが 0 ということです。NOR は「入力が全部 0 のとき 1」になるゲートでした。4 入力の NOR が 1 個あれば足ります。

```logic run title="ゼロフラグ付きの ALU"
in a[4], b[4], op[3]
out y[4], zero
x = b xor op[2]
sum = a + x + op[2]
v = (a[3] xnor x[3]) and (a[3] xor sum[3])
lt = sum[3] xor v
y = mux(op[1:0], a and b, a or b, sum, {0b000, lt})
zero = nor(y[0], y[1], y[2], y[3])              # 結果が 0 なら 1

test a=9, b=9, op=0b110
test a=9, b=8, op=0b110
test a=5, b=10, op=0b000
test a=5, b=10, op=0b001
```

ゼロフラグのいちばん大事な使い道は、**等しいかどうかの判定**です。1 行目と 2 行目を見てください。SUB をさせて zero が 1 なら、a と b は等しいとわかります。等しい数どうしを引くと 0 になるからです。「等しい」比較器を別に作らなくても、ALU の引き算とゼロフラグで代わりができます。

3 行目も面白い使い方です。5（`0101`）と 10（`1010`）の AND は 0 で、zero が 1 になります。2 つの数に、共通して 1 のビットが 1 つもないことがわかります。

## RISC-V の命令と ALU {#riscv}

ここで作った ALU は、練習用のおもちゃではありません。幅を 4 ビットから 32 ビットに広げれば、RISC-V の CPU の中にある ALU と同じ働きをします。

第 10 章から、RISC-V のアセンブリでプログラムを書きます。そこで使う命令のほとんどは、ALU に「この 2 つの数に、この計算をせよ」と頼む命令です。

```fig circuit 命令と ALU。命令の種類が op を決め、ALU が 2 本のレジスタの値を計算して、結果をレジスタに戻す

  parts: [
    { id: 'ra', type: 'box', x: 0, y: 2, w: 3, h: 2, label: 'レジスタ\nx1', outs: ['_q'] },

    { id: 'op', type: 'in', x: 10.5, y: 8.5, labelPos: 'bottom', label: 'op' },

    { title: 'add x3, x1, x2', vals: { op: '010' }, wires: [{ from: 'ra', to: 'alu.a', bus: 32, mid: 6 }, { from: 'rb', to: 'alu.b', bus: 32, mid: 6 }, { from: 'op', to: 'alu.op', bus: 3 }, { from: 'alu.y', to: 'rd', bus: 32, hl: true, label: 'x1 + x2', ldy: -6 }], say: '「x1 と x2 を足して x3 に入れる」命令。op は 010（ADD）になります。' },

  ],

```

`add` と `sub` と `and` は、別々の回路で実行されるのではありません。**同じ ALU に、違う op を渡しているだけ**です。命令と、この章の ALU の op の対応を表にします。

| RISC-V の命令 | すること | ALU の op |
| --- | --- | --- |
| `add` | 足す | `010` ADD |
| `sub` | 引く | `110` SUB |
| `and` | ビットごとの AND | `000` AND |
| `or` | ビットごとの OR | `001` OR |
| `slt` | 小さければ 1（符号付き） | `111` SLT |
| `addi` | 命令に書いた数を足す | `010` ADD |
| `beq` | 等しければ分岐する | `110` SUB をして、zero を見る |
| `lw`、`sw` | メモリを読む、書く | `010` ADD（番地の計算） |

計算に見えない命令も、ALU を使っています。`beq`（等しければ分岐）は、引き算をしてゼロフラグを見ます。メモリを読み書きする `lw` と `sw` は、「レジスタの値 + ずらす量」という番地の計算に加算器を使います。

本物の RISC-V の ALU には、このほかに XOR、ビットをずらすシフト、符号なしの比較（`sltu`）も入っています。それでも作りは同じで、「全部計算しておいて、マルチプレクサで選ぶ」です。第 16 章で、この ALU をレジスタやメモリとつないで、CPU 全体の図（データパス）を組み立てます。

:::deep op の 3 ビットはだれが決めるのか
命令は 32 ビットの数で、その中の決まった位置のビットが、命令の種類を表しています（第 9 章）。そのビットを見て、ALU の op などの信号を作る回路を**制御回路**と呼びます。制御回路の中身は、この章のデコーダと同じ種類の、記憶を持たないゲートの組み合わせです。「命令のビット → 制御信号」という大きな真理値表を、回路にしたものです。
:::

:::try やってみよう
下は、この章の ALU です。次のことを試してください。

1. `a=6, b=6` に SUB をさせて、zero が 1 になることを確かめる（`beq` がしていること）
2. `a=15, b=1` に SLT をさせる。15 は符号付きでは −1 なので、結果は 1 になる
3. マルチプレクサの入力を 1 つ入れ替えて、op = `001` で `a xor b` を出す ALU に改造する
4. `out y[4], zero, neg` にして、`neg = y[3]` を足す。結果が負（符号付き）のとき 1 になるフラグです
:::

```logic run title="練習用：ALU"
in a[4], b[4], op[3]
out y[4], zero
x = b xor op[2]
sum = a + x + op[2]
v = (a[3] xnor x[3]) and (a[3] xor sum[3])
lt = sum[3] xor v
y = mux(op[1:0], a and b, a or b, sum, {0b000, lt})
zero = nor(y[0], y[1], y[2], y[3])

test a=6, b=6, op=0b110
test a=15, b=1, op=0b111
```

:::key この章のまとめ
- **マルチプレクサ**（MUX）は、選択の信号 s で入力の 1 つを選んで出す。中身は「AND の門 2 つと OR」。s が n ビットなら 2 の n 乗個から選べる
- 回路は、両方を計算してから選ぶ。選ばれなかった結果は捨てられる
- **デコーダ**は、番号を受け取って、その番号の出力 1 本だけを 1 にする。レジスタやメモリの「どれか 1 つ」を指すのに使う
- 等しいかどうかは、桁ごとの XNOR を AND でまとめる。大小は引き算の結果で決める。**大小の比較は、符号付きと符号なしで答えが変わる**
- **ALU** は、AND、OR、加減算器、比較を並べ、op の信号でマルチプレクサが 1 つを選ぶ。op の 1 ビットが足し算と引き算を切り替える
- **ゼロフラグ**は結果が 0 のとき 1。引き算と組み合わせると「等しい」の判定になる
- RISC-V の `add`、`sub`、`and`、`or`、`slt` は、同じ ALU に違う op を渡している。`beq` や `lw` も ALU を使う
:::

## 確認問題 {#quiz}

この章の内容を、自分で回路を書いて確かめます。入力と出力の名前、ビットの幅は、問題文のとおりにしてください。

:::quiz NAND 4 個でマルチプレクサ
1 ビットの入力 `s`、`a`、`b` と、1 ビットの出力 `y` を持つ回路を書いてください。`s` が 0 なら `y` は `a`、`s` が 1 なら `y` は `b` にします。

使ってよいゲートは `nand` だけで、個数は 4 個以下にしてください。`mux` は使えません。

```logic answer only="nand" maxgates="4"
in s, a, b
out y
ns = s nand s
p = a nand ns
q = b nand s
y = p nand q
```

```logic starter
in s, a, b
out y
```

:::hint
`(a and not s) or (b and s)` から出発します。第 4 章のド・モルガンの法則で、`x or y` は `(not x) nand (not y)` と書けました。x が `a and not s` なら、`not x` は `a nand (not s)` で、NAND 1 個です。`not s` も NAND 1 個で作れます。
:::
:::

:::quiz == を使わずに「等しい」を作る
4 ビットの入力 `a`、`b`（`in a[4], b[4]`）と、1 ビットの出力 `eq` を持つ回路を書いてください。`eq` は、`a` と `b` が等しいとき 1、違うとき 0 にします。

`==`、`+`、`-` は使えません。`and`、`or`、`not`、`xor`、`xnor`、`nand`、`nor` のゲートだけで作ってください。

```logic answer only="and,or,not,xor,xnor,nand,nor"
in a[4], b[4]
out eq
e = a xnor b
eq = and(e[0], e[1], e[2], e[3])
```

```logic starter
in a[4], b[4]
out eq
```

:::hint
`a xnor b` は 4 ビットのバスで、桁ごとに「同じなら 1」になります。その 4 本が全部 1 のときだけ、`eq` を 1 にします。逆に、`a xor b`（違う桁が 1）の 4 本が全部 0 のとき、と考えて NOR を使う方法もあります。
:::
:::

:::quiz 大きいほうを選ぶ
4 ビットの入力 `a`、`b`（`in a[4], b[4]`）と、4 ビットの出力 `y`（`out y[4]`）を持つ回路を書いてください。`y` は、`a` と `b` を**符号なし**の数（0〜15）として比べて、大きいほうの値にします。等しいときはその値です。

たとえば a = 3、b = 12 なら `y` は 12 です。

```logic answer
in a[4], b[4]
out y[4]
d = {0, a} - {0, b}
y = mux(d[4], a, b)
```

```logic starter
in a[4], b[4]
out y[4]
```

:::hint
まず「a < b」の 1 ビットを作ります。本文の符号なしの比較と同じで、5 ビットに広げて引き算をし、いちばん上のビットを取り出します。その 1 ビットをマルチプレクサの選択に使って、a < b なら b、そうでなければ a を選びます。
:::
:::

:::quiz 小さな ALU
4 ビットの入力 `a`、`b` と 2 ビットの入力 `op`（`in a[4], b[4], op[2]`）、4 ビットの出力 `y` と 1 ビットの出力 `zero`（`out y[4], zero`）を持つ回路を書いてください。

- `op` が 0 なら `y` は a and b、1 なら a or b、2 なら a + b、3 なら a − b（どれも 4 ビット。あふれた分は捨てる）
- `zero` は、`y` が 0 のとき 1、それ以外は 0

```logic answer
in a[4], b[4], op[2]
out y[4], zero
y = mux(op, a and b, a or b, a + b, a - b)
zero = nor(y[0], y[1], y[2], y[3])
```

```logic starter
in a[4], b[4], op[2]
out y[4], zero
```

:::hint
`op` が 2 ビットなので、`mux(op, …, …, …, …)` に 4 つの結果を順に並べれば、`op` の値の番目が選ばれます。`zero` は、`y` の 4 本を NOR に入れます。`y == 0` と書くこともできます。
:::
:::
