## レジスタ：CPU の中の 32 個の置き場 {#registers}

第 9 章で、命令は 32 ビットの数であり、アセンブリはそれを人が読める形で書いたものだと分かりました。この章からは、アセンブリを自分で書いていきます。

CPU の計算は、すべて**レジスタ**の上で行われます。レジスタは、CPU の中にある 32 ビットの置き場で、第 7 章でフリップフロップを並べて作ったものです。RISC-V には 32 本あり、`x0` から `x31` までの番号が付いています。

メモリは広い倉庫、レジスタは手元の作業机にあたります。机は狭いけれど、すぐに手が届きます。RISC-V の計算の命令は、レジスタの値どうしでしか計算できません。メモリにある数を使いたいときは、いったん `lw` でレジスタに読み込み、計算して、`sw` で書き戻します（第 12 章）。

### レジスタの名前

32 本のレジスタは、回路としてはどれも同じです（`x0` だけが例外）。しかし、プログラムを書く人どうしで「どのレジスタを何に使うか」の約束を決めてあり、その役目に合わせた別名が付いています。この約束を **ABI**（Application Binary Interface）と呼び、別名を **ABI 名**と呼びます。アセンブリでは、ふつう ABI 名のほうを使います。

| 番号 | ABI 名 | 役目 |
| --- | --- | --- |
| x0 | `zero` | いつも 0。書き込んでも変わらない |
| x1 | `ra` | 関数からの戻り先の番地（return address。第 13 章） |
| x2 | `sp` | スタックの先頭の番地（stack pointer。第 13 章） |
| x3、x4 | `gp`、`tp` | 特別な用途。このサイトでは使わない |
| x5〜x7 | `t0`〜`t2` | 一時的な計算用（temporary） |
| x8、x9 | `s0`、`s1` | 関数を呼んでも値が残る約束のレジスタ（saved。`s0` は `fp` とも書く） |
| x10〜x17 | `a0`〜`a7` | 関数に渡す値と、返ってくる値（argument） |
| x18〜x27 | `s2`〜`s11` | `s0` `s1` と同じ |
| x28〜x31 | `t3`〜`t6` | `t0`〜`t2` と同じ |

この章では、計算の途中に `t0`〜`t6` を、表示したい値に `a0` を使います。`ra` `sp` `s0`〜`s11` の出番は、関数を扱う第 13 章です。

:::note pc は 33 本目
次に実行する命令の番地を持つ pc も 32 ビットのレジスタですが、`x0`〜`x31` には入っていません。`add` などの命令で直接読み書きすることはできず、分岐やジャンプの命令で変えます（第 11 章）。
:::

## 最初の命令：addi {#addi}

最初に覚える命令は `addi`（add immediate）です。レジスタの値に数を足して、レジスタに入れます。

```asm
addi  書き込む先, 読むレジスタ, 足す数
```

次のブロックはステップ実行の画面で開きます。「1 命令進む」を押して、`a0` が変わっていく様子を見てください。

```asm run step title="addi で数を足していく" regs="a0"
    addi a0, zero, 5     # a0 ← 0 + 5
    addi a0, a0, 3       # a0 ← a0 + 3
    addi a0, a0, -1      # a0 ← a0 − 1
```

`a0` は 5、8、7 と変わります。読み方の決まりは次のとおりです。

- **いちばん左が結果の入る先**。`addi a0, a0, 3` は「`a0` に 3 を足した値を `a0` に入れる」。同じレジスタを読んで書いてかまいません
- 命令の名前とオペランド（命令に渡すもの）の間は空白、オペランドどうしはコンマで区切る
- `#` から行の終わりまでは**コメント**。CPU には関係のない、人のためのメモ
- 引き算の `subi` はない。負の数を足せば済むから（第 9 章）

足す数は、命令の中に埋め込まれる**即値**で、-2048 から 2047 までです。命令の名前の最後の `i` は、即値（immediate）を使うという印です。

## x0 はいつも 0 {#zero}

上の 1 行目は `addi a0, zero, 5` でした。`zero`（`x0`）は、**読むといつも 0 で、書き込んでも何も起きない**特別なレジスタです。

```asm run title="zero に書き込んでも 0 のまま" regs="zero,a0"
    addi zero, zero, 99  # zero に 99 を入れようとする
    addi a0, zero, 1     # a0 ← 0 + 1
```

`a0` は 1 です。`zero` に 99 は入りませんでした。

いつも 0 のレジスタなど役に立たないように見えますが、逆です。0 がいつでも手元にあるおかげで、`addi` という 1 つの命令が何通りにも使えます。

| やりたいこと | 書き方 | 仕組み |
| --- | --- | --- |
| レジスタに数を入れる | `addi a0, zero, 5` | 0 + 5 |
| レジスタの値を別のレジスタに写す | `addi a1, a0, 0` | a0 + 0 |
| レジスタを 0 にする | `addi a0, zero, 0` | 0 + 0 |
| 何もしない | `addi zero, zero, 0` | 結果を捨てる |

「数を入れる命令」「写す命令」「何もしない命令」を別々に用意しなくて済むので、CPU の回路が小さくなります。命令の種類を絞るという RISC の考え方（第 1 章）の、分かりやすい例です。

## li と mv：疑似命令 {#pseudo}

とはいえ、数を入れるたびに `addi a0, zero, 5` と書くのは読みにくいものです。そこでアセンブラは、よく使う形に**別の書き方**を用意しています。

```asm run title="li と mv" regs="a0,a1"
    li   a0, 5           # a0 ← 5（load immediate）
    mv   a1, a0          # a1 ← a0（move）
    addi a1, a1, 1       # a1 だけを 1 増やす
```

`a0` は 5、`a1` は 6 です。`mv` は「移す」という名前ですが、実際は**写し**で、元の `a0` は変わりません。

`li` と `mv` は、CPU の命令ではありません。アセンブラが本物の命令に書き直します。こういう書き方を**疑似命令**と呼びます。本当に同じ機械語になるのかを、第 9 章のやり方（プログラムに自分の命令を読ませる）で確かめます。

```asm run title="li a0, 5 と addi a0, zero, 5 は同じ機械語"
    li   a0, 5           # 0 番地
    addi a0, zero, 5     # 4 番地
    lw   a0, 0(zero)     # 0 番地の機械語を読んで表示
    li   a7, 34
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    lw   a0, 4(zero)     # 4 番地の機械語を読んで表示
    li   a7, 34
    ecall
```

```console
0x00500513
0x00500513
```

2 つの行は、まったく同じ 32 ビットになりました。CPU から見れば、`li` という命令は存在しません。

| 疑似命令 | 本物の命令 | 意味 |
| --- | --- | --- |
| `li a0, 5` | `addi a0, zero, 5` | 数を入れる |
| `li a0, 100000` | `lui` + `addi` | 12 ビットに収まらない数は 2 命令になる（第 9 章） |
| `mv a1, a0` | `addi a1, a0, 0` | 写す |
| `nop` | `addi zero, zero, 0` | 何もしない |
| `neg a1, a0` | `sub a1, zero, a0` | 符号を反転する |
| `not a1, a0` | `xori a1, a0, -1` | 全ビットを反転する |

`li` は、数の大きさを気にせずに使えます。大きな数のときは、アセンブラが `lui` と `addi` の 2 命令に分けてくれます。

```asm run title="li は大きな数も入れられる" regs="t0,t1"
    li   t0, 1000000     # 12 ビットに収まらない
    li   t1, -1000000
    mv   a0, t0
    li   a7, 1           # a0 を 10 進数で表示（表示の仕組みは、あとの節で説明）
    ecall
```

## レジスタどうしの足し算と引き算：add と sub {#add-sub}

`addi` は、足す相手が命令に埋め込んだ数でした。レジスタどうしを足すのが `add`、引くのが `sub` です。

```fig graph add a0, t0, t1 の動き。2 本のレジスタを読み、ALU で足して、1 本に書く。読まれた側の t0 と t1 は変わらない
{
  col: 190, row: 80,
  nodes: [
    { id: 't0', label: 't0', sub: '30', x: 0, y: 0, kind: 'stack' },
    { id: 't1', label: 't1', sub: '12', x: 0, y: 1, kind: 'stack' },
    { id: 'alu', label: 'ALU', sub: '足す', x: 1, y: 0.5 },
    { id: 'a0', label: 'a0', sub: '42', x: 2, y: 0.5, kind: 'accent' },
  ],
  edges: [
    { from: 't0', to: 'alu' },
    { from: 't1', to: 'alu' },
    { from: 'alu', to: 'a0', label: '結果' },
  ],
}
```

```asm run title="add と sub" regs="t0,t1,a0,a1"
    li   t0, 30
    li   t1, 12
    add  a0, t0, t1      # a0 ← t0 + t1
    sub  a1, t0, t1      # a1 ← t0 − t1
```

`a0` は 42、`a1` は 18 です。どちらも「結果、入力 1、入力 2」の順に書きます。`sub` は入力 1 から入力 2 を引くので、順番を逆にすると結果の符号が変わります。

1 つの命令でできる計算は 1 つだけです。長い式は、途中の結果をレジスタに置きながら、少しずつ計算します。`(a + b) − (c + d)` を計算してみます。

```asm run title="(a + b) − (c + d) を 3 つの命令で" regs="t4,t5,a0"
    li   t0, 50          # a
    li   t1, 8           # b
    li   t2, 10          # c
    li   t3, 6           # d
    add  t4, t0, t1      # t4 ← a + b
    add  t5, t2, t3      # t5 ← c + d
    sub  a0, t4, t5      # a0 ← (a + b) − (c + d)
```

`a0` は 42 です。高級言語（C や Python など）なら 1 行で書ける式も、CPU にとっては 3 つの命令です。コンパイラは、式をこのような命令の列に分解する仕事をしています（第 20 章）。

:::note あふれても止まらない
32 ビットに収まらない結果は、上の桁が捨てられます（第 2 章、第 3 章）。`0x7FFFFFFF`（符号付きで最大の数）に 1 を足すと、`0x80000000`（最小の負の数、-2147483648）になります。RISC-V の `add` は、あふれてもエラーにも例外にもなりません。
:::

## 結果を表示する：ecall {#ecall}

レジスタの中身は「CPU を見る」で確かめられますが、プログラム自身が結果を外に出すには、**ecall**（environment call）という命令を使います。CPU の外側の世界（ふつうは OS、このサイトではエミュレータ）に仕事を頼む命令です。

頼み方は決まっています。

1. `a7` に、頼みたい仕事の**番号**を入れる
2. `a0` に、仕事に渡す値を入れる
3. `ecall` を実行する

```asm run title="数を表示する"
    li   a0, 42          # 表示したい数
    li   a7, 1           # 仕事の番号：1 ＝ a0 を 10 進数で表示
    ecall
```

このサイトの CPU で使える番号は次のとおりです。RARS という広く使われている RISC-V の学習用シミュレータと同じ番号にしてあります。番号と意味は RISC-V の仕様ではなく、動かす環境ごとの決まりです。

| `a7` | 仕事 | `a0` に入れるもの |
| --- | --- | --- |
| 1 | 整数を 10 進数で表示 | 表示する数 |
| 11 | 文字を 1 つ表示 | 文字コード |
| 4 | 文字列を表示 | 文字列の先頭の番地 |
| 10 | プログラムを終了 | （使わない） |
| 34 | 16 進数で表示 | 表示する数 |
| 35 | 2 進数で表示 | 表示する数 |

数を表示しただけでは改行されません。改行したいときは、改行の文字 `'\n'` を 11 番で表示します。`'A'` のように引用符で囲むと、その文字の文字コードになります。

```asm run title="数と文字を組み合わせて表示する"
    li   a0, 12
    li   a7, 1
    ecall                # 12
    li   a0, '+'
    li   a7, 11
    ecall                # +
    li   a0, 30
    li   a7, 1
    ecall                # 30
    li   a0, '\n'
    li   a7, 11
    ecall                # 改行
    li   a0, 42
    li   a7, 1
    ecall                # 42
```

```console
12+30
42
```

文字列をまとめて表示するには、第 8 章の `.data` と `.asciz` で文字列を置き、その番地を `la` で `a0` に入れて 4 番を呼びます。

```asm run title="文字列と計算結果を表示する"
.data
msg:  .asciz "答えは "

.text
    li   t0, 6
    li   t1, 7
    mul  t2, t0, t1      # 掛け算（後の節で説明）
    la   a0, msg
    li   a7, 4
    ecall                # 文字列
    mv   a0, t2
    li   a7, 1
    ecall                # 数
```

`ecall` のたびに `a0` と `a7` を書き換えるので、大事な値は `t0` などの別のレジスタに置いておくのがコツです。

### プログラムの終わり方

このサイトの CPU では、最後の命令の次まで進むと、プログラムは「最後まで実行しました」と終わります。途中で終わらせたいときは、10 番の ecall を使います。

```asm run title="ecall の 10 番で途中で終わる"
    li   a0, 1
    li   a7, 1
    ecall                # 1 を表示
    li   a7, 10
    ecall                # ここで終了
    li   a0, 2           # ここから先は実行されない
    li   a7, 1
    ecall
```

表示されるのは `1` だけです。本物の機械には「プログラムの外」というものがなく、命令の後ろのメモリにたまたま入っている数を実行し続けてしまいます。だから、OS の上で動くプログラムは、最後に必ず終了を頼みます。

## ビット演算：and、or、xor {#logic}

第 4 章の論理ゲートを、32 ビットまとめて行う命令です。2 つのレジスタの同じ位置のビットどうしを計算します。

| 命令 | 即値の形 | ビットごとの計算 | よくある使い道 |
| --- | --- | --- | --- |
| `and` | `andi` | 両方 1 なら 1 | 一部のビットだけ取り出す（マスク） |
| `or` | `ori` | どちらかが 1 なら 1 | あるビットを 1 にする |
| `xor` | `xori` | 違っていれば 1 | あるビットを反転する |

結果を 2 進数で表示する 35 番の ecall で、ビットの動きを見ます。

```asm run title="and で下位 4 ビットだけ取り出す" regs="t0,a0"
    li   t0, 0b10110110
    andi a0, t0, 0b1111  # 下位 4 ビット以外を 0 にする
    li   a7, 35          # 2 進数（32 桁）で表示
    ecall
```

下の 8 桁は `00000110` です。`1011 0110` のうち、相手が 1 の位置（下位 4 ビット）だけが残りました。取り出したい位置に 1 を並べた数を**マスク**と呼びます。

```asm run title="or でビットを立て、xor で反転する" regs="t0,t1,t2"
    li   t0, 0b00000110
    ori  t1, t0, 0b1000  # ビット 3 を 1 にする → 1110
    xori t2, t1, 0b0011  # ビット 0 と 1 を反転 → 1101
    mv   a0, t2
    li   a7, 35
    ecall
```

下の 4 桁は `1101` です。`or` は「相手が 1 の位置を 1 にする」、`xor` は「相手が 1 の位置を反転する」と覚えると使いやすくなります。

:::tip 偶数か奇数かは、いちばん下のビットで分かる
`andi t1, t0, 1` の結果は、`t0` が奇数なら 1、偶数なら 0 です。2 進数のいちばん下の桁が 1 の位だからです。割り算をしなくても判定できます。第 11 章の分岐でよく使います。
:::

## シフト：ビットを左右にずらす {#shift}

**シフト**は、ビットの並びを左か右にずらす命令です。

```fig layout slli で左に 2 ビットずらす。空いた下のビットには 0 が入り、はみ出した上のビットは捨てられる。2 進数で 1 桁左にずれると 2 倍になる
{
  unit: 30,
  rows: [
    { label: '元の値', cells: [
      { t: '0', w: 1.4 }, { t: '0', w: 1.4 }, { t: '0', w: 1.4 }, { t: '0', w: 1.4 },
      { t: '1', w: 1.4, kind: 'accent' }, { t: '0', w: 1.4, kind: 'accent' }, { t: '1', w: 1.4, kind: 'accent' }, { t: '1', w: 1.4, kind: 'accent' },
    ], note: '11' },
    { label: 'slli 2', cells: [
      { t: '0', w: 1.4 }, { t: '0', w: 1.4 },
      { t: '1', w: 1.4, kind: 'accent' }, { t: '0', w: 1.4, kind: 'accent' }, { t: '1', w: 1.4, kind: 'accent' }, { t: '1', w: 1.4, kind: 'accent' },
      { t: '0', w: 1.4, kind: 'stack' }, { t: '0', w: 1.4, kind: 'stack' },
    ], note: '44 ＝ 11 × 4' },
  ],
}
```

| 命令 | 意味 | 空いたビット |
| --- | --- | --- |
| `slli rd, rs, n` | 左に n ビット（shift left logical） | 下に 0 が入る |
| `srli rd, rs, n` | 右に n ビット（shift right logical） | 上に 0 が入る |
| `srai rd, rs, n` | 右に n ビット（shift right arithmetic） | 上に符号ビットの写しが入る |

10 進数で 1 桁左にずらすと 10 倍になるのと同じで、2 進数で 1 ビット左にずらすと **2 倍**になります。n ビットなら 2 の n 乗倍です。

```asm run title="左シフトは 2 の n 乗倍" regs="t0,t1,t2,t3"
    li   t0, 11
    slli t1, t0, 1       # 11 × 2 = 22
    slli t2, t0, 2       # 11 × 4 = 44
    slli t3, t0, 10      # 11 × 1024 = 11264
```

右シフトは、2 の n 乗で割ること（余りは切り捨て）にあたります。負の数のときに `srli` と `srai` で結果が変わります。

```asm run title="負の数を右にずらす" regs="t0,t1,t2"
    li   t0, -8          # 0xFFFFFFF8
    srai t1, t0, 1       # 符号を保つ：-4
    srli t2, t0, 1       # 上に 0 を入れる：0x7FFFFFFC
```

`srai` の結果は -4 で、ちゃんと半分です。`srli` は上に 0 を入れるので、2147483644 という大きな正の数になります。符号付きの数を割るつもりなら `srai`、ビットの並びとして扱うなら `srli` を使います。

シフトと足し算を組み合わせると、掛け算の代わりになります。10 倍は、8 倍と 2 倍の和です。

```asm run title="シフトと足し算で 10 倍する" regs="t0,a0"
    li   t0, 7
    slli t1, t0, 3       # 7 × 8
    slli t2, t0, 1       # 7 × 2
    add  a0, t1, t2      # 7 × 10
    li   a7, 1
    ecall
```

:::note レジスタの値でずらす命令もある
ずらす量をレジスタで指定する `sll` `srl` `sra` もあります。`sll t1, t0, t2` は、`t0` を `t2` の下位 5 ビットの数だけ左にずらします。
:::

## 掛け算と割り算：mul、div、rem {#muldiv}

RISC-V の基本の命令（RV32I）には、掛け算と割り算がありません。回路が大きくなるので、必要な機械だけが載せる**M 拡張**に分けてあります（第 1 章）。このサイトの CPU は M 拡張を載せた RV32IM です。

| 命令 | 意味 |
| --- | --- |
| `mul rd, rs1, rs2` | 掛け算（結果の下位 32 ビット） |
| `div rd, rs1, rs2` | 割り算の商（0 に向かって切り捨て） |
| `rem rd, rs1, rs2` | 割り算の余り（remainder） |

どれもレジスタどうしの命令で、即値の形（`muli` など）はありません。数で掛けたり割ったりするときは、先に `li` でレジスタに入れます。

```asm run title="3725 秒は何分何秒か" regs="t0,t2,t3"
    li   t0, 3725        # 秒
    li   t1, 60
    div  t2, t0, t1      # 分 ＝ 3725 ÷ 60 の商
    rem  t3, t0, t1      # 秒 ＝ 3725 ÷ 60 の余り
    mv   a0, t2
    li   a7, 1
    ecall
    li   a0, ':'
    li   a7, 11
    ecall
    mv   a0, t3
    li   a7, 1
    ecall
```

`62:5` と表示されます。62 分 5 秒です。商と余りは、数を桁に分けるときにも使います。10 で割った余りが一の位、商が残りの桁です。

```asm run title="数を一の位と十の位に分ける" regs="t2,t3"
    li   t0, 47
    li   t1, 10
    div  t2, t0, t1      # 十の位：4
    rem  t3, t0, t1      # 一の位：7
```

### 0 で割るとどうなるか

多くの CPU や言語では、0 で割るとエラーになります。RISC-V は違います。

```asm run title="0 で割っても止まらない" regs="t2,t3"
    li   t0, 7
    li   t1, 0
    div  t2, t0, t1      # 商は -1（全ビットが 1）
    rem  t3, t0, t1      # 余りは割られる数そのまま
```

`t2` は -1、`t3` は 7 になり、プログラムは止まりません。RISC-V の仕様は、0 で割ったときの結果をこのように決めていて、例外は起こしません。例外を起こす回路を省いて CPU を単純にするためです。0 で割ってはいけないことをプログラムが保証するか、割る前に自分で調べます（調べ方は第 11 章の分岐）。

## ステップ実行で 1 命令ずつ追う {#step}

ここまでの命令を組み合わせた、少し長いプログラムを追ってみます。摂氏の温度を華氏に直す式 `F = C × 9 ÷ 5 + 32` です。

```asm run step title="摂氏 25 度を華氏に直す" regs="t0,t1,t2,a0"
    li   t0, 25          # C
    li   t1, 9
    mul  t2, t0, t1      # C × 9
    li   t1, 5
    div  t2, t2, t1      # ÷ 5
    addi a0, t2, 32      # + 32
    li   a7, 1
    ecall
```

「1 命令進む」を押しながら、次の 3 つを見てください。

- **光っている行**：これから実行する命令。pc がその番地を指している
- **色の変わったレジスタ**：直前の命令が書き込んだレジスタ。1 つの命令が書き換えるレジスタは 1 本だけ
- **`t1` の使い回し**：最初は 9、途中から 5。レジスタは 32 本しかないので、用の済んだものは別の値に使う

`77` と表示されれば正解です。結果がおかしいときは、「最後まで」ではなくステップ実行で、どの命令の後にレジスタが予想と違う値になったかを探します。アセンブリのデバッグ（誤りを見つけて直す作業）は、ほぼこれだけです。

## よくある間違いと、エラーの読み方 {#errors}

書き間違えると、アセンブラが機械語にできず、実行の前にエラーになります。エラーには行番号と理由が出ます。よくあるものを 3 つ見ておきます。

```asm run error title="レジスタどうしの命令に、数を書いた"
    li   a0, 10
    add  a0, a0, 5       # add の 3 つ目はレジスタ
```

`add` の 3 つ目はレジスタでなければなりません。数を足すなら `addi` です。R 形式の命令には、数を入れる場所がないからです（第 9 章）。

```asm run error title="存在しない命令を書いた"
    li   a0, 10
    subi a0, a0, 3       # subi はない
```

`subi` はありません。`addi a0, a0, -3` と書きます。

もう 1 つは、アセンブルはできるのに、実行中に止まる間違いです。

```asm run error title="a7 に番号を入れ忘れた ecall"
    li   a0, 42
    ecall                # a7 は 0 のまま
```

`a7` に番号を入れ忘れると、エミュレータは何を頼まれたのか分かりません。「a7 = 0 の ecall はありません」と言われたら、`ecall` の前の `li a7, 番号` を確かめます。

:::warn エラーにならない間違いがいちばん怖い
`sub a0, t1, t0` と `sub a0, t0, t1` を取り違えても、エラーにはなりません。答えが違うだけです。レジスタの取り違えは、アセンブリでいちばん多い間違いです。各行にコメントで「何を入れたつもりか」を書いておくと、ステップ実行で見比べやすくなります。
:::

:::try やってみよう
下のプログラムは、長方形の縦と横から、面積と周の長さを計算して表示します。

1. 実行して、`面積 = 縦 × 横`、`周 = (縦 + 横) × 2` になっていることを確かめる
2. 周の計算の `slli` を、`add` を使う形に書き換える
3. 面積と周の間に、改行ではなく `/` を表示するように変える
:::

```asm run title="練習用：長方形の面積と周" regs="t0,t1,t2,t3"
    li   t0, 12          # 縦
    li   t1, 30          # 横
    mul  t2, t0, t1      # 面積
    add  t3, t0, t1
    slli t3, t3, 1       # 周 ＝ (縦 + 横) × 2
    mv   a0, t2
    li   a7, 1
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    mv   a0, t3
    li   a7, 1
    ecall
```

:::key この章のまとめ
- 計算はすべて**レジスタ**の上で行う。32 本あり、`zero` `t0`〜`t6` `a0`〜`a7` などの **ABI 名**で呼ぶ
- 命令は「結果を入れる先、入力 1、入力 2」の順に書く。`addi` は即値（-2048〜2047）を足し、`add` と `sub` はレジスタどうしを計算する
- `x0`（`zero`）はいつも 0。これがあるので、`addi` だけで「数を入れる」「写す」「何もしない」ができる
- `li` `mv` `nop` `neg` `not` は**疑似命令**。アセンブラが本物の命令に書き直す
- `and` `or` `xor` はビットごとの演算。`slli` は 2 の n 乗倍、`srli` と `srai` は右シフト（`srai` は符号を保つ）
- `mul` `div` `rem` は M 拡張。0 で割っても例外にならず、商は -1、余りは割られる数になる
- 結果の表示は **ecall**。`a7` に番号（1：整数、11：文字、4：文字列、10：終了）、`a0` に値を入れて呼ぶ。番号はこのサイトの CPU（RARS と同じ）の決まり
- おかしいときは、ステップ実行でレジスタの変化を 1 命令ずつ追う
:::

## 確認問題 {#quiz}

レジスタと計算の命令を、自分で組み合わせて書きます。問題文の「表示」は、コンソールへの出力のことです。

:::quiz 式を計算して表示する
`t0` に 12、`t1` に 30 が入っています。`(t0 + t1) × 2 − 5` を計算し、結果を `ecall` の 1 番で 10 進数として表示してください。

```asm starter
    li   t0, 12
    li   t1, 30
    # ここに書く
```

```asm answer
    li   t0, 12
    li   t1, 30
    add  t2, t0, t1
    slli t2, t2, 1
    addi a0, t2, -5
    li   a7, 1
    ecall
```

:::hint
足す、2 倍する、5 を引く、の順に 3 つの命令で計算します。2 倍は `slli` で 1 ビット左にずらすか、同じレジスタどうしを `add` します。
:::
:::

:::quiz 2 つのレジスタを入れ替える
`a0` に 11、`a1` に 22 が入っています。2 つの値を入れ替えて、`a0` を 22、`a1` を 11 にしてください。ほかのレジスタは自由に使ってかまいません。判定は `a0` と `a1` の値で行います。

```asm starter
    li   a0, 11
    li   a1, 22
    # ここに書く
```

```asm answer regs="a0,a1"
    li   a0, 11
    li   a1, 22
    mv   t0, a0
    mv   a0, a1
    mv   a1, t0
```

:::hint
`mv a0, a1` を先に実行すると、`a0` の元の値が消えてしまいます。消える前に、別のレジスタに写しておきます。
:::
:::

:::quiz 秒を「時:分:秒」にする
`t0` に 7384（秒）が入っています。これを時・分・秒に直し、`時:分:秒` の形で表示してください。数は `ecall` の 1 番、区切りの `:` は 11 番で表示します。7384 秒は 2 時間 3 分 4 秒なので、出力は `2:3:4` になります。計算は `div` と `rem` で行ってください。

```asm starter
    li   t0, 7384
    # ここに書く
```

```asm answer
    li   t0, 7384
    li   t1, 3600
    div  t2, t0, t1      # 時
    rem  t3, t0, t1      # 残りの秒
    li   t1, 60
    div  t4, t3, t1      # 分
    rem  t5, t3, t1      # 秒
    mv   a0, t2
    li   a7, 1
    ecall
    li   a0, ':'
    li   a7, 11
    ecall
    mv   a0, t4
    li   a7, 1
    ecall
    li   a0, ':'
    li   a7, 11
    ecall
    mv   a0, t5
    li   a7, 1
    ecall
```

:::hint
3600 で割った商が時、余りが残りの秒です。その余りを 60 で割ると、商が分、余りが秒になります。`ecall` が `a0` と `a7` を使うので、計算結果は `t` のレジスタに置いておきます。
:::
:::

:::quiz 上位と下位のバイトを入れ替える
`t0` に `0xABCD` が入っています。下位 8 ビット（`CD`）と、その上の 8 ビット（`AB`）を入れ替えた `0xCDAB` を作り、`ecall` の 34 番で 16 進数として表示してください。出力は `0x0000cdab` になります。シフトとビット演算で作ってください。

```asm starter
    li   t0, 0xABCD
    # ここに書く
```

```asm answer
    li   t0, 0xABCD
    andi t1, t0, 0xFF    # 下位 8 ビット：CD
    slli t1, t1, 8       # CD00
    srli t2, t0, 8       # 上の 8 ビット：AB
    or   a0, t1, t2      # CDAB
    li   a7, 34
    ecall
```

:::hint
`andi` で下位 8 ビットを取り出して左に 8 ビットずらし、元の値を右に 8 ビットずらしたものと `or` で合わせます。
:::
:::
