## 同じビットの並び、2 つの読み方 {#two-readings}

第 2 章では、32 ビットで 0 から 4,294,967,295 までの数を表しました。しかし、ここにはマイナスの数がありません。ビットには 0 と 1 しかなく、「−」という記号を書く場所はどこにもないのです。

まず、CPU がマイナスの数をどう覚えているのかを、のぞいてみましょう。`-1` をレジスタに入れて、3 通りに表示します。

```asm run title="-1 を 3 通りに表示する"
    li   a0, -1
    li   a7, 1            # 1 = 符号付きの 10 進数で表示
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    li   a0, -1
    li   a7, 34           # 34 = 16 進数で表示
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    li   a0, -1
    li   a7, 36           # 36 = 符号なしの 10 進数で表示
    ecall
```

結果は `-1`、`0xffffffff`、`4294967295` です。

`-1` の正体は、32 個のビットが全部 1 の並びでした。第 2 章で「いちばん大きな数」と呼んだ `0xffffffff` と、まったく同じです。レジスタの中身は 1 つなのに、表示の番号を変えただけで、-1 にも 4294967295 にもなります。

逆からも確かめます。大きな数を入れて、1 番で表示します。

```asm run title="30 億を、符号付きとして表示する"
    li   a0, 3000000000
    li   a7, 1
    ecall
```

`-1294967296` と出ます。入れたのは 30 億なのに、マイナスの数として読まれました。

ここから分かることが、この章でいちばん大事な点です。

- ビットの並びには、**符号なし**（0 以上の数だけ）と**符号付き**（マイナスも含む）の 2 つの読み方がある
- レジスタは、どちらの読み方なのかを覚えていない。**読む側が決める**
- 符号付きの読み方には、決まった規則がある。それが **2 の補数**

この規則がどう作られているのかを、順に見ていきます。

## 素朴な案：符号と絶対値 {#sign-magnitude}

マイナスの数を表す方法として、最初に思い付くのは次の案でしょう。

> いちばん左のビットを符号に使う。0 ならプラス、1 ならマイナス。残りのビットで大きさ（絶対値）を表す。

紙に書く「−3」と同じ発想です。4 ビットなら、`0011` が +3、`1011` が −3 になります。この方法を**符号と絶対値**と呼びます。

分かりやすい案ですが、困ったことが 2 つあります。

1 つ目は、**0 が 2 つできる**ことです。`0000`（+0）と `1000`（−0）は、どちらも 0 です。「2 つの数が等しいか」を調べるだけでも、この特別な場合を考えなければなりません。

2 つ目のほうが深刻です。**足し算の回路がそのまま使えません。** +3 と −3 を足せば 0 になるはずです。ふつうの足し算の回路に、この 2 つを入れてみます。

```logic run title="符号と絶対値の +3（0011）と −3（1011）を、そのまま足す"
in a[4], b[4]
out s[4]
s = a + b
test a=0b0011, b=0b1011
```

結果は 14、2 進数で `1110` です。符号と絶対値として読むと −6 で、0 にはなりません。

正しく計算するには、「符号が同じなら絶対値を足す。違うなら、大きいほうから小さいほうを引いて、大きいほうの符号を付ける」という手順が要ります。足し算のたびに、比較と引き算の回路が必要になります。回路は大きく、遅くなります。

## 2 の補数：数直線を輪にする {#twos-complement}

今のコンピュータが使っている方法は、まったく別の発想から来ています。手がかりは、第 2 章の**桁あふれ**です。

6 桁の走行距離計を思い出してください。999999 の次は 000000 でした。では、000000 から逆向きに 1 km 戻すと、どうなるでしょうか。999999 になります。つまり、この距離計の上では、**999999 は「0 の 1 つ手前」、−1 の役をしている**のです。

CPU でも同じことが起きます。0 から 1 を引いてみます。

```asm run title="0 から 1 を引く"
    li   t0, 0
    addi a0, t0, -1       # a0 = 0 - 1
    li   a7, 35           # 2 進数で表示
    ecall
```

1 が 32 個並びます。0 の 1 つ手前は、全部のビットが 1 の数です。これを −1 と呼ぶことにする。それが 2 の補数の出発点です。

4 ビットで全体を見てみましょう。16 通りの並びを、時計の文字盤のように輪に並べます。右回りに 1 つ進むと +1 です。

```fig graph 4 ビットの 16 通りを輪に並べる。右回りに 1 つ進むと +1。同じ輪に、2 通りの目盛りを振れる。ボタンで切り替えてください
(() => {

  const bits = (i) => i.toString(2).padStart(4, '0');
  const pos = (i) => {
    const t = (i / 16) * 2 * Math.PI - Math.PI / 2;
    return { x: C + R * Math.cos(t), y: C + R * Math.sin(t) };
  };

  const edges = (style) => Array.from({ length: 16 }, (_, i) => ({ from: 'n' + i, to: 'n' + ((i + 1) % 16), style: style(i) }));
  const signed = (i) => (i < 8 ? i : i - 16);
  return {
    col: 1, row: 1,

      },

      {

```

2 の補数は、新しい数の表し方を発明したというより、**すでにある輪の半分に、別の目盛りを振り直した**ものです。

| ビット | 符号なし | 符号付き | | ビット | 符号なし | 符号付き |
| --- | --- | --- | --- | --- | --- | --- |
| `0000` | 0 | 0 | | `1000` | 8 | −8 |
| `0001` | 1 | 1 | | `1001` | 9 | −7 |
| `0010` | 2 | 2 | | `1010` | 10 | −6 |
| `0011` | 3 | 3 | | `1011` | 11 | −5 |
| `0100` | 4 | 4 | | `1100` | 12 | −4 |
| `0101` | 5 | 5 | | `1101` | 13 | −3 |
| `0110` | 6 | 6 | | `1110` | 14 | −2 |
| `0111` | 7 | 7 | | `1111` | 15 | −1 |

表から、次のことが読み取れます。

- **最上位ビットが 1 なら負、0 なら 0 以上。** 最上位ビットを**符号ビット**と呼ぶ。ただし、符号と絶対値の方式とは違い、残りのビットは絶対値ではない
- 負の数は、符号なしで読んだ値から **16（2 の 4 乗）を引いた**ものになっている。`1101` は 13 − 16 = −3
- **0 は 1 つだけ**（`0000`）
- 表せる範囲は −8 から 7。**負のほうが 1 つ多い**。0 が、0 以上の側の席を 1 つ使っているため

32 ビットでも同じです。最上位ビット（31 番のビット）が 1 の数は、符号なしの値から 2 の 32 乗（4,294,967,296）を引いた負の数として読みます。先ほどの 30 億は、3,000,000,000 − 4,294,967,296 = −1,294,967,296 でした。

32 ビットの符号付きで表せる範囲の両端を、表示してみます。

```asm run title="符号付き 32 ビットの、いちばん大きい数といちばん小さい数"
    li   a0, 0x7fffffff   # 最上位ビットだけ 0、あとは全部 1
    li   a7, 1
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    li   a0, 0x80000000   # 最上位ビットだけ 1、あとは全部 0
    li   a7, 1
    ecall
```

`2147483647` と `-2147483648` です。およそプラスマイナス 21 億が、32 ビットの符号付きの数の範囲です。

## 符号を反転する：反転して 1 を足す {#negate}

ある数 x から −x を作るには、どうすればよいでしょうか。2 の補数には、覚えやすい手順があります。

> **全部のビットを反転して、1 を足す。**

5 から −5 を作ってみます。`not` は、第 2 章で見た、全部のビットを反転する命令です。

```asm run title="5 のビットを反転して 1 を足す"
    li   t0, 5
    not  t1, t0           # 全部のビットを反転
    addi a0, t1, 1        # 1 を足す
    li   a7, 1
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    addi a0, t1, 1
    li   a7, 35           # 同じ数を 2 進数で
    ecall
```

`-5` と、そのビットの並び `11111111111111111111111111111011` が出ます。5 は `…0101`、反転して `…1010`、1 を足して `…1011` です。4 ビットの表の −5（`1011`）と、下の 4 桁が同じになっています。

なぜ、これで符号が反転するのでしょうか。理由は 2 行で説明できます。

1. ある数 x と、それを反転した数を足すと、どの桁も 0 と 1 の組になるので、**全部のビットが 1**になる。全部 1 は −1 だった。つまり x + (x の反転) = −1
2. 両辺に 1 を足して x を移すと、(x の反転) + 1 = −x

同じ手順をもう一度行うと、元の数に戻ります。−5 を反転して 1 を足せば、5 です。

アセンブリには、この計算をまとめた `neg` があります。中身は「0 から引く」です。

```asm run title="neg で符号を反転する"
    li   t0, 5
    neg  a0, t0           # a0 = 0 - t0
    li   a7, 1
    ecall
```

`5` を `-5` や `0` に変えて試してください。

:::warn 反転できない数が 1 つだけある
負のほうが 1 つ多いので、いちばん小さい数 −2147483648 には、対になるプラスの数がありません。`li t0, 0x80000000` として上のプログラムを実行すると、`-2147483648` がそのまま出てきます。絶対値を求めるプログラムが、この 1 つの数でだけ負の数を返す、という不具合は実際によくあります。
:::

## 足し算の回路がそのまま使える {#same-adder}

2 の補数が選ばれた最大の理由は、**符号なしの数のための足し算の回路が、何も変えずに符号付きの数にも使える**ことです。

符号と絶対値で失敗した「3 + (−3)」を、2 の補数でやり直します。4 ビットの −3 は `1101`（符号なしで読むと 13）です。回路は、先ほどとまったく同じです。

```logic run title="同じ足し算の回路に、2 の補数の数を入れる"
in a[4], b[4]
out s[4]
s = a + b
test a=3, b=0b1101     # 3 + (−3)
test a=5, b=0b1110     # 5 + (−2)
test a=2, b=0b1011     # 2 + (−5)
```

結果は順に 0、3、13 です。13 は `1101` で、符号付きで読めば −3。どれも正しい答えになっています。

回路は、符号のことを何も知りません。3 + 13 = 16 を計算し、4 ビットからあふれた 16 を捨てて、0 を出しただけです。輪の上で考えれば当然です。「−3 を足す」とは「左回りに 3 つ戻る」ことで、それは「右回りに 13 進む」のと同じ場所に着きます。

引き算も、同じ回路で済みます。a − b は a + (−b) で、−b は「b を反転して 1 を足す」でした。

```logic run title="引き算を、足し算の回路で作る"
in a[4], b[4]
out d[4]
d = a + (not b) + 1    # a − b
test a=7, b=3
test a=3, b=7
```

7 − 3 は 4、3 − 7 は 12（`1100`、符号付きで −4）です。CPU の中の引き算は、実際にこの形で作られています。第 5 章で、ゲートから組み立てます。

CPU の命令でも確かめましょう。同じ `add` の結果を、2 通りに読みます。

```asm run title="1 つの足し算を、符号なしと符号付きで読む"
    li   t0, 4294967293   # 符号付きで読めば -3
    li   t1, 1
    add  s0, t0, t1       # 足し算は 1 回だけ
    mv   a0, s0
    li   a7, 36           # 符号なしで表示
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    mv   a0, s0
    li   a7, 1            # 符号付きで表示
    ecall
```

`4294967294` と `-2` が出ます。符号なしでは 4294967293 + 1 = 4294967294、符号付きでは −3 + 1 = −2。どちらの読み方でも、正しい足し算になっています。

このため、RISC-V には「符号付きの足し算」と「符号なしの足し算」の区別がありません。`add` と `sub` が 1 種類ずつあるだけです。回路が 1 つで済み、命令も少なくて済みます。

:::note 区別が要る演算もある
足し算、引き算、ビット演算、左シフトは、符号付きでも符号なしでも同じ結果になります。区別が要るのは、**ビット数を増やすとき**、**大小を比べるとき**、**右シフト**、それに割り算と、掛け算の上半分です。この章の残りは、このうち最初の 3 つの話です。
:::

## 符号拡張：ビット数を増やす {#sign-extension}

メモリには、1 バイト（8 ビット）単位で数を置けます。8 ビットの 2 の補数で表せる範囲は −128 から 127 です。この 8 ビットの数を 32 ビットのレジスタに読み込むとき、上の 24 ビットを何で埋めるかが問題になります。

```fig layout 8 ビットの f0 を 32 ビットに広げる 2 つの方法。符号なしとして読むなら 0 で埋め、符号付きとして読むなら符号ビットのコピーで埋める
{
  unit: 21,
  rows: [
    { label: 'メモリの 1 バイト', cells: [{ t: '', w: 24, kind: 'empty' }, { t: '1', w: 1, kind: 'accent' }, { t: '1110000', w: 7, kind: 'stack' }], note: '0xf0' },
    { label: 'lbu（0 で埋める）', cells: [{ t: '00000000 00000000 00000000', w: 24 }, { t: '1', w: 1, kind: 'accent' }, { t: '1110000', w: 7, kind: 'stack' }], note: '240' },
    { label: 'lb（符号ビットで埋める）', cells: [{ t: '11111111 11111111 11111111', w: 24, kind: 'accent' }, { t: '1', w: 1, kind: 'accent' }, { t: '1110000', w: 7, kind: 'stack' }], note: '−16' },
  ],
}
```

0 で埋める方法を**ゼロ拡張**、符号ビット（最上位ビット）と同じ値で埋める方法を**符号拡張**と呼びます。

RISC-V には、メモリから 1 バイトを読む命令が 2 つあります。`lbu`（load byte unsigned）はゼロ拡張、`lb`（load byte）は符号拡張をします。

```asm run title="同じ 1 バイトを、lb と lbu で読む"
    lb   a0, value        # 符号拡張して読む
    li   a7, 1
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    lbu  a0, value        # ゼロ拡張して読む
    li   a7, 1
    ecall

.data
value:
    .byte 0xf0
```

`-16` と `240` です。メモリにあるのは同じ `0xf0` の 1 バイトですが、読む命令によって、レジスタに入る数が変わります。`0xf0` を `0x7f` に変えると、最上位ビットが 0 なので、どちらも 127 になります。

符号拡張した結果を、16 進数で見てみます。

```asm run title="符号拡張した結果のビット"
    lb   a0, value
    li   a7, 34
    ecall

.data
value:
    .byte 0xf0
```

`0xfffffff0` です。上の 24 ビットが全部 1 になっています。

なぜ、1 で埋めると値が変わらないのでしょうか。輪で考えると、−16 は「0 から左回りに 16 戻った場所」です。輪が 256 個（8 ビット）でも約 43 億個（32 ビット）でも、0 の 16 個手前であることは同じです。0 の手前の数は、どの大きさの輪でも、上のほうのビットが 1 で埋まっています（−1 が全部 1 だったことを思い出してください）。

:::tip どちらを使うか
文字コードや色のように、マイナスにならないバイトは `lbu` で読みます。温度の差や座標の移動量のように、マイナスになりうる小さな数は `lb` で読みます。取り違えると、128 以上の値だけがおかしくなります。UTF-8 の日本語（第 2 章の `e3 81 82`）は、どのバイトも最上位ビットが 1 なので、`lb` で読むと全部マイナスになります。
:::

:::deep 命令に書いた数も符号拡張される
第 2 章で、`andi` などに直接書ける数は −2048〜2047 だと説明しました。これは、命令の中の 12 ビットを、2 の補数として符号拡張して使うためです。`addi a0, t0, -1` の命令の中には、12 ビットの `111111111111` が入っていて、実行するときに 32 ビットの全部 1 に広げられます。`not` という命令は実は存在せず、アセンブラが `xori`（相手は −1、つまり全部 1）に置き換えています。
:::

## 大小を比べる：slt と sltu {#compare}

2 つ目の、区別が要る演算は**比較**です。`0xffffffff` と 1 は、どちらが大きいでしょうか。符号なしなら約 43 億と 1 なので、前者です。符号付きなら −1 と 1 なので、後者です。読み方が決まらないと、答えが決まりません。

そのため、比べる命令は 2 つずつあります。`slt`（set if less than）は符号付きで、`sltu`（u は unsigned）は符号なしで比べ、「左が右より小さい」なら 1、そうでなければ 0 をレジスタに入れます。

```asm run title="-1 と 1 を、2 通りに比べる"
    li   t0, -1           # 0xffffffff
    li   t1, 1
    slt  a0, t0, t1       # 符号付きで t0 < t1 か
    li   a7, 1
    ecall
    li   a0, ' '
    li   a7, 11
    ecall
    sltu a0, t0, t1       # 符号なしで t0 < t1 か
    li   a7, 1
    ecall
```

`1 0` と出ます。符号付きでは −1 < 1 なので 1（はい）。符号なしでは 4294967295 < 1 ではないので 0（いいえ）です。

第 11 章で学ぶ分岐の命令にも、同じ区別があります。`blt` は符号付き、`bltu` は符号なしで比べます。

符号なしの比較には、うまい使い道があります。「0 以上で、10 より小さいか」という 2 つの条件を、1 回の比較で調べられるのです。

```asm run title="0 以上 10 未満かどうかを、1 回の比較で調べる"
    li   t0, -3           # 調べる数
    li   t1, 10
    sltu a0, t0, t1       # 符号なしで t0 < 10 か
    li   a7, 1
    ecall
```

`0`（範囲の外）と出ます。マイナスの数は、符号なしで読むととても大きな数になるので、「10 より小さい」という条件ではじかれます。`-3` を `7` や `10` に変えて確かめてください。配列の添字が範囲に入っているかを調べるときに、よく使われる手です。

## オーバーフロー：正の数どうしを足して負になる {#overflow}

符号付きの数にも、表せる範囲の端があります。いちばん大きい数に 1 を足してみます。

```asm run title="いちばん大きい数に 1 を足す"
    li   t0, 2147483647   # 0x7fffffff
    addi a0, t0, 1
    li   a7, 1
    ecall
```

`-2147483648` になります。プラスの数に 1 を足したのに、いちばん小さいマイナスの数になりました。

輪の図（図 3-1）の 3 枚目で見たとおりです。符号付きの目盛りでは、輪のいちばん下に切れ目があります。`0111…1` から 1 つ進むと `1000…0` で、ここで目盛りがプラスの端からマイナスの端へ飛びます。計算の結果が表せる範囲を越えてしまうことを、**オーバーフロー**と呼びます。

2 つの切れ目を整理しておきます。

| | 切れ目の場所 | 起きること |
| --- | --- | --- |
| 符号なしとして読むとき | `1111…1` と `0000…0` の間 | 4294967295 + 1 が 0 になる（第 2 章の桁あふれ） |
| 符号付きとして読むとき | `0111…1` と `1000…0` の間 | 2147483647 + 1 が −2147483648 になる |

RISC-V の CPU は、どちらが起きても、エラーにもしなければ、印も残しません。黙って計算を続けます。気を付けるのは、プログラムを書く人です。

オーバーフローは、思わぬところに潜みます。有名な例が「2 つの数の平均」です。15 億と 20 億の平均を、(a + b) ÷ 2 で求めます。

```asm run title="15 億と 20 億の平均（のつもり）"
    li   t0, 1500000000
    li   t1, 2000000000
    add  t2, t0, t1       # a + b
    li   t3, 2
    div  a0, t2, t3       # ÷ 2
    li   a7, 1
    ecall
```

`-397483648` と出ます。a も b も範囲に収まっていて、平均の 17 億 5 千万も収まるのに、途中の a + b（35 億）が約 21 億を越えたためです。

途中で大きな数を作らない式に変えれば、直せます。a + (b − a) ÷ 2 です。

```asm run title="途中であふれない平均"
    li   t0, 1500000000
    li   t1, 2000000000
    sub  t2, t1, t0       # b - a
    li   t3, 2
    div  t2, t2, t3       # ÷ 2
    add  a0, t0, t2       # a に足す
    li   a7, 1
    ecall
```

今度は `1750000000` です。

:::hist 21 億で止まったカウンタ
2014 年 12 月、動画サイト YouTube で、ある音楽ビデオの再生回数が 2,147,483,647 回を越えました。再生回数を 32 ビットの符号付きの数で数えていたため、YouTube はカウンタを 64 ビットに作り替えました。

もう 1 つ、これから来る例があります。多くのコンピュータは、時刻を「1970 年 1 月 1 日からの秒数」で覚えています。これを 32 ビットの符号付きの数で持っていると、2038 年 1 月 19 日に 2,147,483,647 秒に達し、次の 1 秒でマイナスに飛びます。**2038 年問題**と呼ばれ、64 ビットへの移行が進められています。
:::

## 右シフトは 2 種類：srl と sra {#shifts}

3 つ目の、区別が要る演算は**右シフト**です。第 2 章で、右へ 1 ビットずらすと半分になる、と説明しました。−8 を半分にしてみましょう。

```fig layout −8 を右へ 1 ビットずらす（8 ビットぶんだけ描いた）。空いた最上位に 0 を入れるか、符号ビットのコピーを入れるかで、結果が変わる
{
  unit: 40,
  rows: [
    { label: '元の数', cells: [{ t: '1', kind: 'accent' }, { t: '1' }, { t: '1' }, { t: '1' }, { t: '1' }, { t: '0' }, { t: '0' }, { t: '0' }], note: '−8' },
    { label: 'srl（0 を入れる）', cells: [{ t: '0', kind: 'empty' }, { t: '1', kind: 'accent' }, { t: '1' }, { t: '1' }, { t: '1' }, { t: '1' }, { t: '0' }, { t: '0' }], note: '大きなプラスの数になる' },
    { label: 'sra（符号ビットを入れる）', cells: [{ t: '1', kind: 'accent' }, { t: '1', kind: 'accent' }, { t: '1' }, { t: '1' }, { t: '1' }, { t: '1' }, { t: '0' }, { t: '0' }], note: '−4。符号が保たれる' },
  ],
}
```

- **論理右シフト**（`srl`、`srli`。l は logical）：空いた上のビットに 0 を入れる。符号なしの数を半分にする
- **算術右シフト**（`sra`、`srai`。a は arithmetic）：空いた上のビットに、元の符号ビットと同じ値を入れる。符号付きの数を半分にする

符号拡張と同じ考え方です。マイナスの数は上のビットが 1 で埋まっているので、右にずらしたあとも 1 で埋めておけば、マイナスのままになります。

```asm run title="-8 を、2 種類の右シフトで 1 ビットずらす"
    li   t0, -8
    srai a0, t0, 1        # 算術右シフト
    li   a7, 1
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    srli a0, t0, 1        # 論理右シフト
    li   a7, 1
    ecall
```

`-4` と `2147483644` です。マイナスの数を `srli` でずらすと、最上位に 0 が入ってプラスになり、とても大きな数に化けます。

左シフトには、この区別がありません。空くのは下のビットで、そこに入れるのはいつも 0 だからです。命令も `sll`（`slli`）の 1 種類だけです。

### 割り算との小さな違い

算術右シフトは「2 で割る」計算ですが、割り切れないマイナスの数では、`div` と答えが 1 つずれます。

```asm run title="-7 を 2 で割る：srai と div"
    li   t0, -7
    srai a0, t0, 1        # 右シフト
    li   a7, 1
    ecall
    li   a0, ' '
    li   a7, 11
    ecall
    li   t1, 2
    div  a0, t0, t1       # 割り算
    li   a7, 1
    ecall
```

`-4 -3` と出ます。−7 ÷ 2 は −3.5 です。`srai` は小さいほう（−4）へ、`div` は 0 に近いほう（−3）へ丸めます。プラスの数では、どちらも同じ結果（切り捨て）になります。

### シフトで符号拡張する

左シフトと算術右シフトを組み合わせると、好きなビット数の数を符号拡張できます。レジスタの下 8 ビットに入っている `0xf0` を、32 ビットの −16 に直してみます。

```asm run title="下 8 ビットを、32 ビットに符号拡張する"
    li   t0, 0xf0         # 符号なしで 240
    slli t0, t0, 24       # 8 ビットの符号ビットを、いちばん上まで持ち上げる
    srai a0, t0, 24       # 符号ビットで埋めながら、元の位置へ下ろす
    li   a7, 1
    ecall
```

`-16` です。`lb` が読み込むときにしていることを、シフト 2 回で行いました。`srai` を `srli` に変えると、240 のままです。

:::try 読み方を切り替える
下のブロックで、次のことを試してください。

- `li t0, -100` として、16 進数（34 番）で表示する。下の 2 桁 `9c` を 2 進数に直し、反転して 1 を足すと 100 になることを、紙の上で確かめる
- `li t0, 0x80000000` を、1 番と 36 番で表示する
- −1 を `srai` で何ビットずらしても −1 のままであることを確かめ、理由を考える
:::

```asm run title="練習用"
    li   t0, -100
    mv   a0, t0
    li   a7, 1
    ecall
```

:::key この章のまとめ
- ビットの並びには、**符号なし**と**符号付き**の 2 つの読み方がある。レジスタはどちらなのかを覚えていない。命令と、読む側が決める
- 符号付きの数は **2 の補数**で表す。最上位ビットが 1 なら負で、符号なしの値から 2 の 32 乗を引いた数になる。−1 は全部のビットが 1
- 32 ビットの符号付きの範囲は −2147483648 〜 2147483647。負のほうが 1 つ多い
- 符号の反転は「**全部のビットを反転して 1 を足す**」
- 2 の補数では、足し算と引き算の回路が、符号なしの数と共通で済む。引き算は「反転して 1 を足したものを足す」
- ビット数を増やすとき、符号付きの数は**符号拡張**（符号ビットのコピーで埋める）、符号なしの数はゼロ拡張する。`lb` と `lbu` の違い
- 比較は `slt`（符号付き）と `sltu`（符号なし）、右シフトは `sra`（算術）と `srl`（論理）を使い分ける
- 範囲を越える**オーバーフロー**が起きても、CPU は何も知らせない。2147483647 + 1 は −2147483648 になる
:::

## 確認問題 {#quiz}

この章の内容を、自分でプログラムを書いて確かめます。どの問題も、この章に出てきた命令を上から順に並べるだけで解けます。表示の番号（1 番は符号付き、36 番は符号なし）の使い分けにも気を付けてください。

:::quiz 8 ビットの数を符号拡張する
`t0` の下 8 ビットに、8 ビットの 2 の補数で表した数 `0b10011100` が入っています。これを 32 ビットに符号拡張して、コンソールに符号付きの 10 進数で表示してください。

```asm starter
    li   t0, 0b10011100
    # ここに続きを書く
```

```asm answer
    li   t0, 0b10011100
    slli t0, t0, 24
    srai a0, t0, 24
    li   a7, 1
    ecall
```

:::hint
左へ 24 ビットずらして 8 ビットの符号ビットを最上位に持っていき、算術右シフトで 24 ビット戻します。
:::
:::

:::quiz 2 通りに比べる
`t0` に −5、`t1` に 3 が入っています。「符号付きで比べて `t0` が `t1` より小さいか」と「符号なしで比べて `t0` が `t1` より小さいか」を、この順に、1（小さい）か 0（小さくない）で続けて表示してください。間に空白や改行は入れません。

```asm starter
    li   t0, -5
    li   t1, 3
    # ここに続きを書く
```

```asm answer
    li   t0, -5
    li   t1, 3
    li   a7, 1
    slt  a0, t0, t1
    ecall
    sltu a0, t0, t1
    ecall
```

:::hint
符号付きの比較は `slt`、符号なしの比較は `sltu` です。結果を `a0` に入れて、1 番で表示します。
:::
:::

:::quiz 20 億 + 20 億
`t0` と `t1` に 2000000000 が入っています。この 2 つを足した数を、コンソールに `4000000000` と正しく表示してください。

```asm starter
    li   t0, 2000000000
    li   t1, 2000000000
    # ここに続きを書く
```

```asm answer
    li   t0, 2000000000
    li   t1, 2000000000
    add  a0, t0, t1
    li   a7, 36
    ecall
```

:::hint
40 億は、符号付きの範囲（約 21 億まで）には収まりませんが、符号なしの範囲（約 43 億まで）には収まります。足し算の結果のビットは正しいので、表示の番号を選びます。
:::
:::

:::quiz マイナスの数を 8 で割る
`t0` に −1000 が入っています。これを右シフトで 8 で割り、コンソールに符号付きの 10 進数で表示してください（`-125` と表示されれば正解です）。

```asm starter
    li   t0, -1000
    # ここに続きを書く
```

```asm answer
    li   t0, -1000
    srai a0, t0, 3
    li   a7, 1
    ecall
```

:::hint
8 は 2 の 3 乗なので、3 ビットずらします。マイナスの数の符号を保つ右シフトは、算術右シフトです。
:::
:::
