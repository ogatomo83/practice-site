## レジスタだけでは足りない {#why}

ここまでのプログラムは、数をすべてレジスタに置いていました。レジスタは速いのですが、32 本しかありません。100 個の数の合計を出したくても、100 個を置く場所がないのです。

そこで**メモリ**を使います。第 8 章で見たとおり、メモリは番地の付いたバイトの並びです。このサイトの CPU には 65,536 バイトの RAM があります。

```fig graph レジスタとメモリの役割分担。計算はレジスタの上でしかできないので、メモリの数はいったんレジスタに読み込み、結果をメモリに書き戻す
{
  col: 470, row: 110,
  nodes: [
    { id: 'reg', label: 'レジスタ', sub: '32 本。速いが少ない。計算はここで', x: 0, y: 0, kind: 'accent', w: 230 },
    { id: 'mem', label: 'メモリ', sub: '65,536 バイト。広いが、計算はできない', x: 1, y: 0, kind: 'stack', w: 250 },
  ],
  edges: [
    { from: 'mem', to: 'reg', label: 'ロード（lw, lb …）', curve: -26 },
    { from: 'reg', to: 'mem', label: 'ストア（sw, sb …）', curve: -26 },
  ],
}
```

RISC-V の `add` や `sub` は、メモリの数を直接は扱えません。計算の前に、メモリからレジスタへ数を運びます。これを**ロード**（load、積み込む）と呼びます。結果をメモリへ運ぶのが**ストア**（store、しまう）です。

メモリに触る命令は、このロードとストアの 2 種類だけです。この章で使う命令を先に並べておきます。

| 命令 | 読み書きする大きさ | 意味 |
| --- | --- | --- |
| `lw` | 4 バイト（ワード） | メモリ → レジスタ |
| `sw` | 4 バイト | レジスタ → メモリ |
| `lb` / `lbu` | 1 バイト | メモリ → レジスタ（符号付き / 符号なし） |
| `sb` | 1 バイト | レジスタ → メモリ |
| `lh` / `lhu` / `sh` | 2 バイト（ハーフワード） | 同じく 2 バイト版 |

## lw と sw：ベース + オフセット {#lw-sw}

まず、メモリに数を置く方法です。プログラムの中に `.data` と書くと、そこから先は命令ではなく**データ**の置き場所になります。`.word` は 4 バイトの数を 1 つ置きます。`.text` と書くと、命令の置き場所に戻ります。

```asm run title="メモリから 2 つの数を読んで足す"
.data
a:  .word 100
b:  .word 23

.text
    la   t0, a          # t0 = a の番地
    lw   t1, 0(t0)      # t1 = 「t0 + 0」番地から 4 バイト
    lw   t2, 4(t0)      # t2 = 「t0 + 4」番地から 4 バイト
    add  a0, t1, t2
    li   a7, 1          # a0 を 10 進で表示
    ecall
```

123 と表示されます。新しく出てきたものが 3 つあります。

- `a:` と `b:` は**ラベル**です。第 11 章では命令に付けましたが、データにも付けられます。ラベルは、その場所の番地の別名です
- `la t0, a` は、ラベル `a` の番地を `t0` に入れます（次の節でくわしく見ます）
- `lw t1, 0(t0)` が**ロード**です。`t0` に入っている番地から 4 バイトを読んで、`t1` に入れます

`0(t0)` という書き方が、この章の中心です。括弧の中のレジスタを**ベース**、前の数を**オフセット**（ずれ）と呼びます。読む番地は「ベースの値 + オフセット」です。

```fig layout .data の中身。このサイトの CPU では .data は 0x8000 番地から始まる。t0 = 0x8000 のとき、0(t0) は a を、4(t0) は b を指す
{

  rows: [

      { t: '8004', kind: 'plain' }, { t: '8005', kind: 'plain' }, { t: '8006', kind: 'plain' }, { t: '8007', kind: 'plain' },
    ] },
    { label: 'バイト', cells: [
      { t: '64', kind: 'accent' }, { t: '00', kind: 'accent' }, { t: '00', kind: 'accent' }, { t: '00', kind: 'accent' },
      { t: '17', kind: 'stack' }, { t: '00', kind: 'stack' }, { t: '00', kind: 'stack' }, { t: '00', kind: 'stack' },

    { label: '指し方', cells: [ { t: '0(t0)', w: 4, kind: 'plain' }, { t: '4(t0)', w: 4, kind: 'plain' } ] },

```

100 は 16 進で 0x64、23 は 0x17 です。小さい桁のバイトが小さい番地に来るのは、リトルエンディアンだからでした（第 8 章）。ワードは 4 バイトなので、隣のワードの番地は 4 だけ大きくなります。

### sw でメモリに書く

書くほうは `sw` です。`a + b` を計算して、3 つ目のワード `c` にしまいます。

```asm run title="計算の結果をメモリにしまう" mem="0x8000,12"
.data
a:  .word 100
b:  .word 23
c:  .word 0

.text
    la   t0, a
    lw   t1, 0(t0)      # t1 = a
    lw   t2, 4(t0)      # t2 = b
    add  t3, t1, t2
    sw   t3, 8(t0)      # 「t0 + 8」番地（c）に t3 を書く
```

実行後のメモリの 0x8008 番地からの 4 バイトが `7b 00 00 00` になっています。0x7b は 123 です。

`sw` は、オペランド（命令に渡すもの）の向きに注意が要ります。ほかの命令は左端が「結果の入る先」でしたが、`sw` は**左が書く値、右が書く先**です。

| 命令 | 向き |
| --- | --- |
| `lw t1, 0(t0)` | `t1` ← メモリ |
| `sw t3, 8(t0)` | `t3` → メモリ |

:::note オフセットに書ける範囲
オフセットは -2048 から 2047 までの数です。命令の 32 ビットのうち 12 ビットがオフセットに割り当てられているためです（第 9 章の I 形式と S 形式）。負の数も書けるので、`-4(t0)` は「t0 の 1 ワード手前」を指します。
:::

## la は番地をレジスタに入れる {#la}

`la` は load address（番地を読み込む）の略です。名前に load と付きますが、メモリは読みません。**ラベルの番地という数**をレジスタに入れるだけです。

```asm run title="ラベルの番地を表示する"
.data
a:  .word 100
b:  .word 23
c:  .word 0

.text
    la   a0, a
    li   a7, 34         # a0 を 16 進で表示
    ecall
    li   a0, '\n'
    li   a7, 11         # a0 の文字を表示
    ecall
    la   a0, c
    li   a7, 34
    ecall
```

`a` は 0x00008000、`c` は 0x00008008 です。`.data` に書いた順に、0x8000 番地から詰めて置かれていることが分かります。

`la` と `lw` の違いを、表で確かめておきます。

| 書き方 | `t0` に入るもの |
| --- | --- |
| `la t0, a` | `a` の番地（0x8000） |
| `la t0, a` のあと `lw t0, 0(t0)` | `a` の中身（100） |
| `lw t0, a` | `a` の中身（100）。上の 2 命令を 1 行で書ける省略形 |

```asm run title="lw にラベルを直接書く"
.data
a:  .word 100

.text
    lw   a0, a          # la と lw をまとめた書き方
    li   a7, 1
    ecall
```

:::deep la の正体は lui と addi
`la` は疑似命令です。アセンブラが `lui`（上位 20 ビットを入れる）と `addi`（下位 12 ビットを足す）の 2 命令に置き換えます。番地は 32 ビットあるので、1 つの命令（32 ビット）の中に丸ごとは入らないためです。`li` で大きな数を入れるときと同じ仕組みです（第 10 章）。1 行に見えても、機械語では 2 命令ぶんの場所を使います。
:::

## 配列：番地 = 先頭 + i × 4 {#array}

同じ種類の数を、すき間なく並べたものが**配列**です。`.word` にカンマ区切りで数を書くと、その順に並びます。

```fig layout 5 個のワードの配列 nums。i 番目（0 から数える）の要素の番地は「先頭 + i × 4」
{
  unit: 28,
  rows: [
    { label: '番号 i', cells: [ { t: '0', w: 4 }, { t: '1', w: 4 }, { t: '2', w: 4 }, { t: '3', w: 4 }, { t: '4', w: 4 } ] },
    { label: '中身', cells: [ { t: '31', w: 4, kind: 'stack' }, { t: '4', w: 4, kind: 'stack' }, { t: '15', w: 4, kind: 'accent' }, { t: '92', w: 4, kind: 'stack' }, { t: '65', w: 4, kind: 'stack' } ] },
    { label: '番地', cells: [ { t: '0x8000', w: 4 }, { t: '0x8004', w: 4 }, { t: '0x8008', w: 4 }, { t: '0x800C', w: 4 }, { t: '0x8010', w: 4 } ], note: '4 ずつ増える' },
  ],
}
```

配列には「i 番目」を覚えておく仕組みはありません。あるのは先頭の番地だけです。i 番目の番地は、計算で求めます。

**i 番目の番地 = 先頭の番地 + i × 4**

4 を掛けるのは、要素 1 つが 4 バイトだからです。4 倍は、左に 2 ビットずらす `slli` で作れます（2 進数で 2 桁ずらすと 4 倍）。

```asm run title="配列の 2 番目を読む"
.data
nums: .word 31, 4, 15, 92, 65

.text
    la   t0, nums       # t0 = 先頭の番地
    li   t1, 2          # i = 2
    slli t2, t1, 2      # t2 = i × 4 = 8
    add  t2, t0, t2     # t2 = 先頭 + 8
    lw   a0, 0(t2)      # a0 = nums[2]
    li   a7, 1
    ecall
```

15 と表示されます。`li t1, 2` の 2 を 0 から 4 まで変えて、それぞれの要素が読めることを確かめてください。

### 配列の合計

i を 0 から順に増やしながら読めば、全部の要素をたどれます。第 11 章のループと組み合わせます。

```asm run title="配列の合計（番号で数える）"
.data
nums: .word 31, 4, 15, 92, 65

.text
    la   t0, nums       # 先頭の番地
    li   t1, 0          # i = 0
    li   t2, 5          # 要素の数
    li   a0, 0          # 合計
loop:
    bge  t1, t2, done   # i >= 5 なら終わり
    slli t3, t1, 2
    add  t3, t0, t3     # nums[i] の番地
    lw   t4, 0(t3)
    add  a0, a0, t4     # 合計 += nums[i]
    addi t1, t1, 1      # i += 1
    j    loop
done:
    li   a7, 1
    ecall
```

31 + 4 + 15 + 92 + 65 = 207 です。

### 番地そのものを進める

毎回 `i × 4` を計算し直すのは、少しむだです。**番地を入れたレジスタを、4 ずつ進める**書き方もあります。番地を入れたレジスタを**ポインタ**（pointer、指すもの）と呼びます。

```asm run title="配列の合計（ポインタを進める）"
.data
nums: .word 31, 4, 15, 92, 65

.text
    la   t0, nums       # t0 = いま見ている要素の番地
    addi t1, t0, 20     # t1 = 終わりの番地（先頭 + 5 × 4）
    li   a0, 0
loop:
    bge  t0, t1, done   # 終わりの番地まで来たら終わり
    lw   t4, 0(t0)
    add  a0, a0, t4
    addi t0, t0, 4      # 次の要素へ
    j    loop
done:
    li   a7, 1
    ecall
```

結果は同じ 207 です。ループの中の命令が 7 個から 5 個に減りました。出力欄の「実行した命令数」を、1 つ前のプログラムと比べてみてください。

### 配列の最大

合計を「これまでの最大」に変えれば、最大値が求まります。最初の要素を仮の最大にして、残りと比べていきます。

```asm run title="配列の最大"
.data
nums: .word 31, 4, 15, 92, 65

.text
    la   t0, nums
    addi t1, t0, 20     # 終わりの番地
    lw   a0, 0(t0)      # 仮の最大 = nums[0]
    addi t0, t0, 4
loop:
    bge  t0, t1, done
    lw   t4, 0(t0)
    ble  t4, a0, skip   # nums[i] <= 最大 なら何もしない
    mv   a0, t4         # 最大を更新
skip:
    addi t0, t0, 4
    j    loop
done:
    li   a7, 1
    ecall
```

### 配列に書く

`sw` を使えば、配列の中身を作ることもできます。`.space 20` は、20 バイトの場所を 0 で埋めて確保します。そこへ 0 × 0、1 × 1、2 × 2 … を書き込みます。

```asm run title="配列に 2 乗の数を書く" mem="0x8000,20"
.data
sq: .space 20           # ワード 5 個ぶんの場所

.text
    la   t0, sq
    li   t1, 0          # i
    li   t2, 5
loop:
    bge  t1, t2, done
    mul  t3, t1, t1     # i × i
    sw   t3, 0(t0)      # 書く
    addi t0, t0, 4
    addi t1, t1, 1
    j    loop
done:
```

メモリは `00 00 00 00`、`01 00 00 00`、`04 00 00 00`、`09 00 00 00`、`10 00 00 00` と並びます。最後の 0x10 は 16 です。

## 1 バイトだけ読み書きする：lb、lbu、sb {#bytes}

文字のように、1 バイトで足りるデータもあります。1 バイトを読むのが `lb` と `lbu`、書くのが `sb` です。データを置くときは `.byte` を使います。

まず、同じ場所を `lw` と `lbu` で読み比べます。

```asm run title="ワードをバイトごとに読む"
.data
x:  .word 0x12345678

.text
    la   t0, x
    lbu  a0, 0(t0)      # いちばん小さい番地の 1 バイト
    li   a7, 34
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    lbu  a0, 3(t0)      # 3 つ先の 1 バイト
    li   a7, 34
    ecall
```

0x00000078 と 0x00000012 が出ます。メモリには 78、56、34、12 の順に並んでいて、`lbu` はそのうちの 1 バイトだけを取り出します。オフセットが 1 ずつ進む点が、ワードとの違いです。

### lb と lbu の違いは、上の 24 ビットの埋め方

レジスタは 32 ビットです。8 ビットを読んだら、残りの 24 ビットを何かで埋めなければなりません。

```fig layout バイト 0xF0 を読んだときのレジスタ。lb は符号ビット（いちばん上のビット）を上に広げ、lbu は 0 で埋める
{
  unit: 40,
  rows: [
    { label: 'メモリ', cells: [ { t: '', w: 6, kind: 'plain' }, { t: 'F0', w: 2, kind: 'accent' } ], note: '1 バイト（2 進で 1111 0000）' },
    { label: 'lb', cells: [ { t: 'FF', w: 2, kind: 'heap' }, { t: 'FF', w: 2, kind: 'heap' }, { t: 'FF', w: 2, kind: 'heap' }, { t: 'F0', w: 2, kind: 'accent' } ], note: '符号拡張 → -16' },
    { label: 'lbu', cells: [ { t: '00', w: 2, kind: 'plain' }, { t: '00', w: 2, kind: 'plain' }, { t: '00', w: 2, kind: 'plain' }, { t: 'F0', w: 2, kind: 'accent' } ], note: 'ゼロ拡張 → 240' },
  ],
}
```

- `lb`：バイトを**符号付き**（-128〜127）として読みます。いちばん上のビットを上の 24 ビットに写します。第 3 章の符号拡張です
- `lbu`：バイトを**符号なし**（0〜255）として読みます。上は 0 で埋めます。u は unsigned（符号なし）の u です

```asm run title="同じバイトを lb と lbu で読む"
.data
v:  .byte 0xF0

.text
    la   t0, v
    lb   a0, 0(t0)
    li   a7, 1
    ecall               # -16
    li   a0, ' '
    li   a7, 11
    ecall
    lbu  a0, 0(t0)
    li   a7, 1
    ecall               # 240
```

文字や色の番号のように、負の数にならないデータは `lbu` で読みます。迷ったら `lbu` です。

### sb は下の 8 ビットだけを書く

`sb` は、レジスタの下の 8 ビットだけをメモリに書きます。隣のバイトには触りません。

```asm run title="ワードの真ん中の 1 バイトだけ書き換える" mem="0x8000,4"
.data
x:  .word 0x12345678

.text
    la   t0, x
    li   t1, 0xAB
    sb   t1, 1(t0)      # 0x8001 番地の 1 バイトだけ
    lw   a0, 0(t0)
    li   a7, 34
    ecall
```

メモリは `78 ab 34 12` になり、ワードとして読むと 0x1234ab78 です。0x56 だったバイトだけが変わりました。

### 2 バイトは lh、lhu、sh

2 バイト（ハーフワード）を扱う命令もあります。考え方は 1 バイトのときと同じで、`lh` は符号拡張、`lhu` はゼロ拡張です。データは `.half` で置きます。

```asm run title="2 バイトを読む"
.data
h:  .half 0xFFFE, 1000

.text
    la   t0, h
    lh   a0, 0(t0)      # 符号付き：-2
    li   a7, 1
    ecall
    li   a0, ' '
    li   a7, 11
    ecall
    lhu  a0, 0(t0)      # 符号なし：65534
    li   a7, 1
    ecall
    li   a0, ' '
    li   a7, 11
    ecall
    lh   a0, 2(t0)      # 次のハーフワードは 2 バイト先
    li   a7, 1
    ecall
```

## 文字列は、NUL で終わるバイトの並び {#string}

第 2 章で見たとおり、文字は数です。`A` は 65、`a` は 97 でした。**文字列**は、その数を 1 バイトずつ並べた配列です。

困るのは長さです。配列には「何個あるか」が書かれていません。そこで、文字列の最後に**値が 0 のバイト**を 1 つ置いて、終わりの目印にします。このバイトを **NUL**（ヌル）と呼び、この形の文字列を NUL 終端の文字列と呼びます。

```fig layout .asciz "CPU!" が置く 5 バイト。最後の 00 が終わりの目印（NUL）
{
  unit: 56,
  rows: [
    { label: '番地', cells: [ { t: '0x8000' }, { t: '0x8001' }, { t: '0x8002' }, { t: '0x8003' }, { t: '0x8004' } ] },
    { label: '文字', cells: [ { t: 'C', kind: 'stack' }, { t: 'P', kind: 'stack' }, { t: 'U', kind: 'stack' }, { t: '!', kind: 'stack' }, { t: 'NUL', kind: 'accent' } ] },
    { label: 'バイト', cells: [ { t: '43', kind: 'stack' }, { t: '50', kind: 'stack' }, { t: '55', kind: 'stack' }, { t: '21', kind: 'stack' }, { t: '00', kind: 'accent' } ] },
  ],
}
```

`.asciz "CPU!"` と書くと、文字のバイトと最後の NUL を置いてくれます。z は zero の z です。`.string` も同じ意味です。NUL を付けない `.ascii` もあります。

### 1 文字ずつ読んで表示する

文字列をたどるループは、「1 バイト読む → 0 なら終わり → 何かする → 番地を 1 進める」の形になります。

```asm run title="文字列を 1 文字ずつ表示する"
.data
msg: .asciz "CPU!"

.text
    la   t0, msg
loop:
    lbu  a0, 0(t0)      # 1 文字読む
    beqz a0, done       # NUL なら終わり
    li   a7, 11         # その文字を表示
    ecall
    li   a0, '\n'       # 見やすいように改行も出す
    ecall
    addi t0, t0, 1      # 次の文字へ（1 バイトなので +1）
    j    loop
done:
```

配列の合計のループと見比べてください。違いは 3 つだけです。`lw` が `lbu` に、`+4` が `+1` に、終わりの条件が「個数」から「0 が出たら」に変わりました。

:::note 文字列をまとめて表示する ecall
`a7` に 4 を入れて `ecall` すると、`a0` の番地から NUL までをまとめて表示します。中でやっていることは、上のループと同じです。第 14 章で、この裏側を自分で作ります。
:::

### 文字数を数える

NUL が出るまでに進んだ回数が、文字列の長さです。

```asm run title="文字数を数える"
.data
msg: .asciz "Hello, RISC-V"

.text
    la   t0, msg
    li   a0, 0          # 文字数
loop:
    lbu  t1, 0(t0)
    beqz t1, done
    addi a0, a0, 1
    addi t0, t0, 1
    j    loop
done:
    li   a7, 1
    ecall
```

13 です。NUL 自身は数えません。メモリの上では 14 バイトを使っています。

数えているのは**バイト数**だという点に注意します。日本語の文字は、UTF-8 では 1 文字が 3 バイトです（第 2 章）。`msg` を `"あい"` に変えて実行すると、2 ではなく 6 が出ます。

### 小文字を大文字にする

ASCII では、小文字は大文字よりちょうど 32 大きい数です（`a` = 97、`A` = 65）。`a` から `z` の範囲の文字だけ 32 を引いて、同じ場所に `sb` で書き戻します。

```asm run title="文字列を大文字に書き換える"
.data
msg: .asciz "Hello, risc-v!"

.text
    la   t0, msg
    li   t2, 'a'
    li   t3, 'z'
loop:
    lbu  t1, 0(t0)
    beqz t1, done
    blt  t1, t2, next   # 'a' より小さい → 小文字ではない
    bgt  t1, t3, next   # 'z' より大きい → 小文字ではない
    addi t1, t1, -32    # 大文字にする
    sb   t1, 0(t0)      # 同じ場所に書き戻す
next:
    addi t0, t0, 1
    j    loop
done:
    la   a0, msg
    li   a7, 4          # 文字列をまとめて表示
    ecall
```

`HELLO, RISC-V!` になります。範囲の確認（`blt` と `bgt` の 2 行）を消すと、大文字やカンマや空白からも 32 を引いてしまいます。先頭の `H` は `(` に変わり、空白（32）は 0、つまり NUL になって、表示がそこで切れます。2 行を消して確かめてみてください。

### 文字列をコピーする

読んだバイトを別の場所に書けば、コピーになります。**NUL もコピーする**のがこつです。コピーしてから 0 かどうかを調べます。

```asm run title="文字列を別の場所にコピーする"
.data
src: .asciz "copy me"
dst: .space 16          # コピー先（16 バイト）

.text
    la   t0, src
    la   t1, dst
loop:
    lbu  t2, 0(t0)
    sb   t2, 0(t1)      # 先に書く（NUL も書かれる）
    beqz t2, done       # NUL を書いたら終わり
    addi t0, t0, 1
    addi t1, t1, 1
    j    loop
done:
    la   a0, dst
    li   a7, 4
    ecall
```

:::warn コピー先の広さは、だれも確かめてくれない
コピー先を `.space 4` に減らしても、このプログラムはエラーにならずに動きます。4 バイトを越えた分は、その先にあるメモリを黙って上書きします。これが**バッファオーバーフロー**で、本物のソフトウェアでも重大な不具合の原因になってきました。確保した広さを越えないことは、プログラムを書く側の責任です。
:::

## 整列：lw の番地は 4 の倍数 {#align}

`lw` と `sw` には決まりがあります。**番地は 4 の倍数**でなければなりません。この決まりを**整列**（アラインメント）と呼びます。わざと破ってみます。

```asm run error title="4 の倍数でない番地を lw で読む"
.data
nums: .word 31, 4, 15

.text
    la   t0, nums
    addi t0, t0, 1      # 4 ではなく 1 だけ進めてしまった
    lw   a0, 0(t0)
    li   a7, 1
    ecall
```

エラーで止まります。エラーの文には、止まった命令の番地と行番号も出ます。

:::err 番地 0x00008001 は 4 の倍数ではないので lw で読めません
`lw` に渡した番地が 4 の倍数ではない、というエラーです。配列のポインタを進めるときに、`+4` を `+1` と書き間違えるとよく起きます。ワードの配列は 4 ずつ、バイトの配列は 1 ずつ進めます。
:::

| 命令 | 番地の決まり |
| --- | --- |
| `lw` `sw` | 4 の倍数 |
| `lh` `lhu` `sh` | 2 の倍数 |
| `lb` `lbu` `sb` | どこでもよい |

:::note 本物の CPU ではどうなるか
整列していない番地の読み書きを、時間をかけて処理してくれる CPU もあれば、例外（第 19 章）を起こす CPU もあります。RISC-V では、どちらにするかは CPU の作り手が決めます。どちらにしても速くはならないので、ワードは 4 の倍数の番地に置くのが共通の習慣です。このサイトの CPU は、間違いに気づきやすいようにエラーで止めます。
:::

### .word は自動で整列する

では、1 バイトのデータの後ろにワードを置くと、番地はどうなるでしょうか。

```asm run title="バイトの後ろに置いたワードの番地"
.data
flag:  .byte 1
count: .word 500

.text
    la   a0, flag
    li   a7, 34
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    la   a0, count
    li   a7, 34
    ecall
```

`flag` は 0x00008000、`count` は 0x00008004 です。0x8001 にはなりません。このサイトのアセンブラは、`.word` を置く前に、番地を 4 の倍数まで進めます。

```fig layout .byte 1 個のあとに .word を置いたとき。間の 3 バイトは使われない詰め物（パディング）になる
{
  unit: 44,
  rows: [
    { label: '番地', cells: [ { t: '8000' }, { t: '8001' }, { t: '8002' }, { t: '8003' }, { t: '8004' }, { t: '8005' }, { t: '8006' }, { t: '8007' } ] },
    { label: '中身', cells: [ { t: 'flag', kind: 'accent' }, { t: '—', kind: 'plain' }, { t: '—', kind: 'plain' }, { t: '—', kind: 'plain' }, { t: 'count = 500', w: 4, kind: 'stack' } ], note: '— は詰め物' },
  ],
}
```

文字列の後ろも同じです。`.asciz "CPU!"` は 5 バイトなので、次の `.word` は 3 バイト空けて置かれます。自分で整列させたいときは `.align 2` と書きます。番地を 2 の 2 乗、つまり 4 の倍数まで進めるという意味です。

## 番地を間違えると何が起きるか {#bounds}

配列の外の番地を読もうとしても、CPU は止めてくれません。CPU にとっては、どの番地もただのメモリだからです。

```asm run title="配列の外を読んでしまう"
.data
nums:   .word 31, 4, 15
secret: .word 777

.text
    la   t0, nums
    lw   a0, 12(t0)     # nums[3]？ 要素は 3 個しかない
    li   a7, 1
    ecall
```

777 が出ます。`nums` の 3 個の後ろには、たまたま `secret` が置かれていました。エラーにはならず、間違った数が黙って読めてしまいます。ループの終わりの条件を 1 つ間違えただけで、こうなります。

止まるのは、メモリも機器もない番地に触ったときだけです。

```asm run error title="何もない番地を読む"
    li   t0, 0x30000    # RAM でも画面でも入出力でもない番地
    lw   a0, 0(t0)
```

:::err 番地 0x00030000 にはメモリも入出力もないので、lw で読めません
読み書きしようとした番地に、何もつながっていない、というエラーです。番地を入れたレジスタに、思ったとおりの値が入っているかを確かめます。`la` を忘れて、0 や小さな数のまま使っていることもよくあります。
:::

このサイトの CPU では、RAM は 0x0000〜0xFFFF です。その外にある画面と入出力の番地は、第 14 章で使います。

:::try 逆順に表示する
下のプログラムは、配列を先頭から順に表示します。これを書き換えて、後ろから順（65、92、15、4、31）に表示してください。ポインタを最後の要素の番地から始めて、4 ずつ**引いて**いきます。
:::

```asm run title="練習：配列を表示する"
.data
nums: .word 31, 4, 15, 92, 65

.text
    la   t0, nums
    addi t1, t0, 20     # 終わりの番地
loop:
    bge  t0, t1, done
    lw   a0, 0(t0)
    li   a7, 1
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    addi t0, t0, 4
    j    loop
done:
```

:::key まとめ
- 計算はレジスタの上でしかできない。メモリの数は、ロード（`lw` など）でレジスタに読み、ストア（`sw` など）で書き戻す
- 読み書きする番地は「ベースのレジスタ + オフセット」。`4(t0)` は `t0 + 4` 番地
- `la` はラベルの番地をレジスタに入れる。メモリは読まない
- 配列の i 番目の番地は「先頭 + i × 4」（ワードの場合）。ポインタを 4 ずつ進めてたどることもできる
- 1 バイトは `lb`（符号拡張）、`lbu`（ゼロ拡張）、`sb`。文字には `lbu` を使う
- 文字列は、NUL（0 のバイト）で終わるバイトの配列。長さは、NUL が出るまで数えて初めて分かる
- `lw` と `sw` の番地は 4 の倍数。配列の外を読み書きしても、CPU は止めてくれない
:::

## 確認問題 {#quiz}

この章の内容を、自分でプログラムを書いて確かめます。データは問題の側で用意してあり、あなたのプログラムの後ろに自動でつながります。自分では `.data` を書かずに、命令だけを書いてください。

:::quiz 配列の合計
ラベル `nums` の番地から、ワードが 7 個並んでいます。7 個の合計を、10 進でコンソールに表示してください。負の数も混ざっています。

```asm starter
# nums に 7 個のワードがあります
    la   t0, nums

```

```asm answer
    la   t0, nums
    addi t1, t0, 28
    li   a0, 0
loop:
    bge  t0, t1, done
    lw   t2, 0(t0)
    add  a0, a0, t2
    addi t0, t0, 4
    j    loop
done:
    li   a7, 1
    ecall
```

```asm given
.data
nums: .word 12, -7, 30, 5, -18, 41, 9
```

:::hint
終わりの番地は「先頭 + 7 × 4」です。ポインタは 4 ずつ進めます。1 ずつ進めると、整列のエラーになります。
:::
:::

:::quiz 文字を数える
ラベル `text` の番地に、NUL で終わる文字列があります。その中に小文字の `a` が何個あるかを数えて、10 進でコンソールに表示してください。

```asm starter
# text に NUL で終わる文字列があります
    la   t0, text

```

```asm answer
    la   t0, text
    li   a0, 0
    li   t2, 'a'
loop:
    lbu  t1, 0(t0)
    beqz t1, done
    bne  t1, t2, next
    addi a0, a0, 1
next:
    addi t0, t0, 1
    j    loop
done:
    li   a7, 1
    ecall
```

```asm given
.data
text: .asciz "a banana and a papaya"
```

:::hint
1 バイト読んで、0 なら終わり、`'a'` と等しければ数を 1 増やします。等しくなくても、ポインタは必ず 1 進めます。
:::
:::

:::quiz 配列を 2 倍に書き換える
ラベル `vals` の番地（0x8000）から、ワードが 6 個並んでいます。6 個それぞれを 2 倍にして、同じ場所に書き戻してください。表示は要りません。実行後のメモリの中身で判定します。

```asm starter
# vals に 6 個のワードがあります。2 倍にして書き戻します
    la   t0, vals

```

```asm answer mem="0x8000,24"
    la   t0, vals
    addi t1, t0, 24
loop:
    bge  t0, t1, done
    lw   t2, 0(t0)
    slli t2, t2, 1
    sw   t2, 0(t0)
    addi t0, t0, 4
    j    loop
done:
```

```asm given
.data
vals: .word 3, -5, 1000, 0, 77, 200
```

:::hint
`lw` で読み、2 倍にして（`slli` で 1 ビット左にずらすか、自分自身を `add` する）、`sw` で同じ番地に書きます。`sb` だと下の 1 バイトしか書き換わりません。
:::
:::

:::quiz 大文字にして表示する
ラベル `msg` の番地に、NUL で終わる文字列があります。小文字（`a`〜`z`）だけを大文字に変えて、コンソールに表示してください。数字、空白、記号はそのまま表示します。

```asm starter
# msg に NUL で終わる文字列があります
    la   t0, msg

```

```asm answer
    la   t0, msg
    li   t2, 'a'
    li   t3, 'z'
    li   a7, 11
loop:
    lbu  a0, 0(t0)
    beqz a0, done
    blt  a0, t2, show
    bgt  a0, t3, show
    addi a0, a0, -32
show:
    ecall
    addi t0, t0, 1
    j    loop
done:
```

```asm given
.data
msg: .asciz "zero to a 32-bit risc-v cpu!"
```

:::hint
`'a'` 以上かつ `'z'` 以下のときだけ 32 を引きます。1 文字ずつ `ecall`（`a7` = 11）で出しても、書き戻してからまとめて `ecall`（`a7` = 4）で出しても構いません。
:::
:::
