## 機器も、メモリの番地に住んでいる {#mmio}

CPU ができることは、計算と、メモリの読み書きと、ジャンプだけでした。「文字を表示する」という命令も、「キーを読む」という命令もありません。それなのに、コンピュータは画面に絵を出し、キーボードに反応します。

答えは単純です。**機器を、メモリの番地の上に置く**のです。ある決まった番地に書き込むと、メモリではなく画面につながっていて、点が光ります。別の番地を読むと、メモリではなくキーボードにつながっていて、押されたキーが読めます。

この方法を**メモリマップド I/O**（memory-mapped I/O）と呼びます。I/O は input / output（入力と出力）の略です。CPU の側は何も変わりません。使う命令は、第 12 章の `lw`、`sw`、`lbu`、`sb` のままです。


このサイトの CPU では、機器は次の番地にあります。番地の割り当ては、コンピュータごとに違います。この表は**このサイトの CPU だけの決まり**です。

| 番地 | 機器 | 使い方 |
| --- | --- | --- |
| `0x10000`〜`0x103FF` | 画面 | 1 バイト書くと、点が 1 個その色になる |
| `0x20000` | コンソール | 1 バイト書くと、その文字が出る |
| `0x20004` | キーボード（押されたキー） | 読むと、押されたキーのコード。なければ 0 |
| `0x20008` | 乱数 | 読むたびに、でたらめな 32 ビットの数 |
| `0x2000C` | 命令数 | 読むと、ここまでに実行した命令の数 |
| `0x20010` | フレームの合図 | 書くと、画面を 1 回描き直す |
| `0x20014` | キーボード（押しっぱなし） | 読むと、いま押されているキーがビットで分かる |

この章では、これを上から順に使っていきます。

## コンソール：0x20000 に 1 バイト書く {#console}

いちばん簡単な機器はコンソールです。0x20000 番地に 1 バイト書くと、その文字が表示されます。

```asm run title="番地に書くだけで、文字が出る"
    li   t0, 0x20000    # コンソールの番地
    li   t1, 'A'
    sb   t1, 0(t0)      # 書く → A が出る
    li   t1, 'B'
    sb   t1, 0(t0)      # 同じ番地にもう 1 回 → B が出る
    li   t1, '\n'
    sb   t1, 0(t0)
```

`AB` と出ます。`ecall` は使っていません。使ったのは `sb` だけです。

同じ番地に 2 回書いたのに、`A` が `B` で上書きされず、2 文字とも出ている点に注目してください。ここはメモリではありません。書いた値は覚えられず、そのまま機器に送られます。

何度も使う番地には、名前を付けておくと読みやすくなります。`.equ 名前, 値` で、数に名前を付けられます。

```asm run title="文字列を 1 文字ずつコンソールに送る"
.equ CONSOLE, 0x20000

.data
msg: .asciz "Hello, I/O!\n"

.text
    li   t0, CONSOLE
    la   t1, msg
loop:
    lbu  t2, 0(t1)      # 1 文字読む
    beqz t2, done       # NUL なら終わり
    sb   t2, 0(t0)      # コンソールに書く
    addi t1, t1, 1
    j    loop
done:
```

第 12 章の「1 文字ずつ表示する」ループと同じ形です。`ecall` の代わりに `sb` が入りました。

日本語も出せます。コンソールは、送られてきたバイトを UTF-8 として組み立てて表示します。`あ` は E3、81、82 の 3 バイトでした（第 2 章）。

```asm run title="3 バイトを送ると、1 文字になる"
.equ CONSOLE, 0x20000
    li   t0, CONSOLE
    li   t1, 0xE3
    sb   t1, 0(t0)
    li   t1, 0x81
    sb   t1, 0(t0)
    li   t1, 0x82
    sb   t1, 0(t0)      # 3 バイトそろって「あ」になる
```

## 数を文字にして出す：print_int を作る {#print-int}

コンソールに送れるのは文字だけです。では、レジスタに入っている数 507 を表示するには、どうすればよいでしょうか。

507 をそのまま送っても、`507` とは出ません。`5`、`0`、`7` という **3 つの文字**に直して、1 つずつ送る必要があります。

### 1 桁なら、'0' を足すだけ

数字の文字は、ASCII で `'0'` = 48 から `'9'` = 57 まで順に並んでいます。0〜9 の数に 48（`'0'`）を足せば、その数字の文字になります。

```asm run title="1 桁の数を文字にする"
.equ CONSOLE, 0x20000
    li   t0, CONSOLE
    li   a0, 7          # 数の 7
    addi t1, a0, '0'    # 7 + 48 = 55 = 文字の '7'
    sb   t1, 0(t0)
```

### 10 で割った余りが、いちばん下の桁

2 桁以上の数は、桁に分けます。10 で割った**余り**が、いちばん下の桁です。**商**（割り算の答え）には、残りの桁が入っています。商が 0 になるまで繰り返します。

```fig layout 507 を桁に分ける。余りは下の桁から順に出てくるので、表示するときは逆の順に送る
{
  unit: 34,
  rows: [
    { label: '1 回目', cells: [ { t: '507 ÷ 10', w: 5 }, { t: '商 50', w: 4, kind: 'stack' }, { t: '余り 7', w: 4, kind: 'accent' } ] },
    { label: '2 回目', cells: [ { t: '50 ÷ 10', w: 5 }, { t: '商 5', w: 4, kind: 'stack' }, { t: '余り 0', w: 4, kind: 'accent' } ] },
    { label: '3 回目', cells: [ { t: '5 ÷ 10', w: 5 }, { t: '商 0', w: 4, kind: 'stack' }, { t: '余り 5', w: 4, kind: 'accent' } ], note: '商が 0 → 終わり' },
    { label: '出た順', cells: [ { t: '7', w: 2, kind: 'accent' }, { t: '0', w: 2, kind: 'accent' }, { t: '5', w: 2, kind: 'accent' } ], note: '逆から送ると 507' },
  ],
}
```

困るのは、桁が**下から**出てくることです。そのまま送ると `705` になってしまいます。そこで、出てきた文字をいったんメモリにためておき、最後に逆の順で送ります。ためる場所には、スタックが使えます（第 13 章）。

```asm run title="符号なしの数を 10 進で表示する関数"
.equ CONSOLE, 0x20000

main:
    li   a0, 507
    call print_uint
    li   a0, 0
    call print_uint
    li   a0, 1234567890
    call print_uint
    li   a7, 10
    ecall

# print_uint(a0)：a0 を符号なしの 10 進で表示して、改行する
print_uint:
    addi sp, sp, -16    # 文字をためる場所（最大 10 桁なので 16 バイトで足りる）
    mv   t1, sp         # t1 = 次に文字を置く番地
    li   t2, 10
pu_split:
    remu t3, a0, t2     # 余り = いちばん下の桁
    divu a0, a0, t2     # 商 = 残りの桁
    addi t3, t3, '0'    # 数 → 文字
    sb   t3, 0(t1)      # ためる
    addi t1, t1, 1
    bnez a0, pu_split   # 商が 0 になるまで
    li   t0, CONSOLE
pu_send:
    addi t1, t1, -1     # ためた順の逆にたどる
    lbu  t3, 0(t1)
    sb   t3, 0(t0)      # コンソールに送る
    bne  t1, sp, pu_send
    li   t3, '\n'
    sb   t3, 0(t0)
    addi sp, sp, 16
    ret
```

507、0、1234567890 と表示されます。`remu` は符号なしの余り、`divu` は符号なしの割り算です。

割ってから 0 かどうかを調べる形（`bnez` がループの最後にある）にしているので、0 を渡しても `0` が 1 桁出ます。先に調べる形にすると、0 のときに何も表示されません。

### 負の数

負の数は、先に `-` を送り、符号を反転して正の数にしてから、同じ手順を使います。

```asm run title="符号付きの数を 10 進で表示する関数"
.equ CONSOLE, 0x20000

main:
    li   a0, 42
    call print_int
    li   a0, -2048
    call print_int
    li   a7, 10
    ecall

# print_int(a0)：a0 を符号付きの 10 進で表示して、改行する
print_int:
    addi sp, sp, -16
    li   t0, CONSOLE
    bgez a0, pi_plus    # 0 以上ならそのまま
    li   t3, '-'
    sb   t3, 0(t0)      # 先に - を送る
    neg  a0, a0         # 符号を反転
pi_plus:
    mv   t1, sp
    li   t2, 10
pi_split:
    remu t3, a0, t2
    divu a0, a0, t2
    addi t3, t3, '0'
    sb   t3, 0(t1)
    addi t1, t1, 1
    bnez a0, pi_split
pi_send:
    addi t1, t1, -1
    lbu  t3, 0(t1)
    sb   t3, 0(t0)
    bne  t1, sp, pi_send
    li   t3, '\n'
    sb   t3, 0(t0)
    addi sp, sp, 16
    ret
```

数を 1 つ表示するだけで、割り算を何回も行い、文字をためて、逆順に送っています。ふだん何気なく使っている「数の表示」は、これだけの仕事でできています。

## ecall の裏側 {#ecall}

これまで、数の表示には `li a7, 1` と `ecall` を使ってきました。この 2 行と、いま作った `print_int` は、同じ仕事をしています。

```asm run title="ecall と、自分で書いた出力を並べる"
.equ CONSOLE, 0x20000

.data
msg: .asciz "ecall\n"

.text
    la   a0, msg
    li   a7, 4          # ecall 4：文字列を表示
    ecall

    li   t0, CONSOLE    # 同じことを、番地への書き込みで
    li   t1, 's'
    sb   t1, 0(t0)
    li   t1, 'b'
    sb   t1, 0(t0)
    li   t1, '\n'
    sb   t1, 0(t0)
```

`ecall` は environment call の略で、「プログラムを動かしている外側の環境に、仕事を頼む」命令です。`a7` に頼みたい仕事の番号を、`a0` に引数を入れて実行します。

```fig seq ecall は「外側の環境」に仕事を頼む命令。頼まれた側が、機器の番地に書き込む
{
  colw: 250,
  actors: [ { id: 'p', label: 'あなたのプログラム', kind: 'accent' }, { id: 'e', label: '外側の環境', kind: 'stack' }, { id: 'c', label: 'コンソール', kind: 'ext' } ],
  msgs: [
    { note: 'a7 = 1、a0 = 507', at: 'p' },
    { from: 'p', to: 'e', label: 'ecall', style: 'accent' },
    { note: '507 を桁に分けて文字にする', at: 'e' },
    { from: 'e', to: 'c', label: "'5'、'0'、'7' を書く" },
    { from: 'e', to: 'p', label: '次の命令へ戻る', style: 'dashed' },
  ],
}
```

「外側の環境」がだれなのかは、コンピュータによって違います。

| | 外側の環境 | ecall を実行すると |
| --- | --- | --- |
| このサイトの CPU | エミュレータ（CPU を真似ているプログラム） | エミュレータが直接、文字を出す |
| 本物のコンピュータ | OS（Linux など） | CPU が OS の中のプログラムへ飛び、OS が機器を操作する |

本物のコンピュータでは、ふつうのプログラムは機器の番地に直接は触れません。触ってよいのは OS だけです。プログラムは `ecall` で OS に頼み、OS が代わりに機器を操作します。この仕組みは**システムコール**と呼ばれ、第 19 章でくわしく扱います。

このサイトの CPU には OS がありません。そのため、プログラムが機器の番地に直接触れますし、`ecall` はエミュレータが肩代わりします。このサイトで使える `ecall` の番号は次のとおりです。

| `a7` | 仕事 |
| --- | --- |
| 1 | `a0` を 10 進（符号付き）で表示 |
| 4 | `a0` の番地の文字列（NUL まで）を表示 |
| 11 | `a0` の文字を表示 |
| 34 | `a0` を 16 進で表示 |
| 35 | `a0` を 2 進で表示 |
| 36 | `a0` を 10 進（符号なし）で表示 |
| 10 | プログラムを終える |
| 93 | `a0` を終了コードにして、プログラムを終える |

ここから先は、手軽な `ecall` と、番地への書き込みを、場面に応じて使い分けます。

## 画面：1 バイトが 1 個の点 {#screen}

次は画面です。このサイトの CPU の画面は、横 32 個 × 縦 32 個の点でできています。点のことを**ピクセル**と呼びます。

ピクセル 1 個が、メモリの 1 バイトに対応します。0x10000 番地が左上のピクセルで、右へ 1 つ進むごとに番地が 1 増えます。右端まで行くと、次の行の左端に続きます。

```fig layout 画面の番地。左上が 0x10000。1 行は 32 個（0x20）なので、1 つ下のピクセルは番地が 32 大きい
{
  unit: 62,
  rows: [
    { label: 'y = 0', cells: [ { t: '0x10000', kind: 'accent' }, { t: '0x10001' }, { t: '0x10002' }, { t: '…', kind: 'plain' }, { t: '0x1001F' } ], note: 'x = 0 〜 31' },
    { label: 'y = 1', cells: [ { t: '0x10020', kind: 'stack' }, { t: '0x10021' }, { t: '0x10022' }, { t: '…', kind: 'plain' }, { t: '0x1003F' } ] },
    { label: 'y = 2', cells: [ { t: '0x10040', kind: 'stack' }, { t: '0x10041' }, { t: '0x10042' }, { t: '…', kind: 'plain' }, { t: '0x1005F' } ] },
    { label: 'y = 31', cells: [ { t: '0x103E0', kind: 'stack' }, { t: '0x103E1' }, { t: '0x103E2' }, { t: '…', kind: 'plain' }, { t: '0x103FF' } ], note: '最後の行' },
  ],
}
```

横の位置を x（0〜31）、縦の位置を y（0〜31）とすると、ピクセルの番地は次の式で求まります。y は下へ行くほど大きくなります。

**番地 = 0x10000 + y × 32 + x**

第 12 章の配列の式（先頭 + i × 4）と同じ考え方です。画面は、1,024 バイトの配列なのです。

```asm run title="(5, 3) に赤い点を 1 つ打つ"
.equ SCREEN, 0x10000
    li   t0, SCREEN
    li   t1, 5          # x
    li   t2, 3          # y
    slli t3, t2, 5      # y × 32（左に 5 ビットずらす）
    add  t3, t3, t1     # + x
    add  t3, t3, t0     # + 画面の先頭
    li   t4, 2          # 色 2 = 赤
    sb   t4, 0(t3)
```

出力欄に画面が現れ、左上の近くに赤い点が 1 つ光ります。x と y の数を変えて、点の位置が動くことを確かめてください。

### 色は 0〜15 の番号

書き込むバイトの値が、色の番号です。使えるのは 16 色です。

| 番号 | 色 | 番号 | 色 | 番号 | 色 | 番号 | 色 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 0 | 黒 | 4 | 青 | 8 | 橙 | 12 | 濃い灰 |
| 1 | 白 | 5 | 黄 | 9 | 紫 | 13 | 濃い緑 |
| 2 | 赤 | 6 | 水色 | 10 | 茶 | 14 | 紺 |
| 3 | 緑 | 7 | 桃 | 11 | 灰 | 15 | 肌色 |

16 色を全部並べてみます。画面の全ピクセルを順にたどり、x を 2 で割った数を色にします。

```asm run title="16 色の縦じま"
.equ SCREEN, 0x10000
    li   t0, SCREEN     # いま書くピクセルの番地
    li   t1, 0          # y
rows:
    li   t2, 0          # x
cols:
    srli t3, t2, 1      # 色 = x ÷ 2（0〜15）
    sb   t3, 0(t0)
    addi t0, t0, 1      # 次のピクセルへ
    addi t2, t2, 1
    li   t4, 32
    blt  t2, t4, cols
    addi t1, t1, 1
    blt  t1, t4, rows
```

ピクセルは番地の順に並んでいるので、ポインタを 1 ずつ進めるだけで、左上から右下まで全部をたどれます。左端の 2 列は色 0（黒）なので、見えません。

### 画面は読むこともできる

画面の番地は、読むこともできます。読むと、そのピクセルのいまの色の番号が返ります。

```asm run title="打った点の色を読み返す"
.equ SCREEN, 0x10000
    li   t0, SCREEN
    li   t1, 0x25       # 上の 4 ビットは捨てられる
    sb   t1, 100(t0)    # (4, 3) に書く
    lbu  a0, 100(t0)    # 同じ場所を読む
    li   a7, 1
    ecall
```

5 と出ます。色に使われるのは下の 4 ビットだけなので、0x25 と書いても 5（黄）として残ります。

「その場所に何があるか」を画面から読めることは、第 15 章のゲームで役に立ちます。ヘビが自分の体にぶつかったかどうかを、画面の色を読んで調べます。

## フレームの合図：0x20010 {#frame}

絵を動かすには、「少し描く → 見せる → 描き直す → 見せる」を繰り返します。見せる 1 回ぶんの絵を**フレーム**（frame、こま）と呼びます。パラパラ漫画の 1 枚です。

このサイトの CPU では、0x20010 番地に何かを書くと、「ここで 1 フレーム終わり」という合図になります。合図が来ると、CPU はいったん止まり、その時点の画面が表示されます。続きは、次の表示のタイミングで再開します。表示は、ふつう 1 秒におよそ 60 回です。

合図を使って、点を左から右へ流してみます。

```asm run anim title="点が左から右へ流れ続ける"
.equ SCREEN, 0x10000
.equ FRAME,  0x20010

    li   s0, SCREEN
    addi s0, s0, 480    # y = 15 の行の左端（15 × 32 = 480）
    li   s1, FRAME
    li   t0, 0          # x
loop:
    add  t1, s0, t0
    li   t2, 5
    sb   t2, 0(t1)      # 黄色い点を打つ
    sw   zero, 0(s1)    # 1 フレーム終わり → ここで画面が表示される
    sb   zero, 0(t1)    # 点を消す（色 0 = 黒）
    addi t0, t0, 1      # 右へ
    andi t0, t0, 31     # 32 になったら 0 に戻す
    j    loop
```

このプログラムは終わりません。止めるときは停止ボタンを押します。`andi t0, t0, 31` は、下の 5 ビットだけを残す命令です。31 の次は 32（2 進で 100000）ですが、下の 5 ビットは 0 なので、0 に戻ります。

合図の `sw zero, 0(s1)` がなかったら、どうなるでしょうか。CPU は、点を打っては消すことを、目に見えない速さで繰り返すだけになります。どの瞬間の画面を見せればよいのかが、決まらないからです。**見せたい瞬間に合図を出す**のが、アニメーションの基本です。

:::note 本物のコンピュータの「フレームの合図」
本物のディスプレイも、1 秒に 60 回ほど、画面を上から下へ描き直しています。ゲームのプログラムは、1 回の描き直しが終わるのを待ってから、次の絵を用意します。待たずに画面のメモリを書き換えると、絵の上半分と下半分がずれて見えることがあります。0x20010 番地は、この「描き直しを待つ」仕組みを簡単にしたものです。
:::

## キーボードを読む：ポーリング {#keyboard}

入力も、番地を読むだけです。0x20004 番地を読むと、**押されたキーのコード**が返ります。何も押されていなければ 0 です。

| キー | コード |
| --- | --- |
| ← | 1 |
| ↑ | 2 |
| → | 3 |
| ↓ | 4 |
| そのほか | 文字の ASCII コード（`a` なら 97、スペースなら 32） |

キーは、いつ押されるか分かりません。そこで、プログラムの側から**何度も見に行きます**。「押された？」「まだ」「押された？」「まだ」「押された？」「← が押された」。この方法を**ポーリング**（polling）と呼びます。

```asm run anim title="押されたキーのコードを表示し続ける"
.equ KEY,   0x20004
.equ FRAME, 0x20010

    li   s0, KEY
    li   s1, FRAME
loop:
    lw   a0, 0(s0)      # キーを見に行く
    beqz a0, wait       # 0 なら、何も押されていない
    li   a7, 1          # 押されていたら、コードを表示
    ecall
    li   a0, ' '
    li   a7, 11
    ecall
wait:
    sw   zero, 0(s1)    # 1 フレーム待つ
    j    loop
```

実行して、出てきた画面をクリックしてからキーを押してください。矢印キーなら 1〜4、文字のキーならその ASCII コードが出ます。

0x20004 番地は、**読むと消える**のが特徴です。同じキーを 2 回読むことはありません。押されたキーは、読まれるまで 16 個までためられます。メモリのように見えて、メモリとは違うふるまいをする番地です。

### 矢印キーで点を動かす

キーのコードに応じて x と y を変えれば、点を動かせます。

```asm run anim title="矢印キーで点を動かす"
.equ SCREEN, 0x10000
.equ KEY,    0x20004
.equ FRAME,  0x20010

    li   s0, SCREEN
    li   s1, 16         # x
    li   s2, 16         # y
    li   s3, KEY
    li   s4, FRAME
loop:
    slli t0, s2, 5      # いまの場所の点を消す
    add  t0, t0, s1
    add  t0, t0, s0
    sb   zero, 0(t0)

    lw   t1, 0(s3)      # キーを読む
    li   t2, 1
    beq  t1, t2, left
    li   t2, 2
    beq  t1, t2, up
    li   t2, 3
    beq  t1, t2, right
    li   t2, 4
    beq  t1, t2, down
    j    draw           # 矢印でなければ動かない
left:
    beqz s1, draw       # 左端なら動かない
    addi s1, s1, -1
    j    draw
right:
    li   t2, 31
    beq  s1, t2, draw   # 右端なら動かない
    addi s1, s1, 1
    j    draw
up:
    beqz s2, draw
    addi s2, s2, -1
    j    draw
down:
    li   t2, 31
    beq  s2, t2, draw
    addi s2, s2, 1

draw:
    slli t0, s2, 5      # 新しい場所に点を打つ
    add  t0, t0, s1
    add  t0, t0, s0
    li   t1, 6          # 水色
    sb   t1, 0(t0)
    sw   zero, 0(s4)    # 1 フレーム終わり
    j    loop
```

端の確認（`beqz s1, draw` など）が大切です。これがないと、x が -1 や 32 になり、点が隣の行や画面の外の番地に書かれてしまいます。

### 押しっぱなしを知る：0x20014

0x20004 は「押された」という出来事を 1 回ずつ伝えます。ゲームでは、「いま押されているか」を知りたいことがあります。そのための番地が 0x20014 です。読むと、いま押されているキーが**ビット**で分かります。

| ビット | 値 | キー |
| --- | --- | --- |
| 0 | 1 | ← |
| 1 | 2 | ↑ |
| 2 | 4 | → |
| 3 | 8 | ↓ |
| 4 | 16 | スペース |

← と ↑ を同時に押していれば、1 + 2 = 3 が読めます。あるキーだけを調べるには、`andi` でそのビットを取り出します。`andi t1, t0, 4` の結果が 0 でなければ、→ が押されています。この番地は第 15 章で使います。

:::note ポーリングと割り込み
ポーリングは単純ですが、キーが押されていない間も見に行き続けるので、むだがあります。本物のコンピュータでは、機器の側から「いま押された」と CPU に知らせる**割り込み**という仕組みがよく使われます。割り込みは第 19 章で扱います。このサイトの CPU には割り込みがないので、ポーリングだけを使います。
:::

## 乱数と命令数 {#random}

残りの 2 つの番地は、読むだけの機器です。

### 乱数：0x20008

0x20008 番地は、読むたびに違う数が返ります。でたらめに見える数、**乱数**です。ゲームで、エサの場所や敵の動きを決めるのに使います。

返ってくるのは 32 ビットいっぱいの数なので、そのままでは大きすぎます。欲しい範囲にするには、余りを使います。6 で割った余りは 0〜5 なので、1 を足せばサイコロになります。

```asm run title="サイコロを 10 回振る"
.equ RANDOM, 0x20008
    li   s0, RANDOM
    li   s1, 10         # 回数
    li   s2, 6
loop:
    lw   a0, 0(s0)      # 乱数を読む
    remu a0, a0, s2     # 0〜5（符号なしの余り）
    addi a0, a0, 1      # 1〜6
    li   a7, 1
    ecall
    li   a0, ' '
    li   a7, 11
    ecall
    addi s1, s1, -1
    bnez s1, loop
```

余りには、符号なしの `remu` を使います。乱数は負の数（いちばん上のビットが 1）のこともあり、符号付きの `rem` だと余りが負になってしまうからです。

範囲が 2 の累乗（2、4、8、16、32 …）のときは、`andi` で下のビットを取り出すほうが簡単です。`andi t0, t0, 31` で 0〜31、`andi t0, t0, 15` で 0〜15 になります。これを使って、画面をでたらめな色で埋めます。

```asm run title="画面を乱数の色で埋める"
.equ SCREEN, 0x10000
.equ RANDOM, 0x20008
    li   t0, SCREEN
    li   t1, 1024       # ピクセルの数
    add  t1, t0, t1     # 終わりの番地
    li   t2, RANDOM
loop:
    lw   t3, 0(t2)      # 乱数
    andi t3, t3, 15     # 0〜15 にする
    sb   t3, 0(t0)
    addi t0, t0, 1
    blt  t0, t1, loop
```

:::note このサイトの乱数は、毎回同じ並びになる
何度実行しても、同じ模様が出ることに気づいたでしょうか。この乱数は、決まった計算で「でたらめに見える数の列」を作っています。こういう乱数を**擬似乱数**と呼びます。出発点の数（シード）が同じなら、列も同じです。このサイトでは、結果を再現できるように、シードを固定してあります。0x20008 番地に数を**書く**と、シードを変えられます。
:::

### 命令数：0x2000C

0x2000C 番地を読むと、プログラムが始まってから実行した命令の数が分かります。2 回読んで差を取れば、その間に何命令かかったかを測れます。

```asm run title="ループに何命令かかるかを測る"
.equ CLOCK, 0x2000C
    li   s0, CLOCK
    lw   s1, 0(s0)      # 始め
    li   t0, 100
loop:
    addi t0, t0, -1
    bnez t0, loop       # 2 命令 × 100 回
    lw   s2, 0(s0)      # 終わり
    sub  a0, s2, s1
    li   a7, 1
    ecall
```

202 と出ます。ループの 200 命令に、`li t0, 100` の 1 命令と、2 回目の `lw` 自身の 1 命令が加わっています。

本物のコンピュータにも、時刻や経過時間を読める機器（タイマー）があります。プログラムの速さを測ったり、一定の時間だけ待ったりするのに使います。

:::try 自分の名前を流す
下のプログラムは、コンソールに 1 文字ずつ、1 フレームごとに文字を出します。`msg` を自分の好きな言葉に変えてみてください。次に、文字を出すたびに、画面の左上から順に点も 1 つずつ打つように書き足してください（番地は `0x10000` から 1 ずつ増やします）。
:::

```asm run anim title="練習：1 フレームに 1 文字ずつ出す"
.equ CONSOLE, 0x20000
.equ FRAME,   0x20010

.data
msg: .asciz "Hello, memory-mapped I/O!"

.text
    li   s0, CONSOLE
    li   s1, FRAME
    la   s2, msg
loop:
    lbu  t0, 0(s2)
    beqz t0, done
    sb   t0, 0(s0)      # 1 文字出す
    sw   zero, 0(s1)    # 1 フレーム待つ
    addi s2, s2, 1
    j    loop
done:
```

:::key まとめ
- CPU は、機器を「決まった番地」として読み書きする（メモリマップド I/O）。使う命令は `lw`、`sw`、`lbu`、`sb` のまま
- このサイトの CPU では、コンソールは 0x20000。1 バイト書くと 1 文字出る
- 数を表示するには、10 で割った余りで桁に分け、`'0'` を足して文字にし、逆の順に送る
- `ecall` は、外側の環境に仕事を頼む命令。このサイトではエミュレータが、本物のコンピュータでは OS が引き受ける
- 画面は 0x10000 から 1,024 バイト。(x, y) の番地は `0x10000 + y × 32 + x`。書く値は色の番号（0〜15）
- 0x20010 に書くと 1 フレーム終わり。アニメーションは「描く → 合図」の繰り返し
- キーボードは 0x20004 を何度も読みに行く（ポーリング）。押しっぱなしは 0x20014 のビットで分かる
- 0x20008 は乱数、0x2000C は実行した命令数
:::

## 確認問題 {#quiz}

この章の内容を、自分でプログラムを書いて確かめます。前半の 2 問は関数を書く問題で、`main` は問題の側で用意してあります。後半の 2 問は、実行が終わったときの画面で判定します。

:::quiz 文字列を出す関数
関数 `puts` を書いてください。`a0` に、NUL で終わる文字列の番地を受け取ります。その文字列をコンソールに出し、最後に改行（`'\n'`）を 1 つ出します。NUL 自身は出しません。

```asm starter
# puts(a0 = 文字列の番地)：文字列と改行を出す
puts:

    ret
```

```asm answer
puts:
    li   t0, 0x20000
puts_loop:
    lbu  t1, 0(a0)
    beqz t1, puts_end
    sb   t1, 0(t0)
    addi a0, a0, 1
    j    puts_loop
puts_end:
    li   t1, '\n'
    sb   t1, 0(t0)
    ret
```

```asm given
main:
    la   a0, str1
    call puts
    la   a0, str2
    call puts
    la   a0, str3
    call puts
    la   a0, str1
    call puts
    li   a7, 10
    ecall
.data
str1: .asciz "RISC-V"
str2: .asciz ""
str3: .asciz "32 x 32 pixels"
```

:::hint
0x20000 番地に 1 バイトずつ `sb` で書きます。1 文字読んで 0 なら、ループを抜けて改行を出します。空の文字列（最初のバイトが NUL）のときは、改行だけが出ます。
:::
:::

:::quiz 2 進で 8 桁表示する関数
関数 `print_bin8` を書いてください。`a0` の**下の 8 ビット**を、`0` と `1` の文字 8 個でコンソールに出し、最後に改行を出します。上の桁（ビット 7）から順に出します。たとえば `a0` が 5 なら `00000101` です。

```asm starter
# print_bin8(a0)：下の 8 ビットを 2 進 8 桁で表示して、改行する
print_bin8:

    ret
```

```asm answer
print_bin8:
    li   t0, 0x20000
    li   t1, 7
pb_loop:
    srl  t2, a0, t1
    andi t2, t2, 1
    addi t2, t2, '0'
    sb   t2, 0(t0)
    addi t1, t1, -1
    bgez t1, pb_loop
    li   t2, '\n'
    sb   t2, 0(t0)
    ret
```

```asm given
main:
    li   a0, 5
    call print_bin8
    li   a0, 0xA5
    call print_bin8
    li   a0, 255
    call print_bin8
    li   a0, 0
    call print_bin8
    li   a0, 0x380
    call print_bin8
    li   a7, 10
    ecall
```

:::hint
ビット 7 から 0 まで順に調べます。`srl` で右に n ビットずらして `andi` で 1 と AND を取ると、ビット n が 0 か 1 で取り出せます。それに `'0'` を足すと文字になります。
:::
:::

画面の y = 10 の行に、x = 4 から x = 27 まで（両端を含む 24 個）、赤（色 2）の横線を引いてください。ほかのピクセルは黒（0）のままにします。

```asm starter
# y = 10 の行の、x = 4 〜 27 を赤（2）にする

```

:::

:::quiz 市松模様
画面全体を市松模様（チェック柄）にしてください。x + y が偶数のピクセルを白（色 1）、奇数のピクセルを黒（0）にします。左上の (0, 0) は白です。

```asm starter
# x + y が偶数なら白（1）、奇数なら黒（0）

```

```asm answer screen
    li   t0, 0x10000
    li   t1, 0
rows:
    li   t2, 0
cols:
    add  t3, t1, t2
    andi t3, t3, 1
    xori t3, t3, 1
    sb   t3, 0(t0)
    addi t0, t0, 1
    addi t2, t2, 1
    li   t4, 32
    blt  t2, t4, cols
    addi t1, t1, 1
    blt  t1, t4, rows
```

:::hint
本文の「16 色の縦じま」と同じ二重のループで、全ピクセルをたどれます。x + y の下の 1 ビット（`andi` で 1 と AND）が 0 なら偶数です。
:::
