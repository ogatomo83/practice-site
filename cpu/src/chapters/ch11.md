## 命令は上から順に：pc {#pc}

第 10 章のプログラムは、どれも上から下へ 1 回ずつ命令を実行して終わりました。これでは、命令を 10 行書いたら 10 個ぶんの仕事しかできません。コンピュータが役に立つのは、**条件によってすることを変え**、**同じことを何万回も繰り返せる**からです。

その仕組みは、第 9 章で出てきた **pc**（プログラムカウンタ）にあります。pc は、次に実行する命令の番地を持つレジスタでした。ふつうの命令は、実行が終わると pc を 4 増やします。命令は 4 バイトずつ並んでいるので、これで次の命令に進みます。

では、pc に**別の番地**を入れたらどうなるでしょうか。CPU は、その番地の命令から実行を続けます。これが**ジャンプ**です。

```fig graph pc の動き方は 2 通りしかない。4 増えて次の命令に進むか、ジャンプや分岐で別の番地に変わるか
{

  nodes: [
    { id: 'i0', label: '0x0000  li a0, 1', x: 0, y: 0 },
    { id: 'i1', label: '0x0004  j skip', x: 0, y: 1, kind: 'accent' },
    { id: 'i2', label: '0x0008  li a0, 99', sub: '実行されない', x: 0, y: 2, kind: 'muted' },
    { id: 'i3', label: '0x000c  addi a0, a0, 1', sub: 'skip:', x: 0, y: 3 },
    { id: 'n1', label: 'ふつうの命令', sub: 'pc ← pc + 4', x: 1.6, y: 0, kind: 'stack' },
    { id: 'n2', label: 'ジャンプ', sub: 'pc ← 飛び先の番地', x: 1.6, y: 2, kind: 'stack' },
  ],

```

この図のプログラムを、ステップ実行で動かします。「1 命令進む」を押して、光る行が 3 行目を飛び越すことと、pc が 0 → 4 → 12 と変わることを確かめてください。

```asm run step title="j で命令を飛び越す" regs="a0"
    li   a0, 1
    j    skip            # skip へジャンプ
    li   a0, 99          # 実行されない
skip:
    addi a0, a0, 1
```

`a0` は 2 です。`li a0, 99` は実行されませんでした。

## 飛び先に名前を付ける：ラベル {#labels}

`j`（jump）は、必ず飛ぶ命令です。飛び先は `skip` という名前で書きました。行の先頭に `名前:` と書いたものが**ラベル**で、**その次の命令の番地**に付けた名前です。第 8 章ではデータの番地に名前を付けましたが、命令の番地にも同じように付けられます。

番地を数で書かずにラベルを使うのは、命令を 1 行足しただけで後ろの番地が全部ずれるからです。ラベルで書いておけば、アセンブラが番地を数え直して、機械語に飛び先までの距離を入れてくれます（第 9 章）。

- ラベルは命令と同じ行に書いても、前の行に書いてもよい（`skip: addi a0, a0, 1` でも同じ）
- 同じ名前のラベルは 2 つ作れない
- ラベル自身は命令ではない。機械語にはならず、場所も取らない

存在しないラベルに飛ぼうとすると、アセンブラがエラーにします。

```asm run error title="ラベルの名前を間違えた"
    li   a0, 1
    j    skpi            # skip のつもり
skip:
    addi a0, a0, 1
```

:::note j も疑似命令
`j ラベル` は、`jal zero, ラベル` に展開される疑似命令です。`jal`（jump and link）は「次の命令の番地をレジスタに覚えてから飛ぶ」命令で、覚える先を `zero` にすると、ただのジャンプになります。覚えた番地を使う話は、第 13 章の関数で出てきます。
:::

## 条件で飛ぶ：beq と bne {#branch}

`j` はいつでも飛びます。**条件が成り立つときだけ飛ぶ**命令が、**分岐**（branch）です。

| 命令 | 飛ぶ条件 | 名前の由来 |
| --- | --- | --- |
| `beq rs1, rs2, ラベル` | rs1 と rs2 が等しい | branch if equal |
| `bne rs1, rs2, ラベル` | rs1 と rs2 が等しくない | branch if not equal |

条件が成り立てば pc は飛び先の番地になり、成り立たなければ pc は 4 増えて、すぐ下の命令に進みます。

```asm run step title="beq：等しければ飛ぶ" regs="t0,t1,a0"
    li   t0, 7
    li   t1, 7
    li   a0, 0
    beq  t0, t1, same    # t0 == t1 なら same へ
    li   a0, 1           # 等しくないときだけ実行される
same:
    addi a0, a0, 10
```

`t0` と `t1` は等しいので、`li a0, 1` を飛び越して `a0` は 10 になります。`li t1, 7` を `li t1, 8` に書き換えると、飛ばずにすぐ下へ進み、`a0` は 11 になります。`beq` を `bne` に変えると、結果が入れ替わります。

`zero` と比べる形はとてもよく使うので、短い書き方（疑似命令）があります。

| 疑似命令 | 本物の命令 | 飛ぶ条件 |
| --- | --- | --- |
| `beqz rs, ラベル` | `beq rs, zero, ラベル` | rs が 0 |
| `bnez rs, ラベル` | `bne rs, zero, ラベル` | rs が 0 でない |

## if の形：条件を逆にして飛び越す {#if}

高級言語の `if` は、「条件が成り立つときだけ、中の命令を実行する」という形です。アセンブリでは、これを逆向きに書きます。**条件が成り立たないときに、中の命令を飛び越す**のです。

:::cols
:::col C 風に書くと
```c
if (x == 0) {
    x = 100;
}
// 続き
```
:::
:::col アセンブリ
```asm
    bne  t0, zero, skip  # x != 0 なら飛び越す
    li   t0, 100         # x = 100
skip:
    # 続き
```
:::
:::

C の条件は `==` なのに、アセンブリの命令は `bne`（等しくない）です。分岐は「飛ぶ条件」を書く命令なので、「中を実行する条件」とは逆になります。最初は戸惑いますが、アセンブリの `if` はいつもこの形です。

実際の例として、0 で割るのを避けるプログラムを書きます。第 10 章で、RISC-V は 0 で割っても止まらないことを見ました。割る前に自分で調べます。

```asm run title="割る数が 0 のときは、割り算をしない" regs="t0,t1,a0"
    li   t0, 84          # 割られる数
    li   t1, 0           # 割る数
    li   a0, -1          # 割れなかったときの答え
    beqz t1, skip        # 割る数が 0 なら、割り算を飛び越す
    div  a0, t0, t1
skip:
    li   a7, 1
    ecall
```

`-1` と表示されます。`li t1, 0` を `li t1, 2` に変えると、割り算が実行されて `42` になります。

## if-else の形 {#if-else}

条件によって 2 つの道のどちらかを通るのが `if-else` です。分岐 1 つと `j` 1 つで作ります。


:::cols
:::col C 風に書くと
```c
if (x % 2 == 0) {
    print("even");
} else {
    print("odd");
}
```
:::
:::col アセンブリ
```asm
    andi t1, t0, 1       # x の最下位ビット
    bnez t1, else        # 1 なら else へ
    la   a0, even        # then の側
    j    end             # else を飛び越す
else:
    la   a0, odd         # else の側
end:
    # 続き
```
:::
:::

```asm run title="偶数か奇数かで、表示する文字列を変える"
.data
even:  .asciz "even\n"
odd:   .asciz "odd\n"

.text
    li   t0, 7           # 調べる数
    andi t1, t0, 1       # 最下位ビットが 1 なら奇数
    bnez t1, else
    la   a0, even        # then：偶数
    j    end
else:
    la   a0, odd         # else：奇数
end:
    li   a7, 4
    ecall
```

`odd` と表示されます。`li t0, 7` を偶数に変えて確かめてください。

:::warn j end を忘れると、両方が実行される
then の側の最後の `j end` を書き忘れると、then の命令を実行した後、そのまま下の else の命令も実行してしまいます。ラベルは目印であって、壁ではありません。命令はラベルを素通りして下に進みます。エラーにはならないので、気づきにくい間違いです。上のプログラムから `j end` の行を消して、偶数のときに何が表示されるか試してみてください。
:::

## 大小を比べる：blt と bge {#compare}

等しいかどうかだけでなく、大小でも分岐できます。

| 命令 | 飛ぶ条件 | 数の見方 |
| --- | --- | --- |
| `blt rs1, rs2, ラベル` | rs1 < rs2（less than） | 符号付き |
| `bge rs1, rs2, ラベル` | rs1 ≥ rs2（greater or equal） | 符号付き |
| `bltu rs1, rs2, ラベル` | rs1 < rs2 | 符号なし（unsigned） |
| `bgeu rs1, rs2, ラベル` | rs1 ≥ rs2 | 符号なし |

「より大きい」の `bgt` と「以下」の `ble` は、CPU の命令にはありません。左右を入れ替えれば `blt` と `bge` で済むからです。アセンブラが疑似命令として用意しています。

| 疑似命令 | 本物の命令 | 飛ぶ条件 |
| --- | --- | --- |
| `bgt rs1, rs2, ラベル` | `blt rs2, rs1, ラベル` | rs1 > rs2 |
| `ble rs1, rs2, ラベル` | `bge rs2, rs1, ラベル` | rs1 ≤ rs2 |

大小の分岐を使って、2 つの数の大きいほうを選びます。

```asm run title="2 つの数の大きいほうを表示する" regs="t0,t1,a0"
    li   t0, 17
    li   t1, 42
    mv   a0, t0          # とりあえず t0 を答えにする
    bge  t0, t1, done    # t0 ≥ t1 なら、そのまま
    mv   a0, t1          # t1 のほうが大きい
done:
    li   a7, 1
    ecall
```

`42` と表示されます。「とりあえず片方を答えにしておき、違ったら入れ替える」と書くと、else の側が要らなくなり、`j` を 1 つ減らせます。

同じ形で、絶対値も計算できます。負の数のときだけ、符号を反転します。

```asm run title="絶対値：負のときだけ符号を反転する" regs="a0"
    li   a0, -15
    bge  a0, zero, done  # 0 以上なら何もしない
    neg  a0, a0          # a0 ← −a0
done:
    li   a7, 1
    ecall
```

### 符号付きと符号なしで、結果が変わる

第 3 章で、同じビットの並びが、符号付きと符号なしで違う数に見えることを学びました。`0xFFFFFFFF` は、符号付きなら -1、符号なしなら約 43 億です。大小の比較は、どちらの見方をするかで結果が変わります。だから命令が 2 組あります。

```asm run title="-1 と 1 を、blt と bltu で比べる"
    li   t0, -1          # 0xFFFFFFFF
    li   t1, 1
    li   a7, 11          # 文字を表示

    li   a0, 'N'
    bge  t0, t1, p1      # 符号付きで t0 ≥ t1 なら N のまま
    li   a0, 'Y'         # 符号付きで t0 < t1
p1: ecall

    li   a0, 'N'
    bgeu t0, t1, p2      # 符号なしで t0 ≥ t1 なら N のまま
    li   a0, 'Y'         # 符号なしで t0 < t1
p2: ecall
```

`YN` と表示されます。符号付きでは -1 < 1 が成り立ち（Y）、符号なしでは 4294967295 < 1 が成り立ちません（N）。ふつうの数の比較には `blt` と `bge` を、番地や個数のように負にならないものの比較には `bltu` と `bgeu` を使います。

## while：条件が成り立つ間、繰り返す {#while}

分岐の飛び先は、下とは限りません。**上に戻る**と、同じ命令をもう一度実行することになります。これが**ループ**です。

```fig graph while ループの流れ。先頭で条件を調べ、成り立たなければ出口へ分岐する。本体の最後の j で先頭に戻る
{
  col: 230, row: 110,
  nodes: [
    { id: 'c', label: '条件を調べる', sub: 'loop:', x: 1, y: 0, kind: 'accent' },
    { id: 'b', label: '本体の命令', sub: '条件に関わる値を変える', x: 1, y: 1 },
    { id: 'j', label: 'j loop', sub: '先頭に戻る', x: 0, y: 0.5 },
    { id: 'n', label: '続き', sub: 'done:', x: 2.1, y: 0, kind: 'stack' },
  ],
  edges: [
    { from: 'c', to: 'b', label: '成り立つ' },
    { from: 'b', to: 'j' },
    { from: 'j', to: 'c', style: 'accent' },
    { from: 'c', to: 'n', label: '成り立たない', style: 'accent' },
  ],
}
```

:::cols
:::col C 風に書くと
```c
while (n > 0) {
    print(n);
    n = n - 1;
}
```
:::
:::col アセンブリ
```asm
loop:
    ble  t0, zero, done  # n <= 0 なら抜ける
    # print(n)
    addi t0, t0, -1      # n = n - 1
    j    loop            # 先頭に戻る
done:
```
:::
:::

`if` と同じで、分岐には「抜ける条件」（続ける条件の逆）を書きます。

```asm run title="5 から 1 まで数える"
    li   t0, 5           # n
loop:
    ble  t0, zero, done  # n ≤ 0 なら抜ける
    mv   a0, t0
    li   a7, 1
    ecall                # n を表示
    li   a0, ' '
    li   a7, 11
    ecall                # 空白
    addi t0, t0, -1      # n を 1 減らす
    j    loop
done:
```

`5 4 3 2 1` と表示されます。書いた命令は 10 個ですが、実行した命令は 47 個です。ステップ実行に切り替えると、光る行が `loop` に戻っていく様子が見られます。

### 1 から 100 までの合計

ループの定番、合計の計算です。合計を入れるレジスタと、今の数を入れるレジスタの 2 本を使います。

```asm run title="1 + 2 + … + 100" regs="t0,a0"
    li   a0, 0           # 合計
    li   t0, 1           # i
    li   t1, 100
loop:
    bgt  t0, t1, done    # i > 100 なら抜ける
    add  a0, a0, t0      # 合計に i を足す
    addi t0, t0, 1       # i を 1 増やす
    j    loop
done:
    li   a7, 1
    ecall
```

`5050` と表示されます。実行した命令は 406 個です。`li t1, 100` を `li t1, 10000` に変えれば、同じ 9 個の命令のプログラムが、約 4 万個の命令を実行します。プログラムの長さと仕事の量が、ここで初めて切り離されました。

:::deep 条件を下に置くと、命令が 1 つ減る
上の形では、1 周ごとに `bgt` と `j` の 2 つの分岐・ジャンプを実行します。条件を本体の後ろに置き、「続けるなら先頭に戻る」と書けば、1 周あたり 1 つで済みます。

```asm
loop:
    add  a0, a0, t0
    addi t0, t0, 1
    ble  t0, t1, loop    # i ≤ 100 なら戻る
```

この形は、少なくとも 1 回は本体を実行します（C の `do-while`）。コンパイラは、最初の 1 回の条件だけを別に調べてから、この形のループを作ることがよくあります。分岐が速さにどう響くかは、第 17 章のパイプラインで扱います。
:::

## for：回数の決まった繰り返し {#for}

`for` は、`while` に「最初の準備」と「1 周ごとの更新」を足して整理した形です。アセンブリでは `while` と同じ並びになります。

:::cols
:::col C 風に書くと
```c
for (i = 0; i < 5; i++) {
    print(i);
}
```
:::
:::col アセンブリ
```asm
    li   t0, 0           # 準備：i = 0
loop:
    bge  t0, t1, done    # 条件：i >= 5 なら抜ける
    # print(i)           # 本体
    addi t0, t0, 1       # 更新：i++
    j    loop
done:
```
:::
:::

ループを二重にすると、行と列のある形を出力できます。外側のループが行、内側のループが 1 行の中の文字を担当します。

```asm run title="二重のループで三角形を描く"
    li   t0, 1           # i：何行目か（1〜5）
    li   t1, 5
row:
    bgt  t0, t1, done
    li   t2, 0           # j：この行に出した * の数
col:
    bge  t2, t0, eol     # i 個出したら、行の終わりへ
    li   a0, '*'
    li   a7, 11
    ecall
    addi t2, t2, 1
    j    col
eol:
    li   a0, '\n'
    li   a7, 11
    ecall
    addi t0, t0, 1
    j    row
done:
```

```console
*
**
***
****
*****
```

内側のループの回数が、外側の `i` で決まっています。`bge t2, t0, eol` の `t0` を `t1` に変えると、5 × 5 の四角になります。

### 並んだデータの最大値

ループは、メモリに並んだデータを順に調べるときに力を発揮します。`.data` に並べたワードの最大値を求めます。番地を入れたレジスタを 4 ずつ進めながら、`lw` で 1 つずつ読みます（第 8 章。くわしくは第 12 章）。

```asm run title="5 つの数の最大値" regs="a0"
.data
nums:  .word 3, 41, 7, 26, 15

.text
    la   t0, nums        # 今見ている数の番地
    li   t1, 5           # 残りの個数
    lw   a0, 0(t0)       # 最初の数を、最大値の候補にする
loop:
    addi t0, t0, 4       # 次の数へ（1 ワード = 4 バイト）
    addi t1, t1, -1
    beqz t1, done        # 残りがなくなったら終わり
    lw   t2, 0(t0)
    ble  t2, a0, loop    # 候補以下なら、何もせず次へ
    mv   a0, t2          # 候補より大きいので、入れ替える
    j    loop
done:
    li   a7, 1
    ecall
```

`41` と表示されます。`ble` を `bge` に変えると、最小値を求めるプログラムになります。ループの中に `if` が入った形です。

## FizzBuzz {#fizzbuzz}

ループと分岐を組み合わせた定番の問題です。1 から順に数を表示しますが、3 の倍数のときは `Fizz`、5 の倍数のときは `Buzz`、両方の倍数のときは `FizzBuzz` を代わりに表示します。

倍数かどうかは、`rem` で余りが 0 かを調べれば分かります。「両方の倍数」は、2 つの余りを `or` でまとめて、結果が 0 かどうかで判定できます（どちらも 0 のときだけ、`or` の結果が 0）。

```asm run title="FizzBuzz（1〜15）"
.data
fizz:  .asciz "Fizz"
buzz:  .asciz "Buzz"

.text
    li   t0, 1           # i
    li   t1, 15
    li   t2, 3
    li   t3, 5
loop:
    bgt  t0, t1, done
    rem  t4, t0, t2      # i ÷ 3 の余り
    rem  t5, t0, t3      # i ÷ 5 の余り
    or   t6, t4, t5
    bnez t6, not15       # どちらかが 0 でなければ、15 の倍数ではない
    la   a0, fizz
    li   a7, 4
    ecall
    la   a0, buzz
    ecall
    j    next
not15:
    bnez t4, not3
    la   a0, fizz        # 3 の倍数
    li   a7, 4
    ecall
    j    next
not3:
    bnez t5, number
    la   a0, buzz        # 5 の倍数
    li   a7, 4
    ecall
    j    next
number:
    mv   a0, t0          # どれでもないので、数を表示
    li   a7, 1
    ecall
next:
    li   a0, '\n'
    li   a7, 11
    ecall
    addi t0, t0, 1
    j    loop
done:
```

`if-else if-else` と続く形は、「条件に合わなければ次の判定へ飛ぶ」「合った側の最後で、共通の続き（`next`）へ飛ぶ」の繰り返しになります。`li t1, 15` を 100 に変えても、プログラムの長さは変わりません。

## ループで画面に描く {#draw}

第 8 章では、画面の番地に 1 点ずつ書きました。ループがあれば、線も模様も数行で描けます。画面の (x, y) の番地は `0x10000 + y × 32 + x` でした。

横線は、番地を 1 ずつ進めながら 32 回書けば描けます。

```asm run title="横線を 1 本引く"
    li   t0, 0x10000
    addi t0, t0, 320     # y = 10 の行の左端（10 × 32 = 320）
    li   t1, 0           # 書いた点の数
    li   t2, 32
    li   t3, 3           # 緑
loop:
    sb   t3, 0(t0)       # 点を打つ
    addi t0, t0, 1       # 右隣の番地へ
    addi t1, t1, 1
    blt  t1, t2, loop    # 32 個書くまで繰り返す
```

`addi t0, t0, 1` を `addi t0, t0, 32` に変えると、番地が 1 行ぶんずつ進むので、縦線になります（そのときは、始まりを `addi t0, t0, 10` にして y = 0 から引いてください）。

### 市松模様

画面全体を塗るには、y のループの中に x のループを入れます。色は、x + y が偶数か奇数かで決めます。隣に 1 つ動くと x + y の偶奇が入れ替わるので、縦にも横にも交互の模様になります。

```asm run title="二重のループで市松模様を描く"
    li   t0, 0x10000     # 書く番地（左上から順に進める）
    li   t5, 32
    li   t1, 0           # y
yloop:
    li   t2, 0           # x
xloop:
    add  t3, t1, t2      # x + y
    andi t3, t3, 1       # 偶数なら 0、奇数なら 1
    slli t3, t3, 2       # 0 か 4（黒か青）
    sb   t3, 0(t0)
    addi t0, t0, 1       # 次の点へ
    addi t2, t2, 1
    blt  t2, t5, xloop   # x < 32 の間、繰り返す
    addi t1, t1, 1
    blt  t1, t5, yloop   # y < 32 の間、繰り返す
```

画面は 1,024 点あります。書いた命令は 13 個ですが、7,267 個の命令を実行して全部を塗ります。書き換えて遊んでみてください。

- `andi t3, t3, 1` を `andi t3, t3, 3` にすると、黒・青・橙・濃い灰の 4 色の斜めの縞になる
- さらに `slli t3, t3, 2` の行を消して `andi t3, t3, 15` にすると、16 色の斜めの縞になる
- `add t3, t1, t2` を `mv t3, t2` にすると、x だけで色が決まるので、縦の縞になる

画面の番地は右端の次が次の行の左端なので、番地を 1 ずつ進めるだけで、左上から右下まで順に塗れます。x と y は、色を決めるためだけに数えています。

## 止まらないループ {#infinite}

ループの条件を書き間違えると、いつまでも終わらないプログラムになります。**無限ループ**です。

```asm norun
    li   t0, 5
loop:
    addi t0, t0, 1       # 減らすつもりで、増やしてしまった
    bnez t0, loop        # 0 にならないので、戻り続ける
```

本物の CPU は、電源が切れるまでこれを実行し続けます。このサイトの CPU は、1 回の実行で **1,000,000 命令**を超えると、次のように言って打ち切ります。

```text
1,000,000 命令を実行しても止まらないので打ち切りました（無限ループになっていませんか）
```

このメッセージが出たら、次の 3 点を確かめます。

1. **条件に関わるレジスタを、ループの中で変えているか。** 変えなければ、条件の結果は永久に同じ
2. **変える向きは合っているか。** 0 を目指して数えるなら減らす、上限を目指すなら増やす
3. **`beq` や `bne` で「ちょうど」を待っていないか。** 2 ずつ増やして 5 と等しくなるのを待つと、5 を飛び越えて止まらない。`blt` や `bge` で範囲を調べるほうが安全

ステップ実行で 2、3 周ぶん追うと、たいてい原因が見つかります。

:::note 止まらないのが正しいプログラムもある
ゲームや OS のように、ずっと動き続けるプログラムの中心は、わざと作った無限ループです。入力を調べ、状態を更新し、画面を描く、を繰り返します。第 15 章で、そういうプログラムを書きます。
:::

:::try やってみよう
下のプログラムは、画面全体を 16 色のグラデーションで塗ります。番地を 0 から 1023 まで数え、そこから x と y を逆算しています。

1. `srli t3, t1, 5` と `andi t4, t1, 31` が、なぜ y と x になるのかを考える（32 = 2 の 5 乗）
2. 色の式を `x` だけにして、縦の縞にする
3. `blt` の行の条件を変えて、画面の上半分だけを塗る
:::

```asm run title="練習用：斜めのグラデーション"
    li   t0, 0x10000
    li   t1, 0           # 0〜1023 の通し番号
    li   t2, 1024
loop:
    srli t3, t1, 5       # y ＝ 番号 ÷ 32
    andi t4, t1, 31      # x ＝ 番号 ÷ 32 の余り
    add  t3, t3, t4      # x + y
    srli t3, t3, 2       # 4 点ごとに色を変える
    andi t3, t3, 15      # 色番号は 0〜15
    add  t5, t0, t1      # 書く番地
    sb   t3, 0(t5)
    addi t1, t1, 1
    blt  t1, t2, loop
```

:::key この章のまとめ
- **pc** は次に実行する命令の番地。ふつうは 4 ずつ増える。ジャンプと分岐は、pc を別の番地に変える
- **ラベル**は命令の番地に付けた名前。`j ラベル` は必ず飛ぶ
- **分岐**は条件が成り立つときだけ飛ぶ。`beq`（等しい）、`bne`（等しくない）、`blt`（より小さい）、`bge`（以上）。符号なしで比べるのは `bltu` と `bgeu`
- `bgt` `ble` `beqz` `bnez` は疑似命令。左右を入れ替えたり、`zero` と比べたりする形に展開される
- **if** は「条件の逆で、中を飛び越す」。**if-else** は、then の最後に else を飛び越す `j` を置く
- **while** と **for** は「先頭で抜ける条件を調べ、最後に `j` で先頭に戻る」。ループの中で、条件に関わる値を必ず変える
- ループを二重にすると、行と列のあるもの（三角形、画面全体）を扱える
- 止まらないときは、このサイトの CPU は 1,000,000 命令で打ち切る。条件に関わるレジスタの変化をステップ実行で追う
:::

## 確認問題 {#quiz}

分岐とループを、自分で組み立てます。数の表示は `ecall` の 1 番、文字の表示は 11 番を使ってください。

:::quiz 奇数だけの合計
1 から 50 までの整数のうち、**奇数だけ**を合計し、結果を 10 進数で表示してください（1 + 3 + 5 + … + 49）。ループで計算してください。

```asm starter
    li   a0, 0           # 合計
    li   t0, 1           # i
    # ここに書く
```

```asm answer
    li   a0, 0           # 合計
    li   t0, 1           # i
    li   t1, 50
loop:
    bgt  t0, t1, done
    add  a0, a0, t0
    addi t0, t0, 2       # 次の奇数へ
    j    loop
done:
    li   a7, 1
    ecall
```

:::hint
1 から始めて 2 ずつ増やせば、奇数だけをたどれます。1 ずつ増やして、`andi` で奇数かどうかを調べる書き方でもかまいません。
:::
:::

:::quiz 7 の段
九九の 7 の段（7 × 1 から 7 × 9 まで）を、1 行に 1 つずつ表示してください。出力は `7`、`14`、…、`63` の 9 行で、どの行の後ろにも改行（`'\n'`）を入れます。

```asm starter
    li   t0, 1           # i
    # ここに書く
```

```asm answer
    li   t0, 1           # i
    li   t1, 9
    li   t2, 7
loop:
    bgt  t0, t1, done
    mul  a0, t0, t2
    li   a7, 1
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    addi t0, t0, 1
    j    loop
done:
```

:::hint
`i` を 1 から 9 まで増やしながら、`mul` で 7 × i を計算して表示します。7 ずつ足していく方法でも同じ出力になります。
:::
:::

:::quiz 対角線を引く
画面の左上 (0, 0) から右下 (31, 31) まで、黄色（色番号 5）の対角線を引いてください。(0, 0)、(1, 1)、(2, 2)、…、(31, 31) の 32 点です。ループで描いてください。判定は画面の内容で行います。

```asm starter
    li   t0, 0x10000
    li   t3, 5           # 黄
    # ここに書く
```

```asm answer screen
    li   t0, 0x10000
    li   t3, 5           # 黄
    li   t1, 0
    li   t2, 32
loop:
    sb   t3, 0(t0)
    addi t0, t0, 33      # 1 つ右、1 つ下
    addi t1, t1, 1
    blt  t1, t2, loop
```

:::hint
右に 1 つ動くと番地は 1 増え、下に 1 つ動くと 32 増えます。右下に 1 つ動くと、いくつ増えるでしょうか。
:::
:::

:::quiz コラッツの数列
`t0` に 7 が入っています。次の規則で数を変えていき、1 になるまでの数を、最初の 7 と最後の 1 も含めて 1 行に 1 つずつ表示してください（どの行の後ろにも改行を入れます）。

- 偶数なら、2 で割る
- 奇数なら、3 倍して 1 を足す

7 から始めると、7、22、11、34、… と続き、17 行目で 1 になります。

```asm starter
    li   t0, 7
loop:
    # ここに書く
```

```asm answer
    li   t0, 7
loop:
    mv   a0, t0
    li   a7, 1
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    li   t1, 1
    beq  t0, t1, done    # 1 になったら終わり
    andi t2, t0, 1
    bnez t2, odd
    srli t0, t0, 1       # 偶数：2 で割る
    j    loop
odd:
    slli t3, t0, 1       # 奇数：3 倍して 1 を足す
    add  t0, t0, t3
    addi t0, t0, 1
    j    loop
done:
```

:::hint
ループの先頭で今の数を表示し、1 なら抜けます。そうでなければ、`andi` で偶数か奇数かを調べて、if-else の形で次の数を作ります。
:::
:::
