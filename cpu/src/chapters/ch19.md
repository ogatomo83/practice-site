## プログラムが「困ったこと」をしたら {#trouble}

ここまでのプログラムは、たまにエラーで止まりました。この章は、その「止まる」の中身を開けます。まず、わざと 3 種類の困ったことを起こします。

1 つ目は、命令ではないものを実行することです。`.word` で置いた数 `0xffffffff` は、どの命令の形にも当てはまりません。

```asm run error title="命令ではないものを実行する"
main:
    li   a0, 1
    .word 0xffffffff        # 命令として解釈できない数
    li   a0, 2
```

2 つ目は、4 の倍数ではない番地から `lw` で読むことです。第 12 章で見た**整列**（番地を大きさの倍数にそろえること）の違反です。

```asm run error title="4 の倍数ではない番地を lw で読む"
main:
    li   t0, 0x8001
    lw   t1, 0(t0)
```

3 つ目は、何もない番地に書くことです。このサイトの機械では、`0x30000` 番地にはメモリも入出力もありません。

```asm run error title="何もない番地に書く"
main:
    li   t0, 0x30000
    sw   zero, 0(t0)
```

どれも「何番地のどの命令で、何が起きたか」が出て止まりました。このように、命令を実行している途中で起きる、続けられない出来事を**例外**（exception）と呼びます。

RISC-V は、例外の種類に番号を付けています。このサイトの機械が起こすのは次の 10 種類です。

| 番号 | 名前 | 起きるとき |
| --- | --- | --- |
| 0 | 命令アドレスの整列違反 | 4 の倍数ではない番地へ飛んだ |
| 1 | 命令アクセス違反 | pc が RAM の外に出た |
| 2 | 不正な命令 | 命令として解釈できない数を実行した |
| 3 | ブレークポイント | `ebreak` を実行した |
| 4 | ロードの整列違反 | `lw` `lh` `lhu` で、そろっていない番地を読んだ |
| 5 | ロードのアクセス違反 | 何もない番地を読んだ |
| 6 | ストアの整列違反 | `sw` `sh` で、そろっていない番地に書いた |
| 7 | ストアのアクセス違反 | 何もない番地に書いた |
| 8 | U モードからの ecall | あとの節で使う |
| 11 | M モードからの ecall | 知らない番号の `ecall` を実行した |

:::note 割り算の 0 は例外にならない
多くの CPU では 0 で割ると例外になりますが、RISC-V はなりません。`div` の結果が -1 になるだけです。回路を単純にするための決まりで、0 かどうかを調べたいときは、プログラムが自分で分岐します。
:::

## トラップ：決まった番地へ飛ぶ {#trap}

例外が起きたとき、本物の CPU は「日本語のエラーを出して止まる」わけではありません。CPU がするのは、**あらかじめ決めておいた番地へ飛ぶ**ことだけです。この強制的なジャンプを**トラップ**（trap）、飛び先に置くプログラムを**トラップハンドラ**（以下、ハンドラ）と呼びます。

```fig seq 例外が起きると、CPU は原因と場所を記録して、mtvec に入っている番地へ飛ぶ。ハンドラは mret で元のプログラムへ戻る
{
  colw: 210,
  actors: [
    { id: 'p', label: 'プログラム', kind: 'stack' },
    { id: 'c', label: 'CPU', kind: 'accent' },
    { id: 'h', label: 'ハンドラ', kind: 'heap' },
  ],
  msgs: [
    { from: 'p', to: 'c', label: '困った命令を実行' },
    { note: 'mepc ← その命令の番地', at: 'c' },
    { note: 'mcause ← 原因の番号', at: 'c' },
    { note: 'mtval ← 関係する値', at: 'c' },
    { from: 'c', to: 'h', label: 'pc ← mtvec', style: 'accent' },
    { self: 'h', label: '原因を調べて対処する' },
    { from: 'h', to: 'c', label: 'mret' },
    { from: 'c', to: 'p', label: 'pc ← mepc', style: 'accent' },
  ],
}
```

図に出てくる `mtvec` や `mepc` は、**CSR**（Control and Status Register、制御状態レジスタ）です。x0〜x31 とは別に CPU が持っているレジスタで、CPU 自身の設定と状態が入っています。この章で使うのは次の 6 つです。

| CSR | 中身 | 書くのは |
| --- | --- | --- |
| `mtvec` | トラップの飛び先（ハンドラの番地） | プログラムが最初に設定する |
| `mepc` | 例外を起こした命令の番地 | トラップのときに CPU が入れる |
| `mcause` | 原因の番号（上の表） | トラップのときに CPU が入れる |
| `mtval` | 原因に関係する値。番地の違反なら、その番地 | トラップのときに CPU が入れる |
| `mstatus` | CPU の状態。あとで特権モードの切り替えに使う | CPU とプログラムの両方 |
| `mscratch` | 自由に使える 1 語。ハンドラの作業用 | プログラム |

CSR は `add` や `lw` では触れません。専用の命令で読み書きします。よく使うのは、読む `csrr rd, CSR` と、書く `csrw CSR, rs` です。

最初のハンドラを書きます。`mtvec` にハンドラの番地を入れてから、さっきの整列違反を起こします。

```asm run title="はじめてのハンドラ：原因と場所を表示して終わる"
main:
    la   t0, handler
    csrw mtvec, t0          # 困ったら handler へ飛べ、と CPU に伝える

    li   t0, 0x8001
    lw   t1, 0(t0)          # ここで例外（0x14 番地の命令）
    li   a0, 'X'            # ここには来ない
    li   a7, 11
    ecall

handler:
    la   a0, s_cause
    li   a7, 4
    ecall
    csrr a0, mcause         # 原因の番号
    li   a7, 1
    ecall
    la   a0, s_epc
    li   a7, 4
    ecall
    csrr a0, mepc           # 例外を起こした命令の番地
    li   a7, 34
    ecall
    la   a0, s_tval
    li   a7, 4
    ecall
    csrr a0, mtval          # 読もうとした番地
    li   a7, 34
    ecall
    li   a7, 10
    ecall

.data
s_cause: .asciz "mcause = "
s_epc:   .asciz "\nmepc   = "
s_tval:  .asciz "\nmtval  = "
```

今度はエラーで止まらず、ハンドラが動きました。`mcause` は 4（ロードの整列違反）、`mepc` は `lw` の番地、`mtval` は読もうとした `0x00008001` です。「CPU を見る」でステップ実行すると、`lw` の次に pc が `handler` へ飛ぶ様子を追えます。

:::note このサイトの機械の決まり
`mtvec` が 0 のまま（設定していない）なら、例外はこれまでどおり日本語のエラーになって止まります。これは学習用の親切で、本物の CPU は `mtvec` が指す番地へ必ず飛びます。そこにハンドラがなければ、でたらめな命令を実行し続けることになります。0 を「未設定」の印に使っているので、この機械ではハンドラを 0 番地には置けません。
:::

`mtval` に入る値は、原因によって違います。不正な命令のときは、その機械語が入ります。

```asm run title="不正な命令では、mtval にその機械語が入る"
main:
    la   t0, handler
    csrw mtvec, t0
    .word 0xffffffff

handler:
    csrr a0, mcause
    li   a7, 1
    ecall                   # 2
    li   a0, ' '
    li   a7, 11
    ecall
    csrr a0, mtval
    li   a7, 34
    ecall                   # 0xffffffff
    li   a7, 10
    ecall
```

## 戻る：mepc と mret {#mret}

ハンドラは、対処を終えたら元のプログラムへ戻れます。戻る命令が **`mret`** で、`mepc` に入っている番地へ飛びます。

ここに注意が 1 つあります。`mepc` が指しているのは、**例外を起こした命令そのもの**です。そのまま `mret` すると同じ命令をもう一度実行し、また例外になります。

```asm run title="mepc を進めずに mret すると、同じ命令で例外が起き続ける"
main:
    la   t0, handler
    csrw mtvec, t0
    li   s0, 0              # ハンドラが呼ばれた回数
    li   t0, 0x8001
    lw   t1, 0(t0)
    li   a7, 10
    ecall

handler:
    li   a0, '!'
    li   a7, 11
    ecall
    addi s0, s0, 1
    li   t1, 8
    beq  s0, t1, giveup     # 8 回目であきらめる
    mret                    # mepc は lw を指したまま

giveup:
    li   a7, 10
    ecall
```

`!` が 8 個並びました。8 回であきらめる処理がなければ、いつまでも続きます。困った命令を**飛ばして**続けたいときは、`mepc` を 4 増やしてから戻ります。命令は 1 つ 4 バイトなので、これで次の命令を指します。

```asm run title="メッセージを出して、次の命令から続ける"
main:
    la   t0, handler
    csrw mtvec, t0

    li   t0, 0x8001
    lw   t1, 0(t0)          # 例外 1 回目
    .word 0xffffffff        # 例外 2 回目
    la   a0, s_done
    li   a7, 4
    ecall
    li   a7, 10
    ecall

handler:
    la   a0, s_skip
    li   a7, 4
    ecall
    csrr a0, mepc
    li   a7, 34
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    csrr t0, mepc
    addi t0, t0, 4          # 次の命令へ
    csrw mepc, t0
    mret

.data
s_skip: .asciz "例外。飛ばした命令の番地 = "
s_done: .asciz "最後まで来ました\n"
```

例外が 2 回起きても、プログラムは最後まで進みました。

:::warn 「飛ばす」が正しい対処とは限らない
読めなかった `lw` を飛ばすと、`t1` には古い値が残ったままです。飛ばして続けるのは、仕組みを見るための練習です。本物の OS は、原因を取り除いてから同じ命令をやり直すか（あとで出てくるページフォールト）、そのプログラムを終わらせます。
:::

## ハンドラはレジスタを壊してはいけない {#save}

上のハンドラには欠陥があります。メッセージを出すために `a0`、`a7`、`t0` を書き換えていることです。例外はプログラムのどこで起きるかわかりません。元のプログラムから見ると、ある命令の前後で、関係のないレジスタの値が突然変わることになります。

```asm run title="ハンドラがレジスタを壊す" regs="a0,a7,t0"
main:
    la   t0, handler
    csrw mtvec, t0
    li   a0, 100
    li   a7, 200
    li   t0, 300
    .word 0xffffffff        # 例外。飛ばして続ける
    add  a0, a0, a7
    add  a0, a0, t0         # 100 + 200 + 300 = 600 のはず
    li   a7, 1
    ecall
    li   a7, 10
    ecall

handler:
    li   a0, '!'
    li   a7, 11
    ecall
    csrr t0, mepc
    addi t0, t0, 4
    csrw mepc, t0
    mret
```

600 ではなく、でたらめな数が出ました。関数なら「`t0` や `a0` は壊してよい」という呼び出し規約がありましたが、ハンドラは呼ばれたのではなく**割り込んだ**側です。使うレジスタはすべて、**保存して、戻る前に元に戻す**必要があります。

保存先はスタックです。ただし、割り込まれたプログラムの `sp` が正しい保証はありません。そこでハンドラ専用のスタックを用意し、その番地を `mscratch` に入れておきます。ハンドラの入口で `csrrw sp, mscratch, sp` を実行すると、`sp` と `mscratch` の中身が 1 命令で入れ替わります。

```asm run title="専用のスタックに保存してから使い、元に戻す" regs="a0,a7,t0"
main:
    la   t0, handler
    csrw mtvec, t0
    la   t0, hstack_top
    csrw mscratch, t0       # ハンドラ用のスタックの番地を預ける
    li   a0, 100
    li   a7, 200
    li   t0, 300
    .word 0xffffffff
    add  a0, a0, a7
    add  a0, a0, t0
    li   a7, 1
    ecall                   # 600
    li   a7, 10
    ecall

handler:
    csrrw sp, mscratch, sp  # sp ↔ mscratch。ハンドラ用のスタックに切り替える
    addi sp, sp, -12
    sw   a0, 0(sp)          # 使うレジスタを保存
    sw   a7, 4(sp)
    sw   t0, 8(sp)

    li   a0, '!'
    li   a7, 11
    ecall
    csrr t0, mepc
    addi t0, t0, 4
    csrw mepc, t0

    lw   a0, 0(sp)          # 元に戻す
    lw   a7, 4(sp)
    lw   t0, 8(sp)
    addi sp, sp, 12
    csrrw sp, mscratch, sp  # sp を元のプログラムのものに戻す
    mret

.data
        .space 64
hstack_top:
```

今度は `!600` です。元のプログラムは、例外が起きたことに気づきません。この「保存 → 処理 → 復元 → `mret`」が、ハンドラの基本の形です。

## 原因で振り分ける {#dispatch}

`mtvec` は 1 つしかないので、どの例外でも同じハンドラに飛びます。ハンドラは最初に `mcause` を読み、原因ごとの処理へ分岐します。

次の例は、原因の番号を添字にして、メッセージの番地の表を引きます。第 12 章の配列の読み方と同じです。`ebreak` は、わざとブレークポイントの例外（3 番）を起こす命令です。

```asm run title="mcause で表を引いて、原因の名前を出す"
main:
    la   t0, handler
    csrw mtvec, t0
    .word 0xffffffff        # 2：不正な命令
    ebreak                  # 3：ブレークポイント
    li   t0, 0x8002
    lw   t1, 0(t0)          # 4：ロードの整列違反
    li   t0, 0x30000
    sb   zero, 0(t0)        # 7：ストアのアクセス違反
    li   a7, 10
    ecall

handler:
    csrr t0, mcause
    slli t0, t0, 2          # 番号 × 4
    la   t1, names
    add  t1, t1, t0
    lw   a0, 0(t1)          # names[mcause]
    li   a7, 4
    ecall
    csrr t0, mepc
    addi t0, t0, 4
    csrw mepc, t0
    mret

.data
names:  .word n_x, n_x, n_2, n_3, n_4, n_x, n_x, n_7
n_2:    .asciz "不正な命令\n"
n_3:    .asciz "ブレークポイント\n"
n_4:    .asciz "ロードの整列違反\n"
n_7:    .asciz "ストアのアクセス違反\n"
n_x:    .asciz "そのほか\n"
```

（短くするために、この例のハンドラはレジスタの保存を省いています。）

:::deep ebreak とデバッガ
デバッガで「この行で止める」と指定すると、デバッガはその場所の命令を `ebreak` に書き換えます。実行がそこに来るとトラップが起き、デバッガに制御が移ります。続きを実行するときは、元の命令に書き戻します。ブレークポイントという名前はここから来ています。
:::

## 特権モード：M と U {#modes}

ここまでの話には穴があります。`mtvec` はプログラムが自由に書き換えられるので、行儀の悪いプログラムがハンドラを差し替えられてしまいます。これでは、プログラムを見張る役（OS）が成り立ちません。

そこで CPU は、**特権モード**という「いま、どの立場で動いているか」の状態を持ちます。このサイトの機械にあるのは 2 つです。

```fig graph 2 つの特権モード。U モードのプログラムは、CSR に触れない。M モードへ移る道はトラップだけで、U モードへ移る道は mret だけ
{
  nodes: [
    { id: 'u', label: 'U モード（ユーザー）', sub: 'ふつうのプログラム。CSR 命令と mret は不正な命令になる', x: 0, y: 0, kind: 'stack' },
    { id: 'm', label: 'M モード（マシン）', sub: '何でもできる。OS やファームウェア。電源を入れた直後はここ', x: 0, y: 1, kind: 'accent' },
  ],
  edges: [
    { from: 'u', to: 'm', label: 'トラップ（例外、ecall）', curve: -170 },
    { from: 'm', to: 'u', label: 'mret', curve: -170, style: 'accent' },
  ],
  row: 150,
}
```

- **M モード**（マシンモード）：すべての命令と CSR が使える。機械は必ずこのモードで動き始める
- **U モード**（ユーザーモード）：ふつうのプログラム用。CSR を読み書きする命令と `mret` は、不正な命令（2 番の例外）になる

M モードから U モードへ移るには、`mret` を使います。`mret` は「`mepc` へ飛ぶ」だけでなく、「**`mstatus` の MPP という 2 ビットに書いてあるモードに移る**」命令でもあります。MPP（Machine Previous Privilege）はビット 12〜11 にあり、3 が M、0 が U を表します。トラップが起きると、CPU はここに「直前のモード」を記録します。

つまり、MPP を 0 にして、`mepc` に行き先を入れて `mret` すれば、「U モードのプログラムへ戻る」ふりをして U モードに入れます。

```asm run title="U モードに入る。U モードで CSR に触ると、トラップで M モードへ戻される"
main:
    la   t0, handler
    csrw mtvec, t0
    li   t0, 0x1800         # MPP の 2 ビット（ビット 12 と 11）
    csrc mstatus, t0        # MPP を 0（U）にする。csrc は指定したビットを 0 にする
    la   t0, user
    csrw mepc, t0
    mret                    # user へ飛び、U モードになる

user:
    li   a0, 'U'
    li   t0, 0x20000
    sb   a0, 0(t0)          # コンソールに 1 文字（メモリマップド I/O）
    la   t0, user
    csrw mtvec, t0          # ハンドラを差し替えようとする → 不正な命令
    li   a0, 'X'            # ここには来ない
    li   t0, 0x20000
    sb   a0, 0(t0)

handler:                    # ここは M モード
    la   a0, s_caught
    li   a7, 4
    ecall
    csrr a0, mcause
    li   a7, 1
    ecall
    li   a7, 10
    ecall

.data
s_caught: .asciz "\nU モードのプログラムを止めました。mcause = "
```

U モードのプログラムは `mtvec` を書き換えられず、M モードのハンドラに捕まりました。見張る側と見張られる側が、CPU の仕組みで分けられたことになります。

:::warn このサイトの機械にないもの：メモリの保護
本物の RISC-V には、U モードのプログラムが触れてよい番地の範囲を決める仕組み（PMP：物理メモリ保護、および仮想メモリ）があります。**このサイトの機械にはありません。** U モードのプログラムも、RAM のどこでも読み書きでき、上の例のように入出力の番地へも直接書けます。守られているのは CSR と `mret` だけです。
:::

:::deep S モード
本物の RISC-V には、M と U の間に S モード（スーパーバイザ）があります。Linux のような OS の本体は S モードで動き、その下の M モードではファームウェア（OpenSBI など）が動きます。このサイトの機械は M と U だけなので、OS の役を M モードのプログラムが受け持ちます。小さな組み込み機器の RISC-V も、この 2 つだけの構成をよく使います。
:::

## ecall で OS を呼ぶ {#syscall}

U モードのプログラムは、自分では入出力の設定も終了もできない、という建前です。必要なときは M モードのプログラム、つまり **OS** に頼みます。頼む手段が **`ecall`** です。

`ecall` は、わざと例外（U モードからなら 8 番）を起こす命令です。トラップで OS のハンドラへ飛び、OS は頼まれた仕事をして、`mret` で戻ります。この呼び出しを**システムコール**と呼びます。

```fig seq システムコール。U モードのプログラムは ecall で OS に頼み、OS が代わりに装置を操作する
{
  colw: 200,
  actors: [
    { id: 'u', label: 'プログラム（U）', kind: 'stack' },
    { id: 'o', label: 'OS（M）', kind: 'accent' },
    { id: 'd', label: 'コンソール', kind: 'ext' },
  ],
  msgs: [
    { note: 'a7 ← 1、a0 ← 文字', at: 'u' },
    { from: 'u', to: 'o', label: 'ecall（mcause = 8）', style: 'accent' },
    { self: 'o', label: 'a7 を見て仕事を選ぶ' },
    { from: 'o', to: 'd', label: '0x20000 に 1 バイト書く' },
    { self: 'o', label: 'mepc を 4 進める' },
    { from: 'o', to: 'u', label: 'mret', style: 'accent' },
  ],
}
```

これまで使ってきた `li a7, 11` と `ecall` も、同じ形でした。あれは M モードの `ecall` で、このサイトの機械が OS の代わりに直接処理していたのです。U モードから `ecall` すると、機械は処理せず、`mtvec` のハンドラに任せます。番号と意味は、ハンドラを書く人、つまり OS を作る人が決めます。

小さな OS を作ります。システムコールは 2 つだけです。

| a7 | 仕事 |
| --- | --- |
| 1 | `a0` の文字をコンソールに出す |
| 2 | `a0` を終了コードにして終わる |

```asm run title="小さな OS と、U モードのプログラム"
# ---------- OS（M モード）----------
main:
    la   t0, trap
    csrw mtvec, t0
    la   t0, kstack_top
    csrw mscratch, t0       # OS 用のスタック
    li   t0, 0x1800
    csrc mstatus, t0        # MPP = U
    la   t0, user
    csrw mepc, t0
    mret                    # プログラムを U モードで始める

trap:
    csrrw sp, mscratch, sp
    addi sp, sp, -8
    sw   t0, 0(sp)
    sw   t1, 4(sp)

    csrr t0, mcause
    li   t1, 8
    bne  t0, t1, kill       # ecall 以外の例外なら、プログラムを止める
    csrr t0, mepc
    addi t0, t0, 4          # ecall の次の命令へ戻る
    csrw mepc, t0

    li   t0, 1
    beq  a7, t0, sys_putc
    li   t0, 2
    beq  a7, t0, sys_exit
    li   a0, -1             # 知らない番号には -1 を返す
    j    back

sys_putc:
    li   t0, 0x20000
    sb   a0, 0(t0)          # OS が代わりに装置へ書く
back:
    lw   t0, 0(sp)
    lw   t1, 4(sp)
    addi sp, sp, 8
    csrrw sp, mscratch, sp
    mret

sys_exit:
    li   a7, 93             # 機械に「終了」を頼む（M モードの ecall）
    ecall

kill:
    la   a0, s_kill
    li   a7, 4
    ecall
    csrr a0, mcause
    li   a7, 1
    ecall
    li   a0, 1
    li   a7, 93
    ecall

# ---------- プログラム（U モード）----------
user:
    la   s0, text
1:  lbu  a0, 0(s0)
    beqz a0, 2f
    li   a7, 1              # 文字を出す
    ecall
    addi s0, s0, 1
    j    1b
2:  li   a0, 0
    li   a7, 2              # 終了
    ecall

.data
text:   .asciz "Hello from U mode\n"
s_kill: .asciz "[OS] プログラムを止めました。mcause = "
        .align 2            # スタックは 4 の倍数の番地に置く
        .space 64
kstack_top:
```

U モードのプログラムは、コンソールの番地も CSR も知りません。`a7` と `a0` を決めて `ecall` するだけです。装置の操作は OS の中に閉じ込められています。

この OS は、プログラムが例外を起こすと `kill` で止めます。`user` の先頭に `csrw mtvec, zero` や `lw t0, 1(zero)` を足して実行すると、OS のメッセージが出て、終了コード 1 で終わります。Linux で「Segmentation fault」と出てプログラムが終わるのは、これと同じ流れです。

:::note 本物の OS のシステムコール番号
RISC-V 版の Linux でも、番号は `a7`、引数は `a0` から、戻り値は `a0` です。番号は Linux が決めていて、たとえば `write` が 64、`exit` が 93 です。このサイトの機械の `ecall` の番号（1、4、11 など）は、学習用のシミュレータ RARS のものに合わせています。
:::

## 本物の OS がしていること {#os}

小さな OS は、1 つのプログラムを動かして終わりました。本物の OS は、たくさんのプログラムを同時に動かし、互いに邪魔をさせません。そのための仕組みを 3 つ見ます。最初の 1 つは動かせます。残りの 2 つは、**このサイトの機械にない機能**なので、図で説明します。

### プログラムを切り替える

CPU が 1 つでも、複数のプログラムが同時に動いて見えるのは、OS が短い時間ごとに**切り替えて**いるからです。動いているプログラム 1 つ 1 つを**プロセス**と呼びます。

切り替えの中身は、レジスタの入れ替えです。いまのプロセスのレジスタと `mepc` をメモリに保存し、次のプロセスのものを読み込んで `mret` します。この操作を**コンテキストスイッチ**と呼びます。

次の例は、2 つの仕事 A と B を切り替えます。システムコールを 1 つ足しました。3 番の「ゆずる」（yield）です。呼ぶと、OS はもう片方の仕事に切り替えます。

```asm run title="2 つの仕事を、システムコール「ゆずる」で切り替える"
# コンテキスト（仕事 1 つぶんの保存場所）：+0 pc、+4 sp、+8 s0
main:
    la   t0, trap
    csrw mtvec, t0
    la   t0, ctx_b          # 仕事 B の最初の状態を作っておく
    la   t1, task_b
    sw   t1, 0(t0)          # pc = task_b
    li   t1, 0xf000
    sw   t1, 4(t0)          # sp = 0xf000（A とは別のスタック）
    la   s1, ctx_a          # s1 = いま動いている仕事のコンテキスト（OS が使う）
    li   t0, 0x1800
    csrc mstatus, t0
    la   t0, task_a
    csrw mepc, t0
    mret                    # 仕事 A から始める

trap:
    csrr t0, mepc
    addi t0, t0, 4
    li   t1, 3
    beq  a7, t1, sys_yield
    li   t1, 1
    beq  a7, t1, sys_putc
    li   a7, 10             # それ以外は終了
    ecall
sys_putc:
    csrw mepc, t0
    li   t1, 0x20000
    sb   a0, 0(t1)
    mret
sys_yield:
    sw   t0, 0(s1)          # いまの仕事の pc、sp、s0 を保存
    sw   sp, 4(s1)
    sw   s0, 8(s1)
    la   t0, ctx_a          # もう片方のコンテキストを選ぶ
    bne  s1, t0, 1f
    la   t0, ctx_b
1:  mv   s1, t0
    lw   t0, 0(s1)          # 次の仕事の pc、sp、s0 を読み込む
    csrw mepc, t0
    lw   sp, 4(s1)
    lw   s0, 8(s1)
    mret

task_a:
    li   s0, 3              # 3 回くり返す
1:  li   a0, 'A'
    li   a7, 1
    ecall
    li   a7, 3              # ゆずる
    ecall
    addi s0, s0, -1
    bnez s0, 1b
    li   a0, '\n'
    li   a7, 1
    ecall
    li   a7, 2              # 終了
    ecall

task_b:
    li   s0, 'a'
1:  mv   a0, s0
    li   a7, 1
    ecall
    li   a7, 3
    ecall
    addi s0, s0, 1          # a, b, c, …
    j    1b

.data
ctx_a:  .word 0, 0, 0
ctx_b:  .word 0, 0, 0
```

`AaAbAc` と交互に出ます。A も B も、自分の `s0` を数え続けています。B の `s0` は文字、A の `s0` は残りの回数で、同じレジスタを取り合っているのに混ざりません。切り替えのたびに OS が入れ替えているからです。

:::note この例の簡略化
保存しているのは pc、sp、s0 だけです。この例の仕事はほかのレジスタを ecall の前後で持ち越さないので、これで足ります。本物の OS は 31 本すべてを保存します。また、OS は `s1` を自分用に使っています。
:::

### タイマー割り込み：ゆずらないプログラムからも取り上げる

上の例は、仕事が自分から「ゆずる」と言わないと切り替わりません。無限ループに入ったプログラムは、CPU を独り占めします。

本物の機械には**タイマー**があります。決めた時刻になると、実行中の命令とは関係なく、CPU にトラップを起こさせます。このように、**命令の外からの合図**で起きるトラップを**割り込み**（interrupt）と呼びます。キーボードやネットワークの装置も、割り込みで CPU に知らせます。

割り込みも、CPU から見れば例外と同じトラップです。`mtvec` へ飛び、`mepc` に戻り先が入ります。違いは `mcause` の最上位ビットが 1 になることで、ハンドラはここで区別します。タイマー割り込みなら `mcause` は `0x80000007` です。割り込みを受けるかどうかは、`mstatus` の MIE ビットと、CSR の `mie` で決めます。

:::warn このサイトの機械にないもの：割り込み
このサイトの機械には、タイマーも、割り込みもありません。`mie` に値を書くことはできますが、何も起きません。トラップが起きるのは、命令が原因の例外と `ecall`、`ebreak` だけです。
:::

### 仮想メモリ：プロセスごとに別の番地の世界

最後は、メモリの守り方です。プロセス A が B のメモリを書き換えられては困ります。本物の OS は、プロセスごとに**別の番地の世界**を見せます。

プログラムが使う番地を**仮想アドレス**、本当のメモリの番地を**物理アドレス**と呼びます。CPU は、メモリを読み書きするたびに、仮想アドレスを物理アドレスへ変換します。変換の表が**ページテーブル**で、OS がプロセスごとに作ります。変換の単位は 4 KiB（4096 バイト）の区画で、これを**ページ**と呼びます。

ページテーブルに「割り当てなし」と書いてあるページに触ると、**ページフォールト**という例外が起きます（`mcause` は 12、13、15）。OS はここで、ディスクから中身を読み込んでページを割り当て、**同じ命令をやり直します**。`mepc` が例外を起こした命令そのものを指しているのは、このやり直しのためです。割り当てる理由がなければ、OS はそのプロセスを終わらせます。

:::warn このサイトの機械にないもの：仮想メモリ
このサイトの機械には、ページテーブルも、アドレスの変換もありません。プログラムが書いた番地が、そのまま RAM の番地です。ページフォールトの例外も起きません。
:::

:::try
1. 下の練習用のプログラムは、3 か所で例外を起こします。ハンドラが出す `mcause` の並びを予想してから実行してください
2. ハンドラの `addi t0, t0, 4` を消すとどうなるか、予想してから確かめてください
3. `main` の最後に `ebreak` を足して、3 番が出ることを確かめてください
:::

```asm run title="練習用" maxsteps="5000"
main:
    la   t0, handler
    csrw mtvec, t0
    li   t0, 0x8003
    sw   zero, 0(t0)
    li   t0, 0x40000
    lbu  t1, 0(t0)
    li   a7, 77
    ecall
    li   a7, 10
    ecall

handler:
    csrr a0, mcause
    li   a7, 1
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    csrr t0, mepc
    addi t0, t0, 4
    csrw mepc, t0
    mret
```

:::key この章のまとめ
- 命令の実行中に起きる、続けられない出来事が**例外**。不正な命令（2）、整列違反（4、6）、アクセス違反（5、7）などの番号がある
- 例外が起きると、CPU は `mepc`（場所）、`mcause`（原因）、`mtval`（関係する値）を記録して、`mtvec` の番地へ飛ぶ。これが**トラップ**
- ハンドラは **`mret`** で `mepc` の番地へ戻る。`mepc` は例外を起こした命令を指すので、飛ばして続けるなら 4 を足す
- ハンドラは割り込んだ側なので、使うレジスタは保存して元に戻す。`mscratch` に専用のスタックの番地を預けておく
- **特権モード**は M（何でもできる）と U（CSR と `mret` が使えない）。`mstatus` の MPP を 0 にして `mret` すると U モードに入る
- U モードのプログラムは **`ecall`** で OS に仕事を頼む（システムコール）。番号は `a7`、引数と戻り値は `a0`
- 本物の OS は、**コンテキストスイッチ**でプロセスを切り替え、**タイマー割り込み**で CPU を取り上げ、**仮想メモリ**でプロセスごとに別の番地の世界を見せる。このサイトの機械には、割り込みとメモリの保護、仮想メモリはない
:::

## 確認問題 {#quiz}

この章の内容を、自分でハンドラと小さな OS を書いて確かめます。どの問題も、書いたコードの後ろに、問題文で説明する「用意されたコード」がつながって実行されます。

:::quiz 原因の番号を出して、続ける

    li   a7, 11
    ecall

```

:::quiz レジスタを壊さないハンドラ

    sub  s2, sp, s0
    mv   a0, s1
    li   a7, 1
    ecall
    li   a0, ' '
    li   a7, 11
    ecall
    mv   a0, s2
    li   a7, 1
    ecall
    li   a0, ' '
    li   a7, 11
    ecall
    lw   a0, count
    li   a7, 1
    ecall
    li   a7, 10
    ecall
.data
count: .word 0
```

```asm starter
handler:
    # count を 1 増やして、次の命令へ戻る。レジスタは元に戻す

```

:::hint
`count` を増やすには、番地を入れるレジスタと値を入れるレジスタの 2 本が要ります。最初に `sp` を下げて 2 本を保存し、`mret` の前に読み戻して `sp` を上げます。
:::
:::

:::quiz システムコールを受ける OS
トラップハンドラ `trap` を書いて、次の 2 つのシステムコールを受けられるようにしてください。

| a7 | 仕事 |
| --- | --- |
| 1 | `a0` の文字をコンソールに出して、`ecall` の次の命令へ戻る |
| 2 | `a0` を終了コードにして、機械を終了する |

用意されたコードは、トラップが起きると `trap` へ飛ぶように `mtvec` を設定し、U モードのプログラムを始めます。そのプログラムは上の 2 つを使って `Hi!` と改行を出し、終了コード 7 で終わります。コンソールの出力と終了コードの両方で判定します。`trap` の中では、`a7` と `t0`〜`t2` を壊してかまいません。

```asm answer console exit
trap:
    csrr t0, mepc
    addi t0, t0, 4
    csrw mepc, t0
    li   t0, 2
    beq  a7, t0, sys_exit
    li   t0, 0x20000
    sb   a0, 0(t0)
    mret
sys_exit:
    li   a7, 93
    ecall
```

```asm given
vec:
    j    trap
main:
    la   t0, vec
    csrw mtvec, t0
    li   t0, 0x1800
    csrc mstatus, t0
    la   t0, user
    csrw mepc, t0
    mret
user:
    la   s0, hi
1:  lbu  a0, 0(s0)
    beqz a0, 2f
    li   a7, 1
    ecall
    addi s0, s0, 1
    j    1b
2:  li   a0, 7
    li   a7, 2
    ecall
.data
hi: .asciz "Hi!\n"
```

```asm starter
trap:
    # a7 が 1 なら a0 の文字を出して戻る。2 なら a0 を終了コードにして終わる

```

:::hint
`trap` の中は M モードなので、`ecall` は機械が直接処理します。文字は `0x20000` 番地に `sb` で書くか、`a7` を 11 にして `ecall` します。終了は `a7` を 93 にして `ecall` です。戻る前に `mepc` を 4 進めるのを忘れないでください。
:::
:::

:::quiz OS を呼ぶプログラム
今度は U モードの側です。プログラム `user` を書いてください。`.data` のラベル `text` にある文字列（NUL 終端）を、システムコールで 1 文字ずつ出し、最後に終了コード 0 で終わります。

用意された OS のシステムコールは、本文と同じ 2 つです（`a7` が 1：`a0` の文字を出す。`a7` が 2：`a0` を終了コードにして終わる）。OS は終了のときに、呼ばれた回数を `[N calls]` の形で表示します。`user` は U モードで動くので、`a7` が 11 や 10 の `ecall` は使えません。

```asm answer console exit
user:
    la   s0, text
loop:
    lbu  a0, 0(s0)
    beqz a0, done
    li   a7, 1
    ecall
    addi s0, s0, 1
    j    loop
done:
    li   a0, 0
    li   a7, 2
    ecall
```

```asm given
main:
    la   t0, trap
    csrw mtvec, t0
    li   s11, 0
    li   t0, 0x1800
    csrc mstatus, t0
    la   t0, user
    csrw mepc, t0
    mret
trap:
    csrr t0, mcause
    li   t1, 8
    bne  t0, t1, os_kill
    addi s11, s11, 1
    csrr t0, mepc
    addi t0, t0, 4
    csrw mepc, t0
    li   t0, 1
    beq  a7, t0, os_putc
    li   t0, 2
    beq  a7, t0, os_exit
os_kill:
    la   a0, s_bad
    li   a7, 4
    ecall
    li   a0, 1
    li   a7, 93
    ecall
os_putc:
    li   t0, 0x20000
    sb   a0, 0(t0)
    mret
os_exit:
    mv   s10, a0
    li   a0, '['
    li   a7, 11
    ecall
    mv   a0, s11
    li   a7, 1
    ecall
    la   a0, s_calls
    li   a7, 4
    ecall
    mv   a0, s10
    li   a7, 93
    ecall
.data
text:    .asciz "RISC-V\n"
s_calls: .asciz " calls]\n"
s_bad:   .asciz "[killed]\n"
```

```asm starter
user:
    # text の文字列をシステムコールで 1 文字ずつ出し、終了コード 0 で終わる

```

:::hint
`la` で `text` の番地をレジスタに入れ、`lbu` で 1 文字読みます。0 なら終わり、そうでなければ `a7` を 1 にして `ecall` し、番地を 1 進めて繰り返します。OS は `t0` と `t1` を壊すので、番地は `s0` などに入れておきます。
:::
:::
