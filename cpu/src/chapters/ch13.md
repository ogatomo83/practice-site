## 関数：処理に名前を付けて、何度も呼ぶ {#why}

プログラムが長くなると、同じ処理があちこちに出てきます。数を表示して改行する、2 つの数の大きいほうを選ぶ、といった処理です。そのたびに同じ命令を書き写すのは手間で、間違いのもとにもなります。

そこで、ひとまとまりの処理を 1 か所に書き、必要なところから**呼ぶ**ことにします。このまとまりが**関数**です。

関数を呼ぶ仕組みは、第 11 章のジャンプとほとんど同じです。違いは 1 つだけです。**関数が終わったら、呼んだ場所の続きに戻ってこなければなりません。** この章の内容は、すべてこの「どうやって戻るか」から出てきます。

```fig seq 関数を呼んで、戻る。call は「戻る番地」を ra に入れてから飛び、ret は ra の番地に飛ぶ
{
  colw: 300,
  actors: [ { id: 'm', label: 'main', kind: 'accent' }, { id: 'f', label: 'double', kind: 'stack' } ],
  msgs: [
    { note: 'li a0, 21', at: 'm' },
    { from: 'm', to: 'f', label: 'call double（ra = 次の命令の番地）', style: 'accent' },
    { note: 'add a0, a0, a0', at: 'f' },
    { from: 'f', to: 'm', label: 'ret（ra の番地へ飛ぶ）', style: 'accent' },
    { note: '続きを実行（a0 は 42）', at: 'm' },
  ],
}
```

## call と ret：戻る番地は ra が覚えている {#call-ret}

さっそく動かします。`double` は、`a0` を 2 倍にする関数です。

```asm run step title="関数を呼んで、戻る"
main:
    li   a0, 21
    call double         # double へ飛ぶ。戻る番地を ra に入れる
    li   a7, 1          # ← 戻ってくる場所
    ecall
    li   a7, 10         # プログラムを終える
    ecall

double:
    add  a0, a0, a0     # a0 を 2 倍に
    ret                 # ra の番地へ戻る
```

1 命令ずつ進めて、`ra` の変化を見てください。`call double` を実行すると、`ra` に 8 が入り、`pc` が `double` の番地に飛びます。8 は、`call` の次の命令（`li a7, 1`）の番地です。`ret` を実行すると、`pc` が 8 に戻ります。

- `call ラベル`：**次の命令の番地を `ra` に入れて**、ラベルへ飛ぶ
- `ret`：`ra` に入っている番地へ飛ぶ

`ra` は return address（戻る番地）の略で、レジスタ `x1` の別名です。関数に飛ぶ前に「ここに戻ってきて」という番地のメモを `ra` に残しておく、というだけの仕組みです。

`main` の最後の `li a7, 10` と `ecall` は、プログラムを終える合図です。これがないと、実行が `main` の下にある `double` の中へそのまま流れ込んでしまいます。

### どこから呼んでも、呼んだ場所に戻る

`ra` に入る番地は、呼んだ場所によって変わります。だから、同じ関数を何か所から呼んでも、それぞれの続きに戻れます。関数の中で `ra` を表示して確かめます。

```asm run title="2 か所から呼ぶと、ra が変わる"
main:
    call where          # 1 回目（0 番地の命令）
    call where          # 2 回目（4 番地の命令）
    li   a7, 10
    ecall

where:
    mv   a0, ra         # 戻る番地を表示する
    li   a7, 34
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    ret
```

1 回目は 0x00000004、2 回目は 0x00000008 です。どちらも「`call` の次の命令」の番地になっています。

:::deep call と ret の正体は jal と jalr
`call` と `ret` は疑似命令です。本当の命令は次の 2 つです。

- `jal ra, ラベル`（jump and link）：`pc + 4` を `ra` に入れて、ラベルへ飛ぶ。`call ラベル` はこれに置き換わる
- `jalr zero, 0(ra)`（jump and link register）：レジスタに入っている番地へ飛ぶ。`ret` はこれに置き換わる。戻る番地の書き込み先を `zero` にして、捨てている

第 11 章の `j ラベル` も、実は `jal zero, ラベル` でした。「戻る番地を覚えるかどうか」だけが、ジャンプと関数呼び出しの違いです。
:::

## 引数は a0〜a7 に、戻り値は a0 に {#args}

関数に渡す値を**引数**、関数が返す値を**戻り値**と呼びます。RISC-V では、どのレジスタで受け渡すかが決まっています。

| 何を | どのレジスタに |
| --- | --- |
| 引数（1 番目から順に） | `a0`、`a1`、`a2` … `a7` |
| 戻り値 | `a0`（2 つ目があれば `a1`） |

a は argument（引数）の a です。`double` が `a0` で受け取って `a0` で返していたのは、この約束に従っていたからです。引数が 2 つの関数を書いてみます。

```asm run title="2 つの数の大きいほうを返す関数"
main:
    li   a0, 17         # 1 番目の引数
    li   a1, 42         # 2 番目の引数
    call max2
    li   a7, 1          # 戻り値は a0 に入っている
    ecall
    li   a7, 10
    ecall

# max2(a0, a1)：大きいほうを a0 に返す
max2:
    bge  a0, a1, max2_done
    mv   a0, a1
max2_done:
    ret
```

関数の前には、コメントで「何を受け取り、何を返すか」を書いておく習慣を付けましょう。アセンブリには引数の宣言がないので、コメントだけが頼りです。

関数にしておくと、組み合わせて使えます。`max2` を 2 回呼べば、3 つの数の最大が出せます。

```asm run title="max2 を 2 回使って、3 つの数の最大を出す"
main:
    li   a0, 17
    li   a1, 42
    call max2           # a0 = max(17, 42)
    li   a1, 29
    call max2           # a0 = max(その結果, 29)
    li   a7, 1
    ecall
    li   a7, 10
    ecall

max2:
    bge  a0, a1, max2_done
    mv   a0, a1
max2_done:
    ret
```

配列を受け取る関数は、配列そのものではなく**先頭の番地**を引数にします。第 12 章の合計のプログラムを関数にすると、こうなります。

```asm run title="配列の合計を返す関数"
.data
nums: .word 31, 4, 15, 92, 65

.text
main:
    la   a0, nums       # 1 番目の引数：先頭の番地
    li   a1, 5          # 2 番目の引数：要素の数
    call sum
    li   a7, 1
    ecall
    li   a7, 10
    ecall

# sum(a0 = 配列の番地, a1 = 個数)：合計を a0 に返す
sum:
    li   t0, 0          # 合計
sum_loop:
    beqz a1, sum_done
    lw   t1, 0(a0)
    add  t0, t0, t1
    addi a0, a0, 4
    addi a1, a1, -1
    j    sum_loop
sum_done:
    mv   a0, t0
    ret
```

## 関数の中で関数を呼ぶと、ra が上書きされる {#nested}

ここまでの関数は、自分からはほかの関数を呼びませんでした。関数の中から、さらに関数を呼ぶとどうなるでしょうか。

`ra` は 1 本しかありません。2 回目の `call` は、1 回目の `call` が入れた番地を上書きします。

```fig seq main → outer → inner と呼ぶ。inner を呼んだ時点で、main に戻る番地 A は ra から消えている
{

  actors: [ { id: 'm', label: 'main', kind: 'accent' }, { id: 'o', label: 'outer', kind: 'stack' }, { id: 'i', label: 'inner', kind: 'heap' } ],
  msgs: [
    { from: 'm', to: 'o', label: 'call outer（ra = A）' },
    { from: 'o', to: 'i', label: 'call inner（ra = B）', style: 'accent' },
    { note: 'A は上書きされて消えた', at: 'o', style: 'accent' },
    { from: 'i', to: 'o', label: 'ret（B へ。ここは正しい）' },
    { self: 'o', label: 'ret（また B へ！ main に戻れない）', style: 'accent' },
  ],
}
```

実際に動かします。`outer` は `inner` を呼んでから `o` を表示して戻る、つもりの関数です。

```asm run title="ra を上書きしたまま ret する"
main:
    li   s1, 0
    call outer
    li   a0, 'M'        # outer から戻ったら M を表示するはず
    li   a7, 11
    ecall
    li   a7, 10
    ecall

outer:
    call inner          # ここで ra が上書きされる
    li   a0, 'o'
    li   a7, 11
    ecall
    addi s1, s1, 1      # （安全装置）ここを 5 回通ったら打ち切る
    li   t0, 5
    bge  s1, t0, stop
    ret                 # main に戻るつもりが…

inner:
    li   a0, 'i'
    li   a7, 11
    ecall
    ret

stop:
    li   a7, 10
    ecall
```

出力は `iooooo` です。`M` は表示されません。`outer` の `ret` は、`main` ではなく `call inner` の次の命令に戻ってしまいます。そこからまた `ret` まで進み、同じ場所に戻ります。安全装置がなければ、いつまでも `o` を出し続けます。

直し方は 1 つです。**ほかの関数を呼ぶ前に、`ra` をどこかに退避しておく**。その「どこか」がスタックです。

## スタック：ra を退避する場所 {#stack}

退避先に、別のレジスタは使えません。呼ばれた関数がそのレジスタを使うかもしれませんし、呼び出しが何段にも重なれば、レジスタはすぐに足りなくなります。退避先はメモリにします。

**スタック**（stack、積み重ね）は、メモリの一部を「積んで、上から取り出す」ために使う方法です。後から積んだものを先に取り出します。関数は、後から呼ばれたものが先に戻るので、ちょうど合います。

スタックの位置は、レジスタ `sp`（stack pointer、`x2` の別名）が覚えています。`sp` は「いま積んであるもののいちばん端」の番地を指します。

- このサイトの CPU では、`sp` の最初の値は 0x10000（RAM の終わり）です
- スタックは、**番地の小さいほうへ**伸びます。場所を取るときは `sp` を減らし、返すときは増やします

`ra` を退避する手順は、いつも同じ 4 行です。

```asm
    addi sp, sp, -16    # スタックに 16 バイトの場所を取る
    sw   ra, 12(sp)     # そこに ra をしまう
    …                   # ここで安心してほかの関数を呼べる
    lw   ra, 12(sp)     # ra を取り出す
    addi sp, sp, 16     # 場所を返す
```

さきほどのプログラムを直します。`outer` の最初と最後に、退避と復元を足すだけです。安全装置はもう要りません。

```asm run title="ra をスタックに退避する" mem="0xfff0,16"
main:
    call outer
    li   a0, 'M'
    li   a7, 11
    ecall
    li   a7, 10
    ecall

outer:
    addi sp, sp, -16    # 場所を取る
    sw   ra, 12(sp)     # ra を退避
    call inner
    li   a0, 'o'
    li   a7, 11
    ecall
    lw   ra, 12(sp)     # ra を復元
    addi sp, sp, 16     # 場所を返す
    ret

inner:
    li   a0, 'i'
    li   a7, 11
    ecall
    ret
```

今度は `ioM` と表示されます。出力のメモリを見ると、0xFFFC 番地に `04 00 00 00` が残っています。4 は、`main` の `call outer` の次の命令の番地です。「ステップ実行で見る」で 1 命令ずつ進めると、`sp` が 0x10000 → 0xFFF0 → 0x10000 と動くのも確かめられます。

`inner` は、ほかの関数を呼ばないので `ra` を退避していません。このように、自分からは何も呼ばない関数を**葉の関数**（leaf function）と呼びます。葉の関数はスタックを使わなくても済みます。

:::note 場所を返しても、中身は消えない
`addi sp, sp, 16` は `sp` の数を変えるだけで、メモリを掃除しません。だから、実行が終わったあとも 0xFFFC 番地に古い値が残っています。次に呼ばれた関数が、同じ場所を上書きして使います。
:::

## 呼び出し規約：どのレジスタを誰が守るか {#abi}

`ra` と同じ問題は、ほかのレジスタにも起きます。関数を呼んだら、自分が使っていたレジスタを書き換えられてしまうかもしれません。

```asm run title="関数を呼んだら t0 が変わっていた"
main:
    li   t0, 100        # あとで使うつもりの値
    li   a0, 7
    call square
    add  a0, a0, t0     # 49 + 100 のつもり
    li   a7, 1
    ecall
    li   a7, 10
    ecall

# square(a0)：a0 の 2 乗を返す
square:
    mv   t0, a0         # 計算に t0 を使った
    mul  a0, t0, t0
    ret
```

149 を期待しましたが、56 が出ます。`square` が `t0` を 7 で上書きしたからです。`main` と `square` を別の人が書いていたら、この衝突には気づけません。

そこで、レジスタごとに「関数を呼んだあとも値が残っているか」を決めておきます。この約束を**呼び出し規約**と呼びます。RISC-V の規約は次のとおりです。

| レジスタ | 役割 | 関数を呼んだあと |
| --- | --- | --- |
| `a0`〜`a7` | 引数と戻り値 | **変わっているかもしれない** |
| `t0`〜`t6` | 一時的な計算（temporary） | **変わっているかもしれない** |
| `ra` | 戻る番地 | **変わっているかもしれない** |
| `s0`〜`s11` | 取っておきたい値（saved） | **元のまま** |
| `sp` | スタックの位置 | **元のまま** |

「元のまま」を実現するのは、呼ばれた関数の側です。`s` のレジスタを使いたい関数は、**最初に元の値をスタックに退避し、戻る前に復元します**。`sp` も、取った分を必ず返して元の値に戻します。

これで役割がはっきりします。

- **呼ぶ側**：関数を呼んだあとも使いたい値は、`s` のレジスタに置く（またはスタックに置く）。`t` と `a` は、呼んだら壊れるものとして扱う
- **呼ばれる側**：`t` と `a` は自由に使ってよい。`s` を使うなら、退避して復元する

さきほどのプログラムを、規約どおりに直します。`main` は残したい値を `s0` に置きます。`s0` を使うので、`main` も最初に `s0` を退避します。

```asm run title="残したい値は s レジスタに置く"
main:
    addi sp, sp, -16
    sw   ra, 12(sp)
    sw   s0, 8(sp)      # s0 を使うので、元の値を退避
    li   s0, 100        # 関数を呼んだあとも使う値
    li   a0, 7
    call square
    add  a0, a0, s0     # 49 + 100
    li   a7, 1
    ecall
    lw   ra, 12(sp)
    lw   s0, 8(sp)      # s0 を復元
    addi sp, sp, 16
    ret                 # main も関数。ret で終われる

square:
    mv   t0, a0         # t0 は自由に使ってよい
    mul  a0, t0, t0
    ret
```

149 になりました。最後が `ret` になっている点も見てください。`main` も関数の 1 つです。このサイトの CPU は、最初に `ra` に「プログラムの終わり」の番地を入れてから `main` を始めます。`ra` をきちんと復元すれば、`main` も `ret` で終われます。

### スタックフレーム

関数が自分のためにスタックに取った場所を、その関数の**スタックフレーム**（frame、枠）と呼びます。フレームには、`ra`、退避した `s` のレジスタ、そのほか関数の中だけで使う値を置きます。

```fig layout 16 バイトのスタックフレームの例。sp からのオフセットで、どこに何を置くかを決める
{
  unit: 34,
  rows: [
    { label: 'オフセット', cells: [ { t: '0(sp)', w: 4 }, { t: '4(sp)', w: 4 }, { t: '8(sp)', w: 4 }, { t: '12(sp)', w: 4 } ], note: '→ 大きい番地' },
    { label: '中身', cells: [ { t: '空き', w: 4, kind: 'plain' }, { t: 's1', w: 4, kind: 'stack' }, { t: 's0', w: 4, kind: 'stack' }, { t: 'ra', w: 4, kind: 'accent' } ] },
  ],
}
```

フレームの大きさは、**16 の倍数**にします。RISC-V の規約で、`sp` は 16 の倍数に保つと決まっているためです。退避するものが `ra` だけ（4 バイト）でも、16 バイト取ります。5 個以上退避するなら 32 バイトです。

関数の最初にフレームを作る部分を**プロローグ**、最後に片づける部分を**エピローグ**と呼びます。関数を書くときの型として覚えておくと便利です。

```asm
func:
    addi sp, sp, -16    # プロローグ：フレームを作り、
    sw   ra, 12(sp)     #   ra と、使う s レジスタを退避
    sw   s0, 8(sp)
    …                   # 本体
    lw   ra, 12(sp)     # エピローグ：復元して、
    lw   s0, 8(sp)
    addi sp, sp, 16     #   フレームを片づける
    ret
```

:::note 規約は「約束」であって、CPU は確かめない
`s0` を退避せずに書き換えても、CPU はエラーにしません。規約は、関数どうしが安全に組み合わさるための、人とコンパイラの間の約束です。破ると、呼んだ側がずっとあとで間違った答えを出します。原因を探しにくい不具合になります。
:::

## 再帰：関数が自分自身を呼ぶ {#recursion}

スタックがあれば、関数は**自分自身**を呼べます。これを**再帰**と呼びます。呼ぶたびに新しいフレームが積まれるので、それぞれの呼び出しが自分の `ra` と自分の値を持てるからです。

定番の例は階乗です。5 の階乗は 5 × 4 × 3 × 2 × 1 = 120 です。これを「n の階乗 = n × (n − 1) の階乗。ただし 1 の階乗は 1」と言い換えると、再帰の形になります。

```asm run title="階乗（再帰）"
main:
    li   a0, 5
    call fact
    li   a7, 1
    ecall
    li   a7, 10
    ecall

# fact(a0 = n)：n の階乗を a0 に返す
fact:
    li   t0, 1
    ble  a0, t0, fact_base   # n <= 1 なら、再帰しないで 1 を返す
    addi sp, sp, -16
    sw   ra, 12(sp)
    sw   a0, 8(sp)      # n を退避（呼んだあとも使うので）
    addi a0, a0, -1
    call fact           # a0 = fact(n - 1)
    lw   t1, 8(sp)      # n を取り出す
    mul  a0, t1, a0     # n × fact(n - 1)
    lw   ra, 12(sp)
    addi sp, sp, 16
    ret
fact_base:
    li   a0, 1
    ret
```

120 です。ここでは、残したい値 `n` を `s` のレジスタではなく、スタックに直接しまいました。どちらの方法でも構いません。

### フィボナッチ数

フィボナッチ数は、「前の 2 つを足す」で作る数の並びです（0、1、1、2、3、5、8、13 …）。n 番目は「(n − 1) 番目 + (n − 2) 番目」なので、自分を 2 回呼ぶ再帰になります。

1 回目の結果を、2 回目の呼び出しのあとまで取っておく必要があります。こういう値は `s` のレジスタに置きます。

```asm run title="フィボナッチ数（再帰）と、呼ばれた回数"
.data
calls: .word 0          # fib が呼ばれた回数

.text
main:
    li   a0, 15
    call fib
    li   a7, 1
    ecall               # fib(15)
    li   a0, ' '
    li   a7, 11
    ecall
    lw   a0, calls
    li   a7, 1
    ecall               # 呼ばれた回数
    li   a7, 10
    ecall

# fib(a0 = n)：n 番目のフィボナッチ数を a0 に返す
fib:
    la   t0, calls      # 回数を 1 増やす
    lw   t1, 0(t0)
    addi t1, t1, 1
    sw   t1, 0(t0)
    li   t0, 2
    blt  a0, t0, fib_done    # n < 2 なら n をそのまま返す
    addi sp, sp, -16
    sw   ra, 12(sp)
    sw   s0, 8(sp)
    sw   s1, 4(sp)
    mv   s0, a0         # s0 = n
    addi a0, s0, -1
    call fib
    mv   s1, a0         # s1 = fib(n - 1)
    addi a0, s0, -2
    call fib            # a0 = fib(n - 2)
    add  a0, a0, s1
    lw   ra, 12(sp)
    lw   s0, 8(sp)
    lw   s1, 4(sp)
    addi sp, sp, 16
fib_done:
    ret
```

`610 1973` と出ます。15 番目のフィボナッチ数は 610 で、それを求めるのに `fib` は 1,973 回呼ばれました。同じ計算を何度もやり直しているためです。再帰は書きやすい反面、こういうむだが出やすい書き方でもあります。

### ハノイの塔

再帰が本当に役立つ例を 1 つ見ます。ハノイの塔は、大きさの違う円盤を、棒 A から棒 C へ移すパズルです。1 回に動かせるのは 1 枚で、小さい円盤の上に大きい円盤は置けません。

n 枚を A から C へ移す手順は、次の 3 段階に分けられます。

1. 上の n − 1 枚を、A から B へ移す（同じ問題の小さい版）
2. いちばん下の 1 枚を、A から C へ移す
3. B にある n − 1 枚を、C へ移す（同じ問題の小さい版）

これをそのまま関数にします。引数が 4 つあり、どれも再帰のあとで使うので、`s0`〜`s3` に置きます。退避するものが 5 個なので、フレームは 32 バイトです。

```asm run title="ハノイの塔（3 枚）"
main:
    li   a0, 3          # 枚数
    li   a1, 'A'        # どこから
    li   a2, 'C'        # どこへ
    li   a3, 'B'        # 空いている棒
    call hanoi
    li   a7, 10
    ecall

# hanoi(a0 = 枚数, a1 = 移動元, a2 = 移動先, a3 = 残りの棒)
hanoi:
    beqz a0, hanoi_done      # 0 枚なら何もしない
    addi sp, sp, -32
    sw   ra, 28(sp)
    sw   s0, 24(sp)
    sw   s1, 20(sp)
    sw   s2, 16(sp)
    sw   s3, 12(sp)
    mv   s0, a0
    mv   s1, a1
    mv   s2, a2
    mv   s3, a3

    addi a0, s0, -1     # 1. n-1 枚を、移動元 → 残りの棒
    mv   a1, s1
    mv   a2, s3
    mv   a3, s2
    call hanoi

    mv   a0, s1         # 2. 1 枚を、移動元 → 移動先（「A>C」と表示）
    li   a7, 11
    ecall
    li   a0, '>'
    ecall
    mv   a0, s2
    ecall
    li   a0, ' '
    ecall

    addi a0, s0, -1     # 3. n-1 枚を、残りの棒 → 移動先
    mv   a1, s3
    mv   a2, s2
    mv   a3, s1
    call hanoi

    lw   ra, 28(sp)
    lw   s0, 24(sp)
    lw   s1, 20(sp)
    lw   s2, 16(sp)
    lw   s3, 12(sp)
    addi sp, sp, 32
hanoi_done:
    ret
```

`A>C A>B C>B A>C B>A B>C A>C` の 7 手が出ます。枚数を 4 にすると 15 手、5 にすると 31 手です。枚数が 1 枚増えるたびに、手数はおよそ 2 倍になります。

## スタックの深さを見る {#depth}

再帰が深くなると、スタックはどこまで伸びるのでしょうか。呼ばれるたびに `sp` を表示する関数で確かめます。

```asm run title="呼ばれるたびに sp を表示する"
main:
    li   a0, 4
    call dive
    li   a7, 10
    ecall

# dive(a0 = n)：sp を表示して、n が 0 になるまで自分を呼ぶ
dive:
    addi sp, sp, -16
    sw   ra, 12(sp)
    sw   s0, 8(sp)
    mv   s0, a0
    mv   a0, sp         # いまの sp を 16 進で表示
    li   a7, 34
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    beqz s0, dive_up
    addi a0, s0, -1
    call dive
dive_up:
    lw   ra, 12(sp)
    lw   s0, 8(sp)
    addi sp, sp, 16
    ret
```

0x0000fff0、0x0000ffe0、0x0000ffd0 … と、1 回呼ぶごとに 16（0x10）ずつ減っていきます。5 回の呼び出しで 80 バイトです。

スタックの深さは、**同時に積まれているフレームの数**で決まります。呼んだ回数の合計ではありません。さきほどの `fib(15)` は 1,973 回呼ばれましたが、同時に積まれるフレームは多くても 14 個です。戻るたびにフレームが消えるからです。

## スタックが壊れると何が起きるか {#broken}

スタックの扱いを間違えると、プログラムは思いもよらない動きをします。よくある 3 つの壊れ方を、実際に起こしてみます。

### 止まらない再帰

再帰しない場合を書き忘れた関数です。

```asm run error title="終わりのない再帰"
main:
    call forever
    li   a7, 10
    ecall

forever:
    addi sp, sp, -16
    sw   ra, 12(sp)
    call forever        # 条件なしで自分を呼ぶ
    lw   ra, 12(sp)
    addi sp, sp, 16
    ret
```

「機械語 … は命令として解釈できません」というエラーで止まります。再帰の話なのに、なぜ命令のエラーなのでしょうか。

:::err 機械語 0x00000018 は命令として解釈できません（データを命令として実行していませんか）
CPU が、命令ではないものを命令として実行しようとした、というエラーです。ここでは、伸びすぎたスタックがプログラムを上書きしたのが原因です。再帰が止まる条件を書いたか、その条件に必ずたどり着くかを確かめます。
:::

スタックは 0x10000 から下へ伸びます。1 回の呼び出しで 16 バイトずつ進み、4,096 回で 0 番地まで届きます。0 番地から置かれているのは、**プログラム自身**です。スタックがプログラムの命令を上書きし、CPU は壊れた命令を実行しようとして止まりました。

```fig layout このサイトの CPU の RAM（64 KiB）。スタックが伸びすぎると、データ、そしてプログラム自身を上書きする
{
  unit: 22,
  rows: [
    { label: '番地', cells: [ { t: '0x0000', w: 6 }, { t: '', w: 4 }, { t: '0x8000', w: 6 }, { t: '', w: 4 }, { t: '〜 0xFFFF', w: 6 } ] },
    { label: 'RAM', cells: [ { t: 'プログラム（.text）', w: 6, kind: 'accent' }, { t: '空き', w: 4, kind: 'plain' }, { t: 'データ（.data）', w: 6, kind: 'stack' }, { t: '空き', w: 4, kind: 'plain' }, { t: '← スタック', w: 6, kind: 'heap' } ], note: 'sp は右端から左へ' },
  ],
}
```

これが**スタックオーバーフロー**（スタックあふれ）です。本物のコンピュータでは、OS がスタックの先に「触ると止まる場所」を用意していて、ほかのものを壊す前にプログラムを止めます。

### sp を戻し忘れる

フレームを取ったまま、返さずに `ret` する関数です。

```asm run title="sp を戻し忘れた関数を呼ぶ"
main:
    addi sp, sp, -16
    sw   ra, 12(sp)
    call leak
    li   a0, '!'        # 1 回だけ表示するはず
    li   a7, 11
    ecall
    lw   ra, 12(sp)
    addi sp, sp, 16
    ret

leak:
    addi sp, sp, -16
    sw   ra, 12(sp)
    lw   ra, 12(sp)
    ret                 # addi sp, sp, 16 を忘れた
```

`!!` と、2 回表示されます。エラーにはなりません。

`leak` から戻ったとき、`sp` は 16 だけずれたままです。`main` が `12(sp)` から取り出したのは、自分の `ra` ではなく、`leak` がしまった `ra` でした。その番地は `call leak` の次の命令なので、`main` の `ret` は `main` の途中に戻り、同じ部分をもう一度実行します。2 回目は、たまたまずれが直って終わりました。

間違いのある場所（`leak`）と、おかしな動きが出る場所（`main` の `ret`）が離れている点が、スタックの不具合のやっかいなところです。

### 退避した ra を上書きする

最後は、フレームの中に置いた小さな入れ物から、データがあふれる場合です。`greet` は、受け取った文字列をフレームの中の 12 バイトにコピーしてから表示します。

```asm run error title="フレームの中であふれて、ra を壊す"
.data
name: .asciz "AAAABBBBCCCCDDDD"   # 16 文字。12 バイトには入らない

.text
main:
    addi sp, sp, -16
    sw   ra, 12(sp)
    la   a0, name
    call greet
    lw   ra, 12(sp)
    addi sp, sp, 16
    ret

# greet(a0 = 文字列の番地)：フレームにコピーしてから表示する
greet:
    addi sp, sp, -16
    sw   ra, 12(sp)     # 12(sp)〜15(sp) が ra
    mv   t0, sp         # 0(sp)〜11(sp) をコピー先にする
greet_copy:
    lbu  t1, 0(a0)
    sb   t1, 0(t0)
    beqz t1, greet_show
    addi a0, a0, 1
    addi t0, t0, 1
    j    greet_copy
greet_show:
    mv   a0, sp
    li   a7, 4
    ecall
    lw   ra, 12(sp)     # 取り出した ra は、もう元の値ではない
    addi sp, sp, 16
    ret
```

文字列は表示されますが、そのあと「pc が 0x44444444 になりました」というエラーで止まります。0x44 は文字 `D` のコードです。13 文字目からの `DDDD` が、`ra` をしまった場所に書き込まれました。`ret` は、その 4 バイトを番地だと思って飛んだのです。

:::err pc が 0x44444444 になりました。そこは RAM（0x0000〜0xFFFF）の外なので、命令を読めません
`ret` が飛んだ先が、命令のある番地ではなかった、というエラーです。`ra` を壊したまま `ret` したときに出ます。フレームに置いたデータが、決めた広さを越えていないかを確かめます。
:::

ここでは意味のない番地だったので止まりました。もし、あふれた部分が「だれかが選んだ番地」になっていたら、プログラムはその番地へ飛んでしまいます。第 12 章で触れたバッファオーバーフローが、長いあいだ攻撃に使われてきたのは、この仕組みのためです。

:::try 引数を増やす
下のプログラムは、`max2` で 2 つの数の大きいほうを出します。`max2` を呼ぶ関数 `max4`（`a0`〜`a3` の最大を返す）を足して、4 つの数の最大を表示してください。`max4` はほかの関数を呼ぶので、`ra` の退避が要ります。`a2` と `a3` は、`max2` を呼ぶと壊れるものとして扱います。
:::

```asm run title="練習：max2 を使って max4 を作る"
main:
    li   a0, 17
    li   a1, 42
    call max2
    li   a7, 1
    ecall
    li   a7, 10
    ecall

# max2(a0, a1)：大きいほうを a0 に返す
max2:
    bge  a0, a1, max2_done
    mv   a0, a1
max2_done:
    ret
```

:::key まとめ
- `call` は、次の命令の番地を `ra` に入れてから飛ぶ。`ret` は `ra` の番地へ飛ぶ。正体は `jal` と `jalr`
- 引数は `a0`〜`a7`、戻り値は `a0` で受け渡す
- `ra` は 1 本しかない。関数の中でほかの関数を呼ぶなら、先に `ra` をスタックに退避する
- スタックは `sp` が指す。小さい番地へ伸びる。`addi sp, sp, -16` で場所を取り、同じだけ足して返す
- 呼び出し規約：`t` と `a` と `ra` は、関数を呼ぶと変わるかもしれない。`s` と `sp` は、呼ばれた側が元に戻す
- 再帰は、呼ぶたびに新しいフレームが積まれるから成り立つ。再帰しない場合を必ず書く
- スタックを壊すと、離れた場所でおかしな動きが出る。`sp` は必ず元に戻し、フレームの外に書かない
:::

:::quiz 3 つの数の最大

:::quiz 関数の中から関数を呼ぶ
関数 `step` が用意されています。`a0` を受け取り、`a0 × 3 + 1` を `a0` に返す関数です。これを **2 回**使う関数 `step2` を書いてください。`step2(x)` は `step(step(x))` を `a0` に返します。

```

step2:

    call step
    lw   ra, 12(sp)

```

:::quiz 最大公約数（再帰）
関数 `gcd` を書いてください。`a0` と `a1`（どちらも 0 以上）の最大公約数を `a0` に返します。次の決まりを使います。

- `b` が 0 なら、`gcd(a, b)` は `a`
- そうでなければ、`gcd(a, b)` は `gcd(b, a を b で割った余り)`

余りは `rem` 命令で求められます（`rem t0, a0, a1` で `t0 = a0 % a1`）。

```asm starter
# gcd(a0, a1)：最大公約数を a0 に返す
gcd:

    ret
```

```asm answer
gcd:
    beqz a1, gcd_done
    addi sp, sp, -16
    sw   ra, 12(sp)
    rem  t0, a0, a1
    mv   a0, a1
    mv   a1, t0
    call gcd
    lw   ra, 12(sp)
    addi sp, sp, 16
gcd_done:
    ret
```

```asm given
main:
    li   a0, 48
    li   a1, 18
    call gcd
    call show
    li   a0, 17
    li   a1, 5
    call gcd
    call show
    li   a0, 100
    li   a1, 0
    call gcd
    call show
    li   a0, 21
    li   a1, 84
    call gcd
    call show
    li   a0, 1071
    li   a1, 462
    call gcd
    call show
    li   a7, 10
    ecall
show:
    li   a7, 1
    ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    ret
```

:::hint
`a1` が 0 なら、そのまま `ret` します（`a0` が答え）。そうでなければ、余りを一時的なレジスタに求めてから、`a0` に元の `a1`、`a1` に余りを入れて、自分を呼びます。自分を呼ぶ前に `ra` を退避します。
:::
:::

:::quiz s レジスタを守る
関数 `total` を書いてください。`a0` に配列の番地、`a1` に要素の数を受け取ります。各要素を、用意されている関数 `weight` に渡し（引数は `a0`、戻り値も `a0`）、その戻り値の合計を `a0` に返します。

`weight` は、`t0`〜`t6` と `a1`〜`a7` を書き換えます。`main` は、`total` を呼ぶ前後で `s0`〜`s3` の値が変わっていないかも表示します。

```asm starter
# total(a0 = 配列の番地, a1 = 個数)：weight(要素) の合計を a0 に返す
total:

    ret
```

```asm answer
total:
    addi sp, sp, -32
    sw   ra, 28(sp)
    sw   s0, 24(sp)
    sw   s1, 20(sp)
    sw   s2, 16(sp)
    mv   s0, a0
    mv   s1, a1
    li   s2, 0
total_loop:
    beqz s1, total_done
    lw   a0, 0(s0)
    call weight
    add  s2, s2, a0
    addi s0, s0, 4
    addi s1, s1, -1
    j    total_loop
total_done:
    mv   a0, s2
    lw   ra, 28(sp)
    lw   s0, 24(sp)
    lw   s1, 20(sp)
    lw   s2, 16(sp)
    addi sp, sp, 32
    ret
```
