## コンパイラ・アセンブラ・リンカ {#toolchain}

ここまで、プログラムはアセンブリで書いてきました。ふだんのプログラムは、C や Rust のような**高水準言語**で書きます。人が書いた C のプログラムが CPU で動くまでには、3 つの道具が順に働きます。

```fig graph C のプログラムが実行ファイルになるまで。このサイトのブラウザの中にあるのは、アセンブラだけ
{
  nodes: [
    { id: 'c', label: 'main.c', sub: 'C のプログラム（人が書く）', x: 0, y: 0, kind: 'stack' },
    { id: 's', label: 'main.s', sub: 'アセンブリ', x: 0, y: 1, kind: 'accent' },
    { id: 'o', label: 'main.o', sub: '機械語（番地が未定の部分が残る）', x: 0, y: 2, kind: 'heap' },
    { id: 'x', label: '実行ファイル', sub: 'すべての番地が決まった機械語', x: 0, y: 3, kind: 'heap' },
    { id: 'lib', label: 'ほかの .o、ライブラリ', sub: 'printf などの中身', x: 1, y: 2, kind: 'ext' },
  ],
  edges: [
    { from: 'c', to: 's', label: 'コンパイラ' },
    { from: 's', to: 'o', label: 'アセンブラ' },
    { from: 'o', to: 'x', label: 'リンカ' },
    { from: 'lib', to: 'x', style: 'dashed' },
  ],
  col: 300, row: 96,

```

- **コンパイラ**：C をアセンブリに訳す。どの変数をどのレジスタに置くか、どの命令を使うかを決める。この章の主役
- **アセンブラ**：アセンブリを機械語に直す。第 9 章で手でやった作業で、このサイトの実行ボタンの中でも動いている
- **リンカ**：別々に作った機械語をつなぎ合わせ、関数や変数の番地を最終的に決める。このサイトのプログラムはいつも 1 つのファイルなので、リンカの出番はない

この章では、コンパイラの仕事を**手で**やります。C のコードを見せ、それを訳したアセンブリを動かします。

:::note この章のアセンブリについて
この章のアセンブリは、「コンパイラはたとえばこう訳す」という例を、手で書いたものです。本物の gcc や clang の出力そのものではありません。コンパイラの出力は、種類、版、**最適化レベル**（`-O0`、`-O2` などの指定）によって変わります。変わらないのは、呼び出し規約のような約束と、訳し方の基本の形です。
:::

C を知らなくても読めるように、使う書き方を先にまとめます。

| C の書き方 | 意味 |
| --- | --- |
| `int x = 5;` | 32 ビットの符号付き整数の変数 `x` を作り、5 を入れる |
| `x = a + b * c;` | 右辺を計算して `x` に入れる。`*` は掛け算、`/` は割り算、`%` は余り |
| `if (条件) { … } else { … }` | 条件が成り立てば前、そうでなければ後ろを実行する |
| `while (条件) { … }` | 条件が成り立つ間、繰り返す |
| `int f(int a, int b) { return a + b; }` | 引数を 2 つ受け取り、整数を返す関数 |
| `print_int(x)`、`print_char(c)` | この章だけの約束。このサイトの `ecall` の 1 番と 11 番に当たる |

## 変数と式 {#expr}

C の変数には、置き場所が 2 種類あります。関数の中で作る**ローカル変数**と、関数の外に書く**グローバル変数**です。

コンパイラは、ローカル変数をできるだけ**レジスタ**に置きます。メモリの読み書きより速いからです。式は、演算子の優先順位に従って 1 つずつ命令に直します。途中の結果は、空いているレジスタに一時的に置きます。

```c
int a = 6, b = 7, c = 2;
int x = a + b * c;              // 掛け算が先
int y = (a + b) * c - x / 4;
print_int(x); print_char(' '); print_int(y);
```

```asm run title="ローカル変数はレジスタに、式は 1 演算 1 命令に"
main:
    li   t0, 6              # a
    li   t1, 7              # b
    li   t2, 2              # c
    mul  t3, t1, t2         # 途中の結果：b * c
    add  t3, t0, t3         # x = a + (b * c)
    add  t4, t0, t1         # 途中の結果：a + b
    mul  t4, t4, t2         # (a + b) * c
    li   t5, 4
    div  t5, t3, t5         # 途中の結果：x / 4
    sub  t4, t4, t5         # y
    mv   a0, t3
    li   a7, 1
    ecall                   # print_int(x)
    li   a0, ' '
    li   a7, 11
    ecall
    mv   a0, t4
    li   a7, 1
    ecall                   # print_int(y)
    li   a7, 10
    ecall
```

`a` は `t0`、`x` は `t3`、というように、変数の名前はレジスタの番号に置き換わりました。機械語には、変数の名前は残りません。

グローバル変数は、プログラムのどこからでも使えるので、**メモリ**（`.data`）に置きます。使うたびに、読んで、計算して、書き戻します。

```c
int counter = 10;               // グローバル変数

int main(void) {
    counter = counter + 5;
    print_int(counter);
}
```

```asm run title="グローバル変数はメモリに置く"
main:
    la   t0, counter        # counter の番地
    lw   t1, 0(t0)          # 読む
    addi t1, t1, 5
    sw   t1, 0(t0)          # 書き戻す
    lw   a0, 0(t0)
    li   a7, 1
    ecall
    li   a7, 10
    ecall

.data
counter: .word 10
```

### 型は、命令の選び方に残る

C の変数には `int`（符号付き）や `unsigned`（符号なし）といった**型**があります。レジスタの中身はただの 32 ビットで、型の情報はどこにもありません。型は、**コンパイラがどの命令を選ぶか**に使われて、消えます。

```c
int      s = -7;
unsigned u = 4294967289u;       // ビットの並びは -7 と同じ
print_int(s / 2);   print_int(s >> 1);
print_uint(u / 2);  print_uint(u >> 1);
```

```asm run title="同じビットでも、型によって違う命令になる"
main:
    li   s0, -7             # s と u。ビットの並びは同じ
    li   t1, 2

    div  a0, s0, t1         # int の割り算は div
    call show               # -3
    srai a0, s0, 1          # int の右シフトは srai（符号を保つ）
    call show               # -4
    divu a0, s0, t1         # unsigned の割り算は divu
    call showu              # 2147483644
    srli a0, s0, 1          # unsigned の右シフトは srli（0 を入れる）
    call showu              # 2147483644
    li   a7, 10
    ecall

show:
    li   a7, 1              # 符号付きで表示
    j    1f
showu:
    li   a7, 36             # 符号なしで表示
1:  ecall
    li   a0, '\n'
    li   a7, 11
    ecall
    ret
```

`int` の `-7 / 2` は -3（0 に近いほうへ丸める）、`-7 >> 1` は -4 です。結果が違うので、コンパイラは符号付きの「2 で割る」を、そのまま右シフト 1 個には置き換えられません。符号なしなら、どちらも同じ結果です。

## if と else {#if}

`if` は、条件分岐とラベルに直します。コツは、**条件を逆にして、「成り立たないときに飛び越す」** 形にすることです。

```c
int a = 3, b = 8, m;
if (a > b) {
    m = a;
} else {
    m = b;
}
print_int(m);
```

```asm run title="if / else：条件を逆にして飛び越す"
main:
    li   t0, 3              # a
    li   t1, 8              # b
    ble  t0, t1, else       # a > b ではない（a <= b）なら else へ
    mv   t2, t0             # m = a
    j    endif              # else の部分を飛び越す
else:
    mv   t2, t1             # m = b
endif:
    mv   a0, t2
    li   a7, 1
    ecall
    li   a7, 10
    ecall
```

C の `a > b` が、アセンブリでは逆の `ble`（以下なら飛ぶ）になりました。こうすると、`if` の中身を条件のすぐ下に、C と同じ順番で並べられます。

条件を `&&`（かつ）でつなぐと、分岐が 2 つになります。C には、**前の条件が成り立たなければ、後ろの条件は調べない**という決まり（短絡評価）があります。命令の並びも、そのとおりになります。

```c
int x = 15;
if (x >= 10 && x < 20) {
    print_char('Y');
} else {
    print_char('N');
}
```

```asm run title="&& は分岐 2 つ。前がだめなら、後ろは調べない"
main:
    li   t0, 15             # x
    li   t1, 10
    blt  t0, t1, no         # x >= 10 ではないなら、すぐ no へ
    li   t1, 20
    bge  t0, t1, no         # x < 20 ではないなら no へ
    li   a0, 'Y'
    j    print
no:
    li   a0, 'N'
print:
    li   a7, 11
    ecall
    li   a7, 10
    ecall
```

## while と for {#loop}

ループは、「条件を調べる分岐」と「前へ戻るジャンプ」に直します。C の `for` は `while` の書き方を変えただけなので、同じ形になります。

```c
int sum = 0;
for (int i = 1; i <= 10; i++) {     // i++ は i = i + 1
    sum += i;                        // sum = sum + i
}
print_int(sum);
```

素直に訳すと、条件をループの先頭で調べる形になります。

```asm run title="for：先頭で条件を調べる形" regs="t0,t1"
main:
    li   t0, 0              # sum
    li   t1, 1              # i
    li   t2, 10
loop:
    bgt  t1, t2, done       # i <= 10 ではないなら抜ける
    add  t0, t0, t1         # sum += i
    addi t1, t1, 1          # i++
    j    loop
done:
    mv   a0, t0
    li   a7, 1
    ecall
    li   a7, 10
    ecall
```

この形は、1 周ごとに分岐 `bgt` とジャンプ `j` の 2 つを実行します。コンパイラはふつう、条件を**ループの末尾**に移して、1 周の分岐を 1 つにします。

```asm run title="for：末尾で条件を調べる形（1 周あたり 1 命令少ない）" regs="t0,t1"
main:
    li   t0, 0              # sum
    li   t1, 1              # i
    li   t2, 10
    bgt  t1, t2, done       # 最初の 1 回だけ、入る前に調べる
loop:
    add  t0, t0, t1         # sum += i
    addi t1, t1, 1          # i++
    ble  t1, t2, loop       # i <= 10 なら続ける
done:
    mv   a0, t0
    li   a7, 1
    ecall
    li   a7, 10
    ecall
```

出力の下の「実行した命令数」を比べてください。先頭で調べる形は 49、末尾で調べる形は 39 です。

`while` の中に `if` があっても、部品を組み合わせるだけです。次の例は、コラッツの問題（偶数なら半分、奇数なら 3 倍して 1 を足す。1 になるまでの回数を数える）です。

```c
int n = 27, steps = 0;
while (n != 1) {
    if (n % 2 == 0) {
        n = n / 2;
    } else {
        n = 3 * n + 1;
    }
    steps++;
}
print_int(steps);
```

```asm run title="while の中に if / else"
main:
    li   t0, 27             # n
    li   t1, 0              # steps
    li   t2, 1
    beq  t0, t2, done       # 入る前に 1 回調べる
loop:
    andi t3, t0, 1          # n % 2（下の 1 ビット）
    bnez t3, odd            # 0 ではない（奇数）なら else へ
    srai t0, t0, 1          # n = n / 2（n は正なのでシフトでよい）
    j    endif
odd:
    slli t3, t0, 1          # 2 * n
    add  t0, t3, t0         # 3 * n
    addi t0, t0, 1          # + 1
endif:
    addi t1, t1, 1          # steps++
    bne  t0, t2, loop       # n != 1 なら続ける
done:
    mv   a0, t1
    li   a7, 1
    ecall
    li   a7, 10
    ecall
```

27 は 111 回で 1 になります。ここでは `n % 2` を `andi`、`n / 2` をシフト、`3 * n` をシフトと足し算に直しました。こうした置き換えは、最後の節で扱う最適化の 1 つです。

## 関数 {#func}

関数の呼び出しは、第 13 章の**呼び出し規約**そのままです。コンパイラは、この約束を機械的に守ります。

| 約束 | 中身 |
| --- | --- |
| 引数 | 左から順に `a0`、`a1`、…、`a7` |
| 戻り値 | `a0` |
| 戻り先 | `ra`（`call` が入れる） |
| 呼んだ側が守る | `t0`〜`t6`、`a0`〜`a7`、`ra`。関数を呼ぶと壊れる前提 |
| 呼ばれた側が守る | `s0`〜`s11`、`sp`。使うなら保存して、戻る前に元に戻す |

ほかの関数を呼ばない関数（**葉の関数**）は、スタックを使わずに済みます。

```c
int square(int x) {
    return x * x;
}

int main(void) {
    print_int(square(12));
}
```

```asm run title="葉の関数：引数は a0、戻り値も a0"
main:
    li   a0, 12             # 引数
    call square
    li   a7, 1              # 戻り値は a0 に入っている
    ecall
    li   a7, 10
    ecall

square:
    mul  a0, a0, a0
    ret
```

ほかの関数を呼ぶ関数は、そうはいきません。`call` が `ra` を上書きし、呼んだ先が `a0` や `t0` を壊すからです。呼び出しをまたいで使う値は、`s` の付くレジスタに置き、そのレジスタの元の値と `ra` をスタックに保存します。

```c
int sum_sq(int a, int b) {
    return square(a) + square(b);
}
```

関数の入口で保存する部分を**プロローグ**、出口で元に戻す部分を**エピローグ**と呼びます。

```fig layout sum_sq のスタックフレーム（16 バイト）。プロローグで sp を 16 下げ、ra と s0、s1 を保存する
{
  unit: 30,
  rows: [
    { label: 'sp + 12', cells: [{ t: 'ra（main への戻り先）', w: 9, kind: 'accent' }], note: '高い番地' },
    { label: 'sp + 8', cells: [{ t: 's0 の元の値', w: 9, kind: 'stack' }] },
    { label: 'sp + 4', cells: [{ t: 's1 の元の値', w: 9, kind: 'stack' }] },
    { label: 'sp + 0', cells: [{ t: '（空き）', w: 9, kind: 'pad' }], note: '低い番地 ← sp' },
  ],
}
```

```asm run title="ほかの関数を呼ぶ関数：プロローグとエピローグ"
main:
    li   a0, 3
    li   a1, 4
    call sum_sq
    li   a7, 1
    ecall                   # 25
    li   a7, 10
    ecall

sum_sq:
    addi sp, sp, -16        # ── プロローグ：フレームを作る
    sw   ra, 12(sp)
    sw   s0, 8(sp)
    sw   s1, 4(sp)

    mv   s0, a1             # b を、呼び出しで壊れない s0 へ
    call square             # square(a)。a は a0 に入ったまま
    mv   s1, a0             # 結果を s1 へ
    mv   a0, s0
    call square             # square(b)
    add  a0, s1, a0         # 戻り値

    lw   ra, 12(sp)         # ── エピローグ：元に戻す
    lw   s0, 8(sp)
    lw   s1, 4(sp)
    addi sp, sp, 16
    ret

square:
    mul  a0, a0, a0
    ret
```

:::note フレームの大きさが 16 なのは
保存するのは 3 語（12 バイト）ですが、フレームは 16 バイトにしました。RISC-V の標準の呼び出し規約に、`sp` を 16 の倍数に保つという決まりがあるためです。コンパイラが出すコードで `addi sp, sp, -16` や `-32` をよく見るのは、このためです。
:::

## 配列とポインタ {#pointer}

配列は、同じ型の値をメモリに並べたものです。`int` は 4 バイトなので、`a[i]` の番地は「**`a` の先頭の番地 + i × 4**」です。コンパイラは、添字のたびにこの計算を出します。

```c
int a[5] = {3, 1, 4, 1, 5};

int main(void) {
    int sum = 0;
    for (int i = 0; i < 5; i++) {
        sum += a[i];
    }
    print_int(sum);
}
```

```asm run title="a[i]：先頭の番地 + i × 4"
main:
    la   t0, a              # a の先頭の番地
    li   t1, 0              # sum
    li   t2, 0              # i
    li   t3, 5
loop:
    slli t4, t2, 2          # i × 4
    add  t4, t0, t4         # a + i × 4 … a[i] の番地
    lw   t5, 0(t4)          # a[i]
    add  t1, t1, t5         # sum += a[i]
    addi t2, t2, 1
    blt  t2, t3, loop
    mv   a0, t1
    li   a7, 1
    ecall
    li   a7, 10
    ecall

.data
a:  .word 3, 1, 4, 1, 5
```

**ポインタ**は、番地を入れる変数です。`int *p` は「`int` が置いてある番地」を持ちます。`*p` はその番地の中身、`p++` は**次の要素**へ進める操作です。

```c
int sum = 0;
for (int *p = a; p < a + 5; p++) {
    sum += *p;
}
```

```asm run title="ポインタで配列をたどる。p++ は 4 進む"
main:
    la   t0, a              # p = a
    addi t3, t0, 20         # a + 5 … 終わりの番地（5 × 4 = 20）
    li   t1, 0              # sum
loop:
    lw   t5, 0(t0)          # *p
    add  t1, t1, t5
    addi t0, t0, 4          # p++（int は 4 バイトなので 4 進む）
    bltu t0, t3, loop       # p < a + 5（番地の比較は符号なし）
    mv   a0, t1
    li   a7, 1
    ecall
    li   a7, 10
    ecall

.data
a:  .word 3, 1, 4, 1, 5
```

C の `p++` や `a + 5` は、「1 増やす」「5 を足す」と書いてあっても、アセンブリでは**要素の大きさを掛けた数**になります。`char` のポインタなら 1、`int` のポインタなら 4 です。ここでも、型は命令の中の数に姿を変えて消えています。ループの中身は、添字の形より 2 命令短くなりました。

### 番地を取られた変数はメモリに置く

`&x` は「変数 `x` の番地」です。レジスタには番地がないので、`&` で番地を取られたローカル変数は、**スタックに**置くことになります。

```c
void swap(int *p, int *q) {
    int tmp = *p;
    *p = *q;
    *q = tmp;
}

int main(void) {
    int x = 1, y = 2;
    swap(&x, &y);
    print_int(x); print_int(y);
}
```

```asm run title="&x：ローカル変数をスタックに置いて、番地を渡す"
main:
    addi sp, sp, -16
    sw   ra, 12(sp)
    li   t0, 1
    sw   t0, 8(sp)          # x は sp + 8 に置く
    li   t0, 2
    sw   t0, 4(sp)          # y は sp + 4 に置く

    addi a0, sp, 8          # &x
    addi a1, sp, 4          # &y
    call swap

    lw   a0, 8(sp)          # x
    li   a7, 1
    ecall
    lw   a0, 4(sp)          # y
    li   a7, 1
    ecall
    lw   ra, 12(sp)
    addi sp, sp, 16
    li   a7, 10
    ecall

swap:
    lw   t0, 0(a0)          # tmp = *p
    lw   t1, 0(a1)
    sw   t1, 0(a0)          # *p = *q
    sw   t0, 0(a1)          # *q = tmp
    ret
```

`21` と出ます。`swap` は `x` と `y` という名前を知りません。渡された 2 つの番地の中身を入れ替えただけです。

## 構造体 {#struct}

**構造体**は、型の違う値をひとまとめにしたものです。メモリの上では、メンバが順に並びます。`p->price` のようなメンバの読み書きは、「**先頭の番地 + 決まったずれ**」の `lw` や `sw` になります。このずれを**オフセット**と呼びます。

```c
struct item {
    char  kind;     // 1 バイト
    int   price;    // 4 バイト
    short qty;      // 2 バイト
};
```

```fig layout struct item の配置（1 マス 1 バイト）。int は 4 の倍数の番地に置くので、kind のあとに 3 バイトの詰め物が入る。全体は 12 バイト
{

  rows: [

      { t: 'qty', w: 2, kind: 'heap' },
```

メンバは、自分の大きさの倍数の番地に置かれます（第 19 章で見た整列違反を避けるためです）。そのためのすき間が**詰め物**（パディング）です。末尾にも 2 バイト入り、全体が 4 の倍数の 12 バイトになります。構造体を配列にしたとき、次の要素の `price` も 4 の倍数の番地に来るようにするためです。

```c
struct item items[3] = { {'a', 120, 2}, {'b', 80, 5}, {'c', 300, 1} };

int total(struct item *p, int n) {
    int sum = 0;
    for (int i = 0; i < n; i++, p++) {
        sum += p->price * p->qty;
    }
    return sum;
}
```

```asm run title="p->price は 4(p)、p->qty は 8(p)、p++ は 12 進む"
main:

    li   a1, 3

    li   a7, 1

    li   a7, 10

    addi a0, a0, 12         # p++（struct item は 12 バイト）
    addi a1, a1, -1
    bnez a1, loop
```

`price` や `qty` という名前も、4 と 8 という数になって消えました。`i` を 0 から数え上げる代わりに、残りの個数 `n` を減らしていく形にしてあります。結果が同じなら、コンパイラはこういう書き換えをします。

## 再帰 {#recursion}

自分自身を呼ぶ関数も、特別な訳し方はしません。「ほかの関数を呼ぶ関数」と同じプロローグとエピローグを付けるだけです。呼ばれるたびに新しいフレームがスタックに積まれるので、それぞれの呼び出しが自分の `n` を持てます。

```c
int fib(int n) {
    if (n < 2) return n;
    return fib(n - 1) + fib(n - 2);
}
```

```asm run title="再帰：呼び出しごとにフレームが 1 つ"
main:
    li   a0, 10
    call fib
    li   a7, 1
    ecall                   # 55
    li   a7, 10
    ecall

fib:
    li   t0, 2
    blt  a0, t0, base       # n < 2 なら、フレームを作らずに n を返す

    addi sp, sp, -16
    sw   ra, 12(sp)
    sw   s0, 8(sp)
    sw   s1, 4(sp)

    mv   s0, a0             # n を取っておく
    addi a0, s0, -1
    call fib                # fib(n - 1)
    mv   s1, a0             # 結果を取っておく
    addi a0, s0, -2
    call fib                # fib(n - 2)
    add  a0, s1, a0

    lw   ra, 12(sp)
    lw   s0, 8(sp)
    lw   s1, 4(sp)
    addi sp, sp, 16
base:
    ret
```

`n < 2` の場合を、フレームを作る前に片付けています。この場合は何も呼ばないので、保存が要らないからです。「CPU を見る」でステップ実行すると、`sp` が 16 ずつ下がり、また戻っていく様子を追えます。

## コンパイラの最適化 {#opt}

同じ C のプログラムでも、訳し方は 1 つではありません。コンパイラは、結果を変えない範囲で、より速く、より短い命令の並びを探します。これが**最適化**です。

### 最適化しないと、変数はすべてメモリに置かれる

最適化を切る指定（`-O0`）では、コンパイラは 1 文ずつ、前後を見ずに訳します。変数はすべてスタックに置き、使うたびに読み、変えるたびに書きます。さきほどの 1 から 10 の合計は、たとえば次のようになります。

```asm run title="最適化なしの形：変数はスタックに置き、毎回読み書きする"
main:
    addi sp, sp, -16
    sw   zero, 12(sp)       # sum = 0（sum は sp + 12）
    li   t0, 1
    sw   t0, 8(sp)          # i = 1（i は sp + 8）
    j    cond
body:
    lw   t0, 12(sp)         # sum を読む
    lw   t1, 8(sp)          # i を読む
    add  t0, t0, t1
    sw   t0, 12(sp)         # sum に書く
    lw   t0, 8(sp)          # i を読む
    addi t0, t0, 1
    sw   t0, 8(sp)          # i に書く
cond:
    lw   t0, 8(sp)          # i を読む
    li   t1, 10
    ble  t0, t1, body       # i <= 10 なら続ける
    lw   a0, 12(sp)
    li   a7, 1
    ecall
    addi sp, sp, 16
    li   a7, 10
    ecall
```

同じ計算に、3 通りの訳し方が出そろいました。

```fig bars 1 から 10 の合計を表示するまでに実行する命令数。訳し方で 3 倍近く違う
{
  items: [
    { label: '変数をスタックに置く（最適化なし）', value: 114 },
    { label: 'レジスタに置く、先頭で条件', value: 49 },
    { label: 'レジスタに置く、末尾で条件', value: 39, hl: true },
  ],
  unit: ' 命令',
}
```

変数をレジスタに置くことを**レジスタ割り付け**と呼びます。メモリの読み書きが消えるので、もっとも効き目の大きい最適化の 1 つです。第 18 章で見たとおり、メモリはレジスタよりずっと遅いからです。

### 定数の畳み込みと、軽い命令への置き換え

コンパイルの時点で答えがわかる計算は、コンパイラが済ませてしまいます。これを**定数の畳み込み**と呼びます。また、掛け算や割り算は、同じ結果になる軽い命令に置き換えます。

```c
int secs = 60 * 60 * 24;        // 1 日の秒数
int x = 5;
print_int(secs + x * 8);
```

```asm run title="60 * 60 * 24 は計算ずみの数に、x * 8 はシフトに"
main:
    li   t0, 86400          # 60 * 60 * 24 はコンパイラが計算しておく
    li   t1, 5              # x
    slli t1, t1, 3          # x * 8 は、左へ 3 ビットのシフト
    add  a0, t0, t1
    li   a7, 1
    ecall
    li   a7, 10
    ecall
```

実行時には、掛け算は 1 回もしていません。じつは、さきほどの「1 から 10 の合計」も、最適化するコンパイラなら答えの 55 を自分で求めて、`li a0, 55` の 1 命令にしてしまうことがあります。

### ループの中の計算を外に出す

ループの中にあっても、**何周目でも同じ結果になる計算**は、ループの前に 1 回だけやれば済みます。

```c
int a[8];
int x = 6, y = 7;
for (int i = 0; i < 8; i++) {
    a[i] = x * y + i;           // x * y は毎回同じ
}
```

```asm run title="素直な訳：x * y をループの中で毎回計算する" mem="0x8000,32"
main:
    la   t0, a
    li   t1, 6              # x
    li   t2, 7              # y
    li   t3, 0              # i
    li   t4, 8
loop:
    mul  t5, t1, t2         # x * y（毎回同じ）
    add  t5, t5, t3         # + i
    slli t6, t3, 2
    add  t6, t0, t6         # a[i] の番地
    sw   t5, 0(t6)
    addi t3, t3, 1
    blt  t3, t4, loop
    li   a7, 10
    ecall

.data
a:  .space 32
```

```asm run title="最適化：x * y は外に出し、a[i] の番地はポインタを進めて作る" mem="0x8000,32"
main:
    la   t0, a              # p = a
    li   t1, 6
    li   t2, 7
    mul  t5, t1, t2         # x * y はループの前に 1 回だけ
    addi t4, t0, 32         # 終わりの番地
loop:
    sw   t5, 0(t0)          # *p = x * y + i
    addi t5, t5, 1          # 次の値は 1 大きい
    addi t0, t0, 4          # p++
    bltu t0, t4, loop
    li   a7, 10
    ecall

.data
a:  .space 32
```

メモリの中身（42、43、…、49）は同じです。ループの中身は 7 命令から 4 命令に減り、実行した命令数は 64 から 40 になりました。掛け算は 8 回から 1 回です。

### 末尾呼び出し

関数の最後の仕事が「別の関数を呼んで、その結果をそのまま返す」ことなら、戻ってくる必要がありません。`call` の代わりに、ただのジャンプで済みます。これを**末尾呼び出し**の最適化と呼びます。

```c
int gcd(int a, int b) {             // 最大公約数
    if (b == 0) return a;
    return gcd(b, a % b);           // 最後の仕事が、自分自身の呼び出し
}
```

素直に訳すと、呼ぶたびにフレームを積みます。

```asm run title="素直な訳：呼ぶたびに ra を保存する"
main:
    li   a0, 1071
    li   a1, 462
    call gcd
    li   a7, 1
    ecall                   # 21
    li   a7, 10
    ecall

gcd:
    beqz a1, base
    addi sp, sp, -16
    sw   ra, 12(sp)
    rem  t0, a0, a1         # a % b
    mv   a0, a1
    mv   a1, t0
    call gcd                # gcd(b, a % b)
    lw   ra, 12(sp)         # 戻ってきても、することは片付けだけ
    addi sp, sp, 16
base:
    ret
```

`call` を `tail`（戻り先を記録しないジャンプ）に替えると、フレームが丸ごと要らなくなります。

```asm run title="末尾呼び出し：call を tail に。再帰がループになる"
main:
    li   a0, 1071
    li   a1, 462
    call gcd
    li   a7, 1
    ecall                   # 21
    li   a7, 10
    ecall

gcd:
    beqz a1, base
    rem  t0, a0, a1         # a % b
    mv   a0, a1
    mv   a1, t0
    tail gcd                # 戻り先（ra）は main のまま、先頭へ飛ぶ
base:
    ret
```

実行した命令数は 39 から 24 に減りました。それ以上に大きいのは、**スタックを使わなくなった**ことです。再帰が何万回続いても、スタックがあふれません。C で再帰として書いた関数が、機械語ではただのループになっています。

:::deep 最適化を支えているもの
最適化が「結果を変えない」と言い切れるのは、言語の決まりと呼び出し規約があるからです。たとえば、`t0` は関数を呼ぶと壊れてよいという約束があるので、コンパイラは葉の関数で自由に `t0` を使えます。逆に、C の決まりに反するプログラム（配列の外を読む、初期化していない変数を使う、など）は、最適化レベルを変えると動きが変わることがあります。「`-O0` では動くのに `-O2` では動かない」というバグは、たいていこれが原因です。
:::

:::try
1. 下の練習用のプログラムは、C の `int f(int n)` を訳したものです。C のコードに戻すとどうなるか、考えてください
2. `main` の引数を 5 に変えたときの出力を予想してから、確かめてください
3. `mul` を使わずに、同じ結果になるように書き換えてください（ヒント：前の周の値に何を足せば、次の値になるでしょうか）
:::

```asm run title="練習用"
main:
    li   a0, 4
    call f
    li   a7, 1
    ecall
    li   a7, 10
    ecall

f:
    li   t0, 0              # s
    li   t1, 1              # i
    bgt  t1, a0, done
loop:
    mul  t2, t1, t1
    add  t0, t0, t2
    addi t1, t1, 1
    ble  t1, a0, loop
done:
    mv   a0, t0
    ret
```

:::key この章のまとめ
- コンパイラは C をアセンブリに、アセンブラはアセンブリを機械語に直し、リンカは機械語をつないで番地を決める
- ローカル変数はレジスタに、グローバル変数と、`&` で番地を取られた変数はメモリに置く。変数の名前は機械語に残らない
- 型は、命令の選び方（`div` と `divu`、`srai` と `srli`、`lw` と `lh`）と、番地の計算に掛ける数（`int` なら 4）になって消える
- `if` は条件を逆にした分岐、ループは分岐と前へ戻るジャンプ。条件はループの末尾に置くと 1 周が短い
- 関数は呼び出し規約どおりに訳す。ほかの関数を呼ぶ関数は、**プロローグ**で `ra` と `s` レジスタを保存し、**エピローグ**で戻す
- `a[i]` は「先頭 + i × 要素の大きさ」、`p->member` は「先頭 + オフセット」。構造体には整列のための詰め物が入る
- **最適化**は、結果を変えずに命令を減らす。レジスタ割り付け、定数の畳み込み、軽い命令への置き換え、ループの外への移動、末尾呼び出し
:::

:::quiz 再帰とスタックフレーム
次の C の関数 `sum_digits` を、アセンブリに訳してください。`n`（0 以上）の、10 進での各桁の和を返します。

`main` は、`s0`〜`s3` に値を入れたまま `sum_digits` を 3 回呼び、結果と、`s0`〜`s3` の合計を表示します。`s` レジスタを使うなら、保存して元に戻してください。
