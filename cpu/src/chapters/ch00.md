## この本について {#about}

この本は、コンピュータの中心にある **CPU**（中央処理装置。計算をする部品）の仕組みを、いちばん下の 0 と 1 から学ぶための日本語の学習書です。

CPU の本は、たいてい次のどちらかに偏ります。

- **プログラムの書き方の本**：命令の使い方は詳しいが、その命令を実行する回路には触れない
- **回路の本**：ゲートや加算器には詳しいが、それがプログラムを動かすところまでつながらない

この本は、その間をつなぎます。0 と 1 から始めて回路を組み、命令を覚えてプログラムを書き、最後に CPU の中でその命令がどう流れるかを見ます。

書くときに決めたルールは 3 つです。

1. **自分の手で動かす。** 本文のプログラムと回路は、ほぼすべてその場で実行できます。読むだけより、動かして、少し書き換えて、もう一度動かすほうが、何倍も早く身に付きます。
2. **絵で示せるものは、先に絵で示す。** ビットの並び、回路、メモリの中身、命令の流れ。文章より先に図を置きます。
3. **本物を使う。** 動かすのは、学習用に作った架空の CPU ではありません。実際のチップに使われている **RISC-V**（リスク・ファイブ）という命令セットの CPU です。

前提にする知識は多くありません。何かのプログラミング言語で、変数と if と繰り返しを書いたことがあれば十分です。

## まず動かす：画面に絵を出す {#first-run}

説明の前に、1 つ動かしてみましょう。下のブロックの「実行」ボタンを押してください。Ctrl + Enter（Mac は ⌘ + Enter）でも実行できます。

```asm run title="ハートを描く"
# 絵のデータ（下の .data）を 1 行ずつ読んで、1 のところに点を打つ
    la   s0, picture      # s0 = 絵のデータの場所
    li   s1, 0x10000      # s1 = 画面の左上の番地
    li   s2, 0            # s2 = いま描いている行（0〜15）
row:
    lhu  t0, 0(s0)        # t0 = この行の 16 個の 0 と 1
    li   t1, 0            # t1 = 右から何個目か（0〜15）
dot:
    srl  t2, t0, t1       # 右へずらして
    andi t2, t2, 1        # いちばん右の 1 個だけ取り出す
    beqz t2, next         # 0 なら点を打たない
    li   t3, 15
    sub  t3, t3, t1       # 左から何個目か
    slli t3, t3, 1        # 横の位置 = 2 倍
    slli t4, s2, 6        # 縦の位置 = 行 × 2 × 32
    add  t4, t4, t3
    add  t4, t4, s1       # t4 = 点を打つ番地
    li   t5, 2            # 色の番号（2 = 赤）
    sb   t5, 0(t4)        # 2 × 2 の 4 か所に色を書く
    sb   t5, 1(t4)
    sb   t5, 32(t4)
    sb   t5, 33(t4)
next:
    addi t1, t1, 1
    li   t6, 16
    blt  t1, t6, dot      # 16 個ぶん繰り返す
    addi s0, s0, 2        # 次の行のデータへ
    addi s2, s2, 1
    blt  s2, t6, row      # 16 行ぶん繰り返す
    li   a7, 10
    ecall                 # 終わり

.data
picture:
    .half 0b0000000000000000
    .half 0b0000000000000000
    .half 0b0001110001110000
    .half 0b0011111011111000
    .half 0b0111111111111100
    .half 0b0111111111111100
    .half 0b0111111111111100
    .half 0b0111111111111100
    .half 0b0011111111111000
    .half 0b0001111111110000
    .half 0b0000111111100000
    .half 0b0000011111000000
    .half 0b0000001110000000
    .half 0b0000000100000000
    .half 0b0000000000000000
    .half 0b0000000000000000
```

出力欄に、赤いハートが出たはずです。これは、あなたのブラウザの中で動いている小さな CPU が、上のプログラムを 1 命令ずつ実行した結果です。サーバには何も送っていません。

プログラムの下半分をよく見てください。`0` と `1` の並びの中に、ハートの形が見えます。上半分は、その 0 と 1 を 1 個ずつ調べて、1 のところに赤い点を打つ手順です。

今は、上半分が読めなくてかまいません。**この本を終えるころには、このプログラムの全部の行が読めて、自分で書けるようになります。** さらに、それぞれの行を CPU の中の回路がどう実行しているかも、説明できるようになります。

:::try 絵と色を変える
プログラムはその場で書き換えられます。次の 2 つを試してください。

- `li t5, 2` の `2` を、`7` や `5` に変えて実行する。色が変わります。色の番号は 0〜15 の 16 種類です
- 下半分の `0` と `1` を書き換えて、別の絵にする。1 行は 16 個、全部で 16 行です

書き換えたあとは「元に戻す」ボタンが現れます。壊しても、すぐ最初の状態に戻せます。
:::

| 番号 | 色 | 番号 | 色 | 番号 | 色 | 番号 | 色 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 0 | 黒 | 4 | 青 | 8 | 橙 | 12 | 濃い灰 |
| 1 | 白 | 5 | 黄 | 9 | 紫 | 13 | 濃い緑 |
| 2 | 赤 | 6 | 水色 | 10 | 茶 | 14 | 紺 |
| 3 | 緑 | 7 | 桃 | 11 | 灰 | 15 | 肌色 |

### 何が動いているのか

「実行」を押してから絵が出るまでに、次のことが起きています。

```fig graph 「実行」を押してから結果が出るまで。全部があなたのブラウザの中で起きる
{
  col: 200, row: 96,
  nodes: [
    { id: 'src', label: 'アセンブリ', sub: '人が読み書きする言葉', x: 0, y: 0, mono: false },
    { id: 'bin', label: '機械語', sub: 'CPU が読む数の並び', x: 1, y: 0, kind: 'stack', mono: false },
    { id: 'cpu', label: 'CPU', sub: '1 命令ずつ実行する', x: 2, y: 0, kind: 'accent' },
    { id: 'con', label: 'コンソール', sub: '文字の出力', x: 1.5, y: 1, kind: 'ext', mono: false },
    { id: 'scr', label: '画面', sub: '32 × 32 個の点', x: 2.5, y: 1, kind: 'ext', mono: false },
  ],
  edges: [
    { from: 'src', to: 'bin', label: 'アセンブラ' },
    { from: 'bin', to: 'cpu', label: 'メモリに置く' },
    { from: 'cpu', to: 'con' },
    { from: 'cpu', to: 'scr' },
  ],
}
```

- 上のブロックに書いてある言葉を**アセンブリ**と呼びます。CPU の命令を、人が読める短い単語（`li`、`add` など）で書いたものです。
- CPU は単語を読めません。読めるのは数だけです。そこで**アセンブラ**という道具が、アセンブリを数の並び（**機械語**）に直します。
- CPU は、その数を 1 つずつ取り出して実行します。この本の CPU は、RISC-V の命令を実行する**エミュレータ**（CPU の動きをプログラムでまねたもの）です。動きは本物の RISC-V の CPU と同じです。
- 結果の出口は 2 つあります。文字が出る**コンソール**と、32 × 32 個の点でできた**画面**です。

1 つのブロックは、1 つの独立したプログラムです。実行するたびに、新しい CPU が最初から動きます。前のブロックの結果は、次のブロックに残りません。

## 書き換えて試す {#edit}

ハートのプログラムは長かったので、今度はいちばん短いプログラムを動かします。

```asm run
    li   a0, 42       # a0 に 42 を入れる
    li   a7, 1        # a7 に 1 を入れる（1 = 「a0 を数として表示」）
    ecall             # 頼んだことを実行してもらう
```

コンソールに `42` と出ます。この 3 行は、この先の章で何度も使う形です。

- `a0` や `a7` は**レジスタ**です。CPU の中にある、数を 1 つ入れておける小さな置き場です。名前の付いた変数だと思ってください。
- `li` は、レジスタに数を入れる命令です。`li a0, 42` で、`a0` に 42 が入ります。
- `ecall` は、表示や終了といった仕事を外に頼む命令です。何を頼むかは `a7` の番号で決まります。1 番は「`a0` の値を数として表示する」です。
- `#` から行の終わりまでは**コメント**（人のためのメモ）で、CPU は読みません。

`42` を好きな数に変えて、もう一度実行してみてください。書いた数がそのまま出るはずです。

`a7` の番号を変えると、同じ数が別の姿で表示されます。

```asm run title="同じ数を 3 通りに表示する"
    li   a0, 65
    li   a7, 1        # 1 = 数として表示
    ecall
    li   a7, 11       # 11 = 文字として表示
    ecall
    li   a7, 35       # 35 = 0 と 1 の並びとして表示
    ecall
```

`65`、`A`、`00000000000000000000000001000001` が続けて出ます。CPU の中にあるのは 1 つの数だけで、それを数と見るか、文字と見るか、0 と 1 の並びと見るかは、見る側が決めています。これが第 2 章の主題です。

### エラーも結果のうち

わざと間違えてみましょう。`a0` を `a99` と書き間違えたプログラムです。

```asm run error
    li   a99, 42
    li   a7, 1
    ecall
```

「1 行目：…」という形で、何行目の何がいけないのかが日本語で出ます。プログラムが動かないときは、まずこの行番号を見てください。

「エラーになる」の印が付いたブロックは、わざとエラーを起こす例です。エラーの文を読む練習に使ってください。

## CPU を見る {#cpu-view}

この本のいちばんの道具が、**ステップ実行**です。プログラムを一気に最後まで動かすのではなく、1 命令ずつ進めて、そのたびに CPU の中を見ます。

```asm run step title="1 命令ずつ進める"
    li   t0, 3        # t0 = 3
    li   t1, 4        # t1 = 4
    add  a0, t0, t1   # a0 = t0 + t1
    li   a7, 1
    ecall             # a0 を表示
```

このブロックは、最初からステップ実行の画面で開きます。「1 命令進む」を押すたびに、次のことが見えます。

- 次に実行する行が光る。直前に実行した行にも、うすい色が付く
- 「直前の命令がしたこと」に、その命令が何を読み、何を書いたかが文で出る
- レジスタの一覧で、その命令が書き換えたレジスタに色が付く。1 回目で `t0` が 3 に、2 回目で `t1` が 4 に、3 回目で `a0` が 7 に変わる
- 「戻る」で 1 命令前に戻れる。「最後まで」で残りを一気に実行し、「最初から」でやり直せる

ほかのブロックも、実行したあとに出力欄の「ステップ実行で見る」か、ページの上の「CPU を見る」を押せば、画面の下に同じ画面が開いて、ステップ実行できます。見られるものは次のとおりです。

| 見られるもの | 中身 | くわしく学ぶ章 |
| --- | --- | --- |
| レジスタ | CPU の中の 32 個の置き場と、その値 | 第 10 章 |
| 次に実行する命令 | その命令の場所（pc）と、機械語の 32 個の 0 と 1 | 第 9 章 |
| 直前の命令がしたこと | 読み書きしたレジスタとメモリ。その下に、ALU（計算をする回路）の入力と結果、制御信号 | 第 16 章 |
| メモリ | プログラムとデータが置かれた場所の中身 | 第 8 章、第 12 章 |
| 画面とコンソール | そこまでに出た結果 | 第 14 章 |

「プログラムが思ったとおりに動かない」ときは、たいてい、どこかの行でレジスタが予想と違う値になっています。ステップ実行で 1 行ずつ確かめるのが、いちばんの近道です。

:::note 回路も動かせる
この本には、もう 1 つ実行できるものがあります。**回路**です。第 2 章から、次のような短い記述で回路を作り、入力の全部の組み合わせを試します。くわしい書き方は第 4 章で説明します。
:::

```logic run title="2 つの入力が両方 1 のときだけ 1 を出す回路"
in a, b
out y
y = a and b
```

最初に動かしたハートのプログラムは、この地図のあちこちを使っています。`0b0001110001110000` は第 2 章、右へずらす `srl` と取り出す `andi` も第 2 章、`blt` での繰り返しは第 11 章、`sb` で画面に書くのは第 14 章の話です。

順番に読むのがおすすめですが、プログラムを早く書きたい人は、第 2 章と第 3 章を読んだあと、第 10 章に進んでもかまいません。回路の章（第 4〜7 章）は、第 16 章の前までに読んでおけば間に合います。

### 記号と表記

| 表記 | 意味 |
| --- | --- |
| 「実行」ボタンのあるブロック | ブラウザの中の CPU（または回路シミュレータ）で実行できる。書き換えてよい |
| 「エラーになる」の印 | わざとエラーを起こす例 |
| 「やってみよう」の枠 | 自分で書き換えて試す課題 |
| `0x` で始まる数 | 16 進数（第 2 章）。`0x10` は 16 |
| `0b` で始まる数 | 2 進数（第 2 章）。`0b101` は 5 |

### 実験場

目次のいちばん下にある「実験場」は、自由に書いて試すための広い編集画面です。「CPU を見る」の画面がいつも開いていて、サンプルのプログラム（ライフゲーム、跳ねるボール、キーで動かすゲームなど）を選べます。実行の速さも変えられ、「論理回路」のタブでは回路も試せます。本文の例を大きく作り変えたいときや、自分のプログラムを書きたいときに使ってください。

:::key この本の使い方
- 本文のブロックは「実行」で動かせる。書き換えて、何度でも試せる。「元に戻す」で最初の状態に戻る
- 1 つのブロックは 1 つの独立したプログラム。実行のたびに新しい CPU で動く
- `li a0, 数` → `li a7, 1` → `ecall` で、数をコンソールに表示できる
- 動きが分からないときは、「CPU を見る」で 1 命令ずつ進めて、レジスタの変化を見る
- 章の最後には確認問題がある。自分で書いて、答え合わせをする
:::

## 確認問題 {#quiz}

各章の最後には、自分でプログラム（または回路）を書く確認問題があります。「答え合わせ」を押すと、あなたのプログラムを新しい CPU で実行し、結果が模範解答と同じかどうかを判定します。何度でもやり直せます。まずは、数字を 1 か所書き換えるだけの問題で、使い方を試してください。

:::quiz 今年の数を表示する
下のプログラムは、コンソールに `42` を表示します。これを書き換えて、コンソールに `2026` と表示してください。

```asm starter
    li   a0, 42
    li   a7, 1
    ecall
```

```asm answer
    li   a0, 2026
    li   a7, 1
    ecall
```

:::hint
表示されるのは `a0` に入っている数です。`li a0, 42` の `42` を書き換えます。
:::
:::
