## 出力を入力に戻す {#feedback}

ここまでに作った回路は、ゲートも加算器も ALU も、**いまの入力だけ**で出力が決まりました。入力を変えれば、出力もすぐ変わります。前に何が入力されていたかは、まったく関係ありません。こういう回路を**組み合わせ回路**と呼びます。

組み合わせ回路だけでは、コンピュータは作れません。計算の結果をどこかに取っておいて、次の計算に使う必要があるからです。つまり、**覚えておく**回路が要ります。

ゲートしか持っていないのに、どうやって覚えるのでしょうか。答えは、これまで一度もやらなかった配線にあります。**出力を、自分の入力に戻す**のです。

```fig circuit OR の出力を、自分の入力に戻した回路。一度 1 になると、s を 0 に戻しても 1 のまま
{
  parts: [
    { id: 's', type: 'in', x: 0, y: 1 }, { id: 'g', type: 'or', x: 3, y: 1.5 }, { id: 'q', type: 'out', x: 10, y: 1.5 },
  ],
  wires: ['s -> g.a', 'g -> q', { from: 'g', to: 'g.b', via: [[7.5, 1.5], [7.5, 3.5], [2, 3.5]] }],
  steps: [
    { title: 's = 0', vals: { s: 0, q: 0 }, say: '最初は、OR の入力がどちらも 0 です。出力 q も 0 です。' },
    { title: 's = 1', hl: ['s', 'g'], vals: { s: 1, q: 1 }, say: 's を 1 にすると、q が 1 になります。その 1 は、下の線を通って OR の入力に戻ってきます。' },
    { title: 's = 0 に戻す', hl: ['g'], vals: { s: 0, q: 1 }, say: 's を 0 に戻しても、戻ってきた 1 が OR に入り続けるので、q は 1 のままです。回路が「s が 1 になったことがある」と覚えています。' },
  ],
}
```

出力を入力に戻す配線を**帰還**（フィードバック）と呼びます。回路記述では、式の右辺に自分自身を書きます。

```logic run title="一度 1 になったら戻らない"
in s
out q
q = s or q        # 自分の出力を、自分の入力に使う
step s=0
step s=1
step s=0
step s=0
```

記憶のある回路では、真理値表は作れません。同じ入力でも、それまでのいきさつで出力が変わるからです。代わりに、`step` で**入力を時間の順に与えて**、そのたびの出力を並べた表を出します。これを**タイミング表**と呼びます。上には、同じ内容が波形でも表示されます。

1 行目と 3 行目を比べてください。どちらも s は 0 なのに、q は 0 と 1 で違います。回路が 1 ビットを覚えた証拠です。

ただ、この回路は 1 を覚えたら最後、二度と 0 に戻せません。記憶としては、まだ半人前です。

:::warn 帰還は、落ち着かないこともある
帰還は、いつもうまくいくわけではありません。NOT の出力をそのまま入力に戻すと、「0 なら 1 になり、1 なら 0 になり…」と、いつまでも値が決まりません。これを**発振**と呼びます。下の回路を実行すると、値が決まらない印の `?` と、警告が出ます。
:::

```logic run title="落ち着かない回路"
in a
out y
y = not (y and a)
step a=0
step a=1
```

a が 0 の間は y は 1 で落ち着きますが、a を 1 にすると NOT の輪になって発振します。記憶する回路は、**落ち着く形の帰還**を選んで作ります。

## SR ラッチ：セットとリセット {#sr}

1 にすること（**セット**、set）も、0 に戻すこと（**リセット**、reset）もできる回路を作ります。NOR を 2 個使い、それぞれの出力を、相手の入力にたすき掛けでつなぎます。これを **SR ラッチ**と呼びます。ラッチ（latch）は、扉の掛け金のことです。

```fig circuit SR ラッチ。2 個の NOR が、互いの出力を入力にしている。強調した線が 1
{
  parts: [
    { id: 'r', type: 'in', x: 1, y: 1 }, { id: 's', type: 'in', x: 1, y: 7 },
    { id: 'g1', type: 'nor', x: 4, y: 1.5 }, { id: 'g2', type: 'nor', x: 4, y: 6.5 },
    { id: 'q', type: 'out', x: 11, y: 1.5 }, { id: 'nq', type: 'out', x: 11, y: 6.5 },
  ],
  wires: ['r -> g1.a', 's -> g2.b', 'g1 -> q', 'g2 -> nq',
    { from: 'g1', to: 'g2.a', via: [[8.5, 1.5], [8.5, 3.5], [3, 3.5]] },
    { from: 'g2', to: 'g1.b', via: [[9.5, 6.5], [9.5, 4.5], [2.5, 4.5]] }],
  steps: [
    { title: 's = 1（セット）', hl: ['s', 'g1'], vals: { s: 1, r: 0, q: 1, nq: 0 }, say: 's が 1 なので、下の NOR は 0 を出します。上の NOR は、入力が両方 0 になるので 1 を出します。q は 1 です。' },
    { title: 's = 0（保持）', hl: ['g1'], vals: { s: 0, r: 0, q: 1, nq: 0 }, say: 's を 0 に戻しても、q の 1 が下の NOR に入っているので、下の NOR は 0 のまま。上の NOR も 1 のまま。互いに支え合って、状態が続きます。' },
    { title: 'r = 1（リセット）', hl: ['r', 'g2'], vals: { s: 0, r: 1, q: 0, nq: 1 }, say: 'r が 1 なので、上の NOR は 0 を出します。q は 0 です。下の NOR は、入力が両方 0 になるので 1 を出します。' },
    { title: 'r = 0（保持）', hl: ['g2'], vals: { s: 0, r: 0, q: 0, nq: 1 }, say: 'r を 0 に戻しても、nq の 1 が上の NOR を 0 に押さえ続けます。こんどは q = 0 の状態が続きます。' },
  ],
}
```

NOR は「入力のどちらかが 1 なら 0 を出す」ゲートでした。図を追うと、s = 0、r = 0 のとき、回路には**落ち着ける状態が 2 つ**あることがわかります。「q = 1、nq = 0」と「q = 0、nq = 1」です。どちらの状態にいるかが、覚えている 1 ビットです。

```logic run title="SR ラッチ"
in s, r
out q, nq
q  = r nor nq
nq = s nor q
step s=1, r=0     # セット
step s=0          # 保持
step r=1          # リセット
step r=0          # 保持
step s=1          # もう一度セット
step s=0          # 保持
```

`step` に書かなかった入力は、前の行のままです。s = 0、r = 0 の行が 3 つありますが、q は 1、0、1 と、直前にしたことを覚えています。nq はいつも q の逆です。

| s | r | 働き |
| --- | --- | --- |
| 1 | 0 | セット（q を 1 にする） |
| 0 | 1 | リセット（q を 0 にする） |
| 0 | 0 | 保持（前の状態を続ける） |
| 1 | 1 | 使ってはいけない（下で説明） |

### 電源を入れた直後は、わからない

セットもリセットもしないうちに、いきなり「保持」から始めるとどうなるでしょうか。

```logic run title="最初の状態は決まっていない"
in s, r
out q, nq
q  = r nor nq
nq = s nor q
step s=0, r=0     # 何もしていないのに「保持」
step s=1          # セット
step s=0
```

1 行目の q と nq は `?` です。覚えるべき値がまだ何も入っていないので、どちらの状態になるかは決まりません。本物の回路では、部品のわずかなばらつきで、0 か 1 のどちらかに転がります。どちらになるかは、電源を入れるたびに違うかもしれません。

**記憶する回路は、最初に値を入れるまで、中身がわからない。** コンピュータが電源を入れた直後に「リセット」の手順を踏むのは、このためです。

### s と r を同時に 1 にしてはいけない

もう 1 つ、やってはいけない入力があります。

```logic run title="禁止入力"
in s, r
out q, nq
q  = r nor nq
nq = s nor q
step s=1, r=0
step s=1, r=1     # セットとリセットを同時に
step s=0, r=0     # 同時にやめる
step s=1          # セットし直すと元に戻る
```

s = 1、r = 1 では、q も nq も 0 になります。「nq は q の逆」という約束が破れています。さらに、そこから同時に 0 に戻すと、2 つの NOR がそろって 1 を出そうとし、次の瞬間にはそろって 0 を出そうとして、値が決まらなくなります。「セットしろ」と「リセットしろ」を同時に言われて、言われた側が困っている状態です。

そこで、SR ラッチは s と r を同時に 1 にしない、という約束で使います。次の節で、この約束を回路で守らせます。

## D ラッチ：覚える値を 1 本で渡す {#dlatch}

SR ラッチは、セットとリセットの 2 本の線で操作しました。使う側としては、「**この値**を覚えてくれ」と 1 本の線で渡せるほうが便利です。

そこで、入力を 2 本に作り替えます。

- **d**（data）：覚えさせたい値
- **en**（enable、有効）：1 の間だけ、d を取り込む

en が 1 のとき、d が 1 ならセット、d が 0 ならリセットをします。en が 0 のときは、s も r も 0 にして保持させます。これが **D ラッチ**です。

```fig circuit D ラッチ。左の 2 個の AND が、d と en から s と r を作る。右の 2 個の NOR は SR ラッチ
{
  parts: [
    { id: 'd', type: 'in', x: 0, y: 7.5 }, { id: 'en', type: 'in', x: 0, y: 4 },
    { id: 'n', type: 'not', x: 2, y: 0.5 }, { id: 'ar', type: 'and', x: 6, y: 1 }, { id: 'as', type: 'and', x: 6, y: 7 },
    { id: 'g1', type: 'nor', x: 11, y: 1.5 }, { id: 'g2', type: 'nor', x: 11, y: 6.5 },
    { id: 'q', type: 'out', x: 18.5, y: 1.5 }, { id: 'nq', type: 'out', x: 18.5, y: 6.5 },
    { type: 'text', x: 10, y: 0.3, text: 'r', anchor: 'middle' }, { type: 'text', x: 10, y: 7.7, text: 's', anchor: 'middle' },
  ],
  wires: [
    'd -> as.b', { from: 'd', to: 'n', mid: 1 }, 'n -> ar.a', { from: 'en', to: 'ar.b', mid: 4.5 }, { from: 'en', to: 'as.a', mid: 4.5 },
    'ar -> g1.a', 'as -> g2.b', 'g1 -> q', 'g2 -> nq',
    { from: 'g1', to: 'g2.a', via: [[15.5, 1.5], [15.5, 3.5], [10, 3.5]] },
    { from: 'g2', to: 'g1.b', via: [[16.5, 6.5], [16.5, 4.5], [9.5, 4.5]] },
  ],
  steps: [
    { title: 'en = 1, d = 1', hl: ['d', 'en', 'as', 'g1'], vals: { d: 1, en: 1, q: 1, nq: 0 }, say: '下の AND が 1 を出して、セットします。q は d と同じ 1 になります。' },
    { title: 'en = 0', hl: ['g1'], vals: { d: 0, en: 0, q: 1, nq: 0 }, say: 'en が 0 だと、2 個の AND はどちらも 0 しか出せません。d を 0 に変えても SR ラッチには届かず、q は 1 を保ちます。' },
    { title: 'en = 1, d = 0', hl: ['en', 'n', 'ar', 'g2'], vals: { d: 0, en: 1, q: 0, nq: 1 }, say: 'NOT が 1 を出し、上の AND が 1 を出して、リセットします。q は d と同じ 0 になります。' },
  ],
}
```

s と r は、片方が `d`、もう片方が `not d` から作られるので、同時に 1 になることはありません。禁止入力は、回路の作りによって封じられました。

```logic run title="D ラッチ"
in d, en
out q
s = d and en
r = (not d) and en
q  = r nor nq
nq = s nor q
step d=1, en=1    # 開いている：q は d と同じ
step d=0          # 開いている：q は d についていく
step d=1
step en=0         # 閉じる：このときの d（1）を覚える
step d=0          # 閉じている：d を変えても q は変わらない
step d=1
step d=0
step en=1         # 開く：いまの d（0）が q に出る
```

en が 1 の間、q は d にそのままついていきます。D ラッチが「開いている」状態で、中が透けて見えるという意味で**透過**とも言います。en が 0 になると、その瞬間の d を覚えて、以後は d がどう変わっても動きません。

AND の門（第 6 章）が、ここでも働いています。en は「d を通すか、止めるか」を決める門です。

## クロック：全員が合わせる拍子 {#clock}

D ラッチで 1 ビットを覚えられるようになりました。しかし、CPU の中で使うには、困った性質が 1 つ残っています。**開いている間じゅう、入力が出力に筒抜けになる**ことです。

次の節で作るカウンタのように、「記憶の出力を計算して、同じ記憶に戻す」回路を考えてください。D ラッチが開いている間に、出力が計算を通って入力に戻り、それがまた出力に出て…と、1 回のつもりが何回も回ってしまいます。

必要なのは、「**いまだ**」という一瞬にだけ値を取り込む記憶です。その一瞬を全員に知らせる信号が、**クロック**（clock）です。

```fig wave クロック。0 と 1 を一定の速さで繰り返す。0 から 1 に変わる瞬間（立ち上がり）が「いまだ」の合図
{
  signals: [{ name: 'clk', clock: true }],
  cycles: 6,
  marks: [{ at: 1, label: '立ち上がり' }, { at: 2 }, { at: 3 }, { at: 4 }, { at: 5 }],
  spans: [{ from: 3, to: 4, label: '1 周期' }],
}
```

クロックは、0 と 1 を一定の速さで行き来するだけの信号です。オーケストラの指揮者の棒や、メトロノームにあたります。

- 0 から 1 に変わる瞬間を**立ち上がり**と呼ぶ
- 立ち上がりから次の立ち上がりまでが **1 周期**（1 サイクル）
- 1 秒間の周期の数が**周波数**。3 GHz（ギガヘルツ）の CPU は、1 秒に 30 億回の立ち上がりがある

CPU の中の記憶は、すべて同じクロックにつながっていて、立ち上がりの瞬間にだけ、いっせいに値を取り込みます。立ち上がりと立ち上がりの間は、組み合わせ回路が次の値を計算する時間です。

:::note クロックの速さは、いちばん遅い計算で決まる
第 5 章で、繰り上がりが伝わるのに時間がかかることを見ました。次の立ち上がりまでに、すべての組み合わせ回路が計算を終えていなければ、間違った値を取り込んでしまいます。そのため、1 周期の長さは、回路の中でいちばん時間のかかる道すじより長くする必要があります。クロックを速くするには、その道すじを短くするしかありません。第 17 章のパイプラインは、そのための工夫です。
:::

## D フリップフロップ：立ち上がりの瞬間だけ取り込む {#dff}

立ち上がりの**瞬間にだけ**値を取り込む記憶を、**D フリップフロップ**（D flip-flop）と呼びます。D ラッチを 2 個つないで作れます。

```fig circuit D フリップフロップ。D ラッチを 2 個並べ、前段にはクロックの NOT を、後段にはクロックをそのまま en として入れる。2 つが同時に開くことはない
{
  parts: [
    { id: 'd', type: 'in', x: 0, y: 1.5 }, { id: 'clk', type: 'in', x: 0, y: 7 },
    { id: 'n', type: 'not', x: 2, y: 3.5 },
    { id: 'l1', type: 'box', x: 5, y: 2.5, w: 4, h: 4, label: '前段\nD ラッチ', ins: ['d', '_x', 'en'], outs: ['q'] },
    { id: 'l2', type: 'box', x: 13, y: 2.5, w: 4, h: 4, label: '後段\nD ラッチ', ins: ['d', '_x', 'en'], outs: ['q'] },
    { id: 'q', type: 'out', x: 21, y: 2.5 },
    { type: 'text', x: 11, y: 0.8, text: 'm', anchor: 'middle' },
  ],
  wires: [
    'd -> l1.d', { from: 'clk', to: 'n', mid: 1 }, 'n -> l1.en', { from: 'l1.q', to: 'l2.d', mid: 11.5 },
    { from: 'clk', to: 'l2.en', via: [[12, 7]] }, 'l2.q -> q',
  ],
  steps: [
    { title: 'clk = 0', hl: ['d', 'n', 'l1'], vals: { clk: 0 }, say: '前段が開いていて、d の値が m まで来ています。後段は閉じているので、q は前の値のままです。d が変わっても、q には届きません。' },
    { title: 'clk = 1', hl: ['clk', 'l2'], vals: { clk: 1 }, say: 'クロックが立ち上がると、前段が閉じて、その瞬間の d を m に固定します。同時に後段が開いて、m を q に出します。この後 d が変わっても、前段が閉じているので q は変わりません。' },
  ],
}
```

二重の扉を思い浮かべてください。片方が開いているとき、もう片方は必ず閉まっています。d の値は、clk が 0 の間に 1 枚目の扉を通って中間の部屋（m）に入り、clk が 1 になった瞬間に 2 枚目の扉から q に出ます。入口から出口まで一気に通り抜けることはできません。

ゲートだけで組み立てて、確かめてみましょう。前の節の D ラッチを部品にします。

```logic run title="D ラッチ 2 個で D フリップフロップ"
def dlatch(d, en) -> q {
  s = d and en
  r = (not d) and en
  q  = r nor nq
  nq = s nor q
}

in d, clk
out q
m = dlatch(d, not clk)     # 前段：clk が 0 の間、開く
q = dlatch(m, clk)         # 後段：clk が 1 の間、開く

step d=1, clk=0     # まだ何も取り込んでいない
step clk=1          # 立ち上がり：d = 1 を取り込む
step d=0            # clk が 1 の間に d を変えても…
step d=1
step d=0
step clk=0          # clk を下げても…
step clk=1          # 立ち上がり：d = 0 を取り込む
step d=1
step clk=0
step clk=1          # 立ち上がり：d = 1 を取り込む
```

1 行目の q は `?` です。まだ一度も立ち上がりが来ていないので、後段のラッチの中身が決まっていません（警告が出ますが、正しい動きです）。その後は、q が変わるのは **clk が 0 から 1 になった行だけ**です。clk が 1 の間に d を何度変えても、clk を下げても、q は動きません。

ゲートは 11 個です。これで 1 ビットを、決まった瞬間に取り込んで覚えられます。

### これからは `reg` と書く

D フリップフロップの中身もわかりました。ここから先は、1 つの部品として `reg` と書きます。クロックの線は書かなくても、自動でつながります。

```logic run title="reg は D フリップフロップ"
in d
out q
reg q = d         # クロックの立ち上がりで d を取り込む
step d=1
step d=0
step d=1
step
step d=0
step
```

`reg` を使った回路では、タイミング表の **1 行が、クロックの 1 周期**になります。読み方に 1 つだけ決まりがあります。

- 行に出ているのは、**その周期の間**の値
- 行の終わりでクロックが立ち上がり、そのときの d が取り込まれる。q が新しい値になるのは**次の行から**

1 行目は d = 1 ですが、q はまだ 0 です（`reg` の最初の値は 0 と決めてあります）。2 行目で q が 1 になります。q の列は、d の列を 1 行ぶん下にずらしたものになっています。D フリップフロップは「**1 周期前の d を出す**部品」とも言えます。

```fig wave D フリップフロップの波形。q は、立ち上がりの直前の d を取り込み、次の立ち上がりまで保つ
{
  signals: [{ name: 'clk', clock: true }, { name: 'd', wave: '101100' }, { name: 'q', wave: '010110', hl: true }],
  marks: [1, 2, 3, 4, 5],
  spans: [{ from: 1, to: 2, label: 'q は前の周期の d' }],
}
```

## レジスタ：数を覚える {#register}

D フリップフロップを 4 個並べて、同じクロックをつなげば、4 ビットの数を覚えられます。これが**レジスタ**（register）です。

```fig circuit 4 ビットのレジスタ。D フリップフロップを 4 個並べ、クロックを全部につなぐ。三角の印がクロックの入力
{
  parts: [
    ...[3, 2, 1, 0].flatMap((bit, i) => [
      { id: 'd' + bit, type: 'in', x: 1, y: 1 + i * 4.5, label: `d[${bit}]` },
      { id: 'f' + bit, type: 'dff', x: 5, y: 2 + i * 4.5 },
      { id: 'q' + bit, type: 'out', x: 12, y: 1 + i * 4.5, label: `q[${bit}]` },
    ]),
    { id: 'clk', type: 'in', x: 1, y: 19.5 },
  ],
  wires: [
    ...[3, 2, 1, 0].flatMap((bit) => [`d${bit} -> f${bit}.d`, `f${bit}.q -> q${bit}`, { from: 'clk', to: `f${bit}.clk`, via: [[3, 19.5]] }]),
  ],
}
```

```logic run title="4 ビットのレジスタ"
in d[4]
out q[4]
reg q[4] = d
step d=5
step d=9
step d=12
step d=0
step
```

q は、1 周期遅れて d を追いかけます。ただ、これでは毎周期、新しい値で上書きされてしまいます。覚えておきたい値を、何周期も持ち続けることができません。

### 書き込むときだけ取り込む

そこで、「**いま書き込む**」という合図 en を付けます。en が 1 の周期だけ d を取り込み、0 の周期は自分の値をそのまま取り込み直します。選ぶ回路なので、マルチプレクサの出番です。

```logic run title="書き込みの合図が付いたレジスタ"
in d[4], en
out q[4]
reg q[4] = mux(en, q, d)     # en が 0 なら自分の値、1 なら d
step d=5, en=1     # 5 を書き込む
step d=9, en=0     # 書き込まない
step d=12
step d=7, en=1     # 7 を書き込む
step d=0, en=0
step
```

1 行目で書き込んだ 5 は、2 行目から q に出て、en が 0 の間はずっと 5 のままです。d が 9、12 と変わっても無視されます。4 行目で 7 を書き込むと、5 行目から 7 になります。

`reg q[4] = mux(en, q, d)` は、右辺に q 自身が出てくる帰還の回路です。D ラッチでは困った帰還も、D フリップフロップなら安全です。値が進むのは、立ち上がりの一瞬だけだからです。

第 10 章から使う RISC-V の CPU には、32 ビットのレジスタが 32 本あります（x0〜x31）。その 1 本 1 本が、この回路を 32 ビットに広げたものです。「x5 に書き込む」命令は、第 6 章のデコーダで 5 番のレジスタの en だけを 1 にします。

## カウンタ：数える回路 {#counter}

レジスタと加算器をつなぎます。レジスタの出力に 1 を足して、同じレジスタの入力に戻します。

`clock 18` は、入力を変えずに 18 周期ぶん進める書き方です。q は 0、1、2、… と、1 周期に 1 ずつ増えます。たった 1 行の回路が、**数を数えています**。

15 の次は 0 に戻ります。4 ビットの加算器は、あふれた繰り上がりを捨てるからです（第 5 章）。

### 止める、0 に戻す

カウンタに、操作するための入力を付けます。rst（リセット）が 1 の周期は、次の値を 0 にします。

```logic run title="リセット付きのカウンタ"
in rst
out q[4]
reg q[4] = mux(rst, q + 1, 0)     # rst が 1 なら 0、そうでなければ q + 1
clock 5
step rst=1
step rst=0
clock 3
```


カウンタは、コンピュータのあちこちで使われています。時間を測るタイマー、何回繰り返したかを数える回路、そして次の節のプログラムカウンタです。

## CPU の中の記憶 {#cpu}

この章で作った部品が、CPU のどこにあるかを見ておきましょう。

### プログラムカウンタ

CPU は、メモリに並んだ命令を、1 つずつ順に取り出して実行します（第 1 章のプログラム内蔵方式）。「いま何番地の命令を実行しているか」を覚えているレジスタが、**プログラムカウンタ**（PC）です。

RISC-V の命令は 1 つが 4 バイトなので、PC は 1 命令ごとに 4 ずつ進みます。つまり、**4 ずつ増えるカウンタ**です。ただし、分岐やジャンプの命令のときは、次の番地ではなく、指定された飛び先を PC に入れます。「どちらを入れるか」は、マルチプレクサで選びます。

```fig circuit プログラムカウンタ。ふだんは PC + 4 を、ジャンプのときは飛び先の番地を、次の立ち上がりで取り込む
{
  parts: [
    { id: 'add', type: 'box', x: 2, y: 1.5, w: 3, h: 2, label: '+4', ins: ['_a'], outs: ['_s'] },
    { id: 'm', type: 'mux', x: 8, y: 2 },
    { id: 'pc', type: 'box', x: 12, y: 2, w: 4, h: 3, label: 'PC', ins: ['d'], outs: ['q'], bottoms: ['clk'] },
    { id: 'target', type: 'in', x: 0, y: 4, label: '飛び先' },
    { id: 'jump', type: 'in', x: 9.5, y: 5.5, labelPos: 'bottom' },
    { id: 'clk', type: 'in', x: 14.5, y: 5.5, labelPos: 'bottom' },
    { id: 'out', type: 'out', x: 22, y: 2, label: '命令の番地' },
  ],
  wires: [
    'add -> m.in0', { from: 'target', to: 'm.in1', mid: 7 }, 'jump -> m.s', 'm -> pc.d', 'clk -> pc.clk',
    'pc.q -> out', { from: 'pc.q', to: 'add', via: [[19.5, 2], [19.5, -0.5], [1, -0.5]] },
  ],
  steps: [
    { title: 'jump = 0（次の命令へ）', hl: ['add', 'm'], vals: { jump: 0 }, say: 'マルチプレクサは PC + 4 を選びます。次の立ち上がりで、PC は 4 だけ進みます。' },
```

```logic run title="プログラムカウンタ"
in jump, target[8]
out pc[8]
reg pc[8] = mux(jump, pc + 4, target)
clock 4
step jump=1, target=40     # 40 番地へ飛ぶ
step jump=0
clock 2
```

pc は 0、4、8、12、16 と進み、jump を 1 にした次の周期に 40 へ飛びます。その後は 44、48 と、また 4 ずつ進みます。第 11 章の分岐とループは、この「PC に別の値を入れる」ことで実現されています。

### レジスタと ALU をつなぐ

もう 1 つ、レジスタと加算器の組み合わせを見ます。入力 x を、レジスタの値に足し込んでいく回路です。

```logic run title="足し込んでいく回路"
in x[8]
out acc[8]
reg acc[8] = acc + x
step x=5
step x=10
step x=20
step x=0
step
```

acc は 0、5、15、35 と、入力の合計になっていきます。前の章までの加算器は、入力がなくなれば答えも消えました。レジスタと組み合わせると、**前の計算の結果を、次の計算に使える**ようになります。

これが、CPU の動きの基本の形です。

1. レジスタから値を読む
2. ALU（組み合わせ回路）で計算する
3. クロックの立ち上がりで、結果をレジスタに書く

1 周期ごとにこれを繰り返して、計算を 1 歩ずつ進めます。記憶のある回路を、組み合わせ回路に対して**順序回路**と呼びます。CPU は、巨大な順序回路です。

:::deep メモリも同じ仕組みか
レジスタは速いのですが、1 ビットに D フリップフロップ 1 個（トランジスタ 20 個ほど）を使うので、大量に並べるには大きすぎます。そこで、何億ビットも覚えるメモリには、もっと小さな作りが使われます。キャッシュに使われる SRAM は、NOT を 2 個たすき掛けにした輪（SR ラッチの仲間）に出入口を付けた、トランジスタ 6 個の回路で 1 ビットを覚えます。主記憶に使われる DRAM は、トランジスタ 1 個と、電気をためる小さな部品 1 個です。小さいほどたくさん並べられますが、読み書きは遅くなります。この速さと大きさの取り引きが、第 18 章のキャッシュの話につながります。
:::

:::try やってみよう
下は、en が 1 の間だけ数えるカウンタです。

1. 実行して、en が 0 の周期には q が止まっていることを確かめる
2. `q + 1` を `q - 1` に変えて、逆向きに数えるカウンタにする。0 の次がいくつになるかを見る
3. `q + 1` を `q + 3` に変える。15 を超えたときの値を、第 5 章の桁あふれで説明する
4. 入力 `rst` を足して、`rst` が 1 なら 0 に戻るようにする（マルチプレクサを 2 段にします）
:::

```logic run title="練習用：止められるカウンタ"
in en
out q[4]
reg q[4] = mux(en, q, q + 1)
step en=1
clock 4
step en=0
clock 2
step en=1
clock 3
```

:::key この章のまとめ
- いまの入力だけで出力が決まる回路が**組み合わせ回路**。出力を入力に戻す（**帰還**）と、回路は値を覚えられる
- **SR ラッチ**は、2 個の NOR のたすき掛け。セット、リセット、保持ができる。最初の値は決まっていない。s と r を同時に 1 にしてはいけない
- **D ラッチ**は、en が 1 の間だけ d を通し、0 になるとその値を覚える。開いている間は筒抜けになる
- **クロック**は全体の拍子。0 から 1 への**立ち上がり**の瞬間に、すべての記憶がいっせいに値を取り込む
- **D フリップフロップ**は、立ち上がりの瞬間だけ d を取り込む。D ラッチ 2 個で作れる。回路記述では `reg`
- D フリップフロップを並べたものが**レジスタ**。マルチプレクサを付けると、合図があるときだけ書き込める
- レジスタ + 加算器で**カウンタ**。CPU の**プログラムカウンタ**は、4 ずつ増え、ジャンプのときは飛び先を取り込むカウンタ
- CPU は「レジスタから読む → 組み合わせ回路で計算する → 立ち上がりでレジスタに書く」を繰り返す**順序回路**
:::

## 確認問題 {#quiz}

この章の内容を、自分で回路を書いて確かめます。記憶のある回路の答え合わせでは、模範解答と同じ順番で入力を与えて、タイミング表の出力を比べます。入力の与え方は自動で決まるので、あなたの回路に `step` や `clock` を書く必要はありません（書いても無視されます）。

:::quiz NAND で作る SR ラッチ
1 ビットの入力 `ns`、`nr` と、1 ビットの出力 `q`、`nq` を持つ、NAND 2 個の SR ラッチを書いてください。NOR の SR ラッチとは、入力の 0 と 1 の意味が逆になります。

- `ns` が 0（`nr` は 1）なら、セット：`q` = 1、`nq` = 0
- `nr` が 0（`ns` は 1）なら、リセット：`q` = 0、`nq` = 1
- `ns` も `nr` も 1 なら、前の状態を保持

使ってよいゲートは `nand` だけです。`reg` は使えません。答え合わせは、セット → 保持 → リセット → 保持 → セット → 保持の順に入力を与えて行います。

```logic answer only="nand" maxgates="2"
in ns, nr
out q, nq
q  = ns nand nq
nq = nr nand q
step ns=0, nr=1
step ns=1
step nr=0
step nr=1
step ns=0
step ns=1
```

```logic starter
in ns, nr
out q, nq
q  = 
nq = 
```

:::hint
本文の SR ラッチの `nor` を `nand` に置き換えた形です。NAND は「入力のどちらかが 0 なら 1 を出す」ゲートなので、`ns` を 0 にすると、それを受ける NAND が 1 を出します。その NAND の出力が `q` になるようにつなぎます。
:::
:::

:::quiz 合図のたびにひっくり返る回路
1 ビットの入力 `t` と、1 ビットの出力 `q` を持つ回路を、`reg` を使って書いてください。`q` は最初 0 です。クロックの立ち上がりのとき、`t` が 1 なら `q` をひっくり返し（0 なら 1、1 なら 0）、`t` が 0 なら `q` をそのままにします。

```logic answer
in t
out q
reg q = q xor t
step t=1
step t=1
step t=0
step t=0
step t=1
step t=0
step t=1
step t=1
step
```

```logic starter
in t
out q
reg q = 
```

:::hint
XOR は「条件付きの反転」でした（第 4 章）。`q xor t` は、t が 0 なら q のまま、t が 1 なら q の反転です。これを次の値として `reg` に取り込みます。マルチプレクサで `mux(t, q, not q)` と書いても同じです。
:::
:::

:::quiz シフトレジスタ
1 ビットの入力 `d` と、4 ビットの出力 `q`（`out q[4]`）を持つ回路を、`reg` を使って書いてください。`q` は最初 0 です。クロックの立ち上がりのたびに、`q` の中身を 1 ビット上の桁へずらし、空いたいちばん下の桁（`q[0]`）に `d` を入れます。いちばん上の桁からあふれたビットは捨てます。

たとえば `d` に 1、0、1、1 と順に入れると、`q` は 2 進数で `0001`、`0010`、`0101`、`1011` と変わります。

```logic answer

out q[4]
reg q[4] = {q[2:0], d}
step d=1
step d=0
step d=1
step d=1
step d=0
step d=0
step d=1
step d=0
step
```

```logic starter
in d
out q[4]
reg q[4] = 
```

:::hint
次の値は、いまの `q` の下 3 ビット（`q[2:0]`）を上に、`d` をいちばん下に置いた 4 ビットです。バスの連結 `{上, 下}` を使います。
:::
:::

:::quiz 0 から 9 まで数えるカウンタ
1 ビットの入力 `en` と、4 ビットの出力 `q`（`out q[4]`）を持つ回路を、`reg` を使って書いてください。`q` は最初 0 です。

- `en` が 1 の周期は、次の値を `q` + 1 にする。ただし `q` が 9 のときは、次の値を 0 にする
- `en` が 0 の周期は、`q` を変えない

`q` は 0、1、2、…、9、0、1、… と、10 進数の 1 桁のように数えます。

```logic answer

out q[4]
next = mux(q == 9, q + 1, 0)
reg q[4] = mux(en, q, next)
step en=1
clock 8
step en=0
clock 1
step en=1
clock 4
step en=0
clock 1
step en=1
clock 2
```

```logic starter
in en
out q[4]
reg q[4] = 
```

:::hint
マルチプレクサを 2 段にします。内側で「9 なら 0、そうでなければ q + 1」を選び、外側で「en が 1 ならその値、0 なら q」を選びます。「9 と等しい」は `q == 9` と書けます。
:::
:::
