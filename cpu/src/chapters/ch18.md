## CPU は速く、メモリは遅い {#gap}

第 16 章と第 17 章では、データメモリを「番地を入れると、すぐに値が出てくる箱」として扱いました。本物のコンピュータでは、ここに大きな問題があります。**メモリは、CPU に比べてとても遅い**のです。

CPU の中の ALU は、1 サイクルで足し算を終えます。ところが、主記憶（DRAM と呼ばれるメモリの部品）から値を 1 つ読むには、おおよそ 100 サイクルから数百サイクルかかります。`lw` のたびにそれだけ待っていたら、パイプラインの工夫は台なしです。

メモリは、大きく作るほど遅くなります。番地を選ぶ回路（第 6 章のデコーダ）が大きくなり、信号が届く距離も長くなるからです。逆に、小さく作れば速くできます。そこで、**小さくて速いメモリ**を CPU のすぐそばに置き、よく使うデータの写しを入れておきます。これが**キャッシュ**（cache、隠し場所）です。

```fig graph CPU は、まずキャッシュを見る。そこにあれば（ヒット）すぐ返る。なければ（ミス）主記憶まで取りに行き、写しをキャッシュに置く
{
  col: 250, row: 100,
  nodes: [
    { id: 'cpu', label: 'CPU', sub: 'lw / sw を実行する', x: 0, y: 0, kind: 'accent' },
    { id: 'cache', label: 'キャッシュ', sub: '小さくて速い', x: 1, y: 0, kind: 'stack' },
    { id: 'mem', label: '主記憶（DRAM）', sub: '大きくて遅い', x: 2, y: 0, kind: 'ext' },

  ],

```

探している番地のデータがキャッシュにあることを**ヒット**、ないことを**ミス**と呼びます。ミスのときは、主記憶から読み込む間、CPU は待たされます。この待ち時間が**ミスペナルティ**です。

このサイトのエミュレータは、キャッシュの動きを計測できます。フェンスに `cache="容量,ブロック,連想度"` と書くと、`lw` や `sw` が RAM を読み書きするたびに、ヒットかミスかを数えます。3 つの数字の意味は、この章で順に説明します。まずは動かしてみましょう。

```asm run cache="256,16,1" title="64 個の数を順に読む"
.data
arr: .space 256           # 4 バイトの数が 64 個
.text
la   s0, arr
addi s1, s0, 256
li   a0, 0
loop:
lw   t0, 0(s0)
add  a0, a0, t0
addi s0, s0, 4
bne  s0, s1, loop
```

メモリへのアクセスは 64 回で、ヒットが 48 回、ミスが 16 回です。**ヒット率**（ヒットの割合）は 75% です。

このモデルでは、ミス 1 回につき 10 サイクルを足します。パイプラインを使わない計測では 1 命令を 1 サイクルと数えるので、命令数 260 に、16 × 10 = 160 を足して、420 サイクルです。

:::note このサイトのキャッシュのモデル
数えるのは、データの読み書き（`lw`、`sw` など）だけです。命令の取り出しと、画面やコンソールへの入出力は数えません。本物の CPU は、命令用とデータ用のキャッシュを別々に持っています。ミスペナルティの 10 サイクルは、仮に決めた値です。
:::

## 局所性：近くと最近は、また使われる {#locality}

小さなキャッシュに、メモリのごく一部しか入らないのに、なぜ 75% も当たるのでしょうか。それは、プログラムのメモリの使い方に、強い偏りがあるからです。この偏りを**局所性**（locality）と呼びます。

- **空間的局所性**：ある番地を使ったら、その**近くの番地**もすぐに使う。配列を先頭から順にたどるのが典型です
- **時間的局所性**：ある番地を使ったら、**同じ番地**を近いうちにまた使う。ループの中の変数や、カウンタが典型です

時間的局所性から確かめます。1 つの変数を、100 回読んで 100 回書きます。

```asm run cache="256,16,1" title="同じ変数を 100 回読み書きする"
.data
n:   .word 0
.text
la   s0, n
li   t1, 100
loop:
lw   t0, 0(s0)
addi t0, t0, 1
sw   t0, 0(s0)
addi t1, t1, -1
bnez t1, loop
```

アクセスは 200 回で、ミスは最初の 1 回だけです。ヒット率は 99.5% になります。1 度キャッシュに入った番地は、追い出されるまで、何度使ってもヒットします。

配列を 2 周読む場合も同じです。256 バイトの配列は、256 バイトのキャッシュにちょうど収まります。1 周目で入ったデータが、2 周目ではすべてヒットします。

```asm run cache="256,16,1" title="同じ配列を 2 周読む"
.data
arr: .space 256
.text
li   s2, 2                # 2 周
pass:
la   s0, arr
addi s1, s0, 256
loop:
lw   t0, 0(s0)
addi s0, s0, 4
bne  s0, s1, loop
addi s2, s2, -1
bnez s2, pass
```

128 回のアクセスのうち、ミスは 1 周目の 16 回だけです。ヒット率は 87.5% に上がります。`.space 256` を `.space 512` に、`addi s1, s0, 256` を `addi s1, s0, 512` に変えると、配列がキャッシュに収まらなくなります。2 周目もミスが出て、ヒット率は 75% に戻ります。

## ブロック：近くの番地をまとめて運ぶ {#block}

最初の例に戻ります。64 個の数は、どれも初めて読む番地でした。それなのに 48 回もヒットしたのは、キャッシュが空間的局所性を当てにして、**近くの番地をまとめて読み込む**からです。

キャッシュは、メモリを決まった大きさの**ブロック**（キャッシュラインとも言う）に区切って扱います。`cache="256,16,1"` の 2 つ目の数字が、ブロックの大きさです。16 バイト、つまり 4 バイトの数が 4 個ぶんです。ある番地でミスすると、その番地を含むブロックを丸ごと読み込みます。

```fig layout 0x8000 を読んでミスすると、0x8000 〜 0x800F の 16 バイト（4 個の数）がまとめてキャッシュに入る。続く 3 個はヒットする。次のブロックの先頭で、またミスする
{

  rows: [
    { label: '番地', cells: [{ t: '0x8000', kind: 'empty' }, { t: '0x8004', kind: 'empty' }, { t: '0x8008', kind: 'empty' }, { t: '0x800C', kind: 'empty' }, { t: '0x8010', kind: 'empty' }, { t: '0x8014', kind: 'empty' }, { t: '0x8018', kind: 'empty' }, { t: '0x801C', kind: 'empty' }] },
    { label: 'ブロック', cells: [{ t: 'ブロック 0x8000', w: 4, kind: 'stack' }, { t: 'ブロック 0x8010', w: 4, kind: 'heap' }] },
    { label: '順に読むと', cells: [{ t: 'ミス', kind: 'accent' }, { t: 'ヒット' }, { t: 'ヒット' }, { t: 'ヒット' }, { t: 'ミス', kind: 'accent' }, { t: 'ヒット' }, { t: 'ヒット' }, { t: 'ヒット' }] },
  ],
}
```

4 回に 1 回だけミスするので、ヒット率は 75% です。計測の結果と合っています。

では、近くの番地を使わなかったら、どうなるでしょうか。同じ 64 回の `lw` を、**16 バイトおき**に行います。

```asm run cache="256,16,1" title="16 バイトおきに 64 個読む"
.data
arr: .space 1024
.text
la   s0, arr
addi s1, s0, 1024
li   a0, 0
loop:
lw   t0, 0(s0)
add  a0, a0, t0
addi s0, s0, 16           # 16 バイト先へ
bne  s0, s1, loop
```

ヒットは 0 回です。毎回、新しいブロックの先頭を読むからです。実行する命令数は最初の例と同じ 260 ですが、サイクル数は 260 + 64 × 10 = 900 になります。420 サイクルの 2 倍以上です。**読む回数が同じでも、読む場所の散らばり方で速さが変わります**。

ブロックの大きさを変えると、結果も変わります。最初の例（4 バイトおきに 64 個）で試した結果です。

| 設定 | ブロック | ミス | ヒット率 |
| --- | --- | --- | --- |
| `cache="256,4,1"` | 4 バイト（数 1 個） | 64 | 0% |
| `cache="256,16,1"` | 16 バイト（数 4 個） | 16 | 75% |
| `cache="256,64,1"` | 64 バイト（数 16 個） | 4 | 93.8% |

ブロックが大きいほど、順にたどるときのミスは減ります。ただし、容量が同じなら、ブロックを大きくするほど入るブロックの数は減ります。あちこちの番地を使うプログラムでは、かえって不利になります。本物の CPU では、64 バイトのブロックがよく使われています。

## ダイレクトマップ：番地で置き場所が決まる {#direct}

キャッシュは小さいので、メモリのすべてのブロックは入りません。「このブロックは、キャッシュのどこに置くか」を決める規則が必要です。

一番単純な規則が**ダイレクトマップ**（direct-mapped）です。ブロックごとに、置き場所が 1 か所に決まっています。置き場所は、番地のビットをそのまま使って決めます。`cache="256,16,1"` の最後の 1 が、ダイレクトマップの意味です。

容量 256 バイトをブロック 16 バイトで割ると、16 です。このキャッシュには、ブロックの置き場所が 16 個あります。置き場所には 0 〜 15 の番号を付け、これを**セット**と呼びます。番地は、次の 3 つに分けて使います。

```fig layout 32 ビットの番地を 3 つに分ける（容量 256 バイト、ブロック 16 バイト、ダイレクトマップの場合）。下の行は、番地 0x00008124 の例
{
  unit: 22,
  rows: [
    { label: '役割', cells: [{ t: 'タグ（24 ビット）', w: 14, kind: 'stack' }, { t: 'インデックス（4）', w: 6, kind: 'accent' }, { t: 'オフセット（4）', w: 6, kind: 'heap' }] },
    { label: '0x00008124', cells: [{ t: '0x000081', w: 14, kind: 'stack' }, { t: '0x2', w: 6, kind: 'accent' }, { t: '0x4', w: 6, kind: 'heap' }] },
  ],
}
```

| 部分 | ビット | 意味 |
| --- | --- | --- |
| オフセット | 下位 4 ビット | ブロックの中の何バイト目か（16 バイトなので 4 ビット） |
| インデックス | 次の 4 ビット | どのセットに置くか（16 セットなので 4 ビット） |
| タグ | 残りの 24 ビット | そのセットに、いまどのブロックが入っているかを見分ける札 |

この設定では、16 進数の 1 桁がちょうど 4 ビットなので、番地を 16 進で書けばそのまま読めます。`0x8124` なら、一番下の桁の 4 がオフセット、次の桁の 2 がインデックス、残りの `0x81` がタグです。

キャッシュの各セットには、データのほかに、**有効ビット**（何か入っているか）と**タグ**を覚えておきます。`lw` が来たら、次の順で調べます。

1. 番地のインデックスで、セットを 1 つ選ぶ
2. そのセットが有効で、タグが番地のタグと同じなら、ヒット
3. 違えばミス。主記憶からブロックを読み込み、タグを書き換える。前に入っていたブロックは追い出される

比べるタグは 1 つだけです。第 6 章の比較の回路が 1 つと、マルチプレクサがあれば作れます。単純で速いのが、ダイレクトマップの長所です。

## ヒットとミスを 1 つずつ追う {#trace}

```asm run cache="256,16,1" title="8 回のアクセス"
lw   t0, 36(s0)           # 0x8024
```

## 衝突ミス：空きがあるのに追い出される {#conflict}

この奪い合いが、ループの中で起きると悲惨です。2 つの配列 `a` と `b` を、先頭から順に 1 個ずつ読んで、全部を合計します。`a` と `b` は、ちょうど 256 バイト離して置きます。

```asm run cache="256,16,1" title="256 バイト離れた 2 つの配列を交互に読む"
.data
a:   .space 64            # 0x8000 から
     .space 192           # すき間
b:   .space 64            # 0x8100 から（a のちょうど 256 バイト先）
.text
la   s0, a
la   s1, b
li   t2, 16
li   a0, 0
loop:
lw   t0, 0(s0)            # a[i]
lw   t1, 0(s1)            # b[i]
add  a0, a0, t0
add  a0, a0, t1
addi s0, s0, 4
addi s1, s1, 4
addi t2, t2, -1
bnez t2, loop
```

32 回のアクセスが、**すべてミス**です。ヒット率は 0% です。`a[i]` を読むと `b` のブロックが追い出され、`b[i]` を読むと `a` のブロックが追い出されます。どちらの配列も、順にたどっているのに、です。

```fig graph a と b の同じ位置のブロックは、インデックスが同じなので、同じセットに行く。ダイレクトマップでは 1 つしか置けないので、交互に読むと追い出し合う
{
  col: 250, row: 84,
  nodes: [
    { id: 'a', label: 'a のブロック 0x8000', sub: 'タグ 0x80、インデックス 0', x: 0, y: 0, kind: 'stack' },
    { id: 'b', label: 'b のブロック 0x8100', sub: 'タグ 0x81、インデックス 0', x: 0, y: 1, kind: 'heap' },
    { id: 's0', label: 'セット 0', sub: '置けるのは 1 つだけ', x: 1, y: 0.5, kind: 'accent' },
    { id: 's1', label: 'セット 1 〜 15', sub: '空いているのに使われない', x: 2, y: 0.5, kind: 'muted' },
  ],

    { from: 'a', to: 's0', style: 'accent' },
    { from: 'b', to: 's0', style: 'accent' },
  ],

```

このように、キャッシュに空きがあるのに、置き場所がぶつかって起きるミスを**衝突ミス**（コンフリクトミス）と呼びます。

直し方の 1 つは、配列の置き場所をずらすことです。すき間を 16 バイト増やして、`b` を `0x8110` から始めます。上のブロックの `.space 192` を `.space 208` に書き換えて、実行してみてください。`a[i]` と `b[i]` のインデックスが 1 つずれて、ぶつからなくなります。ミスは 8 回に減り、ヒット率は 75% になります。**データの置き場所を 16 バイトずらしただけで、サイクル数は 454 から 214 に減ります**。

## セットアソシアティブと LRU {#assoc}

置き場所をずらすのは、プログラムを書く側の工夫です。キャッシュの側でも、衝突を減らす工夫ができます。**1 つのセットに、複数のブロックを置けるようにする**のです。

これを**セットアソシアティブ**（set-associative）と呼びます。1 セットに置けるブロックの数が**連想度**で、「2 ウェイ」「4 ウェイ」のように言います。`cache="256,16,2"` の最後の 2 が連想度です。容量が同じ 256 バイトなら、2 ウェイではセットの数が半分の 8 個になります。

```fig layout 容量が同じ 256 バイト（16 ブロック）でも、分け方が違う。ダイレクトマップは 16 セット × 1、2 ウェイは 8 セット × 2。同じセットに来た 2 つのブロックを、両方置ける
{
  unit: 30,
  rows: [
    { label: 'ダイレクトマップ', cells: [{ t: 'セット 0', w: 3, kind: 'accent' }, { t: 'セット 1', w: 3 }, { t: 'セット 2', w: 3 }, { t: '…', w: 2, kind: 'empty' }, { t: 'セット 15', w: 3 }], note: '1 セットに 1 ブロック' },
    { label: '2 ウェイ：ウェイ 0', cells: [{ t: 'セット 0', w: 3, kind: 'accent' }, { t: 'セット 1', w: 3 }, { t: 'セット 2', w: 3 }, { t: '…', w: 2, kind: 'empty' }, { t: 'セット 7', w: 3 }], note: '1 セットに 2 ブロック' },
    { label: '2 ウェイ：ウェイ 1', cells: [{ t: 'セット 0', w: 3, kind: 'accent' }, { t: 'セット 1', w: 3 }, { t: 'セット 2', w: 3 }, { t: '…', w: 2, kind: 'empty' }, { t: 'セット 7', w: 3 }] },
  ],
}
```

さっきの 2 つの配列を、2 ウェイのキャッシュで読みます。プログラムは同じです。

```asm run cache="256,16,2" title="同じプログラムを 2 ウェイのキャッシュで"
.data
a:   .space 64
     .space 192
b:   .space 64
.text
la   s0, a
la   s1, b
li   t2, 16
li   a0, 0
loop:
lw   t0, 0(s0)
lw   t1, 0(s1)
add  a0, a0, t0
add  a0, a0, t1
addi s0, s0, 4
addi s1, s1, 4
addi t2, t2, -1
bnez t2, loop
```

ミスは 8 回、ヒット率は 75% です。`a` のブロックと `b` のブロックが、同じセットの 2 つのウェイに並んで入るからです。

### どれを追い出すか：LRU

1 つのセットに 2 つ置けるようになると、新しい問題が出てきます。セットがいっぱいのときに 3 つ目のブロックが来たら、**どちらを追い出すか**です。

よく使われる規則が **LRU**（Least Recently Used）です。「一番長い間使われていないものを追い出す」という意味です。時間的局所性を信じて、最近使ったものは、また使うだろうと考えます。

```asm run cache="256,16,2" title="同じセットに 3 つのブロックが来る"
li   s0, 0x8000
lw   t0, 0(s0)            # A：ミス
lw   t0, 0x100(s0)        # B：ミス
lw   t0, 0(s0)            # A：ヒット
lw   t0, 0x200(s0)        # C：ミス。A と B のどちらを追い出す？
lw   t0, 0(s0)            # A：？
lw   t0, 0x100(s0)        # B：？
```

A、B、C の 3 つのブロックは、どれもセット 0 に行きます。C が来たとき、セットには A と B が入っています。最後に使ったのは A なので、LRU は **B を追い出します**。そのため、次の A はヒットし、その次の B はミスします。結果は、ヒット 2 回、ミス 4 回です。フェンスを `cache="256,16,1"` に変えると、6 回ともミスになります。

連想度を上げるほど衝突は減りますが、回路は大きく、遅くなります。1 つのセットの中の全部のタグを、同時に比べなければならないからです。本物の CPU では、4 ウェイから 16 ウェイほどがよく使われています。

## 行列をたどる順番で、速さが変わる {#matrix}

ここまでの知識で、有名な現象を確かめられます。**行列を行の順にたどるか、列の順にたどるかで、速さが変わる**という現象です。

8 行 8 列の行列を、メモリに置きます。メモリは 1 列に並んだ番地なので、行列は 1 行目、2 行目、…の順に並べて置きます（第 12 章）。1 行は 8 個 × 4 バイトで 32 バイト、全体で 256 バイトです。

| --- | --- | --- | --- | --- | --- |

サイクル数は 2.2 倍違います。命令数の差はわずかで、差のほとんどはミスペナルティです。

このモデルのミスペナルティは 10 サイクルですが、本物の主記憶はもっと遅いのでした。4 つ目の数字でミスペナルティを変えられます。`cache="64,16,1,100"` として 100 サイクルにすると、行の順は 1,862 サイクル、列の順は 6,694 サイクルで、差は 3.6 倍に広がります。

連想度を上げても、この差は埋まりません。`cache="64,16,2"` でも `cache="64,16,4"` でも、列の順のヒット率は 0% のままです。1 列を下りる間に 8 つのブロックに触るのに、キャッシュには 4 つしか入らないからです。効くのは、容量を増やすか（`cache="256,16,1"` なら、列の順でも 75%）、**たどる順番を変える**かです。後者なら、プログラムを書く人が、今すぐできます。

## メモリ階層：速さと大きさの段々 {#hierarchy}

本物のコンピュータは、キャッシュを 1 つではなく、何段も重ねています。CPU に近いほど小さくて速く、遠いほど大きくて遅い。この並びを**メモリ階層**と呼びます。

```fig layout メモリ階層。上ほど CPU に近く、小さくて速い。下ほど大きくて遅い。数字はおおよその目安で、CPU によって大きく違う

  rows: [
    { label: 'レジスタ', cells: [{ t: '32 本', w: 3, kind: 'accent' }], note: '同じサイクルの中で読める' },
    { label: 'L1 キャッシュ', cells: [{ t: '数十 KB', w: 5, kind: 'stack' }], note: '数サイクル' },
    { label: 'L2 キャッシュ', cells: [{ t: '数百 KB 〜 数 MB', w: 8, kind: 'stack' }], note: '十数サイクル' },
    { label: 'L3 キャッシュ', cells: [{ t: '数 MB 〜 数十 MB', w: 11, kind: 'stack' }], note: '数十サイクル' },
    { label: '主記憶（DRAM）', cells: [{ t: '数 GB 〜 数十 GB', w: 14, kind: 'heap' }], note: '百 〜 数百サイクル' },
    { label: 'SSD', cells: [{ t: '数百 GB 〜', w: 17, kind: 'static' }], note: '数万サイクル以上。電源を切っても消えない' },
```

L1 でミスしたら L2 を、L2 でミスしたら L3 を、それでもなければ主記憶を見に行きます。局所性のおかげで、ほとんどのアクセスは L1 でヒットします。プログラムからは、「主記憶と同じ大きさで、ほとんどいつも L1 と同じ速さのメモリ」があるように見えます。

目安として、遅さを比べてみます。数字は CPU によって大きく違うので、桁の感じだけをつかんでください。

```fig bars データを 1 つ読むのにかかる時間のおおよその目安（サイクル）。主記憶は、L1 キャッシュの数十倍遅い
{
  unit: ' サイクル',
  items: [
    { label: 'L1 キャッシュ', value: 4, text: '約 4' },
    { label: 'L2 キャッシュ', value: 14, text: '約 14' },
    { label: 'L3 キャッシュ', value: 50, text: '約 50' },
    { label: '主記憶', value: 200, text: '約 200', hl: true },
  ],
}
```

このサイトのモデルと、本物の CPU の違いをまとめます。

| | このサイトのモデル | 今の CPU（おおよそ） |
| --- | --- | --- |
| キャッシュの段数 | 1 段 | L1、L2、L3 の 3 段が多い |
| 対象 | データの読み書きだけ | 命令とデータの両方（L1 は別々に持つ） |
| ブロック | 自由に設定（例では 16 バイト） | 64 バイトが多い |
| 連想度 | 自由に設定 | 4 〜 16 ウェイほど |
| ミスペナルティ | 10 サイクル（仮の値） | どの段でヒットするかで変わる |
| 先読み | しない | 順にたどっていると気づくと、先のブロックを先に読み込む |

大きさも段数も違いますが、番地をタグ・インデックス・オフセットに分ける仕組みと、局所性に頼るという考え方は同じです。「配列は順にたどる」「一緒に使うデータは近くに置く」という心がけは、本物の CPU でもそのまま効きます。

:::try やってみよう
1. 下のブロックは、16 バイトおきに並んだ 4 つの数を、10 周読みます。ダイレクトマップの 64 バイトのキャッシュでは、4 つのブロックが 4 つのセットにちょうど収まり、ミスは最初の 4 回だけです。まずこれを確かめましょう。
2. `addi s0, s0, 16` を `addi s0, s0, 64` に、`addi s1, s0, 64` を `addi s1, s0, 256` に変えると、4 つの数は 64 バイトおきになります。ヒット率がどうなるか、予想してから実行しましょう。
3. その状態で、フェンスを `cache="64,16,4"`（1 セットに 4 ブロック）に変えると、どうなるでしょうか。
:::

```asm run cache="64,16,1" title="練習：とびとびの 4 個を 10 周読む"
.data
arr: .space 256
.text
li   s2, 10               # 10 周
pass:
la   s0, arr
addi s1, s0, 64
loop:
lw   t0, 0(s0)
addi s0, s0, 16
bne  s0, s1, loop
addi s2, s2, -1
bnez s2, pass
```

:::key まとめ
- メモリは CPU よりずっと遅い。小さくて速い**キャッシュ**に、よく使うデータの写しを置く
- **局所性**：近くの番地はすぐ使われ（空間的）、同じ番地はまた使われる（時間的）。キャッシュはこの偏りに頼っている
- キャッシュは**ブロック**単位でデータを運ぶ。順にたどれば、ミスはブロックの先頭だけで済む
- **ダイレクトマップ**では、番地を**タグ・インデックス・オフセット**に分ける。インデックスでセットを選び、タグを比べてヒットかミスかを決める
- インデックスが同じブロックは追い出し合う（**衝突ミス**）。**セットアソシアティブ**は 1 セットに複数のブロックを置いて衝突を減らす。追い出す相手は **LRU** で決める
- 同じ計算でも、**メモリをたどる順番**でミスの数が変わり、速さが何倍も変わる。行列は、メモリに並んでいる順にたどる
- 本物のコンピュータは、レジスタ、L1、L2、L3、主記憶、SSD と、速さと大きさの違う記憶を何段も重ねている（**メモリ階層**）
:::

:::quiz 番地を 3 つに分ける

```asm answer
    ret
```

:::quiz ダイレクトマップのキャッシュを作る
関数 `hits` を書いてください。引数は `a0` = 番地が並んだ配列（1 個 4 バイト）の番地、`a1` = 個数です。容量 64 バイト、ブロック 16 バイト、ダイレクトマップ（4 セット）のキャッシュに、この順でアクセスしたときの**ヒットの回数**を `a0` に入れて返します。

各セットのタグを覚えておく場所として、4 ワードの配列 `tags` を用意してあります。初期値はすべて -1 で、「空」を表します。このキャッシュでは、インデックスは番地のビット 5 〜 4、タグは番地を右に 6 ビットずらした値です。`main` が 13 個の番地で 1 回呼び出し、結果を表示します。


:::hint
1 つの番地について、「インデックスとタグを求める → `tags` のその場所と比べる → 同じならヒットを数える、違えばタグを書き込む」を行います。ミスしたときにタグを書き換えるのを忘れると、追い出しが起きません。
:::
:::

:::quiz LRU で追い出す
関数 `lru` を書いてください。引数は `a0` = ブロックの番号（0 以上の数、1 個 4 バイト）が並んだ配列の番地、`a1` = 個数です。**ブロックを 2 つまで置ける 1 つのセット**に、この順でアクセスしたときの**ヒットの回数**を `a0` に入れて返します。セットは最初は空です。いっぱいのときにミスしたら、LRU に従って、一番長い間使われていないほうを追い出します。`main` が 10 個の番号で 1 回呼び出し、結果を表示します。

```asm answer
lru:
    li   t0, 0                # ヒットの回数
    li   t1, -1               # 最近使ったほう
    li   t2, -1               # 古いほう
l_loop:
    beqz a1, l_done
    lw   t3, 0(a0)
    beq  t3, t1, l_hit        # 最近使ったほうに当たり：順番はそのまま
    bne  t3, t2, l_miss
    addi t0, t0, 1            # 古いほうに当たり：順番を入れ替える
    mv   t2, t1
    mv   t1, t3
    j    l_next
l_hit:
    addi t0, t0, 1
    j    l_next
l_miss:
    mv   t2, t1               # 古いほうを追い出す
    mv   t1, t3
l_next:
    addi a0, a0, 4
    addi a1, a1, -1
    j    l_loop
l_done:
    mv   a0, t0
    ret
```

```asm given
main:
    la   a0, blocks
    li   a1, 10
    call lru
    li   a7, 1
    ecall
    li   a7, 10
    ecall
.data
blocks: .word 1, 2, 1, 3, 1, 2, 3, 3, 2, 1
```

```asm starter
lru:
    # a0 = ブロック番号の配列、a1 = 個数
    ret
```

:::hint
レジスタを 2 つ使い、「最近使ったほう」と「古いほう」のブロック番号を覚えます。最初はどちらも -1（空）にします。古いほうに当たったときは、ヒットを数えたうえで、2 つを入れ替えます。ミスしたときは、古いほうを捨てて、新しい番号を「最近使ったほう」にします。
:::
:::
