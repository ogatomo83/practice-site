絵を描き、ゲームを動かす

15.1点を打つ関数 plot

第 14 章で、画面は 0x10000 番地から始まる 1,024 バイトの配列だと分かりました。(x, y) のピクセルの番地は 0x10000 + y × 32 + x です。

絵を描くたびにこの計算を書くのは大変なので、最初に関数にしておきます。名前は plot（点を打つ）です。この章の絵は、すべてこの考え方の積み重ねでできています。

plot で点を打つ⌘↵
.equ SCREEN, 0x10000main:    addi sp, sp, -16    sw   ra, 12(sp)    li   a0, 10         # x    li   a1, 8          # y    li   a2, 5          # 色（黄）    call plot    li   a0, 20    li   a1, 8    li   a2, 5    call plot    li   a0, 15    li   a1, 14    li   a2, 2          # 赤    call plot    li   a0, 40         # 画面の外。plot が何もしないで戻る    li   a1, 8    li   a2, 1    call plot    lw   ra, 12(sp)    addi sp, sp, 16    ret# plot(a0 = x, a1 = y, a2 = 色)：(x, y) に点を打つ。画面の外なら何もしないplot:    li   t0, 32    bgeu a0, t0, plot_done   # x が 0〜31 でなければ戻る    bgeu a1, t0, plot_done   # y も同じ    slli t1, a1, 5      # y × 32    add  t1, t1, a0     # + x    li   t0, SCREEN    add  t1, t1, t0    sb   a2, 0(t1)plot_done:    ret

黄色い点が 2 つと、赤い点が 1 つ出ます。4 回目の plot は x が 40 なので、何も描きません。

範囲の確認に bgeu（符号なしで比べて、以上なら分岐）を使っているのが工夫です。負の数は、符号なしで見るととても大きな数になります（第 3 章）。そのため、「0 未満」と「32 以上」の両方を、1 回の比較で弾けます。

この確認がないと、x = 40 の点は、1 つ下の行の x = 8 に出てしまいます。番地の計算が、行の境目を越えてしまうからです。

ループで点を並べる

関数にしたので、ループの中から何度でも呼べます。i を 0 から 31 まで進めながら、(i, i) と (31 − i, i) に点を打つと、ばつ印になります。

plot を繰り返して、ばつ印を描く⌘↵
.equ SCREEN, 0x10000main:    addi sp, sp, -16    sw   ra, 12(sp)    sw   s0, 8(sp)    li   s0, 0          # i（plot を呼んでも残るように、s0 に置く）cross:    mv   a0, s0         # (i, i)    mv   a1, s0    li   a2, 4          # 青    call plot    li   a0, 31         # (31 - i, i)    sub  a0, a0, s0    mv   a1, s0    li   a2, 8          # 橙    call plot    addi s0, s0, 1    li   t0, 32    blt  s0, t0, cross    lw   ra, 12(sp)    lw   s0, 8(sp)    addi sp, sp, 16    ret# plot(a0 = x, a1 = y, a2 = 色)plot:    li   t0, 32    bgeu a0, t0, plot_done    bgeu a1, t0, plot_done    slli t1, a1, 5    add  t1, t1, a0    li   t0, SCREEN    add  t1, t1, t0    sb   a2, 0(t1)plot_done:    ret

ループの番号 i を s0 に置いている点を見てください。plot は t0 と t1 を使います。t のレジスタに置いた値は、関数を呼ぶと壊れるかもしれないのでした（第 13 章）。

15.2線を引く

点を並べると線になります。まず、簡単な横線と縦線から始めます。

横線と縦線

横に隣のピクセルは番地が 1 大きく、縦に隣のピクセルは番地が 32 大きいのでした。最初の番地だけ計算して、あとはポインタを進めます。

横線と縦線で十字を描く⌘↵
.equ SCREEN, 0x10000main:    addi sp, sp, -16    sw   ra, 12(sp)    li   a0, 4          # (4, 16) から右へ 24 個    li   a1, 16    li   a2, 24    li   a3, 6          # 水色    call hline    li   a0, 16         # (16, 4) から下へ 24 個    li   a1, 4    li   a2, 24    li   a3, 7          # 桃    call vline    lw   ra, 12(sp)    addi sp, sp, 16    ret# hline(a0 = x, a1 = y, a2 = 長さ, a3 = 色)：右へ向かう横線hline:    li   t0, SCREEN    slli t1, a1, 5    add  t0, t0, t1    add  t0, t0, a0     # t0 = 最初のピクセルの番地hline_loop:    sb   a3, 0(t0)    addi t0, t0, 1      # 右隣へ    addi a2, a2, -1    bnez a2, hline_loop    ret# vline(a0 = x, a1 = y, a2 = 長さ, a3 = 色)：下へ向かう縦線vline:    li   t0, SCREEN    slli t1, a1, 5    add  t0, t0, t1    add  t0, t0, a0vline_loop:    sb   a3, 0(t0)    addi t0, t0, 32     # 真下へ    addi a2, a2, -1    bnez a2, vline_loop    ret

2 つの関数の違いは、ポインタに足す数が 1 か 32 か、だけです。

斜めの線：ずれをためて、たまったら 1 段進む

斜めの線は少し考える必要があります。(0, 0) から (31, 12) へ線を引くとしましょう。x が 31 進む間に、y は 12 進みます。x が 1 進むごとに、y は 12/31（約 0.39）ずつ進む計算です。

ところが、ピクセルに 0.39 個という場所はありません。このサイトの CPU には、小数の計算もありません。そこで、整数だけで小数のふりをする方法を使います。

手順は次のとおりです。横の長さを dx（= 31）、縦の長さを dy（= 12）とします。

  1. 点を打つ。x を 1 進める
  2. 「ずれ」に dy を足す。本当の線が、いまの行からどれだけ下に離れたかを表す
  3. ずれが dx の半分を超えたら、y を 1 進めて、ずれから dx を引く

「12/31 を足して、0.5 を超えたら 1 行進む」という計算を、全体を 31 倍して整数にしたものです。

ゆるい斜めの線を引く⌘↵
.equ SCREEN, 0x10000    li   s0, SCREEN    li   t0, 0          # x    li   t1, 0          # y    li   t2, 31         # dx    li   t3, 12         # dy    li   t4, 0          # ずれloop:    slli t5, t1, 5      # 点を打つ    add  t5, t5, t0    add  t5, t5, s0    li   t6, 1    sb   t6, 0(t5)    beq  t0, t2, done   # 右端まで来たら終わり    addi t0, t0, 1      # x を 1 進める    add  t4, t4, t3     # ずれ += dy    slli t5, t4, 1    blt  t5, t2, loop   # ずれ × 2 < dx なら、まだ同じ行    addi t1, t1, 1      # 1 行下へ    sub  t4, t4, t2     # ずれ -= dx    j    loopdone:

階段のような線が出ます。li t3, 12 の 12 を 0 から 31 まで変えて、傾きが変わることを確かめてください。

この考え方は、考案者の名前からブレゼンハムのアルゴリズムと呼ばれています。割り算も小数も使わず、足し算と引き算と比較だけで線が引けます。計算機が遅かった 1960 年代に考え出され、今でも使われています。

どの向きにも引ける line

上のプログラムは、右下へ向かうゆるい線しか引けません。左向き、上向き、急な線にも使えるようにしたのが、次の line です。x と y のどちらを進めるかを、ずれを見て毎回決めます。中身を全部追わなくても構いません。道具として使ってください。

line でいろいろな向きの線を引く⌘↵
.equ SCREEN, 0x10000main:    addi sp, sp, -16    sw   ra, 12(sp)    sw   s0, 8(sp)    li   s0, 0          # 線の行き先の xfan:    li   a0, 0          # (0, 31) から    li   a1, 31    mv   a2, s0         # (s0, 0) へ    li   a3, 0    srli a4, s0, 2    addi a4, a4, 2      # 色を少しずつ変える    call line    addi s0, s0, 5    li   t0, 32    blt  s0, t0, fan    lw   ra, 12(sp)    lw   s0, 8(sp)    addi sp, sp, 16    ret# line(a0 = x0, a1 = y0, a2 = x1, a3 = y1, a4 = 色)：(x0, y0) から (x1, y1) へ線を引くline:    sub  t0, a2, a0     # t0 = dx（横の長さ）    li   t2, 1          # t2 = x の進む向き（1 か -1）    bgez t0, line_1    neg  t0, t0    li   t2, -1line_1:    sub  t1, a3, a1     # t1 = dy（縦の長さ）    li   t3, 1          # t3 = y の進む向き    bgez t1, line_2    neg  t1, t1    li   t3, -1line_2:    sub  t4, t0, t1     # t4 = ずれ    li   t6, SCREENline_loop:    slli t5, a1, 5      # 点を打つ    add  t5, t5, a0    add  t5, t5, t6    sb   a4, 0(t5)    bne  a0, a2, line_step    beq  a1, a3, line_done   # 終点に着いたline_step:    slli t5, t4, 1      # t5 = ずれ × 2    neg  a5, t1    ble  t5, a5, line_y    sub  t4, t4, t1     # x を進める    add  a0, a0, t2line_y:    bge  t5, t0, line_loop    add  t4, t4, t0     # y を進める    add  a1, a1, t3    j    line_loopline_done:    ret

左下の角から、扇のように 7 本の線が広がります。

15.3四角を塗る、画面を消す

次は面です。四角の塗りつぶしは、横線を縦に並べたものです。横線のループを、行の数だけ繰り返します。

四角が描ければ、絵が描けます。空、地面、家、木を、すべて四角で描いてみます。

ここで 1 つ工夫をします。四角 1 個ごとに引数を 5 つ用意して call する命令を書くと、プログラムが長くなります。そこで、四角の一覧をデータの表にして、ループで順に描きます。

四角の表から絵を描く⌘↵
.equ SCREEN, 0x10000.data# 四角の表。1 行が四角 1 個：x, y, 幅, 高さ, 色shapes:    .byte  0,  0, 32, 22,  6    # 空（水色）    .byte  0, 22, 32, 10,  3    # 地面（緑）    .byte 24,  3,  5,  5,  5    # 太陽（黄）    .byte  6, 14, 12,  8, 15    # 家の壁（肌色）    .byte  4, 11, 16,  3,  2    # 屋根（赤）    .byte  7,  9, 10,  2,  2    # 屋根の上の段    .byte 10, 17,  3,  5, 10    # ドア（茶）    .byte 14, 16,  3,  3,  4    # 窓（青）    .byte 25, 17,  2,  5, 10    # 木の幹（茶）    .byte 23, 12,  6,  6, 13    # 木の葉（濃い緑）shapes_end:.textmain:    addi sp, sp, -16    sw   ra, 12(sp)    sw   s0, 8(sp)    sw   s1, 4(sp)    la   s0, shapes     # s0 = いま描く四角のデータの番地    la   s1, shapes_end # s1 = 表の終わりnext:    lbu  a0, 0(s0)      # 表から 5 バイト読んで、引数にする    lbu  a1, 1(s0)    lbu  a2, 2(s0)    lbu  a3, 3(s0)    lbu  a4, 4(s0)    call rect    addi s0, s0, 5      # 次の四角へ    blt  s0, s1, next    lw   ra, 12(sp)    lw   s0, 8(sp)    lw   s1, 4(sp)    addi sp, sp, 16    ret# rect(a0 = x, a1 = y, a2 = 幅, a3 = 高さ, a4 = 色)：四角を塗りつぶすrect:    li   t0, SCREEN    slli t1, a1, 5    add  t0, t0, t1    add  t0, t0, a0     # t0 = 左上のピクセルの番地rect_row:    mv   t1, t0         # t1 = この行の、いま書く場所    add  t2, t0, a2     # t2 = この行の終わりrect_col:    sb   a4, 0(t1)    addi t1, t1, 1    blt  t1, t2, rect_col    addi t0, t0, 32     # 1 行下へ    addi a3, a3, -1    bnez a3, rect_row    ret

後から描いた四角が、前の四角の上に重なります。空と地面を先に、家と木を後に描いているのはそのためです。表の数を書き換えて、家を大きくしたり、雲を足したりしてみてください。命令には触らずに、絵を変えられます。

絵の内容をデータに、描き方を命令に分ける。これは、大きなプログラムでもよく使われる設計です。

画面を消す

画面全体を 1 色で塗れば、「消す」ことになります。rect で 32 × 32 を塗ってもできますが、もっと速い方法があります。sw は 4 バイトを一度に書けるので、4 ピクセルずつ塗れるのです。

画面を 1 色で塗る（4 ピクセルずつ）⌘↵
.equ SCREEN, 0x10000    li   t0, SCREEN    addi t1, t0, 1024   # 終わりの番地    li   t2, 0x0E0E0E0E # 色 14（紺）を 4 バイトぶん並べた数loop:    sw   t2, 0(t0)      # 4 ピクセルを一度に書く    addi t0, t0, 4    blt  t0, t1, loop

ループは 256 回で済みます。黒で消すなら、sw zero, 0(t0) と書くだけです。

15.4アニメーション：消して、動かして、描く

絵を動かしましょう。第 14 章で見たとおり、0x20010 番地に書くと「1 フレーム終わり」の合図になり、その時点の画面が表示されます。

動く絵のプログラムは、どれも同じ 4 つの仕事を繰り返します。この繰り返しをフレームループと呼びます。

跳ねるボール

壁で跳ね返るボールを作ります。ボールには、場所 (x, y) のほかに、速さ (vx, vy) を持たせます。速さは「1 フレームに何ピクセル進むか」です。右へ進むなら vx = 1、左なら vx = -1 です。

壁に当たったら、速さの符号を逆にします。それだけで、跳ね返ったように見えます。

跳ねるボール動き続ける⌘↵
.equ SCREEN, 0x10000.equ FRAME,  0x20010main:    li   s0, 3          # x    li   s1, 9          # y    li   s2, 1          # vx（x の速さ）    li   s3, 1          # vy（y の速さ）    li   s4, SCREEN    li   s5, FRAME    li   s6, 30         # x と y の上限（ボールは 2 × 2 なので、31 ではなく 30）loop:    li   a0, 0          # 1. 消す：いまの場所を黒で描く    call ball    add  t0, s0, s2     # 2. 動かす：次の x が端を越えるなら、向きを逆に    bltz t0, flip_x    ble  t0, s6, keep_xflip_x:    neg  s2, s2keep_x:    add  t0, s1, s3     # y も同じ    bltz t0, flip_y    ble  t0, s6, keep_yflip_y:    neg  s3, s3keep_y:    add  s0, s0, s2    add  s1, s1, s3    li   a0, 5          # 3. 描く：新しい場所を黄色で描く    call ball    sw   zero, 0(s5)    # 4. 見せる：1 フレーム終わり    j    loop# ball(a0 = 色)：(s0, s1) を左上にして、2 × 2 のボールを描くball:    slli t0, s1, 5    add  t0, t0, s0    add  t0, t0, s4    sb   a0, 0(t0)    sb   a0, 1(t0)    sb   a0, 32(t0)    sb   a0, 33(t0)    ret

黄色いボールが、斜めに進んで壁で跳ね返り続けます。止めるときは停止ボタンを押してください。

「消す」は、画面全体を消す必要はありません。前に描いた場所を、黒で描き直すだけで足ります。動くものが小さいときは、このほうがずっと少ない命令で済みます。

ball は、場所を引数ではなく s0 と s1 から読んでいます。ゲームの状態（場所、速さ、スコアなど）は、プログラム全体で使う値です。この章では、こうした値を s のレジスタに置き、どの関数からも見えるものとして扱います。

画面全体を描き直す方法

動くものが画面いっぱいに広がっているときは、消さずに、毎フレーム全部を描き直します。色の帯が上へ流れていくアニメーションです。行ごとの色を、「行の番号 + フレームの番号」から決めます。

色の帯が流れる動き続ける⌘↵
.equ SCREEN, 0x10000.equ FRAME,  0x20010    li   s0, 0          # フレームの番号frame:    li   t0, SCREEN    li   t1, 0          # yrow:    add  t2, t1, s0     # y + フレームの番号    srli t2, t2, 1      # 2 行で 1 色    andi t2, t2, 15     # 色 0〜15    slli t3, t2, 8      # 同じ色を 4 バイトぶん並べる    or   t2, t2, t3    slli t3, t2, 16    or   t2, t2, t3    li   t4, 8          # 1 行 = 4 ピクセル × 8 回col:    sw   t2, 0(t0)    addi t0, t0, 4    addi t4, t4, -1    bnez t4, col    addi t1, t1, 1    li   t5, 32    blt  t1, t5, row    li   t0, FRAME    sw   zero, 0(t0)    # 2 フレーム見せる    sw   zero, 0(t0)    addi s0, s0, 1      # 次のフレームでは、1 行ぶんずれる    j    frame

全部を描き直しても、1 フレームあたり 1,500 命令ほどです。sw で 4 ピクセルずつ書いているのが効いています。

メモ消す行をなくすと、軌跡が残る

li a0, 0 と、その次の call ball の 2 行を消してみてください。ボールの通った跡が消えずに残り、画面に模様が描かれていきます。アニメーションが「消して描く」でできていることが、よく分かります。

15.5キーで動かす

次は、自分で動かせるものを作ります。キーの読み方は 2 通りありました（第 14 章）。

番地分かること向いている使い方
0x20004押されたキーのコード（1 回ずつ）向きを変える、メニューを選ぶ
0x20014いま押されているキー（ビット）押している間ずっと動かす

ここでは 0x20014 を使います。ビット 0 が ←、ビット 1 が ↑、ビット 2 が →、ビット 3 が ↓、ビット 4 がスペースでした。andi で 1 ビットだけ取り出して、0 でなければ押されています。

矢印キーで四角を動かす（スペースで色が変わる）動き続ける⌘↵
.equ SCREEN, 0x10000.equ FRAME,  0x20010.equ HELD,   0x20014main:    li   s0, 14         # x    li   s1, 14         # y    li   s2, SCREEN    li   s3, HELD    li   s4, FRAME    li   s5, 29         # x と y の上限（四角は 3 × 3）loop:    li   a0, 0          # 消す    call block    lw   t0, 0(s3)      # いま押されているキー    andi t1, t0, 1      # ← が押されている？    beqz t1, k_right    beqz s0, k_right    # 左端なら動かない    addi s0, s0, -1k_right:    andi t1, t0, 4      # →    beqz t1, k_up    bge  s0, s5, k_up    addi s0, s0, 1k_up:    andi t1, t0, 2      # ↑    beqz t1, k_down    beqz s1, k_down    addi s1, s1, -1k_down:    andi t1, t0, 8      # ↓    beqz t1, k_color    bge  s1, s5, k_color    addi s1, s1, 1k_color:    li   a0, 6          # ふだんは水色    andi t1, t0, 16     # スペース    beqz t1, k_draw    li   a0, 2          # 押している間は赤k_draw:    call block          # 描く    sw   zero, 0(s4)    # 2 フレーム見せる（速すぎないように）    sw   zero, 0(s4)    j    loop# block(a0 = 色)：(s0, s1) を左上にして、3 × 3 の四角を描くblock:    slli t0, s1, 5    add  t0, t0, s0    add  t0, t0, s2    sb   a0, 0(t0)    sb   a0, 1(t0)    sb   a0, 2(t0)    sb   a0, 32(t0)    sb   a0, 33(t0)    sb   a0, 34(t0)    sb   a0, 64(t0)    sb   a0, 65(t0)    sb   a0, 66(t0)    ret

実行してから画面をクリックし、矢印キーを押してください（画面の横の矢印ボタンでも動かせます）。押している間、四角が動き続けます。← と ↑ を同時に押すと、斜めに動きます。4 つのキーを別々のビットで調べているので、同時押しがそのまま扱えます。

フレームの合図を 2 回続けて出しているのは、速さの調整です。合図 1 回が 1 フレームぶんの待ち時間になります。合図を増やせば、動きがゆっくりになります。

15.6ライフゲーム

ここで、キーを使わない、見て楽しむプログラムを 1 つ作ります。ライフゲームです。数学者ジョン・コンウェイが 1970 年に考えた、生き物の集まりのような模様が、ひとりでに移り変わっていく仕組みです。

画面のピクセル 1 個を、セル（小部屋）と呼びます。セルは「生きている」か「死んでいる」かのどちらかです。次の世代でどうなるかは、まわり 8 マスの生きているセルの数で決まります。

まわりの生きているセル次の世代
3 個生きる（死んでいたセルにも、新しく生まれる）
2 個いまのまま（生きていれば生き、死んでいれば死んだまま）
それ以外（0、1、4〜8 個）死ぬ（少なすぎても、多すぎても生きられない）

規則はこれだけです。それなのに、動き回る模様や、点滅する模様、じっと動かない模様が現れます。

作るときの 2 つの工夫

プログラムにするとき、気を付ける点が 2 つあります。

1 つ目は、世代を 2 枚持つことです。 全部のセルを、「いまの世代」だけを見て同時に決めなければなりません。1 枚の上で順に書き換えると、書き換えたばかりのセルを、隣のセルが見てしまいます。そこで、いまの世代を読みながら、別の 1 枚に次の世代を書きます。

2 つ目は、端の扱いです。 画面の端のセルには、隣が 8 マスそろっていません。そのたびに「ここは端か」を調べると、命令が増えます。そこで、盤を上下左右に 1 マスずつ広げて、34 × 34 にします。広げた部分には、いつも 0（死んでいる）を置いておきます。こうすれば、どのセルも同じ 8 回の読み出しで済みます。このような、境目の確認を省くための詰め物を番兵と呼びます。

セルは 1 バイトで、生きていれば 1、死んでいれば 0 を入れます。すると、まわり 8 バイトを足すだけで、生きている隣の数になります。

動かす

最初の世代は、乱数で決めます。およそ 4 個に 1 個のセルを生きている状態にします。

ライフゲーム動き続ける⌘↵
.equ SCREEN, 0x10000.equ RANDOM, 0x20008.equ FRAME,  0x20010.datagrid_a: .space 1156     # 34 × 34 バイト。まわりの 1 マスは、いつも 0 の番兵grid_b: .space 1156.textmain:    la   s0, grid_a     # s0 = いまの世代    la   s1, grid_b     # s1 = 次の世代    li   s2, SCREEN    li   s3, FRAME    addi t0, s0, 35     # ---- 最初の世代：内側の 32 × 32 を乱数で埋める    li   t1, RANDOM     #      （35 = 1 行ぶんの 34 + 1。内側の左上のセル）    li   t3, 32         # 残りの行seed_row:    li   t4, 32         # 残りの列seed_cell:    lw   t5, 0(t1)    andi t5, t5, 3      # 0〜3    seqz t5, t5         # 0 のときだけ 1（4 回に 1 回、生きている）    sb   t5, 0(t0)    addi t0, t0, 1    addi t4, t4, -1    bnez t4, seed_cell    addi t0, t0, 2      # 右と左の番兵を飛ばして、次の行へ    addi t3, t3, -1    bnez t3, seed_rowgeneration:    addi t0, s0, 35     # t0 = いまの世代のセル    addi t1, s1, 35     # t1 = 次の世代の同じセル    mv   t2, s2         # t2 = 画面の同じピクセル    li   t3, 32row:    li   t4, 32cell:    lbu  a0, -35(t0)    # ---- まわり 8 マスを足す    lbu  a1, -34(t0)    add  a0, a0, a1    lbu  a1, -33(t0)    add  a0, a0, a1    lbu  a1, -1(t0)    add  a0, a0, a1    lbu  a1, 1(t0)    add  a0, a0, a1    lbu  a1, 33(t0)    add  a0, a0, a1    lbu  a1, 34(t0)    add  a0, a0, a1    lbu  a1, 35(t0)    add  a0, a0, a1     # a0 = 生きている隣の数（0〜8）    li   a2, 1          # ---- 次の世代の状態を決める    li   a3, 3    beq  a0, a3, store  # 隣が 3 個 → 生きる    li   a2, 0    li   a3, 2    bne  a0, a3, store  # 2 個でも 3 個でもない → 死ぬ    lbu  a2, 0(t0)      # 2 個 → いまのままstore:    sb   a2, 0(t1)      # 次の世代に書く    neg  a3, a2    andi a3, a3, 3      # 1 → 色 3（緑）、0 → 色 0（黒）    sb   a3, 0(t2)      # 画面にも描く    addi t0, t0, 1    addi t1, t1, 1    addi t2, t2, 1    addi t4, t4, -1    bnez t4, cell    addi t0, t0, 2      # 番兵を飛ばす    addi t1, t1, 2    addi t3, t3, -1    bnez t3, row    mv   t0, s0         # ---- 世代を入れ替える（番地を交換するだけ）    mv   s0, s1    mv   s1, t0    li   t0, 4          # 4 フレームのあいだ見せるshow:    sw   zero, 0(s3)    addi t0, t0, -1    bnez t0, show    j    generation

緑の模様が、生き物のように動き続けます。しばらくすると、動かないかたまりや、点滅するかたまりに落ち着いていきます。

読みどころを 3 つ挙げます。

  • 世代の入れ替え：次の世代を書き終えたら、s0 と s1 の番地を交換します。1,156 バイトをコピーする必要はありません。「どちらがいまの世代か」という見方を変えるだけです
  • 色の作り方：neg で 1 を -1（全ビットが 1）にし、andi で 3 と AND を取ると 3 になります。0 は 0 のままです。分岐を使わずに、0 か 3 かを選んでいます
  • 命令の数：1 世代で 1,024 個のセルを調べます。1 セルあたり 30 命令ほどなので、1 世代で 3 万命令あまりです。番兵を使わずに端の確認を入れると、これがずっと増えます
深掘り画面そのものを「いまの世代」にしない理由

画面も読めるメモリなので、画面を盤として使うこともできそうです。しかし、画面には番兵を置く場所がありません。色の番号（3）をそのまま足すこともできません。「見せるためのデータ」と「計算のためのデータ」は、形を分けたほうが、どちらも単純になります。

15.7ゲームを作る：はらぺこヘビ

最後に、遊べるゲームを 1 本作ります。名前は「はらぺこヘビ」です。

  • ヘビは、止まらずに進み続ける。矢印キーで向きを変える
  • 赤いエサを食べると、体が 1 マス伸びる
  • 壁か、自分の体にぶつかると、ゲームオーバー

一度に全部は書きません。動くものを少しずつ足していきます。大きなプログラムは、いつも動く状態を保ちながら育てるのがこつです。

設計：場所を 1 つの数で表す

最初に、データの持ち方を決めます。ここで楽をすると、あとの命令が短くなります。

ピクセルの場所を、(x, y) の 2 つの数ではなく、画面の先頭から何番目かという 1 つの数で表します。場所 = y × 32 + x で、0 から 1023 までの数です。画面の番地は「0x10000 + 場所」になります。

こうすると、向きも 1 つの数で表せます。場所に足す数です。

もう 1 つの決めごとは、画面のまわりに壁を描いておくことです。ヘビが進む先のピクセルを画面から読み、黒でなければ「何かにぶつかった」と分かります。x が 0 未満か、32 以上か、といった確認は要りません。ライフゲームの番兵と同じ考え方です。

段階 1：頭を動かす

まず、壁を描き、1 マスの頭を動かします。壁にぶつかったら、中央に戻します。

段階 1：壁の中を、頭が進む動き続ける⌘↵
.equ SCREEN, 0x10000.equ KEY,    0x20004.equ FRAME,  0x20010.equ C_WALL, 12         # 色：壁（濃い灰）.equ C_HEAD, 3          # 頭（緑）.equ SPEED,  6          # 何フレームごとに 1 マス進むか.datadirs: .word 0, -1, -32, 1, 32    # キーのコード 1〜4 → 向き（← ↑ → ↓）.text# s0 = 画面の先頭   s2 = 頭の場所（0〜1023）# s4 = いまの向き   s5 = 次の向き   s7 = 待ちフレームの残りmain:    li   s0, SCREEN    call new_board    li   s2, 528            # 中央（16, 16）= 16 × 32 + 16    li   s4, 1              # 右向き    li   s5, 1loop:    li   s7, SPEED          # ---- 待つ。その間もキーを読むwait:    call read_key    li   t0, FRAME    sw   zero, 0(t0)    addi s7, s7, -1    bnez s7, wait    mv   s4, s5             # ---- 1 マス進む    add  t0, s0, s2    sb   zero, 0(t0)        # いまの場所を消す    add  t1, s2, s4         # t1 = 進む先（場所 + 向き）    add  t2, s0, t1    lbu  t3, 0(t2)          # 進む先には何がある？（画面を読む）    beqz t3, move    li   t1, 528            # 黒でない → 壁。中央に戻るmove:    mv   s2, t1    add  t0, s0, s2    li   t3, C_HEAD    sb   t3, 0(t0)          # 新しい場所に頭を描く    j    loop# read_key：矢印キーが押されていたら、次の向き s5 を変えるread_key:    li   t0, KEY    lw   t0, 0(t0)    beqz t0, rk_done        # 押されていない    li   t1, 4    bgtu t0, t1, rk_done    # 矢印キーではない    slli t0, t0, 2    la   t1, dirs    add  t1, t1, t0    lw   t2, 0(t1)          # t2 = そのキーの向き（表から引く）    add  t3, t2, s4    beqz t3, rk_done        # いまの向きの真逆には向けない    mv   s5, t2rk_done:    ret# new_board：画面を黒で消して、まわりに壁を描くnew_board:    mv   t0, s0    addi t1, s0, 1024nb_clear:    sw   zero, 0(t0)        # 4 ピクセルずつ消す    addi t0, t0, 4    blt  t0, t1, nb_clear    li   t2, C_WALL    mv   t0, s0             # t0 は横に、t1 は縦に進む    mv   t1, s0    li   t3, 32nb_wall:    sb   t2, 0(t0)          # 上の辺    sb   t2, 992(t0)        # 下の辺（31 × 32 = 992）    sb   t2, 0(t1)          # 左の辺    sb   t2, 31(t1)         # 右の辺    addi t0, t0, 1    addi t1, t1, 32    addi t3, t3, -1    bnez t3, nb_wall    ret

画面をクリックして、矢印キーで向きを変えてください。この段階で、ゲームの骨組みはもうできています。

  • 速さの調整：毎フレーム進むと速すぎるので、6 フレームに 1 回だけ進みます。待っている間も、毎フレーム read_key を呼びます。こうしないと、待ちの間に押したキーを取りこぼします
  • キーから向きへ：キーのコード（1〜4）を番号にして、表 dirs から向きを引きます。beq を 4 つ並べる代わりに、配列を 1 回読むだけです
  • 真逆を禁止：新しい向きといまの向きを足して 0 なら、真逆です（+1 と -1、+32 と -32）。ヘビは、その場で後ろを向けません
  • ぶつかったかどうか：進む先のピクセルを lbu で読むだけです

段階 2：体を付ける

次に、体を付けます。ヘビが 1 マス進むとき、画面で変わるのは 2 か所だけです。進む先に頭が増え、しっぽの先が 1 マス消えます。 途中の体は動きません。

しっぽを消すには、「しっぽがいまどこにあるか」を知る必要があります。そこで、体の各マスの場所を、頭が通った順に配列に覚えておきます。

番号は進む一方なので、いつか配列の終わりに着きます。そこで、配列の大きさを 1,024 個にして、1023 の次は 0 に戻ることにします。andi s2, s2, 1023 の 1 行で戻せます。終わりと始まりがつながった輪のように使うので、この形をリングバッファ（輪になった入れ物）と呼びます。ヘビは最大でも 1,024 マスより長くなれないので、頭がしっぽを追い越すことはありません。

段階 1 から変わるのは、main と、新しい関数 push_head です。まず、進む部分がどう変わるかを見ます。

アセンブリ
# s1 = body の番地   s2 = 頭の番号   s3 = しっぽの番号    mv   s4, s5             # ---- 1 マス進む    slli t0, s2, 2    add  t0, t0, s1    lw   a0, 0(t0)          # いまの頭の場所（body[頭の番号]）    add  a0, a0, s4         # a0 = 進む先    add  t1, s0, a0    lbu  t2, 0(t1)          # 進む先には何がある？    bnez t2, dead           # 黒でない → 壁か、自分の体     slli t0, s3, 2          # しっぽの先を 1 マス消す    add  t0, t0, s1    lw   t1, 0(t0)          # しっぽの場所（body[しっぽの番号]）    add  t1, t1, s0    sb   zero, 0(t1)    addi s3, s3, 1          # しっぽの番号を進める    andi s3, s3, 1023    call push_head          # 進む先を、新しい頭にする    j    loop

段階 1 では、ぶつかる相手は壁だけでした。体が付いたいま、同じ 1 行の bnez が、自分の体との衝突も見つけます。体もピクセルとして画面に描かれているからです。

全体をつなげると、次のようになります。長さ 6 のヘビが動き回ります。壁か自分の体にぶつかると、最初からやり直します。

段階 2：体を引きずって進む動き続ける⌘↵

頭は明るい緑、体は濃い緑で描き分けています。push_head は、新しい頭を描く前に、いままでの頭を体の色に塗り直します。

段階 3：エサ、成長、ゲームオーバー

残りは 3 つです。

エサを置く。 乱数で場所を選びます。壁や体の上に置かないように、選んだ場所が黒でなければ選び直します。

アセンブリ
# put_food：空いているマスを乱数で選んで、エサを置くput_food:    li   t0, RANDOMpf_retry:    lw   t1, 0(t0)    andi t1, t1, 1023       # 0〜1023 の場所    add  t1, t1, s0    lbu  t2, 0(t1)    bnez t2, pf_retry       # 何かあるマスなら選び直す    li   t2, C_FOOD    sb   t2, 0(t1)    ret

食べたら伸びる。 進む先がエサの色だったら、しっぽを消さずに頭だけを足します。図の 3 枚目の動きです。伸ばすための特別な仕組みは要りません。「消さない」だけです。

やってみようボールを改造する

下の跳ねるボールを改造してください。(1) 壁で跳ね返るたびに、ボールの色が変わるようにします。色を入れるレジスタを 1 つ決めて、flip_x と flip_y で 1 ずつ増やします。(2) 「消す」の 2 行を消して、軌跡が残るようにします。(3) 最初の場所や速さ（s2 を 2 にするなど）を変えて、模様の違いを見ます。

要点まとめ
  • 絵は、点を打つことの積み重ね。横線は番地を 1 ずつ、縦線は 32 ずつ進める。四角は横線の繰り返し
  • 斜めの線は、「ずれ」を整数でためていき、たまったら 1 段進める（ブレゼンハムのアルゴリズム）
  • 絵の内容をデータの表にして、ループで描くと、命令を変えずに絵を変えられる
  • アニメーションは、消す → 動かす → 描く → 見せる（0x20010）の繰り返し。これがフレームループ
  • 押している間動かすなら 0x20014 のビット、1 回ずつの操作なら 0x20004 のコードを読む
  • 端の確認を省くには、まわりに番兵（いつも 0 のマスや、壁）を置く
  • 画面は読めるメモリでもある。ぶつかったかどうかは、進む先のピクセルを読めば分かる
  • 大きなプログラムは、動く状態を保ったまま、少しずつ足して育てる
