第 20 章

C からアセンブリへ

C のプログラムは、コンパイラによってアセンブリに訳されます。変数、式、if、ループ、関数、配列とポインタ、構造体、再帰が、それぞれどんな命令の並びになるかを、手で訳して動かします。最後にコンパイラの最適化を見ます。

20.1コンパイラ・アセンブラ・リンカ

ここまで、プログラムはアセンブリで書いてきました。ふだんのプログラムは、C や Rust のような高水準言語で書きます。人が書いた C のプログラムが CPU で動くまでには、3 つの道具が順に働きます。

  • コンパイラ：C をアセンブリに訳す。どの変数をどのレジスタに置くか、どの命令を使うかを決める。この章の主役
  • アセンブラ：アセンブリを機械語に直す。第 9 章で手でやった作業で、このサイトの実行ボタンの中でも動いている
  • リンカ：別々に作った機械語をつなぎ合わせ、関数や変数の番地を最終的に決める。このサイトのプログラムはいつも 1 つのファイルなので、リンカの出番はない

この章では、コンパイラの仕事を手でやります。C のコードを見せ、それを訳したアセンブリを動かします。

メモこの章のアセンブリについて

この章のアセンブリは、「コンパイラはたとえばこう訳す」という例を、手で書いたものです。本物の gcc や clang の出力そのものではありません。コンパイラの出力は、種類、版、最適化レベル（-O0、-O2 などの指定）によって変わります。変わらないのは、呼び出し規約のような約束と、訳し方の基本の形です。

C を知らなくても読めるように、使う書き方を先にまとめます。

C の書き方意味
int x = 5;32 ビットの符号付き整数の変数 x を作り、5 を入れる
x = a + b * c;右辺を計算して x に入れる。* は掛け算、/ は割り算、% は余り
if (条件) { … } else { … }条件が成り立てば前、そうでなければ後ろを実行する
while (条件) { … }条件が成り立つ間、繰り返す
int f(int a, int b) { return a + b; }引数を 2 つ受け取り、整数を返す関数
print_int(x)、print_char(c)この章だけの約束。このサイトの ecall の 1 番と 11 番に当たる

20.2変数と式

C の変数には、置き場所が 2 種類あります。関数の中で作るローカル変数と、関数の外に書くグローバル変数です。

コンパイラは、ローカル変数をできるだけレジスタに置きます。メモリの読み書きより速いからです。式は、演算子の優先順位に従って 1 つずつ命令に直します。途中の結果は、空いているレジスタに一時的に置きます。

C
int a = 6, b = 7, c = 2;int x = a + b * c;              // 掛け算が先int y = (a + b) * c - x / 4;print_int(x); print_char(' '); print_int(y);
ローカル変数はレジスタに、式は 1 演算 1 命令に⌘↵
main:    li   t0, 6              # a    li   t1, 7              # b    li   t2, 2              # c    mul  t3, t1, t2         # 途中の結果：b * c    add  t3, t0, t3         # x = a + (b * c)    add  t4, t0, t1         # 途中の結果：a + b    mul  t4, t4, t2         # (a + b) * c    li   t5, 4    div  t5, t3, t5         # 途中の結果：x / 4    sub  t4, t4, t5         # y    mv   a0, t3    li   a7, 1    ecall                   # print_int(x)    li   a0, ' '    li   a7, 11    ecall    mv   a0, t4    li   a7, 1    ecall                   # print_int(y)    li   a7, 10    ecall

a は t0、x は t3、というように、変数の名前はレジスタの番号に置き換わりました。機械語には、変数の名前は残りません。

グローバル変数は、プログラムのどこからでも使えるので、メモリ（.data）に置きます。使うたびに、読んで、計算して、書き戻します。

C
int counter = 10;               // グローバル変数 int main(void) {    counter = counter + 5;    print_int(counter);}
グローバル変数はメモリに置く⌘↵
main:    la   t0, counter        # counter の番地    lw   t1, 0(t0)          # 読む    addi t1, t1, 5    sw   t1, 0(t0)          # 書き戻す    lw   a0, 0(t0)    li   a7, 1    ecall    li   a7, 10    ecall.datacounter: .word 10

型は、命令の選び方に残る

C の変数には int（符号付き）や unsigned（符号なし）といった型があります。レジスタの中身はただの 32 ビットで、型の情報はどこにもありません。型は、コンパイラがどの命令を選ぶかに使われて、消えます。

C
int      s = -7;unsigned u = 4294967289u;       // ビットの並びは -7 と同じprint_int(s / 2);   print_int(s >> 1);print_uint(u / 2);  print_uint(u >> 1);
同じビットでも、型によって違う命令になる⌘↵
main:    li   s0, -7             # s と u。ビットの並びは同じ    li   t1, 2    div  a0, s0, t1         # int の割り算は div    call show               # -3    srai a0, s0, 1          # int の右シフトは srai（符号を保つ）    call show               # -4    divu a0, s0, t1         # unsigned の割り算は divu    call showu              # 2147483644    srli a0, s0, 1          # unsigned の右シフトは srli（0 を入れる）    call showu              # 2147483644    li   a7, 10    ecallshow:    li   a7, 1              # 符号付きで表示    j    1fshowu:    li   a7, 36             # 符号なしで表示1:  ecall    li   a0, '\n'    li   a7, 11    ecall    ret

int の -7 / 2 は -3（0 に近いほうへ丸める）、-7 >> 1 は -4 です。結果が違うので、コンパイラは符号付きの「2 で割る」を、そのまま右シフト 1 個には置き換えられません。符号なしなら、どちらも同じ結果です。

20.3if と else

if は、条件分岐とラベルに直します。コツは、条件を逆にして、「成り立たないときに飛び越す」 形にすることです。

C
int a = 3, b = 8, m;if (a > b) {    m = a;} else {    m = b;}print_int(m);
if / else：条件を逆にして飛び越す⌘↵
main:    li   t0, 3              # a    li   t1, 8              # b    ble  t0, t1, else       # a > b ではない（a <= b）なら else へ    mv   t2, t0             # m = a    j    endif              # else の部分を飛び越すelse:    mv   t2, t1             # m = bendif:    mv   a0, t2    li   a7, 1    ecall    li   a7, 10    ecall

C の a > b が、アセンブリでは逆の ble（以下なら飛ぶ）になりました。こうすると、if の中身を条件のすぐ下に、C と同じ順番で並べられます。

条件を &&（かつ）でつなぐと、分岐が 2 つになります。C には、前の条件が成り立たなければ、後ろの条件は調べないという決まり（短絡評価）があります。命令の並びも、そのとおりになります。

C
int x = 15;if (x >= 10 && x < 20) {    print_char('Y');} else {    print_char('N');}
&& は分岐 2 つ。前がだめなら、後ろは調べない⌘↵
main:    li   t0, 15             # x    li   t1, 10    blt  t0, t1, no         # x >= 10 ではないなら、すぐ no へ    li   t1, 20    bge  t0, t1, no         # x < 20 ではないなら no へ    li   a0, 'Y'    j    printno:    li   a0, 'N'print:    li   a7, 11    ecall    li   a7, 10    ecall

20.4while と for

ループは、「条件を調べる分岐」と「前へ戻るジャンプ」に直します。C の for は while の書き方を変えただけなので、同じ形になります。

C
int sum = 0;for (int i = 1; i <= 10; i++) {     // i++ は i = i + 1    sum += i;                        // sum = sum + i}print_int(sum);

素直に訳すと、条件をループの先頭で調べる形になります。

for：先頭で条件を調べる形⌘↵
main:    li   t0, 0              # sum    li   t1, 1              # i    li   t2, 10loop:    bgt  t1, t2, done       # i <= 10 ではないなら抜ける    add  t0, t0, t1         # sum += i    addi t1, t1, 1          # i++    j    loopdone:    mv   a0, t0    li   a7, 1    ecall    li   a7, 10    ecall

この形は、1 周ごとに分岐 bgt とジャンプ j の 2 つを実行します。コンパイラはふつう、条件をループの末尾に移して、1 周の分岐を 1 つにします。

for：末尾で条件を調べる形（1 周あたり 1 命令少ない）⌘↵
main:    li   t0, 0              # sum    li   t1, 1              # i    li   t2, 10    bgt  t1, t2, done       # 最初の 1 回だけ、入る前に調べるloop:    add  t0, t0, t1         # sum += i    addi t1, t1, 1          # i++    ble  t1, t2, loop       # i <= 10 なら続けるdone:    mv   a0, t0    li   a7, 1    ecall    li   a7, 10    ecall

出力の下の「実行した命令数」を比べてください。先頭で調べる形は 49、末尾で調べる形は 39 です。

while の中に if があっても、部品を組み合わせるだけです。次の例は、コラッツの問題（偶数なら半分、奇数なら 3 倍して 1 を足す。1 になるまでの回数を数える）です。

C
int n = 27, steps = 0;while (n != 1) {    if (n % 2 == 0) {        n = n / 2;    } else {        n = 3 * n + 1;    }    steps++;}print_int(steps);
while の中に if / else⌘↵
main:    li   t0, 27             # n    li   t1, 0              # steps    li   t2, 1    beq  t0, t2, done       # 入る前に 1 回調べるloop:    andi t3, t0, 1          # n % 2（下の 1 ビット）    bnez t3, odd            # 0 ではない（奇数）なら else へ    srai t0, t0, 1          # n = n / 2（n は正なのでシフトでよい）    j    endifodd:    slli t3, t0, 1          # 2 * n    add  t0, t3, t0         # 3 * n    addi t0, t0, 1          # + 1endif:    addi t1, t1, 1          # steps++    bne  t0, t2, loop       # n != 1 なら続けるdone:    mv   a0, t1    li   a7, 1    ecall    li   a7, 10    ecall

27 は 111 回で 1 になります。ここでは n % 2 を andi、n / 2 をシフト、3 * n をシフトと足し算に直しました。こうした置き換えは、最後の節で扱う最適化の 1 つです。

20.5関数

関数の呼び出しは、第 13 章の呼び出し規約そのままです。コンパイラは、この約束を機械的に守ります。

約束中身
引数左から順に a0、a1、…、a7
戻り値a0
戻り先ra（call が入れる）
呼んだ側が守るt0〜t6、a0〜a7、ra。関数を呼ぶと壊れる前提
呼ばれた側が守るs0〜s11、sp。使うなら保存して、戻る前に元に戻す

ほかの関数を呼ばない関数（葉の関数）は、スタックを使わずに済みます。

C
int square(int x) {    return x * x;} int main(void) {    print_int(square(12));}
葉の関数：引数は a0、戻り値も a0⌘↵
main:    li   a0, 12             # 引数    call square    li   a7, 1              # 戻り値は a0 に入っている    ecall    li   a7, 10    ecallsquare:    mul  a0, a0, a0    ret

ほかの関数を呼ぶ関数は、そうはいきません。call が ra を上書きし、呼んだ先が a0 や t0 を壊すからです。呼び出しをまたいで使う値は、s の付くレジスタに置き、そのレジスタの元の値と ra をスタックに保存します。

C
int sum_sq(int a, int b) {    return square(a) + square(b);}

関数の入口で保存する部分をプロローグ、出口で元に戻す部分をエピローグと呼びます。

ほかの関数を呼ぶ関数：プロローグとエピローグ⌘↵
main:    li   a0, 3    li   a1, 4    call sum_sq    li   a7, 1    ecall                   # 25    li   a7, 10    ecallsum_sq:    addi sp, sp, -16        # ── プロローグ：フレームを作る    sw   ra, 12(sp)    sw   s0, 8(sp)    sw   s1, 4(sp)    mv   s0, a1             # b を、呼び出しで壊れない s0 へ    call square             # square(a)。a は a0 に入ったまま    mv   s1, a0             # 結果を s1 へ    mv   a0, s0    call square             # square(b)    add  a0, s1, a0         # 戻り値    lw   ra, 12(sp)         # ── エピローグ：元に戻す    lw   s0, 8(sp)    lw   s1, 4(sp)    addi sp, sp, 16    retsquare:    mul  a0, a0, a0    ret
メモフレームの大きさが 16 なのは

保存するのは 3 語（12 バイト）ですが、フレームは 16 バイトにしました。RISC-V の標準の呼び出し規約に、sp を 16 の倍数に保つという決まりがあるためです。コンパイラが出すコードで addi sp, sp, -16 や -32 をよく見るのは、このためです。

20.6配列とポインタ

配列は、同じ型の値をメモリに並べたものです。int は 4 バイトなので、a[i] の番地は「a の先頭の番地 + i × 4」です。コンパイラは、添字のたびにこの計算を出します。

C
int a[5] = {3, 1, 4, 1, 5}; int main(void) {    int sum = 0;    for (int i = 0; i < 5; i++) {        sum += a[i];    }    print_int(sum);}
a[i]：先頭の番地 + i × 4⌘↵
main:    la   t0, a              # a の先頭の番地    li   t1, 0              # sum    li   t2, 0              # i    li   t3, 5loop:    slli t4, t2, 2          # i × 4    add  t4, t0, t4         # a + i × 4 … a[i] の番地    lw   t5, 0(t4)          # a[i]    add  t1, t1, t5         # sum += a[i]    addi t2, t2, 1    blt  t2, t3, loop    mv   a0, t1    li   a7, 1    ecall    li   a7, 10    ecall.dataa:  .word 3, 1, 4, 1, 5

ポインタは、番地を入れる変数です。int *p は「int が置いてある番地」を持ちます。*p はその番地の中身、p++ は次の要素へ進める操作です。

C
int sum = 0;for (int *p = a; p < a + 5; p++) {    sum += *p;}
ポインタで配列をたどる。p++ は 4 進む⌘↵
main:    la   t0, a              # p = a    addi t3, t0, 20         # a + 5 … 終わりの番地（5 × 4 = 20）    li   t1, 0              # sumloop:    lw   t5, 0(t0)          # *p    add  t1, t1, t5    addi t0, t0, 4          # p++（int は 4 バイトなので 4 進む）    bltu t0, t3, loop       # p < a + 5（番地の比較は符号なし）    mv   a0, t1    li   a7, 1    ecall    li   a7, 10    ecall.dataa:  .word 3, 1, 4, 1, 5

C の p++ や a + 5 は、「1 増やす」「5 を足す」と書いてあっても、アセンブリでは要素の大きさを掛けた数になります。char のポインタなら 1、int のポインタなら 4 です。ここでも、型は命令の中の数に姿を変えて消えています。ループの中身は、添字の形より 2 命令短くなりました。

番地を取られた変数はメモリに置く

&x は「変数 x の番地」です。レジスタには番地がないので、& で番地を取られたローカル変数は、スタックに置くことになります。

C
void swap(int *p, int *q) {    int tmp = *p;    *p = *q;    *q = tmp;} int main(void) {    int x = 1, y = 2;    swap(&x, &y);    print_int(x); print_int(y);}
&x：ローカル変数をスタックに置いて、番地を渡す⌘↵
main:    addi sp, sp, -16    sw   ra, 12(sp)    li   t0, 1    sw   t0, 8(sp)          # x は sp + 8 に置く    li   t0, 2    sw   t0, 4(sp)          # y は sp + 4 に置く    addi a0, sp, 8          # &x    addi a1, sp, 4          # &y    call swap    lw   a0, 8(sp)          # x    li   a7, 1    ecall    lw   a0, 4(sp)          # y    li   a7, 1    ecall    lw   ra, 12(sp)    addi sp, sp, 16    li   a7, 10    ecallswap:    lw   t0, 0(a0)          # tmp = *p    lw   t1, 0(a1)    sw   t1, 0(a0)          # *p = *q    sw   t0, 0(a1)          # *q = tmp    ret

21 と出ます。swap は x と y という名前を知りません。渡された 2 つの番地の中身を入れ替えただけです。

20.7構造体

構造体は、型の違う値をひとまとめにしたものです。メモリの上では、メンバが順に並びます。p->price のようなメンバの読み書きは、「先頭の番地 + 決まったずれ」の lw や sw になります。このずれをオフセットと呼びます。

C
struct item {    char  kind;     // 1 バイト    int   price;    // 4 バイト    short qty;      // 2 バイト};

メンバは、自分の大きさの倍数の番地に置かれます（第 19 章で見た整列違反を避けるためです）。そのためのすき間が詰め物（パディング）です。末尾にも 2 バイト入り、全体が 4 の倍数の 12 バイトになります。構造体を配列にしたとき、次の要素の price も 4 の倍数の番地に来るようにするためです。

C
struct item items[3] = { {'a', 120, 2}, {'b', 80, 5}, {'c', 300, 1} }; int total(struct item *p, int n) {    int sum = 0;    for (int i = 0; i < n; i++, p++) {        sum += p->price * p->qty;    }    return sum;}
p->price は 4(p)、p->qty は 8(p)、p++ は 12 進む⌘↵
main:    la   a0, items    li   a1, 3    call total    li   a7, 1    ecall                   # 120×2 + 80×5 + 300×1 = 940    li   a7, 10    ecalltotal:    li   t0, 0              # sum    blez a1, doneloop:    lw   t1, 4(a0)          # p->price（オフセット 4）    lh   t2, 8(a0)          # p->qty（オフセット 8。short なので lh）    mul  t1, t1, t2    add  t0, t0, t1    addi a0, a0, 12         # p++（struct item は 12 バイト）    addi a1, a1, -1    bnez a1, loopdone:    mv   a0, t0    ret.dataitems:    .byte 'a'    .word 120               # .word は自動で 4 の倍数の番地にそろう    .half 2    .align 2                # 末尾の詰め物    .byte 'b'    .word 80    .half 5    .align 2    .byte 'c'    .word 300    .half 1    .align 2

price や qty という名前も、4 と 8 という数になって消えました。i を 0 から数え上げる代わりに、残りの個数 n を減らしていく形にしてあります。結果が同じなら、コンパイラはこういう書き換えをします。

20.8再帰

自分自身を呼ぶ関数も、特別な訳し方はしません。「ほかの関数を呼ぶ関数」と同じプロローグとエピローグを付けるだけです。呼ばれるたびに新しいフレームがスタックに積まれるので、それぞれの呼び出しが自分の n を持てます。

C
int fib(int n) {    if (n < 2) return n;    return fib(n - 1) + fib(n - 2);}
再帰：呼び出しごとにフレームが 1 つ⌘↵
main:    li   a0, 10    call fib    li   a7, 1    ecall                   # 55    li   a7, 10    ecallfib:    li   t0, 2    blt  a0, t0, base       # n < 2 なら、フレームを作らずに n を返す    addi sp, sp, -16    sw   ra, 12(sp)    sw   s0, 8(sp)    sw   s1, 4(sp)    mv   s0, a0             # n を取っておく    addi a0, s0, -1    call fib                # fib(n - 1)    mv   s1, a0             # 結果を取っておく    addi a0, s0, -2    call fib                # fib(n - 2)    add  a0, s1, a0    lw   ra, 12(sp)    lw   s0, 8(sp)    lw   s1, 4(sp)    addi sp, sp, 16base:    ret

n < 2 の場合を、フレームを作る前に片付けています。この場合は何も呼ばないので、保存が要らないからです。「CPU を見る」でステップ実行すると、sp が 16 ずつ下がり、また戻っていく様子を追えます。

20.9コンパイラの最適化

同じ C のプログラムでも、訳し方は 1 つではありません。コンパイラは、結果を変えない範囲で、より速く、より短い命令の並びを探します。これが最適化です。

最適化しないと、変数はすべてメモリに置かれる

最適化を切る指定（-O0）では、コンパイラは 1 文ずつ、前後を見ずに訳します。変数はすべてスタックに置き、使うたびに読み、変えるたびに書きます。さきほどの 1 から 10 の合計は、たとえば次のようになります。

最適化なしの形：変数はスタックに置き、毎回読み書きする⌘↵
main:    addi sp, sp, -16    sw   zero, 12(sp)       # sum = 0（sum は sp + 12）    li   t0, 1    sw   t0, 8(sp)          # i = 1（i は sp + 8）    j    condbody:    lw   t0, 12(sp)         # sum を読む    lw   t1, 8(sp)          # i を読む    add  t0, t0, t1    sw   t0, 12(sp)         # sum に書く    lw   t0, 8(sp)          # i を読む    addi t0, t0, 1    sw   t0, 8(sp)          # i に書くcond:    lw   t0, 8(sp)          # i を読む    li   t1, 10    ble  t0, t1, body       # i <= 10 なら続ける    lw   a0, 12(sp)    li   a7, 1    ecall    addi sp, sp, 16    li   a7, 10    ecall

同じ計算に、3 通りの訳し方が出そろいました。

変数をレジスタに置くことをレジスタ割り付けと呼びます。メモリの読み書きが消えるので、もっとも効き目の大きい最適化の 1 つです。第 18 章で見たとおり、メモリはレジスタよりずっと遅いからです。

定数の畳み込みと、軽い命令への置き換え

コンパイルの時点で答えがわかる計算は、コンパイラが済ませてしまいます。これを定数の畳み込みと呼びます。また、掛け算や割り算は、同じ結果になる軽い命令に置き換えます。

C
int secs = 60 * 60 * 24;        // 1 日の秒数int x = 5;print_int(secs + x * 8);
60 * 60 * 24 は計算ずみの数に、x * 8 はシフトに⌘↵
main:    li   t0, 86400          # 60 * 60 * 24 はコンパイラが計算しておく    li   t1, 5              # x    slli t1, t1, 3          # x * 8 は、左へ 3 ビットのシフト    add  a0, t0, t1    li   a7, 1    ecall    li   a7, 10    ecall

実行時には、掛け算は 1 回もしていません。じつは、さきほどの「1 から 10 の合計」も、最適化するコンパイラなら答えの 55 を自分で求めて、li a0, 55 の 1 命令にしてしまうことがあります。

ループの中の計算を外に出す

ループの中にあっても、何周目でも同じ結果になる計算は、ループの前に 1 回だけやれば済みます。

C
int a[8];int x = 6, y = 7;for (int i = 0; i < 8; i++) {    a[i] = x * y + i;           // x * y は毎回同じ}
素直な訳：x * y をループの中で毎回計算する⌘↵
main:    la   t0, a    li   t1, 6              # x    li   t2, 7              # y    li   t3, 0              # i    li   t4, 8loop:    mul  t5, t1, t2         # x * y（毎回同じ）    add  t5, t5, t3         # + i    slli t6, t3, 2    add  t6, t0, t6         # a[i] の番地    sw   t5, 0(t6)    addi t3, t3, 1    blt  t3, t4, loop    li   a7, 10    ecall.dataa:  .space 32
最適化：x * y は外に出し、a[i] の番地はポインタを進めて作る⌘↵
main:    la   t0, a              # p = a    li   t1, 6    li   t2, 7    mul  t5, t1, t2         # x * y はループの前に 1 回だけ    addi t4, t0, 32         # 終わりの番地loop:    sw   t5, 0(t0)          # *p = x * y + i    addi t5, t5, 1          # 次の値は 1 大きい    addi t0, t0, 4          # p++    bltu t0, t4, loop    li   a7, 10    ecall.dataa:  .space 32

メモリの中身（42、43、…、49）は同じです。ループの中身は 7 命令から 4 命令に減り、実行した命令数は 64 から 40 になりました。掛け算は 8 回から 1 回です。

末尾呼び出し

関数の最後の仕事が「別の関数を呼んで、その結果をそのまま返す」ことなら、戻ってくる必要がありません。call の代わりに、ただのジャンプで済みます。これを末尾呼び出しの最適化と呼びます。

C
int gcd(int a, int b) {             // 最大公約数    if (b == 0) return a;    return gcd(b, a % b);           // 最後の仕事が、自分自身の呼び出し}

素直に訳すと、呼ぶたびにフレームを積みます。

素直な訳：呼ぶたびに ra を保存する⌘↵
main:    li   a0, 1071    li   a1, 462    call gcd    li   a7, 1    ecall                   # 21    li   a7, 10    ecallgcd:    beqz a1, base    addi sp, sp, -16    sw   ra, 12(sp)    rem  t0, a0, a1         # a % b    mv   a0, a1    mv   a1, t0    call gcd                # gcd(b, a % b)    lw   ra, 12(sp)         # 戻ってきても、することは片付けだけ    addi sp, sp, 16base:    ret

call を tail（戻り先を記録しないジャンプ）に替えると、フレームが丸ごと要らなくなります。

末尾呼び出し：call を tail に。再帰がループになる⌘↵
main:    li   a0, 1071    li   a1, 462    call gcd    li   a7, 1    ecall                   # 21    li   a7, 10    ecallgcd:    beqz a1, base    rem  t0, a0, a1         # a % b    mv   a0, a1    mv   a1, t0    tail gcd                # 戻り先（ra）は main のまま、先頭へ飛ぶbase:    ret

実行した命令数は 39 から 24 に減りました。それ以上に大きいのは、スタックを使わなくなったことです。再帰が何万回続いても、スタックがあふれません。C で再帰として書いた関数が、機械語ではただのループになっています。

深掘り最適化を支えているもの

最適化が「結果を変えない」と言い切れるのは、言語の決まりと呼び出し規約があるからです。たとえば、t0 は関数を呼ぶと壊れてよいという約束があるので、コンパイラは葉の関数で自由に t0 を使えます。逆に、C の決まりに反するプログラム（配列の外を読む、初期化していない変数を使う、など）は、最適化レベルを変えると動きが変わることがあります。「-O0 では動くのに -O2 では動かない」というバグは、たいていこれが原因です。

やってみよう
  1. 下の練習用のプログラムは、C の int f(int n) を訳したものです。C のコードに戻すとどうなるか、考えてください
  2. main の引数を 5 に変えたときの出力を予想してから、確かめてください
  3. mul を使わずに、同じ結果になるように書き換えてください（ヒント：前の周の値に何を足せば、次の値になるでしょうか）
練習用⌘↵
main:    li   a0, 4    call f    li   a7, 1    ecall    li   a7, 10    ecallf:    li   t0, 0              # s    li   t1, 1              # i    bgt  t1, a0, doneloop:    mul  t2, t1, t1    add  t0, t0, t2    addi t1, t1, 1    ble  t1, a0, loopdone:    mv   a0, t0    ret
要点この章のまとめ
  • コンパイラは C をアセンブリに、アセンブラはアセンブリを機械語に直し、リンカは機械語をつないで番地を決める
  • ローカル変数はレジスタに、グローバル変数と、& で番地を取られた変数はメモリに置く。変数の名前は機械語に残らない
  • 型は、命令の選び方（div と divu、srai と srli、lw と lh）と、番地の計算に掛ける数（int なら 4）になって消える
  • if は条件を逆にした分岐、ループは分岐と前へ戻るジャンプ。条件はループの末尾に置くと 1 周が短い
  • 関数は呼び出し規約どおりに訳す。ほかの関数を呼ぶ関数は、プロローグで ra と s レジスタを保存し、エピローグで戻す
  • a[i] は「先頭 + i × 要素の大きさ」、p->member は「先頭 + オフセット」。構造体には整列のための詰め物が入る
  • 最適化は、結果を変えずに命令を減らす。レジスタ割り付け、定数の畳み込み、軽い命令への置き換え、ループの外への移動、末尾呼び出し

20.10確認問題

C の関数を、自分でアセンブリに訳します。どの問題も、書くのは関数だけです。書いたコードの後ろに、その関数を呼んで結果を表示する main がつながって実行されます。呼び出し規約（引数は a0 から、戻り値は a0、s レジスタと sp は元に戻す）を守ってください。

問 1

式を訳す

正解済み

次の C の関数 f を、アセンブリに訳してください。

C
int f(int a, int b, int c) {    return (a + b) * c - a;}

main は、f(1, 2, 3)、f(10, -4, 7)、f(-5, 5, 9) の結果を 1 行ずつ表示します。

あなたのコードの後ろに、このコードがつながります
main:    li   a0, 1    li   a1, 2    li   a2, 3    call f    call show    li   a0, 10    li   a1, -4    li   a2, 7    call f    call show    li   a0, -5    li   a1, 5    li   a2, 9    call f    call show    li   a7, 10    ecallshow:    li   a7, 1    ecall    li   a0, '\n'    li   a7, 11    ecall    ret
f:    # a0 = a、a1 = b、a2 = c。結果を a0 に入れて ret
⌘↵コンソールの出力で判定
ヒント

a + b を作業用のレジスタ（t0 など）に入れ、c を掛けてから、a を引きます。a0 を先に書き換えると、最後に引く a がなくなるので注意します。

模範解答
f:    add  t0, a0, a1    mul  t0, t0, a2    sub  a0, t0, a0    ret
問 2

配列とループと if

正解済み

次の C の関数 sum_even を、アセンブリに訳してください。配列 a の n 個の要素のうち、偶数だけを合計して返します。

C
int sum_even(int *a, int n) {    int sum = 0;    for (int i = 0; i < n; i++) {        if (a[i] % 2 == 0) {            sum += a[i];        }    }    return sum;}

main は、3 つの配列（要素が 6 個、4 個、0 個）で呼んで、結果を 1 行ずつ表示します。

あなたのコードの後ろに、このコードがつながります
main:    la   a0, arr1    li   a1, 6    call sum_even    call show    la   a0, arr2    li   a1, 4    call sum_even    call show    la   a0, arr2    li   a1, 0    call sum_even    call show    li   a7, 10    ecallshow:    li   a7, 1    ecall    li   a0, '\n'    li   a7, 11    ecall    ret.dataarr1: .word 3, 8, -4, 7, 10, 1arr2: .word 5, -6, 9, 100
sum_even:    # a0 = 配列の先頭の番地、a1 = 要素の数。偶数の合計を a0 に入れて ret
⌘↵コンソールの出力で判定
ヒント

要素は 4 バイトごとに並びます。偶数かどうかは、andi で下の 1 ビットを取り出して 0 かどうかで調べられます（負の数でも使えます）。n が 0 のときは、1 回も読まずに 0 を返します。

模範解答
sum_even:    li   t0, 0    blez a1, doneloop:    lw   t1, 0(a0)    andi t2, t1, 1    bnez t2, skip    add  t0, t0, t1skip:    addi a0, a0, 4    addi a1, a1, -1    bnez a1, loopdone:    mv   a0, t0    ret
問 3

構造体のオフセット

正解済み

次の C の関数 total_area を、アセンブリに訳してください。

C
struct rect {    char tag;       // 1 バイト    int  w;         // 4 バイト    int  h;         // 4 バイト}; int total_area(struct rect *r, int n) {    int sum = 0;    for (int i = 0; i < n; i++) {        sum += r[i].w * r[i].h;    }    return sum;}

int は 4 の倍数の番地に置かれます。w と h のオフセットと、構造体 1 個の大きさを自分で求めてください。main は、3 個の配列と 1 個の配列で呼んで、結果を 1 行ずつ表示します。

あなたのコードの後ろに、このコードがつながります
main:    la   a0, rects    li   a1, 3    call total_area    call show    la   a0, one    li   a1, 1    call total_area    call show    li   a7, 10    ecallshow:    li   a7, 1    ecall    li   a0, '\n'    li   a7, 11    ecall    ret.datarects:    .byte 'a', 9, 9, 9    .word 3, 4    .byte 'b', 9, 9, 9    .word 10, 20    .byte 'c', 9, 9, 9    .word 7, 1one:    .byte 'z', 9, 9, 9    .word 6, 11
total_area:    # a0 = 配列の先頭の番地、a1 = 個数。面積（w × h）の合計を a0 に入れて ret
⌘↵コンソールの出力で判定
ヒント

tag は +0 の 1 バイトです。次の w は 4 の倍数にそろうので +4、h は +8、全体は 12 バイトです。本文の struct item の例と同じ形のループで書けます。

模範解答
total_area:    li   t0, 0    blez a1, doneloop:    lw   t1, 4(a0)    lw   t2, 8(a0)    mul  t1, t1, t2    add  t0, t0, t1    addi a0, a0, 12    addi a1, a1, -1    bnez a1, loopdone:    mv   a0, t0    ret
問 4

再帰とスタックフレーム

正解済み

次の C の関数 sum_digits を、アセンブリに訳してください。n（0 以上）の、10 進での各桁の和を返します。

C
int sum_digits(int n) {    if (n < 10) return n;    return n % 10 + sum_digits(n / 10);}

main は、s0〜s3 に値を入れたまま sum_digits を 3 回呼び、結果と、s0〜s3 の合計を表示します。s レジスタを使うなら、保存して元に戻してください。

あなたのコードの後ろに、このコードがつながります
main:    li   s0, 1000    li   s1, 200    li   s2, 30    li   s3, 4    li   a0, 7    call sum_digits    call show    li   a0, 2024    call sum_digits    call show    li   a0, 987654321    call sum_digits    call show    add  a0, s0, s1    add  a0, a0, s2    add  a0, a0, s3    call show    li   a7, 10    ecallshow:    li   a7, 1    ecall    li   a0, '\n'    li   a7, 11    ecall    ret
sum_digits:    # a0 = n。各桁の和を a0 に入れて ret
⌘↵コンソールの出力で判定
ヒント

n % 10 は、再帰の呼び出しから戻ったあとで使います。呼び出しで壊れない場所（s0 か、スタック）に取っておきます。call は ra を上書きするので、ra も保存が要ります。余りは rem、割り算は div です。

模範解答
sum_digits:    li   t0, 10    blt  a0, t0, base    addi sp, sp, -16    sw   ra, 12(sp)    sw   s0, 8(sp)    rem  s0, a0, t0    div  a0, a0, t0    call sum_digits    add  a0, s0, a0    lw   ra, 12(sp)    lw   s0, 8(sp)    addi sp, sp, 16base:    ret
