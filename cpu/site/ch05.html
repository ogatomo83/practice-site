第 5 章

足し算をする回路

ゲートを組み合わせて、2 進数の足し算をする回路（加算器）を作ります。1 ビットの足し算から始めて、4 ビット、8 ビットへ伸ばし、同じ回路で引き算もできるようにします。

9 節図 5 点実行できる回路 12 個確認問題 4 問目安 70 分

5.11 ビットの足し算

前の章で作ったゲートは、0 と 1 を見て 0 か 1 を返すだけの部品でした。この章では、それを組み合わせて数の計算をさせます。最初の目標は足し算です。

いちばん小さな足し算は、1 ビットどうしの足し算です。場合は 4 つしかありません。

aba + b（2 進）上の桁下の桁
000000
010101
100101
111010

1 + 1 は 2 で、2 進数では 10 です。1 桁に収まらないので、上の桁に 1 が繰り上がります。答えは 2 ビット必要です。

この表の右の 2 列を、前の章の真理値表と見比べてください。

  • 下の桁は、a と b が違うとき 1。これは XOR の真理値表
  • 上の桁（繰り上がり）は、a と b が両方 1 のとき 1。これは AND の真理値表

足し算の表が、そのままゲートの表になっています。数の計算と、0 と 1 の論理が、ここでつながります。

5.2半加算器

XOR と AND を 1 個ずつ並べれば、1 ビットの足し算の回路になります。これを半加算器（half adder）と呼びます。下の桁を s（sum、和）、繰り上がりを c（carry）と名付けます。

半加算器⌘↵
in a, bout c, ss = a xor bc = a and b

出力を c、s の順に並べたので、表の右の 2 列を続けて読むと、そのまま 2 進数の答えになります。00、01、01、10 です。

5.3全加算器

半加算器だけでは、2 桁以上の足し算はできません。筆算を思い出してください。

  1 1        ← 繰り上がり  0 1 1 1    （7）+ 0 0 1 1    （3）---------  1 0 1 0    （10）

いちばん下の桁は 2 つの数を足すだけです。しかし 2 桁目からは、下の桁からの繰り上がりも足します。1 つの桁で足す数は 3 つです。

入力が 3 本（a、b、下からの繰り上がり cin）ある 1 ビットの足し算の回路を、全加算器（full adder）と呼びます。出力は半加算器と同じく、その桁の答え s と、上の桁への繰り上がり cout です。

全加算器は、半加算器を 2 個使って作れます。まず a と b を足し、その答えに cin を足します。繰り上がりは、どちらかの足し算で出れば出ます。

部品として名前を付ける

同じ形の回路を何度も使うときは、def で部品にします。プログラムの関数にあたるものです。

半加算器 2 個で全加算器⌘↵
def ha(a, b) -> (s, c) {     # 部品 ha：入力 a, b、出力 s, c  s = a xor b  c = a and b}in a, b, cinout cout, ss1, c1 = ha(a, b)            # 1 個目：a + bs, c2 = ha(s1, cin)          # 2 個目：その答え + cincout = c1 or c2              # どちらかで繰り上がれば、繰り上がり

入力が 3 本なので 8 行です。右の 2 列を 2 進数として読むと、3 本の入力のうち 1 がいくつあるかになっています。全部 0 なら 00（0 個）、全部 1 なら 11（3 個）です。全加算器は「1 の数を数える回路」とも言えます。

表の下には「ゲート 5 個（XOR 2、AND 2、OR 1）」と出ます。部品を 2 回使ったので、中のゲートも 2 個ずつ数えられています。

メモ2 つの繰り上がりは同時には出ない

c1 と c2 が両方 1 になることはありません。c1 が 1 なら a と b は両方 1 で、そのとき s1 は 0 です。s1 が 0 なら、2 個目の半加算器は繰り上がりを出せません。だから、まとめるのは OR 1 個で足ります。

5.44 ビットの加算器

全加算器を桁の数だけ並べて、繰り上がりを隣へ渡していけば、何ビットの足し算でもできます。筆算と同じやり方です。

いちばん下の桁には、下からの繰り上がりがありません。そこで cin には 0 を入れておきます。いちばん上の桁の繰り上がり cout は、5 ビット目の答えとして外に出します。

回路で書くと次のようになります。a[4] は 4 本の線の束（バス）で、a[0] がいちばん下の桁です。

4 ビットの加算器⌘↵
def fa(a, b, cin) -> (s, cout) {  p = a xor b  s = p xor cin  cout = (a and b) or (p and cin)}in a[4], b[4]out cout, s[4]wire c[5]                               # 繰り上がりの線を 5 本用意するc[0] = 0                                # いちばん下には繰り上がりがないs[0], c[1] = fa(a[0], b[0], c[0])s[1], c[2] = fa(a[1], b[1], c[1])s[2], c[3] = fa(a[2], b[2], c[2])s[3], c[4] = fa(a[3], b[3], c[3])cout = c[4]test a=7, b=3test a=5, b=9test a=6, b=6

7 + 3 = 10、5 + 9 = 14、6 + 6 = 12。XOR と AND と OR だけで、足し算ができました。使ったゲートは 20 個です。test の行の数を書き換えて、好きな足し算を試してみてください。

wire c[5] は、途中の線の束を先に用意する書き方です。c[1] のように 1 本ずつ値を入れるときに使います。部品 fa の中身は、前の節の「半加算器 2 個と OR」を 1 つにまとめたものです。

4 ビットに収まらないとき

4 ビットで表せる数は 0 から 15 までです。答えが 16 以上になると、どうなるでしょうか。

答えが 15 を超える⌘↵
def fa(a, b, cin) -> (s, cout) {  p = a xor b  s = p xor cin  cout = (a and b) or (p and cin)}in a[4], b[4]out cout, s[4]wire c[5]c[0] = 0s[0], c[1] = fa(a[0], b[0], c[0])s[1], c[2] = fa(a[1], b[1], c[1])s[2], c[3] = fa(a[2], b[2], c[2])s[3], c[4] = fa(a[3], b[3], c[3])cout = c[4]test a=15, b=1test a=9, b=8test a=15, b=15

15 + 1 は、s が 0 で cout が 1 です。正しい答えの 16 は 2 進数で 10000 なので、下の 4 ビットが s、あふれた 5 ビット目が cout に出ています。9 + 8 = 17 は s が 1、15 + 15 = 30 は s が 14 で、どちらも cout が 1 です。cout は 16 の位だと考えれば、つじつまが合います。

第 2 章で見た「桁あふれ」は、この cout を捨てたときに起こります。s だけを見ると、15 + 1 が 0 に戻ってしまいます。

5.5繰り上がりが伝わる遅さ

この加算器には、弱点が 1 つあります。上の桁は、下の桁の繰り上がりが届くまで、答えを決められないのです。

7 + 1（0111 + 0001）を例に、繰り上がりが伝わる様子を追ってみましょう。

繰り上がりが、さざ波（ripple）のように 1 段ずつ伝わっていくので、この作りをリップルキャリー加算器と呼びます。

ゲートは、入力が変わってから出力が変わるまでに、ほんの少し時間がかかります。上の fa では、cin から cout までに AND と OR の 2 個のゲートを通ります。4 ビットなら 4 段でおよそ 8 個分、32 ビットなら 32 段でおよそ 64 個分の時間を、最悪の場合には待つことになります。

深掘り速い加算器

実際の CPU は、繰り上がりを 1 段ずつ待たない加算器を使っています。代表が桁上げ先見加算器（carry-lookahead adder）です。各桁について「この桁だけで繰り上がりが出るか」「下から来た繰り上がりを上へ通すか」を先に計算しておき、そこから何桁分もの繰り上がりを一気に求めます。ゲートの数は増えますが、待ち時間は桁数に比例しなくなります。「ゲートを増やして時間を買う」のは、回路の設計でよく出てくる取り引きです。

8 ビットに伸ばす

部品は、別の部品の中でも使えます。4 ビットの加算器を部品 add4 にして、2 個つなげば 8 ビットです。下の 4 ビットの cout を、上の 4 ビットの cin につなぎます。

8 ビットの加算器⌘↵
def fa(a, b, cin) -> (s, cout) {  p = a xor b  s = p xor cin  cout = (a and b) or (p and cin)}def add4(a[4], b[4], cin) -> (s[4], cout) {  s[0], c1 = fa(a[0], b[0], cin)  s[1], c2 = fa(a[1], b[1], c1)  s[2], c3 = fa(a[2], b[2], c2)  s[3], cout = fa(a[3], b[3], c3)}in a[8], b[8]out cout, s[8]lo, c = add4(a[3:0], b[3:0], 0)          # 下の 4 ビットhi, cout = add4(a[7:4], b[7:4], c)       # 上の 4 ビットs = {hi, lo}                             # 2 つを連結して 8 ビットにtest a=100, b=55test a=200, b=100test a=255, b=1

a[3:0] はバスの一部（3 番から 0 番までの 4 本）を取り出す書き方、{hi, lo} は 2 つのバスを連結する書き方です（左が上の桁）。100 + 55 = 155 は 8 ビットに収まります。200 + 100 = 300 は収まらず、s は 44（300 − 256）で cout が 1 になります。

同じやり方で 32 ビットにも伸ばせます。ゲートの数は、8 ビットで 40 個、32 ビットなら 160 個です。

これからは + と書く

足し算の回路の中身は、もうわかりました。ここから先は、加算器を 1 つの部品として + で書きます。

+ は加算器⌘↵
in a[8], b[8]out s[8]s = a + btest a=100, b=55test a=200, b=100

上の 8 ビットの加算器と、s は同じ値になります。+ の結果の幅は入力と同じで、あふれた繰り上がりは捨てられます。

5.6引き算は足し算でできる

足し算ができたので、次は引き算です。引き算のための回路を新しく設計する必要はありません。第 3 章の 2 の補数を使えば、いま作った加算器がそのまま使えます。

第 3 章で見たとおり、2 の補数では、数の符号を変えるには「全ビットを反転して 1 を足す」のでした。つまり、次のように書き換えられます。

a - b  =  a + (-b)  =  a + (not b) + 1
  • 「全ビットを反転」は、NOT を並べるだけ
  • 「1 を足す」には、うまい手があります。いちばん下の桁の cin は 0 にしてありました。ここに 1 を入れれば、それだけで 1 が足されます

加算器を 1 個も増やさずに、引き算ができます。

足し算だけで引き算をする⌘↵
in a[4], b[4]out y[4]y = a + (not b) + 1test a=7, b=3test a=9, b=9test a=3, b=5

7 − 3 = 4、9 − 9 = 0 になりました。3 − 5 は 14 と表示されます。14 は 2 進数で 1110 で、これは 4 ビットの 2 の補数では −2 です（14 − 16 = −2）。表は符号なしの数として表示しているだけで、ビットの並びは正しい答えになっています。

この回路記述では、引き算も - で書けます。中身は上と同じです。

- と比べる⌘↵
in a[4], b[4]out y1[4], y2[4]y1 = a + (not b) + 1y2 = a - btest a=7, b=3test a=3, b=5test a=0, b=1test a=12, b=15

5.7加減算器：1 本の信号で切り替える

足し算と引き算の違いは、「b を反転するか」と「cin が 0 か 1 か」の 2 点だけでした。この 2 つを、1 本の信号 sub で切り替えられるようにします。

ここで、前の章の XOR の 2 つ目の見方が役に立ちます。XOR は条件付きの反転でした。b xor sub は、sub が 0 なら b のまま、sub が 1 なら b の反転です。

XOR で、反転するかどうかを選ぶ⌘↵
in b[4], subout x[4]x = b xor subtest b=0b0101, sub=0test b=0b0101, sub=1

表の「2 進で表示」を押すと、sub が 1 の行で 0101 が 1010 にひっくり返っているのがわかります。4 ビットのバスと 1 ビットの線を XOR すると、1 ビットの線が 4 本すべてに配られます。

これを加算器の手前に置き、同じ sub を cin にも入れます。

加減算器⌘↵
in a[4], b[4], subout y[4]x = b xor sub          # sub が 1 なら b を反転y = a + x + sub        # sub が 1 なら、さらに 1 を足すtest a=9, b=4, sub=0test a=9, b=4, sub=1test a=4, b=9, sub=0test a=4, b=9, sub=1

9 + 4 = 13、9 − 4 = 5、4 + 9 = 13、4 − 9 = 11（1011、2 の補数で −5）です。1 つの加算器が、sub の値しだいで足し算も引き算もします。

CPU の中にあるのは、まさにこの回路です。第 10 章で使う RISC-V の add 命令と sub 命令は、同じ加算器を使い、sub にあたる 1 本の信号だけが違います。

メモ符号付きでも符号なしでも、同じ回路

この加減算器は、入力が符号なしの数（0〜15）でも、2 の補数の符号付きの数（−8〜7）でも、同じように正しく働きます。4 − 9 の答え 1011 は、符号なしで読めば 11、符号付きで読めば −5 です。回路はビットを足しているだけで、どちらで読むかは使う側が決めます。2 の補数が広く使われているのは、このように加算器が 1 種類で済むからです。

5.8オーバーフローを見つける

最後に、答えが決められた幅に収まらなかったこと（オーバーフロー）を、回路で見つける方法を考えます。見つけ方は、符号なしと符号付きで違います。

符号なし：いちばん上の繰り上がり

符号なしの足し算では、いちばん上の桁からの繰り上がり cout が 1 なら、答えは収まっていません。これはすでに見ました。

符号付き：符号がおかしくなる

符号付きでは事情が変わります。4 ビットの符号付きの数は −8 から 7 までです。5 + 3 を計算してみます。

  0101    （5）+ 0011    （3）------  1000    （符号付きで読むと −8）

cout は 0 なのに、答えの符号が変わってしまいました。正しい答えの 8 は、4 ビットの符号付きでは表せないからです。

第 3 章で見たとおり、符号付きのオーバーフローが起こるのは、同じ符号の数を足したのに、答えの符号が違うときです。正 + 正が負になるか、負 + 負が正になる場合です。符号はいちばん上のビットなので、この条件はゲートで書けます。

オーバーフローの検出⌘↵
in a[4], b[4], subout y[4], cout, vx = b xor subt = {0, a} + {0, x} + sub        # 5 ビットで計算して、繰り上がりも取り出すy = t[3:0]cout = t[4]v = (a[3] xnor x[3]) and (a[3] xor y[3])   # 足す 2 数の符号が同じで、答えの符号が違うtest a=5, b=3, sub=0test a=7, b=1, sub=0test a=15, b=1, sub=0test a=8, b=1, sub=1test a=5, b=3, sub=1

{0, a} は、a の上に 0 を 1 ビット付けて 5 ビットに広げる書き方です。結果を 1 行ずつ読んでみます。

計算ycoutv符号なしで読むと符号付きで読むと
5 + 38018（正しい）−8（あふれた）
7 + 18018（正しい）−8（あふれた）
15 + 10100（あふれた）−1 + 1 = 0（正しい）
8 − 17117（正しい）−8 − 1 が 7（あふれた）
5 − 32102（正しい）2（正しい）

符号なしのあふれは cout、符号付きのあふれは v と、別々の信号でわかります。15 + 1 は、符号なしではあふれていますが、符号付きでは −1 + 1 = 0 という正しい計算です。

引き算のときの cout にも注目してください。5 − 3 のように引ける場合は cout が 1、引けない場合（a が b より小さい場合）は cout が 0 になります。次の章で、これを大小の比較に使います。

コツもう 1 つの見つけ方

符号付きのオーバーフローは、「いちばん上の桁に入る繰り上がり」と「いちばん上の桁から出る繰り上がり」が違うとき、とも言えます。全加算器を並べた回路なら c[3] xor c[4] の XOR 1 個で済みます。確認問題の別解に使えます。

やってみようやってみよう

下は 4 ビットの加減算器です。

  1. test の数を書き換えて、12 - 5、5 - 12、0 - 1 を計算する。答えを 2 進で表示して、2 の補数として読んでみる
  2. a と b を [8] に変えて、8 ビットにする。200 - 100 と 100 - 200 を試す
  3. 出力を out y[4], z にして、z = not (y[0] or y[1] or y[2] or y[3]) を足す。z は「答えが 0 のとき 1」になる線です。a と b が等しい引き算で 1 になることを確かめる
練習用：加減算器⌘↵
in a[4], b[4], subout y[4]x = b xor suby = a + x + subtest a=12, b=5, sub=1
要点この章のまとめ
  • 1 ビットの足し算は、下の桁が XOR、繰り上がりが AND。この 2 個で半加算器になる
  • 全加算器は、下の桁からの繰り上がりも入れて 3 つを足す。半加算器 2 個と OR 1 個（ゲート 5 個）で作れる
  • 全加算器を桁の数だけ並べ、繰り上がりを隣へ渡すと、何ビットでも足せる（リップルキャリー加算器）。繰り上がりが 1 段ずつ伝わるので、桁が多いほど遅い
  • def で回路を部品にできる。部品の中で別の部品も使える
  • 引き算は、反転して 1 を足す足し算：a - b = a + (not b) + 1。1 を足すには cin に 1 を入れる
  • b xor sub で反転を切り替えれば、1 つの加算器で足し算と引き算ができる（加減算器）。符号付きでも符号なしでも同じ回路で済む
  • オーバーフローは、符号なしなら cout、符号付きなら「同じ符号を足したのに答えの符号が違う」で見つける

5.9確認問題

この章の内容を、自分で回路を書いて確かめます。入力と出力の名前、ビットの幅は、問題文のとおりにしてください。

問 1

1 の数を数える

正解済み

1 ビットの入力 a、b、c と、2 ビットの出力 n（out n[2]）を持つ回路を書いてください。n は、3 本の入力のうち 1 になっている本数（0〜3）にします。

たとえば a = 1、b = 0、c = 1 なら n は 2 です。

in a, b, cout n[2]n[0] = n[1] =
⌘↵出力の表で判定
ヒント

全加算器そのものです。n[0]（1 の位）が全加算器の s、n[1]（2 の位）が cout にあたります。

模範解答
in a, b, cout n[2]p = a xor bn[0] = p xor cn[1] = (a and b) or (p and c)
問 2

2 ビットの加算器をゲートで作る

正解済み

2 ビットの入力 a、b（in a[2], b[2]）と、3 ビットの出力 s（out s[3]）を持つ回路を書いてください。s は a + b です。繰り上がりは s[2] に出します（3 + 3 なら s は 6）。

+ と - は使えません。and、or、xor、not などのゲートだけで作ってください。def は使えます。

in a[2], b[2]out s[3]
⌘↵出力の表で判定（使えるゲートは AND・OR・XOR・NOT・NAND・NOR・XNOR だけ）
ヒント

1 の位は半加算器（または cin を 0 にした全加算器）、2 の位は全加算器です。2 の位の繰り上がりを、そのまま s[2] に入れます。

模範解答

問 3

1 を足すだけの回路

正解済み

4 ビットの入力 a（in a[4]）と、4 ビットの出力 y（out y[4]）を持つ回路を書いてください。y は a + 1 です。a が 15 のときは 0 に戻します。

使ってよいゲートは and、xor、not だけで、個数は 7 個以下にしてください。+ は使えません。

in a[4]out y[4]
⌘↵出力の表で判定（使えるゲートは AND・XOR・NOT だけ、ゲートは 7 個まで）
ヒント

足す相手が 1 と決まっているので、全加算器は要りません。1 の位は「a[0] + 1」なので、答えは a[0] の反転、繰り上がりは a[0] そのものです。2 の位から上は、その桁と下からの繰り上がりを足す半加算器（XOR と AND）で足ります。いちばん上の桁の繰り上がりは捨てるので、AND は作らなくてかまいません。

模範解答
in a[4]out y[4]y[0] = not a[0]c1 = a[0]y[1] = a[1] xor c1c2 = a[1] and c1y[2] = a[2] xor c2c3 = a[2] and c2y[3] = a[3] xor c3
問 4

オーバーフローを知らせる加減算器

正解済み

4 ビットの入力 a、b と 1 ビットの入力 sub（in a[4], b[4], sub）、4 ビットの出力 y と 1 ビットの出力 v（out y[4], v）を持つ回路を書いてください。

  • sub が 0 なら y は a + b、1 なら y は a − b（どちらも下の 4 ビット）
  • v は、a と b を 4 ビットの符号付きの数（2 の補数）として見たときに、答えが −8〜7 に収まらなければ 1、収まれば 0

+ と - は使えます。

in a[4], b[4], subout y[4], v
⌘↵出力の表で判定
ヒント

本文の「オーバーフローの検出」と同じです。引き算のときは、b ではなく反転した後の x の符号と比べる点に気を付けてください。a − b は a + (not b) + 1 という足し算として計算されるからです。

模範解答
in a[4], b[4], subout y[4], vx = b xor suby = a + x + subv = (a[3] xnor x[3]) and (a[3] xor y[3])
