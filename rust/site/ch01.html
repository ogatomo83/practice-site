第 1 章

事始め

Rust をインストールし、最初のプログラムを書いて動かします。rustc で直接コンパイルする方法と、実際の開発で使う cargo の両方を体験します。

4 節図 5 点目安 30 分

1.1インストール

Rust のインストールには、公式のインストーラ兼バージョン管理ツール rustup を使います。rustup を入れると、次の 3 つがまとめて手に入ります。

macOS / Linux

ターミナルで次のコマンドを実行します。

ターミナル
$ curl --proto '=https' --tlsv1.2 https://sh.rustup.rs -sSf | sh

インストールが終わると、次のメッセージが表示されます。

ターミナル
Rust is installed now. Great!

Rust のコンパイラは最後の仕上げ（リンク）にリンカという別のプログラムを使います。「linker cc not found」のようなエラーが出たら、C コンパイラを入れてください。

  • macOS: xcode-select --install
  • Ubuntu など: sudo apt install build-essential

Windows

rustup.rs から rustup-init.exe をダウンロードして実行します。途中で Visual Studio の C++ ビルドツールを求められたら、指示どおりにインストールしてください。

インストールできたか確かめる

ターミナル
$ rustc --versionrustc 1.82.0 (f6e511eec 2024-10-15)

rustc バージョン番号 (コミットハッシュ 日付) の形式で表示されれば成功です。表示されない場合は、~/.cargo/bin に PATH が通っているか確認してください（ターミナルを開き直すと直ることが多いです）。

更新とアンインストール

やりたいことコマンド
Rust を最新版に更新するrustup update
Rust と rustup を削除するrustup self uninstall
手元でドキュメントを開くrustup doc
標準ライブラリのドキュメントを開くrustup doc --std
コツドキュメントはオフラインでも読める

rustup doc は、インストールに含まれるドキュメント一式をブラウザで開きます。この本の英語原典や標準ライブラリのリファレンスも入っているので、ネットにつながっていなくても調べものができます。

1.2Hello, World!

伝統にならって、画面に Hello, world! と表示するプログラムから始めます。

プロジェクト用のディレクトリを作る

どこに置いてもかまいませんが、この本ではホームディレクトリに projects を作ることにします。

ターミナル
$ mkdir ~/projects$ cd ~/projects$ mkdir hello_world$ cd hello_world

プログラムを書く

main.rs というファイルを作り、次のように書きます。Rust のソースファイルの拡張子は .rs で、ファイル名が複数の単語からなる場合はアンダースコアでつなぐのが慣習です（hello_world.rs）。

main.rs
fn main() {    println!("Hello, world!");}

コンパイルして実行する

ターミナル
$ rustc main.rs$ ./mainHello, world!

Windows では ./main の代わりに .\main.exe です。Hello, world! と表示されたら、あなたはもう Rust プログラマです。

プログラムを分解する

たった 3 行ですが、Rust の基本がいくつも詰まっています。

  • fn main() { } は main という名前の関数を定義しています。main は特別な関数で、実行可能な Rust プログラムは必ずここから始まります。引数はなく、何も返しません。
  • インデントはスペース 4 つが標準です。タブは使いません。rustfmt というツール（付録 D）が自動で整形してくれます。
  • println! の ! は、これが普通の関数ではなくマクロであることを示しています。マクロはコードを生成するコードで、普通の関数にはできないこと（引数の数が可変、など）ができます。詳しくは第 19 章で扱います。今は「! が付いていたらマクロ」とだけ覚えておけば十分です。
  • 行末の ; は、その式が終わったことを示します。Rust のほとんどの行はセミコロンで終わります。

コンパイルと実行は別の段階

Ruby や Python、JavaScript のような言語では、1 つのコマンドでプログラムを実行します。Rust は事前コンパイル（ahead-of-time compilation）型の言語なので、「コンパイル」と「実行」が分かれています。

コンパイルした実行ファイルを渡せば、相手のマシンに Rust が入っていなくても動きます。Python のスクリプトを渡すと相手に Python が必要なのとは対照的です。

小さなプログラムなら rustc だけで十分ですが、プロジェクトが大きくなると、ファイルや依存ライブラリの管理が大変になります。そこで登場するのが Cargo です。

1.3Hello, Cargo!

Cargo は Rust のビルドシステム兼パッケージマネージャです。Rust のプロジェクトはほぼすべて Cargo で管理されています。Cargo は次のような仕事をまとめて引き受けてくれます。

  • コードのビルド
  • 依存しているライブラリ（クレートと呼びます）のダウンロードとビルド
  • テストの実行、ドキュメントの生成、公開

rustup で Rust を入れたなら、Cargo もすでに入っています。

ターミナル
$ cargo --versioncargo 1.82.0 (8f40fc59f 2024-08-21)

Cargo でプロジェクトを作る

ターミナル
$ cd ~/projects$ cargo new hello_cargo$ cd hello_cargo

cargo new は、次のようなディレクトリ構成を作ります。

Cargo.toml の中身を見てみましょう。

Cargo.toml
[package]name = "hello_cargo"version = "0.1.0"edition = "2021" [dependencies]

これは TOML（Tom's Obvious, Minimal Language）という形式の設定ファイルです。

部分意味
[package]ここから下がパッケージの設定であることを示す見出し
name, versionパッケージの名前とバージョン
edition使う Rust のエディション（付録 E）。言語の大きな版のようなもの
[dependencies]依存するクレートを書く場所。今は空

src/main.rs には、さっき書いたものと同じ Hello, world! がすでに用意されています。

ビルドと実行

ターミナル
$ cargo build   Compiling hello_cargo v0.1.0 (/Users/you/projects/hello_cargo)    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.52s$ ./target/debug/hello_cargoHello, world!

cargo build は、実行ファイルを target/debug/hello_cargo に作ります。ビルドと実行を 1 回でやりたいなら cargo run です。

ターミナル
$ cargo run    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.01s     Running `target/debug/hello_cargo`Hello, world!

2 回目は Compiling の行が出ていません。ソースが変わっていないので、Cargo はビルドを省略して前回の実行ファイルをそのまま使ったのです。

よく使う Cargo コマンド

コマンドすることいつ使う
cargo new 名前新しいプロジェクトを作る最初に 1 回
cargo checkコンパイルできるかだけ確かめる（実行ファイルは作らない）書いている途中に何度も
cargo buildデバッグ用にビルドする実行ファイルが欲しいとき
cargo runビルドして実行する動作を確かめるとき
cargo build --release最適化を有効にしてビルドする完成品・速度の計測

cargo check は実行ファイルを作る段階を省くので、cargo build よりずっと速く終わります。書きながら cargo check を何度も走らせて、コンパイラに間違いを指摘してもらうのが Rust らしい書き方です。

リリースビルド

cargo build --release は、時間をかけて最適化した実行ファイルを target/release/ に作ります。コンパイルは遅くなりますが、できたプログラムはずっと速く動きます。速度を測るときは、必ずリリースビルドで測ってください。

慣習としての Cargo

どんな Rust プロジェクトでも、Git でクローンしてきたら次の 3 行で動かせます。これが Cargo を使う最大の利点です。

ターミナル
$ git clone example.org/someproject$ cd someproject$ cargo build

1.4この章のまとめ

  • rustup で Rust をインストール・更新する
  • rustc でファイルを直接コンパイルできるが、普段は cargo を使う
  • cargo new でプロジェクトを作り、cargo check / cargo run / cargo build --release を使い分ける
  • ! の付いた println! はマクロ
