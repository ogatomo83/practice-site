第 8 章

一般的なコレクション

実行中に伸び縮みする 3 つの定番コレクション、ベクタ・文字列・ハッシュマップ。どれも中身はヒープにあり、所有権と借用のルールがそのまま効いてきます。

5 節図 7 点目安 60 分

8.1コレクションとは

配列やタプルは、要素の数がコンパイル時に決まっていて、スタックに置かれます。一方、標準ライブラリのコレクションは、データをヒープに置くので、実行中に要素を増やしたり減らしたりできます。

この章では、最もよく使う 3 つを扱います。

コレクション何を保持するか似ているもの
Vec<T>同じ型の値の並び他の言語の動的配列・リスト
StringUTF-8 でエンコードされた文字の並び文字列
HashMap<K, V>キーと値の組辞書、連想配列、マップ

8.2ベクタで値のリストを持つ

ベクタ Vec<T> は、同じ型の値をメモリ上に隣り合わせで並べて持つコレクションです。

作る

Rust
let v: Vec<i32> = Vec::new();   // 空のベクタ。要素の型を推論できないので注釈が必要 let v = vec![1, 2, 3];          // 初期値があるなら vec! マクロが便利。型は Vec<i32> と推論される

追加する

Rust
let mut v = Vec::new(); v.push(5);v.push(6);v.push(7);v.push(8);

push で後ろに要素を追加します。中身を変えるので、mut が必要です。追加した値から、型は Vec<i32> と推論されます。

ベクタの中身はどうなっているか

Vec<T> の実体は、String と同じく「ポインタ・長さ・容量」の 3 つ組です。長さ（len）は今入っている要素の数、容量（capacity）は再確保なしで入れられる要素の数です。

容量がいっぱいの状態で push すると、ベクタはもっと大きな領域を新しく確保し、全要素をコピーして、古い領域を解放します。

この「引っ越し」が、次の節で出てくる借用エラーの理由になります。

要素を読む

要素を読む方法は 2 つあります。

Rust
let v = vec![1, 2, 3, 4, 5]; let third: &i32 = &v[2];        // 添字で参照を得るprintln!("The third element is {third}"); let third: Option<&i32> = v.get(2);   // get で Option を得るmatch third {    Some(third) => println!("The third element is {third}"),    None => println!("There is no third element."),}

2 つの違いは、範囲外の添字を渡したときに現れます。

Rust実行時にパニックする
let v = vec![1, 2, 3, 4, 5]; let does_not_exist = &v[100];      // パニックするlet does_not_exist = v.get(100);   // None が返る
書き方範囲外のとき向いている場面
&v[i]パニックしてプログラムが止まる範囲外になることはあり得ない（バグ）とき
v.get(i)None を返すユーザー入力など、範囲外も普通に起こるとき

借用ルールとベクタ

次のコードはコンパイルできません。

Rustコンパイルエラーになる
let mut v = vec![1, 2, 3, 4, 5]; let first = &v[0];      // 1 つ目の要素への不変参照 v.push(6);              // ベクタを変更（可変の借用） println!("The first element is: {first}");
ターミナル
error[E0502]: cannot borrow `v` as mutable because it is also borrowed as immutable --> src/main.rs:6:5  |4 |     let first = &v[0];  |                  - immutable borrow occurs here5 |6 |     v.push(6);  |     ^^^^^^^^^ mutable borrow occurs here7 |8 |     println!("The first element is: {first}");  |                                     ------- immutable borrow later used here

「最初の要素を参照しているだけなのに、末尾に追加して何が悪いの？」と思うかもしれません。理由はさっきの「引っ越し」です。

ベクタの要素への参照を持ったままベクタを変更できないのは、この危険があるからです。

走査する

for ループで全要素を順に処理できます。

Rust
let v = vec![100, 32, 57];for i in &v {               // 不変参照で走査    println!("{i}");} let mut v = vec![100, 32, 57];for i in &mut v {           // 可変参照で走査して書き換える    *i += 50;               // * で参照外しをして、指す先の値を変える}

*i の * は参照外し演算子です。i は &mut i32 という参照なので、その指す先の値を変えるには * で「参照の先」を指定します。第 15 章で詳しく扱います。

走査中に要素を追加・削除しようとすると、さっきと同じ理由でコンパイルエラーになります。for ループが持っている参照が、ベクタ全体の同時変更を防ぐのです。

enum で複数の型を入れる

ベクタには同じ型の値しか入れられません。でも、表計算のある行のように、整数・浮動小数・文字列が混ざったデータを扱いたいこともあります。そんなときは、enum でまとめます。

Rust
enum SpreadsheetCell {    Int(i32),    Float(f64),    Text(String),} let row = vec![    SpreadsheetCell::Int(3),    SpreadsheetCell::Text(String::from("blue")),    SpreadsheetCell::Float(10.12),];

enum のすべての列挙子は同じ型なので、1 つのベクタに入れられます。そして取り出すときは match で処理するので、どの型の場合も漏れなく扱えます。

ドロップ

ベクタもスコープを抜けると drop され、中の要素もすべて一緒に drop されます。

Rust
{    let v = vec![1, 2, 3, 4];    // v を使う}   // v がスコープを抜け、v とその要素が解放される

8.3文字列で UTF-8 テキストを扱う

Rust を始めたばかりの人がつまずきやすいのが文字列です。理由は 3 つあります。

  1. Rust はエラーになり得る部分を表に出す設計になっている
  2. 文字列は多くの人が思っているより複雑なデータ構造である
  3. UTF-8 の扱い

「文字列」は 2 種類

Rust の言語の中核にある文字列型は、文字列スライス &str だけです。一方、標準ライブラリが提供する String は、伸び縮みでき、可変で、所有権を持つ UTF-8 の文字列です。「文字列」と言うとき、Rust のプログラマはこのどちらか、あるいは両方を指しています。

String&str
所有権持つ持たない（借用）
変更できる（mut なら）できない
データの場所ヒープどこでも（ヒープ・静的領域・スタック）
典型的な使い方文字列を作る・組み立てる関数の引数で文字列を受け取る

作る

Rust
let mut s = String::new();             // 空の String let data = "initial contents";let s = data.to_string();              // &str から String へlet s = "initial contents".to_string();let s = String::from("initial contents"); // to_string と同じ

String は UTF-8 なので、どんな言語の文字も入れられます。

Rust
let hello = String::from("السلام عليكم");let hello = String::from("Dobrý den");let hello = String::from("こんにちは");let hello = String::from("안녕하세요");let hello = String::from("你好");let hello = String::from("Здравствуйте");

追加する

Rust
let mut s = String::from("foo");s.push_str("bar");      // 文字列スライスを追加。所有権は取らないs.push('l');            // 1 文字（char）を追加// s は "foobarl"

push_str は &str を受け取るので、渡した文字列の所有権を奪いません。

Rust
let mut s1 = String::from("foo");let s2 = "bar";s1.push_str(s2);println!("s2 is {s2}");   // s2 はまだ使える

+ 演算子と format!

2 つの文字列をつなぐには + が使えます。

Rust
let s1 = String::from("Hello, ");let s2 = String::from("world!");let s3 = s1 + &s2;   // s1 はムーブされ、もう使えない

s1 は使えなくなり、s2 は & が付いています。これは、+ が次のようなシグネチャのメソッドを呼んでいるからです。

Rust
fn add(self, s: &str) -> String {
  • add は self を受け取るので、s1 の所有権は add にムーブされ、結果として s3 に移ります
  • 2 つ目の引数は &str です。&s2 は &String ですが、参照外し型強制（deref coercion）によって自動で &s2[..] に変換されます（第 15 章）

たくさんの文字列をつなぐなら、format! マクロのほうが読みやすくなります。format! は println! と同じ書き方で、画面に表示する代わりに String を返します。引数の所有権も取りません。

Rust
let s1 = String::from("tic");let s2 = String::from("tac");let s3 = String::from("toe"); let s = s1 + "-" + &s2 + "-" + &s3;     // 読みにくいlet s = format!("{s1}-{s2}-{s3}");      // 読みやすく、s1 も使い続けられる

添字アクセスはできない

多くの言語では s[0] で文字列の 1 文字目が取れます。Rust ではコンパイルエラーになります。

Rustコンパイルエラーになる
let s1 = String::from("hello");let h = s1[0];
ターミナル
error[E0277]: the type `str` cannot be indexed by `{integer}` --> src/main.rs:3:16  |3 |     let h = s1[0];  |                ^ string indices are ranges of `usize`  |  = help: the trait `SliceIndex<str>` is not implemented for `{integer}`  = note: you can use `.chars().nth()` or `.bytes().nth()`

なぜでしょうか。String の中身が、UTF-8 でエンコードされたバイトの並びだからです。

"Hola" の長さ（len()）は 4 ですが、"Здравствуйте" は 12 文字なのに長さは 24、"こんにちは" は 5 文字なのに 15 です。len() が返すのはバイト数だからです。

もし s[0] が使えたとして、"Здравствуйте"[0] は何を返すべきでしょう。最初のバイトは 208 ですが、これ単体では文字として意味を持ちません。ユーザーが期待しているのはおそらく З ですが、それは 2 バイトの組で表されています。

Rust は、意味のない値を黙って返してバグを生むより、最初からコンパイルさせない道を選びました。

バイト・スカラー値・書記素クラスタ

もう 1 つの理由は、テキストを見る「単位」が 3 通りあることです。ヒンディー語の「नमस्ते」（デーヴァナーガリー文字）を例にとると、次のようになります。

見方内容数
バイト（u8）[224, 164, 168, 224, 164, 174, …]18
Unicode スカラー値（char）['न', 'म', 'स', '्', 'त', 'े']6
書記素クラスタ（人が「文字」と感じる単位）["न", "म", "स्", "ते"]4

4 番目と 6 番目の char は単独では文字にならない記号（発音区別符号）です。どの単位で数えるのが正しいかは、プログラムが何をしたいかによって違います。だから Rust は、s[0] のような曖昧な操作を用意せず、使う側に単位を選ばせます。

また、添字アクセスは常に一定時間（O(1)）で終わることが期待されますが、文字列で「n 番目の文字」を探すには先頭から読む必要があるので、その期待にも応えられません。

スライスはできる（ただし慎重に）

範囲を指定してスライスを作ることはできます。範囲はバイト単位です。

Rust
let hello = "Здравствуйте";let s = &hello[0..4];   // 先頭 4 バイト = "Зд"

文字の途中で切ると、実行時にパニックします。

Rust実行時にパニックする
let s = &hello[0..1];
ターミナル
thread 'main' panicked at src/main.rs:4:19:byte index 1 is not a char boundary; it is inside 'З' (bytes 0..2) of `Здравствуйте`

走査するときは単位を選ぶ

Rust
for c in "Зд".chars() {   // Unicode スカラー値（char）ごと    println!("{c}");       // З, д} for b in "Зд".bytes() {   // バイトごと    println!("{b}");       // 208, 151, 208, 180}

書記素クラスタ単位で扱う機能は標準ライブラリにはないので、crates.io のクレート（unicode-segmentation など）を使います。

要点文字列はシンプルではない

Rust の文字列が面倒に見えるのは、他の言語が隠している複雑さを表に出しているからです。そのおかげで、ASCII 以外の文字を扱うときのバグに、開発の早い段階で気づけます。

8.4ハッシュマップでキーと値を結びつける

HashMap<K, V> は、型 K のキーと型 V の値の対応を保持します。内部ではハッシュ関数を使って、キーから値の置き場所を決めます。添字ではなく、任意の型のキーでデータを探したいときに使います。

作る・挿入する

Rust
use std::collections::HashMap; let mut scores = HashMap::new(); scores.insert(String::from("Blue"), 10);scores.insert(String::from("Yellow"), 50);

ベクタや文字列と違い、ハッシュマップは prelude に含まれていないので、use が必要です。データはヒープに置かれます。キーはすべて同じ型、値もすべて同じ型でなければなりません。

値を読む

Rust
let team_name = String::from("Blue");let score = scores.get(&team_name).copied().unwrap_or(0);

get は Option<&V> を返します。キーがなければ None です。ここでは、copied で Option<&i32> を Option<i32> に変え、unwrap_or(0) で「なければ 0」としています。

for で全要素を走査することもできます。順番は不定です。

Rust
for (key, value) in &scores {    println!("{key}: {value}");}

所有権

i32 のような Copy な型は、ハッシュマップにコピーされます。String のような所有権を持つ型は、ハッシュマップにムーブされ、ハッシュマップが所有者になります。

Rust
let field_name = String::from("Favorite color");let field_value = String::from("Blue"); let mut map = HashMap::new();map.insert(field_name, field_value);// field_name と field_value はここから先は使えない

参照を入れることもできますが、その場合は参照先がハッシュマップより長く生きている必要があります（ライフタイム、第 10 章）。

更新する

1 つのキーには値を 1 つしか結びつけられません。既にキーがあるときにどうするかで、3 つの書き方があります。

上書き

Rust
scores.insert(String::from("Blue"), 10);scores.insert(String::from("Blue"), 25);   // 10 は 25 で置き換えられるprintln!("{scores:?}");                    // {"Blue": 25}

キーがないときだけ追加

entry は、キーに対応する場所を Entry という enum で返します。or_insert は、値があればそれへの可変参照を、なければ引数の値を挿入してその可変参照を返します。

Rust
scores.entry(String::from("Yellow")).or_insert(50);  // ないので 50 を追加scores.entry(String::from("Blue")).or_insert(50);    // あるので何もしない

古い値をもとに更新

テキストの中の単語の出現回数を数える例です。

Rust
use std::collections::HashMap; let text = "hello world wonderful world"; let mut map = HashMap::new(); for word in text.split_whitespace() {    let count = map.entry(word).or_insert(0);   // count: &mut i32    *count += 1;                                // 参照外しして 1 足す} println!("{map:?}");   // {"world": 2, "hello": 1, "wonderful": 1}

or_insert が返す可変参照 count は、for ループの 1 周の終わりでスコープを抜けるので、借用ルールにも引っかかりません。

深掘りハッシュ関数について

HashMap は、デフォルトで SipHash というハッシュ関数を使います。最速ではありませんが、ハッシュの衝突を狙ってサーバを遅くする DoS 攻撃に耐性があります。速度が問題になるなら、BuildHasher トレイトを実装した別のハッシャーに切り替えられます。crates.io に多くの実装があります。
