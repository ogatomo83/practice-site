第 5 章

構造体で関係のあるデータをまとめる

関連する値に名前を付けて 1 つにまとめる構造体。定義と生成、所有権との関係、そして impl でメソッドを生やすところまで進みます。

4 節図 4 点目安 50 分

5.1構造体を定義し、インスタンスを作る

構造体（struct）は、関係のある複数の値をまとめて、意味のある 1 つのかたまりにする型です。タプルにも似ていますが、構造体は各要素に名前を付けます。そのため、値の順番に頼らずにデータを読み書きでき、コードの意図が伝わりやすくなります。

Rust
struct User {    active: bool,    username: String,    email: String,    sign_in_count: u64,}

struct キーワードに続けて構造体の名前を書き、波かっこの中にフィールドの名前と型を並べます。これはいわば「設計図」です。設計図から実際の値（インスタンス）を作るには、各フィールドに値を入れます。

Rust
fn main() {    let user1 = User {        active: true,        username: String::from("someusername123"),        email: String::from("someone@example.com"),        sign_in_count: 1,    };}

フィールドの順番は、定義と違っていてもかまいません。

（図では String の「ポインタ・長さ・容量」をポインタ 1 つに省略しています。）

フィールドの読み書き

ドット記法でフィールドにアクセスします。値を変えるには、インスタンス全体が可変である必要があります。一部のフィールドだけを可変にすることはできません。

Rust
fn main() {    let mut user1 = User {        active: true,        username: String::from("someusername123"),        email: String::from("someone@example.com"),        sign_in_count: 1,    };     user1.email = String::from("anotheremail@example.com");}

フィールド初期化の省略記法

関数の引数とフィールドの名前が同じなら、email: email を email と省略できます。

Rust
fn build_user(email: String, username: String) -> User {    User {        active: true,        username,          // username: username と同じ        email,             // email: email と同じ        sign_in_count: 1,    }}

構造体更新記法

既存のインスタンスをもとに、一部だけ変えた新しいインスタンスを作りたいことがあります。.. を使うと、残りのフィールドを別のインスタンスから持ってこられます。

Rust
fn main() {    // --snip--     let user2 = User {        email: String::from("another@example.com"),        ..user1   // 残りのフィールドは user1 から    };}

ここで所有権に注意が必要です。..user1 は、フィールドごとに = で代入するのと同じです。username は String なので、user1 から user2 にムーブされます。

その結果、user1 全体はもう使えません（user1.username を使うとエラー）。ただし、ムーブされていない user1.email や、Copy な型の user1.active は使えます。もし email と username の両方に新しい値を渡していれば、残りは Copy な型だけなので、user1 はそのまま使えます。

タプル構造体

フィールドに名前を付けず、型だけを並べた構造体も作れます。タプル構造体と呼びます。

Rust
struct Color(i32, i32, i32);struct Point(i32, i32, i32); fn main() {    let black = Color(0, 0, 0);    let origin = Point(0, 0, 0);     let r = black.0; // タプルと同じく、添字で取り出す}

Color と Point は中身の型が同じでも、別の型です。Color を受け取る関数に Point を渡すことはできません。「同じ (i32, i32, i32) だけど意味が違うもの」を型で区別したいときに便利です。

ユニット様構造体

フィールドを 1 つも持たない構造体も作れます。ユニット型 () に似ているので、ユニット様（unit-like）構造体と呼びます。データは持たないけれど、トレイト（第 10 章）を実装したい型を作るときに使います。

Rust
struct AlwaysEqual; fn main() {    let subject = AlwaysEqual;}
深掘り構造体に参照を入れるには

User のフィールドに &str ではなく String を使ったのは意図的です。構造体のインスタンスが自分のデータをすべて所有していれば、構造体が有効な間はデータも有効だと保証できます。

参照をフィールドに持たせることもできますが、そのためにはライフタイム（第 10 章）を書く必要があります。書かずに試すと、コンパイラがこう言います。

ターミナル
error[E0106]: missing lifetime specifier --> src/main.rs:3:15  |3 |     username: &str,  |               ^ expected named lifetime parameter

今は「構造体には所有する型（String など）を入れる」と覚えておいてください。

5.2構造体を使ったプログラム例

長方形の面積を計算するプログラムを、少しずつ書き直しながら、構造体のありがたみを確かめましょう。

版 1：ばらばらの変数

Rust
fn main() {    let width1 = 30;    let height1 = 50;     println!("The area of the rectangle is {} square pixels.", area(width1, height1));} fn area(width: u32, height: u32) -> u32 {    width * height}

動きますが、area のシグネチャを見ても、width と height が同じ長方形のものであることは伝わりません。

版 2：タプル

Rust
fn area(dimensions: (u32, u32)) -> u32 {    dimensions.0 * dimensions.1}

1 つにまとまりましたが、今度は .0 が幅なのか高さなのか、名前からわからなくなりました。面積なら入れ替わっても困りませんが、描画するときに取り違えたらバグになります。

版 3：構造体

Rust
struct Rectangle {    width: u32,    height: u32,} fn main() {    let rect1 = Rectangle { width: 30, height: 50 };     println!("The area of the rectangle is {} square pixels.", area(&rect1));} fn area(rectangle: &Rectangle) -> u32 {    rectangle.width * rectangle.height}

area は &Rectangle、つまり借用を受け取ります。main は rect1 の所有権を持ったまま、area を呼んだ後も rect1 を使えます。

デバッグ表示：derive(Debug)

rect1 の中身を println! で表示しようとすると、エラーになります。

Rustコンパイルエラーになる
println!("rect1 is {}", rect1);
ターミナル
error[E0277]: `Rectangle` doesn't implement `std::fmt::Display`

{} は Display という「利用者向けの表示方法」を使います。数値や文字列なら表示方法は明らかですが、構造体をどう見せるべきかは Rust にはわかりません。

開発中に中身を確認したいだけなら、Debug という「開発者向けの表示方法」を使います。構造体に #[derive(Debug)] という属性を付けると、Rust が Debug の実装を自動で生成してくれます。

Rust
#[derive(Debug)]struct Rectangle {    width: u32,    height: u32,} fn main() {    let rect1 = Rectangle { width: 30, height: 50 };     println!("rect1 is {rect1:?}");   // 1 行で表示    println!("rect1 is {rect1:#?}");  // 整形して表示}
ターミナル
rect1 is Rectangle { width: 30, height: 50 }rect1 is Rectangle {    width: 30,    height: 50,}

dbg! マクロ

もう 1 つ便利なのが dbg! マクロです。式を受け取り、ファイル名・行番号・式・値を標準エラー出力に表示して、その値をそのまま返します。

Rust
fn main() {    let scale = 2;    let rect1 = Rectangle {        width: dbg!(30 * scale),   // 値を返すので、式の途中に挟める        height: 50,    };     dbg!(&rect1);                  // 所有権を取られないよう、参照を渡す}
ターミナル
[src/main.rs:10:16] 30 * scale = 60[src/main.rs:14:5] &rect1 = Rectangle {    width: 60,    height: 50,}
println!dbg!
出力先標準出力標準エラー出力
引数参照を取る所有権を取る（そして返す）
表示内容値だけファイル・行・式・値
戻り値なし受け取った値

5.3メソッド記法

area は長方形の面積を計算する関数で、Rectangle 以外には使えません。それなら、Rectangle 型そのものに結びつけてしまいましょう。それがメソッドです。

Rust
#[derive(Debug)]struct Rectangle {    width: u32,    height: u32,} impl Rectangle {    fn area(&self) -> u32 {        self.width * self.height    }} fn main() {    let rect1 = Rectangle { width: 30, height: 50 };     println!("The area of the rectangle is {} square pixels.", rect1.area());}
  • impl Rectangle { ... } は「Rectangle の実装（implementation）ブロック」です。この中に書いた関数は Rectangle に結びつきます
  • メソッドの最初の引数は必ず self で、メソッドを呼び出したインスタンスを表します
  • &self は self: &Self の省略形です。Self は impl の対象の型（ここでは Rectangle）の別名です

self の 3 つの受け取り方

メソッドも普通の関数と同じく、self の所有権をどう受け取るかを選べます。

self を丸ごと受け取るメソッドは珍しく、self を別の何かに変換して、元のインスタンスを使えなくしたいとき（変換後に古いものを使われると困るとき）に使います。

フィールドと同じ名前のメソッド

メソッドはフィールドと同じ名前にもできます。rect1.width はフィールド、rect1.width() はメソッドです。

Rust
impl Rectangle {    fn width(&self) -> bool {        self.width > 0    }}

フィールドと同じ名前で、そのフィールドの値を返すだけのメソッドはゲッターと呼ばれます。フィールドを非公開にして、読み取りだけを公開したいときに使います（公開・非公開は第 7 章）。

深掘り-> 演算子はどこへ行った？

C や C++ では、オブジェクトのメソッドを呼ぶのに . と -> を使い分けます（ポインタ経由なら ->）。Rust には -> がありません。代わりに自動参照・参照外しという機能があり、object.something() と書くと、Rust がメソッドのシグネチャに合わせて自動的に &、&mut、* を付けてくれます。

Rust
p1.distance(&p2);(&p1).distance(&p2); // 上と同じ意味

メソッドには self の型という明確な受け取り方の指定があるので、Rust はどれを付ければいいか判断できるのです。

引数を増やす

もう 1 つの長方形を受け取って、それがすっぽり収まるかを判定するメソッドを追加しましょう。

Rust
impl Rectangle {    fn area(&self) -> u32 {        self.width * self.height    }     fn can_hold(&self, other: &Rectangle) -> bool {        self.width > other.width && self.height > other.height    }} fn main() {    let rect1 = Rectangle { width: 30, height: 50 };    let rect2 = Rectangle { width: 10, height: 40 };    let rect3 = Rectangle { width: 60, height: 45 };     println!("Can rect1 hold rect2? {}", rect1.can_hold(&rect2)); // true    println!("Can rect1 hold rect3? {}", rect1.can_hold(&rect3)); // false}

関連関数

impl ブロックの中には、self を受け取らない関数も書けます。これを関連関数と呼びます。インスタンスがなくても呼べるので、コンストラクタ（新しいインスタンスを作る関数）によく使われます。String::from もその 1 つです。

Rust
impl Rectangle {    fn square(size: u32) -> Self {        Self {            width: size,            height: size,        }    }} fn main() {    let sq = Rectangle::square(3);}

関連関数は 型名::関数名 で呼びます。:: は、関連関数にもモジュールの名前空間（第 7 章）にも使われる記号です。

メソッド関連関数
最初の引数self, &self, &mut selfself なし
呼び方rect.area()Rectangle::square(3)
主な用途インスタンスに対する操作コンストラクタ（new など）

impl ブロックは複数書ける

1 つの型に対して、impl ブロックを複数に分けて書くこともできます。ここでは分ける理由はありませんが、ジェネリクスやトレイト（第 10 章）で役に立ちます。

Rust
impl Rectangle {    fn area(&self) -> u32 {        self.width * self.height    }} impl Rectangle {    fn can_hold(&self, other: &Rectangle) -> bool {        self.width > other.width && self.height > other.height    }}

5.4この章のまとめ

  • 構造体は関連するデータに名前を付けてまとめる。フィールドの型には、原則として所有する型を使う
  • 構造体更新記法 ..other はフィールドごとの代入と同じ。String などはムーブされる
  • #[derive(Debug)] と {:?}、dbg! で中身を確認できる
  • impl ブロックにメソッド（self を取る）と関連関数（self を取らない）を書く

構造体は「A かつ B かつ C」というデータを表します。次の章で学ぶ enum は、「A または B または C」というデータを表します。
