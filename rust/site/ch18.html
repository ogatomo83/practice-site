第 18 章

パターンとマッチング

match や let で何度も使ってきた「パターン」を体系的に整理します。どこで使えるのか、失敗し得るのか、そしてどんな書き方ができるのか。リファレンスとして手元に置いておける章です。

5 節図 5 点目安 60 分

18.1パターンとは

パターンは、型の構造に合わせて値を照合するための、Rust の特別な構文です。match 式などと組み合わせて、プログラムの制御の流れを変えたり、値の一部を取り出したりします。パターンは次の要素を組み合わせて作ります。

要素例
リテラル1, 'a', "hello", true
分配された配列・enum・構造体・タプルSome(x), Point { x, y }, (a, b)
変数x, name
ワイルドカード_
プレースホルダ..

値とパターンを比べて、値の形がパターンに合えば、その部分を変数に束縛して処理を続けます。

18.2パターンが使える場所

パターンは、match 以外にもいろいろな場所に現れます。実は let 文でさえパターンを使っています。

match のアーム

Rust
match 値 {    パターン => 式,    パターン => 式,    パターン => 式,}

match は網羅的でなければなりません。最後のアームに _ のような何にでも合うパターンを置くと、残りすべての場合を受け止められます。

if let・else if・else if let

if let、else if、else if let は、自由に組み合わせられます。条件がそれぞれ無関係でもかまいません。

Rust
fn main() {    let favorite_color: Option<&str> = None;    let is_tuesday = false;    let age: Result<u8, _> = "34".parse();     if let Some(color) = favorite_color {        println!("Using your favorite color, {color}, as the background");    } else if is_tuesday {        println!("Tuesday is green day!");    } else if let Ok(age) = age {        if age > 30 {            println!("Using purple as the background color");        } else {            println!("Using orange as the background color");        }    } else {        println!("Using blue as the background color");    }}

if let Ok(age) = age の内側で、新しい age が古い age を覆い隠しています（シャドーイング）。新しい age が使えるのは波かっこの中だけなので、if let Ok(age) = age && age > 30 のように条件をまとめることはできず、if を入れ子にしています。

if let は網羅性をチェックしません。最後の else がなくても、コンパイラは警告しないので注意してください。

while let

パターンに合い続ける間、ループを回します。

Rust
let (tx, rx) = std::sync::mpsc::channel();std::thread::spawn(move || {    for val in [1, 2, 3] {        tx.send(val).unwrap();    }}); while let Ok(value) = rx.recv() {    println!("{value}");}

recv が Ok を返す間ループし、送信側が drop されて Err が返ると終わります。

for ループ

for の直後に書くものもパターンです。

Rust
let v = vec!['a', 'b', 'c']; for (index, value) in v.iter().enumerate() {    println!("{value} is at index {index}");}

enumerate は (添字, 値) のタプルを返すので、タプルのパターンで 2 つに分けています。

let 文

実は、let 文も正式にはこう書けます。

Rust
let PATTERN = EXPRESSION;

let x = 5; の x は、「何にでも合い、値を x に束縛する」というパターンです。タプルを分配するのもパターンの働きです。

Rust
let (x, y, z) = (1, 2, 3);

要素の数が合わないと、エラーになります。

Rustコンパイルエラーになる
let (x, y) = (1, 2, 3);
ターミナル
error[E0308]: mismatched types --> src/main.rs:2:9  |2 |     let (x, y) = (1, 2, 3);  |         ^^^^^^   --------- this expression has type `({integer}, {integer}, {integer})`  |         |  |         expected a tuple with 3 elements, found one with 2 elements

関数の引数

関数の引数もパターンです。

Rust
fn print_coordinates(&(x, y): &(i32, i32)) {    println!("Current location: ({x}, {y})");} fn main() {    let point = (3, 5);    print_coordinates(&point);}

&(x, y) というパターンで、タプルへの参照を分配しています。クロージャの引数も同じです。

18.3論駁可能性：パターンが合わない可能性

パターンには 2 種類あります。

種類意味例
論駁不可能（irrefutable）どんな値にも必ず合うlet x = 5; の x、(a, b)
論駁可能（refutable）合わない値がありうるSome(x)（None には合わない）

「論駁」は、「反論して否定する」という意味です。論駁可能なパターンとは、「合わない」と否定されうるパターンのことです。

let 文、関数の引数、for ループは、パターンが合わなかったときにやることがないので、論駁不可能なパターンしか受け付けません。

Rustコンパイルエラーになる
let some_option_value: Option<i32> = None;let Some(x) = some_option_value;
ターミナル
error[E0005]: refutable pattern in local binding --> src/main.rs:3:9  |3 |     let Some(x) = some_option_value;  |         ^^^^^^^ pattern `None` not covered  |  = note: `let` bindings require an "irrefutable pattern", like a `struct` or an `enum` with only one variant  = note: for more information, visit https://doc.rust-lang.org/book/ch19-02-refutability.html  = note: the matched type is `Option<i32>`help: you might want to use `let else` to handle the variant that isn't matched  |3 |     let Some(x) = some_option_value else { todo!() };  |                                     ++++++++++++++++
error[E0005]ローカル束縛に論駁可能なパターンがあります

some_option_value が None だったら、let は何をすればいいのでしょうか。やることがないので、Rust はコンパイルを拒否します。合わない場合の処理を書くために、let else や if let を使います。

逆に、if let に論駁不可能なパターンを書くと、警告が出ます。条件分岐の意味がないからです。

Rust
if let x = 5 {   // warning: irrefutable `if let` pattern    println!("{x}");};

18.4パターンの構文

ここからは、パターンで書けることを一通り見ていきます。

リテラルに合わせる

Rust
let x = 1; match x {    1 => println!("one"),    2 => println!("two"),    3 => println!("three"),    _ => println!("anything"),}

名前付き変数と、シャドーイングの罠

名前付き変数は何にでも合う論駁不可能なパターンです。ただし、match の中では新しいスコープが始まるので、外側と同じ名前の変数を書くと、外側の変数を覆い隠してしまいます。

Rust
let x = Some(5);let y = 10; match x {    Some(50) => println!("Got 50"),    Some(y) => println!("Matched, y = {y}"),   // この y は新しい変数。外側の 10 とは関係ない    _ => println!("Default case, x = {x:?}"),} println!("at the end: x = {x:?}, y = {y}");
ターミナル
Matched, y = 5at the end: x = Some(5), y = 10

外側の y と比較したいなら、後で説明するマッチガードを使います。

複数のパターン

| で「または」を表します。

Rust
let x = 1; match x {    1 | 2 => println!("one or two"),    3 => println!("three"),    _ => println!("anything"),}

範囲に合わせる

..= で、端を含む範囲を表せます。数値と char で使えます。

Rust
let x = 5; match x {    1..=5 => println!("one through five"),    _ => println!("something else"),} let x = 'c'; match x {    'a'..='j' => println!("early ASCII letter"),    'k'..='z' => println!("late ASCII letter"),    _ => println!("something else"),}

範囲が空でないことは、コンパイラがコンパイル時にチェックします。

分配して値を取り出す

構造体

Rust
struct Point {    x: i32,    y: i32,} fn main() {    let p = Point { x: 0, y: 7 };     let Point { x: a, y: b } = p;   // フィールド x を a に、y を b に    assert_eq!(0, a);    assert_eq!(7, b);     let Point { x, y } = p;         // フィールド名と同じ変数名なら省略できる    assert_eq!(0, x);    assert_eq!(7, y);}

フィールドの一部にリテラルを書くと、条件付きの照合になります。

Rust
fn main() {    let p = Point { x: 0, y: 7 };     match p {        Point { x, y: 0 } => println!("On the x axis at {x}"),        Point { x: 0, y } => println!("On the y axis at {y}"),        Point { x, y } => println!("On neither axis: ({x}, {y})"),    }}

enum

Rust
enum Message {    Quit,    Move { x: i32, y: i32 },    Write(String),    ChangeColor(i32, i32, i32),} fn main() {    let msg = Message::ChangeColor(0, 160, 255);     match msg {        Message::Quit => {            println!("The Quit variant has no data to destructure.");        }        Message::Move { x, y } => {            println!("Move in the x direction {x} and in the y direction {y}");        }        Message::Write(text) => {            println!("Text message: {text}");        }        Message::ChangeColor(r, g, b) => {            println!("Change the color to red {r}, green {g}, and blue {b}");        }    }}

パターンの形は、列挙子の定義の形に合わせます。データのない列挙子は名前だけ、構造体のような列挙子は { }、タプルのような列挙子は ( ) です。

入れ子の構造

パターンは入れ子にできます。

Rust
enum Color {    Rgb(i32, i32, i32),    Hsv(i32, i32, i32),} enum Message {    Quit,    Move { x: i32, y: i32 },    Write(String),    ChangeColor(Color),} fn main() {    let msg = Message::ChangeColor(Color::Hsv(0, 160, 255));     match msg {        Message::ChangeColor(Color::Rgb(r, g, b)) => {            println!("Change color to red {r}, green {g}, and blue {b}");        }        Message::ChangeColor(Color::Hsv(h, s, v)) => {            println!("Change color to hue {h}, saturation {s}, value {v}");        }        _ => (),    }}

構造体とタプルの組み合わせ

Rust
let ((feet, inches), Point { x, y }) = ((3, 10), Point { x: 3, y: -10 });

複雑な値も、一度に部品へ分解できます。

値を無視する

_ で値全体を無視する

Rust
fn foo(_: i32, y: i32) {    println!("This code only uses the y parameter: {y}");}

トレイトを実装するときなど、シグネチャは決まっているけれど、ある引数を使わないときに便利です。

入れ子の _ で一部を無視する

Rust
let mut setting_value = Some(5);let new_setting_value = Some(10); match (setting_value, new_setting_value) {    (Some(_), Some(_)) => {        println!("Can't overwrite an existing customized value");    }    _ => {        setting_value = new_setting_value;    }}

「両方が Some かどうか」だけを知りたくて、中の値には興味がない、という場合です。

Rust
let numbers = (2, 4, 8, 16, 32); match numbers {    (first, _, third, _, fifth) => {        println!("Some numbers: {first}, {third}, {fifth}");    }}

_ で始まる変数名

使わない変数を作ると、Rust は警告を出します。名前を _ で始めると、警告が消えます。

Rust
let _x = 5;   // 警告なしlet y = 10;   // warning: unused variable: `y`

ただし、_x と _ には違いがあります。_x は値を束縛する（ムーブする）が、_ は束縛しないのです。

Rustコンパイルエラーになる
let s = Some(String::from("Hello!")); if let Some(_s) = s {     // s の中身が _s にムーブされる    println!("found a string");} println!("{s:?}");        // error[E0382]: borrow of partially moved value: `s`
Rustコンパイルできる
let s = Some(String::from("Hello!")); if let Some(_) = s {      // _ は何も束縛しないので、ムーブも起きない    println!("found a string");} println!("{s:?}");

.. で残りをまとめて無視する

Rust
struct Point {    x: i32,    y: i32,    z: i32,} let origin = Point { x: 0, y: 0, z: 0 }; match origin {    Point { x, .. } => println!("x is {x}"),} let numbers = (2, 4, 8, 16, 32); match numbers {    (first, .., last) => {        println!("Some numbers: {first}, {last}");    }}

.. は、「残りの部分すべて」を表します。どこからどこまでが残りなのか曖昧になる使い方はエラーになります。

Rustコンパイルエラーになる
match numbers {    (.., second, ..) => {   // error: `..` can only be used once per tuple pattern        println!("Some numbers: {second}")    },}

マッチガードで条件を追加する

マッチガードは、パターンの後ろに if で付ける追加の条件です。パターンだけでは表せない複雑な条件を書けます。

Rust
let num = Some(4); match num {    Some(x) if x % 2 == 0 => println!("The number {x} is even"),    Some(x) => println!("The number {x} is odd"),    None => (),}

コンパイラは、マッチガードの中の条件までは網羅性の判定に使いません。

マッチガードを使うと、さきほどのシャドーイングの問題も解決できます。

Rust
let x = Some(5);let y = 10; match x {    Some(50) => println!("Got 50"),    Some(n) if n == y => println!("Matched, n = {n}"),   // 外側の y と比較できる    _ => println!("Default case, x = {x:?}"),}

ガードは、| で並べたパターン全体に適用されます。

Rust
let x = 4;let y = false; match x {    4 | 5 | 6 if y => println!("yes"),   // (4 | 5 | 6) if y という意味    _ => println!("no"),}

4 | 5 | (6 if y) ではありません。y が false なので、x が 4 でも no が表示されます。

@ 束縛

@（アットマーク）を使うと、値をテストしながら、同時に変数に束縛できます。

Rust
enum Message {    Hello { id: i32 },} let msg = Message::Hello { id: 5 }; match msg {    Message::Hello { id: id_variable @ 3..=7 } => {        println!("Found an id in range: {id_variable}")    }    Message::Hello { id: 10..=12 } => {        println!("Found an id in another range")    }    Message::Hello { id } => println!("Found some other id: {id}"),}

1 つ目のアームは、id が 3 から 7 の範囲にあるかを確かめつつ、その値を id_variable で使えるようにしています。2 つ目のアームは範囲を指定しているだけなので、id の値を使えません。

18.5この章のまとめ

書き方意味例
リテラルその値と一致1, 'a'
変数何にでも一致して束縛（新しい変数を作る）x
|または1 | 2
..=範囲1..=5, 'a'..='j'
分配構造体・enum・タプルを分解Point { x, y: 0 }, Some(v)
_何にでも一致、束縛しないSome(_)
_name束縛するが、未使用の警告を出さない_unused
..残りすべてを無視Point { x, .. }, (first, .., last)
マッチガード追加の条件Some(x) if x > 5
@テストしながら束縛id @ 3..=7

パターンは、複雑なデータ構造をすっきり分解し、場合分けを網羅的に書くための強力な道具です。次の章では、Rust のさらに高度な機能を見ていきます。
