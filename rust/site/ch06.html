第 6 章

enum とパターンマッチング

「いくつかの可能性のうちどれか 1 つ」を表す enum と、それを漏れなく場合分けする match。null がない Rust で「値がないかもしれない」を表す Option もここで登場します。

4 節図 4 点目安 50 分

6.1enum を定義する

構造体が「A かつ B」を表すのに対して、enum（列挙型）は「A または B」を表します。取り得る値をすべて列挙して型を定義するので、この名前があります。

例として IP アドレスを考えましょう。IP アドレスには現在 IPv4 と IPv6 の 2 種類があり、ある IP アドレスは必ずどちらか一方です。

Rust
enum IpAddrKind {    V4,    V6,} let four = IpAddrKind::V4;let six = IpAddrKind::V6;

V4 と V6 を列挙子（variant）と呼びます。どちらも同じ IpAddrKind 型なので、1 つの関数で両方を受け取れます。

Rust
fn route(ip_kind: IpAddrKind) {} route(IpAddrKind::V4);route(IpAddrKind::V6);

列挙子にデータを持たせる

種類だけでなく、アドレスの値も持たせたいとします。構造体と組み合わせることもできますが、Rust の enum は列挙子そのものにデータを持たせることができます。

Rust
enum IpAddr {    V4(u8, u8, u8, u8),    V6(String),} let home = IpAddr::V4(127, 0, 0, 1);let loopback = IpAddr::V6(String::from("::1"));

列挙子ごとに、持つデータの型や数が違ってもかまいません。そして列挙子の名前 IpAddr::V4 は、データを受け取ってインスタンスを返す関数のように使えます。

enum の値の大きさは、最も大きい列挙子に合わせて決まります。どの列挙子でも同じ大きさなので、スタックに置けます。

いろいろな列挙子

1 つの enum の中に、さまざまな形の列挙子を混ぜられます。

Rust
enum Message {    Quit,                       // データなし    Move { x: i32, y: i32 },    // 名前付きフィールド（構造体のような形）    Write(String),              // String を 1 つ    ChangeColor(i32, i32, i32), // i32 を 3 つ}

これを構造体で書こうとすると、4 つの別々の型になってしまいます。そうすると「このどれか 1 つを受け取る関数」が書けません。enum なら Message という 1 つの型にまとまります。

enum にも impl でメソッドを定義できます。

Rust
impl Message {    fn call(&self) {        // self の中身に応じた処理（次の節の match を使う）    }} let m = Message::Write(String::from("hello"));m.call();

Option：null の代わり

標準ライブラリの中で最もよく使われる enum が Option です。Option は「値がある、または、ない」を表します。

Rust
enum Option<T> {    None,    Some(T),}

<T> はジェネリック型引数（第 10 章）で、「どんな型でも入れられる」という意味です。Option は prelude に含まれているので、use しなくても使えますし、Some と None も Option:: を付けずに書けます。

Rust
let some_number = Some(5);            // Option<i32>let some_char = Some('e');            // Option<char> let absent_number: Option<i32> = None; // None だけだと型がわからないので注釈が必要

なぜ null ではないのか

多くの言語には null（値がないことを示す特別な値）があります。null の発明者であるトニー・ホーアは、のちにこれを「10 億ドルの間違い」と呼びました。問題は、null かもしれない値を、null でないつもりで使ってしまうことです。そしてそれは、実行するまでわかりません。

Rust には null がありません。値がないかもしれないなら、型が Option<T> になります。そして Option<T> と T は別の型なので、そのままでは混ぜて使えません。

Rustコンパイルエラーになる
let x: i8 = 5;let y: Option<i8> = Some(5); let sum = x + y;
ターミナル
error[E0277]: cannot add `Option<i8>` to `i8` --> src/main.rs:5:17  |5 |     let sum = x + y;  |                 ^ no implementation for `i8 + Option<i8>`

Option<i8> の中の i8 を使うには、まず Option から取り出さなければなりません。そして取り出すときには、None だった場合のことを書かざるを得ない。こうして「null を null でないつもりで使う」というバグが、型の仕組みで防がれます。

逆に言えば、型が Option でない値は、絶対に null ではないと信じてよいのです。

Option の中身を取り出す方法は、標準ライブラリのドキュメントにたくさん載っていますが、最も基本になるのが次の match です。

6.2match 制御フロー構造

match は、値を一連のパターンと照合し、合致したパターンに応じたコードを実行します。コイン選別機を想像してください。コインがレールを転がり、最初に合った大きさの穴に落ちます。

Rust
enum Coin {    Penny,    Nickel,    Dime,    Quarter,} fn value_in_cents(coin: Coin) -> u8 {    match coin {        Coin::Penny => 1,        Coin::Nickel => 5,        Coin::Dime => 10,        Coin::Quarter => 25,    }}

if の条件は bool でなければなりませんが、match のパターンはどんな型でもかまいません。各アームは パターン => 式 の形で、アームの式の値が match 全体の値になります。複数行の処理を書きたいときは波かっこで囲みます。

Rust
fn value_in_cents(coin: Coin) -> u8 {    match coin {        Coin::Penny => {            println!("Lucky penny!");            1        }        Coin::Nickel => 5,        Coin::Dime => 10,        Coin::Quarter => 25,    }}

値を束縛するパターン

パターンは、列挙子の中のデータを取り出して変数に束縛できます。1999 年から 2008 年にかけて、アメリカでは 25 セント硬貨の裏面に 50 州それぞれのデザインを刻んでいました。そのデータを Quarter に持たせてみます。

Rust
#[derive(Debug)]enum UsState {    Alabama,    Alaska,    // --snip--} enum Coin {    Penny,    Nickel,    Dime,    Quarter(UsState),} fn value_in_cents(coin: Coin) -> u8 {    match coin {        Coin::Penny => 1,        Coin::Nickel => 5,        Coin::Dime => 10,        Coin::Quarter(state) => {            println!("State quarter from {state:?}!");            25        }    }}

value_in_cents(Coin::Quarter(UsState::Alaska)) を呼ぶと、Coin::Quarter(state) のパターンに合致し、state に UsState::Alaska が束縛されます。

Option とのマッチ

同じ方法で、Option<T> から値を取り出せます。「Option<i32> を受け取り、中身があれば 1 を足す。なければ None を返す」関数を書いてみましょう。

Rust
fn plus_one(x: Option<i32>) -> Option<i32> {    match x {        None => None,        Some(i) => Some(i + 1),    }} let five = Some(5);let six = plus_one(five);   // Some(6)let none = plus_one(None);  // None

match と enum を組み合わせて、中のデータに名前を付けて取り出し、処理する。これは Rust で非常によく出てくるパターンです。

match は網羅的

match のアームは、取り得るすべての可能性を網羅していなければなりません。None のアームを書き忘れると、こうなります。

Rustコンパイルエラーになる
fn plus_one(x: Option<i32>) -> Option<i32> {    match x {        Some(i) => Some(i + 1),    }}
ターミナル
error[E0004]: non-exhaustive patterns: `None` not covered --> src/main.rs:3:15  |3 |         match x {  |               ^ pattern `None` not covered  |note: `Option<i32>` defined here  = note: the matched value is of type `Option<i32>`help: ensure that all possible cases are being handled by adding a match arm with a wildcard pattern or an explicit pattern as shown  |4 ~             Some(i) => Some(i + 1),5 ~             None => todo!(),  |
error[E0004]パターンが網羅されていません。None がカバーされていません

Rust は、どのパターンを忘れているかを具体的に教えてくれます。これが「null を null でないつもりで使う」バグを防ぐ仕組みの正体です。また、enum に新しい列挙子を追加したときにも、その列挙子を処理していない match がすべてエラーになるので、対応漏れが起きません。

包括パターンと _

特定のいくつかの値だけを特別扱いして、残りはまとめて処理したいことがあります。ゲームで、サイコロの目が 3 なら帽子をもらい、7 なら帽子を失い、それ以外ならその目の数だけ進む、という例で考えます。

Rust
let dice_roll = 9;match dice_roll {    3 => add_fancy_hat(),    7 => remove_fancy_hat(),    other => move_player(other),  // それ以外すべて。値を other に束縛}

最後のアームの other は、どんな値にも合致し、その値を変数に束縛するパターンです。u8 の値すべてを列挙しなくても、網羅性の条件を満たせます。パターンは上から順に評価されるので、包括パターンは最後に置きます。

値を使わないなら、_ を使います。_ はどんな値にも合致し、何にも束縛しません。

Rust
match dice_roll {    3 => add_fancy_hat(),    7 => remove_fancy_hat(),    _ => reroll(),      // それ以外なら振り直し}

何もしないなら、ユニット値 () を返します。

Rust
match dice_roll {    3 => add_fancy_hat(),    7 => remove_fancy_hat(),    _ => (),            // それ以外は何もしない}

6.3if let で簡潔に書く

1 つのパターンにだけ興味があって、他はすべて無視したいとき、match は少し冗長です。

Rust
let config_max = Some(3u8);match config_max {    Some(max) => println!("The maximum is configured to be {max}"),    _ => (),   // これを書くのが面倒}

if let を使うと、同じことを短く書けます。

Rust
let config_max = Some(3u8);if let Some(max) = config_max {    println!("The maximum is configured to be {max}");}

if let パターン = 式 { ... } は、「式がパターンに合致したら、ブロックを実行する」という意味です。else も付けられます。

Rust
let mut count = 0;if let Coin::Quarter(state) = coin {    println!("State quarter from {state:?}!");} else {    count += 1;}

if let は短く書けますが、match が強制してくれる網羅性のチェックを失います。どちらを使うかは、その場面で簡潔さと網羅性のどちらが大事かで決めます。

let else

「パターンに合致したら値を取り出して先に進み、合致しなければ関数から抜ける」という処理は、let ... else で書くとすっきりします。

Rust
fn describe_state_quarter(coin: Coin) -> Option<String> {    let Coin::Quarter(state) = coin else {        return None;    // 合致しなければ、ここで抜ける（必ず抜ける必要がある）    };     // ここから先は state を普通の変数として使える    Some(format!("{state:?} quarter"))}

if let で書くと、成功時の処理がブロックの中に入り込んで、ネストが深くなっていきます。let else なら、「ダメなら早めに抜ける」処理を先に書いて、本筋の処理を平らに書けます。

6.4この章のまとめ

  • enum は「いくつかの可能性のうちどれか 1 つ」を表す。列挙子ごとに違う形のデータを持てる
  • Option<T> は null の代わり。「値がないかもしれない」が型に現れるので、取り出す前に必ず None を考えさせられる
  • match は網羅的。書き忘れた場合をコンパイラが指摘してくれる
  • 1 つのパターンだけ見たいなら if let、ダメなら早めに抜けたいなら let else

構造体と enum を組み合わせれば、プログラムの中の概念を型として正確に表現できます。型が正確なら、コンパイラが正しさをより多くチェックしてくれます。次の章では、大きくなっていくコードを整理するためのモジュールシステムを学びます。
