第 14 章

Cargo と crates.io をもっと使う

ビルド設定の切り替え、ドキュメントの書き方、crates.io への公開、複数のクレートをまとめるワークスペース、そしてコマンドの追加。Cargo のもう一歩進んだ使い方です。

6 節図 5 点目安 50 分

14.1リリースプロファイルでビルドを変える

リリースプロファイルは、コンパイルのオプションをまとめた設定です。Cargo には 2 つの主要なプロファイルがあります。

プロファイル使われるコマンド目的opt-level の初期値
devcargo build開発中。コンパイルを速く0（最適化しない）
releasecargo build --release完成品。実行を速く3（最大限の最適化）
ターミナル
$ cargo build    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.00s$ cargo build --release    Finished `release` profile [optimized] target(s) in 0.32s

Cargo.toml に [profile.*] セクションを書くと、初期値を上書きできます。

Cargo.toml
[profile.dev]opt-level = 1    # 開発中も少しだけ最適化する [profile.release]opt-level = 3

opt-level は 0 から 3 で、上げるほど実行は速くなりますが、コンパイルに時間がかかります。開発中は何度もコンパイルするので低く、リリースは 1 回だけなので高く、というのが初期値の考え方です。

14.2crates.io にクレートを公開する

crates.io は、Rust のクレートの公開レジストリです。ここでは、自分のクレートを公開するまでの準備を見ていきます。

ドキュメンテーションコメント

公開するクレートには、使い方がわかるドキュメントが欠かせません。Rust には、ドキュメント用の特別なコメント /// があり、Markdown で書けます。

src/lib.rs
/// Adds one to the number given.////// # Examples////// ```/// let arg = 5;/// let answer = my_crate::add_one(arg);////// assert_eq!(6, answer);/// ```pub fn add_one(x: i32) -> i32 {    x + 1}

cargo doc --open を実行すると、HTML のドキュメントが生成されてブラウザで開きます。

よく使われる見出しは次のとおりです。

見出し書く内容
# Examples使い方の例（最も重要）
# Panicsどんな状況でパニックするか
# ErrorsResult を返すなら、どんなエラーがどんな条件で返るか
# Safetyunsafe な関数なら、呼ぶ側が守るべき条件（第 19 章）

ドキュメントはテストにもなる

ドキュメントの中のコード例は、cargo test でテストとして実行されます。

ターミナル
   Doc-tests my_crate running 1 testtest src/lib.rs - add_one (line 5) ... ok test result: ok. 1 passed; 0 failed; 0 ignored; 0 measured; 0 filtered out; finished in 0.27s

コードを変更してドキュメントの例が動かなくなると、テストが失敗します。ドキュメントが古くなることを防げるのです。

クレート全体へのコメント

//! は、そのコメントを含んでいる要素（ここではクレート全体）のドキュメントになります。src/lib.rs の先頭に書くのが一般的です。

src/lib.rs
//! # My Crate//!//! `my_crate` is a collection of utilities to make performing certain//! calculations more convenient. /// Adds one to the number given.// --snip--

pub use で使いやすい公開 API を作る

第 7 章で学んだ pub use は、公開するクレートで特に重要になります。

開発するときは、モジュールを深く入れ子にして整理したくなります。しかし利用者にとっては、使いたい型が深い場所にあると探すのが大変ですし、use my_crate::some_module::another_module::UsefulType; と書くのも面倒です。

美術のクレート art を例にとります。

src/lib.rs
//! # Art//!//! A library for modeling artistic concepts. pub mod kinds {    /// The primary colors according to the RYB color model.    pub enum PrimaryColor {        Red,        Yellow,        Blue,    }     /// The secondary colors according to the RYB color model.    pub enum SecondaryColor {        Orange,        Green,        Purple,    }} pub mod utils {    use crate::kinds::*;     /// Combines two primary colors in equal amounts to create    /// a secondary color.    pub fn mix(c1: PrimaryColor, c2: PrimaryColor) -> SecondaryColor {        // --snip--    }}

利用者はこう書く必要があります。

Rust
use art::kinds::PrimaryColor;use art::utils::mix;

pub use で、最上位に再公開しましょう。

src/lib.rs
//! # Art//!//! A library for modeling artistic concepts. pub use self::kinds::PrimaryColor;pub use self::kinds::SecondaryColor;pub use self::utils::mix; pub mod kinds {    // --snip--} pub mod utils {    // --snip--}

アカウントの設定と公開

公開までの流れは次のとおりです。

ターミナル
$ cargo loginabcdefghijklmnopqrstuvwxyz012345

API トークンは秘密です。誰にも見せないでください。

公開するには、Cargo.toml にメタデータが必要です。名前は crates.io で早い者勝ちなので、既に使われている名前は使えません。

Cargo.toml
[package]name = "guessing_game"version = "0.1.0"edition = "2021"description = "A fun game where you guess what number the computer has chosen."license = "MIT OR Apache-2.0" [dependencies]

license には SPDX のライセンス識別子を書きます。Rust 自身と同じ MIT OR Apache-2.0 がよく使われます。

ターミナル
$ cargo publish    Updating crates.io index   Packaging guessing_game v0.1.0 (file:///projects/guessing_game)   Verifying guessing_game v0.1.0 (file:///projects/guessing_game)   Compiling guessing_game v0.1.0(file:///projects/guessing_game/target/package/guessing_game-0.1.0)    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.19s   Uploading guessing_game v0.1.0 (file:///projects/guessing_game)
注意公開は永久

公開したバージョンは、上書きも削除もできません。crates.io は、そのクレートに依存しているすべてのプロジェクトが、いつでも同じようにビルドできることを保証するアーカイブだからです。公開する前に、内容をよく確認してください。

新しいバージョンと yank

変更を公開するときは、version をセマンティックバージョニングに従って上げ、もう一度 cargo publish します。

壊れたバージョンを公開してしまったら、yank（取り下げ）できます。

ターミナル
$ cargo yank --vers 1.0.1$ cargo yank --vers 1.0.1 --undo

yank は削除ではありません。そのバージョンを Cargo.lock で使っている既存のプロジェクトは引き続きビルドできますが、新しく依存を追加するプロジェクトがそのバージョンを選ぶことはなくなります。

14.3Cargo のワークスペース

プロジェクトが大きくなると、ライブラリクレートをさらに分割したくなります。ワークスペースは、複数の関連するパッケージを一緒に管理するための仕組みです。ワークスペースのパッケージは、Cargo.lock と出力ディレクトリ target/ を共有します。

ワークスペースを作る

1 つのバイナリと 2 つのライブラリからなるワークスペースを作ります。

ターミナル
$ mkdir add$ cd add
Cargo.toml
[workspace]resolver = "2"members = ["adder", "add_one"]
ターミナル
$ cargo new adder$ cargo new add_one --lib

各メンバーが自分の target/ を持つと、互いに依存するクレートを何度もビルドし直すことになります。共有することで、無駄なビルドを避けられます。

メンバー同士の依存

adder から add_one を使うには、パスで依存を書きます。ワークスペースの中でも、依存関係は自動では張られません。

add_one/src/lib.rs
pub fn add_one(x: i32) -> i32 {    x + 1}
adder/Cargo.toml
[dependencies]add_one = { path = "../add_one" }
adder/src/main.rs
fn main() {    let num = 10;    println!("Hello, world! {num} plus one is {}!", add_one::add_one(num));}
ターミナル
$ cargo build   Compiling add_one v0.1.0 (file:///projects/add/add_one)   Compiling adder v0.1.0 (file:///projects/add/adder)    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.22s$ cargo run -p adderHello, world! 10 plus one is 11!

ワークスペースの最上位で実行するときは、-p でどのパッケージかを指定します。

外部クレートへの依存

外部クレートの依存は、各メンバーの Cargo.toml に書きます。ただし、Cargo.lock は 1 つなので、ワークスペース全体で同じバージョンが使われます。

ただし、add_one の Cargo.toml に rand を書いても、adder から rand を使うことはできません。使いたいメンバーそれぞれの Cargo.toml に書く必要があります（バージョンは共有されます）。

テスト

最上位で cargo test を実行すると、すべてのメンバーのテストが実行されます。特定のメンバーだけなら -p を使います。

ターミナル
$ cargo test -p add_one

ワークスペースのクレートを crates.io に公開するときは、メンバーごとに cargo publish します。

14.4cargo install でバイナリを入れる

cargo install は、crates.io で公開されているバイナリクレートをビルドして、ローカルにインストールします。開発者向けのツールを手軽に入れるための仕組みで、OS のパッケージマネージャの代わりではありません。

ターミナル
$ cargo install ripgrep    Updating crates.io index  Downloaded ripgrep v14.1.1  Downloaded 1 crate (213.6 KB) in 0.40s  Installing ripgrep v14.1.1--snip--   Compiling grep v0.3.2    Finished `release` profile [optimized + debuginfo] target(s) in 6.73s  Installing ~/.cargo/bin/rg   Installed package `ripgrep v14.1.1` (executable `rg`)

インストール先は $HOME/.cargo/bin です。ここに PATH が通っていれば、rg --help のように実行できます。

14.5独自のコマンドで Cargo を拡張する

PATH の通った場所に cargo-something という名前の実行ファイルがあると、cargo something で実行できます。cargo --list に一覧も表示されます。

cargo install と組み合わせれば、組み込みのコマンドと同じ感覚で、自作やコミュニティのツールを使えます。
