生識別子

生識別子（raw identifier）を使うと、普通はキーワードとして使えない名前を識別子として使えます。キーワードの前に r# を付けます。

Rust
fn r#match(needle: &str, haystack: &str) -> bool {    haystack.contains(needle)} fn main() {    assert!(r#match("foo", "foobar"));}

他のエディションや他の言語で書かれたライブラリに、新しいエディションでキーワードになった名前の関数がある場合などに使います。

C：derive できるトレイト

#[derive(...)] 属性を構造体や enum に付けると、指定したトレイトのデフォルト実装を自動生成できます。標準ライブラリのうち、derive できるのは次のトレイトです。

トレイト何ができるようになるかderive したときの振る舞い必要になる場面
Debug{:?} で表示型名とフィールドを表示assert_eq! の失敗メッセージ
PartialEq==, !=すべてのフィールドが等しければ等しい（enum は同じ列挙子のときだけ）assert_eq!
Eq（マーカー）値が自分自身と常に等しいメソッドなしHashMap のキー
PartialOrd<, >, <=, >=フィールドを定義順に比較（enum は先に宣言した列挙子が小さい）gen_range など
Ord常に順序が決まる cmpPartialOrd と同じ順BTreeSet など
Clone.clone() で明示的に複製各フィールドの clone を呼ぶスライスから Vec を作る to_vec
Copy代入時に暗黙にビットコピーClone も必要。全フィールドが Copy であること値をムーブしたくないとき
Hashハッシュ値の計算各フィールドの hash を組み合わせるHashMap のキー
DefaultDefault::default() で既定値各フィールドの既定値..Default::default()、unwrap_or_default

Display は derive できません。利用者向けにどう表示すべきかは、型ごとに人間が決めるべきことだからです。

D：便利な開発ツール

rustfmt：自動整形

コードを、コミュニティ共通のスタイルに自動整形します。どのスタイルを使うかで議論する時間がなくなります。

ターミナル
$ cargo fmt

rustfix：警告の自動修正

コンパイラの警告のうち、修正方法が明確なものは自動で直せます。

Rust
fn main() {    let mut x = 42;   // warning: variable does not need to be mutable    println!("{x}");}
ターミナル
$ cargo fix    Checking myprogram v0.1.0 (file:///projects/myprogram)      Fixing src/main.rs (1 fix)    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.59s

エディションの移行（付録 E）にも使います。

Clippy：より多くのリント

Clippy は、よくある間違いや、より良い書き方を指摘してくれるリント（静的解析）の集まりです。

ターミナル
$ cargo clippy

例えば、円周率を自分で書いていると、こう教えてくれます。

Rust
fn main() {    let x = 3.1415;    let r = 8.0;    println!("the area of the circle is {}", x * r * r);}
ターミナル
error: approximate value of `f{32, 64}::consts::PI` found --> src/main.rs:2:13  |2 |     let x = 3.1415;  |             ^^^^^^  |  = note: `#[deny(clippy::approx_constant)]` on by default  = help: consider using the constant directly

標準ライブラリの std::f64::consts::PI を使えば、より正確です。

rust-analyzer：エディタとの統合

rust-analyzer は、LSP（Language Server Protocol）を実装したツールで、VS Code などのエディタに組み込んで使います。

  • 入力補完
  • 定義へのジャンプ
  • エラーのインライン表示
  • 推論された型の表示

ほぼ必須のツールです。お使いのエディタのプラグインを入れてください。

E：エディション

Rust は 6 週間ごとに新しいバージョンをリリースしています。1 つ 1 つのリリースの変化は小さいですが、積み重なると大きな変化になります。そこで、約 3 年ごとにエディションという区切りを設け、それまでの変化をまとめて、新しいドキュメントやツールとともに提供しています。

エディション主な変化
Rust 2015最初の安定版（1.0）
Rust 2018モジュールシステムの改良、NLL（非レキシカルライフタイム）、async / await などがキーワードに
Rust 2021クロージャの部分キャプチャ、IntoIterator の配列への実装、prelude の拡張
Rust 2024gen の予約、unsafe extern、if let の一時値のスコープの変更 など

Cargo.toml の edition キーで、パッケージのエディションを指定します。

TOML
[package]edition = "2021"
要点エディションは互換性を壊さない

異なるエディションのクレート同士でも、問題なくリンクできます。 2015 エディションのクレートが 2021 エディションのクレートに依存していても、逆でもかまいません。エディションによる変化は、コンパイラがコードを解析するときの方法だけに影響します。

そのため、エコシステムが新旧のエディションに分断されることはありません。自分のプロジェクトのエディションを上げるときは、cargo fix --edition が多くの書き換えを自動でしてくれます。

F：本の翻訳

The Rust Programming Language は、さまざまな言語に翻訳されています。日本語訳は doc.rust-jp.rs/book-ja で読めます。英語の最新版は doc.rust-lang.org/book です。

この本は、それらの内容を土台に、図を中心にして日本語で書き直したものです。用語は日本語訳に準じていますが、わかりやすさを優先して言い換えた箇所があります。

G：Rust の作られ方と Nightly Rust

停滞なき安定

Rust は、停滞なき安定（stability without stagnation）を大切にしています。安定版の Rust で動くコードは、将来の安定版でもコンパイルできることが約束されています。その一方で、新しい機能は着実に追加されていきます。

リリーストレイン

Rust の開発は、リリーストレインという方式で行われています。3 つのリリースチャネルがあります。

チャネル更新頻度内容
Nightly毎晩最新の開発中のコード。不安定な機能も試せる
Beta6 週間ごと次の安定版の候補。テスト期間
Stable6 週間ごと安定版。ほとんどの人が使う

リリースは列車のように、時刻表どおりに出発します。ある機能が間に合わなくても、次の列車（6 週間後）に乗ればよいので、リリースが遅れることはありません。

不安定な機能とフィーチャーフラグ

開発中の新しい機能は、フィーチャーフラグの後ろに隠されています。Nightly の Rust で、ソースコードに属性を書いたときだけ使えます。

Rust
#![feature(some_unstable_feature)]

Beta と Stable では、フィーチャーフラグは使えません。安定版で使えるのは、安定化された機能だけです。だからこそ、安定版のコードは将来も動き続けることが保証できるのです。

rustup で Nightly を使う

ターミナル
$ rustup toolchain install nightly$ rustup toolchain liststable-x86_64-apple-darwin (default)beta-x86_64-apple-darwinnightly-x86_64-apple-darwin$ cd ~/projects/needs-nightly$ rustup override set nightly

rustup override set を使うと、そのディレクトリの中でだけ Nightly を使うように設定できます。

RFC プロセスとチーム

新しい機能を追加したいときは、RFC（Request For Comments）を書きます。RFC は誰でも書くことができ、関連するチームが議論して、受け入れるかどうかを決めます。受け入れられた機能は Nightly でフィーチャーフラグの後ろに実装され、十分に試されたあとで安定化されます。

Rust は、こうしたオープンなプロセスで、多くの人の手によって作られています。この本を読み終えたあなたも、もうその一員になれます。
