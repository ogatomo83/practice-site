## この本について {#about}

この本は、Rust 公式の入門書「The Rust Programming Language」（通称 The Book）の内容を、日本語で一から書き直したものです。章立ては原典と同じ 20 章と付録ですが、文章はすべて新しく書いています。

書き直すときに決めたルールは 3 つです。

1. **絵で示せるものは、先に絵で示す。** 所有権の移動、借用の範囲、モジュールの木、スレッドの間でのデータのやりとり。文章だと 1 段落かかる説明も、図なら一目で伝わります。
2. **「なぜそうなっているのか」を必ず書く。** Rust のルールは意地悪で決まっているわけではありません。どの種類のバグを防ぐためのルールなのかを、毎回はっきりさせます。
3. **コンパイラのエラーを怖がらない。** Rust のコンパイラ `rustc` は、エラーを出すたびに「どこが・なぜ・どう直すか」を教えてくれる先生です。この本では、わざとエラーを起こしてメッセージを読む練習をたくさんします。

:::

## Rust とはどんな言語か {#what-is-rust}

Rust は、**C や C++ と同じくらい速く、でもメモリ関連のバグを起こさない**ことを目指して作られたプログラミング言語です。

これまで、プログラミング言語は大きく 2 つの陣営に分かれていました。

```fig graph 従来の言語の 2 つの陣営と、Rust の立ち位置
{
  col: 250, row: 110,
  nodes: [
    { id: 'c', label: 'C / C++', sub: '速い・メモリは手で管理', x: 0, y: 0, kind: 'mod' },
    { id: 'gc', label: 'Java / Go / Python', sub: '安全・GC が自動で回収', x: 2, y: 0, kind: 'ext' },
    { id: 'r', label: 'Rust', sub: '速い・コンパイル時に安全を証明', x: 1, y: 1, kind: 'accent' },
  ],
  edges: [
    { from: 'c', to: 'r', label: '速さを受け継ぐ', style: 'muted' },
    { from: 'gc', to: 'r', label: '安全さを受け継ぐ', style: 'muted' },
  ],
}
```

- **C や C++** はとても速く、ハードウェアを細かく制御できます。しかし、メモリの確保と解放をプログラマが手作業で行うため、「解放したメモリをまた使う」「同じメモリを 2 回解放する」といったバグが起きやすく、それがセキュリティ事故の大きな原因になってきました。
- **Java、Go、Python など** は、ガベージコレクタ（GC）という仕組みが使われなくなったメモリを自動で回収してくれます。安全ですが、GC が動いている間はプログラムが一瞬止まったり、メモリを多めに使ったりします。

Rust はこのどちらでもない 3 つ目の道を選びました。**所有権（ownership）**というルールをコンパイラがチェックし、「このメモリはいつ解放してよいか」をコンパイルの時点で決めてしまいます。実行時に GC は動かず、それでいて解放忘れや二重解放はコンパイルエラーとして事前に弾かれます。

この所有権こそが Rust の心臓部であり、この本の第 4 章のテーマです。

## 誰のための本か {#audience}

この本は、**何か 1 つ以上のプログラミング言語を書いたことがある人**を想定しています。変数、関数、if 文、ループが何かは説明しません。逆に、メモリ管理やポインタの知識は前提にしていません。必要になったところで、図を使って一から説明します。

Rust が特に力を発揮するのは次のような場面です。

| 場面 | Rust が向いている理由 |
| --- | --- |
| コマンドラインツール | 起動が速く、1 つの実行ファイルで配布できる |
| Web サーバ・バックエンド | GC による停止がなく、少ないメモリで高い処理性能が出る |
| 組み込み・OS | ハードウェアを直接扱えて、ランタイムがいらない |
| WebAssembly | ブラウザで動く高速なコードを安全に書ける |
| チーム開発 | 「並行処理のバグ」をコンパイラが見つけてくれるので、大胆に変更できる |

### コードの見方

コードブロックの上には、そのコードがどうなるかを示すラベルが付いています。

```rust fail
fn main() {
    let x = 5;
    x = 6; // 不変の変数に再代入している
}
```

上のように **コンパイルエラーになる** と書かれたコードは、わざと間違えている例です。どんなエラーが出て、なぜ出るのかを本文で説明します。

```rust
fn main() {
    let x = 5;
@@    let x = x + 1; // 変更・追加した行は、このように色が付く
    println!("{x}");
}
```

前のコードから変更・追加した行は、左端に色の付いた線が引かれます。

コンパイラのエラーを読み解くときは、次のようなカードを使います。これがこの本の「先生」です。

:::rustc E0384 不変の変数に 2 回代入できません
`let` で作った変数は、何も付けなければ**不変（immutable）**です。値を変えたいなら `let mut x = 5;` のように `mut` を付けます。詳しくは第 3 章で扱います。
:::
