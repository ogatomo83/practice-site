## 重複を関数に抜き出すところから {#intro}

この章の 3 つの道具は、どれも**重複をなくす**ための仕組みです。その出発点は、誰でも知っている「関数への抜き出し」です。

リストの中の最大値を探すコードがあるとします。

```rust
fn main() {
    let number_list = vec![34, 50, 25, 100, 65];

    let mut largest = &number_list[0];
    for number in &number_list {
        if number > largest {
            largest = number;
        }
    }
    println!("The largest number is {largest}");

    // 別のリストでも同じことをしたい → コードをコピーする？
}
```

2 つのリストで同じことをしたいなら、コピーするのではなく関数にします。

```rust
fn largest(list: &[i32]) -> &i32 {
    let mut largest = &list[0];

    for item in list {
        if item > largest {
            largest = item;
        }
    }

    largest
}
```

では、`i32` のリストと `char` のリストの両方で最大値を探したいときは？ 型だけが違う 2 つの関数を書くのは重複です。そこで**型そのものを引数にする**のがジェネリクスです。

## ジェネリックなデータ型 {#generics}

### 関数で

型の引数（**型パラメータ**）は、関数名の後ろの山かっこ `<>` で宣言します。慣習として、短い大文字の名前、多くは `T`（type の頭文字）を使います。

```rust fail
fn largest<T>(list: &[T]) -> &T {
    let mut largest = &list[0];

    for item in list {
        if item > largest {
            largest = item;
        }
    }

    largest
}
```

「`largest` は、ある型 `T` についてジェネリックで、`T` のスライスを受け取って `T` への参照を返す」と読みます。ところが、これはまだコンパイルできません。

```console

  |
5 |         if item > largest {
  |            ---- ^ ------- &T
  |            |

  |

:::rustc E0369 `>` 演算子は `&T` 型には使えません
`T` は**どんな型でもよい**ので、比較できない型が渡される可能性もあります。比較できる型だけに限定するには、`T` に**トレイト境界**を付けます（`help` に答えが書いてあります）。これは次の節で扱います。
:::

### 構造体で

```rust
struct Point<T> {
    x: T,
    y: T,
}

fn main() {
    let integer = Point { x: 5, y: 10 };
    let float = Point { x: 1.0, y: 4.0 };
}
```

`x` と `y` は同じ型 `T` なので、`Point { x: 5, y: 4.0 }` はエラーになります。別々の型を許したいなら、型パラメータを 2 つにします。

```rust
struct Point<T, U> {
    x: T,
    y: U,
}

let both_integer = Point { x: 5, y: 10 };
let both_float = Point { x: 1.0, y: 4.0 };
let integer_and_float = Point { x: 5, y: 4.0 };
```

### enum で

すでに見た `Option<T>` と `Result<T, E>` が、ジェネリックな enum です。

```rust
enum Option<T> {
    Some(T),
    None,
}

enum Result<T, E> {
    Ok(T),
    Err(E),
}
```

### メソッドで

```rust
struct Point<T> {
    x: T,
    y: T,
}

impl<T> Point<T> {           // すべての T について実装
    fn x(&self) -> &T {
        &self.x
    }
}

impl Point<f32> {            // f32 のときだけ実装
    fn distance_from_origin(&self) -> f32 {
        (self.x.powi(2) + self.y.powi(2)).sqrt()
    }
}
```

`impl<T>` の `<T>` は、「この後の `Point<T>` の `T` は具体的な型ではなく型パラメータですよ」という宣言です。`impl Point<f32>` のように具体的な型を書けば、その型のときだけ使えるメソッドを定義できます。

### ジェネリクスのコスト

ジェネリクスを使うと、実行時に遅くなるのでしょうか。答えは **いいえ** です。Rust はコンパイル時に**単相化（monomorphization）**を行い、ジェネリックなコードを、実際に使われている具体的な型ごとのコードに展開します。

## トレイト：共通の振る舞いを定義する {#traits}

**トレイト（trait）**は、ある型が持つ機能を定義し、他の型と共有するための仕組みです。他の言語の**インターフェース**に似ています。

### トレイトを定義する

ニュース記事（`NewsArticle`）とソーシャルメディアの投稿（`SocialPost`）という 2 つの型があり、どちらも「要約を表示する」機能を持たせたいとします。

```rust file="src/lib.rs"
pub trait Summary {
    fn summarize(&self) -> String;
}
```

トレイトの中には、メソッドの**シグネチャだけ**を書き、本体は書きません。このトレイトを実装する型は、それぞれ独自の本体を用意しなければなりません。

### トレイトを型に実装する

```rust file="src/lib.rs"
pub struct NewsArticle {
    pub headline: String,
    pub location: String,
    pub author: String,
    pub content: String,
}

impl Summary for NewsArticle {
    fn summarize(&self) -> String {
        format!("{}, by {} ({})", self.headline, self.author, self.location)
    }
}

pub struct SocialPost {
    pub username: String,
    pub content: String,
    pub reply: bool,
    pub repost: bool,
}

impl Summary for SocialPost {
    fn summarize(&self) -> String {
        format!("{}: {}", self.username, self.content)
    }
}
```

使う側は、普通のメソッドと同じように呼べます。ただし、トレイトのメソッドを呼ぶには、**トレイト自体もスコープに入っている**必要があります。

```rust
use aggregator::{SocialPost, Summary};

fn main() {
    let post = SocialPost {
        username: String::from("horse_ebooks"),
        content: String::from("of course, as you probably already know, people"),
        reply: false,
        repost: false,
    };

    println!("1 new post: {}", post.summarize());
}
```

### 孤児ルール

トレイトの実装には 1 つ制約があります。**トレイトか型のどちらか少なくとも一方が、自分のクレートのもの**でなければなりません。

| | 自分の型（`Tweet` など） | 外部の型（`Vec<T>` など） |
| --- | --- | --- |
| **自分のトレイト**（`Summary` など） | できる | できる |
| **外部のトレイト**（`Display` など） | できる | **できない** |

このルールがないと、2 つのクレートが同じ型に同じトレイトを別々に実装して、どちらを使うべきか決められなくなってしまいます。

### デフォルト実装

トレイトのメソッドに、デフォルトの本体を書いておくこともできます。

```rust
pub trait Summary {
    fn summarize_author(&self) -> String;   // これは各型が実装する

    fn summarize(&self) -> String {          // デフォルト実装。他のメソッドを呼べる
        format!("(Read more from {}...)", self.summarize_author())
    }
}

impl Summary for SocialPost {
    fn summarize_author(&self) -> String {   // これだけ実装すれば summarize も使える
        format!("@{}", self.username)
    }
}
```

`impl Summary for NewsArticle {}` のように空のブロックで実装すると、すべてデフォルト実装が使われます（この例では `summarize_author` にデフォルトがないので空にはできません）。

### 引数としてのトレイト

トレイトを使うと、「`Summary` を実装している何か」を受け取る関数が書けます。

```rust
pub fn notify(item: &impl Summary) {
    println!("Breaking news! {}", item.summarize());
}
```

`&impl Summary` は、「`Summary` を実装している任意の型への参照」という意味です。`NewsArticle` も `SocialPost` も渡せます。`String` や `i32` は `Summary` を実装していないので、渡すとコンパイルエラーです。

### トレイト境界

`impl Trait` は、実は**トレイト境界（trait bound）**という書き方の省略形です。

```rust
pub fn notify<T: Summary>(item: &T) {
    println!("Breaking news! {}", item.summarize());
}
```

「型パラメータ `T` は、`Summary` を実装している型に限る」と読みます。2 つの書き方には、次のような違いがあります。

```rust
pub fn notify(item1: &impl Summary, item2: &impl Summary)  // item1 と item2 は別の型でもよい
pub fn notify<T: Summary>(item1: &T, item2: &T)            // item1 と item2 は同じ型でなければならない
```

複数のトレイトを要求するときは `+` でつなぎます。

```rust
pub fn notify(item: &(impl Summary + Display)) {}
pub fn notify<T: Summary + Display>(item: &T) {}
```

境界が増えて関数のシグネチャが読みにくくなったら、`where` 句に分けて書けます。

```rust
fn some_function<T, U>(t: &T, u: &U) -> i32
where
    T: Display + Clone,
    U: Clone + Debug,
{
    // --snip--
}
```

### 戻り値としてのトレイト

戻り値の型にも `impl Trait` が使えます。「`Summary` を実装している何かを返す。具体的な型は秘密」という意味です。

```rust
fn returns_summarizable() -> impl Summary {
    SocialPost {
        username: String::from("horse_ebooks"),
        content: String::from("of course, as you probably already know, people"),
        reply: false,
        repost: false,
    }
}
```

第 13 章で学ぶクロージャやイテレータは、コンパイラだけが知っている型や、書き切れないほど長い型を持つので、この書き方がとても役立ちます。

ただし、`impl Trait` で返せるのは **1 つの型だけ**です。条件によって `NewsArticle` か `SocialPost` のどちらかを返す、ということはできません。それが必要なら、第 17 章のトレイトオブジェクトを使います。

### largest を完成させる

さっきの `largest` に戻りましょう。比較するには `PartialOrd` トレイトが必要でした。

```rust
fn largest<T: PartialOrd>(list: &[T]) -> &T {
    let mut largest = &list[0];

    for item in list {
        if item > largest {
            largest = item;
        }
    }

    largest
}

fn main() {
    let number_list = vec![34, 50, 25, 100, 65];
    println!("The largest number is {}", largest(&number_list));

    let char_list = vec!['y', 'm', 'a', 'q'];
    println!("The largest char is {}", largest(&char_list));
}
```

### トレイト境界で条件付きでメソッドを実装する

トレイト境界は、`impl` ブロックにも付けられます。

```rust
use std::fmt::Display;

struct Pair<T> {
    x: T,
    y: T,
}

impl<T> Pair<T> {                       // どんな T でも new は使える
    fn new(x: T, y: T) -> Self {
        Self { x, y }
    }
}

impl<T: Display + PartialOrd> Pair<T> { // 表示も比較もできる T のときだけ
    fn cmp_display(&self) {
        if self.x >= self.y {
            println!("The largest member is x = {}", self.x);
        } else {
            println!("The largest member is y = {}", self.y);
        }
    }
}
```

さらに、「あるトレイトを実装しているすべての型に、別のトレイトを実装する」こともできます。これを**ブランケット実装**と呼びます。標準ライブラリには次のような実装があります。

```rust
impl<T: Display> ToString for T {
    // --snip--
}
```

`Display` を実装している型ならどれでも、`to_string` メソッドが使えます。`3.to_string()` が動くのは、`i32` が `Display` を実装しているからです。

:::key トレイトとトレイト境界の効能
動的型付けの言語では、メソッドが存在しない型でそのメソッドを呼ぶと、**実行時に**エラーになります。Rust は、トレイト境界によってその問題を**コンパイル時に**見つけます。実行時に「このメソッドはあるか」を調べる必要がないので、柔軟さと速さを両立できます。
:::

## ライフタイムで参照を検証する {#lifetimes}

**ライフタイム（lifetime）**は、参照が有効である範囲のことです。実はすべての参照にライフタイムがあり、これまでは型と同じくコンパイラが推論してくれていました。ライフタイムの注釈を書く必要があるのは、**推論できないときだけ**です。

ライフタイムの目的は、第 4 章で見た**ダングリング参照を防ぐ**ことです。

### 借用チェッカー

```rust fail
fn main() {
    let r;                // ---------+-- 'a
                          //          |
    {                     //          |
        let x = 5;        // -+-- 'b  |
        r = &x;           //  |       |
    }                     // -+       |
                          //          |
    println!("r: {r}");   //          |
}                         // ---------+
```

Rust のコンパイラには**借用チェッカー**という部分があり、スコープを比較して、すべての借用が有効かどうかを判断します。ここでは、参照する側（`r`、`'a`）が、参照される側（`x`、`'b`）より長生きしています。**参照先は、参照より長く生きていなければならない**ので、エラーです。

`x` のほうが長生きなら、問題ありません。

```rust ok
fn main() {
    let x = 5;            // ----------+-- 'b
                          //           |
    let r = &x;           // --+-- 'a  |
                          //   |       |
    println!("r: {r}");   //   |       |
                          // --+       |
}                         // ----------+
```

2 つの文字列スライスのうち、長いほうを返す関数を書いてみます。

```rust fail
fn longest(x: &str, y: &str) -> &str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}
```

:::rustc E0106 ライフタイム指定子がありません
`help` の 1 行目がすべてです。**戻り値は借用された値を含んでいるが、それが x から借りたものか y から借りたものか、シグネチャからはわからない。** 実際、`if` の結果によってどちらが返るかは実行時に決まります。借用チェッカーは、戻り値の参照がいつまで有効なのかを判断できないのです。
:::

### ライフタイム注釈の書き方

ライフタイム注釈は、アポストロフィ `'` で始まる名前で、普通は `'a` のように短い小文字を使います。参照の `&` の後に書きます。

```rust
&i32        // 参照
&'a i32     // 明示的なライフタイム付きの参照
&'a mut i32 // 明示的なライフタイム付きの可変参照
```

注釈は、**参照が生きる長さを変えるものではありません**。複数の参照のライフタイムが互いにどう関係しているかを、コンパイラに**説明する**ためのものです。

### longest にライフタイムを付ける

```rust
fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() {
        x
    } else {
        y
    }
}
```

このシグネチャは、こう読みます。

> ある生存期間 `'a` について、2 つの引数はどちらも少なくとも `'a` の間は有効であり、戻り値の参照も少なくとも `'a` の間は有効である。

実際に具体的な参照を渡すと、`'a` は **x のスコープと y のスコープが重なる部分**、つまり**短いほうのライフタイム**になります。そして戻り値は、その短いほうと同じだけしか使えません。

人間が見れば、`string1` のほうが長いので `result` は `string1` を指すはずだとわかります。でもコンパイラは、関数のシグネチャだけを見て判断します。シグネチャは「戻り値は短いほうと同じだけ生きる」と言っているので、エラーにするのです。

### ライフタイムの観点で考える

どの引数にライフタイムを付けるべきかは、関数が何をするかで決まります。必ず `x` を返すなら、`y` にはライフタイムは要りません。

```rust
fn longest<'a>(x: &'a str, y: &str) -> &'a str {
    x
}
```

関数の中で作った値への参照を返そうとすると、どう注釈を付けてもダングリング参照になるのでエラーです。

```rust fail
fn longest<'a>(x: &str, y: &str) -> &'a str {
    let result = String::from("really long string");
    result.as_str()   // result は関数の終わりで drop される
}
```

この場合は、参照ではなく `String` を返して、所有権ごと呼び出し元に渡すのが正解です。

:::key ライフタイム構文の本質
ライフタイムの構文は、**関数の引数と戻り値のライフタイムを結びつける**ためのものです。結びつきさえわかれば、Rust はメモリ安全な操作を許可し、ダングリング参照を生む操作を拒否できます。
:::

### 構造体のライフタイム

構造体に参照を持たせる場合は、すべての参照にライフタイム注釈が必要です。

```rust
struct ImportantExcerpt<'a> {
    part: &'a str,
}

fn main() {
    let novel = String::from("Call me Ishmael. Some years ago...");
    let first_sentence = novel.split('.').next().unwrap();
    let i = ImportantExcerpt {
        part: first_sentence,
    };
}
```

この注釈は、「`ImportantExcerpt` のインスタンスは、`part` フィールドの参照より長生きできない」という意味です。

### ライフタイムの省略規則

第 4 章で書いた `first_word` は、参照を受け取って参照を返すのに、ライフタイム注釈がありませんでした。

```rust
fn first_word(s: &str) -> &str {
```

初期の Rust では、これにも `fn first_word<'a>(s: &'a str) -> &'a str` と書く必要がありました。しかし同じパターンを何度も書くことになったので、コンパイラが決まったパターンを推論するようになりました。これを**ライフタイム省略規則（lifetime elision rules）**と呼びます。

用語として、引数のライフタイムを**入力ライフタイム**、戻り値のライフタイムを**出力ライフタイム**と呼びます。

| 規則 | 対象 | 内容 |
| --- | --- | --- |
| 1 | 入力 | 参照である引数それぞれに、別々のライフタイムを割り当てる |
| 2 | 出力 | 入力ライフタイムが**ちょうど 1 つ**なら、それをすべての出力ライフタイムに割り当てる |
| 3 | 出力 | 引数に `&self` か `&mut self` があれば、`self` のライフタイムをすべての出力ライフタイムに割り当てる |

3 つの規則を適用しても出力ライフタイムが決まらなければ、エラーになり、注釈を求められます。

### メソッドのライフタイム

構造体にライフタイムがあるなら、`impl` の後と型名の後にライフタイムを書きます。

```rust
impl<'a> ImportantExcerpt<'a> {
    fn level(&self) -> i32 {
        3
    }

    fn announce_and_return_part(&self, announcement: &str) -> &str {
        println!("Attention please: {announcement}");
        self.part
    }
}
```

`announce_and_return_part` は入力ライフタイムが 2 つありますが、規則 3 により、戻り値は `&self` と同じライフタイムになります。省略規則のおかげで、メソッドではライフタイムを書く場面がほとんどありません。

### 静的ライフタイム

特別なライフタイム `'static` は、**プログラムの実行中ずっと有効**であることを表します。文字列リテラルはすべて `'static` です。

```rust
let s: &'static str = "I have a static lifetime.";
```

文字列リテラルはバイナリに直接埋め込まれているので、常に存在します。

:::warn 'static で黙らせない
ライフタイムのエラーを見て、「`'static` を付けろ」というヒントをもらうことがあります。でも、付ける前に「本当にプログラムの終わりまで生きている必要があるのか」を考えてください。ほとんどの場合、問題はダングリング参照を作ろうとしていることか、ライフタイムの不一致にあります。`'static` を付けるのではなく、そちらを直すべきです。
:::

## 3 つを組み合わせる {#together}

ジェネリクス、トレイト境界、ライフタイムは、1 つの関数に同時に書けます。

```rust
use std::fmt::Display;

fn longest_with_an_announcement<'a, T>(
    x: &'a str,
    y: &'a str,
    ann: T,
) -> &'a str
where
    T: Display,
{
    println!("Announcement! {ann}");
    if x.len() > y.len() {
        x
    } else {
        y
    }
}
```

ライフタイムもジェネリクスの一種なので、`<'a, T>` のように同じ山かっこの中に並べます。

## この章のまとめ {#summary}

| 道具 | 抽象化するもの | 書き方 | 確認するタイミング |
| --- | --- | --- | --- |
| ジェネリクス | 型 | `fn f<T>(x: T)` | コンパイル時（単相化） |
| トレイト | 振る舞い | `trait Summary { … }`、`T: Summary` | コンパイル時 |
| ライフタイム | 参照の有効範囲 | `fn f<'a>(x: &'a str) -> &'a str` | コンパイル時（借用チェッカー） |

どれもコンパイル時に検査されるので、実行時のコストはありません。トレイトとライフタイムには、まだ扱っていない高度な使い方がたくさんあります。第 17 章ではトレイトオブジェクトを、第 19 章ではさらに高度なトレイトの機能を扱います。
