## A：キーワード {#keywords}

以下は、Rust の言語自体が使うために予約されている**キーワード**です。関数・変数・型・モジュールなどの名前には使えません（生識別子を除く）。

### 現在使われているキーワード

| キーワード | 意味 |
| --- | --- |
| `as` | 型のキャストをする、`use` で別名を付ける、完全修飾構文でトレイトを指定する |
| `async` | 現在のスレッドをブロックせずに、`Future` を返す |
| `await` | `Future` の結果が準備できるまで実行を中断する |
| `break` | ループを即座に抜ける |
| `const` | 定数や、定数の生ポインタを定義する |
| `continue` | ループの次の繰り返しへ進む |
| `crate` | モジュールパスで、クレートのルートを指す |
| `dyn` | トレイトオブジェクトへの動的ディスパッチ |
| `else` | `if` と `if let` の代替の分岐 |
| `enum` | 列挙型を定義する |
| `extern` | 外部の関数や変数をリンクする |
| `false` | 論理値の偽 |
| `fn` | 関数や関数ポインタ型を定義する |
| `for` | イテレータの要素を繰り返す、トレイトを実装する、高階ライフタイムを指定する |
| `if` | 条件式で分岐する |
| `impl` | 固有の機能やトレイトの機能を実装する |
| `in` | `for` ループの構文の一部 |
| `let` | 変数を束縛する |
| `loop` | 無条件にループする |
| `match` | 値をパターンと照合する |
| `mod` | モジュールを定義する |
| `move` | クロージャにキャプチャしたものの所有権を取らせる |
| `mut` | 参照・生ポインタ・パターンの束縛を可変にする |
| `pub` | 構造体のフィールド・`impl` ブロック・モジュールなどを公開する |
| `ref` | 参照で束縛する |
| `return` | 関数から戻る |
| `Self` | 定義中・実装中の型の別名 |
| `self` | メソッドの対象、または現在のモジュール |
| `static` | グローバル変数、またはプログラム全体の実行期間にわたるライフタイム |
| `struct` | 構造体を定義する |
| `super` | 親モジュール |
| `trait` | トレイトを定義する |
| `true` | 論理値の真 |
| `type` | 型エイリアスや関連型を定義する |
| `union` | ユニオンを定義する（ユニオンの宣言の中でだけキーワード） |
| `unsafe` | unsafe なコード・関数・トレイト・実装を示す |
| `use` | シンボルをスコープに持ち込む |
| `where` | 型を制約する節を示す |
| `while` | 式の結果に応じて条件付きでループする |

### 将来のために予約されているキーワード

次のキーワードは、まだ機能を持ちませんが、将来使われる可能性があるので予約されています。

`abstract` `become` `box` `do` `final` `gen` `macro` `override` `priv` `try` `typeof` `unsized` `virtual` `yield`

### 生識別子

**生識別子（raw identifier）**を使うと、普通はキーワードとして使えない名前を識別子として使えます。キーワードの前に `r#` を付けます。

```rust
fn r#match(needle: &str, haystack: &str) -> bool {
    haystack.contains(needle)
}

fn main() {
    assert!(r#match("foo", "foobar"));
}
```

他のエディションや他の言語で書かれたライブラリに、新しいエディションでキーワードになった名前の関数がある場合などに使います。

## B：演算子と記号 {#operators}

### 演算子

「オーバーロード可能なトレイト」の列があるものは、そのトレイトを実装すれば自分の型でも使えます（第 19 章）。

| 演算子 | 例 | 意味 | オーバーロード可能なトレイト |
| --- | --- | --- | --- |
| `!` | `ident!(...)` | マクロの展開 | |
| `!` | `!expr` | ビット反転・論理否定 | `Not` |
| `!=` | `expr != expr` | 等しくない | `PartialEq` |
| `%` | `expr % expr` | 剰余 | `Rem` |
| `%=` | `var %= expr` | 剰余して代入 | `RemAssign` |
| `&` | `&expr`, `&mut expr` | 借用 | |
| `&` | `&type`, `&mut type` | 借用されたポインタ型 | |
| `&` | `expr & expr` | ビット AND | `BitAnd` |
| `&=` | `var &= expr` | ビット AND して代入 | `BitAndAssign` |
| `&&` | `expr && expr` | 短絡論理 AND | |
| `*` | `expr * expr` | 乗算 | `Mul` |
| `*=` | `var *= expr` | 乗算して代入 | `MulAssign` |
| `*` | `*expr` | 参照外し | `Deref` |
| `*` | `*const type`, `*mut type` | 生ポインタ | |
| `+` | `trait + trait`, `'a + trait` | 型の制約の組み合わせ | |
| `+` | `expr + expr` | 加算 | `Add` |
| `+=` | `var += expr` | 加算して代入 | `AddAssign` |
| `,` | `expr, expr` | 引数や要素の区切り | |
| `-` | `- expr` | 符号反転 | `Neg` |
| `-` | `expr - expr` | 減算 | `Sub` |
| `-=` | `var -= expr` | 減算して代入 | `SubAssign` |
| `->` | `fn(...) -> type`, `\|…\| -> type` | 関数・クロージャの戻り値の型 | |
| `.` | `expr.ident` | フィールドアクセス・メソッド呼び出し | |
| `..` | `..`, `expr..`, `..expr`, `expr..expr` | 終端を含まない範囲 | `PartialOrd` |
| `..=` | `..=expr`, `expr..=expr` | 終端を含む範囲 | `PartialOrd` |
| `..` | `..expr` | 構造体更新記法 | |
| `..` | `variant(x, ..)`, `struct_type { x, .. }` | パターンの「残り」 | |
| `/` | `expr / expr` | 除算 | `Div` |
| `/=` | `var /= expr` | 除算して代入 | `DivAssign` |
| `:` | `pat: type`, `ident: type` | 型の制約 | |
| `:` | `ident: expr` | 構造体のフィールドの初期化 | |
| `:` | `'a: loop {...}` | ループラベル | |
| `;` | `expr;` | 文・要素の終わり | |
| `;` | `[...; len]` | 固定長配列の構文の一部 | |
| `<<` | `expr << expr` | 左シフト | `Shl` |
| `<<=` | `var <<= expr` | 左シフトして代入 | `ShlAssign` |
| `<` / `<=` / `>` / `>=` | `expr < expr` など | 比較 | `PartialOrd` |
| `=` | `var = expr`, `ident = type` | 代入・等価性 | |
| `==` | `expr == expr` | 等しい | `PartialEq` |
| `=>` | `pat => expr` | match のアームの構文の一部 | |
| `>>` | `expr >> expr` | 右シフト | `Shr` |
| `>>=` | `var >>= expr` | 右シフトして代入 | `ShrAssign` |
| `@` | `ident @ pat` | パターン束縛 | |
| `^` | `expr ^ expr` | ビット XOR | `BitXor` |
| `^=` | `var ^= expr` | ビット XOR して代入 | `BitXorAssign` |
| `\|` | `pat \| pat` | パターンの「または」 | |
| `\|` | `expr \| expr` | ビット OR | `BitOr` |
| `\|=` | `var \|= expr` | ビット OR して代入 | `BitOrAssign` |
| `\|\|` | `expr \|\| expr` | 短絡論理 OR | |
| `?` | `expr?` | エラーの伝播 | |

### 演算子以外の記号

| 記号 | 意味 |
| --- | --- |
| `'ident` | 名前付きライフタイムまたはループラベル |
| `...u8`, `...i32`, `...f64` など | 型を指定した数値リテラル |
| `"..."` | 文字列リテラル |
| `r"..."`, `r#"..."#` | 生文字列リテラル（エスケープを処理しない） |
| `b"..."` | バイト文字列リテラル（`&[u8]`） |
| `'...'` / `b'...'` | 文字リテラル / ASCII バイトリテラル |
| `\|…\| expr` | クロージャ |
| `!` | 常に空のボトム型（never 型） |
| `_` | 「無視される」パターン束縛。数値リテラルの区切り |
| `ident::ident` | 名前空間のパス |
| `::path` | 外部プレリュードからの相対パス |
| `self::path` / `super::path` / `crate::path` | 現在・親・クレートルートからの相対パス |
| `type::ident` | 関連定数・関数・型 |
| `<type>::...` | 直接書けない型（`<&T>::...` など）の関連要素 |
| `<type as trait>::ident` | 完全修飾構文 |
| `path<...>` | 型の中で、ジェネリック型の引数を指定する（`Vec<u8>`） |
| `path::<...>`, `method::<...>` | 式の中で型引数を指定する（ターボフィッシュ。`"42".parse::<i32>()`） |
| `fn ident<...> ...` / `struct ident<...>` | ジェネリックな関数・型の定義 |
| `for<...> type` | 高階ライフタイム境界 |
| `T: U` | 型パラメータ `T` は `U` を実装する型に限られる |
| `T: 'a` | 型 `T` はライフタイム `'a` より長生きする |
| `T: ?Sized` | `T` は動的サイズ型でもよい |
| `#[meta]` / `#![meta]` | 外部属性 / 内部属性 |
| `$ident`, `$ident:kind`, `$(…)…` | マクロの構文 |
| `//` / `//!` / `///` | 行コメント / 内部ドキュメント / 外部ドキュメント |
| `/*...*/` / `/*!...*/` / `/**...*/` | ブロックコメント / 内部ドキュメント / 外部ドキュメント |
| `()` | 空のタプル（ユニット） |
| `(expr,)` | 要素 1 つのタプル |
| `expr.0`, `expr.1` | タプルの添字アクセス |
| `[type; expr]` / `[expr; len]` | 配列型 / 配列リテラル |
| `expr[expr]` | 添字アクセス（`Index`, `IndexMut`） |
| `expr[..]`, `expr[a..b]` | スライス |

## C：derive できるトレイト {#derivable-traits}

`#[derive(...)]` 属性を構造体や enum に付けると、指定したトレイトのデフォルト実装を自動生成できます。標準ライブラリのうち、derive できるのは次のトレイトです。

```fig graph derive できるトレイトの依存関係。矢印の先のトレイトを derive するには、矢印の元のトレイトも必要になる
  nodes: [

    { id: 'eq', label: 'Eq', sub: '反射律も成り立つ', x: 0, y: 1, kind: 'mod' },
    { id: 'po', label: 'PartialOrd', sub: '< > <= >=', x: 1, y: 1, kind: 'mod' },

    { from: 'pe', to: 'po', style: 'muted' },

```

| トレイト | 何ができるようになるか | derive したときの振る舞い | 必要になる場面 |
| --- | --- | --- | --- |
| `Debug` | `{:?}` で表示 | 型名とフィールドを表示 | `assert_eq!` の失敗メッセージ |
| `PartialEq` | `==`, `!=` | すべてのフィールドが等しければ等しい（enum は同じ列挙子のときだけ） | `assert_eq!` |
| `Eq` | （マーカー）値が自分自身と常に等しい | メソッドなし | `HashMap` のキー |
| `PartialOrd` | `<`, `>`, `<=`, `>=` | フィールドを定義順に比較（enum は先に宣言した列挙子が小さい） | `gen_range` など |
| `Ord` | 常に順序が決まる `cmp` | `PartialOrd` と同じ順 | `BTreeSet` など |
| `Clone` | `.clone()` で明示的に複製 | 各フィールドの `clone` を呼ぶ | スライスから `Vec` を作る `to_vec` |
| `Copy` | 代入時に暗黙にビットコピー | `Clone` も必要。全フィールドが `Copy` であること | 値をムーブしたくないとき |
| `Hash` | ハッシュ値の計算 | 各フィールドの `hash` を組み合わせる | `HashMap` のキー |
| `Default` | `Default::default()` で既定値 | 各フィールドの既定値 | `..Default::default()`、`unwrap_or_default` |

`Display` は derive できません。利用者向けにどう表示すべきかは、型ごとに人間が決めるべきことだからです。

## D：便利な開発ツール {#tools}

### rustfmt：自動整形

コードを、コミュニティ共通のスタイルに自動整形します。どのスタイルを使うかで議論する時間がなくなります。

```console
$ cargo fmt
```

### rustfix：警告の自動修正

コンパイラの警告のうち、修正方法が明確なものは自動で直せます。

```rust
fn main() {
    let mut x = 42;   // warning: variable does not need to be mutable
    println!("{x}");
}
```

```console
$ cargo fix
    Checking myprogram v0.1.0 (file:///projects/myprogram)
      Fixing src/main.rs (1 fix)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.59s
```

エディションの移行（付録 E）にも使います。

### Clippy：より多くのリント

**Clippy** は、よくある間違いや、より良い書き方を指摘してくれるリント（静的解析）の集まりです。

```console
$ cargo clippy
```

例えば、円周率を自分で書いていると、こう教えてくれます。

```rust
fn main() {
    let x = 3.1415;
    let r = 8.0;
    println!("the area of the circle is {}", x * r * r);
}
```

```console
error: approximate value of `f{32, 64}::consts::PI` found
 --> src/main.rs:2:13
  |
2 |     let x = 3.1415;
  |             ^^^^^^
  |
  = note: `#[deny(clippy::approx_constant)]` on by default
  = help: consider using the constant directly
```

標準ライブラリの `std::f64::consts::PI` を使えば、より正確です。

### rust-analyzer：エディタとの統合

**rust-analyzer** は、**LSP**（Language Server Protocol）を実装したツールで、VS Code などのエディタに組み込んで使います。

- 入力補完
- 定義へのジャンプ
- エラーのインライン表示
- 推論された型の表示

ほぼ必須のツールです。お使いのエディタのプラグインを入れてください。

## E：エディション {#editions}

Rust は 6 週間ごとに新しいバージョンをリリースしています。1 つ 1 つのリリースの変化は小さいですが、積み重なると大きな変化になります。そこで、約 3 年ごとに**エディション**という区切りを設け、それまでの変化をまとめて、新しいドキュメントやツールとともに提供しています。

| エディション | 主な変化 |
| --- | --- |
| Rust 2015 | 最初の安定版（1.0） |
| Rust 2018 | モジュールシステムの改良、NLL（非レキシカルライフタイム）、`async` / `await` などがキーワードに |
| Rust 2021 | クロージャの部分キャプチャ、`IntoIterator` の配列への実装、prelude の拡張 |
| Rust 2024 | `gen` の予約、`unsafe extern`、`if let` の一時値のスコープの変更 など |

`Cargo.toml` の `edition` キーで、パッケージのエディションを指定します。

```toml
[package]
edition = "2021"
```

:::key エディションは互換性を壊さない
**異なるエディションのクレート同士でも、問題なくリンクできます。** 2015 エディションのクレートが 2021 エディションのクレートに依存していても、逆でもかまいません。エディションによる変化は、コンパイラがコードを解析するときの方法だけに影響します。

そのため、エコシステムが新旧のエディションに分断されることはありません。自分のプロジェクトのエディションを上げるときは、`cargo fix --edition` が多くの書き換えを自動でしてくれます。
:::

## G：Rust の作られ方と Nightly Rust {#nightly}

### 停滞なき安定

Rust は、**停滞なき安定（stability without stagnation）**を大切にしています。安定版の Rust で動くコードは、将来の安定版でもコンパイルできることが約束されています。その一方で、新しい機能は着実に追加されていきます。

### リリーストレイン

Rust の開発は、**リリーストレイン**という方式で行われています。3 つのリリースチャネルがあります。

| チャネル | 更新頻度 | 内容 |
| --- | --- | --- |
| **Nightly** | 毎晩 | 最新の開発中のコード。不安定な機能も試せる |
| **Beta** | 6 週間ごと | 次の安定版の候補。テスト期間 |
| **Stable** | 6 週間ごと | 安定版。ほとんどの人が使う |

### 不安定な機能とフィーチャーフラグ

開発中の新しい機能は、**フィーチャーフラグ**の後ろに隠されています。Nightly の Rust で、ソースコードに属性を書いたときだけ使えます。

```rust
#![feature(some_unstable_feature)]
```

Beta と Stable では、フィーチャーフラグは使えません。安定版で使えるのは、安定化された機能だけです。だからこそ、安定版のコードは将来も動き続けることが保証できるのです。

### rustup で Nightly を使う

```console
$ rustup toolchain install nightly
$ rustup toolchain list
stable-x86_64-apple-darwin (default)
beta-x86_64-apple-darwin
nightly-x86_64-apple-darwin
$ cd ~/projects/needs-nightly
$ rustup override set nightly
```

`rustup override set` を使うと、そのディレクトリの中でだけ Nightly を使うように設定できます。

### RFC プロセスとチーム

新しい機能を追加したいときは、**RFC**（Request For Comments）を書きます。RFC は誰でも書くことができ、関連するチームが議論して、受け入れるかどうかを決めます。受け入れられた機能は Nightly でフィーチャーフラグの後ろに実装され、十分に試されたあとで安定化されます。
