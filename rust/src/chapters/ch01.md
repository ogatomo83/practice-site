## インストール {#installation}

Rust のインストールには、公式のインストーラ兼バージョン管理ツール **rustup** を使います。rustup を入れると、次の 3 つがまとめて手に入ります。

```fig graph rustup が管理するツール群。普段直接触るのは cargo がほとんど
{
  col: 200, row: 100,
  nodes: [
    { id: 'up', label: 'rustup', sub: 'ツールチェーンの管理', x: 1, y: 0, kind: 'accent' },
    { id: 'rustc', label: 'rustc', sub: 'コンパイラ', x: 0, y: 1, kind: 'mod' },
    { id: 'cargo', label: 'cargo', sub: 'ビルド・依存関係・テスト', x: 1, y: 1, kind: 'crate' },

  ],

    { from: 'up', to: 'cargo', style: 'muted' },
    { from: 'up', to: 'std', style: 'muted' },
  ],
}
```

### macOS / Linux

ターミナルで次のコマンドを実行します。

```console
$ curl --proto '=https' --tlsv1.2 https://sh.rustup.rs -sSf | sh
```

インストールが終わると、次のメッセージが表示されます。

```console
Rust is installed now. Great!
```

Rust のコンパイラは最後の仕上げ（リンク）に**リンカ**という別のプログラムを使います。「linker `cc` not found」のようなエラーが出たら、C コンパイラを入れてください。

- macOS: `xcode-select --install`
- Ubuntu など: `sudo apt install build-essential`

### Windows

[rustup.rs](https://rustup.rs) から `rustup-init.exe` をダウンロードして実行します。途中で Visual Studio の C++ ビルドツールを求められたら、指示どおりにインストールしてください。

### インストールできたか確かめる

```console
$ rustc --version
rustc 1.82.0 (f6e511eec 2024-10-15)
```

`rustc バージョン番号 (コミットハッシュ 日付)` の形式で表示されれば成功です。表示されない場合は、`~/.cargo/bin` に PATH が通っているか確認してください（ターミナルを開き直すと直ることが多いです）。

### 更新とアンインストール

| やりたいこと | コマンド |
| --- | --- |
| Rust を最新版に更新する | `rustup update` |
| Rust と rustup を削除する | `rustup self uninstall` |
| 手元でドキュメントを開く | `rustup doc` |
| 標準ライブラリのドキュメントを開く | `rustup doc --std` |

:::tip ドキュメントはオフラインでも読める
`rustup doc` は、インストールに含まれるドキュメント一式をブラウザで開きます。この本の英語原典や標準ライブラリのリファレンスも入っているので、ネットにつながっていなくても調べものができます。
:::

## Hello, World! {#hello-world}

伝統にならって、画面に `Hello, world!` と表示するプログラムから始めます。

### プロジェクト用のディレクトリを作る

どこに置いてもかまいませんが、この本ではホームディレクトリに `projects` を作ることにします。

```console
$ mkdir ~/projects
$ cd ~/projects
$ mkdir hello_world
$ cd hello_world
```

### プログラムを書く

`main.rs` というファイルを作り、次のように書きます。Rust のソースファイルの拡張子は `.rs` で、ファイル名が複数の単語からなる場合はアンダースコアでつなぐのが慣習です（`hello_world.rs`）。

```rust file="main.rs"
fn main() {
    println!("Hello, world!");
}
```

### コンパイルして実行する

```console
$ rustc main.rs
$ ./main
Hello, world!
```

Windows では `./main` の代わりに `.\main.exe` です。`Hello, world!` と表示されたら、あなたはもう Rust プログラマです。

### プログラムを分解する

たった 3 行ですが、Rust の基本がいくつも詰まっています。

```fig graph Hello, world! を部品に分けると
{
  col: 210, row: 82, minW: 150,
  nodes: [
    { id: 'fn', label: 'fn main()', sub: '関数の定義。main は入口', x: 0, y: 0, kind: 'mod' },
    { id: 'body', label: '{ ... }', sub: '関数の本体', x: 1, y: 0, kind: 'plain' },
    { id: 'mac', label: 'println!', sub: '! が付くのはマクロ', x: 0, y: 1, kind: 'accent' },
    { id: 'arg', label: '"Hello, world!"', sub: '文字列リテラル', x: 1, y: 1, kind: 'ext' },
    { id: 'semi', label: ';', sub: '式の終わり', x: 2, y: 1, kind: 'plain' },
  ],
  edges: [
    { from: 'fn', to: 'body', style: 'muted' },
    { from: 'body', to: 'mac', style: 'muted' },
    { from: 'mac', to: 'arg', style: 'muted' },
    { from: 'arg', to: 'semi', style: 'muted' },
  ],
}
```

- `fn main() { }` は `main` という名前の関数を定義しています。`main` は特別な関数で、実行可能な Rust プログラムは必ずここから始まります。引数はなく、何も返しません。
- インデントは**スペース 4 つ**が標準です。タブは使いません。`rustfmt` というツール（付録 D）が自動で整形してくれます。
- `println!` の `!` は、これが普通の関数ではなく**マクロ**であることを示しています。マクロはコードを生成するコードで、普通の関数にはできないこと（引数の数が可変、など）ができます。詳しくは第 19 章で扱います。今は「`!` が付いていたらマクロ」とだけ覚えておけば十分です。
- 行末の `;` は、その式が終わったことを示します。Rust のほとんどの行はセミコロンで終わります。

### コンパイルと実行は別の段階

Ruby や Python、JavaScript のような言語では、1 つのコマンドでプログラムを実行します。Rust は**事前コンパイル（ahead-of-time compilation）**型の言語なので、「コンパイル」と「実行」が分かれています。

```fig graph rustc はソースコードを実行ファイルに変換する。できた実行ファイルは Rust がない環境でも動く
{
  col: 210, row: 80,
  nodes: [
    { id: 'src', label: 'main.rs', sub: 'ソースコード', x: 0, y: 0, kind: 'plain' },
    { id: 'rustc', label: 'rustc', sub: 'コンパイラ', x: 1, y: 0, kind: 'accent' },
    { id: 'bin', label: 'main', sub: '実行ファイル（Windows は main.exe）', x: 2, y: 0, kind: 'crate' },
    { id: 'run', label: '実行', sub: 'Rust がなくても動く', x: 3, y: 0, kind: 'muted', mono: false },
  ],
  edges: [
    { from: 'src', to: 'rustc', style: 'muted' },
    { from: 'rustc', to: 'bin', style: 'accent', label: 'コンパイル' },
    { from: 'bin', to: 'run', style: 'muted' },
  ],
}
```

コンパイルした実行ファイルを渡せば、相手のマシンに Rust が入っていなくても動きます。Python のスクリプトを渡すと相手に Python が必要なのとは対照的です。

小さなプログラムなら `rustc` だけで十分ですが、プロジェクトが大きくなると、ファイルや依存ライブラリの管理が大変になります。そこで登場するのが Cargo です。

## Hello, Cargo! {#hello-cargo}

**Cargo** は Rust のビルドシステム兼パッケージマネージャです。Rust のプロジェクトはほぼすべて Cargo で管理されています。Cargo は次のような仕事をまとめて引き受けてくれます。

- コードのビルド
- 依存しているライブラリ（**クレート**と呼びます）のダウンロードとビルド
- テストの実行、ドキュメントの生成、公開

rustup で Rust を入れたなら、Cargo もすでに入っています。

```console
$ cargo --version
cargo 1.82.0 (8f40fc59f 2024-08-21)
```

### Cargo でプロジェクトを作る

```console
$ cd ~/projects
$ cargo new hello_cargo
$ cd hello_cargo
```

`cargo new` は、次のようなディレクトリ構成を作ります。

```fig tree cargo new が作るファイル。Git リポジトリとしても初期化される
{
  root: { label: 'hello_cargo/', kind: 'dir', children: [
    { label: 'Cargo.toml', note: 'プロジェクトの設定（マニフェスト）', hl: true },
    { label: '.gitignore', note: 'target/ を Git の管理外にする' },
    { label: '.git/', note: 'Git リポジトリ' },
    { label: 'src/', kind: 'dir', children: [
      { label: 'main.rs', note: 'ソースコードはすべて src/ の下に置く', hl: true },
    ]},
  ]},
}
```

`Cargo.toml` の中身を見てみましょう。

```toml file="Cargo.toml"
[package]
name = "hello_cargo"
version = "0.1.0"
edition = "2021"

[dependencies]
```

これは **TOML**（Tom's Obvious, Minimal Language）という形式の設定ファイルです。

| 部分 | 意味 |
| --- | --- |
| `[package]` | ここから下がパッケージの設定であることを示す見出し |
| `name`, `version` | パッケージの名前とバージョン |
| `edition` | 使う Rust のエディション（付録 E）。言語の大きな版のようなもの |
| `[dependencies]` | 依存するクレートを書く場所。今は空 |

`src/main.rs` には、さっき書いたものと同じ Hello, world! がすでに用意されています。

### ビルドと実行

```console
$ cargo build
   Compiling hello_cargo v0.1.0 (/Users/you/projects/hello_cargo)
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.52s
$ ./target/debug/hello_cargo
Hello, world!
```

`cargo build` は、実行ファイルを `target/debug/hello_cargo` に作ります。ビルドと実行を 1 回でやりたいなら `cargo run` です。

```console
$ cargo run
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 0.01s
     Running `target/debug/hello_cargo`
Hello, world!
```

2 回目は `Compiling` の行が出ていません。ソースが変わっていないので、Cargo はビルドを省略して前回の実行ファイルをそのまま使ったのです。

### よく使う Cargo コマンド

```fig graph 開発中の Cargo コマンドの使い分け。check が最も速く、run と build は実行ファイルまで作る
{
  col: 190, row: 92,
  nodes: [
    { id: 'src', label: 'src/*.rs', sub: '編集する', x: 0, y: 1, kind: 'plain' },
    { id: 'check', label: 'cargo check', sub: '型チェックのみ・最速', x: 1, y: 0, kind: 'mod' },
    { id: 'build', label: 'cargo build', sub: 'target/debug/ に出力', x: 1, y: 1, kind: 'crate' },
    { id: 'run', label: 'cargo run', sub: 'ビルドして実行', x: 1, y: 2, kind: 'crate' },
    { id: 'rel', label: 'cargo build --release', sub: '最適化して target/release/ に', x: 2.4, y: 1, kind: 'accent' },
  ],
  edges: [
    { from: 'src', to: 'check', style: 'muted' },
    { from: 'src', to: 'build', style: 'muted' },
    { from: 'src', to: 'run', style: 'muted' },
    { from: 'build', to: 'rel', style: 'muted', label: '完成したら' },
  ],
}
```

| コマンド | すること | いつ使う |
| --- | --- | --- |
| `cargo new 名前` | 新しいプロジェクトを作る | 最初に 1 回 |
| `cargo check` | コンパイルできるかだけ確かめる（実行ファイルは作らない） | 書いている途中に何度も |
| `cargo build` | デバッグ用にビルドする | 実行ファイルが欲しいとき |
| `cargo run` | ビルドして実行する | 動作を確かめるとき |
| `cargo build --release` | 最適化を有効にしてビルドする | 完成品・速度の計測 |

`cargo check` は実行ファイルを作る段階を省くので、`cargo build` よりずっと速く終わります。書きながら `cargo check` を何度も走らせて、コンパイラに間違いを指摘してもらうのが Rust らしい書き方です。

### リリースビルド

`cargo build --release` は、時間をかけて最適化した実行ファイルを `target/release/` に作ります。コンパイルは遅くなりますが、できたプログラムはずっと速く動きます。速度を測るときは、必ずリリースビルドで測ってください。

### 慣習としての Cargo

どんな Rust プロジェクトでも、Git でクローンしてきたら次の 3 行で動かせます。これが Cargo を使う最大の利点です。

```console
$ git clone example.org/someproject
$ cd someproject
$ cargo build
```

## この章のまとめ {#summary}

- `rustup` で Rust をインストール・更新する
- `rustc` でファイルを直接コンパイルできるが、普段は `cargo` を使う
- `cargo new` でプロジェクトを作り、`cargo check` / `cargo run` / `cargo build --release` を使い分ける
- `!` の付いた `println!` はマクロ

次の章では、もう少し本格的なプログラム、数当てゲームを作りながら、Rust の色々な機能を駆け足で体験します。
