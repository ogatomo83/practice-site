## シングルスレッドの Web サーバ {#single-threaded}

### TCP と HTTP

Web サーバで使われる主なプロトコルは 2 つです。

| プロトコル | 層 | 役割 |
| --- | --- | --- |
| **TCP**（Transmission Control Protocol） | 下位 | 情報をあるサーバから別のサーバへ届ける方法。中身は問わない |
| **HTTP**（Hypertext Transfer Protocol） | 上位 | TCP の上で、リクエストとレスポンスの中身の形式を定める |

どちらも**リクエスト・レスポンス型**のプロトコルです。**クライアント**がリクエストを送り、**サーバ**がそれを受けてレスポンスを返します。

### TCP の接続を待ち受ける

```console
$ cargo new hello
$ cd hello
```

```rust file="src/main.rs"
use std::net::TcpListener;

fn main() {
    let listener = TcpListener::bind("127.0.0.1:7878").unwrap();

    for stream in listener.incoming() {
        let stream = stream.unwrap();

        println!("Connection established!");
    }
}
```

- `TcpListener::bind` は、指定したアドレスとポートで待ち受けを始めます。`127.0.0.1` は自分のコンピュータ、`7878` はポート番号です（電話のキーパッドで「rust」と打つと 7878 になります）
- `bind` は失敗することもあるので `Result` を返します。管理者権限が必要なポート（1023 以下）や、他のプログラムが使っているポートだと失敗します
- `incoming` は、接続の試み（`TcpStream`）のイテレータを返します。**ストリーム**は、クライアントとサーバの間の 1 つの開いた接続です

`cargo run` して、ブラウザで `127.0.0.1:7878` を開いてみてください。ブラウザはエラーを表示しますが、ターミナルには `Connection established!` が何度か表示されます。

### リクエストを読む

```rust file="src/main.rs"
use std::{
    io::{prelude::*, BufReader},
    net::{TcpListener, TcpStream},
};

fn main() {
    let listener = TcpListener::bind("127.0.0.1:7878").unwrap();

    for stream in listener.incoming() {
        let stream = stream.unwrap();

        handle_connection(stream);
    }
}

fn handle_connection(mut stream: TcpStream) {
    let buf_reader = BufReader::new(&stream);
    let http_request: Vec<_> = buf_reader
        .lines()
        .map(|result| result.unwrap())
        .take_while(|line| !line.is_empty())
        .collect();

    println!("Request: {http_request:#?}");
}
```

`BufReader` でストリームを包むと、`lines` で 1 行ずつ読めます。HTTP のリクエストは、空行でヘッダが終わるので、`take_while` で空行が来るまでを集めます。

### リクエストに応じて返すものを変える

今はどんなリクエストにも同じ HTML を返しています。`/` 以外のパスには 404 を返しましょう。

```rust file="src/main.rs"
fn handle_connection(mut stream: TcpStream) {
    let buf_reader = BufReader::new(&stream);
    let request_line = buf_reader.lines().next().unwrap().unwrap();

    let (status_line, filename) = if request_line == "GET / HTTP/1.1" {
        ("HTTP/1.1 200 OK", "hello.html")
    } else {
        ("HTTP/1.1 404 NOT FOUND", "404.html")
    };

    let contents = fs::read_to_string(filename).unwrap();
    let length = contents.len();

    let response =
        format!("{status_line}\r\nContent-Length: {length}\r\n\r\n{contents}");

    stream.write_all(response.as_bytes()).unwrap();
}
```

`404.html` も用意しておきます。`if` と `else` で違うのはステータス行とファイル名だけなので、それだけを `if` 式でタプルとして選び、残りの処理は共通にしています。

## マルチスレッド化する {#multithreaded}

### 遅いリクエストを再現する

今のサーバは、リクエストを**1 つずつ順番に**処理します。時間のかかるリクエストが来ると、後ろのリクエストはすべて待たされます。`/sleep` にアクセスすると 5 秒かかる、というリクエストを追加して確かめましょう。

### スレッドプール

**スレッドプール**は、あらかじめ作っておいた、仕事を待っているスレッドの集まりです。新しい仕事が来たら、プールの中の空いているスレッドに割り当てます。仕事が終わったスレッドはプールに戻り、次の仕事を待ちます。

リクエストごとにスレッドを作るという方法もありますが、それだと大量のリクエストが来たときにスレッドを作りすぎて、システムが止まってしまいます（DoS 攻撃に弱い）。スレッドの数を固定しておけば、その心配はありません。

### コンパイラ駆動開発で API を決める

まず、**使う側のコードを先に書きます**。そして、コンパイルエラーを頼りに、必要なものを 1 つずつ作っていきます。

```rust file="src/main.rs"
fn main() {
    let listener = TcpListener::bind("127.0.0.1:7878").unwrap();
    let pool = ThreadPool::new(4);

    for stream in listener.incoming() {
        let stream = stream.unwrap();

        pool.execute(|| {
            handle_connection(stream);
        });
    }
}
```

`thread::spawn` と同じような感覚で、`pool.execute` にクロージャを渡したい、というのが目標です。

### ThreadPool の定義

`src/lib.rs` を作り、`ThreadPool` を定義します。

```rust file="src/lib.rs"
pub struct ThreadPool;

impl ThreadPool {
    /// 新しい ThreadPool を作る
    ///
    /// size はプールのスレッドの数
    ///
    /// # Panics
    ///
    /// size が 0 のとき、`new` はパニックする
    pub fn new(size: usize) -> ThreadPool {
        assert!(size > 0);

        ThreadPool
    }

    pub fn execute<F>(&self, f: F)
    where
        F: FnOnce() + Send + 'static,
    {
    }
}
```

`execute` のトレイト境界は、`thread::spawn` のシグネチャを参考にしています。

```rust
pub fn spawn<F, T>(f: F) -> JoinHandle<T>
where
    F: FnOnce() -> T,
    F: Send + 'static,
    T: Send + 'static,
```

| 境界 | 理由 |
| --- | --- |
| `FnOnce()` | 仕事（リクエストの処理）は 1 回だけ実行される |
| `Send` | クロージャを別のスレッドに送る必要がある |
| `'static` | スレッドがいつまで動くかわからないので、クロージャは借用を持てない |

### スレッドを保持する Worker

`ThreadPool` にスレッドを持たせたいのですが、`thread::spawn` は作った瞬間にコードの実行を始めてしまいます。プールのスレッドは「仕事が来るまで待つ」必要があります。

そこで、スレッドと ID を持つ **`Worker`** という構造体を用意し、`ThreadPool` は `Worker` のベクタを持つことにします。

```rust file="src/lib.rs"
use std::thread;

pub struct ThreadPool {
    workers: Vec<Worker>,
}

impl ThreadPool {
    // --snip--
    pub fn new(size: usize) -> ThreadPool {
        assert!(size > 0);

        let mut workers = Vec::with_capacity(size);

        for id in 0..size {
            workers.push(Worker::new(id));
        }

        ThreadPool { workers }
    }
    // --snip--
}

struct Worker {
    id: usize,
    thread: thread::JoinHandle<()>,
}

impl Worker {
    fn new(id: usize) -> Worker {
        let thread = thread::spawn(|| {});

        Worker { id, thread }
    }
}
```

### チャネルで仕事を Worker に届ける

`ThreadPool` から `Worker` へ仕事を届けるには、第 16 章のチャネルがぴったりです。

1. `ThreadPool` がチャネルを作り、**送信側**を持つ
2. 各 `Worker` が**受信側**を持つ
3. 送る仕事の型として `Job` を定義する
4. `execute` は、受け取ったクロージャを送信側から送る
5. `Worker` のスレッドは、受信側をループで待ち、届いたクロージャを実行する

ところが、ここで問題が起きます。`mpsc` は「複数の生産者、**1 つの消費者**」なので、受信側をクローンして複数の `Worker` に配ることはできません。

```rust fail

            workers.push(Worker::new(id, receiver));   // 1 回目でムーブされる
        }
```

複数のスレッドで 1 つの受信側を**共有**し、しかも 1 つの仕事を 1 つの `Worker` だけが受け取るようにしたい。第 16 章の答えが使えます。**`Arc<Mutex<T>>`** です。`Arc` で複数の `Worker` が受信側を所有でき、`Mutex` で一度に 1 つの `Worker` だけが受信側から仕事を取り出せます。

```rust file="src/lib.rs"
use std::{
    sync::{mpsc, Arc, Mutex},
    thread,
};

pub struct ThreadPool {
    workers: Vec<Worker>,
    sender: mpsc::Sender<Job>,
}

type Job = Box<dyn FnOnce() + Send + 'static>;

impl ThreadPool {
    // --snip--
    pub fn new(size: usize) -> ThreadPool {
        assert!(size > 0);

        let (sender, receiver) = mpsc::channel();

        let receiver = Arc::new(Mutex::new(receiver));

        let mut workers = Vec::with_capacity(size);

        for id in 0..size {
            workers.push(Worker::new(id, Arc::clone(&receiver)));
        }

        ThreadPool { workers, sender }
    }

    pub fn execute<F>(&self, f: F)
    where
        F: FnOnce() + Send + 'static,
    {
        let job = Box::new(f);

        self.sender.send(job).unwrap();
    }
}

struct Worker {
    id: usize,
    thread: thread::JoinHandle<()>,
}

impl Worker {
    fn new(id: usize, receiver: Arc<Mutex<mpsc::Receiver<Job>>>) -> Worker {
        let thread = thread::spawn(move || loop {
            let job = receiver.lock().unwrap().recv().unwrap();

            println!("Worker {id} got a job; executing.");

            job();
        });

        Worker { id, thread }
    }
}
```

```fig seq 仕事が届いてから処理されるまで。ロックを持っている Worker だけが recv でき、取り出した直後にロックを手放す
}
```

:::warn while let で書かない理由
ループを `while let Ok(job) = receiver.lock().unwrap().recv() { job(); }` と書きたくなるかもしれません。これはコンパイルできますが、**意図どおりに動きません**。

`let job = receiver.lock().unwrap().recv().unwrap();` では、`lock()` が返した `MutexGuard` は、`let` 文の終わりで**すぐに drop され**、ロックが解放されます。

一方、`while let`（や `if let`、`match`）では、条件式の中で作られた一時的な値は、**ブロックの終わりまで生き続けます**。つまり `job()` を実行している間もロックが握られたままになり、他の `Worker` は仕事を受け取れません。せっかくのマルチスレッドが、事実上シングルスレッドになってしまうのです。
:::

## 正常なシャットダウンと片付け {#shutdown}

今のサーバを Ctrl-C で止めると、処理中のリクエストがあっても、すべてのスレッドが即座に止まります。ここでは、**`Drop` トレイト**を実装して、プールが drop されるときに各スレッドの `join` を呼び、**処理中の仕事を終えてから止まる**ようにします。

### Drop で join する

```rust file="src/lib.rs" fail
        }
    }
}
```

### Worker にループを抜けさせる

しかし、これだけでは終わりません。`Worker` のスレッドは `loop` で永遠に仕事を待っているので、`join` は永遠に戻ってきません。**デッドロック**です。

`Worker` にループを抜けさせるには、**チャネルを閉じる**のが一番です。送信側を drop すると、受信側の `recv` は `Err` を返すようになります。`Worker` はそれを合図にループを抜ければよいのです。

送信側を先に drop できるように、`sender` を `Option` で包みます。

## 完成したコード {#final}

```rust file="src/main.rs"
use hello::ThreadPool;
use std::{
    fs,
    io::{prelude::*, BufReader},
    net::{TcpListener, TcpStream},
    thread,
    time::Duration,
};

fn main() {
    let listener = TcpListener::bind("127.0.0.1:7878").unwrap();
    let pool = ThreadPool::new(4);

    for stream in listener.incoming().take(2) {
        let stream = stream.unwrap();

        pool.execute(|| {
            handle_connection(stream);
        });
    }

    println!("Shutting down.");
}

fn handle_connection(mut stream: TcpStream) {
    let buf_reader = BufReader::new(&stream);
    let request_line = buf_reader.lines().next().unwrap().unwrap();

    let (status_line, filename) = match &request_line[..] {
        "GET / HTTP/1.1" => ("HTTP/1.1 200 OK", "hello.html"),
        "GET /sleep HTTP/1.1" => {
            thread::sleep(Duration::from_secs(5));
            ("HTTP/1.1 200 OK", "hello.html")
        }
        _ => ("HTTP/1.1 404 NOT FOUND", "404.html"),
    };

    let contents = fs::read_to_string(filename).unwrap();
    let length = contents.len();

    let response =
        format!("{status_line}\r\nContent-Length: {length}\r\n\r\n{contents}");

    stream.write_all(response.as_bytes()).unwrap();
}
```

```rust file="src/lib.rs"
use std::{
    sync::{mpsc, Arc, Mutex},
    thread,
};

pub struct ThreadPool {
    workers: Vec<Worker>,
    sender: Option<mpsc::Sender<Job>>,
}

type Job = Box<dyn FnOnce() + Send + 'static>;

impl ThreadPool {
    /// 新しい ThreadPool を作る
    ///
    /// size はプールのスレッドの数
    ///
    /// # Panics
    ///
    /// size が 0 のとき、`new` はパニックする
    pub fn new(size: usize) -> ThreadPool {
        assert!(size > 0);

        let (sender, receiver) = mpsc::channel();

        let receiver = Arc::new(Mutex::new(receiver));

        let mut workers = Vec::with_capacity(size);

        for id in 0..size {
            workers.push(Worker::new(id, Arc::clone(&receiver)));
        }

        ThreadPool {
            workers,
            sender: Some(sender),
        }
    }

    pub fn execute<F>(&self, f: F)
    where
        F: FnOnce() + Send + 'static,
    {
        let job = Box::new(f);

        self.sender.as_ref().unwrap().send(job).unwrap();
    }
}

impl Drop for ThreadPool {
    fn drop(&mut self) {
        drop(self.sender.take());

        for worker in self.workers.drain(..) {
            println!("Shutting down worker {}", worker.id);

            worker.thread.join().unwrap();
        }
    }
}

struct Worker {
    id: usize,
    thread: thread::JoinHandle<()>,
}

impl Worker {
    fn new(id: usize, receiver: Arc<Mutex<mpsc::Receiver<Job>>>) -> Worker {
        let thread = thread::spawn(move || {
            loop {
                let message = receiver.lock().unwrap().recv();

                match message {
                    Ok(job) => {
                        println!("Worker {id} got a job; executing.");

                        job();
                    }
                    Err(_) => {
                        println!("Worker {id} disconnected; shutting down.");
                        break;
                    }
                }
            }
        });

        Worker { id, thread }
    }
}
```
