## 変数と可変性 {#variables}

第 2 章で触れたとおり、Rust の変数は**デフォルトで不変（immutable）**です。一度値を入れたら、その値は変えられません。

```rust fail
fn main() {
    let x = 5;
    println!("The value of x is: {x}");
    x = 6;
    println!("The value of x is: {x}");
}
```

```console
error[E0384]: cannot assign twice to immutable variable `x`
 --> src/main.rs:4:5
  |
2 |     let x = 5;
  |         - first assignment to `x`
3 |     println!("The value of x is: {x}");
4 |     x = 6;
  |     ^^^^^ cannot assign twice to immutable variable
  |
help: consider making this binding mutable
  |
2 |     let mut x = 5;
  |         +++
```

なぜデフォルトが不変なのでしょうか。コードのある部分が「この値は変わらない」と思って書かれているのに、別の部分がこっそり値を変えてしまう。これは原因を突き止めにくいバグの典型です。不変がデフォルトなら、**値が変わる可能性がある場所は `mut` と書かれた場所だけ**になり、コードを読むときに追いかける範囲がぐっと狭まります。

変えたいときは `mut` を付けます。

```rust
fn main() {
    let mut x = 5;
    println!("The value of x is: {x}"); // 5
    x = 6;
    println!("The value of x is: {x}"); // 6
}
```

### 定数

**定数（constant）**も「変えられない値」ですが、不変の変数とはいくつか違いがあります。

```rust
const THREE_HOURS_IN_SECONDS: u32 = 60 * 60 * 3;
```

| | 不変の変数 `let` | 定数 `const` |
| --- | --- | --- |
| `mut` を付けられるか | 付けられる | 付けられない（常に不変） |
| 型注釈 | 省略できる | **必須** |
| 書ける場所 | 関数の中 | グローバルスコープを含むどこでも |
| 値 | 実行時に計算した値でもよい | コンパイル時に計算できる式だけ |
| 命名規則 | `snake_case` | `SCREAMING_SNAKE_CASE` |

プログラムの中で何度も使う固定値（最大ポイント数、光の速さなど）に名前を付けておくと、意味が伝わりやすく、変更するときも 1 か所で済みます。

### シャドーイング

同じ名前で `let` を書き直すと、新しい変数が前の変数を**覆い隠し（shadow）**ます。

```rust
fn main() {
    let x = 5;

    let x = x + 1;          // 新しい x（6）が前の x を隠す

    {
        let x = x * 2;      // このブロックの中だけ、さらに新しい x（12）
        println!("The value of x in the inner scope is: {x}"); // 12
    }

    println!("The value of x is: {x}"); // 6（内側の x はブロックと一緒に消えた）
}
```

```fig mem シャドーイングでは、毎回新しい変数が作られる。前の変数は消えるのではなく、名前で呼べなくなるだけ

    { title: '{ let x = x * 2 }', stack: [{ frame: 'main', vars: [{ name: 'x', value: '5', state: 'dead', deadLabel: '隠された' }, { name: 'x', value: '6', state: 'dead', deadLabel: '隠された' }] }, { frame: '内側のブロック', vars: [{ name: 'x', value: '12' }] }], say: '内側のブロックでさらに新しい x（12）' },

  ],

```

シャドーイングと `mut` の違いは 2 つあります。

1. シャドーイングは `let` を書かないと起きないので、うっかり値を書き換えてしまう心配がない
2. **型を変えられる**。新しい変数を作っているからです

```rust
let spaces = "   ";          // 文字列
let spaces = spaces.len();   // 数値（3）に変えられる
```

`mut` で同じことをしようとすると、型が違うのでエラーになります。

```rust fail
let mut spaces = "   ";
spaces = spaces.len(); // error[E0308]: mismatched types
```

## データ型 {#data-types}

Rust は**静的型付け**言語です。すべての値の型が、コンパイルの時点で決まっていなければなりません。ほとんどの場合はコンパイラが型を推論してくれますが、推論できないときは型注釈を書きます。

```rust
let guess: u32 = "42".parse().expect("Not a number!");
```

ここで `: u32` を消すと、`parse` が何の型に変換すればいいかわからず、エラーになります。

```console
error[E0284]: type annotations needed
 --> src/main.rs:2:9
  |
2 |     let guess = "42".parse().expect("Not a number!");
  |         ^^^^^        ----- type must be known at this point
  |
help: consider giving `guess` an explicit type
  |
2 |     let guess: /* Type */ = "42".parse().expect("Not a number!");
  |              ++++++++++++
```

Rust の型は、大きく**スカラー型**と**複合型**に分かれます。

### 整数型

| 長さ | 符号あり | 符号なし | 符号ありの範囲 |
| --- | --- | --- | --- |
| 8 bit | `i8` | `u8` | -128 〜 127 |
| 16 bit | `i16` | `u16` | -32,768 〜 32,767 |
| 32 bit | `i32` | `u32` | 約 ±21 億 |
| 64 bit | `i64` | `u64` | 約 ±922 京 |
| 128 bit | `i128` | `u128` | 約 ±1.7 × 10^38 |
| アーキテクチャ依存 | `isize` | `usize` | 64 bit 環境なら 64 bit |

`i` は符号あり（integer）、`u` は符号なし（unsigned）です。`n` ビットの符号ありなら -(2^(n-1)) から 2^(n-1) - 1 まで、符号なしなら 0 から 2^n - 1 までを表せます。

迷ったら `i32` を使ってください。これがデフォルトです。`usize` は、コレクションの添字（インデックス）や長さに使われます。

整数リテラルはいくつかの書き方ができます。

| 書き方 | 例 |
| --- | --- |
| 10 進数（区切りに `_` を使える） | `98_222` |
| 16 進数 | `0xff` |
| 8 進数 | `0o77` |
| 2 進数 | `0b1111_0000` |
| バイト（`u8` のみ） | `b'A'` |
| 型の接尾辞 | `57u8`, `1_000i64` |

:::deep 整数オーバーフローはどうなるか
`u8` の変数に 256 を入れようとすると何が起きるでしょうか。

- **デバッグビルド**では、オーバーフローを検出してプログラムを**パニック**（エラーで終了）させます。
- **リリースビルド**（`--release`）では検査を省き、**2 の補数ラップアラウンド**をします。256 は 0 に、257 は 1 になります。

どちらにしても、オーバーフローに頼るのはバグです。意図的に扱いたいときは、標準ライブラリのメソッドを使います。

| メソッド | 振る舞い | `250u8` に `+10` |
| --- | --- | --- |
| `wrapping_add` | 常にラップアラウンド | `4` |
| `checked_add` | 溢れたら `None` | `None` |
| `overflowing_add` | 値と溢れたかどうかの組 | `(4, true)` |
| `saturating_add` | 最大値・最小値で止める | `255` |
:::

### 浮動小数点型・数値演算

浮動小数点数には `f32` と `f64` があり、デフォルトは `f64` です。今の CPU では `f64` も `f32` とほぼ同じ速さで、精度は高くなります。

```rust
fn main() {
    let x = 2.0;      // f64
    let y: f32 = 3.0; // f32

    let sum = 5 + 10;              // 加算
    let difference = 95.5 - 4.3;   // 減算
    let product = 4 * 30;          // 乗算
    let quotient = 56.7 / 32.2;    // 除算
    let truncated = -5 / 3;        // 整数の除算は 0 に向かって切り捨て → -1
    let remainder = 43 % 5;        // 剰余 → 3
}
```

### 論理値型と文字型

```rust
let t = true;
let f: bool = false;

let c = 'z';
let z: char = 'ℤ';
let heart_eyed_cat = '😻';
```

`char` は**シングルクォート**で書きます（文字列はダブルクォート）。Rust の `char` は 4 バイトで、1 つの **Unicode スカラー値**を表します。ASCII だけでなく、日本語、絵文字なども 1 つの `char` です。ただし、人間が「1 文字」と感じるものと `char` は必ずしも一致しません（第 8 章）。

### タプル型

**タプル**は、型の異なる値をいくつかまとめて 1 つの値にするものです。長さは固定です。

```rust
let tup: (i32, f64, u8) = (500, 6.4, 1);

let (x, y, z) = tup;          // 分配（destructuring）で取り出す
println!("The value of y is: {y}");

let five_hundred = tup.0;     // 添字でも取り出せる
let six_point_four = tup.1;
let one = tup.2;
```

### 配列型

**配列**は、同じ型の値を決まった数だけ並べたものです。

```rust
let a = [1, 2, 3, 4, 5];
let a: [i32; 5] = [1, 2, 3, 4, 5];   // 型は [要素の型; 要素数]
let a = [3; 5];                      // [3, 3, 3, 3, 3]

let first = a[0];
let second = a[1];
```

配列はヒープではなく**スタック**に置かれます。要素数が実行時に変わる可能性があるなら、標準ライブラリの**ベクタ** `Vec<T>` を使います（第 8 章）。配列が向いているのは、月の名前のように数が決まっているデータです。

### 範囲外アクセスは必ず止まる

配列の範囲外にアクセスしたらどうなるでしょうか。

```rust panic
use std::io;

fn main() {
    let a = [1, 2, 3, 4, 5];

    println!("Please enter an array index.");
    let mut index = String::new();
    io::stdin().read_line(&mut index).expect("Failed to read line");
    let index: usize = index.trim().parse().expect("Index entered was not a number");

    let element = a[index];
    println!("The value of the element at index {index} is: {element}");
}
```

`10` を入力すると、次のようにパニックします。

```console
thread 'main' panicked at src/main.rs:19:19:
index out of bounds: the len is 5 but the index is 10
```

C 言語なら、範囲外のメモリを黙って読んでしまい、何が起きるかわかりません。Rust は添字を使うたびに範囲をチェックし、外れていれば**その場でプログラムを止めます**。不正なメモリに触れて動き続けるより、止まるほうがずっと安全です。

## 関数 {#functions}

関数は `fn` で定義します。関数名や変数名は **スネークケース**（小文字をアンダースコアでつなぐ）にするのが慣習です。

```rust
fn main() {
    println!("Hello, world!");

    another_function();
}

fn another_function() {
    println!("Another function.");
}
```

`another_function` は `main` の後に定義されていますが、問題なく呼べます。Rust は関数を定義する順番を気にしません。

### 引数

関数の引数には、**必ず型を書きます**。シグネチャに型があれば、コンパイラは関数の中身を見ずに呼び出し側をチェックできますし、エラーメッセージもわかりやすくなります。

```rust
fn main() {
    print_labeled_measurement(5, 'h');
}

fn print_labeled_measurement(value: i32, unit_label: char) {
    println!("The measurement is: {value}{unit_label}");
}
```

### 文と式

Rust を理解するうえでとても大切なのが、**文（statement）**と**式（expression）**の区別です。

- **文** は、何かの処理をするだけで、値を返さない
- **式** は、評価されて値になる

`let y = 6;` は文なので値を返しません。そのため、C や Ruby のように `x = y = 6` とは書けません。

```rust fail
fn main() {
    let x = (let y = 6); // let は文なので値を持たない
}
```

一方、波かっこのブロック `{ }` は**式**です。ブロックの値は、最後の式の値になります。

```rust
fn main() {
    let y = {
        let x = 3;
        x + 1        // ← セミコロンがない。これがブロックの値になる
    };

    println!("The value of y is: {y}"); // 4
}
```

:::key セミコロンの意味
式の末尾にセミコロンを付けると、それは**文**になり、値を返さなくなります。`x + 1` は値 4 を持つ式ですが、`x + 1;` は値を持たない文です。この違いが、次の「戻り値」で効いてきます。
:::

### 戻り値

戻り値の型は `->` の後に書きます。関数の本体はブロックなので、**最後の式の値がそのまま戻り値**になります。`return` で途中から返すこともできますが、最後の式で返すのが普通です。

```rust
fn five() -> i32 {
    5
}

fn plus_one(x: i32) -> i32 {
    x + 1
}

fn main() {
    let x = plus_one(five());
    println!("The value of x is: {x}"); // 6
}
```

うっかり最後にセミコロンを付けると、エラーになります。

```rust fail
fn plus_one(x: i32) -> i32 {
    x + 1;
}
```

```console
error[E0308]: mismatched types
 --> src/main.rs:7:24
  |
7 | fn plus_one(x: i32) -> i32 {
  |    --------            ^^^ expected `i32`, found `()`
  |    |
  |    implicitly returns `()` as its body has no tail or `return` expression
8 |     x + 1;
  |          - help: remove this semicolon to return this value
```

:::rustc E0308 i32 を期待しましたが、() が見つかりました
`x + 1;` は文なので、関数の本体は値を持たず、ユニット `()` を返したことになります。`help` がセミコロンを消すよう提案しています。「`()` が見つかった」というエラーを見たら、まず余計なセミコロンを疑いましょう。
:::

## コメント {#comments}

コメントは `//` から行末までです。複数行にわたるときは、各行に `//` を付けます。

```rust
// これはコメントです。
// 長い説明は、このように
// 各行に // を付けて書きます。

fn main() {
    let lucky_number = 7; // 行の終わりにも書ける
}
```

`///` で始まる**ドキュメンテーションコメント**もあります。こちらは HTML のドキュメントとして出力されるもので、第 14 章で扱います。

## 制御フロー {#control-flow}

### if 式

```rust
fn main() {
    let number = 3;

    if number < 5 {
        println!("condition was true");
    } else {
        println!("condition was false");
    }
}
```

条件は**必ず `bool` 型**でなければなりません。JavaScript のように、数値や文字列を自動で真偽値に変換してはくれません。

```rust fail
let number = 3;
if number {  // error[E0308]: expected `bool`, found integer
    println!("number was three");
}
```

`0` でないことを確かめたいなら、`if number != 0` と明示的に書きます。

`else if` で条件を重ねられます。上から順に評価され、最初に真になったブロックだけが実行されます。`else if` が多くなってきたら、第 6 章の `match` を使うと読みやすくなります。

### if は式

`if` は**式**なので、値を返せます。`let` の右辺に置けば、三項演算子のように使えます。

```rust
let condition = true;
let number = if condition { 5 } else { 6 };
```

それぞれの腕の値は、**同じ型**でなければなりません。変数の型はコンパイル時に 1 つに決まっている必要があるからです。

```rust fail
let number = if condition { 5 } else { "six" };
// error[E0308]: `if` and `else` have incompatible types
```

#### loop

`loop` は `break` するまで繰り返します。`break` の後ろに値を書くと、それが `loop` 式の値になります。「成功するまで再試行して、結果を返す」といった処理に便利です。

```rust
fn main() {
    let mut counter = 0;

    let result = loop {
        counter += 1;

        if counter == 10 {
            break counter * 2;   // loop の値として 20 を返す
        }
    };

    println!("The result is {result}"); // 20
}
```

#### ループラベル

ループが入れ子になっているとき、`break` や `continue` は一番内側のループに作用します。外側のループを抜けたいときは、**ループラベル**を付けます。ラベルはシングルクォートで始めます。

```rust
fn main() {
    let mut count = 0;
    'counting_up: loop {
        println!("count = {count}");
        let mut remaining = 10;

        loop {
            println!("remaining = {remaining}");
            if remaining == 9 {
                break;                 // 内側のループだけを抜ける
            }
            if count == 2 {
                break 'counting_up;    // 外側のループを抜ける
            }
            remaining -= 1;
        }

        count += 1;
    }
    println!("End count = {count}");
}
```

#### while

条件が真の間だけ繰り返します。`loop` と `if` と `break` を組み合わせて書けることを、短く書けます。

```rust
fn main() {
    let mut number = 3;

    while number != 0 {
        println!("{number}!");
        number -= 1;
    }

    println!("LIFTOFF!!!");
}
```

#### for

コレクションの要素を 1 つずつ処理するなら、`for` が最も安全で簡潔です。

```rust
fn main() {
    let a = [10, 20, 30, 40, 50];

    for element in a {
        println!("the value is: {element}");
    }
}
```

`while` と添字で同じことを書くこともできますが、添字の範囲を間違えるとパニックしますし、毎回の範囲チェックのぶん遅くなります。`for` なら範囲外アクセスは起こり得ません。

決まった回数だけ繰り返したいときも、範囲（`Range`）と `for` を使います。

```rust
fn main() {
    for number in (1..4).rev() {   // 3, 2, 1 の順
        println!("{number}!");
    }
    println!("LIFTOFF!!!");
}
```

## この章のまとめ {#summary}

| 概念 | Rust ならでは のポイント |
| --- | --- |
| 変数 | デフォルトで不変。変えたいなら `mut` |
| シャドーイング | 同名の `let` で新しい変数を作る。型も変えられる |
| 整数 | 迷ったら `i32`。添字は `usize`。デバッグビルドではオーバーフローでパニック |
| 配列 | 範囲外アクセスは必ずパニック。黙って不正なメモリを読まない |
| 関数 | 引数の型は必須。最後の式が戻り値（セミコロンを付けない） |
| `if` | 条件は `bool` のみ。式なので値を返せる |
| ループ | `loop`（値を返せる）、`while`、`for`（最も安全） |
