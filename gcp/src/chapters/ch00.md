## この本について {#about}

この本は、**Google Cloud**（グーグル クラウド。以前の名前から今も **GCP**、Google Cloud Platform と呼ばれます）を体系的に学ぶための日本語の学習書です。Google Cloud は、Google のデータセンターにある計算機、ストレージ、データベース、分析の仕組みを、インターネット越しに借りて使うサービスの集まりです。

Google Cloud のサービスは 100 を超えます。全部を順に説明すると、どれも浅くなります。そこでこの本は、2 つのことに絞りました。

- **どのサービスにも共通する土台**：組織・フォルダ・プロジェクトという入れ物、リージョンとゾーン、請求先アカウント、アカウントの種類（人の Google アカウント、グループ、サービスアカウント）、IAM（だれに何を許すか）
- **よく使う主要サービス**：Cloud Storage、Compute Engine、VPC、Cloud Run、Cloud Run functions、Pub/Sub、Firestore、Cloud SQL、BigQuery、Cloud Logging と Monitoring

土台を先に固めるのは、つまずきの多くがそこで起きるからです。「API が有効になっていない」「請求先がない」「権限がない」「プロジェクトが違う」。この 4 つのエラーは、どのサービスを使っても出てきます。仕組みが分かっていれば、エラーの文を読んだだけで直し方が分かります。

書くときに決めたルールは 3 つです。

1. **自分の手で動かす。** 本文のコマンドは、ほぼすべてその場で実行できます。
2. **入れ物と権限を、いつも見えるようにする。** どのリソースがどのプロジェクトにあり、だれがどのロールを持っているかを、画面の下に木の形で出します。
3. **本物と同じ形にする。** コマンドの名前、フラグ、出力の形、エラーの文は、本物の `gcloud` と `bq` に合わせてあります。

前提にする知識は、コマンドを打つ画面（シェル）を少し触ったことがある程度です。シェルが初めての人は、先に[図解 Linux](../../linux/site/ch02.html) の第 2 章を読むと楽になります。

## まず動かす：最初の gcloud {#first-run}

説明の前に、1 つ動かしてみましょう。下のブロックの「実行」ボタンを押してください。

```sh run title="最初の gcloud"
gcloud config list
```

**`gcloud`**（ジー クラウド）は、Google Cloud を操作するコマンドです。`gcloud config list` は、いまの設定を表示します。`account` がいまログインしているアカウント、`project` がいま操作の対象にしているプロジェクトです。

出力の前に付いている `you@cloudshell:~ (tsubame-shop)$ ` は**プロンプト**です。「コマンドを打ってください」という合図で、かっこの中にいまのプロジェクトが出ています。これは **Cloud Shell**（クラウド シェル）という、ブラウザから使える Google Cloud の端末と同じ形です。

もう 2 つ打ってみます。1 つのブロックに何行かあるときは、上から順に 1 行ずつ実行されます。

```sh run title="プロジェクトの一覧と、その中身"
gcloud projects list
gcloud projects describe tsubame-shop
```

- `gcloud projects list` は、あなたが見られるプロジェクトの一覧です。`tsubame-shop` と `tsubame-public` の 2 つがあります
- `gcloud projects describe` は、1 つのプロジェクトの詳しい情報です。`parent` が、このプロジェクトの「親」（組織）を指しています

**ID**（`tsubame-shop`）、**名前**（`つばめ文具 オンライン店`）、**番号**（`365600345236`）の 3 つが出てきました。プロジェクトは 3 つの呼び名を持っています。その違いは第 2 章で説明します。

## 動かしているのは「小さな GCP」 {#machine}

いまコマンドを実行したのは、本物の Google Cloud ではありません。**このページの中で動いている「小さな GCP」**です。

小さな GCP は、この本のために書いた模型です。Cloud Shell の端末（シェル、`gcloud`、`bq`、`curl`、`node`）と、組織・プロジェクト・IAM・各サービスの振る舞いを、JavaScript でまねています。BigQuery の SQL は DuckDB、Cloud SQL の PostgreSQL は PGlite という、ブラウザで動く本物のデータベースで実行します。

模型なので、本物とは違うところがあります。

- **お金がかからない**。VM を何台作っても、BigQuery で何バイト読んでも、請求は来ません。そのかわり、料金の話は「本物ならいくらか」を文で説明します
- **時計が仮想**。いまは 2026 年 11 月 16 日の午前 9 時（UTC）から始まり、VM の作成やデプロイを実行すると、本物でかかるくらいの時間だけ進みます。だから何度やっても、同じ結果になります
- **できないことがある**。コンソール（Web の管理画面）、本物の SSH の端末、Python や Go の関数などは、ありません。付録に違いの一覧があります

コマンドの名前、フラグ、出力の形は本物に合わせてあります。ここで覚えたことは、本物の Cloud Shell でそのまま使えます。本物で試したくなったら、[無料トライアル](https://cloud.google.com/free)や BigQuery サンドボックス（第 4 章、第 15 章）を使えます。

:::note 登場する人と会社
この本の舞台は、文房具の店「つばめ文具」です。あなたは情報システム担当の **小林 遥**（`you@tsubame.example`）として、つばめ文具の Google Cloud を整えていきます。ほかに、アプリ開発の青木さん（`alice@`）、売上分析の馬場さん（`bob@`）、Workspace の管理者（`admin@`）、社外の協力者（`taro@example.com`）が登場します。`tsubame.example` と `example.com` は、例に使うために予約されたドメインで、実在しません。
:::

## コマンドは、上から順に積み上がる {#stack}

1 つの章の中のブロックは、**上から順に積み上がります**。前のブロックで作ったバケットや VM を、後のブロックが使います。試しに、設定を 1 つ変えてみます。

```sh run title="いまのプロジェクトを変える"
gcloud config set project tsubame-public
gcloud config get-value project
```

プロンプトのかっこの中が `tsubame-public` に変わりました。このあと、このページのどのブロックを実行しても、プロジェクトは `tsubame-public` のままです。戻すには、もう一度 `gcloud config set project tsubame-shop` を打つか、ページの上の **「リセット」** を押します。リセットすると、このページの小さな GCP は最初の状態に戻ります。

前のブロックを飛ばして後のブロックを実行すると、「まだ実行していないブロックがある」と知らせが出ます。そこの「前を順に実行」を押すと、最初の状態に戻してから、上から順に実行し直します。

```sh run title="元に戻す"
gcloud config set project tsubame-shop
```

ブロックの中のコマンドは、書き換えて実行できます。「元に戻す」で、書いてあったコマンドに戻ります。⌘（Ctrl）+ Enter でも実行できます。

## 「クラウドを見る」 {#view}

ページの上の **「クラウドを見る」** を押すと、画面の下にパネルが開きます。

- **階層と IAM**：組織 → フォルダ → プロジェクト → リソースの木。行を押すと、そこに効いている IAM の割り当て（だれに、どのロールか）が、上の階層から引き継いだものも含めて出ます
- **アカウント**：人の Google アカウント、グループ、サービスアカウント
- **API と請求**：プロジェクトごとの請求先と、有効になっている API
- **監査ログ**：「だれが・いつ・何をしたか」の記録

ブロックを実行して新しくできたリソースには、木の左に緑の印が付きます。下のブロックを実行して、パネルの木を見てください。

```sh run title="フォルダを 1 つ作る"
gcloud resource-manager folders create --display-name=sandbox --organization=405918273641
```

組織 `tsubame.example` の下に、フォルダ `sandbox` ができました。出力の `Created [<Folder …>]` という形は、本物の gcloud の、少し古風な表示そのままです。

## 確認問題と実験場 {#quiz-and-play}

各章の終わりには **確認問題** があります。自分でコマンドを書いて「答え合わせ」を押すと、模範解答と同じ出力になるかを判定します。判定は、本文とは別の小さな GCP で行うので、何度試しても本文の状態は変わりません。

答えの数字を直接 `echo` しただけでは正解になりません。判定のときに、準備のデータを変えてもう一度比べるからです。

**実験場**（サイドバーのいちばん下）では、Cloud Shell のように好きなコマンドを打てます。章の流れから外れて試したいときに使ってください。

- この本は、Google Cloud の土台（入れ物、場所、請求、アカウント、IAM）と、主要サービスに絞って説明する

- 1 つの章のブロックは上から順に積み上がる。「リセット」で最初に戻る
- 「クラウドを見る」で、リソースの木と IAM の継承、監査ログが見える

## 確認問題 {#quiz}

最初の 1 問です。プロジェクトの情報は、`--format` を付けると、欲しい項目だけを取り出せます（第 1 章で詳しく扱います）。

:::quiz いまのプロジェクトの番号
いま設定されているプロジェクト（`gcloud config get-value project`）の、プロジェクト番号だけを 1 行で表示してください。

ヒント：`gcloud projects describe プロジェクト --format="value(projectNumber)"` で番号だけが出ます。プロジェクトの ID は `$(gcloud config get-value project)` で取り出せます。

```sh vary
gcloud config set project tsubame-public
```

```sh starter
# ここにコマンドを書く
```

```sh answer
gcloud projects describe $(gcloud config get-value project) --format="value(projectNumber)"
```
:::
