## 関数とは何か {#what}

第 10 章の Cloud Run では、**コンテナ**（プログラムと、動かすのに必要なものを 1 つにまとめた箱）を作ってデプロイしました。どのポートで待ち受けるか、どんな Web の仕組みを使うかは、自分で決めました。

**Cloud Run functions**（クラウド ラン ファンクションズ）は、そこをもっと省きます。書くのは**関数**だけです。「要求が来たら、この関数を呼ぶ」「メッセージが届いたら、この関数を呼ぶ」という形で、1 つの処理を 1 つの関数に書きます。コンテナを作るのも、待ち受けるのも、Google Cloud がやります。

```fig graph 書くのは関数だけ。コンテナにするのも、置くのも、gcloud functions deploy が引き受ける
{

    { id: 'src', label: 'index.js と package.json', sub: 'あなたが書く', x: 0, y: 0, kind: 'accent', mono: false },
    { id: 'build', label: 'Cloud Build', sub: 'コンテナを作る', x: 1, y: 0, kind: 'stack', mono: false },
```

関数を呼ぶきっかけを**トリガー**と呼びます。この章で扱うトリガーは 3 つです。

| トリガー | 関数の種類 | 関数が受け取るもの |
| --- | --- | --- |
| HTTP の要求（`--trigger-http`） | **HTTP 関数** | 要求（`req`）と応答（`res`） |
| Pub/Sub のトピックへの publish（`--trigger-topic`） | **イベント関数** | CloudEvent（できごとの記録） |
| Cloud Storage のバケットにファイルができた（`--trigger-bucket`） | **イベント関数** | CloudEvent |

Cloud Run が向いているのは、Web アプリや API 全体のように、待ち受けるプログラムをまるごと置くときです。Cloud Run functions が向いているのは、「注文が来たら記録する」「ファイルが届いたら取り込む」といった小さな処理や、サービスどうしのつなぎです。

:::hist 名前の移り変わり
この製品は、以前は **Cloud Functions** という名前でした。いまの第 2 世代の関数は、中身が Cloud Run のサービスとして動くようになり、名前も Cloud Run functions に変わりました。コマンドは今も `gcloud functions` のままです。本物のドキュメントや記事で「Cloud Functions」「2nd gen」とあれば、この章と同じものを指していることが多いです。
:::

## Functions Framework で HTTP 関数を書く {#http-function}

HTTP 関数は、`(req, res)` の 2 つを受け取る関数です。`req`（リクエスト）は届いた要求、`res`（レスポンス）は返す応答です。関数は `req` を読み、`res` に書いて終わります。

```fig graph HTTP 関数の 1 往復。req から読み、res に書く
{
  col: 210, row: 90,
  nodes: [
    { id: 'c', label: 'curl', sub: 'GET ?name=Haruka', x: 0, y: 0, kind: 'ext', mono: false },
    { id: 'ff', label: 'Functions Framework', sub: '待ち受けて、関数を呼ぶ', x: 1, y: 0, kind: 'stack', mono: false },
    { id: 'fn', label: 'helloHttp(req, res)', sub: 'あなたの関数', x: 2, y: 0, kind: 'accent' },
    { id: 'rq', label: 'req.query.name', sub: 'URL の ?name=…', x: 1, y: 1, kind: 'plain' },
    { id: 'rb', label: 'req.body.name', sub: 'POST の JSON', x: 2, y: 1, kind: 'plain' },
    { id: 'rs', label: 'res.send / json / status', sub: '応答を書く', x: 3, y: 0, kind: 'crate' },
  ],
  edges: [
    { from: 'c', to: 'ff' }, { from: 'ff', to: 'fn' }, { from: 'rq', to: 'fn', style: 'dashed' }, { from: 'rb', to: 'fn', style: 'dashed' }, { from: 'fn', to: 'rs' },
  ],
}
```

**Functions Framework**（ファンクションズ フレームワーク）は、Google が公開している小さなライブラリです。Node.js では `@google-cloud/functions-framework` という名前です。要求を待ち受けて、名前で登録した関数を呼びます。Cloud Run functions の中では、このライブラリがあなたの関数を包んで動きます。

作業用のディレクトリ `~/hello` を作り、`index.js` に関数を書きます。

```sh run title="index.js：HTTP 関数を 2 つ"
mkdir ~/hello && cd ~/hello
cat > index.js <<'EOF'
const functions = require('@google-cloud/functions-framework');

// GET /?name=… でも、POST の {"name": …} でも、あいさつを返す
functions.http('helloHttp', (req, res) => {
  const greeting = process.env.GREETING || 'Hello';
  const name = req.query.name || req.body.name || 'World';
  console.log(`hello: name=${name}`);
  res.send(`${greeting}, ${name}!\n`);
});

// 注文の合計を JSON で返す
functions.http('orderTotal', (req, res) => {
  const items = req.body.items;
  if (!Array.isArray(items)) {
    res.status(400).json({ error: 'items がありません' });
    return;
  }
  const total = items.reduce((sum, it) => sum + it.price * it.qty, 0);
  res.json({ count: items.length, total });
});
EOF
```

読み方は次のとおりです。

- `functions.http('helloHttp', 関数)` は、「`helloHttp` という名前で、この HTTP 関数を登録する」という意味です。この名前を**エントリポイント**（入口の関数の名前）と呼びます
- `req.query` は URL の `?` の後ろ（クエリ文字列）、`req.body` は POST で送られた本文です。本文が JSON なら、オブジェクトに直してから渡されます
- `res.send(文字列)` は文字列を、`res.json(オブジェクト)` は JSON を返します。`res.status(400)` で、返す状態コードを変えられます。何も付けなければ 200 です
- `process.env.GREETING` は環境変数です。あとで、デプロイのときに値を入れます

Node.js の関数には、もう 1 つ **package.json** が要ります。どのファイルが入口か（`main`）と、使うライブラリ（`dependencies`）を書きます。

```sh run title="package.json"
cat > package.json <<'EOF'
{ "name": "hello", "main": "index.js",
  "dependencies": { "@google-cloud/functions-framework": "^3.0.0" } }
EOF
ls
```

`index.js` と `package.json` の 2 つが並びました。これで、デプロイするものはそろいました。

:::tip exports.名前 の書き方
`functions.http(…)` を使わずに、`exports.helloHttp = (req, res) => { … };` と書くこともできます。モジュールが外に出した（export した）関数のうち、エントリポイントと同じ名前のものが呼ばれます。古い記事にはこの書き方が多く、どちらでも動きます。イベント関数では `functions.cloudEvent(…)` で登録すると、受け取るものが CloudEvent だとはっきりします。
:::

## デプロイして、呼び出す {#deploy}

関数を置くコマンドは `gcloud functions deploy` です。さっそく打ってみます。

```sh run title="API が無効のままデプロイする" error
gcloud functions deploy hello-http --runtime=nodejs22 --region=asia-northeast1 --source=. --entry-point=helloHttp --trigger-http --allow-unauthenticated
```

`PERMISSION_DENIED: Cloud Functions API has not been used in project 365600345236 before or it is disabled.` は、第 3 章で見た「API が無効」のエラーです。数字はプロジェクト番号です。直し方は、文にあるとおり API を有効にすることです。

```sh run title="Cloud Functions API を有効にする"
gcloud services enable cloudfunctions.googleapis.com
gcloud services list --enabled --format="value(config.name)" | grep -E "^(cloudfunctions|run|cloudbuild|artifactregistry|eventarc|pubsub)\."
gcloud config set functions/region asia-northeast1
```

`cloudfunctions.googleapis.com` を 1 つ有効にしただけで、`run`、`cloudbuild`、`artifactregistry`、`eventarc`、`pubsub` も有効になりました。関数は、これらのサービスを組み合わせて動くからです（API の**依存**、第 3 章）。最後の行は関数の既定のリージョンの設定で、このあとは `--region` を省けます。

### デプロイする

```sh run title="HTTP 関数をデプロイする"
gcloud functions deploy hello-http --runtime=nodejs22 --source=. --entry-point=helloHttp --trigger-http --allow-unauthenticated
```

標準エラーに、作業の段階が並びます。`[Build]` でコンテナを作り、`[Service]` で Cloud Run のサービスを作り、`[Healthcheck]` で起動を確かめています。最後に出る yaml が、できた関数の情報です。`url` は関数の URL で、「リージョン - プロジェクト ID」と関数の名前でできています。`serviceConfig.uri` は `run.app` で終わるもう 1 つの URL です（次の節）。`buildConfig` の `entryPoint` と `runtime` が、どの関数をどのランタイムで動かすかです。

`hello-http` は関数の名前です（プロジェクトとリージョンの中で 1 つ）。フラグの意味は次のとおりです。

| フラグ | 意味 |
| --- | --- |
| `--runtime=nodejs22` | ランタイム（動かす言語と版）。Node.js 22 |
| `--source=.` | ソースのディレクトリ。`.` はいまのディレクトリ |
| `--entry-point=helloHttp` | 呼ぶ関数の名前。省くと、関数の名前（`hello-http`）が使われる |
| `--trigger-http` | HTTP の要求で呼ぶ |
| `--allow-unauthenticated` | だれでも（ログインしていない人も）呼べるようにする |

:::note このサイトの GCP では
動かせるランタイムは Node.js（`--runtime=nodejs22` など）だけです。本物は Python、Go、Java、Ruby、PHP、.NET も使えます。`npm install` も行わず、`require` できるのはこのサイトが用意したライブラリだけです。
:::

### 呼び出す

関数の URL に、curl で要求を送ります。

```sh run title="GET、POST、functions call で呼ぶ"
curl "https://asia-northeast1-tsubame-shop.cloudfunctions.net/hello-http?name=Haruka"
curl -X POST -H "Content-Type: application/json" -d '{"name":"Alice"}' https://asia-northeast1-tsubame-shop.cloudfunctions.net/hello-http
gcloud functions call hello-http --data='{"name":"Bob"}'
```

1 つめは `req.query.name` から `Haruka`、2 つめは `req.body.name` から `Alice` を読みました。POST の本文は `Content-Type: application/json` なので、`req.body` は JSON を直したオブジェクトです。3 つめの `gcloud functions call` は、URL を打たずに関数の名前で呼ぶコマンドで、`--data` が POST の本文になります。

### 認証が必要な関数

今度は `--allow-unauthenticated` を付けずに、`orderTotal` をデプロイします。出力は `--format` で状態だけにします。そのあと、トークンなしと、ID トークン付きで呼びます。

```sh run title="認証が必要な関数をデプロイして呼ぶ"
gcloud functions deploy order-total --runtime=nodejs22 --source=. --entry-point=orderTotal --trigger-http --format="value(state)"
curl -s -o /dev/null -w "%{http_code}\n" -X POST -H "Content-Type: application/json" -d '{"items":[]}' https://asia-northeast1-tsubame-shop.cloudfunctions.net/order-total
curl -H "Authorization: Bearer $(gcloud auth print-identity-token)" -X POST -H "Content-Type: application/json" -d '{"items":[{"price":120,"qty":3},{"price":450,"qty":1}]}' https://asia-northeast1-tsubame-shop.cloudfunctions.net/order-total
```

トークンなしでは `403`（Forbidden、禁止）でした。`--allow-unauthenticated` は、関数の Cloud Run のサービスに「`allUsers` に `roles/run.invoker`（呼び出す権限）」を足すフラグです。付けなければ、呼べるのは権限を持つ人だけです。第 10 章と同じく、**ID トークン**（自分がだれかを示す、署名付きの短い文字列）を付けると通ります。`120 × 3 + 450 × 1 = 810` が返りました。

`gcloud functions call` は、あなたのアカウントで呼ぶので、トークンなしで通ります。本文に `items` がないと、関数は `res.status(400)` で 400 を返します。

```sh run title="関数が 400 を返す" error
gcloud functions call order-total --data='{}'
```

`ResponseError: status=[400]` は、関数が 400 を返したことを示します。`message=[…]` には、関数が `res.json` で返した本文がそのまま入っています。`functions call` は 400 以上の応答を、エラーとして表示します。関数そのものが壊れたのではなく、関数が「入力がおかしい」と答えた、という読み方をします。

```sh run title="関数の一覧と、Cloud Run のサービスの一覧"
gcloud functions list
gcloud run services list
```

関数が 2 つ、`HTTP Trigger`（HTTP のトリガー）で `ACTIVE`（動いている）です。`ENVIRONMENT` の `GEN_2` は第 2 世代を表します。そして、Cloud Run のサービスの一覧にも、同じ名前の `hello-http` と `order-total` が出ています。第 10 章の `gcloud run deploy` で作ったものと同じ、**Cloud Run のサービス**です。

だから、`run.app` の URL でも呼べます。
```sh run title="サービスの URL で呼ぶ"
gcloud functions describe hello-http --format="yaml(url,serviceConfig.uri,serviceConfig.revision)"
curl "$(gcloud functions describe hello-http --format='value(serviceConfig.uri)')?name=Run"
```

`serviceConfig.revision` は、いま動いている**リビジョン**（サービスの版）です。関数のコンテナの**イメージ**（コンテナの元になるファイル）は、Artifact Registry の `gcf-artifacts` というリポジトリに置かれます。デプロイの出力の `buildConfig.dockerRepository` が、その場所です。

### 再デプロイと環境変数

`index.js` の `helloHttp` は、環境変数 `GREETING` があれば、それをあいさつに使います。`--set-env-vars` で入れて、もう一度デプロイします。2 回目からは、`--runtime` やトリガーなど、前と同じものは省けます。

```sh run title="環境変数を入れて再デプロイし、リビジョンを見る"
gcloud functions deploy hello-http --source=. --set-env-vars=GREETING=Hi --format="value(serviceConfig.revision)"
curl "https://asia-northeast1-tsubame-shop.cloudfunctions.net/hello-http?name=Haruka"
gcloud run revisions list --service=hello-http --region=asia-northeast1
```

あいさつが `Hi` に変わり、リビジョンの番号が `00002` に進みました。Cloud Run と同じく、デプロイのたびに新しいリビジョンができて、要求はそちらへ向かいます。リビジョンの一覧で `ACTIVE` が `yes` なのも、新しい `00002` のほうです。第 10 章のトラフィック分割（リビジョンに割合で振り分けること）も、仕組みとしては同じものの上に乗っています。

:::deep なぜ Cloud Run の上に作ったのか
関数とコンテナのサービスは、「要求が来たらインスタンス（動いている 1 つの実体）を起こし、来なければ 0 まで減らす」という、同じ土台を必要とします。土台を 1 つにすれば、スケール、リビジョン、トラフィック分割、ログ、IAM の仕組みを、両方で共有できます。関数を使っていて Cloud Run の機能（同時実行の数、最小インスタンス数など）が欲しくなったら、それは Cloud Run の設定です。ただし、関数が作ったサービスは `gcloud functions deploy` で更新するのが基本です。`gcloud run deploy` で直接変えると、関数の設定とずれます。
:::

## console.log はログになる {#logs}

関数の中で `console.log` に書いたものは、**Cloud Logging**（Google Cloud のログの置き場）に 1 行ずつ残ります。関数のログを読むコマンドは `gcloud functions logs read` です。

```sh run title="関数のログを読む"
gcloud functions logs read hello-http
```

新しいものが上で、いままでに呼んだ回数だけ `hello: name=…` の行があります。

`LEVEL` は重大度の頭文字で、`E` がエラーです（`console.log` の行は空）。`EXECUTION_ID` は 1 回の実行の ID で、イベント関数では同じ実行のログに同じ ID が付きます。`LOG` の `Default STARTUP TCP probe succeeded …` は、インスタンスが起動したときに Cloud Run が書いた行です。

`gcloud functions logs read` は、Cloud Logging を関数向けに読みやすくしたものです。中身は、Cloud Run のサービスのログ（`resource.type="cloud_run_revision"`）です。下の 1 行めは `--limit` で行数を絞り、`--format` で中身だけにしたもの、2 行めは `gcloud logging read` で同じログを直接読んだものです。

```sh run title="行数を絞る、Cloud Logging から直接読む"
gcloud functions logs read hello-http --limit=2 --format="value(log)"
gcloud logging read 'resource.type="cloud_run_revision" AND resource.labels.service_name="hello-http" AND textPayload:"hello"' --limit=2 --format="value(textPayload)"
```

`logging read` のほうは `textPayload:"hello"` で `hello` を含む行に絞ったので、起動の行が出ていません。ログのクエリの書き方は、第 16 章でくわしく扱います。

## 失敗を読む：エントリポイントと例外 {#errors}

### エントリポイントの書き間違い

関数でよく出る失敗を、わざと起こします。まず `--entry-point=helloHtp`（`t` が 1 つ足りない）でデプロイします。

```sh run title="エントリポイントを書き間違える" error
gcloud functions deploy hello-typo --runtime=nodejs22 --source=. --entry-point=helloHtp --trigger-http
```

`X [Service] Container Healthcheck failed.` で止まりました。エラーの文の後ろに、理由が書いてあります。

`Function 'helloHtp' is not defined in the provided module.` は「`helloHtp` という関数が、モジュール（`index.js`）の中に見つからない」という意味です。コンテナを作るところ（`[Build]`）までは成功しています。コンテナを起動して、Functions Framework が関数を探したところで失敗しました。直し方は、`--entry-point` を `index.js` の `functions.http('…')` の名前と同じにすることです。大文字と小文字も区別されます。

失敗した関数も、一覧には残ります。
```sh run title="失敗した関数の状態とログ。そして消す"
gcloud functions list --format="table(name.basename(),state)"
gcloud functions logs read hello-typo
gcloud functions delete hello-typo --quiet
```

`hello-typo` は `FAILED` です。ログには、起動に失敗したときの文がそのまま残っています。デプロイで失敗したら、まず `functions logs read` を見るのが近道です。最後の `delete` で、いらない関数を消しました。`--quiet` は「消してよいか」の確認を省くフラグです。

### 関数の中で例外を投げる

デプロイは通っても、呼ばれたときに失敗することがあります。`index.js` に、もう 1 つ関数を足します。`>>` は、ファイルの終わりに書き足すリダイレクトです。

```sh run title="例外を投げうる関数を書き足す"
cat >> index.js <<'EOF'

// 品物の名前を大文字にして返す。item がないと例外になる
functions.http('stock', (req, res) => {
  const item = req.body.item;
  res.send(`${item.toUpperCase()} の在庫を調べます\n`);
});
EOF
gcloud functions deploy stock --runtime=nodejs22 --source=. --trigger-http --allow-unauthenticated --format="value(buildConfig.entryPoint)"
```

`--entry-point` を省いたので、関数の名前の `stock` がエントリポイントになりました。正しい本文と、`item` のない本文で呼び、ログを見ます。

```sh run title="item のない要求で 500 になる"
curl -X POST -H "Content-Type: application/json" -d '{"item":"pen"}' https://asia-northeast1-tsubame-shop.cloudfunctions.net/stock
curl -i -X POST -H "Content-Type: application/json" -d '{}' https://asia-northeast1-tsubame-shop.cloudfunctions.net/stock
gcloud functions logs read stock --limit=6
```

2 つめは `HTTP/2 500` と `Internal Server Error` が返りました。500 は「サーバの中で何かが壊れた」という状態コードで、呼んだ側には理由が知らされません。理由はログにあります。

`E`（エラー）の行に `TypeError: Cannot read properties of undefined (reading 'toUpperCase')` があります。「`undefined`（値がない）の `toUpperCase` を読もうとした」、つまり `req.body.item` がなかった、という意味です。関数が投げた例外は、Functions Framework が受け止めて 500 を返し、例外の中身をログに書きます。入力を調べて `res.status(400)` を返す `orderTotal` の書き方なら、呼んだ側にも理由を伝えられます。

## イベント関数：Pub/Sub のメッセージで動く {#pubsub-trigger}

ここからは、HTTP ではなく**イベント**（何かが起きたこと）で動く関数です。まず Pub/Sub です。**Pub/Sub**（パブサブ）は、メッセージを**トピック**（宛先の名前）に送ると、そのトピックを購読しているところへ届ける仕組みです。第 12 章でくわしく扱います。

```fig seq Pub/Sub のトリガー。デプロイのときに、Eventarc がトピックに push のサブスクリプションを作っておく
{
  colw: 190,
  actors: [
    { id: 'you', label: 'あなた', kind: 'ext' },
    { id: 't', label: 'トピック orders', kind: 'stack' },
    { id: 's', label: 'eventarc-…-sub', kind: 'stack' },
    { id: 'f', label: '関数 on-order', kind: 'accent' },
  ],
  msgs: [
    { from: 'you', to: 't', label: 'publish（メッセージ）', style: 'accent' },
    { from: 't', to: 's', label: 'コピーを渡す' },
    { from: 's', to: 'f', label: 'CloudEvent にして POST', style: 'accent' },
    { self: 'f', label: 'console.log … ログに残る' },
    { from: 'f', to: 's', label: '204（受け取った）', style: 'dashed' },
  ],
}
```

イベント関数が受け取るのは、**CloudEvent**（クラウドイベント）という決まった形のデータです。CloudEvent は、どのサービスでも共通の「できごとの記録」の形式です。Pub/Sub から届く CloudEvent の中身は、次のようになっています。

```fig tree Pub/Sub から届く CloudEvent。メッセージの本文は ce.data.message.data に base64 で入っている
{
  root: { label: 'ce（CloudEvent）', kind: 'dir', children: [
    { label: 'type', note: 'google.cloud.pubsub.topic.v1.messagePublished' },
    { label: 'source', note: '//pubsub.googleapis.com/projects/…/topics/orders' },
    { label: 'id', note: 'メッセージ ID と同じ' },
    { label: 'data', kind: 'dir', children: [
      { label: 'message', kind: 'dir', children: [
        { label: 'data', hl: true, note: '本文。base64 で符号化されている' },
        { label: 'attributes', note: '属性（キーと値）。あれば' },
        { label: 'messageId', note: 'メッセージ ID' },
      ] },
      { label: 'subscription', note: 'eventarc-… のサブスクリプション' },
    ] },
  ] },
}
```

大事なのは、本文が `ce.data.message.data` に **base64**（バイト列を英数字と記号だけの文字列にする符号化）で入っていることです。そのままでは読めないので、`Buffer.from(…, 'base64').toString()` で元の文字列に戻します。

イベント関数用のディレクトリを作ります。`onOrder` は Pub/Sub 用、`onUpload` は次の節の Cloud Storage 用です。

```sh run title="イベント関数を書く"
mkdir ~/events && cd ~/events
cat > index.js <<'EOF'
const functions = require('@google-cloud/functions-framework');

functions.cloudEvent('onOrder', (ce) => {
  console.log(`type: ${ce.type}`);
  const msg = ce.data.message;
  console.log(`data（base64）: ${msg.data}`);
  const order = JSON.parse(Buffer.from(msg.data, 'base64').toString());
  console.log(`注文 ${order.id}：${order.total} 円`);
});

functions.cloudEvent('onUpload', (ce) => {
  const file = ce.data;
  console.log(`type: ${ce.type}`);
  console.log(`受け取ったファイル：${file.name}（${file.size} バイト、${file.contentType}）`);
});
EOF
echo '{ "name": "events", "main": "index.js", "dependencies": { "@google-cloud/functions-framework": "^3.0.0" } }' > package.json
```

HTTP 関数との違いは、`functions.cloudEvent` で登録することと、引数が `(ce)` の 1 つだけで、応答を書かないことです。関数が例外を投げずに終われば、「受け取った」ことになります。

`--trigger-topic=orders` でデプロイします。トピック `orders` がまだなければ、作られます。

```sh run title="Pub/Sub のトリガーでデプロイする"
gcloud functions deploy on-order --runtime=nodejs22 --source=. --entry-point=onOrder --trigger-topic=orders --format="yaml(eventTrigger.eventType,eventTrigger.pubsubTopic)"
```

`eventTrigger` が、この関数を呼ぶきっかけです。`eventType` の `google.cloud.pubsub.topic.v1.messagePublished` は「トピックにメッセージが publish された」という種類です。サブスクリプション（トピックの購読）の一覧を見てから、メッセージを publish して、関数のログを見ます。

```sh run title="サブスクリプションを見て、注文を publish する"
gcloud pubsub subscriptions list --format="table(name.basename(),topic.basename())"
gcloud pubsub topics publish orders --message='{"id":"A-1001","total":1200}'
gcloud functions logs read on-order --limit=3
```

トピック `orders` に、`eventarc-asia-northeast1-on-order-…` というサブスクリプションができています。**Eventarc**（イベントアーク）は、イベントを集めて Cloud Run のサービスに届ける仕組みです。関数のデプロイのときに、Eventarc が「トピック `orders` に届いたメッセージを、関数のサービスへ push（相手に送り込む）する」サブスクリプションを作りました。

ログには、下から順に、`type`、`data（base64）`、`注文 A-1001：1200 円` が並びました。`eyJpZCI6…` が base64 の本文で、関数がそれを戻して JSON として読みました。3 行の `EXECUTION_ID` が同じなので、1 回の実行で書いたものだと分かります。

## イベント関数：Cloud Storage にファイルを置くと動く {#storage-trigger}

もう 1 つのイベントは、Cloud Storage です。バケットにオブジェクト（ファイル）ができたときに、関数を呼べます。領収書の画像が置かれたら処理する、取り込み用のファイルが届いたら読み込む、といった使い方をします。

トリガーにするバケットを作ってから（バケットの名前は世界で 1 つです）、`--trigger-bucket` にバケットの名前（`gs://` は付けない）を渡してデプロイします。

```sh run title="バケットを作り、Cloud Storage のトリガーでデプロイする"
gcloud storage buckets create gs://tsubame-shop-receipts-ch11 --location=asia-northeast1
gcloud functions deploy on-upload --runtime=nodejs22 --source=. --entry-point=onUpload --trigger-bucket=tsubame-shop-receipts-ch11 --format="yaml(eventTrigger.eventType,eventTrigger.eventFilters)"
```

`eventType` は `google.cloud.storage.object.v1.finalized` です。**finalized**（確定した）は、「オブジェクトの書き込みが終わって、読めるようになった」という意味です。`eventFilters` が、どのバケットのイベントかを絞っています。ファイルを置いてみます。

```sh run title="ファイルを置くと、関数が動く"
echo "えんぴつ 3 本 360 円" > receipt.txt
gcloud storage cp receipt.txt gs://tsubame-shop-receipts-ch11/2026/11/receipt.txt
gcloud functions logs read on-upload --limit=2 --format="value(log)"
```

`cp` しただけで、関数が動きました。CloudEvent の `data` は、オブジェクトの情報そのものです。`name` はバケットの中の名前（`2026/11/receipt.txt`）、`size` はバイト数です。ファイルの中身は入っていないので、中身が要るときは、関数の中から Cloud Storage を読みます。

ないバケットを指定すると、`Bucket … not found`（バケットが見つからない）でデプロイが止まります。

```sh run title="ないバケットをトリガーにする" error
gcloud functions deploy on-upload2 --runtime=nodejs22 --source=. --entry-point=onUpload --trigger-bucket=tsubame-shop-no-such-bucket
```

名前の書き間違いか、まだ作っていないかのどちらかです。本物では、バケットと関数のリージョンの組み合わせにも決まりがあります（公式ドキュメントを参照）。

:::warn 関数が書いたファイルで、また関数が動く
トリガーのバケットに、関数の中からファイルを書くと、そのファイルでまた関数が動きます。処理の結果は、別のバケットに書くようにします。そうしないと、関数が自分を呼び続けて、呼び出しの回数と料金が増え続けます。
:::

最後に片付けます。関数を消すと、Cloud Run のサービスと、Eventarc のサブスクリプションも一緒に消えます。

```sh run title="関数を消す"
gcloud functions delete on-order --quiet
gcloud functions delete on-upload --quiet
gcloud functions list --format="value(name.basename())"
gcloud pubsub subscriptions list --format="value(name)"
```

一覧に残るのは HTTP 関数の 3 つです。`eventarc-…` のサブスクリプションもなくなりました。トピック `orders` とバケットは、関数とは別のリソースなので残ります。本物の Cloud Run functions には毎月の無料枠（200 万回の呼び出し、400,000 GB 秒と 200,000 GHz 秒、外向き転送 5 GB）があり、それを超えた分と、Cloud Build や Artifact Registry の分が料金になります。

:::key まとめ
- Cloud Run functions は、関数を 1 つ書けば動く。コンテナは `gcloud functions deploy` が Cloud Build で作り、Artifact Registry に置く
- HTTP 関数は `functions.http('名前', (req, res) => …)`。`req.query` と `req.body` を読み、`res.send` / `json` / `status` で返す
- `--trigger-http` で HTTP、`--allow-unauthenticated` でだれでも呼べる。付けなければ ID トークンが要る。`gcloud functions call` は自分のアカウントで呼ぶ
- 関数の正体は Cloud Run のサービス。`run services list` に出て、デプロイのたびにリビジョンが増える
- イベント関数は `functions.cloudEvent('名前', (ce) => …)`。`--trigger-topic` は Eventarc のサブスクリプション経由、`--trigger-bucket` はオブジェクトの finalized で動く。Pub/Sub の本文は `ce.data.message.data` に base64 で入っている
- `console.log` は `gcloud functions logs read` で読める。エントリポイントの書き間違いはデプロイの失敗（`is not defined in the provided module`）、関数の中の例外は 500 とログの `E` 行になる
:::

## 確認問題 {#quiz}

この章のコマンドを、自分で組み立てて確かめます。どの問題も、Cloud Functions API は有効で、関数の既定のリージョンは `asia-northeast1` になっています。

:::quiz HTTP 関数をデプロイする
`~/greet` に、HTTP 関数の `index.js` と `package.json` が用意してあります。`index.js` は `functions.http('greetUser', …)` で関数を登録しています。

これを（`index.js` の中の名前と、関数の名前が違うことに注意）、関数の名前 `greet`、ランタイム `nodejs22`、HTTP のトリガーで、**だれでも（トークンなしで）呼べるように**デプロイしてください。採点では、`https://asia-northeast1-tsubame-shop.cloudfunctions.net/greet?name=…` をトークンなしの curl で呼んだ結果と、関数のエントリポイントを調べます。

```sh prep
gcloud services enable cloudfunctions.googleapis.com
gcloud config set functions/region asia-northeast1
mkdir ~/greet
cat > ~/greet/index.js <<'EOF'
const functions = require('@google-cloud/functions-framework');
functions.http('greetUser', (req, res) => {
  res.send(`こんにちは、${req.query.name || 'ゲスト'} さん\n`);
});
EOF
echo '{ "main": "index.js", "dependencies": { "@google-cloud/functions-framework": "^3.0.0" } }' > ~/greet/package.json
```

```sh answer
gcloud functions deploy greet --runtime=nodejs22 --source=$HOME/greet --entry-point=greetUser --trigger-http --allow-unauthenticated
```

```sh check
curl -s "https://asia-northeast1-tsubame-shop.cloudfunctions.net/greet?name=採点"
gcloud functions describe greet --format="value(buildConfig.entryPoint)"
```
:::

:::quiz base64 を戻してログに書く
`~/ping` に、Pub/Sub のメッセージで動くイベント関数を書いてデプロイし、メッセージを 1 つ publish してください。

- 関数の名前は `on-ping`、エントリポイントは `onPing`、ランタイムは `nodejs22`、トリガーはトピック `pings`
- 関数は、メッセージの本文を元の文字列に戻して、`受け取り: 本文` の形で `console.log` に 1 行書く
- 最後に、トピック `pings` に本文 `hello-11` のメッセージを publish する

採点では、`gcloud functions logs read on-ping --format="value(log)"` のうち `受け取り` を含む行を比べます。`~/ping/package.json` は用意してあります。

```sh prep
gcloud services enable cloudfunctions.googleapis.com
gcloud config set functions/region asia-northeast1
mkdir ~/ping
echo '{ "main": "index.js", "dependencies": { "@google-cloud/functions-framework": "^3.0.0" } }' > ~/ping/package.json
```

```sh answer
cd ~/ping
cat > index.js <<'EOF'
const functions = require('@google-cloud/functions-framework');
functions.cloudEvent('onPing', (ce) => {
  const text = Buffer.from(ce.data.message.data, 'base64').toString();
  console.log(`受け取り: ${text}`);
});
EOF
gcloud functions deploy on-ping --runtime=nodejs22 --source=. --entry-point=onPing --trigger-topic=pings
gcloud pubsub topics publish pings --message=hello-11
```

```sh check
gcloud functions logs read on-ping --format="value(log)" | grep 受け取り
```

:::hint
本文は `ce.data.message.data` に base64 で入っています。`Buffer.from(…, 'base64').toString()` で戻します。publish は、関数をデプロイした後に行います。
:::
