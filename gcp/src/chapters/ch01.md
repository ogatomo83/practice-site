## クラウドとは、何を借りることか {#cloud}

自分の会社の建物に計算機を置いて動かすことを、**オンプレミス**（on-premises、「自分の敷地で」）と呼びます。機械を買い、電源と空調を用意し、壊れたら部品を替えます。使い始めるまでに何週間もかかり、使わなくなっても機械は残ります。

**クラウド**は、その計算機を、インターネット越しに必要な分だけ借りる使い方です。借りるときも返すときもコマンド 1 つで、料金は使った分だけ（**従量課金**）です。どこまでを借りて、どこからを自分で受け持つかで、呼び名が分かれます。

- **IaaS**（Infrastructure as a Service）：仮想の機械（VM）とディスクとネットワークを借ります。OS から上は自分で面倒を見ます。Google Cloud では Compute Engine（第 8 章）です
- **PaaS**（Platform as a Service）：OS やデータベースの運用まで任せ、アプリとデータだけを持ち込みます。Cloud SQL（第 14 章）は、PostgreSQL の運用を任せる PaaS です
- **サーバーレス**：機械の台数すら意識しません。リクエストやクエリが来たときだけ動き、動いた分だけ払います。Cloud Run（第 10 章）や BigQuery（第 15 章）です

図の PaaS とサーバーレスは、受け持つ範囲は同じで、違いは台数の考え方です。サーバーレスは、使われていないときは 0 台まで縮みます。

どの形でも、最後の 2 列（アプリとデータ）は自分の受け持ちです。だれにデータを見せるか（IAM、第 6 章）を決めるのも、利用者の仕事です。クラウドの会社が守るのは基盤で、使い方を守るのは利用者です。この分担を**責任共有モデル**と呼びます。

## Google Cloud は、どう育ってきたか {#history}

Google Cloud は、Google が自社の検索や Gmail のために作った仕組みを、外の人にも貸し出すところから始まりました。

最初のサービスは、2008 年の **App Engine** です。コードを置くだけで、Google のデータセンターで動きます。図の分類では PaaS にあたります。つまり Google Cloud は、VM を貸す IaaS ではなく、「機械を意識させない」側から始まりました。

VM を貸す **Compute Engine** の発表は 2012 年です。その間の 2010 年に、のちの Cloud Storage と BigQuery が発表されています。BigQuery の元は、社内で使われていた Dremel という分析の仕組みです。

いまの主力の 1 つ **Cloud Run**（2019 年）は、App Engine の「置くだけで動く」を、どの言語でも動くコンテナで実現したものです。2024 年には、関数を置くだけで動く Cloud Functions も、Cloud Run の一部（**Cloud Run functions**）になりました。15 年以上かけて、最初の考え方に戻ってきたとも言えます。

:::hist GCP と Google Cloud
「GCP」は Google Cloud Platform の略です。2016 年に、クラウドの事業全体が「Google Cloud」という名前にまとめられました。いまの公式の文書では、ほとんどの場所で「Google Cloud」と書かれます。それでも、技術者のあいだでは今も「GCP」がよく使われます。この本の題名もそれに合わせています。
:::

### 本物で試すなら：無料トライアルと無料枠 {#free}

本物で試したくなったら、仕組みが 2 つあります。**無料トライアル**は、新しく登録すると $300 のクレジットが付き、登録から 90 日使えます。**無料枠**（Free Tier）は、毎月決まった量まで無料になる仕組みで、トライアルが終わっても続きます。使わなかった分は翌月に繰り越されません。主なものは次のとおりです（2026 年 11 月の公式ドキュメントによる）。

| サービス | 毎月の無料枠（主なもの） |
| --- | --- |
| Compute Engine | e2-micro の VM 1 台（us-west1、us-central1、us-east1 のどれか）、標準永続ディスク 30 GB-月 |
| Cloud Storage | US のリージョンのストレージ 5 GB-月、クラス A の操作 5,000 回、クラス B の操作 50,000 回 |
| BigQuery | クエリ 1 TiB、ストレージ 10 GiB |
| Cloud Run | 200 万リクエスト、メモリ 360,000 GB 秒、vCPU 180,000 秒 |
| Cloud Run functions | 200 万回の呼び出し |
| Pub/Sub | メッセージ 10 GiB |
| Firestore | ストレージ 1 GiB、1 日あたり読み取り 50,000 回・書き込み 20,000 回・削除 20,000 回 |
| Cloud Logging | プロジェクトあたり 50 GiB のログ |

:::warn 無料枠には条件がある
無料枠は、決められたリージョンや種類で使ったときだけ効きます。たとえば Compute Engine の無料枠は、e2-micro を US の 3 つのリージョンのどれかで動かしたときだけです。東京リージョンで動かした VM は対象外です。Cloud SQL のように、無料枠がないサービスもあります。料金の仕組みと予算のアラートは第 4 章で扱います。
:::

## 操作の 3 つの道：コンソール、gcloud、API {#three-ways}

Google Cloud を操作する方法は、大きく 3 つあります。

- **Google Cloud コンソール**（console.cloud.google.com）：ブラウザで開く管理画面です。全体を見渡したり、初めての設定を試したりするのに向いています
- **gcloud**（Google Cloud CLI）：コマンドで操作します。同じ操作を何度でも、同じ形で繰り返せます。スクリプトに書いて自動化もできます
- **API を直接呼ぶ**：プログラムから HTTP で呼びます。ふつうは各言語の**クライアントライブラリ**（Python、Java、Go、Node.js など向けの部品）を使い、ライブラリが HTTP を組み立てます

この 3 つは、別々の入口ではありません。**どれも最後は同じ API を呼んでいます**。コンソールのボタンも、gcloud のコマンドも、裏では `https://○○.googleapis.com/…` に HTTP の要求を送っています。だから、どの道で作ったリソースも、ほかの道から見えます。


この本では、主に gcloud を使います。コンソールは画面がよく変わり、文章で手順を説明しにくいからです。gcloud が入っている場所としていちばん手軽なのが、序章で触れた **Cloud Shell** です。コンソールの右上のボタンで開く、ブラウザの中の端末です。gcloud、bq、curl などが最初から入っていて、ログインも済んでいます。手元のパソコンに Google Cloud CLI を入れても、同じコマンドが使えます。

```sh run title="gcloud の版と、いまの設定"
gcloud version
gcloud config list
```

`gcloud version` の 1 行目が Google Cloud CLI の版です（`Google Cloud SDK` は、Google Cloud CLI の以前の名前です）。`bq` や `gsutil` も、同じ Google Cloud CLI の一部として入っています。`gcloud config list` は、序章で見たとおり、いまのアカウント（`account`）とプロジェクト（`project`）です。

## gcloud の文法：グループ、コマンド、フラグ {#grammar}

gcloud のコマンドは、どれも同じ形をしています。大きな分類から小さな分類へ、**グループ**をたどり、最後に**コマンド**（動詞）を置きます。そのあとに、対象の名前（**位置引数**）と、細かい指定（**フラグ**）が続きます。

```fig layout gcloud のコマンドの形。グループは何段あってもよく、最後の 1 語が動詞になる

  rows: [
    { label: '例', cells: [
      { t: 'gcloud', w: 3, kind: 'plain' }, { t: 'compute', w: 4, kind: 'stack' }, { t: 'instances', w: 5, kind: 'stack' }, { t: 'create', w: 3, kind: 'accent' }, { t: 'web-1', w: 3, kind: 'heap' }, { t: '--zone=asia-northeast1-a', w: 9, kind: 'static' },

    { label: '役割', cells: [
      { t: '', w: 3, kind: 'empty' }, { t: 'グループ', w: 4, kind: 'stack' }, { t: 'グループ', w: 5, kind: 'stack' }, { t: 'コマンド', w: 3, kind: 'accent' }, { t: '位置引数', w: 3, kind: 'heap' }, { t: 'フラグ', w: 9, kind: 'static' },
    ] },
    { label: '意味', cells: [
      { t: '', w: 3, kind: 'empty' }, { t: 'サービス', w: 4, kind: 'empty' }, { t: 'リソースの種類', w: 5, kind: 'empty' }, { t: '何をするか', w: 3, kind: 'empty' }, { t: 'どれを', w: 3, kind: 'empty' }, { t: 'どのように', w: 9, kind: 'empty' },
    ] },
  ],

```

- グループは、ふつう「サービス → リソースの種類」の 2 段です。`compute instances`、`storage buckets`、`pubsub topics` などです。`projects` のように 1 段のものもあります
- コマンドは、どのリソースでもほぼ同じ動詞がそろっています。`list`（一覧）、`describe`（1 つの詳しい情報）、`create`、`update`、`delete` です
- フラグは `--名前=値` の形です。`=` の代わりに空白で区切っても同じです（`--zone asia-northeast1-a`）

グループの名前だけを打つと、その下に何があるかを教えてくれます。

```sh run error title="グループだけを打つ"
gcloud compute
```

`Command name argument expected.`（コマンドの名前が要る）と言われ、`gcloud compute` の下にあるものが並びます。`instances`、`disks`、`networks` などがリソースの種類です。名前を忘れたときは、こうして 1 段ずつたどれます。

:::note このサイトの GCP では
本物の gcloud は 1 つのグループの下にもっと多くのものを持っています。ここに出るのは、この本で使うものだけです。`--help` を付けると、本物ではそのコマンドのマニュアルが開きますが、このサイトでは短い説明だけを出します。
:::

gcloud は、文法の間違いをその場で教えてくれます。エラーの文は、いつも `ERROR: (gcloud.…)` で始まります。かっこの中は「どのコマンドで止まったか」を、`.` でつないだものです。

```sh run error title="グループの名前を書き間違える"
gcloud projets list
```

`(gcloud)` の段で、`projets` という選択肢はない（`Invalid choice`）と止まりました。`Maybe you meant:` の下に、近い名前の候補が出ています。

```sh run error title="位置引数を忘れる"
gcloud projects describe
```

今度はかっこの中が `gcloud.projects.describe` です。コマンドまでは合っていて、`PROJECT_ID_OR_NUMBER` という位置引数が足りない（`Must be specified`）と言われています。`Usage:` の行に、正しい形が書いてあります。

### どのコマンドにも使えるフラグ

フラグの多くはコマンドごとに決まっています。ただし、いくつかは**どのコマンドにも付けられる共通のフラグ**です。よく使うものを挙げます。

| フラグ | 意味 |
| --- | --- |
| `--project=ID` | このコマンドだけ、対象のプロジェクトを変える |
| `--account=ACCOUNT` | このコマンドだけ、別のアカウントとして実行する |
| `--format=…` | 出力の形を選ぶ（次の節） |
| `--filter=…`、`--sort-by=…`、`--limit=N` | 一覧を絞る、並べる、件数を切る（その次の節） |
| `--quiet`（`-q`） | 「続けますか」の確認を出さずに進める。スクリプトで使う |
| `--log-http` | 送った HTTP の要求を表示する（この章の最後の節） |
| `--help` | そのコマンドの説明を出す |

`--project` と `--account` は、`gcloud config` の設定より優先されます。設定を書き換えずに、1 回だけ別の対象を指せます。

```sh run error title="--project で、このコマンドだけ対象を変える"
gcloud services list --enabled --project=tsubame-public
```

エラーになりましたが、文をよく読むと `projects/tsubame-public` と書いてあります。設定は `tsubame-shop` のままですが、このコマンドだけは `tsubame-public` を見に行きました。`Permission 'serviceusage.services.list' denied` は、あなたが `tsubame-public` の API の一覧を見る権限を持っていない、という意味です。権限の読み方は第 6 章で扱います。

```sh run error title="ログインしていないアカウントを指す"
gcloud projects list --account=alice@tsubame.example
```

`--account` で青木さんを指しましたが、この Cloud Shell で青木さんはログインしていません。`does not have any valid credentials`（有効な資格情報がない）と言われ、`gcloud auth login` を打つよう案内されています。アカウントとログインの話は第 5 章で扱います。

## 出力の形を選ぶ：--format {#format}

gcloud の出力は、コマンドごとに既定の形が決まっています。`list` はたいてい表（`table`）、`describe` はたいてい YAML です。

```sh run title="既定の形：list は表、describe は YAML"
gcloud projects list
gcloud projects describe tsubame-shop
```

表は人が読むには便利です。でも、表から番号だけを取り出すのは面倒です。そこで `--format` で形を選びます。形は主に 4 つです。

| 形 | 出力 | 向いている使い道 |
| --- | --- | --- |
| `value(…)` | 値だけ。列はタブで区切り、見出しはない | シェルの変数に入れる、ほかのコマンドに渡す |
| `table(…)` | 見出しの付いた表。列を選べる | 人が読む |
| `json` | JSON | ほかのプログラムに渡す、全部の項目を見る |
| `yaml` | YAML | 全部の項目を見る（describe の既定） |

### value：値だけを取り出す

```sh run title="value で ID だけ、番号と名前だけ"
gcloud projects list --format="value(projectId)"
gcloud projects describe tsubame-shop --format="value(projectNumber, name)"
gcloud projects describe tsubame-shop --format="value(parent.id, labels.env)"
```

1 つ目は、見出しも罫線もない、ID だけの行が 2 つです。2 つ目は、番号と名前が、タブで区切られて 1 行に出ています。かっこの中の名前は、YAML で見た項目の名前そのままです。3 つ目のように、YAML で字下げされていた入れ子の項目は `.` でたどります。`405918273641` は組織の ID、`prod` は `env` というラベル（リソースに付ける札、第 2 章）の値です。

この形は、シェルの変数に入れるために使います。`$( … )` は「中のコマンドの出力に置き換える」という意味です。

```sh run title="値を変数に入れて使う"
NUM=$(gcloud projects describe tsubame-shop --format="value(projectNumber)")
echo "tsubame-shop の番号は $NUM"
for p in $(gcloud projects list --format="value(projectId)"); do echo "$p: $(gcloud projects describe $p --format="value(projectNumber)")"; done
```

`for` の行は、プロジェクトの ID を 1 つずつ取り出して、それぞれの番号を出しています。表のままでは、こうはいきません。スクリプトで gcloud を使うときは、ほとんどいつも `value` を使います。

### json と yaml：全部を見る

```sh run title="json で全部の項目を見る。yaml は項目を選んで"
gcloud projects list --format=json
gcloud projects list --format="yaml(projectId, projectNumber)"
```

一覧の `json` は、`[ … ]` の配列になります。表には出ていなかった `createTime`（作った時刻）や `lifecycleState`（状態）も見えます。gcloud が API から受け取ったものは、ほぼこのままの形です。どんな項目があるか分からないときは、まず `json` か `yaml` で全部を見て、欲しい名前を探します。

2 行目のように、`yaml` にもかっこで項目を選べます。2 件目の前の `---` は、YAML で「ここから次の文書」という区切りです。番号に `'365600345236'` のような引用符が付いているのは、値が数ではなく文字列だからです。

### table：列を選び、見出しと値を整える

```sh run title="表の列を選ぶ"
gcloud projects list --format="table(projectId, labels.env:label=ENV, createTime.date('%Y-%m-%d'):label=CREATED)"
```

かっこの中には、列の名前のあとに飾りを付けられます。

- `:label=ENV`：列の見出しを `ENV` にする。付けないと、項目の名前を大文字にしたもの（`PROJECT_ID`）になる
- `.date('%Y-%m-%d')`：時刻を「年-月-日」の形に変える。このような変換を**変換関数**（transform）と呼ぶ。ほかに、パスの最後だけを取る `.basename()` などがある。`tsubame-public` の `ENV` が空なのは、`env` のラベルがないから

```sh run error title="形の名前を書き間違える"
gcloud projects list --format=jsn
```

`Format must be one of …` のあとに、使える形の名前が全部並びます。`csv`（カンマ区切り）や `none`（何も出さない）などもあります。`received [jsn]` が、受け取った間違いの値です。

## 欲しい行だけにする：--filter、--sort-by、--limit、--flatten {#filter}

`--format` が「どの列を、どの形で」を決めるのに対して、ここからのフラグは「どの行を、どの順で、何行」を決めます。gcloud は、API から受け取った一覧に、次の順で手を加えてから表示します。

1. `--flatten`：入れ子の一覧を、行に開く
2. `--filter`：条件に合う行だけを残す
3. `--sort-by`：並べ替える
4. `--limit`：先頭の N 行だけを残す
5. `--format`：形を整えて表示する

### --filter：条件で行を絞る

条件の左側には、`--format` と同じ項目の名前を書きます。書き方は、主に次のとおりです。

| 書き方 | 意味 |
| --- | --- |
| `key=値` / `key!=値` | 等しい / 等しくない |
| `key:値` | 値を含む（大文字と小文字を区別しない） |
| `key~正規表現` | 正規表現に合う |
| `key<値` / `key>値` | より小さい / より大きい（時刻にも使える） |
| `key:*` | その項目がある |
| `NOT`、`-`、`AND`、`OR`、`( )` | 否定、組み合わせ |

```sh run title="いろいろな条件"
gcloud projects list --filter="labels.env=prod" --format="value(projectId)"
gcloud services list --enabled --filter="config.name~^bigquery" --format="value(config.name)"
gcloud projects list --filter="createTime>2025-01-01" --format="value(projectId)"
gcloud projects list --filter="-labels.env:*" --format="value(projectId)"
```

1 つ目は、ラベル `env` が `prod` のプロジェクトで、`tsubame-shop` だけが合います。2 つ目は、名前が `bigquery` で始まる（正規表現の `^` は「先頭」）API が 2 つです。3 つ目は、2025 年より後に作ったプロジェクトです。4 つ目は `-`（否定）で、「`env` のラベルを持たない」プロジェクトです。

### --sort-by と --limit：並べて、切る

```sh run title="名前の逆順に並べて、3 件だけ"
gcloud services list --enabled --sort-by=~config.name --limit=3
```

`--sort-by` に項目の名前を渡すと、その順に並びます。頭に `~` を付けると逆順です。`--limit=3` で先頭の 3 件だけが残りました。並べてから切るので、「最後の 3 つ」ではなく「逆順にした先頭の 3 つ」です。

### --flatten：入れ子の一覧を行に開く

IAM のポリシー（だれにどのロールを与えたかの表、第 6 章）は、入れ子の一覧になっています。このページの準備で、`tsubame-shop` に 2 つのグループのロールを足しておきました。

```sh setup
gcloud projects add-iam-policy-binding tsubame-shop --member=group:dev-team@tsubame.example --role=roles/viewer
gcloud projects add-iam-policy-binding tsubame-shop --member=group:analysts@tsubame.example --role=roles/bigquery.dataViewer
```

```sh run title="IAM のポリシーをそのまま見る"
gcloud projects get-iam-policy tsubame-shop --format=json
```

`bindings` の配列の中に、`role`（ロール）と `members`（そのロールを持つ相手の配列）の組が 3 つ並んでいます。これを表にしようとすると、困ったことになります。

```sh run title="flatten なしで表にする"
gcloud projects get-iam-policy tsubame-shop --format="table(bindings.role)"
```

ポリシーは 1 つのものなので、行も 1 つです。3 つのロールが `,` でつながって、1 つのマスに詰め込まれました。これを「1 つの組が 1 行」にするのが `--flatten` です。

```sh run title="flatten で、組ごとの行に開く"
gcloud projects get-iam-policy tsubame-shop --flatten="bindings[].members" --format="table(bindings.role, bindings.members)"
```

`--flatten="bindings[].members"` は、「`bindings` の配列を 1 つずつ別の行に開き、さらにその中の `members` も 1 人ずつ別の行に開く」という意味です。開いたあとの行では、`bindings` は配列ではなく 1 つの組になります。だから `bindings.role` と `bindings.members` で、その行の値を取り出せます。開いてしまえば、`--filter` で行を選べます。「`roles/owner` を持っているのはだれか」は、次のように書きます。

```sh run title="flatten と filter を組み合わせる"
gcloud projects get-iam-policy tsubame-shop --flatten="bindings[].members" --filter="bindings.role=roles/owner" --format="value(bindings.members)"
```

この 3 つのフラグの組み合わせは、IAM を調べるときの決まった形です。第 6 章で何度も使います。

## gcloud は API を呼んでいるだけ {#api}

「gcloud もコンソールも、裏では同じ API を呼んでいる」ことを、自分の目で確かめます。

### --log-http：gcloud が送った要求を見る

共通のフラグ `--log-http` を付けると、gcloud が送った HTTP の要求が表示されます。

```sh run title="describe が送った要求"
gcloud projects describe tsubame-shop --format="value(name)" --log-http
```

`==== request start ====` から `==== request end ====` までが、送った要求 1 つ分です。読みどころは 3 か所です。

- `uri:`：送り先です。`https://cloudresourcemanager.googleapis.com/v1/projects/tsubame-shop` は、**Cloud Resource Manager API**（組織・フォルダ・プロジェクトを扱う API）の、`v1` 版の、`projects` の中の `tsubame-shop` を指しています
- `method: GET`：HTTP の動詞です。読むだけなので `GET` です
- `b'authorization': --- Token Redacted ---`：本人であることを示す**アクセストークン**です。画面に出ると危ないので、gcloud が伏せています

最後の 1 行が、いつもの出力（名前）です。gcloud は、この要求の答え（JSON）を受け取り、`--format` で整えて表示しただけです。

書き換えるコマンドでは、要求の中身（`body`）も見えます。

```sh run title="API を有効にするときの要求"
gcloud services enable pubsub.googleapis.com --log-http
```

要求が 2 つ出ました。1 つ目は、プロジェクトの情報を読む `GET` です。2 つ目は、**Service Usage API**（API の有効・無効を扱う API）への `POST` です。`uri` の末尾が `services:batchEnable`（まとめて有効にする）で、`body` に `{"serviceIds":["pubsub.googleapis.com"]}` という JSON が入っています。`gcloud services enable` というコマンドは、この JSON を組み立てて送る道具だった、ということです。

:::note このサイトの GCP では
本物の `--log-http` は、要求に加えて、返ってきた答え（`---- response start ----` から始まる部分）も表示します。このサイトでは要求だけを表示します。答えの中身は、次の curl で見てください。
:::

### curl で、同じ API を直接呼ぶ

要求の形が分かれば、gcloud を使わなくても同じことができます。**curl**（カール）は、HTTP の要求を送るコマンドです。まずは、何も工夫せずに送ってみます。

```sh run title="トークンなしで送る"
curl -s https://cloudresourcemanager.googleapis.com/v1/projects/tsubame-shop
```

`"code": 401`、`"status": "UNAUTHENTICATED"` と断られました。`missing required authentication credential` は「本人であることを示すものがない」という意味です。API は、だれが呼んだのか分からない要求には答えません。

本人であることは、アクセストークンで示します。`gcloud auth print-access-token` が、いまのアカウントのアクセストークンを出します。

```sh run title="アクセストークンを出す"
gcloud auth print-access-token
```

`ya29.` で始まる長い文字列が出ました。これは、あなた（`you@tsubame.example`）として API を呼べる「通行証」です。本物のアクセストークンは、ふつう 1 時間ほどで期限が切れます。

:::warn トークンは人に見せない
アクセストークンを持っている人は、期限が切れるまで、あなたと同じ権限で何でもできます。画面の写真やログに残さないでください。gcloud の `--log-http` が `Token Redacted` と伏せていたのは、そのためです。
:::

このトークンを、HTTP の `Authorization: Bearer トークン` という見出し（ヘッダ）に付けて送ります。トークンを手で写すのは間違いのもとなので、`$( … )` でその場に埋め込みます。

```sh run title="トークンを付けて、gcloud と同じ要求を送る"
curl -s -H "Authorization: Bearer $(gcloud auth print-access-token)" https://cloudresourcemanager.googleapis.com/v1/projects/tsubame-shop
```

今度は答えが返ってきました。中身を、`gcloud projects describe tsubame-shop --format=json` と見比べてください。項目の名前も値も同じです。並び順だけが違います。gcloud は表示の前に項目の名前を ABC 順に並べ替えますが、curl は API の答えをそのまま出すからです。

URL の `tsubame-shop` は番号でもかまいません。同じ API の新しい版 `v3` でも読んでみます。

```sh run title="v3 の API で、番号を指定して読む"
curl -s -H "Authorization: Bearer $(gcloud auth print-access-token)" https://cloudresourcemanager.googleapis.com/v3/projects/214441484921
```

番号 `214441484921` は `tsubame-public` です。`v3` では答えの形が少し違い、`name` が `projects/214441484921`、表示名が `displayName`、親が `organizations/405918273641` という 1 つの文字列になっています。API は版ごとに形が決まっていて、gcloud はコマンドごとに、どの版を呼ぶかを決めています。

### HTTP の状態コードで、成否を知る

API の成否は、HTTP の**状態コード**（200 なら成功、400 番台なら呼んだ側の問題）で返ります。curl の `-w "%{http_code}\n"` で、状態コードだけを出せます。`-o /dev/null` は、本文を捨てるという意味です。

```sh run title="状態コードだけを見る"
curl -s -o /dev/null -w "%{http_code}\n" -H "Authorization: Bearer $(gcloud auth print-access-token)" https://cloudresourcemanager.googleapis.com/v1/projects/tsubame-shop
curl -s -o /dev/null -w "%{http_code}\n" https://cloudresourcemanager.googleapis.com/v1/projects/tsubame-shop
curl -s -o /dev/null -w "%{http_code}\n" -H "Authorization: Bearer $(gcloud auth print-access-token)" https://cloudresourcemanager.googleapis.com/v1/projects/tsubame-nothing
```

1 行目の `200` は成功、2 行目の `401` はトークンがない、3 行目の `403` は「権限がない（または存在しない）」です。存在しないプロジェクトでも `404` ではなく `403` になるのは、他人のプロジェクトがあるかどうかを、権限のない人に教えないためです。gcloud の `PERMISSION_DENIED` のエラーも、この 403 を言い換えたものです。

:::key まとめ
- クラウドは、計算機を必要な分だけ借りる使い方。IaaS（Compute Engine）、PaaS（Cloud SQL）、サーバーレス（Cloud Run、BigQuery）で、任せる範囲が違う。アプリとデータは、いつも自分の受け持ち
- Google Cloud は 2008 年の App Engine から始まり、Compute Engine、BigQuery、Cloud Run と広がった。この本は、土台（入れ物と人）と主要サービスに絞る
- 操作の道は、コンソール、gcloud、API の 3 つ。どれも最後は同じ `○○.googleapis.com` の API を呼ぶ
- gcloud の形は「グループ … コマンド 位置引数 フラグ」。`--project`、`--account`、`--format`、`--quiet` などは、どのコマンドにも付く
- `--format` は value（スクリプト）、table（人が読む）、json / yaml（全部を見る）。入れ子は `.` でたどる
- 一覧には flatten → filter → sort-by → limit → format の順で手が加わる。IAM は `--flatten="bindings[].members"` で開いてから絞る
- `--log-http` で要求が見える。`gcloud auth print-access-token` のトークンを付ければ、curl で同じ API を直接呼べる
:::

## 確認問題 {#quiz}

この章で使った `--format`、`--filter`、`--sort-by`、`--limit`、`--flatten`、curl を、自分で組み立てます。どの問題も、準備のデータを変えてもう一度判定します。

:::quiz ラベルと組織の ID
`tsubame-shop` のラベル `env` の値と、親（組織）の ID を、この順にタブで区切って 1 行で表示してください。見出しは付けません。

```sh vary
gcloud projects update tsubame-shop --update-labels=env=staging
```

```sh answer
gcloud projects describe tsubame-shop --format="value(labels.env, parent.id)"
```

:::hint
`value(…)` のかっこの中に、項目の名前をカンマで区切って並べます。入れ子の項目は `.` でたどります。
:::
:::

:::quiz 逆順の先頭 3 つ
`tsubame-shop` で有効になっている API の名前（`config.name`）を、名前の逆順（z から a の向き）に並べ、先頭の 3 つだけを、1 行に 1 つずつ表示してください。名前のほかには何も出しません。

```sh vary
gcloud services enable sqladmin.googleapis.com
```

```sh answer
gcloud services list --enabled --sort-by=~config.name --limit=3 --format="value(config.name)"
```

:::

:::quiz 閲覧者はだれか
`tsubame-shop` の IAM のポリシーから、ロール `roles/viewer` を持っている相手（`group:…` や `user:…` の形のまま）を、1 行に 1 つずつ表示してください。ほかのロールの相手は出しません。

```sh vary
gcloud projects remove-iam-policy-binding tsubame-shop --member=group:dev-team@tsubame.example --role=roles/viewer
gcloud projects add-iam-policy-binding tsubame-shop --member=user:bob@tsubame.example --role=roles/viewer
```

```sh answer
gcloud projects get-iam-policy tsubame-shop --flatten="bindings[].members" --filter="bindings.role=roles/viewer" --format="value(bindings.members)"
```

:::hint
`--flatten="bindings[].members"` で組ごとの行に開き、`--filter` でロールを選び、`--format="value(…)"` で相手だけを出します。
:::
:::

:::quiz curl で表示名を読む
gcloud の `projects` のコマンドを使わずに、curl で Cloud Resource Manager API（`v1`）を直接呼んで `tsubame-shop` の情報を取り出し、その答え（JSON）のうち `"name"` を含む行だけを表示してください。トークンは `gcloud auth print-access-token` で取り出してかまいません。

```sh vary
gcloud projects update tsubame-shop --name="つばめ文具 本店"
```

```sh answer require="curl" forbid="projects describe,projects list"
curl -s -H "Authorization: Bearer $(gcloud auth print-access-token)" https://cloudresourcemanager.googleapis.com/v1/projects/tsubame-shop | grep '"name"'
```

:::hint
`curl -s -H "Authorization: Bearer $(gcloud auth print-access-token)" URL` の出力を、`| grep '"name"'` で絞ります。URL は `--log-http` で見た `uri:` から、`?alt=json` を除いたものです。
:::
:::
