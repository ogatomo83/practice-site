第 2 章

リソースの階層

Google Cloud のリソースは、組織 → フォルダ → プロジェクトという入れ物の木に入っています。組織とは何か、プロジェクトの ID・名前・番号の違い、フォルダとプロジェクトの作成、ラベル、移動、削除と猶予期間までを、自分で木を組み替えながら確かめます。

2.1Google Cloud の「入れ物」は 4 段の木

Google Cloud で作るものは、すべてリソース（資源）と呼ばれます。バケット、VM、データセットなどです。リソースは、ばらばらに置かれているわけではありません。必ずどこかの「入れ物」に入っていて、入れ物は木の形につながっています。

4 つの段には、それぞれ役目があります。

段何のための入れ物か数
組織（organization）会社そのもの。会社のドメイン（tsubame.example）と結び付く会社に 1 つ
フォルダ（folder）部署・チーム・環境で、プロジェクトをまとめる0 個でも、何段に重ねてもよい
プロジェクト（project）リソースを入れる実際の箱。API の有効化と請求先はここで決めるいくつでも
リソースバケット、VM、データセットなどプロジェクトごとにいくつでも

いちばん大事なのはプロジェクトです。リソースは必ずどれか 1 つのプロジェクトに入ります。「どの API を使えるか」（第 3 章）と「料金をどこに請求するか」（第 4 章）も、プロジェクトごとに決まります。

組織とフォルダは、プロジェクトを整理するための上の段です。上の段で決めた権限（IAM）は、下の段に引き継がれます（第 6 章）。木の形が、そのまま「だれが何をできるか」の形になるのです。

いまの木を見てみましょう。

いまあるプロジェクトと、その親⌘↵
gcloud projects list --format="table(projectId, parent.type, parent.id)"

TYPE と ID の列が、それぞれのプロジェクトの親です。いまは 2 つとも organization の 405918273641、つまり組織の真下にあります。フォルダはまだありません。

親をたどって根まで出すのが get-ancestors（祖先を出す）です。

tsubame-shop の祖先⌘↵
gcloud projects get-ancestors tsubame-shop

1 行目が自分（project）、2 行目がその親（organization）です。下から上へ、根に着くまで並びます。この章では、ここにフォルダをはさみ、行が増えていくのを見ていきます。ページの上の「クラウドを見る」を開いておくと、木の変化が画面の下でも見えます。

2.2組織：会社のドメインと結び付いた根

組織は木の根です。会社が Google Workspace か Cloud Identity（社員のアカウントを管理するサービス。第 5 章）を使っていると、そのドメインに 1 つだけ、組織が自動で作られます。

組織を調べる⌘↵
gcloud organizations listgcloud organizations describe 405918273641
  • DISPLAY_NAME の tsubame.example は、組織の名前です。会社のドメイン名がそのまま使われます
  • ID の 405918273641 は、組織の番号です。コマンドで組織を指すときは、この番号を使います（--organization=405918273641）
  • DIRECTORY_CUSTOMER_ID の C03k8x2pq は、Workspace / Cloud Identity の側の顧客 ID です。「この組織は、どのアカウント管理とつながっているか」を表します

describe の name: organizations/405918273641 は、API の中でのリソース名です。リソース名は「種類の複数形 / ID」の形をしています。フォルダは folders/…、プロジェクトは projects/… です。

組織がない場合

個人の Google アカウント（@gmail.com など）で Google Cloud を始めると、組織はありません。社外の協力者 taro@example.com は、そういうアカウントです。切り替えて同じことをしてみます。

個人のアカウントから見る⌘↵
gcloud auth login taro@example.comgcloud organizations listgcloud projects listgcloud auth login you@tsubame.example

Listed 0 items. が 2 回出ました。taro さんには、見える組織もプロジェクトもありません。つばめ文具の組織の外にいるからです。最後の行で、あなた（you@tsubame.example）に戻しました。

組織がないアカウントでプロジェクトを作ると、そのプロジェクトは親のないプロジェクト（コンソールでは「組織なし」と出ます）になります。

組織がある（会社のドメイン）組織がない（個人のアカウント）
木の根組織プロジェクトがそれぞれ根
フォルダ使える使えない（フォルダは組織の下にしか作れない）
組織全体の IAM・ポリシーかけられるかけられない。プロジェクトごとに設定する
社員が辞めたときプロジェクトは会社に残るプロジェクトは個人のアカウントのもの

会社で使うなら、組織を用意してからプロジェクトを作るのが基本です。

メモこのサイトの GCP では

本物の gcloud auth login はブラウザを開いてアカウントを選びます。このサイトでは、ログインするアカウントを引数で指定します。

2.3プロジェクトの 3 つの呼び名：ID・名前・番号

序章で、プロジェクトには 3 つの呼び名があると書きました。改めて並べて見ます。

ID・名前・番号⌘↵
gcloud projects describe tsubame-shopgcloud projects describe 365600345236 --format="value(projectId, name)"

1 つ目の出力の、次の 3 行が呼び名です。

  • projectId: tsubame-shop … プロジェクト ID
  • name: つばめ文具 オンライン店 … プロジェクト名
  • projectNumber: '365600345236' … プロジェクト番号

2 つ目のコマンドは、ID の代わりに番号で同じプロジェクトを引いています。tsubame-shop と つばめ文具 オンライン店 が出ました。どちらで指しても、同じ 1 つのプロジェクトです。

呼び名だれが決めるか後から変えられるか重なってよいか主に使う場所
ID作る人変えられない世界で 1 つgcloud の --project、URL、リソース名
名前作る人いつでも重なってよいコンソールなど、人が読む表示
番号Google が自動で変えられない世界で 1 つAPI の内部、サービスアカウントの名前、エラーの文

ふだんコマンドで打つのは ID です。名前は人が読むための飾りで、検索や区別には向きません。番号は、自分で打つことは少ないのですが、エラーの文に出てきます。

番号が出てくるエラーエラーになる⌘↵
gcloud compute instances list

Compute Engine API has not been used in project 365600345236 before or it is disabled. と出ました。「プロジェクト 365600345236 では、この API が使われたことがないか、無効になっている」という意味です。ここに出ているのは ID ではなく番号です。番号を見て「どのプロジェクトのことか」が分かるように、gcloud projects describe 番号 で引けることを覚えておきましょう。API の有効化は第 3 章で扱います。

ID の決まり：小文字で始まり、世界で 1 つ

ID は、作るときに一度決めたら変えられません。だから決まりを知っておく必要があります。わざと決まりを破ってみます。

ID の形が決まりに合わないエラーになる⌘↵
gcloud projects create Tsubame-Dev

エラーの文 Project IDs must start with a lowercase letter and can have lowercase ASCII letters, digits or hyphens. Project IDs must be between 6 and 30 characters. を読むと、決まりがそのまま書いてあります。

  • 英小文字で始まる（T は大文字なので不可）
  • 使える文字は、英小文字、数字、ハイフン（-）
  • 6 文字以上 30 文字以下

形が正しくても、作れないことがあります。

ID がもう使われているエラーになる⌘↵
gcloud projects create tsubamegcloud projects create tsubame-shop

どちらも The project ID you specified is already in use by another project. です。tsubame-shop は自分たちのプロジェクトなので当然です。tsubame のほうは、つばめ文具のどのプロジェクトでもありません。世界のどこかのだれかが、すでにその ID を使っているのです。

プロジェクト ID は、Google Cloud を使う全員の間で 1 つしか存在できません。短くて分かりやすい ID ほど、先に取られています。会社名や用途、環境を組み合わせた ID（tsubame-shop-dev など）にすると、ぶつかりにくくなります。

メモこのサイトの GCP では

「世界のだれかが使っている ID」は、このサイトでは tsubame、my-project、shop などいくつかを決め打ちで用意しています。本物では、本当にほかの人のプロジェクトとぶつかります。

2.4フォルダを作る

プロジェクトが増えてくると、まとめる入れ物が欲しくなります。それがフォルダです。組織の下に、店のチームのためのフォルダ shop を作ります。

組織の下にフォルダを作る⌘↵
gcloud resource-manager folders create --display-name=shop --organization=405918273641

フォルダのコマンドは gcloud resource-manager folders の下にあります。Resource Manager（リソース マネージャー）は、組織・フォルダ・プロジェクトの木を管理する API の名前です。

出力の name: 'folders/…' の数字が、フォルダの ID です。フォルダの ID は Google が付ける数字で、自分では決められません。自分で決めるのは --display-name（表示名）です。parent: 'organizations/405918273641' が親を表します。

同じ名前でもう 1 つ作ってみます。

同じ親の下に、同じ名前のフォルダエラーになる⌘↵
gcloud resource-manager folders create --display-name=shop --organization=405918273641

A folder with the same name already exists under the parent resource.（同じ親の下に、同じ名前のフォルダがすでにある）です。下の type: FOLDER_NAME_UNIQUENESS_VIOLATION が、破った決まりの名前です。

フォルダの表示名は、同じ親の下でだけ 1 つです。親が違えば、同じ名前のフォルダを作れます。プロジェクト ID が「世界で 1 つ」なのとは、範囲がまったく違います。

フォルダの ID を変数に入れる

フォルダを指すには、表示名ではなく数字の ID が要ります。毎回コピーするのは大変なので、シェルの変数に入れておきます。

表示名から ID を引く⌘↵
SHOP=$(gcloud resource-manager folders list --organization=405918273641 --filter="displayName=shop" --format="value(name.segment())")echo $SHOP

folders list で組織の真下のフォルダを並べ、--filter で表示名が shop のものに絞り、--format="value(name.segment())" で folders/… の最後の部分（数字）だけを取り出しています。$( … ) は、コマンドの出力をその場に埋め込むシェルの書き方です。echo で 12 桁の数字が出れば成功です。

フォルダの中に、さらにフォルダを作れます。本番用と開発用に分けます。

フォルダの中にフォルダ⌘↵
gcloud resource-manager folders create --display-name=prod --folder=$SHOPgcloud resource-manager folders create --display-name=dev --folder=$SHOP

親の指定が --organization から --folder に変わりました。2 つとも parent: 'folders/…' が $SHOP の番号になっています。

shop の中を見て、ID を変数に⌘↵
gcloud resource-manager folders list --folder=$SHOPPROD=$(gcloud resource-manager folders list --folder=$SHOP --filter="displayName=prod" --format="value(name.segment())")DEV=$(gcloud resource-manager folders list --folder=$SHOP --filter="displayName=dev" --format="value(name.segment())")

folders list が出すのは、指定した親の真下のフォルダだけです。PARENT_NAME が 2 つとも folders/…（shop）になっています。これで木は「組織 → shop → prod / dev」の形になりました。

2.5プロジェクトを作り、ラベルを付ける

開発用のプロジェクトを、フォルダ dev の中に作ります。

フォルダの中にプロジェクトを作る⌘↵
gcloud projects create tsubame-shop-dev --name="つばめ文具 開発" --folder=$DEV --labels=env=dev,team=shop
  • 最初の引数 tsubame-shop-dev が ID です
  • --name が名前です。省くと、ID と同じ文字列になります
  • --folder が親です。--organization=405918273641 と書けば組織の真下に作られます
  • --labels はラベル（後で説明します）です

指定の書き方を間違えると、作る前に止まります。

フラグの間違いエラーになる⌘↵
gcloud projects create tsubame-shop-test --name="開発"gcloud projects create tsubame-shop-test --folder=$DEV --organization=405918273641

1 つ目は Project name must be between 4 and 30 characters. で、名前が短すぎます（4 文字以上 30 文字以下）。2 つ目は At most one of --folder | --organization can be specified. で、親は 1 つしか選べません。どちらも [exit 2] で、API を呼ぶ前に gcloud が止めています。

できたプロジェクトを確かめます。

できたプロジェクト⌘↵
gcloud projects listgcloud projects describe tsubame-shop-dev

list に tsubame-shop-dev が増えました。PROJECT_NUMBER の番号は、Google が自動で付けたものです。describe の parent が type: folder と dev のフォルダの ID になっています。

祖先が 1 段増える⌘↵
gcloud projects get-ancestors tsubame-shop-dev

project → folder（dev）→ folder（shop）→ organization の 4 行です。冒頭の tsubame-shop は 2 行でした。フォルダを重ねた分だけ、根までの道が長くなります。

名前は重なってもよい

名前は、いつでも変えられます。わざと本番と同じ名前にしてみます。

名前を本番と同じにする⌘↵
gcloud projects update tsubame-shop-dev --name="つばめ文具 オンライン店"gcloud projects list --format="table(projectId, name)"

エラーにはならず、NAME が同じプロジェクトが 2 つ並びました。名前だけでは区別できないので、コマンドでは ID を使います。紛らわしいので元に戻し、ついでにラベルを足します。

名前を戻し、ラベルを足す⌘↵
gcloud projects update tsubame-shop-dev --name="つばめ文具 開発" --update-labels=owner=you

labels に owner: you が足されました。--update-labels は「このラベルを足す（あれば書き換える）」、--remove-labels=キー は「消す」です。

ラベルで探す

ラベルは、キー=値 の形でプロジェクトに付けるメモです。「どの環境か」「どのチームのものか」を書いておくと、探したり、料金を分けて集計したりできます。

ラベルで絞り込む⌘↵
gcloud projects list --filter="labels.env=dev" --format="value(projectId)"gcloud projects list --filter="labels.env=prod" --format="value(projectId)"

env=dev で tsubame-shop-dev、env=prod で tsubame-shop が出ました。tsubame-shop には、最初から env: prod のラベルが付いていたのです（前の節の describe の出力にあります）。

ラベルは、プロジェクトのほかにバケットや VM など多くのリソースにも付けられます。請求のデータにもラベルが残るので、「env=dev の費用はいくらか」を後で集計できます（第 4 章）。

2.6移動：プロジェクトの住所を変える

いまの tsubame-shop は、まだ組織の真下にいます。本番のフォルダ prod に入れましょう。プロジェクトの移動は、中のリソースを壊さずに「親」だけを付け替える操作です。

tsubame-shop を prod に移す⌘↵
gcloud projects move tsubame-shop --folder=$PRODgcloud projects get-ancestors tsubame-shop

Moved [tsubame-shop] to [folders/…] の後に、移した後のプロジェクトが出ます。parent が type: folder に変わりました。ID・名前・番号は変わりません。get-ancestors は、冒頭の 2 行から 4 行になりました。

移動で変わるのは、親から引き継ぐものです。とくに IAM は、親のフォルダや組織で付けた権限が下に引き継がれるので、移した先のフォルダの権限が新しく効き、元の場所の権限は効かなくなります（第 6 章）。本番のプロジェクトを動かすときは、だれの権限が増え、だれのが減るかを先に確かめます。

フォルダも、gcloud resource-manager folders move で移動できます。ただし、木が輪にならないように止められます。

自分の子の下には移せないエラーになる⌘↵
gcloud resource-manager folders move $SHOP --folder=$DEV

The folder move would create a cycle.（この移動は循環を作る）です。dev は shop の子なので、shop を dev の下に入れると「shop の中の dev の中の shop…」と終わらなくなります。木は必ず根から枝分かれするだけの形でなければなりません。

2.7削除：すぐには消えず、猶予がある

まず、フォルダ dev を消してみます。

中身があるフォルダは消せないエラーになる⌘↵
gcloud resource-manager folders delete $DEV

Folder … is not empty and cannot be deleted.（フォルダが空ではないので削除できない）です。type: FOLDER_TO_DELETE_NON_EMPTY_VIOLATION が、破った決まりの名前です。dev の中には tsubame-shop-dev があります。フォルダを消すには、中のプロジェクトとフォルダを、先に消すか外へ移す必要があります。中身ごと一度に消すことはできません。うっかり本番を消さないための決まりです。

では、中のプロジェクトを消します。

プロジェクトを削除する⌘↵
gcloud projects delete tsubame-shop-dev --quiet

--quiet は、「本当に消しますか」という確認を省くフラグです。出力の You can undo this operation for a limited period by running the command below.（しばらくの間は、下のコマンドで取り消せる）に注目してください。プロジェクトの削除は、すぐには実行されません。

削除したプロジェクトは、まず DELETE_REQUESTED（削除を頼まれた）という状態になります。中のリソースは止まり、課金も止まります。そのまま猶予期間（本物ではおよそ 30 日。正確には公式ドキュメントを参照）が過ぎると、中身ごと本当に消えます。

削除したプロジェクトの状態⌘↵
gcloud projects listgcloud projects describe tsubame-shop-dev --format="value(lifecycleState)"

list からは tsubame-shop-dev が消えました。list が出すのは ACTIVE（使える）のプロジェクトだけだからです。それでも describe では引けて、lifecycleState（一生の中の状態）が DELETE_REQUESTED になっています。まだ消えていないので、困ることが 2 つあります。

消したのに、まだ残っているものエラーになる⌘↵
gcloud projects create tsubame-shop-devgcloud resource-manager folders delete $DEV

1 つ目は、同じ ID でプロジェクトを作り直せないことです。already in use が出ます。ID は削除を頼んだ後も使われたままで、本物では、完全に消えた後も同じ ID は二度と使えません。ID を使い捨てにしないよう、名前を付けるときに気を付けます。

2 つ目は、フォルダ dev がまだ消せないことです。削除を待っているプロジェクトも、フォルダの中身として数えられます。

猶予の間なら、削除を取り消せます。

ターミナル
$ gcloud projects undelete tsubame-shop-dev

成功すると lifecycleState が ACTIVE に戻り、projects list にもまた出てきます。中のリソースも戻ってきます。

注意プロジェクトの削除は、いちばん強い片付け

プロジェクトを消すと、中のバケット、VM、データベース、ログが全部いっしょに消えます。猶予を過ぎたら戻せません。逆に言えば、「試しに作ったものを確実に全部片付けて、料金を止めたい」ときは、プロジェクトごと消すのがいちばん確実です。試すときは専用のプロジェクトを作る、という習慣はここから来ています。

空のフォルダなら消せることも確かめます。

空のフォルダは消せる⌘↵
gcloud resource-manager folders create --display-name=tmp --folder=$SHOPTMP=$(gcloud resource-manager folders list --folder=$SHOP --filter="displayName=tmp" --format="value(name.segment())")gcloud resource-manager folders delete $TMPgcloud resource-manager folders list --folder=$SHOP

Deleted [folders/…]. と出て、最後の一覧は dev と prod だけに戻りました。中身のないフォルダは、待たずに消せます。

2.8フォルダをどう分けるか

フォルダの分け方に正解はありません。ただ、フォルダは権限と規則を引き継ぐ単位なので、「同じ人が同じ権限で触るものを、同じフォルダに入れる」のが基本です。よくある分け方は 2 つです。

  • 部署・チームで分ける：上の図の 1 段目です。チームのグループに、そのフォルダの権限を 1 回付ければ、中のプロジェクト全部に効きます
  • 環境で分ける：上の図の 2 段目です。prod（本番）と dev（開発）を分けると、「本番は限られた人だけ、開発はチーム全員」と権限の強さを変えられます

フォルダは 2〜3 段で足りることがほとんどです。深いと、権限がどの段から来ているかを追うのが大変になります（重ねられる段の数にも上限があります。公式ドキュメントを参照）

プロジェクトの分け方は、もっと大事です。プロジェクトは API・請求・権限の境目なので、本番と開発は必ず別のプロジェクトにします。開発の実験が本番のデータを消す、開発のお試しの費用が本番の費用に混ざる、といった事故を、入れ物の段階で防げます。この本の最後の第 17 章で、つばめ文具の木を最後まで組み立てます。

要点まとめ
  • リソースは必ず 1 つのプロジェクトに入る。プロジェクトはフォルダか組織に入り、木の根は組織。上で付けた権限は下に引き継がれる
  • 組織は Workspace / Cloud Identity のドメインに 1 つ。個人のアカウントには組織がなく、フォルダも使えない
  • プロジェクトには ID（自分で決める・変えられない・世界で 1 つ）、名前（いつでも変えられる・重なってよい）、番号（Google が付ける）の 3 つの呼び名がある
  • フォルダの ID は数字で、表示名は同じ親の下でだけ 1 つ。folders list --filter --format="value(name.segment())" で ID を引く
  • projects move は親だけを付け替える。get-ancestors で根までの道が見える
  • プロジェクトの削除は DELETE_REQUESTED を経て、猶予の後に本当に消える。その間 ID は使えず、フォルダも空にならない。中身のあるフォルダは消せない

2.9確認問題

木を組み立てて、調べる問題です。フォルダは数字の ID で指すので、表示名から ID を引く書き方（$( … ) と --filter、--format="value(name.segment())"）を使ってください。

問 1

祖先の種類

正解済み

プロジェクト tsubame-shop の祖先を gcloud projects get-ancestors で調べ、種類（project、folder、organization）だけを、コマンドが出す順に 1 行に 1 つ表示してください。

gcloud projects get-ancestors tsubame-shop
⌘↵標準出力で判定（行の順番も見る）
ヒント

表の TYPE の列は、--format="value(type)" で取り出せます。

模範解答
gcloud projects get-ancestors tsubame-shop --format="value(type)"
問 2

フォルダの中にプロジェクトを作る

正解済み

組織の下に、フォルダ dev と prod が用意してあります。フォルダ dev の中に、次のプロジェクトを作ってください。

  • ID：tsubame-quiz-dev
  • 名前：つばめ 検証
  • ラベル：env=dev
DEV=$(gcloud resource-manager folders list --organization=405918273641 --filter="displayName=dev" --format="value(name.segment())")
⌘↵実行した後の状態（下の「確かめ方」のコマンドの出力）で判定
ヒント

--folder には表示名ではなく数字の ID を渡します。starter の 1 行目で、dev の ID を変数 DEV に入れています。

この問題の準備

答え合わせのたびに、章の最初の状態にこの準備をしてから、あなたのコマンドを実行します。

gcloud resource-manager folders create --display-name=prod --organization=405918273641gcloud resource-manager folders create --display-name=dev --organization=405918273641
確かめ方

あなたのコマンドを実行した後に、root でこのコマンドを実行して、その出力を模範解答のときと比べます。

gcloud projects describe tsubame-quiz-dev --format="value(name, parent.type, labels.env)"gcloud resource-manager folders describe $(gcloud projects describe tsubame-quiz-dev --format="value(parent.id)") --format="value(displayName)"
模範解答
DEV=$(gcloud resource-manager folders list --organization=405918273641 --filter="displayName=dev" --format="value(name.segment())")gcloud projects create tsubame-quiz-dev --name="つばめ 検証" --folder=$DEV --labels=env=dev
問 3

フォルダの直下にあるプロジェクト

正解済み

フォルダ shop の真下にあるプロジェクトの ID を、1 行に 1 つ表示してください（組織の真下のプロジェクトや、shop の中のフォルダに入っているプロジェクトは含めません）。

# ここにコマンドを書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵標準出力で判定（行の順番も見る）
ヒント

gcloud projects list --format="table(projectId, parent.type, parent.id)" で、それぞれの親が見えます。--filter="parent.id=…" で親を指定して絞り込めます。

この問題の準備

答え合わせのたびに、章の最初の状態にこの準備をしてから、あなたのコマンドを実行します。

gcloud resource-manager folders create --display-name=shop --organization=405918273641SHOP=$(gcloud resource-manager folders list --organization=405918273641 --filter="displayName=shop" --format="value(name.segment())")gcloud resource-manager folders create --display-name=team-a --folder=$SHOPgcloud projects create tsubame-q3-app --folder=$SHOPgcloud projects create tsubame-q3-web --folder=$SHOPgcloud projects create tsubame-q3-othergcloud projects create tsubame-q3-deep --folder=$(gcloud resource-manager folders list --folder=$SHOP --format="value(name.segment())")
模範解答
SHOP=$(gcloud resource-manager folders list --organization=405918273641 --filter="displayName=shop" --format="value(name.segment())")gcloud projects list --filter="parent.id=$SHOP" --format="value(projectId)"
問 4

フォルダを片付ける

正解済み

フォルダ old を削除してください。old の中には、空のフォルダ archive と、まだ使うプロジェクト tsubame-q4-app があります。プロジェクトは消さずに、組織の真下へ移してください。

OLD=$(gcloud resource-manager folders list --organization=405918273641 --filter="displayName=old" --format="value(name.segment())")
⌘↵実行した後の状態（下の「確かめ方」のコマンドの出力）で判定
ヒント

中身のあるフォルダは消せません。中のフォルダは先に消し、中のプロジェクトは gcloud projects move … --organization=405918273641 で外へ出します。プロジェクトを削除しても、削除を待つ間はフォルダの中身として数えられるので、フォルダは消せません。

この問題の準備

答え合わせのたびに、章の最初の状態にこの準備をしてから、あなたのコマンドを実行します。

gcloud resource-manager folders create --display-name=keep --organization=405918273641gcloud resource-manager folders create --display-name=old --organization=405918273641OLD=$(gcloud resource-manager folders list --organization=405918273641 --filter="displayName=old" --format="value(name.segment())")gcloud resource-manager folders create --display-name=archive --folder=$OLDgcloud projects create tsubame-q4-app --folder=$OLD
確かめ方

あなたのコマンドを実行した後に、root でこのコマンドを実行して、その出力を模範解答のときと比べます。

gcloud resource-manager folders list --organization=405918273641 --format="value(displayName)"gcloud projects describe tsubame-q4-app --format="value(lifecycleState, parent.type)"
模範解答
OLD=$(gcloud resource-manager folders list --organization=405918273641 --filter="displayName=old" --format="value(name.segment())")gcloud projects move tsubame-q4-app --organization=405918273641gcloud resource-manager folders delete $(gcloud resource-manager folders list --folder=$OLD --format="value(name.segment())")gcloud resource-manager folders delete $OLD
