6.1スクリプトファイルと #!

これまでは、コマンドを 1 行ずつ端末に打ってきました。同じ手順を明日もくり返すなら、その行をファイルに書いておくのが楽です。コマンドを並べて書いたファイルをシェルスクリプト（shell script）と呼びます。

ホームディレクトリに、最初から 1 つ置いてあります。

置いてあるスクリプトを読んで、実行する⌘↵
cat hello.shsh hello.sh

3 行のファイルです。sh hello.sh は「sh というプログラムに、hello.sh を読んで実行させる」という意味です。sh はファイルを上から 1 行ずつ読み、端末に打ったのと同じように実行します。# で始まる行はコメントで、何もしません。

実行権限をつけて、名前で実行する

ls や cat のように、ファイルの名前だけで実行したいところです。試してみます。

そのままでは実行できないエラーになる⌘↵
./hello.sh

Permission denied（権限がない）と言われ、終了ステータスは 126 になりました。第 4 章で見たとおり、ファイルをプログラムとして実行するには x（実行）の権限が要ります。chmod +x でつけます。

x をつけると実行できる⌘↵
ls -l hello.shchmod +x hello.shls -l hello.sh./hello.sh

権限が -rw-r--r-- から -rwxr-xr-x に変わり、./hello.sh で動くようになりました。

1 行目の #! は、だれが読むのか

hello.sh の 1 行目は #!/bin/sh です。この #! をシバン（shebang）と呼びます。これを読むのはシェルではなく、カーネルです。

プログラムを実行するとき、シェルはカーネルに execve というシステムコール（カーネルへの頼みごと）を出します。カーネルはファイルの先頭を見て、#! で始まっていたら、その後ろに書いてあるプログラム（ここでは /bin/sh）を起動し、スクリプトのパスを引数として渡します。

システムコールの列を出して、確かめます。execve の相手は ./hello.sh そのものです。そのあと、起動された sh がスクリプトを openat で開いて read で読んでいます。

スクリプトを実行したときのシステムコールstrace：システムコールも表示⌘↵
./hello.sh

#! の後ろは /bin/sh でなくてもかまいません。#!/usr/bin/python3 と書けば Python のスクリプトになります。sh にとっては、1 行目は # で始まるただのコメントです。だから sh hello.sh でも同じように動きます。

なぜ ./ が要るのか

./ をつけずに名前だけを打つと、見つかりません。

名前だけでは見つからないエラーになる⌘↵
hello.sh

command not found で、終了ステータスは 127 です。第 2 章で見たとおり、シェルは、/ を含まない名前を環境変数 PATH に並んだディレクトリの中だけで探します。いまいるディレクトリは、PATH に入っていません。./hello.sh は「いまいるディレクトリ（.）の hello.sh」というパスなので、PATH を使わずに実行できます。

自分のスクリプトを名前だけで実行したければ、置き場所を PATH に足します。

~/bin を PATH に足す⌘↵
echo $PATHmkdir bincp hello.sh bin/helloPATH=$PATH:$HOME/binhellotype hello

type は、その名前が何として実行されるかを答えます。hello は /home/you/bin/hello でした。

注意PATH に . を入れない

「いまいるディレクトリ」を PATH に入れれば ./ は要らなくなりますが、やってはいけません。だれかが /tmp に ls という名前のスクリプトを置いておくと、/tmp で ls と打っただけで、それが実行されてしまうからです。

6.2変数と引用符、コマンド置換

スクリプトでいちばんよく使う 3 つの道具を、まとめて確かめます。変数と引用符は第 2 章で使いました。ここでは、スクリプトを書くのに要るところだけをおさらいします。

変数は 名前=値 で作り、$名前 で取り出します。= の前後に空白を入れてはいけません。

変数と、2 種類の引用符⌘↵
name=youecho "hi $name"echo 'hi $name'echo "${name}san"
  • 二重引用符 "…" の中では、$name が値に置き換わる
  • 一重引用符 '…' の中では、何も置き換わらない。書いたとおりの文字になる
  • ${name} は $name と同じ。すぐ後ろに文字が続くときに、名前の終わりをはっきりさせる

$(コマンド) はコマンド置換です。コマンドを実行して、その標準出力をその場に埋め込みます。hello.sh の $(whoami) がこれでした。

コマンドの出力を変数に入れる⌘↵
n=$(wc -l < fruits.txt)echo "fruits.txt は $n 行"today=$(date +%F)echo "backup-$today.tar"
注意変数は二重引用符で囲む

値に空白が入っていると、引用符のない $f は空白で分かれて、2 つの引数になります。ファイル名を入れた変数は、いつも "$f" と書く習慣にしてください。このあとの例もそうしています。

変数の値を少し加工する

${…} の中に記号を足すと、値の一部を取り除けます。ファイル名の拡張子を付け替えるときに使います。

後ろを削る %、前を削る ##、なければ別の値 :-⌘↵
f=report.txtecho "${f%.txt}"echo "${f%.txt}.md"echo "${f##*.}"echo "${color:-none}"
書き方意味上の例の結果
${f%パターン}後ろから、パターンに合う部分を削るreport
${f##パターン}前から、パターンに合ういちばん長い部分を削るtxt
${color:-値}変数が空か、ないときは、代わりの値none

6.3ヒアドキュメント：何行もの文字をその場で渡す

スクリプトを作るには、何行もの文字をファイルに書かなければなりません。本物の Linux ではエディタ（vi や nano）を使いますが、この本ではヒアドキュメント（here document）を使います。<<目印 と書くと、次の行から「目印だけの行」の手前までが、そのコマンドの標準入力になります。

<<EOF から EOF までが、cat の標準入力になる⌘↵
cat <<EOFホームは $HOME です今日は $(date +%F) ですEOF

目印は EOF でなくてもかまいません。中の $HOME や $(…) は、二重引用符の中と同じように置き換わります。置き換えたくないときは、目印を一重引用符で囲みます。

目印を引用符で囲むと、中は書いたとおりのまま⌘↵
cat <<'EOF'ホームは $HOME ですEOF

スクリプトを作るときは、こちらを使います。$1 のような文字を、そのままファイルに書きたいからです。cat > ファイル <<'EOF' で、ヒアドキュメントの中身がファイルになります。

ヒアドキュメントでスクリプトを作る⌘↵
cat > first.sh <<'EOF'#!/bin/shecho "ここは $(pwd)"echo "スクリプトの名前は $0"EOFchmod +x first.sh./first.sh

$0 には、スクリプトを起動したときの名前が入っています。

6.4引数：$1、$#、"$@"

ls -l notes の -l や notes のように、スクリプトも引数を受け取れます。引数は、位置パラメータと呼ばれる特別な変数に入ります。

変数中身
$1、$2、…1 番目、2 番目、… の引数
$#引数の個数
$0スクリプトの名前
"$@"すべての引数。1 つ 1 つを別々の単語として
$*すべての引数。空白でつないで
引数を表示するスクリプト⌘↵
cat > args.sh <<'EOF'#!/bin/shecho "個数: $#"echo "1 番目: $1"echo "2 番目: $2"EOFchmod +x args.sh./args.sh apple banana./args.sh "apple banana"

2 回目は、引用符で囲んだので引数は 1 個です。$2 は空になりました。

"$@" と $* の違い

「すべての引数」には 2 つの書き方があり、空白を含む引数で違いが出ます。for で 1 つずつ取り出して確かめます（for は後の節で説明します）。

空白を含む引数を、3 通りに展開する⌘↵
cat > each.sh <<'EOF'#!/bin/shecho '--- "$@"'for a in "$@"; do echo "[$a]"; doneecho '--- $*'for a in $*; do echo "[$a]"; doneecho '--- "$*"'for a in "$*"; do echo "[$a]"; doneEOFchmod +x each.sh./each.sh "my file.txt" memo.txt

受け取った引数をそのまま別のコマンドに渡すときは、いつも "$@" と書きます。$* を使う場面は、ほとんどありません。

shift で引数をずらす

shift は、$1 を捨てて、$2 を $1 に、$3 を $2 に、と 1 つずつ前へずらします。「最初の引数は特別な意味、残りはファイル名」というスクリプトでよく使います。

最初の引数を取り出して、残りを渡す⌘↵
cat > tag.sh <<'EOF'#!/bin/shtag=$1shiftecho "残りは $# 個"for f in "$@"; do echo "$tag: $f"; doneEOFchmod +x tag.sh./tag.sh TODO memo.txt poem.txt

6.5終了ステータスと &&、||

第 2 章で見たとおり、どのコマンドも、終わるときに 0 〜 255 の数を 1 つ残します。終了ステータス（exit status）です。スクリプトでは、これが条件分岐の土台になります。0 が成功、0 以外が失敗を表します。直前のコマンドの終了ステータスは $? に入っています。

成功は 0、失敗は 0 以外⌘↵
true; echo $?false; echo $?grep -q banana fruits.txt; echo $?grep -q mango fruits.txt; echo $?

true は何もせず成功するコマンド、false は何もせず失敗するコマンドです。grep -q は何も表示せず、見つかれば 0、見つからなければ 1 で終わります。

ここまでに出てきた終了ステータスを整理します。

終了ステータス意味
0成功
1ふつうの失敗（grep で見つからなかった、など）
2使い方の誤りなど（コマンドによる）
126ファイルはあるが、実行できない（x の権限がない）
127コマンドが見つからない
128 + nシグナル n で終了させられた（第 8 章）

成功したら、失敗したら

A && B は「A が成功したら B を実行する」、A || B は「A が失敗したら B を実行する」です。

&& と ||⌘↵
grep -q banana fruits.txt && echo "banana がある"grep -q mango fruits.txt || echo "mango はない"mkdir -p work && cd work && pwdcd ..

3 行目は、「ディレクトリを作る。できたら入る。入れたら場所を表示する」という鎖です。途中で失敗したら、そこで止まります。cd に失敗したまま次のコマンドを実行してしまう事故を防げます。

点線に注意してください。A && B || C では、A が成功しても B が失敗すれば C が実行されます。「A なら B、そうでなければ C」を正確に書きたいときは、次の節の if を使います。

スクリプトの終了ステータス

スクリプトも、終わるときに終了ステータスを残します。exit 数 で決められます。exit がなければ、最後に実行したコマンドの終了ステータスがそのまま使われます。

exit で終了ステータスを決める⌘↵
cat > has.sh <<'EOF'#!/bin/shif [ $# -ne 1 ]; then  echo "usage: $0 word" >&2  exit 2figrep -q "$1" fruits.txtEOFchmod +x has.sh./has.sh apple; echo "apple: $?"./has.sh mango; echo "mango: $?"./has.sh; echo "引数なし: $?"

引数が 1 個でなければ、使い方を標準エラー出力に書いて（>&2）、2 で終わります。エラーの文を標準出力に混ぜないのは、スクリプトの出力をパイプで次のコマンドに渡せるようにするためです。

6.6if と test、case

if は終了ステータスを見る

if は「条件」を調べる文ですが、シェルの条件は式ではなくコマンドです。if の後ろのコマンドを実行して、終了ステータスが 0 なら then の側、0 以外なら else の側を実行します。

コマンドの成功・失敗で分かれる⌘↵
if grep -q cherry fruits.txt; then  echo "cherry がある"else  echo "cherry はない"fi

test と [ ]

数や文字列を比べたり、ファイルがあるかを調べたりするには、test コマンドを使います。test は条件を調べて、成り立てば 0、成り立たなければ 1 で終わるだけのコマンドです。

test は終了ステータスで答える⌘↵
test 3 -gt 5; echo $?test -f memo.txt; echo $?[ -f memo.txt ]; echo $?type [

[ は test の別名です。最後の引数に ] を書く決まりになっているだけで、やっていることは同じです。type [ が答えるとおり、[ は文法の記号ではなく、[ という名前のコマンドです（速く動くようにシェルに組み込まれていますが、/usr/bin/[ というファイルもあります）。コマンドと引数は空白で区切るものなので、[ の後ろと ] の前には空白が要ります。

空白を忘れると、] が見つからないエラーになる⌘↵
[ -f memo.txt]

memo.txt] という 1 つの引数になってしまい、最後の引数が ] でなくなったからです。

よく使う条件を表にします。

書き方成り立つのは
[ "$a" = "$b" ]、[ "$a" != "$b" ]文字列が同じ、違う
[ -z "$a" ]、[ -n "$a" ]文字列が空、空でない
[ "$x" -eq 3 ]、-ne、-lt、-le、-gt、-ge数として等しい、違う、小さい、以下、大きい、以上
[ -e パス ]存在する
[ -f パス ]、[ -d パス ]通常のファイル、ディレクトリ
[ -r パス ]、[ -w パス ]、[ -x パス ]読める、書ける、実行できる
[ ! 条件 ]条件が成り立たない

数の比較に < や > を使わないのは、シェルではそれがリダイレクトの記号だからです。

elif で 3 つに分ける⌘↵
x=5if [ "$x" -gt 3 ]; then  echo "3 より大きい"elif [ "$x" -eq 3 ]; then  echo "ちょうど 3"else  echo "3 より小さい"fi
注意変数を引用符で囲まないと

変数が空のとき、[ $color = red ] は [ = red ] になり、文法の誤りになります。[ "$color" = red ] なら [ "" = red ] になるので、正しく比べられます。

空の変数を、引用符なしと引用符つきで比べる⌘↵
[ $color = red ]; echo $?[ "$color" = red ]; echo $?

1 つ目はエラーの文が出て、終了ステータスは 2 です。2 つ目は静かに 1（成り立たない）を返します。

case：パターンで分ける

1 つの値を、いくつものパターンと比べるときは case が読みやすくなります。パターンには、ファイル名と同じワイルドカード（*、?）が使えます。

拡張子で分ける⌘↵
cat > kind.sh <<'EOF'#!/bin/shfor f in "$@"; do  case "$f" in    *.txt)       echo "$f: テキスト" ;;    *.sh)        echo "$f: スクリプト" ;;    *.csv|*.tsv) echo "$f: 表" ;;    *)           echo "$f: そのほか" ;;  esacdoneEOFchmod +x kind.sh./kind.sh memo.txt hello.sh scores.csv notes
  • 上から順に比べて、最初に合ったパターンの行だけを実行する
  • ;; がその行の終わり
  • | で、パターンをいくつか並べられる
  • *) は何にでも合うので、最後に置いて「そのほか」にする
  • 終わりは esac（case を逆から書いたもの）

6.7くり返し：for、while、read

for：並べたものを 1 つずつ

for 変数 in 単語… は、単語を 1 つずつ変数に入れて、do から done までをくり返します。

単語の並び、ワイルドカード、コマンドの出力⌘↵
for c in red green blue; do echo "色: $c"; donefor f in notes/*.txt; do echo "$f は $(wc -l < "$f") 行"; donefor i in $(seq 1 3); do echo "$i 回目"; done

2 つ目のように、ワイルドカードはシェルがファイル名の並びに展開するので、「このディレクトリのファイルすべてに同じことをする」が 1 行で書けます。3 つ目の seq 1 3 は、1 から 3 までの数を出力するコマンドです。

while：条件が成り立つあいだ

while コマンド は、コマンドの終了ステータスが 0 のあいだ、くり返します。if と同じで、条件はコマンドです。

数を数える⌘↵
i=1while [ $i -le 3 ]; do  echo "i = $i"  i=$((i + 1))done

$((…)) は算術展開で、中の式を計算した結果に置き換わります。後の節でくわしく見ます。

条件がいつまでも成り立つと、ループは終わりません。この本の Linux は、一定の時間で打ち切ります（本物では、Ctrl-C で止めます。第 8 章）。

終わらないループ（途中で打ち切られる）上限で打ち切られる⌘↵
while true; do :; done

: は、何もしないで成功するコマンドです。

read：1 行ずつ読む

read 変数… は、標準入力から 1 行読んで、変数に入れます。行は空白で区切られ、1 つ目の単語が 1 つ目の変数に、2 つ目が 2 つ目に入ります。最後の変数には、残り全部が入ります。

端末から 1 行読む（入力は Linus Benedict Torvalds）入力つき⌘↵
read first rest; echo "first=$first"; echo "rest=$rest"

read は、読めたら 0、入力の終わり（EOF）に来たら 1 で終わります。だから while read と組み合わせると、「ファイルを 1 行ずつ、最後まで」処理できます。ループ全体の標準入力を、done の後ろの < でファイルにつなぎます。

ファイルを 1 行ずつ処理する⌘↵
cat numbers.txtsum=0while read n; do  sum=$((sum + n))done < numbers.txtecho "合計 $sum"

区切りを空白でなくカンマにしたいときは、read の前に IFS=, と書きます。IFS は、シェルが単語を区切るのに使う文字を入れた変数です。

CSV を列に分けて読む⌘↵
head -3 scores.csvwhile IFS=, read name subject score; do  echo "$name の $subject は $score"done < scores.csv

1 行目の見出しも、ほかの行と同じように読まれている点に注意してください。見出しを飛ばす方法は、確認問題で考えます。

注意パイプの右側の while は、別のプロセス

cat numbers.txt | while read n; do sum=$((sum + n)); done と書くと、ループの中で変えた sum は、ループの外では元のままです。パイプの右側は、別のプロセス（シェルの複製）の中で実行されるからです。上のように done < ファイル と書けば、いまのシェルの中で実行されます。別のプロセスで何が起きるかは、第 7 章で確かめます。

パイプの右側で変えた変数は、外に戻らない⌘↵
sum=0cat numbers.txt | while read n; do sum=$((sum + n)); doneecho "合計 $sum"

6.8関数と local、算術展開

関数：コマンドの並びに名前をつける

同じ処理を何度も書くなら、関数にします。名前() { … } で定義し、コマンドと同じように名前で呼びます。引数は、スクリプトと同じく $1、$2、$#、"$@" で受け取ります。

関数を定義して呼ぶ⌘↵
greet() {  echo "こんにちは、$1 さん（引数は $# 個）"}greet yougreet alice bob

関数の中の $1 は、関数に渡した引数です。スクリプトの引数ではありません。

関数は、結果を 2 通りの方法で返せます。

  • 終了ステータス：return 数。成功か失敗かを伝える。if や && で使える
  • 標準出力：echo で出力する。呼ぶ側は $(…) で受け取る
終了ステータスで返す関数と、出力で返す関数⌘↵
is_big() { [ "$1" -gt 100 ]; }max() {  if [ "$1" -gt "$2" ]; then echo "$1"; else echo "$2"; fi}is_big 500 && echo "500 は大きい"is_big 7 || echo "7 は小さい"m=$(max 3 9)echo "大きいほうは $m"

is_big には return がありません。そのときは、最後のコマンド（[ … ]）の終了ステータスが、関数の終了ステータスになります。

local：関数の中だけの変数

シェルの変数は、何もしなければスクリプト全体で 1 つです。関数の中で代入すると、外の変数が書き換わります。local をつけると、その関数の中だけの変数になります。

local のある変数、ない変数⌘↵
count() {  local n=0  for x in "$@"; do n=$((n + 1)); done  total=$n}n=100count a b cecho "n=$n total=$total"

関数の中の n は local なので、外の n は 100 のままです。total は local でないので、関数の外からも見えます。

メモlocal は POSIX にはない

local は POSIX の決まりには入っていませんが、bash、dash など、ふつうに使われている sh はどれも対応しています。

算術展開 $(( ))

$((式)) は、式を整数として計算します。中では、変数に $ をつけなくてもかまいません。

整数の計算⌘↵
echo $((7 + 2)) $((7 - 2)) $((7 * 2))echo $((7 / 2)) $((7 % 2))echo $(( (3 + 4) * 2 ))x=10echo $((x * x)) $((x > 3)) $((x == 3))
  • / は割り算の商（小数は切り捨て）、% は余り。7 ÷ 2 は 3 余り 1
  • 比較（>、== など）の結果は、成り立てば 1、成り立たなければ 0
  • 小数は扱えない

6.9getopts と、set -u、set -x

getopts：オプションを解釈する

ls -l の -l のようなオプションを自分のスクリプトでも受けつけたいときは、シェルの組み込みコマンド getopts を使います。

-v と -n 回数 を受けつけるスクリプト⌘↵
cat > hi.sh <<'EOF'#!/bin/shcount=1mark=""while getopts "n:v" opt; do  case $opt in    n) count=$OPTARG ;;    v) mark="!" ;;    *) echo "usage: $0 [-v] [-n 回数] 名前" >&2; exit 2 ;;  esacdoneshift $((OPTIND - 1))i=0while [ $i -lt $count ]; do  echo "hi, $1$mark"  i=$((i + 1))doneEOFchmod +x hi.sh./hi.sh you./hi.sh -v -n 2 you
  • "n:v" が、受けつけるオプションの一覧。n: のように後ろに : がつくものは、値を取る（-n 2）
  • getopts は、呼ぶたびにオプションを 1 つ取り出して、変数 opt に文字を入れる。値は OPTARG に入る。オプションがなくなると 1 で終わるので、while が終わる
  • 知らないオプションが来ると、opt に ? が入る。*) の行で使い方を表示して、2 で終わる
  • OPTIND は「次に見る引数の番号」。shift $((OPTIND - 1)) で、オプションの分だけ引数をずらす。残った $1 が名前になる
知らないオプションエラーになる⌘↵
./hi.sh -x you

set -u：空の変数を見逃さない

シェルでは、作っていない変数を使ってもエラーにならず、空の文字列になります。変数名の打ち間違いに気づけません。スクリプトの先頭に set -u と書くと、作っていない変数を使った時点で、エラーで止まります。

変数名の打ち間違いを、set -u が見つけるエラーになる⌘↵
cat > typo.sh <<'EOF'#!/bin/shset -utarget=workecho "消すのは $taget/ の中"echo "ここまでは来ない"EOFchmod +x typo.sh./typo.sh

taget（r が抜けている）は作っていない変数なので、4 行目でスクリプトが止まりました。set -u がなければ、消すのは / の中 と表示されて先へ進みます。これが rm -r "$taget/" だったら、と考えてみてください。

set -x：実行する行を表示する

スクリプトが思ったとおりに動かないときは、set -x が役に立ちます。変数を置き換えたあとの、実際に実行するコマンドを、+ をつけて表示します。スクリプトを書き換えずに、sh -x スクリプト と起動しても同じです。

sh -x で、実行の様子を追う⌘↵
sh -x ./tag.sh TODO memo.txt

+ の行は標準エラー出力に出ます。tag=TODO、shift、echo '残りは 1 個' と、変数が値に置き換わった形で見えます。

メモset -e

もう 1 つよく使われるのが set -e です。コマンドが失敗（終了ステータスが 0 以外）したら、その場でスクリプトを止めます。本物の Linux のスクリプトでは、先頭に set -eu と書くのが定番です。

ターミナル
$ cat stop.sh#!/bin/shset -ecd /nonexistentecho "ここまでは来ない"$ ./stop.sh./stop.sh: 3: cd: can't cd to /nonexistent$ echo $?2

if の条件や、&&、|| の左側での失敗では止まりません。

6.10実用的なスクリプトを 2 つ

ここまでの道具を組み合わせて、実際に役に立つスクリプトを 2 つ作ります。

ファイルの拡張子を一括で変える

.jpeg のファイルを、すべて .jpg に改名します。まず、練習用のファイルを作ります。

練習用のファイル⌘↵
mkdir photostouch photos/cat.jpeg photos/dog.jpeg "photos/my bird.jpeg" photos/readme.txtls photos

ファイルを書き換えるスクリプトは、まず echo をつけて、何が実行されるかを確かめるのが安全です。

echo をつけて、実行されるコマンドを確かめる⌘↵
cat > chext.sh <<'EOF'#!/bin/sh# 使い方: chext.sh 古い拡張子 新しい拡張子 ディレクトリset -uif [ $# -ne 3 ]; then  echo "usage: $0 old new dir" >&2  exit 2fiold=$1new=$2dir=$3for f in "$dir"/*."$old"; do  [ -e "$f" ] || continue  echo mv "$f" "${f%.$old}.$new"doneEOFchmod +x chext.sh./chext.sh jpeg jpg photos

${f%.$old} で後ろの .jpeg を削り、.jpg をつけ直しています。[ -e "$f" ] || continue は、合うファイルが 1 つもなかったときの用心です。そのとき、シェルは photos/*.jpeg という文字をそのまま f に入れるので、存在しなければ continue で飛ばします。

よさそうなので、echo を外して実行します。sed で echo mv を mv に書き換えた版を作ります。

echo を外して、本当に改名する⌘↵
sed 's/echo mv/mv/' chext.sh > chext2.shchmod +x chext2.sh./chext2.sh jpeg jpg photosls photos

空白を含む my bird.jpeg も、正しく改名できました。変数をすべて二重引用符で囲んであるからです。

アクセスログを集計する

/var/log/access.log は、Web サーバのアクセスログです。1 行が 1 回のアクセスで、空白で区切った 9 番目がステータスコード（200 は成功、404 は見つからない）、10 番目が送ったバイト数です。

ログの形⌘↵
head -3 /var/log/access.log

ステータスコードごとの回数は、第 5 章の道具だけで数えられます。

ステータスコードごとの回数⌘↵
cut -d' ' -f9 /var/log/access.log | sort | uniq -c | sort -rn

「エラー（400 以上）の回数」と「送ったバイト数の合計」も一緒に出したくなったら、スクリプトの出番です。while read で 1 行ずつ読み、10 個の変数に分けます。

ログを集計するスクリプト⌘↵
cat > logsum.sh <<'EOF'#!/bin/sh# 使い方: logsum.sh ログファイルset -ulog=${1:-/var/log/access.log}if [ ! -r "$log" ]; then  echo "$0: $log が読めません" >&2  exit 1filines=0errors=0bytes=0while read ip a b date zone method path proto status size; do  lines=$((lines + 1))  bytes=$((bytes + size))  if [ "$status" -ge 400 ]; then    errors=$((errors + 1))    echo "エラー $status: $path"  fidone < "$log"echo "アクセス $lines 回、エラー $errors 回、合計 $bytes バイト"EOFchmod +x logsum.sh./logsum.sh
読めないファイルを渡すと、1 で終わるエラーになる⌘↵
./logsum.sh /var/log/nothing.log

このスクリプトには、この章で学んだことがほとんど入っています。#!、set -u、引数と ${1:-…}、[ ]、exit、while read、$(( ))、if、標準エラー出力です。

コツスクリプトを書くときの習慣
  • 1 行目は #!/bin/sh。2 行目あたりに、使い方をコメントで書く
  • set -u をつける
  • 変数は "$f" のように二重引用符で囲む。すべての引数は "$@"
  • 引数の数を確かめ、足りなければ使い方を標準エラー出力に出して、0 以外で終わる
  • ファイルを消す・書き換える行は、まず echo をつけて確かめる
  • 動きがおかしければ、sh -x で追う

6.11確認問題

この章の内容を、自分でスクリプトを書いて確かめます。入力欄にコマンドを書いて「答え合わせ」を押してください。スクリプトファイルを作る問題では、ヒアドキュメントの中に続きを書きます。どの問題も、中身を少し変えたデータでも試されるので、答えを直接 echo しただけでは通りません。

問 1

引数の合計を出すスクリプト

正解済み

ホームディレクトリに sum.sh を作ってください。引数として渡された整数をすべて足して、合計を 1 行で出力します。引数が 1 つもなければ 0 を出力します。たとえば sh sum.sh 1 2 3 の出力は 6 です。

cat > sum.sh <<'EOF'#!/bin/shEOF
⌘↵実行した後の状態（下の「確かめ方」のコマンドの出力）で判定
ヒント

for n in "$@" で引数を 1 つずつ取り出し、total=$((total + n)) で足していきます。total を最初に 0 にしておくのを忘れずに。

確かめ方

あなたのコマンドを実行した後に、root でこのコマンドを実行して、その出力を模範解答のときと比べます。

cd /home/yoush sum.sh 1 2 3sh sum.shsh sum.sh $(cat numbers.txt)
模範解答
cat > sum.sh <<'EOF'#!/bin/shtotal=0for n in "$@"; do  total=$((total + n))doneecho $totalEOF
問 2

パスの種類を答えるスクリプト

正解済み

ホームディレクトリに what.sh を作ってください。引数のパスを 1 つずつ調べて、ディレクトリなら パス: dir、通常のファイルなら パス: file、存在しなければ パス: none と 1 行ずつ出力します。たとえば sh what.sh notes memo.txt の出力は、notes: dir と memo.txt: file の 2 行です。

cat > what.sh <<'EOF'#!/bin/shfor p in "$@"; dodoneEOF
⌘↵実行した後の状態（下の「確かめ方」のコマンドの出力）で判定
ヒント

[ -d "$p" ] はディレクトリ、[ -f "$p" ] は通常のファイルのときに成り立ちます。if … elif … else … fi で 3 つに分けます。

確かめ方

あなたのコマンドを実行した後に、root でこのコマンドを実行して、その出力を模範解答のときと比べます。

cd /home/yoush what.sh notes memo.txt nothingsh what.sh inbox inbox/a.txt /etc /etc/hostname "my file"
模範解答
cat > what.sh <<'EOF'#!/bin/shfor p in "$@"; do  if [ -d "$p" ]; then    echo "$p: dir"  elif [ -f "$p" ]; then    echo "$p: file"  else    echo "$p: none"  fidoneEOF
問 3

数学の点の合計

正解済み

scores.csv は、1 行目が見出し（name,subject,score）、2 行目からが「名前,科目,点」の CSV です。科目が math の行の点を合計して、数だけを 1 行で出力してください。スクリプトファイルは作らず、コマンドをそのまま書いてかまいません。

# ここにコマンドを書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵標準出力で判定（行の順番も見る）
ヒント

while IFS=, read name subject score; do … done < scores.csv で 1 行ずつ読みます。[ "$subject" = math ] のときだけ足せば、見出しの行（科目の欄が subject）は自然に飛ばされます。

模範解答
total=0while IFS=, read name subject score; do  if [ "$subject" = math ]; then    total=$((total + score))  fidone < scores.csvecho $total
問 4

拡張子を一括で変える

正解済み

inbox ディレクトリに、.text で終わるファイルがいくつかあります。それらをすべて .txt に改名してください（a.text → a.txt）。ほかのファイルは変えません。ファイル名には空白が入っているものもあります。

# ここにコマンドを書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵実行した後の状態（下の「確かめ方」のコマンドの出力）で判定
ヒント

for f in inbox/*.text で 1 つずつ取り出し、"${f%.text}.txt" で新しい名前を作ります。空白を含む名前のために、"$f" の二重引用符を忘れずに。

この問題の準備

答え合わせのたびに、章の最初の状態にこの準備をしてから、あなたのコマンドを実行します。

mkdir inboxtouch inbox/a.text inbox/b.text "inbox/my memo.text" inbox/keep.md inbox/text
確かめ方

あなたのコマンドを実行した後に、root でこのコマンドを実行して、その出力を模範解答のときと比べます。

ls -1 /home/you/inbox
模範解答
for f in inbox/*.text; do  mv "$f" "${f%.text}.txt"done
要点この章のまとめ
  • シェルスクリプトは、コマンドを並べたファイル。sh ファイル で実行するか、chmod +x で実行権限をつけて ./ファイル で実行する
  • 1 行目の #!/bin/sh を読むのはカーネル。execve されたファイルが #! で始まっていたら、そのプログラムを起動してスクリプトを渡す
  • 名前だけで実行できるのは、PATH に並んだディレクトリにあるものだけ。だから ./ が要る
  • 引数は $1、$2、…、個数は $#。すべての引数は "$@"。shift で前へずらす
  • 終了ステータスは 0 が成功、0 以外が失敗。$? で見る。A && B は成功したら、A || B は失敗したら。exit 数 で自分の終了ステータスを決める
  • if と while の条件はコマンド。終了ステータスが 0 なら成り立つ。[ … ] は test コマンドで、空白が要る
  • case はパターンで分ける。for は並べた単語を 1 つずつ。while read はファイルを 1 行ずつ
  • 関数は 名前() { … }。結果は return の終了ステータスか、標準出力で返す。local で関数の中だけの変数
  • $(( )) は整数の計算。ヒアドキュメント <<EOF は何行もの文字を標準入力に渡す
  • getopts でオプションを解釈する。set -u は作っていない変数でエラー、set -x（sh -x）は実行する行を表示
