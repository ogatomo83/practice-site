第 3 章

ファイルとディレクトリ

Linux のファイルは、/ から始まる 1 本の木に並んでいます。その木の中を動き、ls -l の 1 行を読み、ファイルを作り、コピーし、動かし、消し、探します。最後に、名前と中身が別のものであることを、リンクと inode 番号で確かめます。

3.1ディレクトリの木

Linux では、すべてのファイルが、1 本の木の中に並んでいます。木の根は / という名前のディレクトリで、ルートディレクトリと呼びます。ディレクトリは、ファイルやほかのディレクトリを入れておく入れ物です（Windows や macOS の「フォルダ」と同じものです）。

Windows には C: や D: のようにドライブごとの木がありますが、Linux の木は 1 本だけです。2 台目のディスクも、USB メモリも、この木のどこかの枝としてつながります（第 12 章のマウント）。

まず、根の直下を見てみましょう。

ルートディレクトリの中身⌘↵
ls /

本物の Linux でも、ほぼ同じ名前が並びます。どのディレクトリに何を置くかは、FHS（Filesystem Hierarchy Standard）という取り決めで決まっているからです。主なものを、木の形で示します。

ディレクトリ置くもの
/etcシステム全体の設定ファイル。ほとんどがテキストで、cat で読める
/home一般ユーザーのホームディレクトリ。自分のファイルを自由に置ける場所
/rootroot のホームディレクトリ。/home の下ではない
/usr/binコマンドの実体。/bin は、昔との互換のために /usr/bin を指している
/usr/libプログラムが共通で使う部品（ライブラリ。第 18 章）
/var動いている間に変わるデータ。/var/log にはログがたまる
/tmp一時ファイル。だれでも書ける。再起動すると消える
/dev装置を表す特別なファイル。/dev/null など
/procカーネルの中の情報を、ファイルの形で見せる場所。ディスクの上にはない
/boot起動に使うカーネル本体（第 17 章）

設定ファイルを 1 つ読んでみましょう。

/etc の中身と、設定ファイル⌘↵
ls /etccat /etc/hostname

第 2 章で hostname コマンドが表示した名前は、このファイルに書いてあったものです。Linux では、設定の多くが、こういう小さなテキストファイルです。

3.2いまいる場所を動かす：pwd と cd

シェルは、木の中のどこか 1 か所に「いる」ことになっています。その場所をカレントディレクトリ（作業ディレクトリ）と呼びます。pwd で表示し、cd で動かします。

いまいる場所⌘↵
pwd

ログインした直後は、ホームディレクトリにいます。/etc へ移動してみます。

/etc へ移動する⌘↵
cd /etcpwdlscat hostname

プロンプトの ~ が /etc に変わりました。プロンプトは、いつもカレントディレクトリを表示しています。

ls に引数を付けなければ、カレントディレクトリの中身が表示されます。cat hostname も、/etc/ を付けずに読めました。カレントディレクトリは、「名前だけを書いたとき、どこから探すか」の基準です。

cd には、よく使う行き先の書き方があります。

書き方行き先
cdホームディレクトリ（引数なし）
cd ~ホームディレクトリ。~/notes のように、うしろに続けられる
cd ..1 つ上のディレクトリ（次の節）
cd -直前にいたディレクトリ。移動先を表示する
戻る、行き来する⌘↵
cdpwdcd -cd -

1 行目の cd でホームに戻り、cd - で /etc へ、もう 1 回の cd - でホームへ戻りました。2 つのディレクトリを行き来するときに便利です。

ないディレクトリや、ディレクトリでないものには、移動できません。

移動できない例エラーになる⌘↵
cd nowherecd memo.txtcd /root

3 つのエラーの文は、理由がそれぞれ違います。

  • No such file or directory：その名前のものがない
  • Not a directory：あるけれど、ディレクトリではない（memo.txt はふつうのファイル）
  • Permission denied：あるけれど、入る許可がない（/root は root だけが入れる。第 4 章）

エラーの文をきちんと読めば、何が悪いのかがわかります。

3.3絶対パスと相対パス

木の中のファイルやディレクトリの場所を、文字で書いたものをパスと呼びます。パスは、ディレクトリの名前を / で区切ってつなげたものです。書き方は 2 通りあります。

  • 絶対パスは、/ で始まる。根から順にたどる。カレントディレクトリがどこでも、同じ場所を指す
  • 相対パスは、/ で始まらない。カレントディレクトリからたどる。いまいる場所によって、指す先が変わる
同じファイルを、2 通りのパスで⌘↵
cat /home/you/notes/todo.txtcat notes/todo.txt

カレントディレクトリが /home/you なので、notes/todo.txt は /home/you/notes/todo.txt と同じファイルを指します。

. と ..

どのディレクトリにも、特別な名前が 2 つ入っています。

  • .（ドット 1 つ）は、そのディレクトリ自身
  • ..（ドット 2 つ）は、1 つ上のディレクトリ（親ディレクトリ）

.. を使うと、相対パスで木を上へたどれます。

.. で上へたどる⌘↵
cd notespwdls ..cat ../memo.txt

notes の中にいるとき、.. は /home/you です。../memo.txt は「1 つ上がって、そこの memo.txt」です。

.. は、いくつでもつなげられます。

2 つ上へ⌘↵
cd ../..pwdls

/home/you/notes から 2 つ上がって、/home に来ました。ほかのユーザーのホームディレクトリが並んでいます。

根より上はありません。/ の .. は、/ 自身です。

根より上はない⌘↵
cd /cd ..pwdcd

最後の cd で、ホームディレクトリに戻りました。

. は、何の役に立つのでしょうか。1 つは、第 2 章で見た ./hello.sh です。「PATH から探すのではなく、いまいるディレクトリのこのファイル」と、はっきり伝えられます。もう 1 つは、「ここへ」という行き先としての使い方です。このあとの cp や find で使います。

コツどちらを使うか

手で打つときは、短く済む相対パスが便利です。スクリプトや設定ファイルに書くときは、どこから実行されても同じ場所を指す絶対パスが安全です。realpath コマンドは、相対パスを絶対パスに直して表示します。

3.4ls -l の 1 行を読む

ls -l は、ファイルごとに 1 行ずつ、詳しい情報を表示します。Linux を使っていると、毎日この表示を読むことになります。

ls -l⌘↵
ls -l

最初の total 28 は、ここにあるファイルが使っているディスクの量の合計です（単位は 1 K バイト）。そのあとの 1 行 1 行は、7 つの部分からできています。

部分例意味
種類-最初の 1 文字。- はふつうのファイル、d はディレクトリ、l はシンボリックリンク
権限rw-r--r--だれが読めて（r）、書けて（w）、実行できる（x）か。第 4 章で読み方を扱う
リンク数1このファイルに付いている名前の数。この章の「リンク」の節で扱う
持ち主youこのファイルを持っているユーザー
グループyouこのファイルが属するグループ（第 4 章）
大きさ127中身のバイト数
更新時刻Mar 28 10:40中身を最後に書き換えた日時
名前poem.txtファイルの名前

notes の行は d で始まっています。ディレクトリです。ディレクトリの大きさが 4096 なのは、ディレクトリ自身（名前の一覧を入れておく場所）の大きさで、中のファイルの合計ではありません。

種類の違うものを、いくつか並べて見てみましょう。

いろいろな種類⌘↵
ls -l /bin /dev/null /etc/hostnamels -ld /etc
  • /bin は l で始まり、名前のあとに -> usr/bin と付いている。シンボリックリンク（この章の後半）
  • /dev/null は c で始まる。装置を表す特別なファイル（第 12 章）
  • /etc/hostname は -。ふつうのファイル
  • /etc は d。ディレクトリ

ls -l /etc と打つと、/etc の中身の一覧が出てしまいます。ディレクトリそのものの情報を見たいときは、-d（directory）を付けます。

ls のオプションを、まとめておきます。

オプション動き
-l詳しい情報を付けて、1 行に 1 つ
-a. で始まる名前も表示する（次の節）
-dディレクトリの中身ではなく、ディレクトリそのものを表示する
-h大きさを 18K、2.8M のように、人が読みやすい単位で表示する（-l と一緒に使う）
-t更新時刻の新しい順に並べる
-S大きさの大きい順に並べる
-r並び順を逆にする
-R中のディレクトリも、再帰的に（奥まで）表示する
-F名前のうしろに、種類の印を付ける（ディレクトリは /、リンクは @）
-iinode 番号を表示する（この章の「リンク」の節）
オプションを組み合わせる⌘↵
ls -Fls -lSls -R

ls -lS は、大きい順です。ls -R は、notes の中まで表示しました。

3.5隠しファイル

ls は、名前が . で始まるものを表示しません。-a を付けると出てきます。

ls -a⌘↵
ls -acat .profile

.profile というファイルがありました。名前が . で始まるファイルを、隠しファイル（ドットファイル）と呼びます。特別な仕組みがあるわけではなく、「ls とワイルドカードの * が、. で始まる名前を飛ばす」という約束があるだけです。

ホームディレクトリの隠しファイルには、プログラムごとの設定を置くのが習慣です。ふだんの一覧のじゃまにならないように、隠してあります。.profile は、ログインしたシェルが最初に読む設定ファイルです。本物の Linux のホームディレクトリには、.bashrc（bash の設定）、.ssh（ssh の鍵）、.config（いろいろなプログラムの設定）などが並びます。

ls -a には、. と .. も出ています。前の節で見た「自分自身」と「1 つ上」です。この 2 つも . で始まるので、ふだんは隠れています。

3.6作る、コピーする、動かす、消す

ここからは、木の形を自分で変えます。練習用に、work というディレクトリを作って、その中で作業します。

mkdir と touch：作る

mkdir（make directory）はディレクトリを作り、touch は空のファイルを作ります。

ディレクトリとファイルを作る⌘↵
mkdir worktouch work/a.txtls -l work

a.txt の大きさは 0 です。touch は本来、ファイルの更新時刻を「いま」にするコマンドです。ファイルがなければ空のファイルを作るので、その使い方のほうが有名になりました。

深いディレクトリを一度に作ろうとすると、失敗します。途中のディレクトリがないからです。-p（parents）を付けると、途中のディレクトリも一緒に作ります。

途中のディレクトリがないと、作れないエラーになる⌘↵
mkdir work/2026/04/photos
-p で、途中も一緒に作る⌘↵
mkdir -p work/2026/04/photosls -R work

cp：コピーする

cp（copy）は、cp コピー元 コピー先 の形で使います。コピー先がディレクトリなら、その中に同じ名前でコピーします。

ファイルをコピーする⌘↵
cp memo.txt work/cp memo.txt work/memo-copy.txtls work

ディレクトリをコピーするには、-r（recursive。再帰的に、中身ごと）が要ります。

ディレクトリは、そのままではコピーできないエラーになる⌘↵
cp notes work
-r で、中身ごとコピーする⌘↵
cp -r notes workls -R work/notes
注意コピー先に同じ名前があると、黙って上書きする

cp も、次の mv も、コピー先に同じ名前のファイルがあると、確認せずに上書きします。上書きされた中身は戻りません。-i（interactive）を付けると、上書きの前に確認します。y で始まる答えなら上書きし、それ以外なら何もしません。

上書きされるファイルを用意する⌘↵
cp memo.txt keep.txt
-i：上書きの前にたずねる（n と答える）入力：n ⏎⌘↵
cp -i fruits.txt keep.txthead -1 keep.txt

cp: overwrite 'keep.txt'? とたずねられ、n と答えたので、keep.txt は元の中身のままです。たずねる文は標準エラー出力に出て、答えは標準入力から読みます。

mv：動かす、名前を変える

mv（move）は、ファイルを別の場所へ動かします。同じディレクトリの中で動かせば、名前を変えることになります。Linux に「名前を変える」専用のコマンドはなく、mv がその役目をします。

名前を変える、動かす⌘↵
mv work/memo-copy.txt work/list.txtls workmv work/list.txt work/2026/ls work work/2026

1 行目は名前を変え、3 行目は work/2026 の中へ動かしました。mv はディレクトリも、オプションなしで動かせます。

rm と rmdir：消す

rm（remove）は、ファイルを消します。

ファイルを消す⌘↵
rm work/a.txtls work

ディレクトリは、rm だけでは消せません。空のディレクトリを消す rmdir か、中身ごと消す rm -r を使います。

ディレクトリを消そうとするとエラーになる⌘↵
rm workrmdir work

rm は「ディレクトリだ」と言って断り、rmdir は「空ではない」と言って断りました。

rm -r で、中身ごと消す⌘↵
rm -r work/2026ls work
注意rm にごみ箱はない

rm で消したファイルは、ごみ箱に入りません。その場でなくなり、取り戻す方法は基本的にありません。とくに rm -r は、ディレクトリの中身を奥まで全部消します。ワイルドカードと組み合わせるときは、先に同じ引数で ls を実行して、消えるものを確かめる習慣をつけてください。rm -r * の代わりに、まず ls * です。

rm -i は、1 つ消すたびに rm: remove regular file 'memo.txt'? とたずねます。書き込みを禁止したファイル（第 4 章）を消そうとすると、-i がなくても remove write-protected regular file とたずねられます。rm -f（force）は、ファイルがなくてもエラーを出さず、確認もしません。rm -rf は、Linux でいちばん事故の多いコマンドです。このサイトの Linux は、リセットすれば元に戻ります。本物では戻りません。

ワイルドカード（第 2 章）は、これらのコマンドと一緒に使うと力を発揮します。

ワイルドカードでまとめて扱う⌘↵
touch work/1.log work/2.log work/keep.txtls work/*.logrm work/*.logls work

rm work/*.log を実行する前に、同じワイルドカードで ls を実行して、何が当てはまるかを確かめています。

3.7中身を見る：cat、head、tail、less

ファイルの中身を見るコマンドは、ファイルの大きさと、見たい場所で使い分けます。

コマンド見せるもの使いどころ
cat全部短いファイル
head最初の 10 行（-n 数 で行数を指定）どんなファイルかを、ちょっと見る
tail最後の 10 行（-n 数 で行数を指定）ログの最新の部分を見る
less1 画面ずつ。上下に動ける長いファイルを読む

cat は、もう何度も使いました。名前は concatenate（つなげる）から来ていて、複数のファイルを渡すと、順につなげて表示します。-n を付けると、行番号が付きます。

cat⌘↵
cat -n poem.txtcat memo.txt notes/ideas.txt

長いファイルは、head と tail で端だけを見ます。/var/log/access.log は、Web サーバのアクセスの記録（の見本）です。

head と tail⌘↵
head -n 3 /var/log/access.logtail -n 2 /var/log/access.log

ログは、新しい記録が下に足されていきます。だから、「さっき何が起きたか」を見るには tail を使います。本物の Linux では、tail -f ファイル で、ファイルに行が足されるたびに表示し続けることもできます。

less は、長いファイルを 1 画面ずつ読むためのコマンドです。本物の Linux では、次のキーで操作します。

キー動き
スペース / b1 画面進む / 戻る
↓ / ↑（または j / k）1 行進む / 戻る
/文字文字を探す。n で次の候補へ
g / G先頭へ / 末尾へ
q終わる

man（第 2 章）がマニュアルを表示するときも、中で less を使っています。だから、操作のキーは同じです。

メモこのサイトの Linux では

less は、cat と同じように全部を表示して終わります。画面の中で上下に動く操作はできません。

ディレクトリや、読む許可のないファイルは、cat できません。

読めないものエラーになる⌘↵
cat notescat /etc/shadow

/etc/shadow は、パスワードの情報を入れるファイルで、root しか読めません。Permission denied の理由は、第 4 章で ls -l の権限の部分を読めるようになるとわかります。

テキストでないファイルを cat すると、画面が乱れます。中身の種類がわからないときは、先に file コマンドで調べます。

file で種類を調べる⌘↵
file memo.txt hello.sh notes /usr/bin/ls

/usr/bin/ls は ELF という形式の実行ファイルです（第 18 章）。Linux は、Windows と違って、名前の最後の .txt や .sh（拡張子）でファイルの種類を決めません。拡張子は、人が見分けるための習慣にすぎません。file は、名前ではなく中身を見て判断しています。

3.8名前と中身は別のもの：リンク

ここまで、「ファイルには名前がある」と考えてきました。実は、Linux のファイルシステムでは、名前と中身は別々に管理されています。

  • ファイルの中身と、その情報（大きさ、持ち主、権限、時刻）は、inode（アイノード）という入れ物に入っている。inode には、名前ではなく番号が付いている
  • ディレクトリは、「名前 → inode 番号」の対応表にすぎない

ls -i で、inode 番号を見られます。

inode 番号を見る⌘↵
ls -i memo.txtls -li

行の先頭に付いた数が、inode 番号です。ファイルごとに違う番号が付いています。

ハードリンク：同じ inode に、もう 1 つ名前を付ける

名前が対応表の 1 行にすぎないなら、1 つの inode に、2 つの名前を付けることもできるはずです。それがハードリンクです。ln 元の名前 新しい名前 で作ります。

ハードリンクを作る⌘↵
ln memo.txt memo-hard.txtls -li memo.txt memo-hard.txt

2 つの名前の inode 番号が、同じです。そして、ls -l の 3 番目の列（リンク数）が、1 から 2 に増えました。リンク数とは、「この inode を指している名前の数」です。

これはコピーではありません。中身は 1 つしかなく、名前が 2 つあるだけです。片方の名前で書き換えると、もう片方から見ても変わっています。

片方に書くと、もう片方も変わる⌘↵
echo "たまご" >> memo-hard.txtcat memo.txt

>> は、ファイルの末尾に書き足す記号です（第 5 章）。memo-hard.txt に足した 1 行が、memo.txt にも現れました。どちらが「本物」で、どちらが「リンク」という区別はありません。2 つの名前は対等です。

stat コマンドは、inode の中の情報をまとめて表示します。

stat で inode の情報を見る⌘↵
stat memo.txt

Inode: が inode 番号、Links: がリンク数です。Size: が 55 から 65 に増えているのは、いま書き足した「たまご」と改行のぶんです（日本語の 1 文字は、UTF-8 で 3 バイト）。名前は、File: の行にしか出てきません。名前は inode の中には入っていないからです。

シンボリックリンク：行き先のパスを書いた、小さなファイル

もう 1 つのリンクが、シンボリックリンクです。ln -s 指す先 リンクの名前 で作ります。

シンボリックリンクを作る⌘↵
ln -s memo.txt memo-sym.txtls -li memo*cat memo-sym.txt

memo-sym.txt は、ハードリンクとは違います。

  • inode 番号が別。シンボリックリンクは、それ自身が 1 つの独立したファイル
  • 種類が l で、名前のあとに -> memo.txt と、指す先が表示される
  • 大きさが 8 バイト。これは memo.txt という文字の数。シンボリックリンクの中身は、指す先のパスそのもの
  • memo.txt のリンク数は 2 のまま。シンボリックリンクは、リンク数に数えない

cat memo-sym.txt を実行すると、カーネルは「これはシンボリックリンクだ。中に書いてあるパスへ行き直そう」と、memo.txt を開きます。Windows のショートカットに近いものですが、カーネルが自動でたどるので、どのプログラムからも、ふつうのファイルのように使えます。

元の名前を消すと、違いがわかる

2 種類のリンクの違いは、元の名前を消したときにはっきりします。下の図で先に流れを確かめてから、実行してみましょう。

元の名前を消す⌘↵
rm memo.txtls -li memo*cat memo-hard.txt

memo.txt という名前は消えましたが、中身は memo-hard.txt から読めます。リンク数は 1 に戻りました。rm がしているのは、「ファイルを消す」ことではなく、「名前を 1 つ外す」ことです。中身が本当に消えるのは、リンク数が 0 になったとき、つまり、どの名前からも指されなくなったときです。

シンボリックリンクのほうは、どうでしょうか。

壊れたリンクエラーになる⌘↵
cat memo-sym.txt

memo-sym.txt というファイルは、目の前にあります。それなのに No such file or directory です。ないのは、リンクが指している先の memo.txt です。指す先がなくなったシンボリックリンクを、壊れたリンクと呼びます。

シンボリックリンクは「名前」を覚えているだけなので、同じ名前のファイルがもう一度できれば、また使えるようになります。

同じ名前が戻れば、リンクも直る⌘↵
mv memo-hard.txt memo.txtcat memo-sym.txtrm memo-sym.txt

2 つのリンクを比べる

ハードリンクシンボリックリンク
作り方ln 元 新しい名前ln -s 指す先 リンクの名前
正体同じ inode を指す、もう 1 つの名前指す先のパスを書いた、別のファイル
inode 番号元と同じ元と別
元の名前を消すと中身は残る壊れたリンクになる
ディレクトリに作れない作れる
別のファイルシステムへ作れない作れる
ls -l での見え方ふつうのファイルと同じ（リンク数が増える）l で始まり、-> 指す先 が付く

ハードリンクの 2 つの制限を、確かめておきます。

ハードリンクの制限エラーになる⌘↵
ln notes notes-hardln memo.txt /tmp/memo-hard

1 つ目は、ディレクトリへのハードリンクです。これを許すと、木の中に輪ができて、「上へたどる」ことの意味が壊れてしまうので、禁止されています。2 つ目の /tmp は、/home とは別のファイルシステムです（第 12 章）。inode 番号はファイルシステムごとに付いているので、別のファイルシステムの inode を、番号で指すことはできません。

シンボリックリンクには、どちらの制限もありません。パスを文字で覚えているだけだからです。

ディレクトリへのシンボリックリンク⌘↵
ln -s notes nls -l nls nrm n

実際に使われるのは、ほとんどがシンボリックリンクです。この章の最初に見た /bin -> usr/bin も、そうでした。

深掘り. と .. も、ハードリンク

ディレクトリの ls -l のリンク数を見ると、2 以上になっています。ディレクトリを指す名前は、親ディレクトリの中の名前（notes）と、自分の中の . の 2 つが必ずあるからです。さらに、中にディレクトリを 1 つ作るたびに、その中の .. がこちらを指すので、リンク数が 1 つ増えます。. と .. は、カーネルが自動で作る、ディレクトリへのハードリンクです（人が ln で作ることだけが、禁止されています）。

ls -lid . と ls -lid notes/.. を実行して、inode 番号が同じになることを、実験場で確かめてみてください。

inode の中に何が入っているのか、ディスクの上でどう並んでいるのか、「消す」とは正確には何か。この続きは、第 11 章「ファイルシステムの中身」で扱います。

3.9探す：find

ファイルがどこにあるかわからないときは、find で探します。find 探し始める場所 条件 の形で使い、その場所から下を奥まで全部調べて、条件に合うもののパスを表示します。

条件を付けなければ、全部が出てきます。

find：条件なしなら、全部⌘↵
find .

.（カレントディレクトリ）から下にあるものが、隠しファイルも含めて、すべて表示されました。並ぶ順番は、名前の順ではありません。ディレクトリの中に入っている順です。

よく使う条件は、次の 3 つです。

条件意味
-name 'パターン'名前がパターンに合うもの。ワイルドカードが使える
-type f / -type d / -type lふつうのファイルだけ / ディレクトリだけ / シンボリックリンクだけ
-maxdepth 数何段下まで調べるか。1 なら、その場所の直下だけ
名前と種類で探す⌘↵
find . -name '*.txt'find . -type dfind /etc -name 'host*'

条件を並べると、「すべてに合うもの」になります。

条件を組み合わせる⌘↵
find . -maxdepth 1 -type f -name '*.txt'

ls *.txt との違いは、find が奥のディレクトリまで探すことです。1 つ目の例では、./notes/todo.txt も見つかっています。

注意-name のパターンは、引用符で囲む

find . -name *.txt と、引用符なしで書いてはいけません。第 2 章で見たとおり、*.txt は find に渡る前に、シェルがカレントディレクトリのファイル名に置き換えてしまいます。find に *.txt という文字のまま届けるために、'*.txt' と囲みます。

引用符を忘れた findエラーになる⌘↵
find . -name *.txt

シェルが *.txt を 4 つのファイル名に置き換えたので、find は意味のわからない引数を受け取って、エラーになりました。

読む許可のないディレクトリがあると、find はそこでエラーの文を出して、先へ進みます。

入れないディレクトリがあるときエラーになる⌘↵
find /home -name '*.txt'

/home/bob には入れなかった、と言っています。それ以外の場所の結果は、ちゃんと出ています。エラーの文だけを画面から消す方法（2>/dev/null）は、第 5 章で扱います。

3.10大きさを調べる：du と df

最後に、ディスクの使い方を調べる 2 つのコマンドを、軽く見ておきます。名前が似ていますが、見ているものが違います。

  • du（disk usage）は、ディレクトリやファイルが使っているディスクの量を調べる
  • df（disk free）は、ファイルシステム全体の空きを調べる
du：ディレクトリが使っている量⌘↵
dudu -sh .du -sh /usr/bin

du は、ディレクトリごとに、その下にあるもの全部の合計を表示します。単位は 1 K バイトです。-s（summary）は合計の 1 行だけにし、-h は K や M を付けて読みやすくします。

ここで、ls -l との違いに気づくかもしれません。ls -l では数十バイトだった小さなファイルが、du では 1 つ 4 K バイトとして数えられています。

大きさと、使っているディスクの量⌘↵
ls -l memo.txtdu memo.txt

ディスクは、ブロックという決まった大きさ（ここでは 4 K バイト）の区画に分けて使われます。1 バイトのファイルでも、ブロックを 1 つ使います。ls -l が表示するのは中身のバイト数、du が表示するのは使っているブロックの量です。

df：ファイルシステムの空き⌘↵
df -h

1 行が 1 つのファイルシステムです。/ には 64 M バイトのディスク（/dev/sda1）がつながっていて、そのうち使っているのは 6% ほどです。/tmp と /dev は、別のファイルシステムになっています。「1 本の木」が、実は何枚かのファイルシステムをつなぎ合わせてできていることが、ここに見えています。

「ディスクが一杯で書けない」というときは、まず df -h でどのファイルシステムが一杯かを見て、次に du -sh * で、どのディレクトリが大きいかを探していきます。この調べ方は、第 20 章でもう一度使います。ブロックの仕組みは第 11 章、ファイルシステムをつなぐ仕組みは第 12 章で扱います。

要点この章のまとめ
  • Linux のファイルは、/（ルートディレクトリ）から始まる 1 本の木に並ぶ。/etc は設定、/home はユーザーの場所、/usr/bin はコマンド、/var/log はログ、/tmp は一時ファイル
  • シェルはカレントディレクトリにいる。pwd で表示し、cd で動かす。cd だけでホームへ、cd - で直前の場所へ
  • 絶対パスは / から、相対パスはカレントディレクトリからたどる。. は自分自身、.. は 1 つ上
  • ls -l の 1 行は、種類と権限、リンク数、持ち主、グループ、大きさ、更新時刻、名前。-a で隠しファイル（. で始まる名前）、-d でディレクトリそのもの
  • mkdir（-p で途中も）、touch、cp（ディレクトリは -r）、mv（移動と名前の変更）、rm（ディレクトリは -r）。rm にごみ箱はない
  • 中身を見るのは cat（全部）、head と tail（端だけ）、less（1 画面ずつ）。種類は file で調べる
  • 名前と中身は別のもの。中身と情報は inode にあり、ディレクトリは「名前 → inode 番号」の表。ls -i と stat で見える
  • ハードリンクは同じ inode へのもう 1 つの名前。シンボリックリンクは、指す先のパスを書いた別のファイル。rm は名前を 1 つ外すだけ
  • find 場所 条件 は、奥まで探す。-name のパターンは引用符で囲む
  • du はディレクトリが使っている量、df はファイルシステムの空き

次の第 4 章では、ls -l の rw-r--r-- の部分を読みます。だれがそのファイルを読めて、書けて、実行できるのか。この章で何度か出てきた Permission denied の理由が、そこでわかります。
