第 5 章

テキスト処理とパイプ

プログラムには、入力の口が 1 つ、出力の口が 2 つあります。その行き先をファイルに付け替えるのがリダイレクト、別のプログラムにつなぐのがパイプです。grep、sort、uniq、cut などの小さな道具をつないで、ログや表を集計できるようになります。

5.13 つの口：標準入力・標準出力・標準エラー

第 1 章で、Unix の考え方を見ました。「1 つのことをうまくやる小さなプログラムを、つないで使う」です。この章では、それを自分の手でやります。

つなぐためには、プログラムに「つなぎ口」が要ります。Linux のプログラムは、起動した時点で、はじめから 3 つの口を持っています。

番号名前英語役目何もしないときの相手
0標準入力stdinデータを読む口キーボード
1標準出力stdout結果を書く口画面
2標準エラーstderrエラーや注意を書く口画面

0、1、2 という番号は、ファイルディスクリプタ（fd）と呼ばれるものです。正体は第 9 章で見ます。今は「口の番号」と思ってください。

標準入力から読む

sort は、行を並べ替えるコマンドです。ファイル名を渡さずに起動すると、標準入力、つまりキーボードから読みます。次のブロックでは、キーボードから 3 行を打ったことにしてあります（実験場の端末で試すときは、行を打ち終えたら Ctrl-D で「入力の終わり」を知らせます）。

sort にキーボードから 3 行を渡す入力つき⌘↵
sort

打った 3 行（banana、apple、cherry）が、並べ替えられて出てきました。sort は「ファイルを並べ替えるプログラム」というより、「標準入力から読み、並べ替えて、標準出力に書くプログラム」なのです。

出力の口は 2 つある

出力の口が 2 つあることは、ふだんは気づきません。どちらも画面に出るからです。あるファイルと、ないファイルを、いちどに ls してみます。

結果とエラーが、両方とも画面に出るエラーになる⌘↵
ls fruits.txt nope.txt

2 行が出ました。fruits.txt は標準出力に、ls: cannot access … は標準エラーに書かれています（このサイトの画面では、標準エラーの行に色が付きます）。なぜ 2 つに分けてあるのかは、すぐあとでわかります。

口の行き先を見る

3 つの口がどこにつながっているかは、/proc/self/fd で見えます。/proc/self は「このコマンド自身のプロセス」を指す特別なディレクトリです。

3 つの口の行き先⌘↵
ls -l /proc/self/fd

0、1、2 が、どれも /dev/pts/0 を指しています。/dev/pts/0 は、あなたの端末を表すファイルです。キーボードも画面も、プログラムからは 1 つの「端末」というファイルに見えます。（3 は、ls がこのディレクトリ自身を読むために開いたものです。気にしなくてかまいません。）

5.2リダイレクト：口の行き先をファイルにする

口の行き先は、付け替えられます。これをリダイレクトと呼びます。付け替えるのはシェルの仕事で、プログラムのほうは何も知りません。

> で、標準出力をファイルへ

コマンドのあとに > ファイル名 と書くと、標準出力の行き先がそのファイルになります。

> で出力をファイルに入れる⌘↵
echo "1 行目" > out.txtcat out.txtls -l /proc/self/fd > fd.txtcat fd.txt

echo の出力は画面に出ず、out.txt に入りました。後半は、さっきの ls -l /proc/self/fd の出力を fd.txt に入れて、あとから見ています。1 の行き先が /home/you/fd.txt に変わっています。ls 自身は、いつもどおり 1 番の口に書いただけです。

> は、ファイルがなければ作り、あれば中身を空にしてから書きます。前の中身は消えます。

> は上書き、>> は追記⌘↵
echo "上書きした" > out.txtcat out.txtecho "2 行目" >> out.txtecho "3 行目" >> out.txtcat out.txt

>> は、ファイルの末尾に足します。ログのように、書き足していくものに使います。

注意読んでいるファイルに > で書かない

sort numbers.txt > numbers.txt のように、入力と同じファイルに > で書いてはいけません。シェルは、sort を起動する前に > のファイルを空にします。sort が読み始めたときには、もう中身がありません。

入力と同じファイルに書くと、空になる⌘↵
cp numbers.txt n.txtsort n.txt > n.txtwc -c n.txt

n.txt は 0 バイトになりました。結果は別の名前のファイルに書き、あとで mv します。

< で、標準入力をファイルから

< ファイル名 は、標準入力の相手をキーボードからファイルに替えます。

< でファイルを標準入力にする⌘↵
sort < numbers.txtwc -l < fruits.txtwc -l fruits.txt

wc -l は行の数を数えます。最後の 2 つの違いを見てください。wc -l fruits.txt は、ファイル名を引数で受け取ったので、名前も一緒に表示します。wc -l < fruits.txt は、数だけです。wc は標準入力から読んでいるだけで、その先がどのファイルなのかを知らないからです。

< と > は一緒に使えます。

入力も出力もファイルにする⌘↵
sort -n < numbers.txt > sorted.txtcat sorted.txt

-n は「数として並べる」オプションです（あとの節で扱います）。

5.3標準エラーを分ける

> が付け替えるのは、1 番の口（標準出力）だけです。2 番の口は、そのままです。

> では、エラーはファイルに入らないエラーになる⌘↵
ls fruits.txt nope.txt > list.txtcat list.txt

エラーの知らせは画面に出て、list.txt には fruits.txt だけが入りました。これが、口を 2 つに分けてある理由です。結果をファイルやほかのプログラムに送っても、エラーは人の目に届きます。結果のデータにエラーの文が混ざることもありません。

2> で、標準エラーをファイルへ

2 番の口を付け替えるには、> の前に番号を付けて 2> と書きます（> は 1> の略です）。

結果とエラーを別のファイルにエラーになる⌘↵
ls fruits.txt nope.txt > list.txt 2> err.txtcat list.txtcat err.txt

今度は、画面には何も出ません。2>> と書けば追記になります。

/dev/null：何でも捨てる

エラーの知らせが要らないときは、/dev/null に送ります。/dev/null は、書かれたものを全部捨てる特別なファイルです（第 12 章）。

エラーを捨てるエラーになる⌘↵
ls fruits.txt nope.txt 2> /dev/null

画面に出るのは結果だけになりました。逆に > /dev/null と書けば、結果を捨ててエラーだけを見られます。

2>&1：標準エラーを、標準出力と同じところへ

結果とエラーを同じファイルに入れたいときは、2>&1 と書きます。「2 番の口を、いま 1 番の口が向いているところへ向ける」という意味です。

両方を 1 つのファイルにエラーになる⌘↵
ls fruits.txt nope.txt > all.txt 2>&1cat all.txt

2>&1 は、書く順番が大事です。シェルは、リダイレクトを左から順に処理します。

順番を逆にすると、エラーは画面に出るエラーになる⌘↵
ls fruits.txt nope.txt 2>&1 > all2.txtcat all2.txt

all2.txt に入ったのは fruits.txt だけで、エラーは画面に出ました。図の最後の段階のとおりです。

リダイレクトの書き方を、まとめておきます。

書き方意味
> file標準出力を file へ（上書き）
>> file標準出力を file へ（追記）
< file標準入力を file から
2> file標準エラーを file へ
2>&1標準エラーを、標準出力と同じところへ
> file 2>&1両方を file へ（bash では &> file とも書ける）
2> /dev/nullエラーを捨てる
深掘りsudo とリダイレクト

sudo echo "…" > /etc/motd は、Permission denied になります。> のファイルを開くのは sudo や echo ではなく、あなたのシェルだからです。シェルは root ではないので、/etc の下に書けません。root の権限でファイルに書きたいときは、あとで出てくる tee を使って echo "…" | sudo tee /etc/motd と書きます。

5.4パイプ：プログラムとプログラムをつなぐ

リダイレクトは、口の相手をファイルにしました。パイプは、口の相手を別のプログラムにします。A | B と書くと、A の標準出力が、B の標準入力につながります。

最初のパイプ⌘↵
ls /usr/bin | wc -l

ls /usr/bin の出力（コマンドの名前が 1 行に 1 つ）が、画面ではなく wc -l に流れ込み、wc -l が行を数えました。出てきた数が、このサイトの Linux の /usr/bin にあるコマンドの個数です。

パイプなしで同じことをするには、途中の結果をいったんファイルに置くことになります。

パイプを使わないと⌘↵
ls /usr/bin > tmp.txtwc -l < tmp.txtrm tmp.txt

パイプは、この「いったん置くファイル」をなくします。そして、ただの省略ではありません。次の図のとおり、2 つのプログラムは同時に動きます。

口の行き先を、さっきと同じ方法で確かめます。

パイプにつながった口⌘↵
ls -l /proc/self/fd | cat

1 の行き先が、pipe:[…] になりました。ls の標準出力は、端末ではなくパイプにつながっています。2 は端末のままです。

2 つのプロセスは、同時にいる

パイプでつないだコマンドが同時に動いていることを、ps で見ます。sleep 1 は、1 秒待つだけのコマンドです。2 つの sleep と ps をパイプでつなぎます（データは何も流れませんが、つなぐことはできます）。

パイプの 3 つのプロセスを ps で見る⌘↵
sleep 1 | sleep 1 | ps -o pid,ppid,stat,args

ps が表示した時点で、2 つの sleep が両方とも存在しています。「1 つ目が終わってから 2 つ目を起動する」のではありません。3 つとも、親（PPID）は同じシェル（PID 2）です。シェルは、パイプでつないだコマンドを全部いっぺんに起動して、全部が終わるのを待ちます。

同時に動くので、上流のプログラムが出力を全部作り終える必要はありません。yes は、止められるまで y を出し続けるコマンドです。

終わらないプログラムも、つなげる⌘↵
yes | head -n 3

head -n 3 は、3 行読んだところで終わります。読み手がいなくなったので、yes も止まります（止まる仕組みは、第 8 章のシグナルで説明します）。

標準エラーはパイプを通らない

図のとおり、パイプにつながるのは 1 番の口だけです。

エラーはパイプに入らない⌘↵
ls nope.txt | wc -l

エラーの知らせは画面に出て、wc -l には何も届かなかったので、0 と数えました。エラーもパイプに流したいときは、2>&1 で 1 番の口に合わせます。

エラーもパイプに流す⌘↵
ls nope.txt 2>&1 | wc -l

今度は、エラーの 1 行が wc -l に届いて、1 になりました。

メモパイプの正体は第 9 章で

シェルがパイプを作って、2 つのプロセスの口につなぐ手順（pipe、fork、dup2 というシステムコール）は、第 9 章で strace を使って見ます。

5.5フィルタという考え方：cat、wc、head、tail

「標準入力から読み、加工して、標準出力に書く」プログラムを、フィルタと呼びます。フィルタは、前に何がつながっているか、後ろに何がつながっているかを知りません。だから、どんな順番にでもつなげます。

フィルタの多くは、ファイル名を引数に渡すとそのファイルを読み、渡さなければ標準入力を読みます。次の 3 つは、どれも同じ結果になります。

同じ結果になる 3 つの書き方⌘↵
wc -l fruits.txtwc -l < fruits.txtcat fruits.txt | wc -l

cat は、ファイルの中身をそのまま標準出力に流します。パイプの「蛇口」としてよく使います。

この節と次の節で使う練習用のファイルは、3 つです。fruits.txt（果物の名前が 9 行）、poem.txt（英語の 5 行）、scores.csv（試験の点数）です。

練習用のファイル⌘↵
cat poem.txtcat scores.csv

wc：数える

wc（word count）は、行・単語・バイトの数を数えます。

wc⌘↵
wc poem.txtwc -l poem.txtwc -w poem.txtwc -c memo.txtwc -m memo.txt

オプションなしでは、行数（5）、単語数（25）、バイト数（127）を並べます。-l は行だけ、-w は単語だけ、-c はバイトだけです。-m は文字数です。日本語の入った memo.txt は、55 バイトで 25 文字です。日本語の 1 文字は、UTF-8 で 3 バイトになるからです。

head と tail：先頭と末尾

head と tail⌘↵
head -n 2 poem.txttail -n 2 poem.txttail -n +2 scores.csv

head -n 2 は先頭の 2 行、tail -n 2 は末尾の 2 行です。tail -n +2 のように + を付けると、「2 行目から最後まで」になります。CSV の見出しの行を取り除くのに便利です。

組み合わせると、「3 行目だけ」も取り出せます。

3 行目だけを取り出す⌘↵
head -n 3 poem.txt | tail -n 1

5.6grep：行を選ぶ

grep は、パターンに合う行だけを通すフィルタです。

grep⌘↵
grep fox poem.txtgrep -i the poem.txt

grep fox は、fox を含む行だけを出します。grep は大文字と小文字を区別するので、grep the では The で始まる行は選ばれません。-i（ignore case）を付けると、区別しなくなります。

よく使うオプションです。

オプション意味
-i大文字と小文字を区別しない
-v合わない行を出す（反転）
-c合う行の数だけを出す
-n行番号を付ける
-E拡張正規表現を使う（`、+、( )` など）
grep のオプション⌘↵
grep -n fox poem.txtgrep -c apple fruits.txtgrep -v apple fruits.txt

-c は、grep apple fruits.txt | wc -l と同じ数になります。-v は、apple でない行だけを出します。

正規表現を少しだけ

grep のパターンは、正規表現です。文字の並びの「型」を書けます。まず覚えるのは、次の 4 つで十分です。

書き方意味例
^行のはじめ^The：The で始まる行
$行の終わりfox$：fox で終わる行
.何か 1 文字b.g：big、bag、bug …
`AB（-E` が要る）A または B`foxdog`
正規表現⌘↵
grep '^The' poem.txtgrep 'fox$' poem.txtgrep -E 'fox|dog' poem.txtgrep ',math,' scores.csv

パターンは、'…'（シングルクォート）で囲む習慣を付けてください。$ や | や * は、シェルにとっても特別な文字です。囲んでおけば、シェルは手を付けずに、そのまま grep に渡します（引用符は第 6 章で詳しく扱います）。

パイプの途中に入れれば、どんなコマンドの出力も絞り込めます。

コマンドの出力を絞り込む⌘↵
ls /usr/bin | grep '^s' | head -n 5ls /usr/bin | grep -c '^s'

5.7sort と uniq：並べて、数える

sort：行を並べ替える

sort は文字の順に並べる⌘↵
sort fruits.txtsort numbers.txt

sort は、行を文字の順（辞書の順）に並べます。2 つ目の結果を見てください。10、100、23、42、5 … と並んでいます。文字として比べると、1 で始まる 100 は、2 で始まる 23 より前に来るからです。数として並べるには、-n（numeric）を付けます。

-n で数として、-r で逆順に⌘↵
sort -n numbers.txtsort -rn numbers.txt | head -n 3

-r（reverse）は逆順です。sort -rn | head -n 3 は、「大きいほうから 3 つ」という決まり文句です。

オプション意味
-n数として比べる
-r逆順にする
-k NN 番目の欄で比べる
-t 文字欄の区切りの文字（指定しなければ空白）
-u同じ行は 1 つにまとめる

scores.csv を、3 番目の欄（点数）の大きい順に並べます。区切りは , です。見出しの行は、tail -n +2 で先に取り除いておきます。

CSV を点数の順に並べる⌘↵
tail -n +2 scores.csv | sort -t, -k3 -n -r

uniq：隣り合った同じ行をまとめる

uniq は、隣り合った同じ行を 1 行にまとめます。

uniq は、隣り合っていないとまとめない⌘↵
uniq fruits.txt | head -n 4sort fruits.txt | uniq

fruits.txt には apple が 3 回出てきますが、離れた行にあるので、そのまま uniq に通しても減りません（1 つ目。先頭の 4 行に apple が 2 回残っています）。先に sort して同じ行を隣り合わせにすると、6 種類にまとまります。uniq の前には sort。これは対で覚えます。（重複を取るだけなら、sort -u でも同じ結果になります。）

uniq -c（count）は、まとめた行の数を先頭に付けます。

数えて、多い順に並べる⌘↵
sort fruits.txt | uniq -csort fruits.txt | uniq -c | sort -rnsort fruits.txt | uniq -c | sort -rn | head -n 2

sort | uniq -c | sort -rn は、「何が何回出てくるかを、多い順に」という集計の定番です。第 1 章で 1 度見た形です。データの流れを、1 段ずつ追ってみてください。

  1. sort：同じ名前を隣り合わせにする
  2. uniq -c：隣り合った同じ行を 1 つにまとめ、回数を先頭に付ける
  3. sort -rn：先頭の回数で、大きい順に並べ直す
  4. head -n 2：上位の 2 つだけを残す

パイプラインを書くときは、いきなり全部を書かずに、左から 1 段ずつ足して、そのつど出力を見るのがコツです。

5.8cut、tr、sed：行の中を加工する

grep や sort は、行をまるごと扱いました。ここからは、行の中身を変えるフィルタです。

cut：欄を切り出す

cut は、各行から決まった欄だけを切り出します。-d で区切りの文字、-f で欄の番号を指定します。

cut⌘↵
cut -d, -f1 scores.csvcut -d, -f1,3 scores.csv | head -n 3cut -d: -f1,7 /etc/passwd

-f1,3 のように、いくつも指定できます。3 つ目の例は、第 4 章で読んだ /etc/passwd（: 区切り）から、ユーザー名とシェルだけを取り出しています。

cut と前の節の道具を合わせると、「科目ごとの行の数」が出せます。

科目ごとに数える⌘↵
tail -n +2 scores.csv | cut -d, -f2 | sort | uniq -c

tr：文字を置き換える

tr（translate）は、文字を 1 文字ずつ置き換えます。tr はファイル名を引数に取れないので、いつも標準入力から読ませます。

tr⌘↵
tr a-z A-Z < fruits.txt | head -n 2tr , ' ' < scores.csv | head -n 2tr -d aeiou < fruits.txt | head -n 2echo "a   b    c" | tr -s ' '

1 つ目は小文字を大文字に、2 つ目は , を空白に置き換えています。-d（delete）は、その文字を消します。-s（squeeze）は、同じ文字の続きを 1 つに縮めます。

tr で空白を改行に置き換えると、文章が「1 行に 1 単語」になります。あとは、いつもの定番です。

どの単語が何回出てくるか⌘↵
tr A-Z a-z < poem.txt | tr -d . | tr ' ' '\n' | sort | uniq -c | sort -rn | head -n 3

大文字を小文字にそろえ、ピリオドを消し、空白を改行に替えてから、数えて多い順に並べました。the と a が 3 回、fox が 2 回です。

sed：文字列を置き換える

sed（stream editor）は多機能ですが、まず使うのは s/古い/新しい/ の置き換えです。

sed の s⌘↵
sed 's/apple/りんご/' fruits.txt | head -n 4echo "banana" | sed 's/a/A/'echo "banana" | sed 's/a/A/g'

s/a/A/ は、各行で最初に見つかった 1 つだけを置き換えます。最後に g（global）を付けると、行の中の全部を置き換えます。「古い」のほうには、grep と同じ正規表現が書けます。

sed でできる、ほかのこと⌘↵
sed 's/,/ /g' scores.csv | head -n 2sed -n '2,3p' poem.txtsed '1d' scores.csv | head -n 2

sed -n '2,3p' は 2〜3 行目だけを表示し、sed '1d' は 1 行目を消します（tail -n +2 と同じ結果です）。

メモsed はファイルを書き換えない

sed も、ほかのフィルタと同じく、結果を標準出力に書くだけです。元のファイルは変わりません。本物の GNU の sed には、ファイルを直接書き換える -i オプションがありますが、このサイトの sed にはありません。結果を残したいときは、sed '…' file > new.txt のように、別のファイルにリダイレクトします。

5.9tee と xargs：流れを分ける、引数に変える

tee：ファイルに書きながら、先へも流す

長いパイプラインの途中の結果を、ファイルにも残したいことがあります。tee は、標準入力をファイルと標準出力の両方に書きます。配管の T 字の分かれ道（T）が名前の由来です。

tee で途中の結果を残す⌘↵
sort fruits.txt | tee sorted-fruits.txt | uniq -c | sort -rn | head -n 2wc -l sorted-fruits.txt

集計の結果は画面に出て、途中の「並べ替えた 9 行」は sorted-fruits.txt に残りました。tee -a とすると、上書きではなく追記になります。

xargs：標準入力を、引数に変える

パイプが渡すのは、標準入力です。ところが、標準入力を読まず、引数でしか相手を受け取らないコマンドもあります（rm、ls、echo など）。xargs は、標準入力から読んだ言葉を、別のコマンドの引数に並べて実行します。

xargs⌘↵
cat fruits.txt | xargscat fruits.txt | xargs -n 3

実行するコマンドを書かなければ、echo が使われます。9 行の入力が、echo apple banana cherry … という 1 回の実行になりました。-n 3 は、「引数 3 つごとに 1 回実行する」です。

find（第 3 章）で探したファイルを、別のコマンドに渡すのがよくある使い方です。

find で探したファイルに、まとめて grep をかける⌘↵
find notes -name '*.txt'find notes -name '*.txt' | xargs grep -c 'パイプ'

find が出した 2 つのファイル名が、grep -c 'パイプ' notes/todo.txt notes/ideas.txt の形の引数になりました。

パイプと xargs の違いを、1 つの例で確かめておきます。

標準入力として渡すか、引数として渡すか⌘↵
echo poem.txt | wc -lecho poem.txt | xargs wc -l

1 つ目の wc -l は、「poem.txt」という 1 行の文字列を数えたので 1 です。2 つ目は、wc -l poem.txt が実行されて、ファイルの行数の 5 が出ました。

メモpaste と awk

列を横に並べる paste（paste -sd+ numbers.txt で 10+5+23+… のように 1 行につなぐ）と、欄ごとの計算ができる awk も、テキスト処理でよく使う道具です。どちらも、このサイトの Linux にはまだ入っていないので、付録で紹介します。この章の道具だけでは、「欄の合計を出す」ような計算はできません。合計は、第 6 章のシェルスクリプトで計算します。

5.10実例：アクセスログを集計する

ここまでの道具で、本物の仕事をしてみます。/var/log/access.log は、Web サーバのアクセスログ（だれが、いつ、何を要求したかの記録）です。

アクセスログ⌘↵
wc -l /var/log/access.loghead -n 3 /var/log/access.log

12 行あります。1 行が 1 回のアクセスです。空白で区切って、欄に番号を付けてみます。

1 番目が相手の IP アドレス、7 番目が要求されたパス、9 番目が結果を表す番号（ステータスコード。200 は成功、404 は「見つからない」）、10 番目が返したバイト数です。

アクセスの多い IP アドレスの上位 3 つ

1 番目の欄を切り出して、定番の集計にかけます。1 段ずつ組み立てましょう。

1 段目：IP アドレスだけを切り出す⌘↵
cut -d' ' -f1 /var/log/access.log | head -n 4
2 段目：数える⌘↵
cut -d' ' -f1 /var/log/access.log | sort | uniq -c
3 段目：多い順に並べて、上位 3 つ⌘↵
cut -d' ' -f1 /var/log/access.log | sort | uniq -c | sort -rn | head -n 3

192.168.1.10 が 5 回で、いちばん多いことがわかりました。専用の「アクセス解析プログラム」は、どこにもありません。4 つの小さな道具をつないだだけです。

結果の番号ごとの件数

欄の番号を 9 に替えるだけで、別の集計になります。

ステータスコードごとの件数⌘↵
cut -d' ' -f9 /var/log/access.log | sort | uniq -c | sort -rn

成功（200）が 8 件、「見つからない」（404）が 2 件です。

失敗したアクセスを調べる

404 になったのは、どのパスへの、だれからのアクセスでしょうか。grep で行を選んでから、欄を切り出します。

404 になったアクセス⌘↵
grep ' 404 ' /var/log/access.log | cut -d' ' -f1,7

パターンを ' 404 ' と、前後に空白を付けて書いたのは、ほかの欄（時刻やバイト数）にたまたま 404 という数字が出てきても、選ばないようにするためです。

いちばん大きい応答

10 番目の欄（バイト数）で並べ替えれば、いちばん大きなファイルを返したアクセスがわかります。sort は、区切りを指定しなければ空白で欄を分けます。

バイト数のいちばん大きいアクセス⌘↵
sort -k10 -n -r /var/log/access.log | head -n 1 | cut -d' ' -f7,10

/logo.png の 20480 バイトでした。

コツパイプラインの組み立て方
  1. まず head で、データの形を見る。区切りは何か、ほしい欄は何番目か
  2. 行を選ぶ（grep）→ 欄を切り出す（cut）→ 並べる（sort）→ まとめて数える（uniq -c）→ 並べ直す（sort -rn）→ 上位だけ残す（head）の順に考える
  3. 左から 1 段ずつ足して、そのつど出力を確かめる
要点この章のまとめ
  • プログラムは、はじめから 3 つの口を持つ。標準入力（0）、標準出力（1）、標準エラー（2）。何もしなければ、3 つとも端末につながっている
  • リダイレクトは、口の行き先をファイルに付け替える。>（上書き）、>>（追記）、<（入力）、2>（エラー）、2>&1（エラーを標準出力と同じところへ）。付け替えるのはシェルで、左から順に処理される。捨てるなら /dev/null
  • パイプ A | B は、A の標準出力を B の標準入力につなぐ。A と B は同時に動く。標準エラーはパイプを通らない
  • 標準入力から読んで標準出力に書くプログラムがフィルタ。行を選ぶ grep、並べる sort、まとめて数える uniq -c、欄を切り出す cut、文字を置き換える tr、文字列を置き換える sed、数える wc、先頭と末尾の head と tail
  • uniq の前には sort。sort | uniq -c | sort -rn | head が、「何が何回、多い順に」の定番
  • tee は流れをファイルにも残す。xargs は標準入力を引数に変える
  • パイプラインは、左から 1 段ずつ足して、出力を確かめながら組み立てる

5.11確認問題

この章の道具をつないで、自分で集計します。採点は、コマンドの標準出力（1 問目は、できたファイルの中身）を比べて行います。データを少し変えた状態でも確かめるので、答えの数字や名前を echo で直接書いても正解になりません。

問 1

結果とエラーを別のファイルに分ける

正解済み

ls /etc/hostname /etc/nope を実行して、標準出力を ok.txt に、標準エラーを ng.txt に入れてください。画面には何も出ないようにします。

# ここにコマンドを書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵実行した後の状態（下の「確かめ方」のコマンドの出力）で判定
ヒント

標準出力は >、標準エラーは 2> で、それぞれ別のファイルを指定します。

確かめ方

あなたのコマンドを実行した後に、root でこのコマンドを実行して、その出力を模範解答のときと比べます。

echo "[ok.txt]"; cat /home/you/ok.txtecho "[ng.txt]"; cat /home/you/ng.txt
模範解答
ls /etc/hostname /etc/nope > ok.txt 2> ng.txt
問 2

math の最高点はだれか

正解済み

scores.csv から、科目が math の行のうち、点数（3 番目の欄）がいちばん高い人の名前だけを表示してください。

# ここにコマンドを書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵標準出力で判定（行の順番も見る）
ヒント

4 段で書けます。math の行を選ぶ（grep）→ 点数の大きい順に並べる（sort -t, -k3 -n -r）→ 先頭の 1 行（head）→ 名前の欄（cut）。点数は、数として比べることを忘れずに。

模範解答
grep ',math,' scores.csv | sort -t, -k3 -n -r | head -n 1 | cut -d, -f1
問 3

404 を受け取った IP アドレスは何種類か

正解済み

/var/log/access.log で、ステータスコード（9 番目の欄）が 404 だったアクセスについて、相手の IP アドレスが何種類あるかを、数だけ表示してください。同じ IP アドレスが何回 404 になっても、1 種類と数えます。

# ここにコマンドを書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵標準出力で判定（行の順番も見る）
ヒント

404 の行を選ぶ → IP アドレスの欄を切り出す → 重複を取り除く（sort -u か sort | uniq）→ 行を数える。grep のパターンは、ほかの欄の数字に当たらないように ' 404 ' と空白で挟みます。

模範解答
grep ' 404 ' /var/log/access.log | cut -d' ' -f1 | sort -u | wc -l
問 4

いちばん多く要求されたパス

正解済み

/var/log/access.log で、いちばん多く要求されたパス（7 番目の欄）を 1 つ、パスだけ表示してください（回数は表示しません）。

# ここにコマンドを書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵標準出力で判定（行の順番も見る）
ヒント

sort | uniq -c | sort -rn | head -n 1 までは定番です。その出力は 4 /index.html のように、先頭に空白と回数が付いています。tr -s ' ' で空白の続きを 1 つに縮めてから cut -d' ' で切り出すか、sed 's/^ *[0-9]* //' で先頭の空白と数字を消します。

模範解答
cut -d' ' -f7 /var/log/access.log | sort | uniq -c | sort -rn | head -n 1 | tr -s ' ' | cut -d' ' -f3
