第 16 章

ネットワークとソケット

別のプログラムと、ときには別の機械の上のプログラムと話すための入口が、ソケットです。ソケットもファイルディスクリプタで、read と write で読み書きします。nc でサーバとクライアントを自分で動かし、TCP がつながるまでのパケットを 1 個ずつ見て、ss で接続の状態を追い、最後に HTTP を手で話します。

16.1ソケット：プログラムどうしをつなぐ fd

第 9 章のパイプは、2 つのプロセスをつなぎました。ただし、パイプでつなげるのは、同じシェルから生まれた親子や兄弟だけです。作るときに、両端の fd を fork で受け継ぐ必要があるからです。

Web ブラウザと Web サーバは、親子ではありません。別々に起動され、たいていは別の機械の上にいます。こういう赤の他人のプログラムどうしをつなぐ仕組みが、ソケット（socket。差し込み口）です。

  • つなぐ相手は、番地（アドレス）で指名する。親子でなくてよい
  • 相手は、同じ機械の上でも、ネットワークの向こうでもよい
  • パイプは一方通行だが、ソケットは両方向。1 つの fd で、読むことも書くこともできる
  • つながった後は、ふつうの fd。read と write と close で扱う

この章で扱うのは、インターネットでいちばんよく使われる TCP のソケットです。TCP は、「送った順に、欠けずに、相手に届く」ことを約束する通信の決まり（プロトコル）です。Web、メール、SSH は、みな TCP の上で動いています。

メモこの Linux のネットワーク

この小さな Linux は、外の世界とつながっていません。話せる相手は、自分自身だけです。それでも、ソケットの作り方、接続の手順、状態の移り変わりは、本物と同じです。外のネットワークの話は、章の最後に図でまとめます。

16.2IP アドレスとポート

ソケットの番地は、2 つの数の組です。IP アドレス（どの機械か）と、ポート番号（その機械の中の、どの窓口か）です。

IP アドレス：機械の番地

機械が持っている IP アドレスは、ip addr で見られます。

この機械の IP アドレス⌘↵
ip addr

2 つのインターフェース（ネットワークへの出入口）があります。inet の行が IP アドレスです。

名前アドレス何か
lo127.0.0.1ループバック。自分自身につながる、仮想の出入口
eth0192.168.1.5ネットワークカード。外につながる出入口（この Linux では、先に何もない）

IP アドレス（IPv4）は 32 ビットの数で、8 ビットずつ 4 つに区切って、10 進数で書きます。/8 や /24 は、先頭の何ビットが「同じネットワーク」を表すかです。

127.0.0.1 は、どの機械でも「自分自身」を指す特別なアドレスです。ここに送ったデータは、ネットワークカードを通らず、カーネルの中で折り返して戻ってきます。開発中のサーバを自分の機械だけで試すときに使います。

ポート：機械の中の窓口

1 つの機械の上で、Web サーバも、メールサーバも、データベースも動きます。IP アドレスだけでは、どのプログラムあてなのか決まりません。そこで、0 から 65535 までのポート番号で区別します。IP アドレスが建物の住所なら、ポートは部屋番号です。

よく使われるサービスには、決まったポート番号があります。その一覧が /etc/services です。

サービス名とポート番号の対応⌘↵
cat /etc/services

HTTP は 80、HTTPS は 443、SSH は 22 です。ブラウザで http://example.com/ を開くと、ブラウザは example.com の機械の 80 番に接続します。名前から番号を引くには、getent services が使えます。

名前から番号を、番号から名前を引く⌘↵
getent services sshgetent services 5432

1024 未満のポートで待ち受けられるのは、root だけです。ふつうのユーザーが 80 番で待ち受けようとすると、断られます。

80 番は、root でないと使えないエラーになる⌘↵
nc -l -p 80

Permission denied（EACCES）です。昔、「22 番や 80 番で答えているのは、その機械の管理者が動かしたプログラムだ」と信用できるようにした名残りです。自分で試すサーバには、1024 以上の番号（8080、3000、5000 など）を使います。

16.3nc：サーバとクライアントを動かす

ソケットを使うプログラムには、2 つの役があります。

  • サーバ：決まったポートで、接続が来るのを待ち受ける
  • クライアント：サーバの番地を指定して、接続しに行く

nc（netcat）は、ソケットをそのまま扱う小さなコマンドで、どちらの役にもなれます。cat がファイルと標準入出力をつなぐように、nc はソケットと標準入出力をつなぎます。

まず、サーバです。-l（listen）で待ち受け、-p でポートを指定します。受け取ったものは標準出力に出るので、got.txt に入れます。接続が来るまで終わらないので、& をつけてバックグラウンドで動かします。

5000 番で待ち受ける⌘↵
nc -l -p 5000 > got.txt &ss -tlnp

ss（socket statistics）は、ソケットの一覧を出すコマンドです。-t は TCP、-l は待ち受け中のもの、-n は番号を名前に直さない、-p は使っているプロセスを表示、です。

State が LISTEN、Local Address:Port が 0.0.0.0:5000 です。0.0.0.0 は、「この機械のどのアドレスあてでも受ける」という意味です。右端に、nc の PID と、ソケットの fd 番号（fd=3）が出ています。

ソケットが fd であることを、/proc で確かめます。

サーバの fd 表⌘↵
ls -l /proc/$!/fd

fd 1 は、リダイレクトした got.txt。そして fd 3 が socket:[…] です。ファイルやパイプと同じ表に、ソケットが並んでいます。

次に、クライアントです。相手の IP アドレスとポートを指定します。標準入力から読んだものを、ソケットに送ります。

クライアントからつないで、1 行送る⌘↵
echo "こんにちは、サーバ" | nc -N 127.0.0.1 5000cat got.txt

サーバの nc が終わり、got.txt に、送った 1 行が入りました。2 つの nc は親子ではなく、パイプもありません。番地 127.0.0.1:5000 だけを頼りに、つながりました。

注意-N を忘れると、終わらない

クライアントの -N は、「標準入力が終わったら、ソケットの書く側も閉じる」というオプションです。これがないと、nc は「相手からまだ何か来るかもしれない」と待ち続け、サーバも「まだ何か送ってくるかもしれない」と待ち続けます。両方が相手を待って、どちらも終わりません。echo … | nc の形で使うときは、-N をつけてください。

16.4socket・bind・listen・accept・connect

nc の裏側で、どんなシステムコールが呼ばれているかを見ます。ソケットのためのシステムコールは、5 つ覚えれば足ります。

システムコールだれが何をするか
socket()両方ソケットを作って、fd をもらう。まだどこにもつながっていない
bind(fd, 番地)サーバソケットに、自分の番地（IP アドレスとポート）をつける
listen(fd, n)サーバ待ち受けを始める。n は、待たせておける接続の数
accept(fd)サーバ接続が来るまで待ち、来たら、その接続のための新しい fd を返す
connect(fd, 番地)クライアント相手の番地に接続する

サーバのほうは、strace -o で記録をファイルに取りながら動かします。

サーバを strace つきで動かし、クライアントからつなぐ⌘↵
strace -o server.txt nc -l -p 5001 > got.txt &echo "hello again" | nc -N 127.0.0.1 5001waitcat server.txt

上から読みます。

  1. socket(AF_INET, SOCK_STREAM, …) = 3：ソケットを作った。AF_INET は IPv4、SOCK_STREAM は TCP。fd は 3
  2. bind(3, {… sin_port=htons(5001), sin_addr=inet_addr("0.0.0.0")} …)：5001 番をつけた
  3. listen(3, 1)：待ち受けを始めた
  4. accept(3, {… sin_port=htons(32769), sin_addr=inet_addr("127.0.0.1")} …) = 4：接続が来た。相手は 127.0.0.1 の 32769 番。新しい fd 4 が返った
  5. close(3)：待ち受け用のソケットを閉じた（nc は 1 人だけ相手にする）
  6. read(4, "hello again\n", …)、write(1, …)：fd 4 から読んで、標準出力へ
  7. read(4, "", …) = 0：相手が閉じた（ファイルの終わりと同じ、0）
  8. close(4)

あいだにある poll は、「どの fd が読めるようになったか」を待つシステムコールです。nc は、ソケットと自分の標準入力の両方を見張っています。

大事なのは accept です。待ち受け用のソケット（fd 3）と、実際に話すためのソケット（fd 4）は、別物です。待ち受け用のソケットは、電話の代表番号のようなものです。そこにかかってきた 1 件ごとに、専用の回線（新しい fd）が作られます。ふつうのサーバは fd 3 を閉じずに、accept をくり返し呼んで、何人もの相手を同時に受け持ちます。

クライアントのほうは、もっと単純です。

クライアントのシステムコールstrace：システムコールも表示⌘↵
nc -l -p 5002 > /dev/null &echo hi | nc -N 127.0.0.1 5002

2 つ目のコマンドの列を見てください。socket で作り、connect で相手の番地（127.0.0.1 の 5002 番）につなぐだけです。bind は呼んでいません。クライアントのポート番号は、カーネルが空いている番号（32768 以降）を自動で選びます。さっきの accept に出ていた 32769 が、それです。その後は write(3, "hi\n", 3) で送り、shutdown(3, SHUT_WR)（-N の働き。「もう送らない」と伝える）、read(3, "", …) = 0 で相手が閉じたのを知って終わります。

16.5TCP の 3 ウェイハンドシェイク

connect が呼ばれてから accept が戻るまでのあいだに、カーネルどうしは何をしているのでしょうか。

ネットワークを流れるデータは、パケットという小さな包みに分けて運ばれます。TCP は、データを送る前に、まず 3 個のパケットをやりとりして、「つながった」ことを両方で確かめます。これが 3 ウェイハンドシェイク（3 回の握手）です。

パケットには、フラグという印がついています。

フラグ意味
SYN接続を始めたい（synchronize。番号を合わせる）
ACK受け取った（acknowledge）。ack の番号は、「次は、この番号から送ってほしい」
PSHデータが入っている。すぐプログラムに渡してほしい
FINこちらからは、もう送らない（finish）
RSTこの接続は成り立たない。打ち切る（reset）

TCP は、送るバイトに通し番号（シーケンス番号、seq）をつけます。受け取った側は、「何番まで受け取ったか」を ack で返します。パケットが途中でなくなっても、ack が返ってこなければ気づいて、送り直せます。順番が入れ替わって届いても、番号で並べ直せます。「順番どおり、欠けずに届く」という TCP の約束は、この番号で守られています。握手の目的は、お互いの最初の番号を教え合うことです。

実際のパケットを見ます。サーバを用意してから、クライアントでつなぎます。

つないで、3 バイト送って、閉じるネットワークを観察⌘↵
nc -l -p 5003 > /dev/null &echo hi | nc -N 127.0.0.1 5003

2 つ目のコマンドの「ネットワークの観察」のうち、pkt がパケットです。flags を上から追うと、SYN、SYN,ACK、ACK、PSH,ACK（len 3、data が hi）、ACK、FIN,ACK、ACK、FIN,ACK、ACK の 9 個です。たった 3 バイトを送るのに、9 個のパケットが飛びました。rseq と rack が、図に書いた相対的な番号です。seq の欄の大きな数が、実際の番号です。最初の番号は、接続のたびに違う値が選ばれます。

tcp の行は、ソケットの状態が変わった記録です。次の節で読みます。

16.6ss で接続の状態を見る

TCP のソケットは、いまどの段階にあるかという状態を持っています。握手の途中、つながっている、閉じている途中、などです。ss -tan（-a は全部）で見られます。

いまあるソケット⌘↵
ss -tan

TIME-WAIT という状態のソケットが、いくつか残っています。さっきまでのクライアントのものです。これは後で説明します。先に、つながっている最中の状態を見ます。

クライアントの標準入力を sleep 5 にして、5 秒間つないだままにします。そのあいだに ss を実行します。

つながっている最中⌘↵
nc -l -p 6000 > /dev/null &sleep 5 | nc -N 127.0.0.1 6000 &sleep 1; ss -tanp | grep -E 'State|6000'wait

ESTAB（ESTABLISHED。確立した）が 2 行あります。1 つの接続に、ソケットは 2 つあるからです。

  • 127.0.0.1:32772 → 127.0.0.1:6000：クライアント側。nc の fd 3
  • 127.0.0.1:6000 → 127.0.0.1:32772：サーバ側。nc の fd 4（accept が返した fd）

TCP の接続は、（自分の IP、自分のポート、相手の IP、相手のポート）の 4 つの組で区別されます。サーバの 6000 番に 100 人がつないでも、相手のアドレスかポートが違うので、100 本の別々の接続になります。待ち受けていた LISTEN のソケットは、nc が閉じたので、もうありません。

状態の移り変わり

主な状態は、次のとおりです。

閉じるときは、両方がそれぞれ FIN を送り、相手の ACK を受け取ります。両方向の通信なので、「こちらはもう送らない」を、片方ずつ伝えます。

先に閉じた側のソケットは、すぐには消えず、TIME-WAIT で 60 秒ほど残ります。最後の ACK が相手に届かなかったときに送り直すためと、遅れて届いた古いパケットが、同じ番地の新しい接続に紛れ込まないようにするためです。ss -tan に残っていたのは、これです。プロセスはもう終わっていて、カーネルだけが覚えています。

60 秒たつと、消える⌘↵
ss -tan | grep -c TIME-WAITsleep 61ss -tan

5 個あった TIME-WAIT が、61 秒後には 1 つもありません。

遅い回線で、握手の途中を見る

SYN-SENT のような途中の状態は、一瞬で通り過ぎるので、ふつうは見えません。回線をわざと遅くすれば、見えます。tc（traffic control）で、ループバックのパケットを 100 ミリ秒ずつ遅らせます。

lo のパケットを 100 ミリ秒遅らせるroot で実行⌘↵
tc qdisc add dev lo root netem delay 100mstc qdisc show dev lo
握手の途中の状態⌘↵
nc -l -p 6001 > /dev/null &echo hi | nc -N 127.0.0.1 6001 & sleep 0.05; ss -tan | grep 6001; wait

SYN-SENT のソケットが見えました。クライアントは SYN を送りましたが、まだサーバに届いていません（届くのは 100 ミリ秒後です）。サーバ側は、まだ LISTEN のソケットしかありません。

ping は、相手に小さなパケットを送り、返事が帰ってくるまでの時間を計るコマンドです。行きに 100 ミリ秒、帰りに 100 ミリ秒です。

往復で 200 ミリ秒⌘↵
ping -c 1 127.0.0.1

日本からアメリカのサーバまでの往復が、およそ 100 〜 200 ミリ秒です。TCP は、データを送る前に握手で 1 往復を使います。遠くのサーバへの最初の接続に時間がかかるのは、このためです。遅延を元に戻します。

遅延を外すroot で実行⌘↵
tc qdisc del dev lo root

16.7つながらないとき

ソケットのエラーも、第 10 章で見た errno で返ります。よく出会うのは、次の 2 つです。

ECONNREFUSED：だれも待ち受けていない

だれも待ち受けていないポートに接続すると、どうなるでしょうか。

だれもいないポートにつなぐエラーになるstrace：システムコールも表示⌘↵
nc -N 127.0.0.1 5999 < /dev/null

connect(…) = -1 ECONNREFUSED (Connection refused) です。相手の機械には届いたけれど、そのポートで待ち受けているプログラムがいません。カーネルが、SYN に対して RST（打ち切り）を返しました。

「Connection refused」を見たら、確かめることは 3 つです。サーバは起動しているか。ポート番号は合っているか。サーバが待ち受けているアドレスは合っているか（127.0.0.1 だけで待ち受けているサーバには、外からつなげません）。サーバの機械で ss -tlnp を実行すれば、全部わかります。

EADDRINUSE：そのポートは使用中

逆に、すでにだれかが待ち受けているポートで、もう 1 つ待ち受けようとすると、bind が失敗します。

同じポートで 2 つは待ち受けられないエラーになる⌘↵
nc -l -p 7000 > /dev/null &nc -l -p 7000ss -tlnpkill %1

Address already in use（EADDRINUSE）です。1 つの番地で待ち受けられるのは、1 つのソケットだけです。開発中に「サーバが起動しない」ときの、いちばん多い原因です。前に起動したサーバが、まだ動いています。犯人は、ss -tlnp の右端の pid= でわかります。最後の kill %1 で、片づけています。

16.8HTTP は、文字の会話

ソケットの上を流れるのは、ただのバイトの列です。それをどう読むかは、プログラムどうしの約束（プロトコル）で決まります。Web で使う HTTP は、人が読める文字で書かれた、簡単な約束です。

この Linux には、小さな Web サーバ httpd が入っています。8080 番で待ち受けて、/var/www/html の下のファイルを配ります。

Web サーバを起動する⌘↵
ls /var/www/htmlhttpd > /tmp/httpd.log &

curl は、URL を指定してサーバにリクエストを送り、返ってきた中身を表示するコマンドです。ブラウザの、画面のないものだと思ってください。

curl でファイルをもらう⌘↵
curl http://127.0.0.1:8080/hello.txt

-v をつけると、やりとりの全部が見えます。> で始まる行が curl の送ったもの、< で始まる行がサーバの返したものです。

HTTP のやりとりを見る⌘↵
curl -v http://127.0.0.1:8080/hello.txt

クライアントが送るリクエストは、こういう形です。

  • 1 行目：GET /hello.txt HTTP/1.1。「/hello.txt をください」。GET はメソッド（何をしたいか）
  • 2 行目から：ヘッダ。名前: 値 の形の付け足し情報
  • 空行：ここでリクエストは終わり

サーバが返すレスポンスも、同じ作りです。

  • 1 行目：HTTP/1.0 200 OK。200 はステータスコードで、成功を表す
  • ヘッダ：Content-Type（中身の種類）、Content-Length（中身のバイト数）など
  • 空行
  • 本文：ファイルの中身

文字の会話なのですから、curl を使わずに、自分の手で話すこともできます。nc でつないで、リクエストの 2 行（1 行目と、空行）を送ります。HTTP の行の終わりは \r\n と決まっているので、printf で書きます。

nc で HTTP を話す⌘↵
printf 'GET /hello.txt HTTP/1.0\r\n\r\n' | nc -N 127.0.0.1 8080

curl のときと同じレスポンスが返ってきました。サーバから見れば、相手が curl でも、ブラウザでも、nc でも、区別はありません。ソケットから、約束どおりの文字が届いただけです。

ないファイルを頼むと、ステータスコードが変わります。-i は、レスポンスのヘッダも表示するオプションです。

ないファイルを頼む⌘↵
curl -i http://127.0.0.1:8080/nothing.txt | head -1cat /tmp/httpd.log

有名な 404 Not Found です。httpd は、受けたリクエストを 1 行ずつ記録しています（アクセスログ）。第 5 章で集計した access.log は、こうして作られたものです。

ステータスコードは、百の位で大きく分かれます。200 番台は成功、300 番台は「別の場所へ」、400 番台は頼んだ側の間違い（403 は権限がない、404 はない）、500 番台はサーバの中のエラーです。

深掘りHTTPS は、何が違うか

HTTP は、文字がそのままネットワークを流れます。途中の機械は、中身を読むことも、書き換えることもできます。HTTPS は、TCP の接続の上で、まず TLS という暗号の握手をして、その後の HTTP のやりとりを全部暗号化します。中身は同じ HTTP ですが、nc で手で話すことはできません。本物の Linux では、openssl s_client -connect example.com:443 が、暗号の部分を肩代わりしてくれる nc の代わりになります。

16.9名前で相手を指す

IP アドレスは覚えにくいので、ふつうは名前（ホスト名）を使います。名前を IP アドレスに直すことを、名前解決と呼びます。

いちばん単純な名前解決は、/etc/hosts というファイルです。IP アドレスと名前の対応が、1 行ずつ書いてあります。

/etc/hosts⌘↵
cat /etc/hosts

localhost は 127.0.0.1 です。だから、127.0.0.1 と書いていたところは、localhost と書けます。

名前でつなぐ⌘↵
getent hosts localhostcurl http://localhost:8080/hello.txt

getent hosts は、プログラムが名前を引くのと同じ手順で、名前を引いて見せるコマンドです。curl の中でも、同じことが起きています。connect に渡せるのは IP アドレスだけなので、プログラムは connect の前に、名前を IP アドレスに直します。

/etc/hosts に行を足せば、自分だけの名前を作れます。逆に、/etc/hosts にない名前は、この Linux では引けません。

知らない名前エラーになる⌘↵
curl http://example.com/

本物の Linux では、/etc/hosts になければ、DNS（Domain Name System）に問い合わせます。DNS は、世界中の名前と IP アドレスの対応を、たくさんのサーバで分担して持っている仕組みです。問い合わせる先の DNS サーバは、/etc/resolv.conf に書いてあります。

ターミナル
$ cat /etc/resolv.confnameserver 192.168.1.1$ getent hosts example.com93.184.215.14   example.com

「サイトにつながらない」ときは、名前解決の失敗（Could not resolve host）なのか、接続の失敗（Connection refused、タイムアウト）なのかを、まず見分けます。原因も、調べる場所も、まったく違います。

16.10UNIX ドメインソケット

同じ機械の中のプログラムどうしなら、IP アドレスとポートの代わりに、ファイルのパスを番地にするソケットが使えます。UNIX ドメインソケットです。nc では -U をつけます。

パスで待ち受ける⌘↵
nc -lU /tmp/chat.sock > got.txt &sleep 0.1; ls -l /tmp/chat.sockss -xl

ls -l の先頭の文字が s です。第 3 章から見てきたファイルの種類（-、d、l、c、p）に、最後の 1 つ、ソケットが加わりました。ss -x は、UNIX ドメインソケットの一覧です。/run/systemd/private は、起動のときから init が待ち受けているものです（第 17 章）。

パスを指定してつなぐ⌘↵
echo "パスでつないだ" | nc -NU /tmp/chat.sockcat got.txt

使うシステムコールは、TCP のときと同じ 5 つです。違うのは番地の種類だけで、socket(AF_UNIX, SOCK_STREAM, 0) で作り、bind と connect に sun_path="/tmp/chat.sock" を渡します。

UNIX ドメインソケットには、TCP にない利点があります。

  • ファイルの権限で、つなげる人を絞れる。ソケットのファイルに chmod 600 すれば、持ち主しかつなげない
  • ネットワークの外からは、絶対につなげない
  • 握手も番号の管理もないので、速い

データベース（PostgreSQL は /var/run/postgresql/.s.PGSQL.5432）、Docker（/var/run/docker.sock）、systemd など、同じ機械の中で話すプログラムの多くが、これを使っています。

16.11本物のネットワーク

最後に、この小さな Linux にはない、外の世界とのつながりを、図で見ておきます。

自分の機械が直接つながっているのは、同じネットワーク（192.168.1.0/24）の中の機械だけです。それ以外のあて先のパケットは、ルータに渡します。どこへ渡すかを決める表が、ルーティングテーブルです。

この Linux のルーティングテーブル⌘↵
ip route

この Linux には、「192.168.1.0/24 あては、eth0 から直接出す」の 1 行しかありません。本物の機械には、もう 1 行あります。

ターミナル
$ ip routedefault via 192.168.1.1 dev eth0192.168.1.0/24 dev eth0 proto kernel scope link src 192.168.1.5

default via 192.168.1.1 が、「ほかのあて先は、全部 192.168.1.1（ルータ）に渡す」という意味です。この行をデフォルトゲートウェイと呼びます。ルータも同じように表を引いて、次のルータへ渡します。これをくり返して、パケットは世界の反対側まで届きます。

この Linux にはデフォルトゲートウェイがないので、外のアドレスには、送り出すことさえできません（Network is unreachable）。

外へつながらないときは、手前から順に確かめます。

確かめることコマンドだめなら
自分に IP アドレスがあるかip addrケーブル、Wi-Fi、DHCP
ルータに届くかping 192.168.1.1家の中のネットワーク
外の IP アドレスに届くかping 8.8.8.8ルータから先、回線
名前が引けるかgetent hosts example.comDNS の設定
相手のポートにつながるかnc -vz example.com 443相手のサーバ、ファイアウォール
注意本物との違い
  • この小さな Linux がつなげる相手は、自分自身（127.0.0.1、192.168.1.5）だけです。DNS、ルーティング、ファイアウォールはありません
  • TCP のほかに、UDP（握手も送り直しもない、軽い通信。DNS や動画の通話で使う）と、IPv6（128 ビットのアドレス）がありますが、この Linux にはありません
  • 本物の TCP は、パケットがなくなれば送り直し、相手や回線の速さに合わせて送る量を調整します（再送、ウィンドウ、輻輳制御）。この Linux では、パケットはなくならず、状態の移り変わりと番号だけを再現しています
  • 本物では、クライアントのポート番号は 32768 〜 60999 からでたらめに選ばれます。この Linux では、32768 から順番です
  • 本物の ping は、TCP ではなく ICMP という別のプロトコルのパケットを送ります。この Linux の ping は、表示だけを真似ています
  • ss の -p でほかのユーザーのプロセスが表示されないのは、本物も同じです。全部見るには sudo ss -tlnp とします
要点この章のまとめ
  • ソケットは、親子でないプログラムどうしを、番地を頼りにつなぐ仕組み。つながった後は、両方向に使えるふつうの fd
  • TCP の番地は、IP アドレス（どの機械）とポート番号（どの窓口）。127.0.0.1（localhost）は自分自身。1024 未満のポートは root だけ
  • サーバは socket → bind → listen → accept。クライアントは socket → connect。accept は、接続ごとに新しい fd を返す
  • TCP は、SYN → SYN,ACK → ACK の 3 ウェイハンドシェイクでつながる。バイトに番号をつけ、ACK で受け取りを確かめる。閉じるときは、両方が FIN を送る
  • ss -tlnp で、待ち受けているポートとプロセスがわかる。ss -tan で、全部のソケットの状態（LISTEN、ESTAB、TIME-WAIT）がわかる
  • 待ち受けがなければ ECONNREFUSED、ポートが使用中なら EADDRINUSE
  • HTTP は、ソケットの上の文字の会話。GET /パス HTTP/1.0 と空行を送れば、nc でも話せる
  • 名前は、/etc/hosts（と、本物では DNS）で IP アドレスに直してから connect する
  • UNIX ドメインソケットは、パスを番地にする、同じ機械の中だけのソケット。ファイルの種類は s

16.12確認問題

ソケットと ss、nc、curl を使った問題です。どの問題も、新しい Linux から始まります。

問 1

サービスのポート番号を調べる

正解済み

この機械の /etc/services に、myapp というサービスが登録されています。myapp のポート番号だけを、数字で表示してください。

# ここにコマンドを書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵標準出力で判定（行の順番も見る）
ヒント

getent services myapp で、myapp 9100/tcp のような 1 行が出ます。awk '{print $2}' で 2 列目を取り出し、cut -d/ -f1 で / の前だけにします。

この問題の準備

答え合わせのたびに、章の最初の状態にこの準備をしてから、あなたのコマンドを実行します。

sudo sh -c 'echo "myapp        9100/tcp" >> /etc/services'
模範解答
getent services myapp | awk '{print $2}' | cut -d/ -f1
問 2

待ち受けているポートを見つける

正解済み

バックグラウンドで、Web サーバ httpd が動いています。ただし、どのポートで待ち受けているかは、わかりません。httpd が待ち受けているポート番号だけを、数字で表示してください。この機械で待ち受けている TCP のソケットは、これ 1 つだけです。

# ここにコマンドを書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵標準出力で判定（行の順番も見る）
ヒント

ss -tln の 4 列目（Local Address:Port）が 0.0.0.0:3000 のような形です。見出しを tail -1 で除き、awk '{print $4}' で 4 列目、cut -d: -f2 で : の後ろを取り出します。

この問題の準備

答え合わせのたびに、章の最初の状態にこの準備をしてから、あなたのコマンドを実行します。

httpd -p 3000 > /dev/null &
模範解答
ss -tln | tail -1 | awk '{print $4}' | cut -d: -f2
問 3

Web サーバからファイルをもらう

正解済み

この機械の 8000 番で、root の動かしている Web サーバが待ち受けています。このサーバが配っている /token.txt の中身を、表示してください。元のファイルは root しか読めない場所にあるので、サーバに頼むしかありません。

# ここにコマンドを書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵標準出力で判定（行の順番も見る）
ヒント

curl http://ホスト:ポート/パス で、サーバにファイルを頼めます。ホストは localhost、ポートは 8000、パスは /token.txt です。

この問題の準備

答え合わせのたびに、章の最初の状態にこの準備をしてから、あなたのコマンドを実行します。

sudo mkdir -p /root/sitesudo chmod 700 /rootsudo sh -c 'echo tok-48213 > /root/site/token.txt'sudo httpd -p 8000 -d /root/site > /dev/null &
模範解答

問 4

ポートを使っているプロセスを突き止める

正解済み

7000 番でサーバを起動しようとしたら、Address already in use と言われました。バックグラウンドで動いているいくつかのプロセスのうち、どれかが 7000 番で待ち受けています。そのプロセスの PID だけを、数字で表示してください。

# ここにコマンドを書いて「答え合わせ」（Ctrl / ⌘ + Enter）
⌘↵標準出力で判定（行の順番も見る）
ヒント

ss -tlnp の右端に、users:(("nc",pid=5,fd=3)) の形でプロセスが出ます。grep ':7000 ' で 7000 番の行だけにして（:17000 と間違えないように、: と空白ではさみます）、sed 's/.*pid=\([0-9]*\).*/\1/' で pid= の後ろの数字だけを取り出します。

この問題の準備

答え合わせのたびに、章の最初の状態にこの準備をしてから、あなたのコマンドを実行します。

nc -lk -p 7001 > /dev/null &nc -lk -p 7000 > /dev/null &nc -lk -p 17000 > /dev/null &
模範解答
ss -tlnp | grep ':7000 ' | sed 's/.*pid=\([0-9]*\).*/\1/'
