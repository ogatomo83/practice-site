この章は、読み通すためのものではありません。本文を読んでいて「このコマンドは何だったか」「この番号は何か」と思ったときに、引いてください。

表の右端の「章」は、その項目を説明している場所です。7.5 は、第 7 章の 5 番目の節という意味で、押すとその節へ飛びます。

21.2コマンドの早見表

小さな Linux の /usr/bin と /usr/sbin には、126 個のコマンドがあります。本物の Linux にある同じ名前のコマンドに、出力の形とエラー文を合わせてあります。ただし、オプションは主なものだけです。

「使い方」の [ ] は省略できる部分、… はくり返せる部分、A | B はどちらか、という意味です。

21.10このサイトの Linux と本物の違い

この本の「小さな Linux」は、JavaScript で書いた教育用のシミュレータです。システムコールの名前と意味、エラー番号、コマンドの出力の形は、本物に合わせてあります。しかし、本物の Linux の全部を再現してはいません。違いを、まとめておきます。

全体

  • カーネルは、JavaScript のシミュレータです。機械語は実行しません。/usr/bin のコマンドの中身は、ELF に似せた短い印で、実体は JavaScript のプログラムです
  • 時間は、仮想の時間です。システムコール 1 回が 1 ミリ秒で、コマンドを実行している間だけ進みます。起動するたびに、時刻は 2026 年 4 月 1 日 9 時 0 分 0 秒から始まります。本物は、ずっと速く動きます
  • 同じ操作は、いつも同じ結果になります。乱数も、決まった種から作ります。/dev/urandom も、ページを開き直して同じ順に実行すれば、同じバイト列を返します。本物は、PID も時刻も乱数も、実行するたびに変わります
  • CPU は 1 つです。スレッド、割り込み、カーネルスレッド（本物の ps -ef に [kworker/…] と出るもの）はありません
  • 物理メモリは 64 MiB、ディスクは 64 MiB です
  • システムコールは 93 個だけです。そのうち pivot_root は、呼ぶといつも ENOSYS で失敗します
  • ユーザーは 4 人（root、you、alice、bob）です。su と sudo は、パスワードをたずねません。本物では、sudo は自分の、su はなる相手のパスワードが要ります
  • ロケールは C です。エラー文は英語で、並び順はバイトの順です。日本語のファイル名は、そのまま表示します

シェルとコマンド

  • sh は、POSIX のシェルに、bash の一部（local、${x/a/b}、<<<、&>、{a,b} など）を足したものです。配列、[[ ]]、(( ))、select、プロセス置換 <( ) は使えません。ulimit もありません
  • コマンドのオプションは、主なものだけです。使えるオプションは、help コマンド名 に出るものが全部です
  • man は help と同じものを表示します。less と more は、cat と同じように全部を表示して終わります。top は、1 回表示して終わります。clear は何もしません
  • エディタ（vi、nano）はありません。ファイルを作るには、リダイレクトやヒアドキュメントを使います
  • rm は、書き込めないファイルを消すときも、確認をたずねません
  • sed が使える命令は s、p、d だけです。awk は簡易版です
  • 出力のバッファが違います。本物の libc は、出力先が端末なら 1 行ごとに write します。小さな Linux のコマンドは、端末でも、4096 バイトたまるか終了するまでためます（10.7）
  • (core dumped) と表示されても、core ファイルは作りません
  • strace は、本物より行が少なくなります。本物では、execve の直後に、共有ライブラリを読み込むための openat や mmap が 30 行ほど並びます（10.4）

プロセスとシグナル

  • fork は、内部では「子が実行する関数を渡す」形です。外から見た動き（clone が親には子の PID を返し、fd 表やカレントディレクトリが複製される）は、本物と同じです
  • 孤児を引き取るのは、いつも PID 1（または PID 名前空間の中の 1 番）です。本物には、ほかのプロセスが引き取り役を名乗る仕組み（subreaper）があります
  • /proc/PID/fdinfo の ofd と refs の 2 行は、このサイトだけのものです。ファイル記述が共有されているかどうかを、見えるようにしています

ファイルシステム

  • / は ext4 と表示されますが、本物の ext4 のディスク上の形（ブロックグループ、ビットマップ、エクステント、ジャーナル）は持っていません。inode、ディレクトリエントリ、リンク数、ブロックの割り当て、という考え方をまねています
  • ファイルを読んでも、atime（最後に読んだ時刻）は変わりません
  • ブロックデバイス（/dev/sda など）はありません。mount でつなげるのは、tmpfs、proc、devtmpfs、sysfs、cgroup2 です。バインドマウント（mount --bind）はできません。-o ro は、書いても読み取り専用になりません
  • /proc と /sys のファイルは、本文で使うものだけです。本物には、/proc/sys だけで千個を超える設定があります

仮想メモリ（第 13 章）

  • スワップ、巨大ページ、NUMA はありません。メモリが足りないときにページを回収する細かい方針（本物の LRU のリスト、kswapd）もありません
  • 番地は、毎回同じです。本物は、実行のたびに番地をずらします（ASLR）
  • 1 つのプロセスの領域は、text、data、ヒープ、スタックなど 9 個だけです。本物の cat には 20 前後の領域があります。VSZ や RSS の値は、本物より 1 桁ほど小さくなります
  • 読むだけのページフォルトでも、フレームを 1 つ割り当てます。本物は、中身が 0 の共有のページを写して、書くまで割り当てを遅らせます
  • OOM killer は、メモリをいちばん使っているプロセスを選び、すぐに殺します。本物は、もっと細かい点数で選びます

スケジューラ（第 14 章）

  • CFS を単純にしたものです。周期は 24 tick、最小の持ち時間は 3 tick で、次のプロセスは赤黒木ではなく、順に調べて探します
  • リアルタイムのクラス（SCHED_FIFO、SCHED_RR）、CPU の割り当て（アフィニティ）、cgroup ごとの CPU の配分はありません
  • 本物の Linux は、バージョン 6.6 からスケジューラが EEVDF という方式に変わっています。「公平に分ける」という考え方は同じです

ページキャッシュとディスク（第 15 章）

  • ディスクは「1 ページ読むのに 5 ミリ秒、一度に 1 つ」という単純な装置です。先読みや、I/O の順番を並べ替える仕組みはありません
  • 書き戻しは、ファイル単位です。途中で電源が切れると、そのファイルの書き戻し中の分は、全部失われます。ファイルの作成、削除、名前の変更は、すぐディスクに書かれたものとして扱います
  • free の buffers は、いつも 0 です

ネットワーク（第 16 章）

  • 通信できるのは、自分自身あてだけです。IPv4 の TCP と、UNIX ドメインソケットだけがあります。UDP、IPv6、DNS、経路の選択、ファイアウォールはありません。ping は、表示だけです
  • TCP は、状態の移り変わりと番号だけをまねています。再送、ウィンドウ、輻輳制御、パケットの喪失はありません
  • 自動で割り当てるポートは、32768 から順です。本物は、ばらばらの番号を選びます

起動と init（第 17 章）

  • ファームウェア、ブートローダ、initramfs は、ログの行として出てくるだけです
  • PID 1 は、systemd そのものではありません。unit ファイルの一部（ExecStart、Restart、User など）だけを読む、小さな init です。After= などの依存関係は読みません。target は multi-user.target だけです
  • systemctl と journalctl の出力の形は、本物と照合できていません（下の「照合」を参照）
  • 電源を切っても、次のコマンドのために、すぐ起動し直します

コンテナ（第 19 章）

  • 名前空間は、PID、マウント、UTS（ホスト名）などです。ユーザー名前空間はないので、unshare は root でしか使えません
  • pivot_root、overlayfs、capabilities、seccomp はありません。本物のコンテナは、これらも組み合わせています
  • cgroup で制限できるのは、プロセスの数（pids）とメモリ（memory）だけです。CPU や I/O の制限はありません
