## ディレクトリの木 {#tree}

Linux では、すべてのファイルが、**1 本の木**の中に並んでいます。木の根は `/` という名前のディレクトリで、**ルートディレクトリ**と呼びます。**ディレクトリ**は、ファイルやほかのディレクトリを入れておく入れ物です（Windows や macOS の「フォルダ」と同じものです）。

Windows には `C:` や `D:` のようにドライブごとの木がありますが、Linux の木は 1 本だけです。2 台目のディスクも、USB メモリも、この木のどこかの枝としてつながります（第 12 章のマウント）。

まず、根の直下を見てみましょう。

```sh run title="ルートディレクトリの中身"
ls /
```

本物の Linux でも、ほぼ同じ名前が並びます。どのディレクトリに何を置くかは、**FHS**（Filesystem Hierarchy Standard）という取り決めで決まっているからです。主なものを、木の形で示します。

```fig tree ディレクトリの木（主なものだけ）。/ が根で、あなたのファイルは /home/you の下にある
{

    { label: 'bin', note: '基本のコマンド。いまは usr/bin を指すリンク' },
    { label: 'etc', kind: 'dir', note: 'システムの設定ファイル', children: [
      { label: 'hostname', note: 'この計算機の名前' },
      { label: 'passwd', note: 'ユーザーの一覧（第 4 章）' },
```

| ディレクトリ | 置くもの |
| --- | --- |
| `/etc` | システム全体の**設定ファイル**。ほとんどがテキストで、`cat` で読める |
| `/home` | 一般ユーザーの**ホームディレクトリ**。自分のファイルを自由に置ける場所 |
| `/root` | root のホームディレクトリ。`/home` の下ではない |
| `/usr/bin` | **コマンド**の実体。`/bin` は、昔との互換のために `/usr/bin` を指している |
| `/usr/lib` | プログラムが共通で使う部品（ライブラリ。第 18 章） |
| `/var` | 動いている間に**変わるデータ**。`/var/log` にはログがたまる |
| `/tmp` | **一時ファイル**。だれでも書ける。再起動すると消える |
| `/dev` | **装置**を表す特別なファイル。`/dev/null` など |
| `/proc` | **カーネルの中の情報**を、ファイルの形で見せる場所。ディスクの上にはない |
| `/boot` | 起動に使うカーネル本体（第 17 章） |

設定ファイルを 1 つ読んでみましょう。

```sh run title="/etc の中身と、設定ファイル"
ls /etc
cat /etc/hostname
```

第 2 章で `hostname` コマンドが表示した名前は、このファイルに書いてあったものです。Linux では、設定の多くが、こういう小さなテキストファイルです。

## いまいる場所を動かす：pwd と cd {#cd}

シェルは、木の中のどこか 1 か所に「いる」ことになっています。その場所を**カレントディレクトリ**（作業ディレクトリ）と呼びます。`pwd` で表示し、`cd` で動かします。

```sh run title="いまいる場所"
pwd
```

ログインした直後は、ホームディレクトリにいます。`/etc` へ移動してみます。

```sh run title="/etc へ移動する"
cd /etc
pwd
ls
cat hostname
```

プロンプトの `~` が `/etc` に変わりました。プロンプトは、いつもカレントディレクトリを表示しています。

`ls` に引数を付けなければ、カレントディレクトリの中身が表示されます。`cat hostname` も、`/etc/` を付けずに読めました。カレントディレクトリは、「名前だけを書いたとき、どこから探すか」の基準です。

`cd` には、よく使う行き先の書き方があります。

| 書き方 | 行き先 |
| --- | --- |
| `cd` | ホームディレクトリ（引数なし） |
| `cd ~` | ホームディレクトリ。`~/notes` のように、うしろに続けられる |
| `cd ..` | 1 つ上のディレクトリ（次の節） |
| `cd -` | 直前にいたディレクトリ。移動先を表示する |

```sh run title="戻る、行き来する"
cd
pwd
cd -
cd -
```

1 行目の `cd` でホームに戻り、`cd -` で `/etc` へ、もう 1 回の `cd -` でホームへ戻りました。2 つのディレクトリを行き来するときに便利です。

ないディレクトリや、ディレクトリでないものには、移動できません。

```sh run error title="移動できない例"
cd nowhere
cd memo.txt
cd /root
```

3 つのエラーの文は、理由がそれぞれ違います。

- `No such file or directory`：その名前のものがない
- `Not a directory`：あるけれど、ディレクトリではない（`memo.txt` はふつうのファイル）
- `Permission denied`：あるけれど、入る許可がない（`/root` は root だけが入れる。第 4 章）

エラーの文をきちんと読めば、何が悪いのかがわかります。

## 絶対パスと相対パス {#paths}

木の中のファイルやディレクトリの場所を、文字で書いたものを**パス**と呼びます。パスは、ディレクトリの名前を `/` で区切ってつなげたものです。書き方は 2 通りあります。

- **絶対パス**は、`/` で始まる。根から順にたどる。カレントディレクトリがどこでも、同じ場所を指す
- **相対パス**は、`/` で始まらない。**カレントディレクトリから**たどる。いまいる場所によって、指す先が変わる

```sh run title="同じファイルを、2 通りのパスで"
cat /home/you/notes/todo.txt
cat notes/todo.txt
```

カレントディレクトリが `/home/you` なので、`notes/todo.txt` は `/home/you/notes/todo.txt` と同じファイルを指します。

### . と ..

どのディレクトリにも、特別な名前が 2 つ入っています。

- `.`（ドット 1 つ）は、**そのディレクトリ自身**
- `..`（ドット 2 つ）は、**1 つ上のディレクトリ**（親ディレクトリ）

`..` を使うと、相対パスで木を上へたどれます。

```sh run title=".. で上へたどる"
cd notes
pwd
ls ..
cat ../memo.txt
```

`notes` の中にいるとき、`..` は `/home/you` です。`../memo.txt` は「1 つ上がって、そこの `memo.txt`」です。

`..` は、いくつでもつなげられます。

```sh run title="2 つ上へ"
cd ../..
pwd
ls
```

`/home/you/notes` から 2 つ上がって、`/home` に来ました。ほかのユーザーのホームディレクトリが並んでいます。

```fig tree カレントディレクトリが /home/you/notes のとき。相対パスは、いまいる場所から木をたどる
{
  root: { label: '/', kind: 'dir', children: [
    { label: 'etc', kind: 'dir', children: [
      { label: 'hostname', note: '../../../etc/hostname　または　/etc/hostname' },
    ] },
    { label: 'home', kind: 'dir', note: '../..', children: [
      { label: 'you', kind: 'dir', note: '..', children: [
        { label: 'memo.txt', note: '../memo.txt' },
        { label: 'notes', kind: 'dir', hl: true, note: '.　← いまここ', children: [
          { label: 'todo.txt', note: 'todo.txt　または　./todo.txt' },
        ] },
      ] },
    ] },
  ] },
}
```

根より上はありません。`/` の `..` は、`/` 自身です。

```sh run title="根より上はない"
cd /
cd ..
pwd
cd
```

最後の `cd` で、ホームディレクトリに戻りました。

`.` は、何の役に立つのでしょうか。1 つは、第 2 章で見た `./hello.sh` です。「PATH から探すのではなく、いまいるディレクトリのこのファイル」と、はっきり伝えられます。もう 1 つは、「ここへ」という行き先としての使い方です。このあとの `cp` や `find` で使います。

:::tip どちらを使うか
手で打つときは、短く済む相対パスが便利です。スクリプトや設定ファイルに書くときは、どこから実行されても同じ場所を指す絶対パスが安全です。`realpath` コマンドは、相対パスを絶対パスに直して表示します。
:::

## ls -l の 1 行を読む {#ls}

`ls -l` は、ファイルごとに 1 行ずつ、詳しい情報を表示します。Linux を使っていると、毎日この表示を読むことになります。

```sh run title="ls -l"
ls -l
```

最初の `total 28` は、ここにあるファイルが使っているディスクの量の合計です（単位は 1 K バイト）。そのあとの 1 行 1 行は、7 つの部分からできています。

```fig layout ls -l の 1 行。左から、種類と権限、リンク数、持ち主、グループ、大きさ、更新時刻、名前
{
  unit: 11,
  rows: [
    { label: '表示', cells: [{ t: '-', w: 2, kind: 'accent' }, { t: 'rw-r--r--', w: 9, kind: 'stack' }, { t: '1', w: 3, kind: 'heap' }, { t: 'you', w: 5, kind: 'static' }, { t: 'you', w: 5, kind: 'static' }, { t: '127', w: 5, kind: 'heap' }, { t: 'Mar 28 10:40', w: 12, kind: 'plain' }, { t: 'poem.txt', w: 9, kind: 'accent' }] },
    { label: '意味', cells: [{ t: '種', w: 2, kind: 'accent' }, { t: '権限', w: 9, kind: 'stack' }, { t: '数', w: 3, kind: 'heap' }, { t: '持ち主', w: 5, kind: 'static' }, { t: '集団', w: 5, kind: 'static' }, { t: 'バイト', w: 5, kind: 'heap' }, { t: '更新した時刻', w: 12, kind: 'plain' }, { t: '名前', w: 9, kind: 'accent' }] },
  ],
}
```

| 部分 | 例 | 意味 |
| --- | --- | --- |
| 種類 | `-` | 最初の 1 文字。`-` はふつうのファイル、`d` はディレクトリ、`l` はシンボリックリンク |
| 権限 | `rw-r--r--` | だれが読めて（r）、書けて（w）、実行できる（x）か。第 4 章で読み方を扱う |
| リンク数 | `1` | このファイルに付いている名前の数。この章の「リンク」の節で扱う |
| 持ち主 | `you` | このファイルを持っているユーザー |
| グループ | `you` | このファイルが属するグループ（第 4 章） |
| 大きさ | `127` | 中身のバイト数 |
| 更新時刻 | `Mar 28 10:40` | 中身を最後に書き換えた日時 |
| 名前 | `poem.txt` | ファイルの名前 |

`notes` の行は `d` で始まっています。ディレクトリです。ディレクトリの大きさが 4096 なのは、ディレクトリ自身（名前の一覧を入れておく場所）の大きさで、中のファイルの合計ではありません。

種類の違うものを、いくつか並べて見てみましょう。

```sh run title="いろいろな種類"
ls -l /bin /dev/null /etc/hostname
ls -ld /etc
```

- `/bin` は `l` で始まり、名前のあとに `-> usr/bin` と付いている。シンボリックリンク（この章の後半）
- `/dev/null` は `c` で始まる。装置を表す特別なファイル（第 12 章）
- `/etc/hostname` は `-`。ふつうのファイル
- `/etc` は `d`。ディレクトリ

`ls -l /etc` と打つと、`/etc` の**中身**の一覧が出てしまいます。ディレクトリそのものの情報を見たいときは、`-d`（directory）を付けます。

`ls` のオプションを、まとめておきます。

| オプション | 動き |
| --- | --- |
| `-l` | 詳しい情報を付けて、1 行に 1 つ |
| `-a` | `.` で始まる名前も表示する（次の節） |
| `-d` | ディレクトリの中身ではなく、ディレクトリそのものを表示する |
| `-h` | 大きさを `18K`、`2.8M` のように、人が読みやすい単位で表示する（`-l` と一緒に使う） |
| `-t` | 更新時刻の新しい順に並べる |
| `-S` | 大きさの大きい順に並べる |
| `-r` | 並び順を逆にする |
| `-R` | 中のディレクトリも、再帰的に（奥まで）表示する |
| `-F` | 名前のうしろに、種類の印を付ける（ディレクトリは `/`、リンクは `@`） |
| `-i` | inode 番号を表示する（この章の「リンク」の節） |

```sh run title="オプションを組み合わせる"
ls -F
ls -lS
ls -R
```

`ls -lS` は、大きい順です。`ls -R` は、`notes` の中まで表示しました。

## 隠しファイル {#dotfiles}

`ls` は、**名前が `.` で始まるもの**を表示しません。`-a` を付けると出てきます。

```sh run title="ls -a"
ls -a
cat .profile
```

`.profile` というファイルがありました。名前が `.` で始まるファイルを、**隠しファイル**（ドットファイル）と呼びます。特別な仕組みがあるわけではなく、「`ls` とワイルドカードの `*` が、`.` で始まる名前を飛ばす」という約束があるだけです。

ホームディレクトリの隠しファイルには、プログラムごとの**設定**を置くのが習慣です。ふだんの一覧のじゃまにならないように、隠してあります。`.profile` は、ログインしたシェルが最初に読む設定ファイルです。本物の Linux のホームディレクトリには、`.bashrc`（bash の設定）、`.ssh`（ssh の鍵）、`.config`（いろいろなプログラムの設定）などが並びます。

`ls -a` には、`.` と `..` も出ています。前の節で見た「自分自身」と「1 つ上」です。この 2 つも `.` で始まるので、ふだんは隠れています。

## 作る、コピーする、動かす、消す {#ops}

ここからは、木の形を自分で変えます。練習用に、`work` というディレクトリを作って、その中で作業します。

### mkdir と touch：作る

`mkdir`（make directory）はディレクトリを作り、`touch` は空のファイルを作ります。

```sh run title="ディレクトリとファイルを作る"
mkdir work
touch work/a.txt
ls -l work
```

`a.txt` の大きさは 0 です。`touch` は本来、ファイルの更新時刻を「いま」にするコマンドです。ファイルがなければ空のファイルを作るので、その使い方のほうが有名になりました。

深いディレクトリを一度に作ろうとすると、失敗します。途中のディレクトリがないからです。`-p`（parents）を付けると、途中のディレクトリも一緒に作ります。

```sh run error title="途中のディレクトリがないと、作れない"
mkdir work/2026/04/photos
```

```sh run title="-p で、途中も一緒に作る"
mkdir -p work/2026/04/photos
ls -R work
```

### cp：コピーする

`cp`（copy）は、`cp コピー元 コピー先` の形で使います。コピー先がディレクトリなら、その中に同じ名前でコピーします。

```sh run title="ファイルをコピーする"
cp memo.txt work/
cp memo.txt work/memo-copy.txt
ls work
```

ディレクトリをコピーするには、`-r`（recursive。再帰的に、中身ごと）が要ります。

```sh run error title="ディレクトリは、そのままではコピーできない"
cp notes work
```

```sh run title="-r で、中身ごとコピーする"
cp -r notes work
ls -R work/notes
```

:::warn コピー先に同じ名前があると、黙って上書きする
`cp` も、次の `mv` も、コピー先に同じ名前のファイルがあると、確認せずに上書きします。上書きされた中身は戻りません。`-i`（interactive）を付けると、上書きの前に確認します。`y` で始まる答えなら上書きし、それ以外なら何もしません。
:::

```sh run title="上書きされるファイルを用意する"
cp memo.txt keep.txt
```

```sh run stdin="n\n" title="-i：上書きの前にたずねる（n と答える）"
cp -i fruits.txt keep.txt
head -1 keep.txt
```

`cp: overwrite 'keep.txt'?` とたずねられ、`n` と答えたので、`keep.txt` は元の中身のままです。たずねる文は標準エラー出力に出て、答えは標準入力から読みます。

### mv：動かす、名前を変える

`mv`（move）は、ファイルを別の場所へ動かします。同じディレクトリの中で動かせば、**名前を変える**ことになります。Linux に「名前を変える」専用のコマンドはなく、`mv` がその役目をします。

```sh run title="名前を変える、動かす"
mv work/memo-copy.txt work/list.txt
ls work
mv work/list.txt work/2026/
ls work work/2026
```

1 行目は名前を変え、3 行目は `work/2026` の中へ動かしました。`mv` はディレクトリも、オプションなしで動かせます。

### rm と rmdir：消す

`rm`（remove）は、ファイルを消します。

```sh run title="ファイルを消す"
rm work/a.txt
ls work
```

ディレクトリは、`rm` だけでは消せません。空のディレクトリを消す `rmdir` か、中身ごと消す `rm -r` を使います。

```sh run error title="ディレクトリを消そうとすると"
rm work
rmdir work
```

`rm` は「ディレクトリだ」と言って断り、`rmdir` は「空ではない」と言って断りました。

```sh run title="rm -r で、中身ごと消す"
rm -r work/2026
ls work
```

:::warn rm にごみ箱はない
`rm` で消したファイルは、ごみ箱に入りません。その場でなくなり、取り戻す方法は基本的にありません。とくに `rm -r` は、ディレクトリの中身を奥まで全部消します。ワイルドカードと組み合わせるときは、先に同じ引数で `ls` を実行して、消えるものを確かめる習慣をつけてください。`rm -r *` の代わりに、まず `ls *` です。

`rm -i` は、1 つ消すたびに `rm: remove regular file 'memo.txt'?` とたずねます。書き込みを禁止したファイル（第 4 章）を消そうとすると、`-i` がなくても `remove write-protected regular file` とたずねられます。`rm -f`（force）は、ファイルがなくてもエラーを出さず、確認もしません。`rm -rf` は、Linux でいちばん事故の多いコマンドです。このサイトの Linux は、リセットすれば元に戻ります。本物では戻りません。
:::

ワイルドカード（第 2 章）は、これらのコマンドと一緒に使うと力を発揮します。

```sh run title="ワイルドカードでまとめて扱う"
touch work/1.log work/2.log work/keep.txt
ls work/*.log
rm work/*.log
ls work
```

`rm work/*.log` を実行する前に、同じワイルドカードで `ls` を実行して、何が当てはまるかを確かめています。

## 中身を見る：cat、head、tail、less {#view}

ファイルの中身を見るコマンドは、ファイルの大きさと、見たい場所で使い分けます。

| コマンド | 見せるもの | 使いどころ |
| --- | --- | --- |
| `cat` | 全部 | 短いファイル |
| `head` | 最初の 10 行（`-n 数` で行数を指定） | どんなファイルかを、ちょっと見る |
| `tail` | 最後の 10 行（`-n 数` で行数を指定） | ログの最新の部分を見る |
| `less` | 1 画面ずつ。上下に動ける | 長いファイルを読む |

`cat` は、もう何度も使いました。名前は concatenate（つなげる）から来ていて、複数のファイルを渡すと、順につなげて表示します。`-n` を付けると、行番号が付きます。

```sh run title="cat"
cat -n poem.txt
cat memo.txt notes/ideas.txt
```

長いファイルは、`head` と `tail` で端だけを見ます。`/var/log/access.log` は、Web サーバのアクセスの記録（の見本）です。

```sh run title="head と tail"
head -n 3 /var/log/access.log
tail -n 2 /var/log/access.log
```

ログは、新しい記録が下に足されていきます。だから、「さっき何が起きたか」を見るには `tail` を使います。本物の Linux では、`tail -f ファイル` で、ファイルに行が足されるたびに表示し続けることもできます。

`less` は、長いファイルを 1 画面ずつ読むためのコマンドです。本物の Linux では、次のキーで操作します。

| キー | 動き |
| --- | --- |
| スペース / `b` | 1 画面進む / 戻る |
| ↓ / ↑（または `j` / `k`） | 1 行進む / 戻る |
| `/文字` | 文字を探す。`n` で次の候補へ |
| `g` / `G` | 先頭へ / 末尾へ |
| `q` | 終わる |

`man`（第 2 章）がマニュアルを表示するときも、中で `less` を使っています。だから、操作のキーは同じです。

:::note このサイトの Linux では
`less` は、`cat` と同じように全部を表示して終わります。画面の中で上下に動く操作はできません。
:::

ディレクトリや、読む許可のないファイルは、`cat` できません。

```sh run error title="読めないもの"
cat notes
cat /etc/shadow
```

`/etc/shadow` は、パスワードの情報を入れるファイルで、root しか読めません。`Permission denied` の理由は、第 4 章で `ls -l` の権限の部分を読めるようになるとわかります。

テキストでないファイルを `cat` すると、画面が乱れます。中身の種類がわからないときは、先に `file` コマンドで調べます。

```sh run title="file で種類を調べる"
file memo.txt hello.sh notes /usr/bin/ls
```

`/usr/bin/ls` は ELF という形式の実行ファイルです（第 18 章）。Linux は、Windows と違って、名前の最後の `.txt` や `.sh`（拡張子）でファイルの種類を決めません。拡張子は、人が見分けるための習慣にすぎません。`file` は、名前ではなく中身を見て判断しています。

## 名前と中身は別のもの：リンク {#links}

ここまで、「ファイルには名前がある」と考えてきました。実は、Linux のファイルシステムでは、**名前と中身は別々に管理されています**。

- ファイルの中身と、その情報（大きさ、持ち主、権限、時刻）は、**inode**（アイノード）という入れ物に入っている。inode には、名前ではなく**番号**が付いている
- ディレクトリは、「**名前 → inode 番号**」の対応表にすぎない

`ls -i` で、inode 番号を見られます。

```sh run title="inode 番号を見る"
ls -i memo.txt
ls -li
```

行の先頭に付いた数が、inode 番号です。ファイルごとに違う番号が付いています。

### ハードリンク：同じ inode に、もう 1 つ名前を付ける

名前が対応表の 1 行にすぎないなら、**1 つの inode に、2 つの名前**を付けることもできるはずです。それが**ハードリンク**です。`ln 元の名前 新しい名前` で作ります。

```sh run title="ハードリンクを作る"
ln memo.txt memo-hard.txt
ls -li memo.txt memo-hard.txt
```

2 つの名前の inode 番号が、同じです。そして、`ls -l` の 3 番目の列（**リンク数**）が、1 から 2 に増えました。リンク数とは、「この inode を指している名前の数」です。

これはコピーではありません。中身は 1 つしかなく、名前が 2 つあるだけです。片方の名前で書き換えると、もう片方から見ても変わっています。

```sh run title="片方に書くと、もう片方も変わる"
echo "たまご" >> memo-hard.txt
cat memo.txt
```

`>>` は、ファイルの末尾に書き足す記号です（第 5 章）。`memo-hard.txt` に足した 1 行が、`memo.txt` にも現れました。どちらが「本物」で、どちらが「リンク」という区別はありません。2 つの名前は対等です。

`stat` コマンドは、inode の中の情報をまとめて表示します。

```sh run title="stat で inode の情報を見る"
stat memo.txt
```

`Inode:` が inode 番号、`Links:` がリンク数です。`Size:` が 55 から 65 に増えているのは、いま書き足した「たまご」と改行のぶんです（日本語の 1 文字は、UTF-8 で 3 バイト）。名前は、`File:` の行にしか出てきません。名前は inode の中には入っていないからです。

### シンボリックリンク：行き先のパスを書いた、小さなファイル

もう 1 つのリンクが、**シンボリックリンク**です。`ln -s 指す先 リンクの名前` で作ります。

```sh run title="シンボリックリンクを作る"
ln -s memo.txt memo-sym.txt
ls -li memo*
cat memo-sym.txt
```

`memo-sym.txt` は、ハードリンクとは違います。

- inode 番号が**別**。シンボリックリンクは、それ自身が 1 つの独立したファイル
- 種類が `l` で、名前のあとに `-> memo.txt` と、指す先が表示される
- 大きさが 8 バイト。これは `memo.txt` という**文字の数**。シンボリックリンクの中身は、指す先のパスそのもの
- `memo.txt` のリンク数は 2 のまま。シンボリックリンクは、リンク数に数えない

`cat memo-sym.txt` を実行すると、カーネルは「これはシンボリックリンクだ。中に書いてあるパスへ行き直そう」と、`memo.txt` を開きます。Windows のショートカットに近いものですが、カーネルが自動でたどるので、どのプログラムからも、ふつうのファイルのように使えます。

```sh run error title="壊れたリンク"
cat memo-sym.txt
```

シンボリックリンクは「名前」を覚えているだけなので、同じ名前のファイルがもう一度できれば、また使えるようになります。

```sh run title="同じ名前が戻れば、リンクも直る"
mv memo-hard.txt memo.txt
cat memo-sym.txt
rm memo-sym.txt
```

### 2 つのリンクを比べる

| | ハードリンク | シンボリックリンク |
| --- | --- | --- |
| 作り方 | `ln 元 新しい名前` | `ln -s 指す先 リンクの名前` |
| 正体 | 同じ inode を指す、もう 1 つの名前 | 指す先のパスを書いた、別のファイル |
| inode 番号 | 元と同じ | 元と別 |
| 元の名前を消すと | 中身は残る | 壊れたリンクになる |
| ディレクトリに | 作れない | 作れる |
| 別のファイルシステムへ | 作れない | 作れる |
| `ls -l` での見え方 | ふつうのファイルと同じ（リンク数が増える） | `l` で始まり、`-> 指す先` が付く |

ハードリンクの 2 つの制限を、確かめておきます。

```sh run error title="ハードリンクの制限"
ln notes notes-hard
ln memo.txt /tmp/memo-hard
```

1 つ目は、ディレクトリへのハードリンクです。これを許すと、木の中に輪ができて、「上へたどる」ことの意味が壊れてしまうので、禁止されています。2 つ目の `/tmp` は、`/home` とは別のファイルシステムです（第 12 章）。inode 番号はファイルシステムごとに付いているので、別のファイルシステムの inode を、番号で指すことはできません。

シンボリックリンクには、どちらの制限もありません。パスを文字で覚えているだけだからです。

```sh run title="ディレクトリへのシンボリックリンク"
ln -s notes n
ls -l n
ls n
rm n
```

実際に使われるのは、ほとんどがシンボリックリンクです。この章の最初に見た `/bin -> usr/bin` も、そうでした。

:::deep . と .. も、ハードリンク
ディレクトリの `ls -l` のリンク数を見ると、2 以上になっています。ディレクトリを指す名前は、親ディレクトリの中の名前（`notes`）と、自分の中の `.` の 2 つが必ずあるからです。さらに、中にディレクトリを 1 つ作るたびに、その中の `..` がこちらを指すので、リンク数が 1 つ増えます。`.` と `..` は、カーネルが自動で作る、ディレクトリへのハードリンクです（人が `ln` で作ることだけが、禁止されています）。

`ls -lid .` と `ls -lid notes/..` を実行して、inode 番号が同じになることを、実験場で確かめてみてください。
:::

inode の中に何が入っているのか、ディスクの上でどう並んでいるのか、「消す」とは正確には何か。この続きは、第 11 章「ファイルシステムの中身」で扱います。

## 探す：find {#find}

ファイルがどこにあるかわからないときは、`find` で探します。`find 探し始める場所 条件` の形で使い、その場所から下を**奥まで全部**調べて、条件に合うもののパスを表示します。

条件を付けなければ、全部が出てきます。

```sh run title="find：条件なしなら、全部"
find .
```

`.`（カレントディレクトリ）から下にあるものが、隠しファイルも含めて、すべて表示されました。並ぶ順番は、名前の順ではありません。ディレクトリの中に入っている順です。

よく使う条件は、次の 3 つです。

| 条件 | 意味 |
| --- | --- |
| `-name 'パターン'` | 名前がパターンに合うもの。ワイルドカードが使える |
| `-type f` / `-type d` / `-type l` | ふつうのファイルだけ / ディレクトリだけ / シンボリックリンクだけ |
| `-maxdepth 数` | 何段下まで調べるか。`1` なら、その場所の直下だけ |

```sh run title="名前と種類で探す"
find . -name '*.txt'
find . -type d
find /etc -name 'host*'
```

条件を並べると、「すべてに合うもの」になります。

```sh run title="条件を組み合わせる"
find . -maxdepth 1 -type f -name '*.txt'
```

`ls *.txt` との違いは、`find` が奥のディレクトリまで探すことです。1 つ目の例では、`./notes/todo.txt` も見つかっています。

:::warn -name のパターンは、引用符で囲む
`find . -name *.txt` と、引用符なしで書いてはいけません。第 2 章で見たとおり、`*.txt` は `find` に渡る前に、**シェルが**カレントディレクトリのファイル名に置き換えてしまいます。`find` に `*.txt` という文字のまま届けるために、`'*.txt'` と囲みます。
:::

```sh run error title="引用符を忘れた find"
find . -name *.txt
```

シェルが `*.txt` を 4 つのファイル名に置き換えたので、`find` は意味のわからない引数を受け取って、エラーになりました。

読む許可のないディレクトリがあると、`find` はそこでエラーの文を出して、先へ進みます。

```sh run error title="入れないディレクトリがあるとき"
find /home -name '*.txt'
```

`/home/bob` には入れなかった、と言っています。それ以外の場所の結果は、ちゃんと出ています。エラーの文だけを画面から消す方法（`2>/dev/null`）は、第 5 章で扱います。

## 大きさを調べる：du と df {#du}

最後に、ディスクの使い方を調べる 2 つのコマンドを、軽く見ておきます。名前が似ていますが、見ているものが違います。

- `du`（disk usage）は、**ディレクトリやファイル**が使っているディスクの量を調べる
- `df`（disk free）は、**ファイルシステム全体**の空きを調べる

```sh run title="du：ディレクトリが使っている量"
du
du -sh .
du -sh /usr/bin
```

`du` は、ディレクトリごとに、その下にあるもの全部の合計を表示します。単位は 1 K バイトです。`-s`（summary）は合計の 1 行だけにし、`-h` は `K` や `M` を付けて読みやすくします。

ここで、`ls -l` との違いに気づくかもしれません。`ls -l` では数十バイトだった小さなファイルが、`du` では 1 つ 4 K バイトとして数えられています。

```sh run title="大きさと、使っているディスクの量"
ls -l memo.txt
du memo.txt
```

ディスクは、**ブロック**という決まった大きさ（ここでは 4 K バイト）の区画に分けて使われます。1 バイトのファイルでも、ブロックを 1 つ使います。`ls -l` が表示するのは中身の**バイト数**、`du` が表示するのは使っている**ブロックの量**です。

```sh run title="df：ファイルシステムの空き"
df -h
```

1 行が 1 つのファイルシステムです。`/` には 64 M バイトのディスク（`/dev/sda1`）がつながっていて、そのうち使っているのは 6% ほどです。`/tmp` と `/dev` は、別のファイルシステムになっています。「1 本の木」が、実は何枚かのファイルシステムをつなぎ合わせてできていることが、ここに見えています。

「ディスクが一杯で書けない」というときは、まず `df -h` でどのファイルシステムが一杯かを見て、次に `du -sh *` で、どのディレクトリが大きいかを探していきます。この調べ方は、第 20 章でもう一度使います。ブロックの仕組みは第 11 章、ファイルシステムをつなぐ仕組みは第 12 章で扱います。

:::key この章のまとめ
- Linux のファイルは、`/`（ルートディレクトリ）から始まる **1 本の木**に並ぶ。`/etc` は設定、`/home` はユーザーの場所、`/usr/bin` はコマンド、`/var/log` はログ、`/tmp` は一時ファイル
- シェルは**カレントディレクトリ**にいる。`pwd` で表示し、`cd` で動かす。`cd` だけでホームへ、`cd -` で直前の場所へ
- **絶対パス**は `/` から、**相対パス**はカレントディレクトリからたどる。`.` は自分自身、`..` は 1 つ上
- `ls -l` の 1 行は、種類と権限、リンク数、持ち主、グループ、大きさ、更新時刻、名前。`-a` で隠しファイル（`.` で始まる名前）、`-d` でディレクトリそのもの
- `mkdir`（`-p` で途中も）、`touch`、`cp`（ディレクトリは `-r`）、`mv`（移動と名前の変更）、`rm`（ディレクトリは `-r`）。**`rm` にごみ箱はない**
- 中身を見るのは `cat`（全部）、`head` と `tail`（端だけ）、`less`（1 画面ずつ）。種類は `file` で調べる
- 名前と中身は別のもの。中身と情報は **inode** にあり、ディレクトリは「名前 → inode 番号」の表。`ls -i` と `stat` で見える
- **ハードリンク**は同じ inode へのもう 1 つの名前。**シンボリックリンク**は、指す先のパスを書いた別のファイル。`rm` は名前を 1 つ外すだけ
- `find 場所 条件` は、奥まで探す。`-name` のパターンは引用符で囲む
- `du` はディレクトリが使っている量、`df` はファイルシステムの空き
:::

次の第 4 章では、`ls -l` の `rw-r--r--` の部分を読みます。だれがそのファイルを読めて、書けて、実行できるのか。この章で何度か出てきた `Permission denied` の理由が、そこでわかります。

## 確認問題 {#quiz}

この章の内容を、自分でコマンドを書いて確かめます。ファイルを作る問題では、あなたのコマンドを実行したあとの**ファイルの状態**を、模範解答のものと比べます。

:::quiz 深いディレクトリとファイルを作る
ホームディレクトリの下に、`projects/web/css` というディレクトリを作り、その中に `style.css` という空のファイルを作ってください。`projects` も `web` も、まだありません。

```sh answer
mkdir -p projects/web/css
touch projects/web/css/style.css
```

```sh check
cd /home/you; find projects | sort; stat -c '%F %s' projects/web/css/style.css
```

:::hint
途中のディレクトリも一緒に作るオプションがありました。空のファイルを作るコマンドは `touch` です。
:::
:::

:::quiz 別の場所にいるまま、ファイルを読む
いま、カレントディレクトリは `/var/log` です（問題の準備で移動してあります）。`cd` で移動せずに、あなたのホームディレクトリの `notes` の中にある `todo.txt` の、**最後の 1 行**だけを表示してください。

採点では、`todo.txt` に行を足した状態でも試します。

```sh prep
cd /var/log
```

```sh answer
tail -n 1 ~/notes/todo.txt
```

```sh vary
echo "[ ] find を試す" >> /home/you/notes/todo.txt
```

:::hint
`notes/todo.txt` という相対パスは、いまは `/var/log/notes/todo.txt` を指してしまいます。絶対パスで書くか、`~` を使うか、`..` で上へたどります。最後の何行かを表示するコマンドは `tail` です。
:::
:::

:::quiz 2 種類のリンクを作る
ホームディレクトリで、次の 2 つを作ってください。

1. `memo.txt` の**ハードリンク** `memo2.txt`
2. `notes` ディレクトリを指す**シンボリックリンク** `n`

```sh answer
ln memo.txt memo2.txt
ln -s notes n
```

```sh check
cd /home/you; test memo.txt -ef memo2.txt && echo "same inode"; stat -c '%h %F' memo.txt memo2.txt; stat -c '%F' n; ls n
```

:::hint
どちらも `ln` で作ります。シンボリックリンクには `-s` を付けます。引数の順番は「元（指す先）、新しい名前」です。`cp` で作ったコピーは、inode 番号が別になるので、ハードリンクにはなりません。
:::
:::

:::quiz 奥まで探す
カレントディレクトリ（ホームディレクトリ）から下を奥まで探して、名前が `.txt` で終わる**ふつうのファイル**のパスを、すべて表示してください。ディレクトリは、名前が `.txt` で終わっていても表示しません。行の順番は問いません。

採点では、ファイルやディレクトリを足した状態でも試します。

```sh answer unordered
find . -type f -name '*.txt'
```

```sh vary
mkdir -p notes/old archive.txt
touch notes/old/plan.txt archive.txt/readme.txt notes/old/plan.txt.bak
```

:::hint
`find` に、名前の条件と種類の条件を並べます。名前のパターンは、シェルに展開されないように引用符で囲みます。
:::
:::
