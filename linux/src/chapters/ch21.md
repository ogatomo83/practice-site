## この付録の使い方 {#about}

この章は、読み通すためのものではありません。本文を読んでいて「このコマンドは何だったか」「この番号は何か」と思ったときに、引いてください。

表の右端の「章」は、その項目を説明している場所です。`7.5` は、第 7 章の 5 番目の節という意味で、押すとその節へ飛びます。

コマンドの表は、小さな Linux の `help` と同じ文から作っています。その場で調べたいときは、`help コマンド名` と打つほうが早いでしょう。

```sh run title="help で使い方を調べる"
help grep
help cd
```

## コマンドの早見表 {#commands}

小さな Linux の `/usr/bin` と `/usr/sbin` には、126 個のコマンドがあります。本物の Linux にある同じ名前のコマンドに、出力の形とエラー文を合わせてあります。ただし、オプションは主なものだけです。

「使い方」の `[ ]` は省略できる部分、`…` はくり返せる部分、`A | B` はどちらか、という意味です。

## シェルの書き方 {#shell}

小さな Linux の `sh` は、POSIX のシェルに、bash の書き方の一部を足したものです。この節の表は、どれも小さな Linux で動きます。

### 終了ステータス

| 終了ステータス | 意味 | 章 |
| --- | --- | --- |
| 0 | 成功 | [2.8](ch02.html#status) |
| 1 | 失敗（ふつうの失敗。`grep` なら「1 行も見つからなかった」） | [2.8](ch02.html#status) |
| 2 | 使い方の誤り（オプションの間違いなど）。シェルの構文エラーも 2 | [2.8](ch02.html#status) |
| 126 | ファイルは見つかったが、実行できない（実行権限がない） | [6.1](ch06.html#script) |
| 127 | コマンドが見つからない（`command not found`） | [2.4](ch02.html#path) |
| 128 + n | シグナル n で終わった。130 = SIGINT（Ctrl-C）、137 = SIGKILL、143 = SIGTERM | [8.2](ch08.html#kill) |

```sh run title="終了ステータスを確かめる" error
ls /nofile
echo $?
nosuch
echo $?
```

`ls` は「使い方は正しいが、ファイルがなかった」ので 2、`nosuch` は「コマンドが見つからない」ので 127 です。

### 制御の構文

形だけを並べます。くわしくは第 6 章（[6.6](ch06.html#if)、[6.7](ch06.html#loop)、[6.8](ch06.html#func)）を見てください。

```sh
if 条件のコマンド; then … ; elif 条件のコマンド; then … ; else … ; fi

case "$x" in
  a|b) … ;;
  *.txt) … ;;
  *) … ;;
esac

for f in *.txt; do … ; done
while 条件のコマンド; do … ; done
until 条件のコマンド; do … ; done
while read line; do … ; done < ファイル

名前() { … ; return 0; }
```

`if` と `while` が見ているのは、条件のコマンドの終了ステータスです。`[ "$a" = "$b" ]` の `[` も、1 つのコマンドです。

| `test`（`[ ]`）の式 | 成り立つとき |
| --- | --- |
| `-e パス`　`-f パス`　`-d パス` | ある / 通常のファイルである / ディレクトリである |
| `-r パス`　`-w パス`　`-x パス` | 読める / 書ける / 実行できる |
| `-s パス` | 大きさが 0 でない |
| `-z "$s"`　`-n "$s"` | 文字列が空 / 空でない |
| `"$a" = "$b"`　`"$a" != "$b"` | 文字列が同じ / 違う |
| `"$n" -eq 数`　`-ne`　`-lt`　`-le`　`-gt`　`-ge` | 整数として、等しい / 等しくない / より小さい / 以下 / より大きい / 以上 |
| `! 式`　`式 -a 式`　`式 -o 式` | 否定 / かつ / または |

## シグナルの表 {#signals}

シグナルは 1 番から 31 番までです。番号は、x86-64 や ARM の Linux のものです（[8.2](ch08.html#kill)）。

「デフォルトの動作」は、プロセスがハンドラを登録していないときに、カーネルがすることです（[8.3](ch08.html#default)）。

- **終了**：プロセスを終わらせる
- **終了（コア）**：終わらせて、メモリの中身（コア）をファイルに残す。小さな Linux は、ファイルを作らない
- **無視**：何もしない
- **停止**：プロセスを一時停止する（状態 `T`）
- **再開**：停止しているプロセスを、再び動かす

「シェルの表示」は、そのシグナルで終わった・止まったジョブについて、シェルが出す文です。

### rwx と 8 進数

権限は、持ち主（u）、グループ（g）、その他（o）の 3 組です。1 組は r、w、x の 3 ビットで、8 進数 1 桁で書けます（[4.2](ch04.html#rwx)、[4.3](ch04.html#chmod)）。r は 4、w は 2、x は 1 で、足した数がその組の権限です。

| 8 進数 | 2 進数 | rwx | ファイルでは | ディレクトリでは |
| --- | --- | --- | --- | --- |
| 0 | `000` | `---` | 何もできない | 何もできない |
| 1 | `001` | `--x` | 実行できる | 中へ進める |
| 2 | `010` | `-w-` | 書ける | 中の名前を作る・消す・変える（x も要る） |
| 3 | `011` | `-wx` | 書ける、実行できる | 中の名前を作る・消す・変える（x も要る）、中へ進める |
| 4 | `100` | `r--` | 読める | 一覧を読める |
| 5 | `101` | `r-x` | 読める、実行できる | 一覧を読める、中へ進める |
| 6 | `110` | `rw-` | 読める、書ける | 一覧を読める、中の名前を作る・消す・変える（x も要る） |
| 7 | `111` | `rwx` | 読める、書ける、実行できる | 一覧を読める、中の名前を作る・消す・変える（x も要る）、中へ進める |

カーネルは、3 組のうち、**最初に当てはまった 1 組だけ**を見ます。プロセスの実効 uid がファイルの持ち主と同じなら、持ち主の組です。違っていて、グループが合えばグループの組、どちらでもなければその他の組です（[4.4](ch04.html#check)）。root（uid 0）は、読み書きの検査を受けません。

### よく使うモード

| モード | ls -l の表示 | 意味 | よくある使い道 |
| --- | --- | --- | --- |
| `644` | `-rw-r--r--` | 持ち主は読み書き、ほかは読むだけ | ふつうのファイル（umask 022 のときの既定） |
| `600` | `-rw-------` | 持ち主だけが読み書き | 人に見せないファイル（秘密鍵、日記） |
| `664` | `-rw-rw-r--` | 持ち主とグループは読み書き、その他は読むだけ | グループで共同で書くファイル |
| `755` | `-rwxr-xr-x` | 持ち主は全部、ほかは読むと実行 | コマンド、スクリプト |
| `700` | `-rwx------` | 持ち主だけが全部 | 自分専用のスクリプト |
| `444` | `-r--r--r--` | 全員が読むだけ | 書き換えたくないファイル |
| `755` | `drwxr-xr-x` | 持ち主は全部、ほかは一覧と通過 | ふつうのディレクトリ（umask 022 のときの既定） |
| `700` | `drwx------` | 持ち主だけが入れる | 人に見せないディレクトリ |
| `750` | `drwxr-x---` | 持ち主は全部、グループは一覧と通過、その他は入れない | グループにだけ見せるディレクトリ |
| `775` | `drwxrwxr-x` | 持ち主とグループは全部、その他は一覧と通過 | グループで共同で使うディレクトリ |

```sh run title="数字と rwx の対応を確かめる"
touch memo2.txt
chmod 640 memo2.txt
stat -c '%a %A %n' memo2.txt
chmod u+x,o+r memo2.txt
stat -c '%a %A %n' memo2.txt
```

`chmod` の記号の書き方は、「だれの（u、g、o、a）」「足すか引くか置き換えるか（+、-、=）」「どの権限（r、w、x）」の順です。

### 特別なビット

8 進数の 4 桁目は、特別なビットです（[4.9](ch04.html#special)）。

| ビット | 8 進数 | ls -l の表示 | 意味 | 例 |
| --- | --- | --- | --- | --- |
| setuid | `4000` | 持ち主の x の位置が `s`（`-rwsr-xr-x`） | 実行すると、プロセスの実効 uid が、ファイルの持ち主になる | `/usr/bin/sudo`、`/usr/bin/su`、`passwd` |
| setgid | `2000` | グループの x の位置が `s`（`-rwxr-sr-x`） | ファイル：実効 gid がファイルのグループになる。ディレクトリ：中に作るファイルが、ディレクトリのグループを引き継ぐ | 共同作業のディレクトリ（`drwxrwsr-x`） |
| sticky | `1000` | その他の x の位置が `t`（`drwxrwxrwt`） | ディレクトリ：中のファイルを消したり名前を変えたりできるのは、そのファイルの持ち主（とディレクトリの持ち主と root）だけ | `/tmp` |

x の権限がないのに setuid や setgid をつけると、表示は大文字の `S` になります（sticky なら `T`）。たとえば `chmod 4644` は `-rwSr--r--` です。

## このサイトの Linux と本物の違い {#diff}

この本の「小さな Linux」は、JavaScript で書いた教育用のシミュレータです。システムコールの名前と意味、エラー番号、コマンドの出力の形は、本物に合わせてあります。しかし、本物の Linux の全部を再現してはいません。違いを、まとめておきます。

### 全体

- **カーネルは、JavaScript のシミュレータ**です。機械語は実行しません。`/usr/bin` のコマンドの中身は、ELF に似せた短い印で、実体は JavaScript のプログラムです
- **時間は、仮想の時間**です。システムコール 1 回が 1 ミリ秒で、コマンドを実行している間だけ進みます。起動するたびに、時刻は 2026 年 4 月 1 日 9 時 0 分 0 秒から始まります。本物は、ずっと速く動きます
- **同じ操作は、いつも同じ結果**になります。乱数も、決まった種から作ります。`/dev/urandom` も、ページを開き直して同じ順に実行すれば、同じバイト列を返します。本物は、PID も時刻も乱数も、実行するたびに変わります
- **CPU は 1 つ**です。スレッド、割り込み、カーネルスレッド（本物の `ps -ef` に `[kworker/…]` と出るもの）はありません
- **物理メモリは 64 MiB、ディスクは 64 MiB** です
- **システムコールは 93 個**だけです。そのうち `pivot_root` は、呼ぶといつも ENOSYS で失敗します
- **ユーザーは 4 人**（root、you、alice、bob）です。`su` と `sudo` は、パスワードをたずねません。本物では、`sudo` は自分の、`su` はなる相手のパスワードが要ります
- **ロケールは C** です。エラー文は英語で、並び順はバイトの順です。日本語のファイル名は、そのまま表示します

### シェルとコマンド

- `sh` は、POSIX のシェルに、bash の一部（`local`、`${x/a/b}`、`<<<`、`&>`、`{a,b}` など）を足したものです。配列、`[[ ]]`、`(( ))`、`select`、プロセス置換 `<( )` は使えません。`ulimit` もありません
- コマンドのオプションは、主なものだけです。使えるオプションは、`help コマンド名` に出るものが全部です
- `man` は `help` と同じものを表示します。`less` と `more` は、`cat` と同じように全部を表示して終わります。`top` は、1 回表示して終わります。`clear` は何もしません
- エディタ（`vi`、`nano`）はありません。ファイルを作るには、リダイレクトやヒアドキュメントを使います
- `rm` は、書き込めないファイルを消すときも、確認をたずねません
- `sed` が使える命令は `s`、`p`、`d` だけです。`awk` は簡易版です
- **出力のバッファ**が違います。本物の libc は、出力先が端末なら 1 行ごとに `write` します。小さな Linux のコマンドは、端末でも、4096 バイトたまるか終了するまでためます（[10.7](ch10.html#libc)）
- `(core dumped)` と表示されても、core ファイルは作りません
- `strace` は、本物より行が少なくなります。本物では、`execve` の直後に、共有ライブラリを読み込むための `openat` や `mmap` が 30 行ほど並びます（[10.4](ch10.html#cat)）

### プロセスとシグナル

- `fork` は、内部では「子が実行する関数を渡す」形です。外から見た動き（`clone` が親には子の PID を返し、fd 表やカレントディレクトリが複製される）は、本物と同じです
- 孤児を引き取るのは、いつも PID 1（または PID 名前空間の中の 1 番）です。本物には、ほかのプロセスが引き取り役を名乗る仕組み（subreaper）があります
- `/proc/PID/fdinfo` の `ofd` と `refs` の 2 行は、このサイトだけのものです。ファイル記述が共有されているかどうかを、見えるようにしています

### ファイルシステム

- `/` は ext4 と表示されますが、本物の ext4 のディスク上の形（ブロックグループ、ビットマップ、エクステント、ジャーナル）は持っていません。inode、ディレクトリエントリ、リンク数、ブロックの割り当て、という考え方をまねています
- ファイルを読んでも、atime（最後に読んだ時刻）は変わりません
- ブロックデバイス（`/dev/sda` など）はありません。`mount` でつなげるのは、tmpfs、proc、devtmpfs、sysfs、cgroup2 です。バインドマウント（`mount --bind`）はできません。`-o ro` は、書いても読み取り専用になりません
- `/proc` と `/sys` のファイルは、本文で使うものだけです。本物には、`/proc/sys` だけで千個を超える設定があります

### 仮想メモリ（第 13 章）

- スワップ、巨大ページ、NUMA はありません。メモリが足りないときにページを回収する細かい方針（本物の LRU のリスト、kswapd）もありません
- 番地は、毎回同じです。本物は、実行のたびに番地をずらします（ASLR）
- 1 つのプロセスの領域は、text、data、ヒープ、スタックなど 9 個だけです。本物の `cat` には 20 前後の領域があります。VSZ や RSS の値は、本物より 1 桁ほど小さくなります
- 読むだけのページフォルトでも、フレームを 1 つ割り当てます。本物は、中身が 0 の共有のページを写して、書くまで割り当てを遅らせます
- OOM killer は、メモリをいちばん使っているプロセスを選び、すぐに殺します。本物は、もっと細かい点数で選びます

### スケジューラ（第 14 章）

- CFS を単純にしたものです。周期は 24 tick、最小の持ち時間は 3 tick で、次のプロセスは赤黒木ではなく、順に調べて探します
- リアルタイムのクラス（SCHED_FIFO、SCHED_RR）、CPU の割り当て（アフィニティ）、cgroup ごとの CPU の配分はありません
- 本物の Linux は、バージョン 6.6 からスケジューラが EEVDF という方式に変わっています。「公平に分ける」という考え方は同じです

### ページキャッシュとディスク（第 15 章）

- ディスクは「1 ページ読むのに 5 ミリ秒、一度に 1 つ」という単純な装置です。先読みや、I/O の順番を並べ替える仕組みはありません
- 書き戻しは、ファイル単位です。途中で電源が切れると、そのファイルの書き戻し中の分は、全部失われます。ファイルの作成、削除、名前の変更は、すぐディスクに書かれたものとして扱います
- `free` の buffers は、いつも 0 です

### ネットワーク（第 16 章）

- 通信できるのは、自分自身あてだけです。IPv4 の TCP と、UNIX ドメインソケットだけがあります。UDP、IPv6、DNS、経路の選択、ファイアウォールはありません。`ping` は、表示だけです
- TCP は、状態の移り変わりと番号だけをまねています。再送、ウィンドウ、輻輳制御、パケットの喪失はありません
- 自動で割り当てるポートは、32768 から順です。本物は、ばらばらの番号を選びます

### 起動と init（第 17 章）

- ファームウェア、ブートローダ、initramfs は、ログの行として出てくるだけです
- PID 1 は、systemd そのものではありません。unit ファイルの一部（`ExecStart`、`Restart`、`User` など）だけを読む、小さな init です。`After=` などの依存関係は読みません。target は `multi-user.target` だけです
- `systemctl` と `journalctl` の出力の形は、本物と照合できていません（下の「照合」を参照）
- 電源を切っても、次のコマンドのために、すぐ起動し直します

### コンテナ（第 19 章）

- 名前空間は、PID、マウント、UTS（ホスト名）などです。ユーザー名前空間はないので、`unshare` は root でしか使えません
- `pivot_root`、overlayfs、capabilities、seccomp はありません。本物のコンテナは、これらも組み合わせています
- cgroup で制限できるのは、プロセスの数（pids）とメモリ（memory）だけです。CPU や I/O の制限はありません

### 本物との照合

コマンドの出力の形は、Debian（stable）のコンテナで同じコマンドを実行して、見比べてあります。

| 照合したもの | 照合できなかったもの（資料をもとに書いた） |

| `strace` の行の形（引数、戻り値、シグナルの行） | `dmesg`（コンテナの中では読めない） |
| `nc`、`ss`、`ip`、`ping`、`curl` の出力 | `fincore`、`lsof` の細かい形 |

本物の Linux で同じコマンドを打つと、PID、時刻、番地、大きさは違って当然です。出力の形や意味が違っていたら、上の一覧にあるかを確かめてください。本物の Linux を手元に用意するいちばん手軽な方法は、Docker で `docker run -it --rm debian` を実行することです（コンテナの仕組みは第 19 章）。
