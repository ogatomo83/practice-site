## 端末とシェル：文字を運ぶものと、読むもの {#terminal}

Linux を使うとは、多くの場合、**コマンド**（命令の文）を文字で打ち、結果を文字で受け取ることです。このとき、画面の向こうでは 2 つのものが働いています。**端末**と**シェル**です。この 2 つは、よく混同されます。

- **端末**（ターミナル）は、文字を運ぶ係。あなたが押したキーをプログラムに届け、プログラムが出した文字を画面に映す。昔はキーボードと画面（もっと昔は印字機）が付いた本物の機械だった。今は、ウィンドウの中でそのまねをするソフトウェア（端末エミュレータ）を使う
- **シェル**は、文字を読む係。端末から届いた 1 行を読み、意味を解釈して、コマンドを実行する。シェルは特別な仕組みではなく、`ls` や `cat` と同じ、ふつうの**プログラム**の 1 つ

シェルが「ふつうのプログラム」であることを、確かめましょう。`ps` は、いま動いているプログラム（**プロセス**）の一覧を表示します。`tty` は、自分がつながっている端末の名前を表示します。

```sh run title="シェルも 1 つのプロセス"
ps
tty
```

`ps` の出力の `sh` が、あなたのコマンドを読んでいるシェルです。`TTY` の列の `pts/0` と、`tty` が表示した `/dev/pts/0` は、同じ端末を指しています。Linux では、端末も 1 つのファイルとして見えます（第 12 章で扱います）。

シェルにはいくつも種類があります。

| シェル | 特徴 |
| --- | --- |
| `sh` | Unix の昔からのシェル。POSIX（第 1 章）が文法を決めている。どの Unix 系の OS にも必ずある |
| `bash` | GNU プロジェクトのシェル。`sh` を拡張したもの。多くの Linux で、ログインしたときの既定のシェル |
| `zsh` | 補完などが強力なシェル。macOS の既定 |
| `dash` | 小さくて速い `sh`。Debian や Ubuntu では、`/bin/sh` の実体がこれ |

このサイトの Linux のシェルは `sh` です。POSIX の `sh` の文法に、`bash` の便利な書き方を少し足してあります。この章で覚えることは、どのシェルでもそのまま通じます。

## プロンプトを読む {#prompt}

シェルは、コマンドを受け付けられるようになると、**プロンプト**を出して待ちます。このサイトのプロンプトは `you@zukai:~$ ` です。短い文字の中に、4 つの情報が入っています。

| 部分 | 意味 | 確かめるコマンド |
| --- | --- | --- |
| `you` | いまのユーザーの名前 | `whoami` |
| `zukai` | この計算機の名前（ホスト名） | `hostname` |
| `~` | いまいるディレクトリ。`~` はホームディレクトリの略 | `pwd` |
| `$` | 一般ユーザーの印。管理者（root）なら `#` になる | |

```sh run title="プロンプトの中身を、コマンドで確かめる"
whoami
hostname
pwd
```

`pwd`（print working directory）は、いまいるディレクトリを表示します。`/home/you` が、あなたの**ホームディレクトリ**（自分のファイルを置く場所）です。プロンプトでは、これを `~` と短く書いています。

次のブロックは、管理者である **root** のシェルで実行します。プロンプトの形を見比べてください。

```sh run root title="root のプロンプト"
whoami
pwd
```

プロンプトの最後が `#` になりました。root は、どのファイルでも読み書きでき、システムを壊すこともできるユーザーです。`#` のプロンプトを見たら、「いまは何でもできてしまう」と気を引き締める。これが Linux を使う人の習慣です。ユーザーと権限は、第 4 章で扱います。

:::note 本に出てくる $ は、打たない
Linux の解説では、コマンドの例を `$ ls -l` のように書くことがよくあります。先頭の `$` はプロンプトを表しているだけなので、打つのは `ls -l` の部分です。`#` で始まる例は、「root で実行する」という意味です。
:::

## コマンド、オプション、引数 {#args}

シェルは、受け取った 1 行を**空白で区切って**、単語に分けます。最初の単語が**コマンドの名前**、残りが**引数**（ひきすう。コマンドに渡す情報）です。引数のうち、`-` で始まり、コマンドの動きを切り替えるものを**オプション**と呼びます。

```fig layout コマンドの 1 行を単語に分ける。最初の単語がコマンドの名前で、残りはすべて引数としてコマンドに渡される
{
  unit: 13,
  rows: [
    { label: '打った 1 行', cells: [{ t: 'ls', w: 4, kind: 'accent' }, { t: '-l', w: 4, kind: 'stack' }, { t: '-a', w: 4, kind: 'stack' }, { t: 'notes', w: 7, kind: 'heap' }] },
    { label: '役割', cells: [{ t: '名前', w: 4, kind: 'accent' }, { t: 'オプション', w: 8, kind: 'stack' }, { t: '引数', w: 7, kind: 'heap' }], note: '何を、どう、何に対して' },
  ],
}
```

`ls` で試します。`ls` は、ファイルの一覧を表示するコマンドです。

```sh run title="引数なし、引数あり"
ls
ls notes
```

引数がなければ、`ls` はいまいるディレクトリの中身を表示します。`notes` という引数を渡すと、`notes` ディレクトリの中身を表示します。

オプションを付けると、表示のしかたが変わります。

```sh run title="オプションを付ける"
ls -l notes
ls -l -a notes
ls -la notes
```

- `-l`（long）は、1 行に 1 つずつ、詳しい情報を付けて表示する。各列の読み方は、第 3 章で扱う
- `-a`（all）は、`.` で始まる名前のものも表示する。`.` と `..` が増えた（これも第 3 章）
- 1 文字のオプションは、`-l -a` を `-la` のようにまとめて書ける。2 行目と 3 行目の出力は同じ

オプションには、`--all` のように `--` で始まる長い名前のものもあります。`ls -a` と `ls --all` は同じ意味です。

単語の間の空白は、いくつあっても同じです。シェルが単語に分けるときに、空白は捨てられます。

```sh run title="空白はいくつでも同じ"
echo a b c
echo a      b      c
```

`echo` は、受け取った引数を、空白 1 つで区切って表示するコマンドです。2 行目でも、`echo` に届く引数は `a`、`b`、`c` の 3 つだけです。空白をそのまま渡す方法は、この章の「引用符と展開」で扱います。

知らないオプションを渡すと、コマンドはエラーを出します。

```sh run error title="知らないオプション"
ls -z
```

:::note オプションの形は、コマンドごとの約束
`-l` がどういう意味かは、シェルではなく、それぞれのコマンドが決めています。シェルの仕事は、単語に分けて渡すところまでです。`ls -l` の `-l` と、あとで出てくる `wc -l` の `-l` は、別の意味です。とはいえ、`-a` は「全部」、`-r` は「再帰的に（中まで）」または「逆順」、`-v` は「詳しく」、`-h` は「人が読みやすく」のように、よくある習慣はあります。
:::

## コマンドはどこにあるのか：PATH {#path}

`ls` と打つと、シェルは `ls` というプログラムを起動します。そのプログラムは、どこにあるのでしょうか。`which` で調べられます。

```sh run title="コマンドの実体の場所"
which ls
which cat whoami
```

`ls` の実体は、`/usr/bin/ls` というファイルです。コマンドとは、**実行できるファイル**のことです。`/usr/bin` の中を見てみましょう。

```sh run title="/usr/bin の中身"
ls /usr/bin
```

これまでに使った `cat`、`echo`、`ls`、`ps`、`whoami` が、ファイルとして並んでいます。

では、`ls` とだけ打ったのに、シェルはなぜ `/usr/bin/ls` を見つけられたのでしょうか。答えは、**PATH**（パス）という名前の変数です。

```sh run title="PATH の中身"
echo $PATH
```

PATH には、ディレクトリの名前が `:` で区切って並んでいます。シェルは、コマンドの名前に `/` が入っていなければ、PATH のディレクトリを**左から順に**探し、最初に見つかったファイルを実行します。

どこにもなければ、シェルは `command not found` と言います。次のブロックは、シェル自身がカーネルに頼んだこと（システムコール）も表示します。`nosuch` というコマンドを、シェルが 3 か所で探して、あきらめる様子が見えます。

```sh run error strace="all" title="見つからないコマンドを、シェルが探す様子"
nosuch
```

`stat` は、「このファイルはあるか」をカーネルに尋ねるシステムコールです。PATH の 3 つのディレクトリの順に尋ね、3 回とも `ENOENT`（そのようなファイルはない）が返っています。図 2-3 のとおりの順番です。

### PATH にないコマンドを実行する

PATH を書き換えると、何が起きるでしょうか。実験のために、PATH を存在しないディレクトリだけにしてみます。

```sh run error title="PATH を壊してみる"
OLD=$PATH
PATH=/nowhere
ls
```

さっきまで動いていた `ls` が、`command not found` になりました。`ls` のファイルが消えたわけではありません。シェルが探しに行かなくなっただけです。`/` を含む名前で場所を直接書けば、PATH を使わずに実行できます。

```sh run title="場所を直接書けば動く。PATH を戻す"
/usr/bin/ls notes
PATH=$OLD
ls notes
```

逆に、PATH にディレクトリを足せば、自分で作ったプログラムを名前だけで呼べるようになります。小さなコマンドを作ってみましょう。中身の書き方は第 6 章、`chmod +x`（実行できるようにする）は第 4 章で扱います。ここでは「`bin/greet` という実行できるファイルを作った」とだけ読んでください。

```sh run title="自分のコマンドを作る"
mkdir bin
echo 'echo "hello from greet"' > bin/greet
chmod +x bin/greet
ls -l bin
```

```sh run error title="まだ PATH にないので、見つからない"
greet
```

```sh run title="PATH に足すと、名前だけで呼べる"
PATH=$PATH:/home/you/bin
greet
which greet
```

:::warn いまいるディレクトリは、探してくれない
`hello.sh` のような、いまいるディレクトリにあるプログラムも、名前だけでは実行できません。PATH にないからです。実行するには `./hello.sh` のように、`/` を含む形で書きます（`.` は「いまいるディレクトリ」。第 3 章）。これは安全のための決まりです。もし「いまいるディレクトリ」が先に探されると、だれかが置いた `ls` という名前の偽物を、うっかり実行してしまいます。
:::

## シェル自身が実行する：組み込みコマンド {#builtin}

すべてのコマンドが、`/usr/bin` のファイルというわけではありません。`type` は、ある名前がコマンドとしてどう解釈されるかを教えてくれます。

```sh run title="type で種類を調べる"
type ls
type cd
type echo
type if
```

- `ls` は `/usr/bin/ls`。シェルの外にある、別のプログラム（**外部コマンド**）
- `cd` と `echo` は shell builtin。シェルの中に作り込まれた**組み込みコマンド**
- `if` は shell keyword。シェルの文法の一部（第 6 章）

外部コマンドと組み込みコマンドでは、実行のしかたが違います。次の 2 つのブロックで、シェルがカーネルに頼んだことを見比べてください。まず、組み込みの `pwd` です。

```sh run strace="all" title="組み込みコマンド：シェルが自分で実行する"
pwd
```

シェルが自分で `write`（画面に書く）をしています。そのあとの `wait4` は、終わった子プロセスが残っていないかをシェルが確かめているだけで、`ECHILD`（子プロセスはいない）が返っています。新しいプロセスは 1 つも作られていません。次は、外部コマンドの `whoami` です。

```sh run strace="all" title="外部コマンド：新しいプロセスを作って実行する"
whoami
```

列がずっと長くなりました。いまは、次の 3 つだけ見つけてください。

1. `clone`：シェルが、自分の複製である新しいプロセス（子プロセス）を作る
2. `execve("/usr/bin/whoami", ...)`：子プロセスが、`whoami` のプログラムに入れ替わる
3. `wait4`：シェルは、子プロセスが終わるのを待つ

外部コマンドは、打つたびに新しいプロセスが 1 つ生まれ、仕事をして、消えます。この仕組みは、第 7 章の主題です。

### なぜ cd は組み込みなのか

`cd`（change directory）は、いまいるディレクトリを変えるコマンドです。「いまいるディレクトリ」は、プロセスが 1 つずつ持っている情報です。もし `cd` が外部コマンドだったら、子プロセスが自分のディレクトリを変えて、そのまま終わるだけです。シェル自身は、もとの場所から動きません。シェルの状態を変えるコマンドは、シェル自身が実行するしかないのです。

```sh run error title="cd は /usr/bin にない"
which cd
```

`which` は PATH の中のファイルを探すコマンドなので、組み込みコマンドは見つけられません。何も表示せず、失敗で終わります。コマンドの種類を調べるには、`which` より `type` のほうが確かです。

:::note 両方にあるコマンド
`echo` や `pwd` は、組み込みコマンドでもあり、`/usr/bin/echo` というファイルでもあります。名前だけで打つと、組み込みが優先されます。よく使うコマンドは、プロセスを作る手間を省くために、シェルに作り込まれています。
:::

## 変数と環境変数 {#vars}

### シェル変数

シェルは、名前を付けて値を覚えておけます。これが**変数**です。`名前=値` で入れ、`$名前` で取り出します。

```sh run title="変数に入れて、取り出す"
name=Linux
echo $name
echo "I am learning $name."
```

`=` の両側に空白を入れてはいけません。空白を入れると、シェルは 1 行を単語に分けてしまい、`name` をコマンドの名前だと解釈します。

```sh run error title="= の前後に空白を入れると"
name = Linux
```

### 環境変数：子プロセスに渡る変数

いま作った `name` は、このシェルの中だけの変数（**シェル変数**）です。シェルが起動するコマンドには伝わりません。確かめるために、もう 1 つシェルを起動して、そこで `$name` を表示させます。`sh -c '…'` は、新しい `sh` を起動して、引用符の中のコマンドを実行させる書き方です。

```sh run title="シェル変数は、子プロセスに伝わらない"
sh -c 'echo "name is [$name]"'
```

`[ ]` の中は空です。子のシェルは `name` を知りません。

`export` を使うと、変数が**環境変数**になります。環境変数は、シェルが起動するすべてのコマンドに、コピーされて渡ります。

```sh run title="export すると伝わる"
export name
sh -c 'echo "name is [$name]"'
```

| `HOME` | ホームディレクトリ。`cd` を引数なしで打ったときの行き先 |
| `USER` | ユーザーの名前 |
| `SHELL` | ログインしたときに起動するシェル |
| `PATH` | コマンドを探すディレクトリの並び（前の節） |
| `LANG` | 言語と文字コード。メッセージの言語や、並べ替えの順番に影響する |
| `PWD` | いまいるディレクトリ。シェルが `cd` のたびに書き換える |

PATH が環境変数であることには、意味があります。シェルから起動されたプログラムが、さらに別のプログラムを起動するときにも、同じ PATH で探せるからです。

1 回のコマンドのためだけに環境変数を渡したいときは、コマンドの前に `名前=値` を書きます。シェル自身の変数は変わりません。

```sh run title="1 回だけ環境変数を渡す"
greeting=hello sh -c 'echo "greeting is [$greeting]"'
echo "greeting is [$greeting]"
```

変数を消すには `unset` を使います。

```sh run title="変数を消す"
unset name
echo "name is [$name]"
```

設定されていない変数を取り出しても、エラーにはなりません。空の文字になるだけです。変数名の打ち間違いに気づきにくいので、注意してください。

## 引用符と展開 {#quoting}

シェルは、コマンドを実行する前に、1 行の中の特別な文字を別のものに置き換えます。これを**展開**と呼びます。`$name` が `Linux` に変わったのも、展開の 1 つです。大事なのは、**展開するのはシェルで、コマンドは展開が済んだ結果しか受け取らない**ことです。

### 3 つの展開

**変数の展開**は、もう見ました。`$名前` が値に置き換わります。うしろに文字を続けたいときは、`${名前}` と書いて、名前の範囲をはっきりさせます。

```sh run title="変数の展開"
echo $HOME
echo ${USER}_backup
```

**コマンド置換**は、`$(コマンド)` を、そのコマンドの出力に置き換えます。

```sh run title="コマンド置換"
echo "I am $(whoami) on $(hostname)."
today=$(date)
echo "today: $today"
```

**ワイルドカード**（パス名展開、グロブともいう）は、`*` や `?` を含む単語を、当てはまるファイルの名前の並びに置き換えます。

| 記号 | 当てはまるもの |
| --- | --- |
| `*` | 0 文字以上の、どんな文字の並びでも |
| `?` | どんな文字でも 1 文字 |
| `[abc]` | `a` か `b` か `c` のどれか 1 文字。`[a-z]` のように範囲でも書ける |

```sh run title="ワイルドカード"
echo *.txt
echo notes/*
echo [fm]*.txt
echo ????.txt
```

`echo *.txt` を実行したとき、`echo` が受け取ったのは `*.txt` ではありません。シェルが置き換えた `fruits.txt memo.txt numbers.txt poem.txt` という 4 つの引数です。`echo` は、`*` のことを何も知りません。

当てはまるファイルが 1 つもないときは、置き換えは起きず、打った文字のまま渡されます。

```sh run title="当てはまるファイルがないとき"
echo *.md
```

ほかに、`~` をホームディレクトリに置き換える展開と、`$((式))` を計算の結果に置き換える展開があります。

```sh run title="~ と計算"
echo ~
echo $((1 + 2 * 3))
```

### 引用符：展開を止める、空白を守る

空白や `$` や `*` を、特別な意味なしでそのまま渡したいときは、**引用符**で囲みます。引用符は 2 種類あり、強さが違います。

| 書き方 | 変数と `$( )` | ワイルドカード | 空白 |
| --- | --- | --- | --- |
| 引用符なし | 展開する | 展開する | 単語の区切りになる |
| `"…"`（二重引用符） | **展開する** | 展開しない | そのまま残る |
| `'…'`（一重引用符） | 展開しない | 展開しない | そのまま残る |
| `\` + 1 文字 | 次の 1 文字だけ、特別な意味を消す | | |

```sh run title="引用符の強さを比べる"
echo $HOME *.txt
echo "$HOME *.txt"
echo '$HOME *.txt'
echo \$HOME \*.txt
```

1 行目はどちらも展開され、2 行目は変数だけが展開され、3 行目と 4 行目は何も展開されません。

引用符は、空白を守るためにも使います。

```sh run title="空白を守る"
echo "a      b      c"
```

前の節では、空白をいくつ入れても `a b c` になりました。今度は `" "` で囲んだので、空白ごと 1 つの引数として `echo` に届きます。

空白を含む名前のファイルを扱うとき、引用符を忘れると困ったことになります。`touch` は、空のファイルを作るコマンドです。

```sh run title="空白を含むファイル名"
touch "my file.txt"
ls
```

```sh run error title="引用符を忘れると、2 つの引数になる"
ls -l my file.txt
```

`ls` は、`my` と `file.txt` という 2 つのファイルを探して、どちらもないと言っています。引用符で囲めば、1 つの名前として渡ります。

```sh run title="引用符で囲めば 1 つの引数"
ls -l "my file.txt"
rm "my file.txt"
```

変数の中身に空白が入っているときも同じです。**変数は、いつも `"$name"` のように二重引用符で囲む**と覚えておくと、事故が減ります。

```sh run title="変数は二重引用符で囲む"
list=$(ls notes)
echo "$list"
echo $list
```

`ls notes` の出力は 2 行です。`"$list"` と囲めば、改行ごとそのまま `echo` に渡ります。囲まないと、シェルが空白と改行で単語に分け直すので、改行が消えて 1 行になります。

## 終了ステータス：うまくいったかどうか {#status}

コマンドは、終わるときに 0〜255 の数を 1 つ、シェルに返します。これが**終了ステータス**です。**0 が成功、0 以外が失敗**を表します。直前のコマンドの終了ステータスは、`$?` という特別な変数に入っています。

```sh run title="成功は 0"
ls notes
echo $?
```

```sh run error title="失敗は 0 以外"
ls nofile
echo $?
```

`ls` は、ファイルが見つからないと 2 を返しました。このブロックに「エラーになる」の印が付いているのは、途中のコマンドが失敗しているからです。最後の `echo` 自身は成功しています。

0 以外の数の意味は、コマンドごとに決まっています。ただし、シェルが使う数には決まりがあります。

| 終了ステータス | 意味 |
| --- | --- |
| 0 | 成功 |
| 1〜125 | 失敗。意味はコマンドによる（多くは 1。`ls` は 2 も使う） |
| 126 | ファイルは見つかったが、実行できない（実行する権限がない、など） |
| 127 | コマンドが見つからない（`command not found`） |
| 128 + n | シグナル n で終了させられた（第 8 章） |

```sh run error title="127 と 126"
nosuch
echo $?
./hello.sh
echo $?
```

`hello.sh` は、ファイルはあるのに `Permission denied`（許可がない）で 126 です。実行する権限が付いていないからです。権限の付け方は、第 4 章で扱います。

「成功が 0」というのは、最初は逆に感じるかもしれません。こう考えてください。成功のしかたは 1 通りですが、失敗の理由はたくさんあります。だから、失敗のほうに 1 以上の数を割り当てて、区別できるようにしてあるのです。

`true` と `false` は、何もせずに、それぞれ 0 と 1 を返すだけのコマンドです。

```sh run title="true と false"
true; echo $?
false; echo $?
```

`;` は、1 行に複数のコマンドを並べる記号です。左から順に実行されます。

### 失敗は「エラー」とは限らない

終了ステータスは、「はい / いいえ」の答えとしても使われます。`grep` は、ファイルの中から、指定した文字を含む行を探すコマンドです（第 5 章）。見つかれば 0、見つからなければ 1 を返します。

```sh run title="grep の終了ステータス"
grep apple fruits.txt; echo $?
grep kiwi fruits.txt; echo $?
```

`kiwi` は見つからなかったので、何も表示されず、終了ステータスは 1 です。これは故障ではなく、「なかった」という答えです。

終了ステータスを使うと、「うまくいったら次を実行する」という書き方ができます。

- `A && B`：A が成功（0）したときだけ、B を実行する
- `A || B`：A が失敗（0 以外）したときだけ、B を実行する

```sh run title="&& と ||"
grep kiwi fruits.txt || echo "kiwi is not in the list"
mkdir backup && echo "backup is ready"
```

終了ステータスで動きを変える書き方（`if` など）は、第 6 章のシェルスクリプトで本格的に使います。

## 調べる、楽をする：help、man、履歴、補完 {#help}

### 使い方を調べる

コマンドの使い方を忘れたら、コマンド自身に聞きます。このサイトの Linux では、`help` で一覧が出て、`help コマンド名` で使い方が出ます。

```sh run title="help で使い方を調べる"
help ls
help cd
help type
```

`[ ]` で囲まれた部分は「省略できる」、`…` は「いくつでも並べられる」という意味です。これは、本物のマニュアルでも同じ書き方です。

本物の Linux で使い方を調べる方法は、3 つあります。

| 方法 | 対象 | 中身 |
| --- | --- | --- |
| `man ls` | 外部コマンド、設定ファイル、システムコールなど | 正式な**マニュアル**。`q` で閉じる、`/文字` で検索、スペースで次のページ |
| `ls --help` | ほとんどの外部コマンド | オプションの一覧を短く表示する |
| `help cd` | bash の組み込みコマンド | 組み込みコマンドの説明 |

```console
$ man ls
LS(1)                    User Commands                    LS(1)

NAME
       ls - list directory contents

SYNOPSIS
       ls [OPTION]... [FILE]...

DESCRIPTION
       List information about the FILEs (the current directory by default).
       ...
```

`LS(1)` の `(1)` は、マニュアルの**章**の番号です。1 章がコマンド、2 章がシステムコール、5 章が設定ファイルの書式です。この本の後半で `open(2)` のような書き方が出てきたら、「マニュアルの 2 章にある open」、つまりシステムコールの `open` という意味です。

:::note このサイトの Linux では
`man` は `help` と同じものを表示します。本物のマニュアルは入っていません。外部コマンドの `--help`（`ls --help` など）は、`help 名前` と同じ短い説明を出します。組み込みコマンドは、`help 名前` で調べてください。
:::

### 履歴と補完

本物のシェルには、打つ量を減らすための仕組みがあります。この 2 つは、キーを押して使うものなので、本文のブロックでは試せません。サイドバーの**実験場**で試してください。

**履歴**は、前に打ったコマンドを呼び戻す仕組みです。

| キー | 動き |
| --- | --- |
| ↑ / ↓ | 前に打ったコマンド / 次のコマンドを、入力行に呼び戻す |
| Ctrl + R | 履歴を検索する（bash、zsh）。文字を打つと、それを含むコマンドが出る |

打ったコマンドは、シェルが覚えています。組み込みコマンドの **`history`** で、番号つきの一覧が出ます。`history 3` なら、最後の 3 つです（いま打った `history 3` 自身も入ります）。

```sh run title="打ったコマンドの履歴"
echo one
echo two
history 3
```

先頭に空白を入れて打ったコマンドは、履歴に残りません（本物の bash では、`HISTCONTROL` という変数でこの動きを選びます。Debian や Ubuntu の既定の設定は、こうなっています）。パスワードのような、残したくない文字を含むコマンドに使います。

**補完**は、名前の途中まで打って Tab キーを押すと、残りをシェルが補ってくれる仕組みです。

```console
$ cat fr<Tab>          → cat fruits.txt     候補が 1 つなら、最後まで補う
$ cat n<Tab>           → cat n              候補が複数（notes、numbers.txt）なら、共通の部分まで
$ cat n<Tab><Tab>      → notes/  numbers.txt   もう 1 回押すと、候補の一覧が出る
$ who<Tab>             → whoami             最初の単語なら、コマンドの名前を補う
```

補完は、楽をするためだけのものではありません。Tab を押して補われなければ、その名前のファイルは**ない**ということです。長い名前を打ち間違えずに済みますし、実行する前に間違いに気づけます。慣れた人ほど、数文字ごとに Tab を押しています。

端末でよく使うキーも、まとめておきます。

| キー | 動き |
| --- | --- |
| Ctrl + C | 実行中のコマンドを止める（第 8 章で、何が起きているかを見る） |
| Ctrl + D | 入力の終わりを知らせる。プロンプトで押すと、シェルが終わる |
| Ctrl + L | 画面を消す（`clear` コマンドと同じ） |
| Ctrl + A / Ctrl + E | 入力行の先頭 / 末尾へ移動する |

:::key この章のまとめ
- **端末**は文字を運び、**シェル**はその 1 行を解釈してコマンドを実行する。シェルも 1 つのプログラム（プロセス）
- **プロンプト** `you@zukai:~$ ` は、ユーザー、ホスト名、いまいるディレクトリを表す。`#` は root の印
- シェルは 1 行を空白で単語に分ける。最初が**コマンドの名前**、残りが**引数**。`-` で始まる引数が**オプション**
- 外部コマンドは実行できるファイル。シェルは **PATH** のディレクトリを左から順に探す。なければ `command not found`（127）。`which` と `type` で調べられる
- `cd` のようにシェルの状態を変えるコマンドは**組み込みコマンド**。外部コマンドは、新しいプロセスを作って実行する
- 変数は `名前=値`（空白なし）で入れ、`$名前` で取り出す。`export` した**環境変数**だけが、子プロセスにコピーされる
- シェルは実行の前に**展開**する：変数 `$name`、コマンド置換 `$(…)`、ワイルドカード `*` `?` `[…]`。コマンドは展開の結果しか受け取らない
- `"…"` は空白を守り、変数は展開する。`'…'` は何も展開しない。変数は `"$name"` と囲む
- **終了ステータス**は 0 が成功、0 以外が失敗。`$?` で見る。`&&` と `||` でつなげられる
- 使い方は `help`（本物では `man` と `--help`）。**履歴**（↑）と**補完**（Tab）は実験場で試す
:::

## 確認問題 {#quiz}

この章の内容を、自分でコマンドを書いて確かめます。どの問題も、あなたのコマンドと模範解答を、まっさらな Linux で実行して、標準出力（画面に出た文字のうち、エラーの文を除いたもの）を比べます。

:::quiz コマンドの実体を探す
`sort` と打ったときに実行されるファイルの場所を、`/` から始まる形で 1 行で表示してください。

採点では、PATH の中に別の `sort` を置いた状態でも試します。

```sh answer
which sort
```

```sh vary
sudo sh -c 'echo "echo fake" > /usr/local/bin/sort; chmod +x /usr/local/bin/sort'
```

:::hint
PATH を左から順に探して、最初に見つかったファイルの場所を表示するコマンドがありました。`type` は「sort is …」という文になるので、この問題の答えにはなりません。
:::
:::

:::quiz ワイルドカードで名前を並べる
`notes` ディレクトリの中にある、名前が `.txt` で終わるファイルを、`echo` とワイルドカードを使って 1 行に表示してください。先頭に `files:` という単語を付けます。最初の状態では、次のように表示されれば正解です。

```text
files: notes/ideas.txt notes/todo.txt
```

採点では、`notes` にファイルを足した状態でも試します。

```sh answer
echo files: notes/*.txt
```

```sh vary
touch notes/extra.txt notes/skip.md
```

:::hint
`*` は、0 文字以上のどんな文字の並びにも当てはまります。引用符で囲むと展開されなくなるので、ワイルドカードの部分は囲みません。
:::
:::

:::quiz 環境変数を子プロセスに渡す
ホームディレクトリに `report.sh` というスクリプトがあります。中身は、環境変数 `LEVEL` の値を表示する 1 行です。

`LEVEL` を `3` にして、`sh report.sh` を実行してください。`level=3` を含む行が表示されれば正解です。

```sh prep
echo 'echo "level=$LEVEL"' > report.sh
```

```sh starter
LEVEL=3
sh report.sh
```

```sh answer
export LEVEL=3
sh report.sh
```

```sh vary
echo 'echo "report: level=$LEVEL (user $USER)"' > report.sh
```

:::hint
入力欄に最初から入っているコマンドは、そのままでは `level=` としか表示しません。`sh report.sh` は新しいシェル（子プロセス）で実行されます。シェル変数は、子プロセスに伝わりません。
:::
:::

:::quiz 終了ステータスを表示する
`cd backup` を実行して、`backup` ディレクトリへ移動を試み、その直後に `cd` の終了ステータスを表示してください。

最初の状態では、`backup` というディレクトリはありません（本文のブロックで作ったものは、採点には影響しません）。採点では、`backup` がある状態でも試します。

```sh answer
cd backup; echo $?
```

```sh vary
mkdir backup
```

:::hint
直前のコマンドの終了ステータスは、特別な変数に入っています。`&&` でつなぐと、`cd` が失敗したときに何も表示されなくなります。
:::
:::
