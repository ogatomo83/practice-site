## 3 つの口：標準入力・標準出力・標準エラー {#stdio}

第 1 章で、Unix の考え方を見ました。「1 つのことをうまくやる小さなプログラムを、つないで使う」です。この章では、それを自分の手でやります。

つなぐためには、プログラムに「つなぎ口」が要ります。Linux のプログラムは、起動した時点で、はじめから 3 つの口を持っています。

```fig graph プログラムが最初から持っている 3 つの口。何もしなければ、3 つとも端末（キーボードと画面）につながっている
{
  col: 250, row: 80,
  nodes: [
    { id: 'kb', label: 'キーボード', x: 0, y: 0.5, kind: 'ext', mono: false },
    { id: 'p', label: 'プログラム', sub: 'sort、cat、grep …', x: 1, y: 0.5, kind: 'accent', mono: false },
    { id: 'out', label: '画面', sub: 'ふつうの出力', x: 2, y: 0, kind: 'ext', mono: false },
    { id: 'err', label: '画面', sub: 'エラーの知らせ', x: 2, y: 1, kind: 'ext', mono: false },
  ],
  edges: [
    { from: 'kb', to: 'p', label: '0：標準入力' },
    { from: 'p', to: 'out', label: '1：標準出力' },
    { from: 'p', to: 'err', label: '2：標準エラー', style: 'bad' },
  ],

```

| 番号 | 名前 | 英語 | 役目 | 何もしないときの相手 |
| --- | --- | --- | --- | --- |
| 0 | 標準入力 | stdin | データを読む口 | キーボード |
| 1 | 標準出力 | stdout | 結果を書く口 | 画面 |
| 2 | 標準エラー | stderr | エラーや注意を書く口 | 画面 |

0、1、2 という番号は、**ファイルディスクリプタ**（fd）と呼ばれるものです。正体は第 9 章で見ます。今は「口の番号」と思ってください。

### 標準入力から読む

`sort` は、行を並べ替えるコマンドです。ファイル名を渡さずに起動すると、標準入力、つまりキーボードから読みます。次のブロックでは、キーボードから 3 行を打ったことにしてあります（実験場の端末で試すときは、行を打ち終えたら Ctrl-D で「入力の終わり」を知らせます）。

```sh run stdin="banana\napple\ncherry\n" title="sort にキーボードから 3 行を渡す"
sort
```

打った 3 行（banana、apple、cherry）が、並べ替えられて出てきました。`sort` は「ファイルを並べ替えるプログラム」というより、「**標準入力から読み、並べ替えて、標準出力に書く**プログラム」なのです。

### 出力の口は 2 つある

出力の口が 2 つあることは、ふだんは気づきません。どちらも画面に出るからです。あるファイルと、ないファイルを、いちどに `ls` してみます。

```sh run error title="結果とエラーが、両方とも画面に出る"
ls fruits.txt nope.txt
```

2 行が出ました。`fruits.txt` は標準出力に、`ls: cannot access …` は標準エラーに書かれています（このサイトの画面では、標準エラーの行に色が付きます）。なぜ 2 つに分けてあるのかは、すぐあとでわかります。

### 口の行き先を見る

3 つの口がどこにつながっているかは、`/proc/self/fd` で見えます。`/proc/self` は「このコマンド自身のプロセス」を指す特別なディレクトリです。

```sh run title="3 つの口の行き先"
ls -l /proc/self/fd
```

`0`、`1`、`2` が、どれも `/dev/pts/0` を指しています。`/dev/pts/0` は、あなたの端末を表すファイルです。キーボードも画面も、プログラムからは 1 つの「端末」というファイルに見えます。（`3` は、`ls` がこのディレクトリ自身を読むために開いたものです。気にしなくてかまいません。）

## リダイレクト：口の行き先をファイルにする {#redirect}

口の行き先は、付け替えられます。これを**リダイレクト**と呼びます。付け替えるのはシェルの仕事で、プログラムのほうは何も知りません。

### > で、標準出力をファイルへ

コマンドのあとに `> ファイル名` と書くと、標準出力の行き先がそのファイルになります。

```sh run title="> で出力をファイルに入れる"
echo "1 行目" > out.txt
cat out.txt
ls -l /proc/self/fd > fd.txt
cat fd.txt
```

`echo` の出力は画面に出ず、`out.txt` に入りました。後半は、さっきの `ls -l /proc/self/fd` の出力を `fd.txt` に入れて、あとから見ています。`1` の行き先が `/home/you/fd.txt` に変わっています。`ls` 自身は、いつもどおり 1 番の口に書いただけです。

`>` は、ファイルがなければ作り、**あれば中身を空にしてから**書きます。前の中身は消えます。

```sh run title="> は上書き、>> は追記"
echo "上書きした" > out.txt
cat out.txt
echo "2 行目" >> out.txt
echo "3 行目" >> out.txt
cat out.txt
```

`>>` は、ファイルの末尾に足します。ログのように、書き足していくものに使います。

:::warn 読んでいるファイルに > で書かない
`sort numbers.txt > numbers.txt` のように、入力と同じファイルに `>` で書いてはいけません。シェルは、`sort` を起動する**前に** `>` のファイルを空にします。`sort` が読み始めたときには、もう中身がありません。

```sh run title="入力と同じファイルに書くと、空になる"
cp numbers.txt n.txt
sort n.txt > n.txt
wc -c n.txt
```

`n.txt` は 0 バイトになりました。結果は別の名前のファイルに書き、あとで `mv` します。
:::

### < で、標準入力をファイルから

`< ファイル名` は、標準入力の相手をキーボードからファイルに替えます。

```sh run title="< でファイルを標準入力にする"
sort < numbers.txt
wc -l < fruits.txt
wc -l fruits.txt
```

`wc -l` は行の数を数えます。最後の 2 つの違いを見てください。`wc -l fruits.txt` は、ファイル名を引数で受け取ったので、名前も一緒に表示します。`wc -l < fruits.txt` は、数だけです。`wc` は標準入力から読んでいるだけで、その先がどのファイルなのかを知らないからです。

`<` と `>` は一緒に使えます。

```sh run title="入力も出力もファイルにする"
sort -n < numbers.txt > sorted.txt
cat sorted.txt
```

`-n` は「数として並べる」オプションです（あとの節で扱います）。

## 標準エラーを分ける {#stderr}

`>` が付け替えるのは、1 番の口（標準出力）だけです。2 番の口は、そのままです。

```sh run error title="> では、エラーはファイルに入らない"
ls fruits.txt nope.txt > list.txt
cat list.txt
```

エラーの知らせは画面に出て、`list.txt` には `fruits.txt` だけが入りました。これが、口を 2 つに分けてある理由です。結果をファイルやほかのプログラムに送っても、エラーは人の目に届きます。結果のデータにエラーの文が混ざることもありません。

### 2> で、標準エラーをファイルへ

2 番の口を付け替えるには、`>` の前に番号を付けて `2>` と書きます（`>` は `1>` の略です）。

```sh run error title="結果とエラーを別のファイルに"
ls fruits.txt nope.txt > list.txt 2> err.txt
cat list.txt
cat err.txt
```

今度は、画面には何も出ません。`2>>` と書けば追記になります。

### /dev/null：何でも捨てる

エラーの知らせが要らないときは、`/dev/null` に送ります。`/dev/null` は、書かれたものを全部捨てる特別なファイルです（第 12 章）。

```sh run error title="エラーを捨てる"
ls fruits.txt nope.txt 2> /dev/null
```

画面に出るのは結果だけになりました。逆に `> /dev/null` と書けば、結果を捨ててエラーだけを見られます。

### 2>&1：標準エラーを、標準出力と同じところへ

結果とエラーを**同じファイル**に入れたいときは、`2>&1` と書きます。「2 番の口を、いま 1 番の口が向いているところへ向ける」という意味です。

```sh run error title="両方を 1 つのファイルに"
ls fruits.txt nope.txt > all.txt 2>&1
cat all.txt
```

`2>&1` は、**書く順番**が大事です。シェルは、リダイレクトを左から順に処理します。


```sh run error title="順番を逆にすると、エラーは画面に出る"
ls fruits.txt nope.txt 2>&1 > all2.txt
cat all2.txt
```

`all2.txt` に入ったのは `fruits.txt` だけで、エラーは画面に出ました。図の最後の段階のとおりです。

リダイレクトの書き方を、まとめておきます。

| 書き方 | 意味 |
| --- | --- |
| `> file` | 標準出力を file へ（上書き） |
| `>> file` | 標準出力を file へ（追記） |
| `< file` | 標準入力を file から |
| `2> file` | 標準エラーを file へ |
| `2>&1` | 標準エラーを、標準出力と同じところへ |
| `> file 2>&1` | 両方を file へ（bash では `&> file` とも書ける） |
| `2> /dev/null` | エラーを捨てる |

:::deep sudo とリダイレクト
`sudo echo "…" > /etc/motd` は、`Permission denied` になります。`>` のファイルを開くのは `sudo` や `echo` ではなく、**あなたのシェル**だからです。シェルは root ではないので、`/etc` の下に書けません。root の権限でファイルに書きたいときは、あとで出てくる `tee` を使って `echo "…" | sudo tee /etc/motd` と書きます。
:::

## パイプ：プログラムとプログラムをつなぐ {#pipe}

リダイレクトは、口の相手をファイルにしました。**パイプ**は、口の相手を**別のプログラム**にします。`A | B` と書くと、A の標準出力が、B の標準入力につながります。

```sh run title="最初のパイプ"
ls /usr/bin | wc -l
```

`ls /usr/bin` の出力（コマンドの名前が 1 行に 1 つ）が、画面ではなく `wc -l` に流れ込み、`wc -l` が行を数えました。出てきた数が、このサイトの Linux の `/usr/bin` にあるコマンドの個数です。

パイプなしで同じことをするには、途中の結果をいったんファイルに置くことになります。

```sh run title="パイプを使わないと"
ls /usr/bin > tmp.txt
wc -l < tmp.txt
rm tmp.txt
```

パイプは、この「いったん置くファイル」をなくします。そして、ただの省略ではありません。次の図のとおり、2 つのプログラムは**同時に**動きます。

```fig graph パイプ A | B。シェルは 2 つのプロセスを同時に起動し、A の口 1 と B の口 0 をパイプでつなぐ。パイプはカーネルの中にある小さな置き場（バッファ）
{
  col: 215, row: 100,
  nodes: [
    { id: 'kb', label: '端末', sub: 'キーボード', x: 0, y: 0, kind: 'ext', mono: false },
    { id: 'a', label: 'ls /usr/bin', sub: 'プロセス A', x: 1, y: 0, kind: 'accent' },

    { id: 'b', label: 'wc -l', sub: 'プロセス B', x: 3, y: 0, kind: 'accent' },

  ],

```

口の行き先を、さっきと同じ方法で確かめます。

```sh run title="パイプにつながった口"
ls -l /proc/self/fd | cat
```

`1` の行き先が、`pipe:[…]` になりました。`ls` の標準出力は、端末ではなくパイプにつながっています。`2` は端末のままです。

### 2 つのプロセスは、同時にいる

パイプでつないだコマンドが同時に動いていることを、`ps` で見ます。`sleep 1` は、1 秒待つだけのコマンドです。2 つの `sleep` と `ps` をパイプでつなぎます（データは何も流れませんが、つなぐことはできます）。

```sh run title="パイプの 3 つのプロセスを ps で見る"
sleep 1 | sleep 1 | ps -o pid,ppid,stat,args
```

`ps` が表示した時点で、2 つの `sleep` が両方とも存在しています。「1 つ目が終わってから 2 つ目を起動する」のではありません。3 つとも、親（PPID）は同じシェル（PID 2）です。シェルは、パイプでつないだコマンドを全部いっぺんに起動して、全部が終わるのを待ちます。

同時に動くので、上流のプログラムが出力を全部作り終える必要はありません。`yes` は、止められるまで `y` を出し続けるコマンドです。

```sh run title="終わらないプログラムも、つなげる"
yes | head -n 3
```

`head -n 3` は、3 行読んだところで終わります。読み手がいなくなったので、`yes` も止まります（止まる仕組みは、第 8 章のシグナルで説明します）。

### 標準エラーはパイプを通らない

図のとおり、パイプにつながるのは 1 番の口だけです。

```sh run title="エラーはパイプに入らない"
ls nope.txt | wc -l
```

エラーの知らせは画面に出て、`wc -l` には何も届かなかったので、`0` と数えました。エラーもパイプに流したいときは、`2>&1` で 1 番の口に合わせます。

```sh run title="エラーもパイプに流す"
ls nope.txt 2>&1 | wc -l
```

今度は、エラーの 1 行が `wc -l` に届いて、`1` になりました。

:::note パイプの正体は第 9 章で
シェルがパイプを作って、2 つのプロセスの口につなぐ手順（`pipe`、`fork`、`dup2` というシステムコール）は、第 9 章で `strace` を使って見ます。
:::

## フィルタという考え方：cat、wc、head、tail {#filter}

「標準入力から読み、加工して、標準出力に書く」プログラムを、**フィルタ**と呼びます。フィルタは、前に何がつながっているか、後ろに何がつながっているかを知りません。だから、どんな順番にでもつなげます。

フィルタの多くは、ファイル名を引数に渡すとそのファイルを読み、渡さなければ標準入力を読みます。次の 3 つは、どれも同じ結果になります。

```sh run title="同じ結果になる 3 つの書き方"
wc -l fruits.txt
wc -l < fruits.txt
cat fruits.txt | wc -l
```

`cat` は、ファイルの中身をそのまま標準出力に流します。パイプの「蛇口」としてよく使います。

この節と次の節で使う練習用のファイルは、3 つです。`fruits.txt`（果物の名前が 9 行）、`poem.txt`（英語の 5 行）、`scores.csv`（試験の点数）です。

```sh run title="練習用のファイル"
cat poem.txt
cat scores.csv
```

### wc：数える

`wc`（word count）は、行・単語・バイトの数を数えます。

```sh run title="wc"
wc poem.txt
wc -l poem.txt
wc -w poem.txt
wc -c memo.txt
wc -m memo.txt
```

オプションなしでは、行数（5）、単語数（25）、バイト数（127）を並べます。`-l` は行だけ、`-w` は単語だけ、`-c` はバイトだけです。`-m` は文字数です。日本語の入った `memo.txt` は、55 バイトで 25 文字です。日本語の 1 文字は、UTF-8 で 3 バイトになるからです。

### head と tail：先頭と末尾

```sh run title="head と tail"
head -n 2 poem.txt
tail -n 2 poem.txt
tail -n +2 scores.csv
```

`head -n 2` は先頭の 2 行、`tail -n 2` は末尾の 2 行です。`tail -n +2` のように `+` を付けると、「2 行目から最後まで」になります。CSV の見出しの行を取り除くのに便利です。

組み合わせると、「3 行目だけ」も取り出せます。

```sh run title="3 行目だけを取り出す"
head -n 3 poem.txt | tail -n 1
```

## grep：行を選ぶ {#grep}

`grep` は、**パターンに合う行だけ**を通すフィルタです。

```sh run title="grep"
grep fox poem.txt
grep -i the poem.txt
```

`grep fox` は、`fox` を含む行だけを出します。`grep` は大文字と小文字を区別するので、`grep the` では `The` で始まる行は選ばれません。`-i`（ignore case）を付けると、区別しなくなります。

よく使うオプションです。

| オプション | 意味 |
| --- | --- |
| `-i` | 大文字と小文字を区別しない |
| `-v` | 合わ**ない**行を出す（反転） |
| `-c` | 合う行の**数**だけを出す |
| `-n` | 行番号を付ける |
| `-E` | 拡張正規表現を使う（`|`、`+`、`( )` など） |

```sh run title="grep のオプション"
grep -n fox poem.txt
grep -c apple fruits.txt
grep -v apple fruits.txt
```

`-c` は、`grep apple fruits.txt | wc -l` と同じ数になります。`-v` は、apple でない行だけを出します。

### 正規表現を少しだけ

`grep` のパターンは、**正規表現**です。文字の並びの「型」を書けます。まず覚えるのは、次の 4 つで十分です。

| 書き方 | 意味 | 例 |
| --- | --- | --- |
| `^` | 行のはじめ | `^The`：The で始まる行 |
| `$` | 行の終わり | `fox$`：fox で終わる行 |
| `.` | 何か 1 文字 | `b.g`：big、bag、bug … |
| `A|B`（`-E` が要る） | A または B | `fox|dog` |

```sh run title="正規表現"
grep '^The' poem.txt
grep 'fox$' poem.txt
grep -E 'fox|dog' poem.txt
grep ',math,' scores.csv
```

パターンは、`'…'`（シングルクォート）で囲む習慣を付けてください。`$` や `|` や `*` は、シェルにとっても特別な文字です。囲んでおけば、シェルは手を付けずに、そのまま `grep` に渡します（引用符は第 6 章で詳しく扱います）。

パイプの途中に入れれば、どんなコマンドの出力も絞り込めます。

```sh run title="コマンドの出力を絞り込む"
ls /usr/bin | grep '^s' | head -n 5
ls /usr/bin | grep -c '^s'
```

## sort と uniq：並べて、数える {#sort}

### sort：行を並べ替える

```sh run title="sort は文字の順に並べる"
sort fruits.txt
sort numbers.txt
```

`sort` は、行を**文字の順**（辞書の順）に並べます。2 つ目の結果を見てください。`10`、`100`、`23`、`42`、`5` … と並んでいます。文字として比べると、`1` で始まる `100` は、`2` で始まる `23` より前に来るからです。数として並べるには、`-n`（numeric）を付けます。

```sh run title="-n で数として、-r で逆順に"
sort -n numbers.txt
sort -rn numbers.txt | head -n 3
```

`-r`（reverse）は逆順です。`sort -rn | head -n 3` は、「大きいほうから 3 つ」という決まり文句です。

| オプション | 意味 |
| --- | --- |
| `-n` | 数として比べる |
| `-r` | 逆順にする |
| `-k N` | N 番目の欄で比べる |
| `-t 文字` | 欄の区切りの文字（指定しなければ空白） |
| `-u` | 同じ行は 1 つにまとめる |

`scores.csv` を、3 番目の欄（点数）の大きい順に並べます。区切りは `,` です。見出しの行は、`tail -n +2` で先に取り除いておきます。

```sh run title="CSV を点数の順に並べる"
tail -n +2 scores.csv | sort -t, -k3 -n -r
```

### uniq：隣り合った同じ行をまとめる

`uniq` は、**隣り合った**同じ行を 1 行にまとめます。

```sh run title="uniq は、隣り合っていないとまとめない"
uniq fruits.txt | head -n 4
sort fruits.txt | uniq
```

`fruits.txt` には apple が 3 回出てきますが、離れた行にあるので、そのまま `uniq` に通しても減りません（1 つ目。先頭の 4 行に apple が 2 回残っています）。先に `sort` して同じ行を隣り合わせにすると、6 種類にまとまります。**`uniq` の前には `sort`**。これは対で覚えます。（重複を取るだけなら、`sort -u` でも同じ結果になります。）

`uniq -c`（count）は、まとめた行の数を先頭に付けます。

```sh run title="数えて、多い順に並べる"
sort fruits.txt | uniq -c
sort fruits.txt | uniq -c | sort -rn
sort fruits.txt | uniq -c | sort -rn | head -n 2
```

**`sort | uniq -c | sort -rn`** は、「何が何回出てくるかを、多い順に」という集計の定番です。第 1 章で 1 度見た形です。データの流れを、1 段ずつ追ってみてください。

1. `sort`：同じ名前を隣り合わせにする
2. `uniq -c`：隣り合った同じ行を 1 つにまとめ、回数を先頭に付ける
3. `sort -rn`：先頭の回数で、大きい順に並べ直す
4. `head -n 2`：上位の 2 つだけを残す

パイプラインを書くときは、いきなり全部を書かずに、左から 1 段ずつ足して、そのつど出力を見るのがコツです。

## cut、tr、sed：行の中を加工する {#cut}

`grep` や `sort` は、行をまるごと扱いました。ここからは、行の**中身**を変えるフィルタです。

### cut：欄を切り出す

`cut` は、各行から決まった欄だけを切り出します。`-d` で区切りの文字、`-f` で欄の番号を指定します。

```sh run title="cut"
cut -d, -f1 scores.csv
cut -d, -f1,3 scores.csv | head -n 3
cut -d: -f1,7 /etc/passwd
```

`-f1,3` のように、いくつも指定できます。3 つ目の例は、第 4 章で読んだ `/etc/passwd`（`:` 区切り）から、ユーザー名とシェルだけを取り出しています。

`cut` と前の節の道具を合わせると、「科目ごとの行の数」が出せます。

```sh run title="科目ごとに数える"
tail -n +2 scores.csv | cut -d, -f2 | sort | uniq -c
```

### tr：文字を置き換える

`tr`（translate）は、文字を 1 文字ずつ置き換えます。`tr` はファイル名を引数に取れないので、いつも標準入力から読ませます。

```sh run title="tr"
tr a-z A-Z < fruits.txt | head -n 2
tr , ' ' < scores.csv | head -n 2
tr -d aeiou < fruits.txt | head -n 2
echo "a   b    c" | tr -s ' '
```

1 つ目は小文字を大文字に、2 つ目は `,` を空白に置き換えています。`-d`（delete）は、その文字を消します。`-s`（squeeze）は、同じ文字の続きを 1 つに縮めます。

`tr` で空白を改行に置き換えると、文章が「1 行に 1 単語」になります。あとは、いつもの定番です。

```sh run title="どの単語が何回出てくるか"
tr A-Z a-z < poem.txt | tr -d . | tr ' ' '\n' | sort | uniq -c | sort -rn | head -n 3
```

大文字を小文字にそろえ、ピリオドを消し、空白を改行に替えてから、数えて多い順に並べました。the と a が 3 回、fox が 2 回です。

### sed：文字列を置き換える

`sed`（stream editor）は多機能ですが、まず使うのは `s/古い/新しい/` の**置き換え**です。

```sh run title="sed の s"
sed 's/apple/りんご/' fruits.txt | head -n 4
echo "banana" | sed 's/a/A/'
echo "banana" | sed 's/a/A/g'
```

`s/a/A/` は、各行で**最初に見つかった 1 つ**だけを置き換えます。最後に `g`（global）を付けると、行の中の全部を置き換えます。「古い」のほうには、`grep` と同じ正規表現が書けます。

```sh run title="sed でできる、ほかのこと"
sed 's/,/ /g' scores.csv | head -n 2
sed -n '2,3p' poem.txt
sed '1d' scores.csv | head -n 2
```

`sed -n '2,3p'` は 2〜3 行目だけを表示し、`sed '1d'` は 1 行目を消します（`tail -n +2` と同じ結果です）。

:::note sed はファイルを書き換えない
`sed` も、ほかのフィルタと同じく、結果を標準出力に書くだけです。元のファイルは変わりません。本物の GNU の `sed` には、ファイルを直接書き換える `-i` オプションがありますが、このサイトの `sed` にはありません。結果を残したいときは、`sed '…' file > new.txt` のように、別のファイルにリダイレクトします。
:::

## tee と xargs：流れを分ける、引数に変える {#tee}

### tee：ファイルに書きながら、先へも流す

長いパイプラインの途中の結果を、ファイルにも残したいことがあります。`tee` は、標準入力を**ファイルと標準出力の両方**に書きます。配管の T 字の分かれ道（T）が名前の由来です。

```sh run title="tee で途中の結果を残す"
sort fruits.txt | tee sorted-fruits.txt | uniq -c | sort -rn | head -n 2
wc -l sorted-fruits.txt
```

集計の結果は画面に出て、途中の「並べ替えた 9 行」は `sorted-fruits.txt` に残りました。`tee -a` とすると、上書きではなく追記になります。

### xargs：標準入力を、引数に変える

パイプが渡すのは、標準入力です。ところが、標準入力を読まず、**引数**でしか相手を受け取らないコマンドもあります（`rm`、`ls`、`echo` など）。`xargs` は、標準入力から読んだ言葉を、別のコマンドの引数に並べて実行します。

```sh run title="xargs"
cat fruits.txt | xargs
cat fruits.txt | xargs -n 3
```

実行するコマンドを書かなければ、`echo` が使われます。9 行の入力が、`echo apple banana cherry …` という 1 回の実行になりました。`-n 3` は、「引数 3 つごとに 1 回実行する」です。

`find`（第 3 章）で探したファイルを、別のコマンドに渡すのがよくある使い方です。

```sh run title="find で探したファイルに、まとめて grep をかける"
find notes -name '*.txt'
find notes -name '*.txt' | xargs grep -c 'パイプ'
```

`find` が出した 2 つのファイル名が、`grep -c 'パイプ' notes/todo.txt notes/ideas.txt` の形の引数になりました。

パイプと `xargs` の違いを、1 つの例で確かめておきます。

```sh run title="標準入力として渡すか、引数として渡すか"
echo poem.txt | wc -l
echo poem.txt | xargs wc -l
```

1 つ目の `wc -l` は、「poem.txt」という 1 行の**文字列**を数えたので 1 です。2 つ目は、`wc -l poem.txt` が実行されて、**ファイル**の行数の 5 が出ました。

:::note paste と awk
列を横に並べる `paste`（`paste -sd+ numbers.txt` で `10+5+23+…` のように 1 行につなぐ）と、欄ごとの計算ができる `awk` も、テキスト処理でよく使う道具です。どちらも、このサイトの Linux にはまだ入っていないので、付録で紹介します。この章の道具だけでは、「欄の合計を出す」ような計算はできません。合計は、第 6 章のシェルスクリプトで計算します。
:::

```sh run title="アクセスログ"
wc -l /var/log/access.log
head -n 3 /var/log/access.log
```

### アクセスの多い IP アドレスの上位 3 つ

1 番目の欄を切り出して、定番の集計にかけます。1 段ずつ組み立てましょう。

```sh run title="1 段目：IP アドレスだけを切り出す"
cut -d' ' -f1 /var/log/access.log | head -n 4
```

```sh run title="2 段目：数える"
cut -d' ' -f1 /var/log/access.log | sort | uniq -c
```

```sh run title="3 段目：多い順に並べて、上位 3 つ"
cut -d' ' -f1 /var/log/access.log | sort | uniq -c | sort -rn | head -n 3
```

192.168.1.10 が 5 回で、いちばん多いことがわかりました。専用の「アクセス解析プログラム」は、どこにもありません。4 つの小さな道具をつないだだけです。

### 結果の番号ごとの件数

欄の番号を 9 に替えるだけで、別の集計になります。

```sh run title="ステータスコードごとの件数"
cut -d' ' -f9 /var/log/access.log | sort | uniq -c | sort -rn
```

成功（200）が 8 件、「見つからない」（404）が 2 件です。

### 失敗したアクセスを調べる

404 になったのは、どのパスへの、だれからのアクセスでしょうか。`grep` で行を選んでから、欄を切り出します。

```sh run title="404 になったアクセス"
grep ' 404 ' /var/log/access.log | cut -d' ' -f1,7
```

パターンを `' 404 '` と、前後に空白を付けて書いたのは、ほかの欄（時刻やバイト数）にたまたま 404 という数字が出てきても、選ばないようにするためです。

### いちばん大きい応答

10 番目の欄（バイト数）で並べ替えれば、いちばん大きなファイルを返したアクセスがわかります。`sort` は、区切りを指定しなければ空白で欄を分けます。

```sh run title="バイト数のいちばん大きいアクセス"
sort -k10 -n -r /var/log/access.log | head -n 1 | cut -d' ' -f7,10
```

`/logo.png` の 20480 バイトでした。

:::tip パイプラインの組み立て方
1. まず `head` で、データの形を見る。区切りは何か、ほしい欄は何番目か
2. **行を選ぶ**（`grep`）→ **欄を切り出す**（`cut`）→ **並べる**（`sort`）→ **まとめて数える**（`uniq -c`）→ **並べ直す**（`sort -rn`）→ **上位だけ残す**（`head`）の順に考える
3. 左から 1 段ずつ足して、そのつど出力を確かめる
:::

:::key この章のまとめ
- プログラムは、はじめから 3 つの口を持つ。**標準入力**（0）、**標準出力**（1）、**標準エラー**（2）。何もしなければ、3 つとも端末につながっている
- **リダイレクト**は、口の行き先をファイルに付け替える。`>`（上書き）、`>>`（追記）、`<`（入力）、`2>`（エラー）、`2>&1`（エラーを標準出力と同じところへ）。付け替えるのはシェルで、左から順に処理される。捨てるなら `/dev/null`
- **パイプ** `A | B` は、A の標準出力を B の標準入力につなぐ。A と B は同時に動く。標準エラーはパイプを通らない
- 標準入力から読んで標準出力に書くプログラムが**フィルタ**。行を選ぶ `grep`、並べる `sort`、まとめて数える `uniq -c`、欄を切り出す `cut`、文字を置き換える `tr`、文字列を置き換える `sed`、数える `wc`、先頭と末尾の `head` と `tail`
- `uniq` の前には `sort`。**`sort | uniq -c | sort -rn | head`** が、「何が何回、多い順に」の定番
- `tee` は流れをファイルにも残す。`xargs` は標準入力を引数に変える
- パイプラインは、左から 1 段ずつ足して、出力を確かめながら組み立てる
:::

## 確認問題 {#quiz}

この章の道具をつないで、自分で集計します。採点は、コマンドの標準出力（1 問目は、できたファイルの中身）を比べて行います。データを少し変えた状態でも確かめるので、答えの数字や名前を `echo` で直接書いても正解になりません。

:::quiz 結果とエラーを別のファイルに分ける
`ls /etc/hostname /etc/nope` を実行して、標準出力を `ok.txt` に、標準エラーを `ng.txt` に入れてください。画面には何も出ないようにします。

```sh answer
ls /etc/hostname /etc/nope > ok.txt 2> ng.txt
```

```sh check
echo "[ok.txt]"; cat /home/you/ok.txt
echo "[ng.txt]"; cat /home/you/ng.txt
```

:::hint
標準出力は `>`、標準エラーは `2>` で、それぞれ別のファイルを指定します。
:::
:::

:::quiz math の最高点はだれか
`scores.csv` から、科目が math の行のうち、点数（3 番目の欄）がいちばん高い人の**名前だけ**を表示してください。

```sh answer
grep ',math,' scores.csv | sort -t, -k3 -n -r | head -n 1 | cut -d, -f1
```

```sh vary
echo "yamada,math,95" >> scores.csv
```

```sh vary
echo "kato,english,99" >> scores.csv
```

```sh vary
echo "mori,math,100" >> scores.csv
```

:::hint
4 段で書けます。math の行を選ぶ（`grep`）→ 点数の大きい順に並べる（`sort -t, -k3 -n -r`）→ 先頭の 1 行（`head`）→ 名前の欄（`cut`）。点数は、数として比べることを忘れずに。
:::

:::quiz 404 を受け取った IP アドレスは何種類か
`/var/log/access.log` で、ステータスコード（9 番目の欄）が 404 だったアクセスについて、相手の IP アドレスが**何種類あるか**を、数だけ表示してください。同じ IP アドレスが何回 404 になっても、1 種類と数えます。

```sh answer
grep ' 404 ' /var/log/access.log | cut -d' ' -f1 | sort -u | wc -l
```

```sh vary
sudo sh -c 'echo "192.168.1.20 - - [01/Apr/2026:09:00:10 +0900] \"GET /old.html HTTP/1.1\" 404 512" >> /var/log/access.log'
sudo sh -c 'echo "192.168.1.13 - - [01/Apr/2026:09:00:11 +0900] \"GET /missing.html HTTP/1.1\" 404 512" >> /var/log/access.log'
sudo sh -c 'echo "192.168.1.20 - - [01/Apr/2026:09:00:12 +0900] \"GET /old.html HTTP/1.1\" 404 512" >> /var/log/access.log'
sudo sh -c 'echo "192.168.1.21 - - [01/Apr/2026:09:00:15 +0900] \"GET /404.html HTTP/1.1\" 200 404" >> /var/log/access.log'
```

:::hint
404 の行を選ぶ → IP アドレスの欄を切り出す → 重複を取り除く（`sort -u` か `sort | uniq`）→ 行を数える。`grep` のパターンは、ほかの欄の数字に当たらないように `' 404 '` と空白で挟みます。
:::
:::

:::quiz いちばん多く要求されたパス
`/var/log/access.log` で、いちばん多く要求されたパス（7 番目の欄）を 1 つ、**パスだけ**表示してください（回数は表示しません）。


```sh vary
sudo sh -c 'for i in 1 2 3; do echo "192.168.1.30 - - [01/Apr/2026:09:01:0$i +0900] \"GET /about.html HTTP/1.1\" 200 2048" >> /var/log/access.log; done'
```

:::hint
`sort | uniq -c | sort -rn | head -n 1` までは定番です。その出力は `      4 /index.html` のように、先頭に空白と回数が付いています。`tr -s ' '` で空白の続きを 1 つに縮めてから `cut -d' '` で切り出すか、`sed 's/^ *[0-9]* //'` で先頭の空白と数字を消します。
:::
