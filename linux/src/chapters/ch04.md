## ユーザーとグループ {#users}

第 1 章で見たとおり、Unix は 1 台の計算機を何人もが同時に使うために生まれました。そこで必要になるのが、「他人のファイルを勝手に読めない、消せない」という仕組みです。Linux はこれを受け継いでいます。

仕組みの土台は、**ユーザー**と**グループ**です。まず、自分がだれなのかを確かめましょう。

```sh run title="自分はだれか"
whoami
id
```

`whoami` は名前だけを出します。`id` は、もう少し詳しく出します。読み方は次のとおりです。

| 部分 | 意味 |
| --- | --- |
| `uid=1000(you)` | **ユーザー ID**（uid）。あなたは 1000 番で、名前は you |
| `gid=1000(you)` | **主グループ**の ID（gid）。新しく作るファイルは、ふつうこのグループのものになる |
| `groups=1000(you),27(sudo),50(staff),100(users)` | 入っているグループの全部。you は 4 つのグループに入っている |

大事なのは、**カーネルが見ているのは番号だけ**だということです。`you` という名前は、人が読むための飾りです。番号と名前の対応は、ただのテキストファイルに書いてあります。

### /etc/passwd：ユーザーの一覧

```sh run title="ユーザーの一覧"
cat /etc/passwd
```

1 行が 1 人のユーザーです。`:`（コロン）で 7 つの欄に区切られています。`you` の行で読んでみます。

| 欄 | `you` の行の値 | 意味 |
| --- | --- | --- |
| 1 | `you` | ユーザー名 |
| 2 | `x` | 昔はここにパスワード（を変換したもの）があった。今は `/etc/shadow` に移してあり、`x` とだけ書く |
| 3 | `1000` | uid |
| 4 | `1000` | 主グループの gid |
| 5 | `You` | 説明（本名など） |
| 6 | `/home/you` | ホームディレクトリ |
| 7 | `/bin/sh` | ログインしたときに動くシェル |

このサイトの Linux には、人のユーザーが 3 人います。`you`（1000）、`alice`（1001）、`bob`（1002）です。人のユーザーの uid は、多くのディストリビューションで 1000 番から始まります。

いちばん上の `root` は uid が **0** の特別なユーザーです。あとの節で扱います。`daemon` や `nobody` は、人ではなく、裏で動くプログラムのためのユーザーです。シェルの欄が `/usr/sbin/nologin` なので、ログインはできません。

### /etc/group：グループの一覧

```sh run title="グループの一覧"
cat /etc/group
```

こちらは 4 つの欄です。グループ名、パスワードの欄（使わないので `x`）、gid、そして**メンバー**の一覧です。`staff:x:50:you,alice` は、「staff は 50 番のグループで、you と alice が入っている」と読みます。

`you:x:1000:` のように、ユーザーと同じ名前でメンバーの欄が空のグループもあります。これは、そのユーザーの主グループです。主グループは `/etc/passwd` の 4 番目の欄で決まるので、ここには書きません。

ほかの人のことも、`id` で調べられます。

```sh run title="alice と bob"
id alice
id bob
groups
```

alice は staff に入っていますが、bob は入っていません。この違いを、あとで使います。`groups` は、自分のグループの名前だけを並べます。

:::note このサイトのユーザー
| ユーザー | uid | 入っているグループ |
| --- | --- | --- |
| root | 0 | root |
| you | 1000 | you、sudo、staff、users |
| alice | 1001 | alice、staff、users |
| bob | 1002 | bob、users |
:::

## ls -l の読み方：rwx と 3 つの組 {#rwx}

ファイルには、1 つ 1 つに**持ち主**（ユーザー）と**グループ**が記録されています。第 2 章で使った `ls -l` を、もう一度見てみましょう。

```sh run title="ホームディレクトリの ls -l"
ls -l
```

3 列目の `you` が持ち主、4 列目の `you` がグループです。そして、行のはじめの `-rw-r--r--` のような 10 文字が、この章の主役です。これを**モード**（パーミッション、権限）と呼びます。

```fig layout ls -l の最初の 10 文字の読み方。1 文字目は種類、残りの 9 文字は 3 文字ずつ、持ち主・グループ・その他の権限
  ],

```

1 文字目は**種類**です。`-` はふつうのファイル、`d` はディレクトリ、`l` はシンボリックリンク（第 11 章）です。上の出力では、`notes` だけが `d` で始まっています。

残りの 9 文字は、3 文字ずつの組になっています。

- 2〜4 文字目：**持ち主**（user）ができること
- 5〜7 文字目：**グループ**（group）のメンバーができること
- 8〜10 文字目：**その他**（other）の人ができること

それぞれの組の 3 文字は、順に `r`、`w`、`x` です。許されていないところは `-` になります。

| 文字 | 名前 | ファイルに対して |
| --- | --- | --- |
| `r` | read（読み） | 中身を読める |
| `w` | write（書き） | 中身を書き換えられる |
| `x` | execute（実行） | プログラムとして実行できる |

つまり `-rw-r--r--` は、「ふつうのファイル。持ち主は読み書きできる。グループの人は読めるだけ。その他の人も読めるだけ」です。図の下の 2 段（2 進数と 8 進数）は、次の節で使います。

### alice のホームで確かめる

alice のホームディレクトリに、権限の違う 3 つのファイルが置いてあります。

```sh run title="alice のファイル"
ls -l /home/alice
```

あなた（you）から見て、それぞれ何ができるかを、表で予想してから試しましょう。

| ファイル | モード | 持ち主 / グループ | you はどの組か | できること |
| --- | --- | --- | --- | --- |
| `diary.txt` | `-rw-------` | alice / alice | その他（`---`） | 何もできない |
| `public.txt` | `-rw-r--r--` | alice / alice | その他（`r--`） | 読める |
| `shared.txt` | `-rw-rw-r--` | alice / staff | グループ（`rw-`）。you は staff のメンバー | 読み書きできる |

```sh run title="public.txt は読める"
cat /home/alice/public.txt
```

```sh run error title="diary.txt は読めない"
cat /home/alice/diary.txt
```

`Permission denied`（許可がない）と断られました。この先、何度も出会うエラーです。

`shared.txt` は、グループ staff のメンバーなら書き込めます。`>>` は「ファイルの末尾に足す」という意味です（第 5 章で扱います）。

```sh run title="shared.txt には書き込める"
echo "you が 1 行足しました。" >> /home/alice/shared.txt
cat /home/alice/shared.txt
```

```sh run error title="public.txt には書き込めない"
echo "落書き" >> /home/alice/public.txt
```

表の予想どおりです。`public.txt` は、読めても書けません。

## chmod：権限を変える {#chmod}

権限を変えるコマンドが `chmod`（change mode）です。書き方は 2 通りあります。記号で書く方法と、数字で書く方法です。

### 記号で書く：u+x

ホームディレクトリの `hello.sh` は、短いシェルスクリプト（第 6 章）です。`./hello.sh` と打てば実行できるはずですが、今は断られます。

```sh run error title="実行の権限がない"
ls -l hello.sh
./hello.sh
```

モードが `-rw-r--r--` で、`x` がどこにもないからです。持ち主（u）に実行（x）を足します。

```sh run title="u+x：持ち主に実行の権限を足す"
chmod u+x hello.sh
ls -l hello.sh
./hello.sh
```

モードが `-rwxr--r--` に変わり、実行できるようになりました。記号の書き方は、「だれの」「どうする」「どの権限」の 3 つを並べます。

| 部分 | 書けるもの |
| --- | --- |
| だれの | `u`（持ち主）、`g`（グループ）、`o`（その他）、`a`（全員）。並べてもよい（`go`） |
| どうする | `+`（足す）、`-`（外す）、`=`（ちょうどこれにする） |
| どの権限 | `r`、`w`、`x`。並べてもよい（`rw`） |

```sh run title="いろいろな書き方"
chmod go-r memo.txt
ls -l memo.txt
chmod a+r memo.txt
ls -l memo.txt
chmod u=rwx,g=rx,o= hello.sh
ls -l hello.sh
```

`go-r` は「グループとその他から、読みを外す」。`a+r` は「全員に読みを足す」。最後のように、`,` で区切っていくつも書けます。`o=` は「その他は、何もなし」です。

### 数字で書く：644

もう 1 つの書き方は、**8 進数**の 3 桁です。慣れると、こちらのほうが速く書けます。

`rwx` の 3 文字を、3 ビットの 2 進数だと考えます。許されていれば 1、いなければ 0 です。`r` が 4、`w` が 2、`x` が 1 の重みを持つので、足し合わせると 0 から 7 までの 1 桁になります。

| 権限 | 2 進数 | 計算 | 数字 |
| --- | --- | --- | --- |
| `---` | 000 | 0 | 0 |
| `--x` | 001 | 1 | 1 |
| `-w-` | 010 | 2 | 2 |
| `-wx` | 011 | 2 + 1 | 3 |
| `r--` | 100 | 4 | 4 |
| `r-x` | 101 | 4 + 1 | 5 |
| `rw-` | 110 | 4 + 2 | 6 |
| `rwx` | 111 | 4 + 2 + 1 | 7 |

これを持ち主・グループ・その他の順に 3 桁並べます。`rw-r--r--` は 6・4・4 なので **644** です（図 4-1 の下の 2 段）。`stat` コマンドに `-c` で書式を渡すと、数字の形（`%a`）と文字の形（`%A`）を並べて見られます。

```sh run title="数字と文字を並べて見る"
stat -c '%a %A %n' memo.txt hello.sh notes
```

よく使う数字は、多くありません。

| 数字 | 文字 | よくある使い道 |
| --- | --- | --- |
| 644 | `rw-r--r--` | ふつうのファイル。自分は読み書き、ほかの人は読むだけ |
| 600 | `rw-------` | 自分だけが読み書きする秘密のファイル（鍵、日記） |
| 755 | `rwxr-xr-x` | プログラムとディレクトリ。だれでも実行できる（入れる） |
| 700 | `rwx------` | 自分だけのディレクトリ |
| 664 / 775 | `rw-rw-r--` / `rwxrwxr-x` | グループで共有するファイル / ディレクトリ |

```sh run title="数字で指定する"
chmod 600 memo.txt
ls -l memo.txt
chmod 644 memo.txt
chmod 755 hello.sh
ls -l memo.txt hello.sh
```

数字の書き方は、3 つの組を**まるごと置き換え**ます。記号の `u+x` は、ほかのビットをそのままにして 1 つだけ変えます。ここが使い分けの目安です。

### chmod できるのは持ち主だけ

`chmod` コマンドがしている仕事は、`chmod` という名前のシステムコール（カーネルへの頼みごと。第 10 章）を 1 回呼ぶことです。`strace` を付けると、その呼び出しが見えます。

```sh run strace title="chmod コマンドの中身"
chmod 640 memo.txt
```

下から 3 行目の `chmod("memo.txt", 0640) = 0` が本体です。頭に 0 を付けた `0640` は、C 言語での 8 進数の書き方です。`= 0` は「成功」を表します。途中の `umask` の行は、あとの節で説明します。

では、他人のファイルのモードは変えられるでしょうか。alice になって、あなたの `memo.txt` を変えようとしてみます（このブロックは alice のシェルで実行します。プロンプトを見てください）。

```sh run error user="alice" title="alice が、you のファイルを chmod する"
chmod 666 /home/you/memo.txt
```

`Operation not permitted`（その操作は許されていない）です。**モードを変えられるのは、そのファイルの持ち主と root だけ**です。ファイルの `w` の権限とは関係ありません。`w` は「中身を書き換えてよいか」であって、「権限を書き換えてよいか」ではないからです。

```sh run title="元に戻す"
chmod 644 memo.txt
ls -l memo.txt
```

## カーネルは何を比べているか {#check}

ここまでで、「you は staff のメンバーだから書ける」のような言い方をしてきました。正確には、権限を調べられているのは「人」ではなく、**プロセス**（実行中のプログラム。第 7 章）です。`cat` というプロセスがファイルを開こうとしたとき、カーネルは 2 つのものを比べます。

**1. プロセスが持っている番号。** プロセスは 1 つ 1 つ、uid、gid、入っているグループの一覧を持っています。シェルから起動したコマンドは、シェルの番号をそのまま受け継ぎます。

```sh run title="プロセスが持っている uid と gid"
ps -o pid,user,uid,comm
grep -E '^(Uid|Gid|Groups)' /proc/self/status
```

`ps` の出力では、シェル（`sh`）も `ps` 自身も uid が 1000 です。2 つ目のコマンドは、`/proc/self/status`（自分自身のプロセスの状態が読めるファイル）から、3 つの行だけを取り出しています。`Uid:` の行に 1000 が 4 つ並んでいるのは、uid に 4 つの種類があるからです。1 つ目が**実 uid**（もともとだれか）、2 つ目が**実効 uid**（権限の検査に使う番号）です。ふつうは同じ値です。違う値になる場合を、この章の最後に見ます。

**2. ファイルに記録されている番号。** ファイルの持ち主の uid、グループの gid、モードは、ファイルごとの管理情報（**inode**。第 11 章）に入っています。

```sh run title="ファイルに記録されている uid、gid、モード"
stat -c '%U(%u) %G(%g) %a %n' /home/alice/diary.txt /home/alice/shared.txt
```

カーネルは、この 2 つを次の順に比べます。

```fig graph カーネルの権限の検査。上から順に調べ、最初に当てはまった組の 3 ビットだけを見る。ほかの組は見ない

```

選ばれた組の 3 ビットの中に、しようとしている操作（読むなら `r`）があれば許可、なければ拒否です。拒否のとき、カーネルはシステムコールの結果として **EACCES** というエラー番号を返します。`strace` で見てみましょう。

```sh run strace error title="拒否の瞬間を見る"
cat /home/alice/diary.txt
```

2 行目が、その瞬間です。

```text
openat(AT_FDCWD, "/home/alice/diary.txt", O_RDONLY) = -1 EACCES (Permission denied)
```

`cat` は、`openat` というシステムコールで「このファイルを読むために開きたい」とカーネルに頼みました。カーネルは図の順に調べます。プロセスの実効 uid は 1000 で、0 ではありません。ファイルの持ち主は 1001 なので、持ち主でもありません。ファイルのグループは 1001（alice）で、プロセスのグループ（1000、27、50、100）のどれとも違います。残るのは「その他」の組で、`diary.txt` のその組は `---` です。`r` がないので、`-1 EACCES` が返りました。

`cat` は、このエラー番号を文に直して、`Permission denied` と表示しただけです。**断っているのはコマンドではなく、カーネルです。** だから、どのコマンドを使っても、自分でプログラムを書いても、同じように断られます。

### 最初に当てはまった組だけを見る

図の説明に、「最初に当てはまった組の 3 ビットだけを見る」と書きました。これは、少し意外な結果を生みます。自分の `memo.txt` を、「持ち主は何もできない、グループとその他は読める」というモード 044 にしてみます。

```sh run error title="持ち主なのに読めない"
chmod 044 memo.txt
ls -l memo.txt
cat memo.txt
```

その他の人が読めるファイルなのに、持ち主のあなたは読めません。あなたは「持ち主」に当てはまったので、カーネルは持ち主の 3 ビット（`---`）だけを見て、そこで決めてしまうからです。alice は「その他」なので、読めます。

```sh run user="alice" title="alice は読める"
cat /home/you/memo.txt
```

実用上の意味はほとんどないモードですが、カーネルの調べ方を確かめるにはよい例です。「3 つの組のうち、いちばん有利なもの」が選ばれるのではありません。持ち主は、いつでも `chmod` で元に戻せます。

```sh run title="元に戻す"
chmod 644 memo.txt
cat memo.txt
```

:::note 第 10 章と第 11 章へ
`openat` や `EACCES` のようなシステムコールとエラー番号は、第 10 章でまとめて扱います。uid、gid、モードが入っている inode の中身は、第 11 章で見ます。
:::

## ディレクトリの r と w と x {#dir}

ディレクトリにも `rwx` があります。ところが、意味がファイルとは違います。ここは、権限でいちばんつまずきやすいところです。

先に、ディレクトリとは何かを一言で言っておきます。ディレクトリは、**「名前」と「その名前が指すファイル」の対応表**です（中身は第 11 章で見ます）。ディレクトリの `rwx` は、この表に対する権限です。

| 文字 | ディレクトリに対して | できなくなること |
| --- | --- | --- |
| `r` | 表の**名前の一覧**を読める | `ls` |
| `w` | 表を**書き換え**られる（名前を足す、消す、変える） | 中にファイルを作る、消す、名前を変える |
| `x` | 表を引いて、**名前の先へ進める**（通り抜ける） | `cd`。中のファイルを開く。その下のどこにも行けない |

実験用のディレクトリを作ります。

```sh run title="実験用のディレクトリ box"
mkdir box
echo "ひみつ" > box/a.txt
echo "ふたつめ" > box/b.txt
ls -ld box
ls -l box
```

`ls -ld` の `-d` は、「ディレクトリの中身ではなく、ディレクトリそのもの」を表示するオプションです。`box` は `drwxr-xr-x`（755）で、中のファイルはどちらも 644 です。

### x がないと、通れない

`box` から、持ち主の `x` を外します。中のファイルのモードは変えません。

```sh run error title="x のないディレクトリ"
chmod u-x box
ls -ld box
ls box
cat box/a.txt
```

`ls box` は成功して、名前が見えました。`r` があるからです。ところが `cat box/a.txt` は断られました。`a.txt` 自体は 644 で、あなたは持ち主なのに、です。

理由は、`box/a.txt` というパスをたどる途中にあります。カーネルは、パスを左から 1 つずつたどります。`box` の表を引いて `a.txt` を探すところで、`box` の `x` を調べます。ここで拒否されると、`a.txt` のモードを見るところまで進めません。

```sh run strace error title="どこで断られたか"
cat box/a.txt
```

`openat(AT_FDCWD, "box/a.txt", O_RDONLY) = -1 EACCES (Permission denied)` と出ました。エラーの番号は、ファイル自体が読めないときと同じ EACCES です。`Permission denied` と言われたら、**そのファイルだけでなく、そこへ至る途中のディレクトリの x** も疑ってください。

`cd` もできません。

```sh run error title="cd もできない"
cd box
```

### 消せるかどうかは、ディレクトリの w で決まる

最後に `w` です。`box` を `r-x`（読めて通れるが、書き換えられない）にします。

```sh run error title="w のないディレクトリ"
chmod u=rx box
echo "新しい" > box/c.txt
rm -f box/a.txt
echo "書き換えた" > box/a.txt
cat box/a.txt
```

新しいファイルは作れず、`a.txt` を消すこともできません。どちらも「表を書き換える」操作だからです。一方、`a.txt` の**中身を書き換える**ことはできました。それは `a.txt` 自身の `w` の話で、ディレクトリの表は変わらないからです。

逆も成り立ちます。ディレクトリに `w` があれば、**自分が書き込めないファイルでも消せます**。

```sh run title="書き込めないファイルを消す"
chmod 755 box
chmod 444 box/b.txt
ls -l box
rm -f box/b.txt
ls box
```

`b.txt` は 444（だれも書けない）ですが、消せました。「ファイルを消す」とは、ファイルの中身に触ることではなく、ディレクトリの表から 1 行消すことだからです。第 11 章で、これを「リンクを外す」という言葉で説明します。

:::note 本物の rm は、たずねてくる
本物の Linux の `rm` は、書き込めないファイルを端末から消そうとすると、`rm: remove write-protected regular file 'box/b.txt'?` と確認を求めます。これは `rm` コマンドの親切であって、カーネルの権限の検査ではありません。`-f` を付けると、たずねずに消します。このサイトの `rm` は、`-f` がなくてもたずねません。
:::

### bob のホームディレクトリ

`/home` を見ると、bob のホームだけモードが違います。

```sh run error title="bob のホームには入れない"
ls -ld /home/alice /home/bob
cat /home/bob/readme.txt
```

`/home/bob` は `drwxr-x---`（750）です。あなたは持ち主でも bob グループのメンバーでもないので、「その他」の `---` が使われます。`x` がないので通れません。中の `readme.txt` がどんなモードであっても、たどり着けません。

ホームディレクトリを 700 や 750 にしておくのは、中のファイルを 1 つずつ守るより確実な方法です。入口を 1 か所閉じれば、中の全部が守られます。

## umask：新しいファイルの権限はどう決まるか {#umask}

`touch` や `mkdir` で作ったファイルは、何も指定しなくても 644 や 755 になっていました。この最初のモードを決めているのが **umask**（ユーマスク）です。

```sh run title="今の umask と、新しく作ったもの"
umask
touch new.txt
mkdir newdir
ls -ld new.txt newdir
```

umask は 0022 です（先頭の 0 は、ここでは気にしなくてかまいません）。umask は、「新しく作るときに、**与えない**権限」を 8 進数で書いたものです。

プログラムは、ファイルを作るときに「このモードで作りたい」とカーネルに頼みます。ふつうのファイルなら 666（`rw-rw-rw-`）、ディレクトリなら 777（`rwxrwxrwx`）を頼むのが習慣です。カーネルは、そこから umask に立っているビットを**取り除いて**から作ります。

| | 頼むモード | umask 022 | できるモード |
| --- | --- | --- | --- |
| ファイル | 666 `rw-rw-rw-` | `----w--w-` を取り除く | 644 `rw-r--r--` |
| ディレクトリ | 777 `rwxrwxrwx` | `----w--w-` を取り除く | 755 `rwxr-xr-x` |

022 は、「グループとその他には、書き込みを与えない」という意味になります。umask を 077 にすると、グループとその他には何も与えなくなります。

```sh run title="umask を 077 にする"
umask 077
touch secret.txt
mkdir private
ls -ld secret.txt private
umask 022
```

`secret.txt` は 600、`private` は 700 になりました。最後の行で、umask を元の 022 に戻しています。

:::warn 引き算ではなく、ビットを取り除く
「666 − 022 = 644」と引き算で覚えても、たいていは合います。しかし正しくは、ビットごとに「umask で 1 のところを 0 にする」操作です。たとえば umask が 033 のとき、ファイルは 666 − 033 = 633 ではなく、644 になります。666（`rw-rw-rw-`）にはもともと `x` がないので、033 の `x` のビット（1）は取り除くものがないからです。
:::

umask は、**プロセスごとの設定**です。uid と同じく、シェルから起動したコマンドに受け継がれます。`/proc` で確かめられます。

```sh run title="umask はプロセスが持っている"
grep Umask /proc/self/status
```

前の節の `strace` で、`chmod` コマンドが `umask(0000) = 0022` というシステムコールを呼んでいました。あれは、自分の umask を調べていたのです（`chmod +x` のように「だれの」を省いた書き方のとき、umask を考えに入れるためです）。

`umask 077` と打って変わるのは、そのシェルと、そこから起動するコマンドだけです。いつも同じ umask にしたいときは、ログインのたびに読まれる `~/.profile` に書いておきます。

## chown と chgrp：持ち主とグループを変える {#chown}

モードを変えるのが `chmod` なら、持ち主を変えるのが `chown`（change owner）、グループを変えるのが `chgrp`（change group）です。

```sh run error title="自分のファイルを alice に渡す"
chown alice new.txt
```

断られました。**持ち主を変えられるのは root だけ**です。自分のファイルを他人に「あげる」ことも、ふつうのユーザーにはできません。これができると、たとえば自分が作ったファイルを他人のものに見せかけることができてしまうからです。

グループのほうは、少しゆるくなっています。持ち主は、**自分が入っているグループ**になら変えられます。

```sh run title="グループを staff に変える"
chgrp staff new.txt
ls -l new.txt
```

```sh run error title="入っていないグループには変えられない"
chgrp alice new.txt
```

root なら、どちらも自由に変えられます。`chown 持ち主:グループ` と書くと、両方をいちどに変えます（次のブロックは root のシェルで実行します。プロンプトの最後が `#` になります）。

```sh run root title="root が持ち主を変える"
chown alice:staff /home/you/new.txt
ls -l /home/you/new.txt
chown you:you /home/you/new.txt
ls -l /home/you/new.txt
```

どのコマンドがだれに許されるかを、まとめておきます。

| したいこと | コマンド | できる人 |
| --- | --- | --- |
| モードを変える | `chmod` | 持ち主と root |
| グループを変える | `chgrp`、`chown :グループ` | root。持ち主は、自分が入っているグループにだけ |
| 持ち主を変える | `chown` | root だけ |

## root と su と sudo {#root}

何度も出てきた **root** は、uid が 0 のユーザーです。「スーパーユーザー」とも呼びます。図 4-2 のいちばん上にあるとおり、カーネルは実効 uid が 0 のプロセスに対して、`rwx` の検査をほとんどしません。

特別なのは「root」という名前ではなく、**0 という番号**です。カーネルの中の検査は、「uid が 0 かどうか」で書かれています。

システムの設定ファイルやほかの人のファイルを直すには、root の権限が要ります。たとえば、パスワードの情報が入った `/etc/shadow` は、ふつうのユーザーには読めません。

```sh run error title="/etc/shadow は読めない"
ls -l /etc/shadow
cat /etc/shadow
```

### sudo：1 つのコマンドだけ root で実行する

`sudo コマンド` と書くと、そのコマンドだけを root として実行します。

```sh run title="sudo"
sudo whoami
sudo id
sudo cat /etc/shadow
```

`sudo whoami` の答えが `root` になりました。`/etc/shadow` も読めます。2 つ目の欄がパスワードです。そのままではなく、元に戻せない形に変換した**ハッシュ**（`$y$` で始まる長い文字列）が入っています。root の欄は `*` です。これは「パスワードではなれない（ロック）」という印です。

だれでも `sudo` を使えるわけではありません。使ってよい人は `/etc/sudoers` というファイルに書いてあります。

```sh run title="sudo を使ってよい人"
sudo cat /etc/sudoers
```

`%sudo` は「sudo グループのメンバー」という意味です。you は sudo グループに入っているので使えます。`NOPASSWD:` が付いているので、パスワードもたずねられません（クラウドのサーバでよく見る設定です。ふつうに入れた Debian や Ubuntu では `NOPASSWD:` がなく、最初の 1 回は**自分の**パスワードをたずねられます）。上の `Defaults` の行は、sudo の動き方の設定です（`secure_path` は、sudo で動かすコマンドを探す PATH）。自分が何を許されているかは、`sudo -l` で確かめられます。

```sh run title="自分に許されていること"
sudo -l
```

bob は sudo グループに入っていません。sudo は、まず本人であることを確かめるために bob のパスワードをたずね、それから断ります。このサイトの Linux の練習用のパスワードは、**ユーザー名と同じ**です（bob なら `bob`）。この例では、打つ文字を `stdin` で先に渡しています。本物の端末では、パスワードとして打った文字は画面に出ません。

```sh run error user="bob" stdin="bob\n" title="bob は sudo を使えない"
sudo whoami
```

### su：別のユーザーになる

`su`（substitute user）は、別のユーザーとしてシェルを動かすコマンドです。名前を省くと root になります。`-c` を付けると、コマンドを 1 つだけ実行して戻ります。`su` は、**なる相手の**パスワードをたずねます。alice のパスワード（`alice`）を渡します。

```sh run stdin="alice\n" title="su で alice になる"
su alice -c 'id; cat /home/alice/diary.txt'
```

alice として実行したので、alice の日記が読めました。では、root になろうとするとどうなるでしょうか。

```sh run error stdin="you\n" title="root はロックされている"
su -c whoami
```

root のパスワードの欄は `*`（ロック）なので、どんなパスワードを打っても `Authentication failure` です。間違えると、2 秒待たされてから断られます（パスワードを片端から試す攻撃を遅くするためです）。Ubuntu も同じで、root のパスワードは最初からロックされています。root のシェルが要るときは、`sudo` に `su` を起動させます。`su` を起動したのが root なら、パスワードはたずねられません。

```sh run title="sudo で su を起動する"
sudo su -c 'whoami; cat /home/bob/readme.txt'
```

root として実行したので、あなたが入れなかった `/home/bob` の中も読めました。

`sudo` と `su` の使い分けは、次のとおりです。

| | `sudo コマンド` | `su` |
| --- | --- | --- |
| すること | 1 つのコマンドを root（または `-u ユーザー` で別の人）として実行 | 別のユーザーのシェルを始める |
| 必要なもの | `/etc/sudoers` で許されていること。自分のパスワード（`NOPASSWD:` なら不要） | 相手のパスワード（root が使うなら不要） |
| 向いている場面 | 日々の管理作業。だれが何をしたかが記録に残る | 続けて何個もコマンドを打つとき |

今の Linux では、root のパスワードを共有せずに済む `sudo` を使うのがふつうです。Ubuntu のように、root としては直接ログインできないようにしてあるディストリビューションもあります。

:::warn root で作業するときは
root のプロセスは、カーネルに止めてもらえません。`rm -rf` の行き先を 1 文字間違えれば、システムのファイルが消えます。ふだんはふつうのユーザーで作業し、必要なコマンドにだけ `sudo` を付ける。これが、権限の仕組みを自分の安全のために使うということです。
:::

:::deep root にもできないこと
root が素通しになるのは、読みと書きです。**実行**だけは例外で、ふつうのファイルは、3 つの組のどこかに `x` が 1 つも立っていなければ、root でも実行できません。このサイトの Linux でも、モード 644 のスクリプトを root が `./` で実行しようとすると、`Permission denied` になります。また、今の Linux は root の力を「ケーパビリティ」という細かい単位に分けていて、コンテナ（第 19 章）の中の root からは、その一部を取り上げることができます。
:::

## setuid と sticky ビット {#special}

ここで、1 つ疑問が出てきます。`su` や `sudo` は、ふつうのユーザーが起動するプログラムです。プロセスはシェルの uid を受け継ぐのでした。それなら、uid 1000 のプロセスが、どうやって root になれるのでしょうか。

### setuid：ファイルの持ち主の権限で動く

`su` と `sudo` のモードを見ると、見慣れない文字があります。

```sh run title="su と sudo のモード"
ls -l /usr/bin/su /usr/bin/sudo /usr/bin/cat
stat -c '%a %n' /usr/bin/su /usr/bin/cat
```

`cat` は `-rwxr-xr-x` ですが、`su` と `sudo` は `-rw`**`s`**`r-xr-x` です。持ち主の `x` の場所が `s` になっています。これが **setuid**（set user ID）ビットです。数字では、3 桁の前にもう 1 桁付けて 4755 と書きます。

setuid ビットが立ったプログラムを実行すると、そのプロセスの**実効 uid**は、起動した人ではなく、**ファイルの持ち主**の uid になります。`su` の持ち主は root なので、だれが起動しても、実効 uid が 0 のプロセスとして動きます。

```fig graph setuid ビットの働き。ふつうは、起動した人の uid がそのまま受け継がれる。setuid ビットがあると、実効 uid だけがファイルの持ち主のものになる
{
  col: 300, row: 110,
  nodes: [
    { id: 'sh', label: 'シェル', sub: '実 uid 1000 / 実効 uid 1000', x: 0, y: 0.5, mono: false },
    { id: 'cat', label: 'cat のプロセス', sub: '実 uid 1000 / 実効 uid 1000', x: 2, y: 0, mono: false },
    { id: 'su', label: 'su のプロセス', sub: '実 uid 1000 / 実効 uid 0', x: 2, y: 1, kind: 'accent', mono: false },
  ],
  edges: [
    { from: 'sh', to: 'cat', label: '/usr/bin/cat（rwx、持ち主 root）を実行' },
    { from: 'sh', to: 'su', label: '/usr/bin/su（rws、持ち主 root）を実行', style: 'accent' },
  ],
}
```

自分の目で確かめましょう。root になって、`cat` のコピーに setuid ビットを付けたものを作ります。

```sh run root title="cat のコピーに setuid ビットを付ける"
cp /usr/bin/cat /usr/local/bin/rootcat
chmod u+s /usr/local/bin/rootcat
ls -l /usr/local/bin/rootcat
```

ふつうのユーザーに戻って、ふつうの `cat` と `rootcat` の両方に、自分自身の uid を表示させます。

```sh run title="実 uid と実効 uid"
cat /proc/self/status | grep Uid
rootcat /proc/self/status | grep Uid
```

`cat` は `1000 1000 …` ですが、`rootcat` は `1000 0 …` です。1 つ目の**実 uid**（起動した人）は 1000 のままで、2 つ目の**実効 uid** が 0 になりました。権限の検査に使われるのは実効 uid なので、このプロセスは root として扱われます。

```sh run title="rootcat なら、だれでも /etc/shadow が読める"
rootcat /etc/shadow
```

`sudo` も付けていないのに、読めてしまいました。

:::warn setuid は危険と隣り合わせ
`rootcat` は、「だれでも、どのファイルでも読める道具」になってしまいました。setuid root のプログラムは、利用者に**決まった仕事だけ**をさせるように、注意深く書かれていなければなりません。`su` や `sudo` は、root になったあと、まず「この人に許してよいか」を自分で調べます。何も調べない `cat` に setuid を付けるのは、鍵を配っているのと同じです。実験が済んだら、すぐに消します。
:::

```sh run root title="片づける"
rm /usr/local/bin/rootcat
```

### 古典的な例：passwd

setuid の代表的な使い道が、パスワードを変える `passwd` コマンドです。パスワードは `/etc/shadow` に入っていて、root しか書き換えられません。しかし、自分のパスワードは自分で変えたいはずです。そこで `passwd` は setuid root になっています。

```sh run title="passwd と /etc/shadow"
ls -l /usr/bin/passwd /etc/shadow
```

`passwd` は root として動きますが、「実 uid が示す本人の行だけを書き換える」ように作られています。ふつうのユーザーに「`/etc/shadow` 全体を書き換える権限」を渡す代わりに、「自分の行だけを書き換えてくれるプログラム」を渡しているわけです。今のパスワード（`you`）、新しいパスワード、確かめのためにもう一度、の 3 行を渡して変えてみます。

```sh run stdin="you\nnew-pass-42\nnew-pass-42\n" title="自分のパスワードを変える"
passwd
```

```sh run title="変わったことを確かめる"
passwd -S
sudo grep '^you:' /etc/shadow
```

`passwd -S` の 2 つ目の `P` は「使えるパスワードがある」、3 つ目は最後に変えた日です。`/etc/shadow` の you の行のハッシュも変わりました。他人の行は、`passwd` が書き換えさせません。

```sh run error title="他人のパスワードは変えられない"
passwd alice
```

:::note setgid
同じ仕組みがグループにもあります。**setgid** ビット（数字では 2000、表示はグループの `x` の場所が `s`）です。プログラムに付けると、実効 gid がファイルのグループになります。ディレクトリに付けると意味が変わり、「その中に作ったファイルのグループが、作った人の主グループではなく、ディレクトリのグループになる」という働きをします。グループで共有するディレクトリに便利です。
:::

### sticky ビット：/tmp で他人のファイルを消せない理由

`/tmp` は、だれでも一時的なファイルを置けるディレクトリです。モードを見てみます。

```sh run title="/tmp のモード"
ls -ld /tmp
stat -c '%a %n' /tmp
```

`drwxrwxrw`**`t`** です。全員に `rwx` があります。そして、その他の `x` の場所が `t` になっています。これが **sticky ビット**（数字では 1000。合わせて 1777）です。

前の節で、「ディレクトリに `w` があれば、中のファイルは他人のものでも消せる」ことを見ました。そうすると、全員に `w` がある `/tmp` では、他人のファイルを消し放題になってしまいます。sticky ビットは、それを防ぎます。**sticky ビットの立ったディレクトリでは、ファイルを消したり名前を変えたりできるのは、そのファイルの持ち主（とディレクトリの持ち主と root）だけ**になります。

あなたが `/tmp` にファイルを置き、だれでも書けるモード 666 にしておきます。

```sh run title="/tmp にファイルを置く"
echo "you のファイル" > /tmp/you.txt
chmod 666 /tmp/you.txt
ls -l /tmp
```

alice が、これに書き足し、それから消そうとします。

```sh run error user="alice" title="alice は書けるが、消せない"
echo "alice が足した行" >> /tmp/you.txt
cat /tmp/you.txt
rm -f /tmp/you.txt
```

書き足すことはできました。ファイルのモードが 666 だからです。しかし、消すことは `Operation not permitted` で断られました。`/tmp` に `w` はあるのに、sticky ビットが止めたのです。

エラーの文が、これまでの `Permission denied`（EACCES）と違うことにも注目してください。`Operation not permitted` は **EPERM** という別のエラー番号です。大まかには、EACCES は「`rwx` の検査で断られた」、EPERM は「持ち主や root でなければできない操作だった」ときに返ります。`chmod` や `chown` を断られたときも、EPERM でした。

特別な 3 つのビットを、まとめておきます。

| ビット | 数字 | `ls -l` での表示 | 働き |
| --- | --- | --- | --- |
| setuid | 4000 | 持ち主の `x` が `s` | 実行すると、実効 uid がファイルの持ち主になる |
| setgid | 2000 | グループの `x` が `s` | 実行すると、実効 gid がファイルのグループになる。ディレクトリでは、中のファイルがグループを受け継ぐ |
| sticky | 1000 | その他の `x` が `t` | ディレクトリの中のファイルを、持ち主しか消せなくなる |

:::key この章のまとめ
- ユーザーとグループは**番号**（uid、gid）で区別される。名前との対応は `/etc/passwd` と `/etc/group` に書いてある。`id` で自分の番号とグループがわかる
- ファイルには、持ち主・グループ・**モード**が記録されている。モードは、持ち主（u）・グループ（g）・その他（o）の 3 つの組に、それぞれ `r`（4）`w`（2）`x`（1）。8 進数 3 桁で 644、755 のように書く
- 権限を調べるのは**カーネル**で、調べられるのは**プロセス**。プロセスの実効 uid とグループを、ファイルの uid と gid と順に比べ、**最初に当てはまった組の 3 ビットだけ**を見る。だめなら EACCES（Permission denied）を返す
- `chmod` でモードを変える（`u+x` の記号か、`644` の数字）。変えられるのは持ち主と root。`chown` は root だけ。`chgrp` は、持ち主が自分の入っているグループにだけ
- **ディレクトリ**では、`r` は名前の一覧、`x` は通り抜け、`w` は中のファイルを作る・消す。`x` のないディレクトリの下には行けない。ファイルを消せるかどうかは、ファイルではなくディレクトリの `w` で決まる
- 新しいファイルのモードは、頼んだモード（666 や 777）から **umask** のビットを取り除いたもの。umask 022 なら 644 と 755
- **root**（uid 0）は検査をほとんど受けない。`sudo` は 1 つのコマンドを root で実行し、`su` は別のユーザーのシェルを始める
- **setuid** ビットの付いたプログラムは、ファイルの持ち主の権限で動く（`su`、`sudo`、`passwd`）。**sticky** ビットの付いたディレクトリ（`/tmp`）では、他人のファイルを消せない
:::

## 確認問題 {#quiz}

自分でコマンドを打って確かめます。どの問題も、この章の最初の状態（ホームディレクトリ `/home/you` にいる状態）から始まります。採点は、コマンドを実行したあとのファイルの状態や、出力を比べて行います。

:::quiz スクリプトを仲間にだけ使わせる
`hello.sh` のモードを、次のとおりにしてください。

- 持ち主：読み・書き・実行ができる
- グループ：読みと実行ができる
- その他：何もできない

```sh answer
chmod 750 hello.sh
```

```sh check
stat -c '%a %A %n' /home/you/hello.sh
```

:::hint
数字なら、`rwx` は 7、`r-x` は 5、`---` は 0 です。記号なら `chmod u=…,g=…,o= hello.sh` の形で書けます。
:::
:::

:::quiz 新しく作るものを、はじめからグループ止まりにする
`umask` を設定してから、ファイル `report.txt` とディレクトリ `logs` を作ってください。できあがりのモードは、`report.txt` が 640（`rw-r-----`）、`logs` が 750（`rwxr-x---`）になるようにします。`chmod` は使わないでください。

```sh answer forbid="chmod"
umask 027
touch report.txt
mkdir logs
```

```sh check
stat -c '%a %n' /home/you/report.txt /home/you/logs
```

:::hint
ファイルは 666、ディレクトリは 777 から、umask のビットが取り除かれます。グループからは `w` を、その他からは `rwx` を全部取り除く umask を考えます。
:::
:::

:::quiz staff だけが使える共有ディレクトリ
ホームディレクトリに `share` というディレクトリを作り、**staff グループのメンバー（you と alice）だけ**が、中にファイルを作ったり一覧を見たりできるようにしてください。staff に入っていない bob は、中に入ることも、一覧を見ることもできないようにします。

採点では、alice と bob がそれぞれ `share` の中にファイルを作れるか、一覧を見られるかを試します。

```sh answer
mkdir share
chgrp staff share
chmod 770 share
```

```sh check
stat -c '%G %n' /home/you/share
su alice -c 'touch /home/you/share/from-alice && echo alice: can create'
su alice -c 'ls /home/you/share > /dev/null && echo alice: can list'
su bob -c 'touch /home/you/share/from-bob 2> /dev/null && echo bob: can create'
su bob -c 'ls /home/you/share > /dev/null 2>&1 && echo bob: can list'
su bob -c 'cat /home/you/share/from-alice > /dev/null 2>&1 && echo bob: can pass'
echo done
```

:::hint
作っただけの `share` は、グループが you です。まずグループを staff に変えます（`chgrp`）。それから、グループに `rwx` を与え、その他からは全部取り上げます。
:::
:::

:::quiz Permission denied の原因を直す
`proj/data/result.txt` を `cat` で表示しようとすると、`Permission denied` になります。原因は 2 か所あります。権限を直して、`cat proj/data/result.txt` で中身を表示してください。`sudo` と `su` は使わないでください。ファイルを移動したりコピーしたりする必要はありません。

```sh prep
mkdir -p proj/data
echo "測定の結果：42" > proj/data/result.txt
chmod 200 proj/data/result.txt
chmod 644 proj/data
```

```sh vary
chmod 755 proj/data
chmod 644 proj/data/result.txt
echo "測定の結果：1987" > proj/data/result.txt
chmod 200 proj/data/result.txt
chmod 644 proj/data
```

```sh starter
ls -ld proj proj/data
cat proj/data/result.txt
```

```sh answer forbid="sudo,su"
chmod u+x proj/data
chmod u+r proj/data/result.txt
cat proj/data/result.txt
```

:::hint
`ls -ld proj proj/data` で、途中のディレクトリのモードを見ます。ディレクトリを通り抜けるのに要るのは、どの文字でしたか。そこを直すと、`ls -l proj/data` でファイルのモードも見えるようになります。
:::
:::
